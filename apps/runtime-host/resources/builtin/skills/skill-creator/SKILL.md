# 编制与维护 Skill

交付一套可被当前 Host 发现和加载的 Skill，保留用户已经选择的目标、工具和授权范围。普通单次任务不必沉淀为 Skill。

先查看目标位置是否已有同类技能及其资源，优先修改现有内容。以用户指定目录和作用域为准；未指定时优先使用当前运行环境给出的 `user_skills_directory/<name>/SKILL.md`。用户需要项目专用技能时，使用工作区的 `.ez-assistant/skills/<name>/SKILL.md`。环境未提供用户目录时先确认实际可写的 Skill 根目录，不猜测其他用户的 Home，也不要把本技能的 `builtin:skill-creator` 来源标签当作磁盘目录。内置正文只读，新内容写入用户或工作区目录。

## 可发现的入口

目录名和 `name` 保持一致，使用小写字母、数字及单个连字符，最多 64 字符。入口文件必须为 UTF-8 的 `SKILL.md`，以 YAML frontmatter 开始：

```markdown
---
name: task-name
description: 简要说明技能的实际能力和适用请求。
---

正文从这里开始。
```

`description` 用于未加载正文时选择技能，应明确用途，避免吸引无关请求。默认允许用户和模型按需加载；仅在用户明确要求时使用 `disable-model-invocation: true` 或 `user-invocable: false`。不要把工具提示或技能启用当作权限授权。

## 有用的正文与资源

记录能够改变执行选择的信息：输入和结果、关键领域约束、真实工具入口、易错步骤及失败后如何收敛。删去模型已知的常识、重复规则和从单次偶发故障推导的通用禁令。不为所有任务强制额外审批、联网、发布或固定格式。

仅为实际需要增加 `scripts/`、`references/` 或 `assets/`。重复且容易出错的机械工作可使用脚本；较长的条件性细节放入 references，并从入口说明何时读取。资源路径相对本 Skill 目录，禁止依赖开发机私有绝对路径、已有凭据或未交付的运行时。不要创建空目录、占位说明、无关 README 或另一份配置副本。

## 验证与交付

核对 frontmatter 的名称、说明、正文和所有资源引用；有脚本时在授权范围内用可重建输入验证。通过设置中的 Skill 列表重新读取，确认实际来源、同名覆盖及名称禁用状态；必要时在新一轮执行中加载并验证真实行为。已有会话的历史激活正文不会被新文件改写。

以一个真实请求检查技能是否能产出用户需要的结果，发现问题后做有证据的修正。说明实际写入位置、验证结果和未验证条件；只有任务本身明确要求的外部操作才属于本次交付。
