# 企业后台前端开发规范

本规范适用于 `apps/enterprise-admin/`（企业中心管理后台）。通用 TypeScript/React 原则沿用
[`前端编程规范.md`](前端编程规范.md)，本文件只约定企业后台特有的技术基线、状态架构、请求与
Token 设计；冲突时以本文件为准。模块职责边界见
[`docs/modules/enterprise-admin.md`](../modules/enterprise-admin.md)。

技术选型与写法参考用户指定项目 `zhkf-monorepo/frontend/zx-zhkf-admin`。

## 一、技术栈基线

| 维度 | 约定 |
| --- | --- |
| 框架 | React 19，函数组件 + Hooks |
| 语言 | TypeScript strict |
| UI | Ant Design 6（ConfigProvider Token 定制），不引入 Pro/Umi |
| 状态 | MobX 6（`makeObservable` 显式声明），Store 单例 |
| 路由 | React Router 8，`createHashRouter`（配合 `/admin/` 静态部署） |
| 样式 | SCSS Modules（布局）+ AntD Token（视觉），不引入第二个 CSS-in-JS |
| HTTP | `@hey-api/openapi-ts` 生成 SDK + `@hey-api/client-axios` |
| 测试 | Vitest（node 环境）+ 真实浏览器回归 |
| 构建 | Vite（rolldown），产物 `dist/admin` 由 Center 同源装配 |

## 二、目录与分层

```text
src/
├── app/               # 路由表（routes.tsx）、应用壳（AdminApp）、页面布局（PageLayout）、身份守卫（IdentityRoutes）
├── features/          # 业务页面：login/users/audit/account/passwords，页面私有组件与 hook 就近放置
├── stores/            # AdminStore（身份与写入权威，单例）
├── request/           # api.ts（薄封装）、paged-list.ts（PagedList）、openapi/（生成代码，禁手改）
├── components/        # 跨页面复用的无业务组件（UserIdentity、useElementHeight）
├── model.ts           # 视图投影类型与映射（userView/auditView/actionLabels）
├── theme.ts           # 主题 Token（见第五节）
├── bootstrap.ts       # 渲染前装配：MobX 配置、client、拦截器
└── main.tsx           # 入口
```

- 页面私有组件、hook、样式 colocate 在页面目录内（如 `UsersRoute/useUsersData.ts`）；
  只有两个以上页面稳定复用才上提 `components/` 或 `request/`。
- PageLayout 只组合顶栏、侧栏、内容区和 Outlet，不读取业务 Store 或维护弹窗状态。导航菜单、面包屑、用户菜单按层级放在布局下的独立子组件；路由选中态归导航菜单，账号弹窗及焦点恢复归用户菜单，专属样式随组件归属。页面数据与页面弹窗归各路由页面本地管理。
- 离开确认统一由身份守卫下的 NavigationGuard 注册唯一 useBlocker，各编辑器只登记/释放放弃编辑回调，不能各自注册 blocker（路由库只执行最后一项）。登记表与当前身份同生命周期，不复制表单数据；提交中禁止导航，确认离开才调用当前编辑器的清理回调。

## 三、状态管理（2026-09-18 用户确立）

1. **Store 单例直引**：Store 文件尾 `export default new XxxStore()`，组件直接 `import`，
   **禁止经 props、路由参数或 Outlet context 透传 Store**。保留具名 class 导出供测试实例化。
2. **Store 职责收窄为身份与写入权威**：当前用户、内存 Token、登录提示、退出确认、写入锁，
   以及 login/logout/verifyIdentity 和 saveUser/toggle/resetPassword/changePassword 等
   与身份生命周期耦合的写入方法。
3. **页面临时态不进 Store**：列表数据、筛选参数、分页、加载/失败态属于路由页面，使用页面级
   hook（`useState` + `PagedList`）承载；弹窗开关与表单草稿留组件本地。
4. **写入后刷新用回调**：新增/编辑/启停成功后，页面直接调用列表 hook 的刷新回调重载；
   不用版本计数、事件总线或 Store 反向感知列表。
5. `makeObservable` 显式声明 observable/action/computed，不新增 `makeAutoObservable`；
   只有实际读取 observable 的组件用 `observer` 包裹。

## 四、请求层与竞态守卫

- **生成 SDK 只读**：`src/request/openapi/` 由 genapi.js 生成，禁止手改；协议变更后重新生成并
  跑 `genapi:check`。
- **api.ts 薄封装**：每个方法显式携带 `Authorization: Bearer <token>`（发起时身份快照）与
  `AbortSignal`，`throwOnError` 收窄响应类型；不另建业务 DTO 层。
- **bootstrap 集中装配**：baseURL/超时、无显式头时注入当前 Token、响应拦截器集中处理
  `TOKEN_INVALID`/`ADMIN_REQUIRED`——只清除**匹配该请求 Token** 的身份，旧 Token 的迟到失败
  不能登出新身份；断网与业务错误不触发退出。拦截器随 dispose 释放。
- **刷新恢复身份**：前端会话 Cookie 只保存后台 Token，bootstrap 在路由首次渲染前进入恢复态并查询本人身份；恢复中或失败时由壳层遮蔽路由内容，网络故障保留凭据并提供重试，确认失效或退出成功才清理。Cookie 属性及安全边界遵循 enterprise-admin 模块约束；不引入后端 Session。Store 由 bootstrap 销毁，组件 effect 清理不清身份或 Cookie。
- **PagedList 代次守卫**：页面读取统一走 `PagedList`——新查询中止旧请求并成为唯一可提交代次；
  响应提交前校验身份快照（`isCurrent`），卸载或身份切换后的迟到响应不能写入页面。
  取消请求不代表服务端回滚；写入不自动重试。
- **身份切换整树重建**：`RequireIdentity` 以 `key={token}` 挂载 Outlet，换身份即卸载全部页面
  状态，不逐个清理投影。
- **错误呈现**：`failure()` 按错误码映射文案；写入失败（"结果未确认，不重复提交"）与读取失败
  （页面 Result 区可重试）分开呈现；附 request_id 便于核对。

## 五、主题 Token

Ant Design ConfigProvider 是控件视觉的**唯一 Token 来源**，业务代码不得覆写 AntD 内部 DOM
选择器；SCSS Module 只承担布局结构。Token 的完整清单、取值与设计意图见
[`企业后台主题Token设计.md`](企业后台主题Token设计.md)；新增视觉需求先查 `src/theme.ts`
能否用 Token 表达，禁止在业务代码里硬编码与 Token 重复的颜色/字号/圆角。

## 六、验证

- 改动后按范围执行：`typecheck`、`lint`（oxlint + Prettier format:check）、`test`、
  `build`；协议相关改动加 `genapi:check`。
- 2026-09-20 用户要求测试只覆盖核心逻辑：保留身份登录/恢复/失效、管理权限、关键写入与两种改密、异步竞态、失败恢复和敏感信息过滤。每项行为优先在最有效的一层验证，不在 Store、拦截器和集成入口重复铺相同用例。
- 不测试框架已保证的路由匹配/历史行为，不扫描源码字符串约束组件写法，不逐字比对 CSS 或为文案、菜单排列、简单布局专门增加单测。UI 沿用设计仍是开发要求，但不转化为脆弱的自动化快照。测试统一在 `tests/unit/`，语义命名。
- 真实浏览器按改动风险抽查核心链路（登录、关键写入、退出及受影响的交互），不为每次小改动重复完整页面/状态矩阵；无法执行时说明，不用测试数量替代验收结论。
