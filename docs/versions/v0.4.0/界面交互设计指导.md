## 二、产品定位与设计目标

Safety Demo 不是普通聊天产品，也不是只读调试器。它的首要用途是让开发者在一个页面
内核验：

- 当前 Run 冻结了哪组 Plan/Build × Ask/Auto；
- 一个工具调用经过了哪条策略；
- 审批时实际将执行什么 resolved 路径或 Shell command；
- 工具是否执行、失败、超时、被取消或被 Guardrail 终止；
- 页面断线后后端 Run 是否仍在继续，以及恢复后的权威状态。

设计目标：

1. **运行边界始终可见**：工作目录、临时工作区、当前 Run 模式和高风险状态不隐藏在
   设置弹层里。
2. **审批事实完整**：不截断 Shell command、路径、workdir 或有效 timeout，不用风险
   评分代替实际参数。
3. **对话与执行并重**：模型文本是主内容，但工具过程、审批和审计不能退化成原始 JSON
   日志。
4. **状态以服务端为准**：前端只展示 snapshot 和事件事实，不因按钮点击自行宣称成功。
5. **适合快速开发验证**：单页面、无导航层级、无组件库，常用动作在一屏内完成。

非目标：

- 模拟正式桌面应用视觉；
- 管理多个 Session、多账户或持久规则；
- 编辑任意工作目录、环境变量或策略文件；
- 提供 Markdown 富文本、文件预览器、终端模拟器；
- 把审计时间线做成完整日志检索产品。

## 三、页面入口与启动状态

### 3.1 正常入口

后端启动后输出：

```text
http://127.0.0.1:<port>/
```

页面加载顺序：

```text
请求 /api/snapshot
→ snapshot 成功
→ 建立 SSE
→ 进入可交互页面
```

本 Demo 不实现访问令牌，刷新页面可直接恢复连接。页面必须持续说明：

> Safety Demo 仅监听本机，但以当前用户权限执行工具；请在使用后关闭进程。

页面不为鉴权写入 localStorage、sessionStorage 或 cookie。

### 3.2 后端不可达

首次连接失败时显示独立阻断页，不渲染聊天、路径、审计或模式控件：

```text
无法连接 Safety Demo
本机 Safety Demo 尚未启动或已经停止。

请检查启动终端并重新打开其中的地址。
```

提供“重试连接”按钮，不提供修改后端地址的输入框。

### 3.3 服务重启

连接中断且原端口不再响应时进入断开状态：

```text
Safety Demo 连接已断开
服务可能已经重启。若终端显示了新地址，请重新打开该地址。
```

停止对已失效端口的无限重连，保留已有只读投影。

### 3.4 初次加载

使用完整骨架屏：

- 顶栏保留高度；
- 左侧显示 3 个对话卡片骨架；
- 右侧显示状态卡骨架；
- 文案为“正在读取 Session 快照…”；
- snapshot 未成功前不展示可点击的模式、发送、审批或 reset。

## 四、整体布局

### 4.1 桌面布局

页面分为三层：

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部安全状态栏：连接 / Session / 路径 / 当前 Run / 停止 / 重置 │
├──────────────────────────────────┬───────────────────────────┤
│                                  │ 右侧检查器                 │
│ 左侧对话与工具过程                │ ┌ 审批                     │
│                                  │ ├ 活动                     │
│                                  │ └ 审计                     │
│                                  │                           │
├──────────────────────────────────┴───────────────────────────┤
│ 运行配置 + 消息输入 + 发送                                    │
└──────────────────────────────────────────────────────────────┘
```

- 左栏约 `62%`，最小宽度 `560px`；
- 右栏约 `38%`，最小宽度 `380px`；
- 顶栏固定在页面顶部；
- 输入区固定在左栏底部，不覆盖右栏；
- 左侧对话和右侧检查器分别滚动，避免长 Shell 输出把审批按钮推出视口。

建议页面最小可用宽度为 `960px`；开发验收主视口为 `1440 × 900`。

### 4.2 窄屏

`< 960px`：

- 顶栏允许换行；
- 主区改为单栏；
- 对话区在上，检查器在下；
- 检查器标签保持 sticky；
- 输入区不使用 fixed，跟随对话区底部；
- Shell command 和 JSON 详情横向滚动，不缩小到不可读字号。

本版本不为手机触屏做专门产品体验，但必须保证 `768px` 宽度仍能完成审批和取消。

### 4.3 信息层级

从高到低：

1. 当前是否连接、是否高风险、是否有活动 Run；
2. 待审批动作和停止入口；
3. 模型消息与工具执行结果；
4. 当前 Run 冻结模式与下一 Run 配置；
5. 活动/审计详情和原始数据。

待审批不能只靠右侧标签上的小圆点提示；审批存在时右栏自动切到“审批”，顶栏同时显示
“等待审批”状态。

## 五、顶部安全状态栏

### 5.1 左侧品牌与连接

显示：

```text
ez-assistant · Safety Demo
[已连接 / 正在重连 / 已断开]
```

连接状态：

| 状态 | 颜色 | 行为 |
| --- | --- | --- |
| 正在连接 | 中性蓝灰 | 控件禁用 |
| 已连接 | 绿色 | 正常交互 |
| 正在重连 | 黄色 | 禁止新 Run 和审批决定 |
| 已断开 | 红色 | 禁止所有写动作，显示恢复说明 |

### 5.2 Session 环境

紧接连接状态显示两个可展开字段：

- `工作目录`：完整 `session_workdir`；
- `临时工作区`：完整 temporary workspace。

默认以末尾 2–3 个路径分量紧凑展示，hover/focus tooltip 与展开详情必须提供完整路径。
复制按钮复制完整路径。路径不可在页面编辑。

旁边固定显示提示：

> 路径规则是逻辑路径策略，不是系统沙盒；符号链接可能指向范围外目标。

桌面宽度不足时提示折叠为“逻辑路径策略”信息按钮，但不能完全消失。

### 5.3 当前 Run 状态

没有 Run：

```text
当前：空闲
```

活动 Run：

```text
Run 4 · Plan + Ask · 正在执行
```

状态枚举：

- 正在启动；
- 模型生成中；
- 正在解析工具；
- 等待审批；
- 工具执行中；
- 正在停止；
- 已完成；
- 已失败；
- 已取消；
- Guardrail 终止。

终态保留到下一 Run 开始，不立刻退回“空闲”，避免结果闪退；同时用较小文字标明“可开始
下一 Run”。

### 5.4 顶栏动作

活动 Run 时显示“停止运行”：

- 单击立即发送取消，不弹二次确认；
- 请求发出后变为 disabled 的“正在停止…”；
- 辅助文案：“正在等待模型请求或工具进程完成清理”；
- 后端确认终态前不显示“已取消”。

空闲时显示“重置 Session”：

- 活动 Run 或审批存在时 disabled；
- 点击打开确认层；
- 确认层明确展示将清空的对话、审计和临时工作区完整路径；
- 主按钮为“重置并删除临时工作区”；
- 取消按钮获得默认焦点；
- reset 成功后以新 snapshot 重建页面，不能只清空 DOM。

## 六、左侧对话与工具过程

### 6.1 消息流

按权威 Journal 顺序显示：

- UserMessage；
- AssistantMessage；
- Tool exchange；
- 最终 AssistantMessage；
- Run 终态提示。

不直接把每个 SSE delta 当独立消息。流式 Assistant 卡片只在当前 Run 内增量更新；收到
最终消息或重取 snapshot 后，以权威完整内容校准。

### 6.2 用户消息

- 右对齐或浅蓝背景；
- 标记“你”与发送时间；
- 保留换行；
- 不支持 Markdown；
- 只显示用户实际提交内容，不重复显示系统 instructions。

### 6.3 Assistant 消息

- 左对齐，中性面板；
- 流式时显示轻量脉冲光标和“生成中”；
- reasoning 不默认展开为正文；
- 若事件提供 reasoning，可在卡片下方使用折叠区“Reasoning（调试）”展示；
- 最终显示模型名、finish reason 和 token usage（若有）；
- 不把 ProviderState 直接渲染为面向用户的文本，原始内容只在详情中查看。

### 6.4 Tool exchange 卡片

每个 Tool Call 有一张内嵌卡：

```text
[文件 / Shell / 通用] 工具名
策略：Plan 临时工作区允许
状态：等待审批 / 执行中 / 成功 / 失败 / 拒绝 / 超时 / 已取消
```

摘要按类型：

- 文件：operation + 完整绝对逻辑路径；
- Shell：command 第一行 + workdir + process_mode；
- 通用：tool name；
- invalid/unknown：原工具名 + 参数错误摘要。

Shell command 摘要可只显示第一行，但展开区必须展示完整 command，不允许用省略后的内容
审批。

工具卡状态：

| 状态 | 展示 |
| --- | --- |
| resolved | “参数已解析” |
| policy allowed | 绿色“策略允许” |
| awaiting approval | 黄色“等待审批”，右侧检查器同步卡片 |
| denied | 红灰“已拒绝”，显示模型可见 reason |
| running | 蓝色“执行中”与流式输出 |
| success | 绿色“成功”与结果摘要 |
| failed | 红色“失败”与错误 |
| timeout | 红色“超时”与部分 stdout/stderr |
| cancelled | 灰色“已取消/未执行” |

### 6.5 Shell 输出

工具卡展开后提供：

- command；
- workdir；
- effective timeout；
- process mode（`managed` / `detached`）；
- exit code；
- stdout；
- stderr；
- truncated 标记。

stdout/stderr 使用等宽字体和不同左侧色条，不合并来源。流式输出按到达顺序追加到一个
“实时输出”视图，每行保留 channel 标签；最终结果仍分别显示两个区。

输出区域：

- 默认最大高度 `320px`，内部滚动；
- 提供“展开到页面”；
- 不提供 ANSI 终端模拟，控制字符按纯文本处理；
- truncated 时在顶部和底部均显示“输出已达到 1 MiB 上限，后续内容已排空但未保留”；
- 复制只复制当前保留内容。

detached 成功不能展示成“服务已就绪”，只展示“启动命令已完成，后台进程已脱管”。若
输出含 PID 或日志路径，按普通 stdout 展示并允许复制；页面不据此建立后台任务状态。

### 6.6 文件结果

- read：显示 effective offset、limit、next offset、truncated；内容等宽显示；
- list：表格显示 name/path、kind、symlink 标记；
- find/search：显示结果数、truncated、稳定截断原因、路径和内容行号；
- write/edit/delete：显示 bytes/replacements/deleted path；
- UnsupportedEncoding、UnsupportedFileType、TooLarge、rg 不可用分别使用明确文案，
  不统一成“工具失败”。

symlink 条目采用“File · 符号链接”“Directory · 符号链接”双标签，不把 Symlink 当成
与 File/Directory 平级的 kind。

### 6.7 Run 终态

对话末尾加入不可折叠终态条：

- 完成：绿色；
- 失败：红色，显示受控 ExecutionError；
- 取消：灰色，说明未结算 Tool Call 已补记；
- Guardrail Enforce：红橙色，显示 detector、threshold 和触发 call；
- Observe 不形成终态，只显示诊断提示。

## 七、右侧检查器

### 7.1 标签

三个标签：

1. 审批；
2. 活动；
3. 审计。

标签显示数量：

- 审批：`审批 1`；
- 活动：当前 Run 工具/事件数量，可不显示精确数；
- 审计：当前内存条目数。

默认标签：

- 有 pending approval：审批；
- 有活动 Run 无审批：活动；
- 空闲：审计；
- 用户手动切换后保持选择，除非出现新审批，新审批必须自动切回审批。

### 7.2 审批空状态

```text
没有待审批动作
Ask 模式下，未命中信任规则的调用会显示在这里。
Plan 的能力边界不能通过审批越过。
```

Plan + Auto 时补充：

> Auto 只在 Plan 能力边界内自动允许。

### 7.3 文件审批卡

显示顺序：

1. `文件操作 · Write/Edit/Delete/...`；
2. 完整绝对逻辑路径；
3. 路径范围判断；
4. symlink 风险固定提示；
5. 未命中规则原因；
6. Allow once / Deny。

完整路径使用可选择文本和复制按钮，不在中间省略。内容本身不进入审批卡，避免把完整
文件内容复制到审计 UI；write/edit 只显示字节数、old/new 字符数等摘要。

### 7.4 Shell 审批卡

显示顺序：

1. `Shell · 当前用户权限` 高风险标签；
2. 完整 command；
3. 完整 workdir；
4. effective timeout；
5. process mode；
6. 输出上限；
7. 环境策略摘要：“继承父环境，已过滤敏感变量”；
8. 未命中规则原因；
9. Allow once / Deny。

command 使用 `pre`，完整保留换行、空格、管道和重定向。默认高度最多 `280px`，允许
内部滚动和复制完整 command，但 DOM 中不能保存另一份被截断的审批值。

固定提示：

> Shell 可以读取当前用户有权访问的文件、网络和进程，也可以绕过结构化文件策略。

detached 额外固定提示：

> 此调用完成后，后台进程不再由 Session 管理；Run 取消、Session reset 或 Demo 退出都
> 不会停止它。启动成功也不代表服务健康，请通过命令输出的 PID、日志或服务端口自行
> 核验和停止。

### 7.5 审批操作

- Deny 放左侧，视觉为中性红灰；
- Allow once 放右侧，视觉为明确主按钮；
- 初始焦点在审批标题或 Deny，不在 Allow；
- Enter、Space、Escape 不设置全局快捷批准；
- 单击后两按钮立即 disabled，显示“正在提交决定…”；
- 只有服务端事件确认后卡片才消失；
- 409/已失效时显示“该审批已结束”，随后重取 snapshot；
- 不显示“始终允许”“会话允许”或规则保存入口。

若一次 Run 后端未来产生多个审批，本版仍一次只展示当前 pending；不预留批量勾选 UI。

### 7.6 活动标签

按 seq 展示可读时间线：

```text
14:08:31 Run started · Plan + Ask
14:08:33 Model streaming
14:08:36 write_file resolved
14:08:36 Plan temporary workspace allowed
14:08:36 Tool started
14:08:36 Tool completed · success
```

- 默认只显示可读标题；
- 展开后显示结构化详情 JSON；
- Provider credential、完整文件内容不进入详情；
- 最多保留后端 snapshot 提供的内存范围，前端不自行宣称完整审计。

Guardrail Observe 使用黄色诊断卡：

```text
重复调用达到阈值 3
当前仅观察，不会中止执行。
```

Enforce 使用红橙色卡并与 Run 终态关联。

### 7.7 审计标签

按工具调用聚合，而不是按所有底层事件逐条铺开：

```text
read_file · success
Resolved → Plan allow → Started → Completed
```

每条展示：

- run/call/tool；
- resolved facts；
- policy 与命中依据；
- approval decision；
- start/end/elapsed；
- success/error/timeout/cancel；
- Shell exit code；
- 展开原始审计对象。

过滤器首期只有：

- 全部；
- 文件；
- Shell；
- 拒绝/失败。

不增加搜索、日期范围、导出或持久化按钮。

## 八、底部运行配置与输入

### 8.1 配置区

配置区标题为“下一次运行”，避免和当前 Run 混淆：

```text
下一次运行
执行模式  [Plan | Build]
审批模式  [Ask  | Auto]
```

使用两个独立 segmented controls，不用一个包含四项的下拉框，直观表达两个维度。

默认：

- Plan；
- Ask。

每个选项的短说明：

- Plan：只在只读工作目录和临时工作区能力边界内执行；
- Build：允许进入更广泛的文件/Shell 策略；
- Ask：未命中信任规则时请求一次性审批；
- Auto：能力边界内未匹配调用自动允许。

### 8.2 模式冻结

Run 开始后：

- 顶栏与消息流显示“当前 Run：Plan + Ask”；
- 配置区仍可编辑“下一次运行”；
- 若配置与当前 Run 不同，显示黄色提示“仅对下一次运行生效”；
- 当前 Run 的审批和策略展示始终使用冻结模式，不读取控件当前值；
- 页面 reload 后从 snapshot 恢复当前 Run 模式，本地下一 Run 配置重置为服务端默认或
  snapshot 中的 draft，不能覆盖活动 Run。

### 8.3 Build + Auto 高风险确认

用户首次在当前页面会话选中 Build + Auto 时，配置区展开确认条：

```text
Build + Auto 会自动允许能力边界内未命中的文件和 Shell 调用。
Shell 以当前用户权限运行，这不是沙盒。

[返回安全模式] [启用 Build + Auto]
```

- 选中不立即生效，必须点击“启用 Build + Auto”；
- 不要求输入固定短语；
- 确认只保存在页面内存，刷新后重新确认；
- 启用后顶栏和配置区持续显示红橙色“高风险”标签；
- 开始 Run 时不再重复弹一次确认；
- 当前 Build + Auto Run 结束前风险标签不消失，即使“下一次运行”改回 Plan。

Plan + Auto 不显示高风险确认，但显示说明“Auto 不能越过 Plan 边界”。

### 8.4 消息输入

- 多行 textarea；
- placeholder：“描述要完成的任务，或要求读取/修改/执行命令…”；
- `Ctrl/Cmd + Enter` 发送；
- 单独 Enter 换行；
- 空白消息不能发送；
- 发送按钮显示将冻结的模式，例如“以 Plan + Ask 运行”；
- 活动 Run、等待审批、断线或正在恢复 snapshot 时 textarea 和发送按钮 disabled；
- 不实现消息排队。

点击发送：

1. 按钮进入“正在启动…”；
2. POST 成功只表示请求被接受；
3. 收到 RunStarted/snapshot 后才清空 textarea 并显示活动 Run；
4. 请求失败保留原输入，显示就地错误；
5. 409 时重取 snapshot，提示已有活动 Run。

## 九、状态同步与断线恢复

### 9.1 权威状态

前端只维护两类状态：

- 服务端投影：snapshot + 按 seq 应用的事件；
- 页面草稿：消息输入、下一 Run 模式、展开/标签选择。

Run、审批、Journal、审计和临时工作区状态都属于服务端投影。

### 9.2 seq

- 记录最后应用 seq；
- 小于等于最后 seq 的重复事件忽略；
- seq 连续则增量应用；
- 出现 gap、SSE 断开或 JSON 解析失败，进入“正在恢复”并重新请求 snapshot；
- snapshot 成功后替换服务端投影，再从其 seq 建立事件流；
- 不尝试根据缺失事件自行补算工具或审批结果。

### 9.3 重连期间

页面已有内容保持可读，但：

- 新 Run disabled；
- 审批按钮 disabled；
- reset disabled；
- 模式草稿可编辑；
- 停止按钮显示 disabled 的“连接中断，状态未知”；
- 顶部固定黄色/红色横幅说明后端 Run 可能仍在继续。

恢复后：

- 若审批仍 pending，重新启用并自动切到审批；
- 若 Run 已结束，展示实际终态；
- 若 temporary workspace 已 reset，整体替换 Session 内容。

## 十、异常与反馈

### 10.1 页面级错误

使用固定横幅：

- SSE 断开；
- snapshot 恢复失败；
- Safety Demo 后端不可达。

首次加载不可达时进入阻断页；已有连接断开时保留已有只读内容。

### 10.2 操作级错误

在发起动作附近展示，不只使用 toast：

- 发送失败：输入区；
- 审批失败：审批卡；
- cancel 失败：顶栏 Run 状态旁；
- reset 失败：确认层和顶栏；
- 复制失败：对应复制按钮旁。

Toast 只用于“已复制”等短暂、非关键反馈。

### 10.3 工具错误文案

稳定映射：

| 分类 | 标题 | 说明 |
| --- | --- | --- |
| InvalidInput | 参数无效 | 展示模型可读 message |
| NotFound | 路径不存在 | 展示完整逻辑路径 |
| UnsupportedEncoding | 不支持的文本编码 | 本版只支持 UTF-8 文本 |
| UnsupportedFileType | 不支持的文件类型 | 设备、FIFO、Socket 等不处理 |
| TooLarge | 文件超过工具上限 | 展示实际工具上限 |
| SearchBackendUnavailable | ripgrep 不可用 | 安装系统 `rg` 后重试 |
| Deny | 策略或用户拒绝 | 展示具体依据 |
| Timeout | Shell 执行超时 | 展示 timeout 与部分输出 |
| Guardrail | Guardrail 已触发 | 展示 detector、mode、threshold |
| Cancelled | Run 已取消 | 工具进程已完成清理后才显示 |

不得把 Deny 文案写成操作系统权限拒绝，也不得把逻辑路径范围写成“沙盒阻止”。

## 十一、视觉规范

### 11.1 基调

采用紧凑的深色开发工具界面，但不直接复制 debug-viewer：

- 背景：近黑蓝灰；
- 面板：两级深灰；
- 主文字：浅灰白；
- 次文字：中灰；
- 强调：冷蓝；
- 成功：绿色；
- 等待/Observe：黄色；
- 高风险/Enforce：橙红；
- 失败/Deny：红色；
- 取消/未执行：灰色。

避免大面积纯红。红色用于风险标签、失败边框和关键动作，保证长时间调试可读。

### 11.2 字体

- UI：系统无衬线字体；
- command、path、stdout/stderr、JSON：系统等宽字体；
- 正文 `13–14px`；
- 辅助信息不低于 `11px`；
- command 与审批 facts 不使用过小字号压缩。

### 11.3 组件

- 卡片圆角 `8px`，边框区分状态；
- 状态 badge 使用文字 + 颜色，不能只靠颜色；
- segmented control 有清晰 selected、hover、focus；
- 按钮至少 `32px` 高；
- 所有可滚动代码区有可见边界和键盘滚动能力；
- copy 按钮使用文字“复制”，不只用无标签图标。

### 11.4 高风险表现

Build + Auto：

- 顶栏红橙 badge；
- 输入区淡橙背景；
- 发送按钮文案包含 Build + Auto；
- 不使用持续闪烁或动画。

等待审批：

- 审批标签、顶栏状态和对应 Tool 卡同时变黄；
- 只在新审批出现时做一次轻微强调，不持续脉冲。

## 十二、可访问性与键盘

- 使用语义化 `header`、`main`、`aside`、`section`、`button`、`textarea`；
- 右侧标签实现 `role=tablist/tab/tabpanel` 和方向键切换；
- 连接、Run、审批变化进入 `aria-live=polite`；
- Enforce 和不可恢复错误使用 `role=alert`；
- 所有 focus 状态清晰；
- 审批出现时不强行抢走正在输入的 textarea 焦点，但若当前没有文本焦点，将焦点移到
  审批标题；
- 不设置单键全局 Allow 快捷键；
- `Ctrl/Cmd + Enter` 只在消息输入聚焦时发送；
- 颜色对比达到 WCAG AA 的正文标准；
- `prefers-reduced-motion` 下关闭强调动画。

## 十三、前端组织

保持单 `app.js` 可接受，但按清晰区域分函数，不建立隐式全局状态：

```text
createInitialViewState
applySnapshot
applyEvent
renderHeader
renderConversation
renderInspector
renderComposer
startEventStream
recoverSnapshot
requestRun / requestCancel / decideApproval / resetSession
```

前端 view state 建议：

```javascript
{
  connection: { status, lastSeq },
  snapshot: { session, run, journal, approval, audit },
  draft: {
    message,
    executionMode,
    approvalMode,
    buildAutoConfirmed,
  },
  view: {
    inspectorTab,
    expandedItems,
  },
}
```

要求：

- 外部 JSON 先检查必要字段再使用；
- 不用 `innerHTML` 渲染模型、路径、command、stdout/stderr 或错误；
- 所有不可信文本用 `textContent`；
- 原始 JSON 使用 `JSON.stringify` 后放入 `textContent`；
- DOM event listener 只注册一次，重渲染不重复绑定；
- 页面卸载时中止 fetch SSE 和在途请求；
- 前端 cap 只限制已渲染的诊断节点数量，不改写服务端 snapshot 事实。

## 十四、验收口径

### 14.1 页面与模式

1. loopback 启动链接可直接进入页面；后端不可达或服务重启后进入明确断开状态。
2. 工作目录、临时工作区、逻辑路径非沙盒提示和连接状态始终可见。
3. Plan/Build 与 Ask/Auto 是两个独立控件；默认 Plan + Ask。
4. 当前 Run 冻结模式与下一 Run 草稿可同时区分；修改草稿不会改变活动 Run。
5. Build + Auto 必须完成一次明确确认，且活动 Run 全程显示高风险标签。
6. Plan + Auto 明确说明不能越过 Plan 能力边界。

### 14.2 对话、工具与审批

7. 对话流能展示用户、Assistant、Tool exchange 和 Run 终态，不重复流式消息。
8. 文件卡展示完整绝对逻辑路径、操作、结果范围和 symlink 正交标记。
9. Shell 卡与审批卡能访问完整 command、workdir、timeout、process_mode、分离
   stdout/stderr 和 truncated 状态，不以省略值审批；detached 明确提示其不受 Run、
   Session 或 Demo 生命周期管理。
10. pending approval 同时反映在顶栏、Tool 卡和审批标签；新审批自动进入审批视图。
11. 审批只有 Allow once / Deny；没有保存、批量和隐式快捷批准。
12. Deny、timeout、取消、Observe、Enforce 和工具错误都有不同且准确的反馈。

### 14.3 运行控制与恢复

13. 活动 Run 可立即请求停止；页面在工具进程清理完成前保持“正在停止”。
14. 活动 Run、审批或断线时不能启动第二个 Run。
15. SSE gap/断线后通过 snapshot 替换投影；不根据缺失事件推测终态。
16. 重连期间禁止审批和新 Run，并说明后端任务可能仍继续。
17. reset 明确确认会删除临时工作区，并以服务端新 snapshot 重建页面。

### 14.4 安全与可访问性

18. 页面不创建鉴权 storage/cookie，所有请求保持同源且不依赖通用 CORS。
19. 模型、command、路径和输出都通过 `textContent` 渲染，不产生 HTML 注入。
20. Provider credential 和完整文件内容不进入审计详情。
21. 键盘可以完成模式选择、发送、标签切换、审批、取消和 reset；不存在单键批准。
22. 连接、Run、审批和 Guardrail 状态不只依赖颜色表达。

### 14.5 人工视口

至少核对：

- `1440 × 900`：双栏完整布局；
- `1024 × 768`：双栏或临界布局无审批遮挡；
- `768 × 900`：单栏仍可完成审批和停止；
- command 超长、多行、含管道与重定向；
- Windows 与 POSIX 长路径；
- stdout/stderr 接近输出上限；
- 审计条目和对话足够长时双区独立滚动。

## 十五、明确不进入本页面的内容

- 正式桌面导航、会话列表、设置页或系统托盘；
- 工作目录选择器；
- API Key 输入框；
- 规则编辑器、持久信任或审批历史管理；
- 多 Session、多 Run 并发；
- 消息队列；
- Terminal/PTY；
- Markdown/HTML 富文本；
- 日志导出或数据库；
- No Progress Guardrail；
- 资源预算面板；
- 把 Demo HTTP DTO 提升到 `assistant-protocol`。
