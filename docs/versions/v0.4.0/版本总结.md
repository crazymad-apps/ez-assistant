## 三、形成的核心能力

- Tool Call 在授权前完成类型校验、默认值落实与纯词法 resolve；Authorizer、Guardrail
  和 executor 共享同一 resolved invocation，避免重复解析和参数漂移。
- Core 提供与工作模式无关的顺序策略装配及类型化事实适配；Plan/Build × Ask/Auto、
  allow 优先和一次性审批只由上层 Safety Demo 组织，没有进入 Core 业务词汇。
- Repeated Invocation 与 Consecutive Failures 检测器均可省略、Observe 或 Enforce；
  Enforce 在终止前可靠补齐 Tool Result 和 Recorder 交换。
- `agent-tools-local` 提供真实 UTF-8 文件、系统 `rg` 搜索和 Shell Adapter；权限、审批
  与审计仍属于上层。文件授权使用绝对逻辑路径，不把符号链接或工作目录描述为沙箱。
- Shell 使用完整 command 和平台 launcher，支持分通道流式输出、输出上限、超时、
  取消和进程树清理；`managed` 清理可管理后代，`detached` 仅在父 Shell 退出且 stdio
  收敛后交接，不承诺服务健康或提供后台句柄。
- Safety Demo 在 loopback 上验证真实工具、四种模式、审批、取消、Guardrail、审计和
  断线恢复；其 Session、Run、HTTP DTO 和页面状态不构成正式 Runtime 契约。

## 四、偏差与边界

- 正式 `assistant-runtime`、`assistant-protocol` 和 Desktop 没有代码改动；审批模式、
  持久化授权和 Session 托管后台服务留待后续 Runtime 设计。
- 新增资源预算、AgentExecution 总超时、No Progress Guardrail 和正式 Approval SPI
  未进入本版本。
- Unix 进程组无法约束主动 `setsid` / `setpgid` 逃逸的后代；Shell 仍以当前用户权限
  运行，不是 OS 沙箱。
- Windows Job Object、launcher 和环境变量大小写分支没有 Windows 实机证据；当前仅
  有条件编译实现和平台条件测试。
- 真实 DeepSeek Tool Call 补验及三个指定浏览器视口截图未重新执行；用户在知悉原因、
  影响和替代证据后明确接受并要求归档。

## 五、遗留与后续入口

- `v0.5.0` 进入可插拔记忆系统；启动设计前重新核对 Memory Service、Plugin、
  Orchestrator、作用域、召回与失败隔离边界，不直接复制 Safety Demo 私有编排。
- 正式 Runtime 后续设计需要独立确定审批持久化、后台服务管理、Session/Run 调度和
  产品协议；本版本只提供可装配的底层事实与能力。
- 若后续需要强安全隔离，应单独设计 OS 沙箱、权限降级或容器方案，不能把逻辑路径
  名单、workdir 或进程组清理升级表述为强隔离。
- 归档没有执行 `git add`、`git commit` 或 `git push`；提交准备等待用户另行授权。
