## 六、问题修复与偏差

### 6.1 DeepSeek Tool Call reasoning 缺失

用户实际验证发现：DeepSeek 偶发返回含 Tool Call、但没有 `reasoning_content` 的
Assistant 消息。旧实现会先执行工具并提交该回合，到下一 Model Step 重放历史时才被
Provider 拒绝，导致当前内存 Session 持续失败。

候选版本已调整为：

1. Safety Demo 每次 DeepSeek 请求显式启用 thinking；
2. Provider Decoder 在 `TurnFinished` 前检查需要 reasoning 的 Tool Call；
3. 缺失 reasoning 时直接返回 Protocol 错误，不执行工具、不提交坏回合；
4. 流式、非流式、完整服务终态和 Demo 请求装配均有确定性测试。

修复不会静默改写已经污染的内存 Session。使用旧进程验证过该错误时，需要重启 Demo
或 reset Session 后再试。

### 6.2 实现偏差

- Demo 为展示实时模型内容和 Shell 分通道输出，在私有 SSE `RunProgress` 中加入脱敏
  detail；该 DTO 没有进入 `assistant-protocol`。
- 前端活动列表只保留当前页面收到的最多 200 条诊断事件；刷新后由权威
  Run/Journal/审计 snapshot 重建，不宣称保留完整事件历史。
- 本版本按确认范围不修改正式 Runtime，不把 Demo 的审批模式组织提升为产品契约。
