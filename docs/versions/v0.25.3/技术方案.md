## 三、目标架构与最小新增

不新增进程、队列、数据库或客户端形态。新增集中在四类：

1. **Host 平台 Adapter 层**：`apps/runtime-host/src/platform/` 从"Unix 专用 detach 工具"
   扩展为承载 Windows／Unix 文件安全、锁、进程树的原生实现目录；各业务模块
   （endpoint、config_source、storage、files）改为调用平台抽象，删除模块级整体
   `cfg(unix)` gate。
2. **固定 Shell 目录 + 绑定状态**：`ShellKind` 协议枚举、Host shell catalog 探测、
   sessions 表一列 + settings 单行全局默认 + runs 表冻结事实、`SessionCommand` 新
   variant。
3. **Desktop Windows 原生适配**：bootstrap 存活/安全检查、`desktop_platform`、窗口／托盘
   实机回归；Windows 私有安全打开 helper 就近放于 runtime_bootstrap 下，不新增 crate。
4. **Windows 构建发布入口**：`tauri.windows.conf.json`、`prepare-sidecar` 三元组扩展、
   `release-windows.mjs`。

平台抽象遵循"归属优先"：优先用 `std` 跨平台 API（`File::try_lock` 在 Windows 是
LockFileEx、`fs::rename`、`sync_all`），仅 std 不覆盖处引入 `windows-sys`（无运行时依赖、
官方维护）。不引入 `winapi`、`windows` 大 crate 全量 feature 或新的 async 运行时。

### 3.1 Windows 文件安全模型（对 Unix 安全目标的分层取舍）

原则：**保密性交给操作系统 ACL，软件层只保留对抗路径逃逸与保证功能正确所必需的检查**。
Windows 单用户 Profile 目录的 ACL（默认仅当前用户/SYSTEM/Admins）已覆盖 Unix 下靠
mode/uid 逐文件核验对抗的"其他用户读取/替换"威胁；同用户攻击者本可直接读取 token，
对私有文件做换文件（TOCTOU）防护没有增量价值。因此 Unix 的逐项检查在 Windows 分支
**不逐项移植**：

| Unix 现有检查 | Windows 处理 | 理由 |
| --- | --- | --- |
| 0600/0700 mode 核验与修复、DACL 重写 | **不做** | 依赖 Profile ACL 继承，不重写 DACL，不逐文件复检 |
| uid==euid 属主校验 | **保留**（GetNamedSecurityInfo 取 owner 比对当前用户 SID，失败 fail-closed） | 防 Home 被配置到共享/他人目录的一次性廉价检查 |
| O_NOFOLLOW 防符号链接 | **保留**：`symlink_metadata` 检测 `FILE_ATTRIBUTE_REPARSE_POINT`，symlink/junction/一切 reparse 一律拒绝 | 路径逃逸问题而非权限粒度问题：junction 可指向授权根之外，与多用户无关 |
| dev/ino TOCTOU 复核 | **仅 Host 文件浏览保留**（打开句柄取 File ID 与路径 stat 对比） | 防授权根判定与实际打开之间被 junction 掉包；私有文件（token/配置/锁）不做 |
| 目录 fsync | 无通用等价。降级为：staging 文件 `sync_all` + rename + **重打开读取校验内容**；崩溃窗口仅可能残留 staging 或旧文件，重启时按既有"发现文件无效即视为无实例"路径自愈 | 已接受差异 |
| flock 实例锁 | `File::try_lock()` 在 Windows 映射 LockFileEx 独占锁，语义一致（进程退出即释放） | 功能正确性要求，`endpoint.rs:110` 现有调用直接复用 |

任何 owner 不符、reparse point 命中的 Home/discovery/token/配置/数据库路径一律
fail-closed，报明确错误，不静默继续。

### 3.2 Windows Shell 目录与 launcher

`ShellKind` 协议枚举（snake_case serde，进 `assistant-protocol`）：

```text
windows_powershell_51 | cmd | powershell_7 | git_bash | posix_sh
```

`posix_sh` 表达 macOS／Linux 现状（`/bin/sh -c`），使跨平台移动 Session 数据时绑定可
表示为"当前 OS 不可执行"而不是丢失。macOS／Linux 既有会话不写绑定列（NULL = 平台默认
`posix_sh`），行为零变化。

Host shell catalog 探测规则（只判断真实可执行性，不接受用户路径）：

| 类型 | 探测 | Agent 非交互 launcher | 交互终端 |
| --- | --- | --- | --- |
| PowerShell 5.1 | `%WINDIR%\System32\WindowsPowerShell\v1.0\powershell.exe` | `powershell.exe -NoProfile -NonInteractive -Command <cmd>` | `powershell.exe -NoLogo` |
| CMD | `%COMSPEC%`（回退 `%WINDIR%\System32\cmd.exe`） | `cmd.exe /d /s /c <cmd>` | `cmd.exe` |
| PowerShell 7 | `pwsh.exe`：PATH + `%ProgramFiles%\PowerShell\7\pwsh.exe` | `pwsh.exe -NoProfile -NonInteractive -Command <cmd>` | `pwsh.exe -NoLogo` |
| Git Bash | Git for Windows：注册表 `SOFTWARE\GitForWindows\InstallPath` 的 `bin\bash.exe`，回退 PATH 中 `bash.exe`；校验父目录形态防 CYGWIN 冒充（同目录存在 `git.exe`） | `bash.exe -c <cmd>`（登录 shell 环境由 bash 自身提供，不传 `--login` 避免改写 PATH） | `bash.exe -i` |

CMD 用 `/d /s /c` 禁用 AutoRun 并使用标准引号解析；PowerShell `-Command` 模式下模型方言
按"PowerShell 语法、单引号优先、反引号续行"描述；Git Bash 模型方言按 POSIX。多行命令由
launcher 参数整体传递，不做文本互译。方言提示文本与 launcher 由同一 `ShellKind` 派生，
结构上不可能出现"提示与执行不一致"（见 4.4）。

2026-09-13 用户修正：普通输入不重新探测环境。会话初始化确认一次完整 Shell 环境；尚无快照的旧会话在首次执行时初始化一次。之后只在用户显式刷新或切换到达队首时重新探测；设置/终端目录查询仅用于可用性展示，不改写会话环境。执行失败不自动失效重探或回退。**【原型验证】**注册表 Git 路径、`pwsh` PATH 解析、`-Command` 对
中文/引号/`$LASTEXITCODE` 的行为。

## 四、分模块实现方案

### 4.1 Host 入口与平台层重构（前置里程碑）

- `main.rs` 删除 15 个模块的整体 `#[cfg(unix)]` 与 `fn main` 的 gate；`access`/`launch`/
  `serve` 在 Windows 直接可用（Windows 无 setsid，`--detached` 用 `creation_flags`
  `DETACHED_PROCESS\|CREATE_NEW_PROCESS_GROUP` 重实现 `launch_detached`）。
- 新增 `src/platform/windows.rs` 与既有 `unix.rs` 对等：文件打开/身份/ACL/reparse 工具、
  `sync` 语义封装（提供 `write_private_atomic(path, bytes)`：staging + fsync + rename +
  重读校验，内部按平台处理目录 fsync 差异）、进程树工具。
- `endpoint.rs`/`config_source.rs`/`storage/filesystem.rs` 的私有文件与原子替换改为调用
  上述封装；Unix 路径行为不变（mode/O_NOFOLLOW/目录 fsync 保留），Windows 走 3.1 模型。
- `image.rs` 的 Unix 权限调用改为平台封装。26 个 `#![cfg(unix)]` 集成测试在 Windows 上
  仍按平台跳过，但编译门禁（`cargo check`）必须两平台通过。
- `rg`：维持 PATH 探测（`LocalFileSystemConfig.ripgrep_program` 已可注入）。本版**不随包
  rg.exe**（避免体积与许可审查），探测失败时 Shell 目录式诊断明确报告"文件搜索依赖
  `rg` 未安装"；随包作为后续版本候选。

### 4.2 Host 文件安全打开（`http/resources/files.rs`）

Windows 版 `open_resolved`：

1. 输入路径先规范化为绝对路径；支持盘符绝对路径与 `\\?\` 前缀（长路径 >260 字符经
   `\\?\` 处理）；UNC（`\\server\share\...`）首版**明确拒绝**并在结果中说明（与既有
   路径白名单语义一致，不新增网络文件域）。
2. 逐级使用 OPEN_REPARSE_POINT 打开：任何组件带 FILE_ATTRIBUTE_REPARSE_POINT 即拒绝。
   父目录句柄不共享 WRITE/DELETE，保持至路径操作完成，阻止替换与原地 reparse 改写；
   从固定路径再次打开并以 GetFileInformationByHandleEx(FileIdInfo) 的卷号及 128 位 ID
   复核。std 的 file_index 尚未稳定，不使用长度/时间戳代替真实文件身份。规范化前即执行
   此检查，不能先 canonicalize 消除链接再检查。目录列举保留全部 guard 至扫描结束。
3. 大小写不敏感：规范化时按 `std::fs::canonicalize`（Windows 返回实际大小写）后与
   授权根比较，授权判断用规范化结果，不做逐字符 casefold。
4. 目录列举用 `std::fs::read_dir`（替代 rustix `Dir`）；预览嗅探保持句柄式有界读取。

**【原型验证】**`\\?\` 前缀与 canonicalize 组合在中文／空格目录的实际行为；File ID 在
ReFS 的 128 位扩展 ID 情况（`nFileIndexHigh==0xFFFFFFFF` 时取 `FileIdInfo`）。

### 4.3 用户终端（ConPTY）

2026-09-12 实现核对：下面原型中的“取消后停止 reader 再 drop master”不能直接使用。
实际实现取消后 reader 继续丢弃并排空字节，Job 先终止子树，再在阻塞线程释放 master；
Shell 自然退出同样清理 Job 后代并释放 master。三个真实 ConPTY 关闭/背压/UTF-8 测试已通过。
Open 的 ShellKind 已贯穿 Rust/TS 协议与 Host，四种已安装交互 Shell 输入/退出测试通过；
Ctrl+C 尚未通过，不能以 Job 关闭代替中断验收，正在核查控制事件与 console 输入模式。

- 非阻塞 I/O 等价：Windows 无 `O_NONBLOCK`。改为读侧专用线程 + `Arc<AtomicBool>` 取消
  标志：正常时阻塞读线程照常 `blocking_send`（容量 1 mpsc + ack 背压语义不变）；取消/
  关闭时先 `drop(master)` 令 ConPTY 读返回错误退出线程。写侧用"写前检查取消标志 +
  现有 3s 网络写超时"替代 WouldBlock 轮询。该实现以 `#[cfg]` 分支放在
  `user_terminal/process.rs` 内部，Unix 路径不动。
- 进程树回收：PTY 子进程统一包入 Job Object（`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`），
  terminate 时先发 Ctrl+C 等价（`GenerateConsoleCtrlEvent` 不可靠于 detached，故直接走
  Job 终止）、等待宽限、再关 Job 句柄，最后复用现有"组消失轮询"等价物：Job Object
  查询活跃进程数为 0 才报完成。**【原型验证】**portable-pty 0.9 的 `CommandBuilder`
  是否暴露 Windows creation flags／raw command line；若不暴露，备选方案是在 PTY
  slave spawn 后用 `OpenProcess + AssignProcessToJobObject`（CREATE_SUSPENDED 不可行时
  接受极小竞态窗口并以轮询复核补足）。不以 `taskkill /T` 作为主路径。
- TERM 注入、环境过滤、心跳／写超时／输入 ACK 协议全部复用；Windows 环境过滤补充过滤
  `ProgramData`、OneDrive 等敏感前缀按现有策略评估。
- Ctrl+C／Ctrl+D 由 ConPTY 本身转为对应信号传递给 shell（**【原型验证】**CMD 与
  PowerShell 5.1 下 Ctrl+C 中断行为、UTF-8 代码页：Host 侧为 launcher 追加
  `chcp 65001` 等价设置仅限于 Agent 非交互命令包装层评估，交互终端以默认代码页真实
  行为验收）。

### 4.4 Agent Shell 目录、绑定与 Run 冻结

执行链（全部复用现有机制）：

1. **探测**：Host `shell_catalog` 按 3.2 提供 `ShellCatalogEntry` 列表，经设置/会话上下文
   HTTP 投影给 UI。
2. **全局默认**：settings 单行表；新建 Session 时 `HostSessionEnvironmentFactory`/
   Session 创建路径读取并写入 `sessions.agent_shell_kind` 初值。
3. **切换/刷新**：右栏提交AgentShellSwitch，复用MCP/Skill的可靠接纳、幂等、FIFO和控制结果提交，不创建Run。队首才探测目标；成功结果、Session绑定及确认环境在同一控制事务中提交，失败保留旧绑定。普通输入不重复探测。
4. **Run冻结**：普通输入到达队首，读取会话已确认环境（旧会话缺失时初始化一次），原领取事务冻结Run快照。活动Run及continuation始终使用自己的快照。控制操作完成后只保留可见控制结果，下一次普通输入通过既有内部上下文入口告知模型，无第二队列或环境监控。
5. **装配**：`RunToolFactoryRequest` 扩展冻结 shell 事实字段；Session 的不可变目录
   环境保持原职责，不能把可切换绑定混入创建时冻结的目录。`tools.rs` 的 `compile` 据此构造
   `LocalShell { config: LocalShellConfig { launcher, environment } }`——`LocalShell`
   从进程级单例改为按 Run 构造轻量配置对象（其内部无进程状态，改造成本低）。
   `agent-tools-local` 的既有 launcher 增加宿主编码初始化前缀；模型命令保持原文，
   不自动转换方言。该前缀与固定参数一起属于持久化的冻结事实。
6. **模型告知**：Run 装配时把 `shell_snapshot_json` 编译为一段 `<shell_environment>` 内部
   上下文（OS、Shell 类型、方言/路径/引号/转义/环境变量/退出码约定、cwd），经现有
   InternalBoundary 注入通道（`channel_input_context` 先例）进入该 Run 的消息组装，不改写
   冻结 System Prompt。提示文本与 launcher 同源于 `ShellKind`。
   模型环境段携带完整冻结快照的 JSON，包括 kind、program、fixed_args、command_prefix、
   operating_system 和 dialect，另附编码后的 cwd；所有动态文本转义 XML 边界。
   不能仅凭程序路径与方言文本判断环境未变化，否则相同路径下的类型或启动参数变化会被漏掉。
   固定参数与前缀由 launcher 应用，模型只生成所选方言的命令正文。
   子任务复用父 Run 冻结的基础工具，因此 Shell 环境也从同一快照及 Session 执行 cwd 派生，
   随子任务首次调用、步骤续接和允许的压缩续接补入；不得把子任务私有目录误作执行 cwd。
   Shell 环境与 MCP disclosure 分开传递，不改变冻结 System Prompt 或现有子任务压缩边界。
   控制结果的旧绑定不能从当前 Session 倒推：领取切换时将当时绑定作为
   `shell_switch_previous` 内部消息片段随用户消息同事务落账；启动前失败时随失败结果同事务落账。
   ConversationItem.previous_shell 只投影该历史展示事实，Fork 随规范消息保留；它不参与解释器装配或绑定恢复。
   注意：`shell` 工具的模型可见描述与 schema 保持静态平台无关
   （`agent-tools/src/standard/shell.rs:159` 的现有措辞不修改）——方言差异只通过上述内部
   上下文表达，不把 Shell 类型写进工具描述。ToolSet 本就逐 Run compile
   （`tools.rs:106-238`），Shell 切换只改变注入的 launcher，工具名/描述/schema 不变，
   因此**不存在"切换时重建会话 ToolSet"的动作**，也不破坏既有"注册顺序固定保提示缓存"
   的约束。
   注入策略采用**变化触发注入**（参照 codex 的 `<environment_context>` 差分机制）：会话
   首个 Run 在领取首条用户消息时附入一次全量 `<shell_environment>`，不重复写进 System Prompt 或工具描述。显式刷新/切换后的新事实仍使用相同内部上下文入口；普通输入只读取确认快照与有效上下文，不探测文件系统或注册表，不额外查询上一 Run。
   快照相同也必须核对当前有效上下文是否仍包含对应 Shell 事实；压缩或 Clear 已移除时，
   从当前冻结快照补回。不能仅因为上一 Run 的快照相同就省略已经丢失的模型告知。
   切换指令产生的可见控制结果同时以自然语言记录新 Shell 及方言要点，但历史文字或
   模型摘要不承担恢复执行环境的权威职责。事实仍在时不做逐 Run 重复注入——对照 codex（首 turn 全量 + 变化
   差分）、opencode／gemini-cli（工具描述常驻）、hermes-agent（系统提示环境块）四种开源
   实现，无一采用逐消息注入，逐 Run 注入的 token 成本无必要。不选择工具描述路线
   （opencode/gemini-cli 模式）：gemini-cli 已出现描述写死 `powershell.exe` 而执行实际
   选 `pwsh.exe` 的提示与执行不一致问题，且会话中途切换将改变工具身份；内部上下文注入
   与 Run 冻结快照同源派生，结构上保证一致。

   Fork 不复制源 Run。为使分支历史的切换结果独立于源会话生命周期，Fork 时把目标、
   成功状态和脱敏错误冻结为 `inherited_shell_switch_result` 内部展示上下文，随原历史正文
   复制；连续 Fork 复用已有片段。该片段不能用于绑定恢复、解释器探测或执行装配。
   原会话结果仍从 Input/Run 权威事实派生；分支投影不返回本会话不存在的 Run ID。

跨平台语义：macOS/Linux 的 `ShellKind::PosixSh` 目录项恒可用；Windows 会话绑定
`posix_sh`（或反之）时 catalog 判不可执行，UI 要求显式切换，无回退——与功能设计 5.3
一致。**【原型验证】**`accept_session_input` 与 `execute_session_command` 的事务边界在
`input/mod.rs:223-273` 的 claim 顺序下是否满足第 4 点断言（特别是 command 执行释放
mutation 期间新消息入队的窗口）。

### 4.5 MCP stdio Windows 启动形态

按命令形态分类（`connect_stdio` 内新增平台解析函数）：

- 显式路径相对 cwd 解析，裸名使用最终子进程环境的 PATH；无扩展名时依次查 `.exe`、
  `.cmd`、`.bat`，返回绝对路径。显式扩展名保持原样，不借助文件关联或任意 PATHEXT。
- `.exe` 直接 spawn；`.cmd`/`.bat` 复用 Rust Command 已有的 cmd.exe 包装和参数转义，
  不另拼接 `/c` 原始命令行。Job Object 与 KillOnDrop 沿用现有连接生命周期。
- `node`/`npx`/`python` 等裸名适用相同解析；找不到程序或解释器、权限拒绝和不支持的
  参数分别返回连接诊断，不回退至其他 Shell，也不自动安装依赖。
- cwd 仍为 `runtime_home/mcp/<server_key>`，经 4.1 平台化后的 `prepare_private_directory`
  创建。环境白名单沿用（已含 SYSTEMROOT/WINDIR/TMP/TEMP，补充 `PROCESSOR_*`、
  `ComSpec` 已补齐）。`env_clear` + 白名单策略不变。
- 2026-09-13 Windows 实测 exe/cmd/bat/node/npx/Python 握手、中文/空格 cwd 与批处理参数
  转义通过；关闭、drop、握手取消后 cmd → Node → 后代服务均回收。npx 采用离线夹具，
  不把此结果表述为联网下载或 ctrl-break 信号测试；连接取消使用既有生命周期回收。

- **编码问题（方案 3.2 补充）**：非交互管道模式下 PowerShell 5.1 与 CMD 输出 **ANSI/OEM
  代码页**（本机 GBK，`中文` = `d6 d0 ce c4`），Git Bash 输出 UTF-8；Agent Shell 工具按
  UTF-8 增量解码。修复实测有效：PowerShell 在 `-Command` 内前置
  `[Console]::OutputEncoding=[Text.Encoding]::UTF8;`（输出变为 `e4 b8 ad e6 96 87`）；
  CMD 包装 `chcp 65001>nul & <command>`。launcher 定义更新为：
  - PS 5.1：`powershell.exe -NoProfile -NonInteractive -Command "[Console]::OutputEncoding=[Text.Encoding]::UTF8; <cmd>"`
  - PS 7：`pwsh.exe -NoProfile -NonInteractive -Command "<cmd>"`（pwsh 默认 UTF-8，M5/6 实机复核）
  - CMD：`cmd.exe /d /s /c "chcp 65001>nul & <cmd>"`
  - Git Bash：`bash.exe -c "<cmd>"`（原生 UTF-8）
- 注：交互终端走 ConPTY（输出即 UTF-8），不受此问题影响。
- 2026-09-13 M4 无窗口启动回归修订上述原型结论：PS7 在新建隐藏控制台下也需显式

  CMD 在外层完成 chcp 后启动内层 CMD，使其初始化编码缓存；脚本原文仅通过本次
  子进程环境变量 `EZ_ASSISTANT_CMD_SCRIPT` 延迟展开传入，避免外层提前展开 `%VAR%`。
  内层关闭延迟展开以保留默认 `!`/`^` 语义。此变量不持久化，不是新的 Shell 环境监测。

  Job 挂接先于执行。已有会话在重启 Host 后通过显式刷新取得新的 PS7 初始化前缀。

### A.5 切换事务衔接（原推演，顺序结论已被 B.2 否定，不得据此实现）

基于 2.4 节代码事实推演（M3 落地时以测试固化）：

1. `accept_session_input` 在 mutation gate + Store 事务内创建 Input 与首次 Run；Run 的
   shell 快照在**入队事务**内冻结（非 claim 时）。因此"排在切换之前的输入用旧 Shell"由
   入队顺序天然保证；切换命令执行更新绑定列后，后续入队的 Run 读到新值。同一 Session
   的 FIFO claim 由 mutation gate 串行，无竞态窗口。
2. `execute_session_command` 释放 mutation 执行期间新消息可入队，但都排在其后
   （`queue_item_ids` 顺序在 accept 时已定），不影响断言。
3. **历史原型偏差（已由2026-09-13用户决定及B.2替代，不再待确认）**：功能设计写"切换消息对应的 Agent Run"，
   本实现采用与 `McpRefresh` 同构的 command 语义——切换命令产生可见控制结果消息，
   **不创建 Agent Run**。理由：`inputs` 的 command 行 CHECK 约束不含 Run；为 command 附带
   Run 需要新的 schema 语义且模型无需对切换本身生成回复；切换效果经右栏绑定投影即时可见。
   "切换消息对应的 Run"按"切换生效后的下一个输入 Run"解释。

### B.2 Shell 顺序结论修正（已按2026-09-13用户反馈统一）

A.5 的“入队冻结天然保证 FIFO”论证不成立：活动 Run A 执行中，先入队切换命令 C，
再入队普通输入 B，此时 C 尚未提交绑定，B 若在接纳时读取 Session 绑定会冻结旧 Shell。
mutation gate 只串行接纳／执行临界区，不会让 C 在 B 接纳前完成。修正实现边界见 4.4：
普通输入沿用Queue driver准备后复核及commit_user_message冻结Run，控制操作沿用MCP/Skill控制事务更新确认环境，不新增队列或revision。A/C/B顺序与失败恢复仍须验证；控制操作沿用控制队列能力，不伪造Run取消入口。
2026-09-13用户明确切换/刷新不得触发回复，最终采用无Run控制操作；A.5的无Run方向与该决定一致，但其“接纳时冻结天然保证FIFO”的论证仍不成立。
