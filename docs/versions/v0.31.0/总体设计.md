## 二、目标与范围

用户无需登录即可了解产品、下载客户端并阅读更新日志和操作手册；安装后可以直接在登录页选择
登录模式及企业中心地址；出现模型调用异常时能够查询已有请求与响应证据；日常工作界面支持
统一配色切换。

| Feature | 用户结果 | 主要影响模块 |
| --- | --- | --- |
| F01 企业中心官网与公开页面 | 免登录首页、下载页、更新日志和操作手册，提供后台入口；内容数据独立维护 | enterprise-center、enterprise-admin、现有构建与部署入口 |
| F02 登录选项设置 | 登录页本机信息卡提供登录选项，可选择个人/企业模式并配置企业中心地址；Logo 右侧显示应用名称 | desktop、runtime-host、必要的共享协议 |
| F03 异常模型调用证据 | 异常调用保留请求体和已收到的响应体；左侧请求消息、右侧事件流程轴与聚合内容，清楚说明完整性及失败原因 | enterprise-center、enterprise-admin；评估 Host 独有失败的覆盖边界 |
| F04 整套配色切换 | 一次选择统一切换工作台、代码高亮与终端，保存并恢复偏好 | desktop 的共享界面、查看器、终端和展示偏好 |

服务端搜索保留后续规划。本版不建设通用内容管理系统或主题市场。

## 三、现有基础与设计方向

### F01 企业中心官网与公开页面

企业中心已有 `/admin` 管理前端、安装包上传/发布/撤回、更新说明和公开的更新查询/下载接口。
下载复用现有发布事实和文件服务；官网内容独立维护，不另建安装包存储或发布状态。

- 首页提供产品介绍和下载、更新日志、操作手册入口；管理员通过独立入口进入后台。
- 下载页按实际平台/架构展示已发布且可下载的安装包；撤回、文件不可用和暂无制品时如实展示。
- 更新日志与操作手册以仓库 Markdown 为权威静态源，面向用户简明说明，维护要求纳入
  [开发流程规范](../../specs/开发流程规范.md#用户向更新日志与操作手册)，不从开发过程文件自动生成。
- 最新维护边界：版本详情直接编辑更新日志，复用现有 notes，官网和客户端读取同一发布副本；
  平台纠错后回存仓库。首页与手册独立发布到固定静态目录，不放在安装包管理界面、不绑定安装版本。
  官网下载自动读取各平台最新可用版本，无需额外手选官网版本或上传联合内容包。
- 操作手册覆盖安装、登录配置、基本使用与常见问题，注明适用产品版本；F02 完成后复核。
- 公开路由与管理路由明确分离，调用正文、账号和管理操作继续受原权限保护。
- 2026-10-13 用户明确正式首页使用 `/`，具体公开页面优先匹配；Docker 同一对外域名和端口
  通过 Nginx `location` 分离页面、后台与 `/api/`，直接访问域名不能落到后端接口。
  该要求本轮仅记录方案，Demo 保持现有路径，不修改服务器和部署配置；细节见 F01 功能设计第六节。

2026-10-13 用户进一步明确：官网前端整合进现有 `apps/enterprise-admin` 工程，与 Center 一起
构建部署，不另建官网前端仓库。需要解耦的是内容数据：下载和日志复用安装版本，首页与手册独立读取静态目录。
公开查询、日志编辑、静态内容维护与恢复边界见 [F01 功能设计](features/F01-企业中心官网与公开页面/功能设计.md)，
按最新反馈同步修订；M0／M1 已确认；2026-10-14 按自主推进到 M3 的授权完成 M2 同端口交付，M3 正式内容与端到端验证完成、待人工验收。

### F02 登录选项设置

现有登录后访问设置已支持 Host 模式与中心地址，并通过原生管理证明保护本机配置；更改模式
和中心后需要重启 Host。新入口复用此能力，避免让用户为修改地址必须先完成企业登录。

- 2026-10-13 用户要求结合当前布局重新选址；设计推荐在“这台电脑”卡片内右侧提供“登录选项”，
  个人/企业模式与企业中心地址可直接编辑，替代原页面右上角方案。Logo 右侧增加 `ez-assistant`，图文整体居中。
- 2026-10-13 用户补充：首页账号菜单移除可唤起完整设置的选项；断线退回首页或初始化失败也不能
  打开完整设置。完整设置仅在工作区开放，卡片入口只提供本 Feature 的登录选项。
- 地址校验、保存、生效进度和失败反馈形成闭环；取消编辑不更改实际配置。
- 企业中心地址与远程 Runtime Host 地址采用明确标签，不能混为同一项。
- 编辑态仅保留模式与地址，简短输入提示使用 placeholder；保存模式／地址变更自动清除旧中心绑定，企业地址与原数据保留，后续企业登录重新建立绑定。
- 本机 Desktop 管理自身 Host；普通 Web 或连接远程 Host 的客户端不得借未登录入口修改服务端模式。
- 模式切换、换中心绑定和重启沿用现有数据域及生命周期边界，保留旧用户数据；实际影响在操作前说明。

该需求明确调整既有“登录页不提供本机 Host 管理入口”的产品限制，只开放本项所需登录配置。
登录前原生管理通路、中心换绑与重启交互在 F02 设计中细化，不扩展成全部 Host 管理面板。

2026-10-13 用户确认 [F02 功能设计](features/F02-登录选项设置/功能设计.md)及卡片内入口、品牌横排布局，
并在补充模式切换保留企业地址后要求继续；[技术方案](features/F02-登录选项设置/技术方案.md)已确认，
[界面交互设计指导](features/F02-登录选项设置/界面交互设计指导.md)经用户修订并要求继续后已确认，
[开发计划](features/F02-登录选项设置/开发计划.md)已获用户“可以开始了”授权，F02 M0、M1 已确认，M2 本机集成及正式桌面操作验证完成；Windows 原生覆盖限制保留。

### F03 异常模型调用证据

现有调用记录在启用正文录制后已能保存中断响应的部分快照；关闭录制时没有正文。
本版重点是异常采集策略和真实失败信息，不建立另一套调用日志。

- 范围包括上游错误、连接/超时/流中断等异常下的请求体和实际收到的响应体。
- 区分完整、部分、未收到、截断、采集失败与已清理；无响应时不伪造上游响应正文。
- 记录调用标识、模型、时间、HTTP 状态和已知原因；未知原因保持未知，客户端断开不直接认定为用户主动取消。
- 必须评估 Center 转发成功而 Runtime 解析失败的漏记边界；不能仅凭 HTTP 2xx 认定模型执行成功。
- 正文继续使用既有受保护快照文件，数据库维护检索元数据；与普通运行日志、用量统计分别处理。
- 正常正文录制关闭时如何保留异常证据、缓冲上限、保留期和管理入口必须在 F03 设计中确定。
  不因本次规划启用生产录制或更改现有保留策略。

HTTP 原始转发与 WebSocket 桥接的采集位置必须分别说明，准确标明保存的是哪一段链路的正文；
不能把 Host 与 Center 间的快照冒充未经转换的上游帧。历史未采集内容无法补录。

2026-10-13 用户授权直接编写技术方案，追加调用正文可视化阅读，并确认左侧请求消息、右侧
“事件流程轴 + 聚合内容卡片”的方向；连续同类增量合并，异常落在对应位置，原文按需展开。
不将网络 chunk 当作阅读单位，不虚构事件耗时，终态快照与增量避免重复展示。
见 [F03 技术方案](features/F03-异常模型调用证据/技术方案.md)，其中包含本 Feature 的范围、交互规则与验收口径。
2026-10-13 用户在技术方案及[界面交互设计指导](features/F03-异常模型调用证据/界面交互设计指导.md)
交付后分别要求继续，两份设计及[开发计划](features/F03-异常模型调用证据/开发计划.md)已确认；待明确与 F02 的并行安排。
计划分为异常证据采集与管理、消息与事件可视化、端到端验收三个里程碑，均已完成实现和相应验证；真实上游异常覆盖限制保留。

### F04 整套配色切换

2026-10-13 用户确认纳入，沿用原输入中已确认的统一预设方向：默认浅色、Monokai、
Solarized Light、Solarized Dark。一个选择同时作用于工作台、控件、消息、Markdown 代码块、
Monaco 查看器与终端，不拆分独立的界面和代码主题选项。

- 设置提供主题名称和预览，切换立即生效并保存；重启恢复，配置无效时使用默认主题。
- 复用现有语义颜色变量和展示偏好；主题属于客户端展示，不进入 Session/Run 的业务状态。
- 切换不重建会话、资源标签或终端进程，保留输入和滚动位置；保存失败明确反馈。
- 原生窗口、侧栏毛玻璃和各渲染器保持协调，检查启动闪色、文字对比与状态色可辨识性。
- 图片、PDF 和第三方网页内容保持原色，外围界面跟随主题。
- 不包含主题导入、任意色值编辑、主题市场或系统自动切换。

2026-10-13 用户确认 [F04 功能设计](features/F04-整套配色切换/功能设计.md)并要求继续，确定
“设置 → 外观”入口、Desktop 设备级主题、Host Web 同源浏览器偏好，以及保存失败保留当前配色
并支持重试。[技术方案](features/F04-整套配色切换/技术方案.md)在固定样式核查后随用户要求继续已确认；
[界面交互设计指导](features/F04-整套配色切换/界面交互设计指导.md)与四套配色预览交付后用户再次要求继续，
交互设计已确认，明确左侧栏直接继承全局语义色。[开发计划](features/F04-整套配色切换/开发计划.md)已确认，用户同意先并行不重叠部分，
M0—M3 实现和相应验证完成，正式 Host Web 与 macOS Release 主路径已核验；其他平台实测限制保留，企业中心官网和管理后台不纳入。

## 四、系统边界与跨 Feature 约束

1. 保持 Desktop 与 Runtime Host 双进程、Runtime 内部模块化；UI 仅发送意图和展示状态。
2. Center 持有发布记录、企业配置和调用追溯，Runtime 持有会话与 Run；公开站点不复制这些权威状态。
3. F01 的登录手册与 F02 最终行为一致；F04 覆盖 F02 新增界面，避免新入口遗留固定配色。
4. F01 公开资源与 F03 私有正文严格分离；不得通过静态目录或公开接口访问调用快照。
5. 优先复用已有发布、配置、快照和展示偏好。新增协议、字段或持久化机制前需证明现有事实无法承载。
6. 兼容版本、企业协议和数据升级根据各 Feature 的实际契约变化评估；本草案不预先提升兼容下限，
   不批准生产迁移、部署或修改现有用户数据。

## 五、推进顺序与验收

建议顺序为 F01 → F02 → F03 → F04，默认逐个推进。四者没有必须同时实现的依赖；
官网手册在 F02 完成后复核，主题在新增登录界面稳定后统一收口。

总体设计确认后再形成版本开发计划；各 Feature 进入时分别完成设计、必要方案、交互指导与
开发计划。F01、F02、F04 需要界面交互设计，F03 新增的可视化正文阅读也需交互指导；F01 涉及独立静态内容与公开查询，F02、F03 涉及权限/配置
或采集策略，需明确技术方案；F04 也需技术方案细化偏好保存、启动与渲染器联动。
四项 Feature 已按后续用户授权完成实现及相应集成验证，并完成企业中心部署与多平台包交付。最新用户实测、验收覆盖限制与最终包差异统一见[版本开发台账](开发计划.md#验收就绪核对2026-10-14)，各 Feature 的阶段记录不替代版本最终确认。

版本验收至少覆盖：

- 匿名访问官网全部页面，公开下载与发布/撤回事实一致，后台与私有正文权限不被放开。
- 新安装和已有配置下，登录页修改模式/地址后的真实登录、重启及数据域行为正确；失败可恢复。
- 代表性异常可定位到同一次调用并读取实际采集正文，各类不完整状态真实可辨；采集受资源边界约束。
  请求消息与响应事件聚合保持内容和顺序，异常位置、原文来源及 Runtime 覆盖限制可核对。
- 四套主题覆盖主要界面、代码和终端，重启恢复、切换状态保持及常用平台显示通过核验。
- 跨 Feature 完成下载、配置登录、使用、异常排查的联合路径，并核对手册描述。
