## 二、台账原则与实施边界

1. 里程碑依次为 M0 → M1 → M2 → M3；每步完成实现及最小有效验证后先标为“待确认”，
   获得用户确认才进入下一步。2026-10-14 用户明确授权自主推进到 M3，本次按该授权连续推进并逐步汇报，最终提交 M3 验收。
2. 官网归属现有 enterprise-admin；内容源独立维护，下载与版本状态复用安装包管理。
   不新建官网仓库、CMS、独立内容生命周期或同步任务。
3. 仓库 `docs/site/` 是权威内容源；日志在版本详情编辑发布副本并回存仓库，首页／手册独立部署。正式页面不得用 Demo 示例日志、假下载
   或未实现的操作说明填充；隔离测试可以使用明确的测试夹具，不进入对外交付内容清单。
4. 一个里程碑内交付可实际操作和验证的能力，不以空接口、临时成功状态或仅生成类型宣告完成。
   后续里程碑可以集成已有能力，不能承接前一步本应完成的权限、失败恢复或数据一致性。
5. 只做与当前里程碑有关的检查；关键逻辑用定向测试，布局、焦点和原生下载用浏览器核对。
   不重复堆叠单测、CSS 快照或另建验证报告，计划只保留结论、确认与必要限制。
6. 生产部署、正式发布、迁移用户数据、Git 提交和推送不因计划获批自动执行。

  收敛相关测试、契约、脚本和依赖，不为中间设计保留兼容机制，不操作真实／共享数据库。
- 复用版本 notes 编辑、权限、冲突保护和审计，增加 Markdown 预览及公开日志投影；官网／客户端共用说明。
- 简化静态清单，移除安装版本与日志集合，保留首页、手册、资源校验及安全阅读器；输出独立静态数据。
- 完成固定内容目录只读服务、本地校验／预览及独立更新约定；不需要安装版本、数据库写入或后台重载。
- 更新维护说明、模块边界与生成契约。使用合成夹具验证，不向正式目录填入虚构发布内容。

### M2 同端口正式交付

**目标**：在同一产品部署中完成 Nginx 入口，使直接访问域名进入官网，后端接口保持原有传输行为。

**前置依赖**：M1 已确认；可用的本地隔离容器环境。不用现有用户服务器验证路由变化。

**交付范围**：

- 扩展现有打包流程，交付同版本入口镜像与 Center 镜像，静态文件来自同一次构建。
- 按技术方案的优先级实现页面／后台／API／静态资源分流，Nginx 使用原对外端口，Center 仅走内部网络。
- 补齐安装包私有数据卷与独立公开内容只读挂载、静态资源安全头与缓存、代理流式传输、上传大小与取消约束。
- 更新通用部署示例及运维说明，明确成套升级、卷权限、外部 origin、备份对象和回退边界。
  真实部署地址、账号与专用脚本仍留私有资料，不写入公开交付包。

**验证入口**：复用 Center `npm run package:docker` 及其扩展后的正式打包入口，执行 Compose
配置与 Nginx 语法检查，在新建隔离 Compose 项目上启动实际制品。核对根路径、文章深链接、后台、
有效／未知 API、缺失资源、Center 暂停时的静态入口；通过确定性上游检查流式首字节与取消，
检查较大上传和下载不被截断，并复核既有代理路由。重建容器后核对私有卷与独立静态内容仍可读取。

**完成判定**：仅一个对外入口，Center 没有直出绕过路径；静态资源缺失返回真实错误，接口错误
不是首页 HTML；流式／上传／下载符合原接口语义，私有卷不对外公开，静态目录仅有可公开内容，成套构建及恢复路径可操作。
没有容器运行证据不能以配置文件生成成功标记该里程碑完成。

**Review 重点**：location 优先级是否正确；是否遗漏 `/api` 无尾斜杠入口；是否把私有数据或仓库根目录挂静态；
是否误用短超时／缓冲截断长流；是否通过 API-only 绕过完整资源检查；入口和 Center 是否发生版本错配。

**当前状态**：✅ 已完成；2026-10-14 两镜像同批装配、唯一对外入口、只读内容及安装包私有卷已实现。隔离 Compose 语法／健康、路由与私有路径、真实 Center 模型流与取消、签名文件传输、停机静态访问及重建持久化验证通过。用户已授权自主推进到 M3，未部署真实环境。
