## 三、工程与独立静态内容

### 3.1 同工程的公开入口

官网源码位于 `apps/enterprise-admin/src/site/`，独立 HTML 入口及 Vite 配置，构建至 `dist/site`，
URL base 为 `/`、构建资源固定在 `/site-assets/`。后台继续构建至 `dist/admin`。
共用现有 React、组件依赖和基础样式能力，但官网入口不实例化 AdminStore，不读取后台凭据，
也不加载登录守卫。公开请求使用由 Center OpenAPI 生成的契约，显式不附加后台身份。

官网采用 BrowserRouter：`/`、`/download`、`/changelog`、`/manual`、`/manual/:articleId`。
`/manual` 进入清单指定的第一篇文章；未知文章显示不存在，不以第一篇文章代替。
日志版本定位使用 `/changelog#vX.Y.Z`，文章段落使用 `/manual/:articleId#heading-id`。
已确认 Demo 继续保留 `/site/` Hash 路径，其模拟数据不进入正式构建。

公开布局沿用 Demo 的悬浮／滚动吸顶导航、内容阅读布局和下载分段选择。下载弹窗与 `/download`
复用同一查询和展示组件；正式数据为空或失败时有对应状态，不沿用演示版本或安装按钮假反馈。

### 3.2 仓库内容与公开目录

```text
docs/site/
├── site.json                  # 首页配置、手册目录与公开资源清单
├── home/*.md                  # 首页区块正文
├── manual/*.md                # 一套当前手册
├── assets/                    # 公开图片
└── changelog/vX.Y.Z.md         # 版本日志权威源，单独在版本详情保存
```

静态清单只包含 `format`、`home`、`manual`、`assets`；删除 `release_version` 和 `changelog`。
日志文件留在仓库，但不输出到静态目录。首页仅支持已实现区块；文章带稳定 ID、标题、维护日期与
适用版本，不借内容文件注入 JS、CSS、HTML 或组件。未列入清单的草稿不进入公开输出。

沿用已有受限 Markdown 编译与 React 节点阅读器，将选中内容输出为静态 `content.json` 和图片，
不输出 ZIP。此处构建仅处理内容文件，不重新编译平台程序。输出目录只包含可公开产物，不能放
仓库、开发记录、源配置或临时文件。格式详情随 M0 收敛更新[内容维护说明](../../../../site/README.md)。

M1 沿用六个固定首页区块；标题、简介和 Markdown 来自静态内容，不从 Demo 导入兜底数据。
`workspace` 可选 `scenarios` 是客户端演示的静态投影，严格限制字段、长度、数量和图形种类；
`capabilities` 正文以二级标题分卡，显式标题 ID 对应场景 ID，重排不会错配示意图。
平台选择、导航和图形呈现属于 UI；演示输入／回复等内容归静态目录。格式详见内容维护说明。

### 3.3 固定路径与更新

对外固定地址为 `/site-content/content.json` 和 `/site-content/assets/<内容哈希>.<扩展名>`。
部署配置 `CENTER_SITE_CONTENT_ROOT` 指向独立公开目录；非 Docker 完整模式由 Center 静态路由只读
提供，Docker 由 Nginx 挂载同一职责的只读目录提供。该目录独立于安装包根、快照目录和数据库。
路径只在部署时设置，日常内容更新不改路径，不需要重启或后台重载按钮。

维护者先校验／预览，准备完整 JSON 和图片，再发布到该目录：先写入新的哈希图片，最后原子替换
`content.json`。JSON 的所有正文与目录一次读取；图片名按实际字节哈希生成，旧正文不会引用新图。
静态 JSON 使用 no-cache 重新验证；图片可按不可变资源缓存。更新时保留既有公开图片，确保已打开
的页面继续可读，不在普通内容发布时删除旧图片；清理属于明确的运维动作，不引入自动清理服务。

发布失败时不替换 JSON；恢复时使用仓库中经核对的内容重新输出并替换。可公开的静态文件不绑定
安装包版本，草稿不得复制进此目录。禁止目录列表、点文件、任意路径及软链逃逸；根目录必须由部署
配置指定，不接受请求参数选取系统目录。内容目录缺失与应用构建资源缺失分别处理：前者显示内容
不可用，后者仍拒绝启动不完整产品。

### 3.4 内容安全与本地预览

保留 markdown-it 结构化解析和白名单节点渲染，不手写正则解析器，不使用 dangerouslySetInnerHTML。
支持常用 Markdown，拒绝原始 HTML、脚本、嵌入对象；外链仅 HTTP／HTTPS，服务器不抓取外部资源。
静态图片只支持经类型／尺寸校验的 PNG、JPEG、WebP，不接受 SVG 或远程图片。

校验入口只读清单引用闭包，拒绝绝对路径、父目录跳转、链接文件及大小写冲突。沿用清单／单篇文档
128 KiB、文本合计 2 MiB、单图 5 MiB、尺寸 8192×8192、输出投影 4 MiB 的边界；删除 ZIP 专属限制。
站内手册与段落链接按清单校验；日志版本链接只检查合法形式，不要求静态编译时连接发布数据库。

本地预览复用同一编译结果和阅读器，只监听 loopback，不依赖数据库或真实安装包，不导入后台身份。
前后端不直接跨工程 import 源码；静态节点契约仍由 Center 的契约生成链路输出，运行时不为静态数据
增加一套动态内容接口。M1 本地内容预览已使用同一正式页面入口；禁用真实下载，日志页面明确提示预览不读取中心日志。

## 四、版本详情更新日志

### 4.1 唯一运行时说明

复用 `desktop_releases.notes` 存储 Markdown；仍使用现有说明保存接口、16 KiB UTF-8 上限、
`expected_notes` 冲突保护和 `desktop_release_notes_changed` 审计。不增加正文表、修订号或迁移。
仓库日志文件含版本／日期元信息，版本详情编辑框只保存正文，不粘贴 YAML 头部。

正常发布从仓库复制正文到版本详情，可直接编辑并预览；平台纠错后由维护者回存仓库。
这是人工维护约定，不新增 Git 接入、定时拉取或双向同步。官网与 Desktop 均读取 notes，避免两套说明。
保存即时生效于已发布版本，未发布版本仅管理员可见；不触碰已签名清单和安装文件的不可变约束。

公开与后台预览复用受限 Markdown 编译。现有 notes 可能含不支持的 Markdown，展示时将不支持的
标记当作转义文本，不让一条旧说明使整个列表失败；新编辑预览明确显示最终呈现。拒绝可执行 HTML，
不自动加载正文中的远程图片。保留现有字符串存储与保存契约，不因官网接入改变已发布客户端行为。

### 4.2 公开资格、排序与日期

查询至少一个平台 `first_published_at` 非空的版本，按既有 SemVer 比较倒序；每版只输出一条非空 notes。
日期取平台最早首次发布时间，编辑日志和补平台不改此日期。只含草稿的平台版本不公开，全部撤回
仍保留发布历史和日志。下载资格另行实时查询，不以日志存在保证可下载。

公开投影只包含版本、首次发布日期、受限正文；不返回私有路径、签名内部状态、草稿或管理员信息。
现有版本直接复用说明，空说明略过；没有可展示条目返回空集合。数据库故障返回错误，不能伪装为空。
本版不引入历史日志导入系统；本中心未保存的历史版本不会凭仓库文件自动成为发布记录。

### 4.3 编辑交互与失败

版本详情原“更新说明”改为“更新日志”，提供编辑／预览、保存。说明清楚标注官网与客户端共用。
保留脏稿、离开守卫及旧值核对；冲突时显示当前服务端说明并保留草稿，不自动覆盖。
网络结果不明先重读，确定成功但回读失败不改口为保存失败。发布／撤回保持原确认流程，只补充日志
是否可见的准确说明，不再计算首页或手册的来源影响。

## 六、正式路由与 Docker 同端口分流

### 6.1 交付结构

沿用一个 Center 产品交付包和同一 enterprise-admin 工程。装配同时生成 `public/admin` 与
`public/site`；不复制原型、内容源或服务器内容副本到公开目录。
非 Docker 完整模式由 Center 静态路由提供相同页面白名单；API-only 只用于显式后端开发。

Docker 在同一 Compose 部署内增加 Nginx 入口容器，静态文件随同一次构建装入入口镜像；Center
只在内部网络监听，撤下直接对外 ports。Nginx 独占原 `CENTER_BIND_ADDRESS`／`CENTER_PUBLISHED_PORT`
映射，官网、后台与 `/api/` 共用域名端口。它是产品入口基础设施，不是独立官网应用或另一套内容服务。
入口镜像与 Center 镜像使用同一发布版本及装配产物，一起打包、升级和回滚，不从运行中 Center 拉静态文件。

Center 保持正式资源检查，入口构建也执行相同产物完整性检查；不能将 API-only 当作 Docker 默认
来绕过完整制品要求。Nginx 不挂载任何私有数据卷；只读挂载独立公开内容目录至 `/site-content/`。
安装包根目录继续作为 Center 私有持久卷，原 snapshots、plugins 与模型配置的边界不变。
`CENTER_PUBLIC_ORIGIN` 继续由运维显式设置为对外地址，不从不可信 Host／转发头推断。

### 6.2 location 匹配约定

以下匹配规则已落实到部署配置；Nginx 配置随同批制品打包，并经过隔离容器语法与真实请求验证。

| 优先级／匹配 | 行为 |
| --- | --- |
| `location = /api`、`location ^~ /api/` | `proxy_pass` 到内部 Center，保留完整原 URI；API 错误不拦截成 HTML |
| `location = /admin` | 规范化跳转到 `/admin/` |
| `location ^~ /admin/` | 仅允许入口与构建 assets；Hash 路由不需服务端通配回退；缺失资源 404 |
| `location ^~ /site-content/` | 读取独立公开内容目录，禁止目录列表与点文件；未命中 404，不代理 Center 或回退 HTML |
| `location ^~ /site-assets/` | 只读构建资源，`try_files` 未命中直接 404 |
| `location = /` | 返回官网 `index.html` |
| 精确 `/download`、`/changelog`、`/manual` | 返回同一官网入口 |
| 限定正则 `/manual/[a-z0-9]+(?:-[a-z0-9]+)*` | 返回官网入口；文章是否存在由内容清单判断，未知文章呈现明确 404 视图 |
| 其他路径 | HTTP 404；没有 `location /` 全局代理 Center 或通配 SPA 回退 |

公开文章是 SPA，合法形状但未知文章路径的入口响应可为 200，渲染后显示不存在；不承诺 SSR 的
文章级 HTTP 404。根路径不能吞掉 API 和缺失资源。favicon 等必要根资源逐项列入白名单，禁止
点文件、源码映射、Vite 清单或目录列表公开；不因静态扩展名使用覆盖 `/api/` 的正则 location。

### 6.3 传输、缓存与故障

- `/api/` 保留 Authorization、请求方法、状态码与 Content-Type，使用 HTTP/1.1；流式代理禁用
  响应缓冲与请求缓冲，不缓存 API，不跟随错误页。大安装包上传大小边界兼容现有最多两个
  512 MiB 文件加清单；正文限额仍由各业务入口执行。
- 读取／发送超时按既有模型流、下载及上传约束配置，不能使用短默认值提前截断长任务；浏览器
  中断必须传到 Center 以释放 owner。保留 Upgrade／Connection 条件转发能力，但不声称因此
  新增客户端 WS 路由；当前 Center 的上游 WebSocket 桥接仍由原代理管理。
- HTML 禁止长期缓存；只对带构建哈希的静态资源启用长期缓存。静态内容 JSON 使用 no-cache，带内容哈希的图片可缓存；
  日志查询使用 no-store，下载沿用当前传输语义，不新增 Range 支持。
- 入口补齐原 Center 静态响应的安全头与 CSP：同源脚本、连接和图片，禁止任意 HTML 执行；
  配合既有样式注入实际需求确定样式策略，不把脚本 unsafe-inline 当作默认方案。
- Center 不可用时 Nginx 仍能返回静态框架；静态首页内容与手册仍可读取，下载和日志查询显示失败，管理页显示连接失败。
  `/api/` 返回真实 502／503，不能转换为首页或空列表。
- 数据库、私有卷、Center 与入口镜像是不同恢复对象。入口切换前核对制品和路由；数据库变更
  按独立迁移流程执行，失败停止切换，不以镜像回滚代替数据库回退。
