## 二、目标与非目标

匿名访问企业中心即可了解产品、选择安装包、阅读更新日志和操作手册，并找到管理后台入口。
维护者修改官网内容时，无需修改平台源码、重新构建前端或发布 Center 程序。

官网页面在现有 `apps/enterprise-admin` 工程内实现，与后台共享工程依赖和构建装配流程，
由同一 Center 提供。公开页面有自己的导航和阅读布局，不要求登录，也不进入后台身份恢复流程。
管理员仍通过现有后台管理安装包。

除版本详情的 Markdown 更新日志编辑外，本 Feature 不建设在线内容编辑器、通用 CMS、可拖拽页面搭建、多语言、全文搜索、评论、内容审批流、
定时发布或独立官网服务。内容维护不要求新建远程仓库，也不要求 Center 访问 Git 服务。
Desktop 登录配置和客户端主题仍分别属于 F02、F04。

## 四、公开页面与使用路径

### 4.1 首页

公开首页固定为 `/`，固定提供“下载”“更新日志”“操作手册”和“管理后台”导航。
首屏展示产品名称、一段简明说明和下载入口，随后按独立静态配置展示已实现能力和产品配图。
维护者可以调整文案、图片、已有区块的显示与顺序；新增布局类型或交互能力仍属于平台开发。

首页如展示版本信息，必须读取安装包查询结果；不能以手工文案宣称某版本已经发布。
无可下载版本时仍可了解产品和阅读手册，下载入口明确显示暂无可用安装包。

### 4.2 下载页

建议入口为 `/download`，按当前实际支持的平台和架构列出安装包：Windows x64、Windows ARM64、
macOS Apple Silicon。平台范围来自既有安装包契约，不预设尚未支持的 Linux Desktop 或 Intel Mac。

每个平台独立选取版本号最高、已发布、文件可用且与当前中心企业协议兼容的安装包。
沿用现有版本比较与兼容判定，不能按上传时间或字符串排序判断“最新”。各平台允许对应不同版本。
页面称其为该平台“最新可用版本”，不暗示所有平台同步发布。

展示版本、平台／架构、文件名、大小、发布日期、SHA-256 和安装说明入口。浏览器平台识别只用于
优先展示，不猜测架构，也不自动开始下载；用户始终可以手动选择平台。
下载指向已有 `installer` 用途文件：macOS 为 DMG，Windows 为 MSI，不把 macOS updater 压缩包当成安装包。

点击下载时仍由服务端核对当前发布状态及文件可用性。页面打开后发生撤回或文件丢失时，下载失败
应提示刷新获取当前版本；不静默下载另一个版本。查询失败与确实没有安装包分开展示。
若较新版本不可用而选中较早版本，只称其为最新可用版本；不改写实际版本号或发布事实。

### 4.3 更新日志

入口为 `/changelog`，按软件版本倒序展示本中心曾发布版本的非空 Markdown 更新日志。
版本和日期来自安装包管理的版本身份与首次发布时间，正文来自版本详情保存的 `notes`。
同一版本多平台只展示一条，日期取最早首次发布时间；编辑正文不改发布日期。

日志写法遵循[开发流程规范](../../../../specs/开发流程规范.md#用户向更新日志与操作手册)：
几条用户可感知的新增、改进、修复即可，需要时补升级提醒，不混入开发过程信息。
草稿版本的日志仅供管理员编辑／预览，至少一个平台首次发布后才对外可读。
全部平台撤回后日志保留，下载资格独立变化；较旧版本的日志修改只影响那一条，不切换首页或手册。

每条日志有稳定版本锚点，下载入口读取该版本实际制品状态。没有日志时显示空态，不拿开发文档补齐。
本中心没有的历史版本不虚构记录；现有版本说明直接作为日志展示，无需另传官网包。

### 4.4 操作手册

建议入口为 `/manual`，提供按章节组织的目录、正文与稳定文章链接。文章包含标题、适用产品版本
说明和维护日期。首版维护一套当前手册，可在文章内说明版本差异，不复制每个软件版本的整套手册。

初始内容覆盖安装与启动、企业登录及账号获取、个人／企业模式说明、基础会话与工作空间、
附件与文件、权限确认、插件／智能体入口、更新和常见问题。只描述已有能力，F02 完成前不把
计划中的登录页设置入口写成现有操作；版本联合验收时同步复核。

支持常用 Markdown 标题、段落、列表、表格、代码块、链接和目录中的公开图片。内容不能执行脚本、
原始 HTML、内嵌页面或任意组件。站内文章链接与图片引用纳入静态内容校验；外部文档链接可以存在，
但不由 Center 自动抓取或执行。移动端可折叠目录，代码与表格不撑破正文宽度。

## 五、独立维护与发布

### 5.1 更新日志：版本详情编辑

仓库按版本维护简短 Markdown。管理员在现有版本详情的“更新日志”区域直接编辑、预览并保存，
复用既有说明字段、权限、冲突核对和审计；不要求选择或上传官网 ZIP，不重传安装制品。
已发布版本保存后更新公开日志和客户端说明；未发布版本仍为草稿。
保存失败保留编辑稿，结果未知先回读；不能自动覆盖其他管理员保存的新内容。

### 5.2 首页与手册：固定静态目录

本次选择用户提出的固定静态目录方式，首版不增加独立上传界面。源文件继续在 `docs/site/` 维护，
校验和本地预览后，将选定的公开内容发布到专用目录，由固定 `/site-content/` 地址读取。
目录由部署配置指定，独立于程序镜像、安装包存储及数据库；不直接公开整个仓库或开发文档目录。

维护流程为“修改仓库 → 校验／预览 → 更新静态目录”。无需上传安装包、选择软件版本、修改平台源码、
重新构建应用或重启 Center。首页与手册维护一套当前内容，适用软件版本写在文章内。
发布、撤回或补传任何安装平台均不切换手册；尚未安装任何制品的中心也可提供首页和手册。

先准备完整内容及图片再切换入口，避免逐文件覆盖造成引用缺失；失败保持上一次已发布内容。
恢复时重新部署仓库中经核对的内容。已有页面不强制热更新，刷新或下一次导航读取新内容。
具体静态路径、缓存和资源一致性见技术方案，不增加内容版本数据库、发布审批或重载管理按钮。

### 5.3 空态与故障

静态目录尚未配置或内容缺失时，首页与手册明确显示暂不可用，固定导航、下载、更新日志和后台仍可使用。
日志查询失败与没有日志分开展示。静态内容故障不影响安装包发布和说明保存，安装包管理故障也不阻止
已部署的手册被读取。禁止以 Demo 文案或虚构版本掩盖数据缺失。

## 六、模块边界与权限

### 正式路由与 Docker 同端口分流（2026-10-13 用户确认方向）

正式页面采用明确的路径：`/` 为首页，`/download` 为下载页，`/changelog` 为更新日志，
`/manual` 与 `/manual/:articleId` 为手册入口及文章。公开页面采用路径路由，后台保持现有
`/admin/` 及内部 Hash 路由。具体页面与资源优先匹配，首页只匹配根路径，不作为接口的兜底。

Docker 部署由 Nginx 在同一对外域名、端口下通过 `location` 分流，前端页面和后端接口
共用访问入口；Center 后端位于内部网络，不让域名根路径默认代理到后端。规则按以下边界细化：

| 匹配范围 | 处理方式 |
| --- | --- |
| `/api` 与 `/api/` 前缀 | 明确优先代理 Center 接口，保留原接口路径、鉴权和响应语义，不进入前端页面回退 |
| `/admin` 与 `/admin/` 前缀 | 优先进入现有管理前端，目录入口规范化；静态资源缺失返回资源错误 |
| 官网静态资源前缀 | 精确按构建产物提供资源，缺失返回 404，不返回 HTML 冒充资源 |
| `/download`、`/changelog`、`/manual` 及文章路径 | 匹配公开页面后提供前端入口，支持直接访问、刷新与深链接 |
| 精确 `/` | 返回官网首页，不能返回 API 内容或后端默认页面 |
| 其他路径 | 显示明确的不存在状态；不通配代理后端，也不静默展示首页 |

技术方案应落实 `location` 精确匹配和前缀优先级、页面入口回退、资源缓存与内部 upstream，
复核所有已有接口（含流式响应及升级连接）的传输要求。部署验证覆盖：直接打开域名、刷新文章、
进入后台、访问有效／未知接口及缺失静态资源；后端不可用时首页静态入口仍可访问，接口错误不能
变成首页 HTML。Compose 已由入口独占对外端口，Center 仅在容器网络监听；已在隔离环境验证，未升级真实服务器。

路由要求最初仅记录到方案；正式实现已按后续授权落地 Docker／Nginx，Demo 的 `/site/` Hash 路径保持不变。

### 模块归属

| 模块 | 本 Feature 职责 |
| --- | --- |
| enterprise-admin | 在同一工程增加公开页面；版本详情复用 Markdown 日志编辑与预览 |

前端工程中；是否采用工程内独立入口以及静态装配细节由技术方案确定，不新建前端工程、仓库或独立官网业务服务；Docker 入口 Nginx 属于同一产品部署的分流设施。
公开查询由 Center OpenAPI 描述并生成前端调用代码，不跨工程直接导入服务端源码。

匿名接口只返回公开内容及发布信息，不放开现有管理员列表接口。草稿制品、未接纳内容、账号、
调用正文、文件系统路径和私有配置不得通过官网访问。静态目录只接收经校验的公开产物，
不挂载仓库根目录或任何私有卷，拒绝路径越界及软链逃逸。

更新日志保存使用现有管理员权限和审计；静态内容部署由目录写入权限保护，不提供匿名写入口。
正文按受限格式渲染，公共入口不加载后台凭据处理流程。未知页面和资源返回明确的不存在状态，
不能让官网路由吞掉 `/api/`、`/admin/` 或其他错误。

## 八、验收标准

1. 匿名可访问首页、下载、日志和手册；同工程交付，刷新／深链接及后台入口正常。
2. 官网自动按平台选择最高已发布、文件可用且协议兼容的 installer，无需后台额外选“官网版本”。
   覆盖平台版本不齐、撤回、缺文件、空结果与点击时状态变化。
3. 版本详情直接编辑、预览并保存 Markdown 日志；官网与客户端读取同一说明，冲突或失败保留草稿。
4. 草稿日志不公开，多平台不重复；首次发布后可见，全部撤回后仍可读，下载反映实时可用性。
5. 手册和首页从独立静态目录读取，更新不要求安装包操作或应用重建；安装版本变化不切换手册。
6. 仓库保留权威 Markdown，平台直接修改日志有回存约定；不存在第二份独立官网日志字段。
7. 静态内容校验覆盖引用、大小、非法语法及路径；更新失败不替换有效入口，图文不混用。
8. 内容缺失与服务错误如实展示，互不牵连；不公开草稿、账号、调用正文、私有目录或源码。
9. 手册覆盖初次安装到基本使用的路径，F02 完成后对照真实登录行为复核。
10. 已确认 Demo 视觉保留；桌面、窄屏、长文、代码表格、导航、下载与键盘操作可用。
11. `/` 精确进入官网，Docker 同端口优先分流 API／后台／静态资源，缺失资源不被首页兜底。
