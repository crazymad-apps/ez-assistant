## 四、各里程碑交付与验证

### M0 现有偏好接入与首屏配色

**目标**：建立可以真实保存和恢复的统一主题来源，不依赖业务连接就能确定启动外观。

**交付范围**：

- 按技术方案第三、四节装配预设表、应用级外观 owner 与只读消费入口；连接／身份替换不销毁主题。
- Desktop 在原偏好文档中保存设备级主题，复用布局写锁和安全替换；Web 使用独立主题键，保持原布局保存语义。
- 接入窄原生读写／应用命令，保持受信任主窗口边界；失效值回退、损坏文档保护、保存失败和快速选择按已确认规则执行。
- 按技术方案第五节调整主窗口创建前的外观及前端挂载时序，保留原生配置与窗口状态恢复；补齐退出保存等待、读取超时和迟到结果失效。
- 同步必要模块约束。此步用定向测试及隔离配置验证能力，不新增临时产品开关或隐藏主题设置入口。

**验证入口**：仓库根执行 `cargo fmt --all --check`、
`cargo test -p ez-assistant-desktop desktop_preferences`，并定向执行实际新增的启动／主题测试，
核对过滤器确有匹配用例。在 `apps/desktop` 运行 `npm run test -- <实际新增主题测试路径>`、
`npm run test -- tests/unit/application-connection.test.ts`、`npm run build`；完成
`npm run tauri -- build --no-bundle` 检查原生创建与桥接编译。尖括号为实施时替换的实际文件，不是已有测试。

重点覆盖主题与布局交错保存且互不覆盖、未知／损坏输入、A→B→A、旧读写结果迟到、保存／原生应用
分别失败及 owner 更换。隔离原生窗口验证深色首次展示、窗口位置恢复、关闭／退出和再次打开；
纯状态测试不能证明首帧正确。平台可用范围与未实测部分单独说明。

**完成判定**：统一来源、持久化和启动恢复形成闭环，原布局与身份分区信息保持，失败不误报保存成功；
原生创建路径可运行且不引入等待 Host 的显示门禁。尚未交付外观页和全量组件配色，不宣称四主题可用。

**Review 重点**：主题是否有第二份可写状态，文件是否安全合并，超时是否触发覆盖，原生窗口／托盘／退出
语义是否被改变，是否把 Runtime Home 错当成偏好隔离。

### M1 外观设置与全局界面配色

**目标**：用户能够在现有设置中选择配色，普通界面统一使用全局语义色。

**交付范围**：

- 接入“设置 → 外观”的四张静态预览卡、单选键盘路径、保存范围与失败重试；使用当前主题绘制选中和焦点，不创建预览编辑器或终端。
- 将固定文字、背景、边框、焦点、状态、阴影和有效 fallback 转为现有或确有必要的语义角色；颜色集中在预设中，非颜色 Token 保持原职责。
- 左侧栏直接继承全局文字变量；保留既有 hover／选中结构及 macOS 材质，按主题调整覆盖色。
- 覆盖会话、输入区、列表、设置、菜单／弹窗、登录装饰及 HTML 主题色；亮色主按钮使用配套文字色。
- 图标明暗变体消费当前主题。沿用 F02 的非工作区设置限制与登录选项最终行为，不以恢复主题为由重新挂载完整设置。

**验证入口**：Desktop 执行
`npm run test -- tests/unit/settings-dialog.test.tsx tests/unit/application-connection.test.ts`，
补充外观页的用户操作与失败重试测试，再运行 `npm run lint`、`npm run build`。
在真实页面检查四套主题、单选焦点、保存反馈、窄屏和缩放；检查登录、左侧栏与浮层的实际混合背景。
重新搜索固定色并逐项判断剩余用途，不能以搜索结果为零替代视觉检查。

**完成判定**：选择、即时应用、保存与重试有完整用户路径，普通 UI 在四套主题下可读且入口边界正确；
关闭设置不取消保存或丢失失败状态。代码、图表和终端专用配色尚待 M2，不将它们混记为已验收。

**Review 重点**：是否又产生局部固定色覆盖；是否仅改背景导致按钮文字、辅助文字或焦点不可见；
切换是否影响未保存表单、草稿及连接 owner；F02 最新界面是否遗漏。

### M2 代码、图表与终端联动

**目标**：让应用内内容渲染器遵循同一选择，更新外观时保持内容、实例与操作状态。

**交付范围**：

- 按技术方案第六节接入 Streamdown 实际代码插件主题；公共 MarkdownContent 通过只读参数消费，逐个核对工作区内外调用方。
- 高亮与 Mermaid 异步结果按当前内容和主题失效，图表私有串行渲染不扩大为业务队列；保留解析失败的可读回退与既有内容安全处理。
- Monaco 注册四套有限映射，加载后取当前主题，在现有实例中切换；xterm 复用既有变量监听与主题更新，不重建终端、连接或进程。
- 保留图片、PDF、网页及用户显式颜色内容；第三方网页自身响应原生明暗的限制按技术方案说明。
- 在现有许可证分发入口保留主题来源与实际采用依赖声明，不新增主题导入器或并行渲染框架。

**验证入口**：Desktop 执行
`npm run test -- tests/unit/markdown-content.test.tsx tests/unit/resource-workspace.test.tsx tests/unit/terminal-controller.test.ts`，
并运行新增渲染器主题行为测试、`npm run lint`、`npm run build`。
定向测试用可控异步完成顺序覆盖旧主题／旧流片段、未知语言、图表失败、加载中切换与卸载；
真实页面验证流式 Markdown、隐藏后恢复的资源标签、终端历史／选区和代码查看位置。

**完成判定**：最终选择决定各渲染器外观，旧结果不反向覆盖，切换不清空内容或丢失编辑／选择／滚动状态；
终端没有额外重连，安全链接、媒体和原有复制行为保持。不能只根据背景色或主题名称断言通过。

**Review 重点**：插件是否真正消费指定主题，异步保护是否同时覆盖文本与主题，Mermaid 全局状态是否串色，
Monaco／xterm 是否被无必要重建，公共组件是否反向依赖业务 Store。

人工验收重点：

1. 在“设置 → 外观”依次选择四套配色，确认文字、左侧栏、焦点、弹窗和选中项的实际观感。
2. 在样例会话切换 Markdown、代码与终端标签，再切换主题，确认内容、阅读位置和终端历史保持。
3. 退出重开并返回首页，确认保存的配色恢复，登录选项与工作区使用同一选择。
4. 确认是否接受下述平台缺口，或在相应设备补验后再确认 Feature；本机通过不代表版本发布门禁通过。

尚未实测：Windows／Linux 原生 WebView，系统明暗交叉与减少透明度设置，安装更新后的重开链路。
macOS 材质会受系统背景与窗口激活状态影响，颜色不承诺逐像素等同于浏览器实色。
F02 登录选项已纳入本机配色检查；F01 官网与 F03 企业后台不消费 Desktop 主题，联合版本验收仍按各自边界执行。
