# v0.31.0 F04 功能设计：整套配色切换

- 需求来源：2026-10-13 用户要求开始 F04 设计；四套预设与统一切换方向来自
  [整套配色输入](../../../../inputs/260905-整套配色主题预设与切换方案.md)。
- 上位依据：[总体设计](../../总体设计.md)的 F04、客户端展示偏好边界及跨 Feature 验收；
  按已确认总体方向实施，不改变其他 Feature 的边界。
- 影响模块：Desktop／Host Web 共用界面、设置、Markdown、资源查看器、终端及客户端展示偏好；

分别归技术方案与界面交互设计指导；实施里程碑与当前结论统一维护在开发计划中。

## 二、背景、目标与非目标

当前工作台以浅色语义变量为基础，但 Markdown、代码查看器、终端、登录背景和原生窗口各有
自己的配色来源。只调整页面底色会留下浅色代码块、侧栏文字和不协调的弹窗，无法形成完整主题。

目标是一个“配色方案”选择同时覆盖应用界面、代码与终端。用户选择后即时看到结果，下次打开
客户端自动恢复；正在输入、阅读和执行的任务不受影响。主题明暗由预设决定，不再组合独立的
浅色／深色开关或强调色。

本 Feature 不包含主题导入、主题市场、任意色值编辑、系统自动切换、跨设备账号同步、字体与
字号调整、界面布局改版或新增终端能力；不修改 Shell 配置、第三方网页及文档内容本身的颜色。

## 四、预设、入口与使用路径

### 4.1 四套完整预设

| 名称 | 明暗 | 用户可见结果 |
| --- | --- | --- |
| 默认浅色 | 浅色 | 保留当前浅色外观及蓝色交互方向，补齐统一代码和终端配色 |
| Monokai | 深色 | 深色工作台，搭配 Monokai 风格语法色与协调的交互、状态和终端颜色 |
| Solarized Light | 浅色 | 暖浅色背景，整套界面、代码与终端采用协调的 Solarized 浅色配色 |
| Solarized Dark | 深色 | 深青色背景，整套界面、代码与终端采用协调的 Solarized 深色配色 |

“默认浅色”是新安装、缺失偏好和无效主题的回退。系统外观变化不会覆盖已选主题，登录装饰也
遵守同一选择。具体色值和主题资源来源已在技术方案中确定，实施沿用已核查的依赖许可并补齐产品状态色。

### 4.2 设置入口与预览

工作区内进入“设置 → 外观 → 配色方案”。Desktop 与 Host Web 都提供此入口，不要求 Host
管理员权限。页面说明保存范围：Desktop 为“仅此桌面客户端”，Web 为“仅此浏览器的当前站点”。

四个选项以同构预览卡呈现，预览包含界面底色、侧栏、普通文字、交互色和简短代码色；同时显示
名称及浅色／深色说明，选中态有明确文字或标记，不能仅依靠颜色区别。预览使用内置样例，无需
打开真实文件、连接终端或发起模型调用。

点击选项或用键盘确认后立即切换并自动保存，无额外“应用”按钮。卡片悬停只表达可点击，不临时
改变全局主题。关闭设置保留已选择结果；选择“默认浅色”即恢复默认，不新增重置流程。

完整设置入口遵守 [F02 功能设计](../F02-登录选项设置/功能设计.md)：登录页、初始化失败或断线
退回首页时沿用当前主题，但不因此重新开放完整设置；F02 登录选项弹窗只编辑其原有配置。

### 4.3 生效与保存反馈

- 正常选择：预览卡立即标记当前主题，各区域同步更新；保存完成后可显示简短“已保存”反馈。
- 保存中继续选择：以最后一次选择作为最终结果；较早的完成或失败反馈不能覆盖新选择。
- 保存失败：保留本次已应用配色，明确提示“已应用，本次未保存；下次打开可能恢复之前的配色”，
  提供重试。不能显示已保存，也不能因关闭设置静默撤销用户当前看到的配色。
- 重试：保存当前选择；用户已选新主题时不重试旧值。成功后清除未保存提示。
- 偏好缺失：直接使用默认浅色，不作错误提示。主题标识无效时回退默认浅色并给出一次可理解的提示。
- 偏好读取失败或浏览器禁用存储：默认浅色仍可进入应用，本次运行允许切换；提示无法恢复／保存，
  不阻塞登录和使用，不以恢复默认为理由覆盖其他未读出的偏好内容。

## 五、覆盖范围与状态保持

| 区域 | 本次覆盖与边界 |
| --- | --- |
| 启动与登录 | 应用拥有的启动背景、连接与登录页面、品牌文字、点阵／静态背景、F02 登录选项及错误提示 |
| 工作台 | 会话侧栏、标题栏、中栏、右侧资源区、分割线、空态与加载态；保持原信息结构和尺寸 |
| 控件与浮层 | 按钮、字段、焦点、选中／悬停／禁用态、菜单、弹窗、提示、通知及审批／问答区 |
| 会话 | 用户与助手消息、引用、链接、工具卡、推理与子任务视图、状态和用量提示 |
| Markdown | 正文、表格、引用、行内代码、代码块背景和语法色、复制按钮；数学文字和默认 Mermaid 图保持可读 |
| 代码查看器 | 编辑区、行号、选区、搜索结果、折叠与内置菜单；同一主题在 Markdown 与 Monaco 中保持一致的配色方向 |
| 终端 | 背景、默认文字、光标、选区、标准与亮色 ANSI 色；已有和新建终端都读取同一预设 |
| 原生与资源外围 | 应用窗口背景、可控窗口外观、macOS 侧栏材质与文字、文件图标明暗版本、资源工具栏和加载／失败状态 |

不同语法引擎对 token 的分类可能不同，不要求每个字符逐像素相同，但不能出现同一方案中一处
采用默认浅色、另一处采用所选深色的混用。语法高亮尚未加载或失败时，代码仍以当前主题的
可读普通文字呈现，不丢失内容或改用不可读配色。

终端内应用显式指定的 RGB／扩展颜色及 Shell 自有提示符按原输出呈现；不通过改写输出或修改
Shell 主题来强制统一。图片、PDF 页面、第三方网页和用户显式指定颜色的内容保持原色，外围容器
跟随主题；不对整页使用反色滤镜。应用默认生成的 Mermaid 图可适配，作者显式样式不被悄悄重写。

切换只改变外观。会话、Run、网络连接、资源身份、标签顺序与激活项、输入草稿、焦点和滚动位置
保持；Monaco 模型、搜索与阅读位置保持；终端进程、连接、缓冲、选区与输入保持。允许渲染器为
颜色重新绘制，不允许通过重载应用或关闭重开资源来完成切换。隐藏标签在再次显示前应用当前主题，
流式追加内容和切换后新开的资源同样使用当前选择。

原生窗口与应用主题的明暗一致；平台不能提供指定材质时使用可读的实色回退。系统拥有的文件
对话框、菜单、通知等遵守系统能力边界，不承诺四套自定义色值完整接管系统 UI。默认浅色保持现有
视觉方向，必要的对比度修正不作为界面改版。

## 六、偏好归属、启动与模块契约

### 6.1 保存范围

| 客户端 | 保存与恢复范围 | 切换身份／连接时 |
| --- | --- | --- |
| Desktop | 当前应用配置目录中的设备展示偏好；开发与正式应用继续按现有配置隔离 | 本机／远程 Host、个人／企业账号和中心切换都保留同一选择；重启桌面客户端后恢复 |
| Host Web | 当前浏览器配置文件、当前 origin 下的展示偏好 | 同源退出再登录仍保留；不同浏览器、设备、端口或协议可有不同选择；清除站点存储后恢复默认 |

Desktop 复用 `desktop-preferences.json`，但主题是文件内的一份设备级事实，不能跟随各 Host／
用户视图快照复制。保存主题不能覆盖既有布局、资源恢复索引和设备默认；其他偏好保存也不能用
旧快照覆盖新主题。确切字段位置与原生读写接口由技术方案确定。

Web 复用现有无用户数据的展示偏好存储，只新增主题选择；不引入账号标识或资源信息。
浏览器存储不可用时降级为当前页面有效；隐私模式的实际保留期由浏览器决定，不承诺跨隐私会话恢复。
本版不增加跨标签实时同步能力；已打开页面保持各自当前主题，刷新／重新打开读取最近成功保存值。
同源标签保存其他布局时不得将未修改的旧主题回写覆盖，具体处理归技术方案。

主题不上传 Center 或 Runtime，不写入业务数据库、Session、Run、模型配置及共享应用协议；
连接远端 Host 也只修改当前客户端。Host Web 复用前端构建即可获得主题能力，不新增主题服务。

### 6.2 启动与失败恢复

已保存主题在应用首次展示主体内容前恢复，覆盖启动、登录、工作区及原生窗口可控背景，避免
先展示整屏默认浅色再跳到深色。偏好恢复不依赖 Host 在线、认证成功或业务初始化完成；读取失败
可明确回退，不能无限等待或导致空白窗口。具体启动时序、失败边界与系统绘制的首帧限制在技术
方案中说明，实际平台核验后如实报告。

退出账号、Host 断线、连接重试和工作区重建不清空主题。清除账号数据与恢复客户端外观是不同
动作；本 Feature 不增加清理数据入口。

### 6.3 模块与兼容

- 共用前端负责单一当前选择、主题应用、预览、提示及渲染器联动；沿用现有状态与组件组织方式。
- 原生层只承担应用偏好和可控窗口外观，不管理业务主题配置，不重启 Host。
- Runtime、Center、Agent 执行与共享协议没有新增主题权威状态。
- F02 提供最终登录界面，F04 负责配色覆盖；F01 官网及后台继续维护自身样式，不读取此偏好。

旧偏好没有主题字段时默认浅色；未知标识局部回退，不因一个主题值无效而丢弃全部视图记录。
本次预计只需扩展客户端展示偏好，不提升企业协议或业务存储兼容下限。技术方案仍须核查已发布
偏好格式与旧客户端重写文件的行为，说明降级可能丢失新主题选择的边界；不默认增加双写文件、
主题别名、迁移版本或历史主题兼容服务。

## 七、验收标准

1. Desktop 与 Host Web 的工作区设置均可访问四个预设，名称、预览、明暗说明、选中态和键盘操作完整。
2. 每个选择一次覆盖工作台、控件、消息、Markdown、代码查看器和已有终端；当前不可用的客户端能力
   不因主题新增入口，Web 不为验收额外获得 Desktop 专属资源能力。
3. 默认浅色保留现有视觉方向；四套主题的常规、悬停、焦点、选中、禁用、错误、警告与成功状态可辨；
   状态同时有文字或图形线索。常规正文与底色对比度目标不低于 4.5:1，关键控件边界与焦点目标不低于 3:1。
4. Markdown 长消息、流式追加、代码高亮延迟加载及失败回退可读；默认数学和图表显示正常，作者显式色与媒体保持原意。
5. Monaco 已打开、后台隐藏和切换后新建实例均使用当前主题，模型、查找、选区与阅读位置保持。
6. 活跃终端切换后无重建进程、断连、丢输出或丢输入，选区与滚动保持；ANSI、亮色及显式 RGB 输出
   按约定呈现，使用正式 CSP 的 Release WebView 验证。
7. 正在执行的 Run、会话选择、草稿、弹窗表单及资源标签状态不因主题选择变化；无需刷新或重启。
8. Desktop 冷启动、重开、退出登录、本机／远程连接及账号切换保留设备主题；F02 首页、品牌行和
   登录选项正确配色，首页仍不能唤起完整设置。
9. Web 同源刷新与重新登录恢复；不同 origin／浏览器独立；禁用或清除存储、已打开多标签的表现与第五、六节一致。
10. 快速连续选择以最后一次为准，旧保存反馈不覆盖新状态；主题保存与布局／资源偏好保存互不覆盖。
11. 保存失败能区分“已应用”和“已保存”，可重试当前选择；关闭设置后外观不回退，失败不被误报成功。
12. 缺失、未知主题和偏好读取失败分别按约定回退；不丢弃或覆盖其他有效偏好，不阻塞应用进入。
13. 四套主题与系统浅／深外观交叉检查，系统变化不改选择；启动无应用主体先浅后深的闪色，
    macOS 材质及 Windows 窗口控件可读，能力不足时回退明确。
14. 图片、PDF、第三方网页保持内容原色，外围工具栏及失败态跟随主题；文件图标在浅深背景均可识别。
15. 不产生 Runtime／Center 配置、业务数据库或会话记录变化；Desktop 账号隔离、Web 存储边界及 F02 设置限制保持。

验证按风险覆盖四套主题与代表性页面；平台实测、启动首帧、终端和连续保存故障不能以构建通过
替代。测试使用隔离的应用偏好与场景，Runtime 场景按仓库要求在 `.runtime-test/` 新建，
不修改真实用户偏好或运行数据。未实测的平台或系统原生限制如实报告。

## 八、后续设计与确认取舍
