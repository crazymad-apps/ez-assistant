## 二、设置入口与布局

在工作区的“设置”导航中，将“外观”置于“通知”之前。登录及其他非工作区阶段继续遵守
F02 的设置入口限制；这些界面继承已保存配色，不额外增加主题入口。

复用 SettingsDialog 与 SettingsPageContainer。页标题为“外观”，唯一设置项为“配色方案”，
不新增头部副标题、保存按钮、应用按钮或恢复默认按钮；选择“默认浅色”即恢复默认方案。

```text
设置                                                 关闭
┌────────────┬───────────────────────────────────────────┐
│ 外观       │ 外观                                      │
│ 通知       │                                           │
│ …          │ 配色方案                                  │
│            │ ┌────────────────┐ ┌────────────────┐    │
│            │ │ 固定配色预览   │ │ 固定配色预览   │    │
│            │ │ ● 默认浅色     │ │ ○ Monokai      │    │
│            │ └────────────────┘ └────────────────┘    │
│            │ ┌────────────────┐ ┌────────────────┐    │
│            │ │ 固定配色预览   │ │ 固定配色预览   │    │
│            │ │ ○ Solarized    │ │ ○ Solarized    │    │
│            │ │   Light        │ │   Dark         │    │
│            │ └────────────────┘ └────────────────┘    │
│            │ 仅此桌面客户端                            │
│            │ 保存反馈                                  │
└────────────┴───────────────────────────────────────────┘
```

- 顺序固定为默认浅色、Monokai、Solarized Light、Solarized Dark，按行排列。
- 卡片包含约 16:9 的静态工作台缩略预览及下方名称。示意内容相同，仅颜色不同；不创建真正的编辑器、终端或会话，也不展示用户内容。
- 卡片外围、名称、选中标记与焦点使用**当前应用主题**；只有缩略预览使用所代表的候选主题，避免未选卡片的亮色被误认为选中状态。
- 选中项以单选标记与外边框同时表示；键盘焦点另有带间隔的轮廓，不靠颜色单独区分。
- 内容区域可用宽度不小于 440px 时两列，间距 12px；不足时一列。主题名称可自然换行，不省略成无法区分的 “Solarized…”；卡片高度随同一行最高内容对齐。
- 沿用现有设置弹窗的桌面尺寸及 760px／560px 响应式布局。560px 以下导航横向滚动；外观页只用既有内容滚动区，不增加卡片内部滚动。
- 字体沿用客户端 Inter／系统中文字体，文字以现有 12／14／16px 层级为准；控件与容器复用现有圆角和间距变量，不另建视觉系统。

保存范围在选项下方只显示一行：Desktop 为“仅此桌面客户端”，Web 为“仅此浏览器的当前站点”。
不向用户展示存储键、路径、账号分区或运行进程等实现细节。

## 三、操作与反馈

### 3.1 选择与键盘

点击卡片或单选控件立即应用并自动保存，不先弹预览、不要求二次确认。悬停只显示可点击状态，
不切换主题；重复点击已经保存的当前项不额外发起保存。

使用原生 radio 组语义，以“配色方案”为可访问名称，每个候选有完整名称。Tab 进入单选组，
方向键在候选间移动并选择，Space 选择当前焦点项；切换配色不重建控件、不丢失键盘焦点。
关闭与 Escape 沿用设置弹窗既有行为。缩略预览作为装饰对读屏隐藏，读屏读取名称、选中及保存状态。

### 3.2 保存状态

| 状态 | 呈现与行为 |
| --- | --- |
| 已保存 | 当前项保持选中；静止状态不长期显示成功横幅 |
| 保存中 | 在选项下方显示“正在保存…”，允许继续选择其他方案 |
| 保存成功 | 可短暂显示“已保存”后消失；不使用全局 Toast 连续刷屏 |
| 保存失败 | 保持当前配色及选中项，显示“已应用，未保存。下次打开可能恢复之前的配色。”及“重试” |
| 重试 | 保存当前所选值，原位显示保存状态；不跳回之前的主题 |
| 连续快速切换 | 只展示最终选择对应的状态，旧请求成功或失败不覆盖当前反馈 |

保存状态区域保留一行高度；错误允许自然换行，不裁切重试按钮。普通保存状态使用礼貌播报，
错误不抢走焦点。颜色变化直接生效，不对全页做渐变动画或先闪回浅色。

关闭设置不会取消已开始的保存，也不因主题保存失败弹出“放弃修改”。重新打开时仍能看到当前
未保存状态并重试。主题选择不是表单草稿；从其他有未保存表单的设置页切入外观时，沿用原页面
既有离开确认，不绕过其他页面的数据保护。

### 3.3 恢复与平台反馈

- 启动按技术方案恢复已保存主题。未知值采用默认浅色；读取失败使用默认浅色并给一次简短提示，外观页可显示相关恢复状态，不阻止进入应用。
- Web 无法保存时保持本页有效，沿用上面的保存失败反馈；不引导用户修改浏览器内部选项。
- 原生窗口适配失败与偏好保存失败分开表达：偏好已保存时，不误报“未保存”；可显示“配色已保存，窗口外观未更新。”并提供重试。
- 系统明暗变化不替用户改选主题。Desktop 和 Web 的原生可控范围继续以技术方案为准。

## 四、四套主题的视觉基准

以下是应用语义色基准，统一预设为实际配置源。2026-10-13 用户反馈默认主题边框过深后，
默认浅色恢复 F04 前已有全局配色，包括边框、辅助文字、强调色和状态色；经典主题保留各自色调，
不要求逐色复制其编辑器原始配置。

| 语义 | 默认浅色 | Monokai | Solarized Light | Solarized Dark |
| --- | --- | --- | --- | --- |
| 主背景 | `#ffffff` | `#272822` | `#fdf6e3` | `#002b36` |
| 面板背景 | `#f8f9fb` | `#1e1f1c` | `#eee8d5` | `#073642` |
| 弱背景／选中底色 | `#f1f3f6` | `#3e3d32` | `#e4ddc8` | `#0b4250` |
| 正文 | `#252932` | `#f8f8f2` | `#52686f` | `#b2c2c3` |
| 次级文字 | `#5f6673` | `#c5c3b4` | `#52686f` | `#9db3b7` |
| 辅助文字 | `#9299a6` | `#aaa89a` | `#52686f` | `#94adb1` |
| 主按钮／强调色 | `#496cf2` | `#a6e22e` | `#806c3a` | `#67b7e6` |
| 主按钮文字 | `#ffffff` | `#272822` | `#ffffff` | `#002b36` |
| 焦点轮廓 | `#3551b7` | `#a6e22e` | `#806c3a` | `#67b7e6` |
| 成功 | `#249d65` | `#a6e22e` | `#4c6800` | `#a3b83c` |
| 警告 | `#cc7b12` | `#e6db74` | `#805b00` | `#d9ad4a` |
| 错误 | `#d14d4d` | `#ff7096` | `#b3312d` | `#f08075` |

默认浅色普通边框为 `#e2e5eb`，强调边框为 `#d3d8e1`；输入框、卡片与分隔线按既有语义引用，
不能用辅助文字颜色替代边框颜色。左侧导航栏背景仍为 `#f7f8fa`。

Solarized Light 按人工反馈采用低饱和深芥黄色强调色 `#806c3a`，悬停为 `#705e32`，
强调文字为 `#75612f`，浅强调底色为 `#eee4c8`。普通边框为暖灰 `#e2dbc7`，输入框与弹层强调边框为 `#d5ccb6`；
导航、按钮、焦点、登录点阵与终端选区共用该方向。成功状态、代码语法和 ANSI 颜色继续保持各自语义。

Solarized Light 的文字层级优先通过字号、字重与位置区分，避免为制造灰阶而降低小字可读性。
亮色按钮的文字从统一前景角色取值，尤其 Monokai 不保留固定白字。状态始终结合图标和文案，
选中、警告、错误均不能仅靠颜色识别。

上表不是另一个主题运行时配置源。实现时集中进入技术方案约定的预设表，派生边框、遮罩、hover、
选区及终端角色；组件只引用全局语义变量。预览文件是评审材料，不从中读取产品配置。

### 4.1 左侧栏

这里指工作区／会话列表所在的**左侧导航栏**。移除它对 `--ez-text-secondary` 和
`--ez-text-muted` 的固定颜色重定义，直接继承全局变量；标题、列表和底部入口与其他区域共用语义。
无需侧栏专用主题表、单独选择或额外同步逻辑。

macOS 透明材质保留现有能力。验收时检查明暗桌面背景下的文字；若混合后的对比度不足，优先调整
背景覆盖强度或整体预设，不重新添加固定浅色文字覆盖。Windows／Web 的实体背景仍使用同一组语义色。

### 4.2 内容与特殊表面

- 会话正文、工具卡片、菜单、弹窗、输入框、提示和禁用态统一引用语义色；遮罩采用各主题适合的透明度，不把遮罩黑色机械替换成正文色。
- 登录页继续沿用 F02 结构和现有装饰，只切换背景、文字、边框及按钮；Logo 不重新设计。
- Markdown 代码、Monaco、终端随方案联动，字体及交互不变。语法引擎各自映射，不承诺每个 token 逐字符同色。
- Mermaid 图表使用当前背景、文字、边界与语义强调；深色背景下不能残留浅色硬底。
- 终端默认前景、背景及 ANSI 调色板随主题变化；进程输出指定的 truecolor 不强制重写，历史内容和选区保留。
- 图片、视频、PDF、用户 SVG、网页内容和文件品牌图标不统一反色。图标明暗变体按已有库能力切换。
- 掩码中的黑白保留其遮罩含义；原生关闭按钮的危险悬停色保留平台语义，不机械替换为主题主色。

### 4.3 可读性与视觉验收

普通文字在实际承载背景上以 4.5:1 为最低目标，焦点、必要控件边界与状态图形以 3:1 为最低目标。
纯装饰分隔线可弱于控件边界；输入框不能只依靠低对比装饰线识别，需使用合适的强边界角色。
禁用控件仍须可辨认，并与可操作控件区分。

预览采用实体色样，仅证明设计方向。透明侧栏、遮罩混合、选中／悬停、小字号、语法色和平台原生
表面必须在实现后检查；不能用色板计算代替真实页面验收。统一变量只消除颜色来源分叉，不自动保证所有搭配可读。

## 五、状态保持与验收重点

主题切换只改变外观，不清空输入、不滚动会话、不切换资源标签，不重建 Monaco 或终端。
代码和图表异步更新期间保留可读内容；最后一次选择生效后，不出现旧主题结果反向覆盖。
不新增整页 loading、强制刷新或主题专用转场。

| 检查面 | 通过表现 |
| --- | --- |
| 外观设置 | 四项、完整名称、选择标记、焦点与窄屏滚动清晰 |
| 键盘与读屏 | 单选组路径正确，主题切换后焦点保留，状态可获知 |
| 全局一致 | 四套主题覆盖左侧栏、会话、代码、终端、菜单／弹窗与登录 |
| 内容保持 | 草稿、滚动位置、编辑器修改及终端状态持续存在 |
| 连续选择及失败 | 最后一次选择为准，保存失败留在当前方案，重试可用 |
| 启动与身份切换 | 恢复已保存主题，切换 Host／账号不回到另一套配色 |
| 平台限制 | 实际检查原生首屏、透明材质及 Web 存储；未实测项明确保留 |
