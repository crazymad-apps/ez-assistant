## 二、页面与入口

### 2.1 调用列表

沿用 `/calls`、现有筛选和服务端分页。保留“转发结果”，增加独立的“响应观察”列与枚举筛选：
观察中、响应正常结束、响应异常、结果未确认；历史空值显示“历史未记录”，不填成正常。
“请求 / 响应快照”继续各自显示状态；有上游失败帧时增加简短“有失败帧”文字，不在列表加载正文。

顶部现有采集提示按当前策略显示“正文留存：关闭／仅异常与未确认／全部调用”，旁边复用“记录策略”入口。
历史行状态以当时记录为准，不随当前策略重标。详情操作继续固定在右侧并居中，按钮用 small 尺寸。
查询参数随进入详情及返回列表保留；新增观察筛选与既有查询一起提交，清空筛选返回全部结果。

### 2.2 调用详情

沿用 `/calls/:id`，标题仍为“调用详情”，右侧保留“刷新”和“返回列表”。进入时只读取详情元数据；
正文区先展示两侧状态与“查看正文”。没有任何可读取快照时不提供无效的查看操作，直接说明缺失原因。
请求／响应均不可用但存在失败帧时，仍提供独立的“查看上游失败帧”入口。

不增加实时监控页、事件回放、逐 token 播放或从此页重新执行请求的入口。

## 三、布局与信息层级

### 3.1 两栏正文区

```text
调用详情                                      刷新   返回列表
调用标识 / 用户 / 模型 / 类型 / 起止时间 / 用量
转发：完成 · HTTP 200    响应：异常    请求：完整 / 响应：部分

正文与事件                                     查看正文 / 收起正文
┌──────────────────────┬────────────────────────────────┐
│ 请求消息              │ 响应过程                       │
│ 完整 · 本次实际发送    │ 部分 · 连接中断                │
│                      │                                │
│ developer  …         │ ○ 响应已建立                   │
│ user       …         │ │                              │
│ assistant  …         │ ○ 推理摘要          展开        │
│ tool       …         │ │                              │
│                      │ ○ 输出文本          未完成      │
│ 模型参数与工具定义 ▸  │   已收到的可读文本……           │
│ 请求原文 ▸           │   查看聚合来源 ▸               │
│ 快照信息 ▸           │ │                              │
│                      │ ! 连接中断 · 原因未确认         │
│                      │ 响应原文 ▸  快照信息 ▸         │
└──────────────────────┴────────────────────────────────┘
```

此结构示意包含可能出现的角色和事件，不要求每次调用都有这些节点；以实际快照生成界面。

可用正文宽度达到 900px 时使用约 40%／60% 双栏；不足时改为“请求消息 → 响应过程”的上下布局。
判断正文容器宽度，不依赖整个屏幕宽度。两栏顶部对齐，不用请求侧空白填充说明卡片。
阅读正文沿用详情页的主滚动，不增加双栏同步滚动或两套固定高度滚动区；原文查看区可有独立有界滚动。
不做拖拽分栏或持久化布局偏好。

### 3.2 信息优先级

1. 调用概况保留用户、模型、时间和已有用量；状态用“转发”“响应观察”“快照”明确命名。
2. 正文两侧标题下各显示自己的保存状态；不将两侧合成一个模糊的“调用完整”。
3. 消息与聚合内容承载阅读主体。生命周期节点保持紧凑，错误原因在节点外层可见。
4. 原始事件、SHA-256、字节数、媒体类型和链路来源放在就近折叠区；历史来源未知如实显示。

默认不自动跳到错误、不抢键盘焦点。已解析且能确定原文位置时，在响应摘要旁提供“定位首个异常”；
点击后展开到该节点、补齐到该位置的必要视图并定位，保持请求侧状态。不能确定位置时不提供定位按钮，
将已知终止原因放在流程尾部，不猜测对应的事件编号。

## 四、消息、事件与原文阅读

### 4.1 请求消息

消息按原请求顺序纵向展示为紧凑卡片，角色使用清晰文字标识，不套用左右聊天气泡暗示真实对话界面。
卡片头部集中角色、工具名及关联信息，右侧提供“原文”展开入口；默认不重复显示“请求 JSON”来源行。
卡片间距收紧，正文直接接在头部下方；关联缺失与异常提示保持可见，原文按需展开完整请求上下文。
短文本直接展示；长指令、历史消息、工具结果使用有标识的预览及“展开内容”，不通过无提示裁剪隐藏正文。
Responses 的独立 `instructions` 作为“系统提示词”区块，与消息角色区分。

工具调用显示工具名和 call ID，工具结果显示关联 ID；本次缺少对应项时标“本次请求中未包含关联项”，
不能判定整个会话缺失。历史续接引用单列“本次含历史引用，仅展示实际发送的增量”，ID 可展开查看。
模型参数与工具定义独立折叠；图片／文件显示引用摘要，加密项仅显示类型与可用原文入口。

若整个请求 JSON 无法解析，消息区显示“请求正文无法完整解析”及已有位置线索，切换为安全原文阅读。
不展示经猜测修复的消息列表；位置无法确定时不伪造行号或列号。

### 4.2 响应流程与聚合卡片

流程轴只表示接收内容的顺序，节点长度随内容变化，不表示时间。节点使用中文语义标题，原事件类型作次要标识。
一个内容块标题最多显示类型、局部完成状态和“聚合 N 条增量事件”；N 不称为 chunk 数或 token 数。

- **生命周期**：响应建立、输出项建立及结束等节点紧凑展示，事件原文折叠；缺少某事件时不补画。
- **文本输出**：聚合正文默认可读，超过预览范围后提供展开；同一输出项被其他事件打断后再次出现时标“续段”，保持实际顺序。
- **推理／摘要**：默认短预览，可展开实际返回内容；未返回不显示空的推理节点。
- **工具调用请求**：显示工具名、call ID、参数是否生成完整。完整合法 JSON 可缩进展示；未完成／非法参数保留文本。
  只称“工具调用请求”，不使用执行成功、运行时长或完成打勾暗示工具已执行。
- **未知事件**：保留类型与折叠原文，不让整页失败；合法扩展事件不用错误色。
- **心跳／注释**：合并到来源信息，不绘制大量空节点，不计入文本增量数量。

同一内容的完成快照一致时，只更新完成标记并将完成事件保留在来源中，不重复显示整段回答。
合法的终态补足标“由结束事件补全”；若值冲突，节点默认展开“增量内容／结束事件内容”两份值及冲突提示。
相同增量文字不据此删除；聚合规则仍以技术方案为准。

非流式 JSON 显示“响应对象”及真实输出项；compact 显示压缩结果项，input_tokens 显示计量对象。
这些场景不生成模拟的创建／增量事件或逐步动画。

### 4.3 来源与原文

“查看聚合来源”在卡片内展开，显示原事件类型、局部事件序号和原文范围，顺序与快照一致。
格式化内容标“结构化展示”，未经改写的字符串标“原文”，不能把重新序列化的 JSON 称为原始字节。
坏帧的原文直接可展开；查看失败不会收起已经读到的正常内容。

原文默认自动换行，保留换行开关。长行关闭换行后只在原文区域横向滚动，不撑宽整个页面。
文本、工具参数、HTML 错误页均作为文字显示；不执行 HTML，不自动打开远程图片、文件或链接。
非文本／压缩字节显示“已保存字节证据，无法按文本解析”，按需展示有界字节预览或 Base64；不以乱码代替原文。

WS 失败帧是独立的“上游失败帧”区块，明确标记来源，不混入桥接后的 SSE 流程。
有证据时才显示入口，失败帧单独读取、失败单独重试；没有失败帧时不推断上游没有错误。

## 五、读取、刷新与资源反馈

| 操作／状态 | 行为 |
| --- | --- |
| 首次查看 | 按请求、响应顺序读取可用正文；各侧独立显示加载／等待状态，可用的一侧先呈现，不等全部成功 |
| 一侧失败 | 错误留在该侧，提供“重试读取”；另一侧正文和展开状态保持，不自动重发两侧请求 |
| 保存中 | 显示“正文尚在保存”，可刷新元信息；不轮询、不显示空白成功、不提供读取未发布文件的入口 |
| 元数据刷新 | 查看正文意图尚有效且快照变为可读时，读取新可用的一侧；未曾点击查看则仍只刷新元信息 |
| SHA 未变且仍可读 | 复用本页已解析内容，保留展开、分页和滚动；不重复拉取正文 |
| SHA 或可用状态变化 | 清理受影响侧旧投影；变为过期／缺失／不可用时立即隐藏该侧缓存，不因正文已加载就继续显示为最新证据 |
| 刷新失败 | 普通网络错误时保留已读内容并标“刷新失败，当前为上次读取内容”；权限失效则清除正文，沿用身份失效处理 |
| 收起正文 | 取消读取与解析，清除正文和展开状态；不删除服务端文件，焦点回到“查看正文” |
| 切换调用／身份／离开页 | 清除本页内容及未完成读取，迟到响应不能进入新页面；不跨页面缓存正文 |
| 读取繁忙 | 显示“正文读取繁忙，请稍后重试”，由用户重试；不自动循环排队 |

首次至多呈现 100 个流程块，按钮标“继续显示后续事件”，每次再呈现最多 100 个；已知总量时可显示“已展示 X / Y”，
解析未完成或达到上限时只显示已知数量。原始来源每次最多显示 50 条；长正文和原文也分段展开。
追加保持当前位置，不跳回顶部或自动滚到底部；收起使当前焦点节点消失时，焦点回到对应展开按钮。

解析达到 20,000 帧索引或单事件 1 MiB 上限时，在具体位置显示“展示解析已到上限”，保留剩余原文入口。
这种提示属于阅读能力限制，不使用“响应已结束”文案；文件截断与阅读预览截断必须分别命名。

## 六、异常、空态与事实边界

| 证据情况 | 默认表现与可操作入口 |
| --- | --- |
| HTTP 200 内模型失败 | 概况保留 HTTP 200／转发结果，响应侧显示失败事件与原因；不出现笼统“调用成功” |
| 响应中断 | 已收到的文本继续可读，受影响输出标“未完成”，末端显示已知中断原因 |
| 中断原因不明 | 显示“调用中断，原因未确认”；客户端断开不展示为用户主动取消 |
| 事件格式损坏 | 在可定位事件处标“事件无法解析”，可展开原文；下一条完整事件继续呈现 |
| 终态与增量冲突 | 标“内容不一致”，展示两份值的来源；不静默覆盖或只保留其中之一 |
| 快照被截断 | 末端标“采集在此截断，后续未知”；不能据此标“模型断流” |
| 响应完整但阅读解析失败 | 快照仍显示完整，阅读区域标解析问题；允许查看原文，不改写后端状态 |
| 未收到响应 | 明确“未收到响应正文”及已知原因；请求仍可读，不生成上游错误正文 |
| 完整零字节响应 | 显示“响应正文为空，已完整保存”，模型结果另按已记录观察显示 |
| 当时未采集 | 显示“当时未启用正文采集”，不提示刷新可以补录 |
| 正常内容按策略未保留 | 显示“按当时策略未保留正常正文”，与未启用分开 |
| 已清理／文件丢失／保存失败 | 分别显示已过期、文件缺失、保存失败；已知元信息仍可读，不显示重试生成证据的按钮 |
| 历史观察为空 | 显示“历史记录未记录响应观察”；已有正文仍可提供标为“阅读解析”的视图，不冒充当时后端判断 |

采集元信息、后端响应观察、前端阅读解析允许结果不同，界面明确来源。
“响应正常结束”只证明 Center 的有限观察结果；技术方案已明确无法覆盖所有 Runtime 独有失败，
在记录策略的相关说明中提供这一限制，不把它作为每张正常卡片的常驻警告。

## 七、记录策略弹窗

沿用列表“记录策略”弹窗与现有保存流程，控件改为单选留存模式，保留正文／索引保留天数。

| 选项 | 操作位置的说明 |
| --- | --- |
| 关闭 | 仅记录调用索引和用量，已有正文按原保留期清理 |
| 仅异常与未确认 | 调用期间有界暂存，明确正常时不落盘；不能覆盖所有仅在 Runtime 内发生的错误 |
| 全部调用 | 保存所有已接纳调用的已有请求与响应，仍受采集上限约束 |

打开弹窗读取当前实际值，不重置为默认值。天数必须满足正文 ≥ 1、索引 ≥ 正文且索引 ≤ 3650；
错误定位到对应字段，合法前禁止提交。无改动时禁用保存；取消编辑不改变实际策略。

从关闭改为任一录制模式，或从“仅异常与未确认”扩大为“全部调用”，保存前显示具体变化并要求确认。
缩短任一保留期时同时列出原值与新值，并说明既有到期内容会被清理；多个影响合并为一次确认。
确认说明保存后仅新调用使用新模式，正在进行的调用保持开始时策略；保留期调整会影响已有记录。
关闭或缩小录制模式不能被描述成“立即删除历史内容”。

提交中锁定草稿与重复提交，沿用 AdminStore 写入门。明确校验／权限拒绝时保留草稿并显示原因；
网络断开等结果未知时提示“保存结果未确认”，先回读实际配置，再决定是否重新提交，禁止自动重发。
保存成功后关闭弹窗、回读当前策略并显示成功；回读失败单独提示，不能把已成功保存说成回滚。
策略写入不会刷新或清除正在查看的历史调用正文，不在详情页增加第二套策略配置入口。

## 八、视觉、可访问性与验收

使用现有 Card、Timeline、Collapse、Tag、Alert、Descriptions、Form、Radio、InputNumber、Modal、Button。
颜色、字号、圆角、控件高度由 ConfigProvider Token 提供；状态色表达成功／警告／错误，不能只靠红绿区分。
业务样式仅处理分栏、间距、换行和滚动，不覆写 Ant Design 内部 DOM。普通正文保持 14px、辅助信息 12px，
沿用后台 Token；不通过缩小字体强行把两栏塞进窄屏。

展开头支持键盘 Enter／Space、正确的 expanded 状态及可访问名称。加载与失败就近反馈，
不将每条事件逐条播报；刷新和异步解析完成不自动抢焦点。错误不能藏在默认收起的标题内部。
折叠、追加和定位遵守减少动态效果偏好，不用持续闪烁的流程轴或模拟打字。

实现后按下列口径核验，结果记入开发计划／进度，不单独创建验证报告：

1. 普通管理员从列表筛选、进详情、查看正文、返回列表闭环可用；普通用户／失效身份不能查看证据。
2. 正常、HTTP 错误、HTTP 200 模型失败、断流、坏事件、尾部截断及无正文状态均能识别，原文入口准确。
3. 多工具／多输出项交错不乱序，聚合来源可追溯，完成快照不重复，冲突保留两份来源。
4. 两侧独立加载／失败，刷新不覆盖阅读位置；正文过期、换调用、收起和换身份后缓存按本指导释放。
5. WS 失败帧来源独立；JSON、compact、input_tokens 页面不伪造 SSE 事件；没有虚构耗时、chunk 数或工具执行结果。
6. 900px 分栏临界宽度、窄屏、100%／125%／150% 缩放、长中文／长 ID／长参数均无遮挡，键盘与焦点恢复可用。
