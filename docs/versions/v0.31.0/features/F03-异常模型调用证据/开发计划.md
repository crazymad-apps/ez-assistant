## 二、台账原则

1. 按能力闭环拆分，不把建表、接口、SDK 和页面分别留成不能使用的中间里程碑。
2. 每个里程碑先核对当前代码、依赖、授权和测试目标，再实现并完成最小有效验证；完成后先标记
   `🟨 待确认`，用户确认后才记 `✅ 已完成` 并进入下一里程碑。
3. 设计或资源假设与实际代码不符时，先停止扩大范围并修订设计；不能在实现中默默放宽采集或数据保护边界。
4. 默认一次仅一个 Feature 开发或验证；本次按用户明确授权并行 F02／F03，既有工作树改动和其他 Feature 文档保持原样，不主动提交或推送。
5. 此计划的确认不授权生产部署、修改用户采集策略或操作已有用户数据库；数据库操作继续按根安全规则执行。
6. 验证覆盖到当前里程碑结束，不把已实现的核心风险推迟到 M2；M2 聚焦跨层路径和验收缺口。
7. 本计划只登记状态、用户确认、完成结论和必要风险；实际验证细节在会话中汇报，不创建独立验证报告。

## 四、各里程碑

### M0 异常证据采集与管理闭环

**目标**：通过正式代理、存储与管理入口完成“设置策略 → 产生调用 → 按结果留存 → 查看证据”的闭环。
管理员此阶段可以读取原文及必要状态，消息／流程轴阅读归 M1。

**前置依赖**：总体设计、版本级 Feature 总台账、本计划均确认；核实当前没有冲突的并行实施；
版本进入开发中后，读取对应语言／模块规范，核查最新迁移序列及生成契约。

**交付范围**：

- 实现三种留存模式、冻结策略与有界响应观察；HTTP 转发、响应观察、usage 和快照完整性独立结算。
- 实现请求／响应原始字节保存、WS 未转发失败帧补证与来源标识；覆盖普通生成、配置测试、compact 和计量。
- 完成必要的迁移、历史值保留、文件恢复与到期清理，确认采集、解析、读取资源边界及失败释放。
- 完成管理查询／正文接口、观察筛选、鉴权与审计；更新 OpenAPI 并生成 Admin SDK。
- 同步后台策略弹窗、列表状态和原文读取，使模式、观察结果、非文本证据及失败帧在正式入口可用；
  不能只更新生成类型却留下旧页面无法保存策略，或为 M1 暂留虚假的成功投影。
- 同步受影响的模块约束与 Center 运维说明，明确默认关闭、保留期、升级／回退及 Runtime 独有失败限制。

依据：[技术方案第四、五、七节](技术方案.md#四采集策略与响应观察)、
[交互指导的记录策略](界面交互设计指导.md#七记录策略弹窗)。

**验证入口**：

- 在 Center 工程依次执行所需构建与定向测试，优先扩展现有 `llm-transport`、`llm-usage`、
  `llm-websocket`、`llm-records`、`llm-snapshots` 核心单测；新观察／分帧测试按实际职责命名。
  构建入口 `npm run build`；指定文件运行 `npx vitest run tests/unit/<实际测试文件>.test.ts`，不默认扩大到整个工作区。
- 两工程按改动执行 `npm run typecheck`、`npm run lint`、`npm run build`；契约检查分别用
  Center `npm run openapi:check` 与 Admin `npm run genapi:check`。生成产物只能由各自生成入口更新。
- 在新建、已核实的隔离 PostgreSQL 和私有快照目录中，通过正式 HTTP 管理与代理接口验证三种模式、
  HTTP 200 失败事件、超时／断流、WS 转换前失败、零字节与未收到、字节证据及读取审计。
- 定向验证旧结构升级、旧快照读取、部分文件发布／索引结算失败、重启与到期清理；核对真实表和文件状态。
- 真实浏览器检查模式保存／结果未知回读、旧页面写入拒绝、列表状态及各种原文入口；不能仅以 SDK 类型检查代替。

**完成判定**：正常与异常调用在三种模式下按设计保留或释放；HTTP／WS 证据来源准确，
读写／恢复／清理失败不产生假完整；旧数据与策略迁移符合设计；后台可管理策略并查看已保存证据。
以上须在本里程碑验证通过，M1 不承担补齐 M0 的采集或存储功能。

**Review 重点**：新字段与文件是否确有现有事实无法表达的需求；未接纳流量不采正文；未知取消不归因为用户；
只有响应正常且观察可靠时才按策略丢弃；观察失败不影响模型执行；错误正文不进入普通日志和审计。

**当前状态**：✅ 已完成；2026-10-13 用户要求继续 F03，确认本里程碑。已完成采集策略、响应观察、原始字节与独立失败帧、迁移恢复清理、管理接口及后台原文入口。定向单测、隔离正式 HTTP／WS 集成、两工程静态检查／构建与契约检查、真实浏览器验证通过。未接真实 Provider 或用户环境；Runtime 独有失败覆盖限制保留，消息／事件可视化仍归 M1。

### M1 消息与事件可视化阅读

**目标**：在 M0 正式快照上完成已确认的“两栏阅读”，让用户能从可读内容定位到原始事件和异常证据。

**前置依赖**：M0 实现与验证获用户确认；继续复用其最终契约，不临时加入第二套正文接口或持久事件模型。

**交付范围**：

- 请求消息、独立指令、模型参数与工具定义、历史引用和多模态引用的分层阅读。
- 响应流程轴、相邻同类增量聚合、交错输出保持顺序、终态校准／去重及冲突展示。
- 原始事件来源、异常定位、坏帧／残片展示、非文本字节与独立失败帧阅读；适配 JSON、compact 和计量。
- 两侧独立加载及重试、刷新时投影复用／失效、正文释放与迟到结果隔离；大快照分批解析及展示。
- 窄屏、长内容、键盘、焦点与现有主题接入；将 M0 原文入口整理进最终正文布局，不保留平行的临时详情页。

依据：[技术方案正文阅读与事件聚合](技术方案.md#六正文阅读与事件聚合)、[交互指导](界面交互设计指导.md)。

**验证入口**：

- Admin 私有解析器／投影单测覆盖相同字节的不同分片、跨字符边界、交错输出、多工具参数、终态重复与冲突、
  坏帧恢复及解析上限；用内容、顺序和原文定位断言，不写 CSS 或大段 DOM 文案快照。
- Admin 执行 `npm run typecheck`、`npm run lint`、`npm run build` 和本里程碑相关单测。
  生成契约未变时不重新导出 Center OpenAPI；若确需契约调整，先复核对 M0 和消费者的影响。
- 真实浏览器连接 M0 的正式隔离 Center，覆盖正常文本、错误、断流、失败帧及大内容，检查定位、展开、
  分批显示、只重试失败侧、过期清理、换身份／调用和收起正文。
- 按交互指导检查分栏临界宽度、窄屏及 100%／125%／150% 缩放；页面布局验证不依靠单测推断。

**完成判定**：正文阅读与原始证据一致，事件顺序和重复文本不被错误处理；坏数据不拖垮整页，
未知信息不补造；各读取／清理状态及可访问操作符合交互指导。原型或静态示意不能作为正式页面验收结果。

**Review 重点**：展示层是否擅自改写后端观察；工具调用是否被误说成已执行；正常预览限制是否被误说成采集截断；
是否出现新的全局 Store、跨页面正文缓存、伪事件时间或仅为展示建立的事件表。

**当前状态**：✅ 已完成；2026-10-13 用户确认卡片与系统提示词命名调整后要求继续。正式详情已接入两栏消息／事件阅读、相邻增量聚合、结束校准及冲突保留、来源原文、独立失败帧与字节证据。读取顺序、单侧重试、刷新复用／失效、取消释放及分批展示已完成定向单测和隔离正式后台浏览器验证，类型／格式／静态检查及构建通过。未接真实 Provider；M2 联合验收已获继续授权。

### M2 端到端验收与 Feature 收口

**目标**：验证采集、策略、权限、文件、接口和可视化在同一次调用上的一致性，补齐跨层风险后提交 F03 验收。

**前置依赖**：M1 已获用户确认；M0／M1 未完成项已处理或有明确的待验收限制，不以收口代替缺失实现。

**交付范围与验证入口**：

- 在正式 Center/Admin 装配中走完整管理路径：设置策略、产生调用、筛选定位、读取消息／事件／异常原文，
  核对最终记录、文件字节、接口返回和页面解释；确定性 HTTP／WS 上游覆盖核心故障。
- 定向核验权限失效、并发读取预算、策略变更期间的在途调用、重启恢复和保留期清理与已打开页面的联动。
  M0 已通过且无后续变动的独立单测不因进入 M2 重复扩充。
- 以隔离升级场景回证旧策略、历史调用／快照可读、旧页面拒绝写入及回退限制；不向用户现有 Center 执行验收迁移。
- 若具备已授权 Provider 路由，用独立 Runtime Home 的正式 Host 做代表性企业链路回证；不能复制用户会话或直接用用户库。
  未具备条件时明确记录未执行路由及对验收的影响，不以合成上游代替真实 Provider 结论。
- 确认已有 F01 公开路由不能读取私有快照；F01 尚未实现的联合路径留给版本整体验收，记录该依赖。
- 按最终变动执行必要的两工程静态检查、构建及契约检查；以 `npm run build:bundle` 验证正式装配（Center 工程）。
  没有 Rust／Desktop 改动时不要求全 Rust 工作区或 Tauri 打包；实际涉及范围变化时重新评估。
- 同步最终模块说明、运维边界与用户向文档；用户向内容遵循 `docs/site` 的唯一内容源约定，
  不把本 Feature 的内部设计或验证数据当作官网日志上传，也不在此里程碑发布内容包。

**完成判定**：[技术方案验收标准](技术方案.md#81-验收标准)和[交互验收](界面交互设计指导.md#八视觉可访问性与验收)
中的相关要求均有实际结论；遗漏或偏差已修正，无法实测的范围明确交用户判定。
M2 完成后先等待确认；用户确认 Feature 验收后，在本计划登记 F03 已完成，版本仍须执行跨 Feature 验收。

**Review 重点**：不能混淆数据库、快照文件、内存投影与页面状态；不能把 Center 正常终态当作所有 Runtime 失败均已覆盖；
不能将仅编译、原型或单元测试通过表述为生产部署、全平台或全部 Provider 验收通过。

**当前状态**：🟨 待确认。2026-10-13 联合验证完成：真实隔离 HTTP／WS 调用、历史正文升级、策略冻结、读取限额与身份失效、重启恢复及过期页面联动通过；修正 WS 上游错误被归为中心失败的问题。正式前后端装配、契约检查、定向回归和浏览器核验通过。未连接真实 Provider／正式 Host 企业路由；F01 完整公开站点联合验收留给版本验收，当前私有快照静态隔离已核对。

## 五、环境与数据库执行约束

- M0 实施与验证已使用项目 `.runtime-test/` 下按场景新建的私有测试目录和独立数据库，
  不复用历史场景数据，不读取用户 Runtime Home 的数据库、会话或配置作为测试夹具。
- 已核查 `tests/integration/calls.test.ts` 固定绑定历史数据库与目录，且依赖旧策略字段；不能直接执行，
  也不能仅伪设“备份已验证”环境标记绕过保护。优先复用现有隔离数据库测试支持，建立 F03 专属新场景，
  或在不放宽目标校验的前提下调整原入口。测试支持只在测试目录，不把环境开关接进生产逻辑。
- 写入前按实际连接核实主机、端口、库、迁移账本和受影响表，核对代理／管理接口确实读取这些表。
  核心业务目标为调用、采集策略和审计表；夹具涉及的用户／Provider 等配置表也纳入核查与实际结果汇报。
- 一次性无用户数据场景按根第七节执行；涉及生产、共享或需保留数据的环境，写前明确确认并验证独立备份，
  迁移事务、异常停止和回退按技术方案及根安全规则执行，不能因计划确认省略。
- 验证后按实际影响核对精确数量和关键字段，并检查文件及正式接口；详细结果在会话汇报，不堆入流程文档。

## 六、Feature 完成条件与确认记录

F03 完成需要同时满足：

1. M0—M2 均完成实现／验证并获得用户确认，未完成项、偏差与必要风险已收口或获明确接受。
2. 三种模式、HTTP／WS 证据、迁移／恢复／清理、私有访问与正文可视化形成正式闭环。
3. Runtime 独有失败、预算不足、历史未采集等限制如实保留；不承诺事后补录或未经验证的 Provider 支持。
4. 技术方案、交互指导、模块说明与实际实现一致，版本台账登记最终结论；源码提交不是完成前置条件。
5. F03 完成不等于版本发布；跨 Feature 联合验收、真实环境迁移、部署和发布按对应授权另行推进。
