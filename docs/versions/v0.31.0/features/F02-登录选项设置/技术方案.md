## 三、权威状态与组件归属

| 事实 | 唯一来源／owner | 本次处理 |
| --- | --- | --- |

阶段只表达本次 UI 操作：读取、编辑、影响确认、保存、核对保存结果、重启、核对生效结果、失败。
失败携带阶段及已经取得的 Host 快照，不能用一个 error 覆盖“已保存”的事实。对话框卸载丢弃草稿；
应用退出后不恢复一条自动执行的保存／重启任务。

## 五、管理读取、保存与重启契约

### 5.1 管理读取与原生投影

继续使用 `manage_local_host`，调用方不能传任意 Host URL、Runtime Home、Token 或文件路径。
原生层发现本机实例，以独立管理证明请求 HostAccess；不调用 `/runtime/ensure-ready` 来取得权限。

Host 共享响应继续使用 `HostAccessStatus`，不新增 Host 接口或改变字段意义。原生 bridge 的返回值
在该状态上平铺增加当前 `instance_id`、`current_mode`、`current_center_url`：分别来自捕获的本机
bootstrap、同实例 capabilities 与已有 `/desktop-update-context`。Rust 使用现有 DTO 组合序列化，
TS 使用 `HostAccessStatus` 的交叉类型，不手写一份 HostAccess 字段。

M0 实施将管理读取与受控操作放在 `runtime_bootstrap/management.rs`，由既有协调器持有生命周期 gate，
`runtime_connection::manage_local_host` 保持薄转发；避免对外暴露锁或在连接模块复制进程所有权。
管理与启动错误共用原生 `RuntimeBootstrapError` 的 `{code,message}` 形状，新增配置冲突、输入拒绝、
操作拒绝、结果未知及更新忙分类；Host 的共享 `RuntimeErrorInfo` 与协议保持不变。

这是原生 IPC 投影，不是新的配置实体；目的是让保存值与生效值及实例核对具有同一次操作的依据。
读取前后确认 discovery 仍属于同一实例；若实例改变则丢弃这次组合结果，要求重读。当前状态读取
失败时不拿已保存字段补成当前值。登录后原生访问设置适配这一返回类型，普通 Web 仍使用原 HTTP DTO。

### 5.2 保存输入

复用 `HostAccessCommand::Configure`，只构造一次提交：

| 字段 | 取值与约束 |
| --- | --- |
| `expected_revision` | 打开／显式重载后用户编辑所基于的 Host revision，不以提交前最新 revision 偷换 |
| `mode` | 用户选择的个人或企业模式 |
| `center_url` | 企业模式取去除首尾空白后的输入；个人模式不提交该字段，保留 host.toml 中已有企业地址 |
| `clear_center_binding` | 存在实际模式／地址变更且读取快照含旧绑定时自动为 true，含切到个人模式；无旧绑定为 false，不再由复选框控制 |
| `configuration` | 基于同一读取快照完整保留监听、证书和允许地址，仅在身份配置确有变化时按确认将 `remote_enabled` 设为 false |

无差异且没有待重启配置时不发送 Configure。已有待重启配置只执行确认后的重启，不重新保存原值。
进入影响确认时锁定本次草稿和基线；返回编辑后原确认失效。确认不是创建一份长期配置快照。

2026-10-13 用户明确要求模式切换保留中心地址。表单切换 mode 只改变字段显隐，不能重置地址草稿；
重新打开表单始终从已保存的 `HostAccessStatus.center_url` 初始化，即使当前 mode 为 personal。
`current_center_url` 在个人模式为空仅表示当前进程不使用企业中心，不得用于清空已保存地址或草稿。
沿用 Host `set_mode` 保留企业地址的行为：个人模式不传 center_url；同次 Configure 按新交互规则
清除 enterprise.center_id，保留 enterprise.center_url。恢复企业模式优先用已有地址，
不重新套用构建默认值。不新增客户端“上次中心地址”缓存或第二份持久配置。

2026-10-13 用户进一步要求精简编辑态并默认清除旧绑定。本次调整复用现有 clear_center_binding
命令意图，不修改 Host 全局默认值或普通登录逻辑，不让打开弹窗、模式草稿切换或无改动操作产生写入。
现有 enterprise_login 在验证中心登录身份后调用 bind_center，绑定为空时才保存返回的中心 ID；
这不是每次初始化重新生成中心 ID。登录校验失败时仍不自行清除或重试换绑。

`manage_local_host` 对 Configure 增加可选的原生 `expected_instance_id` 前置条件，F02 必须提供；
发现本机实例已经更换时拒绝写入并要求重新读取。现有 Host CAS 继续负责同实例的配置并发，
请求 ID 只承担请求关联，不把当前固定 request_id 当作持久幂等凭证。

### 5.3 稳定错误与不确定结果

原生层解析正式 `RuntimeErrorInfo`，保留 `configuration_conflict`、`invalid_request`、
`operation_not_allowed` 等安全错误码，不再将所有 Host 错误统一改成 configuration_unavailable。
消息沿用已脱敏的 Host 错误，未知响应不回显正文、凭据或原始输入。

- 已确认由提交前校验拒绝：保留草稿，反馈未保存；不重启。
- 超时、断线、响应无法解析或配置服务不可用：按保存结果未知处理。Host 中保存后仍有策略发布，
  因此不能把任何非 2xx 都解释为文件未写入。
- 取得成功状态：记录已保存快照，再发起重启阶段；后续失败不能覆盖保存成功事实。

对未知结果只执行有界的状态回读，不自动重发 Configure。回读与提交意图一致时显示“当前配置已保存，
尚未确认重启”，由用户显式重启；不声称已证明由原请求写入。回读仍为旧值或不同值时提示重新核对，
不能据此自动重试尚可能在 Host 执行的写命令。用户后续提交仍受现有 revision CAS 保护。

### 5.4 带配置核对的既有重启

扩展原生 `restart_runtime` 的可选校验参数，传入已保存状态的 `instance_id` 和 `revision`。
F02 的正常应用和“应用已有待重启配置”均传入；普通生命周期入口可以保持无该参数的原有行为。
参数仅复用现有实例标识与配置 revision，不创建新的序号或持久恢复记录。

在既有 `lifecycle_gate` 内，停止前依次核对：实例仍一致、GetStatus 的 revision 仍一致、原启动
来源可用。任一不一致则不停止 Host，返回明确错误。将已有重启实现拆成持锁入口和私有核心步骤，
不能在持有 gate 时再次调用会取同一 gate 的公开 `restart()`／`bootstrap()`。

通过后复用原有 Shutdown、等待实例退出、再次核验原来源、启动与新实例发现。新 bootstrap 仅作为
本机管理结果，不激活成企业用户连接；关闭期限和启动期限沿用协调器，不为 F02 新建后台守护循环。
来源缺失、实例被别人替换或启动失败均不自动改用其他二进制，也不自动恢复旧配置。

重启后重新读取状态，必须同时满足：新实例与返回 bootstrap 一致、当前模式／中心与目标一致、
保存配置与已确认目标一致且 `restart_required` 为 false。清除绑定后、重新登录前中心绑定应为空；
若其他客户端已经完成首次绑定导致 revision 改变，要求核对，不擅自再次清除。

保存和重启不是跨进程事务。Desktop 内 gate 不阻止另一台管理客户端或人工修改文件；停止前核对
缩小并发窗口，重启后核对发现最终偏差。本 Feature 不为消除文件系统层面的全部竞争新增跨进程
配置租约或分布式事务，不承诺阻止恶意并发文件修改。发现变化即停止自动续作，交给用户重新核对。

## 六、连接失效、更新互斥与异步所有权

### 6.1 UI 连接衔接

登录选项读取不建立普通用户身份。打开时合并本机已有启动等待；旧读取以该次表单 owner 和现有
连接 generation 判定是否仍可接纳，关闭、切换目标或离开首页后不得写回新页面。

确认保存前，`ApplicationConnectionStore` 进入 pending，阻止本次 UI 发起登录、切换目标、升级或
重复应用。保存失败仍保留必要的原身份恢复入口；一旦保存成功并进入重启，先释放旧业务投影、订阅
和账号状态，清空表单密码、旧 bootstrap 与 `#local_start` 缓存，递增既有连接／发现失效标识。

原生连接清理由已有 `begin_runtime_connection` 完成：取消旧 selection、关闭其原生浏览器及资源、
收束旧更新任务。只调用 JS 的 `clearRuntimeBinding()` 不足以撤销原生凭据，不能作为完整清理。
这一步不发送企业账号 logout；Host 受控重启负责结束本机全部连接和用户域，避免对中心发起额外账号操作。

重启完成后只更新本机可连接状态、运行中模式和本次管理结果，再按新中心准备更新检查。保持首页，
不调用 `#enter()`、不初始化个人／企业业务域。用户下一次点击进入时才创建普通登录并按原流程初始化。
旧登录响应、原初始化回调、先前 startLocal Promise 及 updater 探测都必须因现有 owner 不匹配而失效。

### 6.2 操作互斥与锁顺序

- 单一界面通过 pending 防止重复意图，但原生侧仍负责更新／生命周期互斥，不能只依赖按钮禁用。
- 登录配置写入取得 `DesktopUpdater::lifecycle_permit`，在同一 updater jobs 锁下核对没有活动下载或
  安装，再取得 bootstrap 的 lifecycle gate，发现实例并发送一次 Host 配置命令；返回后释放两个锁。
- F02 带前置校验的重启同样先取 updater permit，再取 bootstrap gate，并复核更新阶段。
  普通停止／升级继续使用原锁序，不增加 F02 专用进程锁。
- 固定锁顺序为 updater jobs → bootstrap lifecycle gate → Host 的有界配置请求；原生 Selection
  同步锁仅用于短期捕获／失效，不跨 await。Host 的 actor 和文件 CAS 继续负责 Host 侧写入。
- 管理保存前的 bootstrap 与生命周期读取提取可在已持锁上下文调用的私有步骤，避免重入锁。
  `begin_runtime_connection`／`replace_connection` 会自行获取 updater jobs，因此只能在前一次
  invoke 已返回、permit 已释放后调用，不能放入持锁的管理／重启 helper。
- 保存与重启之间若另一个更新操作抢先启动，重启须返回忙，保留“已保存待重启”，不取消或抢占安装。
  UI 允许稍后重试，不宣称整个保存重启过程不可打断。

本 Feature 不增加长驻 actor、额外工作队列或脱离调用者的重试任务。原生 invoke 完成其已开始的有界
步骤；UI 等待消失不能撤销已经落盘的配置或已发出的停止命令。所有结果经回读恢复，不能在卸载时
盲目补偿或重发。

## 七、失败与恢复判定

| 已知事实 | 显示／后续动作 | 禁止行为 |
| --- | --- | --- |
| 尚未读取可信状态 | 重新读取，保留首页 | 使用默认配置提交 |
| 明确前置校验拒绝 | 保留草稿，定位错误或重新载入 | 继续重启、偷换 revision |
| 保存结果未知 | 回读；仍未知则保留未知提示与手动检查 | 自动重发 Configure |
| 已保存、旧 Host 仍运行 | 待重启，按当前 revision 再次确认 | 显示新模式已生效 |
| 已保存、原 Host 已停止但新进程未就绪 | 显示启动失败；复核发现与原来源后显式重试 | 调用可能回退随包来源的普通 bootstrap 冒充原来源重试 |
| 已出现新实例、最终读取失败 | 只重新检查该实例 | 为了刷新状态再次重启 |
| 最终配置或实例与预期不同 | 报告变化并重新核对 | 回滚覆盖、再次清除绑定 |
| 新配置生效，企业登录失败 | 保留登录选项及真实登录错误 | 回落个人模式或旧中心 |

“旧实例已停止”的重试必须沿用协调器已核验的原启动来源；当前 `restart()` 依赖仍运行的实例，
不能直接再次调用。若现有失败返回不足以支持原来源的安全重试，则界面仅提供“重新检查”和既有
本机维护指引，不新增持久的原来源副本，也不承诺一键恢复所有启动失败。

WebView 刷新或应用重开后，从发现、运行中能力、已保存配置与 restart_required 重新判断；不恢复
历史进度条，不自动补发保存／停止。旧进程已退出而需要重新启动时仍遵循既有启动来源和升级规则，
无法核实来源则如实提示维护。应用内重试和用户下次常规启动是不同意图，不能混为同一个自动补救步骤。

身份配置保存与重启不移动用户目录，不对会话、附件、模型库执行迁移。关闭非本地访问即时断开对应
连接，任务中断发生在受控重启；两者的反馈应分开。重启影响所有用户，首页不查询全部用户数据来凑
影响计数；任务数量未知时直接说明未知。

## 八、兼容、最小新增与实施范围

共享 HostAccess 命令、状态、Center 协议、配置 schema、数据库结构和用户域布局保持现有形状。
新增项仅为 Desktop 随包更新的原生 IPC 投影字段和重启前置参数，Rust／TS 同步修改；普通 Web／Client
不消费这些私有字段，不增加旧版本双读双写或别名。不因 F02 单独提升应用／存储／企业协议下限，
版本统一软件号与其他 Feature 的兼容要求在版本级计划处理。

**删除本次新增机制后，现有事实是否已经足够？**

- 数据事实足够：使用现有 mode、center、revision、instance_id，不新增配置表、设置同步服务、
  “生效记录”、全局计数或恢复日志。
- 页面入口不足：新增窄对话框和卡片按钮，已有完整设置不能直接用于首页。
- 当前原生返回不足以同时区分保存与运行中值：只组合已有投影，不添加第二份持久配置。
- 无前置核对的重启不能区分保存后他人已更换实例／配置：复用现有 ID 和 revision 作 expected-value
  校验， mismatch 时拒绝停止；不创建新 revision、generation 或租约。
- UI pending 不足以防止原生更新并发：复用既有 updater 与 bootstrap gate，不另建协调器。

主要实施落点为上述现有文件与新的 LoginOptionsDialog 组件。Host 生产逻辑以复用为基线，补鉴权、
绑定和配置回读的定向测试；如实施发现确需 Host 契约变更，应重新说明原因和兼容影响，不默默扩大范围。
Desktop 模块约束中旧登录页禁用全部管理的条款，在实施时更新为已确认的登录选项窄例外与完整设置禁入。
