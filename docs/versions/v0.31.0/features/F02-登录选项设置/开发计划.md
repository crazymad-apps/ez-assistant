   实际路径、地址、端口、数据库与涉及表；遵循根数据库规则。不得使用用户 Home 或已有共享测试库。

7. 计划只维护完成结论、用户确认、未完成项和必要风险，不另建验证报告或归档测试数据；不主动提交或推送。

## 四、各里程碑交付与验证

### M0 本机配置与受控重启通路

**目标**：为登录前的配置读取、保存和应用提供可验证的原生边界，不依赖企业身份或业务初始化。

**交付范围**：

- 按[技术方案第五、六节](技术方案.md#五管理读取保存与重启契约)组合已有管理状态与运行中事实，
  同步原生 IPC 与 TypeScript 消费方；登录后访问设置继续正常工作。
- 保留结构化错误，区分明确拒绝与保存结果未知；配置提交核对实例，重启核对实例及已保存修订。
- 复用更新与生命周期锁、受控停止及原启动来源，防止下载／安装竞争和重入；保留原有普通生命周期入口行为。
- 根据[技术方案第七节](技术方案.md#七失败与恢复判定)明确实际可用的恢复动作，不能承诺不存在的原来源安全重试。
- 补充当前原生模块及 Host 的定向测试，不引入新 Host 管理接口或全局自动清除默认值。

**验证入口**：仓库根运行 `cargo fmt --all --check`，对 `ez-assistant-desktop` 的 `runtime_connection`、
`runtime_bootstrap`、`desktop_update` 以及 `assistant-runtime-host` 的 `access` 测试分别定向执行；
命令形态为 `cargo test -p <package> <filter>`，按实际测试名称核对确有匹配测试执行。
在 `apps/desktop` 运行 `npm run build`，验证 IPC 消费方同步。

重点验证同实例组合读取、过期实例／修订拒绝、错误码透传、原来源不可用、更新互斥和无锁重入。
需要真实进程的故障场景在已核实的新隔离 Home 执行，不能由纯模拟证明停止和启动正确。

**完成判定**：新增契约有真实调用方且定向测试通过；旧访问设置与普通重启无回归，错误能够支持
后续 UI 的准确恢复判断。尚未交付登录页入口，M0 不能标记为 Feature 完成。

**Review 重点**：状态是否来自同一 Host、锁顺序是否统一、错误是否丢失已保存事实、是否意外扩大管理授权。

### M1 登录选项与首页入口闭环

**目标**：用户在首页完成模式／地址变更，并准确看到保存和生效结果。

**交付范围**：

- 登录壳层改为居中的 Logo 与名称组合，本机卡片内增加登录选项；普通 Web 和远程目标不显示本机管理入口。
- 编辑态只显示模式与企业地址，提示放在 placeholder；模式来回切换保留地址草稿，重新打开使用已保存地址。
  保存实际模式或地址变更时自动提交清除旧绑定意图，个人模式不提交隐藏地址修改。
- 接入同一弹窗内的影响确认、保存、重启与回读；处理无修改、已有待重启、冲突、未知结果和部分成功。
- 将操作编排接入现有连接 owner，失效旧请求、密码与原生资源，重启成功后由用户发起登录。
- 首页账号菜单、非工作区弹窗挂载及已有其他设置入口统一收口；断线退回首页关闭完整设置。
  必要账号操作保留，工作区完整设置正常。
- 同步 Desktop 模块中旧登录页约束为本次已确认的窄例外；其余模块只在实际约束变化时更新。

**验证入口**：在 `apps/desktop` 运行
`npm run test -- tests/unit/account-menu.test.tsx tests/unit/application-connection.test.ts tests/unit/settings-dialog.test.tsx`，
并运行本次新增登录选项测试；再执行 `npm run lint`、`npm run build`。
UI 定向测试覆盖参数和调用顺序、地址保持、自动清除、旧异步结果失效、重复提交和恢复动作，
而非只断言组件静态渲染。使用真实页面核对布局、输入、焦点与滚动。

**完成判定**：已有配置下读写应用形成完整闭环；保存失败不重启，未知结果不自动补发，已保存待生效
可辨认；首页完整设置没有残留入口。正常模式切换与企业登录成功后绑定恢复完成定向集成检查。

**Review 重点**：个人模式运行中空地址是否错误覆盖保存值、清除绑定是否仅随实际提交发生、RootStore
是否仍被误用作首页设置可用条件、只隐藏菜单但保留弹窗等旁路是否全部消除。

### M2 集成验证与 Feature 验收准备

**目标**：用正式 Host 与原生客户端验证端到端行为，形成可交给用户验收的 Feature 结果。

**交付范围与验证入口**：

- 新隔离 Home 下覆盖个人／企业互切、中心 A／B 切换、同中心换址、返回旧模式／中心；按接口实际读取
  的用户域核验原数据保留，不仅检查配置文件。保存个人后退出再打开应用，切回企业地址自动填回。
- 复用 `isolated_login_configuration_restarts_only_the_confirmed_host` 原生场景。先读取测试所需环境并准备对应夹具，再显式执行
  `EZ_ASSISTANT_TEST_HOST_BINARY="$PWD/target/debug/ez-assistant-runtime" cargo test -p ez-assistant-desktop isolated_login_configuration_restarts_only_the_confirmed_host -- --ignored --test-threads=1`；
  不对用户正在运行的 Host 执行该测试，不使用未核对的旧场景目录。
- 复核普通 Token、Cookie、非 loopback 的管理拒绝；覆盖响应丢失、配置冲突、实例替换、更新占用、
  停止／启动失败及最终回读失败。故障应可控注入，不靠反复手动竞速制造结果。
- 在 macOS／Windows 目标 WebView 检查本机卡片、无绑定描述的表单、确认、键盘焦点与错误恢复，
  同时检查普通 Web 的入口边界；按交互指导检查窄／矮窗口、长地址和三档缩放。
- 仓库根执行 `cargo fmt --all --check`、`cargo clippy --workspace --all-targets --all-features -- -D warnings`、
  `cargo test --workspace`；Desktop 执行 `npm run lint`、`npm run test`、`npm run build` 和
  `npm run tauri -- build --no-bundle`。仅在新变更、失败或未解风险出现后重复相应检查。
- 将实际行为交给 F01 手册与 F04 配色集成使用；F04 未实现时只确认语义 Token 接入，四主题最终覆盖
  留作跨 Feature 联合验收，不能提前记为通过。按开发流程更新本次已实现的用户向手册／日志内容，
  与 F01 内容源协调，不发布、不上传。

**完成判定**：功能设计的验收点均有真实结论，编译／模拟／真实进程／目标平台结果分开报告；
可用环境未覆盖的 Windows 或其他场景明确保留为未完成项，不能直接宣布全部验收通过。
问题在本里程碑内修正并重验，完成后交用户确认 M2，再进行 Feature 验收确认。

**Review 重点**：同名账号是否跨中心串域、保存与生效是否被混为一谈、重启是否偏离原来源、
失败恢复是否扩大副作用、其他 Feature 未实现的能力是否被误算为本 Feature 已交付。
