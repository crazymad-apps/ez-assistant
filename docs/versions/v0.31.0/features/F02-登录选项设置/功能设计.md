## 二、背景、目标与非目标

目前本机 Host 的模式与企业中心地址通过完整访问设置或 Client 修改，缺少独立的登录前配置入口。
企业中心地址错误、中心不可达或暂时没有企业账号时，用户难以从登录页面完成纠正，即使原生本机
管理能力本身不依赖企业登录。另有入口泄漏：已有登录身份但连接中断时，首页账号菜单仍能打开完整
设置，这正是用户截图指出的问题，需在本 Feature 一并移除。

目标是在 Desktop 登录页“这台电脑”卡片内提供“登录选项”，让本机用户选择个人／企业模式、填写企业中心地址，
并完成保存、受控重启和重新进入。企业登录失败不阻断本机配置入口；所有结果以 Host 的实际状态为准。
登录表单上方以 Logo 与应用名称的横排组合明确产品身份。

本 Feature 不提供完整 Host 管理面板、远程配置管理、多中心列表、账号注册、密码找回、数据搬迁或合并、
配置损坏修复器，不调整个人模式的使用授权，也不把企业登录改成客户端直接访问 Center。
端口、HTTP／HTTPS、证书、访问密码和允许地址等完整设置继续由既有入口维护。

| --- | --- |
| 登录入口 | Desktop 已有“本机 Runtime／其他 Runtime”选择；企业模式显示账号密码，个人本机沿用直接进入路径 |
| 首页完整设置入口 | 登录表单在仍有 session 时复用 AccountMenu，菜单“设置”只检查 Store 是否存在；App 在非工作区阶段仍挂载 SettingsDialog，因此断线返回首页后仍可唤起完整设置 |

| 配置权威 | `host.toml` 持有模式、中心地址及中心绑定；访问设置状态返回已保存值、配置修订及重启要求 |

| 换绑限制 | 现有 Host 要求改动已绑定地址时命令明确携带清除意图；F02 保存模式／地址变更时自动构造该意图，不要求用户勾选 |
| 远程接入限制 | 模式、中心或绑定变化时，提交的非本地访问必须为关闭；重启后只能显式重新开启 |

| 数据隔离 | 个人域与企业域分开，企业域按中心和用户身份定位；切换配置不迁移或删除原数据 |

## 四、入口、表单与使用路径

### 4.1 入口与可用范围

Desktop 登录页的“这台电脑”卡片内，右侧放置带小齿轮图标的文字按钮“登录选项”，打开同页对话框。
左侧保留设备图标、设备名称和连接状态，原右侧状态圆点移到连接状态文字旁。设置按钮垂直居中，
使用现有轻量文字按钮样式，视觉层级低于“进入项目”；不将整张状态卡片变为可点击入口。

选择这一位置是因为模式与企业中心属于这台电脑的 Runtime，用户可以在确认连接目标后、输入账号
之前完成配置。入口随本机信息卡呈现，不放在窗口标题栏、品牌行或主按钮下方，避免与窗口操作、
产品标识和提交登录混在一起。卡片在启动中、连接失败时仍保留，按钮按真实管理可用性展示读取或
失败状态；不因尚未登录或业务初始化失败而消失。

顶部原独立 Logo 改为居中的品牌横排：Logo 在左，`ez-assistant` 在右，整个组合相对表单居中，
不是 Logo 单独居中后再向右追加文字。沿用现有字体和主文字色，名称使用中等偏粗字重，不增加
标语或副标题。常规窗口建议保持现有 52px Logo、12px 图文间距及下方 24px 间距；名称沿用
`--ez-font-large` 标题字号。矮窗口沿用紧凑方向，Logo 40px、下方间距 16px，最终尺寸在交互指导
中校准。2026-10-13 技术方案核查后将先前 24px／20px 名称字号建议收敛为现有 Token，遵守三档字号规范。
窗口标题栏中的名称与版本继续承担窗口识别职责，不在品牌行重复版本号。

结构示意（本机企业模式）：

```text
              [Logo] ez-assistant

        [ 本机 Runtime | 其他 Runtime ]

        ┌──────────────────────────────┐
        │ [设备] 这台电脑    ⚙ 登录选项 │
        │        ● 本机 Runtime 可连接 │
        └──────────────────────────────┘

        企业账号
        [ 输入企业账号                 ]
        账号密码
        [ 请输入                       ]
        [ 进入项目                   → ]
```

保留当前表单宽度与整体纵向布局；窄窗口允许卡片操作换行到内容末尾并右对齐，不能挤压或遮挡
连接状态。品牌组合保持名称在 Logo 右侧，必要时缩小图标与字号，不裁切名称。键盘顺序跟随视觉
顺序，先目标选择、登录选项，再账号密码和主操作。共用登录壳层的 Desktop／Web 都显示品牌组合，
普通 Web 不因此获得登录选项入口。紧凑窗口可滚动，控件与焦点保持可达。

**首页完整设置入口移除（用户已明确要求）：** 首页／登录页账号菜单不再显示“设置”选项，也不能
通过账号区齿轮、快捷键、原生菜单或残留弹窗状态唤起完整设置。完整设置仅在进入工作区后开放；
从工作区断线退回首页时，已打开的完整设置应关闭，不覆盖登录页。此边界同样覆盖已有登录身份但
业务初始化失败、尚未进入工作区的状态；不能仅以 session 或 Store 存在判断是否可打开设置。

卡片内“登录选项”只打开本 Feature 的模式与中心配置，不跳转完整设置或提供其他设置分类。
账号相关的必要改密、退出和重试仍按各自条件提供，不因移除完整设置而丢失登录失败恢复能力。
共用登录壳层的 Web 同样不能从首页打开完整设置；工作区内原有设置入口继续保留。

| 场景 | 入口行为 |
| --- | --- |
| Desktop，选中本机 Runtime | 可读取并修改本机登录配置；中心不可达、登录失败、未登录不影响管理授权 |
| Desktop，选中其他 Runtime | 替换为既有远程地址表单，不显示本机信息卡或登录选项；远程模式由目标 Host 决定，不暗中管理本机或远程 Host |
| 普通浏览器访问 Host，包括本机地址 | 不提供模式／中心编辑入口；本机网页地址本身不构成原生管理授权 |
| 本机 Host 正在启动或管理状态读取中 | 展示读取进度，禁止提交，不使用默认值冒充真实配置 |
| 本机 Host 不可管理、启动失败或版本不兼容 | 展示原因与适用的重试／既有更新入口，禁止写入；不绕过存储或版本准入 |

界面是否显示不能替代服务端鉴权。普通用户 Token、企业管理员身份或访问 loopback 地址，都不能
单独获得修改 Host 模式与中心的能力。

### 4.2 表单内容

对话框标题为“登录选项”，编辑态仅保留两个字段，不显示常驻描述、中心 ID 或绑定操作：

- **使用模式**：个人模式／企业模式，打开时选中已保存值，不追加模式描述。
- **企业中心地址**：仅企业模式显示且必填，placeholder 为“输入企业中心地址，如 https://center.example.com”。
  保留短字段标签，错误仅在校验失败时显示。

2026-10-13 用户要求取消清除绑定选项，改为默认自动处理：保存实际模式或地址变更时，在同次配置
提交中自动清除已有中心绑定，包括切到个人模式；企业地址和原用户数据保留。普通初始化、打开弹窗、
切换表单草稿、取消和无改动操作均不清除。绑定在后续企业登录成功时重新建立，不是每次初始化重新生成。

打开时读取已保存配置。存在待重启改动时，明确标识“已保存，待重启”，不把表单中的模式称为当前
进程模式。当前登录表单仍以运行中 Host 的能力为准，避免在旧企业进程尚未退出时提前切成个人入口。

企业地址遵循现有 Host 校验：支持 HTTP／HTTPS、显式端口及现有合法路径前缀；拒绝空值、凭据、
查询参数、片段和非法空白。可以去除输入首尾空白，不擅自补协议、替换端口或移除路径。
前端用于即时提示，最终由 Host 校验。格式通过不代表中心可达、协议兼容或账号能登录。

2026-10-13 用户明确要求：切换登录模式不能清空企业中心访问地址，切回企业模式无需再次输入。
切到个人模式只隐藏地址输入，不提交企业地址修改，保留已有企业地址；实际保存模式变更时自动清除旧绑定。保存为个人模式后，
即使重启 Host、退出再打开应用，切回企业模式也必须自动填回已保存地址，不能用空值或构建默认值替换。
同一次对话框内来回切换模式时，未保存的地址草稿也必须保留；显式取消或关闭后才丢弃未保存编辑，
下次打开仍读取已保存地址。取消、关闭或无改动确认均不写配置、不重启。

### 4.3 保存与生效

主操作为“保存并重启”，取消为“取消”。提交前展示一次集中确认，列明模式／地址变化和以下实际影响：

1. 配置作用于本机整个 Host，不只是当前登录页面或当前账号。
2. 若非本地访问已开启，本次保存同时关闭它，现有远程连接会断开；重启后保持关闭，用户需在登录后
   的访问设置显式重新开启。该影响必须在写入前可见，不隐藏成自动修复。
3. 保存模式／地址变更自动清除旧绑定，后续企业登录成功时重新建立；原中心和个人数据均保留。
   确认页只用一句话说明，不增加复选框或额外确认步骤。
4. 重启会中断本机 Host 全部用户的任务并断开所有客户端，不承诺任务自动续跑。
   登录前无法取得全 Host 任务数量时说明数量未知，不显示“0 个任务”或冒充已核实空闲。

确认后先按现有配置修订检查保存；需要关闭非本地访问时，在同次配置保存中提交关闭意图，保留其余
监听、证书、密码和允许地址。成功后再调用既有受控重启。保存失败不能继续重启。

过程分别展示“正在保存”“正在重启”“正在重新连接”。期间禁止重复提交、目标切换、发起登录和
再次触发重启；下载／安装更新等既有生命周期操作与本操作互斥，不能竞争停止或替换 Host。
打开表单、编辑草稿不触发重启或换绑；不在有修改时以关闭对话框代替保存。

重启成功后重新读取 Host 能力与配置，确认新进程已就绪、保存配置已被接纳，才显示生效成功。
个人模式返回本机“进入项目”，企业模式返回账号密码登录。均不自动提交登录；清除旧密码与失效的
账号／连接上下文，旧异步请求不得覆盖新模式。登录和业务初始化仍按现有流程独立判断成功。

如果进入表单前已经存在待重启配置，提供“重启并应用已保存配置”，即使没有新编辑也可操作。
确认提示应说明会同时应用 Host 其他已保存的待重启配置，不能假装只影响本次字段。

### 4.4 换中心与数据保留

| 操作 | 预期数据与登录结果 |
| --- | --- |
| 个人切企业 | 个人数据保留，成功企业登录后进入对应企业用户域；不复制个人模型、会话或附件 |
| 企业切个人 | 企业用户域保留，使用既有个人域；个人域尚无数据时按原有初始化处理 |
| 企业 A 切企业 B | 保存时自动清除旧绑定，重启后用 B 的账号登录；相同账号名不视为相同用户 |
| 同一企业更换访问地址 | 保存时自动清除绑定；登录确认同一中心和同一用户身份后复用原数据域，不仅按 URL 或用户名判断 |
| 返回旧中心或旧模式 | 在配置和身份核验成功、原数据仍存在的前提下访问对应原数据；不承诺自动恢复活动任务 |

本入口不再提供单独清除绑定操作。同一地址背后更换了中心身份时，普通登录仍按现有身份校验报错，
可通过既有本机管理能力处理；不因错误地址、网络或协议错误自动换绑，也不静默回到个人模式。

## 五、异常与恢复

配置保存、进程重启和企业登录是不同结果；界面必须分别报告。

| 状态／失败 | 必须提供的反馈与恢复 |
| --- | --- |
| 配置读取失败 | 禁用保存，保留登录页，允许重新读取；不从客户端缓存拼造可写配置 |
| 地址非法 | 定位到地址字段，保留草稿，不写入、不重启 |
| 配置已被另一客户端修改 | 提示重新载入；保留草稿供核对，由用户显式重新编辑提交，不自动覆盖新配置 |
| 保存明确失败 | 显示未保存并保留草稿；不重启，也不宣称模式已变更 |
| 保存响应丢失、结果未知 | 先重新读取核对已保存事实，未确认前不重复写入或重启；不能把断线直接说成保存失败 |
| 已保存但重启失败 | 明示配置已保存与当前已知进程状态，提供重试启动／重启；不回滚配置或恢复非本地访问 |
| 重启后状态读取失败 | 显示生效尚未确认，允许重新检查；不得重复发起无必要的重启 |
| 重启成功但中心不可达或协议不兼容 | 明示配置已应用、登录仍不可用，保留登录选项供更正；不显示保存失败 |
| 账号密码错误／中心身份不符 | 沿用实际登录错误，不自动清除绑定或尝试其他中心；允许返回登录选项 |

重新读取发现保存值与刚提交意图不同，应提示配置发生变化并由用户核对，不替其他管理者重启未确认
的配置。明确未保存、已保存、结果未知三类状态都不能依赖按钮点击或单个请求发出推定。

Host 仍可管理时，恢复旧模式／地址使用同一表单重新保存并重启，按当前绑定规则再次确认。
Host 因配置损坏、原启动来源缺失等无法启动时，仅提供真实错误和既有 Client／本机维护指引；
本 Feature 不新增绕过 Host 的前端文件写入或通用离线修复。首次启动、现有 Host 发现和升级继续走
原有协调器；不能为了显示设置创建另一份 Runtime Home。

## 六、模块边界与最小新增

| 模块 | 本 Feature 职责与边界 |
| --- | --- |
| Desktop 登录界面 | 表单草稿、影响确认、过程和错误展示；不保存第二份模式／地址作为业务权威 |
| Desktop 原生层 | 核实本机目标，复用管理证明及受控重启；防止登录、目标切换与旧请求串入新的连接 |
| Runtime Host | 继续持有配置、鉴权、绑定、冲突检查与所有用户域生命周期；不把管理证明当作企业用户身份 |
| assistant-protocol | 优先复用 HostAccess 命令与状态；必要增量在技术方案核对全部生产者和消费者 |
| assistant-runtime／Agent Core | 沿用既有用户域、任务中断与恢复边界，不增加登录选项业务或配置副本 |

**删除本次新增机制后，现有事实是否已经足够？**

- 模式、地址、绑定与配置修订已经存在，足够承载需求，不新增数据库表、配置文件、模式缓存或独立版本字段。
- 原生管理权限和重启协调器已经存在，补登录前界面及衔接即可；不能新建匿名写接口或第二套进程管理。
- 已保存值与运行中状态已有各自来源，应组合展示，不新增“已生效配置”持久副本。
- 新增对话框及其短期交互状态是必要入口；优先复用既有 Dialog、选择控件、按钮和语义颜色。
  不为一个表单建设通用配置框架。

本机登录选项和登录后访问设置操作同一配置，使用相同校验、冲突和绑定契约；F02 自动构造清除意图，
不改变登录后访问设置或其他管理客户端的交互。
F01 手册描述最终真实行为，F04 为新对话框及所有状态统一配色；本 Feature 不自行增加主题设置。

## 七、验收标准

1. 新安装、已有个人／企业配置和企业登录失败时，本机 Desktop 均可从“这台电脑”卡片进入登录选项；
   状态读取不要求企业账号或业务 Runtime 初始化成功。
2. 普通 Web、远程客户端和仅持企业用户凭据的请求不能修改模式、中心或绑定；伪造本机地址不获授权。
3. 个人／企业模式与本机／远程目标标签明确区分；远程目标下不会误改另一台或本机 Host。
4. 读取、编辑、取消、无改动和窗口重新打开的值符合实际配置；企业地址格式与 Host 校验一致。
5. 保存模式或地址变更自动清除已有绑定，后续企业登录成功后重建；编辑态不显示绑定说明或清除选项。
   普通登录、初始化或无改动操作不清除绑定；切个人模式保留企业地址与原数据。
   覆盖同一表单企业→个人→企业的地址草稿保持，以及保存为个人模式、重启 Host／应用后再切回企业
   自动填回原地址；不能被空值或构建默认地址覆盖。
6. 保存前完整显示影响；非本地访问开启时经明确确认随保存关闭，重启后不自动恢复；其余访问配置不被覆盖。
7. 保存和重启按顺序执行，重复点击不会重复写入或重启；取消确认没有写入或停止副作用。
8. 配置冲突、保存失败、保存结果未知、重启失败与重连失败分别可辨并可恢复，不把部分完成说成整体成功。
9. 保存值不提前替代运行中模式；已有待重启改动可应用，重启后实际状态不符或未知时不能宣称已生效。
10. 重启影响本机 Host 全部用户；未知任务数量不显示为空闲，继续沿用受控关闭与原启动来源校验。
11. 个人与企业互切、双中心切换、同中心换址及返回旧中心后，数据按真实身份隔离并保留；
    不复制、删除或串用会话、附件、模型和原生资源。
12. 模式生效后登录字段正确，旧密码、登录响应及初始化结果不能进入新上下文；登录成功与业务初始化成功独立展示。
13. 登录选项与既有更新门禁、下载／安装和登录后访问设置协调，不放宽兼容检查，不竞争重启或改变更新来源。
14. macOS／Windows 的登录选项位于本机信息卡内，状态圆点与状态文字相邻；远程目标不显示本机登录选项。
    窄窗口、长连接状态、键盘焦点、错误提示及四套主题接入可核验，不与窗口控件和拖拽区冲突。
15. 首页账号菜单无“设置”选项；首次进入、已登录但初始化失败、断线退回首页及刷新恢复时，
    账号区、快捷键、原生菜单和残留弹窗均不能打开完整设置。返回首页时关闭原设置，进入工作区后
    完整设置正常可用；卡片按钮只打开登录选项，改密、退出及重试路径仍可用。
16. Desktop／Web 登录页均在 Logo 右侧显示 `ez-assistant`，图文整体居中；常规、窄及矮窗口下
    名称完整可读，表单可达，不引入副标题或重复版本号。

实现验证使用 `.runtime-test/` 下新建且核实无用户数据的隔离场景，不以真实用户目录做切换或恢复测试。
未实测的平台和故障组合按实际结果报告，不由编译通过推定完成。

## 八、后续设计、兼容与确认边界

本 Feature **需要技术方案**，在功能设计确认后明确：

- 登录前管理与重启如何接入现有连接 owner，清理旧请求、缓存和身份，避免迟到响应复用。
- 已保存配置、运行中能力与待重启状态的读取顺序；保存结果未知、重启失败及并发外部修改的回读判断。
- 登录后现有入口的共用边界，管理证明的完整服务端校验，以及应用更新与本次重启的互斥。
- 首页与工作区的设置入口、弹窗挂载和快捷键／原生菜单边界，清除退回首页后的残留设置状态；
  不只隐藏账号菜单文字而保留其他唤起路径。
- 现有状态是否足够表达待重启中心信息；如确需协议增量，列出 Rust／TS、Desktop／Web／Client 的影响，
  再决定兼容下限，不预先添加双读双写或历史字段别名。

本 Feature **需要界面交互设计指导**，明确卡片内入口、品牌图文组合、表单、影响确认、错误恢复和键盘焦点。
视觉沿用当前登录壳层和组件，主题由 F04 统一覆盖。以上确认后再进入开发计划。

本草案预期不改变数据库结构、用户域路径、Center 登录协议或既有配置格式；不提升企业协议下限。
已有用户数据的保持与模式切换行为需要独立验证，不能因无迁移就免除数据隔离检查。

本功能设计的产品取舍为：只在本机 Desktop 可编辑、主操作保存并重启、非本地访问随确认关闭且
不自动恢复、保存身份配置变更自动清除旧绑定、重启成功后仍由用户发起登录、无法启动时不增加离线修复入口。
