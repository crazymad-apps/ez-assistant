## 三、形成的核心能力

- `agent-context` 统一承担 Context Window 评估、有效 Conversation 布局、replacement
  校验和 Compression Strategy 扩展边界，业务代码不再裸算窗口比例。
- 模型的 `context_window_tokens` 作为统一模型参数，最近完整 Result 的
  `total_tokens` 作为窗口使用量权威来源。
- Agent Core 仍只承担单次 Run：每个 Model Step 调用前预检窗口，达到阈值或遇到
  Provider Context Overflow 时，以可靠 `CompactionRequired` 终态结束，不在 Core
  内主动压缩或续跑。
- 首期仅实现同模型 Rolling Summary。压缩提示词在生成压缩请求时追加，不修改原始
  system prompt 前缀；原始消息保持不变，Checkpoint 只存完整 replacement。
- 临时 Runtime Harness 通过唯一压缩入口验证 Run 前压缩、Run 内交接、Provider
  Overflow、continuation 和用户主动 `/compact`；主动压缩只压缩，不续跑。
- 未完成 Overflow Step 整体丢弃，以前一个完整 Step 为稳定边界，避免半配对 Tool
  Call/Result 和工具副作用重放。

## 四、偏差与边界

- Tool Result 裁剪、最近窗口裁剪、分层摘要和 Passthrough 均未在本版本实现，只保留
  Compression Strategy 扩展接口；相关输入继续保存在
  [`上下文裁剪压缩`](../../inputs/260729-上下文裁剪压缩.md)。
- `tools/runtime-harness` 仍是版本验证宿主，其 Session、Run、Checkpoint、任务链和
  CLI 语义不构成正式 Runtime 产品契约。
- 真实 Provider smoke 本轮未重新执行，因为需要外部凭据并可能产生费用；Provider
  Overflow fixture、scripted compression request 和真实 Core Loop 提供离线替代证据。
- debug-viewer 是独立开发工具，展示和事件保留行为不进入正式应用协议。
- 归档没有执行 `git add`、`git commit` 或 `git push`；提交准备等待用户另行授权。

## 五、遗留与后续入口

- 正式 `assistant-runtime` 的总体设计、持久化、并发调度和产品接口仍需后续版本单独
  讨论，不能直接复制 Harness 私有实现。
- 后续增加裁剪或其他压缩方案时，应复用现有 Layout、Evaluator、Strategy 和
  replacement Checkpoint，不在 Runtime 或 Provider 中重复实现 Context 算法。
- 下一目标版本为 `v0.4.0`（安全与执行控制）：启动前先核对输入池、Agent 系统技术
  架构和路线图范围，再形成独立功能设计。
