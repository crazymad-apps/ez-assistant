## 二、背景与目标

v0.2.0 已建立多 Step Agent Loop、两阶段 Tool Exchange Recorder 和规范对话；
v0.2.1 已提供累计版本 Harness、真实多轮工具 Chat 与分层调试。当前每次模型调用仍
无条件重发完整对话与工具定义，长会话最终会撞上模型上下文窗口。

v0.3.0 建立可验证的上下文能力闭环。正式能力落在 Agent/Provider 各 crate；尚未完成
总体设计的产品 Runtime 行为先由临时 Harness 验证：

- 用户输入落账后、Harness 创建 Run 前以及每次 Model Step 建立请求前，使用最近一次
  Provider Result 的 `total_tokens`、模型上下文窗口和统一阈值进行判断；
- 预算内请求保持现有语义，不发生额外模型调用；
- Run 创建前需要压缩时，Harness 先提交 Checkpoint 再创建本轮正常 Run；Run 内需要
  压缩时结束当前 Core 执行，压缩后创建 continuation；
- 首期使用当前会话同一个模型生成 Rolling Summary；
- Provider 明确报告 Context Overflow 时可以进入同一 Harness 恢复链；
- 原始 Conversation History 始终保留，模型上下文从最新 replacement Checkpoint
  稳定恢复；
- 为未来 Tool Result 裁剪等方案保留 Compression Strategy 接口，但不在本版本实现。

## 三、明确非目标

本版本不实现：

- 长期记忆召回、写入、向量检索或 Memory Plugin；
- 正式 `assistant-runtime` 的总体设计、公共 API、数据库、迁移、重启恢复或多设备
  同步；
- 通用任务 drain 循环、todo/ask_user、完成判据或 Length 自动续写；
- v0.4.0 的 Approval、Guardrail、权限和成本治理；
- 所有 Provider/模型的精确 tokenizer；
- 通用 Prompt 模板语言、Agent Profile 编辑器或桌面 UI；
- [`Tool Result 裁剪`](../../inputs/260729-上下文裁剪压缩.md)、最近窗口裁剪、分层摘要、
  多模型摘要或混合压缩的具体实现；
- Provider Adapter 或 Agent Core 内部的隐藏压缩、重试或 Runtime Run 调度。

## 四、功能范围与使用路径

### 4.1 预算内正常请求

用户输入落账后的 Harness Run 前检查，以及每个 Model Step 的 Core Preflight，都
复用统一 Context Window Evaluator。请求未达到压缩阈值或尚无可信 usage 时：

- 使用最新有效上下文直接建立模型调用；
- 不调用 Compression Strategy；
- 不生成新的 Checkpoint；
- 请求内容和消息顺序与 v0.2.x 等价。

“不压缩”是正常请求路径，不是一种名为 Passthrough 的 Compression Strategy。

### 4.2 预算阈值压缩

预算阈值有两条主动处理路径：

- 用户输入先写入 Conversation History；Harness 在创建本轮 Run 前发现达到阈值时，
  先压缩并提交 replacement Checkpoint，再创建本轮正常 Run。此时还没有旧 Run，
  不产生 CompactionRequired Run，也不叫 continuation。
- Core 在某个 Model Step 建立 Provider Turn 前发现达到阈值时，当前 AgentExecution
  以 CompactionRequired 可靠终态结束；未实际开始的 Step 不产生虚假的 StepStarted。
  Harness 压缩成功后创建不重复 UserMessage 的 continuation Run。

Core 不执行压缩，也不在原 AgentExecution 内重试。

### 4.3 Provider Overflow 恢复

Provider 在请求建立前或流内明确报告 Context Overflow 时：

1. Provider/Model 层只报告 provider-neutral 错误；
2. Core 把错误转换为与预算阈值相同的 CompactionRequired Agent 终态；
3. 当前未完成 Step 的临时 reasoning/text/tool-call 增量整体丢弃；
4. Harness 以上一个完整提交点为稳定事实执行统一压缩；
5. 压缩成功后创建 continuation；恢复次数耗尽或无法压缩时受控失败。

认证、限流、传输、协议和普通 Provider 错误不进入该恢复链。

### 4.4 用户主动压缩

用户可以通过 Harness 的 `/compact` 开发入口主动压缩当前 Session：

- 指令不作为 UserMessage 写入 Conversation History；
- Harness 调用与自动恢复完全相同的私有压缩编排入口；
- 成功只提交 Checkpoint 并返回压缩结果；
- 成功、无可压缩内容或失败都不创建 Run/AgentExecution，也不自动续跑；
- 当前 Session 有活动用户任务链时，主动压缩按同会话串行规则等待，不并发修改
  对话或 Checkpoint。

### 4.5 Rolling Summary

首期唯一实现的 Compression Strategy 是 `RollingSummarySameModel`：

- 使用当前会话已经绑定的同一个模型；
- 只压缩较早且结构闭合的历史；
- 当前用户输入、当前执行尾部和必要近期历史的模型可见内容与 ProviderState 原样保留；
- compression request 不携带工具、不进入 Agent Loop，也不回答用户问题；
- 只有存在可压缩 head，且摘要完整、非空、replacement 结构合法时才能形成
  Checkpoint；
- 再次压缩时，旧 Summary 与后续可压缩历史共同形成新的 Summary。

摘要必须保留用户目标、关键约束、已确认事实、重要完成结果和未完成事项，不得写入
credential 或原材料中不存在的事实。

### 4.6 Conversation History 与 Checkpoint

Harness Conversation History 是本版本验证中的权威原始事实，压缩前后不删除、
不覆盖、不修改原始
消息。Context Checkpoint 是派生状态：

- payload 只保存一份完整、可独立发送的 replacement；
- Checkpoint 在 Harness 有序记录中的提交顺序就是上下文边界；
- 不增加 `covers_through`、revision、父 Checkpoint、strategy、model 或 usage 字段；
- 后续有效上下文使用最新 replacement，再拼接 Checkpoint 之后新增的规范消息；
- UI 会话展示仍读取原始消息，Checkpoint 不伪装成聊天消息。

策略、模型、usage 和窗口判断进入运行报告与调试事件，不是恢复上下文所需的数据。

### 4.7 单一压缩入口

Run 前预算阈值、Run 内预算阈值、Provider Overflow 和用户主动请求必须复用 Harness
同一个私有压缩编排入口。该入口统一负责：

- 读取最新有效上下文；
- 调用已选择的 Compression Strategy；
- 校验 replacement；
- 提交 Context Checkpoint；
- 返回结构化结果。

四条路径的差异只存在于调用原因、恢复次数和结果后的 Harness 调度：

- Run 前预算阈值：成功后创建本轮正常 Run；
- Run 内预算阈值/Provider Overflow：成功后创建 continuation；
- 用户主动压缩：任何结果都不 continuation。

禁止复制上下文切分、compression request、replacement 校验或 Checkpoint 提交逻辑。

### 4.8 Tool Call/Result 与 Provider 状态

压缩只能在结构完整的历史边界发生：

- Tool Call 与其全部 Tool Result 必须保持配对和顺序；
- reasoning、文本、多个 Tool Call 与 Provider continuation state 的相对顺序不变；
- 当前未完成 Provider Step 不进入 Conversation History；
- 此前完成的工具副作用不会因压缩恢复而重放；
- replacement 不能包含悬空 Tool Call 或孤立 Tool Result。

## 五、模块边界与契约影响

### `agent-context`

- 提供基于 Provider `total_tokens` 的统一窗口判断、Context Preflight、
  原子历史块、replacement 校验和 Compression Strategy 边界；
- 实现 `RollingSummarySameModel`；
- 不知道 Session、Run、Checkpoint Store、Provider Adapter 或 Tauri。

### `agent-core`

- 每个 Model Step 建立请求前调用 Context Preflight；
- 将预算阈值和 provider-neutral Context Overflow 收敛为 CompactionRequired 终态；
- 丢弃当前未完成 Step，不发起压缩、不提交 Checkpoint、不创建 continuation；
- 保持现有 Tool Recorder、Authorizer 和副作用顺序。

### `agent-types` / `agent-model`

- `agent-types` 提供可识别的 Context Summary 规范消息；
- `agent-model` 提供 Context Overflow 错误语义、模型
  `context_window_tokens` 参数和上下文所需能力声明；
- 两者不依赖 Runtime、存储或具体 Provider。

### `agent-provider-openai-compatible`

- 编码 Context Summary，并继续保证 Tool Call/Result 与 DeepSeek reasoning 状态保真；
- 将 fixture 已确认的原生上下文过长错误映射为 Context Overflow；
- 不发布 AgentEvent，不压缩、不重试。

### `agent-testkit` / `runtime-harness` / `debug-viewer`

- testkit 提供可配置窗口、脚本化 TokenUsage/模型事件和断言辅助；
- Harness 使用私有 Checkpoint、任务链与压缩编排类型验证完整闭环并增加 `/compact`；
- 这些 Harness 类型只作为行为样例，不进入 `assistant-runtime` 或应用协议；
- debug-viewer 消费新增事件和 Harness Runtime 报告，不持有上下文业务状态。

## 六、关键取舍

- **压缩编排先由 Harness 验证**：Core 只负责一个 AgentExecution；本版本所有压缩
  经过 Harness 同一个私有入口，正式 Runtime 如何承接留待总体设计。
- **新增第四种终态**：CompactionRequired 在生命周期上结束当前执行，但不是成功回答
  或普通失败，Harness 可验证上层后继动作。
- **完整 replacement Checkpoint**：恢复只依赖最新派生快照和外层提交顺序，不维护
  多余位置或父子字段。
- **用户输入先成为上层事实**：continuation 不重复追加 UserMessage，Core 不把
  UI 输入当作自己的持久化事实；Run 前压缩发生在 UserMessage 落账之后。
- **真实 usage 判断窗口**：只使用最近完整 Provider Result 的 `total_tokens` 与当前
  模型直接配置的 `context_window_tokens`，比例计算集中在共享 Evaluator，不引入
  本地 TokenEstimator。
- **同模型滚动摘要**：首期不增加摘要模型配置，所有额外调用可观察且受显式预算控制。
- **不实现 Passthrough Strategy**：预算内请求自然直通，避免空操作策略。
- **裁剪只留接口**：本版本先稳定 Strategy、replacement 和校验边界，具体方案进入
  后续版本。
- **共享 Context 组件独立**：Core、Harness 与未来 Runtime 必须复用同一预算和校验
  规则，物理组织与接口详见技术方案。

## 七、验收标准

1. 用户输入落账后、Run 创建前和每个 Model Step 都经过共享 Context Window
   Evaluator；
   预算内请求不发生摘要或额外模型调用，并与 v0.2.x 请求语义等价。
2. 窗口判断严格使用最近完整 Result 的 `total_tokens / context_window_tokens`；模型
   窗口是 ModelService 参数，比例计算只能经过统一 Evaluator，并产生可核对报告。
3. v0.3.0 只实现 `RollingSummarySameModel`；不存在 Passthrough 或 Tool Result
   裁剪实现。
4. Run 前达到阈值时先压缩再创建本轮正常 Run，不产生空的 CompactionRequired Run；
   Run 内预算阈值在 Provider Turn 前产生 CompactionRequired；Provider Overflow 在
   建立前和流内都能转换为同一 Agent 终态；普通错误仍为 Failed。
5. 每个 AgentExecution 恰有 Completed、Failed、Cancelled、CompactionRequired 四种
   终态之一，观察者断开不影响可靠结果。
6. Harness 四条压缩路径复用同一私有核心入口；测试能够证明共享 Context 算法没有
   分叉实现。
7. Run 前自动压缩成功后创建本轮正常 Run；Run 内自动压缩成功后创建 continuation，
   两者都不重复 UserMessage；用户主动压缩在所有结果下都不创建 Run 或
   continuation。
8. 原始 Conversation History 在压缩前后不变；Checkpoint 只保存完整 replacement，
   后续请求可从最新 Checkpoint 稳定恢复。
9. Summary head 与 recent tail 只在闭合历史边界切分；replacement 不破坏
   Tool Call/Result、reasoning、Provider State 和消息顺序。
10. Provider Overflow 所在未完成 Step 被丢弃，不执行其中的 Tool Call，也不重放此前
    完成的工具副作用。
11. 压缩结果为空、截断、产生 Tool Call、没有可压缩 head、次数耗尽、取消或 Store
    失败时
    不提交无效 Checkpoint，也不形成隐藏重试。
12. `runtime-harness verify v0.3` 完全离线覆盖短上下文、Run 前阈值压缩、Run 内阈值
    压缩、Provider Overflow、用户主动压缩、多次滚动、同会话串行和不可压缩失败，
    并继续回归 v0.2。

## 八、风险、兼容性与待确认项

### 风险与控制

- **usage 滞后或缺失**：最近 Result 尚未包含后续新增的 User/Tool 消息；不在业务层
  猜测 token，以规范 Overflow 恢复兜底。
- **摘要遗漏或幻觉**：原始历史保留；Summary 明示派生；近期和当前执行上下文原样
  保留；空摘要或非法结果不提交。
- **隐藏模型费用**：只有显式策略触发或用户主动请求才调用摘要模型；报告模型、usage
  和结果。
- **无限压缩循环**：Harness 管理显式恢复次数；NoOp、失败和次数耗尽不 continuation。
- **跨层重复实现**：共享 Context 规则只有一份；Harness 的私有编排只组合共享能力，
  不复制窗口、布局、校验或滚动摘要算法。
- **Provider 误判**：只映射结构化、fixture 已确认的错误，不按任意文本猜测。
- **公共契约变更**：所有生产者、消费者、序列化、调试和回归测试必须同步更新。

### 兼容性

- 短上下文保持 v0.2.x 消息顺序和工具循环语义；
- 原始 Conversation History 与两阶段 Tool Exchange Recorder 语义不变；
- Context Summary 是新增规范类型，Provider Codec 必须显式处理或拒绝；
- Runtime Harness 的 v0.2 场景继续保留，v0.3 验证是累计能力基线。
- `assistant-runtime` 保持原有空骨架和依赖，不把 Harness 私有类型视为产品兼容契约。

### 待确认项

无功能范围待确认项。实现级类型、依赖、算法和测试设计以关联技术方案为唯一来源。
