## 四、关键路径审查

### 4.1 窗口判断与请求边界

- `ContextWindowEvaluator` 从最近完整 Assistant Result 读取 `usage.total_tokens`，
  从当前 `ModelService` 读取 `context_window_tokens`；
- usage 缺失返回 `UsageUnavailable`，不回退 TokenEstimator 或业务层估算；
- Core 在 `StepStarted` 和 Provider 调用前完成判断；
- Harness 在 UserMessage 落账后、创建初始 Run 前复用同一 Evaluator；
- 预算内路径不调用 Strategy，不增加 Checkpoint 或额外模型请求。

### 4.2 四种终态与 Overflow

- `AgentExecution` 可靠结果和终态事件均为 Completed、Failed、Cancelled、
  CompactionRequired 四选一；
- 阈值命中发生在 Provider Turn 前；
- Provider 建立前与流内结构化 Context Overflow 都映射到 CompactionRequired；
- 普通 Provider/模型错误保持 Failed；
- 流内 Overflow 的未完成 delta、Tool Call 不进入规范历史，也不触发工具副作用；
- 已完成 Tool Exchange 已落账且 continuation 不重放其副作用。

### 4.3 Rolling Summary 与 replacement

- v0.3.0 唯一生产策略是 `RollingSummarySameModel`；
- 正常 system instructions 保持不变，压缩指令作为临时 Injected User Part 追加；
- compression request 使用当前模型、空 tools、`ToolChoice::None` 和显式输出上限；
- 只有 Stop、无 Tool Call、存在非空 Text 的完整响应可以形成 Candidate；
- replacement 保留 System prefix、一个最新 Context Summary 和完整 recent tail；
- Tool Call/Result、reasoning、ProviderState 和消息顺序由 Layout/Validator 保证；
- 原始 Conversation 不被修改，retained Assistant 的旧 usage 只在派生 replacement
  中清除。

### 4.4 Checkpoint 与三类调度

- Checkpoint payload 只包含完整 replacement；
- 原始 Message 记录始终保留，effective snapshot 从最新 Checkpoint 开始投影；
- Candidate 校验成功后才在同一 Journal 临界区追加 Checkpoint；
- Store 失败、取消、NoOp、非法摘要和次数耗尽都不提交无效 Checkpoint；
- Run 前压缩返回 Initial context，Run 内交接返回不重复 UserMessage 的 Continuation；
- 用户主动压缩不接收 Run/continuation 规划参数，所有结果都不续跑。
