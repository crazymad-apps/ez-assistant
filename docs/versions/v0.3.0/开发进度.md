### 功能设计

- 目标：定义上下文预算、Runtime 多压缩策略出口、同模型滚动摘要
  与 Provider overflow 恢复的完整能力闭环。
- 状态：✅ 已确认（2026-07-29；用户明确进入技术方案阶段）
- 实际结果：已核对现有四字段 `ExecutionSpec`、机械 `build_request`、Conversation
  类型、Provider 错误、Journal/Recorder 边界、v0.2.1 Harness 与长任务输入；创建
  `功能设计.md` 初稿。
- 讨论修订：按用户结论取消 v0.3.0 Tool Result 裁剪实现，只保留策略扩展点；首期
  使用当前会话同一模型发起无工具 compression request；采用方案 A，Checkpoint 只含
  完整 replacement，不使用 `covers_through`；同一会话上下文写入保持串行，不维护
  revision 竞争检查或显式摘要父子关系。上层负责多 Run 调度和唯一压缩链路；
  UserMessage 落账后、创建 Run 前先复用 Context Window Evaluator，以最近完整
  Result 的 `total_tokens / context_window_tokens` 判断窗口，达到阈值时先压缩、提交
  Checkpoint，再创建本轮正常 Run。Core 在每个 Model Step 建立请求前继续执行同一套
  窗口预检，达到阈值或收到 Provider Context Overflow 时，以第四种
  可靠终态 CompactionRequired 结束当前执行。上层丢弃当前未完成 Step，以上一个
  完整 Step 为稳定边界执行压缩、提交 Checkpoint，再创建不重复 UserMessage 的
  continuation。Provider 已有 TurnFailed 终态，v0.3
  增加 provider-neutral ContextOverflow 分类；Tool Call 只有 TurnFinished 后才落账
  和执行，因此 overflow Step 不产生半配对。用户主动压缩作为上层同会话串行的
  上下文维护操作，直接执行压缩并提交 Checkpoint，不写 UserMessage、不创建
  AgentExecution，且成功/no-op/失败都不自动续跑。Run 前阈值、Run 内阈值、
  Provider Overflow 和用户主动压缩四条路径复用同一 `compact_context` 语义入口，
  复用 head/tail 选择、compression request、
  replacement 校验和 Checkpoint 提交；轻量调用封装只负责 cause 与续跑后处理。
- 2026-07-30 边界修订：正式 `assistant-runtime` 尚未进行总体设计，上述上层行为
  在 v0.3.0 只由 `runtime-harness` 私有验证，不形成产品 Store、Run、任务链或压缩
  API；正式 Runtime 的接口与持久化设计后续单独讨论。
- 当前结果：功能设计已按能力视角重写；实现级类型、接口、状态机、预算字段、存储
  结构、Provider 编码和测试矩阵迁移至技术方案，功能设计只保留范围、使用路径、
  跨层职责、关键取舍和验收。

### M4：同模型滚动摘要与 Provider Overflow

- 状态：✅ 已完成（2026-07-29；用户确认继续）
- 目标：实现当前版本唯一的 `RollingSummarySameModel` 压缩策略，并完成
  OpenAI-compatible 结构化 Context Overflow 映射。
- 实际产出：
  - `RollingSummarySameModel` 复用既有 `CompressionStrategy`、`ContextLayout` 和
    replacement validator；用当前 ModelService 发起一次空 tools、
    `ToolChoice::None`、显式 `summary_output_tokens` 的 compression request，不进入
    Agent Loop；
  - 评审修订：`CompactionInput` 增加正常 Agent instructions；compression request
    不再用压缩指令替换 system prompt，而是原样保留正常 instructions，并由 Strategy
    内部在 `protected prefix + compressible head` 后追加临时
    `UserPart::Injected` 压缩指令。调用方不组织临时 conversation，recent tail
    只用于 Candidate，不发送给压缩模型，从而保持可复用的 Provider 请求前缀；
  - 只接受 `Stop`、无 ToolCall、至少一个非空 TextPart 的完整响应；Reasoning 不进入
    摘要正文，Length/空摘要/ToolCall 均返回 `InvalidResponse`，取消、普通模型错误和
    ContextOverflow 不重试并保留规范分类；
  - 首次摘要和再次滚动摘要都生成
    `protected prefix + ContextSummary + recent tail`；Summary 复用 compression
    AssistantMessage ID，报告保留模型 identity、usage 与准确 head/tail 块数；
  - 候选仅清除派生 replacement 中 retained Assistant 的旧 usage，原始 snapshot
    不变；近期完整多 Tool Exchange 的顺序、配对和消息内容保持不变；
  - OpenAI-compatible Error Decoder 只对结构化 code/type
    `context_length_exceeded` 精确映射 ContextOverflow，不匹配 message 文本；
