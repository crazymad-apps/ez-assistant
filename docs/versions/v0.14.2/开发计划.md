# v0.14.2 开发计划：设置、原生生命周期与发布收口

## 一、计划信息与设计依据

- 版本：`v0.14.2`
- 状态：已完成并归档；M0–M4 与版本验收均已通过
- 前置计划：[`v0.14.0`](../v0.14.0/开发计划.md)、
  [`v0.14.1`](../v0.14.1/开发计划.md)
- 统一功能范围：[`统一功能设计`](../v0.14.0/功能设计.md)
- 统一实现依据：[`统一技术方案`](../v0.14.0/技术方案.md)
- 视觉依据：[`桌面端设计语言`](../../resources/桌面端设计语言.md)与已确认亮色 Demo

本计划是统一桌面 MVP 的最终收口版本：补齐 Runtime 诊断、模型和权限设置，落实窗口、菜单、托盘、
关闭/退出/停止 Runtime 的原生语义，并完成安全、可访问性、性能和当前目标平台发布验收。

本版本不重新设计 `v0.14.0`、`v0.14.1` 已完成的主会话、资源或子 Agent 业务。开始前必须根据前序
版本实际结果复核命令、依赖版本和平台打包条件；Windows 仍只保留兼容边界，不进入正式开发与验收。

## 二、推进原则

1. M0 至 M4 顺序推进，每个里程碑完成实现和验证后等待用户确认。
2. 设置页编辑 Runtime 的唯一配置/权限源，不建立 Desktop 数据库或 LocalStorage 副本；保存成功
   必须以 Runtime revision 和新快照为准。
3. 窗口按钮、系统菜单、快捷键和托盘统一进入 Tauri Rust 生命周期协调器；WebView 只表达意图。
4. 关闭窗口、退出客户端和停止 Runtime 始终是三个动作；任何入口都不默认停止 Runtime。
5. WebView capabilities 按最小权限配置，主页面不获得通用 Shell、文件、opener 或任意远程 HTTP 权限。
6. M3 先完成组件和页面的系统性质量收口；M4 才执行当前发布目标 bundle 与完整桌面 MVP 验收。
7. 不为通过验收重新加入 Demo/Mock 路径；不主动执行 Git 暂存、提交或推送。

## 四、里程碑台账

### M0：设置外壳、Runtime 状态与模型管理

- 前置：`v0.14.1` 已完成并归档；本计划复核并确认；当前版本进入 `开发中`。
- 目标：让用户在统一设置弹窗中诊断 Runtime，并安全完成模型配置全生命周期。
- 交付范围：
  - Settings modal route、固定侧栏、统一最小 Header 高度、淡色返回按钮、dirty guard 和焦点恢复；
  - Runtime 版本、连接、instance、capability、配置有效性、重连/重启/停止影响摘要和安全诊断复制；
  - 模型列表、Create/Edit/Delete、默认模型、连接测试、引用阻塞和 replacement 流程；
  - 配置文件 revision/CAS、candidate 编译、原子发布、Registry swap 和外部修改冲突；
  - API Key 专用写入 DTO、脱敏回显、表单生命周期清理和失败关闭；
  - Composer 模型选择器与设置列表消费同一 Runtime 模型安全投影。
- 验证入口：

  ```bash
  cargo test -p assistant-protocol -p assistant-runtime -p assistant-runtime-host --all-features
  cargo clippy -p assistant-protocol -p assistant-runtime -p assistant-runtime-host --all-targets --all-features -- -D warnings

  cd apps/desktop
  npm run lint
  npm run test
  npm run build
  ```

- 完成判定：新增、编辑、删除、默认值、连接测试和冲突恢复均形成真实闭环；无效新配置不继续用旧
  凭据执行新 Run；API Key 不进入投影、日志、可恢复 draft 或生成示例。
- Review 重点：双配置源、secret 回显、删除被引用模型、保存文件成功但 Registry 未更新、Header 跳动。
- 技术依据：功能设计 F18–F20；技术方案 3.6、第十一、15.3、16.1 和 17.2。

### M1：Session/Workspace 权限文档管理

- 前置：M0 已确认。
- 目标：提供与 Runtime Authorizer 一致的可编辑 Session/Workspace 权限入口，不制造更高权限层。
- 交付范围：
  - Permission 公共 DTO、Session/Workspace 文档读取、规则列表/编辑/删除和 CAS replace；
  - Global 只读投影与显式 reload，不提供“全局允许”快捷入口；
  - matcher、effect、capability、来源和校验错误的安全展示；
  - invalid draft、外部修改冲突、Registry 替换失败和未保存离开；
  - 规则更新后由 Runtime 重新核验待审批队列，只自动通过精确匹配项；
  - Ask/Auto 选择器文案与权限设置对默认允许、Deny/Ask/Guardrail 上层约束保持一致。
- 验证入口：

  ```bash
  cargo test -p assistant-protocol -p assistant-runtime -p assistant-runtime-host --all-features

  cd apps/desktop
  npm run lint
  npm run test
  npm run build
  ```

- 完成判定：Session/Workspace 权限可安全管理，Global 只读；并发修改不静默覆盖；权限保存、审批队列
  drain 和后续工具授权均以 Runtime 规则为准。
- Review 重点：Desktop 重新实现 matcher、Auto 被描述成全权限、Global 越权编辑、规则更新错误放行队尾项。
- 技术依据：功能设计 F21、F11、F14；技术方案第九、十二和 15.3。

### M2：窗口、菜单、托盘与 Runtime 生命周期

- 前置：M1 已确认。
- 目标：将所有桌面入口收敛到一致的原生生命周期，并保持 Runtime 与客户端进程解耦。
- 交付范围：
  - macOS 原生 traffic lights、overlay/transparent title bar、系统菜单和标准编辑行为；
  - Linux 无边框按钮、拖动/双击标题栏、最大化状态、Tooltip、键盘焦点和可访问名称；
  - 原生 Menu/Tray：显示窗口、Runtime 状态、停止 Runtime、退出客户端；
  - 关闭窗口、退出客户端、退出并停止 Runtime、重启 Runtime 的统一协调器和影响确认；
  - Runtime detached launch、单实例收敛、客户端退出后继续运行、显式 shutdown 和新 instance 重连；
  - window state 与设备级关闭偏好的原子保存；危险的“同时停止 Runtime”不持久化为默认值；
  - 平台私有 Adapter 边界 Review，不实现 Windows 空壳或宣称 Windows 支持。
- 验证入口：

  ```bash
  cargo test -p assistant-runtime-host -p ez-assistant-desktop --all-features
  cargo clippy -p assistant-runtime-host -p ez-assistant-desktop --all-targets --all-features -- -D warnings
  cargo fmt --all --check

  cd apps/desktop
  npm run test
  npm run tauri -- build --no-bundle
  ```

- 完成判定：所有关闭入口进入同一语义；默认退出客户端不停止 Runtime；停止/重启期间不接受新工作；
  失败时保留诊断入口；当前 macOS/Linux 目标的窗口与托盘人工矩阵有实际证据。
- Review 重点：Tauri child handle 退出时误杀 Host、按 PID 强杀、菜单与 Web 按钮语义分叉、平台类型泄漏。
- 技术依据：功能设计 F01、F23；技术方案第四、14.2–14.3 和 18.3–18.4。

### M3：桌面安全、可访问性、视觉与性能收口

- 前置：M2 已确认。
- 目标：把统一设计从“功能可用”收敛到可长期维护和可安全发布的桌面体验。
- 交付范围：
  - Tauri capabilities、CSP、外部导航拦截、窄 native command 与日志/诊断脱敏；
  - Dialog、Menu、Listbox、RadioGroup、Disclosure、Tooltip、InlineEdit 的键盘、role、focus trap
    和关闭后焦点恢复；
  - `prefers-reduced-motion`、颜色对比、screen reader label 和缩放下的可读性；
  - 逐页对照设计语言清理冗余文案、死控件、错位、裁切、二级抽屉遮挡和不一致 Header；
  - 长 Conversation、连续 delta、Streamdown Code/Math/Mermaid、分页 prepend 和 Store dispose 性能；
  - bundle 体积、主线程长任务、输入响应、滚动稳定性和内存泄漏记录。
- 验证入口：

  ```bash
  cd apps/desktop
  npm run lint
  npm run test
  npm run test:e2e
  npm run build
  npm run tauri -- build --no-bundle
  ```

- 完成判定：核心页面可完全使用键盘操作，焦点与选中图标不裁切；100%、125%、150% 和窄窗口
  通过视觉核对；长流输出没有不可接受的整树重渲染或输入阻塞；WebView 无通用本机权限。
- Review 重点：为便利放宽 CSP/capability、组件各自实现不一致键盘逻辑、只在浏览器而非目标 WKWebView
  测性能、视觉修复覆盖业务状态。
- 技术依据：功能设计 F24、12.6；技术方案 6.3、6.7、17.1–17.3、19.3。

### M4：当前目标平台打包与统一 MVP 验收

- 前置：M3 已确认。
- 目标：对 `v0.14.0`–`v0.14.2` 统一设计范围执行最终回归、真实 Host 集成和当前目标平台发布验收。
- 交付范围：
  - 功能设计 12.1–12.6 每条验收项到自动测试、人工步骤或明确未执行原因的映射；
  - workspace 全量 fmt/clippy/test、Desktop lint/test/build、Tauri 构建和实际 bundle；
  - 临时正式 Host 的启动/重连、主会话、队列、审批、Session/资源、子 Agent、模型/权限和退出矩阵；
  - 旧 v0.13 Runtime Home 副本的 additive migration、历史缺字段与损坏/冲突诊断；

  - 生产产物确认无 Web Demo、Mock fixture、DevTools、凭据或宽泛 capabilities；
  - 创建 `v0.14.2` 验收记录前的版本总结素材、偏差、遗留和后续 Windows 入口。
- 验证入口：

- 完成判定：统一功能设计全部验收点均有证据；三版本累积回归通过；当前发布目标 bundle 可安装并
  连接随包 Runtime；所有未执行项、偏差和风险均已明确，不以浏览器 Mock 代替正式链路。
- Review 重点：只跑 `--no-bundle` 却宣称发布完成、真实数据污染、旧数据迁移无副本验证、平台证据缺失。
- 技术依据：功能设计第十二–十四节；技术方案第十九–二十二节。
