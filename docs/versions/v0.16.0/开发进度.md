### M0：模型协议与能力编译底座

- 状态：✅ 已完成（2026-08-19 用户确认）

  - `agent-provider-openai-compatible` 已整体迁移为 `agent-openai-compatible`，生产依赖与当前模块文档
    不再使用旧名称；公开扁平 Profile 已替换为字段私有的 `ProtocolAdapter` 与
    `ReasoningReplayPolicy`。
  - Host 随包只读 `resources/model-catalog.json` 在启动前严格解析并注入 Runtime；Runtime 按
    `(provider, protocol, model_id)` 精确匹配并编译唯一能力事实。
  - 用户 capability override、目录与协议保守基线优先级已实现；reasoning 整块替换，effort map
    校验五档 key、label、字符串/正整数 wire value、重复实际强度和默认档位。
  - 旧 `chat_completions` 可读取并归一化，新模型配置写入 `openai_chat_completions`；未知协议失败。
  - 可靠性 Trace 新写 `protocol_adapter`，并通过 serde alias 继续读取旧 `profile` 字段。
- 验证：
  - `cargo test` 覆盖 Adapter、Runtime、Host、reliability/core/memory/runtime-harness/safety Demo：通过；
    真实 Provider 和手工性能测试按既有 `ignored` 约定未执行。
  - 上述 package 全目标、全 feature Clippy `-D warnings`：通过。
  - `cargo check --workspace --all-targets`、`cargo fmt --all --check`、Host `--help`、
    `git diff --check`：通过。
  - `cargo metadata --no-deps` 与源码检索：当前生产依赖不存在旧 crate/package 标识。
- 偏差/遗留/风险：M0 未实现图片 I/O、Session effort 或 Desktop UI，符合计划。

    缓存统计或输入为零时保持“未提供”，上下文压缩后的历史 Usage 同样保留该未知语义。
