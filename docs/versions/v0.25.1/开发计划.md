参数默认值、厂商上限、用户运行限制与接入套餐分别验证，不自动导入旧配置或建立静态目录。

## 二、台账与实施原则

1. 2026-09-10 用户授权进入 M4 验收；M5 归档仍需验收确认。按 M0—M5 顺序推进，每个里程碑完成后标为
   `🟨 待确认`，汇报实际结果，用户确认后标为 `✅ 已完成` 再进入下一项。
2. M0—M3 为取证与实现，M4 为版本验收，M5 为归档。进入 M4 前状态改为 `验证中`，M5 完成后
   才标记 `已完成`。过程中的构建成功不能代替用户确认。
3. 先验证接口事实，再建立迁移基础和启动诊断，最后统一切换模型系统。旧字段删除、所有正式
   读写消费者替换和首次迁移启用必须在 M3 一起完成；不能先上线删除列的迁移，再让旧 Runtime
   读取它，也不能通过保留旧列、别名或双写跨越这一断点。
4. M1 的迁移器先在隔离夹具中运行，M2 的启动状态先接入现有初始化并通过夹具覆盖升级阶段。
   正式 v0.25.1 初始 SQL、版本号更新与自动迁移启用均在 M3 完成。M0—M2 中间构建不是可分发
   的 v0.25.1 升级包，不提前给用户目录执行未完成的初始迁移，也不新增产品兼容开关。
5. 代码开工前读取对应语言和模块规范，核对真实调用链；新增类型和依赖随实际消费者引入。
   模型、存储和执行边界遵守 Runtime 单一 owner，UI 不直连服务商或数据库。
6. 所有自动化使用显式临时 Runtime Home 和人工构造的数据库／配置夹具，不读取或复制用户库
   作为默认测试数据。实际数据库操作仍遵守根 AGENTS.md 的核对、确认、备份与停止规则；
   本计划不是操作 `~/.ez-assistant` 或 `.ez-assistant-dev` 的授权。
7. 真实接口取证只使用获准用于联调的连接，凭据不进入文档、夹具或日志；没有可用访问条件则
   记录具体缺口，不能用 Mock 证明真实服务商已支持。需要改变接入范围或参数规则时先报告并
   修订设计；用户现已授权显式参数编辑／固定，不恢复静态自动填充、旧配置导入或失败目录缓存。
8. 每项同步必要的边界注释与长期规范，保留用户现有改动。未获明确要求不暂存、提交、推送、
   签名、公证或公开发布；验收构建与正式分发分开记录。

### 验证入口约定

按用户 2026-09-09 最新要求简化日常验证：先执行必要编译／静态检查，并按功能点通过隔离 Web 端验证；单元测试集中到 M4 版本验收阶段执行，不逐项新增或反复运行。
通过后不反复扩大到全仓、Host 启动、GUI 或真实服务商。只在修改影响相应链路或出现失败证据时
补充该层验证；完整验收集中在 M4。数据库相关验证始终使用人工模拟库，不操作生产环境。


命令从仓库根运行。以下命令已核对当前 package 与脚本名称；实际用例、输出和未执行原因记入
本地进度。每个里程碑按变更执行最小有效测试，已有证据没有被新改动影响时不机械重复。

| 范围 | 验证入口 |
| --- | --- |
| Host／存储／模型接入 | `cargo test -p assistant-runtime-host`，按实际模块使用定向测试过滤 |
| Runtime／协议／Adapter | `cargo test -p assistant-runtime -p assistant-protocol -p agent-openai-compatible`，检查受影响消费者 |
| Rust 公共契约、并发与跨模块改动 | `cargo fmt --all --check`；按受影响 package 执行 `cargo test -p <package>` 和局部 Clippy；完整 workspace 门禁集中在版本验收 |
| 应用 DTO | `npm --prefix apps/desktop run generate:protocol`，再运行 `npm --prefix apps/desktop run check:protocol` |
| 前端 | `npm --prefix apps/desktop run test -- <定向用例文件>`、`npm --prefix apps/desktop run build` |
| 正式 Host 的 Desktop／Web 集成 | `npm --prefix apps/desktop run test:e2e -- <定向用例文件>`、`npm --prefix apps/desktop run test:e2e:web -- <定向用例文件>`，先核对测试 Runtime Home 隔离 |
| 原生打包构建 | `npm --prefix apps/desktop run tauri -- build --no-bundle`；涉及原生行为补正式 WKWebView 证据 |
| 文档 | 本地链接、路径、状态、验收覆盖和差异空白检查 |

表中的定向用例文件是实施时选定的测试路径，不是可直接照抄的文件名。前端测试沿用应用级 tests
目录，数据库故障注入留在 Host 存储／启动测试，不建立新的长期验证产品。

## 四、里程碑明细

### M0：在线模型接口与参数取证

**目标：** 验证在线列表、可获取的元数据与厂商文档，明确用户固定参数补齐后的执行规格来源。

**前置依赖：** 本计划已确认；涉及真实请求时已有可用且获准联调的服务商连接。

**交付范围：**

- 核查当前服务商适配范围，为每类记录列表／详情接口、必要参数来源、统一方言与能力差异。
  必须区分真实返回、官方文档说明和本地 Mock，不将它们合并成“已支持”。
- 在现有 Host 模型资源边界完成在线发现与标准化解析的首个可验证实现及脱敏夹具；只增加
  本阶段实际调用的能力，不提前切换数据库、TOML 模型来源或正式设置界面。
- 验证上下文窗口、输出上限、图片／工具／推理能力等实际来源，以及缺字段可编辑、非法值拒绝和不支持
  接口时的明确反馈。移除逐模型方言分支的具体替代映射在技术方案中补齐。
- 在技术方案对应节补充取证矩阵；没有必要字段的服务商记录缺口与官方文档，不默认缩小发布范围；区分接口缺字段与用户固定参数未配置。

**验证入口：** Host 模型模块测试、相关 Adapter 测试、获准连接的定向真实发现请求；按第二节
执行实际改动门禁。真实推理仅做验证当前规格所需的最小调用，不借此调用用户工具或运行工作任务。

**完成判定：** 至少有真实在线模型与明确参数来源构成的规格链路；接口不全时可使用用户明确
固定的有效运行参数，不能以静默预置数值补齐。拟支持接入类型的字段／文档／套餐限制逐项记录；
固定优先、重置回在线与缺参数反馈的解析契约有验证。完整数据库和界面闭环仍归 M3。
旧纯在线参数门禁仅是缺口诊断，不再要求所有服务商在线返回全部字段，也不将旧失败改记成功。

**Review 重点：** 是否偷偷使用静态参数、模型名猜测能力或任意错误跨协议重发；真实凭据和响应
是否泄漏到夹具；取证结论是否超过证据范围。对应 A03—A07。

**当前进展（2026-09-08）：** M0 修订实现与验证完成，用户已确认，标为 `✅ 已完成`。显式路径／格式已贯通，
六个远端连接的模型列表解析通过，本地 vLLM 未启动。固定参数解析有四项测试覆盖固定优先、
快照、重置后的在线分支及非法值；Host 在线解析另含 Kimi 字段测试。一次百炼最小真实文本调用
通过，参数仅固定在隔离测试内存，未写用户数据库。常规 workspace 测试 1,417 项通过、26 项
按设置忽略；真实固定参数测试另行显式执行 1 项通过。旧纯在线诊断仍 7/7 无法得到完整规格，
保留为已知缺口，不记成功。技术细节见[技术方案 2.5](技术方案.md#25-m0-修订实现与验证2026-09-08)。
各家工具／图片／完整思考调用和本地 vLLM 实机验证仍在 M3／M4；持久化与三级页面尚未开始。

### M1：数据库迁移与备份基础

**目标：** 将版本账本、迁移事务和备份验证做成可独立检验的 Host 内部能力。

**前置依赖：** M0 已确认。

**交付范围：**

- 实现技术方案 4.6、4.7 节规定的迁移器、发布链检查、逐版本事务与经校验的独立备份。
  为现有 schema 初始化逐句分类，区分一次性变更与每次启动恢复。
- 使用构造的旧 schema 夹具验证 v0.25.1 所需增量加列、删除旧列和保留数据的路径；正式入口
  在 M3 与新消费者一起启用，本阶段不在产品启动中删除 model_key。
- 覆盖空库、无版本表、空账本、跳版本、空迁移、二次运行、高版本、缺失版本、事务失败和
  备份失败；后续版本只使用测试 manifest，不伪造尚未发布的软件版本记录。
- 备份重新只读打开并核对精确数量、关键字段与完整性；错误后停止后续写入与自动补救。

**验证入口：** Host 存储定向测试及隔离 SQLite 集成测试，按第二节完成 Rust 门禁。
测试过程中核对源／目标 Runtime Home，所有破坏性夹具操作只作用于该测试创建的临时目录。

**完成判定：** 当前版本 SQL 和记账同时提交／回滚，失败不执行后继；高版本拒绝降级，备份
验证失败早于迁移写入；数据保留以精确查询证明。现有产品路径不误用尚未切换的目标 schema。

**Review 重点：** 是否猜测历史版本、只取最大版本忽略缺口、用文件存在替代备份验证，或把日常
恢复误作只执行一次的迁移。对应 A14—A19、A22 的基础用例，完整产品升级在 M3 回证。

**当前进展（2026-09-08）：** 独立迁移器和备份核验完成，`🟨 待确认`。15 项定向测试通过，
workspace 1,432 项通过、26 项忽略；最后的校验事务防护和表名过滤修正后，15 项定向测试再次通过。
workspace Clippy、fmt、差异检查通过。现有初始化已逐项分类；生产入口未接入，没有用户数据库操作。
实现边界见[技术方案](技术方案.md#m1-当前实现边界2026-09-08)，过程证据在本地开发进度。


### M2：Host 启动诊断与客户端准入

**目标：** 数据未就绪时能够显示原因，并保证业务没有提前读取或写入。

**前置依赖：** M1 已确认。

**交付范围：**

- 按技术方案 4.8 节调整 Host 的监听、认证、初始化和 Ready 发布顺序，接入现有初始化路径；
  用受控测试入口覆盖 M1 的迁移阶段和失败，不启用正式破坏性模型迁移。
- Desktop/Web 在既有连接入口与故障详情中展示启动状态；覆盖首次连接、已进入工作台后的
  Host 重启、版本不匹配与监听前错误，沿用受控退出／重启边界。
- 业务 commands、SSE、上传和 WS 统一执行准入；健康与能力查询仍要求正确认证。
- 应用协议版本在首次破坏性启动 DTO 替换时升为 3，同步 Host、Desktop 与生成类型；M3 继续
  在同一尚未发布的 v3 契约中完成模型 DTO，不声明尚未实现的模型管理 capability。

**验证入口：** Host 启动／认证集成测试、连接 Store 与启动页面测试、隔离 Host 的 Desktop/Web
定向 E2E；按第二节补齐协议、前端和原生改动门禁。

**完成判定：** 升级／初始化中与失败状态可见，业务始终在 Ready 后开放；等待不会反复启动或
杀死 Host，失败不清库、不无限重试。匿名访问不能取得受保护诊断，监听前故障不伪装为数据库状态。

**Review 重点：** 是否增加第二个监听、假的 Runtime 或第二份权威业务状态；是否漏拦上传／WS，
以及关闭客户端是否意外取消迁移。对应 A18—A20、A21 及 U09 的启动基础。

### M3：模型管理完整切换

**目标：** 正式产品从旧逐模型配置切换为数据库服务商与在线模型，并可安全升级旧数据。

**前置依赖：** M2 已确认；M0 的拟支持服务商参数问题已收口。

**交付范围：**

- 接通服务商、model_fixed_configs、默认／会话／辅助引用的 RuntimeStore、SQLite 和 Volatile 实现；
  新执行优先用完整固定记录，无记录才在线获取并冻结。首次固定仅在线来源验证在线身份，手动来源直接保存，已有记录离线可编辑；
  reset 幂等删除，不改选择；普通缺模型仍可启动、看历史和进入设置。
- 一次性替换所有正式模型契约与消费者，包括会话持久化、运行装配、管理命令、事件、Host 路由、
  RuntimeClient、生成类型、harness 及受影响测试。删除旧 ModelKey／逐模型 CRUD／静态目录
  产品依赖，不保留旧配置转换、别名或双写。
- 完成设置首页、服务商详情／编辑／删除、第三级固定参数表单／重置、默认与辅助选择、Composer“服务商 → 模型”两级
  级联及独立推理强度；按展开获取、局部刷新与重试，失败无旧目录回退；已固定配置在在线列表行内打标，
  不混入在线结果。
- 删除前从 Runtime 查询完整引用；处理活动 Run 冻结、准备中编辑／删除／固定保存／重置、请求迟到、保存结果
  不确定、失效显式选择与跟随默认。旧辅助选择要求手动重选。
