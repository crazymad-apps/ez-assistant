# v0.13.0 版本总结：单层子 Agent 与同步任务委派

- 状态：已完成
- 完成与归档日期：2026-08-13
- 功能范围：[`功能设计`](功能设计.md)
- 实现方案：[`技术方案`](技术方案.md)
- 开发过程：[`开发计划`](开发计划.md)、[`开发进度`](开发进度.md)
- 验收证据：[`验收记录`](验收记录.md)

本版本建立了单层通用子 Agent 和同步任务委派闭环。父 Agent 通过标准
`delegate_task` Tool Call 创建独立子任务；同一模型 Turn 中显式具备并行资格的委派可以
并行执行，父 Run 等待全部结果后按原始顺序结算，主 Conversation 仍保持串行权威。

## 二、主要交付

1. Agent Core 支持默认串行和显式并行两种内部工具执行模式，执行属性不进入 Provider
   可见 Tool Definition，Plan/Build 继续共享稳定工具定义。
2. 子任务拥有独立标识、状态、Conversation JSONL、usage、观察事件和临时目录 lease；
   复用父级冻结模型、Provider、工具基础设施、Workspace、权限、Guardrail、Recorder 和
   上下文压缩能力，不建立第二套 Agent Loop。
3. Runtime 建立父 Run 与 child task 的持久关系，支持 list/get/cancel、审批归属、预算、
   超时、单任务取消、父取消级联、归档恢复和启动一致性修复。
4. 子任务重启后不自动续跑或重放工具副作用；未完成任务收敛为中断终态，并修复父级
   `delegate_task` 配对结果。
5. 父 Agent 和每个子 Agent 的 usage 分别持久化，不保存冗余聚合副本；客户端需要总量时
   动态聚合。
6. Runtime Host Web Demo 补齐子任务列表、独立 Conversation、取消、审批和动态 usage 的
   验收入口，但不形成正式桌面 UI 契约。
7. 父会话和子任务均接入滚动上下文压缩，可在阈值到达或 Provider Overflow 后压缩并续跑。

## 四、Review 收敛

- 委派审批使用专用展示 subject，权限匹配继续使用通用工具名。
- child Registry 状态单调推进，取消请求保持粘性，避免取消与结算竞态回退终态。
- 历史重新输入级联删除 Run 时同步清理 child Conversation 目录。
- 修复 Testkit `Notify` 潜在丢失唤醒，并补齐并行分组边界、创建失败清理、usage、Plan
  私有目录、未知控制字段、Deny 委派和输出上限回归。
- 统一技术依据中的滚动摘要、continuation、恢复和公共协议描述。

## 五、保留边界

- 只支持单层、同步委派；不支持递归、后台 child、重启自动续跑或 child 直接对用户输出。
- 共享 Workspace 暂不提供文件冲突追踪、锁、陈旧读取检测或自动合并。
- Plan Shell 仍以当前操作系统用户权限执行，不是强沙箱。
- child 完整 Conversation 仍通过 Host-private 查询提供，不提前承诺公共 Protocol DTO。
- Runtime 不保存父子 usage 聚合副本；更大规模子任务列表优化在出现真实需求后处理。
