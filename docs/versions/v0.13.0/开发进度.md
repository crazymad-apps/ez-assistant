## 当前范围

- 路线主题：单层子 Agent 与同步任务委派。
- 功能设计已经确认，覆盖标准 `delegate_task` Tool Call、单层通用子 Agent、同批并行、
  独立上下文、权限继承、共享 Workspace 与独立私有目录、查询取消、持久化恢复和 usage 展示。
- 本版本不引入后台/递归委派、专用 Agent Profile、文件追踪与冲突控制，也不保存父 Run
  聚合 usage。
- 子 Agent 必须最大程度复用现有 Agent Core、Provider、Context、Tool、权限、Guardrail、
  Recorder、文件/Shell 和 Runtime 执行能力，只增加必要的父子任务编排接缝。
- 技术方案已经确认，明确保留 `Serial`/`ParallelEligible` 两种内部执行模式，只给
  `delegate_task` 启用并行资格；父子 Agent 复用冻结执行资源、独立子任务
  JSONL、兼容性新增关系表、临时目录 lease、可靠提交与恢复顺序。
- 开发计划已确认，并按 M0–M5 拆分 Core 并行、存储基础、单任务执行、并发控制、恢复协议和
  Web Demo/验收；当前 M4 已确认，M5 实现、正式 Host、真实 LLM 和全量回归均已完成。
- 正式桌面端 MVP 暂列为后续 `v0.14.0`，不因 v0.13.0 启动而提前实现。

- 私有 Web Demo 新增子任务区域，使用正式 child list/cancel 和 SSE 生命周期事件；子 Conversation
  通过既有 Host-private 验收查询独立展开，不把 child 伪装成普通 Session/Run。

- 正式 Host 回证覆盖公共查询/取消、并行 child 归档恢复、跨两次 Host 启动一致性，以及运行中

- 针对真实长子任务暴露的 Context Overflow，父 Run 与 child 已统一接入自动 Rolling Summary：
  replacement 通过正文 generation 原子切换，continuation 保留累计剩余预算；child 单 Turn 工具链
  可整体摘要，失败诊断区分 `threshold_reached`/`provider_overflow`，摘要 usage 随正文持久化。
- 全量 Review 后修正两个 Core 正确性问题：CompactionRequired 由 Engine 可靠携带已消费 Step/实际
  dispatch 工具数，不再从可丢弃事件反推；整体摘要活动 Turn 后持久化 Injected User continuation
  锚点，避免最终 Assistant 落在 User Turn 之外。

  Notify 丢唤醒和 child 创建失败清理；并补齐委派 Deny、Plan child 私有目录和并行分组边界测试。

## M4 实际结果

### 产出

- Host 启动恢复改为严格的 child -> parent 顺序：先完成 child staged append 和内部 pending tool
  exchange 修复，再把非终态 child 结算为 `interrupted`，之后才重建父 `delegate_task` Tool Result；
  全过程不重放模型或历史工具副作用。
- 父委派 begun 恢复会按 `(session_id, parent_run_id, parent_tool_call_id)` 查找 child：缺失关系形成
  interrupted 结果，不伪造 child；已完成 child 从其规范最终 Assistant Message 重建成功结果；
  失败、取消和中断使用稳定结构化错误结果。
- 公共协议增加 child list/get/cancel、`ChildTaskSnapshot`、`ChildTaskNotFound` 和嵌套
  `ChildTaskEvent`。事件覆盖 created/started、text/reasoning、usage、工具生命周期和 finished；
  SSE 仍是可丢失观察流，最终状态以查询和独立 Conversation 为准。
- Runtime 增加带 Session/父 Run 所有权校验的查询、取消及 Host-private child Conversation 读取。
  取消先可靠写入 `cancel_requested`，再向活动 child 发布 token；终态重复取消幂等返回原快照。
- Session 归档/恢复不改写 child 关系或正文，child 只通过父 Run 查询，不进入普通 Session/Run
  列表。Host `/commands` 与 `/events` 只做新协议的薄适配，完整 child Conversation 没有提前成为
  公共 DTO。

### 验证

- `cargo test -p assistant-protocol -p assistant-runtime -p assistant-runtime-host --all-features`：通过；
  包含 25 个协议、99 个 Runtime、54 个 Host 单测及既有离线 HTTP/恢复验收，真实 Provider 测试
  保持 ignored。
- `cargo test -p assistant-runtime-host --test v0_13_child_observation --all-features`：通过；使用隔离
  Runtime Home 和 loopback 假 Provider，经正式 Host 验证 child list/get、终态取消幂等及私有
  Conversation 查询。
- `cargo clippy -p assistant-protocol -p assistant-runtime -p assistant-runtime-host --all-targets --all-features -- -D warnings`、
  `cargo fmt --all --check`、`git diff --check`：通过。

### 偏差、遗留与风险

- M4 不实现 Web Demo child 展开、前端动态 usage 聚合和真实 LLM 场景；这些仍属于 M5。
- child 事件与父事件共用现有有界 broadcast；客户端遇到丢帧只能重新查询，不支持历史事件重放。
- 恢复测试全部使用临时 SQLite/Runtime Home；未读取或写入 `~/.ez-assistant`，未调用真实 LLM。

## M3 实际结果

### 产出

- `delegate_task` 改为显式 `ParallelEligible`；Core 只并发同一 Turn 中连续的委派调用，其他工具的
  历史串行语义不变。父 Run 再用独立 Semaphore 冻结实际 child 并发数，等待 permit 期间不创建
  OS 临时目录、不持有 Runtime 长锁。
- 父 Run 总任务数、child 并发数、执行 timeout 以及 child step/tool/output 上限均接入已校验
  delegation 配置；step/tool/output 与现有 Agent 配置取较小值，timeout 从取得 permit 后开始。
- 活动 child Registry 保存精确 Session、父 Run 和取消控制句柄；单独取消只影响目标 child，父 Run
  取消与 Runtime shutdown 通过派生 token 级联。timeout 稳定结算为 `failed/timeout`，显式取消为
  `cancelled`，完整终态与取消竞态不会被无条件覆盖。
- 审批快照和 resolved/cancelled 事件增加可选 child 归属；父审批保持字段缺省。child 取消会移除其
  pending approval 且不执行工具，等待审批的 child 不阻止 sibling 完成。
- 每个 child 继续只在独立 Conversation 保存正文与实际 usage，父 Run 不写聚合 usage。M3 只建立
  Runtime 内部单独取消接缝；公共 list/get/cancel、child 生命周期/Message 事件和重启修复留给 M4。

### 验证

- `cargo test -p assistant-runtime runtime::tests::delegation --all-features`：11 个委派场景通过，覆盖
  并发重叠且峰值受限、任务总量拒绝、timeout、单 child 取消、父级级联、审批 child 归属、sibling
  独立等待及取消审批清理。
- `cargo test -p agent-core -p agent-testkit -p assistant-protocol -p assistant-runtime -p assistant-runtime-host --all-features`：通过；真实 Provider 测试保持 ignored。
- `cargo clippy -p agent-core -p agent-testkit -p assistant-protocol -p assistant-runtime -p assistant-runtime-host --all-targets --all-features -- -D warnings`：通过。
- `cargo fmt --all --check`、`git diff --check`：通过。

### 偏差、遗留与风险

- 按计划未在 M3 提前公开 child 查询/取消命令，也未透传 child reasoning/text/tool/usage 实时事件；
  这些需要与恢复和断线重建一起在 M4 形成完整契约。
- child 共享父 Workspace，当前没有文件写入冲突追踪；父 Agent 仍负责合理拆分和复核结果，文件追踪
  不属于本版本。
- 验证只使用确定性 Provider、易失 Store 或隔离临时 SQLite/Runtime Home；未读取或写入
  `~/.ez-assistant`，未调用真实 LLM。

## M2 实际结果

### 产出

- Runtime 注册稳定 `delegate_task`，严格校验 title/task/context/expected_output；工具保持
  `Serial`，且 M2 每个父 Run 最多创建一个子任务，未提前开放 M3 并行能力。
- Host Base ToolSet 只派生父 ToolSet；子 Agent 复用同一冻结模型、请求配置、Context、变体、
  Guardrail、权限作用域和基础工具，但不包含 `delegate_task`，也不读取父 Conversation。
- 子身份指令、自包含任务、可选上下文/输出要求、变体和稳定目录事实作为真实规范输入一次性
  持久化；子 reasoning、工具轨迹和正文只进入独立 child JSONL。
- `ParentDelegationController` 复用现有 `AgentExecution`、Runtime Authorizer 与 child Recorder；
  子终态先可靠提交，再生成父模型可见的成功 JSON 或受控错误 Tool Result。
- `ChildTaskWorkspaceFactory` 把 OS 临时目录创建/清理留在 Host；lease 持续到子终态提交后释放，
  Plan Authorizer 将该路径视作本次子执行的额外私有可写根。
- Tool 执行上下文由 Core 绑定原始 call ID，使 Runtime 可以可靠建立 parent Tool Call 到 child 的关系，
  call ID 不进入模型输入 Schema 或权限事实。

### 验证

- `cargo test -p agent-tools -p agent-core -p assistant-runtime -p assistant-runtime-host --all-features`：
  通过；真实 Provider 测试保持 ignored。
- `cargo clippy -p agent-tools -p agent-core -p assistant-runtime -p assistant-runtime-host --all-targets --all-features -- -D warnings`：通过。
- `cargo fmt --all --check`、`git diff --check`：通过。
- 确定性测试覆盖成功委派、子模型失败、父结果回传、父/子 Conversation 隔离、子不可递归委派、
  Plan/Build Tool Definition 字节一致、临时目录终态释放，以及 accepted 子任务在启动前失败的
  Host 可靠结算。

### 偏差、遗留与风险

- 无范围扩张：M2 明确限制一个父 Run 只创建一个串行 child；同批并发、配额、timeout、单独取消、
  child 审批关联和 usage 观察仍属于 M3/M4。
- 子任务模型 attempt 暂不形成独立公共事件/查询投影；M4 接入 child 观察契约时再按 child 归属输出，
  不在 M2 提前扩展协议。
- 非终态 child 的启动恢复和 child -> parent 结果修复仍属于 M4；本阶段只保证正常执行路径中
  child 终态先于父 Tool Result。
- 全部数据库验证使用临时 SQLite/Runtime Home；未读取或写入 `~/.ez-assistant`，未调用真实 LLM。

## M0 实际结果

### 产出

- `agent-tools` 新增注册时冻结的 `ToolExecutionMode`，默认 `Serial`；内部执行属性不进入
  Provider 可见 Tool Definition 或授权事实。
- `ToolSetSnapshot::try_with_tool` 支持消费式追加新工具，保留已有定义、顺序与执行句柄，
  并复用注册边界的定义冻结和重名校验。
- `agent-core` 只把至少两个连续 `ParallelEligible` valid invocation 组成并行组；Invalid 与
  Serial 项保持顺序屏障，单个 eligible 调用沿用原串行路径。
- 并行组同时等待授权，在任何 execution future 被 poll 前完成工具预算和每项 started 可靠边界；
  工具执行全部收敛后按原 Call 顺序形成结果、观察 Guardrail 并原子完成 exchange。
- `agent-testkit` 新增计数式授权/执行 gate 和并行 Harness，确定性覆盖默认串行、并行重叠、
  串行屏障、结果保序、预算超限、取消清理和调用前 Guardrail Enforce。
- 同步更新 Agent Core、Agent Tools 和上位架构约束及长期决策记录。
- 根据里程碑 Review，将 Tool Batch 编排从 `engine.rs` 抽入私有
  `engine/tool_batch.rs`，并把原先冗长的 `execute_batch` 拆成批次遍历、单位置结算、
  已授权串行执行、并行组执行和终态收敛；Agent Loop 不再承载这些边缘细节。

### 验证

- `cargo test -p agent-tools -p agent-core -p agent-testkit --all-features`：通过；目标范围共
  169 个测试（38 + 33 + 52 + 46），无失败。
- `cargo clippy -p agent-tools -p agent-core -p agent-testkit --all-targets --all-features -- -D warnings`：通过。
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`：通过。
- `cargo test --workspace`：通过；真实 Provider、系统 `rg` 和真实进程树等显式 ignored 测试
  保持未执行。
- `cargo fmt --all --check`、`git diff --check`：通过。

### 偏差、遗留与风险

- 无设计偏差。M0 只提供通用调度能力，尚无生产工具声明 `ParallelEligible`；`delegate_task`
  要到 M2/M3 才接入并行资格和 Runtime 级并发上限。
- 并行资格不是副作用无冲突证明；共享 Workspace 的任务拆分与最终复核仍按技术方案留给父 Agent，
  本版本不提前引入文件追踪。
- 本里程碑不涉及数据库写操作、正式 Host 行为或真实 LLM 调用。

## M1 实际结果

### 产出

- `assistant-protocol` 新增稳定 `ChildTaskId` 与独立 `ChildTaskStatus`；`assistant-runtime`
  新增 delegation 默认预算、严格配置校验和不含凭证的安全投影。
- `RuntimeStore` 与易失实现新增 child 关系、初始消息、两阶段工具交换、终态结算及独立正文读取；
  `ChildTaskRecord` 使用独立 Journal 和 mutation gate。
- Runtime Recorder 保留一套 begin/started/complete 主算法，父 Run 与 child 的目标适配已拆入私有
  `run/recorder/target.rs`，Core Recorder trait 不变。
- Host SQLite 兼容性新增 child 关系/状态、pending、started 和 staged append 表；每个 child 使用
  独立规范 Conversation JSONL，正文不进入 SQLite。
- Host 父/子目标共用 staged append 与 pending tool exchange 状态机；`child_task.rs` 只保留
  child 生命周期、投影和所有权校验，未复制恢复算法。
- 增加 schema 幂等、旧数据保持、父子/跨 Session 所有权、独立 JSONL、完整生命周期、started
  未知结果恢复和 Runtime child Recorder 隔离测试。

### 验证

- `cargo test -p assistant-protocol -p assistant-runtime -p assistant-runtime-host --all-features`：通过；
  真实 Provider 测试保持 ignored。
- `cargo clippy -p assistant-protocol -p assistant-runtime -p assistant-runtime-host --all-targets --all-features -- -D warnings`：通过。
- `cargo fmt --all --check`、`git diff --check`：通过。

### 偏差、遗留与风险

- 无设计偏差。M1 不创建真实 child execution；`delegate_task` 工具、子 Agent 装配、临时目录
  lease、终态结果回传和运行期 Registry 从 M2 开始接入。
- M1 只修复 child 自身 staged append 与 pending tool exchange；非终态 child 中断结算以及
  child -> parent 的完整启动修复顺序属于 M4。
- 本里程碑所有 Store/SQLite 测试使用临时 Runtime Home，没有读取或写入用户真实数据库，
  也没有调用真实 LLM。
