## M0 实际结果（2026-09-16，已确认）

- 软件版本：workspace、Runtime Host、Desktop、Client 与独立 TS 协议包统一为 `0.26.0`。
- 应用协议：`ListProviderModels` 改为目录快照响应并新增 `RefreshProviderModels`，属于破坏性响应
  变化，因此最低兼容版本取最小必要值 `0.26.0`；共享 Rust/TS 向量覆盖 v0.25.3 Client 与
  v0.26.0 Host 的双向拒绝。
- 数据库：`v0_26_0` 只为 `providers` 增加三列并记录迁移，不新增目录表，不改写 Run/Input；最低
  兼容 Host 保持 `0.25.3`。隔离 v0.25.3 库迁移前后
  `providers/sessions/runs/inputs = 1/0/0/0`，独立备份位于测试 TempDir 的
  `backups/database/upgrade-*/runtime.sqlite3`，已只读打开并精确核对，测试结束后随 TempDir 清理。
- 目录后端：Provider 持有唯一快照；本地 list 零网络，显式 refresh 固定使用 5 秒连接／20 秒整次
  预算；完整结果经领域校验和 Store CAS 原子替换。刷新失败、Store 失败或连接并发变化保留旧值；
  语法或语义损坏的目录降级为 `stored_snapshot_invalid`。
- 旧版本证据：v0.25.3 Provider upsert 夹具不会清空新增列；v0.25.3 Host 对含 `0.26.0` 迁移账本的
  数据库返回 `NewerDatabase`，源库业务数量不变。
- 验证通过：`cargo test -p assistant-protocol`（44 项）、`cargo test -p assistant-runtime`
  （326 项库测试、6 项集成测试）、`cargo test -p assistant-runtime-host`（完整单元与隔离集成套件；
  主二进制 337 通过、4 项显式忽略）、受影响三包 Clippy、`cargo fmt --all --check`、Rust→TS 生成
  一致性、独立 TS 包构建、版本一致性和 `git diff --check`。
- 未执行：真实 Provider 目录联调（没有使用获准连接，Host 对应付费/真实连接用例保持显式忽略）；
  Desktop 全量构建与 UI 测试属于 M1 接入后的门禁。M0 按计划没有修改 Desktop 消费路径，现有隐式
  目录发现仍只作为过渡保留，不能宣称关键路径已经断网。

## M1 实际结果（2026-09-16，已确认）

## M2 实际结果（2026-09-16，已确认）

- `StoredRunSettlement` 已支持携带 queued 来源 Input 的完整原 `UserMessage`。Runtime 与 Host 都在
  同一结算中按“原用户消息 → 其他可见消息 → Input committed → Run terminal”收敛；已 committed
  Input 的 retry 不重复用户消息，Store 成功后内存 Input 同步清除 queued payload。
- 新增 `StoredTerminalRunInputReconciliation` 和 `RuntimeStore::reconcile_terminal_run_input`；只修复
  terminal Run 精确关联的 queued Input，不改 Run 终态、不执行模型或工具。Host 使用 staged append
  与事务预检，身份或正文不一致整次冲突，重复恢复幂等，无关 queued Input 保持不变。
- `SessionLoader::prepare` 已统一非终态 Run 中断恢复和 terminal+queued 定向修复，并在修复后重新
  加载权威状态；`load`、会话列表、标题搜索和单独 Run 元数据查询保持只读。组合会话视图以及删除、
  归档、清空、换模、历史重入、手动压缩等 idle-sensitive mutation 在判断前走单 Session prepare。
- 测试覆盖模型、Shell、Skill、工具装配和模型 currentness 的启动前失败；Store 结算失败保持
  `accepted + queued` 并令 Session faulted；Host 覆盖消息不匹配无半提交、两个 staged 崩溃断点、
  terminal 修复重复执行和无关队列隔离。会话视图恢复测试验证原消息只出现一次且合法队列仍保留。
- M2 没有应用协议或数据库 schema 变化，没有新增迁移或批量改写；应用协议 minimum 仍为 `0.26.0`，
  数据库最低 Host 仍为 `0.25.3`。
- 验证通过：`cargo test -p assistant-runtime`（331 项库测试、6 项集成测试）、
  `cargo test -p assistant-runtime-host`（主二进制 339 通过、4 项显式忽略，全部隔离正式 Host 集成
  测试通过，需真实 Provider、旧发布 Host 或人工性能运行的用例按声明忽略）、受影响两包 Clippy
  `--all-targets --all-features -- -D warnings`、`cargo fmt --all --check` 和 `git diff --check`。
- 未执行：真实 Provider/用户 Runtime Home（M2 不需要且禁止触碰）；Desktop 测试与构建（M2 未修改
  协议或 Desktop 代码，沿用 M1 已通过结果）；M3 及后续能力未提前实现。

## M4 实际结果（2026-09-16，已确认）

- `RuntimeToolAuthorizer` 和 `RuntimeApprovalResolver` 不再持有 Run 创建时的审批模式副本；每次新工具
  授权都从同一 `SessionController` 读取当前模式，parent 与 child 共用该状态。Run 快照和存储中的
  `approval_mode` 明确只表示接纳时审计基线，Agent 变体、工作空间和 Shell 等既有冻结事实不变。
- `set_session_approval_mode` 固定按 mutation gate、Store、Session state、事件和成功响应顺序提交；
  Store 成功但 state 更新失败时尝试令 Session faulted 并返回失败。已经 pending、已经授权或已经执行
  的调用不被追溯改变，显式 Deny/Ask/Allow 权限优先级保持不变。
- 原生 Desktop 偏好新增 `default_approval_mode` 与 `last_model_selection`，继续使用既有原子、串行保存，
  并按本机与每个远端目标 namespace 隔离；旧文件默认 Ask/无模型，非法或超长值拒绝进入状态。
  普通 Web 明确忽略且不保存这两个设备默认。
- 新草稿只在创建时复制当时设备默认；草稿切换立即更新默认，已有 Session 仅在 Runtime mutation
  成功后更新，选择“默认模型”保存为 `null`。默认变化不会改写其他已有草稿，customized 判断改为
  对比当前设备基线；偏好保存失败保留内存选择并显示错误。
- Provider 删除会清除最近模型覆盖、清理仍为空且未开始物化的继承草稿并显示提示；有正文等用户
  内容的草稿不被改写。只要 Provider 仍存在，即使本地目录暂时缺少模型 ID，也保留固定或陈旧选择。
- 正式 Host 新增两项隔离 E2E：Ask→Auto 后同一父 Run 的第二个工具不再审批且原 pending 仍需明确
  处理；切换后启动的 child 工具读取 parent Session 当前 Auto 模式。Runtime 另覆盖 Auto→Ask、
  Ask→Auto、child 共享状态和权限优先级。
- M4 没有应用协议形状或数据库 schema 变化，没有新增迁移；应用协议 minimum 仍为 `0.26.0`，
  数据库最低 Host 仍为 `0.25.3`，未随软件版本机械提升。
- 验证通过：`cargo test -p assistant-runtime`（340 项库测试、6 项集成测试及 doc tests）、正式 Host
  `v0_26_live_approval`（2 项）、Desktop Tauri 偏好定向测试（5 项）、Desktop `npm test -- --run`
  （55 个文件、455 项）、`npm run lint`、`npm run build`、受影响 Runtime/Host/Desktop Rust 包 Clippy
  `--all-targets --all-features -- -D warnings`、协议生成一致性、版本一致性与 Rust fmt。
- 未执行：真实 Provider、用户 Runtime Home 和数据库写入（本里程碑不需要）；Desktop GUI 重启后的
  本机/多远端人工切换、Windows/Linux 实机和候选 Tauri no-bundle 留待 M6 组合回归。M5 尚未开始。
