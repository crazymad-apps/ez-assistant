## 二、背景、现状与版本目标

### 2.1 背景

`v0.25.0`—`v0.25.3` 已建立远端直连、模型管理、Client 与 Windows Desktop 闭环。当前需要先
收口已被真实使用暴露的关键路径阻塞、Session/Run/Input 状态残留、运行中投影错位和
审批信息不足，否则继续扩展 Computer Use、服务端工具或分布式能力会放大这些问题。

### 2.2 已核实的现状

| 主题 | 当前事实 | 直接影响 |
| --- | --- | --- |
| 模型目录 | 无固定记录时，会话视图与 Run 装配可同步调用外部 `/models`，目录发现沿用推理长超时 | 页面卡顿、Run 启动失败、计划外联网 |
| 状态收敛 | 模型准备阶段失败不会使已接纳 Input 进入终态；中断 Run 的恢复只在执行准备路径上运行 | 会话长期非空闲，无法删除、归档、清空或换模型 |
| Live 投影 | 已提交 step 从只有 30 条的会话页反推，而工具从整轮快照补回；重建 step 只向尾部追加 | 运行中的历史工具错位，reasoning 跨 step 混合 |
| 工具参数 | 普通工具的实时活动与 General 审批没有可见的脱敏参数 | 用户无法在执行前或执行中确认真实操作对象 |
| 审批模式 | Session 切换会立即持久化，但 Run 装配时已把模式复制进 Authorizer/Approval Resolver；新会话草稿始终硬编码为 Ask | 同一 Run 后续 step 仍按旧模式审批；每次新建会话都要重新切换 |
| 新会话模型 | 新草稿的显式 `model_selection` 固定为空，只跟随 Runtime 全局默认；草稿或 Session 选中的模型不会成为下一草稿默认 | 用户连续新建会话时需要重复选择同一模型 |
| `detached` | 只取消 drop 时主动清理；输出结算超时或取消时仍会清理进程组 | 工具说明与实际存活语义不一致 |
| Windows 还原图标 | 当前图标用两个带完整边框的透明方框重叠，后层边线透过前层 | 最大化后的还原图标出现多余内部线框，层级和 Windows 窗口语义不清晰 |
| Desktop 滚动 | WKWebView 与 WebView2 在嵌套滚动容器到达边界后仍会产生橡皮筋或越界弹动 | macOS 修复后 Windows 仍出现不必要的缓冲滑动 |
| 模型模板 | OpenAI/DeepSeek 的 `/models` 目录只返回基础身份，不能提供窗口、输出和能力；DeepSeek Flash 已换为 `deepseek-flash` 且具备视觉能力 | 新型号缺少可执行模板，旧 Flash 能力与当前实际模型不一致 |
| 标题旁路 | 标题生成固定 20 秒总超时，并把模型、协议和 Store 错误全部折叠成无原因的 `failed` | 推理模型可能被过早取消，失败无法区分超时与模型错误 |
| 默认 Agent Shell | Runtime 概览用标题、选择器和说明三行展示同一个简单默认值 | 占用过多纵向空间，副标题没有必要 |

### 2.3 版本目标

本版交付十二个可独立验证、又共同服务于“会话可靠性”的结果：

1. 模型目录只在模型管理页由用户显式刷新，成功结果持久保存，其他会话和执行路径只消费本地事实。
2. Run 启动前失败和 Runtime 中断都能可靠收敛 Input/Run，不再把会话永久留在不可管理状态。
3. 运行中投影以可靠提交事实封口，step 顺序和内容最终与权威 Conversation 一致。
4. 工具执行和审批展示同一条经过投影、脱敏和大小限制的实际参数，不暴露 API Key 等秘密。
5. Session 审批模式切换对同一 Run 中切换成功后才开始授权的后续工具实时生效；Desktop 新会话默认使用当前连接目标最后一次成功选择的模式。
6. Desktop 新会话默认使用当前连接目标最后一次成功选择的具体模型；选择“默认模型”后重新跟随 Runtime 全局默认。
7. 模型选择冻结提示不再重复挤占菜单；Shell `detached` 说明如实表达现有生命周期。
8. Windows 自定义标题栏的还原按钮显示清晰的双窗口图标，不再出现多余内部边线。
9. macOS 与 Windows Desktop 到达滚动边界时不再产生 WebView 越界回弹，正常滚动保持可用。
10. Runtime 概览中的默认 Agent Shell 收为标题与选择器同一行，不再展示描述性副标题。
11. `deepseek-flash` 及临时兼容别名使用同一 V4.1 Flash 多模态模板；GPT-6 Astra 继续按官方规格由本地模板补齐。
12. 标题旁路允许推理模型在合理总时限内完成，并向 Desktop 返回脱敏、可分类的失败原因。

### 2.4 成功标准

- 打开、切换、刷新会话和装配 Run 不会调用任何服务商模型目录接口。
- 目录刷新失败可快速返回，已有快照不被清除，并可继续选择或运行已具备完整本地参数的模型。
- 任一 Run 终态都不会留下阻止会话管理的可运行 Input；崩溃残留 Run 在查看或管理时可被明确恢复为中断终态。
- 超过 30 条消息窗口的多 step、迟到事件和跨 Run 会话均不再产生投影错位。
- 用户在审批前可理解普通工具将操作什么；运行中和历史展示的参数语义一致。
- 同一 Run 中 Ask/Auto 切换成功后，后续未开始授权的工具使用新模式；已挂起、已授权或已开始执行的工具不被追溯改变。
- 原生 Desktop 重启或新建会话时，审批模式默认值与该 Desktop 对当前连接目标的上一次成功选择一致。
- 原生 Desktop 重启或新建会话时，具体模型默认值与该 Desktop 对当前连接目标的上一次成功选择一致；无设备覆盖时继续使用 Runtime 全局默认。
- Windows 窗口最大化后，还原图标在常见系统缩放比例和明暗主题下轮廓正确、居中且状态切换准确。
- macOS 与 Windows Desktop 的主要滚动容器到达顶部或底部时不发生边界回弹，普通滚轮与触控板滚动不受影响。
- 默认 Agent Shell 使用单行布局且无描述性副标题，原选择和禁用行为不变。
- 在线目录仍只提供模型身份时，`deepseek-flash` 与 GPT-6 Astra 可由已核查模板形成完整本地执行参数；不新增隐式联网。
- 标题模型失败、协议输出无效和总超时均保留旧标题，并通过既有完成事件返回稳定脱敏诊断。
- 不执行本版新增的自动联网、后台预热、目录 TTL、进程守护或事件重放机制。

## 三、明确非目标

- 不恢复 `v0.25.4`—`v0.25.6` 的组网、P2P、中继或 Web 工作区扩展。
- 不实现 DeepSeek 或其他 Provider 的服务端 Web Search，不新增 Computer Use、CDP、浏览器 MCP 或桌面控制。
- 不实现整套主题预设，不调整会话中 reasoning、正文和工具块的产生顺序或聚合方式。
- 不为模型目录增加 TTL、自动刷新、定时刷新、后台预热、内存/磁盘二级缓存或新的快照业务实体。
- 不在模型不可用时自动切换服务商、模型或协议，不自动清理用户选择。
- 不建立可重放事件日志、per-run 事件序号或另一套 live 投影协议；只在现有事件和权威快照上收口。
- 审批模式切换不自动批准已挂起审批，不取消已授权或已开始执行的工具，不让 Auto 绕过显式 Deny/Ask 权限规则。
- Desktop 默认审批模式只是新会话草稿的设备端便捷默认，不覆盖已有 Session，不成为 Runtime 全局业务配置，不改变独立 Web 客户端的 Ask 缺省值。
- Desktop 最近模型只是新草稿的设备端默认，不修改 Runtime 全局默认模型，不覆盖已有 Session 或已有草稿，也不改变独立 Web 客户端的现有跟随默认行为。
- 不调整现有上下文压缩方案；本版继续沿用 `RollingSummarySameModel` 和既有压缩边界，
  不实现确定性 Tool Result 裁剪或混合压缩策略。允许修正压缩前的占用计量与 UI 展示口径，
  但不得改变摘要算法或保留边界；终态实际用量与临时估算分开记录，不增加联网计数请求。
- 不把 Shell `detached` 改造为跨平台 daemon/服务管理器，不改变超时或取消时的进程树清理行为。
- 不借还原图标修复替换整套自定义标题栏、按钮热区或 Tauri 窗口状态协议。
- 设计阶段不连接、迁移或修改用户 `~/.ez-assistant` 数据库；开发与验收使用隔离 Runtime Home。

## 四、功能范围与使用路径

### 4.1 持久化模型目录快照

模型目录快照与服务商实例共享生命周期，持久保存最后一次成功刷新结果和获取时间。
它是用户显式刷新形成的本地事实，不是后台自动保鲜的缓存层。

- 新建服务商保存成功后不强制与目录刷新绑成一个成功/失败结果；用户可在管理页显式刷新。
- 刷新成功时原子替换该服务商的快照和时间；刷新失败只报告失败，不删除、清空或覆盖旧快照。
- 修改 endpoint、服务商类型或列表路径后保留已有快照，但清晰标记“连接已变更，建议刷新”和原获取时间。
- 删除服务商时一并删除其快照；快照不离开服务商独立存在，不新增可独立管理的快照实体。
- 快照内容损坏或不可解析时降级为“尚未获取”并产生可见诊断，不阻断服务商、Runtime 或会话加载。

### 4.2 联网入口与超时

只有“设置 → 模型与服务商 → 刷新在线模型列表”是目录发现入口。以下路径必须完全本地化：

- 应用启动、应用快照、会话打开/切换/刷新；
- Composer 模型选择器和模型配置查看；
- 会话创建、会话模型切换与草稿首次物化；
- Run 装配、标题生成、上下文压缩、子 Agent 和会话代理。

显式目录发现使用独立且明显短于模型推理的超时预算。具体时长、是否可配置和底层 Client 复用
方式由技术方案基于现有 transport 配置收口。

### 4.3 选择器与本地执行事实

- 模型选择器合并“最后成功目录快照 + 已保存固定模型”，按服务商实例和模型 ID 去重。
- 无快照时显示“尚未获取模型列表”及前往模型管理页的入口，但已保存固定模型仍可选择。
- 刷新失败后显示“仍在使用上次结果（获取于…）”，不把旧快照伪装为刚刚成功获取。
- Run 只消费会话已接纳的模型 binding、固定配置、快照和内置模板能够形成的完整本地参数。
  本地事实不完整时立即给出可执行提示，不通过联网“顺便补齐”。
- 服务商下线某模型不会自动更改默认、会话或辅助识图选择；用户在显式刷新或执行失败后手动处理。

无活动 Run 且无排队 Input 时，选择入口正常展开。存在运行或排队输入时，直接禁用选择入口，
在入口 tooltip 统一说明冻结原因，不再在每个 Provider 后重复追加说明。

### 4.4 Run/Input 失败收敛与中断恢复

- Run 在模型、工具或执行上下文完成准备前失败时，Run 和来源 Input 必须在同一可恢复结算中进入一致终态。
- 失败原始输入不自动重放、不自动重发给模型；用户可从失败信息中修改配置并显式重试。
- 只要业务命令需要判定会话是否空闲，就必须先在共用会话装载/恢复边界结算崩溃遗留的 running Run。
- 恢复只把无法继续的历史 Run 结算为 interrupted 并收敛相关 Input，不执行历史工具副作用，不自动继续 Goal。
- 删除、归档、清空、换模型等操作在恢复后按真实状态决定是否允许；前端不再对拒绝结果静默无响应。
- 对已存在的“终态 Run + queued Input”和崩溃残留 Run，升级后在可审计、幂等的恢复路径中定向收敛。
  不对所有 queued Input 做无条件批量改写；精确识别条件、事务边界、迁移/运行时恢复归属和回复方案由技术方案确认。

### 4.5 Live step 投影一致性

Desktop 保持“live 尾部 + 权威历史”的现有双源渲染，但交接依据改为 Runtime 已经发出的可靠
step 提交事实，不再从当前分页中是否仍能看到某条 assistant message 来反推。

1. 每个正在执行的 owner/Run 记录已可靠提交的 step 水位。
2. 已封口 step 不再接受迟到 delta、tool proposed/output/completed 或快照补回。
3. 新建或恢复 step 按数字顺序插入，不依赖事件到达顺序和数组尾追加。
4. step 终结时以权威 Conversation segment 覆盖本地累积内容，不使用局部删工具/再补工具的对称性假设。
5. 现有 SSE 事件序列出现 gap 时，不让缺口两侧的 live 内容继续拼接；最小处理为作废受影响的 live 尾部
   并等待权威快照重建。

技术方案需先核实现有 `StepCommitted` 的 owner、step、generation 是否足以在事件缓冲和跨 Run 边界下
精确封口。只有现有事实无法唯一定位目标时才增补最小关联信息，不预设新的事件日志、序号或重放机制。

### 4.6 工具参数可见性

- 执行中 Tool Activity 展示 Runtime 已有工具输入投影，不直接把 Provider 原始 arguments 无限长度下发。
- 审批对话框对 file/files/shell/delegation/MCP 与 General 工具使用一致的“这次将操作什么”口径。
- 参数必须在 Runtime 唯一投影边界完成类型化归一、敏感字段隐去、过长文本/列表截断和不支持类型的诚实降级。
- 实时、审批和历史详情复用同一条脱敏语义，不在 Desktop 再次解析或猜测工具秘密。
- 如果参数因历史协议、截断或不可投影而不完整，UI 明确标识，不伪装为已展示全部。

### 4.7 审批模式实时生效与 Desktop 默认值

Session 当前 `approval_mode` 改为后续工具授权的权威实时事实，不再由 Run 启动时的副本决定整轮后续行为。

- `set_session_approval_mode` 在持久化和 Session 内存状态都更新成功后才回复成功并发布事件。以该成功边界为准，之后才开始授权的父 Run 和 child task 工具读取新模式。
- Ask 切换为 Auto 不会自动决定已经在 Approval Registry 中等待的审批；用户仍需处理当前审批，同批或后续 step 中此后才进入授权的工具使用 Auto。
- Auto 切换为 Ask 不会撤销已经完成的授权，但之后才开始授权且未命中 Allow/Deny/Ask 规则的工具需要请求审批。
- 权限优先级不变：明确 Deny 始终拒绝，明确 Ask 始终请求审批，明确 Allow 与工作区默认规则按既有语义生效；Ask/Auto 只决定其余未匹配调用是请求审批还是自动允许。
- Run 中已持久化的 `approval_mode` 若为审计或兼容保留，只表示该 Run 接纳时的模式，不得再作为本 Run 后续工具的授权依据；是否保留及对外命名由技术方案核查兼容影响。

Desktop 复用现有 `desktop-preferences.json` 和连接目标 namespace 保存最后一次成功选择的审批模式：

- 本机 Host 和每个远程 Host 各自保持默认值，不把在高信任本机选择的 Auto 自动带到另一远程目标。
- 已物化 Session 只在 Runtime 切换命令成功后更新该 Desktop 默认；命令失败不保存未生效值。新会话草稿中的手动切换立即成为新默认。
- 新建草稿时读取默认；已存在草稿保留自身值，不因其他会话切换而静默改写。
- 偏好缺失、旧文件无字段或值无效时回退 Ask；偏好保存失败要给出可见反馈，但不回滚已成功的 Session 切换。
- 草稿是否“已自定义”以当前偏好默认为基准，不再把 Auto 固定视为偏离默认。

### 4.8 Desktop 新会话默认模型

Desktop 复用同一偏好文件和连接目标 namespace 保存最近一次成功选择的具体模型：

- 在新会话草稿中选择具体模型后，立即更新该草稿与设备默认；之后新建的草稿使用该选择。
- 在已有 Session 中切换具体模型时，只有 Runtime 命令成功后才更新设备默认；切换失败不得记住未生效选择。
- 选择“默认模型”表示清除设备端具体模型覆盖；之后的新草稿继续用空显式选择跟随 Runtime 全局默认。
- 已经打开的其他草稿和已有 Session 保留自身模型，不因设备默认变化被追溯改写。
- 偏好中的 Provider 已删除或身份字段无效时回退 Runtime 全局默认并给出可见提示，不自动选择其他具体模型。
- 普通 Web 客户端不读取 Desktop 设备偏好，继续使用现有 Runtime 全局默认模型。

### 4.9 Shell `detached` 语义与使用指引

本版不改变 Shell 进程树安全收敛，只修正对模型、用户和开发者的描述：

- `managed` 由工具掌控完整进程树，父 Shell 退出、超时、取消或工具结束都依现有安全语义清理。
- `detached` 只表示父 Shell 正常退出且输出管道在 deadline 内完整 EOF 时，工具不在 drop 阶段主动清理已交接后代。
- 输出结算超时或取消时，工具仍可清理所在进程组；`detached` 不保证任意后台 GUI/服务跨工具存活。
- 使用指引可说明将 GUI/服务交给操作系统服务管理机制的平台建议，但不把临时命令技巧承诺为跨平台产品能力。

### 4.10 Windows 标题栏还原图标

- 窗口处于最大化状态时，“最大化”按钮切换为两个错位窗口组成的“还原”图标。
- 前窗显示完整轮廓，后窗只显示未被前窗遮挡的上边和右边；不得让后窗完整边框透过前窗形成内部线。
- 图标沿用当前文字颜色和 hover 状态，在 42px 按钮热区内视觉居中，不改变最小化、关闭按钮及双击标题栏行为。
- `desktop://window-maximized`、首次状态查询和点击命令仍是状态来源；本项只修复图形，不以 CSS 状态猜测替代原生窗口状态。
- Windows 至少覆盖 100%、125%、150% 缩放及明暗主题；Linux 共用该自定义控件时不得出现视觉回退。

### 4.11 macOS 滚动与默认 Agent Shell 紧凑布局

- Desktop 只在 `data-platform="macos"` 下禁止滚动边界越界，消除 WKWebView 的橡皮筋回弹；正常滚轮、
  触控板惯性和滚动容器自身的滚动保持不变，不改变 Windows、Linux 或普通 Web。
- Runtime 概览中的“默认 Agent Shell”标题与选择器使用同一行布局，删除描述性副标题；选择器的值、
  可用性判断、禁用逻辑、保存行为和无障碍名称保持不变。

## 五、模块边界与契约影响

| 模块 | 职责 |
| --- | --- |
| `assistant-runtime` | 持有模型目录快照、显式刷新语义、本地模型装配、Session/Run/Input 恢复、工具参数唯一投影、Session 实时审批模式和压缩调度 |
| `runtime-host` | 实现 SQLite 模型目录快照持久化与版本迁移，验证恢复写入的事务性；不持有第二份 Runtime 状态 |
| `assistant-protocol` | 承载快照时间/状态、类型化工具输入和必要的 step 提交关联；保持 Provider-neutral |
| `agent-tools-local` | 保持实际进程组和输出结算行为，同步 Shell Schema/注释/测试名与使用文档的真实语义 |
| Desktop/Web | 只触发显式目录刷新，消费本地模型列表；按提交水位折叠 live 尾部；展示脱敏工具参数、冻结 tooltip 和操作失败；原生 Desktop 在现有目标 namespace 中保存新会话默认审批模式与最近模型，并收口平台窗口与滚动细节；Runtime 概览使用紧凑 Shell 默认值布局 |

## 六、关键取舍

### 6.1 为什么快照跟随 Provider 而不新增快照系统

模型目录快照没有独立身份、所有者或生命周期，只有“某个 Provider 最后一次成功刷新”的含义。
因此复用现有 Provider 持久化和内存聚合，不新增表、文件、二级缓存、刷新队列或失效机制。

### 6.2 为什么关键路径必须完全断网

缓存只能减少联网次数，不能阻止任意一次不可控外网请求卡住会话视图或 Run。所以“手动刷新”
不只是 UI 口径，而是 Runtime 联网权属边界。

### 6.3 为什么不自动重试、回退或重放

模型目录是用户管理事实，不是 Run 副作用。执行失败不能授权 Runtime 自动联网、改选模型或
重放工具。恢复的目标是将状态收敛为可理解终态，由用户决定下一步。

### 6.4 为什么不改变 `detached` 清理行为

仅在超时/取消分支跳过进程树清理，会把“用户要求中止”改成“后代继续运行”，并留下孤儿进程和管道
读取任务。本版先保持安全行为并修正承诺；真正的后台服务交接需要独立的身份、管理和停止契约，
不在本版为一个分支增加伪脱离机制。

### 6.5 为什么审批模式实时读 Session，但不追溯已有授权

审批模式是用户对当前 Session 的即时执行意图，而不是模型、工具列表或对话历史那样的 Run 内容快照。
因此后续授权应读 Session 最新值。但已经挂起的审批、已授权调用和已开始副作用都有独立时点与审计事实，
追溯改变会导致无声放行或撤销不可回滚操作。所以切换成功是只影响后续授权的清晰分界。

### 6.6 最小新增自检

- 删除目录快照持久化后，无法满足“刷新失败继续用上次结果”和“Runtime 重启不丢失”，所以必须保留。
- 删除专门的新快照实体、TTL、后台刷新和二级缓存后，现有 Provider 事实已足够，所以不新增这些机制。
- 删除新 live 事件日志和序号后，现有 step commit、全局 gap 检测和权威快照理论上足以收口；技术方案需用事件时序测试证明。
- 工具参数复用 Runtime 既有输入投影；不新增第二条 Desktop 脱敏路径。
- 审批模式复用 Session 已有持久化字段和切换命令；不新增第二份 Runtime 当前模式。Desktop 审批与模型默认值复用已有偏好文件和 Host namespace，不新建设置页、Runtime 全局字段或独立存储。
- Windows 还原图标只修正本地窗口控件的绘制，不新增图标资产、Runtime 协议或第二套最大化状态。

## 七、验收标准

### A. 模型目录与会话恢复

1. 新建 Provider 后无快照是合法状态；选择器不联网，显示空态与前往管理页入口。
2. 管理页显式刷新成功后，重启 Runtime 仍能读取同一快照和获取时间。
3. 已有快照时刷新失败，旧快照与时间不变，UI 同时显示失败和正在使用的历史时间。
4. 打开/切换会话、快照刷新、打开模型选择器、连续执行 Run 的可观察请求中均没有目录联网。
5. 目录接口卡住时在独立短超时内失败，不占用推理的长超时预算。
6. 模型准备失败后 Run 与 Input 一致进入终态，会话恢复空闲，可删除、归档、清空和切换模型。
7. 恢复启动前留下的 running Run 后，查看、删除和归档不再因历史运行态永久被拒绝。
8. 定向恢复已有异常记录是幂等的；重复加载不重复追加消息、重放工具或改变其他 queued Input。

### B. Live 投影与工具参数

9. 超过 30 条可见消息的单 Run 多 step 用例中，已提交工具不会出现在最新 step 后面。
10. 跨 step 重复 `part_id` 不会把不同 step 的 reasoning/text 合并到同一 segment。
11. 已封口 step 收到迟到 delta 或工具事件时 no-op，不复活该 step。
12. 事件 sequence gap 后 live 尾部作废并由权威快照恢复，不把缺口两侧内容拼接。
13. Run 终结后的展示与重新加载会话的权威展示一致。
14. 普通工具在审批中和执行中都可查看有用的脱敏参数；file/files/shell/delegation/MCP 现有展示不回退。
15. 包含 API Key、长文本、大列表、MCP JSON 和不可投影参数的 fixture 覆盖脱敏、截断和降级标记。

### C. 审批模式、Desktop 默认、Shell 与 UI

16. Ask 切换为 Auto 成功后，同一父 Run 和 child task 后续才开始授权的未匹配工具不再请求审批。
17. Auto 切换为 Ask 成功后，同一 Run 后续才开始授权的未匹配工具请求审批。
18. 切换不自动决定已挂起审批，不撤销已授权/已执行工具；显式 Deny/Ask/Allow 规则在两种模式下均保持现有优先级。
19. 原生 Desktop 本机目标和两个远程目标的 fixture 证明审批默认按目标 namespace 隔离，重启后新会话使用各自最后选择。
20. 审批偏好旧文件无字段、值无效和保存失败均有明确行为：前两者回退 Ask，后者不回滚已生效 Session 切换但显示失败。
21. 已存在草稿不被其他会话的审批切换静默改写；新草稿以当前偏好为默认，草稿自定义判定不再固定以 Ask 为基线。
22. 草稿或已有 Session 成功选择具体模型后，新建草稿默认使用该模型；本机和两个远端目标相互隔离，Desktop 重启后仍保持。
23. 选择“默认模型”会清除设备覆盖；偏好模型的 Provider 已删除或字段无效时回退 Runtime 全局默认并显示提示，不自动改选其他模型。
24. 已打开草稿和已有 Session 不被新的模型默认追溯改写；已有 Session 切换失败或 Desktop 偏好保存失败时分别保持旧默认或显示保存失败。
25. Shell Schema、工具描述、模块文档和测试名称都不再承诺 `detached` 在超时/取消/管道未 EOF 时仍存活。
26. 实际 `managed`/`detached` 正常交接、超时和取消回归测试证明文档描述与实现一致。
27. 会话不可换模型时，模型选择入口整体禁用并有 tooltip，Provider 条目不重复显示冻结文案。
28. Windows 最大化后的还原图标只有清晰的前后两个窗口轮廓，在 100%、125%、150% 缩放和明暗主题下无多余内部线；点击、状态事件、Tooltip 与无障碍名称保持正确。
29. macOS 与 Windows Desktop 的嵌套滚动容器到达边界时不产生橡皮筋或越界弹动，容器内部的正常滚动和惯性仍可用；普通 Web 与 Linux 样式不受影响。
30. 默认 Agent Shell 的标题和选择器稳定处于同一行，说明副标题已移除，原值、禁用态、选择和无障碍行为不变。

### D. 跨版本与回归

31. 新持久化字段的数据库迁移在隔离旧库备份上按顺序执行，迁移前后精确核对 Provider、Session、Run、Input 关键数量。
32. 旧客户端/新 Host、新客户端/旧 Host 按已发布的应用协议最低兼容规则明确接受或拒绝，不因新字段解码失败白屏。
33. macOS、Linux 与 Windows 的现有模型执行、会话、压缩、审批、Shell 和 Desktop 主要回归不因本版退化。
34. DeepSeek 官方 `deepseek-flash`、两个临时兼容 Flash 别名和 GPT-6 Astra 模板的窗口、输出、视觉、工具与推理字段有定向测试。
35. 标题旁路超过旧 20 秒边界不会提前失败；模型/协议/Store 失败事件携带可选安全错误，旧事件缺少该字段仍可读取。
36. 自动压缩与 UI 使用同一上下文占用口径：Provider `total_tokens` 加尚未计量的新增文本；加密状态不按
    字节重复计费，活动 Run 的最新已完成 step 可实时覆盖旧快照，且 UI 区分阈值触发与 Provider Overflow；
    终态实际用量与临时估算分开记录，下一完整响应替换基数并清除已计量增量，不增加 Provider 请求。

## 八、风险、兼容性与恢复

- **持久化兼容**：模型目录快照需要新的可空持久化内容；旧库升级后等价于“从未刷新”，不回填、不联网。
- **正式数据**：本版存在数据库迁移与定向恢复写入。开发只使用隔离非生产库；任何对用户真实库的手工清理、批量更新或恢复，
  在写入前都必须重新列出主机、端口、数据库、表和影响范围，创建并验证独立备份后取得确认。
- **快照过期**：本版故意不判定 TTL。UI 必须展示获取时间和连接变更提示，模型不可用时由用户处理。
- **恢复过度**：不能把合法排队 Input 当作残留数据收敛。恢复条件必须绑定已终态/已中断 Run 和其精确来源 Input，并使用事务与幂等验证。
- **投影时序**：`StepCommitted` 目前不直接携带 `run_id`。技术方案必须用跨 Run、断线重连和缓冲事件用例验证现有 owner/step/generation 是否足够；不足时只增补最小关联事实。
- **参数泄露**：实时和审批参数不得比历史详情暴露更多信息；脱敏和截断必须在 Runtime 发送前完成。
- **切换竞态**：审批模式切换与同批工具授权可并发。技术方案必须固定线性化时点，证明“切换成功前已登记的审批保持，成功后才开始的授权读新值”，不得用最终 UI 状态推测历史决策。
- **Auto 默认的安全性**：Desktop 记住 Auto 是用户明确要求的便捷性，但必须按连接目标隔离、在新草稿中持续可见，且不能降低显式 Deny/Ask 规则的优先级。
- **模型默认失效**：设备记住的模型可能在另一客户端被删除；新草稿必须回退并提示，不能自动联网或静默改选。
- **Shell 预期**：如实描述可能降低对 `detached` 的表面能力期待，但比在取消后留下不可管理进程更符合安全边界。
- **图标缩放**：细线图标在非整数缩放下可能发生半像素模糊；必须使用确定的矢量路径和实机缩放验证，不能只看开发机截图。

## 九、预计实施顺序

下列只用于验证版本规模和依赖顺序，不代替后续开发计划，也不构成开发授权：

4. M3：Live step 投影、gap 收敛与工具参数投影。
5. M4：审批模式实时生效与 Desktop 新会话审批/模型默认。

## 十、确认结果

1. 当前活跃版本直接升为 `v0.26.0`；`v0.25.4`—`v0.25.6` 继续暂停，其未实施内容后续择期重新安排版本。
2. 本版同时纳入 P0/P1 缺陷、审批模式实时生效、Desktop 记住每个连接目标的新会话审批与模型默认、Shell `detached` 语义收口与 UI-001—UI-005；
   不把真正的后台进程托管、DeepSeek Web Search、Computer Use、主题和组网带入本版。
3. 对已有异常 Input/Run 的产品结果是“升级后按精确关联幂等收敛，不重放副作用”；具体是迁移还是共用恢复路径属于技术方案。
4. 本版必须编写技术方案；界面调整先由本功能设计直接约束，不单独编写界面交互设计指导。
