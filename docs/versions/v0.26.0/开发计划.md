## 二、台账原则与验证约定

1. 里程碑严格逐个执行“核查 → 实现 → 最小有效验证 → 记录实际结果 → 汇报 → 用户确认”。
   当前计划确认只授权开始 M0，不授权连续完成 M1—M6。
2. 每个里程碑实现和验证完成后先标记 `🟨 待确认`；用户确认后才标记 `✅ 已完成` 并进入下一里程碑。
3. 任一实现事实与技术方案不一致，或协议、数据库、权限、恢复边界出现新取舍时，立即停止扩大修改，
   先修订设计并重新确认。
4. 保留用户现有工作树改动，不清理、不重置、不顺手修改无关范围；未经明确要求不执行
   `git add`、`git commit`、`git push`、签名、公证或发布。
5. 新增公共类型、Store 操作、状态或模块前先复核现有消费者；能够由现有 Provider、Session、
   `StepCommitted`、Desktop 偏好和工具投影承载的事实不得另建生命周期。
6. 自动化和迁移验收只使用测试创建的 TempDir／隔离 Runtime Home，不读取、复制或修改用户
   `~/.ez-assistant`。涉及 SQLite 的里程碑开始前仍须重新列出实际文件、表、预期影响和备份路径。
7. 本版隔离数据库没有网络主机和端口：源／目标都是当前测试 TempDir 中同一份 SQLite 文件；M0
   只允许迁移 `providers`、`schema_migrations` 及版本账本，预期 Provider 行数不变，增加目录列和
   `0.26.0` 迁移记录。破坏性故障夹具执行前先创建独立备份，重新只读打开并对关键表精确计数。
8. 真实 Provider 联调仅用于证明显式刷新和“其他路径零目录请求”，使用获准连接且不把凭据、原始
   响应或敏感参数写入文档与日志；无连接条件时用 loopback 假 Provider 验证请求计数并记录实测缺口。
9. 文档、注释和测试名称属于交付内容。跨持久化/内存、事件提交/live 投影、审批判定时点、偏好
   回退和 Shell 生命周期等非显然边界必须同步中文注释，不能只靠测试暗示。

## 四、里程碑明细

### M0：版本、协议与模型目录后端基线（✅ 已完成）

**目标：** 建立 v0.26.0 的协议、版本、Provider 目录持久化和安全迁移底座，使后续功能只依赖一份
权威本地目录事实。

**前置依赖：** 本开发计划获得用户确认；开始前读取协议、Runtime、Host、Desktop 对应规范与模块约束。

**交付范围：**

- 将 workspace、Host、Desktop、Client 和 TS 协议包的软件版本统一升到 `0.26.0`；先列出最终
  Rust/TS DTO、command/result、SSE 快照与 Host 行为相对 v0.25.3 的兼容差异，再独立确定应用协议
  minimum。按当前破坏性响应与隐式联网语义预计为 `0.26.0`；若最终实现消除全部破坏性变化，则
  保留 `0.25.3`，不得因软件升版机械抬高。
- 增加已确认的目录快照 DTO、诊断、显式刷新 command/result 和 Rust/TS 导出；接通 Runtime/Host
  的本地 list 与显式 refresh 后端，不保留只为后续占位的死字段。
- 在 `StoredProvider`、`RuntimeStore` 和 Host SQLite 实现目录读取、原子替换与连接变更标记；保持
  Provider 为唯一 owner，不新增目录表、revision、TTL 或后台任务。
- 实现 refresh 后端的 5 秒连接/20 秒整次发现预算、完整成功后原子替换、连接 currentness 复核和
  分类错误；本阶段不改 Desktop，也不宣称既有隐式目录调用已经清除，该切换属于 M1。
- 新增 `v0_26_0` migration；按当前增量列方案继续声明数据库最低 Host `0.25.3`。只有旧 Host
  读写夹具证明存在误读、破坏或覆盖风险时，才提升到 `0.26.0`；旧 Provider 升级后目录为空，
  不联网回填，不扫描或改写 Run/Input。
- 覆盖目录 JSON round-trip、损坏降级、失败不覆盖旧值、并发连接变化冲突，以及 v0.25.3 ↔
  v0.26.0 应用协议兼容/拒绝矩阵和旧 Host 对较新数据库的拒绝路径。

**验证入口：**

- `cargo test -p assistant-protocol` 及 Rust/TS 协议导出检查。
- `cargo test -p assistant-runtime-host` 的迁移、model management、compatibility 定向用例。
- `cargo test -p assistant-runtime` 的 Store/配置目录定向用例。
- 对人工构造的 v0.25.3 隔离库：迁移前验证备份可读及 `providers`、`sessions`、`runs`、`inputs`
  精确数量；迁移后核对数量不变、新列默认值、schema migration 和 minimum host version；另用旧 Host
  Provider SQL 兼容夹具验证新增列不会被既有更新意外清空，并验证旧 Host 因较新 schema 被明确拒绝。
- 受影响 Rust package 的 fmt、Clippy 与差异检查。

**完成判定：** 隔离旧库可安全升到 v0.26.0，失败保持源库/备份可恢复；目录持久化及 list/refresh
后端可往返；应用协议和数据库 minimum 都有独立证据，数值是满足最终变化的最小版本；不兼容混连和
旧 Host 回退被明确拒绝；没有第二张目录表或 Run/Input 批量改写。

**Review 重点：** Store 是否接收稳定业务事实而非 HTTP/SQLite 细节；目录失败是否保留旧快照；迁移
是否验证独立备份和精确数量；是否把软件版本误当 minimum；协议拒绝/兼容是否覆盖 Client、Desktop
与 Host 两个方向，数据库 minimum 提升是否有旧 Host 数据安全证据。

### M1：模型目录显式刷新与关键路径断网（✅ 已完成）

**目标：** 完成模型目录的产品闭环，确保只有用户显式刷新会访问 Provider 目录接口。

**前置依赖：** M0 已确认。

**交付范围：**

- 将 M0 的显式 refresh 后端接入唯一 Desktop 管理入口，回证超时、currentness、分类错误和失败保留
  旧目录/时间/连接变更标记；不在选择器、详情或应用启动时调用 refresh。
- 将 `list_provider_models`、模型详情、固定配置、默认/辅助选择、Session 模型切换、Run 装配、
  标题、压缩和 child 路径统一改为本地快照/固定配置/模板解析。
- 搜索并删除除显式 refresh 外全部生产 `discover_models` 调用点；不得以缓存命中、失败回退或
  后台刷新保留隐式网络分支。
- Desktop 模型管理页提供唯一显式刷新入口，选择器和详情只读本地；覆盖空目录、旧目录、刷新失败、
  连接变更、固定模型合并及可操作错误。
- 用 loopback 假 Provider 记录请求，分别跑应用加载、会话打开/切换、模型菜单、发送、标题、压缩和
  child，证明请求计数为零；显式刷新恰好产生预期请求。

**验证入口：** Runtime/Host 模型定向测试、协议 fixture、`settings-store`、`model-management`、
`model-picker`、`composer-dock` 单元测试、模型管理 E2E、Desktop build；必要时最小真实 Provider 刷新。

**完成判定：** 用户可显式刷新并跨 Runtime 重启复用最后成功结果；目录故障不会卡住会话或 Run；
所有非刷新路径零目录请求，本地参数不足时快速失败且不自动改选模型。

**Review 重点：** 是否仍有隐藏 Factory 调用；在线结果是否在连接并发变化后误落库；固定配置优先级、
敏感错误脱敏和旧快照保留是否一致；UI 是否把本地列表伪装成刚刷新成功。

### M2：Run/Input 原子收敛与恢复（✅ 已完成）

**目标：** 让所有启动前失败和既有终态 Run + queued Input 残留安全收敛，恢复会话管理能力且不重放副作用。

**前置依赖：** M1 已确认，模型准备失败已稳定为本地、可分类错误。

**交付范围：**

- 扩展 Run settlement，使启动前失败在一个 staged append 中提交原 UserMessage、将来源 Input 置
  committed 并终结 Run；关联或身份不一致时整次冲突。
- 新增定向 reconciliation Store 操作，只处理终态 Run 精确关联的 queued Input；使用既有 operation
  receipt 保证重放幂等，不改变合法 `accepted + queued`。
- 在 `SessionLoader::prepare` 中统一 running/cancelling 恢复与 terminal+queued 定向修复；`load`
  保持纯历史读取。
- 会话组合视图及删除、归档、清空、换模型、重入、手动压缩等 idle-sensitive mutation 在判断前
  走恢复边界；会话列表和标题搜索不触发正文扫描或写恢复。
- 覆盖模型、Shell、Skill、Tool/currentness 准备失败，Store 半途失败、重复恢复、无关 queued Input
  以及恢复后真实接口行为。

**验证入口：** `assistant-runtime` input/failures/runs/session-management/startup 定向测试，Host storage
staged append 与隔离正式 Host 集成测试；按改动执行 Rust fmt/Clippy。

**完成判定：** 任一 terminal Run 不留下自己的 runnable Input；原始用户消息可见且只提交一次；合法
队列未被误改，历史工具不重放；查看和各管理命令在恢复后按真实 idle 状态工作。

**Review 重点：** 精确 Run/Input/Session/message 关联、事务原子性、operation receipt 幂等、Store
失败后的 faulted 状态，以及是否误把读取列表变成批量恢复入口。

### M3：Live step 与工具参数投影（✅ 已完成）

**目标：** 让运行中时间线稳定交接到权威 Conversation，并让审批、live 和历史展示同一份安全工具参数。

**前置依赖：** M2 已确认，Run/Session 终态与恢复时序稳定。

**交付范围：**

- 将现有 `StepCommitted` 纳入 Desktop live 事件消费；按 owner、generation 和当前唯一非终态 Run
  封口 step，无法唯一定位时作废 live 尾部并刷新，不新增 run 序号或事件日志。
- `LiveExecutionStore` 增加 sealed step 状态、升序插入和迟到事件拒绝；sequence gap 在异步快照前
  同步清空 pending/live/seal，防止缺口两侧拼接。
- 抽出 Runtime 唯一工具输入投影器，落实类型化、敏感键隐去、深度/集合/字符串/总字节限制和
  `redacted/truncated/unavailable` 标记。
- 在 Tool Activity、父/子 ToolProposed、Approval、历史事件和详情中统一携带投影；Ask 审批的关键
  shell/path 字段若被截断则安全拒绝，不创建不可理解的审批。
- Desktop 只按协议类型渲染参数和完整性提示，不新增第二套解析、脱敏或工具名猜测。

**验证入口：** Runtime product/approval/delegation 与协议 fixture；Desktop
`live-execution-store`、`runtime-projection-store`、`conversation-view`、`tool-detail-dialog` 单元测试；
超过 30 条、多 step、child、gap/reconnect 与 General/MCP 敏感参数的正式 Host E2E。

**完成判定：** 迟到内容不能复活 sealed step，跨 Run/child/generation 不串线，gap 后由权威快照重建；
三处工具展示语义一致且秘密不出 Runtime，审批看不全关键操作时不能放行。

**Review 重点：** `StepCommitted` 的唯一映射假设、gap 清理顺序、跨 step `part_id` 去重范围、原始参数
是否进入事件/日志，以及 Desktop 是否偷偷形成第二份安全策略。

### M4：实时审批与 Desktop 新会话默认（✅ 已确认）

**目标：** 同一 Run 后续工具实时使用 Session 当前审批模式；原生 Desktop 按连接目标记住新草稿的
审批模式和最近具体模型。

**前置依赖：** M3 已确认；M1 已提供完全本地的模型准备和 Provider 事实。

**交付范围：**

- Authorizer/Resolver 移除冻结审批模式副本，父 Run 与 child 共用 Session Controller；每个工具调用
  在既定权限优先级下读取当前模式，Run 字段仅保留接纳时审计含义。
- 固定 `set_session_approval_mode` 的 Store/state/event/reply 顺序；模式切换不追溯 pending、已授权或
  已执行调用，state 更新失败进入 faulted 而不回复成功。
- 在原生 Desktop 偏好中增加每目标 `default_approval_mode` 和 `last_model_selection`，保持原子、串行
  保存与旧文件默认；普通 Web 继续使用 Ask 和 Runtime 全局模型默认。
- 新草稿创建时复制当前默认；草稿切换立即更新设备默认，已有 Session 仅在 Runtime 命令成功后更新；
  选择“默认模型”清除设备模型覆盖。
- Provider 已删除时清除最近模型并提示；只因目录缺少 ID 不清除固定/陈旧选择。已有草稿、已有
  Session 和已开始物化载荷不被追溯改写。
- 调整草稿 customized 基线、偏好保存失败反馈和本机/多个远端 namespace 切换。

**验证入口：** Runtime approval/permission/delegation/concurrency 测试；Desktop preferences Rust 测试，
`new-session-draft-store`、`session-management-controller`、`composer-dock`、`application-connection`、
`desktop-snapshot-persistence` 单元测试；正式 Host 父/子并发授权 E2E。

**完成判定：** Ask↔Auto 成功边界后新授权读取新模式，显式 Deny/Ask/Allow 优先级不变；Desktop
重启后每个目标的新草稿使用各自最近审批/模型，默认模型清除和 Provider 删除回退可见且不联网。

**Review 重点：** 授权读取线性化时点、pending 不追溯、Store 成功/state 失败、Web 与 Desktop 边界、
偏好无秘密/有界校验、已有草稿不被静默覆盖，以及 null“默认模型”语义是否仍由 Runtime 解释。

### M5：UI 与 Shell 语义收口（✅ 已确认）

## 五、版本级完成条件

开发阶段完成必须同时满足：

1. M0—M6（含 M5.1）全部完成实现、最小有效验证、实际结果记录，并逐个获得用户确认。
2. 功能设计 36 条验收标准均已映射到里程碑或后续正式验收，没有遗漏或以设计描述代替证据。
3. 目录联网只有显式刷新，Run/Input 可恢复，Live/工具参数、实时审批、Desktop 默认、UI 和 Shell
   语义均在同一候选构建闭环。
4. 隔离数据库备份、迁移、精确数量、关键字段、接口读取和回退拒绝均有实际证据；未操作用户真实库。
5. Rust workspace、Desktop tests/lint/build、正式 Host E2E、Tauri no-bundle 和适用三平台实机项
   有真实结果；未执行项已明确影响并由用户决定是否接受。
6. 软件版本、协议最低兼容、数据库最低 Host 均与各自证据一致，并与生成类型、文档和模块注释对应；
   minimum 未被机械抬高，且无临时兼容层、死字段、失效文案、调试产物或未说明偏差。
7. 用户确认 M6 后，才把版本状态从 `开发中` 改为 `验证中`，创建验收记录并开始正式版本验收；
   未经验收确认不归档、不提交、不发布。
