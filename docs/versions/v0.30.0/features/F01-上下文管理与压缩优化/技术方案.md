### 1.1 M0 后的接口边界（2026-10-10）

用户确认本体保持统一 HTTP 接口，API/订阅差异由企业中心封装。原生自动/手动共用
`POST /responses/compact`：API 上游直接转发 compact；Codex 订阅上游由中心构造有效
输入加 `compaction_trigger`，经 WS 请求原生状态，并规范化为完整 compact JSON 返回。
本体不识别订阅、不拼 V2 trigger、不增加 WS 客户端。

本版暂不引入普通生成请求中的 `context_management/compact_threshold` 自动机制，不能
将此范围缩减扩大为删除 HTTP compact。Runtime 按窗口阈值或模型超限触发同一原生
compact 方法；超限恢复仍受准入与无进展预算约束，不能保证任意超窗请求都可压缩。

M0 已通过临时 HTTP compact 封装连接真实订阅 V2，核实完整窗口映射、工具/图片、连续压缩和错误边界；M0 结果已获用户确认，正式企业链路随后在 M5/M7 验证。计量独立声明，当前路由不支持时沿用既有 usage 与增量估算，等待正常响应校准。

通过调小阈值或新增 Provider Options 完成接入。

| 现有入口 | 已有能力 | 本 Feature 的必要调整 |
| --- | --- | --- |

| `agent-openai-compatible/src/responses/` | 编码、严格流解码、route fingerprint、continuation v1 | 原生项编解码、原生参数、压缩后稳定续接校验、输入计量 |
| `runtime/model.rs` 与 `runtime/model/history_recovery.rs` | 图片准备、有限重试、单逻辑调用一次历史重建 | 新 SPI 逐层委托、计量图片准备复用、模式与可信作用域绑定 |
| Host `storage/conversation.rs` / `context_replacement.rs` | JSONL 可靠追加、本地摘要新 generation 与 SQLite 指针提交 | 原生结果沿现有追加；本地锚点引用校验、持久模式及最低 Host 准入 |
| Center `llm/{body,proxy,transport,websocket}.ts` | 透明创建代理、受控 WS 桥与身份准入 | 原生能力校验、独立 HTTP 计量路径，不能把计量当 response.create |
| `assistant-protocol/src/product.rs` | context 的 token、window、百分比均为非空数字 | 当前机制、准确度、未知值及父子任务一致消费 |

两个容易遗漏的事实：

1. 本地替换目前只允许 `System → Summary → 原历史连续尾部 → 可选能力恢复消息`，
   不能直接把较早原始 User 再插进尾部，否则会重复 MessageId 或破坏尾部校验。
2. continuation v1 的 `request_len/request_hash` 基于响应前完整请求；原生压缩会裁掉这个
   前缀，不能继续要求它与下次有效快照的 Assistant 下标相等。

补充核查：现有手动命令使用 prepare/replace/finish 和 `IdleSession` generation 切换，
`body_appends.run_id` 必填，不能直接承载没有 Run 的原生手动追加。`usage.rs` 按规范
消息记录费用，已用 MessageId 唯一键去重；没有可直接调用的独立手动原生费用入口。
因此手动分支复用已有 replacement 事务，自动原生分支仍沿已有响应追加。

手动压缩当前没有运行中的工具快照，构造的摘要请求 `tools=[]`。本稿复用该独立操作边界，
不把空工具摘要请求的计量冒充下一次正常 Agent 请求的窗口计量。

## 三、目标架构、权威状态与最小新增

### 3.1 所有权和依赖

保持既有进程与 crate 方向：Desktop/Web 发送意图，Runtime 拥有 Session/Run 与唯一机制，
Host 负责存储/传输，Core 负责一次执行，Context 负责纯规则，Adapter 负责 Provider wire。
不新增 crate、进程、压缩服务、计量数据库表、全局队列或并行历史文件。

| 事实 | 唯一 owner | 其他层怎样使用 |
| --- | --- | --- |
| 模型自动压缩启用配置及已核实支持能力 | 现有个人模型配置 / 企业模型源 | Runtime 编译不可变模型实例，客户端展示来源 |
| 当前会话使用的机制 | Runtime Session；Store 可靠保存 | Core/Adapter 接收冻结策略，不能重新选择 |
| 原始产品历史及已提交压缩事实 | Runtime 的 RuntimeStore 端口；Host 物理实现 | Context 作纯投影，UI 只读历史 |
| 本轮待执行请求、计量值 | 当前执行 owner 的不可变请求和易失测量结果 | Evaluator 与 UI 使用对应快照，不跨请求沿用精确标记 |
| 原生编码、路由相容判断与计量 HTTP | 构造期固定的 ModelService / Adapter | 不持有另一份 Session/Journal 或内存链头 |

按有序 Parts 定位原生替代边界、保留该项及后缀的最小纯操作放 `agent-types`，与规范对话
及配对校验相邻；Context 与 Adapter 的续接哈希都需要这项操作，不能各写一套。
该操作只接收规范消息，按最近已提交边界投影，不依赖模型名称、入口地址、Store 或产品 ID。协议与窗口格式归 Adapter 校验。
模式感知的布局与有效投影放 `agent-context`，由 Core/Runtime 使用；产品历史的 User
引用解析、模式选择和可靠提交留在 Runtime。Adapter 仍只依赖 Model/Types，不反向依赖
Context；Core 不依赖 Runtime 或具体 Adapter。

### 3.2 必要新增及排除项

| 新增事实 | 为什么现有事实不足 | 消费者 |
| --- | --- | --- |
| ProviderState 可选 `context_effect` | 普通 reasoning/continuation 不能作为替代前文的边界 | 共享校验与投影、Runtime、Responses Adapter |
| AssistantMessage 缺省为模型回复的 `purpose` | 原生压缩状态不能冒充普通模型回复；费用分类、历史展示与窗口基线需要共同识别这项来源 | Adapter、Store 费用去重/恢复、Runtime/UI |
| Summary 可选 `retained_user_message_id` | 连续尾部不含较早 User 时，不能保留任务原文而又不重复写消息 | Runtime 合并/恢复、共享候选校验 |
| Session 当前及 child 冻结的 `context_management_mode` | 当前模型配置可变，仅从当前设置或是否出现压缩项无法恢复原先机制 | Run/手动准入、重启恢复、父子任务展示 |
| ModelService 的只读上下文策略、可选输入计量与显式原生压缩方法 | stream 不能查询 token 或执行非生成的原生压缩，也不能靠 private options 决定 Core 是否触发本地压缩 | Core/Runtime、Adapter、装饰器与 testkit |
| 原生完整窗口状态 | compact 返回整个规范窗口，自动/手动共用有序 output 封装与 usage，以 purpose 区别普通回复，不另建压缩账本 | Adapter、Runtime 自动/手动操作、Store |
| context 展示准确度及可空数字 | 现有三个数字无法表达估算/未知，`None` 又无法携带已知模型窗口和机制 | Desktop/Web、子任务、协议包 |

持久账本或 token revision。原生边界的位置由有序 Parts 已经表达。

## 四、模型配置与执行机制冻结

### 4.1 配置归属

在既有 `ModelParameters` 中增加以下字段，Rust/Center DTO、手动参数页、固定参数页和
模板解析同步，沿用字段来源与只读管理规则：

| 字段 | 含义与默认 |
| --- | --- |
| `server_compaction_enabled: bool` | 选择服务端原生机制；缺省 false，关闭使用本地摘要，不能从能力推导为 true |
| `server_auto_compaction_enabled: bool` | 选择由服务端自动判断触发；依赖前项启用。false 时由 Agent 判断并调用 compact；缺省 false，本版仅允许 false，UI 标注暂不支持 |
| `server_compaction_support: ModelFeatureSupport` | 当前路由 compact 与完整有效窗口回放能力；缺省 unknown，不代表服务端自动触发能力 |
| 原生手动能力 | 与自动共用同一 compact 能力，不另加手动接口能力字段 |
| `input_token_count_support: ModelFeatureSupport` | 当前路由输入计量能力；缺省 unknown，与压缩支持独立 |

两个启用子项分别表达“谁生成压缩结果”和“谁决定自动触发”，不可合并。关闭
server_auto_compaction_enabled 时，Agent 自动压缩仍开启，按阈值/模型超限调用 compact；
手动共用该实现。未来启用服务端自动触发时，必须停止 Agent 的竞争性自动 compact，
手动仍跟随原生机制，且需独立能力与协议验证。

本版保留这两个配置概念，但不实现服务端自动触发；自动子项不可开启，持久/输入配置
true 明确拒绝，不能忽略或静默改为 Agent 触发。父开关 false、子项 true 也是无效组合。
该说明不授权预建未来原生自动参数、迁移或第二个会话触发状态；具体字段随 M1 统一落地。
能力字段属于准入元数据，不与上述用户启用选项混作同一开关。

不在 ProviderConnection 重复增加业务启用开关，也不在 Session 提供自由混搭开关。已有
`server_history_enabled` 继续只决定是否使用远端 ID 续接：服务端原生压缩允许在无 ID 的
完整有效输入模式工作，不能强制它依赖服务端历史开启。

启用原生模式要求：Responses 协议、压缩能力 supported、完整原生项处理和可信作用域均
可装配；不满足则配置/准入失败。计量 unknown/unsupported 不阻止原生执行，显示准确度
按第九节处理。Provider Options 禁止注入 context_management/compact_threshold，普通请求不伪造 trigger。原生自动/手动共用已核实的 compact 能力，入口另检查操作互斥与绑定；不支持或未知时明确不可用，不回退本地。企业上游协议选择归中心当前模型装配，本体不增加 API/订阅类型字段。

支持事实来自经核实的模型模板/显式配置及企业上游能力；不按模型字符串、代理地址或历史
续接支持猜测。M0 已证明一个拟接入代理上游的 V2 协议可用，不将其外推至其他账号、代理或企业产品链路。

### 4.2 绑定与变更

`agent-model` 增加中立 `ContextManagementMode`：`LocalSummary / ServerCompaction`。
`ContextPolicy` 表达服务实例冻结事实：本地模式，或原生模式下的阈值与原生状态作用域
指纹。它不含 endpoint、credential 或产品 ID，Debug 隐去指纹。

新 Run 准备读取最新模型固定参数；未保存固定参数的在线模型可复用本进程中仍有效的已接纳
绑定，不隐式联网。配置刷新后无需额外重新选择同一模型。领取输入前，在既有 mutation gate
下从完整产品历史准备目标 Journal；User 提交（或重试 Run 领取）与当前机制在同一可靠提交点
落账，成功后才替换内存 Journal。活动 Run 的 ModelService、策略和 compactor 始终冻结。
目标投影准备失败结算本次输入并返回明确错误，不把普通模式变化标为 Session 内部故障。

空闲手动压缩同样读取最新参数，在既有模型绑定提交路径中接纳机制，再执行用户要求的
压缩。显式换模仍沿用既有续接身份旋转与 Journal 重载；两条入口共用压缩点投影规则。
模式变化本身不生成摘要、不调用 compact、不改写完整历史。参数刷新不批量迁移或压缩所有
Session；新操作准入时才接纳。失败不启动另一机制兜底。

重建从后向前选择最近可用压缩点：原生模式可选相容原生窗口或文本 ContextSummary，
后者沿既有 renderer 编码为 system message item，并接后续消息，无需转换为原生状态。
本地模式过滤原生压缩记录，复用最近文本摘要及后续原始事实；没有文本摘要则使用原文。
原生密文不解密、不冒充文本。模型名称、入口地址及临时续接周期变化不丢弃已提交窗口；Provider/Protocol 与格式由 Adapter 校验，临时 ID 仍按当前路由与绑定决定续接资格。

child 在 accepted 时从自身已装配模型冻结机制，与现有冻结 `context_window_tokens`
一起保存；不得在读取历史 child 时从当前默认模型猜测。child 不继承父的原生密文或续接 ID。

## 五、历史格式与有效投影

### 5.1 统一 compact 完整窗口

扩展 `OpaqueProviderState.context_effect: Option<ProviderContextEffect>`，第一版仅
ReplacePriorContext，缺失省略，保持旧字节与普通 reasoning/continuation 的原语义。

自动/手动共用 `state_type=responses.compacted_window`、media_type=application/json、
format_version=1、context_effect=replace_prior_context，route fingerprint 记录产生结果时的
路由/可信作用域，不作为已提交完整窗口的回放门槛。payload 保存完整 compact 返回对象，尤其有序 output，不解密原生项。
该格式是完整窗口事实，不能只保存最后一个 compaction item 或丢弃保留消息再裁一次。

Adapter 下一次编码时将 output 整体展开为有效输入；内部必须通过受支持项、完整工具
配对和整体传输校验。普通 reasoning 保持单项 2 MiB、单响应状态总计 8 MiB；完整替代窗口
包含保留消息和图片，不套用普通 item/turn 上限，受控构造、JSONL 重载及回放使用同一规则。
JSON 辅助响应的整体传输预算为 32 MiB，超过时明确报告预算错误，不丢项凑数；企业中心
移除完整 compact JSON 的专用 2 MiB 门槛，继续使用通用请求、并发与 WS 缓冲预算。
第一版普通生成请求不启用原生自动阈值，若意外收到无法归属的压缩边界，按机制/协议错误
拒绝，不静默改变原生协议。瞬态 trigger 仅由中心订阅适配产生，不写入产品历史。

订阅 compact 的保留内容由中心作无状态协议转换：用户/客户端 developer 输入按原顺序
保留，随后追加完整原生 compaction 项。已闭合原生 function_call_output 中的图片需作为
带来源 call_id 说明的保留图片消息加入窗口；已采用用户图片信封的输入则原样保留。图片
URL/字节、detail 与顺序保持，不重复执行调用，不把已压缩工具文本重新塞回窗口。
工具配对须在提取前校验，不处理 pending/半组交换；M0 已证明两种图片形状的真实回放。

第一版不照搬 Codex 的固定保留预算或截断原始用户任务来凑大小，保留内容过大按既有
输入/传输预算明确失败。原始工具/图片关系仍保存在产品历史中，中心不持有 Session/
Journal；本体整体回放返回窗口，不再解释或裁剪其中保留项。

### 5.2 共享投影与配对校验

在 `agent-context` 增加纯函数入口（拟名 `project_effective_context`），输入规范快照和
冻结策略，返回合法有效快照或稳定错误；原生边界切取委托 `agent-types` 的共同操作。
Runtime 先完成产品历史选择与引用展开，再调用共享入口；Core 在可靠交换完成后也调用
同一入口，不实现第二套裁剪。Adapter 复用 Types 的有效投影，不承担本地摘要策略。

- 本地模式：识别最新文本 Summary，拒绝把原生替代项作为本地压缩边界。
- 原生模式：从后向前选择最新文本 Summary 或已可靠提交的 `replace_prior_context`；
  保留 System prefix、该摘要/原生项及之后的完整消息，原生项同时保留同一响应中它之后的 Parts。
  文本 Summary 保持现有 system message 编码，轮内原始 User 引用仅展开一次，重复投影幂等。
  自动/手动共用完整窗口容器；仅在容器外确定替代边界，不解释密文或再次裁剪 payload 内的 output。
- 本地模式不使用原生压缩记录作为输入边界；不相容 ProviderState 不回放，但普通
  原始 User/Assistant 文本和工具事实保留，用于目标模式重建。
- 裁剪后的首条可以是仅含原生状态的 Assistant，而没有原始 User。扩展合法起始布局，
  不为满足旧布局生成假的 User；本地摘要仍有明确 User 锚点。
- MessageId 在产品历史中保持唯一；裁剪只改变派生 Parts，不改写原始消息。

工具配对校验统一留在 `agent-types`。原生边界只在没有未完成配对时重置已使用调用 ID；
同一 Assistant 若在最后压缩项之前已经声明了 ToolCall，裁剪会使其后结果失去配对，第一版
拒绝该排列，且必须在 begin_tool_exchange/授权/执行工具之前拒绝。不能先执行，再发现
边界非法。支持的排列必须包含完整原生项，并把本批工具调用留在有效边界之后。

完整历史读取、响应接纳、Journal 和最终 Provider 请求使用同一校验；不得为原生模式全局
放宽“一批调用后立即按序跟随全部结果”的约束。新增排列以严格 fixture 与真实路由核验
支持范围；发现上游产生不可表示的合法排列时先回到设计，不静默丢弃。

### 5.3 本地轮内摘要的 User 引用

扩展 `ContextSummaryMessage.retained_user_message_id: Option<MessageId>`，只引用本地
轮内回收需要保留、已可靠存在的原始 User；缺省不改变已有完整轮次摘要形态。
该引用不表示摘要的覆盖范围，不构成消息复制或新的 continuation 身份。

例子：`U → X1 → X2 → X3`，X 表示完整工具批次。本地候选为
`Summary(引用 U) → 原样 U → 原样 X3`，产品历史写成 `U → X1 → X2 → Summary → X3`。

Store 合并时确认引用 U 确实来自原始历史、内容完全相同，然后从候选的尾部匹配中剥离
该一条引用展开项；剩余 X3 必须仍是原历史的精确连续尾部。只在 Summary 内保存 U 的 ID，
不把 U 再写入 JSONL。恢复时从唯一原始 U 展开 `Summary → U → X3`。重复压缩继续引用
同一个原始 U，不创建别名或重复 ID。

仅在原样尾部已不含 U 时使用引用；尾部本来含 U 则沿用旧形态，不能再次展开同一 ID。
候选中被剥离的展开项必须恰好一条，正文与引用校验不允许通过跳过任意重复消息完成。

引用必须存在、位于该 Summary 之前、role=User，不能自引用/引用 Summary 或指向另一个
generation 的不存在消息。Fork/历史改写后缺失引用不得猜测；拒绝激活该边界并从可用完整
原文按确认规则重建。旧 Summary 无字段仍按既有连续尾部规则读取。

这会调整 Store 的尾部校验、共享布局与 effective projection，不新增 ContextCheckpoint
表或第二文件。仅在无 pending 批次的本地摘要替换中使用；原生模式不创建该字段。

## 六、本地轮内回收与进展预算

### 6.1 分区规则

复用 `ContextLayout` 和 `RollingSummarySameModel`，增加闭合 Tool Exchange 的内部视图；
不把每条消息都升级为公共 block 类型。先尝试旧的完整轮次分区；回收不足且当前轮次膨胀时，
在共享分区逻辑选择轮内安全切点。

1. 保护当前任务原始 User 原文和 Part/附件引用；可从当前有效快照找到最近可见任务 User。
   后续隐藏 Runtime User 不替代真实任务指令，必要能力上下文仍由既有恢复规则保持。
2. 保护至少最新一批完整交换及其后内容；较早已闭合批次可摘要，整个批次不可切开。
3. 没有完整可回收批次、尚有 pending 或无法识别任务锚点时不强行构造轮内候选。
4. Summary 必须准确区分已完成动作、结果、未完成事项和当前任务约束；压缩指令明确只
   摘要所选 head，不能把将原样保留的 tail 当成已经被替换的历史。

摘要请求仍克隆正常冻结请求、保留系统/工具与原前缀，仅在尾端追加临时指令，关闭工具并
设摘要输出上限 4096。head/tail 与用户锚点的范围只以内部压缩指令表达，不改写原正常历史。
无需新模型、分块摘要循环或结果按需取回协议。完整摘要请求本身不能装入时有界失败；
提前触发能降低风险，但不承诺巨型工具输出已经超窗后还可执行旁路摘要。

正常自动摘要有工具时仍要求 `tool_choice=None` 能力；手动路径没有活动工具快照时延用
其独立请求，不创建 Run、不运行工具。两者复用相同布局、候选、恢复和 Store 提交流程。

### 6.2 候选效果与继续条件

继续复用共享候选校验、程序化记忆变更保持和 MCP/Shell 恢复；恢复内容加入后再次校验。
完整产品历史不减少，`compacted_usage` 只累计实际替换 head，不提前吸收保留批次的费用。

本地文本候选保留现有紧凑字节缩减检查作为最低防线，同时比较同口径有效输入计量/估算。
字节变小不能单独证明已装入窗口；原生项不走文本摘要的字节缩减判定，不能以密文长度
推导回收 token。若候选有无法量化部分，明确准确度限制，后续 Provider 准入仍是硬边界。

原 `MAX_AUTOMATIC_COMPACTIONS=2` 不再表示整个长 Run 最多压缩两次。改为最多两次
连续恢复尝试，取得新的正常模型结果后才恢复额度；单纯换摘要不重置。维护在现有 Run/child
执行循环的局部状态，不持久化新计数或以压缩重置 Core 步数/工具预算。

摘要明显缩减但仍高于软阈值、且未触及已知硬限制时，允许一次正常调用验证进展，不立即
重复摘要同一源。该一次许可随本地 continuation 显式传入窗口判断，使用既有 step/提交
边界识别来源，不做全局冷却定时器。若立即再次 overflow 且没有新增可回收内容，则停止，
不靠第二次“摘要上一个摘要”耗尽费用。没有安全 head、候选无效或已知必要输入过大直接失败。

## 七、原生结果的提交、投影与续跑

### 7.1 本体统一 HTTP compact

自动/手动均调用显式原生压缩方法：使用冻结的当前有效输入、系统指令和准备结果，向
HTTP `/responses/compact` 发出一次请求并读取完整 JSON。第一版按标准允许字段发送
model/input/instructions，工具调用/结果在 input 中；不把正常生成的 tools、stream、store
或其他专用字段原样带入。正常任务的冻结工具定义仍在其模型请求中保持。本体只处理公共接口契约，
不发送 compaction_trigger，不识别订阅来源，不实现 WS。

普通模型 `/responses` 继续原有流式调用，不发送 context_management/compact_threshold。
原生模式不装配 RollingSummary。Runtime 根据窗口判断调度 compact，Adapter 不隐藏
额外任务/工具循环；压缩结果不能被当作任务最终回复。

compact 响应要求完整成功对象、有序 output、合法原生状态及工具配对，未知/不支持项
不能静默丢弃。API 上游完整返回窗口原样保留；中心订阅适配负责从 WS 终态取得可回放
压缩项及该协议要求的保留内容，统一响应格式。只收到 added、半截密文、failed/incomplete
或连接中断时不返回成功 compact，不能激活候选。

若将上游进度暴露给本体，需要现有协议真实支持；当前 compact JSON 请求复用操作进行中
与取消状态，不因中心收到某个 WS 帧就伪造本体流事件。

### 7.2 自动操作的可靠边界

普通任务响应继续沿既有工具批次与最终回复提交。原生自动压缩是 Run/child 内非终结操作：
在工具批次已可靠闭合时发起，完整状态可靠提交后更新 Journal/Core 有效投影，再继续同一
任务。不能把只有状态的响应当作任务成功完成，也不能执行任何工具副作用。

自动结果复用带 run_id 的既有追加基础设施，产品历史完整保留，不旋转 generation；
手动仍按 §7.4 使用空闲 replacement。具体 Recorder 非终结提交入口与交还宿主位置需
M4 对现有生命周期核实，不为协议验证提前新增 owner/调度器或伪造工具交换。

可靠提交后以共同纯投影同步 Runtime 与 Core，优先复用已存在的 ContextChanged 交接；
旧 ID 能否继续由 continuation v2 对当前有效输入校验决定，不能因收到 response ID 就
跳过一致性校验。失败、取消、未完成流或 Store fault 保持上一可靠边界；不得重放工具。

### 7.3 压缩窗口与临时续接作用域分离

2026-10-12 用户确认：模型名称和企业入口地址不能作为已有压缩窗口的失效条件。
完整窗口是宿主授权提供的可靠历史内容；Adapter 继续校验 Provider/Protocol、窗口格式、
大小和完整工具交换，实际原生项能否被当前上游接受由该上游判定。损坏或协议不兼容明确
失败，不静默跳过最近窗口退回很早的文本摘要及全部旧原文。

现有指纹仍记录新结果的 provider/protocol/endpoint/model 与可信 owner/配置周期。
Runtime 校验本次新 compact 返回的归属，防止迟到结果落入其他操作；已可靠提交的窗口
回放不再比较这个指纹。保留既有 JSONL 字段与 payload，无需生产迁移、重签或批量改写。

临时 `responses.continuation` 与独立 encrypted reasoning item 保持原有精确路由规则。
换模、入口地址、配置参数或续接周期变化使旧响应 ID 不匹配时，按最近完整压缩窗口及后缀
重建新链；不能把“不能复用旧 ID”解释为“压缩内容也失效”。企业中心原有配置绑定继续
用于当前请求准入和临时链，绑定变化不再通过本体投影丢掉已有窗口。

关闭 ID 续接但开启原生压缩时仍校验新 compact 结果归属；compact 请求始终不带
`previous_response_id`。订阅上游由中心转 WS，是否使用 store=true 不改变该适配事实。
Fork 从宿主授权继承的截断历史选择最近完整窗口，使用自己的临时续接身份；child 仍使用
独立任务历史，不自动继承父窗口或续接 ID。

### 7.4 同一个 compact 实现与手动提交

在 `ModelService` 增加可选 `compact(ModelRequest, ModelCallContext)`，默认
不支持，结果复用 `Option<AssistantMessage>`，不另建结果类型。自动和手动调用同一方法，
编码、传输及结果校验一致，均调用 HTTP `/responses/compact`。

AssistantMessage.purpose 缺省 ModelResponse；原生压缩结果为 ContextCompaction（涵盖自动/
手动），含一个完整窗口 ProviderState，无可见回复或 ToolCall，usage 为本次真实消耗。
普通任务 stream 与显式压缩操作分别校验用途，压缩结果不能流入工具执行或最终回复结算。
所有装饰器委托同一方法，图片准备复用 §9.1，不隐藏正常推理重试/历史重建循环。

1. 手动沿既有 operation owner/mutation gate 检查当前机制、能力及绑定；活动 Run/pending 未收口时拒绝。只发送当前有效窗口，不默认回传完整产品历史。
2. Adapter 调用 HTTP `/responses/compact`，按接口允许字段编码当前有效输入，不带 previous_response_id、store/stream 或自动阈值。中心按当前上游配置直接转发或封装 WS V2，返回统一的完整 compact JSON。
3. Runtime 使用 `System prefix → 状态消息`（及 M0 核实的必要保留内容）候选，复用 `ContextReplacementTarget::IdleSession`。Store 保留完整原历史、增加压缩事实；新 generation fsync 后事务切换指针、完成回执及费用。无 Run 的手动不使用要求 run_id 的追加通道。
4. Store 成功后替换有效投影，旧续接失效；下一正常请求无旧 ID 新建链。完整压缩窗口不随临时续接身份失效。
5. 唯一计费来源是状态消息 usage，沿现有 `record_usage_messages` 以 `context_compaction` 分类，用既有唯一键去重。自动归属当前 Run；手动 request_id=MessageId、run_id=None，并在 replacement 事务落账。payload/历史旧项不重复累计，缺失 usage 不填零。

自动/手动使用同一种完整窗口封装与同一个 compact 能力，不另设手动专用封装。两种提交
方式沿已有活动 Run 与空闲操作边界，不能演变为两套压缩机制。窗口计数描述有效输入
替换，不表示物理删除；压缩 usage 不冒充压缩后占用。

取消、超时、校验/提交失败保留旧窗口，绑定改变或取消后的迟到结果丢弃。原生操作不
套用计量 3 秒预算；响应建立和正文空闲超时沿用宿主配置的模型 Transport（默认 300 秒），
不额外施加固定 120 秒总时限。不盲目重发付费压缩、不回退本地摘要。

### 7.4.1 Goal 累计 token 限制取消

2026-10-11 用户要求取消 Goal 的累计 token 上限。Goal 续跑门禁不再根据累计用量暂停，
模型注入和跨会话状态报告不再包含剩余 token 或上限；公开 Goal 投影删除 token 上限及
对应暂停原因，界面仅展示累计用量。已有运行次数、连续失败、取消及 Core 执行限制继续生效。

正式用户库已有 `session_goals.max_total_tokens` 和旧 token 暂停记录；保留存储列及旧原因
解码以读取这些数据，不做删除列迁移或生产批量更新。该列仍写原 schema 的固定占位值，
不参与执行或公开投影；旧 token 暂停在内存中按需要显式恢复处理，用户继续后不再次卡在
累计 token 上限。累计 usage 和完整性标记沿用既有统计。

### 7.4.2 Goal 超限统计读取

2026-10-13 验收修正：`used_runs` 是已发生累计事实，恢复时允许其超过 `max_runs`，保留原统计及暂停状态，不将整个会话判为存储不可用。配置、类型、目标摘要、状态及时间合法性校验保持；自动执行门禁继续使用 `used_runs >= max_runs`，剩余次数使用饱和减法。无新增迁移、生产计数重置或历史改写。修正经用户要求并入本版归档。

### 7.5 原生模式的程序化事实保持

原生状态不能替代宿主已经掌握的精确记忆净变化。复用
`context_compaction/memory.rs` 从完整产品历史推导的结果，在原生模式的请求准备阶段
合并入本次冻结的系统/宿主指令层，不读取密文推断变化，也不创建本地 Summary。
正常准备继续核对当前 MCP/Shell 能力事实；compact 完整窗口保持原样，新增的
宿主事实在其外按既有指令装配加入。计量和续接哈希使用同一准备结果；净变化/能力语义
改变时失去旧 ID 资格，重启仍从完整产品历史及当前装配重建，不持久化第二份事实缓存。

## 八、续接一致性、断流与换模重建

### 8.1 continuation v2

原生边界会改变请求前缀，采用统一 v2 校验，不在原生模式关闭增量续接来回避问题。
`responses.continuation` 仍是普通 ProviderState，没有 context_effect。v2 保存：

- 现有可信 binding 与 response_id；
- `context_len`：将完整请求与新 Assistant 合并、按当前边界规范化后，截止该 Assistant
  的消息数；响应内 Parts 的裁剪已包含在规范化结果中；
- `context_hash`：上述有效 wire 前缀及固定语义参数的规范哈希，排除 continuation 元数据、
  store/stream/previous_response_id 等传输控制字段；包含系统、工具、reasoning、受管压缩
  参数及实际图片投影；
- 仍保留当前 Assistant 原生输出对应的校验依据，或将其完整纳入 context_hash，不能只
  校验 response_id 存在。

Service 构建候选时必须保留本次不可变请求和 PreparedModelImages 的生命周期，不再只把
旧 request_len/hash 传给尾部 attach。attach 先移除待写 continuation，使用 Types 的共同
原生规范化操作计算有效前缀，再生成 v2；本地 Summary 已在冻结请求中，无需 Adapter
重新选择摘要。每个响应最多附加一份 continuation。

编码器拆分“完整请求工具配对校验”与“已校验项的机械编码”。哈希计算可以机械编码截止
Assistant 的前缀（此时结果尚未返回），但真正出站的完整请求仍必须通过全部配对校验。
不得为支持哈希而放宽真实请求 validator。图片信封在真实结果批次之后生成，不被前缀
哈希提前猜测；下次比较前缀时也不包含后加的该批结果/信封。

下次调用先编码并校验完整有效请求，再定位最近相容 v2，在截止该 Assistant 的同样前缀
上计算哈希；匹配后只编码其后新增消息，设置 previous_response_id。这保证裁剪发生在
本地重建输入而不是远端 ID 链；不向远端发送“删除前缀”命令。

模式、路由、作用域、系统/工具/图片或相关语义参数变化导致不匹配时，不使用旧 ID，按当前
可靠有效输入发起新链。JSON 对象的 canonical 编码规则复用现有 serde/BTreeMap 稳定
路径，新增缺省字段必须省略，哈希不依赖内存地址。

v1 元数据保留在原始历史，但不维护两套写入和恢复算法：读取为普通 opaque state，不
获得 v2 续接资格，首个请求从完整有效上下文新建链；这不影响原始正文，也不是压缩机制回退。

### 8.2 有界恢复

继续复用 `CallScopedHistoryModelService`，每逻辑调用只处理一次明确的建流前
`HistoryUnavailable`，后续有限瞬态重试保持 rebuild=true。完整有效输入从最近相容、
已可靠提交的边界及后续内容构造；没有边界时才使用未压缩的相容原文。

流中断开不等同旧 ID 丢失，沿用原请求的有限 attempt 预算和 TurnRestarted 清理；不能
激活部分 compaction 或重放已执行工具。取消/认证/协议错误不因为“可能能重建”无限重试。
原生模式 ContextOverflow 不交给本地 RuntimeContextCompactor。通过同一个 compact 方法作有界恢复；若 compact 自身也返回 ContextOverflow，停止本次恢复，不重复同一超窗输入。M0 已验证原生压缩输入也受窗口限制，不承诺错误后必可恢复，不切换压缩协议或回退本地摘要。

换模或参数刷新后的新操作基于完整产品历史，按目标模式从后向前选取可用边界；
服务端模式选最近完整原生窗口或直接复用 Agent 文本摘要，换模不丢弃原生窗口；本地模式只认文本摘要；
不解密转码、不把原始历史全量重发作为无条件保证。新输入超限时报告必要输入过大。
Session 模型修改和 Journal 替换均在既有串行边界完成，旧响应不能落进新绑定。

## 九、计量 SPI、窗口判断与展示

### 9.1 最小模型契约

在 `ModelService` 增加只读 `context_policy()` 和可选
`count_input_tokens(&ModelRequest, &mut ModelCallContext) -> Future<Result<Option<u64>, ModelError>>`。
默认策略为 LocalSummary，默认计量返回 None（不支持）；不新增独立计量 trait、服务或
ModelEvent 流。该能力有真实消费者 Core/Runtime，且由模型路由实现，不能只留空接口。

所有装饰器必须委托新方法：RetryingModelService、ObservedModelService、图片准备、
CallScoped/RecoveringHistoryModelService，以及 testkit/demo 使用的包装器。计量本身不
进入模型生成 retry/历史重建额度，不生成 TurnStarted、工具或 Assistant 消息。

提取 ImagePreparingModelService 中已有图片准备为内部 helper，计量与正常调用复用同一
不可变请求及 PreparedModelImages；不在计量后重新读文件得到另一张图。附件与 Tool Image
仍有独立命名空间。准备失败按已有输入错误处理，不能计量时忽略图片、正常调用再加入。
Core/Runtime 为同一步创建一份 ModelCallContext，图片包装器通过可变借用填入已有
prepared_images，计量结束后将这份 context 交给正常 stream。不能只在计量方法的私有
clone 中准备图片，否则返回 token 数后正常调用仍会重新读取。所有包装器透传同一准备
结果；没有计量支持时正常 stream 仍按既有路径准备，不为了返回 None 额外读图。

### 9.2 Responses 实现

通过现有 Transport 对 `POST /responses/input_tokens` 发一次 HTTP JSON 请求。
使用完整有效输入、不带 previous_response_id，包含与真实调用一致的 model/instructions/
tools/reasoning/图片与原生项；计量不依赖远端 ID 链是否仍存在。
从统一编码器派生计量 body，只保留计量接口已声明支持的字段，不把 stream/store 或生成
专用字段原样倾倒进去。原生输入项格式复用创建编码，不能按密文字节换算 token。

响应必须是完成的有限 JSON，`object=response.input_tokens`，`input_tokens` 为可表示
u64 的非负整数；缺失、负数、溢出或不完整读取均不可标精确。JSON 辅助响应共用 32 MiB 整体传输上限，
计量总等待上限 3 秒（不超过当前执行的剩余有效期限），本次失败不自动重试。取消必须可
立即中止，结束释放 body/连接；不新增全局连接池或 detached task。

该方法只测量不生成内容，不发送 `compaction_trigger`。当前订阅路由计量接口返回 404，登记不支持并沿用既有 usage 与增量估算，不重复调用已知不可用接口。它也不向 Runtime usage 账本
写入一次虚假的模型生成消耗；Provider/中心若实际存在计量费用，按其真实契约另核实，
不在本稿承诺外部免费。

### 9.3 触发时机、准确度与失效

优先触发：正常执行首次准备完成、本地摘要提交后的 continuation、包含新原生边界的
提交后、显式换模/路由重建。相同准备结果每个逻辑 step 最多一次计量，已有已校验结果
可直接复用；普通 UI 刷新、每个 token delta 和每个无压缩工具 step 不额外计量。

Core 先构造一次正常 ModelRequest，再评估该请求；不能先对裸 Conversation 计量，后面
另补工具和系统。输入更新后精确值立即失效；同一执行 owner 仅持当前不可变请求对应的
易失结果，不创建 digest → token 的跨会话缓存。

主动计量是可选增强。接口不支持、失败或结果范围不可核实时，两种模式均复用现有
`context_token_usage` 的正常响应 usage 基线与后续增量估算，准确度标为 estimated；
下一次正常响应返回后更新基线，不因计量接口不可用或原生状态为密文直接改为 unknown。

本地压缩继续使用既有 `ContextUsageAdjustment` 扣除回收部分、加回摘要的临时修正。
原生压缩没有可核实的即时回收 token 时，保留最近正常响应基线作为滞后的参考估算，
注明待校准，等待下一次正常响应更新；不将本地摘要扣减公式套到密文，不使用密文长度
或 compact 调用 usage 推算新窗口。滞后的旧高占用参考不能单独触发对同一已压缩窗口
的重复压缩；正常请求仍接受真实 Provider 限制与现有有界超限处理。只有既无可用基线、
又无法形成有依据的估算时才 unknown。正常响应若内部发生新压缩，其总消耗也不能
标为压缩后精确值，仍按估算与待校准处理。

最终无工具响应中的原生边界在 settlement 后也需刷新：沿已冻结请求的准备上下文作一次
有界计量，结果写当前 owner 的易失 context 投影；计量失败不撤销已提交最终回复。结果
回来时核对 owner、generation、模型绑定和当前快照是否仍相同，过期结果丢弃。

手动空闲压缩缺少完整下一次工具快照时，仅展示有依据的估算或未知；不能把 `tools=[]`
摘要请求标为正常 Agent 全输入精确值。下一次 Run 准备真实请求时主动计量，仍无需等待
它生成完响应。重启后精确投影不恢复，按可靠历史重新评估，不读取持久 token 缓存。

共享 `ContextWindowEvaluation` 增加准确度，used_tokens/ratio 保持可空；Evaluator
只使用传入测量与请求快照作纯判断，不执行网络或另开 Tokenizer。Core 可增加中立
`ContextWindowEvaluated` 观察事实，使 Runtime 更新父/子当前展示；该事件非持久事实，
丢失时从 Journal 与当前执行快照恢复为估算/未知，不依赖必达的计量事件。

### 9.4 输入边界与触发阈值

令 C 为显式总窗口、I 为可选 max_input_tokens、R 为本次已冻结输出预留：

- 已知输入硬边界 H 为 `min(I（若有）, C-R（R 已知时）)`，未声明的限制不编造。
- Runtime 统一自动触发比例为 90%，本地摘要与服务端原生压缩共用同一常量；Evaluator 按 `used_tokens/C >= 0.9` 判断，原生能力装配收到 token 阈值 `T=floor(0.9×C)`。输入硬边界独立约束准入，不另行降低窗口占比阈值；模型超限恢复和手动压缩入口保持原有行为。
- 本地模式达到 T 可交回宿主摘要；原生模式达到 T 由 Runtime 调用 HTTP compact，Evaluator 不组织本地摘要，也不向普通生成请求写入 compact_threshold。模型超限沿同一机制有界处理，已知 compact 输入超过准入边界时失败，不能保证上游接纳。
- unknown 不表示 0 或无限空间；允许符合显式配置的请求接受 Provider 实际准入结果，
  超限按当前唯一模式有界处理。

max_input_tokens 不另行作为自动预触发阈值；窗口占用按前述计量与兼容估算路径校准，
正常调用的 total_tokens 不冒充压缩后的精确窗口。输出预留不加入已用输入数字；缓存不从
窗口占用扣除。估算数字不证明服务端一定接受。

### 9.5 应用协议与 UI

扩展既有 ContextUsageSnapshot：保留 window_tokens，used_tokens 与 usage_basis_points
改为可空，增加中立 `accuracy=exact/estimated/unknown` 与 `mode=local_summary/server_compaction`。
准确度与数字约束：unknown 时两数字均空；exact/estimated 时两者存在，百分比从同一值
派生。占用环可以按 100% 截断绘制，详情仍展示真实 token，不用截断图形反向覆盖数据。

SessionUsage/ChildTaskUsage 继续使用同一个 context 类型；未绑定模型时 context=None。
延用累计/上一轮 usage 和缓存命中字段，不创建第二套费用字段。Rust → TS 由现有导出器
生成，共享包/Client/Desktop 的使用者全部检查，不手改生成投影。

现有 ContextPanel、ComposerDock、ChildTaskSubheader 共用格式化函数，分别展示数值、约、
未知及机制。手动入口按当前机制与独立能力选择本地摘要或原生接口，UI/Runtime 同时执行
能力和活动操作守卫。显式手动操作复用现有进行中/取消状态；无真实原生开始事件时，不为
普通 Run 中的自动压缩虚构独立 spinner 或取消按钮。

## 十、企业中心统一转发与订阅封装

本体统一使用 HTTP `/responses`、`/responses/compact` 与可选 `/responses/input_tokens`。
企业中心按当前准入的模型/上游配置决定转发与封装，不让本体识别 API/订阅，不新增产品
Session 历史、第二份 Journal 或连接 owner。

| 本体 HTTP operation | API 上游 | Codex 订阅上游 |
| --- | --- | --- |
| `/responses` | 既有 Responses 转发 | 既有 WS response.create 与 HTTP SSE 桥接 |
| `/responses/compact` | HTTP compact 完整请求/响应转发 | 请求 input 加 compaction_trigger，经 WS 收取完整终态，规范化为 compact JSON |
| `/responses/input_tokens` | 有真实支持时独立 HTTP 转发 | 当前所测不支持，声明 unknown/unsupported，不伪造计量 |

1. Host/Center 受信 operation 白名单新增固定 compact 路径及可选计量路径，沿同一凭据、模型归属/绑定、撤销、资源预算与取消生命周期，不接受任意 URL。
2. compact 不带旧 ID，也不依赖客户端 store=true。订阅分支显式进入现有 WS 基础设施，不因 kind=context_compaction 或缺少 store 字段误走 HTTP。普通续接仍沿现有身份/ID 映射，不共享或推进旧链头。
3. 中心订阅适配仅作当前请求的协议转换：使用 V2 trigger、上游 store=false、收齐 response.completed 后，返回 object=response.compaction、有序 output 与真实 usage。保留项与错误映射遵守本节及 §5.1；不能只换 URL 或把普通 WS 响应冒充 compact 成功。无需存储产品历史。
4. API 路由整体透传标准 compact 结果；无论上游类型，保留全部有效 output，不解密、重新摘要或只抽取密文。取消、错误或终态不完整不得返回成功窗口。
5. 计量保持独立 HTTP JSON operation，禁止转 response.create、触发压缩或修改 WS 链。模型能力与开关沿现有配置下发，stale configuration 拒绝，不静默切换机制。

调用记录增加 context_compaction，自动/手动真实 usage 正常计费且只计一次；压缩结果不作
可见文本/工具流。可选计量 input_token_count 排除推理消耗。沿既有 CHECK/Entity/筛选/
汇总扩展，不新增费用表或压缩记录服务。

M0 先通过临时 HTTP compact 封装验证本映射，M5/M7 已完成正式企业实现与真实链路验证。订阅响应
使用真实 id/created_at/usage，object 规范化为 response.compaction，output 为保留项加完整
compaction。ID 只标识此次 compact 结果，不获得普通 response 续接资格。usage 缺失时
不得补零伪造已计量；是否可接纳缺失用量仍沿既有账本契约明确处理。

上游 invalid_encrypted_content 为状态错误，不自动当历史链丢失；409
previous_response_not_found 是可识别的历史不可用，中心须规范化为现有 Host 能识别的
控制错误，不能只透传 409 后让客户端猜测。compact 的 context_length_exceeded 映射为
ContextOverflow，停止重复压缩。错误/取消/半截终态不返回成功窗口，连接与在途预算
随当前 owner 释放。M5/M7 验证正式身份、取消、记录、映射和完整产品链路。

## 十一、持久化、兼容与回滚

### 11.1 最小存储变化

  会话迁移为 local_summary，因为原生自动压缩此前尚未交付，不能从当前模型设置反推。
- `child_tasks` 增加冻结机制，已有 child 标为 local_summary；
  与其已有窗口快照一起读取，不从现在的父模型猜测。
- 模型配置的新增参数沿用现有 JSON/固定配置保存机制；缺省 false/unknown，不批量改写
  Conversation。Summary 引用与 ProviderState 新语义由新写入的 JSONL 自带。
- `model_request_records.request_kind` CHECK 增加 context_compaction，保留既有记录、索引
  和 MessageId 去重；`session_usage` 不增列。原生手动沿现有 session_history_operations
  和 replacement 提交，不改 body_appends.run_id 的约束。
- 复用已有 Session/Provider server_history_key 的存储与旋转；不增加新的 epoch/revision。

本地摘要及原生手动继续先写并 fsync 新 generation，再事务更新当前指针；保留完整历史。
原生自动结果只用现有 staged append，不旋转 generation。SQLite、JSONL、Journal、界面分别
验证，不能只看内存计量认定提交成功。

迁移已通过隔离升级与恢复验证。真实生产/共享数据迁移仍须按根 AGENTS 核对目标、独立备份并验证后明确确认，不能由本方案或验收结论替代数据操作授权。

### 11.2 版本与准入

- 最终内部修复包 Runtime 套件软件版本统一为 0.30.1；按用户要求，Goal 超限恢复修正并入 v0.30.0 验收归档，不单列版本。
- 应用协议最低兼容软件版本为 0.30.0：context 数字可空、模型配置与模式守卫需要同步

- 数据库最低 Host 为 0.30.0：旧 Host 即使忽略新 JSON 字段也不理解原生边界/锚点，

continuation 元数据仅失去增量资格，不丢原文、不要求工具重放。新可选语义缺失仍读取为

回滚新版本后已写入的原生项/锚点不能交给旧 Host。需要恢复升级前验证过的完整 Runtime
Home（数据库与正文/资源一致），接受恢复点之后内容不在旧版本中的限制；不只降回二进制，
不删除新字段试图强行打开库。已有迁移备份若只覆盖数据库，不足以单独证明完整历史回滚。

## 十二、并发、取消、错误与关闭

- 同 Session 的模型选择、手动摘要和 Run 上下文改变继续受 mutation gate/现有活动执行
  门禁保护；child 各自 owner 串行，siblings 可并发，不新增全局计量锁。
- Store 的单线程连接/有界命令队列不变；压缩提交不在 Tokio 执行阻塞 I/O。
- 网络计量不持有短状态 Mutex，也不在它期间改变权威上下文；结果落入易失投影前检查
  现有 owner/generation/绑定/快照。相同 owner 内需要串行就复用 gate，不再新增 revision。
- 配置/能力错误禁止执行；协议/原生状态错误在工具副作用前拒绝；计量网络/格式错误降为
  估算或未知；原生 overflow 沿同一 compact 有界恢复，compact 自身超限则停止；Store 错误保持现有 fault，不以恢复压缩扩大写入。
- 身份退出、Run 取消和 Host 关闭取消所属计量/模型任务，停止新工作，收口可靠工具批次，
  等待 Store flush/join 后释放资源；计量没有后台游离任务，失败不阻塞最终回复的可靠保存。

M0 之后的产品实现，最小先跑直接 crate/module 与 Center 单元验证，协议变化执行正式 TS 导出/类型检查及
Desktop/Client 构建；跨执行、存储、重试改动需相应隔离 Host 闭环，必要时再 workspace
检查。生产代码实现前仍按根 AGENTS 读取语言规范和受影响模块约束。

M0 须先取得至少一个拟接入原生路由的自动/手动、续接与重建实测结论，并区分上游与现有
产品代理的能力。M7 最终验收再通过正式产品链路覆盖个人/企业支持矩阵和本地摘要路由，
复核连续压缩、恢复和容量效果；不是到最终验收才首次核实协议。原生计量须核实相同有效
输入的真实返回，未核实的组合不标 supported。真实探测结论只代表所测路由，不能把公开 API 文档或 fixture
当作订阅账号、代理及企业 WebSocket 支持证据。

M0 收口结论（2026-10-10）：**真实协议验证已完成并获用户确认**。指定模型
`gpt-6.1-sol`、CLIProxyAPI v7.2.155 的订阅 V2 已取得真实原生项，完成工具/ID 续接、
多次压缩与无旧 ID 的新连接重建。临时 HTTP compact 封装经真实 WS 上游验证完整 JSON
映射和窗口整体回放；长闭合工具记录、用户图片信封及原生工具图片均能回收并继续。

错误边界已核实：损坏密文返回 invalid_encrypted_content，旧 ID 丢失返回
previous_response_not_found；压缩中途断开不激活未完成状态，上一完整窗口可恢复；
超窗 compact 返回 context_length_exceeded，不能靠压缩接口接收任意超窗输入。账本消耗
使用真实 usage，压缩后占用不能直接沿用该调用总量；当前计量接口不支持，按用户确认沿用既有 usage 与增量估算，压缩后等待正常响应校准。

本体保留统一 HTTP compact；订阅差异由中心封装，公开 API 普通请求内的自动阈值暂缓。
两个配置子项“启用服务端压缩”与“服务端自动压缩”已获用户认可，本版后者不可启用。
正式企业链路、调度和持久化已在 M3—M7 核实，完整带图窗口预算也已完成定向回归；其他 API/账号、任意图片规模及状态排列不默认支持。探测数据与凭据保持私有且不纳入归档。

固定效果目标（以下确定性 Context 夹具沿用显式 0.8 比例，不代表 Runtime 最终自动阈值；产品自动阈值为 0.9）：

- 本地确定性容量样本：`C=32768、R=4096、I 未声明`，因此 `H=28672、T=26214`。
  单一真实 User 下形成至少六批闭合交换；有效输入落在 `[T,H]`，保留的任务原文/固定
  输入/最新批次合计不高于 `0.35C`。受控摘要候选经同一计量器计量后不高于 `0.5C`，
  下一正常请求进入并完成工具续跑；追加新结果后再完成第二次压缩。该样本验证分区、
  提交与继续条件，不把假模型输出当作真实摘要质量证据。
- 本地真实摘要样本：同样限制保留输入不高于 `0.35C`，可回收旧内容占压缩前输入至少
  一半；压缩后有效输入应低于 T，任务约束检查通过，并完成两次压缩后的正常续跑。
- 原生真实路由样本：采用该路由明确声明的 C/R/H，累计输入跨过 T 并取得完整原生项；
  两次可靠压缩后均可继续工具执行、ID 续接和无 ID 重建。计量接口已核实可用时，新有效
  输入须低于 H；接口不可用时沿用 usage 与增量估算并标“约”，以真实请求接纳验证
  继续能力，不能将估算百分比报告为已证明的精确占用。原生回收比例由服务决定，不承诺低于 `0.5C`。
- 必要输入样本：仅保留 User/固定提示/近期批次已超过 H，必须有界失败且历史完整。

上述相对容量与通过条件用于固定隔离样本，不以“所有压缩都低于 50%”作为产品承诺。实际运行问题的诊断与修正见开发计划，不将个案结论外推所有输入。

## 十四、排除方案与保留风险

排除：本地/原生竞争触发或错误后跨机制回退（当前无可靠兜底）、用另一种压缩机制无限兜底超限、第二
历史文件、通过密文长度估算、为计量开无内容推理请求、原生模式永久关闭 ID 续接、靠删除
原文减少计量输入、为当前需求新增公共 Token 服务或全局缓存。

主要风险及收口方式：

1. **原生项排列与工具协议冲突**：本稿只支持能合法表示的排列，其他在副作用前拒绝。
   真实上游若常见排列不能表示，必须修订方案后再宣称支持。
2. **原生计量/账号能力不齐**：接口声明不等于真实路由成功；计量失败沿用既有估算并等待正常响应校准，
   原生执行仍由明确能力与当前唯一机制负责，不回退本地。
3. **轮内摘要遗漏任务或破坏引用**：保留原始 User、近期完整批次与程序化上下文，Store
   在提交前验证源引用与连续尾部；不能只验证摘要文本非空。
4. **续接哈希实现复杂**：统一有效前缀规范化与编码，保证有工具未返回时的哈希不削弱
   真正请求校验；实现前先完成 fixture，不能每轮静默失去增量后声称功能成功。
5. **切模或 Fork 原始输入过大**：没有相容原生状态时本版不承诺自动解决；明确失败且
   保留历史，回退机制待可靠方案形成后另设计。

当前 F01 实施基线已确认：模型配置字段编码与会话冻结方式（两个子项语义已确认）、User 引用式轮内回收、continuation v2、原生 compact 完整窗口封装/费用与互斥、
计量时机/3 秒预算、企业调用记录扩展及三类兼容下限。具体 API 名称允许在实现中按已存在
命名风格收敛，但不可改变字段语义、所有权或恢复边界而不更新方案。

[开发计划](开发计划.md)记录 M0—M7 完成、正式企业链路验证及验收修正；2026-10-13 用户确认 F01 与本版按实际范围验收。无需独立交互指导，不依赖 F02；未执行平台、全工作区合跑和分发限制见[版本总结](../../版本总结.md)。
