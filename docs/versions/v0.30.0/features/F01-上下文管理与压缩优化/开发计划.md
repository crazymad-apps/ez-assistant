## 二、台账原则

1. 本轮依用户明确授权顺序完成 F01 后续实施和必要验证，里程碑完成及时记录结论；仅在需要人工验证或用户外部操作时暂停。该授权不等于 Feature 人工验收或版本发布。
2. 复用现有模型服务、上下文布局、操作 owner、Journal、Store 事务与费用账本；新增契约
   以技术方案为准，不现场增加另一套缓存、压缩历史、调度器或状态版本。
3. 每个里程碑保持仓库可构建；协议/类型变化所需的最小消费者调整在当项完成，不留到
   后续里程碑修复编译。中间实现不登记为完整 Feature 或已验证的真实 Provider 能力。
4. 先核查再实现；源码与方案不符且影响所有权、恢复或兼容时，收口当前项、更新设计并
   重新确认，不通过临时双写/回退继续扩大实现。
5. 验证按直接风险执行，记录完成结论及必要限制；不建立单独验证报告，不将运行输出、
   数据库计数或截图批量加入流程文档。
6. 数据写入仅在项目 `.runtime-test/` 下新建、已核实的隔离 Runtime Home；每个场景独立，
   不读取用户运行历史作默认夹具。生产/共享数据迁移另按根 AGENTS 核对、备份与确认。
7. 提交、推送、打包、部署与公开发布各按实际授权执行；本版验收归档不等于公开发布。

## 四、各里程碑交付与确认

### M0 真实接口协议验证

目标：在产品开发前，通过真实模型接口验证关键协议假设，确定后续实现可以依赖的行为。
文档、Mock、Fake Transport 或手工构造的压缩项均不能作为本阶段通过依据。

执行范围与边界：

- 先核对实际测试模型、路由、公开 API / Codex 订阅上游、代理版本及 HTTP/WS 配置；
  传输与上游协议分别验证，不能用 HTTP 结果代替企业 WebSocket 结论。使用合成任务、工具结果和测试
  图片，不发送用户历史。凭据与实际连接信息不写入公开文档或夹具。
- 使用最小独立探测脚本或现有验证入口直接调用真实接口，必要的探测代码仅服务协议验证；
  不先修改产品 SPI、Session/JSONL、数据库迁移、企业代理或 UI。临时数据放项目
  `.runtime-test/` 下新建场景，不操作用户 Runtime Home。
- 在真实允许范围内选择阈值，控制样本规模与调用次数；记录协议事实、用量与必要限制。
  无法取得真实原生项时，本项保持未完成，不用普通响应或假密文替代。

| 验证项 | 真实请求与判定 |
| --- | --- |
| 自动压缩 | 本体按阈值或模型超限触发同一个 HTTP compact；M0 先验证对应原生操作、容量与有界错误。订阅分支按 Codex V2 取得原生项，连续两次后仍能完成工具往返；普通请求内自动阈值暂缓 |
| 手动压缩 | 与自动共用 HTTP compact 契约；API 上游直接 compact，订阅上游验证 WS V2 及完整 compact JSON 映射。整体回放窗口与真实 usage；M0 当时尚未实现的中心封装由 M5/M7 完成 |
| ID 续接 | 自动/手动提交 compact 窗口后建立新链，再用实际正常 response ID 续接；不将 compact 对象 ID 当旧链头，验证增量工具调用与任务约束 |
| 无 ID 重建 | 保留已完整收到的压缩状态及后续闭合内容，重新启动探测进程并不带旧 ID 发起请求；模拟链失效及断流，验证只采用完整可靠边界，无须回传压缩前全部原文；不执行真实工具副作用 |
| 有效窗口计量 | 分别测试压缩前、自动及手动压缩后的 `POST /responses/input_tokens`，覆盖工具定义/结果、图片与原生状态；对照正常响应 usage，核实数字对应的输入范围及更新时机，不能直接把消耗当作压缩后占用 |
| 限制与错误 | 通过最小必要请求核实不支持参数/接口、无效 ID 或原生状态、上下文超限的返回和重建边界；同机制恢复有界，不切换本地摘要或另一压缩协议兜底 |
| 路由差异 | 分别登记个人/企业上游及 HTTP/WS 的自动、手动、计量、续接/重建支持；本体 compact 始终 HTTP，订阅上游由中心转 WS，计量保持独立 HTTP；上游直连成功不能替代中心封装验收 |

本阶段区分上游协议与当前产品代理能力：现有企业代理尚未开放的路径记录为现状缺口，
可通过明确标识的上游直连或独立探测验证其上游，但不能据此宣称企业产品链路已贯通，
也不提前实施 M5。无可用测试路由的组合保持未验证，不能默认开启。

完成判定与方案收口：

- 至少一个拟接入的真实原生路由完成自动和手动压缩、工具往返、ID 续接及无 ID 重建；
  确认原生项顺序、完整窗口回放与技术方案可以一致表达。
- 计量是独立能力：接口不支持、失败或不能核实完整窗口时，沿用既有 usage 与增量
  估算，压缩后等待正常响应校准并标“约”；既无基线也无可靠估算才显示未知。这不
  单独阻塞已证实的原生执行路径，不能为了通过 M0 虚构精确值。
- 将支持结论、未验证项与影响实现的协议偏差收敛到现有技术方案/计划，不新建验证报告，
  不提交凭据、原始密文或请求日志。后续回归可使用脱敏夹具，但不能替代本次真实调用。
- 核心假设不成立时先调整方案与后续计划，不进入 M1；不能静默取消手动能力、混入本地
  机制或用每次重发全部历史掩盖续接问题。M0 完成并获用户确认后才进入产品开发。

Review 重点：结论来自真实返回；协议可用与产品实现可用分别判断；可选计量不成为错误
前置；所有必须路径具备实测证据或明确的阻塞项。

2026-10-10 完成结论：指定订阅路由已通过真实 V2 压缩、工具/ID 续接、多次新连接恢复，
临时 HTTP compact 封装、长工具记录与两种工具图片布局回放，以及损坏状态、丢失 ID、
未完成压缩和真实超窗错误验证。计量不支持沿用既有估算、等待正常响应校准。**用户已确认并要求继续**；
企业正式封装、产品触发/持久化与其他路由仍由后续实现和验收负责，不将临时探测作为产品交付。

### M1 契约、机制绑定与升级基线

目标：先建立单一机制的可靠归属，避免后续分别接入时出现第二份状态。

交付范围：

- 按技术方案扩展规范状态替代语义、原始 User 引用、状态消息用途、模型策略/计量/手动
  原生方法与准确度契约，所有装饰器和确定性模型同步；缺省保持旧语义。
- 模型压缩分组区分机制与触发方，校验父子选项依赖；服务端自动子项本版不可启用，不预建其执行路径。模型配置来源及 Run/child 冻结机制落地；新 Run 与空闲手动操作接纳刷新后的参数，活动 Run 不变；按最近可用边界重建，原生模式直接通过 message item 复用 Agent 摘要。未核实能力不默认开启。
- Host 单一 v0.30.0 迁移入口覆盖必要字段、费用 kind 和最低 Host；应用协议、TS 正式
  投影及现有消费者完成最小安全适配。企业兼容下限和 Center DDL 在 M5 一并落地。
- 同步直接受影响的 Types/Model/Context/Runtime 长期约束；后续按各里程碑补齐实现边界。

验证入口与完成判定：新旧 JSONL/配置缺省、作用域变化、模式重启恢复、序列化及哈希稳定；
新建隔离库升级/准入及原本地路径回归；受影响消费者构建通过。M0 的上游协议结论作为
实现依据，产品支持仍须后续集成验收，不因新增字段就宣称原生已可用。

Review 重点：每项新增事实有实际消费者；没有凭空新增 epoch 或服务；迁移保留原记录与
引用；未知占用不会被旧消费者显示为零，旧 Host 不能误读新历史继续执行。

### M2 本地轮内回收与持续进展

目标：解决单一任务不断积累已闭合工具结果时无法回收的限制。

交付范围：

- 轮内安全切点、原始 User 引用展开及 Store 精确尾部校验；保留当前任务原文、最新完整
  交换、程序化记忆与必要能力上下文。
- 本地自动、手动与 child 复用相同摘要算法；不改变正常冻结摘要请求的前缀或执行工具。
- 连续无进展预算替代 Run 全局两次限制；新正常结果可恢复预算，摘要本身不能重置预算，
  已知必要输入过大及时失败。

验证入口与完成判定：技术方案 §13 本地容量样本通过；无 pending 切断、重复 User/ID、
记忆遗漏或重复执行；成功进展可以再次回收，无进展有界，自动/手动取消仍可靠。

Review 重点：引用属于源历史且唯一；候选缩短后仍保留约束；不借压缩重置步骤/工具预算，
不把“生成了摘要”当作“正常任务已经取得进展”。

### M3 Responses 原生压缩能力与续接

目标：Adapter 在受控传输下完整表达原生机制，并保持单次模型调用边界。

交付范围：

- 自动/手动共用原生 compact 方法；完整 JSON/有序 output/状态与工具配对校验，不相容或不完整结果在工具副作用前拒绝，普通请求不注入服务端自动阈值。
- 原生 compact 的独立 HTTP 调用、完整窗口封装与整体回放；复用规范状态消息，不裁剪
  返回窗口、不伪造普通回复、工具循环或 response ID。
- Types 的共同原生切取与 continuation v2；compact 后先新建链，随后增量续接可用，语义变化失去资格，
  v1 原文保留且只失去增量资格。
- 输入计量复用实际编码和同一图片准备结果；有限响应/超时/取消，不自动重试计量或
  手动压缩，不把这两者装进生成 retry。

验证入口与完成判定：Fake Transport 的 wire/流/状态/图片/作用域 fixtures 形成闭环；
手动窗口后的首次新链、后续 ID 续接、原生自动 compact 后新链的 v2 匹配及一次链重建验证通过。
本项对照 M0 的真实协议结论验证 Adapter 实现；产品实际链路的最终回归在 M7 完成，
不把关键上游协议是否可用留到封版时才发现。

Review 重点：Adapter 不依赖 Context/Runtime；自动项与手动整个窗口的裁剪语义正确；
哈希机械编码不放宽真实请求校验；不通过每次全量发送掩盖续接失效。

### M4 Runtime 原生提交与恢复

目标：正式 Runtime 中只使用选定机制，原生状态和费用在可靠边界一致提交。

交付范围：

- 主会话/child 的自动原生结果跟随既有完整响应/工具批次追加，可靠完成后通过现有交接
  更新 Journal 与 Core 有效投影。
- 主会话手动入口按机制装配；原生手动复用 IdleSession replacement 和已有操作回执，
  完整产品历史加一条状态消息后切换 generation，不新增无 Run 追加通道。
- 原生手动费用沿既有消息账本结算和去重；payload 旧项不计费，状态用途不冒充普通回复。
- 换模、同模型重新应用、入口变化和 Fork 保留授权历史中的完整压缩窗口，临时 ID 独立
  校验；child 不继承父窗口，格式/协议不相容或重建过大明确失败，无本地兜底。
- 按真实请求准备测量与发布占用可信度，过期结果丢弃，计量失败不撤销已可靠提交结果。
- 从完整历史推导精确记忆净变化，随宿主指令及当前 MCP/Shell 能力装配，不能把必要程序
  事实保持寄托于不透明压缩文本；计量/续接使用同一冻结准备结果。

验证入口与完成判定：隔离 Host 及 Runtime Store 覆盖自动 pending/ready、手动准备/文件
写入/事务提交/恢复等边界；反复恢复不重放工具、不丢历史、不重复费用、不混用机制；
两个会话可并行，同一会话手动/执行互斥，取消及关闭收口。

Review 重点：自动普通追加和手动 generation 切换各用现有可靠路径；物理历史数量不能
替换为短投影长度；费用去重、操作回执和指针更新在同一事务，网络等待不持状态锁。

### M5 企业代理贯通

目标：企业路径与个人路径具有同一产品机制与明确支持矩阵。

交付范围：

- 模型能力/配置可信下发，企业协议升级、最低兼容门禁和旧配置缺省同步。
- Center/Host 固定 HTTP 路径贯通 compact 与可选 input_tokens；compact 对 API 上游转发 HTTP，对订阅上游复用 WS 基础设施加 trigger，收取完整终态并规范化 JSON。计量始终独立 HTTP；不接受任意路径或伪造身份。
- 自动/手动压缩实际 usage、计量非消耗记录及既有调用筛选/费用汇总一致；Center 的 CHECK
  与 Entity 迁移保留既有账本，无新表/第二份服务端会话状态。
- 复用现有取消、请求限额、录制和敏感诊断边界，身份退出不能留下所属在途任务。

验证入口与完成判定：Center 单元验证和 Host 受信 Transport 验证通过；需要数据库时仅
新建隔离场景，覆盖升级、固定路径、过期配置/身份、限额/取消及统计分类。不得拿个人直连
通过证明企业上游可用。

Review 重点：计量不成为生成消耗或 WS 创建；compact 正确封装上游差异、不依赖 store=true、不沿用旧 ID；完整结果/错误映射、准入与企业最低版本配套，本体不识别订阅。

### M6 产品交互与占用展示
