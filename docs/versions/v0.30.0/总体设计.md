## 二、实际交付

| 能力 | 交付结果 |
| --- | --- |
| 唯一压缩机制 | 模型配置选择本地摘要或服务端原生压缩；自动、手动共用所选机制，串行提交，不跨机制兜底 |
| 本地轮内回收 | 同一用户轮次可回收已闭合交互，保留任务原文、近期完整交换、必要记忆与未闭合配对 |
| 服务端原生压缩 | 本体统一 HTTP compact；企业中心转发 API 上游，或封装订阅 WS V2；本版由 Agent 按 90% 阈值或模型超限触发，手动调用同一接口 |
| 持久化与恢复 | JSONL 保留完整产品历史；完整压缩窗口可靠提交后生效，从最近可用边界与后缀恢复，支持重启、换模、Fork 与旧 ID 失效重建 |
| 计量与展示 | 调用消耗与有效窗口分开；主动计量不可用时沿用 usage 与增量估算，标“约/待校准”，正常响应校准 |
| 验收修正 | 修复历史会话输入排队/内部状态故障、压缩固定总时限、带图完整窗口大小门槛及旧 MCP 刷新结果加载；Windows/Web 导航靠左，Web 增加 Logo |
| Goal | 取消累计 token 上限，保留用量统计、运行次数与连续失败保护；超限累计次数可完整恢复，不再阻止会话读取 |

不纳入：普通生成请求内的服务端自行触发自动压缩、Computer Use、整体导航改版、主题、Runtime 组网、手机原生 App、持久自动化和后台 Shell 托管。

## 三、架构与可靠性约束

保持 Desktop 与 Runtime Host 双进程、Runtime 内部模块化和唯一 HTTP/HTTPS 监听。Runtime 持有会话、Run、历史、有效上下文与调度；Host 负责传输、装配及持久化适配，UI 消费投影并发送意图。

1. 复用 ProviderState、Checkpoint、Journal、Store 和模型装配，不新增第二份压缩历史或服务端产品会话状态。
2. 原始产品历史与有效模型输入分别投影。完整响应校验及可靠提交完成后才激活新窗口，取消、失败和迟到结果不能污染旧状态或重放工具。
3. 新 Run 和空闲手动操作接纳最新模型参数，活动 Run 保持冻结。服务端模式直接通过 message item 复用 Agent 文本摘要，不转换或额外压缩；本地模式不解密原生状态。
4. 已提交完整压缩窗口与临时续接 ID 分开。模型、入口地址或绑定变化不丢弃窗口；旧 ID 不满足续接条件时重建新链，协议、格式及工具配对仍校验。
5. 自动/手动不竞争，不跨机制回退。当前没有可靠兜底方案，未来另行设计确认；同机制有限恢复继续保留。
6. 计量与当前有效输入对应，压缩或输入变化后失效重评；无法可靠估算才显示未知，不以密文长度估算或旧百分比冒充精确值。
