## 三、目标与非目标

成功结果是：在相同有效上下文与模型配置下，手动和自动使用同一套本地摘要规则，当前摘要调用不声明可用工具；有效结果经过相同校验与可靠提交规则后才用于后续推理。用户能够区分无需压缩、取消、请求拒绝、传输失败、摘要无效和提交失败。

本次不改变自动阈值、摘要预算、轮次／轮内保留策略、自动压缩次数与 Run 预算；不增加独立摘要模型配置、新压缩机制或手动 child 压缩入口。不合并服务端原生 compact，不开启服务端自行触发，不在压缩失败后跨机制回退。不重开 F02 的历史格式／迁移或长会话分支性能优化，不处理已跳过的 F03 网络问题。

## 四、功能行为

### 4.1 触发与执行身份

- 手动沿现有会话压缩入口，保留当前健康、生命周期、空闲及并发准入条件。它是独立的会话操作，不创建普通输入或 Run，不消费暂存队列；同一操作重试沿既有幂等结果返回。
- 自动沿现有阈值或 Provider overflow 触发，在已经存在的父 Run／child 执行内处理；成功后继续原执行，不新增 attempt、不重置原执行起点或预算、不重放已经完成的工具。
- 主会话与 child 各自核对实际 owner；child 自动摘要采用同一请求和候选规则，提交仍作用于 child 自身上下文。
- 同一 owner 不并发改写上下文。配置与上下文的冻结、取消及提交前重新核对复用当前门禁；不在模型等待期间新增全局锁来阻塞其他会话。

### 4.2 统一摘要请求与调用

统一从当前有效模型配置和可靠上下文准备摘要请求。系统提示词、历史输入、摘要指令、保留边界、摘要输出预算、思考与 Provider 参数采用同一规则；除操作关联、owner 与触发诊断等必要信息外，不因手动／自动形成两套配置口径。

当前摘要请求的可用工具列表为空，不能只设置禁止工具调用而继续发送定义。Chat／Responses 按现有编码契约处理空工具请求；技术方案须核对最终线上字段，避免空工具场景仍发送不适用的工具选择参数，或仍要求与摘要无关的工具能力。

清空的是本次调用的工具定义，不是历史工具消息。源上下文中的历史调用／结果、图片、已有摘要和可靠的原生截断边界继续按既有策略处理；保留内容不被删去或重新执行。正常生成请求的工具能力不受影响，自动摘要成功后继续原任务时仍可使用原工具。

沿用既有模型超时、取消和瞬态错误有限重试。普通 HTTP 400 不因压缩失败被扩大为自动重试，不能自动换参数重发整轮生成或重跑历史副作用。去掉工具定义可能降低摘要调用与正常调用之间的缓存前缀复用，按已确认方向优先保证兼容与继续执行。

### 4.3 校验、提交与继续

本地摘要按同一流程完成：核对源上下文及模型绑定 → 生成摘要 → 验证候选和保留边界 → 核对当前 owner／generation／取消状态 → 可靠提交 → 更新内存投影并发布结束结果。已有共享步骤直接复用，剩余重复编排在技术方案中收敛，不另设通用压缩服务或第二份权威状态。

- 空摘要、意外工具调用、破坏工具配对、来源不匹配或无实际压缩效果的结果不得作为成功上下文发布。
- 压缩不得跨越既有原生截断边界复活旧窗口，不重写冻结系统提示词；Pinned Memory、Skill／MCP 与 Shell 环境按现有规则恢复。
- 文件与存储提交成功前，不替换内存权威上下文、不发布成功，也不开始依赖新窗口的后续生成。提交冲突、失败或重启沿 F02 的可靠提交和恢复语义处理，不能另建 SQL 历史副本。
- 提交已经成功而投影失败时，保留真实提交事实并隔离该 owner；不能将其伪装为“没有提交”后再次调用模型或计费。
- 用量只记录实际发生的摘要调用；幂等回读、重启恢复和历史换代不能重复记账。后续生成沿原有效上下文与身份继续。

无需压缩由同一策略结果表达。手动可返回“无需压缩”；自动入口若仍无法满足继续条件，应按原上下文／预算终态处理，不能把没有缩小窗口的结果当作已经解决溢出。该差异来自后续用途，不允许借此维持不同的摘要生成规则。

### 4.4 失败、取消与界面

共用错误分类及来源保留规则，区分请求拒绝、传输／超时、摘要无效、上下文冲突、持久提交失败与取消。可展示诊断保留适用的 HTTP 状态和错误类别；上游没有给出具体原因时不编造原因，不暴露凭据或原始隐私请求。复用既有错误与压缩结果契约，确需调整字段时在技术方案说明所有消费者和兼容影响。

手动结果继续由会话压缩入口展示；自动失败仍由原 Run／child 展示。两者使用相同失败原因口径，但不将独立手动操作展示成一条普通 Run。保留现有手动取消和自动执行取消的归属，取消不显示为成功或普通请求失败，不额外开放自动压缩的独立取消入口。

沿用当前压缩状态、进度、结果和错误展示，不新增设置页、后台任务或备份／恢复向导。暂不单独编制交互指导；若技术方案发现现有界面不能表达必要结果，再说明具体缺口。

## 五、职责与兼容边界

| 模块 | 约束 |
| --- | --- |
| agent-context | 本地摘要请求规则、裁切和候选校验；保持 Provider-neutral，不接入业务 Store 或界面 |
| assistant-runtime | 触发适配、模型与上下文冻结、owner 调度、共享提交编排、投影及错误映射；复用现有 compactor 和 Store 业务端口 |
| runtime-host | 沿用 F02 文件历史与可靠换代实现；不持有第二份压缩状态或新增 SQL 历史副本 |
| 模型 Adapter | 核对两协议的实际无工具编码和错误元数据；只在存在真实契约缺口时修改，不在 Adapter 内执行压缩生命周期 |
| 协议与 Desktop／Web | 沿既有压缩操作、快照和事件展示必要差异，不持有压缩权威状态；公共契约变化须说明生产者、消费者及兼容影响 |

目标是不新增持久化格式、数据库迁移或公开命令。是否需要收敛内部参数、调整错误契约及如何共享不同提交目标，在技术方案核实，不以本功能设计直接批准接口扩张或真实数据操作。

## 六、验收标准

| 编号 | 可验证结果 |
| --- | --- |
| A01 | 同一有效上下文与模型配置下，手动／自动摘要请求的业务参数一致，两协议均不发送可用工具定义及不适用的工具选择参数 |
| A02 | 原模型即使不支持指定工具选择，也不因正常生成的工具定义而拒绝无工具摘要；正常生成的工具能力保持 |
| A03 | 多轮、单轮内多次工具交互、图片及既有摘要按原策略压缩；保留边界、工具配对、原生截断边界及环境恢复一致 |
| A04 | 主会话与 child 自动摘要均遵守统一规则，owner／generation 不串用；手动不新增 Run 或消费暂存输入 |
| A05 | 有效摘要只提交一次；自动继续原 Run／child，手动返回独立操作结果；重复提交、重启和回读不重复调用模型或记账 |
| A06 | 无可压缩内容、空摘要、工具调用响应、无效或无缩减结果均有正确结果；自动不能用 NoOp 掩盖仍无法继续的上下文 |
| A07 | 模拟真实 HTTP 编码覆盖两协议、普通 400、超时和瞬态错误；重试边界一致，不扩大重放。已记录的真实兼容场景按授权及配置条件补对照，未执行时如实保留限制 |
| A08 | 取消、并发请求、模型／上下文变化、提交失败及提交后投影失败保留可靠事实，不发布虚假成功或重放工具；不长时间阻塞其他会话 |
| A09 | 文件历史、摘要用量和上下文换代跨重启一致；无新 SQL 历史副本；原生 compact 的独立机制及无跨机制回退回归保持 |

## 七、最小新增审查与下一步

现有摘要策略、`compact_once`、`replace_context`、操作幂等、事件与取消机制已经提供主体能力。优先删除请求和提交解释中的重复规则；不新建压缩管理器、恢复服务、持久状态或第二套错误系统。手动与自动的 owner、操作身份和继续行为有实际差异，保留必要触发适配，不将统一理解为强造一个普通 Run。

本设计已于 2026-10-22 获用户确认；[技术方案](技术方案.md)也已获确认，已落实请求归一位置、剩余提交编排、父／child／手动目标适配与错误契约。[开发计划](开发计划.md)已确认，M0 已获用户确认；M1 已获用户确认，M2 实现与验证完成，待用户确认及 F04 验收。未调用真实上游、操作生产数据或完成 Feature 验收。
