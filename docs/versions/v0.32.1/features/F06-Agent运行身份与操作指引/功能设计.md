## 二、背景、目标与非目标

当前 Host 已向 Agent 提供用户数据目录、用户 Skill 目录及工作／会话目录，但没有明确渲染当前个人或企业模式。Agent 仍可能根据安装位置、模型或路径名称猜测身份，并把客户端所在设备误当作实际执行设备。

F05 已建立内置 Skill 来源和 MCP 配置工具。F06 在此基础上让 Agent 获取准确的运行事实，并在用户要求配置或开发 EZ Assistant 能力时，按需读取与当前交付一致的操作说明。

最终结果：

1. Agent 明确当前执行所属的模式、用户域目录和执行环境，不混用客户端、其他用户或其他 Host 的路径。
2. 用户询问目录、Skill、MCP 或插件开发时，Agent 能发现内置操作手册并读取相关主题；普通任务只承受简短的事实与目录描述。
3. Agent 依据当前真实工具完成获授权的操作，并分别核验保存、发现、连接和实际调用结果；缺少入口时说明限制并指向现有用户操作入口。
4. 官网与内置操作指引维护同一正文来源，随 Host 交付的说明可离线读取，历史激活内容保持原事实。

本 Feature 不新增知识库、配置副本、后台自检或独立资源更新服务，不实现任意 Host 管理接口或自动安装依赖；不迁移用户目录、改写历史提示词或补造历史身份。插件依赖故障、MCP 错误展示与长会话性能修正继续归各自问题，不借手册编制扩大实现。

## 三、运行事实与目录职责

### 3.1 模式与执行归属

系统提示词中显式说明当前模式为个人（`personal`）或企业（`enterprise`）。事实由实际执行所属 Host 装配和已核实用户域提供；同一 Host 中的不同用户域分别核对，不能只根据全局启动偏好判断。

模式不从所选模型、中心地址是否存在、客户端平台或目录名称推断，也不用于授予额外权限。企业模式下应按具体来源说明哪些配置由用户管理、哪些内容由企业或插件管理。

用户通过远程 Desktop、Web 或 Client 连接时，操作对象属于所连接的 Host；客户端本机目录不会因此成为 Agent 的文件操作目标。用户要求切换设备或用户时，先沿现有连接／会话归属核对目标，不用手册文字冒充连接或授权已经切换。

### 3.2 复用实际目录事实

| 已有目录事实 | 指引应说明的职责 |
| --- | --- |
| 用户数据目录 | 当前 EZ Assistant 用户域的私有根，不等于操作系统 Home 或项目根 |
| 用户 Skill 目录 | 未指定位置时创建个人可复用技能的默认目标；使用环境提供的完整路径 |
| 工作目录与附加工作区 | 当前项目操作范围；工作目录不构成操作系统强沙盒 |
| Workspace 私有目录 | 由 Host 管理的工作区相关内容，区别于用户项目源码 |
| 会话私有、附件及工具图片目录 | 各自的会话工作文件与受管资源归属，不作为正式 Skill 的默认安装位置 |
| Host 公共 Skill、插件包与内置来源 | 补充或只读资源；不能从读取位置推导新技能的安装位置 |

继续以当前注入的 `user_skills_directory/<name>/SKILL.md` 为默认写入位置；项目专用技能按用户选择进入工作区支持的技能根。手册不硬编码操作系统用户名、企业目录或 `_personal`，不把 `builtin:<name>` 来源标签解释为文件路径。

身份及目录说明只包含本次执行所需的事实，不把凭据、其他用户目录或无关账号资料加入提示词。实际写入继续遵循既有工具权限。

## 四、内置操作手册与使用路径

### 4.1 发现、启停与内容加载

采用 `ez-assistant-guide` 为逻辑名称，作为 F05 机制中的内置 Skill 随 Host 交付：

- 默认可发现、可由用户选择或模型按需加载；仅将简短名称和用途描述纳入现有目录，不自动激活完整正文。
- 沿现有技能设置按名称启停、同名覆盖和来源展示规则；用户／项目／插件的同名资源保持现有优先级，禁用后不绕过用户选择回退加载内置版本。
- 入口只说明适用范围、运行事实的使用方式及主题导航；具体内容按主题读取。用户指定主题时直接进入相关内容，不要求逐页读完整套手册。
- 参考页必须在目标平台脱离源码仓库和官网网络后仍可实际读取，路径或引用与真实加载入口一致。当前内置能力只有正文嵌入，主题资源的读取方式是技术方案必须解决的缺口，不能仅在正文里写一个不存在的 `references/` 路径。
- 默认发现、逻辑名称和主题组织已获功能设计确认；资源读取方式按技术方案确认后再实施。

### 4.2 主题与内容归属

| 主题 | 核心内容 | 复用与边界 |
| --- | --- | --- |
| 产品与执行环境 | Desktop／Host／企业中心职责，个人／企业模式，当前连接与目标设备，目录用途 | 模式和具体路径取自 Host 事实，手册只解释职责 |
| Skill 创建与使用 | 用户／项目／插件／内置来源、同名规则、发现、加载与更新生效 | 操作位置复用当前环境，编制技能方法复用内置 `skill-creator`，不复制另一套创建教程 |
| MCP 配置与使用 | 独立／插件／内置来源，启停、环境变量／请求头、绑定插件参数、保存、测试、刷新及调用 | 对齐 F05 真实管理工具和用户详情页，沿同一配置事实源 |
| 插件开发与交付 | 源码与归档根、清单命名、Skill／MCP 入口、平台运行时、资源与许可证、打包与核验 | 复用[插件开发规则](../../../../site/manual/plugin-development.md)正文；业务插件源码仍归独立仓库 |

目录与 Skill 使用内容复用[创建可复用技能](../../../../site/manual/general-assistant.md)，MCP 使用内容复用[插件与 MCP 操作说明](../../../../site/manual/plugins.md)。需要补充的正文在所属主题源维护；内置版与官网版可采用不同呈现，但不能维护两份独立规则或依赖在线网页才能加载内置说明。

插件开发主题必须区分包内只读 `plugins/<name>/packages/<sha256>/` 与用户可写 `config/`、`data/`，说明清单、入口、平台目录和注入变量的真实契约。源码 README／构建脚本不直接混入归档根，名称声明与实际入口一致；不会指导 Agent 改安装包或 Host 数据库。

### 4.3 代表性操作

**创建 Skill**：读取当前用户 Skill 目录及现有同名内容，按用户要求加载 `skill-creator`，写入目标位置后通过现有发现／详情入口核验来源和正文。已有 Run 的目录与已激活内容按原冻结边界处理，后续执行按现有重新扫描规则接纳；不要求所有场景必须新建会话。

**配置 MCP**：先核对目标来源与服务身份，查询已设置状态，沿现有父 Agent 管理工具及权限修改相关字段、刷新并核对状态。独立服务、插件绑定参数及新增服务的可操作范围以实际暴露入口为准；未覆盖的操作指向现有设置页，不虚构工具或读取原生管理凭据。

手册明确保存配置、临时测试、主动启用、刷新连接和实际业务调用是不同结果；服务启停由开关和保存表达，默认禁用的 DeepSeek 不因保存 Key 自动开启。握手通过不代表 Key 或搜索 API 已验证；新启用 MCP 的业务工具沿 F05 每轮冻结范围，从后续 Run 生效。

同名 MCP 同时启用时说明来源冲突，让用户明确选择保留哪个来源，不自动迁移 Key、删除配置或静默合并服务。敏感值保持已设置状态回读；用户直接在对话中提供的新值可能进入原消息和调用历史，不能宣称其从未被记录。

**开发插件**：用户要求编写或调整插件时，按需加载开发主题，确定源码位置及目标平台，复用实际包契约生成并核验结果。说明文件写成、打包成功、Host 安装、MCP 握手及真实工具调用分别证明什么，不把一种结果替代其他验收。

## 五、新旧会话与历史边界

| 场景 | 已确认行为 |
| --- | --- |
| 新建会话 | 从当前可信 Host／用户域生成模式与目录事实，手册沿现有目录可发现 |
| 已有会话恢复／重启 | 保留冻结系统提示词及已激活 Skill 正文；缺少显式模式的旧会话不由目录补猜，不在升级时回写历史 |
| 已有会话后续读取手册 | 按现有 Skill 重新扫描／新激活语义读取当前可用版本；已有历史激活不会变成新版。旧提示词缺少的新运行事实通过新建会话取得，不宣称加载手册已补齐权威身份 |
| Fork | 新会话的运行事实按目标可信环境重新核对，目录按原 Fork 规则调整；不从源提示词继承不适用于目标的身份，不改动源会话历史 |
| 用户域或 Host 变化 | 现有归属与授权边界保持；仅核查已有转移入口是否会携带过期事实，技术方案明确支持与拒绝条件，不新增跨域导入／迁移功能 |

冻结环境部分如何精确识别、Fork 如何替换本 Feature 所有的事实、主题内容如何参与现有激活及历史记录，由技术方案细化。若需改变已验收的会话持久化或导入契约，必须先列明影响并重新确认，不能在内容装配中隐式完成。

## 六、模块职责与关键取舍

- Host 已持有用户域及环境装配事实，负责将可靠运行信息转成提示词并交付内置资源。Agent Core 保持 Provider-neutral，不读取 Host 配置或业务数据库。
- Runtime 继续持有 Skill 发现／激活、MCP 管理、权限和可靠历史；本 Feature 不建立第二份管理状态，不向 UI 下放业务权威。
- Desktop／Web／Client 复用现有设置、技能选择和工具结果入口；暂不需要新的一级页面或自配置向导。
- 手册正文采用同一源内容随 Host 版本交付，官网可按既有流程独立发布；内置说明不能承诺尚未随该 Host 交付的能力。具体装配和版本核对留技术方案。
- **需要技术方案**：模式事实来源与冻结 Prompt、Fork／恢复边界、内置主题资源的真实读取均跨模块，不能仅靠内容描述落地。
- **暂不另编界面交互设计指导**：当前结果由提示词、既有 Skill 列表和工具入口承载；若技术方案发现需新增可见交互，再说明范围后决定。

## 七、验收标准

| 编号 | 可逐条验证的结果 |
| --- | --- |
| A01 | 新会话在个人／企业用户域中取得正确的显式模式；模型选择、客户端平台、路径或中心地址变化不会被用作模式推断 |
| A02 | 用户 Skill、工作区、会话及插件目录职责和实际装配一致；本机／远端及不同用户之间不串路径，不把来源标签作为磁盘路径 |
| A03 | 内置手册可按现有入口发现、启停和加载，同名覆盖符合 F05 规则；普通任务不自动加载整套正文 |
| A04 | Windows x64 与 macOS arm64 随包内容在脱离源码目录、无官网网络时可按主题读取；引用均有实际目标，缺失时明确失败 |
| A05 | 创建／更新 Skill 的代表性请求落入获授权的实际目录，通过发现与加载核对；不修改只读内置或插件包 |
| A06 | 受控 MCP 配置场景复用实际工具及权限，保存／测试／启用／刷新／业务调用结果明确；覆盖默认关闭、缺值、同名冲突和后续 Run 生效，已有秘密不回读 |
| A07 | 插件开发主题与官网同源正文及当前清单／目录契约一致，示例包归档根、声明入口和目标平台可核对；不重复维护业务插件源码 |
| A08 | 恢复保留旧冻结事实；Fork 采用目标可信环境并保留源历史；实际支持的转移入口不继承错误用户域事实，未支持场景明确说明 |
| A09 | 新资源复用 F05 的装配、发现及权限，不新增数据库历史副本、配置副本、资源服务或隐式真实调用；沿原会话文件保存可靠激活 |

真实用户数据和凭据不作为默认验证输入；代表性操作使用新建隔离场景和受控服务。平台原生及实际模型执行的覆盖按真实条件区分，不能由文案、编译或目录存在推断已经通过。
