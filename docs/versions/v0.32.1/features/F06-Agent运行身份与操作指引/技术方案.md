- 授权依据：用户先确认功能设计并要求编制技术方案，随后明确“可以，按这个技术方案继续编制 F06 开发计划”，确认本方案。用户随后确认开发计划并授权 M0，再明确“连续推进 M1、M2，停在验收”。本轮连续实施与验证，不关闭 F05；F04 最终人工测试与验收继续后置。
- 上位依据：[功能设计](功能设计.md)、[总体设计](../../总体设计.md#36-agent-运行身份与内置操作手册候选)、[F05 技术方案](../F05-内置插件MCP与Skill/技术方案.md)、[Rust 架构规范](../../../../specs/Rust架构设计规范.md)、[Agent 系统技术架构](../../../../modules/agent-system.md)。

采用以下方案：

1. 将实际用户域的个人／企业模式传入现有 Host 环境工厂，在既有 `runtime_directories` 提示词片段内注入，沿原会话文件冻结。
2. 通过 F05 已有内置来源交付 `ez-assistant-guide`，目录只包含简短说明；沿 `load_skill` 加载入口正文，按主题读取参考页。
3. 参考页与官网手册共用 Markdown 源，编译进 Host；扩展现有 `SkillPackageSource` 读取端口，新增普通只读工具 `read_skill_reference`，不生成磁盘缓存或独立资源服务。
4. 恢复保留历史；Fork 精确替换 Host 自己生成的最后一个环境片段。手册入口激活和参考页工具结果均沿现有可靠会话文件记录。

## 三、职责、所有权与依赖

产品仍为 Desktop／Web／Client 经 HTTP Command、SSE 等现有通道连接正式 Runtime Host。参考页读取发生在当前 Run 的普通工具调用中，没有客户端直读 Host 资源的新接口。

| 所有者 | 负责的事实或行为 | 不增加的职责 |
| --- | --- | --- |
| Host 用户域装配 | 本域模式、`UserPaths`、会话环境工厂 | 不从模型、客户端或路径猜模式 |
| Host 内置资源模块 | 入口和主题的编译期字节、白名单映射、来源身份核验 | 不维护安装状态、用户配置或网络更新 |
| Runtime Skill 模块 | 名称状态、Winner、每轮冻结目录、入口激活、受限主题工具 | 不直接读取官网源码、磁盘或 Host 配置 |
| Runtime 权限与 Recorder | 类型化授权、取消、完整工具交换及会话历史 | 不为参考页新建激活表或审计副本 |
| 官网手册源 | 各主题当前正文与适用版本 | 不按官网最新内容改写已经交付的 Host |

依赖保持 `runtime-host -> assistant-runtime -> agent-tools / agent-types`。扩展端口属于已有 Runtime Skill 边界，具体嵌入实现属于 Host；`agent-core`、`assistant-protocol`、TS 协议不增加身份或资源管理类型。前端沿现有 Skill 列表、设置页和通用工具结果展示。

## 四、可信运行模式与冻结提示词

### 4.1 模式来源与渲染

`HostResources::for_user` 将已知 `personal` 传给 `HostSessionEnvironmentFactory`，工厂私有保存该不可变事实。个人用户域输出 `personal`，企业用户域输出 `enterprise`；不新增可由模型或客户端提交的模式字段。

在原环境部分补充：

```xml
<runtime_directories>
  <runtime_mode>personal</runtime_mode>
  <!-- 保留原有用户、工作区、会话、附件等目录字段 -->
</runtime_directories>
```

同时加入简短语义：所有列出的目录和工具执行属于当前连接的 Host／用户域；客户端所在设备不等于执行设备；模式用于理解配置归属，实际操作仍受工具权限控制。企业模式不能被描述为所有配置只读，个人模式也不额外授予权限。

保留现有字段、XML 转义、总提示词大小限制及最后部分的位置约定。模式不加入 `SessionExecutionEnvironment` 或新的数据库字段；可靠的系统提示词快照已经承担冻结事实。现有 Skill 目录与自定义 Agent 指令仍插在环境部分之前，不能将模式段移入可被覆盖的 Persona／AGENTS 正文。

### 4.2 新建、恢复与 Fork

| 路径 | 执行行为 |
| --- | --- |
| 新建会话 | 当前工厂生成模式、当前用户根及实际目录，与系统提示词一同冻结 |
| 重启／恢复旧会话 | 读取原快照，不调用工厂重写；没有模式的旧会话保持缺失，不从旧路径补猜 |
| 旧会话后续 Run | 沿现有规则扫描当前 Skill 候选；读取新版手册不代表冻结模式已更新 |
| 用户显式清空历史 | 复用已有环境重建路径，重新生成当前事实；保留既有目录一致性核验，不自动触发清空 |
| Fork | 保留原冻结工作区和历史，按目标工厂生成当前模式／用户根及新会话私有目录；源文件不修改 |
| 切换连接或用户 | 仍沿已有会话归属选择，不能将源会话直接挂到另一域；不增加跨 Host 导入 |

Fork 替换时先核验 `SystemPromptSnapshot.parts` 的最后一部分是完整独立的 Host `runtime_directories` 部分，再整体替换这一个部分。旧格式没有 `runtime_mode` 但符合该整体边界时可替换；不通过全文查找 XML 标签替换，避免改到用户提供的同名文本。其余系统指令、历史激活正文和源会话保持。

无法识别该最后部分时，返回现有环境构建失败错误，拒绝本次 Fork；不能继续 `pop` 丢弃未知指令或猜造身份。这是对不符合现有环境约定的异常／历史快照的明确限制，实施前用既有会话夹具核对正常旧格式，不增加自动改写或修复迁移。若发现正式支持的旧格式缺少此约定，应先报告实际格式和影响，再调整方案。

入口正文只包括任务适用范围、优先使用环境事实、主题键和读取方式、Skill／MCP 操作核验原则；创建方法转向已有 `skill-creator`。`builtin:ez-assistant-guide` 继续表示来源，不作为文件路径。

新增官网主题须登记 `docs/site/site.json`；不会在本轮部署官网。官网发布与 Host 更新各自按原流程进行，二者共用源正文，但不承诺不同发布时间的交付内容始终相同。

### 5.2 编译与引用

Host 内置模块用静态映射和 `include_str!` 嵌入上述源文件。移走源码、切换工作目录、离线或安装在只读位置都不影响读取；Debug 与正式包采用相同资源集合，不依赖 Web 静态页构建结果。

返回官网 Markdown 的正文，剥离开头的网站 YAML 元信息；入口与标题可说明适用 Host 版本。装配测试将返回正文与对应源去元信息后的内容核对，不能手抄规则或维护另一份正文。静态内容错误在构建检查中失败，不上线后静默忽略。

四个主题键是精确的虚拟引用，只由工具解释。入口列出完整映射；主题间需继续读取的引用统一指向这些键。共享 Markdown 中既有的官网文件名／锚点，按该映射说明如何转入对应主题，不让 Agent 按相对磁盘路径读取。四主题之外的官网导航明确标为官网扩展阅读，不宣称随包可离线读取；所有承诺离线可读的引用必须列入静态映射并核验目标。

每页正文最多 64 KiB UTF-8，四页合计最多 256 KiB；单次只返回一页，超限时要求在源中拆分并修订方案，不静默截断指令。F06 不增加图片、脚本执行、递归目录遍历或在线抓取。

## 六、参考页读取契约与执行链路

### 6.1 为什么扩展现有来源端口

现有 `load_skill(name)` 负责完整 Skill 的激活，普通文件工具要求实际磁盘路径；二者都无法读取只存在于二进制里的主题。F06 在已有 `SkillPackageSource` 上增加有界 `read_reference` 能力，不另建 Reader 服务或资源注册中心。

端口请求携带当前目录选中的 `SkillName`、已有 `definition_digest` 和精确参考页键；返回 `Result<Option<String>, SkillPackageSourceError>` 的异步结果。只有 Host 与 Runtime 实际共享的请求／Future 类型放在现有 Skill 模块，不进入应用协议。未提供嵌入参考页的来源默认返回 `None`；Host 实现委托内置静态映射，不读取文件系统。

Host 对照本进程编译的手册入口身份与请求摘要，拒绝不匹配；摘要继续沿已有 `SKILL.md` 定义算法，不改 `SkillDefinition`／`SkillCatalog` 的序列化格式。此摘要不冒充主题正文的摘要：同一进程主题字节不可变，每次读取的实际正文通过工具结果保存。历史结果不按当前内容重建，也不额外存内容版本表。

### 6.2 Agent 工具

新增 Runtime 普通工具 `read_skill_reference`，模型参数为：

```json
{
  "name": "ez-assistant-guide",
  "reference": "references/mcp.md"
}
```

不改变稳定 `load_skill` 的参数与激活语义。用户已指定主题时可直接读取，不要求先激活入口，也不会将一次参考页读取登记成另一份 Skill 激活。

执行链路：

1. 沿本 Run／子任务已有冻结 Skill 目录解析名称，要求当前可由模型调用且 Winner 为具有参考页的内置手册。
2. 精确匹配主题白名单，解析成类型化只读调用事实；已有定义摘要由 Runtime 填入来源请求，模型不能指定来源或摘要。
3. 沿现有 authorizer 处理该工具专属的只读事实，再调用已有来源端口。
4. Host 比较内置名称及入口摘要并返回完整主题；工具结果含 `name`、`reference`、`content`，沿原工具交换闭合提交。
5. 模型依据说明调用现有文件／Skill／MCP 能力；后续副作用各自重新走权限流程，不继承手册读取的放行。

参数只接受该 Skill 已登记的键；拒绝绝对路径、盘符、URL、反斜杠、空字节、`..` 段及未知键。没有把这些输入拼到磁盘路径的后备逻辑，不存在从同名用户 Skill 的引用回退读取内置主题的路径。

### 6.3 装配、范围与权限

父 Run 在现有 `RunCompilationResources` 传入 `Arc<dyn SkillPackageSource>`，同样沿已有 `ParentDelegationResources` 传给子任务控制器；在装配 `LoadSkillTool` 的位置安装参考页工具。只有本作用域目录中存在合资格内置 Winner 时才安装，不能仅因 Host 带有字节就暴露隐藏资源。

沿 F05 同名优先级与按名称禁用规则：被用户／项目／插件同名 Skill 覆盖时，不注册内置参考页能力；选择自定义 Winner 后继续使用其现有文件资源方式。禁用或刷新对已开始 Run 的影响沿原目录冻结边界，从后续 Run 接纳，不新增执行中动态换表。

只读权限通过工具私有的 resolved facts 接入现有 authorizer，Plan／Build 均可读取；不采用任意名称字符串白名单放行。子任务只获得其既有冻结范围允许的参考读取，不因此获得父 Agent 的 MCP 管理工具，也不能指定其他用户域或 Host。

## 七、可靠历史、并发、取消与失败

### 7.1 历史与更新

入口 `load_skill` 沿既有激活 latch、Recorder 和会话文件保存可靠正文；参考页沿普通 Assistant 调用／ToolMessage 保存完整工具结果，不增加 `StoredSkillActivation`、SQL 表、文件缓存或可重建历史副本。既有 `SkillCatalog` 持久化及按轮刷新规则保持，不把四页全文放进目录快照。

升级后新 Run 可读取当前 Host 编译的主题，已经读过的旧 ToolMessage 和激活正文保持原字节；恢复不会重新执行读工具来替换历史。文档更正须随新 Host 交付，官网更新不能热替换正在执行的主题。

### 7.2 并发和生命周期

工具在既有 Run／child 的 dispatcher 中执行，首版沿串行工具策略，不新建任务、锁、队列、worker 或后台刷新。静态引用查找与有界字符串复制不持有会话锁、不进入 Store worker，也不读全量历史；可靠结果提交继续复用原 Recorder。

不同会话沿原 Tokio 并发执行，同一会话上下文变更沿原调度串行。读取前后检查现有取消令牌；取消和 pending exchange 的可靠闭合沿 Core／Runtime 既有规则，不自动重试或脱离 Run 继续工作。Host 停止时随 Run 清理，不存在独立资源任务需要额外等待。

### 7.3 失败语义

| 情况 | 行为与恢复 |
| --- | --- |
| 参数无效、未登记键 | 正常错误 ToolResult，说明允许的主题；不尝试磁盘／网络替代读取 |
| 名称不可用、非合资格 Winner、来源摘要不匹配 | 明确资源不可用；不回退另一个来源，不自动启用 Skill |
| 来源实现未提供主题或返回失败 | 返回安全错误并保留内部错误链；其他工具继续按现有循环处理 |
| 内容超限、源正文或映射错误 | 构建检查拒绝；运行时仍保留防御性上限，不返回截断的成功 |
| 取消或可靠历史提交失败 | 沿已有取消、失败与恢复机制；未可靠闭合不宣称该结果已保存 |
| Fork 环境部分无法识别 | 返回环境构建失败；保留源会话，不猜测、不自动修复 |

复用现有工具调用与 Run 关联记录即可定位失败；不新增正文日志、凭据日志或专用遥测服务。手册文本不提升为系统权限；外部 Skill 的指令同样不能绕过结构化工具校验与授权。

## 八、操作内容与安全核对

编制主题时逐项对齐当前实现：

- Skill 默认写入实际注入的 `user_skills_directory`；工作区专用目标按用户选择，插件包及内置资源只读。区分刷新列表、新 Run 扫描和已经激活的历史正文。
- MCP 区分独立、插件、内置来源和插件参数绑定；父 Agent 实际可见工具决定可操作范围，未暴露入口指向设置页，不拼 HTTP 请求寻找原生凭据。
- 查询不回读已有秘密；字段保存、临时连接测试、启用、刷新、业务调用分别核验。DeepSeek 默认关闭，保存 Key 不隐式启用；新 MCP 业务工具沿 F05 从后续 Run 生效。
- 同名服务冲突要求选择来源，不自动合并或迁移 Key；握手通过不能证明搜索 API 或用户 Key 有效。对话中直接提交的秘密可能留在原消息和调用历史，应准确说明。
- 插件目录区分只读包与可写配置／数据；源码、归档根、清单声明、平台入口、资源与许可证保持一致。业务插件继续由独立仓库维护，手册不直接修改安装包或数据库。

本 Feature 不变更真实模型、MCP 配置或凭据，不新增数据库迁移。实施验证默认用假凭据与受控本地服务；需要真实调用、生产数据或安装发布时沿对应授权处理。

## 九、兼容、交付与方案取舍

| 边界 | 决策 |
| --- | --- |
| 应用协议／客户端 | 不新增 Command、事件或 DTO；现有客户端通过通用 Skill／工具视图消费 |
| Rust 来源端口 | 在既有 trait 增加可选读取方法；逐一核查正式装配、空实现、测试替身及工具宿主编译，不让非 Host 装配读取 Host 资源 |
| 持久化 | 原系统提示词、Skill 激活和 ToolMessage 格式保持；不迁移／回写旧会话 |
| 平台与打包 | 相同字节随 Windows x64／macOS arm64 Host 编译，复用原 sidecar／Host 打包；不额外复制 docs 目录 |
| 更新和回退 | 随 Host 交付，旧结果保持；回退仍受原版本／存储准入约束，不承诺降级恢复数据 |

不采用的方案及原因：

- **每轮注入全部手册**：增加普通任务上下文，与按需主题目标不符。
- **给 `load_skill` 增加参考页分支**：混合激活与普通读取，改变稳定工具契约及 latch 行为；本方案保持原激活不变量。
- **把主题落盘后交给文件工具**：增加提取目录、权限、清理及篡改后的身份问题；当前只读嵌入内容无需这些状态。
- **只提供官网链接或裸 `references/` 标签**：无法满足离线和脱离源码的真实读取。
- **把每个主题拆成独立可见 Skill**：改变一套手册的启停和同名覆盖关系，重复占用目录；主题只需读取，无须分别激活。
- **新建资源服务、独立 trait／crate、缓存和版本字段**：现有来源端口及可靠工具结果足以承载，无对应的新所有权边界。

## 十、验证边界与后续门禁

实现后的验证对应功能设计 A01—A09，不在本方案中预先宣称通过：

1. **模式和冻结环境**：个人／企业域、同一 Host 多域、模型／客户端差异；XML 转义与大小；正常旧快照恢复原字节、Fork 只替换拥有的最后部分、用户正文同名标签保持；异常部分拒绝，显式清空沿已有重建行为。
2. **发现和来源范围**：默认发现／用户选择／模型加载、按名禁用、同名覆盖、Run 冻结与后续刷新；父／child 各自能力范围，未提供主题的来源不暴露隐藏资源。
3. **真实参考页读取**：四主题与源正文一致、引用目标、未知键／路径穿越／摘要不匹配／超限、取消及提交失败；入口和主题结果重启回读保持，不新增历史表或重复激活。
4. **受控操作闭环**：正式 Host 的新建隔离 Home 配合模拟模型及 loopback 服务，实际经过 `load_skill`／`read_skill_reference`，创建并重新发现技能，验证 MCP 查询／权限／配置／刷新及后续 Run 工具生效；真实外网 API 不作为默认输入。
5. **交付脱离源码**：Windows x64 与 macOS arm64 原生 Host 移至不含源码的独立位置、无官网网络时实际读四主题；不能用单平台编译代替另一平台实测。按官网既有校验器核对导航、元信息和链接，不在验收时自动部署。
6. **回归范围**：受影响 Host 环境、Skill、父／child 工具、权限和会话可靠记录测试；执行 Rust 格式、严格静态检查和 workspace 测试。若后续确需改协议或前端，另列具体原因及消费者检查，不能按本方案默认扩大范围。

所有自动化写入仅指向按场景新建、已核实无用户数据的 `.runtime-test/` Home；首次核对实际数据库、表与接口读取归属，验证后按实际影响核对，沿仓库数据库安全规则执行。本方案编制未操作数据库。
