## 二、实施原则与授权边界

1. 2026-10-23 用户在 M0 汇报后明确选择“连续推进 M1、M2，停在验收”，确认 M0 并授权本 Feature 剩余实施及验证连续推进。M1 完成后汇报实际结果再推进 M2，最终停在 M2／Feature 验收准备；不代替用户验收、不扩展其他 Feature 或发布授权。
2. 每项先核对现有源码及工作树，读取根 AGENTS.md 指定的规范；Rust 改动同时读取编程规范、架构规范、Agent 系统及 Host／Runtime 模块约束。保留已有改动，未经授权不提交或推送。
3. 复用已有环境工厂、最后一个环境提示词部分、Skill 来源端口、冻结目录、authorizer 和 Recorder；不新增模式配置、公开身份 DTO、数据库历史副本、资源缓存、后台服务或更新渠道，不改变 `load_skill(name)` 的激活契约。
4. 每个里程碑交付完整可验证的能力，不先合入占位资源、未装配工具或依赖下一项修复的路径。M2 验证组合行为，不承担补齐 M0／M1 缺失实现的任务。
5. 自动化写入使用项目 `.runtime-test/` 下按场景新建、已核实无用户数据的独立 Home、假凭据和 loopback 服务。首次写入前核对实际主机／端口或 SQLite 文件、涉及表及真实接口读取归属；同一已核实隔离场景沿现有授权执行，切换目标重新核对，完成后核验实际影响并收尾自身进程。
6. 本计划无生产数据库迁移或清理任务，不复制用户历史、Key 或共享数据。测试异常先停下当前步骤核对目标与影响；只对新建一次性隔离场景按既有授权修正，不扩大到日常环境。
7. 本计划不授权真实外网 API、安装、安装包制作、部署、上传或发布；M2 原生 Host 构建与运行属于验证，使用符合上述隔离规则且已获授权的环境。需要测试包或外部条件时另按用户实际授权执行，不借用已有凭据。
8. 只在本计划记录里程碑状态、完成结论、用户确认和必要限制；续作摘要沿本地 `docs/开发进度.md`。不另建验证报告、数据归档或内部产物登记。

## 四、各里程碑范围与完成判定

### M0 可信运行身份与会话环境

**目标与前置**：计划获确认后，让 Agent 获得可信的个人／企业模式和实际执行归属，并守住旧会话与 Fork 的冻结边界。

**交付范围**：

- 将 `HostResources::for_user` 已收到的实际用户域 `personal` 传入 `HostSessionEnvironmentFactory`，作为工厂私有不可变事实；不从全局默认模式、模型、客户端平台、中心地址或路径推断。
- 在原 `runtime_directories` 部分加入 `runtime_mode` 和简短执行／权限语义，保留所有现有目录职责、XML 转义、大小限制和最后部分的位置约定；核对 Skill 目录及自定义 Agent 指令的插入顺序。
- Fork 替换前核验最后部分是完整独立的 Host 环境部分，整体替换该部分；采用目标工厂的模式／用户根及新会话私有目录，保持原冻结工作区及历史。不扫描或替换用户正文中的同名标签。
- 既有恢复不回写旧 Prompt；显式清空沿原重建路径和目录一致性核验。正常旧环境部分缺少模式时仍可 Fork，无法识别时按技术方案拒绝，不盲目丢弃最后指令。
- 核对现有转移与用户域归属入口；不新增跨 Host／跨用户导入，不改 `SessionExecutionEnvironment`、系统提示词存储格式或数据库 schema。

**验证入口与完成要求**：

- 从现有 Host 环境测试开始，执行 `cargo test -p assistant-runtime-host resources::environment`；检查实际命中用例，新增或调整必要测试覆盖真实域参数传递、同 Host 不同用户域、转义与大小及最终部分位置。
- 复用现有会话／Fork／恢复测试，核对旧 Prompt 原字节、来源历史不变、新会话私有目录、用户指令同名标签及异常最后部分拒绝；显式清空不得被升级或读取手册自动触发。执行实际受影响的 Runtime 用例与 Host 集成用例，不以单个渲染函数测试代替调用链核查。
- 定向运行受影响包的严格静态检查与 `cargo fmt --all --check`；规范要求或依赖影响需要扩大时再扩大，完整 workspace 门禁在 M2 最终源码汇总执行。
- 重点 Review 可信模式来源、Prompt 所有权、Fork 的安全拒绝与旧格式范围。若发现正式支持的旧快照不具备技术方案假设的环境部分，停止扩大修复，先说明实际格式和影响，不临时增加迁移分支。

**完成判定**：新会话事实准确，恢复不改历史，Fork 只替换拥有的部分且采用正确目录；相关调用链与故障边界验证通过，无新持久化事实。完成后汇报实际验证及限制，等待 M0 确认。

### M1 同源手册与参考页读取

**目标与前置**：M0 获确认后，交付完整可读的内置操作手册与受限参考页工具，正文、发现、授权和可靠历史在本阶段闭合。

**交付范围**：

- 新增短入口 `ez-assistant-guide`，经现有 `embedded_skill` 解析和候选归并，默认可发现、用户／模型可调用。普通任务只见简短目录；按名禁用、同名覆盖与每轮冻结沿 F05，不绕过用户选择读取隐藏内置资源。
- 维护四个同源主题：环境正文新增于 `docs/site/manual/runtime-environment.md`；Skill 正文复用 `general-assistant.md`；MCP 配置及内置搜索正文由 `plugins.md` 移至新 `mcp-configuration.md` 并从原页链接；插件开发复用 `plugin-development.md`。登记 `docs/site/site.json`，不复制第二套规则，不部署官网。
- Host 静态映射四个精确主题键，通过 `include_str!` 嵌入正文，剥离网站 YAML 元信息。校验主题间引用、源码与返回正文一致、单页 64 KiB 和合计 256 KiB 上限；超限或承诺离线的引用缺失必须失败，不能截断成功或伪造可读文件路径。
- 在既有 `SkillPackageSource` 增加可选参考页读取方法，Host 实现名称／已有定义摘要核验及静态查找；未提供能力的来源返回不可用。核对空实现、测试替身及其他装配消费者，不引入新 Reader 服务、磁盘提取、文件后备读取或网络访问。
- 实现普通工具 `read_skill_reference(name, reference)`，由 Runtime 从冻结 Winner 填充来源请求并形成私有类型化只读事实；沿现有 authorizer、取消和串行 dispatcher 执行。精确白名单及路径输入拒绝按技术方案处理，模型不能指定用户域、Host、来源或摘要。
- 在父 Run 和 child 各自装配 `load_skill` 的位置传递已有来源句柄并安装参考工具，只对合资格的内置 Winner 开放；Plan／Build 可读，child 不因此获得 MCP 管理或父作用域之外的能力。
- 入口仍沿原 latch 激活；主题结果沿完整工具交换写会话文件，不新增激活记录、SQL 历史、目录全文快照或正文日志。恢复保持原结果，不重新读取新版主题改写历史。
- 内容逐项核对当前能力：实际 Skill 可写目录、发现与激活生效差异；MCP 来源／参数归属、秘密状态、保存／测试／启用／刷新／调用、默认关闭及后续 Run 工具生效；插件源码／包根／只读包与可写配置数据及目标平台契约。缺少工具时指向实际用户入口，不虚构自配置能力。

**验证入口与完成要求**：

- 先执行 `cargo test -p assistant-runtime skill` 和 Host 的内置／Skill 定向测试，覆盖名称禁用、同名遮蔽、用户选择、直接主题读取、冻结目录及父／child 范围；确认过滤后的实际用例被运行。
- 用可控模型实际经过工具 resolve／authorize／execute／Recorder，覆盖非法键和路径、非内置 Winner、摘要不匹配、来源不可用、超限、取消及历史提交失败；不只直接调用静态字典。核对稳定 `load_skill` schema 与原激活语义保持。
- 正式 Host 新建隔离 Home 至少完成一次入口发现／激活、四主题读取及重启回读；核对工具结果沿实际会话文件保存，没有重复激活或新增历史副本。每页与对应官网源去元信息后的正文核对。
- 使用既有 `site:build`（`apps/enterprise-center`）校验官网源、元信息与导航，输出到新建的本地预览目录，不运行 `site:publish`。核对所有离线引用的静态目标，官网扩展阅读不伪装成离线资源。
- 完成受影响 Host／Runtime 的编译、格式与严格静态检查。因 trait 扩展核查实际消费者；没有应用协议或前端变更时，不为该内部能力新增 DTO 或强制重建客户端。

**完成判定**：四主题真实可读且与官网同源，入口默认与覆盖规则正确，父／child／权限范围和可靠历史均通过，静态资源不依赖源码路径或网络。重点 Review 新增端口是否最小、是否存在隐藏来源回退，以及文案是否夸大工具能力。完成后等待 M1 确认。

### M2 正式 Host 联合验证与验收准备

**目标与前置**：M1 获确认后，核验完整产品路径、实际操作和跨平台离线交付，为 F06 独立验收形成结论。

**交付范围**：

- 新建个人／企业隔离场景，经正式 Host 的现有会话入口核对模式、用户根和远端执行语义；用受控模型驱动手册发现／加载／主题读取，普通任务不得自动装入整套手册。不连接真实企业账号或借用用户模型 Key。
- 完成代表性 Skill 请求：依据注入目录加载手册／skill-creator、检查同名、写入并重新发现／加载实际文件；核验更新对后续 Run 与已激活历史的不同影响，不修改内置或插件包。
- 复用 F05 工具配合假凭据与 loopback MCP，经过实际查询、授权配置、刷新及后续 Run 调用；验证 Plan 写拒绝、child 无管理能力、默认关闭、仅保存 Key、缺值和同名冲突。分别说明保存、握手和业务调用结果，不以假服务证明真实 DeepSeek API 可用。
- 贯通重启、旧会话恢复、Fork 与显式清空的正常路径；核对源会话、历史激活及已读主题不被新 Host 内容替换，失败／取消不产生不完整成功，其他用户域与会话不串事实。
- 在 Windows x64 与 macOS arm64 原生构建／运行 Host，复制到不含源码的独立位置，无官网网络时通过真实工具读取四主题。复用现有分发准备入口；不增加 DMG／MSI 制作、安装或完整发布校验。环境不可用时准确列未测项，不用交叉编译、源码存在或单平台成功替代。
- 核对现有 Desktop／Web／Client 的 Skill 来源展示与通用工具结果消费，必要处做定向验证；不借联合验证扩大为设置页重构。同步实际交付的用户操作说明，未完成／未验证能力不写成已发布承诺。

**验证入口与完成要求**：

- 扩展已有正式 Host 集成入口，使用模拟模型、假凭据及受控服务；关闭并收尾自身 Host／MCP／mock 进程，不新建验证宿主或重复扫描用户数据。
- 在最终源码上汇总执行 `cargo fmt --all --check`、`cargo clippy --workspace --all-targets --all-features -- -D warnings`、`cargo test --workspace`；从定向检查开始，完整门禁不因文档同步重复运行。区分本次失败、无关已有失败和未执行项。
- 官网源执行既有构建校验；只有实际影响客户端／协议消费者时，运行相应现有构建与测试并说明原因。若实际需要公开协议变化，先更新方案并确认，而非由计划默认授权。
- 功能设计 A01—A09 逐条记录完成结论、未完成项与必要限制。平台、真实模型、真实外网 API、原生 WebView 人工验收分别说明，不互相替代；默认没有真实模型或外网 API 测试。

**完成判定**：必要受控闭环通过，双平台离线交付有实际结论，身份、权限、同源内容与历史边界一致；影响正确性／兼容的缺口已闭合，其余未测项明确。M2 标记待确认，提请用户确认末里程碑与 F06 验收，不自动关闭 F04／F05 或进入版本发布。
