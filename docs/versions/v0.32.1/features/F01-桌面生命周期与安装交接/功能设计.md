## 二、背景与目标

当前关闭窗口默认隐藏到托盘，退出默认保留后台 Host。用户容易以为应用已经退出，实际 Host 继续运行并可能占用安装文件。
Windows 安装成功后也可能留下旧 Host；当前退出／重启先检查业务兼容，重启还检查旧文件摘要，容易出现新 Desktop 不能连接旧 Host、又无法结束它的状态。

本 Feature 形成完整闭环：默认退出可停止本机 Host，后台运行由用户显式选择；正常应用入口恢复已有窗口；安装能处理后台占用；版本不一致或启动卡住的旧 Host 也能退出并用当前安装版本重新启动。

## 三、非目标

- 不修改 Agent 执行、会话存储、数据库迁移或自动重放规则；进程终止后的恢复使用现有机制。
- 不改变远端 Host 生命周期，不通过退出本机 Desktop 停止用户正在查看的远端设备。
- 不新增系统 daemon、后台常驻进程池或跨安装的同名进程清理器；CLI 产品的分发、systemd 与自动升级不扩展到本 Feature。
- 不重做桌面导航、托盘样式、普通业务协议或版本准入，也不借本次修复建设完整 Host 任务计数服务。
- PDF／HTML 资源通道、队列计时、置顶 loading 等各自沿版本范围维护，不混入本 Feature 的实现。

## 四、功能范围与使用路径

### 4.1 关闭主窗口与默认偏好

| 场景 | 行为 |
| --- | --- |
| 新安装或没有有效关闭偏好 | 点击关闭主窗口，进入退出确认；主操作为“退出并停止” |
| 用户选择“隐藏到托盘” | 只隐藏原窗口，保留 Desktop 与 Host；不结束会话、终端或后台任务 |
| 用户选择“退出客户端” | 点击关闭进入退出确认，采用本版统一的主次操作关系 |
| 已有关闭偏好 | 保留已保存值；用户明确本次只改初始化参数，不重设已有配置 |
| 偏好不存在或字段缺失，需要初始化默认值 | 使用新默认；其他字段沿既有读取与校验规则处理，不借本次改动覆盖已有配置 |

“退出客户端”在设置中指进入退出流程，实际是否保留 Host 由当次确认选择。设置项说明需让用户能区分隐藏与退出。
Rust 默认、前端默认、原生关闭按钮和自绘关闭按钮采用同一含义，不能只改设置页展示。

2026-10-20 用户明确：已有配置保留，本次调整的是初始化参数。无论已有值来自用户手选还是程序自动保存，
均不因升级重新赋默认值；不新增偏好重置、迁移或首次升级覆盖逻辑。该项已明确，不再作为待确认选择。

### 4.2 托盘、应用菜单及系统退出

托盘“退出”、应用菜单、系统退出入口和关闭窗口触发的退出采用相同的产品语义：

| 选择 | 结果 |
| --- | --- |
| 主操作：退出并停止 | 明确告知将中断本机 Host 的运行任务、终端及连接；确认后结束目标 Host，并在完成后退出 Desktop |
| 次级操作：保留后台并退出 | 退出 Desktop，Host 与其后台 Agent 工作继续；本客户端终端沿既有退出规则收尾 |
| 取消 | 返回原界面或原隐藏状态，不结束进程或任务 |

确认前保留运行工作，不因弹出确认窗口而提前执行停止。无论原生确认还是 WebView 确认，主次选择及文案一致。
退出前继续询问是否终止现有运行工作；“终止会话”表示结束活动执行，不删除会话记录。
本机 Host 影响所有使用它的用户和客户端。2026-10-20 用户要求退出界面简洁易懂：确认只说明停止本机后台会中断运行中的会话，提供“退出并停止”“保留后台并退出”“取消”；WebView 保留默认选中的停止选项。不展示任务计数、进程细节或协议术语，不新建全局计数。

未能结束目标时保留可操作的 Desktop 并展示失败；不能客户端消失后只留下仍在占用的 Host，也不能将失败标记为已退出。
等待、重复点击及安装短阶段的互斥沿既有生命周期协调处理，不叠加多套确认或停止任务。

### 4.3 应用入口恢复原窗口

- macOS Dock、Finder 和正常应用启动入口：Desktop 仍存活时显示原窗口，取消最小化并聚焦；不刷新 WebView、不新建会话、不切换 Host 或登录身份。
- Windows 快捷方式、开始菜单和正常程序启动入口：复用已有 Desktop，恢复并聚焦原窗口；用于通知的重复启动进程退出，不留下额外窗口、托盘或 Host。
- 覆盖窗口可见、失焦、最小化及隐藏到托盘状态；macOS Dock 隐藏策略与系统重开处理一起核对，不能要求用户只能从托盘恢复。
- Desktop 已退出但 Host 仍在后台时，启动一个 Desktop 并走既有发现流程；Host 已退出时按正常流程启动它。
- 快速重复启动或原实例正在初始化时，仍只保留一个常驻 Desktop。允许操作系统短暂启动用于转交请求的进程。
- 应用正常／异常退出后可以重新启动；升级交接时旧实例不能永久占有单实例入口。正式版与 Dev 的标识隔离保留。

本期以正常系统入口为范围，不为 `open -n` 等显式强制多开的开发命令或跨操作系统用户行为增加产品承诺。

### 4.4 本机 Runtime 退出与重启

用户已明确要求停止阶段独立于业务版本兼容，并允许直接强制结束目标进程：

1. 根据当前本机目标及实际进程身份核实待结束的 Runtime；状态为连接中、启动中、断开或版本不匹配时，仍保留可用的停止／重启入口。
2. 用户确认停止意图后，原生进程控制可以直接结束已确认的目标；不要求 Host 先响应 HTTP、通过业务协议检查或声明全部业务能力。
3. 旧 discovery 对应的安装文件已经更新时，不要求当前磁盘文件仍等于旧摘要才能结束旧进程；陈旧 PID／PID 复用、安装归属及进程身份仍须核实。
4. 确认目标进程退出、实例锁和必要占用释放后，停止才算完成。旧实例已不存在时视为已停止，不为执行停止而新启动 Host。
5. 重启使用当前 Desktop 安装中来源有效的随包 Host，在同一 Runtime Home 启动；不要求新版文件匹配旧 discovery 的版本或摘要，也不改为重新启动旧文件来源。
6. 新 Host 正常执行存储准入与恢复，之后检查业务兼容和就绪；启动失败明确展示“旧 Host 已停止，新 Host 未就绪”的实际结果，不继续转圈或误报重启成功。

如果本机使用的是其他产品安装提供的共享 Host，先核实它确实是本次管理的 Runtime Home 目标；停止该实例的影响明确展示。
独立 Runtime Home、其他用户进程、Dev 实例和远端设备不因同名而被结束。
无法确认进程归属或操作系统拒绝结束时明确失败，保留重试入口，不扩展搜索并批量结束进程。

强制终止可能跳过正常收尾；沿既有可靠历史与中断恢复处理，不承诺未提交输出保留，不自动重放有副作用工具。
配置保存后的重启仍核对用户刚保存的目标配置，不能借放宽版本门禁取消保存对象／实例一致性检查。

### 4.5 Windows 安装前处理占用，macOS 保留 DMG

2026-10-20 用户确认 macOS 保留 DMG，采用平台分别交接的方案：

| 路径 | 交接时机与完成结果 |
| --- | --- |
| Windows 直接运行 MSI 覆盖安装 | 用户开始安装后，在文件替换前结束目标 Desktop／Host，核验真实退出和占用释放；仅 Host 后台运行时也自动处理 |
| macOS DMG 手动覆盖安装 | 保留 Finder 拖拽；实际启动新版 Desktop 后，识别需要换代的旧本机 Host，说明中断影响并在业务准入前完成原生停止／当前随包来源重启。Finder 复制前自动停止不属于本版承诺 |
| 两个平台应用内更新 | 用户确认后下载、校验，停止已确认的旧本机 Host，再安装、重启 Desktop 和随包 Host；保留原 Runtime Home 与配置 |

Windows 安装确认说明会中断本机任务及相关连接；只打开安装器或在开始安装前取消，不停止 Host。
旧 Desktop 仍存活时先协调其退出，避免停止 Host 后又被旧客户端自动拉起；首次安装或目标已停止时正常继续。
权限不足、目标无法确认、实例变化或仍有占用时准确失败并提供重试，不带着已知占用继续替换。

macOS 不新增 PKG、自定义安装应用、安装权限服务或新的分发格式。旧 Desktop 仍存活时，Finder／LaunchServices 的实际替换与重开行为须实机核对，不能把恢复旧窗口误报为已经运行新版 Desktop。
普通同版本 Dock／Finder 唤起仍只恢复原窗口，不在每次启动时无条件结束其他实例。

安装后启动沿用现有安装选项及更新恢复；取消／失败时说明实际进程和文件状态，不盲目启动旧摘要来源，不清理业务数据或自行回退数据库。

### 4.6 登录前旧 Host 企业协议不兼容时完成更新

该场景为本版必须通过的更新路径：用户尚未登录企业账号，旧本机 Host 已不能兼容企业中心当前协议，仍能在登录入口自动检查更新，由用户确认后完成下载、安装、重启，在原 Runtime Home 启动兼容中心的新版随包 Host 并重新登录。

更新发现和下载不依赖企业登录成功，也不要求旧 Host 先通过企业业务协议准入；本机原生停止不受该门禁阻塞。
更新包依据新版随包 Host 的协议能力筛选和校验。中心须存在已发布、可下载且兼容的平台更新包；无包、断网、撤回或签名失败应准确反馈并保留业务准入门禁。

旧 Host 无 HTTP／缺少更新上下文属于额外故障边界，不能从“企业协议不兼容仍可更新”推断任意古老或损坏的 Host 都能自行发现更新源；原生停止与有效来源识别分别核验，不隐藏失败或假称更新完成。

## 五、模块边界与契约影响

| 归属 | 本 Feature 职责 |
| --- | --- |
| Desktop 原生层 | 退出意图、原生窗口恢复、本机进程身份与结束、当前安装来源启动、生命周期互斥及真实结果 |
| Desktop／WebView 状态与设置 | 展示原生状态，维护关闭偏好与确认界面；不独立判断 Host 已退出或自行持有第二份进程生命周期 |
| Windows MSI／macOS DMG 与应用内更新 | Windows 在替换前处理占用；macOS 保留 DMG 并在新版实际启动时处理旧 Host；应用内更新复用停止、安装和恢复，失败如实反馈 |
| Host／Runtime | 保持业务状态、可靠提交、中断恢复和存储准入；不因 Desktop 管理路径放宽而关闭普通业务兼容检查 |

复用现有退出协调、单实例回调、窗口显示、Runtime Home 实例锁、更新互斥和启动发现。
只在既有实现无法承载的原生结束／安装前入口补齐平台适配；不引入第二个业务 Runtime、临时管理服务器或公共进程管理协议。
本 Feature 不预期业务数据库 DDL 或新的会话持久结构；若技术核查发现必须改变协议、配置格式或发布布局，先说明影响再确定最小方案。

## 六、关键取舍与理由

- 默认退出停止本机 Host，同时保留明确的后台选择，使安装和退出结果符合用户预期，继续保留双进程及 Runtime 独立所有权。
- 版本门禁用于业务连接；本机进程结束基于真实身份，解决旧 Host 不兼容而无法管理的循环。认证、实例与保存配置核对仍按各自用途保留。
- 安装后重启选当前已安装来源，解决“磁盘文件已变而旧进程仍存活”的交接问题；不继续要求匹配旧启动摘要。
- 复用原窗口及当前会话视图，使重复启动表现为唤起；Windows 先回归已有实现，macOS 补缺失的系统重开处理。
- 仅修改关闭行为的初始化默认值，已有配置直接沿用，不区分其保存来源；退出确认的主路径统一更新，不将默认值调整实现为配置覆盖。
- 删除拟新增机制后，窗口、偏好、互斥及业务恢复已有事实足够；本次新增能力只针对原生结束和安装前交接的实际缺口，不再建立状态副本。

## 七、验收标准

| 编号 | 完成判定 |
| --- | --- |
| A01 | 新装／缺少关闭偏好时使用新的初始化默认值，关闭窗口进入退出确认，停止本机 Runtime 为主操作；已有关闭偏好及其他配置均保持，不新增升级重置逻辑 |
| A02 | 托盘、菜单、系统退出和关闭触发的退出主次语义一致；取消不停止任务，选择保留 Host 后后台工作继续 |
| A03 | macOS Dock／Finder 和 Windows 正常重复启动恢复原窗口与原连接；最小化、隐藏和快速初始化竞争不留下第二个常驻 Desktop |
| A04 | Windows 既有单实例保护在安装版回归，正常／异常退出后可重开，升级重启不被旧实例永久挡住；Dev 隔离保持 |
| A05 | 本机 Host 启动中、HTTP 无响应或版本不兼容时仍可停止；目标退出与实例锁释放有实际核验，不只依据命令回执 |
| A06 | 覆盖 Windows 安装已替换文件、旧 Host 进程仍存活的场景；旧版本／旧摘要不阻止结束目标，重启使用当前安装 Host 和原 Runtime Home |
| A07 | discovery 过期、PID 被复用、目标已退出、权限不足或实例变化时不误结束其他进程；有清晰的结果与可恢复入口 |
| A08 | Windows MSI 覆盖仅后台 Host、Desktop 与 Host 同时存活、无旧进程及运行任务等情况；替换文件前释放真实占用，不被旧 Desktop 自动拉起竞争破坏 |
| A09 | 应用内更新继续完成停止、安装与新实例启动；覆盖登录前旧 Host 企业协议与中心不兼容时，发现兼容新版包并完成更新、原 Home 接续及新版重新登录；取消／失败展示实际状态，保留用户配置与业务数据，不自动修补或降级存储 |
| A10 | macOS 保持 DMG 拖拽及现有更新包格式；手动覆盖后实际启动新版 Desktop，能够处理旧 Host 并启用当前随包来源；旧窗口唤起与新版启动明确区分。Windows 安装方式分别实机验证，不以跨平台编译推断运行通过 |
| A11 | 当前查看远端 Host 时，本机停止及退出不结束远端工作；共享本机 Host 的影响按实际归属说明 |
| A12 | 活动任务强制结束后，新 Host 按既有中断恢复呈现可靠结果，不重复执行历史工具；没有测试或迁移指向日常用户 Runtime Home |

验证按核心风险选择最小范围；平台环境缺失时明确待验，不把已有源码、构建或历史候选视为本次安装版验收。
