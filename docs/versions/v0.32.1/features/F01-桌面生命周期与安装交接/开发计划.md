## 二、台账与实施原则

1. 一次只实施一个里程碑。计划确认后只启动 M0；每个里程碑实现与验证完成后标为 `🟨 待确认`，获得用户明确确认后才标为 `✅ 已完成` 并进入下一项。
2. 复用既有协调器、实例锁、发现文件、更新恢复记录及单实例机制，不建立第二份生命周期状态；技术细节以技术方案为准。
3. M0 的 Windows 锁占用查询可行性必须先核实，M3 的 MSI 执行顺序必须用实际生成安装包核实。无法满足时先停止扩大实现并修订方案，不按进程名清理或叠加未确认兜底。
4. 不操作日常 Runtime Home、原有测试数据或共享中心。每次验收在项目 `.runtime-test/` 新建独立场景，原生 GUI 使用 Dev 标识隔离偏好；实际连接、配置、数据库与文件目标按项目安全规则核对。
5. 重启不要求旧磁盘摘要仍成立；安装恢复不代表业务数据可降级，强制停止不承诺未提交输出或所有子进程保留／回收。
6. 最小验证按实际改动及仓库矩阵执行。源码／自动化验证与平台安装验证分别汇报；未测平台保持未验，不能以构建或历史结果替代。
7. 计划只维护状态、确认和必要遗留，过程结论写入本地 `docs/开发进度.md`；不另建验证报告或登记内部辅助文件为产物。
8. 不提交、推送、部署或发布。涉及本地测试候选时仅做必要构建、签名和本功能所需真实安装／升级，不额外执行完整发布检查；正式发布另按届时授权处理。

## 四、各里程碑范围与完成判定

### M0 原生停止与当前随包来源重启

**目标**：让明确的本机停止／重启在启动中、业务版本不匹配或 HTTP 不可用时仍能准确处理目标，重启来源固定为当前有效随包 Host。

**前置**：本计划确认；读取 Rust 编程／架构规范及 Desktop、Runtime Host、Agent 系统相应边界。先核对现有 Windows 适配和本机锁实现。

**交付范围**：

- 在现有私有平台适配内完成资源占用、用户／映像／启动时间核对及有界结束等待。先在 Windows 隔离场景证明恢复早期的实际锁持有者可以识别，失败不扩展为名称匹配。
- 将普通停止／重启接入同一原生协调入口；保留实例变化、权限失败、无目标及停止后锁未释放等真实结果。无 HTTP／无 discovery 时按方案证明归属，不为取得管理能力新启 Host。
- 重启前校验当前随包来源，停止后再核对并使用原 Home 启动；保存配置后重启保留既有实例／revision 核对，无法核对时与普通进程重启的承诺区分。
- 核对活动 Shell、MCP、终端及可靠历史在 Host 强制结束后的实际状态；不新增进程树全局清理或副作用重放。

**验证入口**：定向 Rust 测试覆盖目标已退出、陈旧 PID／实例换代、源文件被替换、权限错误及当前来源启动；使用新建隔离 Host 验证无响应／旧版本与进程及锁结果。先执行 `cargo fmt --all --check`、`cargo test -p ez-assistant-desktop --lib runtime_bootstrap`；本里程碑涉及共享生命周期与并发，完成前执行 `cargo clippy --workspace --all-targets --all-features -- -D warnings` 及 `cargo test --workspace`。两平台原生能力须在各自系统核实。

**完成判定**：功能验收 A05—A07、A11—A12 中本机原生管理部分通过；旧摘要和业务兼容不再挡住停止；无法证明身份时不误结束；重启确实运行当前来源且原 Home 保持。平台条件缺失或锁查询不可行时保持本里程碑未完成。

**Review 重点**：实际归属、句柄／缓冲区生命周期、PID 复用与操作竞争；单一 gate、真实退出条件及新启动失败后的准确状态；不得把 macOS 查询后发信号描述为 Windows 句柄同等级的原子保证。

**当前结论**：已通过 Windows 实际 Host 的早期锁占用门禁，完成两平台原生停止／当前随包来源重启；已覆盖旧映像被移动并替换、旧摘要失效、无 HTTP／discovery、陈旧 PID／实例与当前候选不可用的拒绝。无新持久化或版本变更；全仓库测试及严格静态检查通过，2026-10-20 已获用户确认。两平台进程包装探针均确认独立 Shell／MCP 可能在父进程被强制结束后继续，PTY／终端 Job 退出；该限制保留，不扩展为全进程树清理。

### M1 统一退出与系统窗口唤起

**目标**：所有退出入口采用同一主次语义，新初始化关闭窗口进入确认，正常系统入口恢复原窗口。

**前置**：M0 获确认。

**交付范围**：

- 同步 Rust／前端缺失配置默认值与设置说明，只在初始化时使用新默认；已有值直接沿用。
- 原生托盘、菜单、系统退出、自绘及原生关闭走既有协调器；默认停止本机 Host、次级保留后台、取消无副作用，失败保留 Desktop。
- 本机启动中／断开／版本不匹配时保留原生停止／重启入口；运行影响说明不冒充全 Host 精确任务计数。
- macOS 接入 Reopen 并保留隐藏窗口后的 Dock 入口，复用既有主窗口与 WebView；Windows 先对现有单实例和初始化保护回归，有实际缺陷再修复。
- 按用户追加要求，移除 Desktop 登录表单及 Web 初始化失败页残留的用户菜单；工作区菜单和初始化重试保留。

**验证入口**：已有偏好、新装／缺字段偏好、各退出入口和远端查看状态定向验证；macOS Dock／Finder、最小化、隐藏、失焦恢复，Windows 快捷方式／快速重复启动／异常退出重开在安装版核对。执行 Desktop 前端构建；Tauri 入口改动执行 `cargo test --workspace` 和 `npm run tauri -- build --no-bundle`，前端命令在 `apps/desktop` 执行。

**完成判定**：A01—A04 及 A11 的桌面入口部分通过；取消不停止，保留后台继续工作，停止失败不退出；唤起保留原窗口、连接和页面，没有第二个常驻 Desktop。

**Review 重点**：初始化与已有偏好的边界；原生／WebView 语义一致；不将退出动作挂到窗口析构，不以窗口存在推断进程或 Host 已就绪。

**当前结论**：初始化默认及退出主次已统一，已有偏好保留；简化退出确认，默认停止失败时保留客户端。macOS Finder 重开保留原页面，用户确认 Dock 和修复后的托盘“显示主窗口”可恢复。Windows 实际安装版的桌面快捷方式／开始菜单重复启动、最小化唤起和异常退出后重开通过，没有第二个常驻客户端。两平台定向检查、前端及原生构建、全仓库测试和严格静态检查通过；用户追加的登录页菜单残留已修复并通过定向测试及前端构建，该末次前端修正尚未重打安装候选。隔离测试进程及 Windows 临时安装已收尾；日常应用未停止。2026-10-20 用户以“继续”确认，进入 M2。

### M2 登录前更新与 macOS DMG 接续

**目标**：完成用户明确要求的“未登录＋旧 Host 协议不兼容 → 登录页更新 → 新版 Host → 原 Home 接续 → 能登录中心”闭环，同时保持 DMG 手动安装。

**前置**：M1 获确认；核实隔离中心、测试发布来源与签名候选。生成跨版本候选前按仓库规则统一实施软件版本为 `0.32.1`，核对前端／原生／随包 Host 声明；F01 不要求自动提高原应用、存储或企业协议下限，不创建里程碑专用产品版本。

**交付范围**：

- 保持登录前公开更新上下文与原生直连中心的发现／下载；本机新包按随包新版 Host 的协议筛选、验签，不要求旧 Host 企业登录成功。
- 更新 handoff 复用 M0 原生停止及实例核对，清除对旧 HTTP 停止／旧文件摘要的不必要依赖；复用既有 permit、签名、下载、恢复记录、原 Home 及当前来源启动。
- 实机验证登录页自动检查、确认下载、安装和重启；安装完成必须回读新 Desktop／Host 的真实版本及新 Host 登录结果，不能只验证按钮和包文件。
- 保留 DMG 与现有更新包格式。手动覆盖后实际运行新版 Desktop 时，即使普通 bootstrap 因不兼容失败，也可在业务准入前完成旧 Host 交接；旧窗口唤起不能误报为新版启动。
- 覆盖无兼容包、撤回、网络失败、签名失败、不可写位置和停止失败；保持错误可恢复及业务门禁，不增加未确认的更新源推测或任意旧版本桥。

**验证入口**：更新上下文匿名访问、有效协议范围、清单验签、来源／连接换代和原生恢复的定向测试；执行前端构建、相关 Rust 验证及 Tauri 构建。随后用真实可运行的签名 macOS 候选完成登录前下载、原位替换、重启、原 Home 配置和新版重新登录；旧 Host 与中心协议必须真实不相交，新包必须真实相交，不能只改界面提示模拟。不把正式签名／公证发布检查隐含为本地测试打包范围。

**完成判定**：A09、A10 的 macOS 范围通过，核心登录前场景有实际安装结果；旧 Host HTTP 不可用但更新来源已绑定时，停止阶段也能按 M0 处理。来源缺失、平台条件或候选不足时明确未完成，不用单元测试或 v0.29.0 历史结果代替。

**Review 重点**：业务协议门禁与更新控制独立；旧 Host／新包的协议事实没有混用；原生状态与前端一致；恢复目标及真正运行版本可证明；DMG 新启动与普通 Reopen 行为不冲突。

**当前结论**：macOS 未登录且旧 Host 企业协议与中心不相交时，已实际完成签名候选下载、原位替换、重启、同一 Home 接续及新版 Host 登录／就绪；用户确认重启后的登录页可见。真实 DMG 通过 Finder 覆盖后，显式交接按钮能原生停止旧 Host 并启动当前来源，登录已进入实际工作区；修复了旧企业协议检查遮住该按钮的问题。按用户要求删除 Desktop 更新入口的重复标题。包撤回、只读安装位置拒绝时旧 Host 保持运行；签名／下载异常、实例变化及暂停 Host 的原生停止已按对应层验证，相关构建、测试及静态检查通过。隔离进程、挂载及测试服务已收尾，未修改日常数据或发布正式候选。M2 实现与验证通过，2026-10-21 已获用户确认；M3 已实现并验证，待用户确认。

**保留边界**：旧 Desktop 仍运行时 Finder 实测拒绝覆盖并保留旧窗口，需要先退出 Desktop；仅后台 Host 存活时可覆盖，新版启用再交接。候选使用隔离测试签名与 ad-hoc 应用签名，不作为 Developer ID／公证或 Windows MSI 验收。极旧 Host 不能提供更新源时仍需手动安装；原生停止不承诺回收所有独立工具子进程。

### M3 Windows MSI 交接与 Feature 收口

**目标**：直接运行 MSI 能自动处理目标后台占用，且不破坏已完成的正常启停和应用内更新。

**前置**：M2 获确认；Windows 实机或对应原生环境及新建独立安装场景可用。

**交付范围**：

- 在当前 MSI 模板中接入新包内的安装准备执行模式，复用 M0 的安全原生能力；模式在 GUI／普通 bootstrap 之前分流，不依赖旧 Desktop 支持新参数。
- 实际确认临时 EXE 运行条件和生成安装顺序；开始安装后、占用检查及旧包移除／替换之前执行同步准备，失败不忽略。
- 先结束目标旧 Desktop，再处理 Host，核对退出及占用；准备过程中与初始化 StartupGuard 串行，安装中重新占用按真实结果阻止／回滚，不把重启后才替换视为成功。
- 验证全交互与应用内更新使用的被动 MSI 路径，以及首次安装、只有 Host、两进程并存、取消／失败、权限不足、旧文件已换但旧进程仍存活和其他安装共存。
- 对 M0—M2 已完成的入口做必要联合回归，按实际结果更新用户手册和本版更新日志；不补写未完成范围，不开始其他 Feature。

**验证入口**：Windows 原生定向测试、`npm run test:packaging`、构建及实际 MSI 安装／更新；确认临时准备进程已退出、旧目标实际退出、安装后当前随包 Host 与原 Home 接续。联合回归按新改动风险选择，不机械重复全部已通过检查；不以 macOS 构建替代 Windows 行为。

**完成判定**：A08 及 A04、A06、A09—A10 的 Windows 范围通过；其他用户、Home、Dev／独立安装与远端不误结束。F01 A01—A12 全部有明确完成结论；必测登录前 macOS 更新不能作为一般“以后提醒”跳过。

**Review 重点**：MSI 真实时序、执行身份、重复调用／旧包卸载、错误码与回滚；不把临时启动锁夸大为整个安装事务互斥，不把文件回滚夸大为运行任务恢复。

**当前结论**：Windows x64 两版实际 MSI 的全交互升级、开始前取消、被动更新及首次安装通过。早期无 HTTP／discovery、仅 Host、两进程并存和旧 EXE 重命名替换均可准确交接；对照安装未结束，新版窗口恢复并按更新记录接续原 Home，实际 Host 版本及协议正确。权限不足／文件占用会拒绝，安装期间重新占用会触发提交门禁失败与回滚，占用释放后重试成功。随包搜索资源修正为当前用户 HKCU KeyPath 及目录卸载，保留 WiX 校验。两平台既有核心回归、Windows 原生检查、构建及测试通过；测试安装、临时进程和任务已收尾，日常应用保留。用户手册与未发布日志已同步，未提交或发布；2026-10-21 实现与验证后曾待确认，用户本轮明确关闭 F01，M3 已获确认。
