## 二、台账与实施原则

1. 2026-10-23 用户确认计划并授权开始 M0；每个里程碑实现与验证完成后先标记 **🟨 待确认**，获用户确认再进入下一项，不沿用 F02 的连续推进授权。
2. 各阶段均按“核对源码与已有工作树 → 读取相关规范 → 实现 → 最小有效验证 → 汇报”执行。Rust 涉及编程／架构、Agent 系统及 Runtime／Host／协议约束；UI 涉及前端／Desktop 规范；保留全部无关在途改动。
3. 严守已确认的最小新增边界：复用现有配置源、插件参数、MCP Registry、权限、Skill 目录及可靠提交；不新增 SQL 历史、伪插件安装、独立资源注册／更新服务、配置镜像或第三套连接管理。协议变化同时更新实际生产者、消费者、序列化与持久化语义，不手改 TS 生成产物。
4. 每项里程碑完成自身正确性、并发与故障验证；最终联合验证只验证跨边界组合，不接收前项尚未解决的实现缺口。不靠 sleep 猜测并发时序，不把握手、配置保存或旧连接存活当作真实搜索成功。
5. 自动化使用项目 `.runtime-test/` 下按场景新建、已核实无用户数据的独立 Home、假 Key 与 loopback 服务。首次写入前核对实际主机／端口或本机 SQLite 文件、涉及表及接口读取来源；同一隔离场景按既有授权继续，切换目标重新核对。不得指向日常 Home、共享数据或生产库。
6. 本计划无生产迁移／清理任务；确认计划不授权生产数据库写入、删除原生文件、导入旧 Key 或批量改配置。真实搜索只在有明确授权和合适隔离凭据时验证，不扫描、打印或借用用户已有 Key；缺少条件时列出未验范围。
7. 本计划不授权安装、打包、部署、上传或发布。用户要求测试包时使用当时确认的源码范围；平台构建、原生实机、真实服务、Feature 验收及版本验收分别报告，不主动提交或推送。
8. 不新增验证报告、数据归档或内部产物登记；本计划只留里程碑状态、确认、完成结论和必要限制，续作摘要沿用本地 `docs/开发进度.md`。

## 四、各里程碑范围与完成判定

### M0 受管 MCP 配置与生效闭环

**目标及前置**：计划确认后，使现有插件 MCP 经正式命令具备真实、可校验的配置和生效能力，为 UI、Agent 及内置来源提供已实现的统一入口。

**交付范围**：

- 调整现有定义发现与配置查询，按来源＋server_key 返回安全管理信息；禁用、缺参数、来源故障或冲突不因无法生成运行候选而消失。同步共享 DTO、TS 投影及现有消费者，预留已确认的 Builtin 来源但不添加假资源。
- 按用户最新建议，插件 MCP 覆盖放原插件 config/mcp-overrides.json；内置覆盖留用户 mcp.json。复用安全文件源和目标文件 CAS，排除通用原生上传绕过，保留独立服务导入语义；完成 Keep／替换／移除／恢复默认、保留变量与 env／HTTP headers 校验。已声明参数继续调用原插件参数修改，不双写或混合批次伪装原子成功。
- 将明确来源的受管测试、目标刷新和 needs_refresh 接入现有连接生命周期。保存提交点、来源／内容修订复核、包升级、候选失效、旧连接退役、取消及 shutdown 按技术方案落实，不在写门内握手或调用网络。
- 管理与运行投影分别反映已保存状态和实际活动状态；同名执行按用户／插件标识升序／内置选择（2026-10-23 用户调整），插件整体关闭优先，不以来源标签绕过权限或创建第二套 Registry。

**验证入口及必要命令**：

- 使用现有 MCP／插件配置与 Registry 测试，执行 `cargo test -p assistant-runtime mcp`、`cargo test -p assistant-runtime-host mcp` 及实际受影响插件参数测试；核对新用例确实被运行，不能以过滤后零用例通过代替结果。
- 运行 `cargo test -p assistant-protocol`；通过 Desktop 的 `npm run generate:protocol` 生成投影，再执行 `npm run check:protocol` 和受影响消费者的类型／编译检查。格式及受影响包严格静态检查随改动执行。
- 覆盖两客户端旧 revision、来源更换、共享插件参数、文件损坏／CAS 失败、移除与恢复、导入保护、用户隔离、保存后取消及刷新竞态；使用临时 stdio／loopback 夹具核对最终启动环境和头部，不只断言合并函数。
- 使用新建隔离 Home 经实际 Host 命令完成插件定义查询、保存、测试、刷新及重启回读，确认无真实外部调用或无关服务中断。

**完成判定与 Review**：插件受管配置经命令已可独立使用，参数／文件各有唯一事实源，活动连接与保存状态准确，来源校验和失败收口通过。重点检查锁顺序、参数分派死锁、候选安装前复核、秘密回读和旧独立服务回归。完成后等待 M0 确认。

### M1 用户与 Agent 管理入口

**目标及前置**：M0 获确认后，用户和父 Agent 均能经同一管理内核完成配置与目标刷新，不依赖可用的目标 MCP。

**交付范围**：

- 插件 MCP 条目可进入与 MCP 列表相同的 ServerEditor；列表按来源区分，展示启动摘要、字段归属及配置／运行状态。受管启动定义只读，绑定参数复用原参数组件，秘密只展示是否设置。
- 实现启停、直接覆盖、绑定参数、移除／恢复默认、保存、测试和刷新反馈；保持草稿与冲突保护，明确共享参数影响，不把配置保存自动解释为启用或真实验证。内置受管行为沿同一组件接入，不为未交付资源伪造列表项。
- 在 Runtime 注入 `get_mcp_configuration`、`configure_mcp`、`refresh_mcp`，复用 M0 业务入口；查询适用于 Plan／Build，写与刷新遵循 Build 和原权限规则。当前用户域与父 Session 绑定，child 不自动取得配置写能力。
- 管理工具即使 mcp_scope 为空也可用；来源和 revision 在授权、执行边界复核，不持整套 Runtime 自引用、不回环 HTTP、不依赖目标 MCP 或读取管理 Token。
- 对话明确提供的值按原工具历史事实处理；摘要／错误／结果不额外回显秘密，不宣称原始用户消息或 ToolCall 已被清除。更新受影响模块约束及实际入口说明。

**验证入口及必要命令**：

- 复用 [MCP 详情](../../../../../apps/desktop/src/features/settings/SettingsDialog/McpSettingsPage/ServerEditor.tsx)与[插件页](../../../../../apps/desktop/src/features/settings/SettingsDialog/PluginSettingsPage.tsx)对应单元测试，执行 `npm run test -- <实际受影响测试文件>`、`npm run build`（工作目录 `apps/desktop`）。核对 Desktop／Web 共用入口及 RuntimeClient 实际请求。
- 执行 `cargo test -p assistant-runtime` 中管理装配／权限／工具可靠结果的定向用例及相关 Host 命令测试；用可控模型驱动真实工具 resolve／authorize／execute，不只直接调用配置函数。
- 覆盖无连接配置、Plan 写拒绝、Ask／Auto、过期审批、不同用户、child、断连／取消及目标刷新期间其他服务可用。两入口同值回读，直接变量与绑定参数不能形成副本，错误不暴露秘密。

**完成判定与 Review**：用户与 Agent 管理闭环可实际使用，MCP 无法启动仍能修复配置；运行副作用沿原授权，UI 不持权威状态，保存／测试／刷新结果不混淆。重点审查工具装配边界、敏感历史说明、过期草稿及按字段分源提交。完成后等待 M1 确认。

### M2 首批内置资源交付

**目标及前置**：M1 获确认后，交付无需插件安装或外部运行时的两个实际内置资源，并通过前序管理及现有 Agent 路径使用。

**交付范围**：

- Host 交付标准 stdio 子命令承载 `deepseek_search`，使用当前可执行文件绝对路径和既有 MCP 生命周期；子命令不打开 Home、数据库、实例锁或正式监听。按官方契约核对 Search 字段及参考实现差异后落地，不扩展 fetch。
- **DeepSeek Search 默认可见但禁用**，缺 Key 提示待配置；保存 Key 不启用、不测试真实服务。禁用时不自动启动连接；用户显式测试只创建可关闭的临时候选，不改变启用状态或发起搜索。启动环境只使用目标配置，不回退模型 Key、父进程同名变量、.env 或原生 JSON。
- 依技术方案完成请求参数／来源结果、有限重试、总预算、并发容量、响应上限、取消与进程收尾；失败返回安全原因，不缓存或重放搜索历史。
- 产品维护内嵌 skill-creator 正文，增加 Builtin 来源及最低优先级，复用发现／按需激活与历史冻结；来源标签不伪装磁盘路径。既有自定义同名 Skill 和禁用规则继续生效，生成内容写到实际可写 Skill 目录。
- 核对资源源码与授权来源，内容自包含，不打入独立插件整包／Python，不增加安装行或解压缓存。Host、Desktop 内嵌 Host、Client 分发使用相同内容。

**验证入口及必要命令**：

- 执行 `cargo test -p assistant-runtime skill` 及 `cargo test -p assistant-runtime-host` 的内置装配／stdio／搜索定向用例；字段与来源新增后再执行协议 round-trip、投影生成检查及消费者编译。
- 标准 MCP 客户端经正式子命令连接 loopback HTTP，覆盖成功、缺 Key、401／配额、429／可恢复错误、超时、响应超限、满容量、调用取消和关闭；通过受控时钟／服务端观测确认重试和总预算，不等待真实长超时。
- 新建 Home 验证首次默认禁用、仅保存 Key 仍禁用、主动启用刷新后可调用、移除 Key 并刷新后的错误及其他服务不受影响；没有显式测试或启用动作时，断言没有搜索子进程和真实搜索请求。显式测试结束后临时候选关闭，服务仍禁用。
- 按需加载 skill-creator，确认生成的用户 Skill 可被现有发现／加载器读取；覆盖同名遮蔽、用户禁用、激活冻结及重启，不改写内置资源或历史正文。
- 构建正式 Host 并脱离开发源码目录运行；用既有分发准备流程确认嵌入内容，不构造新的安装／发布渠道。本阶段无需制作 DMG。

**完成判定与 Review**：两个内置资源已可在隔离正式 Host 使用，搜索默认禁用及显式启用边界通过，Skill 不是占位文档，协议及来源消费者完整。重点审查子命令启动隔离、父环境剔除、总超时／有界任务、外部结果来源及嵌入资源可移植性。完成后等待 M2 确认。

### M3 正式 Host 联合验证与验收准备

**目标及前置**：M2 获确认后，验证资源、配置、UI／Agent、连接与升级的组合行为，准备 F05 独立验收。

**交付范围**：

- 使用新建隔离 Home 和可重建的旧形态夹具验证独立 MCP、插件参数／原生文件与新增内置资源共存；不复制生产 Key 或操作生产库。覆盖旧资源同名、插件升级／失效、用户覆盖及 null／启停意图保留、重启配置读取与历史不重放。
- 验证无覆盖的新用户／升级用户仍默认禁用 DeepSeek；已显式禁用不被新版打开，已显式启用只保留原意图。升级不导入其他来源的 Key，也不触发真实搜索；连接恢复与计费调用分别验证。
- 正式 HTTP／SSE 路径贯通查询、分源保存、目标测试／刷新、Agent 工具调用和 UI 反馈；并发编辑／包变更／shutdown 不安装过期候选，不阻塞无关 Session。必要组合补实际文件、数据库与接口回读，不能互相替代。
- 核对 Desktop、Web 与 Client 对来源及协议的消费；按实际 Host 分发目标构建。macOS arm64 与 Windows x64 原生 stdio 启动、环境及关闭分别实测，可用环境不足时明确未测项，不以交叉编译当作实机通过。
- 在已授权且具备隔离凭据时做小范围真实搜索，核对 API、Key、来源与错误；没有条件时保留验收限制并提请用户判断，不用 mock 或工具目录替代。用户向操作说明按实际交付更新，不提前发布日志。

**验证入口及必要命令**：

- 先运行正式 Host 的定向集成场景及 Desktop／Web 相关端到端测试，扩展现有测试入口，不新建验证宿主。端到端测试明确绑定本次新建 Home，结束后收尾自身 Host、MCP 子进程及 mock 服务。
- 本 Feature 涉及公共协议、持久 Skill 来源及权限并发，按规范汇总执行 `cargo fmt --all --check`、`cargo clippy --workspace --all-targets --all-features -- -D warnings`、`cargo test --workspace`；从定向检查开始，完整门禁在最终源码上执行，不为每次文档同步重复运行。
- 执行 Desktop 的 `npm run check:protocol`、`npm run build` 和实际受影响测试；Client／共享协议有改动时执行各自现有构建／测试。没有 Tauri 原生改动时不为形成安装包重复完整发布流程。
- 区分本次变更失败、无关已有失败和未执行检查；任何影响正确性／兼容的未闭合问题先修正并重验，不把工作树复杂当作通过理由。

**完成判定与 Review**：A01—A08 逐条有结论，必需受控场景通过，真实 API 和平台限制明确；旧配置、历史和默认禁用规则保持，无临时兼容层、秘密副本或新增管理服务。M3 标记待确认，提请用户确认末里程碑与 F05 验收；不能据此自动关闭 F04、进入 F06 或发布版本。
