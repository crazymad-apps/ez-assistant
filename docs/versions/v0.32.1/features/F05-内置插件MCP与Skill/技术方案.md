## 三、进程、代码与状态归属

产品仍为 Desktop／Client → HTTP Command／SSE → Runtime Host → assistant-runtime → Agent。内置搜索执行时，Host 按现有 MCP stdio 连接能力启动同一个 Host 可执行文件的专用子命令：

```text
ez-assistant-runtime mcp deepseek-search --stdio
```

这是工具进程，生命周期归现有 Host MCP 连接管理，不是第二个产品 Host、daemon 或新监听。子命令只运行 MCP 协议及搜索 HTTP 客户端，不打开 Runtime Home、数据库、discovery、实例锁、企业登录或正式 HTTP 监听。stdout 仅承载 MCP；取消／关闭沿原连接控制，超时后回收所属子进程。

| 所在层 | 负责内容 |
| --- | --- |
| `apps/runtime-host/src/builtin/`（拟新增私有模块） | 内置定义装配、嵌入 Skill 解析、DeepSeek stdio Server 和 HTTP I/O；复用 reqwest、rmcp、Tokio，不导入独立插件仓库私有模块 |
| `apps/runtime-host/resources/builtin/skills/skill-creator/SKILL.md`（拟新增源文件） | 产品自行维护的 Skill 正文，构建嵌入 Host；不复制通用辅助整包及其 Python／依赖 |
| `assistant-runtime::skill`、`mcp`、`runtime/mcp` | 来源归并、用户配置解释、并发校验、管理工具、投影、连接生命周期与安全错误 |
| `assistant-protocol`／TS 投影 | 必要来源、目标、修改意图和安全快照；不依赖具体目录、数据库、rmcp 或 Tauri |
| Desktop／Web | 同一详情、表单草稿、冲突与保存／刷新状态；不持有第二份配置或执行权威状态 |

Host 在用户域装配时直接向 Runtime 注入不可变的内置 MCP 定义值；插件定义继续经过现有 `PluginFilePort`。扩展现有发现结果以携带受管定义／诊断，不另建 definition registry、trait 或扫描后台任务。查询、刷新、修改校验共用同一份定义归并函数。定义只读，用户配置由原配置源持有，连接由原 Registry 持有。

## 四、内置资源的交付与发现

### 4.1 嵌入资源与版本

- Skill 源文档通过 `include_str!` 或现有构建期嵌入方式进入 Host；内置 MCP 定义由同一 Host 私有装配代码生成。Desktop 内嵌 Host、Web Host、Client 平台 Host 共用相同产品内容。
- DeepSeek 使用当前 Host 可执行文件的绝对路径启动，不依赖 PATH 中的同名程序、不经 Shell 拼接、不带管理令牌。rmcp 当前仅开启客户端 feature，本次在 Host 所需范围开启 Server／stdio feature，保持单向依赖。
- 首批不新增 Python 运行时、动态下载、外部资源目录、解压缓存或安装任务。既有签名／分发仅需覆盖构建后的 Host，不增加另一份可执行文件。
- 内置版本沿 Host 软件版本；具体定义／正文使用已有内容摘要参与当前配置或 Catalog 身份，不另设持久 revision 计数、资源版本库或后台更新状态。
- 参照已有需求维护产品版 skill-creator；独立仓库正文只作参考，复用原文前核对来源授权，不以缺少许可证的副本自动取得再分发权。无需复制原文即可实现相同产品功能。

### 4.2 Skill 来源与同名规则

在既有 `SkillSource` 及对应 `SkillSourceSnapshot` 增加 `Builtin`。现有插件／Workspace／用户之间的优先级不变，内置候选放在最后，已存在的同名自定义资源优先，使用当前 Shadowed 诊断说明实际来源；不静默改写旧 Skill 或让内置优先级提升权限。

首批 Skill 无外部脚本或参考资源。Host 直接从嵌入正文生成 `SkillCandidate`，复用 frontmatter 校验、正文、definition_digest、Catalog 与 ActivationLatch。内置候选的 `source_path` 使用明确的 `builtin:skill-creator` 来源标签，不能交给文件工具当真实路径；激活渲染按 Builtin 分支说明正文已随加载提供，省略物理资源目录。相应字段文档及校验同步调整，不伪造安装目录或写一份缓存文件。

skill-creator 默认可发现、可由模型及用户按现有机制加载，已有按名称禁用规则继续生效。正文按需激活，不进入所有系统提示词；新 Run／显式刷新按原目录边界接纳新版，已有可靠激活正文仍按文件历史冻结。F06 后续内置操作手册沿同一候选来源加入。

### 4.3 MCP 身份与默认状态

管理目标使用 `source + server_key`：独立用户服务、`plugin(name)` 服务、`builtin` 服务。插件名／server_key 保持真实已有身份；不新增伪插件名、不以包 SHA 作为用户配置主键，也不为展示创建随机 ID。

DeepSeek 固定 key `deepseek-search`，默认显示、默认禁用；2026-10-23 用户在编制计划时再次明确“deepseek search 默认不启用”。保存 Key 不隐式启用，升级保持已有启停意图，没有明确启用记录时仍禁用。没有 Key 时详情提示待配置；用户保存 Key、启用并刷新后才建立活动连接。用户显式测试可按原测试入口临时握手，结束后关闭候选，不保存启用意图或发起搜索。首次启动不写默认覆盖记录、不探测真实 API。内置子进程握手可以在无 Key 时返回工具目录，实际搜索返回安全的缺配置错误，避免把进程故障当作配置缺失。

执行、权限及历史仍沿原 `server_key`。2026-10-23 用户确认同名按优先级加载：用户添加 > 普通插件 > 内置资源；同级插件按标识升序。禁用条目不参与，管理列表保留各来源并由 Runtime 的可选 `shadowed_by` 标明更高优先级来源。同名不报错、不阻止编辑／启停／删除，也不自动重命名或修改原件。缺配置、禁用、未连接也不能从管理列表消失。

用户条目的启停／删除按用户 `mcpServers` 中的真实条目处理，不因插件声明同名 key 而拒绝；条目不存在或内容修订过期仍拒绝。只改用户条目，保留同名插件及内置配置；保存后仍沿显式刷新生效，刷新按上述优先级选择。用户同名新增、编辑和导入不再因插件声明而被拒绝；用户文件内的真实覆盖仍沿原导入确认及 CAS。

## 五、统一用户配置与字段归属

### 5.1 按来源唯一保存，复用安全文件机制

2026-10-23 M0 期间用户建议插件 MCP 配置放回原插件配置目录，按此调整：独立／内置 MCP 保持用户级配置，插件覆盖按原插件目录归属保存。同一值不跨文件镜像，不自动迁移现有参数或原生文件。

| 来源 | 唯一保存位置与结构 |
| --- | --- |
| 独立 MCP | `<user_home>/mcp.json` 的 `mcpServers`，保持原启动定义 |
| 内置 MCP | 同一文件的 `managedServers.builtin.<server_key>`，只保存用户覆盖 |
| 插件 MCP | `<user_home>/plugins/<plugin_name>/config/mcp-overrides.json` 的 `servers.<server_key>`，只保存该插件服务覆盖 |
| 已声明插件参数 | 原插件设置 Store，不在上面两个文件重复保存 |

内置示意：`{"mcpServers":{},"managedServers":{"builtin":{"deepseek-search":{"enabled":false,"env":{"DEEPSEEK_API_KEY":"<由用户配置>"}}}}}`。插件示意：`{"servers":{"example-server":{"env":{"TOKEN":"<由用户配置>","PACKAGE_DEFAULT":null}}}}`。上述是内部持久格式，不要求用户手写或为 DeepSeek 创建专用 JSON。

受管覆盖只接受 enabled、env 或 HTTP headers，不接受 command／args／cwd／url；这些由内置代码或插件包定义。没有覆盖不自动写记录。插件 file 缺失等价空覆盖，损坏或不符合 `servers` 格式时明确失败，不覆盖可能已有的同名文件。受管文件名从通用原生文件列表及上传目标中排除，避免绕过配置校验；其他原生文件契约保持。

两处均复用 `McpConfigSource`、私有文件权限、原子替换及内容 CAS，不新建文件读写机制、SQL 表、配置同步或目录 Registry。插件来源由既有 PluginFilePort 交回，配置快照携带实际文件 revision；命令使用目标文件 revision，不能误用根 mcp.json 的 revision。既有包摘要、插件参数 revision 和文件 revision 分别承担真实校验，不为展示另造计数。

未知无关字段原样保留。独立 MCP 导入只修改独立定义，明确排除已知 `managedServers`；插件文件没有借该入口导入／导出凭据的通道。新插件覆盖文件不与原生配置形成秘密副本，升级继续保留 config 目录，卸载清理沿原插件数据选择，不另造同步或迁移任务。

### 5.2 默认值、替换、移除及恢复

| 操作／来源 | 生效规则 |
| --- | --- |
| 没有用户覆盖 | 继承包定义／内置定义 |
| Keep | 保持已保存修改，既不写占位符也不读取回显旧值 |
| Replace(value) | 保存该用户值，覆盖同名默认变量 |
| Remove | 持久保存 null，明确从生效环境移除该变量；不是删除覆盖后重新露出包默认值 |
| 恢复默认 | 删除该键的用户覆盖；使用单独的 reset 意图，UI 文字与 Remove 区分 |
| Host 保留目录变量 | 不允许用户替换、移除或 reset 为伪路径，仍由 Host 注入 |

env／headers 复用当前名称、数量、长度、NUL、保留头等校验；仅改变目标子进程环境或该服务 HTTP header，不更改 Host、系统或其他服务环境。HTTP 服务不接受 stdio env，stdio 不接受 HTTP headers。移除的环境变量也必须从最终启动快照剔除，不能又从父进程继承回来。

### 5.3 已声明插件参数不双写

包描述符中的 `${config.<name>}` 绑定继续以原插件参数为权威来源。详情返回环境键与参数绑定关系、已设置状态及插件设置 revision，不回显值；对应编辑直接调用现有 `mutate_plugin_settings(SetParameter)`，同样使用包摘要与参数 revision 校验。MCP 环境覆盖分支拒绝再为绑定键保存第二份值。

UI 在同一详情中展示参数绑定字段并复用原参数编辑组件；Agent 管理工具也按字段归属调用同一 Runtime 参数修改逻辑。直接覆盖和绑定参数分别提交，不声明文件与 SQL 之间存在跨介质原子事务，不接受一个混合批次部分成功后伪装整体成功。为绑定参数执行修改时，不能持有插件只读使用租约再递归申请参数写租约；先按归属分派到已有 PluginManager。

原插件参数保存保持现有自动生效入口，但刷新收窄到该插件的服务，不重连独立或其他插件 MCP；直接覆盖文件保存仍只标记待刷新。同一个插件参数被多个 MCP 引用时，在该字段展示明确说明共享影响；Agent 返回实际影响服务列表。受管覆盖只改本服务，绑定参数则保留原真实作用域，不伪装成 MCP 私有值。

### 5.4 来源变化与异常配置

配置保存按稳定插件名＋server_key 归属；包摘要只用于证明本次编辑所见的定义未变化。查询返回当前来源摘要，提交需同时核验文件 revision 和所见包／内置定义摘要；绑定参数还沿原参数 revision 校验。包更新后若记录不再有合法字段／来源，保留用户记录并诊断，不擅自删除、执行或自动迁移。

顶层 JSON 不可读或损坏时按既有配置错误收口，不自动生成空文件覆盖。单条受管覆盖非法时隔离该条，不回退为“已恢复默认且已连接”；合法独立及其他受管服务按当前故障隔离规则处理。直接编辑文件不能绕过来源、保留变量与大小校验。

## 六、管理协议、详情与 UI

优先扩展已有 DTO／Command，不新增通用管理服务：

| 现有入口 | 本次改动 |
| --- | --- |
| `get_mcp_configuration` | 汇总独立、插件声明和内置定义，返回来源、字段归属、缺配置／来源故障、是否允许修改及当前运行投影；Get 不启动服务或发真实请求 |
| `McpServerSnapshot` | 增加明确来源、当前定义摘要、必要参数绑定及安全已设置状态；原独立服务缺省来源为 user。列表键使用来源和 server_key，不能只用 server_key |
| `mutate_mcp_configuration` | 保留独立 Upsert／SetEnabled／Remove／Import；新增明确 target 的受管 env／header／enabled 修改与 reset 分支，白名单拒绝启动定义字段；原 Upsert 仍拒绝插件 key |
| `test_mcp_server` | 保留独立草稿测试；受管测试按 target 和所见定义解析受管草稿，不接受调用者替换命令／URL。复用 test_id、取消和临时候选关闭 |
| 现有 MCP 刷新入口 | 将 Runtime 的目标刷新能力用于 UI／Agent，区分配置保存和运行交换；目标仍核验完整身份与修订，同一执行 key 按全局优先级刷新；低优先级入口不能抢占 |

跨 UI／Runtime 的来源使用轻量 `McpServerSource` enum，来源目标用于查询、修改及测试，是真实写入所有权边界；不依赖数据库／路径。协议生产、消费、错误映射、Rust 序列化及 `packages/assistant-protocol` TS 生成同轮更新，避免只改前端映射。

插件详情的 MCP 名称改为可点击条目，和 MCP 设置页进入同一个 ServerEditor。受管来源显示启动摘要和所属资源，锁定启动字段，不提供独立服务“删除”按钮；提供 env／header、必要参数绑定、启用开关、保存、测试与刷新。服务启停只由开关明确表达并通过保存提交，不提供“恢复默认启停”按钮；环境变量／请求头仍可按字段恢复默认值，该操作不重置服务启停。插件整体禁用优先于单 MCP 的用户 enabled，不允许子项绕过上层关闭。内置资源不能经插件卸载命令删除。

详情在缺 Key、未连接、禁用及同名覆盖时均可进入。已有秘密值只展示名称和已设置状态；不新增“显示 Key”或回读导出。并发写入冲突继续使用原配置过期反馈，不用后台新 revision 覆盖用户已查看的草稿。原生文件高级入口保留既有第三方适配，内置 DeepSeek 页面不展示 JSON 创建／上传步骤。

## 七、Agent 管理能力与权限

在 Runtime 的 Run 工具装配边界添加三个窄工具（准确名称在本方案固定，不由 MCP 自己实现）：

- `get_mcp_configuration`：可按真实来源／server_key 筛选，返回安全快照、允许修改的键、参数绑定及 revision，不读已有秘密值。
- `configure_mcp`：携带目标、所见来源摘要、实际配置源 revision 及字段级修改；直接覆盖与插件参数分别分派，拒绝混合来源提交、任意启动定义及未声明的管理动作。不包含安装／卸载插件、权限文件或用户域选择能力。
- `refresh_mcp`：只刷新一个明确目标，返回既有连接／目录／诊断结果。不能以管理刷新自动调用一次计费搜索。

三个 Tool 在 assistant-runtime 私有 MCP 管理模块就近实现，通过现有 RunToolAssembly 注入；不在 Host 基础文件工具或 agent-core 新增业务依赖。绑定当前用户域和父 Session，child 不自动继承用户级配置写能力；即使没有已连接 MCP，父 Agent 也可取得管理工具，不能依赖非空 mcp_scope 才装配。

查询可用于 Plan／Build；配置写与启动／刷新仅在 Build 及原权限策略允许时执行，复用 General 工具权限、Ask／Auto 和当前审批规则。resolve 阶段形成真实来源、目标、操作、变更键及预期版本事实，审批摘要不显示值；execute 重新核验，不把旧审批用于更新后的同名来源。首期不新增永久按服务权限规则或高权限管理通道。

工具不直接持有整个 AssistantRuntime 强引用形成自持环，沿现有 Coordinator 模式注入配置源、PluginManager、Registry、配置快照／审批及生命周期所需的窄句柄；不通过 HTTP 回环或寻找原生 Token。管理工具是运行时能力，不是可安装的 MCP，目标服务无法启动时仍可完成配置。

敏感值回读规则对 UI 和 Agent 一致：只有键和是否设置；修改保持／替换／移除，错误不带正文。优先由用户在详情页输入 Key，Agent 查询状态并继续刷新／验证。用户若明确在对话中提供值并要求 Agent 写入，可以沿已有工具执行完成，但用户消息、模型请求及原始 ToolCall 已可能包含该值，不能宣称从未进入可靠历史；管理工具不提供读取已有秘密再转发的能力，本轮不另建秘密令牌系统或改写 Core 历史。日志、事件摘要和工具结果不得额外回显值，不承诺追溯删除已进入对话的秘密。

配置／刷新工具结果沿普通工具可靠提交；只记录操作、目标、变更键及结果摘要，不把完整用户配置另存为 Run 历史。网页和 MCP 结果是资料，不授予用户配置权限；文件／Shell 原有操作能力保持，也不因此被描述成操作系统强沙盒。

## 八、并发、提交与生效生命周期

### 8.1 修改边界

直接覆盖沿 Runtime operation 准入 → 受管来源短时校验／租约 → 原 McpConfigStore 写门 → 文件 CAS。模型等待、审批等待、MCP 握手和网络搜索不持这些门禁；来源摘要与 revision 都在提交前复核。绑定参数先分派原 PluginManager，由原门禁及 Store 提交保护，避免读租约升级造成死锁。

两个客户端或 Agent 同时修改时，后到的旧 revision 返回现有配置冲突；不自动合并、重试覆盖或重复发起写入。替换同值沿原源判断返回状态，重复 remove／reset 幂等。安全文件读取、CAS 或磁盘写失败不发布“保存成功”，也不改活动连接。

文件可靠替换成功是配置提交点。此后 HTTP 断开或晚取消不回滚用户值；返回取消／断连时应能重新查询确认真实状态。保存只发布配置失效通知／needs_refresh，不在写门内启动子进程。原 MCP content fingerprint 继续判定待刷新，不新增持久刷新队列。

### 8.2 刷新与调用边界

复用 Registry 的 refresh gate、候选建立、短观察提交、旧连接退役和有界关闭。刷新先冻结配置文件 revision、插件参数 revision 及来源摘要；候选准备在锁外，安装目录前复核这些身份，变化则关闭候选并返回待重新读取，不让旧候选被标成最新。复核不因无关 Run 流式事件反复失败。

目标变化只影响目标连接及其审批／在途调用；沿现有机制报告取消及副作用可能已发生，不取消整个 Session 或重放工具。管理工具不属于目标 MCP 的调用租约，不会因重连关闭自己；其他 Session、服务和文件操作不被全局锁长期阻塞。关闭的 JoinError、超时及部分失败保留安全诊断。

MCP 业务工具沿既有 Run 装配边界冻结；管理工具不依赖该范围，故无连接时也可在当前轮完成配置／刷新，但新启用服务的发现与调用从下一轮 Run 起可用。M3 按该既有边界验证，不动态扩展运行中工具范围。

连接成功但目录为空、候选失败保留旧连接、因冲突停用、源移除和显式禁用均沿既有结果区分。保存后新配置仍可能待生效，不把旧连接工具数当作新配置已验证。Host 重启重新读取定义和用户配置，通过原 bootstrap 恢复连接；不自动搜索、不自动续跑历史 Run。Runtime shutdown 取消并等待自己持有的刷新／测试与连接，文件提交后的配置继续保留。

## 九、DeepSeek 搜索 MCP

M2 实现已于 2026-10-23 核对 [DeepSeek 官方 Search 契约](https://api-docs.deepseek.com/zh-cn/api/search/)：使用 POST /v1/tools/search，保留官方参数、结果字段及来源信息；联网核对文档不代表已调用真实搜索 API。

- Host 私有 `builtin/deepseek_search` 实现标准 stdio Server，复用同版本 rmcp；只公开 `deepseek_search`，保留参考实现已存在的 query、count、ori_question、localization、need_content 参数约束及结果字段。网页内容按外部资料返回，保留来源 URL。
- 只读取目标启动快照注入的 `DEEPSEEK_API_KEY` 和可选 `DEEPSEEK_BASE_URL`。前者缺少／无效时工具返回待配置，后者缺省为现有官方服务地址；HTTPS 默认，loopback HTTP 仅用于隔离夹具。旧 `.env`、模型 Key、父 Host 进程中的同名 Key、原生 JSON 均不回退。Host 连接 Adapter 显式剔除继承的同名变量，再注入本服务的用户值。
- 请求通过现有 reqwest/Rustls 调用参考实现同一 Search HTTP 契约；新增实现前按官方契约核对线上字段，不把旧代码或本地 mock 当作当前真实服务验证。本技术方案编制不联网调用 API。
- 默认请求超时 30 秒、响应体 10 MiB 上限、最多 2 次瞬态重试，沿参考实现的有界策略；普通 400／401／402／403 不重试，网络、408／429／可恢复 5xx 按有限退避和受限 Retry-After，取消立即终止等待。请求超时与 MCP 工具超时是不同层，不能共用一个名义超时掩盖总耗时；每次 HTTP attempt 使用包含响应读取的 30 秒总预算，2 次 Retry-After 各上限 30 秒，总上界 150 秒；该内置定义的 MCP tool_timeout 设为 180 秒，用户取消或外层更短的有效调用预算均直接终止整个操作，不在服务端继续挂起。
- 默认条数及单次返回选项在工具参数／实现常量处理，不新增原生配置文件或为每个常量开放环境变量。Key 不放命令行、描述符、日志、错误或包内示例。401、配额不足、限流、超时、非法响应和取消分别返回安全原因。
- Server 最多接受 4 个在途搜索，满时返回可观察的忙错误，不新增无界等待队列；每个响应沿 10 MiB 上限读取，参数／请求体继续遵守工具 schema 及既有 MCP 输入上限。标准 MCP 同时包含文本和结构化结果；沿既有 8 MiB 消息上限预检完整工具结果，超限返回减少条数／正文的安全错误，不截断或发送超大消息。父 MCP 的调用容量限制同时生效；子进程关闭取消请求并等待任务，不启动无主循环，不缓存请求／响应历史，不为重试执行历史工具。

### 同名优先级的实现边界（2026-10-23 用户确认）

单次配置归并选择同名已启用来源并生成 `shadowed_by`，不新增 Registry、持久索引或配置镜像。该字段为可选管理投影，不写入业务历史或数据库；旧快照缺失时按未提供处理。被覆盖条目的编辑与临时测试仍以完整来源身份执行，刷新沿原 Registry 交换和来源租约。保存与刷新仍区分；连接状态表示实际来源，覆盖标签表示下一次刷新的配置选择。

真正的配置损坏、不可用和连接错误仍按原规则处理，不将它们当作同名冲突隐藏；最高优先级配置无效时不擅自使用另一份凭据。测试覆盖顺序无关、逐层停用、来源隔离、用户保存与导入、原件保留、实际连接切换及 UI 可编辑。
