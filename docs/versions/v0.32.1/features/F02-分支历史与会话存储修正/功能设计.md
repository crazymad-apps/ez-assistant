# F02 功能设计：分支历史与会话存储修正

## 一、设计信息

- 所属版本：`v0.32.1`；版本整体保持 **开发中**。
- Feature 状态：**已完成，2026-10-22 用户验收确认并收口**。功能设计、调整后的技术方案及开发计划已确认，M0—M4 与验收前修正已完成；用户在最新测试 DMG 交付后明确“可以，继续推进吧，跳过 F03”。实际范围、未实施性能优化及平台限制见[开发计划验收结论](开发计划.md#feature-验收结论2026-10-22)。
- 2026-10-21 用户进一步明确：**这些历史结构只存会话文件，不再往数据库保存一份副本**。本地历史与继承历史均适用；这项已确认方向取代此前允许 SQL 历史派生副本的表述。
- 上位依据：[总体设计](../../总体设计.md)的版本目标第 5、7 项、F02、跨 Feature 契约及验收第 3、9 项；[遗留事项](../../遗留事项.md)中的历史／ID 和会话快照恢复问题。
- 影响模块：`assistant-runtime`、`runtime-host` 存储与读取入口、`assistant-protocol` 及其 TypeScript 投影、Desktop／Web。Core 仅在技术核查证明必要时调整，不把应用历史归属下放给 Core。
- 本 Feature 包含四个相关结果：完整分支历史、会话历史的持久化与身份边界、真实执行耗时、可靠会话加载。后两项复用同一可靠事实和读取链路，不另建计时或历史系统。

## 二、背景与目标

### 2.1 实施前核查（设计基线）

| 现有入口 | 实际行为与问题 |
| --- | --- |
| Runtime `runtime/session_management.rs::fork_session` | 按可靠 Assistant 消息及后续连续 Tool 消息截取前缀；复制规范消息、资源和部分配置／控制结果，不复制 Run 历史结构 |
| Host `storage/session_transfer.rs::fork_session` | 持久保存目标消息文件与会话等结构事实，初始化目标用量；没有复制源 Run 和 `run_message_refs` |
| Runtime `runtime/product.rs::projection_context` | 消息的轮次、attempt、Step、状态和起止投影来自当前 Session 的 Run 及消息关联；Fork 后缺少这些关联，不能靠连续消息分组恢复 |
| Host `storage/conversation.rs`、迁移基线 `v0_25_1/schema.sql` | JSONL 保存规范消息；`runs`、`run_message_refs` 等保存产品历史和执行事实。单独复制正文文件不足以恢复完整产品历史；`runs.run_id` 为全局主键，`run_message_refs` 没有 SessionId |
| Host `storage/run_state.rs`、`storage/append_effect.rs` | 已存在真实开始时刻 `started_at_ms`；Runtime `RunRecord` 与当前 Desktop 计时投影未完整使用，`executionElapsedMs` 仍按 `created_at_ms` 起算并包含 Accepted |
| Runtime `runtime/product.rs::get_session_view`、Desktop `RuntimeLifecycleCoordinator.ts` | 快照以全局事件序号变化重试，耗尽返回 `snapshot_busy`；Desktop 对该错误直接返回，没有重试／失败反馈，读取也缺少应用层超时兜底 |

以上是代码机制核查，不是实际用户数据库核查。多会话同时等待、重启后恢复的现场根因仍未确定；不将上述快照缺口直接认定为该现场唯一根因，也不认定为 Rust 死锁。

### 2.2 成功结果

1. 从可靠消息建立分支后，保留截取范围内真实的轮次、attempt、Step、工具结果和可确认的时间／状态；刷新、重启及删除来源后仍可阅读。
2. 完整产品历史结构只随会话文件保存；不在数据库建立轮次／Step／消息归属等结构副本，即使可重建也不保留。查询直接读文件或使用进程内有界索引；活动执行、队列和副作用恢复仍与历史分工明确。
3. 历史 ID 以所属会话／owner 解释；不同会话允许保留相同的继承历史 ID，查询、控制和内存索引不串会话。
4. 入队只表示等待，真实启动后才开始显示执行耗时；实时展示与历史回读采用同一可靠起止事实。
5. 无关会话持续输出不能阻止当前会话加载；繁忙、超时或失败均能结束等待并给出重试入口，旧读取结果不能覆盖新的选择。

## 三、非目标

- 不恢复或重放分支前的模型调用、工具副作用、排队输入、审批等待、未完成子任务或后台 Goal 执行；保留既有 Fork Goal 暂停语义。
- 不为历史展示复制一套活动 Run、调度器、全局历史服务或通用事件溯源系统，不增加永久流式 token 日志。
- 不把普通复制会话目录承诺为跨用户／跨 Host 导入功能；正式导入导出、目录重定位与安全校验仍需独立设计。
- 不改变 F04 的压缩机制，不越过原生压缩边界恢复模型上下文，不修改冻结系统提示词来伪造历史。
- 不调整运行开始后的审批、问答或模型重试耗时口径，不新增“纯模型用时”或计费时长指标。
- 不处理 STUN、远程桌面连接、UI-024 置顶动画或 F01 的原生安装交接；macOS 安装版偶发启动等待仍为版本级待定位项。

## 四、功能范围与使用路径

### 4.1 从可靠消息建立独立分支

沿用现有“从此消息分叉”入口和可靠消息定位，不通过文本相似度、相邻角色或消息间隔推断轮次。
截取点包含所选 Assistant 消息及其完整工具结果闭包；不能拆开工具调用与结果，也不能带入截取点后的消息。

- 完整保留的历史轮次沿用真实的 attempt、Step、状态及已知时间；同一轮多 Step 在目标会话仍属于同一轮，不合并相邻独立轮次或失败重试。
- 截取在一轮中间时，只保留已经可靠提交的部分。界面能表达“截至分支点”的历史边界，不把源轮次后来完成的状态、结束时刻或后续结果套到截取前缀；不能精确确定的耗时保持未知。
- 继承时仍在运行或等待的事实只作为已保存历史显示，不能在新会话出现可取消、可恢复或等待审批的活动工作。新发送的输入才创建目标会话的新执行。
- 分支可再次分支；来源独立继续／删除、目标刷新及 Host 重启不改变已继承内容。来源引用不能成为读取目标历史的必要条件。
- 保留既有附件、工具图片、Skill／MCP 选择、控制结果与冻结环境的有效绑定规则。涉及子任务的已提交委派结果和历史引用，必须在技术方案中明确可阅读范围与资源归属；不能留下会打开其他会话活动任务的链接。

### 4.2 会话历史文件、数据库与恢复

“完整历史”指恢复产品阅读所需的可靠消息及其轮次／Step／attempt 关联、已知起止与状态、必要控制结果和资源引用。
不包含尚未提交的流式输出，也不意味着文件中包含所有外部资源实体或可重放的执行状态。

| 事实 | 目标职责 |
| --- | --- |
| 可靠正文与历史归属 | 作为会话文件中的唯一历史事实保存；文件具体组织、提交边界和格式版本由技术方案确定 |
| 历史分页、消息归属及轮次查询 | 直接从文件解码，允许进程内有界索引；不向数据库写入 Run／Step／消息关联、历史 attempt／终态或 child 历史结构副本 |
| 全文搜索／Recall | 复用既有文本检索索引，只保存检索内容和必要定位；历史结构及命中结果的时间／状态回读会话文件 |
| 队列、活动执行、幂等接纳、pending 工具交换及恢复控制 | 输入队列的待消费正文、顺序、优先级及恢复控制临时保存在数据库，暂停期间保持原件，重启后恢复为需手动恢复执行；消费结果可靠写入会话文件后才释放已消费载荷。其余未完成控制继续由 Runtime 和其 Store 管理，不能从继承历史自动重建出可执行任务；哪些可靠终态需随历史归档在技术方案逐项划定 |
| 实际发生的调用、用量和计费 | 保留原发生归属；分支中的历史可读用量与目标新增消耗分开，不因复制、重建或重启重复记账 |
| 文件、附件和图片 | 沿现有资源存储与授权机制处理；明确文件事实、资源实体和数据库引用分别是否可用 |

文件及数据库提交必须可恢复：任一步失败不报告完整成功，不以空会话覆盖损坏历史，不让单个损坏会话阻塞其他会话及 Host 就绪。
可重建的是进程内历史索引及既有全文检索索引，不能借重建向数据库恢复历史结构。升级先迁出并核验旧 SQL 历史再删除旧表；普通会话读取不做全库扫描，现有用户数据的实际迁移仍遵守独立确认和备份规则。

### 4.3 身份和操作边界

继承历史可以保留源 Run／Message 等 ID；其身份始终包含目标会话，子任务内容还须包含实际 owner。
新执行沿现有身份分配机制产生。所有读取、分页、详情、反馈、重试、取消和清理均核对所属会话与历史／执行用途，不能以全局 RunId 命中另一个会话。

技术方案必须检查数据库主键、外键和索引，Runtime 注册表与事件路由，以及客户端的 owner、缓存和定位 key。
不能只将 `runs` 主键改为联合主键就宣称完成。继承历史不能冒充目标会话实际执行的 Input／Run，也不自动继承源会话的幂等请求或响应 ID 续接身份。

### 4.4 排队与执行计时

- 输入入队仅为可撤销暂存，只有队列项，不创建 Run、会话历史或正文处理过程。实际领取后才创建 Run；尚未真实开始不显示增长中的执行耗时，撤销暂存项不产生执行记录。
- 启动：使用已经可靠保存的开始时刻，排除之前全部排队时间；前端收到事件的时间不替代 Host 起点。
- 运行／结束：沿现有 Host 时间锚点显示，结束后使用可靠结束时刻减真实开始时刻。切换会话、重连和重启回读一致；缺失或异常起止不以入队时间填补。
- 重试：每个 attempt 使用自身起止，不能把前次失败或下一次排队计入本次；开始后的审批、问答、模型重试等待仍计入当前执行经过时间。
- 子任务沿其真实起止语义核对，不借用父轮次或子任务创建时间。

### 4.5 会话和子任务加载恢复

复用现有会话页面和子任务视图。点击会话后显示加载；临时 `snapshot_busy` 在有限次数及总时限内重试；耗尽、读取超时或持久失败后展示简短错误与“重试”，不能无限保持“正在读取会话”。
超时和次数的具体数值、取消机制及共享等待定位归技术方案，不能由重试次数叠加成无界总等待。

Runtime 的一致性检查仅覆盖当前会话、相关子任务和实际参与快照的共享配置／资源；保留真实关联变化的失效语义。
复用既有 owner、mutation gate、正文 generation 和事件消费机制，先证明其不足再考虑新计数。
快照水位与 SSE 消费必须保证读取期间发生的关联事件不丢失，不能简单移除全局校验或改回较新水位而跳过事件。

切换会话、切换设备／连接、退出和取消后停止旧读取的后续重试；同会话离开再返回也不能接纳前一轮迟到结果。
单个会话读取失败不自动将整个 Host 标为断线，不重发输入或重跑 Agent；鉴权、连接失败仍按现有边界处理。
多个会话一起等待时，以同一请求的身份核验、用户域准备、Runtime 快照和 Store 等待阶段区分原因，必要诊断保持脱敏，不另建永久运行记录产品。

## 五、模块职责与契约影响

| 模块 | 承担内容与约束 |
| --- | --- |
| assistant-runtime | 历史业务语义、Fork 截取与继承归属、活动执行隔离、可靠时间投影、快照一致性；通过 RuntimeStore 表达业务原子操作，不依赖 SQLite 或物理文件 |
| runtime-host | 会话文件格式、必要执行恢复存储及文本检索、迁移和跨介质提交；复用单一存储 worker、版本准入及备份机制，Host 不增加第二份业务调度状态 |
| assistant-protocol／TS 投影 | 只增加经确认且确有消费者的历史边界／时间表达；检查事件、快照、分页、序列化和最低兼容版本，不暴露物理表结构 |
| Desktop／Web | 按可靠轮次与历史边界展示，按 owner 定位；显示排队／运行耗时、加载失败和重试，保留选择与连接隔离，不从正文推断 Run |
| Client／企业中心 | Client 随包 Host 受存储及协议准入影响；企业中心真实调用记账不因历史复制改变，若技术核查发现契约影响再明确调整范围 |

需单独技术方案：涉及文件格式、数据库键与引用、可靠提交、迁移／回退及快照事件一致性。
暂不单独创建交互设计指导：沿用现有消息、处理过程和加载视图，功能设计已规定新增状态；若技术方案引入新页面或复杂修复向导，先重新判断并确认。

## 六、关键取舍与最小新增审查

1. 修复历史事实和读取链路，前端不做相邻消息拼轮次的补丁。
2. 历史结构仅存会话文件，活动执行只保留必要控制；撤回 `run_message_refs` 可重建副本，不能以新表、JSON 列、物化视图或“索引”为名另存同一历史结构。
3. 真实开始时刻已在存储存在，优先贯通已有字段及可靠提交；不另建计时表或重新计时任务。
4. 历史复制不产生新调用及费用；上下文窗口占用可以包含继承消息，与本会话实际新增消耗分开。
5. 现有机制不足以单独承载完整产品历史文件及继承归属，确需演进；但是否需要新增文件、类型或状态必须在技术方案逐项证明。删除某个拟新增机制后若现有事实已足够，就删除该机制。

## 七、验收标准

| 编号 | 可验证结果 |
| --- | --- |
| A01 | 多轮、多 Step、工具配对及失败重试的分支，显示真实轮次与 attempt；刷新和重启后保持一致 |
| A02 | 半轮截取只包含可靠前缀及工具闭包，明确截取边界，不借用源会话未来终态／耗时；未提交输出不进入目标 |
| A03 | 连续分支、同历史 ID 分属多个会话、删除来源后，消息、工具详情及反馈定位不串会话；继承记录不接受活动控制 |
| A04 | 分支及进程内历史索引重建不调用模型／工具、不恢复队列／审批／子任务、不重复调用记账；分支后新输入可独立执行 |
| A05 | 从所定义的会话历史文件及必需资源恢复可读产品历史；数据库没有等价历史结构副本，去掉 SQL 历史关联后仍能正确回读与定位；升级后损坏单会话有明确失败且不阻塞其他会话 |
| A06 | 在跨介质写入、事务提交及恢复的关键失败点保持可判定结果；不丢已确认历史、不激活未确认历史，不用空数据覆盖失败 |
| A07 | 长时间排队不显示执行耗时，启动从可靠开始时刻起算；覆盖排队取消、重试、重连、重启及历史读取，未知时间不补算 |
| A08 | A 会话持续输出时，B／C 首次加载可完成；当前会话、相关子任务和共享配置变化时仍保持一致，不丢 SSE 更新 |
| A09 | 短暂繁忙恢复、持续繁忙和无响应均在有界时间后结束加载或显示可重试失败；快速切换、离开再返回、连接换代时旧结果不覆盖新选择 |
| A10 | 新格式及数据库变更的隔离迁移、失败恢复、旧 Host 拒绝或兼容行为有明确结论；旧分支可恢复范围按证据说明，缺失事实不伪造 |
| A11 | 附件、图片、Skill／MCP、压缩边界和子任务历史引用按确认范围可读且不越权；源会话删除不破坏目标承诺保留的资源 |

验证使用项目 `.runtime-test/` 新建场景，沿正式 Host／Runtime／客户端入口，不使用日常 Home，不把模拟 Provider 验证写成真实上游通过。

## 八、兼容、风险与后续门禁

- 当前已有真实使用的 `0.32.1` 测试候选，无 DDL 的发布登记已经存在。不能因本 Feature 尚未发布就重写该已使用迁移；技术方案需明确新存储格式如何可靠识别、登记及拒绝不兼容写入。
- 应用兼容、企业协议及存储最低 Host 分别评估，不默认沿用或统一提升。文件格式、数据库 schema 和旧 Host 回退方式必须在实施前确认；不默认保留双读双写或猜测迁移。
- 旧分支缺失的轮次归属可能已不可恢复。只根据可靠来源修复可证明的事实；来源已删除或前缀被改写时保持未知，不根据正文猜造 ID、状态或时间。
