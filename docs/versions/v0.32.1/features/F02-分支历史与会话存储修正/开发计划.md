3. 动手前核查工作树、已有生产者／消费者及对应语言与模块规范。复用现有 Store、JSONL、generation、staged append、执行协调与事件机制；不增加持久历史投影、旁路日志或任务恢复入口。
4. 所有自动化写入与升级验证使用项目 `.runtime-test/` 下按场景新建且核实无用户数据的独立 Runtime Home。写入前核对实际连接、数据库文件、涉及表及实际读取入口；不操作日常 Home、共享库或来源不明的数据。
5. 本计划确认不替代真实用户数据迁移、恢复或批量操作前的目标核对与明确确认。产品升级代码必须先验证独立备份及可恢复性，再执行迁出和切换；备份、数据库、文件与接口结果分别核验。失败不跳过会话、不用空历史掩盖错误。
6. 先运行受影响模块的定向验证；跨层存储与并发改动在所属里程碑完成前执行必要的 workspace 门禁，已通过检查只因新改动或新风险重跑。原生文件同步／替换在对应系统验证，不以交叉编译代替。
7. 本计划只维护状态、用户确认、完成结论与必要限制；过程续作写入本地 `docs/开发进度.md`，不另建验证报告，不把辅助脚本、快照或运行数据登记为产物。
8. 不扩大到 F03／F04 等 Feature，不主动提交、推送、打包、安装、部署或发布。历史现场的偶发启动等待与共享等待原因保持待定位，不因增加诊断就宣称根因已修复。

## 四、各里程碑范围与完成判定

### M0 文件历史与迁移闭环

**目标**：建立可实际运行的文件历史唯一事实源，同时完成旧数据迁移及不兼容写入保护，保证删除 SQL 历史后生产路径仍能执行、读取和恢复。

**前置依赖**：本计划确认；读取 Rust 编程／架构规范、Agent 系统架构及 Runtime、Runtime Host、协议相应约束。先核查所有历史读写者、重试／幂等返回、父子恢复、外键及当前同版本迁移账本，不按表名假设用途。

**交付范围**：

- 落实技术方案第三、四节的文件编解码、Store 端口及可靠提交；父／child 正文与历史事实往返一致，零消息的开始／结束事实也可提交，内存 Store 行为对齐。
- 将正常 SessionView、ListRuns、GetRun、around／详情、重试判断、幂等返回及父 pending 恢复接到文件事实；历史不会装配为活动 Run 或 child，不重放模型／工具副作用。
- 同步所有正文换代入口的历史保留，包括清空、压缩和分支使用的存储能力；不改 F04 压缩算法。回执完成后释放临时 payload，终态可靠提交后释放执行控制，独立记账及文本检索不承载历史结构。
- 保留数据库中的输入队列正文、顺序、优先级及必要恢复控制；暂停期间输入保持，重启后沿既有机制要求手动恢复；排队不提前写成历史，消费结果可靠写入会话文件后才释放已消费载荷，迁移删除历史结构时不得清掉待消费队列。
- 按技术方案第八节完成同版本追加迁移、最低存储 Host 准入、备份与回退入口。旧 `0.32.1` 发布登记不重写；所有历史和必需资源准备、校验完成后才切换 generation 并删除旧历史结构。
- 收敛终态控制、外键和历史关联依赖；覆盖升级准备、事务切换及恢复失败，失败保留可解释状态。升级后损坏单会话应明确失败并隔离；旧分支已缺失的事实保持未知。

**验证入口**：

- Runtime／Host 定向测试覆盖文件往返、分页、零消息提交、失败／取消／重试、父子提交、各跨介质失败点及重启；SQL 无等价历史副本、终态控制不积累、回执最终释放必须有断言，不能只验证表被删。
- 输入队列验证覆盖排队后重启、优先级保持及暂停／手动恢复语义、旧库升级及文件提交失败：待消费正文与顺序保持可恢复，可靠提交前不释放载荷，恢复后不重复消费；已消费载荷最终释放且历史从文件读取。
- 新建隔离场景覆盖 `0.32.0`、已有 `0.32.1`、pending／旧 generation；验证备份可读取且能在另一个隔离 Home 配套恢复，核对关键表精确数量、历史关联及资源，再通过实际接口回读。用实际旧候选证明新库写前拒绝；源／目标与备份实际结果按数据库规则汇报。
- 入口为 `cargo test -p assistant-runtime`、`cargo test -p assistant-runtime-host`；协议若变化同步生成检查。完成前执行 `cargo fmt --all --check`、`cargo clippy --workspace --all-targets --all-features -- -D warnings`、`cargo test --workspace`。macOS 与 Windows 原生验证文件同步、切换、失败及恢复差异。

**完成判定**：A05、A06、A10 的存储／升级能力及 A11 的既有资源保持通过；无需 SQL 历史关联即可从文件正确读取并继续合法的新执行。旧库完整迁出后才删表，失败不发布半份新历史，独立备份实际可恢复；新建库和升级库进入相同正常路径。平台验证或旧候选准入未通过时保持 M0 未完成。

**Review 重点**：临时控制与持久历史的边界，所有查询／恢复消费者是否切换；先迁出再删表、账本及旧候选拒绝、外键删除顺序、锁与事务边界；无二次计费或副作用重放。删除本次新增机制后既有事实已足够的，应继续复用，不能保留等价历史副本作兜底。

### M1 分支历史与会话身份

**目标**：分支继承可靠历史并成为独立可读、可继续输入的会话，跨会话重复历史 ID 不导致引用串位。

**前置依赖**：M0 实现与验证通过；本次连续推进授权有效；新格式的正常读写及迁移已闭环。具体截取与资源边界见技术方案第五节。

**交付范围**：

- 完成完整／半轮、运行中可靠前缀、多 Step、失败重试及重复分支的截取；保留工具配对闭包、真实归属和截取标记，不借用截点后的源终态与时间。
- 贯通 Runtime、协议和 Desktop 的继承历史显示与控制判断；消息、工具详情、反馈及进程内索引均校验 owner。继承记录不能重试、取消或恢复原执行，目标新输入仍可独立执行。
- 复制承诺保留的 child 终态历史及附件／图片等受管资源，按结构化引用核对目标归属；Skill／MCP／控制结果与压缩边界可读，不改写自由文本或猜造旧分支来源。

**验证入口**：Runtime 分支及引用定向测试、Host 实际命令／查询、Desktop 相关 Vitest；主路径包含重复 ID、多次分支、半轮工具闭包、child、删除来源、刷新／重启及目标新输入。比较分支前后调用记账，断言读取和分支不调用 Provider／工具。执行受影响 Rust 测试及格式／静态检查；在 `apps/desktop` 执行 `npm test -- <相关测试文件>`、`npm run build`，协议变更执行 `npm run check:protocol`。

**完成判定**：A01—A04、A11 的分支路径通过，M0 文件唯一存储边界保持；来源删除后目标承诺保留的历史和资源可独立读取，继承控制拒绝且新输入可执行。旧分支不可恢复范围按事实说明。

**Review 重点**：会话与 child 的完整 owner、可靠截点、工具闭包、资源授权与路径映射；不复制活动控制、不重复费用、不伪造未知归属或未来终态。

### M2 排队与执行计时

**目标**：从可靠的真实开始时刻统计执行耗时，排队阶段保持排队语义，刷新和历史显示不改变计时口径。

**前置依赖**：M1 实现与验证通过；本次连续推进授权有效；可靠历史时间与继承边界可读，按技术方案第六节贯通已有开始事实。

**交付范围**：连接 Run／child 的开始提交、应用协议、实时事件和前端计时；排队取消、重试、continuation、审批等待、child permit 与历史缺时按方案处理。保持 accepted／created 原语义，未知或异常时间不猜补。

**验证入口**：可控时钟覆盖排队远长于执行、取消未启动、retry、审批／反馈等待、child permit、时间缺失／逆序及客户端时钟差；验证实时、重连、刷新、重启和继承历史口径一致。执行 Runtime／Host／协议定向测试及 Desktop 计时测试；在 `apps/desktop` 执行 `npm run check:protocol`、`npm run build`，受影响 Rust 格式及静态检查按规范执行。

**完成判定**：A07 通过，排队不显示运行耗时，开始／结束与历史字段可互相核对；继承历史不产生新调用或计费。无需真实长时间等待来证明计时正确。

**Review 重点**：开始时刻归属和可靠发布顺序，排队与执行的边界、child 许可等待、重试 attempt，缺失事实及连接时钟偏差；不以 created 替代 started。

### M3 快照一致性与加载恢复

**目标**：在并发输出下完成一致的会话／child 读取，并让所有加载结果在确定预算内成功或可重试失败。

**前置依赖**：M2 实现与验证通过；本次连续推进授权有效；先核查当前 gate、锁顺序、事件发布及前端请求生命周期，先补确定性交错测试。具体屏障、水位和请求预算见技术方案第七节。

**交付范围**：

- 将相关父／child 可靠提交纳入现有读取屏障；共享依赖与会话作用域水位一致发布，处理快照与实时事件的先后交错，不由局部快照推进全局 SSE cursor。
- Desktop 接入请求身份、取消、有限重试、总预算与失败反馈；覆盖 A→B→A、连接换代、晚到结果、正文解析超时与事件缓冲溢出。无关事件刷新合并，不反复重载当前选择。
- 增加既有请求阶段诊断，定位鉴权、域准备、session gate、Store 与投影等待，不记录敏感正文。普通单请求失败与 Host 连接状态分别表达。

**验证入口**：barrier 精确交错 A 持续输出与 B／C 读取、child 变更、共享配置发布、generation 切换及快照返回；fake timers 覆盖最多三次请求、总 15 秒预算和重试间隔、切换／取消／晚到 finally、缓冲上限与重同步。用实际 Host＋Desktop 验证成功与失败恢复。运行受影响 Rust／前端定向测试及前端构建；完成前执行 workspace fmt、严格 Clippy 和测试，重点核验无锁重入、死锁与事件丢失。

**完成判定**：A08、A09 通过；无关会话输出不使读取持续失效，相关变化仍一致且事件不重不漏；持续繁忙／无响应不永久 loading，切换后旧响应不能覆盖新选择。历史现场未复现或未定位时保留限制，不宣称其已解决。

**Review 重点**：parent／child／Store 与观察锁顺序、异步等待范围、快照原子基线、作用域水位和 SSE 游标独立；预算包含响应正文与退避，取消覆盖完整请求生命周期，不重发有副作用的命令。
