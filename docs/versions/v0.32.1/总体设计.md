## 二、版本目标与成功标准

修正 v0.32.0 的已知问题，使应用的启动、窗口恢复、退出和后台运行符合用户预期，并收敛历史、远程连接与实际交付中的遗留。

1. 默认退出应用时受控停止本机 Host；保留 Host 后台运行是明确的次级选择。
2. 默认关闭主窗口时进入退出确认，确认后连带停止本机 Host；继续询问是否终止正在运行的工作。
3. 点击 macOS Dock、Finder 应用入口及 Windows 快捷方式等常规入口，已有 Desktop 存活时恢复原窗口，保留原连接与页面状态。
4. Windows 重复启动的实际行为有安装版回归结论；有缺陷再修复，不能把已有单实例机制当作未实现。
5. 分支历史、网络稳定性及补验按所属 Feature 收口；未执行项与接受的限制如实保留。
6. 售前工程师生成文件前确定目录归属，原始资料、处理过程和最终交付分别存放，产物列表只登记最终交付文件。
7. 排队轮次只展示等待执行，实际启动后才计算处理耗时，不把入队到启动的等待时间计入本轮执行时间。
8. 产品维护内置插件、MCP 与 Skill，首批为 DeepSeek 搜索和 skill-creator；不整体合并通用辅助插件，具体加载及分发方案另行确认，搜索凭据由用户配置。
9. 系统提示词初始化时明确当前 Host 的个人／企业模式，配合实际用户域与目录事实，使 Agent 不必根据路径或主模型猜测运行身份；操作手册 Skill 的候选范围见第 3.6 节。
10. Windows 直接运行 MSI 时，在替换前处理后台 Runtime 占用；macOS 保留 DMG，手动覆盖后在实际启动新版 Desktop 时完成旧 Host 交接，减少手动查找进程和重复尝试安装。
11. 本机 Runtime 版本不兼容、仍在启动或管理 HTTP 不可用时，退出／重启仍能结束已确认的目标进程；重启使用当前已安装的有效 Host，不继续受旧进程版本或旧磁盘摘要阻塞。
12. macOS 完全未登录、旧本机 Host 企业协议与中心不兼容时，登录入口仍能检查并在用户确认后完成更新、原 Home 接续及新版 Host 重新登录；可用更新包、来源和网络失败如实反馈。

## 三、范围与非目标

### 3.1 本轮明确纳入的桌面行为

| 入口／场景 | 目标结果 |
| --- | --- |
| 托盘“退出” | 主路径为“退出并停止本机 Host”；次级路径为“仅退出客户端，Host 继续运行”，并保留取消 |
| 关闭主窗口，未配置关闭偏好 | 默认进入退出确认，主操作连带停止本机 Host；确认前不终止现有任务 |
| 用户显式选择隐藏到托盘 | 保留隐藏能力；Desktop 与 Host 继续运行，之后可从正常应用入口恢复原窗口 |
| macOS Dock／Finder 重开 | Desktop 存活时显示、取消最小化并聚焦原窗口；Desktop 已退出时正常启动并按现有流程发现或启动 Host |
| Windows 快捷方式／开始菜单／应用入口重复启动 | 已有 Desktop 存活时唤起原窗口，重复启动的进程退出，不留下第二套窗口、托盘或 Host |
| 当前查看远端 Host 时退出 | “停止 Host”明确作用于本机；不把关闭本机应用解释为停止当前查看的远端设备 |
| 直接运行安装包覆盖安装／升级 | Windows MSI 在替换前停止目标并核验占用；macOS 保持 DMG，手动覆盖后在新版实际启动时完成旧 Host 交接，应用内更新继续在替换前停止 |

应用菜单与系统退出入口需和托盘采用一致的退出主次关系，避免同名操作的影响不同。
继续复用现有受控停止、终端收尾、取消与错误展示逻辑；停止失败不能宣称退出成功。
“终止运行中的会话”指中断其活动执行，不是删除会话及历史。提示应明确影响本机 Host 的所有用户与客户端；
当前用户的活动数量不能冒充 Host 全部用户的精确数量，也不为改默认值另建全局统计系统。

### 3.4 售前工程师提示词：项目文件目录规范

本项由用户明确纳入当前规划，作为随版本交付的智能体配置小项，不单独拆分 Feature，
也不新增 Runtime 文件管理机制。修改时先核实售前工程师的实际配置来源；插件示例与企业中心已发布配置不能视为同一份事实。
业务插件的源提示词／示例如需调整，在独立插件仓库维护；企业中心配置通过既有管理流程更新，
不把业务插件源码或发布配置复制进主仓库。2026-10-27 已核实中心实际配置，按用户明确确认通过管理接口追加下述正文；独立备份、条件写入及数据库／接口回读已完成。已有会话的冻结提示词不改写，新会话实际文件落点仍待补验。

默认布局如下；已有清晰目录约定时按相同职责复用，避免同时建立中英文或不同编号的重复目录。

```text
项目工作目录/
├── 原始资料/               # 客户输入、参考图纸、源文档与源数据
├── 处理过程/
│   └── <任务名>/           # 多任务分别存放，避免覆盖或混用
│       ├── 脚本/
│       ├── 中间数据/
│       └── 截图与核验/
└── 交付产物/               # 明确交给用户的最终图纸、方案、报价与预览等
```

建议补入售前工程师提示词的正文：

> **项目文件与目录管理**：开始任务先查看当前工作目录和已有文件结构，遵循用户指定目录；没有约定时，
> 在当前项目工作目录按需使用“原始资料”“处理过程”“交付产物”三个目录，不预先建立空目录。
> 不把临时脚本、提取结果、转换文件、调试日志、校验数据、截图或试稿散放在项目根目录。
> 原始资料保存客户输入及参考源文件，保持内容不变；已经存在于其他位置的原件直接读取，
> 仅在需要项目内副本时复制到原始资料目录，不擅自移动、改名或覆盖用户原文件。
> 自己生成的处理脚本、中间数据、过程截图和核验文件统一放入“处理过程/<任务名>/”，
> 根据实际需要分为脚本、中间数据、截图与核验等子目录。不同任务使用可辨认的名称，
> 同一任务继续使用原任务目录，不为每一步或每次重试建立一套项目目录。
> 最终交付的图纸、方案、报价表、报告和面向用户的预览统一保存到交付产物目录；
> 内部脚本、过程截图、试稿和校验记录保留在处理过程，只有用户明确要求交付时才将所需文件整理到交付目录。
> 文件名体现项目、内容及必要版本，避免无含义的 temp、test、final2 等命名，避免覆盖其他任务的结果。
> CAD 或其他工具必须在特定目录生成伴随文件时，优先将输出位置设在本任务处理目录，
> 完成后仅整理本次生成且用途明确的文件，保留图纸外部参照、图片、字体及其他必要依赖的有效关系。
> 不擅自批量整理或删除项目已有文件。结束时提供最终交付文件的路径和用途，
> 产物列表只登记确实交给用户的最终文件，不将进度、计划、辅助脚本、中间数据或核验材料登记为产物。
> 内部文件保留不等于交付；如某项核验尚未完成，在交付说明中如实标明。

验收关注：从空目录开始、已有目录继续、只读外部原件、多任务和失败重试均按该结构归档；
交付物及其依赖可正常打开，过程文件不散落根目录，不误移动旧文件，不将内部材料登记为产物。
提示词更新的实际生效范围需核对现有会话的提示词冻结／刷新语义，不能把配置发布成功视为所有旧会话立即生效。

### 3.5 内置插件、MCP 与 Skill

### 3.7 平台安装交接：Windows MSI 与 macOS DMG

2026-10-20 用户将安装包自动处理后台 Runtime 纳入 F01，随后确认 macOS 保留 DMG，并确保登录前、旧 Host 企业协议不兼容时仍能完成更新。该选择修订此前两平台统一要求安装前停止的草案，最终基线为：

- Windows 直接运行 MSI 覆盖安装／升级时，在开始安装后、文件替换前识别并结束目标 Desktop／Host，等待实际退出及占用释放；仅 Host 在后台也不要求用户重开旧客户端。
- macOS 保留 `.app + .dmg`，不新增 PKG 或自定义安装应用；Finder 拖拽不承诺复制前自动停止。实际运行新版 Desktop 时，在业务准入前识别需要换代的旧 Host，并按确认的原生能力完成停止／当前随包来源重启；普通 Dock 重开仍恢复原窗口。
- 两平台应用内更新沿原有签名下载、停止、安装和恢复流程；停止阶段使用第 3.8 节原生能力。macOS 未登录、旧 Host 企业协议不兼容时必须完成该实际闭环，筛选并校验兼容中心的新包，不先要求旧企业登录成功。
- 目标身份、用户／安装／Home 及实际退出按已确认方案核对，不按进程名结束其他用户、Dev、独立安装或远端 Host。涉及共享本机 Host 时准确说明全部任务及连接影响。
- Windows 安装器开始前取消不停止 Host；开始后的取消／失败如实说明进程与文件状态，文件回滚不等于任务恢复或数据可降级。首次安装无目标正常继续，无法证明归属、权限不足、换代或仍占用则明确失败。
- 保留原 Home 与配置，不为安装新建长期守护服务或清理用户数据。macOS 旧 Desktop 仍存活时，Finder／LaunchServices 的替换与重开组合实机核对，不能将旧窗口唤起误报为新版已经运行。

具体方案与验收见 [F01 功能设计](features/F01-桌面生命周期与安装交接/功能设计.md)、[技术方案](features/F01-桌面生命周期与安装交接/技术方案.md)及 [开发计划](features/F01-桌面生命周期与安装交接/开发计划.md)。来源见 [安装包输入](../../inputs/260928-安装包管理与自动升级.md)。M2 已完成 macOS 隔离安装与更新验证，待用户确认；Windows MSI 交接留 M3。

### 3.8 退出／重启 Runtime 不受版本兼容门禁阻塞

用户报告 Windows 后台 Runtime 持续存活／显示启动中，安装已成功但新 Desktop 因版本不一致无法识别旧 Runtime，
同时无法退出／重启。用户明确建议停止阶段不考虑版本兼容，直接强制退出；该方向纳入 F01，
替代此前“无法通过受控停止就只报错、强制结束另待讨论”的限制，不改变业务连接的版本兼容门禁。

- 本机停止路径不要求旧 Host 完成启动、HTTP 可访问、业务能力齐全或版本兼容，也不先启动另一个 Host 来取得关闭能力。
- 对已确认归属的目标 Runtime，Desktop 的退出／重启停止阶段允许直接使用操作系统进程控制强制结束；保留已有操作确认与任务影响提示，不增加一次版本不兼容的额外确认。
- 强制结束前核对运行进程、实例锁／Runtime Home 和所属本机安装；使用平台实际进程身份防止陈旧 PID 或 PID 复用误伤。安装替换后磁盘文件摘要可能已变化，不能要求它与旧 discovery 的摘要一致才允许停止仍存活的旧进程。
- 发现文件缺失／过期或服务尚未发布 HTTP 时，应通过平台原生信息核实目标；不能仅凭同名进程、端口或某个旧 PID 直接结束其他进程。无法核实归属时明确报告原因。
- 退出成功以目标进程真正结束、相关实例锁和占用释放为准；重启在确认旧进程结束后使用当前已安装、来源有效的 Host，在同一 Runtime Home 启动。不能因旧 discovery 的旧版本／旧文件摘要而重新拉起旧来源或阻止本次恢复。
- 新 Host 启动后的应用协议兼容、存储准入与业务健康检查保持；强制结束不代表升级或恢复完成，不因本机管理放宽而允许不兼容的普通业务请求。
- 本机停止与安装交接共享同一生命周期协调，避免重复点击、安装器与旧 Desktop 自动拉起相互竞争；不跨用户、独立 Dev／Client 安装或远端设备批量结束同名进程。
- 强制终止可能跳过正常收尾；下次启动沿用既有可靠历史与中断恢复，不保证未提交输出保留，不自动重放历史工具。运行数据、配置及数据库不因结束进程而被删除或自行修补。

源码初查支持该阻塞路径：`shutdown()`／`restart_checked()` 先调用带业务兼容门禁的 `discover_target()`；
重启还在停止前按旧 discovery 的可执行文件来源、摘要与软件声明执行校验。该证据说明机制缺陷，
尚未对用户 Windows 实例进行现场复现或结束进程。旧版本无响应、安装后替换文件及版本不一致的实际行为需实施后验证。

## 五、架构原则与权威状态

- 主窗口恢复复用现有窗口与协调器，不创建新窗口、会话或第二份连接状态，不刷新 WebView 以代替唤起。
- macOS 系统重开与 Windows 单实例通知分别接入同一显示操作；不为窗口唤起新增 Runtime 接口或数据库状态。
- 常规重复启动允许系统短暂启动一个用于转交请求的进程，产品保证不留下第二个常驻 Desktop；不要求从技术上杜绝瞬时进程创建。
- 退出默认变化不改变 Runtime 的权威状态和主动停止契约；停止、重启、更新安装仍使用既有生命周期协调，避免竞争。
- 分支继承的是可靠历史，不恢复源任务、重放工具或重复计费用量；历史文件和数据库职责统一设计，禁止仅靠前端合并消息掩盖结构缺失。
- 网络故障按授权、控制、业务流、媒体和 PTY owner 定位，沿用取消与资源回收，不自动重放有副作用请求。
- F04 清空当前摘要请求可用工具，不删除历史工具调用／结果；不通过放宽全部 HTTP 400 重试解决请求兼容问题。
- 删除本次新增机制后若现有事实已足够，应直接复用现有机制；不为展示差异增加实体、迁移或并行生命周期。

6. 各 Feature 完成后仍执行必要跨 Feature、升级／恢复和候选内容核对；OpenCode 真账号及其他人工补验按实际条件收口。
