## 验收反馈修复：网页被超时提示替换（2026-09-05）

用户在准入核查后发现斗鱼页面已显示，仍保持加载中，30 秒后被整页错误提示替换；该问题属于本版本验收缺陷，前述自动门禁未覆盖这一实际场景。

- 原因：导航许可回调也接收 iframe 跳转，旧实现错误地用它更新整页 URL/加载状态；同时将未收到完成事件的 30 秒等待当作阻断错误，导致原生页面被隐藏。
- 修复：许可回调只校验协议，页面 Started/Finished 驱动加载状态。超时只结束进度动画并提供可关闭的慢加载提示，保留原生网页、网络加载和交互；迟到完成后自动清除提示。未增加依赖、页面脚本注入或新的 Runtime 协议。
- macOS 原生回归：独立 `Browser Loading Validation.app` 直接引用产品 BrowserController、ResourceBrowser、useBrowserSurface 与 Rust 浏览器模块。主页面完成后的 iframe 两次延迟导航没有重启整页加载，也没有污染地址栏。
- 慢资源验证：45 秒脚本延迟在 30 秒显示非阻断提示，45 秒 Finished 后自动清除；另用受控慢响应在提示期间实际点击网页按钮，计数由 0 变为 1，释放响应后提示清除。原生布局日志始终保留同一浏览器句柄，没有把页面隐藏。

## 补充复查：3 项浏览器问题（2026-09-05，后续已修复）

用户询问是否仍有问题，本轮仅复查与复现，未修改产品代码。发现：

1. **普通操作错误会隐藏已有网页**：`BrowserController.navigate` 的地址校验失败、ResourceBrowser 的系统打开失败均直接 `reportError`，而原生布局将有 error 的页面隐藏。原生 WKWebView 已复现：正常网页中提交 `https://[` 后正文被“请输入有效的网页地址”整页占位替换。此类错误应保留网页并就近提示；系统打开失败路径本轮仅静态确认。
2. **旧页面查询失败污染恢复后的实例**：`refreshUrl` 的成功分支核对 page/native_id，失败分支却只检查 disposed。地址查询未返回时页面被 LRU 回收/重建，旧请求迟到的 `browser_not_found` 会成为新页面的阻断错误。受控异步回归已复现，真实时序尚未在原生窗口制造。
3. **旧地址查询成功覆盖新导航目标**：同一实例在查询未返回时提交新地址，旧成功回包仍通过 page/native_id 校验，把新地址覆盖回上一页，影响地址栏及后续重试/快照。受控异步回归已复现，真实时序尚未在原生窗口制造。

临时复现位于 `/tmp/ez-browser-review/browser-review.test.ts`，结果 `/tmp/ez-browser-review/results.log`：复查当时 3 条预期行为断言均失败，用于证明缺陷，不作为通过门禁。该次复查未新增仓库测试或重新构建应用，当时的 Release 仍包含上述问题；后续修复及新产物见下节。
