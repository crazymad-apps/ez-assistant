## 二、台账与实施原则

1. 按 M0—M7 顺序实施。开发计划确认后，开始 M0 前才把版本状态从 `计划中` 更新为 `开发中`。
2. 每个里程碑执行“核查 → 实现 → 最小有效验证 → 记录实际结果 → 标记 `🟨 待确认` → 汇报 → 等待
   用户确认”；未确认不得开始下一里程碑。
3. 每个里程碑开始前读取涉及语言规范、Rust 架构规范、模块约束和必要的 Agent 系统架构，核对工作树；
   保留用户已有改动，不主动 commit/push，不清理无关文件。
4. M0 只验证 Tauri 2.11.5 child WebView 与交互式 PTY 的平台事实；原型使用隔离临时目录，不新增产品
   入口、数据库、常驻进程或长期验证 crate。关键假设失败时回到设计阶段，不用独立窗口、系统终端或
   Chromium 替代已经确认的产品行为。
5. 文件资源仍由 Runtime 保存 Session 根事实、Host 执行受控 I/O、Desktop 持有资源标签和原生句柄；
   浏览器与用户终端完全由 Desktop 持有，不进入 Agent Tool、Conversation、Run 或调试事件。
6. 新增依赖只在第一次真实调用它的里程碑引入并固定版本。`material-icon-theme` 在 M2 引入，Monaco
   在 M3 引入，Tauri `unstable` 在 M4 引入，xterm.js、FitAddon、portable-pty 和 nix 在 M5 引入；
   不得在 M0 后留下未使用依赖。
7. 所有新 Tauri command 只允许 Assistant 主 WebView 调用。外部网页 WebView 不获得 capability、Runtime
   bootstrap、文件桥、终端桥或 token；资源原始路径不进入外部网页 DOM。
8. 文件读取、图片解码、目录列举、PTY 输出、浏览器标签和终端滚动内容均执行已确认上限；不新增文件
   内容索引、终端历史、浏览器下载状态机或第二份 Runtime 权威状态；M6 复用 Desktop 偏好文件
   持久保存按会话分组的轻量标签索引，终端不参与普通页面缓存淘汰。
9. System Context 的 file URI 约定只影响新建、clear 和 Fork 后的冻结 Prompt；不迁移或静默改写现有
   Session。Desktop 仍只激活显式 Markdown file URI，不自动链接普通路径。
10. 自动测试使用 `TempDir`、本地 HTTP 页面、确定性 ModelService 和隔离 Runtime Home。真实 Provider、
    真实账号网站和用户 Runtime Home 的验证只在版本验收阶段按当时授权执行。
11. 本版不执行数据库迁移，也不直接操作用户实际数据库。若实现核查意外发现必须改数据库，立即停止并
    回到设计阶段，按仓库数据库安全规则重新核对和确认。
12. 跨 Host/Runtime 根解析、原生句柄所有权、WebView 显隐、PTY 背压、进程组清理和退出协调的非显然
    逻辑必须同步写中文注释，说明 owner、边界、失败恢复、取消和锁顺序。

### M0：macOS 平台原型门禁

前置依赖：本开发计划已确认；版本状态已更新为 `开发中`。

目标：在产品实现前验证 Tauri child WebView 和 portable-pty 的关键平台行为，尽早淘汰不成立的设计假设。

交付范围：

- 在隔离临时目录用项目固定 Rust/Tauri 工具链验证同窗口 child WebView 创建、边界、显隐、焦点、标题、
  导航回调、固定后退/前进/停止脚本、新窗口、下载拒绝、Cookie 重启行为与关闭；
- 使用精确主 WebView capability 和恶意本地测试页验证外部网页无法 invoke、读取 Runtime token 或调用
  文件/终端桥；
- 在隔离临时目录验证 portable-pty 默认登录 Shell、原始字节、ANSI、中文、Ctrl+C、vim/top、resize、
  两个并行终端、有界背压、自然退出与前台进程组升级清理；
- 验证窗口隐藏只停止显示、不停止 PTY，真正结束原型进程后没有本轮 Shell 或网页资源残留；
- 将版本、命令、观察结果、失败和保留风险写入 `docs/versions/v0.24.0/开发进度.md`；M0 完成时不保留临时产品入口或
  未使用依赖。

验证入口：

```bash
cargo check --manifest-path /tmp/ez-assistant-v024-prototypes/child-webview/Cargo.toml
cargo check --manifest-path /tmp/ez-assistant-v024-prototypes/portable-pty/Cargo.toml
```

另执行已确认技术方案列出的 macOS 人工操作矩阵；实际临时路径和精确命令在里程碑结果中记录。

完成判定：两条原型都证明正式方案可落地，外部页面无 Assistant IPC，PTY 长输出不乱序、不无界堆积，
关闭后无可归因残留；仓库没有半成品入口。任一核心条件失败则回到设计阶段，不进入 M1。

Review 重点：原型是否误用了独立窗口、系统 Terminal 或 Chromium；是否依赖私有 unsafe API；是否把
目录存在、MCP 连接或编译通过误当作真实交互证据。

### M1：资源工作区外壳与三栏布局

前置依赖：M0 已确认。

目标：把现有右栏替换为统一资源标签外壳，同时保持 ContextPanel 行为并建立后续资源的唯一前端 owner。

交付范围：

- 增加 `ResourceWorkspaceStore` 与资源标签穷尽模型，固定“当前上下文”首标签，并提供 `+` 菜单、标签
  激活、关闭、去重、焦点和键盘操作；尚未完成的资源类型保持明确禁用，不暴露无效入口；
- 将现有 ContextPanel 原样放入固定标签，保留卡片、折叠、附件、技能、子任务、Run 和 System Context；
- 调整 AppShell 和 NavigationStore：左栏保持现有最小/最大值，中栏保持最小值，右栏采用新最小值和
  动态上限，不再受固定 `800px` 限制；
- 复用现有侧栏响应优先级与 resize handle，覆盖鼠标、键盘、双击恢复、偏好夹取和窄窗口折叠；
- 建立资源正文、标签栏和遮罩协调的 DOM 容器，但不提前实现文件、浏览器或终端能力。

验证入口：

```bash
cd apps/desktop
npm run test -- tests/unit/navigation-store.test.ts tests/unit/app-shell.test.tsx \
  tests/unit/context-panel.test.tsx tests/unit/resource-workspace-store.test.ts
npm run build
```

完成判定：现有右栏功能无回退；标签与 `+` 菜单可用鼠标和键盘操作；三栏满足最小宽度、右栏动态上限
和窄窗口折叠约束；没有第二份 Session/Run 状态或提前开放的空壳能力。

Review 重点：ContextPanel 是否被复制状态；右栏拖拽是否改变左栏；隐藏资源栏是否错误销毁 Desktop 范围
标签；可访问性焦点和关闭后激活顺序是否确定。

### M2：Session 文件根与工作空间树

前置依赖：M1 已确认。

目标：建立受控 Session 文件访问链路，使主目录、附加目录和精确会话私有目录能在工作空间标签中浏览。

交付范围：

- 在 assistant-protocol 增加已确认的资源根、定位、目录项和有界预览 DTO，重新生成 TypeScript；不加入
  RuntimeCommand，不新增数据库字段；
- 在 assistant-runtime 增加只读根解析入口，在 Runtime Host 现有鉴权资源路由族实现目录列举、预览和
  仅供 Tauri 使用的原生路径解析；
- 完成规范化、canonical path 包含检查、符号链接越界、文件类型、读取上限、目录排序与截断；每次操作
  重新校验，不信任旧目录项；
- 扩展 NativeResourceBridge 调用上述路由，但不把会话私有物理路径或 Runtime token 传给 WebView；
- 完成工作空间标签的三个根、按需展开、刷新、隐藏/生成目录开关、错误与截断状态；
- 文件和目录图标直接复用 `material-icon-theme` 的文件名、扩展名、浅色配色及开合状态映射，未知
  类型使用该主题的通用文件图标，不复制维护上游映射；
- 在 ContextPanel 工作区卡片增加会话私有目录快捷入口，覆盖草稿、未绑定 Workspace 和已物化 Session。

验证入口：

```bash
cargo test -p assistant-protocol -p assistant-runtime -p assistant-runtime-host -p ez-assistant-desktop
cargo run -p assistant-protocol --example export_typescript -- --check
cargo clippy -p assistant-protocol -p assistant-runtime -p assistant-runtime-host \
  -p ez-assistant-desktop --all-targets --all-features -- -D warnings
cd apps/desktop
npm run test -- tests/unit/context-panel.test.tsx tests/unit/resource-workspace-store.test.ts \
  tests/unit/resource-workspace-tree.test.tsx
```

完成判定：三类根能按需浏览；未绑定 Workspace 的 Session 仍能打开私有根；路径上跳、越界链接、伪造
根、错误目录序号、资源删除和大目录都有确定结果；WebView 与公开 Session View 均看不到私有物理根。

Review 重点：Host 是否成为第二个 Session owner；是否把整段 Session 存储目录授权为私有根；目录列表
是否执行递归扫描；native-path 是否可能由网页或未授权调用方直接取得。

### M3：资源查看、面包屑与消息链接

前置依赖：M2 已确认。

目标：完成文本、Markdown、图片和显式 file URI 的查看闭环，并让 Agent 更稳定地交付可点击本地结果。

交付范围：

- 固定并按需加载 Monaco；按文件类型自动加载语法能力，实现只读文本/代码标签、查找、自动换行和
  模型释放，不提供语言选择或“转到行”；
- 复用 MarkdownContent 静态链路和消息样式实现 Markdown 标签，加入受控本地相对资源回调，并允许
  `http`/`https` 外链图片通过 CSP 正常加载；
- 实现有界图片标签和消息内图片，复用媒体校验与内存 URL，不创建磁盘缩略图或图片集合状态；
- 实现 ResourceHandleRegistry、显式 `file://` 解析、资源去重、系统应用打开、Finder 定位和统一右键/
  键盘菜单；覆盖 Workspace 外临时父目录范围，不扩大为整卷浏览；
- 实现 ResourceBreadcrumb：从获准根显示相对路径，前置目录以文字和方向箭头组成的单节点按需显示
  同级目录和文件，最后一级保留下拉但无箭头；右侧“更多”统一承载查看器动作和复制完整路径；
- 资源标签正文保留挂载，切换只控制可见性；面包屑跳转目录时展开根到目标的祖先链并复用目录缓存；
- 把文本、Markdown 和图片类附件与工具产物接入同一资源标签，不暴露物理路径；
- 在 HostSessionEnvironmentFactory 最终目录 Prompt Part 加入一次 `local_resource_presentation`，覆盖新建、
  clear 与 Fork，保持既有 Session 冻结，不增加协议或数据库迁移；
- 覆盖流式半截 URI、历史消息、空格/中文/保留字符编码、文件变化、超限、伪格式和本地资源失败。

验证入口：

```bash
cargo test -p assistant-runtime-host -p ez-assistant-desktop
cd apps/desktop
npm run test -- tests/unit/conversation-view.test.tsx tests/unit/resource-workspace-store.test.ts \
  tests/unit/resource-breadcrumb.test.tsx tests/unit/resource-viewer.test.tsx
npm run lint
npm run build
```

完成判定：文本/代码、Markdown 和图片均在带面包屑的资源标签中正确显示；同级菜单不越权；消息、附件、
工具资源和文件树入口按稳定身份去重；普通路径不自动链接；新建/clear/Fork Prompt 各只含一次 file URI
约定，旧 Session 不变。

Review 重点：原始 file URI 是否进入 DOM；外链图片 CSP 是否顺带放开脚本/连接；Monaco model、对象 URL
和请求是否在范围结束时释放；提示词是否诱导模型链接目录或未验证目标。

### M4：用户浏览器

前置依赖：M3 已确认；M0 child WebView 原型结论仍适用于当前依赖锁。

目标：在资源标签中提供用户直接操作的系统 WebView 浏览器，并证明它无法调用 Assistant 能力。

交付范围：

- 为固定 Tauri 2.11.5 启用 `unstable`，将 default capability 从窗口范围收紧为 Assistant 主 WebView；
- 实现 BrowserResourceManager 的创建、导航、固定后退/前进/停止脚本、边界、显隐、聚焦、标题、加载、
  新窗口、下载拒绝和关闭；所有命令再次校验调用方 label；
- 实现浏览器空白页、地址栏、工具栏、加载/失败状态、系统浏览器打开和多浏览器标签；
- 在标签切换、右栏折叠、窗口隐藏、resize、滚动和 Dialog/Popover 遮罩前后同步原生 WebView 边界；
- 使用恶意本地页面回归 capability 隔离，验证外部页面拿不到 `window.__TAURI__`、Runtime token、文件桥
  或终端桥；
- 记录常见页面、重定向、SPA、弹窗、下载拒绝、Cookie 重启和焦点的 macOS 实机结果。

验证入口：

```bash

cd apps/desktop
npm run test -- tests/unit/resource-workspace-store.test.ts tests/unit/resource-browser.test.ts
npm run build
npm run tauri -- build --no-bundle
```

完成判定：用户能完成基本网页操作并连续使用多个标签；原生页面不遮挡 Assistant 控件；关闭标签释放
WebView；恶意页面不能 invoke 或访问本地资源；浏览器未出现在 Agent Tool、MCP 或 Conversation 中。

Review 重点：`windows: ["main"]` 是否仍残留；是否存在接受动态脚本或任意 WebView label 的命令；失败
创建是否遗留原生句柄；隐藏/显示顺序是否造成原生层穿透。

2026-09-05 实施结果：macOS 原生页面、资源菜单、标签生命周期、下载拒绝与 IPC 隔离已验证；原生
`+` 菜单保持网页可见，其他 HTML 浮层仍临时隐藏页面。自定义透明 WebView 菜单未实现；具体网络/
证书错误受 Tauri 公开回调限制，只提供非阻断的慢加载提示，不根据超时隐藏网页。完整本地证据见 `docs/versions/v0.24.0/开发进度.md`。

### M5：用户终端

前置依赖：M4 已确认；M0 PTY 原型结论仍适用于当前依赖锁。

目标：在资源标签中提供用户直接操作的交互式终端，保持有界输出、后台运行和明确关闭语义。

交付范围：

- 固定引入 xterm.js、FitAddon、portable-pty 与 nix；不引入 Tauri Shell plugin、WebGL、WebLinks 或
  Shell Integration；
- 实现 UserTerminalManager：受控目录解析、默认登录 Shell、PTY 原始字节、单 writer、状态、自然退出、
  关闭和前台进程组信号升级；移除 Runtime/MCP/发布凭据；
