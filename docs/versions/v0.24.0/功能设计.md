## 二、背景与目标

当前 Desktop 右栏只展示会话上下文、Workspace、附件、技能、子任务和 Run 信息。Workspace 目录只能
交给系统文件管理器打开，附件和工具产物主要通过弹窗预览；用户无法在 Assistant 内连续查看与切换
这些资源。

本版把右栏升级为统一资源工作区，使用户在对话旁完成五类操作：

1. 保留并随时查看现有会话上下文。
2. 浏览当前会话冻结的 Workspace 目录和 Session 私有目录，在标签页中只读查看常用文件。
3. 在助手消息中直接打开 Agent 明确链接的本地文件，并按需显示本地图片预览。
4. 在标签页中打开一个由用户直接操作的网页浏览器，并保留常规网页登录状态。
5. 在当前工作空间中打开由用户直接操作的交互式终端。

资源工作区是 Desktop 的观察和操作界面，不成为 Session、Conversation 或 Run 的第二份权威状态。
浏览器和终端都属于用户资源，不向 Agent 暴露页面、PTY、输入或输出；需要 Agent 操作网页时继续
使用外部 Chrome + MCP，需要 Agent 执行命令时继续使用既有 Shell Tool。两条用户操作链路不成为
Agent 工具的旁路入口。

## 三、非目标

- 不让 Agent 接管、读取或截图资源栏中的浏览器页面。
- 不让 Agent 接管用户终端、向其中写入命令或读取终端输出。
- 不让内嵌浏览器与 Chrome MCP 共享标签、Cookie、登录状态或操作历史。
- 不替换 Tauri 在 macOS 上使用的 WKWebView，也不引入 Chromium、CEF 或自建浏览器驱动。
- 不提供 Workspace 文件编辑、保存、创建、删除、重命名、移动或上传。
- 不把消息中的普通文本、行内代码或疑似路径自动识别为本地文件；只有显式 Markdown 文件链接和
  图片链接参与资源解析。
- 不把 Session 的上级存储目录、Conversation JSONL、附件目录、工具图片目录、数据库或凭据作为
  “会话私有目录”的内容暴露给文件树。
- 不把文件标签、浏览历史、页面状态、终端输入输出或 PTY 状态写入 Runtime 会话数据库，也不随
  Session 在客户端之间同步。
- 不建设下载管理器、书签、浏览器扩展、开发者工具、广告过滤、密码管理或浏览器设置中心。
- 不在本版实现整个桌面或其他原生应用的 Computer Use。
- 不提供跨 Desktop 重启的终端会话恢复、后台脱离、跨 Desktop 重连、命令审计、Agent Shell 审批复用或终端协作共享；同一 Desktop 内切换会话后恢复原终端属于本版范围。

## 四、功能范围与使用路径

### 4.1 资源工作区外壳

- 右栏从固定“当前上下文”面板改为标签页式资源区。顶部直接显示标签栏，不再额外增加占用纵向空间
  的“资源”标题。首个固定标签为“当前上下文”，复用现有上下文内容和会话切换语义。
- “当前上下文”标签后显示独立的 `+` 按钮。点击后使用现有 DropdownMenu 风格打开资源类型菜单，
  首期固定提供“工作空间”“浏览器”和“终端”三项；按钮和菜单支持键盘操作、焦点恢复和清晰的
  可访问名称。
- 选择“工作空间”时，打开或聚焦当前 Session 的唯一工作空间标签，不重复创建相同文件树。已物化
  Session 即使没有绑定 Workspace，也可以通过其会话私有目录打开该标签；新会话草稿没有选择
  Workspace、Session 尚未创建且没有可用根，或资源不可用时，该菜单项禁用并说明原因。
- 选择“浏览器”时，每次创建一个新的独立浏览器标签，并聚焦其地址栏。浏览器标签允许并存；实际
  同时保留数量和后台资源回收策略在技术原型后确定。
- 选择“终端”时，每次创建一个新的独立终端标签，并聚焦终端输入。绑定 Workspace 的 Session 默认
  使用冻结的主目录；未绑定 Workspace 的已物化 Session 使用会话私有目录；新会话草稿使用当前所选
  Workspace 的主目录。三者均不可用时菜单项禁用。
- 附件、工具产物和具体文件不作为 `+` 菜单中的资源类型。它们分别从消息、工具详情、附件列表或
  工作空间文件树打开，并进入同一标签栏。
- “当前上下文”是固定入口，不显示关闭按钮；工作空间、浏览器、终端和具体资源标签可以关闭。
- 可关闭标签支持鼠标中键直接关闭；固定的“当前上下文”不响应中键关闭。
  关闭当前活动标签后优先回到其左侧最近标签，没有可选资源时回到“当前上下文”。
- 文件、附件、工具产物、浏览器页面和终端使用同一标签栏；活动标签正文占满右栏剩余区域。
- 右栏全部标签均归属当前 Session/草稿，包括工作空间、文件、附件、工具产物、浏览器和终端。切换
  会话时整组切换标签，切回时恢复原标签顺序、活动项和可恢复的查看状态，不能把其他会话的标签混入。
- 标签索引与页面缓存分开：轻量索引保留资源身份、顺序、活动项和恢复位置；页面结构按最近使用顺序
  有界缓存。超限只释放非活动页面结构及其重资源，不删除标签索引；再次打开时按索引重建。
- 终端不参与页面缓存淘汰，切换会话只隐藏原终端，PTY、xterm 和有界滚动缓冲继续保留。浏览器命中
  缓存时保留原页面；已淘汰时按最后 URL 重新加载，不承诺重建网页脚本内存、未提交表单或播放进度。
- `+` 按钮紧跟标签滚动区并始终保持可见。标签不参与 Flex 压缩；标签过多时标签区域横向滚动，鼠标
  纵向滚轮在该区域映射为横向滚动，不把标签压缩到无法辨认。
- 三栏分别保留自己的最小宽度：左栏不受中栏或右栏挤压，中栏保证消息正文、Composer 和会话操作
  可用，右栏保证资源标签和基本操作可用。最小宽度按已确认的实机调整取左栏 `220px`、中栏 `500px`、右栏 `320px`。
- 继续复用中栏与右栏之间的拖拽分隔线。拖拽只调整右栏宽度，不修改左栏宽度，也不把中栏宽度
  持久化为另一份状态；中栏使用剩余空间，并在达到自身最小宽度后阻止右栏继续向左扩展。
- 右栏不设置独立的固定最大宽度。它的动态上限等于窗口可用宽度减去当前左栏宽度和中栏最小宽度；
  浏览器或文件内容需要更大空间时，用户可以一直扩展到这一边界。
- 当窗口无法同时容纳三栏最小宽度时，沿用响应式折叠侧栏的思路，不能缩窄左栏、中栏或右栏来
  勉强显示。具体折叠优先级在界面交互设计中确认。
- 打开的标签、顺序和当前选择由 Desktop 按 Session/草稿分别持有；归属会话不等于进入 Agent 上下文，
  标签、浏览器和终端内容不自动发送给模型。轻量索引保存在现有桌面偏好文件，客户端重启后恢复
  会话/草稿标签、顺序、活动项和查看位置；不新增数据库。浏览器重新加载最后 URL，终端首次激活时
  从原启动来源新建 Shell，不恢复运行中命令、进程或输出。终端启动目录在创建时冻结。
- “当前上下文”的“工作区”卡片保留绑定状态、主目录和附加目录信息，并增加“会话私有目录”快捷
  入口。点击后打开或聚焦“工作空间”标签并选中该根；尚未物化的草稿显示“创建会话后可用”，不
  构造或泄露一个尚不存在的物理路径。

### 4.2 Workspace 与会话私有文件浏览

- “工作空间”标签以并列根节点展示当前 Session 创建时冻结的“主目录”、有序“附加目录”和
  “会话私有目录”；新会话草稿只展示当前 Workspace 配置，物化后切换到冻结快照并加入会话私有根。
- 从面包屑选择目录时聚焦工作空间标签，并自动展开该根到目标目录的完整祖先路径；已读取的目录内容
  直接复用，只有缺失目录才按需读取，用户显式刷新时才强制重新读取。
- 未绑定 Workspace 的已物化 Session 只显示“会话私有目录”，不把同一路径再次显示为主目录。
  界面说明它用于 Agent 在本会话中保存文件，并通过独立图标或副标题与用户 Workspace 区分。
- 本入口只加入 Session 范围的 `session_private_directory`；Workspace 范围的 Agent 私有目录不在本版
  文件树中展示，避免把两种不同生命周期的私有空间混在一起。
- 目录按需展开并可手动刷新；展示名称、类型和必要的文件状态，目录读取失败时在原位置提供重试。
- Workspace 目录访问使用“Session 标识 + 冻结目录序号 + 相对路径”，会话私有目录使用
  “Session 标识 + `session_private` 根类型 + 相对路径”。Desktop 原生层重新向 Runtime 获取权威
  Session 环境、解析物理根目录并检查最终路径仍位于该根下；WebView 不提交任意绝对路径，也不能
  从会话私有根向上遍历到 Session 存储目录。
- 默认忽略仓库内常见的大型生成目录和隐藏目录时，界面必须允许用户显式显示；具体默认列表与
  单次目录项上限在技术方案中依据真实仓库验证确定。
- 普通文本与代码文件使用 Monaco 或同类只读代码编辑器承载；按文件类型自动选择语法高亮，支持行号、
  文本选择与复制、查找、自动换行切换，并跟随右栏尺寸重新布局，不显示语言选择和“转到行”控件。
- Markdown 文件通过文本安全检查后进入只读 Markdown 渲染页，默认且仅展示渲染结果，不显示源码，
  也不创建 Monaco 模型或提供源码切换。渲染页复用消息列表现有的 Markdown 渲染器、插件能力和视觉
  样式，并按完整静态文档模式显示标题、列表、表格、引用、代码块、数学公式和 Mermaid 等已有能力；
  原始 HTML、脚本、内联事件和其他可执行内容继续按消息渲染器现有规则跳过。
- Markdown 文档中的 `http`/`https` 链接沿用受控外部打开流程，`http`/`https` 外链图片由 Markdown
  渲染器正常加载并在加载失败时显示可理解的占位。本地绝对或相对文件链接和图片不能直接成为
  WebView 的 `href` 或 `src`；当来源具有可解析的文件父目录时，由 Desktop 桥以该文档目录为基准
  解析相对目标并重新执行边界与文件检查。附件或工具资源没有可授权的相对文件基准时，保留链接
  文字并显示资源不可用，不猜测物理目录。
- 文本、Markdown 和图片等资源查看标签在标签栏下方统一显示路径面包屑和右侧“更多”菜单，再显示
  正文。面包屑以资源获准访问的根为起点；除最后一级外，目录文字和方向箭头组成同一个下拉节点，
  默认向右、菜单展开时向下，菜单列出该层级对应父目录中的同级目录和文件。最后一级仍以当前资源
  名称作为同级菜单触发器，但不渲染箭头。选择目录时打开或聚焦工作空间标签并定位该目录，选择可预览文件时打开或聚焦
  对应资源标签；菜单不得借由路径显示扩大已授权根。
- 查找、自动换行、刷新、图片尺寸切换、系统应用打开、Finder 定位和复制完整路径统一收进面包屑
  右侧“更多”菜单，不为不同查看器重复占用独立工具栏行。页面只显示根内相对路径，完整物理路径仅在
  用户选择“复制完整路径”时由 Desktop 原生层写入剪贴板。
- 通过媒体校验的独立图片可以创建轻量只读图片预览标签，保持宽高比并允许适应窗口、原始尺寸和
  系统应用打开；PDF 使用 WebView 原生阅读器显示。两者继续复用有界内存字节，不暴露物理路径。
  音视频、Office、压缩包、未知格式等其他二进制文件不创建资源查看标签，只提供文件信息、
  “使用系统应用打开”和“在目录中显示”。
- 文件类型不能只按扩展名判断：Desktop 需结合普通文件状态、读取上限、UTF-8/文本特征和 NUL 字节
  检查决定能否进入文本或 Markdown 查看器；扩展名用于识别 Markdown 或选择代码语言高亮。超过文本
  查看上限时不创建编辑器模型，也不渲染 Markdown 文档。
- 会话私有根中的 `permissions.json` 是现有权限控制文件。文件树可以只读显示并标记为系统配置，
  但本版不得提供修改入口，也不得绕过 Runtime 已有的结构化写入保护。
- 文件内容按打开或刷新时读取，不宣称与磁盘实时同步；磁盘变化后允许用户刷新。

### 4.3 消息中的文件与图片链接

- 首期增强当前 Conversation 中 Assistant 正文的显式绝对 `file://` Markdown URI：
  `[名称](file:///绝对路径)` 渲染为可点击文件链接，`![说明](file:///绝对路径)` 渲染为有界图片并可
  点击。用户消息继续使用现有纯文本、附件和引用结构，不因本功能整体切换为 Markdown 渲染。
- Runtime Host 构造冻结 System Context 时增加本地资源展示约定：当 Agent 已创建、读取或确认一个
  本地普通文件，并需要把它作为结果交给用户打开时，优先输出带可读名称的 Markdown `file://`
  链接；需要直接展示且已确认是受支持图片时，优先输出 Markdown 图片语法。该约定不要求把日志、
  命令参数、源码中的路径、目录或尚未创建的目标全部链接化。
- Agent 输出必须使用绝对、正确 URL 编码的 file URI，例如 `[报告](file:///absolute/report.md)` 或
  `![结果图](file:///absolute/result.png)`；不得仅输出裸 `file://`、相对路径或网络 authority，也不能
  声称未验证存在的路径可打开。链接只改善 Desktop 展示，不扩大 Agent 文件权限或替代工具校验。
- `file://` URI 正确处理 URL 编码、空格和非 ASCII 文件名，只接受空 authority 或 `localhost` 以及
  绝对本地路径；相对路径和网络文件 authority 首期不解释。历史 Assistant Message 使用相同渲染规则，
  文件仍存在即可恢复链接或图片，不要求 Runtime 重新投影或重新生成消息。
- 普通 `http`/`https` 链接继续沿用现有安全外部打开行为；本地文件链接进入右栏资源标签，不交给
  系统浏览器。Desktop Markdown 组件识别 `file://` 后调用 Tauri 原生资源桥，原始 URI 不进入 DOM
  `href`、`img src` 或 WKWebView 的本地文件加载链路。
- `file://` 文件和图片不限制在 Workspace 或 Session 私有目录内；只要当前操作系统用户可读取，文件
  操作通过普通文件校验，图片另通过签名、媒体类型、字节数、像素、边长和完整解码校验，就可以使用。
  这是 Desktop 的本地查看能力，不改变 Agent 文件工具的授权范围，也不让资源栏浏览器 WebView 获得
  本地文件权限。
- 图片桥接不预生成、缓存或持久化缩略图。原生层有界读取通过校验的图片，返回当前页面可展示的
  内存资源；消息内仅以 CSS 限制最大宽高并保留宽高比。若实机证明大图解码内存不可接受，再在技术
  方案中增加仅驻留内存的降采样，不引入缩略图目录或数据库状态。
- 流式生成阶段只显示尚未激活的占位，不读取 `file://`；完整图片 Markdown 节点形成后才调用 Desktop
  桥接，避免半截 URI 触发原生访问。每次重新加载、系统打开或 Finder 定位都重新检查文件状态。
- 文本、代码、Markdown 或通过校验的图片链接点击后打开或聚焦对应资源标签；消息内图片仍先显示
  内嵌预览，点击后进入图片资源标签。资源标签身份由 Desktop 使用规范化本地路径建立，仅用于当前
  客户端去重，不成为 Session、Conversation 或 Runtime 的持久业务身份。其他二进制文件链接不创建
  资源标签。
- 文本、代码、Markdown 和图片文件链接的右键菜单提供“在资源栏打开”“使用系统应用打开”和
  “在 Finder 中显示”；其他二进制文件保留“使用系统应用打开”和“在 Finder 中显示”。
  非 macOS 平台使用对应文件管理器文案。菜单动作由 Desktop 原生层重新解析 `file://` URI 并校验
  当前文件状态，不调用 Runtime Host。
- 右键事件只由已绑定的资源链接、图片和文件条目接管；消息普通文本、选区、代码块及普通 Web 链接
  继续使用现有 WebView 行为。聚焦资源后按 `Shift+F10` 或 Context Menu 键可打开同一菜单，菜单支持
  方向键、回车和 Escape，并在滚动、切换标签或点击外部时关闭。
- 资源不存在或不允许原生打开时保留菜单，但按当前能力禁用“使用系统应用打开”和“在 Finder 中显示”，
  不因右键动作绕过本地文件校验。菜单操作失败时在消息附近或资源标签中显示可恢复错误。
- 文本或代码文件链接可以携带行号定位；资源身份只绑定文件路径，行号作为打开后的可选定位信息。
  行号失效时仍打开文件并说明无法定位，不把带行号的字符串误当成另一个文件名；具体兼容语法在
  技术方案确定。Markdown 渲染页不解释代码行号定位。
- 文件被移动、删除、URI 无效或格式不支持时，保留链接文字、文件名和明确的不可用状态；刷新消息或资源
  标签后可以重新解析当前状态，不用相似文件或同名文件替代原目标。
- 本地链接的可点击能力只在传入 Desktop 本地文件处理器的 Conversation Assistant Message 中启用。
  System Context、Skill 说明、Conversation 搜索摘要和其他复用 `MarkdownContent` 的界面继续只接受
  既有安全 Web 链接；只有 Conversation Assistant 正文传入 Desktop 本地资源处理器。

### 4.4 附件与工具产物

- 会话附件继续使用现有稳定 Attachment 身份，工具产物继续使用 Conversation Owner、Message 和
  Resource Ref 身份，不把物理路径暴露给 WebView。
- 文本、代码、Markdown 或图片类附件与工具文件收敛为资源标签打开方式；从消息、附件列表或工具详情
  进入时聚焦同一资源，避免重复打开多个相同标签。Markdown 使用渲染页，图片使用轻量预览页，其他
  二进制类型不迁入资源标签。
- 附件、工具文件、消息资源、文件树条目和资源预览统一使用同一组动作及状态语义；只有通过文本判定
  或图片媒体校验的文件显示“在资源栏打开”，其他类型只显示可用的系统打开和目录定位动作。
- 继续沿用现有预览大小、媒体识别、缺失与损坏处理边界；若为了统一体验需要调整上限，必须在
  技术方案中给出内存和性能证据。

### 4.5 用户浏览器

- 用户可以新建一个或多个“浏览器”资源标签，输入 `http` 或 `https` 地址并在右栏直接浏览。
- 浏览器提供地址栏、后退、前进、刷新或停止、重新打开以及“在系统浏览器打开”等基本操作。
- 页面标题和当前地址更新到对应资源标签；加载中、导航失败、证书错误和进程异常都有明确状态。
- 浏览器使用 Tauri 在当前平台提供的系统 WebView；macOS 基线为 WKWebView。页面 Cookie、站点存储和
  登录状态由 Desktop 浏览器数据存储管理，应用重启后的保留行为需通过实机验收。
- 网页请求新窗口或弹出页面时，不静默获得新的应用权限；首版按技术方案确认的新标签或系统浏览器
  策略处理。非 `http`/`https` 协议必须经受控外部打开流程或拒绝。
- 浏览器标签关闭后释放对应 WebView；隐藏、切换、拖拽右栏和调整窗口时正确同步原生视图的显示、
  位置与大小，不遮挡 Composer、Dialog 或其他应用区域。
- 浏览器页面不显示“Agent 可操作”状态，不进入 `/mcp` 选择，不注册 MCP Server 或 Agent Tool。

### 4.6 用户可理解的两类浏览器

| 能力 | 资源栏浏览器 | Chrome MCP 浏览器 |
| --- | --- | --- |
| 操作者 | 用户 | Agent，经现有工具审批与记录 |
| 内核 | 当前平台系统 WebView；macOS 为 WKWebView | 本机 Chrome / Chromium |
| 页面位置 | Desktop 右侧资源标签 | Desktop 外部浏览器窗口 |
| 登录状态 | Desktop WebView 自有 | Chrome 对应 Profile |
| Agent 读取与操作 | 不支持 | 支持 MCP Server 已提供的操作 |
| 状态共享 | 不与 MCP 浏览器共享 | 不与资源栏浏览器共享 |

界面文案应让用户能区分这两类浏览器，避免把“在 Assistant 中打开”理解为“Agent 已获得页面权限”。

### 4.7 用户终端

- 每个终端标签对应一个由 Desktop 原生层管理的独立 PTY 和前台 Shell；不同终端不共享输入、终端
  输出、当前目录或进程状态。PTY 将 Shell 的标准输出和标准错误合并为同一终端字节流，本版不提供
  两者分栏或分类展示。
- 默认启动当前用户的系统登录 Shell；绑定 Workspace 的 Session 使用冻结主目录，未绑定 Workspace 的
  Session 使用会话私有目录，草稿使用所选 Workspace 主目录。工作目录只是启动位置，不是文件访问
  沙箱；终端命令以当前用户权限运行。
- 支持字符输入、终端输出、ANSI 颜色、滚动、文本选择、复制粘贴以及随右栏尺寸变化同步 PTY 行列数。
  Shell 退出（包括空命令行 Ctrl+D 或 exit）后自动关闭终端标签，不按退出码区分。启动、通信或清理
  失败时保留标签与错误，允许重试。Ctrl+D 交给终端处理，不直接作为关闭标签快捷键。
- 终端归属创建它的 Session/草稿，运行实例由 Desktop 持有。切换 Session 后不出现在新会话右栏，
  但原 PTY 和 xterm 继续运行；切回恢复同一终端。普通页面缓存淘汰、隐藏窗口或关闭到托盘不回收
  终端，也不改变其目录。删除所属 Session 前，界面显示该会话仍在运行的全部关联终端数量，确认后
  先关闭这些终端，再删除会话及该会话的其他资源标签。
- 关闭仍在运行的终端标签前明确提示将终止其中的 Shell 和 PTY 进程组；确认后先请求正常退出，超时
  后再升级终止信号。真正退出 Desktop 时必须先统一关闭所有用户终端，再允许应用进程退出；不把
  终端交给 Runtime 或后台任务系统继续持有。应用可以保证正常路径下回收其 PTY 进程组，但不能承诺
  在进程崩溃时回收已经通过 `nohup`、`setsid` 或守护化主动脱离的后代进程。
- 终端输入输出只在当前 Desktop 进程内流转，不追加到 Conversation、Run、调试事件或 Agent 上下文，
  不自动生成工具调用记录。
- Desktop 启动 PTY 时不得向子进程注入 Runtime Token、应用私有通信凭据或发布凭据。普通用户环境、
  登录 Shell 初始化和具体环境过滤边界由技术方案核查确定。
- 用户终端和 Agent Shell Tool 是两条独立路径：前者由用户直接输入且没有 Agent 审批，后者继续经过
  Runtime 的权限、审批、超时、取消和审计机制；界面不提供相互接管或“发送到 Agent”能力。
- 终端输出必须以有序、有界的数据流交给终端渲染器；消费跟不上时向 PTY 施加背压，不允许无限堆积
  内存或静默丢弃输出。原始 PTY 字节不得先经过有损字符串转换，避免破坏分块 UTF-8 和控制序列。

## 五、模块边界与契约影响

### 5.1 Desktop React UI

- 现有 `ContextPanel` 内容进入资源工作区的“上下文”标签，避免复制一份会话上下文投影。
- 新增的资源标签状态属于 Desktop Store 或等价的客户端状态；不从网页内容推断 Session、Run 或工具状态。
- `MarkdownContent` 增加可选的 Desktop 本地文件处理器，只在 Conversation Assistant 正文传入；
  自定义链接与图片组件识别 `file://` 并回调资源标签。URL Transform 只将
  `file://` 节点交给自定义组件，不能把其 href 或 src 直接交给 WebView。
- 资源链接组件负责左键、右键和键盘菜单入口；资源菜单作为可复用 Desktop 组件使用，不全局覆盖
  WebView `contextmenu`，也不影响现有消息文本选择、复制和引用操作。
- 文本与代码资源标签使用按需加载的 Monaco 或同类只读编辑器；每个打开文件使用独立模型，切换标签
  时保留当前滚动与光标位置，关闭标签或淘汰页面缓存时释放模型。查看器不提供编辑、保存、格式化、
  代码执行、语言服务器、诊断或补全。
- Markdown 资源标签复用现有 `MarkdownContent` 渲染链路、插件和样式，并增加完整文档所需的资源
  处理参数；使用静态模式，不复用 Conversation 的流式激活状态。组件只消费完成读取且通过文本上限
  检查的内容，继续跳过原始 HTML；`http`/`https` 外链图片正常加载，本地相对资源统一回调 Desktop
  资源桥，不把解析后的本地路径直接写入 DOM。
- 文本、Markdown 和图片资源标签复用一个 `ResourceBreadcrumb`；它只消费资源句柄携带的根身份与
  相对路径，并按需读取某一层的同级目录项。完整物理路径不进入面包屑、Runtime Session 投影或网页
  浏览器 WebView，只可由 Desktop 原生层响应显式复制、系统打开和 Finder 定位动作。
- 文件树只传稳定根身份和相对路径；会话私有根使用专用根类型，不接收或推导 Session 上级目录；
  浏览器正文由原生子 WebView 承载，不使用网页 `iframe`；终端
  使用按需加载的 xterm.js 或同类终端渲染器消费有界 PTY 原始字节，并随容器变化同步行列数，不把
  DOM 文本作为 Agent 可读上下文。

### 5.2 Desktop 原生层

- 增加 Desktop-local 的 `file://` 图片读取、文件预览、系统打开和 Finder 定位命令。命令自行完成 URI
  解码、普通文件与媒体校验、读取上限和错误映射；不通过 Runtime Host 获取文件字节或签发资源引用。
- 复用现有 `RuntimeBootstrapCoordinator` 获取权威 Session View；对会话私有根增加 Host-private 的
  受控解析入口，并在受控命令中完成根解析、路径包含检查、目录列举和有界文件读取。不得把完整
  Session 执行环境或物理 Session 上级目录加入公开协议投影。
- 管理用户浏览器 WebView 的创建、导航、显示、边界同步与销毁。外部网页不得收到 Runtime Token、
  Assistant 初始化脚本、文件桥接或其他 Tauri IPC 权限。
- 当前 capability 按主窗口授权的方式在多 WebView 场景下会覆盖该窗口内所有 WebView；实施前必须
  收紧为仅匹配 Assistant 主 WebView；资源栏中加载互联网网页的外部网页 WebView 不匹配任何
  capability，也不能调用终端、文件或 Runtime command。
- 管理用户终端 PTY 的创建、输入、尺寸、退出和 PTY 进程组回收；只接受 Desktop 生成的终端身份以及
  Runtime 重新解析出的 Workspace 或会话私有根，不接受网页或任意调用方提交 Shell 可执行路径和
  工作目录。终端输出通过面向单个终端的有序通道返回主 WebView，输入、调整尺寸和关闭使用受控命令；
  所有命令同时校验调用方为 Assistant 主 WebView。

### 5.3 Runtime 与应用协议

- Workspace 根目录权威事实继续来自现有 Session View 冻结快照；会话私有根继续来自 Runtime 已持有的
  `session_private_directory`，由 Host-private 查询按 Session 身份解析。首选不新增 Runtime 文件树、
  标签页、浏览器或终端实体，也不为可推导的私有目录新增数据库列。
- Assistant 正文的 `file://` 图片和文件链接保持原始 Markdown 文本，由 Desktop 当前客户端解释；
  Runtime、Host、Conversation 存储和应用协议不新增消息资源字段、解析入口或文件读取接口。现有
  Attachment 与 Tool Resource 的 Host 链路保持不变。
- 本地资源展示约定由 Runtime Host 的 Session Environment Factory 写入冻结 System Context，放在
  每个 Session 最后一个目录提示片段中，使新建、清空和 Fork 都能用当前目录生成同一份规则。现有
  Session 不被静默改写，只有新建、清空或 Fork 后获得该规则；不为此新增配置项、协议字段或数据库迁移。
- 若技术原型证明仅靠现有 Session View 无法安全解析资源，技术方案必须先说明缺口，再评估最小协议；
  不能为 UI 方便新增第二份 Workspace 状态或数据库表。

## 六、关键取舍

1. **资源工作区包含用户浏览器，但不包含浏览器 Agent 接管。** 这使网页查看成为可见的 Desktop 能力，
   同时保持 Playwright MCP 只控制 Chromium 的事实边界。
2. **使用原生子 WebView，不使用 `iframe`。** 普通网页常通过 CSP 或 `X-Frame-Options` 拒绝嵌入，
   `iframe` 无法构成通用浏览器。
3. **文件树访问保持身份化和只读。** 当前应用已通过稳定资源身份保护附件与工具产物；Workspace 与
   会话私有目录的文件树浏览延续同一原则。消息中的显式 `file://` 则由 Desktop 本地查看桥处理，
   两条路径不共用 Runtime 授权或资源身份。
4. **资源查看器承担文本阅读、Markdown 渲染、图片与 PDF 查看。** 普通文本和代码使用 Monaco 类只读组件；
   Markdown 默认且仅显示与消息列表一致的渲染结果，不提供源码视图；图片与 PDF 只复用已经完成媒体
   校验的有界字节，PDF 交给 WebView 原生阅读器。Office、音视频、压缩包等其他二进制文件交给系统应用。
5. **显式 `file://` 才成为消息资源。** 自动识别普通路径容易误把日志、代码和不存在路径变成操作入口；
   绝对本地 URI 表达了 Agent 的展示意图，Desktop 再按当前用户文件权限和有界媒体校验读取。该能力
   明确允许 Workspace 外文件，不借用或改变 Runtime 的 Agent 授权语义。
6. **标签状态由 Desktop 持有。** 标签只描述当前客户端正在看的内容，没有跨客户端业务一致性要求，
   不进入 Runtime 持久化。
7. **先验证 Tauri 多 WebView 再展开完整交互。** 当前使用的 Tauri 2.11.5 支持同窗口子 WebView，
   但创建入口依赖 `unstable` feature；技术方案阶段必须用最小原型验证 macOS 上的布局、焦点、
   Cookie 持久化、导航回调、视图销毁和 capability 隔离，再确认实现路径。
8. **用户终端使用独立 PTY，不复用 Agent Shell Tool。** Agent Shell 是 Runtime 工具调用能力，带有
   权限、审批和可靠记录；用户终端属于 Desktop 交互资源，生命周期跟随标签与 Desktop 进程。复用
   同一执行入口会混淆操作者、授权和状态所有权。
9. **终端按会话归属，由 Desktop 持有运行实例。** 启动目录在创建时冻结，切换 Session、普通页面
   缓存淘汰和隐藏窗口不应中断长任务；真正退出 Desktop、确认关闭标签或删除所属会话时才回收 PTY。正常退出只承诺终止 PTY 进程组，不对
   已主动脱离的守护进程作不真实保证。
10. **System Context 只强化结果交付，不强制链接所有路径。** Agent 在交付已存在文件或图片时优先使用
    Markdown file URI；普通技术说明、命令、源码和目录仍保留适合阅读的文本形式，避免回复被无效链接淹没。

## 七、验收标准

1. 右栏以资源标签形式工作，现有上下文信息无功能回退。
2. “当前上下文”后方的 `+` 菜单可以打开或聚焦唯一工作空间标签，并可连续新建独立浏览器和终端
   标签；菜单可用性按 Session 私有目录和 Workspace 根共同判断，附件和具体文件不出现在该类型菜单中。
3. 当前 Session 的主目录、附加目录及会话私有目录可按需浏览；“当前上下文”的快捷入口能直接定位
   会话私有根，未绑定 Workspace 的已物化 Session 仍可浏览该根。
4. 切换 Session 后右栏只显示新会话的资源，旧异步结果不能写入新会话；切回恢复原标签组、活动项和
   查看位置。触发页面缓存淘汰后仍能按保留索引恢复，终端实例不被淘汰。删除会话后不再读取其根目录；相对路径越界、符号链接越界、无效
   目录序号、伪造根类型和资源消失均被拒绝，并给出可恢复的界面状态。
5. 文本与代码文件使用 Monaco 或同类只读编辑器打开，按文件类型自动应用语法高亮，支持行号、选择
   复制、查找、自动换行和尺寸同步，不显示语言选择或“转到行”；关闭标签或淘汰页面缓存后模型正确释放，普通会话切换不直接丢弃索引。Markdown 文件默认且仅显示安全渲染
   页面，其表现、插件能力和样式与消息列表一致，`http`/`https` 外链图片可正常加载，原始 HTML 或
   脚本继续跳过；通过媒体校验的图片使用支持缩放、拖拽与查看位置恢复的只读预览，PDF 使用系统 WebView 阅读器；自有查看器均无编辑、保存、执行、补全或
   诊断入口。文本、Markdown、图片与 PDF 资源标签在正文上方显示根内路径面包屑和统一“更多”菜单；最后
   一级保留同级下拉但不显示箭头，各级节点均可显示同级目录与文件，并按资源根边界完成跳转。
6. Assistant 正文中的显式本地文本、代码、Markdown 或图片文件链接可点击并打开对应资源标签；文本
   和代码的可选行号能定位预览内容；`file://` 本地图片链接同时显示有界消息预览，含空格、
   URL 编码和非 ASCII 文件名可用。
   Workspace 外的有效本地图片同样可用；流式半截 URI 不触发文件读取，历史消息重新加载后遵循
   同一规则，且该链路不新增 Runtime Host 请求或协议字段。
7. 图片、PDF 之外的普通二进制文件不创建资源查看标签。文本、代码、Markdown、图片或 PDF 文件的右键菜单可以
   在资源栏打开、使用系统应用打开或在 Finder 中显示，其他类型只提供系统打开和 Finder
   定位；键盘入口可用，不可用动作正确禁用，普通消息区域的原生右键与文本选区不回退。
8. 普通文本、行内代码、相对路径、网络文件 URI、非图片内容和超限图片不会被当作可渲染本地图片；
   System Context、Skill 与搜索摘要中的相同 Markdown 也不会启用文件访问。
9. 同一文本、代码、Markdown、图片或 PDF 文件及对应附件或工具产物从不同入口打开时复用并聚焦同一资源
   标签；资源删除后显示不可用，不按文件名寻找替代内容。
10. 用户可以在资源栏浏览器完成地址输入、导航、前进后退、刷新和常规网页交互。
11. 登录一个测试站点后重启 Desktop，按设计约定验证登录状态保留；关闭浏览器标签不影响 Assistant
   主 WebView 和 Runtime 会话。
12. 浏览器页面无法调用 Assistant 的 Tauri command、读取 Runtime Token、访问 Workspace 文件或触发
   Agent 工具；只允许受控的网页导航与外部协议处理。
13. 浏览器标签切换、右栏拖拽、窗口缩放、Dialog 打开和应用隐藏恢复时，原生 WebView 不越界遮挡，
   焦点能够回到 Composer 和资源栏控件。
14. 资源栏浏览器不会出现在 Agent 工具列表、MCP 选择或 Conversation 中；Chrome MCP 原有流程不回退。
15. 用户可以在当前 Workspace 主目录或未绑定 Session 的会话私有目录新建多个独立终端，完成输入、
    输出、ANSI、选择、复制粘贴和尺寸同步；终端退出、重新启动、关闭确认和 Desktop 退出清理均符合设计。
16. 用户终端无法获得 Runtime Token 等应用私有凭据，输入输出不进入 Conversation、Run、Agent
    上下文或工具记录；Agent Shell Tool 的权限审批和记录行为不回退。
17. 切换 Session 或隐藏到托盘后，运行中的终端继续执行且启动目录不变；关闭终端或退出 Desktop 时
    正确回收 PTY 进程组。大量连续输出不会造成无界内存增长、乱序或静默丢失，中文和分块 UTF-8 正常。
18. 外部网页 WebView 无法调用终端命令；伪造终端身份、来源 Session、目录身份或 Shell 路径均被拒绝。
19. 左栏、中栏和右栏均不小于各自的最小宽度；拖动右侧分隔线只改变右栏宽度，左栏宽度不变，
    中栏只占用剩余空间。右栏不受独立固定最大宽度限制，但达到中栏最小宽度后不能继续扩大。
20. 窗口无法同时容纳三栏最小宽度时通过折叠侧栏恢复可用布局，不挤压任一区域；标准宽度和
    `720px` 窄窗口下无主区域水平滚动，并通过 macOS 原生应用实机验收。
21. 新建、清空或 Fork 后的 Session System Context 包含一次本地资源展示约定；Agent 交付已经确认
    存在的本地文件或图片时优先生成正确 URL 编码的 Markdown file URI，同时不会把普通路径说明、
    目录或不存在目标批量转换为链接。既有未重建 Session 的冻结 System Context 保持不变。

## 八、风险、兼容性与待确认项

- **Tauri 稳定性风险**：同窗口子 WebView 目前需要启用 Tauri `unstable` feature。技术方案必须先完成
  可丢弃原型；若关键行为不可靠，应回到设计阶段重新确认，而不是直接改成独立浏览器窗口冒充右栏标签。
- **安全风险**：现有 capability 使用窗口标签授权。多 WebView 前必须先改为主 WebView 精确授权，并用
  恶意测试页验证外部网页 WebView 无法访问 IPC。
- **私有目录边界风险**：Session 私有目录与附件、工具图片、Conversation 和其他持久化对象共享上级
  存储布局。实现只能解析并授权精确的 `private/` 根；目录上跳、符号链接越界和伪造 Session 身份必须
  拒绝，不能把整个 `data/sessions/<session-id>/` 当作文件树根。
- **Markdown 资源风险**：当前 Markdown 渲染器只允许 `http`/`https` 并把其他链接降级为文本。不能
  通过全局放开 `file://` 或让 `<img>` 直接读取本地路径实现本功能；只在 Conversation Assistant 正文
  启用自定义组件，并通过 Desktop 原生桥有界读取。该入口允许 Workspace 外图片，因此安全边界是
  “当前用户可读的本地图片”，不能在界面或文档中表述为 Workspace 沙箱。
- **右键菜单边界**：资源元素需要覆盖默认右键行为，但不能阻断消息正文选择和 v0.22.0 已有引用入口；
  浏览器子 WebView 内的网页右键属于网页自身，不复用本地文件资源菜单。
- **代码查看器成本**：Monaco 类组件会增加前端包体、Worker 配置和模型内存。技术方案必须验证 Vite
  分包与 Tauri CSP/Worker 路径，按需加载语言能力，在关闭标签和淘汰页面缓存时释放模型，并为超限
  文本提供不创建编辑器实例的回退状态。
- **Markdown 文档风险**：文件级 Markdown 默认渲染会引入文档内链接和图片解析。渲染器必须禁用原始
  HTML 与可执行内容；网络链接沿用受控外部打开，外链图片允许由 WebView 正常请求，本地相对资源
  必须基于来源资源身份由 Desktop 桥重新解析和校验，不能通过拼接 URI 绕过 Workspace、会话私有根
  或稳定资源边界。
- **原生布局风险**：React DOM 与原生 WebView 是两个渲染层，遮罩、Dialog、滚动、缩放和 Retina 坐标
  需要实机验证，不能只依赖浏览器组件测试。
- **动态宽度风险**：现有实现以 `800px` 作为右栏固定上限，本版需移除该独立上限，并让拖拽、偏好
  恢复和窗口响应式布局统一使用“窗口宽度减去当前左栏宽度和中栏最小宽度”的动态边界。右栏拖拽
  不能反向修改或挤压左栏；保存的大宽度在小窗口恢复时必须夹取或触发侧栏折叠，不能突破三栏最小值。
- **资源消耗风险**：每个浏览器标签可能对应一个 WebView。并发标签数量、后台页面暂停和内存回收策略
  由技术原型数据决定，不在功能设计中预设新的持久调度系统。
- **PTY 与进程风险**：当前项目没有交互式 PTY 或终端渲染器。技术方案必须核查最小依赖、macOS
  Shell 启动方式、流量背压、输出内存上限、尺寸同步、Unicode、PTY 进程组终止和应用异常退出边界；
  还需把终端清理接入 Desktop 现有“退出客户端”和“退出并停止 Runtime”两条路径，不能让当前
  `app.exit` 绕过清理，也不能把现有一次性 Agent Shell Adapter 直接当成交互式终端。
- **网站兼容性**：WKWebView 与 Chrome 的站点兼容、扩展和登录策略不同。验收只承诺常规 `http`/`https`
  浏览，不承诺所有网站、Chrome 扩展或企业身份系统均可用。
- **平台范围**：本版以 macOS 当前正式平台为完整验收基线；其他平台在技术方案中说明编译与降级边界。
- **实现门禁**：子 WebView、文件根、资源句柄、Monaco、Markdown、图片、PTY、流式背压和终止策略已在
  技术方案中确定。开发先执行可丢弃的平台原型；若实测与方案关键假设不符，必须停止实现并回到设计
  阶段重新确认。

本设计已于 2026-09-04 获得用户确认；技术方案与界面交互设计指导也已确认，开发计划另行确认。
