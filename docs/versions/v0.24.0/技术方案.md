### 2.2 最小新增判断

需要新增的对象都有独立生命周期或边界：

- `ResourceWorkspaceStore`：跨 Context、Conversation、附件和文件树协调当前 Desktop 的资源标签。
- `TerminalController`：在前端持有单个 xterm 实例、输出订阅与 ack，生命周期独立于当前可见的
  React 标签正文。
- `BrowserResourceManager`：持有原生子 WebView 句柄，生命周期独立于 React 节点。
- `UserTerminalManager`：持有 PTY、Shell 和流控状态，生命周期独立于 Runtime Session。
- `SessionResourceRoot` 与 `SessionResourceLocator`：跨 Desktop/Host 表达根身份和相对路径，避免传输
  会话私有物理路径。

不新增资源数据库、独立标签存储、文件索引、通用文件服务器、浏览器进程、终端服务进程、动态
capability 或资源 revision。上述状态只有单一 Desktop owner，顺序命令和明确终态已经足够。

## 三、目标架构与状态所有权

```text
Assistant 主 WebView
  ├─ ResourceWorkspaceStore
  │   ├─ 按 Session/草稿分组：上下文 / 工作空间 / 文件 / 浏览器 / 终端
  │   └─ 非终端页面：有界 LRU；终端实例：独立保留
  ├─ MarkdownContent / Monaco
  ├─ TerminalController ──> xterm.js
  └─ native-bridge
          |
          | Tauri command + Channel（仅 main WebView）
          v
Desktop 原生层
  ├─ NativeResourceBridge ── bearer HTTP ──> Runtime Host resource routes
  ├─ BrowserResourceManager ──> 同窗口外部网页 WKWebView
  └─ UserTerminalManager ──> portable-pty ──> 用户登录 Shell

Runtime Host resource routes
  ├─ AssistantRuntime 解析 Session 根身份
  └─ Host 执行目录列举、规范路径检查和有界读取
```

- Runtime 继续持有 Session 执行环境和 Workspace 冻结关系的权威事实。
- Host 负责受控文件系统 I/O，不保存标签、编辑器、浏览器或终端状态。
- Tauri 原生层持有操作系统资源句柄和当前进程内的短生命周期资源身份。
- React Store 持有用户正在查看的标签、顺序、选择和加载状态，不复制 Session/Run 权威状态。
- 浏览器和终端不会注册为 Agent Tool，也不会进入 Runtime 事件、Conversation 或调试事件。

## 五、资源工作区前端方案

### 5.1 Store 与标签模型

新增 `features/resource-workspace`，其中 `ResourceWorkspaceStore` 由 RootStore 显式装配。标签使用穷尽联合：

```ts
type ResourceTab =
  | { type: "context" }
  | { type: "workspace"; scopeKey: ResourceScopeKey }
  | { type: "text"; resource: ResourceHandle; line: number | null }
  | { type: "markdown"; resource: ResourceHandle }
  | { type: "image"; resource: ResourceHandle }
  | { type: "pdf"; resource: ResourceHandle }
  | { type: "browser"; browserId: string }
  | { type: "terminal"; terminalId: string };
```

- `context` 永远存在且排在第一位。
- `workspace` 在当前 Session/草稿范围内唯一。
- `text`、`markdown`、`image`、`pdf` 用原生层返回的稳定 `resourceKey` 去重；行号只是打开意图，不进入身份。
- 标签逻辑 ID 由 Desktop 主界面分配；原生 WebView/PTY 句柄由原生层创建后返回。页面淘汰不删除
  逻辑标签 ID，重建浏览器时重新取得原生句柄；外部网页不能指定或操作这些身份。
- 每个终端标签对应一个由 `ResourceWorkspaceStore` 持有的 `TerminalController`；React 正文只负责
  挂载可见容器，不能以组件卸载作为取消输出订阅或销毁 xterm 的信号。
- `ResourceWorkspaceStore` 复用 `ResourceScopeKey` 按 Session/草稿保存标签组、顺序、活动项、焦点和轻量
  恢复状态。导航只选择当前 owner，不再调用清空旧 Session 标签的流程；标签去重限定在该 owner 内。
- 新建浏览器、终端及网页弹出的新标签绑定发起时的 owner；异步创建/导航回调不能借“当前会话”改变
  归属。切换后的迟到文件响应只允许写回原 owner 的有效缓存，不得污染新会话或重新挂载已淘汰页面。
- 草稿沿用现有 draft key 隔离；首次物化 Session 时将该草稿标签组一次性转移到新 Session ID，保持
  标签顺序和活跃终端，不重新创建进程，也不把后续新草稿与历史会话共用同一组标签。
- 标签索引常驻当前 Desktop 的内存，只保存稳定资源身份、标签标题/顺序、当前活动项、目录展开/过滤、
  查看位置及浏览器最后 URL；不保存文件正文、DOM、Blob URL、网页脚本状态或终端输出副本。
- 2026-09-05 用户补充授权：右栏轻量 snapshot 写入现有 `desktop-preferences.json`，恢复会话/草稿归属、
  标签顺序/活动项、资源身份、浏览器最后 URL 和可序列化查看状态；不写入 Runtime，也不保存正文、
  网页 DOM/表单、终端输出或旧进程句柄。真正重启后浏览器重新加载，终端在首次激活时从原启动来源新建 Shell。
- 快照复用现有偏好保存入口，合并延迟写入并在受控退出前 flush；恢复完成前不以空工作区覆盖已有快照。
  本地文件重新注册并校验访问，已不存在或无权访问的本地文件跳过并汇总提示；其余标签继续恢复。
  快照限定 4 MiB、256 组、每组 256 标签/合计 2048 标签；空历史组不保存。损坏状态拒绝恢复并提示，
  超限保存不会覆盖上一次成功快照。保存通过原子替换完成，文件权限为当前用户读写。
- 窗口操作使用 `get_window("main")`；加入 child WebView 后不再依赖只适用于单 WebView 窗口的
  `get_webview_window`。关闭依照既有 `hide_to_tray` / `quit_desktop` 设置处理，资源不阻止隐藏。
- 查看状态随交互合并保存；受控退出在清理终端前等待快照保存，异常强杀最多恢复最后一次成功保存。

#### 5.1.1 页面缓存与终端例外

- 非终端页面结构采用一个 Desktop 级 LRU，上限初始设为 **20 个页面实例（包含当前活动页）**，跨会话
  共用预算；工作空间、文件/Markdown/图片/PDF 查看器与浏览器 WebView 都计入。“当前上下文”按当前
  Session 投影，不复制历史实例。采用数量预算，不把它等同于精确的进程内存字节上限。
- 切换标签/会话时先保存原页的轻量查看状态。命中缓存时复用原实例；未命中时先淘汰最久未使用的非
  活动页，再创建目标页。当前活动页不能被淘汰；后台加载完成不能自动挤入缓存或抢占前台。
- 淘汰文件类页面时使其待完成请求失效、卸载 React 正文、释放 Monaco model、解码图片/PDF 与对象 URL，
  只保留索引；恢复后重新按原资源身份校验与读取，再恢复展开项、行号/滚动和换行等状态。资源已消失
  时保留标签并显示不可用，不能按同名文件替换。已发送的原生 IPC 读取允许完成，但结果不能写回失效页面。
  原生 PDF 阅读器未暴露页码/缩放状态；缓存命中复用原实例，淘汰后从初始阅读位置重新加载。
- 淘汰浏览器时保留最后合法 URL/标题并关闭对应原生 WebView。返回该标签时重新创建 WebView 并导航；
  Cookie/站点存储继续由现有平台数据存储管理，不复制网页 DOM、表单或 JS 堆，也不承诺恢复这些瞬态
  状态和完整前进后退栈。未淘汰浏览器则保持原页面及历史。
- 终端不计入 20 页预算，也不因 LRU 淘汰而 dispose：原 PTY、TerminalController、xterm 与最多 5,000
  行 scrollback 均保留，后台继续 write/ack。只移动或显隐原容器；不新增终端快照、第二份输出缓存或
  用新 Shell 冒充同一客户端运行期内的恢复。跨客户端重启仅恢复终端标签及启动来源，首次激活才
  创建新 Shell，明确不恢复退出前的进程、工作目录变化或命令执行。
- 关闭标签会同时删除其索引和实例；删除 Session 清理该 owner 的全部资源；普通导航不等于删除。
  真正退出 Desktop 仍统一清理所有 owner 下的原生句柄。

`NavigationStore` 继续只负责应用导航和侧栏布局。标签行为进入新的 Store，避免把资源生命周期继续
塞入 NavigationStore。

### 5.2 三栏尺寸

- 左栏保持最小 `220px`、默认 `286px`、固定最大 `420px`。
- 中栏保持最小 `500px`。
- 右栏最小调整为 `320px`、默认 `380px`，不设置固定最大值。
- `right_sidebar_current_max_width = viewport - effectiveLeftWidth - CONVERSATION_MIN_WIDTH`；结果不足
  `320px` 时沿用 `responsive_priority` 折叠一侧栏。
- 拖拽和键盘调整仍复用 `SidebarResizeHandle`；右侧 `End` 使用动态上限，偏好恢复时按当前窗口夹取。
- 浏览器 child WebView 的边界由资源正文 DOM `getBoundingClientRect()` 产生逻辑像素，使用
  `requestAnimationFrame` 合并后交给原生层 `set_bounds`。隐藏标签、Dialog、右栏折叠和窗口隐藏时先
  `hide`，恢复边界后再 `show`。

## 六、文件资源与 Markdown 方案

### 6.1 根身份和 Host 路由

在 `assistant-protocol` 增加轻量资源定位类型，不加入 `RuntimeCommand`：

```rust
enum SessionResourceRoot {
    WorkspacePrimary,
    WorkspaceAdditional { directory_index: u32 },
    SessionPrivate,
}

struct SessionResourceLocator {
    root: SessionResourceRoot,
    relative_path: String,
}
```

Host 在现有 `/sessions/{session_id}/...` 资源路由族增加：

- `POST /sessions/{session_id}/resource-files/list`
- `POST /sessions/{session_id}/resource-files/preview`
- `POST /sessions/{session_id}/resource-files/native-path`

前两个返回 `assistant-protocol` 的目录项或有界预览 DTO；`native-path` 只由 Tauri
`NativeResourceBridge` 调用，物理路径不转发给 WebView。三者继续使用现有 bearer token 中间件。

Runtime 新增一个窄的只读根解析方法，根据 Session 当前环境解析主目录、附加目录序号或精确
`session_private_directory`。Host 在执行 I/O 前：

1. 规范化相对路径，拒绝绝对路径、空字节和 `..` 上跳。
2. `canonicalize` 根与目标，并验证目标仍位于根下。
3. 使用 `symlink_metadata` 区分普通文件、目录和符号链接；链接目标越界时返回不可访问条目。
4. 目录只读取一层，目录优先、名称稳定排序，单次最多返回 2,000 项并标记 `truncated`。
5. 每次展开、刷新、预览、系统打开和 Finder 定位都重新验证，不信任旧目录项。

该路径不新增数据库和文件索引。Session 删除继续由现有 Store 删除资源目录；Desktop 在确认删除前先
清理归属该 Session 的全部终端，再释放该会话的资源标签。

### 6.2 本地文件句柄

Tauri 原生层使用进程内 `ResourceHandleRegistry` 保存 `resourceKey -> canonical path/source`：

- Workspace/Session 私有文件由 Host `native-path` 解析后登记。
- 消息中的绝对 `file://` 由 Tauri 完成 authority、URL decode、绝对路径和普通文件检查后登记。
- 附件与工具资源沿用稳定协议身份；需要统一打开时通过现有 native-path 路由登记。
- 相同 canonical path 返回相同 `resourceKey`；若同一文件从不同入口登记，Registry 为该 key 累加已经
  核验的 navigation scope，并优先选用 Session Workspace/私有根生成面包屑，其次才是临时本地父目录。
  句柄只在当前 Desktop 进程内有效，不写入消息或数据库。
- WebView 只提交 `resourceKey` 或稳定协议资源身份，不能把任意路径交给预览、系统打开或 Finder 命令。

每个句柄还保存不可变的 `navigationScope` 与该范围内的相对路径，用于路径面包屑：

- Workspace 与 Session 私有文件沿用 `SessionResourceRoot`，可在该根内逐层列举。
- Attachment 与 Tool Resource 使用各自稳定集合身份；面包屑显示逻辑集合和资源名，同级菜单只列举
  当前 Session、Conversation 或 Message 已公开的同类资源。
- Workspace 外的显式 `file://` 文件以其 canonical 父目录建立临时本地目录范围；面包屑从该获准
  父目录开始，不显示更高物理路径。获准父目录可以列举直接同级项，
  不把单文件点击升级成整卷文件系统浏览。

显式 `file://` 允许 Workspace 外文件，因为这是当前用户主动查看的 Desktop 能力；Session 文件树仍受
根身份约束，两种来源不会混用授权规则。

### 6.3 类型判定与上限

- 文本/代码/Markdown 最大读取量统一为 4 MiB；超过上限返回 `resource_too_large`，不创建查看器。
- 必须是普通文件；拒绝设备、socket、FIFO 和最终越界的符号链接。
- 读取后拒绝 NUL 字节和无效 UTF-8；扩展名只决定 Markdown 分流或 Monaco language id。
- Markdown 扩展名首版接受 `.md`、`.markdown`、`.mdown`、`.mkd`；内容检查失败仍按二进制处理。
- 本地图片最大 16 MiB、最大边长 16,384、最大 40 MP；使用 magic bytes、完整解码和尺寸共同校验。
- 图片只返回内存 data/blob 所需字节，不生成磁盘缩略图或缓存目录；关闭对应消息或资源标签范围时
  回收对象 URL。

### 6.4 路径面包屑与同级菜单

文本、Markdown、图片和 PDF 标签共用 `ResourceBreadcrumb`，固定在标签栏下方并与右侧资源“更多”菜单
处于同一行：

- 面包屑由 `navigationScope + relativePath` 生成，不接受组件自行拆解任意物理路径。
- 除最后一级外，目录文本与箭头组成一个下拉触发节点，关闭时箭头向右、展开时向下；最后一级仍以
  当前资源名称作为同级菜单触发器，但不渲染箭头。
- 每个前置目录节点的下拉按钮按需调用现有一层目录 `list` 路由，查询该路径段父目录，复用文件树缓存、
  排序、隐藏项偏好和 2,000 项截断语义，不新增递归扫描或索引接口。
- 下拉中目录优先、文件随后，当前项有选中标记；目录选择后定位 Workspace，文本、Markdown、图片或 PDF
  选择后按 `resourceKey` 打开或聚焦相应标签，其他二进制项可见但禁用内置预览。
- Workspace 收到目录定位后生成根到目标目录的定位链，合并进现有展开集合，并只请求尚未缓存的目录；
  重复定位同一路径也会重新展开被用户收起的祖先节点，但不会因此清空或重复初始化目录缓存。
- 请求返回后校验当前 scope 与路径；切换 Session、关闭标签或路径失效时丢弃旧结果。面包屑菜单本身
  不持有文件内容，也不把物理路径写入 DOM 属性。

### 6.5 查看器

- 普通文本/代码使用 Monaco readOnly model，关闭 minimap、诊断、补全、格式化和编辑入口；语言由
  文件类型自动确定，不渲染语言选择和“转到行”。保留查找、自动换行、复制、行号和语法高亮，查找
  与自动换行和其他资源动作一起进入面包屑右侧“更多”菜单。Model URI 使用资源稳定身份而不是文件名，
  同时打开不同目录中的同名文件时必须保持独立。直接加载 Monaco 官方语言注册表，由 Monaco 根据
  Model URI 的文件名确定 language id；只有官方注册表无法识别的文件才使用纯文本。
- Markdown 文件复用 `MarkdownContent` 的 Streamdown 2.5.0 渲染链路与样式，使用 `mode="static"`，
  保留现有代码、数学和 Mermaid 插件，继续 `skipHtml`。
- Markdown 文档的 `http`/`https` 图片由 WebView 正常加载；CSP 的 `img-src` 增加 `http:`、`https:`。
- Markdown 本地绝对/相对资源由自定义组件回调资源桥。相对路径以当前 Markdown 文件的已验证父目录
  为基准并再次检查来源边界；没有可授权父目录的附件/工具资源显示不可用，不猜测目录。
- 原始本地 URI 不写入 DOM `href`/`src`。网络链接继续调用 `openExternalHttpUrl`。
- 图片资源标签复用 6.3 的媒体检查与内存 URL；直接引用 `react-zoom-pan-pinch 4.2.0`（MIT），由组件提供缩放、拖拽、初始适配、边界和尺寸变化处理，不自建手势引擎。解码获得自然尺寸后挂载查看器，隐藏缓存页禁用交互和尺寸对齐。
- 图片缩放比例与平移坐标存入现有 `ResourceViewState.preview.image`，沿用页面 LRU 和桌面偏好快照恢复；关闭/淘汰时释放 Blob URL。操作集中在资源“更多”菜单，不提供编辑、缩略图生成、EXIF 修改或图片集合轮播。
- PDF 通过文件签名与 16 MiB 上限检查后复用有界 base64 预览 DTO；Desktop 将其转换为生命周期受控的
  Blob URL，并由 WebView 原生 PDF 阅读器显示。CSP 仅向 Blob URL 开放 `frame-src`，不开放任意网络 frame。
- Session 文件、本地句柄、附件和工具产物分别由 Desktop 原生命令解析完整路径并写入系统剪贴板；
  WebView 只提交稳定资源身份，不自行拼接或接收真实路径。

### 6.6 System Context 的 file URI 输出约定

修改 `apps/runtime-host/src/resources/environment.rs::render_directory_prompt`，在同一个最终 Prompt Part
中追加固定英文指令，使 Fork 现有的“移除最后一个目录片段再重建”语义继续成立：

```text
<local_resource_presentation>
When presenting an existing local file for the user to open, prefer a descriptive Markdown link
whose destination is an absolute, percent-encoded file URI. When an existing supported image is
useful to show directly, prefer Markdown image syntax with that file URI. Only link paths you have
created, read, or otherwise verified. Keep directory paths, command arguments, source-code paths,
and unverified targets as ordinary text unless the user explicitly asks for a link.
</local_resource_presentation>
```

- 文件使用 `[可读名称](file:///absolute/encoded/path)`，直接展示的图片使用
  `![替代文字](file:///absolute/encoded/path)`；不鼓励裸 URI。
- 指令只约束最终内容的展示格式，不改变 File Tool、Shell、权限审批、可访问根或 Desktop 校验。
- 指令固定加入 Host 产品 System Context，不放进用户 Persona、Workspace `AGENTS.md` 或 Desktop 临时
  消息，也不新增用户开关。
- System Prompt 继续是 Session 冻结事实：新建和 clear 会重新生成，Fork 替换来源最后一个目录片段后
  获得当前版本规则；已存在且未重建的 Session 保留原 Prompt。
- Prompt Part 仍计入现有 `MAX_SYSTEM_CONTEXT_BYTES`，新增文本远低于上限；构造失败沿用现有原子失败语义。

## 七、用户浏览器方案

### 7.1 原生 Manager

`BrowserResourceManager` 作为 Tauri managed state 保存：

```text
BrowserId -> Webview handle（原生视图持有网站状态和边界；回调持有 event Channel）
```

创建命令只接受经过 URL parser 验证的 `http`/`https` URL；空地址先创建 UI 标签，用户提交地址后再创建
child WebView。WebView label 使用原生层生成的 `resource-browser-<pid>-<counter>`。

命令范围：创建、导航、后退、前进、刷新、停止、设置边界与显隐、聚焦、关闭。原生回调把加载、URL、
标题、导航拒绝、弹窗请求和下载拒绝状态通过该浏览器专属 Channel 发送给主 WebView。
前端 `BrowserController` 只保留展示投影并串行发送意图；关闭过程中等待尚未完成的创建并释放句柄。
活动标签通过原生 URL getter 同步 SPA/history 路由，不读取页面正文，也不注入路由监听脚本。
URL 查询的成功与失败都须核对原生页面实例及查询有效性；导航、原生页面事件、回收或后续查询使旧查询
失效。提交新地址后，在收到原生页面事件前暂停查询，避免原生 getter 暂时返回上一页地址而覆盖新目标。

macOS WKWebView 默认 UA 缺少 `Version/… Safari/…`，部分站点会误判为过旧浏览器。读取已安装 Safari
的版本补充兼容标记；读取失败或非 macOS 平台保留系统默认 UA，不提供任意 UA 配置。

Tauri 2.11.5 没有跨平台的公开后退、前进和停止方法。首版只执行三段固定且无动态插值的脚本：
`history.back()`、`history.forward()`、`window.stop()`；不得借该入口读取页面 DOM、Cookie 或正文。
技术原型若证明目标平台执行不可靠，必须回到功能设计确认降级，不能引入违反 `unsafe_code = forbid`
的 WKWebView 私有调用。

### 7.2 导航、弹窗与下载

- `on_navigation` 只作 `http`/`https` 许可检查；其他协议拒绝并向主界面报告。该回调也包含 iframe
  等子框架跳转，不得据此更新地址栏或整页加载状态；页面加载状态由 `on_page_load` 的 Started/Finished
  事件驱动，SPA/history 地址同步继续查询原生主页面 URL。
- `on_new_window` 对 `http`/`https` 向主界面发送新浏览器标签请求并拒绝原弹窗；其他协议拒绝。
- 首版 `on_download` 返回拒绝，界面提示使用系统浏览器打开被拒绝的 HTTP/HTTPS 下载 URL；该 URL
  随提示保留，不随地址栏同步变化，不建立下载目录和下载状态机。
- `on_document_title_changed` 只作为标签标题候选，移除控制字符并限制长度。
- 浏览器标签共享 Desktop WebView 的默认网站数据存储；Cookie 重启持久化以原型和实机结果为准。
- 关闭标签调用 `Webview::close` 并从 Manager 移除；任何后续旧命令返回 `browser_not_found`。
- 地址校验和系统浏览器打开失败复用非阻断提示，不改变当前网页、目标 URL 或加载状态；无效地址保留
  在输入框中供用户修正。页面创建、原生页面操作及当前实例查询失败才进入可重试的错误态。
- Tauri 2.11.5 公开 API 没有 WKWebView 的具体加载失败回调；超过 30 秒未完成只结束进度动画，
  在工具条下显示可关闭的“网页加载较慢，可继续浏览或重试”提示与重试/系统打开入口。超时不是加载
  失败的事实，不得设置阻断错误、隐藏原生页面或停止网络加载；迟到的 Finished 自动清除慢加载提示。
  真正创建/原生操作失败仍显示错误与重试，不推断 DNS、证书或服务器错误，不绕过证书校验。

### 7.3 原生与 HTML 层级

- DOM 正文矩形通过主 WebView 实际尺寸与 DOM 视口差转换为原生边界，包含 macOS 标题栏安全区域；
  不硬编码标题栏 padding。原生变更在 UI 线程串行执行，调用平台 API 时不持有 Manager 状态锁。
- 资源 `+` 使用 Tauri 原生菜单，打开时网页继续显示。菜单外观由平台决定，不能直接复用 SCSS；
  自定义透明 WebView 浮层尚未实现，需另行验证定位、焦点和事件隔离。
- 其他 HTML Dialog/Popover 仍通过 Shell 显式提供的 portal 协调：先隐藏原生页面再绘制浮层，关闭后
  按最新边界恢复。它们尚不具备“保留实时网页同时覆盖”的能力。

### 7.4 capability 隔离

`capabilities/default.json` 改为只匹配 `webviews: ["main"]`，不再使用 `windows: ["main"]`。所有新增
Tauri command 还接收调用方 `Webview` 并校验 label 为 `main`，形成配置和实现两道边界。

外部网页 WebView 不注入 Runtime bootstrap、Assistant 初始化脚本、文件桥或终端桥。恶意测试页必须
验证 `window.__TAURI__` 不可用，无法 invoke、读取本地资源或获得 Runtime token。

## 八、用户终端方案

### 8.1 PTY 与 Shell

`UserTerminalManager` 作为 Tauri managed state 保存每个终端的 PTY master、writer、child killer、
启动目录、来源 Session、状态、取消令牌和输出 Channel。

创建流程：

1. 主 WebView 提交 Session 根身份（草稿提交已选择的 Workspace ID）、初始 cols/rows 和 Channel。
2. Tauri 经 Host native-path 或现有 Workspace 查询解析启动目录，不接受 Shell 路径或任意 cwd；解析最多等待 10 秒。
3. `portable_pty::native_pty_system().openpty(PtySize)` 创建 PTY。
4. `CommandBuilder::new_default_prog()` 启动当前用户登录 Shell，设置 cwd。
5. 继承普通用户环境，显式设置 `TERM=xterm-256color`、`COLORTERM=truecolor`、
   `TERM_PROGRAM=ez-assistant`，移除 Runtime token、MCP token 和发布凭据。

PTY 把 stdout/stderr 合并为一个原始字节流。读取使用专用阻塞线程，不能占用 Tokio async worker；
child wait 使用独立阻塞任务，退出后发送最终状态，由标签 owner 回收终端并关闭标签。Unix master 使用 `nix::fcntl`
设置非阻塞 I/O，reader/writer 遇到 WouldBlock 以 10 ms 步长检查取消；不引入 unsafe fd 包装。
当前实现与实机验收以 macOS 为准；Windows 尚未接入可取消 I/O，明确返回不支持，不宣称跨平台已验收。

### 8.2 双向流与背压

- PTY 每次最多读取 32 KiB，通过容量为 1 的有界队列交给 Channel forwarder。
- forwarder 同一时间只发送一个未确认块；前端在 `terminal.write(bytes, callback)` 完成后调用 ack，
  然后才发送下一块。无需新增 sequence/revision，也不会无界堆积或静默丢失。
- `TerminalController` 在终端标签创建后立即订阅 Channel，并在标签未激活、右栏折叠或窗口隐藏时
  继续把输出写入 xterm 缓冲并回传 ack；切换标签不能暂停 PTY 或阻塞子进程。可见正文只挂载或显示
  对应终端容器，恢复显示后执行一次 fit。只有关闭标签、主 WebView reload 或 Desktop 退出才 dispose。
- xterm `onData` 输入以最多 8 ms 合并，单次最多 16 KiB；控制字符在当前批次立即 flush。
- 粘贴分块写入，同样受 16 KiB 上限；原生 writer 由单一 mutex 串行持有。前端待发送输入最多 1 MiB，
  超出时整次拒绝新输入并明确提示分段粘贴，不截断当前批次；启动中的输入暂存到创建完成后发送。
- FitAddon 配合 `ResizeObserver`，尺寸变化 50 ms 合并，拖拽结束发送最终 cols/rows；无变化不调用 PTY。
- xterm scrollback 首版 5,000 行，未激活终端继续受同一上限约束。原生层不保留第二份终端历史；
  主 WebView reload 视为终端不可恢复并关闭现有 PTY。

### 8.3 生命周期和进程回收

- 终端创建后冻结来源 Session 与启动目录；切换 Session、折叠右栏或隐藏到托盘只影响渲染，不终止 PTY。
- 关闭运行中标签先由 UI 确认，再调用 close；原生报告 Shell 结束后，TerminalController
  通知 ResourceWorkspaceStore 复用 close 流程，回收成功才移除对应标签；后台退出不切换当前活动标签。
  不拦截 Ctrl+D 推断退出，创建响应前到达的退出事件仍等待原生句柄后清理。Ctrl+D 会继承上条命令状态，故非零退出也自动关闭；启动、通信或清理错误保留标签供重试。
- 正常关闭冻结前台组与 Shell 组，取消输出/输入等待，按 150 ms 间隔升级 SIGHUP、SIGTERM、SIGKILL。
  Unix 显式 SIGKILL 兜底 Shell，因为 portable-pty 的 cloned killer 只发 HUP。终止信号后再释放 writer/master：
  writer Drop 会发送换行/EOF，不能提前触发未提交输入；Darwin 的 PTY 排空可能阻塞退出，master 又必须在
  child wait 完成前关闭。收齐 reader/wait 任务后核验进程组消失，临时 EPERM 不当作结果。
  单次 close 最多等 3 秒，超时保留 owner 与任务供重试；已经 `setsid`/daemonize 脱离的进程不在保证范围内。
- 重启沿用原生句柄保存的启动目录，不重新读取当前会话或被编辑的 Workspace。主页面 reload 清理所有旧
  PTY；原生注册表锁只短暂持有，创建/重启/重载用独立生命周期 gate 串行，后台 ack 不被路径解析阻塞。
- Session 删除确认按标签归属统计全部关联运行终端（不只按启动目录判断）；确认后先 `shutdown_for_session`，成功后才提交现有
  `delete_session`，再释放该会话的页面缓存与标签索引。终端清理失败则中止删除，不消耗 Runtime delete token。
- `quit_desktop`、菜单退出和“退出并停止 Runtime”共用一个异步退出协调入口：先阻止新建终端，等待
  `shutdown_all`，再按用户选择停止或保留 Runtime，最后 `allow_exit + app.exit`。
- Window close 的“隐藏到托盘”路径不触发 `shutdown_all`。进程异常终止只能依赖 PTY master drop 和
  操作系统挂断语义，不宣称回收主动脱离进程。

## 九、错误、取消与恢复

- 原生桥错误使用稳定 code：`invalid_request`、`resource_not_found`、`resource_not_previewable`、
  `resource_too_large`、`resource_outside_root`、`browser_not_found`、`terminal_not_found`、
  `native_operation_failed`、`runtime_unavailable`。
- 页面缓存淘汰、标签关闭或会话删除时使目录和预览请求失效；普通会话切换不删除标签索引。旧请求返回后
  核对原 scope key、resource key 及实例仍有效，不按新的当前会话提交结果。
- 浏览器 WebView 创建失败保留标签与可重试状态，不遗留 Manager 句柄。
- PTY 任一阶段创建失败按逆序释放 writer、reader、slave、master 和 child；不会留下半注册终端。
- Runtime 暂时不可用时，已运行的浏览器和终端继续工作；新的 Session 文件读取和终端创建显示重试。
- 不为本版新增兼容别名、旧字段双读或 Runtime 资源迁移。跨客户端重启仅按第 5.1 节的桌面偏好快照重建标签与查看位置，不恢复进程或网页脚本内存。

## 十、验证方案与原型门禁

### 10.1 M0 可丢弃原型

在正式实现前先验证，不提交产品入口：

1. 同窗口 child WebView 创建、边界、显隐、焦点、标题、导航、Cookie 重启、关闭与 capability 隔离。
2. 固定脚本后退、前进和停止在 macOS WKWebView 的行为。
3. 两个 portable-pty 终端的输入、ANSI、中文、Ctrl+C、vim/top、尺寸变化、背压、自然退出和进程组回收。
4. 主窗口隐藏与真正退出对终端生命周期的差异。

任一关键能力失败时回到设计阶段报告证据，不把独立窗口、系统 Terminal 或 Chromium 冒充原设计。

### 10.2 自动验证

- Rust 单元测试：根身份解析、路径上跳/符号链接越界、文本/图片上限、URI decode、浏览器 URL、
  调用方 label、终端状态转换、重复关闭和退出协调。
- Runtime Host 测试：三个资源路由鉴权、Session 不存在、根序号错误、目录截断、删除竞态。
- Environment Factory 测试：新建/clear/Fork 各只包含一次 `local_resource_presentation`，旧 Session 不被
  改写，Fork 重建目录后不存在旧路径或重复规则。

## 十一、风险与排除项

- child WebView API 仍是 Tauri unstable，正式实现必须固定版本并保留原型证据。
- 外链图片会由主 WebView 发起网络请求，这是用户确认的 Markdown 展示行为；本版不建设图片代理或缓存。
- Monaco、xterm 和多 WebView 增加内存，需要在标签关闭时严格 dispose；不预设标签硬上限，以实机数据
  决定是否需要提示。
- 首版不提供文件编辑、Markdown 源码切换、图片编辑或轮播、浏览器下载管理、开发者工具、终端进程或输出的持久恢复、Agent 接管、
  Shell Integration、OSC 剪贴板或终端自动链接。
- 删除本方案新增机制后，现有实现无法同时承载原生 WebView、交互 PTY 和多入口资源标签，因此三个
  manager/store 有真实独立 owner；文件 I/O 仍复用现有资源路由与 NativeResourceBridge，不新增通用服务。

本技术方案已于 2026-09-04 获得用户确认；开发计划另行确认，确认后按里程碑门禁推进。

### M7 依赖核对

Monaco 0.56.0 固定依赖 DOMPurify 3.4.8。Desktop 通过定向 npm override 使用 3.4.14，保留 Monaco 版本与既有编辑器接口；锁文件由 npm 更新。修复依据为 [DOMPurify 安全公告](https://github.com/advisories/GHSA-55q2-fjhq-7xh7)。正式 npm registry 的生产依赖审计结果见验收准备，未执行 `audit fix --force` 或成批升级。
