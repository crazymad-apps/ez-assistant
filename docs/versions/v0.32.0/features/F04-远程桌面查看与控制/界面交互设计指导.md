# v0.32.0 F04 界面交互设计指导

## 一、信息与入口

状态：配合已确认方案方向编制[开发计划](开发计划.md)，计划已确认，M0 已确认，M1 已确认，M2 进行中；Windows 实机交互验证纳入实施阶段。依据：[功能设计](功能设计.md)、[技术方案](技术方案.md)及 F03 已交付设备入口／右栏作用域。沿用 Desktop 现有组件、颜色和右栏，不新增独立远控应用壳层。

从右栏“＋ → 远程桌面”打开正文当前会话／草稿所属设备；设备切换菜单不放桌面操作。标签标题“设备名 · 桌面”，在同设备的全部会话／草稿中共享一份，重复打开聚焦已有标签与连接。切换会话不会重新建立桌面连接，切换侧栏设备不改变右栏目标；不同设备的桌面仍分别绑定自身设备。

设备无查看权限不提供可用入口；设备离线时展示离线原因。系统能力未知时允许发起检查，不能仅根据设备平台名称宣称可连接。

## 二、布局

桌面标签工具栏只保留：显示器选择、适应／原始大小、全屏、开启／停止控制、更多。

- 显示器选择是首版必需入口，复用 `SelectionPopover`，显示目标设备提供的名称、主屏标识、分辨率与当前选择。同名显示器可附列表编号辅助区分，编号不作为设备身份。只有一块屏幕时保留名称、禁用切换；多屏时可明确选择所查看和控制的屏幕。
- 默认“适应窗口”，保持比例，画面外留白不映射成输入；“原始大小”按编码视频像素 1:1 CSS 像素展示，支持本地滚动查看，不代表远端面板物理像素 1:1；按钮提示说明这一点。切换显示比例只改变本地布局，不更换被控显示器或重新授权；坐标从视频实际内容区域计算。
- 全屏只放大当前桌面标签，沿用平台窗口与退出约定；退出全屏不结束连接，但焦点变化必须松键。
- 常态用“只读”或“控制中”表达状态。网络细节放在“更多 → 连接详情”，展示直连、目标平台、当前分辨率及必要诊断；不暴露 SDP、ICE 参数或凭据。
- 首版不存在“切换中继”按钮，也不展示尚未实现的音频、剪贴板或文件拖拽控件。

## 三、连接与错误

| 状态 | 展示和操作 |
| --- | --- |
| 核验／连接中 | 统一连接提示和取消；未收到可解码首帧不显示“已连接” |
| 查看中 | 画面、显示器和只读状态；具备控制权时允许“开启控制” |
| 无法直连 | “当前网络无法直连”，重试／关闭；说明其他设备功能仍可用仅在实际可用时显示 |
| 系统权限缺失 | 指出目标设备缺少屏幕录制或辅助功能权限；提供适用的设置引导，不能在本机误开目标设置 |
| 无图形会话／锁屏／安全桌面 | 明确当前桌面不可用，禁止输入，允许重新检查 |
| 编码／平台不可用 | 展示可采取行动的原因；不显示空白画面冒充成功 |
| 媒体中断 | 画面加“画面已中断”遮罩并立即停止控制，提供显式重连；不可将静止桌面直接判断为断线 |
| 授权撤销／用户退出 | 清空视频和远程输入队列，结束连接；退出登录同时清除本地文本草稿，重新获权后显式打开，不保留无权查看的最后一帧 |
| 控制被占用／控制权限失效 | 保留有权查看的画面并回到只读；提示占用或权限原因，不抢占或自动排队 |

连接超时与用户取消均回收该连接；页面切走后的迟到响应不能打开新标签。关闭标签取消查看，设备仍可用于其他操作。

## 四、控制与焦点

首次打开与任何重连都只读。“开启控制”以目标响应为准，等待时按钮不可重复提交；控制占用时提示“该设备正在由其他连接控制”，提供继续查看，不能自动抢占。

点击画面使其获得输入焦点；只有目标确认控制且画面获焦时才发送普通键鼠。工具栏、输入框、菜单的按键保持本地用途，悬停离开画面不等于失焦。拖动出界时停止坐标映射并在最后有效位置松开按钮，不把留白映射到屏幕边缘。

| 焦点或操作变化 | 控制与画面行为 |
| --- | --- |
| 同一桌面的工具栏、更多菜单、输入文本弹层 | 释放远程键鼠、暂停普通输入；暂保留当前控制占用，显示“控制中 · 输入已暂停”；点击画面后继续普通输入 |
| 切换到聊天、其他资源／会话、隐藏桌面标签、客户端窗口失焦 | 立即停止控制并松键，画面可保留只读；返回后显式开启控制 |
| 切换显示器、退出登录、媒体断连、许可撤销 | 使原控制绑定失效，按相应关闭／切屏流程收尾；不恢复旧控制权 |
| 仅切换适应／原始大小 | 暂停映射并松键，布局稳定后按新内容区域定位；设备与显示绑定保持不变 |

文本输入在“更多 → 输入文本”提供小型输入框，标明当前设备／显示器。只有当前连接具备有效控制权才可打开；弹层内用本机输入法完成组合，未结束组合时不允许提交。点“发送”后才提交已完成文字，不自动读取剪贴板；发送成功只表示系统输入接口已接收，不保证目标应用已保存内容。

单次文本上限为 16 KiB UTF-8，超限时提示用户分次提交；输入接口按安全字符边界拆分。许可撤销、切屏或窗口失焦时禁用发送，保留本地草稿供用户处理，但不把草稿自动改绑新目标；关闭弹层清除草稿。结果未知时提示先查看目标画面，不自动重发；部分提交不会自动回滚目标文字。

物理按键遵循目标平台键位，普通字符可能受到目标输入法影响；需要确定文字时使用文本提交。首版支持普通按键、左右修饰键、方向／编辑键及鼠标按钮／滚轮，组合键使用显式 key-down／key-up，不将本机 Command 静默翻译为 Windows Control。系统拦截的快捷键在正式平台验证后确定最小发送菜单；不承诺发送安全桌面组合键。工具栏“停止控制”始终可见，本机退出全屏和切换应用的操作保持可用。

选择另一显示器后立即停止输入并释放旧屏按键，画面加“正在切换显示器”遮罩，关闭旧显示绑定后建立新绑定。新屏首帧就绪时更新当前屏幕名称、尺寸和输入映射，并保持只读；用户重新点击“开启控制”后才能操作。切换失败明确展示错误和重试／重新选择入口，不恢复旧控制权；旧屏迟到画面或输入不得落到新屏。显示器拔除或几何信息变化导致映射失效时停止控制，刷新列表后要求重新选择，不静默跳转主屏。

## 五、本地恢复

标签描述只保存中心／用户／设备、显示器偏好、适应方式和布局；不保存连接或控制状态。客户端重启恢复为“未连接”，由用户重新连接。退出登录或切换企业主体时关闭原用户连接，偏好按既有用户作用域隔离。

同设备重复打开聚焦原标签，不增加连接；关闭共享桌面标签会从该设备的所有会话／草稿中移除，并结束本客户端这次查看。不同客户端的查看者和显示器选择互不覆盖。

## 六、交互验收

在正式 macOS WKWebView 和 Windows WebView2 验收：连接状态、首帧、只读／控制、权限不足、控制占用、显示器切换、缩放后坐标、文本输入、窗口与标签失焦、重连、撤销、关闭及重启恢复。

本轮原生 WKWebView 探针证明视频显示与模拟消息链路；另以 Chromium 经双段 WebRTC 验证 macOS 原生测试窗口中的实际键鼠、文本提交及松键，并接通真实单窗口采集、硬件编码与画面反馈。进一步通过两块真实显示器的整屏采集和选择器往返切换，确认缩放后区域命中、留白无输入、切屏松键、旧绑定拒绝及新屏只读。正式右栏、CSP、WKWebView 输入焦点和快捷键仍待验收；中文提交通过不等于目标输入法组合通过。实施时复用 F03 已交付设备及标签契约，不另建工作区壳层。
