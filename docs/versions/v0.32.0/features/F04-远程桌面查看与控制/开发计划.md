## 二、实施原则与边界

1. 按 M0 → M1 → M2 → M3 推进，每步完成最小有效验证后汇报，用户确认后进入下一步；不以计划确认代替后续里程碑确认。
2. 保持软件版本 **0.32.0**。开发阶段、修复和测试包不触发升版；若实现发现兼容下限或持久化确需变化，先说明影响并取得确认。
3. 复用已有查看／控制权限、访问 ID、取消和续期，不新建权限表或桌面业务数据库，不把桌面资源挂在 Agent Run 生命周期上。
4. 目标 Host 拥有采集、编码、控制占用和输入；本机 Host 拥有跨设备及本地媒体连接。平台 helper 为受管能力子进程，不建立常驻进程池或独立业务服务。
5. 使用 WebRTC／H.264，目标编码一次，本机转交编码载荷。禁用 TURN、中心媒体中继及 RFB 自动回退；普通文件、会话和终端继续经中心桥接。
6. 首次打开、切屏及重连默认只读；整机最多一个远程控制者。失焦、撤权、断线和关闭的松键与资源回收随功能接入，不留到最后补做。
7. 复用现有组件与右栏“＋ → 远程桌面”入口；标签绑定中心、用户、设备，保持本地工作状态。首版交付桌面客户端；完整远程 Web 浏览器工作区、Linux 被控、手机、音频、剪贴板同步、文件拖拽、锁屏登录与安全桌面控制不纳入。
8. 每步只测直接风险。自动化使用新建 `.runtime-test/` 场景；真实桌面测试用受控窗口和文本，不操作用户业务资料，不把探针结果当作正式集成结果。新依赖、平台原生代码及分发按仓库约束核查。
9. 沿用技术方案中的初始资源和性能预算，实测后在方案中更新；不能把预算写成已达成结果。必要环境缺失时保留未完成项，不静默删除平台范围或改为媒体中继。

## 五、各里程碑范围与完成判定

### M0 正式依赖与双平台采集基础

**目标／前置**：计划获确认后，解决原型到正式 Host 的依赖和原生执行基础；M1 不再依赖临时 Demo 程序。

**交付范围**：

- 核查既有 WebRTC 候选与 Host 的工具链、TLS provider、许可证、传递依赖和两平台构建；确认一个正式实现，不同时保留多套媒体栈。构建工具链声明与实际要求必须一致，不能凭 nightly 通过宣称兼容；M0 经实编和用户确认调整为 Rust 1.98 稳定版。
- 将显示器枚举、采集、H.264 编码及系统能力诊断接到 Host 管理的原生 helper；macOS／Windows 都要验证真实画面。核对尺寸与编码能力，硬编不可用时明确降档能力或不可用原因。
- 实现按需启动、独立控制管道、有界帧队列、取消和父进程失联回收。平台不支持、无交互会话、权限不足时返回可解释结果。
- 明确随包位置与签名归属，补齐最小构建入口。此时不向用户展示尚未接通授权和媒体的“打开桌面”成功入口，也不接入控制输入。

**验证入口**：受影响 Host／helper 的编译、静态检查和定向生命周期测试；两平台受控窗口真实采集编码短测。复用原型的合成样本核对编码输出与候选媒体库接口，不重跑无关业务测试。相关 Rust 包使用 `cargo check -p <实际包名>` 与定向 `cargo test -p <实际包名> <测试过滤器>`，具体包按实际归属确定，不为测试新建产品 crate。

**完成判定／Review**：正式源码可在两平台构建，真实采集编码及停止可核验，依赖和 helper 分发边界明确，无闲置常驻或无界缓存。Windows 实机检查安排在本阶段，不以 macOS 原型代替；受环境限制未完成时如实列出，不标记双平台基础已完成。

### M1 授权直连与右栏只读桌面

**目标／前置**：M0 获确认；用户从正式客户端打开目标主屏并看到实时画面。

**交付范围**：

- 将现有查看许可与目标桌面资源绑定，沿已有中心连接转发有界 SDP／ICE；补充可信来源关联，复用现有授权撤销和续期。
- 打通目标 Host → 本机 Host → 原生 WebView 的双段 WebRTC；跨设备段只尝试直连，本地段核验 loopback。STUN 使用显式配置，不硬编码公共服务。
- 两段协商匹配编码能力，处理关键帧请求、各段重传和基本拥塞反馈；不进行本机二次编码，不用无界缓存掩盖慢消费。
- 增加右栏桌面标签、打开／取消／关闭、适应／原始大小、全屏和错误显示；首帧可解码才显示查看就绪。主屏先形成完整路径，显示器选择在 M3 完成。
- 设备和用户按打开时固定；同设备各会话／草稿重复打开聚焦同一桌面标签，连接归设备资源 Store。观看撤权、账号退出、中心断开、媒体失败和关闭时立即停止对应访问并清理画面；显式重连创建新访问。

**验证入口**：中心信令路由和 Host 访问取消定向测试；前端 `npm --prefix apps/desktop run build`、相关组件测试；两台真实机器的 LAN 查看短测，覆盖 macOS／Windows 被控及 WKWebView／WebView2 播放。核对实际选中路径与中心流量，确认无媒体中继；拒绝权限、错目标、迟到信令和取消不能建立查看。至少一种跨 NAT 条件下验证 STUN 与不可直连结果；若环境暂缺，列为 M3 完成前必补项。

**完成判定／Review**：正式权限和实际画面连通，查看关闭／撤销可回收，两段反馈与队列有界；普通项目、文件和终端通道保持原路径。不得把获得 access_id、合成视频或 ICE 建立单独当成桌面已可用。

### M2 键鼠控制与输入生命周期

**目标／前置**：M1 获确认；在已就绪画面上主动获得控制并完成基本操作。

**交付范围**：

- 消费独立控制许可，目标原子管理整机唯一远程控制占用，关联当前查看者、来源与用户；只读者不能通过构造消息注入，停止控制保留有权查看的画面。
- 接入两平台鼠标、拖动、滚轮、物理键及组合键；按实际画面内容区域映射系统坐标，留白不产生输入。文本弹层使用本机输入法完成组合后显式发送，保留既定字符限制和未知结果不重发语义。
- 接入画面焦点、工具栏暂时暂停、切换标签／窗口失焦停止控制及快捷键边界；不自动改写 Command／Control 或更改用户输入法。
- 目标输入 owner 和 helper 记录本控制者已按下集合；输入存活、堵塞、撤权、媒体失败、Host／helper 消失均停止输入并松键。设备心跳不代替控制短存活检测。
- 控制请求结果未知时查询现状，键鼠及文本不自动重放；权限、系统限制和控制占用如实反馈。

**验证入口**：用受控窗口执行 macOS→Windows、Windows→macOS 及 Windows→Windows 的键鼠／文本短流程；覆盖只读拒绝、双用户竞争、查看撤销级联、仅控制撤销、失焦、异常松键和中文／emoji。输入与取消逻辑使用定向测试，真实系统限制由实机核对，不要求用户操作真实业务文件。

**完成判定／Review**：输入落到正确设备和显示绑定；控制权与焦点分别生效，不能因 UI 状态伪造权限；故障不遗留按键、不自动恢复控制。Windows 高完整性应用／锁屏／安全桌面不绕过、不伪报成功。

### M3 多屏、多人查看与交付收尾

**目标／前置**：M2 获确认；补齐首版多屏和并发使用，收口实际交付风险。

**交付范围**：

- 加入显示器选择；切屏关闭旧绑定并停止控制，新屏首帧后只读。处理负坐标、DPI、旋转、布局变化与显示器移除，旧输入或迟到画面不能落到新屏，不影响其他查看者。
- 接入同屏同规格共享采集编码、不同显示器独立采集；查看者连接与预算独立，控制占用仍覆盖整机。按技术方案校准并发限额，慢查看者不能阻塞其他人或无界积压。
- 标签只保存设备／显示器偏好及本地布局，重启后需主动重连；关闭最后一个查看者释放对应采集。账号切换清理旧身份资源，不共享远端标签状态。
- 定向补验丢包关键帧恢复、限带宽、输入堵塞、中心断连、休眠与进程异常；与文件传输／终端并行时心跳、撤销和输入停止仍可用。
- 完成正式随包 helper、权限引导和稳定签名身份；核对 Desktop 与 Client 分发基础设施。测试包保持 0.32.0 并附 release 清单与签名，交付范围与实际授权保持一致，不自动上传、部署或安装用户环境。

**验证入口**：两平台正式构建、原生 WebView 的短组合流程、多查看者和多显示器实测；补齐 M1 暂缺的跨 NAT 条件。性能按技术方案参考场景测量首帧、输入反馈、码率和持续资源占用，不用本机少量点击或模拟连接替代。测试包只做必要构建、签名及平台资源检查，不重复完整安装包验收；正式发布另按发布流程执行。

**完成判定／Review**：首版显示器切换、多人查看、单人控制、撤销／异常回收和本地恢复形成闭环；双平台实机及直连证据齐全，限制明确。不能以一个平台通过标记双平台完成，不能因网络穿透失败引入未经确认的中继。F04 必需能力完成后汇报，由用户确认 Feature 完成，不自动进入 F05 或整版本发布。
