## 二、背景与目标

用户在现有客户端右栏查看和操作授权设备的当前系统桌面。目标 Host 持有采集、输入和访问生命周期；本机 Host 持有跨设备媒体连接，界面只与本机 Host 交互。远程桌面不属于某个 Agent Run，不为聊天创建独立系统桌面。

首版结果：macOS 与 Windows 设备均能被查看和控制；直连时企业中心只承担授权和信令，媒体及输入不经中心。macOS／Windows 客户端的原生 WebView 均需正式验收。Linux 被控、手机和完整远程 Web 工作区不在首版范围。

WebRTC 的本机原型已证明原生进程之间传送编码视频、本机 Host 转交 WKWebView／Chromium 显示及双向数据消息可行。随后补充的 macOS 原生窗口实验已验证实际鼠标、键盘、文本提交和断线松键，并通过 ScreenCaptureKit／VideoToolbox 接通真实单窗口采集到 Chromium 显示的操控闭环。随后在两块实际显示器完成整屏采集、选择切换、缩放坐标映射及切屏松键验证。这个结论足以继续设计，但尚不代表负坐标／混合 DPI／热插拔、跨 NAT、Windows 完整交互、正式 Host／原生 WebView 完整输入交互或弱网质量通过；M0 新增的双平台采集基础结果见技术方案。

## 三、范围与非目标

| 纳入 | 边界 |
| --- | --- |
| 打开桌面、查看、主动开启／停止控制 | 设备可用权、桌面查看权、桌面控制权分别核验；初次及重连默认只读 |
| macOS／Windows 被控 | 当前已登录、可访问的交互桌面；无图形会话、系统权限缺失、锁屏／安全桌面分别反馈 |
| 单屏查看、多屏选择、适应／原始大小、全屏 | 每个查看连接选择一个显示器；切屏不改变其他查看者的选择 |
| 鼠标、滚轮、组合键及文本输入 | 输入作用于整个系统桌面；不是项目沙盒，也不是后台单窗口自动化 |
| 多查看者与一个远程控制者 | 本方案采用目标 Host 的整个桌面同时只授予一个远程控制者，其他人可查看；不抢占本地人的系统操作 |
| 直连与失败恢复 | ICE／STUN 寻路；不配置 TURN、不回落到中心媒体桥接或 RFB |
| 撤销、失焦、掉线、关闭与退出清理 | 释放本连接注入的按键和按钮；重连重新授权，旧输入不重放 |

不包含音频、系统剪贴板同步、桌面内文件拖拽、录屏、无人值守登录、UAC／安全桌面控制、提权、用户登录会话切换、Agent Computer Use、通用端口转发或业务 P2P。文件与终端继续沿 F02 通道。

## 四、功能路径

### 4.1 打开与查看

1. 从右栏“＋ → 远程桌面”打开正文当前会话／草稿所属设备。设备选择菜单仅负责切换设备；同设备所有会话／草稿共享一个桌面标签和连接。标签绑定中心、用户和设备，不随侧栏切换改变。
2. 本机 Host 校验用户，目标 Host 校验查看许可、系统图形会话、采集权限和编码能力；设备在线不等于桌面可用。
3. 协商直连与本地播放；收到可解码首帧后才进入“查看中”。连接过程可取消、有超时。
4. 默认显示目标主屏；显示器列表来源于目标设备。用户已明确首版必须可选择并切换被控显示器，查看与输入共同绑定所选屏幕。切屏先停止控制并释放输入，再建立新的显示绑定，首帧就绪后仍为只读。显示器拔除不静默转到另一块屏幕。
5. 多查看者各自选择显示器；同屏允许共享采集和编码，慢连接不得阻塞其他人。首版建议限制目标同时四个查看者、两个不同显示器的采集，超出时明确返回繁忙；预算须由两平台实测校准。

### 4.2 控制

- “开启控制”重新取得控制许可并检查原生输入权限。目标存在其他远程控制者时返回占用，不抢夺、不排队自动获得控制。
- 控制权是目标 Host 内存中当前查看连接的事实；系统本地用户始终可能操作同一桌面，不承诺独占操作系统。
- 控制许可与输入焦点分开：普通键鼠只在画面获焦时发送。同一桌面工具栏／输入文本弹层获焦时释放已按下键鼠、暂停普通输入，暂保留控制占用；文本提交只作用于弹层打开时绑定的设备、显示器与控制许可。
- 切到其他资源／聊天、隐藏桌面标签或客户端窗口失焦时停止控制、松键并回到只读；回来后需重新开启控制。单纯移动指针离开画面不改变控制权，但画面外不映射输入；拖动出界释放拖动按钮，避免悬挂。
- “停止控制”释放控制占用，回到查看；控制权被撤销时若查看许可仍有效，可保留只读画面。查看权撤销则结束整个查看连接。
- Windows 对更高完整性级别应用、安全桌面及锁屏不提供绕过；不能执行的输入不得报告成功。macOS 未获辅助功能权限时可查看但不能控制。

### 4.3 断线与关闭

- 直连失败显示“当前网络无法直连”，提供重试；项目、会话、文件和终端不因此切换通道。
- 失去可用媒体／输入连接立即停止新输入；目标通过存活检测释放已按下按键。冻结画面必须标为已断开。
- 沿用 F01 实际实现：中心控制连接被判定断开时访问取消，即使媒体尚通也结束访问；静默失联受既有心跳／许可到期上限约束。不能把历史草案中的“最长有效窗口”解读为断线后必须保活。
- 重连创建新的访问和媒体绑定，恢复只读；不能恢复旧控制权或重放输入。
- 关闭标签回收对应查看者；最后一个使用者离开后停止对应采集／编码。Host 停止回收它拥有的原生资源与辅助程序。
- 重启只恢复设备和显示偏好等描述，需用户重新连接；不保存 SDP、ICE 凭据、控制授权或活动连接句柄。

## 五、模块与契约

| 所有者 | 责任 |
| --- | --- |
| 企业中心 | 复用 F01 用户／设备／固定能力授权，按活跃访问路由有界信令；不收视频、键鼠正文或新增桌面业务库 |
| 目标 Host | 查看者、控制权、系统能力、采集编码、输入校验、撤销和资源清理 |
| 本机 Host | 跨设备 PeerConnection、本地媒体交付、客户端离开后的远端收尾；不复制桌面权威状态 |
| 原生适配 | 按 Host 已准入命令采集／编码／输入，报告系统限制；不自行连接中心 |
| Desktop | 视频显示、焦点／缩放、输入意图和本地标签描述；不持有远端组网凭据 |
| assistant-protocol | 必要应用意图、设备／显示器引用及状态／错误；SDK 对象与信令实现保留 Host 私有 |

复用 F01 的 `HostNetworkCapability::{DesktopView, DesktopControl}` 和访问取消，不再建另一套用户权限。普通 HTTP／SSE／文件／终端代理无法承载实时媒体语义，因此增加 Host 私有桌面资源 owner 和媒体适配有必要；不新增 Runtime Session、Run、桌面数据库或通用媒体服务框架。

## 六、关键取舍

- **WebRTC + H.264 优先**：本机双段转发已验证，适合以一次编码、终端解码的方式交付。具体 Rust 库仍须通过正式构建和弱网验证再冻结。
- **跨设备 Host 到 Host，本地 Host 到 WebView**：保持本机统一入口；第二段使用 loopback WebRTC，转发编码数据。二次协商和两段反馈仍有实现成本。
- **直连失败明确结束**：这是用户已确认的首版策略；STUN 不等于任意 NAT 可穿透。
- **一个远程控制者**：控制占用覆盖目标 OS 桌面，包括不同显示器；避免多个查看者互相释放键鼠或争抢系统焦点。该方向已随方案简述获得用户确认。
- **采集输入按平台适配**：首版两平台均是完成条件，不能用 macOS 通过替代 Windows 或静默缩减范围。

## 七、验收标准

1. 两台真实设备间，经本机 Host 完成 macOS／Windows 被控和相应桌面客户端播放；目标权限与数据归属正确。
2. 通过选中候选地址与实际流量确认直连，无 TURN 候选、无中心媒体流量；不可直连时按既定文案结束。
3. 只读者即使构造输入消息也不能注入；控制权占用、控制撤销、查看撤销分别收敛。
4. 多屏偏移、负坐标、DPI、缩放、显示器移除、组合键、文本及鼠标按钮行为正确；切屏不改变其他查看者。
5. 失焦、输入堵塞、中心断开、媒体断线、休眠、关闭及 Host 退出不遗留按键、查看者或采集资源。
6. 重连默认只读，取消后迟到协商不复活已关闭连接；恢复标签不自动启动控制。
7. 正式签名安装包中系统权限和原生 WebView 可用，Client 随包 Host 具备相同被控基础设施；无 GUI 会话明确不可用。
8. 真实画面的清晰度、首帧、交互延迟及资源预算满足技术方案中经确认的目标；弱网和慢查看者不拖垮其他业务。

## 八、待确认与风险

已确认：macOS／Windows 被控；不启用 TURN／中心媒体中继；整屏查看与控制支持选择、切换显示器。

本轮设计收敛为：整机单远程控制者、每次切屏新建查看绑定、控制与焦点分离、显式文本提交、受管原生辅助程序和失败后只读重连。方案方向已获确认；并发上限及性能目标仍是待实测校准的预算，按开发计划分阶段收敛。

Windows 实机验证按用户要求列为待办，不阻塞继续设计，也不等于取消 Windows 范围或通过双平台验收。实施与发布仍需完成 [技术方案中的验证待办](技术方案.md#九验证门槛与兼容)，其中 Windows／WebView2、跨 NAT、正式 WebView 输入、反馈恢复和正式构建是实际交付门槛。
