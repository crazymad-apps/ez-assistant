## 三、里程碑范围

### M0 配置契约与双端管理

**结果**：两端均能明确配置 OpenCode 身份、基础地址、独立模型列表路径、Chat／Responses 协议及固定参数；企业配置传到 Host 后身份不丢失。

**工作项**：

- 重新核查官方文档与路由，固定 Go／普通按量预设；资料冲突保留明确证据状态，不靠失败重试验证地址。
- 扩展现有 Provider 枚举、配置校验、序列化和模板接纳；同一事实沿 Rust／共享 TS／OpenAPI 投影，不建立第二份配置模型。
- 本地和企业表单提供一致配置能力、完整路径说明与最终 URL 预览；OpenCode 仅允许显式协议，目录混合模型不自动推断协议。
- 检查中心配置下发、Host 接纳及配置失效绑定；既有企业代理 URL 不应抹掉 OpenCode 身份。
- 冻结旧客户端未知类型的拒绝行为、应用／企业协议兼容声明与存储影响；已有 OpenAI 配置不自动转换。
- OpenCode 后台测试入口不落入中心原生请求合成分支，清楚标明推理验证需使用客户端；模型发现可独立验证。

**验证**：定向配置往返、路径覆盖、协议校验、模板与未知类型测试；本地／企业正式表单保存回读和目录刷新；相关类型及协议生成检查。使用本地模拟上游与新建隔离数据，不执行真实账号调用。

**完成判定**：配置闭环真实可用，企业来源与本地来源语义一致，能力未知不伪造。此时仍未完成方言执行，执行入口须明确拒绝未完成适配的 OpenCode 调用，不能静默落入通用方言或宣布已可推理。

### M1 本机方言与会话路由

**结果**：本机唯一 OpenCode Adapter 生成请求体和必要请求头，稳定身份覆盖主会话、子任务及旁路调用。

**工作项**：

- 在既有 Chat／Responses 具名方言、Service 与 Host 装配中接入 OpenCode，复用 Codec／Decoder，不创建独立执行器或 Core Provider 分支。
- 在模型工厂构造输入中补通用会话路由参数，使用现有 Session／ChildTask owner 派生，服务实例绑定不可变值；不借用 trace 或历史续接绑定。
- 覆盖普通对话、工具继续、重试、恢复、Fork、子任务、标题、摘要、辅助识图及本机连接测试；同一 owner 稳定，临时测试按次生成。
- 本机写入 `x-opencode-session` 与真实 User-Agent，其他 Provider 不受影响；缺失必需路由参数在请求发送前明确失败。
- HTTP/SSE 为首批路径；续接、原生压缩、计量和 WS 不凭协议名称推断支持。

**验证**：通过注入 Transport 检查两种协议的完整请求与流式解析；正式隔离 Runtime 验证跨 Run／重启稳定及并发隔离，覆盖辅助入口；回归非 OpenCode 方言、取消和建流重试。测试须检查实际出站请求，不能只断言配置字段存在。

**完成判定**：直连执行链路在模拟上游闭环，企业来源即便 endpoint 是中心地址也选择同一方言；Core 与对话持久化未引入 OpenCode 专属内容。真实账号能力仍以 M2 实测为准。

### M2 企业透明转发与完整接入

**结果**：完整配置从企业后台下发到正式 Host，本机编码后经中心转发到上游；中心不执行 OpenCode 方言或生成会话身份。

**工作项**：

- 扩充通用代理受限请求头透传，保留本机生成的会话标识和 User-Agent；单值、长度和换行校验后原值转发。
- 原正文／流保真、既有鉴权替换、配置重验、取消／背压和错误观察保持明确边界；不增加中心 OpenCode body 拼装或缺头兜底。
- 核对直连／代理、Chat／Responses、主／辅助调用四类组合，覆盖配置变更、权限撤销和未知客户端。
- 验收后台完整配置与目录发现、本机推理验证的操作闭环；不存在把目录成功展示为推理成功的路径。
- 在明确账号、模型和调用额度范围后做最小真实 Go／普通路由验证，凭据只通过私有测试环境提供；未授权的真实调用保持待办。
- 同步实际实现对应的模块约束、必要手册和完成结论；文档只记录结论、限制和用户确认，不新增验证报告或运行数据附件。

**验证**：新建隔离正式 Host＋中心＋模拟上游抓取实际请求，比较正文及透传头；两种协议流式与工具轮次、断流／取消、上游错误；必要的真实账号 smoke。后台通过正式接口保存／下发后验证，不能绕过正式模型来源直接构造测试对象冒充闭环。

**完成判定**：满足接入方案第七节全部条件。未完成的真实订阅／按量路由明确列为验收缺口，由用户决定补验或接受限制；不能以公开模型列表请求替代。

## 四、最小验证与操作约束

- 只改文档时检查链接、路径、状态与职责一致性；实现时读取所涉 Rust／前端规范及模块约束，按直接风险执行定向测试与编译，再决定是否扩大范围。
- Provider 类型变化核查所有生产者、消费者、序列化与存储；生成文件使用既有生成入口，不手改。
- 验收 Runtime Home 使用项目 `.runtime-test/` 下新建目录；数据库先确认真实连接、表与影响范围，遵循根数据库规则。方案本身不授权生产迁移或修改用户配置。
- 同一构建目录的构建与运行验证串行；不因本计划自动构建安装包、部署、提交或推送。
- 与 F01—F04 的共享文件和版本声明在实施前重查，不覆盖其他任务状态。F05 完成仍须跨 Feature 验证企业配置下发、远端执行 owner 与模型代理的组合。

## 六、M0 完成结论

2026-10-16 完成双端 OpenCode 配置、地址预设与最终 URL、独立目录发现、显式协议、固定参数及企业下发身份接纳。正式本地 Host 保存／刷新／重启回读及两端表单保存通过；旧版兼容声明在业务读取前被拒绝，未知 Provider 不降级。应用下限统一 0.32.0，企业协议及存储结构／下限保持原值。

Host 推理在构造 Adapter 前拒绝，中心后台测试在合成请求及记录前拒绝；真实推理、稳定会话身份及透明头转发尚未交付。配置／模板／路径及必要核心回归、类型、协议生成、构建与静态检查通过；旧桌面与 Host 回归夹具已对齐本版设备归属、端口和迁移登记。

M0 已完成；用户授权自主开发测试，M1、M2 实现与自动化验证完成，真实账号与人工验收待进行。只使用新建隔离场景，未修改用户配置或共享数据库，未打包、部署、提交或发布。真实账号调用、其他平台安装版及 F04 延后的实机验证继续保留；此前同版本测试包仍需配套更新。


## 七、M1 完成与 M2 实施

稳定路由已覆盖主会话、Fork、子任务、连接测试、标题、摘要和辅助识图；具名 Chat／Responses 方言与实际产品身份请求头已接入。跨 Run、压缩、清空及 Runtime 恢复、独立子任务、建流重试、缺失身份拒绝和非 OpenCode 回归通过。中心受限透明头转发与双端能力限制已实现，继续正式 Host＋中心＋模拟上游闭环。

联调确认既有企业受管模式只下发一个默认模型，不存在独立辅助识图来源；本次不扩展该契约。独立识图覆盖个人配置直连及以个人配置接入已有中心默认模型的代理路径，企业受管路径验证其实际可用的主模型、子任务及旁路调用。


## 八、M2 自动化验证完成与人工交接

2026-10-17 正式隔离 Host、中心配置下发及模拟上游联调通过：双协议直连／代理、正文保真、稳定身份、重启、主／子任务及旁路调用符合既有归属；个人配置的辅助识图同时覆盖直连及中心代理。受限头校验、鉴权替换、错误／取消／背压回归通过。Rust 工作区默认测试、双端界面及中心回归、类型、生成契约、构建与静态检查通过；测试服务已停止，用户数据未改动。

Review 结论：复用现有 owner、配置编译、Codec、Decoder 和代理；新增通用路由输入用于现有历史绑定无法表达的跨正文周期稳定身份。识图只在确定 child owner 后派生冻结资源，不新增执行器、身份存储或中心方言。

真实 Go／普通按量账号、所选模型与额度未提供，未执行真实付费调用，也不能据模拟结果宣称订阅可用。F05 保留该验收缺口，随用户集中人工测试补验；F04 实机遗留继续保留，版本不归档或宣称完整验收通过。本轮未重打安装包、部署、提交或发布；此前同版本测试包须配套更新后再做人工验收。
