## 二、用户结果与范围

2026-10-16 用户纠正右栏设计：取消方案自行增加的独立项目资源模式，右栏始终跟随正文当前会话／草稿。
本次修订替代此前相关设计，现有代码及测试包仍待按[本版待修复项](../../开发计划.md#五现有功能缺陷修复)修正；历史里程碑完成记录不作为新规则已实现的证明。

用户在本机客户端选择另一台授权设备，浏览其项目和独立会话，创建会话并发送本机附件，查看返回的图片、文件和事件，在右栏打开该设备的终端。侧栏切回本机后，原会话及终端仍属于原设备；跨设备常用会话可以加入本机置顶。

首版入口是连接本机 Host 的桌面客户端及企业账号。UI 始终向本机 Host 发送请求，设备路由、接入和中心桥接沿用 F01／F02。个人模式和既有远程 Host 直接登录保持原用途；直接登录后的 Host 不被重新命名为“本机”，也不借此增加多跳组网入口。完整 Web 多设备工作区不作为本次桌面交付承诺。

同一企业 Host 支持多个授权用户同时使用，按中心与用户身份进入各自业务域；F03 的单个客户端窗口仍只使用当前账号。两人将项目指向同一实际目录时操作的是同一份文件，不因此形成操作系统隔离。

不包含会话迁移、自动跨设备 Agent 调度、远端全局配置管理、文件同步挂载、跨设备直接搬运文件或持久终端。远程桌面由 F04 接入；本 Feature 提供固定设备的右栏资源归属，不实现媒体与键鼠控制。

## 三、设备选择与作用范围

### 3.1 侧栏

相关区域保持一层结构：**本机置顶 → 设备切换入口 → 项目 → 独立会话**。项目和独立会话只显示当前选择的设备，不在会话列表中叠加设备分组。

设备选择器默认本机，只列出当前企业账号可用、在线且启用的其他设备，不显示在线文案；设备图标按 Windows、macOS、Linux 区分，未知系统显示电脑图标。本机不因尚未登记而不可使用；设备目录中的本机登记项需要与本机入口去重。当前选中设备离线时保留设备归属与不可用提示，不自动改成本机；离线、目录获取失败、无授权设备和项目列表为空分别显示。刷新不清空已打开的会话或右栏。

采用：启动时侧栏默认本机，本次客户端运行内保留选择；全局“新建会话”继承侧栏设备，从项目新建继承项目设备。新会话输入区的设备选择放在项目选择左侧，首次进入自然为本机。草稿设备切换不反向改变侧栏浏览范围。

| 用户操作 | 变化范围 | 保留内容 |
| --- | --- | --- |
| 切换侧栏设备 | 下方项目、独立会话及其加载状态 | 当前正文会话、草稿和已打开标签的归属 |
| 打开项目中的会话 | 正文切至该设备的会话，展示其本地标签组 | 其他会话的运行与隐藏终端 |
| 点击跨设备置顶 | 打开置顶所指会话，不要求先切侧栏 | 侧栏选择和置顶顺序 |
| 在草稿内切换设备 | 草稿目标与目标配置、项目选择 | 可保留的正文及本地未上传文件 |
| 切换账号／企业中心 | 结束旧身份的订阅、连接与可操作视图，读取新身份偏好 | 各身份独立保存的本地置顶和可恢复标签描述 |

当前会话标题和非本机资源显示设备提示。设备改名只更新名称，不改变目标身份；同名设备通过辅助信息区分。设备撤销或注销后不自动改为本机，也不按名称匹配新登记设备。

上方“助理会话”、智能体管理、插件管理及设置继续作用于当前本机连接。远端普通会话可选择目标已有模型、智能体、Skill 和 MCP；目标缺少配置时明确提示，不借本机配置代替，也不开放远端管理命令。

### 3.2 加载与事件

快速切换时，旧设备的迟到响应只能更新其原作用范围，不能覆盖新设备列表或正文。分页、历史／归档、搜索及导航记录均携带设备归属；首版搜索沿用所选设备范围，不自动全网搜索。返回先前会话时按会话自身目标恢复。

只为正在使用的设备保持必要订阅，不为整个设备目录预先打开连接。设备事件按原目标更新投影，断线后按原协议补事件或恢复快照。标签被隐藏与资源真正关闭分开处理，不把组件卸载当作终端关闭。

## 四、项目与新会话

项目属于目标设备的用户域，对应目标目录。列表、创建、编辑、重命名、移除和恢复复用原项目能力；目录选择器浏览目标 Host，不能弹出本机系统目录选择器后将路径直接用于远端。移除项目继续遵守既有语义，不等同删除磁盘目录。

项目文件通过当前会话／草稿右栏的现有项目标签浏览，目标取自该会话／草稿的设备和项目。
侧栏项目行只承载项目与会话导航、项目管理和新建会话，不提供脱离正文的独立“浏览文件”入口。
浏览文件不自动加入模型上下文，已有文件操作继续按原接口和授权判断。

新草稿复用既有项目草稿／独立草稿机制，补齐设备和账号作用范围。设备切换加载目标项目与可用配置，清除不能跨设备复用的项目、模型等选择；同名不代表同一配置。若切换会命中另一份已有草稿，应恢复原草稿并保留当前草稿，不覆盖另一设备的输入；具体提示由交互指导细化。

已有会话的发送、停止、审批、重命名、归档及删除始终作用于其原设备。侧栏设备与正文不同也不能改变提交目标。远端主控托管等 F02 未开放能力不显示为可执行操作。

## 五、附件、图片与结果文件

1. 本机选择文件、拖拽或粘贴图片，沿用现有本地待发送选择；远端只接收内容，不能尝试读取本机绝对路径。
2. 首次发送冻结目标设备、项目、正文和附件清单，通过本机 Host 使用既有流式上传／会话创建接口。发送中及结果未知时禁止改目标重发这一提交。
3. 上传成功的附件引用只属于原设备及会话。草稿换设备仅可带入仍可读取的本地文件选择，不能携带原目标附件 ID；无本地内容时要求重新选择。
4. 分别展示上传进度、失败与消息接纳状态。取消上传不等于停止已接纳任务；停止运行使用原会话操作。结果未知时按原目标和原幂等标识查询，不自动重复写入。
5. 消息图片、附件预览、工具／子任务产物、下载和导出均通过绑定原设备的资源入口读取，继续使用本机登录上下文。
6. 使用系统应用打开远端文件时先完成下载，再交给本机系统；远端路径不能直接传给系统打开或“在目录中显示”。

跨设备文件传递采用用户显式下载后再上传，不新增设备间搬运服务。原生文件选择、上传和预览分支必须一并适配，不能只为 Web 请求增加设备参数就视为完成。

## 六、本机置顶

置顶是当前客户端的快捷入口，按企业中心、账号及原设备／会话身份区分，记录必要名称和顺序。置顶／取消只保存本机配置，不修改目标会话，也不读取远端置顶列表作为来源。项目会话和独立会话均可置顶；当前设备普通列表按本机置顶引用避免重复展示。

非本机项左侧显示设备图标，辅助信息显示设备名。点击按原目标打开，离线或失去权限时保留不可用入口，用户可自行移除。缓存标题只用于识别；恢复访问必须重新核验权限，不能展示旧缓存正文冒充实时会话。

旧版本置顶位于 Runtime 的 `is_pinned`，存在实际持久化与列表排序影响。本草案建议只将当前本机、当前身份的旧置顶一次性导入该客户端配置，远端置顶不导入，后续不双写。导入标记、完整分页来源、旧命令／字段保留与回退行为由技术方案明确并确认后实施；本步不改旧数据，也不预先删除旧字段。

## 七、右栏标签与终端

标签顺序、激活状态、布局和查看位置仍为本机工作状态，按会话／草稿持有标签组。
右栏显示组始终由正文当前会话／草稿及其设备决定；切换侧栏浏览设备不改变正文和右栏。
设备、身份及资源引用保留每个标签的原归属，切换会话只选择对应组，不重定向已有资源或终端。
取消右栏独立项目组、固定到旧会话的显示状态及“返回会话／返回会话资源”入口。

普通资源关闭只取消读取并释放视图，不删除文件。切换会话恢复该会话的本地标签组，隐藏标签不必断开正在使用的终端。重启仅恢复可重新验证的资源描述，不保存远端正文、凭据、终端输出或进程句柄；恢复的旧会话标签待进入所属会话时展示，不覆盖正文当前会话／草稿的选择。浏览器标签仍运行在本机 WebView，远端 `localhost` 服务不因文件桥接自动可访问。

终端复用原终端界面与协议：打开时固定设备、用户、项目／会话和目录；Shell 列表来自目标。连接过程展示可取消的等待，预算覆盖首次远端准入，不能照搬本机 15 秒等待而提前判失败。

输入、输出、resize、ACK 和关闭经本机 Host 转发；保留原背压，不能因 UI 标签适配提前确认数据。切换侧栏不改变终端目标；真正关闭、断线或权限撤销按现有规则回收相应 PTY。断线后重新打开是新终端，不自动重放输入，也不声称恢复旧 Shell。

## 八、失败与恢复

| 情况 | 用户反馈与处理 |
| --- | --- |
| 本机 Host 不支持目标代理 | 提示更新 Host，禁止发送远端业务，避免旧 Host 忽略目标后执行在本机 |
| 设备离线／中心不可用 | 当前目标显示不可连接，保留可识别入口和本地草稿；本机可用操作继续按原能力执行 |
| 访问被撤销／账号失效 | 停止所属远端订阅、传输和终端，清理旧身份可操作内容；不删除目标业务数据 |
| 明确未执行 | 显示失败，允许用户在目标可用后重试 |
| 写入结果未知 | 保留目标和原提交标识，先核实结果；无查询能力时明确未知，不自动重放 |
| 文件读取中断 | 展示失败或重试入口，不将截断内容视为完整文件 |
| 项目／会话已移除 | 显示原资源不可用，置顶可移除；沿用原恢复入口，不自动另建同名资源 |

## 九、复用依据与后续设计

| 现有实现 | F03 必须补齐的内容 |
| --- | --- |
| `RuntimeClient`、F02 原接口代理 | 固定业务目标与本机控制请求区分，能力响应头、错误结果及设备事件隔离 |
| `SessionSidebar`、项目分组与导航 | 设备选择及设备范围列表，本机置顶引用，跨设备导航 |
| `NewSessionDraftStore`、原会话创建流程 | 设备／账号范围、目标配置、首次发送与附件固定目标 |
| `ClientResources`、原生 Runtime 连接与资源入口 | 原生文件流程携带资源目标；保留本机连接，不复用原切 Host 的全局销毁动作 |
| `ResourceWorkspaceStore`、本地快照、`TerminalSocket` | 资源身份、当前会话／草稿项目文件浏览、标签恢复和终端目标与等待反馈 |

不新建会话镜像、共享标签服务、另一套文件协议或网络连接 owner。设备作用范围补入现有调用与本地状态，目标 Host 继续持有业务权威状态。

本 Feature 需要独立技术方案和界面交互指导：前者确定客户端状态归属、原生适配、旧置顶及偏好过渡；后者明确设备选择、项目文件入口、草稿冲突、不可用状态和标签提示。两者形成后再编制开发计划。

## 十、最小有效验证

按用户要求只做受影响检查和短业务闭环，不全量重复 F01／F02 回归。F03 必须用正式客户端实际操作验证：设备切换与迟到响应、本机附件发到目标并预览／下载、跨设备置顶、当前会话／草稿项目文件浏览、终端打开／输入／关闭，以及切换设备后原会话与标签仍归原目标。右栏专项覆盖会话切换、草稿物化、通知／历史导航和重启恢复：显示组跟随正文，隐藏终端保持原归属，界面无独立资源模式及返回入口。

账号切换、权限撤销和未知结果按本次接入改动选择关键路径，旧置顶及本地快照如实际发生格式变化则验证对应过渡。涉及原生分支须在正式 WebView 核对，浏览器替身与同机双 Host 测试分别注明局限；未执行的跨机器、平台或真实模型检查如实保留，不把 F02 测试结论当成 F03 验收。
