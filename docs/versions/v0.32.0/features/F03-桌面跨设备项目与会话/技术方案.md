## 二、源码事实与最小改动

| 已有位置 | 当前事实 | 本次处理 |
| --- | --- | --- |

| `ResourceWorkspaceStore`、`TerminalController` | 本地标签组、进程内终端 controller 已独立于 DOM 挂载 | 加设备归属和项目浏览 scope，保持隐藏与关闭的区别 |
| `desktopPreferences`、`desktop_preferences.rs` | 已有身份分区、写入合并及原子保存 | 在原文件内保存置顶与设备资源描述，不新建业务库 |
| Runtime `is_pinned` 与 `session_loading.rs` | 持久化置顶；查询按旧置顶优先、更新时间及 ID 排序 | 新桌面置顶改为本地引用；旧契约和分页保持，过渡见第八节 |

不引入 UI 到中心的连接、不增加第二套认证、业务镜像、文件协议或通用 RPC。设备内复用已有同步与操作类；只有需要同时存活的不同设备业务状态才分开持有。

## 三、身份与状态所有权

### 3.1 固定引用

本机企业登录身份取自 Host 已核实的 `HostLoginResult.identity`（`center_id`、`user_id`），不采信用户名、显示名或 UI 自报身份。远端目标取自本人设备目录的 `id`；本机目标使用显式 local 标记，请求省略目标参数。

跨设备本地引用统一表达为“当前身份分区 + local／设备 ID + 原资源 ID”。它只用于导航、缓存及偏好；不会把组合字符串作为 `session_id` 或 `workspace_id` 发送给 Host。设备名称和平台仅为展示信息。`instance_id`、`login_context`、连接地址与 token 均不能当作远端设备永久身份。

当前身份分区继续由 `ApplicationConnectionStore` 管理。侧栏本机去重使用本机登记状态中的当前登记 ID 与目录 ID 比较，不能用机器名；登记状态失败时不猜测合并。注销后重新登记得到不同 ID 时，旧远端引用不可按名称自动重定向。

同一设备同时服务多个用户时，Host 仍按 `center_id + user_id` 管理登录和用户域，不新增设备全局当前用户。一个用户登录或退出不替换其他用户；F03 复用该事实并在 M3 做双用户短联调。客户端单窗口保持一个当前账号，文件和 Shell 仍受目标 Host 的实际操作系统权限约束。

### 3.2 现有 Store 的归属调整

RootStore 仍是当前登录客户端的装配入口，保存以下不同职责，组件按操作来源选择对应状态：

| 状态 | 归属 |
| --- | --- |
| 本机连接、登录、设置、助理会话、插件／智能体管理、生命周期操作 | 当前客户端唯一的本机连接 |
| 设备目录及侧栏所选设备 | RootStore 内的浏览状态，设备目录复用 F01 查询 |
| 应用投影、会话页、流式输出、加载状态、事件水位与重连任务 | 每个实际使用的业务设备一份，复用原 projection／coordinator 的业务部分 |
| 正文选中会话／草稿、前进后退历史 | 客户端导航；每条记录携带固定目标 |
| 项目展开状态、活动／归档列表及分页 | 所属设备，不能共用跨设备 offset |
| 草稿、配置读取、提交中的 manifest 与幂等键 | 所属身份、设备和项目／独立草稿 |
| 置顶、窗口布局、右栏标签与原生文件选择 | 本机客户端；资源描述另含目标 |

从原 RootStore 抽出设备业务装配，而非为每台设备 new 一个包含 Settings、登录和偏好写入的 RootStore。会话操作控制器接收固定业务 client／projection；跨设备导航在根完成。现有 `store.projection`、`store.connection` 的使用点必须逐一按“侧栏／正文／设置”归属改接，禁止统一改成当前侧栏 client。

侧栏浏览设备和正文目标是两个不同引用；右栏活动 scope 由正文当前会话／草稿及其目标设备派生，不再独立选择或固定。
资源组保留固定身份、设备和会话／草稿引用，切换显示组不改变隐藏资源的归属。
事件先进入对应设备投影，再驱动正在显示该投影的视图；待处理审批、通知和标题提示同样携带设备来源。远端反馈请求的展示与回答可以走已开放的原接口；反馈中心提交等本机管理入口不随之开放。

### 3.3 生命周期与迟到结果

设备业务状态按使用创建：所选侧栏、正文、正在发送的草稿及打开的资源／终端维持其所需 client；隐藏终端仍有使用者。仅存在置顶引用不为该设备常驻 SSE 或读取所有正文。设备不再使用时释放订阅和请求，保留必要本地描述；不因释放 UI 同步而停止目标 Run。

每个设备沿用原生命周期 generation 和 AbortController。响应提交前核对账号代次、设备及该次操作代次；旧响应不得修改新选中的列表、草稿或右栏。设备撤权关闭该设备的业务连接和标签内活动内容；本机登录失效或切中心则销毁全部旧身份业务状态。偏好保存必须在旧身份下完成或放弃，不能写入新身份分区。

## 四、RuntimeClient 与事件

### 4.1 目标分流

沿用 RuntimeClient，增加构造时不可变的业务目标；原 client 是本机目标。复用同一已认证本机入口，凭据更新与退出仍由唯一登录 owner 处理；不让各设备各自登录、续期或调用原生 `refresh_runtime_connection`。

- 本机 `/capabilities` 检查兼容 JSON 和 `x-ez-network-proxy: 2`，缺失或不识别时禁止远端请求。能力检查结果绑定当前本机连接代次。
- 远端普通命令、文件请求和 SSE 使用 `x-ez-target-device`；浏览器消费的媒体和 WS URL 使用 `target_device`。只生成一种目标表示，不重复追加。
- 登录、Host 控制、设备目录、登记、插件管理和能力查询必须使用本机 client。远端 client 对这些方法直接拒绝误调用；Host 的 F02 白名单仍为最终检查。
- 远端开始同步不能执行原 `waitUntilReady` 的本机启动／健康流程，也不能代理 `/capabilities`：该路径未在 F02 白名单中。本机能力只证明代理支持，不能当成目标附件限额或目标功能全集；目标拒绝和兼容错误按原接口返回展示。
- 设备目录通过本机 `/host-network/access` 的 `list_devices` 取分页。初次打开、展开菜单、用户刷新及业务不可用后按需刷新；不新增 WebSocket 心跳或轮询连接系统。加载下一页使用返回 offset，失败保留已加载项并允许重试。

原生和 Web 请求统一保留错误 `code`、`message`、`target_device`、`outcome`。网络异常未返回 outcome 时，已发出的写请求按未知处理；明确 `not_executed` 才能提示未执行。设备请求失败不等于本机登录失效，不能让一个远端 403 清除所有登录。

### 4.2 每设备事件恢复

现有事件只有 `sequence`，不含跨重启稳定 epoch；当前 coordinator 依赖 bootstrap 的 `instance_id` 清水位。远端不能借用本机 `instance_id` 判断目标是否重启。

采用保守复用：**远端每次重新建立 SSE 都开启新的本地同步代次，清除该设备旧事件水位与会话投影，重新获取原应用快照**。保留导航／本地描述并按需重读当前会话，不清本地草稿或置顶。流程为先订阅并有界缓冲事件，再读快照，再应用高于快照水位的事件；沿用已有 gap 恢复逻辑。新流就绪前，旧流和其晚到请求全部失效。缓冲达到既有预算则重取快照，不无限积累。

这样无需新增远端实例查询 DTO，也不在同机／远端之间共享水位。若 SSE 被取消或断开，UI 标记同步中／不可用；本机登录仍有效时按原有限重连策略恢复读取，绝不重放写操作。

## 五、项目、草稿与资源

### 5.1 项目浏览

复用 `register_workspace`、`get_workspace`、`list_workspaces`、更新、移除与恢复接口。远端目录使用现有 HostDirectoryDialog 及 `/host-files/list`、`select-directory`；本机原系统目录选择保持。

2026-10-16 按用户确认修正：撤销本节此前增加的独立项目 scope 和手动返回方案，当前实现待修复。

右栏沿用 ResourceTabGroup，只以正文当前 session／draft 选择显示组；当前项目目录从该会话／草稿取得，
文件仍通过既有 `host_file` 来源及 Host 文件接口读取。侧栏不再提供独立项目“浏览文件”入口。
移除固定右栏选择及其返回动作，所有正文导航入口共用同一资源组派生规则，不为每个入口另设恢复模式。
项目编辑／移除事件使相关目录描述重新核实，不把旧路径静默解释为另一项目。

现有 session locator、附件和工具资源协议保持不变。仅在本地 ResourceHandle／scope 中增加固定设备引用；`host_file` 是目标文件，`local_file` 是当前电脑资源，不能按路径长相互换。跨设备资源 key 必须包括目标，同一路径或相同 session ID 不能命中另一设备缓存。

### 5.2 草稿及首次发送

草稿表按设备分区，设备内继续使用项目／unbound key。设备内模型、智能体、Skill、MCP 候选通过原只读命令加载；远端不共用本机 SettingsStore 的可编辑配置或最近模型默认。

切设备时先检查目标独立草稿：若为空，可转移正文与未上传的本地选择；若已有内容，保留两份草稿并打开目标已有草稿，不隐式覆盖或合并。原项目引用和选中的目标配置清除／重新校验，不按名称匹配。移动附件选择时转移其唯一所有者，避免一份草稿发送成功后释放另一份仍引用的 selection。

首次发送沿用 manifest 与 materialization key，额外在本地操作记录绑定目标。发送或结果未知期间禁止切设备修改本次提交；取消只结束等待，保留原目标用于核实。已上传到目标的附件引用不跨设备复用，未上传文件选择可以继续属于本机客户端。

## 六、原生文件与 URL 适配

### 6.1 固定连接加固定设备

原生 `RuntimeTarget` 已在 invoke 时捕获 binding 并跟随取消。保留此身份保护，为资源调用额外携带可选目标设备；在原生参数解析／调用入口校验格式、能力和连接是否仍有效，并冻结到当前操作。不得调用 `begin_runtime_connection` 切换全局 Host 来实现设备选择。

沿用既有资源 HTTP helpers，在发起请求处统一加入目标。不要让每个资源处理器重复实现中心通信。原生调用仍向本机 URL 发送当前普通用户凭据；不能附带本机 bootstrap 特权去访问远端，也不把目标转换成任意 URL。授权最终由本机 Host 与目标 Host 检查。

| 操作 | 目标与处理 |
| --- | --- |
| 本机选文件、剪贴板图片暂存、selection 预览／释放 | 保留本机原生能力；不添加远端目标，不随侧栏切换清空 |
| 上传附件、首次物化、查询结果 | 原 streaming multipart 加固定设备；不改正文，目标只接收文件字节 |
| 项目／会话文件列表、stat、预览 | 原接口加设备，桌面原生与浏览器两条调用路径都核对 |
| 图片、缩略图、附件、工具／子任务产物 | 原 URL／原生读取加固定设备；预览缓存包含身份和目标 |
| 下载、导出、系统打开 | 远端读取经代理后保存到本机，再执行系统打开；取消删除未完成临时下载 |
| native-path、本地注册 URI、在源目录中显示 | 只允许真正本机文件；远端禁止调用 native-path，在菜单中提供下载或显示已下载文件 |

`copy path` 返回目标路径文字并注明设备，不把它当作本机可执行打开凭据。取消按原 operation ID 结束对应传输；原生操作登记包括连接代次与设备，不能因另一设备的标签关闭批量清理本机 selections 或全部 operations。

### 6.2 媒体与账号变化

媒体 URL 始终指向本机 Host，附固定 `target_device`；Cookie 场景继续附本机 `login_context`，token 不进入 URL。显式 bearer 的原生读取沿用原认证方式。临时 Blob URL、解码图片及预览缓存按原设备／身份释放，切账号后不显示旧用户内容。

保留既有 Range、取消、预览大小和临时文件预算，不新增文件持久镜像或整文件转为 base64 的通用路径。原生桌面文件传输按已有流式实现推进；粘贴图片原有字节传输限制继续保留。

## 七、终端与右栏生命周期

TerminalController 创建时捕获固定设备 client；getClient 不再返回侧栏当前对象。Shell 列表和终端 socket 使用同一目标，Open 首帧、输入／输出 ACK、resize、close 继续使用原协议。

远端终端创建等待建议初值 **90 秒**，本机保留 15 秒：远端存在首次准入等待（当前 35 秒）、通道接纳（10 秒）和目标创建等阶段；90 秒是 UI 的总等待上限，不提高 Host 各阶段超时或后台重试次数。收到失败立即结束，用户可随时取消。实施时核对 Shell 列表读取、WS 建连与 created 的整体预算，避免每个子步骤重新开始完整等待。

隐藏／切换 scope 只卸载视图，不 dispose controller；现有 xterm 输出消费与 ACK 保持，不能因为隐藏而让队列无限增长。真正关闭等待原 close 收敛，超时再断 socket。断线、撤权或登录切换结束该终端；重新打开是新 PTY，原输入不重放。

资源快照仅记录终端来源描述，恢复后显示“终端已结束”，由用户点击“重新打开”创建新进程，不在启动应用时自动执行 Shell。浏览器标签继续属于本机网络和原生 WebView，项目文件浏览不增加远端端口代理。F04 可沿本方案的设备资源引用接入，但权限、媒体和控制状态由 F04 自己管理。

## 八、本机偏好、置顶与旧格式

### 8.1 存储位置

扩展现有 DesktopPreferences，在当前身份 namespace 内增加本机置顶引用和必要的导入状态；设备项目展开、最近配置及资源 scope 在同一偏好结构内分区。原生层继续有界校验、写锁合并与暂存替换，保留既有 4 MiB 文档上限，不新建 JSON 文件或数据库。完整保存只有一个本机 owner，设备业务状态不能各自写整份布局。

置顶只记录 target、session ID、必要名称／状态提示和顺序，不存凭据或会话正文。置顶成功以本地保存成功为准，写入失败显示错误并恢复可重试状态。普通会话列表按本地引用排除已置顶项，不能再按远端 `is_pinned` 过滤，否则远端旧置顶会从页面消失。

新客户端的置顶操作全部本地化；既有直接 Host 登录使用其原身份／地址分区保存本机快捷入口，普通 Web 保持旧范围，不引入账号相关 localStorage 存储。组网设备选择仅对本机企业入口开放。

### 8.2 旧置顶过渡建议

以下过渡策略已在 M2 实现，并使用新建隔离数据验证；未对用户实际环境执行迁移：

1. 只在确认当前本机身份和原偏好分区后导入当前本机 Runtime 的旧置顶。直接登录远端的旧置顶不导入，也不遍历组网目录。
2. 使用已有 `list_sessions` 的活动会话分页，按返回原始条数推进 offset，收集普通会话 `is_pinned`。当前排序保证旧置顶连续优先；到首个非置顶或末页即可停止，不读取正文。
3. 导入记录与完成标记在同一次本机偏好保存中提交；成功前不标记完成，失败可重试，按目标／会话去重。导入期间暂缓本机置顶编辑，避免用户刚取消后被导入重新加入。
4. 不修改 Runtime 数据库，不清旧 `is_pinned`，不调用旧设置命令，不建立双写。旧客户端和 Web 仍可使用其原置顶；新桌面的本机置顶不回写它们。
5. 保留现有 Host 列表顺序和 offset，不在 UI 对单页重排序后冒充全局最近排序。旧字段仍可能影响普通列表的历史排列，但不再决定新客户端置顶区。若后续要求更换全局排序，应单独确认原列表契约，不顺手在本 Feature 修改查询语义。

导入只覆盖有效本机旧置顶；不可访问或已移除资源按原列表语义处理，不为恢复历史失效引用扫描数据库。退回旧客户端只能看到旧 Runtime 置顶，不承诺新本机置顶向旧版同步。

### 8.3 旧右栏描述

新增明确版本的本地资源快照结构；旧无设备 scope 仅在其原身份／Host namespace 内解释为原连接资源，禁止映射为当前侧栏设备。旧本机文件沿原本机规则恢复，远端 `local_file` 仍禁止恢复。无可靠身份、损坏或预算超限时保留原记录并提示无法恢复，不凭 ID 猜测归属。

本次右栏纠正后，快照只恢复所属会话／草稿的资源组和查看状态，不将保存的右栏 scope 恢复为独立显示目标，
不覆盖正文导航。已保存的独立项目描述不能重归到当前会话；实施时核对实际偏好，保留有效会话／草稿标签及无关设置。
本版不继续维护独立项目浏览和跟随会话两套模式。

布局宽度、主题、关闭行为继续沿原字段读取；只处理受影响的资源描述。实施时以旧格式样例核对序列化和回退行为，仅在所属实施步骤按已确认策略处理偏好，不以本轮文档编制执行迁移。新格式保存前保留可读取的原偏好备份，供升级失败恢复；不得以重置所有偏好替代适配。旧客户端可能在保存时丢弃新增字段，降级前需另存新版偏好副本；回退到旧数据只能恢复旧工作状态，不能声称双向兼容。

## 九、实施影响与验证边界

主要改动范围为 Desktop stores、runtime-client、native-bridge、会话侧栏／输入区／右栏、原生资源和偏好。复用 F01 设备查询、F02 代理参数与白名单，原则上无需新增中心表、网络帧或业务 DTO。若实现发现现有接口不足，先回到对应契约说明缺口，再决定修改，不伪造目标能力。

开发计划只安排直接相关类型／静态检查与短真实客户端闭环。重点检验：侧栏与正文不同目标、同名／同 ID 资源隔离、设备重启后水位归零、原生附件上传与产物打开、本机置顶保存及旧格式转换、当前会话／草稿项目文件浏览、终端隐藏／关闭／撤权。右栏纠正覆盖正文导航、草稿物化及重启恢复，确认旧固定选择不再覆盖当前组，隐藏终端归属和生命周期保持。只测受影响的旧本机和直连路径，不重复 F01／F02 全量回归。

M0 已完成实际前端与隔离双 Host 的读取联调及定向检查，结果和平台限制见[开发计划](开发计划.md)。各里程碑的实现结论及未测限制见开发计划；M0—M2 已确认，M3 实现与定向验证完成，等待用户人工测试。

### M0 实施边界

`NetworkDevicesStore` 在当前登录身份内持有设备目录，以及被侧栏或正文使用的设备投影／连接；无需再使用的远端连接及时释放，历史只保存带设备的引用。`RootStore` 保留唯一的本机连接、设置、资源和登录生命周期，正文派生到选中会话设备，侧栏派生到浏览设备。客户端检查代理能力后冻结目标，M0 阶段远端白名单仅放行读取；本机控制及原生资源路径不接受远端降级。

远端事件流每次重建均重置本设备投影和水位；断线清除该设备的内容，重新获取快照。快照前事件缓冲有上限，超限重新同步。账号生命周期只监听本机连接，远端错误不会退出本机登录。M0 当时暂停远端写入、文件、资源栏、终端及通知交互；本机现有资源 controller 保持生命周期，切侧栏不切正文或资源。设备登记状态在刷新目录时读取，用于排除本机；原直连 Host 入口不显示组网选择。

### M1 实施边界

每个被使用的设备上下文复用现有草稿、资源和引用 Store，组合“设备上下文 + 原资源 key”隔离缓存；渲染器随正文设备切换，未更改 Host 资源 ID。M1 仅保留进程内工作状态，偏好仍由本机 owner 保存；跨设备持久恢复由 M2 完成。正在编辑项目也属于连接使用者，关闭编辑窗口后才允许释放不用的设备连接。

会话／项目写入与原生资源调用固定原设备。原生 `RuntimeTarget` 保留 binding，资源方法增加设备头；本机原生证明不随远端请求转发，原生控制和 native-path 不开放到远端。资源错误保留目标与 outcome；首次发送结果未知和取消后沿用原 manifest 回查。会话引用仍携带来源 owner，跨设备切草稿前必须移除引用，避免将另一设备的会话 ID 发送到目标。

M1 补充 F02 准入：`prepare_custom_agent` 为既有只读依赖检查，供目标输入区准备智能体；不开放插件安装或全局配置写入。通知内容读取和跳转捕获原设备身份；反馈中心、设置与登录保持本机 owner。此为 M1 当时的范围；本机置顶与资源恢复由 M2 完成，远端终端由 M3 完成。
