# v0.32.0 F03 界面交互设计指导：桌面跨设备项目与会话

## 一、状态与目标

- 状态：**M0—M2 已获用户确认，M3 实现及定向验证完成，双平台测试包已完成，等待用户人工测试与 F03 完成确认**。版本整体仍在开发中，未进入 F04 实施。
- 任务：让用户看清正在浏览和操作哪台设备，沿用现有会话、项目、文件与终端界面；设备差异通过入口和资源归属表达，不增加全网会话树。
- 本文参考 frontend-design 技能进行布局取舍，并服从仓库前端规范及现有设计系统。设计示意中的设备、项目、会话名称均为虚构。

## 二、视觉与组件

沿用当前主题、字体及三栏布局。新增内容只占用侧栏一行设备入口、输入区一个设备选择器和必要的资源设备提示。所有文案左对齐，设备状态不做整块卡片；不为组网另加页面横幅或一排状态徽章。

| 用途 | 既有 Token／组件 |
| --- | --- |
| 背景、正文、辅助文字、边界 | `--ez-sidebar`、`--ez-text`、`--ez-text-secondary`、`--ez-border` |
| 选中与在线 | `--ez-primary`、`--ez-success`；离线用弱文字及明确状态文本 |
| 参考浅色值 | 背景 #f7f8fa，正文 #252932，辅助 #5f6673，边界 #e2e5eb，选中 #496cf2，在线 #249d65；仅说明现有主题，不写入局部硬编码 |
| 字体、字号 | 原应用字体；正文 14px、辅助 12px、弹窗标题 16px，使用既有字号 Token |
| 设备菜单 | `SelectionPopover`，系统图标、名称、选中标识；只列在线且启用设备 |
| 操作与说明 | `Button`、`Icon`、`Tooltip`、`DropdownMenu` |
| 项目展开及表单 | 原 `Collapse`、`TextInput` 和 HostDirectoryDialog |

设备入口及普通菜单项沿用默认 32px 控件高度，输入区沿现有同档尺寸。长名称省略并提供可访问的完整名称；鼠标悬浮与键盘焦点都能识别设备。设备菜单不显示在线标记；当前目标不可用时在内容区明确提示。暗色、浅色及用户当前主题均消费原 Token。

设计取舍：设备入口承担浏览范围提示，当前会话标题承担执行目标提示；不在每条当前设备会话旁重复设备名。跨设备置顶和右栏资源才添加设备提示，减少列表噪声。

## 三、侧栏设备入口

```text
＋ 新建会话
  助理会话
  智能体管理
  插件管理

⌄ 置顶
  报告整理                         取消置顶
  ▣ 接口排查                       取消置顶
    （悬浮：测试电脑）

▣ 测试电脑                        ⌄

⌄ 项目                       ＋  刷新
  ▸ demo-service
  ▸ notes

⌄ 独立会话                   ＋
  昨天的调试记录
```

设备入口始终位于置顶区下方、项目区上方；没有置顶时也保留在项目上方，不额外显示空置顶容器。本机显示“本机”，辅助信息可以显示实际设备名。其他设备显示名称；菜单仅列在线且启用设备，不追加在线文案。输入区设备触发器复用项目／智能体选择的高度、字体、间距和选中样式。

点开入口后复用选择浮层：

```text
搜索设备
────────────────────────
本机                              ✓
测试电脑
构建电脑
────────────────────────
刷新设备
加载更多                         （有下一页时）
```

本机固定第一项，其余从目录中筛选在线且启用的设备，保持原目录顺序。只有已加载目录可搜索时要标明“搜索已加载设备”，并保留加载更多；不能暗示已搜索未加载页。若实现采用逐页加载完整目录，搜索完成前显示加载状态。离线和停用设备不出现在可选列表中；已选目标掉线时仍显示原名称并保留会话、草稿和右栏归属。

选择后关闭浮层，只刷新下方区域。正文不跳回首页，也不自动选择新设备第一个会话。点击原设备置顶打开正文时，侧栏仍停留原浏览设备。

设备目录获取失败在菜单内显示“暂时无法获取设备，刷新重试”；本机仍可选择。权限变化导致所选设备消失时保留“设备不可用”的选中状态及切回本机入口，不静默退回本机后接收用户的远端操作意图。

项目和独立会话沿用原折叠、分页／加载更多方式；一页足够时不显示分页控制。当前页因置顶过滤后为空而服务端仍有下一页时保留“加载更多”，不显示“没有会话”。

## 四、项目与文件浏览

2026-10-16 按用户确认修正：取消独立项目资源模式和“返回会话／返回会话资源”入口。
现有实现待按[本版待修复项](../../开发计划.md#五现有功能缺陷修复)调整。

项目行保留现有展开、会话入口、新建会话与项目管理操作，移除会让右栏脱离正文的“浏览文件”入口。
项目展开箭头只展开会话列表；项目文件从当前会话／草稿的右栏现有项目标签进入。

```text
正文：测试电脑 · demo-service 会话  右栏：该会话的资源标签组
当前会话及输入框                   [项目文件] [README.md] [终端]
                                   src/
                                   README.md
```

右栏始终显示正文当前会话／草稿的标签组，不提供另一套资源选择状态或手动返回操作。
切换会话时同步展示其标签组；只切换侧栏浏览设备时，正文和右栏保持当前会话。
重启恢复的其他会话标签保留在各自所属组内，进入该会话时再显示，不能固定为当前右栏。
隐藏的终端继续遵守原生命周期，不因切换显示组而关闭或改变目标。

新建／编辑项目使用原表单；远端目录通过 HostDirectoryDialog 浏览目标设备，不弹本机系统目录选择器。目录弹窗标题为“选择目录”，紧邻标题显示目标设备。长路径允许复制和完整查看，不用截断字符串发请求。

移除项目沿用原说明和确认，不将操作描述成删除目录。目录不可访问、项目已移除和列表为空各自展示明确状态。

## 五、新会话与发送

新会话输入区排列：**设备 → 项目 → 现有模型及其他配置入口**。已有会话不提供可编辑设备选择，标题旁显示固定目标。

```text
新建会话

[▣ 测试电脑 ⌄] [项目 demo-service ⌄] [模型 ⌄] …

输入消息…
[需求说明.pdf  待发送] [截图.png  待发送]
                                                   发送
```

启动时默认本机；侧栏选择其他设备后点击“新建会话”，继承该设备。从项目的新建入口进入时同时带入项目。输入区切设备不修改侧栏选择；设备切换后项目回到目标独立草稿对应状态，目标模型等配置加载期间显示原控件 loading，不使用本机配置占位为已选择。

切到空草稿可带入正文和未上传本地附件，目标项目及配置重新选择。切到已有草稿时保留当前草稿、打开目标原草稿，显示“已打开该设备的草稿，原草稿已保留”，不弹强制确认、不覆盖已有内容。发送中或结果未知时禁用设备／项目切换，并在发送区说明原因。

附件沿用现有组件，分别显示“待发送／上传中／上传失败”。失败提供对应附件的重试或移除；结果未知展示“正在确认发送结果”，目标不可连接时展示“暂时无法确认发送结果”，提供“重新确认”，不把动作命名为“再发一次”。只有原协议已确认可重试时才恢复发送。

上传到错误设备的风险通过固定目标解决，不增加用户手动选择传输方式。所有资源和发送状态属于正文目标，即便侧栏正在浏览其他设备。

## 六、置顶

置顶在本机保存，可包含任意授权设备的普通会话。会话菜单及列表按钮继续用“置顶／取消置顶”，不要求用户理解保存位置；菜单辅助说明“仅保存在这台电脑”。

本机会话不增加设备图标；非本机会话左侧使用统一设备图标，悬浮／焦点说明设备名称。置顶排列按本机保存的顺序，新置顶放到末尾；本期不为跨设备增加排序拖拽。取消置顶后，当前浏览设备内的会话回到原项目或独立会话区；另一设备的会话在切到其设备后可见。

置顶离线时保留入口，点击显示“测试电脑已离线”，提供“重试／移除置顶”；失去访问权限和会话删除用各自文案，不一概说离线。普通设备目录列表和置顶列表互不覆盖。

首次本机旧置顶导入采用原区域轻量加载，不展示迁移向导。读取或保存失败时提示“旧置顶尚未载入，重试”，不能展示为空且宣称导入成功。具体过渡范围按技术方案执行。

## 七、右栏资源与终端

文件、图片及终端标签的辅助信息显示原设备和资源名；多个标签来自同一设备时可在组标题统一提示，单个跨设备资源仍须可辨识。终端内容上方固定显示设备和工作目录，不能只藏在 Tooltip 内。终端是否可输入以当前连接状态为准。

```text
[项目文件] [README.md] [终端 ×]
▣ 测试电脑   /srv/demo-service
────────────────────────────────
正在连接终端…                      取消
```

终端创建等待只显示连接状态和取消，不显示准入许可、WS 帧等实现细节。错误就近显示并提供“重新打开”；断开终端保留“已断开”，不继续表现为可输入。重启客户端恢复的标签显示“终端已结束”，点击“重新打开”才创建新 Shell。

隐藏右栏、切设备、切会话不关闭终端；点击关闭沿用当前终端关闭确认。确认文案说明会结束该终端，关闭后移除相应标签；不提示会停止整个远端 Host。正在关闭时不接受新的输入。

文件菜单只展示实际支持的操作。远端文件可“下载”“下载并打开”“复制路径”；只有已有完整本机下载副本时才显示“在下载目录中显示”，不能声称能从本机打开远端源目录。图片和文件读取失败就近重试，不清空整个右栏。

## 八、错误、键盘与窄窗口

| 状态 | 就近提示／操作 |
| --- | --- |
| Host 版本缺少代理能力 | 设备入口提示“需要更新本机 Host”；本机功能保留 |
| 已连接但尚未加载目录／会话 | 所属区域 loading，避免整窗遮罩 |
| 设备离线 | 显示设备名及离线，提供刷新／切换设备 |
| 权限撤销 | “你已无法访问这台设备”，停用其资源操作，置顶仍可移除 |
| 目标缺少模型等配置 | 在对应选择器说明原因，不自动用本机配置 |
| 本机偏好保存失败 | “本机置顶未保存，重试”，不误报目标请求失败 |
| 结果未知 | 保留操作目标与草稿，提供核实入口，不自动重发 |

选择器复用键盘上下导航、Enter 选择、Escape 关闭及焦点恢复；非本机图标和刷新／关闭按钮有可访问名称。设备菜单浮层使用原 portal，不通过提高任意 z-index 修补裁切。

窄窗口保持现有侧栏收起规则，设备与项目选择器可以换行但保持先后顺序，发送按钮与文本区仍可见；长名称不挤掉状态与箭头。当前会话的项目文件浏览不能强制改变窗口三栏宽度。

实现后检查关键默认、loading、空、错误、离线、焦点及超长名称状态；涉及浮层和终端时选取窄窗口及缩放场景验证。不为每种颜色、设备或页面排列制作全量截图矩阵。正式原生文件和终端交互需在实际 WebView 核对，单独浏览器预览不作为完成证明。
