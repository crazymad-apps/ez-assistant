1. 按 M0 → M1 → M2 → M3 推进；每步实现及定向验证完成后汇报，用户确认后进入下一步。计划确认后仅启动 M0。

3. 沿用原接口与 DTO；目标字段统一由接口层消费，不向每个业务处理器增加远程分支。中心仅处理路由、流控与连接生命周期。
4. 不新增业务数据库、第二份用户登录、会话镜像、文件缓存、任务队列或通用 RPC 平台；跨端协议夹具复用现有测试工具。
5. 只做受影响检查和新链路验证。M3 是前面能力组合后的增量检查及交接，不重新跑全部 F01 场景，也不机械重跑 M0—M2 已通过的用例。
6. 本轮计划不包含桌面工作区页面、远程桌面、安装包、共享中心部署、发布、提交或推送；已授权的其他交付范围和未完成事项各自保留。

## 四、里程碑范围与完成条件

### M0 普通请求代理闭环

**前置**：本计划获确认；读取 Rust 编程／架构规范、前端 TypeScript 通用规范及 Host、中心、协议、Runtime、Agent 系统相关约束。

**实施范围**：

- 接入 `x-ez-target-device`／`target_device` 的唯一解析与校验；保持本机默认，非法目标、头与 query 冲突、重复参数明确拒绝。补齐调用方识别代理能力的方式。
- 复用 F01 Source，按本机登录 ID、目标和能力匹配；目标保存已准备的访问上下文，禁止把普通许可当桌面许可或借原生权限。
- 在原 Host—中心 WS 实现协议 2、建流／接纳／信用／reset、HTTP 头及正文／FIN、流状态和有界公平调度。中心不解析 HTTP 内层；断连与原访问取消直接关闭所属流。
- 抽出两端共用的 Host 路由与命令准入；接入技术方案中的普通 Command 白名单及嵌套范围检查。旧本机／直接登录路径保持原规则，远端指令不再次代理。
- 目标调用正式业务处理器，校验真实客户端版本与用户域；保留原响应，代理故障区分未执行和未知结果，禁止写请求自动重试。
- 本步只开放已接通的普通 Command 传输；文件、SSE、终端待各自里程碑完成后启用，不能挂上返回空成功的入口。

**改动落点**：Host `http` 与 `access/registration/network`、中心 `host-devices`；确需客户端共享的目标常量、能力／错误 DTO 才进入 `assistant-protocol` 并同步 TS。优先复用现有依赖，不新建代理 crate。

**定向验证**：

- 两个新隔离正式 Host 和一个隔离中心，通过 A 原 `/commands` 查询 B 项目、创建或修改 B 会话并从 B 回读；同时核对 A 不产生对应业务记录。
- 已登记／未登记调用方、不同登录和不同用户隔离；无授权、过期访问、错误能力、伪造内部身份、第三跳和管理命令不能执行。枚举白名单及嵌套拒绝边界，普通业务选代表链路验证，不对每个透传命令重写一套 Runtime 测试。
- 并发打开／取消、旧连接迟到、撤权、目标离线与版本不兼容；写入已接纳但响应丢失时保持未知，不重复提交。
- Rust／TS 帧夹具覆盖边界长度、u64 精度、窗口溢出、重复头、半关闭顺序、reset 及额度释放；最小拥塞场景证明控制消息仍有调度机会。

**完成条件**：真实目标查询和修改可用；身份、目标、兼容和命令准入无法绕过；失败／取消有界收尾；原本机与直接访问完成相关定向回归。此时不能宣称文件、SSE 或终端已完成。

### M1 文件与事件通道

**前置**：M0 获确认；普通请求、双向流和取消已在正式 Host 链路成立。

**实施范围**：

- 开放原首次物化与已有会话附件入口，multipart 字节直接到目标 staging；沿用原 key、内容校验与提交，不在 A 或中心复制会话／落盘整文件。
- 开放技术方案允许的目录、文件、附件、工具／子任务资源、缩略图及 Markdown 导出；保留实际响应头、长度、Range 和预览能力，不添加断点上传承诺。
- 浏览器 GET 媒体通过目标 query 和本机账号上下文认证；原生调用沿用既有凭据方式。目标 URL 构造规则可供 F03 直接使用，不在本步建立桌面多设备状态。
- SSE 按原字节流转发，保留缺口、关闭和快照恢复语义；不合并设备事件、不持久化事件历史。
- 完成响应已开始后的异常中断、上传取消和未提交 staging 回收；消费者阻塞只限制所属流，传输 ACK 不代表业务提交成功。

**定向验证**：首次发送带文件与图片、已有会话附件及附件-only、预览与缩略图、产物／子任务资源、下载和导出各覆盖实际入口；核对目标归属与字节一致。使用明显超过传输窗口的有界测试文件检查内存、背压、截断／超限、取消及部分响应，不为验证制造大量磁盘占用。浏览器直接 GET 验证账号切换后的旧 URL 被拒绝。SSE 覆盖持续事件、慢消费者缺口、断开后原目标快照恢复，确认取消订阅不取消 Run。

**完成条件**：文件和事件均沿同一目标上下文正确工作；本机／中心不整包缓存；取消不会误删已提交数据；未知物化结果可用原 key 查询，缺口不会伪装连续输出。

### M2 远端交互终端

**前置**：M1 获确认；共享传输已经支持持续流、背压和目标固定。

**实施范围**：

- 本机终端 Upgrade 来源检查及首帧身份／版本校验先完成，再取得 Ordinary 访问；本机首帧凭据不透传给目标。
- 将原 socket 收发与已认证终端打开参数分离，桥接消息与本机 WS 共用同一执行循环、目录解析及 PTY Supervisor，不新建终端执行器。
- 开放目标 Shell 目录、终端创建、Text／Binary、resize、业务 ACK、Ping／Pong、错误与关闭；桥接信用和终端消费确认各自保留。
- 连接／许可取消和创建过程竞争均由现有 owner 收尾；不丢弃正在创建 PTY 的任务，不恢复旧 Shell 或重放输入。

**定向验证**：从 A 使用 B 项目／会话目录和 Shell，真实输入输出及 resize；慢输出与输入 ACK 约束、首帧非法／超时／版本冲突、目录失效、单终端关闭、撤权及断连后 PTY 回收。至少同时打开两条终端，确认关闭一条不误关另一条。本机原终端链路执行同等关键回归，不重复全量桌面测试。

**完成条件**：PTY 只在目标创建，消息边界与 ACK 保留，权限失效和断连不遗留终端；不把控制连接 Pong 当成远端终端仍可用的依据。

### M3 组合验证与 F03 交接

**前置**：M2 已获用户“继续”确认。

**2026-10-15 范围调整**：用户明确“简单测试下就行，不会全量回归测试，现在的测试结果不代表 F03 能用”。本步以一次短组合冒烟及接入约定核查收口，不执行原计划的完整故障矩阵、持续混合负载、跨机器与真实模型测试。未测项如实保留；F03 必须按实际界面接入链路验证，不能引用 F02 结果替代。

**实施范围与完成条件**：

- 复用既有正式 Host／隔离中心夹具，在事件订阅和一条真实终端保持打开时，并发上传小附件、修改目标会话和执行终端输入，再下载回读附件、观察事件并关闭终端。
- 确认目标归属、文件字节及关闭回收，调用端不产生对应项目、普通会话与附件；不重复 M0—M2 已通过的回归，不新增产品机制。
- 整理目标参数、代理能力发现、媒体 URL、终端 Open、错误和取消约定；核对现有客户端尚未接入的入口，将风险写入技术方案的 F03 交接节。

**边界**：本步只说明底层组合冒烟通过，不宣称长时间负载、公平调度上限、所有故障组合、跨机器／平台或真实模型已经通过。F03 的设备切换、项目／会话、附件、置顶与右栏资源需要在真实客户端接入后验证；F04 媒体不在本步范围。F01 M4 继续跳过。

## 五、验证入口与环境控制

| 范围 | 执行方式 |
| --- | --- |
| Host／协议 | 使用现有 Cargo crate 定向测试和静态检查；Host 包名 `assistant-runtime-host`。按修改范围执行 fmt、check／clippy，必要时同步协议 exporter；不默认全 workspace 全特性构建 |
| 中心 | 使用现有 typecheck／lint、单元测试及真实隔离集成测试；修改 HTTP 契约时再执行 OpenAPI 一致性检查，不因私有 WS 帧变化机械重生成后台 SDK |
| 客户端消费者 | 若修改共享 DTO／能力判断／URL helper，执行对应生产者、TS 投影与受影响消费者检查；产品页面接入仍归 F03 |
| 正式链路 | 新建 `.runtime-test/` 场景、独立中心与两个正式 Host Home；复用已有 F01 启动工具并核对目标，不复用旧场景用户数据 |

数据库操作按根规则先核对主机、端口、数据库、实际表与影响范围；一次性隔离环境与共享数据区别处理，不默认授权共享库迁移或清理。验证完成按实际影响核对数据和接口结果，但计数、日志和测试夹具不堆入流程文档。

共用受控 Rust 构建缓存，构建与使用同一二进制的运行验证串行；先检查磁盘余量，不为每个场景复制 target 或制作部署归档。仅文档阶段检查链接、路径、接口名称及各文档状态，不构建应用。
