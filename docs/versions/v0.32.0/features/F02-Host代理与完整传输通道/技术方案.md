## 三、客户端接口口径

### 3.1 原接口加目标设备参数

调用方发送远端意图前，必须通过本机既有能力查询确认 Host 支持目标路由；缺少能力时明确拒绝，不能把含未知设备参数的请求发给旧 Host，防止其忽略参数后执行本机业务。M0 使用原 `GET /capabilities` 响应头 `x-ez-network-proxy: 2` 声明目标代理支持，保留原 JSON DTO 和能力枚举不变；跨源显式凭据请求开放该头读取。F03 调用方必须先检查此头，缺失或不支持时停止远端调用；不能仅凭 HTTP 可连接推断支持代理。

业务 URL、方法及正文保持原样，新增统一路由元数据：

| 请求形式 | 目标字段 | 登录与版本 |
| --- | --- | --- |
| Command、普通 HTTP、multipart、通过 fetch 读取的 SSE | 请求头 `x-ez-target-device` | 沿用本机原认证、登录上下文和版本头 |
| 浏览器直接 GET 图片／PDF／下载、终端 socket URL | 查询参数 `target_device` | 沿用本机 Cookie／原生凭据规则；Cookie 媒体保留 `login_context`，终端继续首帧认证 |
| 本机请求 | 两者均省略 | 完全沿用原入口 |

两种字段同时出现必须相同；空值、重复字段或非法设备编号直接拒绝。只接受设备 ID，不接受中心地址、IP、Host URL 或用户 ID。中心及用户从本机已认证登录确定。显式指定本机当前登记 ID 时可归一本机路径，但必须先核实身份；缺失或失效的远端 ID 不允许落回本机。

本机 Host 以当前连接、**本机登录 ID**、目标设备和 Ordinary 能力查找已有 F01 Source。没有则调用已有打开访问流程；同一键的并发首次请求共享一次在途打开，失败后移除，不缓存业务结果。已有 Source 只有完成中心准入后才能接纳流，不能把安装中或等待 open 回执的对象当成可用许可。复用不能仅按企业 user_id，否则会混用不同本机登录的撤销边界。已经开始的请求固定 Source，不随侧栏切换改变。

沿用现有访问数上限、续期及 `CloseAccess`，不创建第二套租约。普通接口不要求 UI 先获得访问 ID；F01 已有打开／查询／关闭入口仍可用于显式访问管理，Host 内部复用同一集合。访问在登录失效、显式关闭、撤权、到期或断连时结束；本版不新增持久许可缓存。

### 3.2 媒体、路径和资源引用

资源 URL 始终指向调用方连接的本机 Host。F03 在现有资源 URL 构造器统一附加目标字段和本机登录上下文，携带会话／标签固定的目标，不临时读取侧栏当前选择。目标返回的资源 ID、相对引用和业务 DTO 原样保留，不通过搜索替换 JSON 或文件正文改写 URL。

URL 不携带访问 Token、中心凭据或目标登录材料。访问 ID 也无需进入 URL。带目标的资源响应使用 `Cache-Control: private, no-store`，避免账号切换复用旧响应；浏览器已解码资源的清理由 F03 标签生命周期处理。

本地文件上传时选择器产生字节，经本机 Host 流向目标；不能把本机绝对路径交给目标读取。浏览远端目录时路径由目标解析。本机操作系统打开远端文件须先通过下载得到本机文件，不能调用远端 `native-path` 后交给本机系统打开。

## 四、Host 分流、身份与可代理清单

### 4.1 分流顺序

1. 外部请求继续通过本机现有来源、认证及账号上下文规则。终端先完成本机 Upgrade 来源检查与有界首帧认证。
2. 无目标走原流程；有目标先匹配允许的方法、路由和命令，校验客户端版本及本机企业用户，取得对应 Ordinary 访问。
3. 普通 JSON 按原限制有界读取；`/commands` 解析既有类型检查具体变体。multipart 不预读整包，不提前创建本机用户 Runtime、附件 staging 或 PTY。
4. 经中心关联到目标的当前访问。目标从该访问取得本人 permit，再检查访问能力、状态、真实客户端兼容及同一允许清单。
5. 目标内部调用共享业务路由，保留用户域绑定、资源归属、大小限制及正文取消守卫。外部认证适配与可信内部入口分开装配；内部入口不监听端口，不生成伪造 loopback 请求，不转发本机凭据。
6. 目标业务请求携带不可从 HTTP 自报的内部来源标记；移除路由参数且禁止再次代理。来自 UI 的同名头不能构造内部来源。

Source 生命周期和 Target permit 生命周期共同控制流。F01 目标初始化使用 Host 当前版本，只能用于初始化；实际请求的版本声明必须取自本机入口校验结果。媒体缺省版本沿用原登录声明；终端使用 Open 中真实声明。目标不得用代理 Host 自己的版本替换它。

## 五、统一连接与业务流格式

### 5.1 协议与所有权

沿用 F01 每个 Host 到中心的一条 WebSocket、设备在线事实及现有访问许可。将未发布组网私有协议从 1 统一为 **2**，同步中心与两端 Host；不保留 F01 开发中间版本的双协议分支。版本不匹配明确停止组网接入并提示升级，本机业务仍可用；不以无穷重连替代不兼容状态。应用协议最低软件版本和企业 HTTP 协议是否调整在编码前按实际消费者核对，不能机械联动。

中心的流键为 `(access_id, stream_id)`，访问已绑定 source／target 当前连接对象；还须校验消息确由允许的一侧发送。stream_id 为源连接内递增 u64、不复用，文本控制消息用十进制字符串编码以避免 JavaScript 数值精度丢失；访问结束或连接换代后所有旧流失效。中心只保存路由、传输类型、窗口和关闭状态，不解析 HTTP 头、业务 JSON、multipart、SSE 或终端正文。

目标 Session 需保留已初始化的目标访问上下文（permit、capability、cancelled），不再仅让 permit 局部存在于续期任务。其 Drop／取消仍归原访问 owner，不安装第二份用户登录。

### 5.2 控制与载荷

原 F01 文本控制消息保持其职责；增补 `stream_open`、`stream_ready`、`stream_credit`、`stream_reset`。open 携带访问 ID、流 ID 和 `http`／`terminal` 类型，ready 仅表示已接受流及初始窗口，不代表业务成功。信用按每个有向链路独立管理，不能拿目标发给中心的信用直接当成中心发给源端的信用。

二进制消息外层固定为：`version:u8 | kind:u8 | access_id:16 bytes | stream_id:u64 | payload_length:u32 | payload`，多字节整数使用大端；UUID 按原 16 字节表示，不转 Base64。version 为 2；长度与实际消息必须一致。kind 固定：1 请求头、2 响应头、3 正文、4 正常半关闭、5 终端打开、6 终端文本、7 终端二进制、8 终端 Ping、9 终端 Pong、10 终端关闭。未知 kind 拒绝。M0 仅开放 kind 1—4 和 `http` 流；M2 已启用 kind 5—10 和 `terminal` 流。

请求头载荷为受限 JSON，包含原方法、相对路径、允许的业务 query／headers 及真实客户端声明；响应头载荷为状态及允许的 headers。它们只由两端 Host 解释。中心仅据流方向及类型检查允许的 kind、长度、预算和顺序，不读取载荷内容。终端 Open 载荷删除本机 bearer／login_context，由有效访问上下文承担目标认证。

HTTP 顺序：open → ready → 请求头一次 → 零到多正文 → 请求半关闭；目标可提前响应，响应头一次 → 零到多正文 → 响应半关闭。双向分别计数，既可边上传边拒绝，也可在请求结束后保持 SSE。半关闭不删除反向流；双方完成才释放流。

同一方向的头、正文和半关闭必须保序，不能把 FIN 当成高优先级控制越过正文。reset 则允许丢弃尚未发送正文并立即结束。中心不把中断合成为正常结束；断连、reset 和正文正常结束是三个不同结果。

非法身份或越权访问帧关闭连接；合法流的格式／窗口错误重置该流。已关闭流的迟到帧丢弃、不重新建立状态；从未 open 的流不能通过 data 创建，重复 open 不允许复用 ID。每访问保留最高已接纳流 ID 以阻止旧 open 重放，不维护无界历史墓碑。控制速率与错误次数也受限，持续违规关闭连接。

### 5.3 有界缓冲与调度

以下为首轮实现参数，**尚未通过混合负载实测**；调参须同时保持字节及并发上界。

| 项目 | 初值与边界 |
| --- | --- |
| 业务分块 | 每帧 payload 最多 32 KiB；头载荷最多 16 KiB；终端消息保留原 16 KiB 上限 |
| 每流每方向窗口 | 最多 64 KiB；每帧按 `max(256, 30 + payload_length)` 计费，覆盖固定头和小帧队列成本；窗口耗尽停止读上游 |
| 并发流 | 每访问最多 16、每 Host 连接最多 64、中心总计最多 512；原访问数限制继续有效 |
| 数据预算 | 每连接最多 4 MiB、中心整体最多 64 MiB；队列、预留信用、在途写及重组缓冲全部计入，预算不足拒绝新流 |
| 控制预算 | 沿用 F01 的 16 KiB 单控制帧／256 KiB 缓冲；独立于业务数据预算，信用更新允许合并 |
| 调度 | 每发一个业务块检查控制队列；业务按流轮转，禁止一次排完整文件；控制消息也限速，不能反向饿死数据 |
| 超时 | 建流 ready 10 秒、ready 后请求头 60 秒、请求正常半关闭后等待响应头 60 秒（提前响应则不再计时）、持续有待发送数据却无消费进展 30 秒；没有待发数据的 SSE／空闲终端不按此计时 |
| 已有连接期限 | F01 Ping 15 秒、Pong 45 秒、写超时 5 秒；访问 20 秒复核／最长 45 秒有效窗口继续有效 |

M0 采用每流双向预留窗口，单连接实际最多 32 流、单访问最多 16 流、中心最多 512 流；因此先触发字节预算而非更宽的并发限额。普通 Command 保留既有 1 MiB JSON 入口上限与业务反序列化；传输预算不表示 Runtime 处理器不分配业务对象。

信用只在下一阶段实际接纳并释放本阶段计费缓冲后归还，不能在收到数据时立即无限补充；操作系统与 WS 发送缓冲另有上限。源、中心、目标各自遵守预算，中心不得把全部业务数据排进现有 control queue。消息重组在校验长度前也必须受 WS max message/frame 限制。

读循环不等待某个业务消费者而停止处理心跳／撤销；预算已用尽仍继续发送的对端属于违约。正常慢消费者先停本流读取，超时只 reset 本流；物理 WS 不可写时按现有超时关闭整个连接。单 TCP 仍有队头阻塞，不宣称媒体／文件繁忙下绝对隔离。

## 六、HTTP、文件与 SSE 的一致性

### 6.1 头部与正文

请求允许 Content-Type（含原 multipart boundary）、Content-Length、Accept、Range、If-Range、If-None-Match、If-Modified-Since 及正式客户端版本声明。其他原业务确实使用的字段先核查再加入清单，不整体复制 HeaderMap。移除路由／本机账号上下文字段及 Authorization、Cookie、Host、Origin、Forwarded／X-Forwarded-* 和逐跳头；Connection 点名的头也移除。

响应允许 Content-Type、Content-Length、Content-Disposition、Content-Range、Accept-Ranges、ETag、Last-Modified、Retry-After 及原接口实际使用的安全响应头（如 X-Content-Type-Options）。Cache-Control 由本机代理限定为 private/no-store，CORS 由本机入口生成。Set-Cookie 不透传；3xx 重定向首版明确拒绝，不能跟随到目标外网或把目标地址交给浏览器。

代理不压缩、不解压、不改编码；默认不向目标声明压缩能力，不支持的 Content-Encoding 拒绝。保留字节计数：有 Content-Length 时完整结束必须匹配，无长度时必须收到明确正常半关闭才算完成。不把 WS Close 当作 HTTP EOF；已向客户端发送响应头后发生异常，通过 Body 错误中断响应，不在文件或 SSE 后追加 JSON 错误。

### 6.2 上传、下载与 SSE

- 首次物化与附件仍由目标原 handler 进行准入、multipart 解析、staging、校验与提交。本机／中心只保留窗口内字节；目标已有单附件 1 GiB 与首次物化最多 32 项等限制继续执行，不等于允许代理预分配这些大小的内存。
- 取消上传会关闭该流并传播到目标请求正文；目标未提交 staging 按现有 guard 清理。已提交部分不自动补偿删除，查询原物化 key／附件／输入结果。
- 下载、预览和导出直接回传。当前 `resources.rs::preview_path` 有单段、有上限的 Range；不扩展为所有下载支持 Range，不把缩略图和直接原图特例当成同一能力。其他路由继续返回原状态和响应头。
- SSE 原样传递字节和业务事件，不合并设备序列。目标广播缺口仍由原 `stream_gap` 处理；代理缓冲失败断开流，客户端向同一目标重订阅并读取权威快照。无需中心事件日志、额外序号协议或断点重放。

## 七、终端适配

UI 仍连接本机 `/user-terminals/socket?target_device=…`。本机保留现有连接数／握手限额和 5 秒首帧认证期限；认证成功后才等待目标准入，不能把 F01 首次接入最长等待塞入首帧读期限。目标未通过许可、兼容与目录检查前不创建 PTY。

把既有终端执行循环所需的消息收发抽为 Host 内部适配，实际调用方只有本机 WebSocket 和桥接终端流。先提取已认证打开参数（source、size、shell、客户端声明和可信 permit），再进入同一 Supervisor 创建及清理逻辑；不新建远端 Shell 执行器，不在目标监听临时 WS 或伪造 bearer。

Open 后保留现有 Text／Binary、Resize、Ack、InputAck、Created、Error 与 Close 语义。桥接信用仅限制传输，不代替 UI 消费 ACK 或 PTY 写入确认。终端 Ping／Pong 作为终端流消息贯穿两端；本机不凭自己的存活替目标持续应答，避免掩盖目标卡死。复用现有 10 秒 Ping／30 秒空闲检测，连接控制心跳独立工作。

许可撤销、断连、目标服务退出或终端关闭都取消对应 PTY，并等待现有 owner 收尾。创建 PTY 的阻塞任务仍须取得结果并交给 owner，不能直接丢弃 JoinHandle。重新连接只允许新建，不回放输入、不恢复旧 PTY；切换侧栏不主动关掉已固定目标的终端。

## 八、错误、撤销与恢复

沿用目标业务响应，不把目标业务错误变成桥接错误。新增代理错误使用既有 HTTP 错误外形的 code/message 扩展，另含 target_device 和 outcome（`not_executed`／`unknown`）；`not_executed` 仅用于本机未转发或目标明确拒绝执行的情形；不为失败再创建持久回执。

| 情况 | HTTP 状态／稳定 code | 结果含义 |
| --- | --- | --- |
| 非法路由目标、字段冲突 | 400 / `network_target_invalid` | 未转发 |
| 无目标权限或操作不开放 | 403 / `network_access_denied`、`network_operation_denied` | 未转发 |
| 本机账号已变化 | 沿用原认证／账号上下文错误 | 未转发；旧请求不切到新账号 |
| 无目标连接 | 503 / `network_target_unavailable` | 发送前可确定未转发 |
| 能力或版本不兼容 | 409 / `network_incompatible`；兼容详情复用原错误结构 | 未执行 |
| 流／缓冲配额不足 | 429 / `network_busy` | 未转发；不替用户排无限队列 |
| 流协议错误、转发途中断连／撤权 | 502 / `network_stream_failed` | 已开始转发且无确定业务结果时为 unknown |
| 等待建流／响应头超时 | 504 / `network_timeout` | 尚未转发或收到目标明确拒绝为 not_executed，其余为 unknown |

这些状态适用于尚未发送响应头时；已经开始的 HTTP 响应直接异常结束，终端用现有错误／关闭通知，不能改写已发状态。`unknown` 不表示业务失败，不允许代理自动重放写请求。只读刷新、首次物化查询和 Input 幂等仍走原业务入口。

中心撤销访问先禁止新流并停止转发，然后通知双方；Host 原取消信号关闭所属流和待发缓冲。旧连接迟到帧不能连接到新 Source。取消流不等于取消已接纳 Run，更不等于目标用户全局退出；停止 Run 必须调用原业务命令。中心重启按 F01 规则重新登录／准入，不恢复旧流。

日志只记录脱敏访问／流关联、设备、类型、字节数和错误码，不记录 URL query 原文、正文、文件清单、终端内容或凭据；不接入模型调用证据采集。

## 九、模块落点、验证与下一步

Host 路由分流和允许清单归 `http`，业务流 owner、编码及调度归现有 `access/registration/network`；中心扩展 `host-devices` 的连接与访问 owner。需要拆文件时按这些归属拆，不新增公共代理服务 crate。客户端目标字段常量、稳定错误投影若需跨产品复用才进入 `assistant-protocol`，内部帧和队列保持传输私有。

Rust／TS 两端用同一组有限协议夹具核对编码、越界、关闭顺序及取消，不需要新生成器。暂不引入额外依赖；优先现有 Axum Body、Tokio 有界通道／取消令牌、tungstenite 和中心 ws。内部业务路由须复用现有 HttpState 所有权，避免 network 与 Router 持有彼此强引用形成循环。

后续开发计划按四个有实际结果的步骤拆分：

1. 普通 HTTP 完整链路：统一目标字段、协议与准入、最小流控、中心转发；正式目标项目／会话查询和一次实际修改可回读，管理入口被拒绝。不得只交付空帧脚手架。
2. 文件与 SSE：首次物化、已有附件、浏览器媒体、资源读写流和事件取消；覆盖字节一致、截断、慢消费者及原目标恢复。
3. 终端：复用目标 PTY，验证输入输出／ACK、目录、resize、关闭与撤权，确认本机终端不回退。
4. 组合链路补验及 F03 交接：在并发真实业务下补验 F01 心跳、续期和定向撤销；验证断连未知结果与预算，核对媒体 URL／账号切换；按适用平台安排跨机器检查。

正式 M0—M3 及确认状态见[开发计划](开发计划.md)；不额外加入 F01 全量验收。每步按风险做定向验证，已有 F01 管理 UI 流程只在受影响时回归。Windows／Linux 原生运行、跨机器与真实模型链路仍为未测项，不能凭本机双 Host 模拟宣称通过。使用新建 `.runtime-test/` 环境和受控共用构建缓存，不部署到共享中心或重打安装包来替代验证。

现已按开发计划完成 M0—M3；M3 按用户要求收窄为简单组合冒烟，持续混合负载与跨机器仍未验证，不将窗口初值视为性能承诺。

## 十一、M0 实现落点

原 `/commands` 外层增加目标分流，位于本机用户 Runtime 激活及正文处理之前。无目标沿原路径，有目标仅接受企业用户及普通命令白名单。M0 目标头仅承载 POST、`/commands`、JSON 类型和真实客户端声明；不接收第三跳路由或源端认证头。目标调用原 `commands::handle_command`，没有新增内部监听、Runtime 镜像或命令 dispatcher。

Source 在原集合内合并同登录／目标／能力的在途准入；等待者全部取消会终止打开，单个等待者取消不影响其他请求。流 owner 绑定原访问取消信号，reset、撤权、断连直接结束对应传输；已接纳的业务写入不自动回滚或重放。M0 仍拒绝文件、事件和终端目标请求，交付范围随 M1／M2 扩展。


## 十二、M1 文件与事件实现落点

`http/routes.rs` 提取原文件和媒体路由装配，两端准入后由目标内部 Router 调用同一组处理器；内部入口不监听、不再解析来源凭据，也不再次代理。M1 请求头承载方法、相对路径、受限业务头和真实客户端声明；当前开放路由没有业务 query，`target_device`／`login_context` 在本机消费，其余 query 拒绝。multipart boundary、Content-Length、Range 和条件读取头保留，逐跳头提名的业务头与 Content-Encoding 明确拒绝。

上传 future 与响应接收由同一 HTTP owner 并行驱动；目标提前拒绝时，完整响应可先结束未完成上传。每次正文读取／信用等待有界，不给整个大文件设置固定总时限；SSE 空闲持续等待，仍由访问取消和原缺口事件结束。响应声明长度时最后一字节等 FIN 后交付，零长度响应在交付响应头前读取 FIN，避免 HTTP 消费者读足长度后掩盖断流。完整响应前中断不回落本机、不自动重放。

目标附件及首次发送用 `TempPath` 保有所有 staging 文件的取消清理责任；文件移动到正式 Blob／会话路径后，清理只针对原暂存路径。目标沿用原 Runtime key、权限、内容校验与提交。CORS 开放实际所需的 Range／条件读取请求头，并暴露文件响应元信息；响应继续经过本机原有 `no-store` 规则。

## 十三、M2 实现补充：远端终端

- `http/proxy` 只解析目标并交回原终端 Upgrade 路由，保留来源检查；`user_terminal/socket` 在本机完成首帧认证及版本检查，再选择本机执行或桥接。不在本机创建目标项目、会话或 PTY，不向目标传输 bearer、Cookie 或 login_context。
- 原 `socket` 拆出已认证打开参数与唯一执行循环；`transport` 适配本机 WS／桥接消息，`bridge` 负责源端双向转发和目标准入。目标建流工作交给原终端 Supervisor 持有，连接任务只撤销流，不能取消正在等待的 PTY 启动结果；取得进程后按原 close 路径取消并等待回收。没有新增线程模型、终端执行器或终端存储。
- 中心与 Host 按流类型校验消息顺序：终端请求首帧为 kind 5，响应首帧为 kind 6，之后允许 kind 6—10；HTTP 仍只接受原序列。Open／Text 最大 16 KiB、Binary 最大 32 KiB、Ping／Pong 最大 125 字节、Close 为空；原终端输入最大 16 KiB 和控制 JSON 最大 8 KiB 仍在入口／执行循环校验。二进制消息保持边界，不拆成 HTTP 正文。
- kind 10 表示该方向正常关闭，发送方等实际写出及另一方向关闭；异常 reset 取消对应流。源端上下行各自推进，只持有一条待写消息，不用额外队列复制输出。原 64 KiB 窗口及控制优先调度保留，业务 InputAck／Ack 独立于桥接信用。
- 原终端 10 秒 Ping／30 秒失联及写入预算保留；Ping／Pong 贯穿目标和客户端，设备控制心跳不延长终端存活。断线／撤权不重放输入、不恢复旧 Shell；单终端关闭不撤销整个访问。
- `/user-terminals/shells` 已加入两端 HTTP 白名单并调用目标原 handler；`/user-terminals/socket` 使用原 URL 的 target_device（或唯一目标头），兼容声明仍位于原 Open 首帧。该能力供 F03 接入，尚未增加设备选择或资源标签 UI。

## 十四、F03 接入交接与未验证边界

2026-10-15 用户要求 M3 只做简单测试，明确当前结果不代表 F03 可用。本步只完成短组合冒烟；不重复此前回归，不补完整故障／性能矩阵，也不将同机多 Host 当作跨机器结果。原生 Windows／Linux、跨机器、持续混合负载及真实企业模型调用仍未测，后续按实际接入风险选择验证。

| 调用方需要接入的事实 | 已实现约定与接入注意 |
| --- | --- |
| 能力发现 | 对本机 `/capabilities` 读取 `x-ez-network-proxy: 2` 响应头；现有 JSON DTO 未新增该字段。未识别能力时不能携带目标后盲发给旧 Host，避免旧端忽略目标并执行本机业务 |
| 默认本机与远端业务 | 本机省略目标；远端在原业务请求使用 `x-ez-target-device` 或 `target_device`，值为目录返回的设备 ID。重复或冲突目标拒绝；每个已打开会话／标签固定目标，不能随当前侧栏选择漂移 |
| 设备目录与管理 | 目录仍向本机 `/host-network/access` 提交 `list_devices` 和 offset。登录、能力查询、登记、插件等本机控制入口不携带远端目标；不能在全部请求头上无差别添加目标 |
| 资源与上传 | 复用原资源接口和 multipart；本机选择文件后传字节，经本机 Host 代理，不能让目标读取本机绝对路径。媒体 URL 指向本机 Host，带固定 target_device；Cookie 方式还需本机 login_context，不在 URL 中放 Token。远端文件的本地打开先下载，不能套用 native-path |
| 事件 | `/events` 与对应设备业务请求绑定同一目标和登录；缺口／重连后读取该目标快照。切换侧栏不应销毁另一个已打开标签所需的连接；取消订阅不会取消已接纳 Run |
| 终端 | 同一 `/user-terminals/socket?target_device=…`，首帧仍为原 Open，含真实客户端版本及本机 bearer 或 login_context。source 中的项目／会话属于目标；桥接、身份交换和 PTY 管理由本机／目标 Host 完成，UI 不连接企业中心 |
| 错误与恢复 | 除 code/message 外保留 target_device 与 outcome；unknown 不能当作未执行，也不能自动重发写请求。物化用原 key 查询，其他操作从目标权威状态恢复；断线终端只能新建，不恢复旧 Shell |

源码核查发现以下 **F03 尚未实现的接入工作**，不是底层冒烟的通过项：

- `RuntimeClient.ts` 尚无固定组网目标；现有 `/capabilities` 消费只读取 JSON，须保留能力头；命令、资源与事件需要按业务范围附带目标，本机登录与控制仍保留原范围。现有错误解码仅保留 code/message，需接上目标与结果未知语义。
- `ClientResources.ts` 的桌面文件／附件分支调用原生桥接；只改浏览器 fetch 不足以覆盖桌面端。现有 `runtime_connection` 的切换会撤销旧绑定并清理资源，不能直接复用为侧栏设备筛选；原生文件传输与资源 URL 同样要携带会话／标签固定目标。
- `TerminalSocket.ts` 目前按本机 URL 建连，创建等待为 15 秒。F01 首次目标准入有独立等待阶段，F03 需要核对远端终端等待与取消反馈，不能只加 query 后沿用本机超时并宣称可用。
- 本机置顶配置、所选设备的项目与独立会话、独立于会话的项目文件浏览、右栏本地标签状态、设备断线提示与快速切换后的迟到响应，均须在 F03 实现后用真实操作验证。

本步没有提前修改 F03 页面或客户端行为；客户端可用性、跨设备交互和文件／终端标签体验以 F03 实际联调为准。
