## 二、目标、范围与现有基础

### 2.1 能力目标

授权用户通过电脑 A 的本机 Host 使用电脑 B 上本人的项目、会话、附件、文件与交互终端。客户端仍向 A 发请求；A 经企业中心桥接到 B，B 使用正式业务接口执行并返回结果。用户不需要开启 B 的直接入站访问或向 A 提供 B 的登录密码。

F02 完成传输与身份闭环，通过正式隔离 Host 和协议客户端验证；沿用 F01 已有验证结果，按新增业务链路补齐身份与传输的联合检查。正式桌面端的设备选择、跨设备投影、草稿、本机置顶及资源标签由 F03 接入；F02 必须交付其可直接使用的完整通道。

```text
本机请求：客户端 → 本机 Host → 本机用户域
远端请求：客户端 → 本机 Host ⇄ 企业中心 ⇄ 目标 Host → 目标本人用户域
                              复用 F01 的 Host—中心 WS／可选 WSS
```

### 2.2 纳入范围

| 能力 | 本 Feature 的结果 |
| --- | --- |
| 目标路由与准入 | 每个请求或长连接固定中心、用户、目标设备和业务能力；本机分流或单跳代理 |
| 普通 HTTP | 项目、会话、消息、Run、审批、快照及会话所需能力读取，保持现有业务语义 |
| SSE | 持续交付目标用户域事件、缺口提示和关闭；恢复仍读取原目标权威状态 |
| 流式文件 | 首次发送、已有会话附件、图片预览、缩略图、产物、文件读取与下载，支持取消和有界传输 |
| 交互终端 | 目标 Shell、创建、输入输出、resize、ACK、错误与关闭，断线按现有规则回收 PTY |
| 生命周期 | 许可撤销、登录失效、连接中断、慢消费者和并发负载均能收尾，副作用未知时可核实 |
| 后续交接 | 向 F03 提供目标绑定、资源访问及错误语义；与 F04 共用身份和撤销边界 |

### 2.3 明确非目标

- 通用业务 P2P、SSH、跨中心访问、任意 URL 代理、离线投递和跨设备自动委派。
- 会话迁移、文件目录同步／挂载、独立跨设备文件编辑服务及服务端设备间文件搬运。
- 持久终端、终端断线续接与输入重放。
- 远端 Host 停止／重启、模式与中心绑定修改、安装升级、插件安装管理及设备授权管理。
- 远程桌面画面、输入、WebRTC、TURN 和平台采集程序；这些由 F04 设计，不塞入普通文件通道。
- 新的登录体系、业务数据库、会话镜像、持久传输队列或中心业务正文采集。

### 2.4 现有实现及最小增量

以下基于 2026-10-15 工作树静态核查，表示复用基础，不表示 F02 已实现。

| 核查入口 | 已有能力及本次缺口 |
| --- | --- |
| Host `access/registration/network/`；Center `host-devices/network.ts`、`connection.ts` | 已有单连接 owner、控制协议、心跳、重连和有界控制队列；中心当前拒绝二进制帧，尚无业务流映射和混合负载调度 |
| Host `access/enterprise/network.rs`；Center `host-devices/access.ts` | 已有目标本人登录复用／首次接入、访问许可和取消；需要将实际业务流绑定到该许可 |
| Host `http/routes.rs`、`auth.rs`、`commands.rs` | 已有认证、版本和用户域装配；需在无关本地业务域装配及流式正文消费前分流，并细分混合命令准入 |
| Host `http/events.rs` | 已有有界广播、`stream_gap` 和关闭；没有可据此承诺的中心事件历史或透明断点重放 |
| Host `http/materializations.rs`、`attachments.rs`、`resources.rs`、`resources/` | 已有 multipart、目标 staging、内容校验、受控资源读取及流式下载；代理应保留这些能力，不能另建远端附件体系 |
| Host `http/terminals.rs`、`user_terminal/`；Desktop `runtime-client/TerminalSocket.ts` | 已有首帧认证、版本声明、单 socket 单 PTY 和 ACK；需要双向传输适配及真实关闭链路 |

最小新增是连接内的业务流关联、受控路由和有界传输调度。一个访问许可下可以同时有查询、SSE、下载和终端，各自有独立关闭时机，因此需要独立流生命周期；它不成为持久业务实体。删除这些流关联后，现有控制消息无法承载并发响应和取消，所以该增量必要。身份、会话和附件事实已经存在，不重复建立。

## 三、使用路径与目标边界

### 3.1 打开授权设备

1. 客户端沿原有登录方式连接本机 Host，通过 F01 入口获取本人设备目录。
2. 用户选定目标后，本机 Host 使用当前企业用户身份申请普通业务访问；本机未登记也可以作为调用方。
3. 中心核对设备、用户关系及当前连接，目标 Host 通过 F01 准入并准备本人用户域。
4. 后续业务流引用有效访问并固定目标；目标离线、未授权或能力不兼容时明确失败，不回落到本机执行。
5. 用户切换浏览设备不改变已经发送请求、已打开会话或活动终端的目标。关闭单条流不取消同许可下其他流；显式关闭访问才收尾所属流。

本机请求继续使用本机接口，不绕中心访问自己。调用方既有登录凭据只用于本机认证；设备秘密、中心用户 Token、目标登录凭据不交给 UI，不通过 URL 携带。

### 3.2 HTTP 业务操作与准入范围

代理范围按实际操作语义确定。技术方案须列出精确路由、方法和命令变体的清单，未知入口默认拒绝；新增业务接口不能因为挂在相同 URL 下而自动获得代理能力。

| 操作类别 | 首版策略 |
| --- | --- |
| 项目查询、新建、编辑、移除与恢复；会话及消息查询、创建、输入、归档、Fork、删除等 | 按原业务能力代理，目标重新核验用户及资源归属 |
| Run 查询／取消、审批、问答、Goal、计划和会话上下文操作 | 按原接口语义代理；取消 Run 必须使用原业务停止入口 |
| 创建或使用会话所需的模型、智能体、Skill／MCP 等目录与可用配置读取 | 只读获取目标实际可用事实；技术方案逐项核对必要字段及敏感数据边界 |
| 会话级模型选择、执行配置或能力激活 | 复用目标已存在能力，不扩展为远端全局配置或安装管理 |
| 全局模型／服务商配置写入、插件安装与配置文件上传、全局能力管理 | 首版不开放；F03 若提出额外需求，先确认范围并补设计和验证 |
| Host 配置、模式／中心绑定、登录退出、设备登记、Gateway 管理、停止／升级 | 本机或原入口处理，不能通过通用业务代理访问 |
| 原生绝对路径解析和系统打开 | 不作为远端代理能力；远端内容使用受控预览／下载，不把远端路径交给本机操作系统 |

`/commands` 同时包含 Runtime、HostAccess 和 DeviceGateway；即使是 Runtime 分支，也包含停止 Host 等管理动作。仅检查 URL 或顶层 scope 不足以放行。两端 Host 在进入业务分发前核验同一允许范围；本机可对有界 JSON 做必要解析，中心仍只处理桥接外层。

现有 Runtime 置顶字段的迁移属于 F03。本 Feature 不把 `set_session_pinned` 作为跨设备置顶入口；目标返回旧置顶字段也不改变本版置顶归客户端本机的方向。

### 3.3 远端消息与事件

HTTP 响应保留关联 ID、业务结果和业务错误，目标 Runtime 决定接纳与持久化。中心收到数据或本机完成发送都不能表示目标已经成功执行。

SSE 按目标设备及当前用户独立订阅，保留现有事件类型、顺序、连接注释、保活、缺口及关闭语义。代理不合并不同设备的事件序列，不创建中心事件日志。目标广播发生缺口时原样交付缺口提示并结束流；代理自身无法继续交付时明确断开，客户端重新订阅原目标并读取快照或既有查询结果。任何游标和恢复状态都不得跨设备复用。

### 3.4 首次发送、附件与资源

首次发送固定目标设备、原提交标识及附件清单。multipart 正文从本机 Host 流经中心到目标 Host，由目标执行既有准入、staging、大小及内容校验、去重和业务提交。本机 Host 与中心不额外保存整文件或复制会话；目标的正常 staging 不属于代理缓存。

已有会话附件、附件-only 输入、图片预览、缩略图、工具产物、子任务资源、Markdown 导出及受控目录／文件读取采用同一目标绑定。下载正文保持字节一致，文件名与内容类型按受控响应规则保留。取消、截断或校验失败不能报告上传／下载完成；目标清理未提交 staging，已提交附件或输入通过原业务查询核实，不自动删除作为补偿。

浏览器直接加载的图片、PDF、下载等资源也必须可固定目标，并沿用本机有效登录及账号上下文校验；不能依赖只能由普通请求设置的自定义头覆盖所有媒体场景。资源 URL 的承载方式和响应中资源引用的处理在技术方案统一确定，不能泄露目标凭据或要求浏览器绕过本机 Host。

目录和文件权限由目标 Host 判断，路径按目标平台解析。原接口的大小、预览及范围读取能力逐项核对：代理保留已存在能力，不把流式传输等同于断点上传或所有下载均支持 HTTP Range。

### 3.5 用户终端

终端通过本机入口创建，Shell 列表、工作目录和 PTY 均来自目标。握手及首帧先验证当前本机用户、目标访问和双方协议，完成前不得创建 PTY。不得把本机首帧 Token 原样当成目标凭据。

文本控制、二进制输入输出、resize、输入／输出 ACK、错误及关闭按现有终端协议传递。桥接流控确认只说明传输缓冲可继续使用，不能提前代替终端消费 ACK。单个终端关闭只回收其目标 PTY；连接中断、许可撤销或目标退出必须关闭相关 socket 并触发现有 PTY 收尾。

重连后需显式新建终端，不重放旧输入，不声称恢复原 Shell。侧栏切换及其他请求失败不主动关闭仍有效的终端。

## 四、身份、所有权与生命周期

| 责任方 | 权威职责及允许持有的状态 |
| --- | --- |
| 客户端 | 当前选择和请求所属目标；只访问本机 Host，不管理组网连接和中心凭据 |
| 本机 Host | 核验客户端身份、目标绑定、允许路由、当前访问许可；持有本侧请求及流缓冲 |
| 企业中心 | F01 的设备与用户授权、当前连接及许可；关联两端流、执行限额与撤销，业务载荷按字节转发 |
| 目标 Host | 重验可信接入、普通业务能力、非原生来源与用户域；调度正式处理器、文件句柄及 PTY |
| 目标 Runtime | 会话、Run、队列、审批、附件引用与持久化；原并发和恢复规则保持唯一权威 |

每条流必须属于当前有效许可及两端当前连接。不能只凭可猜测的访问 ID、流 ID 或 UI 自报用户编号准入。目标普通业务入口拒绝桌面专用许可，已代理请求不得再次代理到第三台设备。

目标接入不借用 loopback、bootstrap 或原生管理权限；既有直接访问开关只控制原直连路径。组网登记不自动开放入站端口，关闭直接访问也不替代已经明确授权的组网准入。

F01 已实现双端每 20 秒复核、最长 45 秒访问窗口；F02 直接消费其取消和到期信号，不另设业务租约。中心撤销后阻止新流并停止相关转发；Host 收到撤销、断连或本地许可到期时关闭所属流。大流量不得绕过许可检查或延长授权期限。

源端退出、设备授权撤回只收尾对应远程访问；不通过全局退出误停目标已接纳 Run。目标用户主动退出、账号停用／删除及中心重启引起的身份失效继续按既有规则处理。中心重启后设备重新在线不代表用户登录恢复，用户可能需要重新登录。

## 五、流控、失败与恢复

### 5.1 有界传输与公平性

普通业务复用 F01 的同一 Host—中心连接。数据有界分块，每流、每连接及中心整体均有内存和并发预算；读取速度受下游消费能力约束，不能只限制帧大小却累计无限队列。

控制消息、许可续期、撤销和心跳需要可调度机会，多个业务流应公平推进。单条慢下载首先限制或关闭自身流，不无限占用整个连接；连接已经不可写或协议被破坏时可关闭整条连接，并报告其全部流失败。共享 TCP 中已发送字节仍可能阻塞后续控制，设计不承诺完全隔离，技术方案须确定块大小、窗口、超时及可验证负载边界。

中心不解析会话／文件／终端正文，不把这些字节送入现有模型调用证据采集。日志仅保留脱敏关联、目标、通道类型、字节数和失败原因，不保存凭据、请求正文、文件路径清单或终端内容。WS 可用、WSS 可选，不叠加 Host 间端到端加密；“不解析正文”不等于中心技术上无法读取。

### 5.2 失败结果

| 情况 | 对调用方的语义与恢复路径 |
| --- | --- |
| 目标离线、权限不足、不支持代理或协议不兼容 | 明确拒绝；不能显示成功、空数据或自动改为本机执行 |
| 两端业务处理器返回错误 | 保留目标业务错误及请求关联，避免伪装成中心网络故障 |
| 已开始转发但未收到确定结果即断开／超时 | 执行结果可能未知；向原目标查询，代理层不重放写请求 |
| 首次物化或输入结果未知 | 复用已有物化查询、输入幂等及附件事实；没有可靠查询能力的操作明确保留未知状态 |
| 下载／SSE 已输出部分内容后失败 | 结束流并暴露失败；不在文件或 SSE 正文中拼接普通 JSON 错误，不伪造完整结束 |
| 单流取消／消费者离开 | 释放本流传输、文件句柄及未提交资源；不把传输取消等同于撤销已提交业务 |
| 终端断线 | 关闭所属终端并回收 PTY；再次使用创建新终端 |
| 中心重启或 Host 换连接 | 所有旧流结束；重新认证及准入，新连接不接管旧流、不复用旧数据队列 |

桥接层不增加自动重试副作用的机制。只读刷新及 SSE 恢复由调用方按原语义重新发起；明确停止任务使用目标原停止接口。错误码、HTTP 状态及流已开始后的终止方式由技术方案形成统一契约，不能依靠匹配文案判断是否可重试。

## 六、跨 Feature 与兼容边界

F02 向 F03 交付：原业务接口的目标路由方式、访问许可使用方式、支持操作清单、媒体资源引用规则、终端接入方式、能力／兼容判定和结构化失败语义。F03 在自己的设计中处理多设备 UI 状态、迟到响应、本机置顶和本地标签，不要求 F02 建立客户端投影仓库。

F04 沿用 F01 身份、能力区分、有效窗口和撤销；桌面打开／关闭及协商入口在 F04 方案中具体接入。F02 保证控制连接扩展边界，不预建未使用的媒体字段、空接口或平台能力声明。

技术方案须分别核对客户端—本机 Host、本机 Host—中心、中心—目标 Host 及目标业务协议兼容。F01 目标初始化使用当前 Host 版本声明，不能据此证明真实调用客户端兼容；F02 需传递并校验实际调用所需声明，禁止以代理本身版本掩盖旧客户端／旧目标差异。

预计不新增业务表或修改 Session／附件持久格式，访问和流只存在内存；若实施需要新增持久化，必须重新说明必要性和范围。现有未发布 F01 中间协议直接统一到本版最终形态；已发布客户端、中心能力和存储影响仍须先核查，再确认是否调整最低兼容版本。旧中心缺能力只禁用组网代理，不以无穷重连替代升级提示。

## 七、验收标准

F02 使用两个正式隔离 Host、一个隔离中心及多个用户进行验证，Home 位于项目 `.runtime-test/` 下新建目录。数据库检查和写入遵守根安全规则。至少覆盖真实跨机器普通业务链路；同机多个 Home 只能证明隔离逻辑，不能冒充跨机器验收。各项以真实业务效果判断，不只检查桥接帧往返。

1. 已登记与未登记调用方均能按授权访问目标本人用户域；跨用户、跨中心、伪造许可、过期许可、错误能力和第三跳被拒绝。本机及既有直连回归通过。
2. 同名项目／相同形状资源标识下，查询、新建、修改、会话输入和审批落到固定设备与用户域；本机未产生远端业务的副本。
3. 混合 `/commands` 只开放逐项允许的业务操作；停止、配置、登记、Gateway、插件安装和原生路径入口不能经代理提权。
4. 正式目标 Runtime 能创建并执行远端 Run，模型请求使用目标自己的有效企业登录；源端退出／设备权限移除不误注销目标登录，目标自身退出仍正确收尾。验证真实模型链路时使用单独确认的测试配置。
5. 首次发送、已有会话附件、附件-only 输入、图片及缩略图、工具／子任务产物、文件读取、Markdown 导出和下载可用；内容及所属关系正确，浏览器媒体也经本机 Host 加载。
6. SSE 连续输出、缺口、断开及快照恢复成立；多设备事件不串写，慢观察者不阻塞目标 Agent 执行，取消订阅不取消 Run。
7. 上传／下载采用有界传输；大文件、慢消费者、取消、截断、超限和响应丢失有确定结果或明确未知结果，未提交 staging 可回收，不自动重放或错误删除已提交数据。
8. 终端首帧认证、目标 Shell／目录、文本与二进制、ACK、resize、关闭和断线回收完整；重连不重复输入，不恢复旧 PTY，单终端关闭不影响其他终端。
9. 并发文件、SSE、普通请求和终端负载下，内存及队列受预算约束，心跳、续期和撤销可推进；单流拥塞的失败范围、共享连接断开的影响均可核验。
10. 撤销、用户退出、中心重启、设备停用及连接替换能停止所属实际数据流；迟到响应不能复活旧许可／旧流，其他用户和设备不被错误清理。
11. 部分响应、未知写结果与授权失效对调用方可区分；首次发送和输入恢复沿用目标权威事实，无重复会话或重复副作用。
12. 版本／能力不兼容明确拒绝；验证中心不解析或采集普通业务正文，资源与凭据不从不受保护入口泄露。向 F03 交付的正式协议足以使用上述能力。

2026-10-15 用户明确跳过 F01 M4；本节按新增链路和实际改动风险安排，不重新执行一套 F01 全量验收。跨机器与 Windows／Linux 原生运行尚未完成，须在后续计划保留实际状态。具体负载阈值、平台矩阵及执行顺序由技术方案和开发计划确定。未测项目如实保留，按验收确认处理；F02 验收不代替 F03 桌面或 F04 媒体验收。

## 八、关键取舍与后续设计

本草案建议按上述范围形成完整普通业务通道，保留原接口及目标权威状态；通用代理严格限制管理能力；控制与业务共用 F01 连接，通过流预算和调度处理拥塞；断线通过原业务查询恢复，不增加持久重放机制。这些取舍随功能设计审阅确认。

本 Feature **需要独立技术方案**，涉及跨层协议、鉴权、传输、兼容及生命周期，不能直接据本文件编码。技术方案必须收敛：

- 精确可代理路由／命令清单，目标路由元数据与媒体资源绑定形式，以及双端认证／业务分发顺序。
- 访问与多流的归属和回收，HTTP、SSE、上传下载与终端的映射及帧校验；未知流、越权帧和迟到帧的处理。
- 分块、信用／窗口或其他最小背压机制、每流／连接／全局限额、公平调度、超时、取消及关闭顺序。
- 请求／响应头允许范围、逐跳头与 Cookie 处理、重定向策略、正文长度／截断判断、资源 URL 和实际 Range 能力。
- 终端首帧身份转换、真实客户端版本声明、PTY owner 的接入方式，避免新增另一套终端执行器。
- 结构化失败、已输出响应的异常结束、未知结果恢复和脱敏可观察性。
- 组网协议及能力协商、已发布接口影响、现有依赖复用和跨机器／平台验证边界。

F02 不新增产品页面，**暂不单列界面交互设计指导**；向调用方提供的状态与错误语义在技术方案明确，正式交互由 F03 承担。若后续发现必须提前修改用户流程，再按实际范围补充。用户在技术方案形成后明确“继续”，已据[技术方案](技术方案.md)编制[开发计划](开发计划.md)，M0—M3 已确认，按收窄范围完成简单冒烟与交接；F03 已进入功能设计，尚未实现；F01 M4 不再作为前置，后续按 F02 里程碑逐步实现与定向验证。
