## 二、现有实现与最小增量

| 已核查实现 | 本次采用方式 |
| --- | --- |
| Center `src/identity/service.ts` 的串行写入、事务审计、内存 Token／LLM key 与撤销通知 | 登记管理写入复用短事务和权限复核；用户凭据仍由唯一 IdentityService 签发，不引入 JWT、刷新令牌、第二套登录表或 Redis |
| Center `src/app.ts` 的 Fastify HTTP 服务；工程已有 `ws` 依赖 | 同监听增加 Host WebSocket upgrade 入口；显式验证握手身份，不能假设 Nest HTTP Guard 自动保护 upgrade；不复用模型上游 WS 的连接 owner |
| Host `host_configuration.rs`、`access/enterprise/`、`user_domain/` | 复用中心绑定、本机管理校验、当前用户凭据及用户域；设备发布配置归 Host 配置，不落到某个用户的业务设置 |
| Host `supervisor.rs` | 组网连接是进程级受监督子系统；故障降级，不停止本机 Host；读写和重连任务归该子系统持有并等待收尾 |
| Host `device/identity.rs` 与 `user_domain/services.rs` | Gateway 实际以 `user_home` 装配，身份属于用户域。不能复用为整个 Host 的组网身份；只复用适用的私有文件保护方法，不要求生成 Gateway TLS 证书 |
| Host `access/enterprise/mod.rs` 的每用户唯一当前登录 | 保持这一权威事实；远端访问不把调用方密码或 Token 直接安装为目标当前登录，具体接入见第六节 |

必要新增只有：中心的设备登记及设备—用户关系、Host 级设备身份文件、两端组网连接 owner，以及实际入口所需的协议。设备不是现有用户或 Gateway 终端，身份、生命周期和持久化均不同，不能只往用户表加设备名。

实现就近放在 Center／Host 各自的组网模块，不新增通用传输框架或独立 crate。Center 复用已有 `ws`；Host 出向异步 WS 客户端拟显式依赖锁文件已有的 `tokio-tungstenite` 系列，实施时核对版本和 TLS features。仅有 Axum 入站 WS 或测试用 `tungstenite` 不代表已具备产品出向连接。

## 三、身份与持久化

### 3.1 三种身份

| 身份 | 生命周期与用途 |
| --- | --- |
| Host 安装标识 | 随 Runtime Home 保存，正常重启不变；关联同一安装的申请，不依赖机器名、IP、MAC 地址或当前用户 |
| 设备登记标识及秘密 | 每次新登记独立产生；待登记到获批沿用，注销后不能复活；秘密只证明对应设备，不代表用户 |
| 企业用户身份 | 沿用中心 ID 与不可复用用户 ID；调用者必须持有有效企业登录，设备在线不能代替登录 |

Host 首次显式申请前生成安装标识、随机登记标识和 32 字节随机设备秘密，先原子保存，成功后才发申请。中心保存秘密摘要，Host 私有文件保存原值；设备凭据不传给 UI、不出现在 URL、日志、审计或普通设备详情。这里的随机凭据是接入认证，**不增加业务载荷加解密**。

拟新增 Host 根目录下 `network/identity.json`，保存安装标识及当前申请／登记的中心 ID、登记 ID、秘密和本机接入意图。接入意图与身份材料一起原子更新，避免“退出成功但重启自动重连”；中心地址仍以 `host.toml` 为唯一来源，不在身份文件再存一套可独立修改的地址。缺少身份文件时不自动申请，损坏时提示重新登记，不按名称认领旧设备。

Gateway 文件仍留在用户域。组网私有文件使用现有平台权限保护和原子写入手段，权限建立失败则不发布凭据。正常用户登录不生成登记材料，不修改本机监听设置。

### 3.2 中心最小存储

拟新增两张表，最终名称和迁移号在实施前核对唯一迁移账本：

- `host_devices`：登记 ID、安装标识、显示名称、平台／Host 版本、原申请人 ID、申请处理状态、启用标志、凭据摘要以及必要申请／处理时间。待登记与已登记是同一条记录，不另建申请表。注销保留失效记录供旧引用识别。
- `host_device_users`：登记 ID 与用户 ID 的唯一关系。普通访问由关系存在表示；若确认桌面权限分离，则在该关系保存查看／控制两个固定权限值，控制必须包含查看，不另建 RBAC 或策略表。

同一安装最多一个未结束登记（待登记或已登记），用唯一约束维护；拒绝、取消、注销后允许新的登记 ID。新申请不复用旧设备引用。申请者或授权用户删除时不删除设备，不按同名新用户重绑；申请人按既有审计方式保留 ID，授权关系清理纳入用户删除事务及通知。

设备当前在线、连接对象、心跳时间和活跃访问只放内存。最近联系时间首版只提供本进程观察值，中心重启后可未知，不为历史显示逐心跳写库。中心 ID 复用既有单例，不在每条设备记录重复维护。

设备审批、分配、启停和注销与审计同事务，进入现有身份写入串行段，段内重新验证管理员和原状态。授权编辑提交所见的原用户集合及权限，服务端规范化后比较；冲突要求重载，不新增 revision 字段或用粗粒度更新时间猜测冲突。通知在提交后触发，网络等待不占事务。

## 四、登记闭环及接口职责

### 4.1 从申请到确认

1. Desktop／Client 通过现有本机 Host 管理入口发送申请意图。Host 核验本机管理权限、当前企业用户及已绑定中心；远程桥接不能调用本机登记管理。
2. Host 保存申请身份，再向中心提交登记 ID、安装标识、设备秘密、名称及版本。使用当前用户 Token 准入；中心不从请求中的申请人编号确定身份。
3. 中心在事务内验证用户、当前申请和安装唯一性，保存设备秘密摘要。完全相同的登记 ID／身份重试只返回原申请；秘密或安装身份不符拒绝，不覆盖原记录。
4. Host 使用设备凭据建立控制连接。中心以数据库事实回复待登记状态；申请人退出不自动取消申请或结束控制连接。
5. 管理员选中待登记项，提交名称和可用用户。登记状态与授权集合同事务提交；允许空集合，不默认全企业或管理员可用。
6. 中心向当前连接通知状态变化；Host 查询当前登记状态更新展示。离线审批有效，在线状态仍为离线；重连查询当前登记状态，不重放历史审批事件。

申请请求结果丢失时，以原登记 ID 和秘密查询结果；若中心确实不存在记录，用户登录仍有效时才重试原申请。已拒绝／取消／注销的旧 ID 返回原终态，不能靠自动重试创建新设备。新申请必须是新的显式操作。

### 4.2 接口分工

以下是拟定接口职责，路径在 OpenAPI 实施时统一，不把未实现接口加入发布契约：

| 能力 | 本机 Host 职责 | 中心职责 |
| --- | --- | --- |
| 申请登记 | 核验本机管理证明与当前企业登录，保存申请身份并提交中心 | 用户 Token 准入，设备身份用于绑定和幂等；不允许从管理页面虚构在线设备 |
| 查询本设备登记状态 | 向中心查询并向 UI 返回可显示状态；申请结果核实和重连恢复复用同一查询 | 按设备凭据返回自身登记状态，不能借此列出其他设备或访问用户业务 |
| 撤回申请／退出组网 | 核验本机管理证明；撤回申请，或按下一节先停止本机目标接入再请求注销 | 按设备凭据撤回自身申请或注销自身登记，返回处理结果 |
| 管理列表、审批、用户分配、启停、注销 | 不承载企业后台管理 | 现有管理员规则；读写均重验，不靠前端隐藏按钮 |
| 本人可用设备目录 | 以当前用户身份查询并交付 UI | 只返回本人授权的设备及必要状态 |
| Host 统一 WS 接入 | 持有连接与认证材料，不向 UI 暴露秘密 | 同中心身份及协议验证；设备模式与仅调用模式见第五节，不通过 URL 携带秘密 |

登记状态查询是一项能力，调用链为 UI → 本机 Host → 中心；两层入口不是两套登记状态业务，不另设“设备本人快照”接口。中心持有登记权威事实，本机未申请、接入意图和连接故障由 Host 补充展示；中心不可达时不能将本机旧显示值当作最新登记结果。

设备通知只表明“需要刷新”或携带当前登记状态，不提供离线事件日志、可靠消息表和通知重放队列。离线期间修改的最终结果由同一登记状态查询恢复。

### 4.3 停用与退出的差异

- **管理员停用**：保留控制连接及重连，阻止成为业务目标；中心再启用可通知到 Host。停用不等于设备离线。功能设计早稿“停用取消重连”据此修正。
- **本机退出组网**：先持久关闭目标接入意图、取消目标访问，再请求中心注销当前登记。中心不可达则保留原凭据用于之后仅执行注销，不恢复目标接入；待处理撤销清楚显示。显式再次申请前先核实旧登记终态。
- **注销／拒绝／取消**：旧设备凭据不能接入业务；若收到明确终态则停止旧身份自动重连。中心允许原凭据查询自身终态以确认结果，不能借此恢复访问。
- **仅访问别的设备**：无需把本机发布为目标；目标接入关闭不禁止当前已登录用户主动访问其他授权设备。

2026-10-16 用户修订：切换中心不等于退出组网，不注销旧中心的登记，也不要求旧中心在线。Host 在既有 `network/identity.json` 中按中心 ID 保留各自的登记材料及意图；只连接当前配置中心，其他中心在断开后按现有心跳转为离线。切回时复用原登记，授权与终态仍以中心最新事实为准；主动退出／撤回只操作当前中心，不清理其他中心材料。

登录设置仍只有模式与地址。Host 在既有配置保存入口通过公开 `GET /api/info` 读取目标中心 ID 和协议范围，成功后随配置 CAS 保存；地址变化但 ID 相同复用登记，ID 不同使用对应登记，无记录时等待用户主动申请。地址相同也允许明确保存重新核验，以支持中心实例重建；保存失败保留原配置，不尝试注销、删除或迁移用户数据。切换个人模式无需访问企业中心。旧单中心身份文件在读取边界归一化为中心索引，读取不落盘，后续原子保存保留全部材料；损坏或重复身份拒绝覆盖。

发送旧设备凭据前，通过同一公开信息接口核对目标中心身份；WS 首帧仍继续校验。此检查只用于中心路由与误配置防护，不替代 HTTPS 的服务端认证；HTTP／HTTPS 仍可选。中心的 `center_id` 直接读取现有中心身份事实，不新增数据表、中心目录服务或身份缓存；旧中心缺少此字段时明确要求配套更新，不向未核实的地址发送登记凭据。

本机登录配置读取不访问中心。中心登记同步等待期间仍响应有界的只读状态请求，配置写入继续由原 Access actor 串行处理，不新增配置副本。保存后沿用既有重启流程，清除旧连接；用户数据仍沿用既有中心 ID／用户 ID 隔离。

## 五、统一 WebSocket 与在线状态

### 5.1 接入与所有权

M1 在中心现有 HTTP 监听增加 `/api/host-network/connect`。Host 从中心 HTTP／HTTPS 地址分别派生 WS／WSS，保留已有部署路径前缀。WS 完整可用；WSS 按部署选择，不强制证书，不叠加自定义隧道加密。

身份在 upgrade 接纳前校验；接纳后 5 秒内完成中心身份、协议和接入模式确认，成功前不报告在线。设备模式使用登记 ID 与设备秘密；中心重启后直接从持久登记恢复认证，不借用已失效的申请人 Token。

仅调用方 Host 可用当前有效用户 Token 建立临时连接，不建设备登记记录，不出现在设备目录；该 Token 只准入连接，不能为后续所有用户授权。每条业务流重新携带自身受保护的用户凭据，由中心独立验证。临时连接不能接收入站设备业务。

每个 Host 对当前中心只维护一个连接 owner。已有设备连接时直接承载合法调用；临时连接后来获批登记时重新认证并受控切换，不维持第二条心跳。原流按断线规则收尾，不假装无缝迁移。设备凭据失效但用户仍有效时，也只有显式出向业务需要才可作为调用方重新接入。

中心内存保存登记 ID 到当前连接对象的映射。所有关闭、超时、通知回调比较对象身份，只能移除自己的映射，不新增持久连接代次。旧连接仍有效时拒绝相同设备的新连接并报告冲突；旧连接超时／关闭后才可重连。复制完整身份文件无法识别物理机器，异常按注销重登处理，不默认后连者抢占。

### 5.2 心跳与资源参数

以下为 M1 控制连接的工程默认值；完整业务混合负载仍由 F02 验证，不作为吞吐性能承诺：

| 项目 | 拟定规则 |
| --- | --- |
| 建连／认证 | 各阶段有界，总连接建立预算 10 秒；upgrade 后协议确认最多 5 秒 |
| 心跳 | 中心每 15 秒尝试 Ping；仅保留一个未完成探针，匹配 Pong 才确认响应；探针待回期间不重复发送并推迟期限 |
| 判离线 | 最后有效 Pong 起 45 秒内未获得新响应即关闭；首次从认证完成计时；关闭／读写失败立即离线 |
| Host 检测中心 | 45 秒未收到有效中心 Ping 则关闭重连；业务帧和本地写成功不能替代中心心跳 |
| 重连 | 1、2、4、8、16、30 秒封顶退避，加入小幅随机抖动；稳定连接 60 秒后复位，停止／终态取消定时器 |
| 控制消息 | 单条至多 16 KiB，待写控制队列总量 256 KiB，单次写等待最多 5 秒；超限／超时关闭连接并触发统一回收 |

使用单调时钟和独立超时检查，不能在等待业务写入时暂停心跳期限；睡眠唤醒只重建连接，不补发积压探针。Pong 必须对应当前连接和探针，旧帧无效。时间界限含正常事件循环调度误差，不承诺进程被系统冻结时仍按墙钟立即执行。

F02 业务数据采用有界分块，在每块之间调度控制消息，且同时限制应用队列及 socket 待写缓冲。控制优先不能消除 TCP 已写入字节的队头阻塞；不得将整份文件单帧写入，也不能只增加控制优先队列便宣称已解决。具体数据块、每流／每连接预算和公平性由 F02 负载验证确定。

中心没有用户 Token 时设备仍可在线；在线只表示控制连接可达。Host 用户 Runtime、PTY 和媒体各有自己的状态与回收，不能拿 Pong 给用户续权或给客户端已断开的终端续命。

## 六、用户访问与目标登录接入

### 6.1 访问准入

本节准入仅适用于企业组网访问。既有通过 Host 地址直连的 HTTP／SSE／WS 入口继续沿用原有来源校验、远程访问开关和登录规则，不检查设备登记及组网用户分配；登记成功不自动开放直连，设备停用／注销及组网授权撤回不撤销直连登录。用户账号与退出仍遵循既有生命周期规则。

每次企业组网访问固定中心、目标设备、当前用户和能力。中心在短串行边界验证当前用户 Token、设备状态、用户分配及当前目标连接，成功才创建所属访问。业务正文仍原样转发，中心只解释认证与路由外层。

目标 Host 的企业组网入口只接受当前已认证中心连接派发的访问，核对自身登记和主体，随后进入既有企业用户域。客户端自报的 `user_id`、普通请求头或设备凭据都不能直接产生 AccessPermit；桥接来源明确标记为远程，禁止获得 loopback／原生管理特权。

F01 交付访问检查及撤销可观察结果，F02 消费它构建具体业务流；不为每个文件接口再建另一套认证。既有直接访问、本机管理和企业退出规则各自保持。

### 6.2 无需重复输入密码的接入闭环

现有 Host 为每个用户保留唯一 `CenterLogin`，模型调用实时读取其中 Token／LLM key。只传用户编号不能启动完整用户域；把调用方的整份登录复制到目标则会把退出和模型凭据错误绑定到另一台 Host。因此采用**中心核验后，为目标建立自己的普通企业登录**：

1. A 的本机 Host 使用现有用户 Token 请求访问 B；中心验证用户与 B 的授权，B 取得可信访问主体。A 的密码不传输，A 的 Token／LLM key 不作为 B 的当前登录保存。
2. B 已有该用户有效当前登录时直接复用，远程访问不替换它；每条 A→B 访问仍单独受 A 的 Token 和设备授权约束。
3. B 尚无有效登录时，由 B 在该次已准入访问内请求中心签发该用户的普通 Token／LLM key。中心再次验证原访问仍有效且来自 B 的当前连接，签发结果只交付 B。设备凭据不能单独指定任意用户换取登录。
4. 签发复用 IdentityService 现有内存凭据生命周期及审计，仅增加受控签发入口；不保存用户密码，不新增登录表、任务级凭据或通用委托 Token。B 沿现有每用户唯一状态安装结果，再装配本人用户域及模型配置。
5. 签发期间若 B 已完成本机登录，本次在途接入取消，撤销未采用的新凭据；下一次显式接入复用新登录，不得用迟到兑换结果覆盖它。原访问取消或 B 退出导致该操作失效时，同样不安装迟到结果。锁内比较捕获的对象／取消句柄，不持锁等待网络。
6. B 后续显式本机登录仍沿既有规则更新当前凭据。B 显式退出仍终止 B 上该用户全部访问和任务；不会自动重试兑换来撤销用户的退出。之后一次新的显式访问可重新接入。

同一目标用户的首次接入共用一个受监督初始化操作，不由并发业务流各自签发登录。签发响应必须关联当前操作；发送失败时中心撤销本次未交付凭据，结果未知不自动连续重试。成功交付也不允许迟到结果重新打开已撤销的访问。

A 退出使 A 的访问失效，不新增全企业退出，也不通过共享凭据误注销 B。已经由 B 接纳的后台 Run 沿 B 的现有用户生命周期继续；移除设备访问权关闭对应远程通道，不调用全局 `end_user`。账号停用、删除、中心重启及 B 自身退出仍执行既有完整收尾。

这是一项新增接入路径，需要在 F01／F02 共享接口落地前确认，并完成正式 Host 的身份接入定向验证；不能因为接口转发成功就宣称模型调用、退出和后台任务已经闭环。F01 验证当前登录复用／首次建立及并发退出，F02 再验证真实远端 Run 和模型请求，不将核心身份问题拖到 F03 界面联调。

## 七、撤销、生效时限与恢复

- **中心提交**：授权移除／设备停用／注销在提交后立即阻止新访问，取消中心对应活跃访问；通知匹配的目标与调用方，不能清理别的用户或设备连接。
- **目标收敛**：通知到达即撤销对应许可。为覆盖漏通知和直连桌面，活跃授权采用目标侧最长 45 秒的有效窗口，30 秒内请求中心复核；中心返回必须属于当前访问，超时不续权。通过同一组网 owner 的定时调度管理，不另建逐用户心跳服务。设备 Pong 不延长许可。
- **状态表达**：管理保存成功代表中心已生效；目标收到撤销或许可超时后才确认目标已收敛。中心控制断开时立即停止桥接流；桌面即使媒体仍通，也只能在现有许可窗口内继续，F04 必须消费相同到期信号。
- **既有身份复核**：保留现有企业用户复核，其负责用户本身的有效性；新增的设备许可只负责用户—目标—能力范围。两者任一失效即拒绝访问，不能互相续期或反复重建用户状态。
- **单次登录退出**：当前中心 `onRevoked` 主要按用户／全局通知，单个 Token 的 `logout` 不发布同等事件。实现须在既有凭据撤销提交路径增加仅针对该凭据所准入访问的取消通知；不能调用 `revokeUser` 冒充单次退出，也不能假设已有监听足够。原始 Token 不出现在公共事件或日志中。
- **中心重启**：登记与分配保留，设备重新认证；用户 Token／LLM key 按现状全部失效。设备可能在线而用户需要重新登录，这不是登记失败。
- **业务重连**：只恢复连接及当前状态快照，不重放写请求、终端输入或媒体控制。新连接不接管旧流；F02 按原接口处理未知结果、SSE 快照和上传确认。

授权有效窗口只属于活跃访问，保存在内存，不扩展成持久租约表或通用权限平台。F01 确定检查／撤销契约，F02／F04 的实际通道 owner 必须接入并验收，不能由 F01 提前宣称资源已回收。

## 八、协议与兼容

Center 管理 HTTP DTO 仍由后端 Swagger／OpenAPI 生成 Admin SDK。Host—中心控制帧属于组网接入契约，放在两端各自的协议适配模块，统一字段、限制及兼容样例；没有 Desktop 消费的秘密和握手类型不搬入公共应用 DTO。

UI 所需登记状态、设备摘要及操作意图才进入 `assistant-protocol`，按现有方式维护 Rust／TS 投影。中心的权威事实不复制为 Runtime 业务数据库；在线变化经本机 Host 已有快照／事件渠道投影，重连取完整快照。

本版拟用中心能力声明区分是否支持组网；旧中心缺能力时仅禁用组网入口，不自动禁止本机既有使用。WS 首帧协商组网协议，失败明确提示升级，不能将“不支持”当网络故障无限重连。是否需要提高企业协议或应用最低版本，须核对 F02／F03 的正式 DTO 和旧客户端影响后统一决定；本次不更改当前版本声明。

中心表由既有迁移账本新增，Host 身份文件按需创建。旧程序对新库／新文件的接受范围必须在实施前核查，不承诺直接降级；实际升级、备份和回退依数据库规则另行核对与授权。本设计不新增旧中间草案兼容层。

## 九、交付与验证边界

F01 验证登记重试／失联恢复、真实控制连接、授权目录、身份接入、定向撤销及本机不受登记状态限制。使用项目 `.runtime-test/` 下新建隔离 Host 和已核实的隔离中心库，绝不借用户 Home 验证注销、复制身份或升级。

重点场景：中心提交后响应丢失；离线审批；两名管理员同时分配；停用后重新启用；取消与审批竞争；用户删除但设备保留；旧连接迟到回调；复制身份冲突；本机退出遇到中心离线；未登记调用方访问；目标已有登录与首次登录；登录安装期间退出；WS 无证书接入及可选 WSS。

心跳参数必须覆盖静默丢包、休眠和慢写；完整文件／终端混合负载由 F02 验证。F01 的访问撤销探针不代表远程桌面撤销已验证，后者在 F04 以实际媒体与输入回收验收。

[F01 界面交互设计指导](界面交互设计指导.md)已形成，复用 Runtime 设置二级入口和企业后台设备管理，Client 衔接同一登记能力。用户审阅后已授权编制[开发计划](开发计划.md)，计划已获确认并分里程碑实施；当前状态与完成结论见开发计划。已执行隔离构建与验证，未修改发布版本、部署或生产数据。

## 十、M0 实施契约（2026-10-15）

- 本步为增量 HTTP 能力，软件版本暂沿用当前开发基线 0.31.0；应用最低兼容版本与用户存储最低版本仍为 0.30.0，企业协议当前／最低版本仍为 3。Center 新增字符串能力 `host_registration`；Host 仅增加登记 HTTP 入口与专用 DTO，不向旧客户端严格反序列化的 `RuntimeHostFeature` 枚举追加 wire 值，保持既有发现接口兼容。不提前提升发布版本或预建 WS 契约。
- 中心迁移为 `012-host-devices.sql`，仅增加 `host_devices`、`host_device_users`。已有库升级须另行确认与备份；降级需匹配备份，不自动删表。普通使用权由关系存在表示，固定 `desktop_view`／`desktop_control` 布尔值，控制必须包含查看；桌面执行留给 F04。
- 管理端按完整原状态、名称、启用值、授权集合比较更新；重复审批返回已登记现状，不覆盖后续修改。用户删除仅级联清理其授权关系，设备保留申请人原 ID。
- Host 的登记命令由已有 HostAccess actor 串行处理，与中心绑定及配置变更共用顺序；只保存私有身份和本机意图，不缓存中心登记事实。申请需要当前企业登录加本机管理证明，查询／撤回／退出允许本机 bootstrap，均无需业务 Runtime 就绪。
- M0 使用 HTTP 查询恢复；没有心跳连接时在线恒为 false。中心不可达保留本机意图并明确返回未同步状态，不能把失败当成未登记。退出未确认的材料按所属中心保留，切回后继续核实，不阻止切换中心。

## 十一、M1 实施契约（2026-10-15）

- 中心 `host-devices/network.ts` 持有唯一设备连接表，`connection.ts` 驱动每条连接。登记凭据核验与变更共用 IdentityService 事务序列；仅提交成功后接纳或通知，数据库内不保存在线状态。停用仍连接；拒绝、撤回、注销立即移除当前连接并关闭。
- WS upgrade 只接收 `Authorization: Bearer <设备秘密>` 和 `x-ez-device-id` 请求头。M1 先交付设备模式；M2 在同一入口增加下述仅调用模式。返回 401 表示凭据无效、409 表示已有连接、410 表示登记终态。未完成认证最多 64 个，超时请求即使仍等待事务也继续占用额度，避免积压无界。
- 私有控制协议版本为 1，与企业 HTTP 协议 3 分开。中心先发送 `hello`（协议版本、中心 ID、登记 ID）；Host 校验后回复同身份的 `ready`，中心再发首条 `registration_changed` 确认并要求回读。后续同名通知合并为失效提示，通过原登记 HTTP 接口获取事实，不另设设备快照接口。二进制业务帧尚未启用。
- 中心每连接只执行一个写操作，并保留一个合并通知和一个未完成 Ping；M2 控制 RPC 队列继续受同一缓冲上限约束；Host 有界写队列与 socket 缓冲受控。中心以 250ms 独立调度检查期限；Host 同时轮询读、写与超时，取消直接释放整个 socket，不留下分离读写任务。控制帧 16KiB、缓冲 256KiB、写期限 5s，心跳和重连参数沿第五节。
- Host 的 `access/registration/network` 由 Supervisor 以降级策略监督，与用户 Runtime、登录和页面生命周期分离。Access actor 串行保存登记意图、核实通知与恢复待退出；连接 owner 只持有当前凭据的传输快照，不自行写身份文件。更换快照取消旧连接和退避；同一目标刷新不重复建连。
- 启动、连接通知和重连触发同一登记查询；离线或待处理意图每 30s 继续恢复。该补偿查询不是在线依据。原申请尚未送达中心时仍须本机企业用户恢复原申请，不能用设备秘密新建申请或把空结果视作退出完成。
- `HostRegistrationStatus.connection` 提供本机连接投影；旧响应缺省 `disconnected`。同一 Host 监听增加本机原生证明保护的 `GET /host-network/events` SSE，发送合并的 `host_network_changed` 提示，客户端回读原登记状态。此管理流无需创建用户 Runtime；断开 UI 不关闭设备 WS。
- 复用已锁定的 tokio-tungstenite 0.29.0（MIT，MSRV 1.63），启用现有 Rustls 与系统根证书，未引入新进程。HTTP 地址派生 WS，HTTPS 地址派生 WSS；证书仍正常校验，不自动忽略证书错误。软件版本、应用兼容下限及企业 HTTP 协议保持 M0 决定。

M1 不交付用户许可、业务代理、文件／PTY 负载或媒体传输；这些由后续里程碑和 Feature 消费同一连接 owner。

## 十二、M2 实施契约（2026-10-15）

### 12.1 调用入口与连接归属

- Host `POST /host-network/access` 接受 `HostNetworkCommand`，沿原用户认证、版本与登录上下文校验，拒绝 bootstrap；正文上限 4KiB。`list_devices` 的 payload 为 `{offset}`，`open_access` 为 `{device_id, capability}`，`get_access`／`close_access` 为 `{access_id}`。UI 不提供中心凭据。
- 本人设备目录按登记 ID 排序分页，每页至多 20 条，只返回名称、平台、启用／在线及本人桌面权限；终态设备不返回。访问结果仅含访问 ID、设备、能力和活动状态，已结束或不存在返回 `closed`，不保存历史许可。查询／关闭只认创建该访问的本机登录。
- 没有设备发布身份时，首次出向操作唤起既有连接 owner：`x-ez-network-mode: caller` 加普通用户 Bearer，hello／ready 中登记 ID 为 null。中心最多接纳 256 条调用连接，不建立设备记录，不能给它派发目标访问。连接入场身份不授予整条连接用户权限，目录和每次 open 仍独立核验。
- 已有设备连接则复用；发布身份变化取消旧连接并重建，不迁移旧许可。调用端最后一个有效用户退出后停止仅调用连接。中心拒绝把同一连接作为自己的远端目标；本机操作继续使用本机接口。
- 不兼容协议停止当前目标的自动重试，目标／配置变化后才重新协商。WS 与可选 WSS、软件和企业 HTTP 协议版本保持既有决定。

### 12.2 私有控制消息与目标初始化

- 复用协议 1 的文本控制帧：`request/response` 以请求 ID 关联，动作是 `directory/open/login/ready/renew/renew_source/close`；中心通知为 `access_offer/access_revoked`。这些消息只承载身份和控制信息，未实现普通业务载荷分帧。
- 调用 Host 先建立本机访问作用域再发 open，访问 ID 在本机生成且不自动重试；close 与 open 共用中心身份事务提交顺序，防止提前关闭后迟到授权复活；中心核验当前用户、目标登记／启用／权限及两端当前连接。设备秘密本身不能签发用户凭据。
- 中心发送 offer 后，目标复用自己的当前企业登录；没有该用户时才请求 login。IdentityService 的普通签发和审计负责新 Token／LLM key；它们只传给目标。目标用这些凭据核验身份并通过既有 UserDomains 初始化用户目录、Runtime 和模型配置。源端凭据不安装到目标。
- 同用户初始化门闩覆盖安装和 ready 回执，并发等待者复用已成功安装的登录。显式本机登录／退出取消在途初始化；回滚只比较自己创建的登录对象，不能删除后来登录。目标就绪后中心才向源端返回访问许可；超时、撤销或未知结果不自动重新兑换。
- 目标访问使用 `native=false` 的现有 AccessPermit 和独立本机 LoginSession，不暴露对应本机 Token。初始化完成后的单次访问收尾仅取消该许可，不调用用户全局退出；既有用户域 owner 仍决定空闲用户回收与任务生命周期。

### 12.3 期限、资源上限与撤销

- offer 初始化上限 30 秒；源端 open 等待上限 35 秒，其余控制请求 5 秒。源／目标每 20 秒各自复核，最长窗口 45 秒；目标 renew 不延长源端窗口。Host 从请求发送前的单调时钟计算期限，迟到返回、睡眠恢复和 Pong 都不能复活过期访问。
- 中心只保存活跃访问对象及两端连接、源登录作用域、目标当前登录作用域和能力。总数最多 1024，单调用连接最多 64；提交后通知只撤销失去对应权限的对象。桌面查看权限移除不误撤普通访问。
- IdentityService 在现有 Token 撤销提交点增加不含原始 Token 的单登录通知；旧的按用户／全局撤销继续服务既有业务。来源登录退出、目标登录退出、授权撤回、连接断开及到期各有明确作用域。账号停用、删除及中心重启仍使普通企业凭据失效。
- Host 每连接最多 16 个待响应请求，写队列 16 帧，待处理访问工作队列 64 项、活跃工作至多 128 项；中心每连接最多 16 个控制请求。帧和缓冲延续 16KiB／256KiB。超限、写失败和超时有界关闭，所有初始化与续期 future 随连接 owner 收尾，无独立脱管任务。
- F01 交付真实身份接入与取消信号。F02 仍须把实际 HTTP／SSE／文件／终端流绑定到许可，F04 仍须绑定媒体和控制；本阶段未验证真实远端 Run、模型调用或桌面流量。
