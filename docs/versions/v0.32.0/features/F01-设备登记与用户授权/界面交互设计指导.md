# v0.32.0 F01 界面交互设计指导：设备登记与用户授权

## 一、设计信息

- 版本：v0.32.0，F01 设备登记与用户授权。
- 状态：2026-10-15 用户审阅并确认最新交互调整后，明确要求编制 [F01 开发计划](开发计划.md)。本文作为计划依据，界面尚未实现。
- 关联：[总体设计](../../总体设计.md)、[功能设计](功能设计.md)、[技术方案](技术方案.md)。
- 影响：Desktop 本机登记入口、Client 无图形界面操作、Enterprise Admin 设备管理。F03 的设备选择、项目与会话工作区，以及 F04 桌面查看界面在对应 Feature 设计。

用户应能完成两件事：在目标电脑申请加入企业组网；管理员在中心确认设备并选择可用用户。申请、审批和在线状态可分别辨认，未登记或离线不遮挡本机工作区。

## 二、入口与现有界面复用

| 界面 | 入口及范围 | 复用依据 |
| --- | --- | --- |
| Desktop | 设置 → Runtime → 企业组网，管理这台电脑的登记 | `RuntimeOverviewPage` 现有二级入口行、`SettingsPageContainer` 和设置导航；不新增主侧栏管理项 |
| 企业后台 | 用户管理之后增加“设备管理”；设备卡片页及详情属于同一路由分组 | `app/routes.tsx`、`PageLayout/NavigationMenu`、现有查询分页机制、详情和表单弹窗；设备展示按用户要求采用卡片 |
| Client | 现有交互式 `config` 中增加“企业组网”；`status` 增加简短登记与连接状态 | `apps/client/src/config/index.ts`、`cli.ts`，调用同一 Host 管理能力 |

Desktop 企业组网页标题固定为“企业组网”，副标题“管理这台电脑的登记”。不随侧栏选中的远端设备变化，也不读取远端 Host 的本机管理接口。现有“智能终端”仍用于外设配对，已有“访问设置”仍管理 Host 模式、企业中心及直接访问。

原有 Desktop 全局直连远端 Host 的模式下，只有能取得本机管理证明时才可管理本机登记；无法确认时显示“请连接本机服务后管理这台电脑的登记”，不回退为管理当前远端 Host。普通 Web 页面不因运行在浏览器或请求来源为 loopback 获得本机登记管理入口。

F03 的设备选择器仍位于本机置顶和项目列表之间；可提供跳转到本机“企业组网”的次级入口，但不在 F01 设置页重复增加远端设备列表或修改侧栏布局。

## 三、本机企业组网页

### 3.1 信息结构

沿用当前设置页的单列布局和返回按钮，页头提供“刷新状态”。内容从上到下为：

1. **企业中心**：只读显示当前已绑定中心地址和当前登录用户。本页不提供修改或切换中心的按钮、跳转入口，也不提供地址、端口、WS／WSS 或证书表单；中心配置统一保留在已有“访问设置”中。
2. **本机登记**：设备名称、登记状态、连接状态，以及对应操作。未登记时设备名称可编辑，默认使用本机名称；同名允许，不能为空。长度和字符校验与正式 API 一致，不在两端维护不同规则。
3. **必要反馈**：申请进度、失败原因、结果未确认等就近显示。编号、平台和 Host 版本放在可展开的“设备信息”中，方便核对；不展示凭据、安装私钥或其他可用用户名单。

已登记后名称以中心保存值为准，名称旁说明“由企业管理员管理”；申请表中的名称不会继续作为另一份可修改的别名。管理员修改名称后更新显示，不改变设备身份或本地数据。

页面结构示意，控件样式沿用现有设置：

```text

管理这台电脑的登记

企业中心       center.example.com
当前账号       用户甲

本机登记
设备名称       办公电脑
登记状态       等待管理员确认
连接状态       已连接企业中心
申请已提交。管理员确认并分配用户后，其他设备可访问本机。
                                              撤回申请

› 设备信息
```

### 3.2 状态与主操作

| 当前情况 | 展示与操作 |
| --- | --- |
| 个人模式／尚未配置中心 | 说明“请先在设置 → Runtime → 访问设置中配置企业中心”；仅作文字提示，不提供配置或切换中心入口 |
| 中心已配置，但当前用户未登录 | 沿用现有 Host 登录页；完整设置在登录后工作区打开，不在登记页重复嵌入登录表单，也不自动申请 |
| 当前中心尚不支持组网 | 显示“当前企业中心尚不支持设备登记”，保留本机工作入口，不反复重连或引导配置证书 |
| 未申请 | 名称输入框与“申请登记”；说明管理员确认后仅获分配的用户可访问 |
| 提交中 | 按钮显示“正在提交”，锁定本次表单；取消网络请求不代表申请已撤回 |
| 提交结果未知 | 显示“正在核实申请结果”，操作为“查询结果”；复用原登记状态查询，不重新生成申请 |
| 待登记 | 显示“等待管理员确认”，提供“撤回申请”；连接状态单独显示，不因在线改成已登记 |
| 已登记且启用 | 显示“已登记”；连接正常时为“已连接企业中心”，提供次级危险操作“退出组网” |
| 已登记但停用 | 显示“已停用”，说明“请联系管理员启用”；控制连接仍可显示已连接，不显示无效的本机启用按钮 |
| 申请被拒绝／已撤回／登记已注销 | 显示实际结果，提供显式“重新申请”；新申请不沿用旧设备引用 |
| 中心不可达 | 保留上次已知登记状态并标明“状态未更新”，连接显示“连接中”或“暂时无法连接”；提供刷新，不显示成未登记 |
| 身份冲突／身份文件损坏 | 显示固定原因与处理指引；不自动生成新身份或踢掉另一连接，先核实旧登记再重新申请 |

“已登记”与“你有权从其他设备访问本机”分别展示；申请人未被分配时提示“你尚未获得本设备的远程访问权限”。这不影响其按既有规则使用本机项目、会话和终端。

### 3.3 提交、撤回和退出

申请登记只需填写名称并点击“申请登记”，按钮上方说明作用，不再叠加一次通用确认弹窗。申请期间关闭设置页不会撤回已提交申请，也不关闭 Host 连接；重新打开查询原结果。

撤回待处理申请时，用现有确认弹窗明确“撤回这台电脑的登记申请？”。审批与撤回竞争时以中心结果为准；若已登记，提示“管理员已完成登记”，更新页面，不将撤回自动升级为注销。

退出组网的确认文案为：“退出后，其他设备将无法通过企业组网访问这台电脑，已有远程连接会中断。本机文件、会话和任务保留。”确认按钮为“退出组网”。关闭直接入站访问、停止 Runtime 或企业账号退出仍是其他操作，不能连带执行。

中心不可达时，本机关闭目标接入成功后显示“本机已停止接入，中心注销待确认”。允许关闭页面，不将此状态显示为已注销；后台只继续核实／完成注销，不重新发布设备。用户点击再次申请时先核实旧登记，不创建并行登记。

## 四、企业后台设备管理

### 4.1 设备卡片与详情

拟定路由为 `/devices` 与 `/devices/:id`，复用现有 Hash Router、身份守卫和面包屑。导航项名称为“设备管理”；标题区不提供“新建设备”，设备只能从真实 Host 申请。

用户明确企业后台设备管理采用卡片式展示，已登记与未登记设备分栏展示，各栏允许收起。页面顶部保留名称／编号搜索和刷新，下方采用上下两个独立分栏：“已登记设备”在上，“未登记设备”在下；每栏内部使用响应式卡片网格，不混排，也不使用列表行、表格或卡片／表格切换。

两栏默认展开，标题行包含展开／收起按钮、栏名及当前查询的设备数量；数量复用查询总数，不新增统计接口。收起后仅保留标题行，不影响另一栏、设备连接或中心处理申请；刷新及新申请到达不强制展开用户已收起的栏。展开状态属于当前页面本地状态，返回详情时尽量保留，不同步到中心或其他管理员。

搜索同时作用于两栏，但各自查询、分页、加载和空状态独立，分页控件放在所属栏底部。设备分栏与用户选择器只有超过一页时才显示分页控件；数据减少导致页码越界时回到有效页。搜索变化时两栏回到首页；不能先对混合设备分页再在前端分组。已登记包括启用、停用和离线设备；未登记只展示当前在线设备，待审批优先、申请时间倒序；在线过滤与排序均在中心计数和分页前完成。历史拒绝、撤回、注销记录保留原引用的失效事实，不作为另一台设备展示。不设置“已结束登记”入口或额外状态筛选。未申请的电脑不会出现在中心。

| 卡片区域 | 内容与操作 |
| --- | --- |
| 顶部 | 设备图标、名称及平台；名称可进入详情，同名不合并 |
| 状态区 | 在线／离线用卡片顶部的状态圆点及文字显示；已登记设备显示启用／停用，未登记显示待审批 |
| 信息区 | 已登记显示可用用户人数；待登记显示申请时间，申请人放在详情及审批弹窗。完整名单及技术信息放入详情 |
| 底部操作区 | 待审批为“确认登记”“拒绝”“详情”；已登记仅提供“详情”。启停和注销仍在详情中操作 |

分栏及卡片结构示意：

```text
▼ 已登记设备（2）                                      收起
┌─────────────────────────┐  ┌─────────────────────────┐
│ 办公电脑 · macOS        │  │ 测试电脑 · Windows      │
│ 启用 · 在线             │  │ 启用 · 离线             │
│ 可用用户 3 人           │  │ 可用用户 1 人           │
│                [详情]  │  │                [详情]  │
└─────────────────────────┘  └─────────────────────────┘

▼ 未登记设备（1）                                      收起
┌─────────────────────────┐
│ 开发服务器 · Linux      │
│ 待登记 · 在线           │
│ 申请人 用户甲           │
│ [确认登记] [拒绝] [详情]│
└─────────────────────────┘

收起后：▶ 未登记设备（1）                              展开
```

卡片以稳定设备 ID 为标识，同一行底部操作对齐。宽页面多列、窄页面逐步降为单列，保持卡片形态，不退化为表格；整卡不设置嵌套点击事件，名称／详情入口与操作按钮各自可聚焦。自动刷新只更新当前卡片内容，不按心跳或在线变化重排，避免操作目标跳动。

登记确认成功后刷新两栏，该设备从待登记栏移入已登记栏；即使已登记栏收起，也保持收起并提示“已登记，可在已登记设备中查看”。拒绝、撤回和注销后从对应活动栏移出。已登记设备停用或离线仍保留原栏；未登记设备离线后从列表和数量中移除，重新在线后再出现。某栏为空时只在该栏显示空状态，不隐藏另一栏；某栏加载失败时只在该栏提示重试。

详情展示设备名称、登记编号、平台、Host 版本、申请人、申请／处理时间，以及本进程可用的最近联系时间。中心重启后最近联系时间可以显示“暂无记录”，不能伪造历史在线。设备编号可复制，身份摘要用于核对，不提供接管或修改身份按钮。

详情中的“可用用户”按当前中心事实显示；停用、注销位于独立操作区。设备离线不阻止审批、修改用户和停用；任何这些操作都不使设备立即显示在线。首版不提供批量审批、批量注销或批量分配。

### 4.2 确认登记与分配用户

待登记项的“确认登记”打开现有样式的表单弹窗：上方只读设备信息和申请人，中间为可编辑名称，下方为可用用户选择。底部按钮“取消”“确认登记”。选择用户、调整名称与登记一次提交，不先批准再打开第二个授权页面。

已登记项“分配用户”复用同一用户选择区，以中心当前集合初始化；登记信息保持只读，底部按钮为“取消”“保存”。用户选择可搜索账号／显示名，沿用中心已有用户查询能力；分页搜索不丢失已选项，不以当前搜索结果覆盖完整授权集合。

授权控件沿功能草案细化如下，具体权限拆分仍随 F01／F04 确认：

- 用户分配以表格展示，点击“添加用户”打开可搜索、分页的候选表，逐个添加；申请人和当前管理员均不自动添加，每行显示账号及显示名。
- 选中用户即授予普通业务访问；不再提供一个可与“已选用户”相矛盾的普通访问开关。
- 已添加用户的表格行使用 Switch 设置“查看桌面”“控制桌面”，新增用户默认均关闭。选择控制同时启用查看；取消查看同时取消控制。设备暂不支持桌面时，显示“设备暂不支持远程桌面”，不把权限已分配显示成桌面已可用。
- 允许零用户，表单内显示“尚未分配用户，登记后暂时无人可远程访问”，无需再弹一次确认；不自动改成全企业可用。
- 已停用用户保留在既有分配展示中并注明停用，不能新选；被删除用户的分配由中心清理。提交期间用户状态变化时按服务端结果重载，不替换为同名账号。

添加、移除和开关变更均先保留在草稿，点击保存统一提交；移除用户或降低桌面权限时，在保存区明确显示影响人数及“相关远程访问将停止”，点击保存即提交，不再套通用确认。启停与注销采用下面独立的确认规则。

### 4.3 管理操作反馈

| 操作 | 交互及结果 |
| --- | --- |
| 拒绝申请 | 明确设备名称的确认弹窗，按钮“拒绝申请”；不额外增加原因必填字段或审批流程 |
| 停用设备 | 确认“停用后，用户将无法通过企业组网访问该设备，已有远程访问将停止”；提交后管理状态为停用，在线状态保持实际值 |
| 启用设备 | 直接提交并刷新；恢复访问资格，不自动打开桌面或接管用户会话 |
| 注销设备 | 确认“注销后需要重新申请登记；本机文件和会话保留，旧设备引用不会自动指向新登记”；危险按钮“注销设备” |
| 修改用户 | 保存后刷新当前设备及卡片页；移除用户不提示“该用户已退出企业”或“任务全部停止” |

中心提交成功使用“已保存”“已停用”等准确提示。目标尚未确认收敛且仍存在待停止访问时，按已有连接 owner 提供的事实显示“正在停止远程访问”；未取得回证时不显示“全部连接已断开”。不为这个提示新增持久化管理状态或历史任务表。

## 五、刷新、并发与异常

Desktop 页面首次进入读取本机状态，通过 Host 现有事件刷新；重连和手动刷新复用同一登记状态查询。页面卸载释放 UI 订阅，Host 连接继续运行；不从 UI 新建中心 WS，也不增加“快照查询”旁路接口。

后台页使用普通管理 HTTP 查询。卡片页／详情在可见时建议每 10 秒刷新显示状态，隐藏、卸载或身份失效时停止；卡片页共用一个刷新调度，每栏最多一个未完成查询，详情页最多一个未完成查询，手动刷新复用相同请求控制。收起只隐藏该栏卡片，不停止状态与数量更新。编辑弹窗打开时暂停自动替换表单，提交仍由中心检查原状态及授权集合；不为后台页面新建设备心跳连接。

| 情况 | 页面行为 |
| --- | --- |
| 加载失败 | 保留明确错误和重试；已有卡片注明未更新，不用空白设备区域冒充加载成功 |
| 分栏为空／无匹配设备 | 已登记栏显示“暂无已登记设备”，未登记栏显示“暂无在线的未登记设备”；搜索无结果时在对应栏显示“没有匹配的设备”。待登记空状态说明需在目标设备主动申请，不放无效“新增”按钮 |
| 两人同时审批／编辑授权 | 显示“设备状态或用户分配已变化，请重新载入后确认”；保留本地编辑供查看，禁止自动合并或覆盖中心最新值 |
| 写请求超时／连接中断 | 显示“处理结果尚未确认，请先查询最新状态”；禁用重复提交，先查询同一申请／设备，不自动重试写入 |
| 提交期间关闭／切换页面 | 沿用既有提交锁与导航保护；请求超时后可退出，取消客户端等待不宣称中心回滚 |
| 未保存名称或授权变化 | 沿用脏表单离开确认；普通状态刷新不标记为用户修改 |
| 当前身份失效 | 沿现有身份守卫退出对应管理界面；旧请求失败不能登出后来的新身份 |
| 设备注销后打开旧详情 | 展示已注销事实，禁用分配和启用；不按同名新设备自动跳转 |

刷新只更新当前页面的数据投影，不持久保存另一套审批状态。用户切换、筛选变化和页面卸载后，旧响应不得覆盖新页面。

## 六、Client 与无图形设备

`config` 的“企业组网”展示当前中心、本机名称、登记与连接状态，再按状态提供申请、查询结果、撤回或退出。名称预填并可编辑，身份和确认语义与 Desktop 相同；不用输入设备秘密、登记码或中心管理员账号。

申请要求实际运行的本机 Host 和有效企业用户身份。Client 没有该用户的有效登录时，在此操作中接入 Host 的既有企业登录能力，交互输入账号和隐藏密码；凭据不进入命令参数、环境变量或终端输出。实现时补齐 Client 到既有登录接口的调用，不把目前仅有配置菜单当成已实现登录。关闭 Client 只结束本次交互，不退出该 Host 用户或撤回申请。

Host 未启动时提示通过现有启动操作启动后再申请，不离线生成待发送申请；非交互终端沿现有 `config` 限制返回明确错误。`status` 只读查询，不自动启动 Host、登录或申请；Host 不在线时如展示本地记录，明确注明当前中心状态尚未核实。
