# v0.32.0 F01 功能设计：设备登记与用户授权

- 所属版本：`v0.32.0`，开发中；2026-10-15 用户确认 [F01 开发计划](开发计划.md)并授权 M0。

- 授权范围：2026-10-15 用户明确“继续版本设计，设备登记就按设备主动申请、中心确认的流程来”。随后明确“可以，开始 M0”，按 [技术方案](技术方案.md)实施登记与授权事实闭环。

目标是让管理员能够登记一台实际运行的 Host、指定可使用它的企业用户，并能核验接入、离线和撤销结果。设备登记成功不等于用户已登录，也不等于会话、终端或桌面通道已可用。

## 二、范围与复用依据

### 2.1 本 Feature 交付范围

- 管理员登记、命名、绑定、启停和注销设备，分配可用用户。
- Host 证明自己是被登记的设备，向同一中心建立受监督的控制连接；通过 WebSocket 控制连接与心跳提供在线状态和能力摘要。
- 当前用户取得本人可用设备目录；中心和目标 Host 能共同核验用户是否可访问该设备。
- 用户授权变更、设备停用、账号失效与中心重启时，身份和可用状态正确收敛。

F01 不实现业务请求代理、文件传输、PTY 和媒体通道；这些由 F02／F04 消费本 Feature 的授权边界。F01 验收仍必须使用正式隔离 Host 证明设备身份、控制连接和访问判定，不能只交付后台卡片或静态设备目录。

### 2.2 已有实现与缺口

| 核查入口 | 现有事实与复用边界 |
| --- | --- |
| `apps/enterprise-center/src/identity/service.ts` | 已有中心稳定身份、普通／管理员认证、身份写入串行边界、事务审计与撤销通知；用户 Token 在内存保存，中心重启失效，不能拿它作为永久设备身份 |

| `apps/runtime-host/src/access/enterprise/`、`user_domain/` | 企业用户按中心与用户标识隔离；Host 持有当前中心登录，既有退出、身份失效、中心不可达各有收尾规则；组网接入不能仅凭用户编号绕过这些规则 |

设备登记与用户关系是现有用户表无法表达的新事实，可以形成最小持久化增量；在线连接属于 Host／中心的运行状态。表结构、凭据格式和可选 WSS 接入配置在技术方案论证，不在功能设计预建数据库、第二套登录表或通用权限平台。

## 三、角色与身份边界

以下是本草案建议的首版产品规则，用户已经明确的“中心登记设备并设置可用用户”在此细化：

| 角色 | 可以做的事 | 边界 |
| --- | --- | --- |
| 企业管理员 | 登记、命名、分配用户、启停、注销设备及查看管理状态 | 管理员身份不自动授予设备业务数据或系统桌面访问；需要显式分配本人 |
| 目标设备的本机操作者 | 在受保护的本机 Host 管理入口申请登记、查看结果、退出组网 | 本机管理证明不等于企业管理权限；申请不自动获得共享授权 |
| 已授权企业用户 | 查看本人可用设备、申请访问目标本人的用户域 | 不查看其他用户的项目、会话或附件，不修改设备授权 |
| 设备 Host | 证明设备身份、报告在线与能力、核验请求并接入本人用户域 | 设备身份不能代表任意企业用户，也不能使用管理员 Token 执行业务 |

一次企业设备登记代表一个受管理的 Host 安装／Runtime Home，不按物理机器名、IP 或每次启动实例编号识别。同一电脑的不同隔离 Home 不合并；正常重启和重命名保持设备身份。首版只登记企业模式 Host，不自动将个人模式内容共享到企业。

设备登记与可用用户关系归中心持有；设备私有身份材料归本机 Host；用户域业务状态归目标 Host／Runtime。客户端只持有授权目录和显示状态。

本机使用与企业组网发布分开：未登记、待登记、登记被拒绝或设备在线心跳超时，都不新增本机项目、会话、文件和终端的使用限制，仍沿原有登录和权限规则操作。设备登记仅决定本机能否作为企业组网目标被发现并申请访问；本机尚未登记为组网目标，也不能仅因此禁止当前用户通过中心访问已获授权的其他设备。F02 必须核对调用方的可信用户与连接身份，不以“已发布为组网目标”作为额外使用门槛。

既有远程 Host 直连登录独立保留：通过 Host 地址直接连接时，继续执行原有“允许非本地访问”、登录与权限规则，不增加设备登记或组网用户分配条件。登记、停用、注销设备及撤回设备用户授权仅作用于企业组网访问，不关闭既有直连入口、不撤销既有直连登录；登记成功也不自动开启直连。企业账号停用、用户退出等原有用户生命周期规则保持不变。

## 四、登记、绑定与日常使用

2026-10-15 用户已确认采用“设备主动申请、管理员在中心确认登记”的单一主流程。中心预建登记码不并行纳入首版。设备申请与正式发布分开，不因申请状态限制本机使用。

### 4.1 设备主动申请

本机操作者在当前企业中心的设备连接入口点击“申请登记”，Host 使用当前有效企业身份发起申请，并提供稳定安装身份、显示名称、系统及 Host 版本。中心核验申请人和安装身份后，将其显示为管理员设备管理页中的待登记卡片；申请人身份用于申请准入，不自动成为登记后的长期设备凭据或唯一可用用户。

同一安装身份、同一中心下的未完成申请复用原申请，不因重试或重连生成多台设备。申请可以取消；中心可以拒绝；失败或取消均不清理本机项目、文件与会话。结果未知时用原身份查询，不自动换身份重新申请。

Host 只连接当前绑定中心，不因为申请请求静默修改企业配置、迁移用户域或开启公网监听。入口面向 Desktop 和 Client 所管理的同一 Host；无 GUI 节点也应能通过本机管理能力发起，具体界面／命令形式留待后续设计。正常登录不自动提交登记申请。

### 4.2 管理员确认登记

企业后台新增“设备”入口，待登记区域展示设备名称、系统、版本、申请人、在线状态及安装身份摘要。管理员选中申请，核对设备，调整显示名称并指定可用用户，执行“登记”。同名设备可存在，不能只按名称认领或合并。

1. 中心提交前重新核验管理员权限与申请状态，确保申请未取消、未被其他操作处理，身份仍对应原设备。
2. 登记与可用用户分配一起提交；允许用户集合为空，但不得隐含“全企业可用”。提交成功后才发布登记结果。
3. 在线 Host 经原 WebSocket 收到登记结果并保存必要的绑定事实；离线时保留“已登记／离线”，恢复后核验原身份并取得当前结果，不需要管理员重新登记。
4. 中心已登记但 Host 保存失败或通知丢失时，保留原身份并查询恢复；不把通知未达当作登记失败，也不重复登记。设备真正恢复连接后才显示在线。
5. 重复点击或迟到审批只回到当前事实，不覆盖后来修改的用户分配。待登记设备拒绝／取消后的迟到消息不能重新开放访问。

中心的“待登记在线”表示申请连接仍可达，不等于设备已经公开给其他用户。登记前后的连接都归 Host 管理；正式登记后的持续在线使用设备身份，不依赖申请人继续登录。具体身份交接和中心重启后的恢复由技术方案确定，不为简化流程持久保存申请人的账号密码。

既有“允许非本地访问”控制直接入站监听，组网申请是单独的显式接入意图；本流程不会自动开启公网 HTTP 监听、修改端口或关闭既有来源校验。经企业组网进入的业务访问须按设备与用户权限准入。本机作为调用方经中心访问其他已授权设备，不以登记获批为前提。

### 4.3 使用与用户分配

管理员在设备详情编辑可用用户，保存后以中心提交的集合为准；并发修改必须拒绝冲突或明确重载，不能静默覆盖别人的授权。首版使用显式用户集合，不引入部门继承、用户组和授权审批流。

普通用户目录只返回当前中心下本人可用且未注销的设备；允许保留离线项，不能把离线误报成无设备。失去权限的设备从可选择目录移除，已有本机置顶和标签保留不可用提示，不继续显示新业务内容。

新授权不替用户创建目标会话、复制项目或导入本机配置。目标 Host 在真实访问到来时核验中心、用户、设备和当前授权，再复用本人用户域装配。用户不应为每台目标设备再次输入账号密码；如何在保持当前企业登录、模型配置和退出语义的前提下完成可信身份接入，是 F01 技术方案的必答项，不能只传一个 `user_id`。

桌面查看／控制权限与普通用户域访问分开。建议新分配默认仅允许普通业务；如需远程桌面，再显式授予查看，控制以查看为前提。只涉及这几个固定能力，不扩展为通用角色系统；具体后台控件与 F04 共同确认。企业授权仍不替代目标操作系统的屏幕录制和输入权限。

### 4.4 停用、退出组网与注销

- **停用设备**：中心保留设备身份、用户分配和控制连接／重连，拒绝新的业务访问并收敛已有组网访问。再次启用沿原控制连接恢复接入资格；不自动打开桌面控制。停用不等于离线。
- **本机退出组网**：停止该 Host 的组网连接并使当前绑定不可继续使用，保留本机业务数据。中心不可达时先停止本机接入，显示中心解绑待核实；恢复后不能自动重新加入。
- **注销设备**：使该登记和凭据失效，已有引用保留失效事实；不删除目标电脑上的目录、会话或附件，不远程卸载 Host。重新登记视为新设备，旧置顶不能按同名自动改指向。
- **重装／丢失身份材料**：不得仅凭设备名称或地址恢复旧身份。首版建议注销后重新登记，不加入隐式身份接管；必要的数据保留与旧引用提示在实施方案明确。
- **身份冲突**：同一绑定出现无法确认归属的并发接入时，阻止可疑接入并显示异常，不静默让“后连接者”踢掉原设备。复制完整 Home 也会复制身份，首版不宣称能靠软件凭据识别物理机器；检测、恢复和密钥更换边界须在技术方案说明。

## 五、设备状态与页面反馈

不将登记、在线、授权和功能可用混成一个“可用”状态，也不为所有组合新增持久状态机。

| 展示维度 | 可观察结果 | 判断来源 |
| --- | --- | --- |
| 登记 | 待登记、已登记、已注销；申请拒绝／取消单独反馈 | 中心权威事实 |
| 管理 | 启用、停用 | 中心管理设置 |
| 连接 | 在线、离线、状态未知／连接异常 | 已认证控制连接和有界存活判断；重启后不能沿用旧在线标记 |
| 当前用户权限 | 可访问、无权限；桌面查看／控制单独判断 | 当前用户身份与中心分配 |
| 能力 | 协议兼容、普通业务能力；桌面支持、系统授权和首帧就绪由 F04 细化 | 目标 Host 实际能力，不能按系统名称猜测 |

设备管理采用卡片网格，已登记设备与待登记申请分为两个可独立收起的区域，不混排；审批成功后移入已登记区，停用或离线不改变登记归属。卡片展示名称、平台、登记／连接状态及可用用户摘要，提供登记确认和用户分配入口；Host 版本、最近联系时间、完整授权及启停／注销放入详情。最近联系时间只是历史信息，不代表当前在线。普通用户不看到其他用户名单、密钥或任意设备内网地址。

设备离线不影响查看管理登记和修改授权；当前不可达的设备在重新连接时必须重新取得有效授权。目录加载失败保留明确错误和重试，不把过期缓存当成可访问依据。后台状态查询不读取远端项目或文件。

### 5.1 Host 在线心跳

2026-10-14 用户明确将心跳机制纳入本版，并提出使用 WebSocket。本草案采用 Host 主动连接中心的 WS 控制通道，支持 WS，WSS 为可选配置，不区分环境强制加密或部署证书；心跳是 F01 设备连接生命周期的一部分，不单列 F05 或新建独立心跳服务。F01 与 F02 共同定义统一 Host—中心连接：心跳、控制与桥接优先复用此连接，业务载荷由 F02 映射；本版不额外实现业务载荷加密，WSS 按需启用，不叠加 Host 间业务载荷端到端加密，中心处理路由和流控但不解析业务正文。

- **唯一所有者**：控制连接由 Host Supervisor 管理，中心持有当前连接及在线投影。按 Host 安装和中心绑定维护，不按用户、会话、标签或窗口各开一条设备心跳；关闭 UI 或用户退出不自动下线仍运行的 Host，停止 Host 才结束其连接。
- **准入与身份**：先完成身份与协议核验再计入已登记设备在线。待登记连接只更新对应候选状态；不能靠持续心跳升级为已登记设备。仅作为调用方的本机 Host 不因未发布节点而丧失原本授权能力，其接入身份在 F02 中落实。
- **心跳内容**：优先使用标准 Ping/Pong 检测连接存活，关联当前连接的探针与响应；必要的能力、授权变更和协商消息复用控制通道。心跳不携带用户密码、会话正文或屏幕内容，不另设逐用户心跳协议。它证明控制连接可达，不证明 Runtime、PTY、采集或媒体首帧就绪。
- **在线判定**：中心以自身单调时钟、当前连接收到的有效响应及超时窗口判断，不相信设备上报时间续在线。关闭／失败即时处理，静默丢包在限定窗口内判离线；单次探针延迟不直接触发全设备注销。间隔、失活期限和调度容差在技术方案给出，须保证期限不会因发送下一次探针而无限后移。
- **恢复与竞态**：网络恢复以有上限的退避和抖动重连，重新认证后恢复在线；休眠唤醒不补发积压心跳。旧连接的迟到 Pong 或关闭回调只能更新自己的连接，不能把新连接标离线或复活已注销设备。合法重连与复制身份冲突分别处理，不能任意后连接抢占。
- **资源与流量**：心跳和撤销通知保持小消息、有界队列及写入期限，不排在大文件／终端输出后无限等待。逻辑控制通道与业务数据的调度隔离；优先共用物理连接并分块、限队列，F02 验证队头阻塞和公平调度。只有实际负载证明必要时再论证拆分，不为心跳预设第二套连接。
- **状态发布**：中心的当前连接状态为唯一在线事实；F03 经本机 Host 的既有事件／快照机制取得投影，界面不直连中心。状态重连后重新取快照，不依赖恰好收到某次在线事件。无需每次心跳写数据库；如保留最近联系时间，应限频持久化，旧时间不能恢复在线。

设备注销或退出组网须取消目标接入重连意图；管理员停用保留控制连接及重连，以接收恢复启用通知，业务访问保持关闭。中心重启清空在线投影，由 Host 重新认证建立；不凭数据库的“上次在线”自动标在线。实际中心不可达可能触发既有企业身份处理，但单独设备心跳失败不能直接调用用户退出、清空全部登录或取消本机 Runtime；既有企业身份复核仍由其原所有者判断。

### 5.2 与其他 Feature 的冲突检查

| 范围 | 容易混淆的地方 | 本版处理 |
| --- | --- | --- |
| F01 登记与授权 | 在线被误当已登记、已授权；中心重启丢用户 Token 被误当设备注销 | 登记、设备连接、用户身份分别核验；持久登记保留，在线重建，用户登录沿原规则 |
| F02 代理与流式文件 | 共用队列时大文件阻塞心跳；心跳在线被当成所有桥接请求成功 | 控制消息有界及时处理，每条业务流独立报错与取消；只重建连接，不自动重放写请求 |
| F03 设备入口与本地状态 | 切换设备或关闭窗口结束 Host 心跳；离线清空置顶和标签 | 心跳归 Host，UI 只展示状态；离线保留本地引用与恢复入口，不新增本机使用门禁 |
| F03 交互终端 | Host 在线被当作客户端仍持有 PTY，代理代答心跳造成终端泄漏 | 设备心跳与终端连接存活、输入输出 ACK 分开；原客户端断开必须关闭对应远端终端，不能靠 Host 心跳续命 |
| F04 远程桌面 | 中心控制通道离线被误报为媒体立即断开；媒体通畅被当作授权永远有效 | 分别展示控制／媒体状态；心跳失败不直接伪造媒体状态，目标仍按既有身份复核及授权到期规则停止访问，重连默认只读 |
| 既有企业身份复核 | 收到 Pong 就续用户登录，或新建一套逐用户计时器与原循环竞争 | 设备心跳只管连接；复用现有用户复核和撤销，不能靠设备证明延长用户权限 |
| 既有 Gateway／模型 WS | 同为 WebSocket 就复用智能终端配对或上游模型连接的生命周期 | 仅评估底层库与局部实现复用，不合并业务身份、在线表或连接所有权 |

源码核查：`apps/runtime-host/src/user_terminal/socket.rs` 已有终端 Ping/Pong、超时及断开回收；`apps/runtime-host/src/access/enterprise/mod.rs` 已有活动用户身份复核；`apps/runtime-host/src/device/connection.rs` 已有智能终端专属心跳；`apps/enterprise-center/src/llm/websocket.ts` 持有上游模型连接。它们都不能直接作为企业 Host 在线通道。

### 5.3 统一连接的生命周期与交付边界

Host 主动向当前企业中心建连，连接本身不依赖某个聊天窗口。F01 和 F02 共同维护这条连接的契约；F01 实现设备接入与在线管理，F02 在原连接上接入业务流，不另建“桥接专用设备身份”或第二份在线状态。

```text
Host 启动／恢复网络
    → 连接中心 → 身份与版本核验 → 进入对应接入状态
    → 心跳保活；接收登记结果、授权变化等控制消息
    → F02 按实际请求建立桥接流；不同流独立完成或取消
    → 连接断开：更新在线状态、结束所属流、按意图重连
```

登记状态控制这台 Host 能否成为被访问的目标，不改变其已登录用户作为调用方访问其他授权设备的资格；具体身份核验仍区分调用方与目标设备。登记批准、用户分配和业务访问不能仅靠连接已建立推导。

| 连接承载内容 | 处理方与完成含义 | 交付边界 |
| --- | --- | --- |
| 身份与在线心跳 | 中心核验连接并维护在线；心跳成功只说明连接存活 | F01 完整实现 |
| 登记结果与设备授权通知 | 中心持有权威事实，Host 更新投影；断线后重新查询当前状态 | F01 完整实现 |
| 请求及响应载荷 | 中心按连接／目标／流标识转发，目标 Host 解析业务 | F02 实现，不纳入 F01 的业务代理验收 |
| 流取消与结束 | 清理指定请求或资源的传输，不代替停止 Run | F02 实现，复用 F01 连接所有权 |
| 远程桌面协商 | 复用当前身份和控制连接交换连接信息 | F04 实现；画面与键鼠优先直连 |

以上只固定功能职责，不预设消息类型名、二进制布局或新增公共 DTO。技术方案需在 F01 连接代码落地前明确可承载 F02 的边界，避免 F02 重做连接层；F01 不提前实现尚无消费者的文件队列或媒体协议。

同一 Host 连接可能服务多个已登录用户；每条业务流仍固定调用用户、目标设备和原请求。连接在线不能共享用户权限，某个用户退出只清理其应被撤销的访问，不能关闭其他用户共用的连接。请求返回或取消时释放所属流，不因短请求完成就反复断开整条 WebSocket。

中心只解析转发所需的外层信息，保持业务载荷原样；接收成功不等于目标已执行业务。WS 与可选 WSS 使用相同的功能和授权语义，不增加载荷加解密阶段。普通业务不自动改走直连，桌面直连失败也不自动挤入普通业务流。

连接故障恢复只恢复通信能力。SSE 从原目标快照补齐，上传按原接口确认结果，终端依既有规则重新创建，桌面重连恢复只读；不能把一条 WebSocket 的自动重连承诺成所有业务无缝续接。这些业务恢复分别由 F02／F03／F04 验证。

## 六、撤销与恢复语义

撤销有不同作用域，不能统一调用“退出用户”处理：

| 事件 | 必须收敛的访问 | 保留的事实与影响边界 |
| --- | --- | --- |
| 移除用户对设备 B 的权限 | 用户到 B 的新请求及已有组网访问；后续 F02 关闭对应文件／事件／PTY 通道，F04 关闭查看／控制并释放按键 | 不撤销用户的全部企业登录，不影响设备 A 或 B 上其他用户；不删除业务数据 |
| 停用／注销设备 B | B 的全部组网业务访问及桌面通道 | 不停止整台计算机，不删除 B 的用户域，不结束其他设备的连接 |
| 账号停用、删除或现有规则判定身份失效 | 沿既有企业身份收尾规则处理该主体访问与 Runtime | 不将其降格为只移除一个设备；同名重建账号不继承旧身份 |
| 显式企业退出 | 沿当前 Host 的用户退出及捕获的中心登录撤销规则处理 | 不新增全企业广播退出语义；设备登记不随某个用户退出消失 |
| 仅网络断开 | 结束或恢复相应连接，依据现有业务协议确认未知结果 | 不把断线当注销或删数据；终端、桌面资源按各自规则回收 |
| 中心重启 | 设备重新证明身份，清空旧在线投影；用户凭据按现有规则失效并重新登录 | 中心的设备登记与分配保留，设备在线不代表用户登录有效 |

设备权限移除本身不等于撤销目标用户的全部 Runtime 任务。本草案建议已经接纳的 Run 按目标 Runtime 既有身份与生命周期规则处理，不因一条设备授权变化全局退出该用户，也不自动重发或迁移任务；如果同时触发中心不可达或身份失效，仍执行既有收尾。F01 明确访问许可作用域，F02 验证该作用域不会误取消其他合法入口。

授权变更提交后立即阻止中心接受新的旧权限请求，并通知对应 Host 收敛；在线通知、并发在途请求与最终生效时间须纳入验收。中心提交成功和远端实际断开分别展示，不能用一次保存成功宣称远端瞬时完成撤销。通知延迟或失联时依靠目标权限复核，在明确的最长窗口内停止访问；窗口与现有企业复核策略统一，由技术方案给出具体值。

中心暂不可达沿用现有企业处理规则，不新增允许用户无限离线工作的例外。设备控制连接可以按有界退避恢复，用户业务不能以设备凭据冒充登录续期；直连桌面也必须受授权复核约束。迟到绑定、登录、授权及在线结果不能复活已注销设备或已退出用户。

## 七、跨 Feature 契约与必要持久事实

F01 向后续 Feature 提供的是稳定身份和授权结果，不是第二套业务命令：

- F02 使用中心／设备／用户作用域、可信设备身份、当前授权及撤销通知，建立普通业务桥接。可发现与有访问权都不代表具体业务接口已开放。
- F03 使用本人设备目录、显示名称、在线状态和能力摘要。选中设备仅影响浏览范围，不能向中心写入“当前全局设备”。
- F04 复用身份、查看／控制许可和撤销边界，增加媒体协商及系统权限；桌面输入不因直连而绕过目标校验。

中心需要保留设备登记、身份绑定、管理状态与用户分配；现有用户、中心身份和审计直接复用。Host 需要保护安装／绑定材料，控制连接及当前有效访问归运行时管理。具体存储复用、迁移和兼容下限由技术方案核查，不持久化媒体内容或复制用户业务库。

设备身份必须独立于短期用户登录：能重连中心不等于能代替用户调用业务；申请准入身份、设备证明和用户访问凭据不得混用。若新增授权证明，它必须有不可由客户端伪造的主体与目标绑定、限定用途及撤销机制，不能成为平行的企业登录系统。是否需要新增证明形式，先检查现有身份核验能否承载。

登记、分配、启停、注销复用现有审计与写入规则，只记录操作者、目标、动作、结果和必要变更摘要；不写绑定秘密、请求正文或业务内容。数据库变更按仓库升级及确认规则执行，本设计阶段无任何数据操作。

## 八、验收边界

1. 实际 Host 可主动申请，管理员能确认登记并分配用户；普通用户不能伪造管理请求，自报设备编号不能冒充设备身份。
2. 重复申请、取消／拒绝、中心不匹配及并发审批被正确处理；结果丢失后原 Host 能查询恢复，离线审批不冒充已在线，不重复登记或抢占已有设备。
3. 未分配的用户和未显式分配自己的管理员不能访问目标业务；允许用户进入目标本人用户域，不读取其他用户项目与附件。
4. 同名设备互不混淆，正常重启／重命名保持引用；注销重登、身份损坏和并发身份冲突不静默接管旧引用。
5. 真正的控制连接决定在线状态；中心重启、Host 退出、网络中断和失效身份均能在确定窗口内更新，不用旧记录假装在线。
6. 修改设备 B 授权只影响相应用户与 B，其他设备、其他用户及合法本机入口不被误退出；中心提交和目标收敛分别可核验。
7. 设备凭据不能访问用户数据或替用户续期；中心重启后登记保留、用户登录失效的两种结果同时正确。
8. 本机绑定不隐式打开公网监听；远程请求不能利用 bootstrap 或 loopback 获得本机管理特权，普通企业登录不自动登记或共享设备。
9. 停用、退出组网和注销不清空业务数据；重新启用不会恢复桌面控制，晚到消息不复活旧授权。
10. 后台表单覆盖空用户集合、长名称、离线设备、并发编辑、提交未知与身份失效；界面成功状态与中心权威事实一致。
11. 关闭窗口、切换设备、用户退出和待登记不阻断 Host 自身心跳或新增本机使用限制；Host 停止、静默丢包、休眠唤醒和中心重启按确定窗口更新在线状态。
12. 大文件与终端繁忙不饿死心跳及撤销；重连后的旧 Pong／关闭回调不能覆盖新状态，心跳不能复活已注销设备或续用户登录；设备在线时仍能回收已断开的客户端 PTY。
13. 授权拒绝与撤销通过隔离正式 Host 的真实控制连接回证，不能只靠前端模拟或中心单元测试；普通业务与媒体通道的最终效果由 F02／F04 衔接验收。

隔离验证使用项目 `.runtime-test/` 下新建场景；既有数据升级按数据库安全要求核对和授权。F01 验收不宣称 F02 代理或 F04 远程桌面已实现。

## 九、待确认取舍与下一阶段

设备主动申请、中心确认的主流程已于 2026-10-15 获用户确认，不再列为待选方案。待收敛的细化取舍：显式分配用户且不默认授予管理员使用权；普通业务与桌面查看／控制分别准入；注销后重新登记视为新设备；移除设备权限不等同全局企业退出。

[技术方案草案](技术方案.md)已形成，覆盖以下内容，新增工程选择仍待审阅：

- Host 独立身份、申请到正式登记的身份延续与幂等恢复、凭据保护、WS 控制连接、可选 WSS 配置及协议准入、心跳间隔／失活窗口／连接对象归属和资源上限。
- 当前企业 Token／模型 key 与目标用户域接入，防止跨 Host 登录互相替换或错误退出；用户本人无需重复输入密码的完整链路。
- 用户／设备／连接各级撤销作用域、存活与复核时间、提交和通知竞态，以及复用现有串行写入／审计的方式。
- 与既有外部访问开关、本机管理、模式切换、中心换绑、安装升级和旧智能终端 Gateway 的兼容。
- 最小持久化、升级与回退影响，以及中心／Host／Desktop／Client 的协议生产者和消费者。

[界面交互设计指导](界面交互设计指导.md)已形成，明确后台设备卡片与登记流程、本机登记入口、用户分配、能力权限和失败恢复。用户审阅修订后已授权编制[开发计划](开发计划.md)，计划已确认，M0、M1 已确认完成，M2 已实现并验证、待确认；正式管理界面尚未开始，具体状态与边界以开发计划和技术方案实施契约为准，发布版本声明未更改。
