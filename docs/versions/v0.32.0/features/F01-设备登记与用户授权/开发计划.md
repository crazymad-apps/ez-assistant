## 二、台账原则与实施边界

1. 按用户最新安排，M0 → M1 → M2 → M3 后直接转入 F02，跳过 M4。每个里程碑实现和最小有效验证完成后标为 `🟨 待确认`，汇报后获得用户确认才进入下一步。计划确认仅允许启动首个未完成里程碑，不自动授权完成全部里程碑。
2. 每步交付能通过真实接口或正式 Host 验证的结果，不以空接口、生成类型或静态卡片作为完成。没有 UI 的前置里程碑使用隔离协议客户端验证，不增加产品调试接口。
3. 继续复用中心用户、审计与事务；Host 配置、每用户当前登录、用户域和 Supervisor 保持唯一所有者。登记身份不等同用户身份，设备心跳不替代业务资源存活。
4. 数据库操作先核实实际连接与影响范围，适用仓库生产／共享数据与一次性隔离库规则。所有验收 Home 在 `.runtime-test/` 下新建；不读取用户 Home 作测试夹具，不操作真实企业部署。
5. 按改动执行定向检查，共享构建目录上的 Rust 构建与运行验证串行。不默认全 workspace 全特性构建、不为每个场景新建构建缓存、不生成部署归档或安装包；实际需要扩大验证时说明原因。
6. 计划只维护状态、确认及必要遗留。详细验证在会话汇报，不另建验证报告、结果数据库或产物清单；更新模块约束与用户手册反映已实现事实。
7. 编制计划和里程碑确认均不额外授权发布、生产迁移、部署、Git 提交或推送。用户既有无关改动保留。

## 四、各里程碑

### M0 登记与授权事实闭环

**目标**：以一个真实 Host 安装为对象，完成申请、审批、用户分配、状态查询及退出登记；无需 UI 或在线假数据即可验证中心权威事实。

**前置依赖**：取得本计划与 M0 启动确认；读取涉及模块与语言规范，核对共用工作树、协议版本和隔离数据库。关键契约决策先回写技术方案，不新建独立设计清单。

**交付范围**：

- 中心最小设备及用户关系迁移、登记／管理 HTTP 接口、审计和管理员复核；申请与确认状态使用同一记录。状态筛选及分页支持后续两栏独立查询，不依赖前端拆分混合分页。
- Host 安装身份与登记材料的私有原子保存，本机申请、查询、撤回、退出入口；中心地址沿用既有配置，查询不另设“设备快照”接口。
- 登记 ID 幂等、提交结果核实、离线审批、取消／审批竞争、注销重登和待注销恢复。该阶段可通过 HTTP 核实状态，未建立控制连接的设备明确离线，不以近期请求伪造在线。
- 用户分配、空集合、管理员不自动获使用权、用户删除与设备保留；并发编辑冲突及写入失败保持原事实。
- 仅为本步已实现接口维护 OpenAPI 与必要应用协议投影，不预建业务流、媒体或 UI 空实现。

依据：技术方案第三、四、八节；交互指导第四节的数据需求。

**验证入口**：Center 类型检查、相关单元与真实隔离 PostgreSQL 接口验证、OpenAPI 检查；Host 定向测试覆盖身份文件、本机管理和申请恢复。使用正式隔离 Host 发起申请，协议客户端执行管理员确认并回读。按本文件第五节选用检查命令，不访问既有企业库。

**完成判定**：申请到终态及用户分配可实际回读；未知结果不会产生重复设备，中心权限和本机管理边界正确；操作不改变本机业务数据或直接访问开关。未接通心跳的状态如实显示。

**Review 重点**：是否复制身份或登录体系；是否遗漏事务后通知边界；是否凭名字认领；迁移及降级影响是否明确；敏感材料是否进入 UI／日志。

### M1 统一连接与在线生命周期

**目标**：Host 持有一条受监督的中心连接，登记通知、在线判定、掉线与重连不依赖客户端页面。

**前置依赖**：M0 已获确认；设备身份与登记状态接口可用。

**交付范围**：

- 中心同端口 WS upgrade 与设备认证、控制协议协商；Host 进程级连接 owner 及读写／关闭任务收尾。支持 WS，WSS 按需使用。
- Ping/Pong、独立超时、退避重连、控制消息与缓冲上限；中心重启清空在线投影，设备重新证明身份。
- 登记变化通知与重连状态查询，旧连接事件隔离、并发身份冲突、睡眠／唤醒及明确协议不兼容反馈。
- 停用保留控制连接；注销／退出停止目标接入和旧身份重连。UI 关闭、用户退出及待登记不新增本机使用限制。
- 向本机快照／事件机制提供状态投影，F02 后续在同一 owner 上接入业务流；不新增独立桥接心跳系统。

依据：技术方案第五节和功能设计第五节。

**验证入口**：正式隔离 Host 与中心建立真实 WS；定向覆盖静默丢包、慢写、旧连接迟到关闭、中心重启和同身份冲突。常用时序用可控时钟验证，补真实进程连接验证；在隔离配置下核验可选 WSS 的认证与关闭行为。只用有界控制负载，不假称文件／终端混合负载已验证。

**完成判定**：在线状态由已认证连接产生，在确定期限内收敛；无界队列和遗留任务不存在；连接故障不停止本机 Host，已注销身份不能复活。

**Review 重点**：心跳是否被其他写入饿死；是否无限推迟期限；是否混用 Gateway／模型 WS；旧回调能否影响新连接；中心重启是否误注销设备。

### M2 用户接入与定向撤销

**目标**：真实调用者取得针对目标设备的访问许可，目标进入该用户已有业务域；撤销仅影响正确的访问范围。

**前置依赖**：M1 已获确认；技术方案第六、七节的接入与撤销边界已落实为可实施契约。

**交付范围**：

- 仅调用模式认证，未登记本机访问其他授权设备无需先发布自己；同一连接上的用户身份逐访问核验，连接身份不成为全用户授权。
- 中心准入、目标主体核对、本人设备目录及访问许可；普通访问和桌面权限使用同一分配事实。
- 目标已有当前登录的复用、首次接入的受控凭据签发与唯一用户状态安装；并发初始化、迟到结果及退出竞争不覆盖新登录。
- 用户／设备／单次登录的定向撤销及最长有效窗口；原中心用户复核仍独立有效，设备 Pong 不延长用户权限。
- 提供 F02／F04 所需的准入结果、取消和到期信号，保持进程内所有权；不创建新的 Session、Run 或持久授权平台。

依据：技术方案第六、七节，功能设计第六、七节。

**验证入口**：两个隔离正式 Host 和真实中心，通过正式认证控制消息完成 A→B 准入及 B 用户域初始化；复用现有用户域测试入口核验当前登录、模型配置凭据来源及用户隔离，不加入产品专用探针路由。覆盖 A 退出、B 退出、删除某设备授权、停用账号、中心重启和迟到签发，观察同一用户的其他合法入口与其他用户不被误清理。

**完成判定**：无需传播密码或共享调用方当前凭据即可完成可信接入；许可撤销／失联到期可以在正式 Host 中观察，访问作用域与用户任务生命周期明确分离。真实远端业务请求及模型执行的最终闭环留到 F02，不以 F01 许可测试代替。

**Review 重点**：能否仅凭设备秘密冒充用户；是否发生本机管理提权；是否借全局退出完成定向撤销；是否为尚无业务流预建庞大的传输体系。

### M3 正式管理交互

**目标**：用户和管理员通过正式产品入口完成登记及日常管理，不依赖测试客户端。

**前置依赖**：M2 已获确认；前述 HTTP、连接与用户接入均具备真实结果。

**交付范围**：

- Desktop 设置 → Runtime → 企业组网：申请、只读中心信息、同一登记状态查询、撤回及退出反馈；没有修改中心按钮或跳转入口。
- 企业后台设备卡片：已登记／未登记上下独立分栏、各自收起／展开、分页及错误反馈；审批后归属更新，刷新保持收起状态。详情、用户分配及启停／注销接入实际接口。
- Client 在现有配置菜单和状态查询中接入同一管理能力；需要申请时完成真实企业身份接入，密码隐藏，不增加 CLI 会话能力。
- 脏表单、提交锁、未知结果核实、离线审批、停用／离线区分、退出待注销与身份失效。复用现有组件和状态架构，不做独立原型作为交付替代。
- 同步对应模块说明与必要用户手册，描述实际可用能力；不提前开放 F03 远端项目／会话入口或 F04 桌面操作。

依据：交互设计指导第二至八节。

**验证入口**：相关前端类型、静态、协议生成与构建检查；对写入、身份和异步竞态执行定向测试。真实浏览器验证后台分栏、审批及授权；实际 Desktop 验证原生本机管理入口，Client 交互终端验证申请／查询／退出。窄窗口和键盘操作做交互检查，不编写逐字文案或 CSS 布局快照测试。

**完成判定**：本机提交申请到后台确认／分配，再回本机看到真实状态的完整链路可操作；卡片不混排，收起不改变设备状态，本机登记状态不遮挡正常工作区；无 GUI 设备可以独立完成同等登记流程。

**Review 重点**：是否误用侧栏当前远端设备作为登记目标；是否在本页恢复修改中心入口；是否 UI 直连组网 WS；是否刷新覆盖编辑或用旧数据假装提交成功。

### M4 F01 集成验收与收口（用户明确跳过）

2026-10-15 用户明确 F01、F02 为延续开发，跳过本里程碑。以下保留原范围供追溯，不作为进入 F02 的前置门禁，也不标为验收通过。与真实业务流有关的身份、心跳、撤销及断连检查并入 F02 定向验证；跨机器与 Windows／Linux 原生运行仍如实保留未测状态，不重复执行整套 F01 管理流程。

**目标**：验证 F01 独立交付结果，固定与 F02／F03／F04 的交接边界并提交用户验收。

**前置依赖**：M3 已获确认；M0—M3 的关键失败与恢复场景已在所属阶段通过，不将前面遗留实现推迟到验收。

**交付范围**：

- 两个独立正式 Host、一个中心、多用户及正式管理 UI 的端到端验证；至少补一次真实跨机器中心连接，不能把同机多个 Home 当作跨机器验证。
- 组合覆盖离线审批、停用再启用、退出时中心离线、注销重登、中心重启、用户权限移除与登录失效；确认本机正常工作、既有直接访问及 Gateway 配对不被误改。
- macOS Desktop 管理主路径、Windows Host 身份保存与重连、Linux Client 无 GUI 管理路径的适用验证；受限平台如实记录未测项，需用户接受限制后才能收口，不以编译替代运行。
- 核对协议兼容和隔离升级结果，补充实际恢复／回退说明；对本轮尚未覆盖且有风险的生产装配执行必要检查，避免无理由重复完整构建。
- 回写必要模块约束、用户手册和版本台账，在本计划保留完成结论及已接受限制，不新建独立验收报告。

**验证入口**：复用 M0—M3 的正式服务及交互入口；只补跨模块、跨机器和平台相关检查。涉及真实数据库的操作仍先核对；已有用户环境升级不在本里程碑默认授权中。

**完成判定**：本文件第六节满足，影响范围和未测限制有清楚结论，用户确认 F01 验收后标为已完成。F01 完成不触发版本发布；下一 Feature 按自己的设计与计划推进。

**Review 重点**：是否夸大验证范围；是否把设备在线等同所有业务可用；是否提前宣布文件、PTY、媒体撤销成功；是否存在未收尾的测试进程或混入公开文档的私有环境信息。
