## 二、拆分原则与跨 Feature 契约

按独立能力结果和状态所有权分为 F01—F05；F01—F04 沿现有依赖推进，F05 作为用户新增的模型接入能力独立验收，实施排期须单独确认，不自动并行。一个 Feature 完成后，后续 Feature 使用其已验收契约，不静默改变已完成的身份、授权或生命周期边界。

- F01 持有设备登记、明确用户分配和在线事实，交付统一连接与可信访问准入；本机使用不以设备登记为门槛。
- F02 在同一 Host—中心连接上接入普通业务流，覆盖 HTTP、SSE、文件和终端；中心只解析转发所需外层，界面仍连接本机 Host。
- F03 使用前述目录和传输能力，落实设备选择、项目与独立会话切换、本机置顶和右栏本地状态。
- F04 复用授权及撤销，补充桌面协商、直连优先媒体和输入生命周期。用户确认 macOS／Windows 被控、禁用 TURN；M0—M2 当前交付已确认，M3 接入多屏选择、共享采集和交付收尾，剩余实机验证转 v0.32.1 维护。
- F05 复用模型配置、具名方言和企业模型代理；本地与企业后台均可配置 OpenCode，本机 Runtime 编码原生请求并生成稳定会话头，中心保留配置／发现／下发与受限透明转发，不执行 OpenCode 方言。它不依赖 F02 设备业务隧道或 F04 媒体选型。

F01 不以身份和控制连接验证替代真实业务流。仍未覆盖的混合负载、平台及生命周期组合检查统一在 v0.32.1 定向补验，不重启 F01 M4 全量验收。

2026-10-19 调整：下列保留原验收维度；其中未完成部分已转 v0.32.1，不继续作为 v0.32.0 的实施待办。用户已在接受实际交付范围与未测限制后确认封版；这不表示原未测项目验证通过。

F01 保留 M0—M3 的身份、控制连接、许可及管理验证结果；M4 明确跳过。F02 须真实覆盖普通业务各传输形式，并结合实际数据流补验身份、撤销、断连和混合负载下心跳；F03 须在正式桌面端验证设备／用户／资源归属与本地偏好；F04 须以真实机器验证媒体、输入及授权失效。每项在所属计划记录完成结论，不以其他 Feature 的模拟结果替代。

F05 按配置与兼容契约 → 本机方言与会话路由 → 企业转发与完整接入三个里程碑推进；验收同时覆盖本地和企业配置来源。后台现有中心合成请求的测试路径不扩展 OpenCode 方言，推理验证由客户端 Runtime 执行；公开目录成功不等于订阅推理通过。

全部必需 Feature 完成后，再按 [总体设计第十节](总体设计.md#十版本整体验收门禁)执行跨 Feature 验收，重点覆盖：

1. 同中心的多设备、多用户完整业务操作及定向撤销，不产生本机管理提权或用户域混用。
2. 大文件、终端与桌面繁忙时控制连接仍可管理，断连／取消／未知结果不重放副作用。
3. 侧栏设备范围、本机置顶和右栏标签一致，上传、预览、下载与终端归属正确。
4. 远程桌面优先直连，中心普通桥接与媒体通道分工可核验；真实平台范围及未测限制明确。
5. 原本机、直接访问、企业身份、协议及数据升级行为不回退；实际迁移／恢复按数据库安全规则执行。
6. OpenCode 本地／企业配置能力一致，原生请求与稳定会话头由实际执行会话的 Host 产生；经中心正文与必要请求头保持一致，跨设备显示不改变执行 owner，企业端不新增方言编码或会话生成逻辑。

版本验收通过并获用户确认后才归档。软件版本、安装包、部署和发布按最终源码与实际授权处理；F01 完成不触发单独发布，前版交付收尾也不自动并入本版。
