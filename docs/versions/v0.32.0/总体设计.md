## 二、目标与范围

用户在一个桌面客户端中浏览和使用多台已授权设备的项目与会话。界面始终通过本机 Host 发起业务操作，本机 Host 在接口入口判断本机处理或远端代理；目标 Host 继续拥有会话、任务和文件。用户不需要为远端会话另开客户端，也不需要理解文件传输或桥接细节。

典型结果：在电脑 A 的侧栏选择电脑 B，查看 B 上本人可访问的项目，创建会话、上传 A 的截图和文件、处理审批、查看产物，并在本地右栏使用 B 的文件资源、交互终端和经授权的系统桌面；将 B 的会话置顶后，切回 A 的项目列表仍可通过本机置顶入口打开 B 的原会话。

### 已确认方向

1. 企业中心登记设备，并设置每台设备有哪些用户可用；中心在业务数据通道中仅作桥接，不解包会话、文件、终端和桌面画面／输入内容。
2. 电脑或服务器上的 Runtime Host 是执行节点；企业中心是独立角色。二者可以同机部署，但服务器节点不等于企业中心。
3. 界面不持有组网连接与桥接逻辑。本机 Host 统一代理远端请求，复用现有业务接口、上传下载和事件语义。
4. 在置顶列表与项目列表之间设置设备入口。项目和独立会话随设备切换，置顶区保持不变。
5. 置顶是本机独立配置，可引用本机或远端会话，不拉取远端置顶列表。
6. 右栏标签页是本地工作状态，不同步其他设备或客户端的标签状态；标签内容可以来自远端，终端需完整覆盖双向数据通道。
7. 手机端暂不作为本版目标，先完成现有客户端跨设备使用。
8. 本版增加远程桌面能力，参考 `ez-vnc-demo`；WebRTC 纳入重点候选，尚未确定最终传输与编码方案。用户明确不希望服务器承担全部代理流量：远程桌面按两端 Host 直连优先设计，中心负责授权与连接协商；2026-10-15 用户确认首版不启用 TURN，直连失败提示不可连接。
9. 用户进一步明确：仅远程桌面优先直连，附件、文件、会话、终端等其他业务先经中心桥接；两类通道共用身份与授权，不强求相同传输实现。

10. 本版纳入 Host 与中心之间的设备在线心跳，优先采用 WebSocket 控制连接；由 Host 持有，不绑定 UI、会话或用户登录。未登记、待登记和设备心跳掉线不新增本机功能限制，企业身份规则仍沿既有机制执行。
11. 本版补充 OpenCode 接入：两端保留完整服务商／模型配置，复用独立模型列表路径和现有 Chat／Responses 方言机制；会话标识与产品请求头在执行会话的 Host 产生，中心保持配置、发现、下发与透明转发职责，不实现 OpenCode 方言。

### 本草案建议的首版边界

- 新组网能力先覆盖同一企业中心下登记、授权的 Host，由中心桥接打通内网设备；个人模式的本地使用和既有直连另行保持现有口径。本版不把企业中心改造成个人云服务，不加入跨中心联邦。
- 桌面端为主要交互验收入口。Client 随包 Host 也可作为执行节点；不因此新增 CLI 会话命令。共享 Web 代码和既有直接访问能力须回归，完整 Web 多设备工作区及其本地置顶存储不作为首版承诺。
- 普通业务接口按用户确认以中心桥接闭环为完成条件；远程桌面媒体按最新约束改为 Host 直连优先，通用业务 P2P 优化与 SSH 接入暂不纳入。Host—中心统一采用 WebSocket 连接（支持 WS，WSS 可选）承载心跳、控制与业务桥接，具体封装和流映射按 F02 技术方案实施，不把既往 iroh／QUIC 候选或 Codex SSH 参考当成已选技术。
- Agent 自动跨设备委派、统一任务调度、会话迁移、目录同步／挂载、跨设备文件编辑、持久终端及离线任务投递不纳入本版。它们可以复用后续形成的 Host 通道，但不预建接口。
- 远程桌面是用户主动查看和控制目标系统桌面的能力，作为 F04 纳入。WebRTC 优先评估，现有 RFB Demo 作为对照；音频、系统剪贴板同步、桌面内文件拖拽传输及无人值守登录不作为本草案首版承诺。2026-10-15 用户确认首版同时支持 macOS／Windows 被控，Linux 被控后置；当前 Demo 和本机探针不代表两平台均已完成。
- Agent Computer Use 保持独立分支；助理模式、持久自动化、前版安装包收尾均不自动并入本版。

上述建议边界随总体设计确认；不是此前用户已经逐项确认的功能限制。

## 四、系统边界与数据归属

```text
本机操作：Desktop → 本机 Host → 本机 Runtime／文件／PTY

远端操作：Desktop → 本机 Host ⇄ WS／可选 WSS ⇄ 企业中心 ⇄ WS／可选 WSS ⇄ 远端 Host → Runtime／文件／PTY
                                     路由与流控；业务载荷原样转发
```

普通业务桥接支持 WS，WSS 作为可选部署配置，不强制证书或 TLS，不叠加 Host 间业务载荷端到端加密。加密增强可在后续有明确需要时另行安排，不作为本版交付前置；选择 WSS 时沿用标准 TLS 实现。用户所说“中心不解包”指中心无需解析业务正文，不是中心技术上无法读取内容：中心处理 WebSocket 帧及必要的身份、路由、流编号和流控信息，业务载荷按字节转发；业务请求由目标 Host 解析与执行。中心收到转发字节不表示目标接纳请求，不记录业务正文，也不复制 Session／Run 状态。中心既有模型代理仍按原职责处理模型内容。

| 权威事实／资源 | 所有者 | 其他层能持有的内容 |
| --- | --- | --- |
| 企业用户、设备登记、用户可用设备关系 | 企业中心 | Host／UI 的受控目录与授权投影 |
| 设备持有的身份材料、中心连接和对端通道 | 各设备 Host | UI 只取得设备标识和状态，不持有组网凭据 |
| 目标用户域、项目、会话、Run、审批、附件与产物 | 目标 Host／Runtime | 本机 Host 转发、UI 展示，不复制第二份可写会话 |
| 目标系统桌面、采集与输入执行 | 目标操作系统；目标 Host 管理访问和辅助程序 | 本机 Host 交付画面／转发输入，当前客户端持有查看标签；不为会话创建独立桌面 |
| 远端交互终端进程 | 目标 Host Supervisor | 本机代理通道、当前客户端 xterm 显示 |
| 置顶引用和顺序 | 当前客户端本机配置 | 读取原会话的标题／状态，不修改远端置顶 |
| 右栏标签、布局、查看位置、草稿 | 当前客户端本地状态 | 记录目标设备与资源引用，不向其他客户端同步 |

设备编号必须跨正常 Host 重启保持，不能直接使用每次启动变化的实例编号或可修改名称代替。设备重装、重新登记、复制 Runtime Home 和身份冲突的处理由 F01 明确，旧引用不得静默指向另一设备。会话和资源引用须有中心／用户／设备作用域，不能只依赖裸 SessionId 或路径。

设备可用权限不等于读取该设备所有用户数据。默认按中心可信用户身份访问目标 Host 的本人用户域，复用既有项目、文件和工具权限；不引入跨用户共享项目，也不把项目目录描述成操作系统强沙盒。服务器节点关机或离线时，中心不代替它执行任务。系统桌面是操作系统登录会话的共享资源，不能套用 Runtime 用户域隔离承诺；设备可用授权之外，F04 须明确桌面查看／控制的准入与本地系统权限，不能让普通项目访问自动获得桌面控制。

## 五、Host 接口代理契约

### 5.1 统一入口

本机 Host 接收界面意图，验证调用者身份，解析目标设备并校验可用权限，然后选择本机处理或远端代理。设备是统一路由元数据，具体承载位置由 F02 确定；现有业务 DTO 和方法尽量保持原样，不逐个处理器重复编写远程分支。

- 在完整消费请求体、创建本机会话／附件或初始化无关本地业务域之前分流。
- 目标只能是已登记且获授权的设备，不能接受任意目标 URL 作为转发地址。目标身份固定到整个请求或长连接，不随侧栏选择变化。
- 复用现有路由分组声明可代理性。`/commands` 含多个业务和管理分支，不能仅按 URL 全量放行；F02 必须核对混合命令准入、有限正文解析及最终分发边界。
- 登录、本机 bootstrap、模式配置、停止／重启、安装升级等具有本机管理语义的入口不自动远程化。远端项目管理不扩大为远端进程管理。
- 保留语义所需的方法、路径、查询、正文、状态码和响应头；逐跳头、认证材料、重定向、Cookie、媒体 URL 等按具体协议安全转换，不能笼统透传全部头。
- 远端重新核验可信调用者、目标设备和资源权限，不信任 UI 自报用户编号，不传递本机 bootstrap 特权；桥接进入 loopback 也不能成为本机特权来源。已代理请求不再二次转发，避免循环。

### 5.2 必须覆盖的通道

设备在线由 F01 的 Host—中心控制连接与心跳判定，详见 [F01 心跳及冲突边界](features/F01-设备登记与用户授权/功能设计.md#51-host-在线心跳)。心跳、控制和桥接优先共用同一 Host—中心连接，F01 建立连接生命周期，F02 增加流映射；不为心跳单独建立平行连接系统。它与下面的业务通道分工：同一设备在线不表示每条请求、终端或桌面均可用；控制通道复用和数据调度须由 F02 保证不会让大流量阻塞心跳与撤销。

| 通道 | 行为要求 |
| --- | --- |
| HTTP Command／Snapshot／目录与资源查询 | 维持原请求结果、错误和幂等语义；错误区分目标拒绝与通道不可用 |
| SSE | 长连接流式转发，设备级隔离事件及恢复位置；继续使用既有缺口查询与快照恢复，不把设备 A 的游标用于 B |
| Streaming Upload／Download | 有界缓冲、背压、取消和完整性校验；不默认整文件落本机或中心；核查既有媒体、流式响应和范围请求支持，未支持的能力不虚构 |
| WebSocket 用户终端 | 转发握手、文本控制帧和二进制帧、关闭与错误，保持端到端输入输出 ACK 语义；传输心跳与应用 ACK 分开 |
| 远程桌面控制面与媒体数据面 | 打开／关闭、授权和连接协商复用 Host 接口；画面与输入按 F04 的媒体方案承载。WebRTC 不等于 HTTP／WS 透明转发，不照搬终端 ACK，也不默认把全部媒体塞入有序文件通道 |

代理连接丢失不等于目标尚未接纳写请求。代理层不自动重放有副作用的请求或终端输入；使用目标原有的首次发送查询、输入幂等与附件去重机制确认结果。通道取消仅取消相应传输，业务停止通过原停止接口表达；终端断线回收另按第七节处理。

普通业务中心桥接因中心停机或授权撤销不可用时，不将目标任务自动迁回本机。目标已接纳 Run 按原 Runtime 规则处理，仍可能受中心模型代理或身份复核不可用影响，不承诺企业任务在中心停机后一定完成。设备访问撤销对连接、终端和已接纳任务的具体影响须与既有用户退出规则逐项区分。

## 六、桌面交互基线

### 6.1 侧栏与新会话

侧栏相关区域顺序固定为：**本机置顶列表 → 设备切换入口 → 项目列表 → 独立会话列表**。

- 初次进入默认本机。设备选择展示本人可用设备及在线状态；项目与独立会话只显示所选设备的数据，不汇总全网独立会话、不增加设备分组层级。
- 设备切换改变下方浏览范围，不改变当前已打开会话的执行位置，也不关闭其他设备的右栏终端。加载失败、离线与空列表分别展示，不将迟到结果写入新选择。
- 新建会话输入区的设备选择位于项目选项左侧；本草案建议全局新建继承当前侧栏设备，从项目新建带入项目所属设备。首次进入为本机，具体默认值保存范围在 F03 交互指导确认。
- 切换新会话设备后加载目标项目、模型、智能体、Skill／MCP 可用配置；不能沿用本机项目 ID、文件路径或已上传附件 ID。正文和本地待发送文件可保留，失效配置明确提示。
- 首次发送开始后固定目标设备与发送清单；结果未知时先向原目标恢复，不切设备后重发同一提交。已有会话绑定所属设备，不提供迁移执行地。
- 会话标题和非本机资源保留设备提示，避免浏览设备与当前会话所属设备不同造成误操作。
- 上方智能体／插件管理和设置不因下方设备筛选而静默换目标；本草案建议沿用本机管理范围。远端会话使用目标设备已有配置，缺失能力需明确提示；远端插件安装／管理是否纳入须在 F03 功能设计前收敛，不能由通用代理默认开放。

### 6.2 项目与文件

项目及目录归所属设备的用户域管理。查看、新建、重命名、编辑和移除沿用目标 Host 的项目接口；新建项目目录选择器浏览目标设备目录。移除项目与删除实际目录按既有语义区分。

项目目录在正文当前会话／草稿的右栏项目标签中浏览，目标取自其设备和项目，读取文件不自动加入模型上下文。
2026-10-16 用户明确取消此前自行增加的右栏独立项目浏览模式；侧栏项目不提供脱离正文的文件浏览入口。
从当前会话的远端文件引用打开本地右栏，通过代理读取内容。文件选择、图片粘贴使用当前客户端已有能力；不把远端路径交给当前电脑的系统文件打开接口。

首版不强制增加“任意设备 A 文件直接加入设备 B 会话”的新资源抽象或服务端拉取接口；已有下载到本机再选取上传可以完成显式传递，后续按真实需求评估组合入口。界面正常的上传、预览、下载均直接复用原 Host 接口。

### 6.3 本机置顶

置顶为本机独立快捷入口，记录设备及会话身份、必要展示信息和顺序，并按当前登录主体隔离。可置顶本机或远端项目会话、独立会话；置顶和取消置顶不修改目标 Runtime 会话属性。

切换设备不变更置顶区，点击置顶直接代理访问原会话，不要求先切换项目设备。远端项左侧增加设备图标并可查看设备名称。离线、权限失效、会话删除时保留可识别的不可用入口，允许用户移除；缓存标题不是权限或会话仍存在的证据。

现有 `is_pinned` 是持久化事实，本版必须评估本机旧置顶的保留／导入、旧字段和命令处理、列表排序与分页影响。不得持续拉取或导入其他设备的置顶，不新增长期双写体系；具体迁移和兼容选择在 F03 技术方案获得确认后实施。

## 七、附件与右栏完整闭环

### 7.1 附件、图片和产物

1. 选择文件／粘贴图片时只保存本地待发送选择，延迟到发送时上传。
2. 新会话复用首次发送物化接口；已有会话复用附件上传后提交消息的流程，均通过本机 Host 送到会话所属设备。
3. 目标 Host 校验、保存并登记附件；图片理解和 Agent 文件工具在目标执行。中心与本机代理不创建另一份远端附件权威记录。
4. 预览、缩略图、下载、消息资源链接和产物均带设备作用域，经本机 Host 取回。媒体地址不能暴露远端内网地址，也不能要求 WebView 直连远端。
5. 上传完成、目标保存、消息接纳和 Run 状态分别展示。部分附件成功时复用既有成功记录，失败项可重试；网络响应丢失按原目标结果确认，不重复创建会话或执行任务。

### 7.2 本地右栏状态

复用现有按会话／草稿持有标签组的机制，加入设备和用户作用域；不另造共享工作台或全局同步标签。标签的顺序、激活状态、查看位置和布局只保存在当前客户端；切换会话展示所属标签组，切回时恢复本地工作现场。

右栏始终跟随正文当前会话／草稿，不设置独立项目组、固定右栏选择或“返回会话”入口。
只切换侧栏浏览设备不改变正文和右栏；重启恢复仅重建各所属组的资源描述，不让旧会话资源覆盖当前显示组。
此规则已按 2026-10-16 用户要求同步 F03 方案并修复实现，确认与安装版验证状态见[本版修复项](开发计划.md#五现有功能缺陷修复)。

远程桌面由当前设备的资源 Store 持有，同设备会话／草稿共享一份桌面标签及连接，从右栏“＋”打开；普通资源仍按会话／草稿归属。

远端资源标签记录原设备和资源引用，任何操作都使用该绑定，不能借当前侧栏设备寻址。关闭普通资源标签只取消所属读取或释放视图；不删除远端资源。重启只恢复可验证描述，不保存文件正文、登录凭据、终端输出或可复用进程句柄。

本地浏览器标签仍使用当前电脑的 WebView 和网络环境。访问远端终端启动的 `localhost` 服务涉及另一个端口代理问题，不从文件代理推导已支持，本版不默认引入通用端口转发或远端浏览器共享。

### 7.3 用户终端

- xterm、标签和滚动缓冲属于当前客户端；PTY／Shell 属于目标 Host Supervisor。用户终端与 Agent Shell 分开。
- 创建时固定目标设备、用户、来源会话／项目、目录和 Shell。键盘输入、输出、resize、错误及 close 经过本机 Host 和中心桥接；其他客户端不共享这一 PTY 或标签。
- 保留现有“远端写入后确认输入、客户端解析后确认输出”的背压。代理不得提前伪造业务 ACK，控制帧不能被等待输出确认阻塞；各通道有界并隔离慢消费者。
- 隐藏标签、切换会话和侧栏设备保留活动连接；当前客户端切回时沿用原 PTY。真正关闭标签时请求关闭该终端，并收敛目标进程回收，不能清理全 Host 的终端。
- 原有断线／登录撤销／来源删除／Host 停止回收 PTY 的规则继续成立；本机客户端连接断开必须传播至对应远端通道，不能因本机 Host 仍在线而遗留无人拥有的 PTY。
- 通道重建不自动重放终端输入，也不假称恢复旧进程。重启恢复标签或断线后的重新创建，均明确是新终端；持久终端和断线续接不纳入首版。

### 7.4 远程桌面：查看与人工控制

本版建议在所选设备的操作入口提供“打开桌面”，在本地右栏显示桌面资源标签。标签固定目标设备；侧栏和会话切换不改变被控对象，也不新建系统桌面。复用右栏本地标签描述与查看状态，查看连接与目标 Host 桌面资源分离；多标签复用还是多查看连接在 F04 交互指导收敛，不复制目标桌面权威状态。

- 默认只读，显式开启控制；目标 Host 实际校验查看／控制权限和原生权限，前端按钮禁用不能替代授权。权限不足、无图形桌面、离线和采集未就绪分别反馈。
- 覆盖显示器选择、缩放、全屏、指针、点击、滚轮、组合键和文本输入。显示器坐标、缩放及原生输入由目标平台处理；首帧到达才表示画面就绪。
- 显示器选择是查看请求的一部分。Demo 目前共享一个采集源、切屏会影响所有查看者；正式产品须明确多查看者的切屏影响，不静默将这一全局行为当成本地标签操作。共享控制或独占控制的规则在 F04 明确。
- 停止控制、失焦、撤销与断线必须释放本连接按下的键和鼠标按钮；重新连接恢复只读，旧输入不重放。释放不能误清其他查看者的有效输入，需核对多控制者状态归属。
- 关闭标签释放对应查看连接，不关闭目标系统应用或其他查看者。共享采集资源由 Host 按实际使用管理，Host 停止须回收辅助程序。标签恢复不保存控制权限或可复用连接凭据。

### 7.5 WebRTC 候选与 Demo 复用边界

用户提出 WebRTC，并明确不希望服务器承担全部代理流量。本草案将其作为远程桌面的重点候选，优先验证 Host 直连；这替代前稿“媒体必须经中心中继”的建议，尚不锁定具体库、编码器或进程拓扑：

```text
媒体与输入：本地右栏 ⇄ 本机 Host ══ 加密直连优先 ══ 远端 Host ⇄ 采集／输入
协商与授权：                本机 Host ⇄ 企业中心 ⇄ 远端 Host
直连失败：                  明确提示不可连接；首版不启用 TURN 或中心媒体中继
```

1. **控制面**：设备选择、查看连接创建、授权、关闭及协商信息仍经本机 Host 统一入口。WebRTC 的信令需要应用自行承载，可复用组网身份与控制通道；它不替代企业授权和资源生命周期。依据：[WebRTC 连接与信令](https://webrtc.org/getting-started/peer-connections)。
2. **画面与输入**：候选为编码视频承载画面、DataChannel 承载键鼠控制；原生采集和输入可以保留分层，但不要求把原始 RFB 全量装入 DataChannel。按键按下／释放须保证顺序与完整性；可合并的移动事件不能阻塞关键输入。具体通道语义、编码、清晰度与延迟取舍由验证决定。
3. **本机 Host 边界**：优先评估由两端 Host 持有跨设备 WebRTC 连接，本机 Host 再向本地界面交付媒体。本地交付方式、是否需要二次协商／编码及其成本必须验证；仅把信令走本机 Host、让 WebView 直接连接远端媒体，不满足当前约定。这里的“同接口”指统一业务入口，不表示所有媒体都用同一种字节转发。
4. **直连与失败策略**：中心交换连接信息，STUN 获取映射地址，ICE 检查可用路径；2026-10-15 用户明确首版不启用 TURN，直连失败提示不可连接，不回落到普通业务桥接。STUN 无法保证覆盖所有 NAT／防火墙；同网和跨 NAT 仍须实机验证。沿用 WebRTC 原生传输安全，校验协商与当前访问身份；中心控制连接取消、授权到期或撤销均须收尾媒体与输入。依据：[WebRTC 连接与信令](https://webrtc.org/getting-started/peer-connections)、[TURN 中继](https://webrtc.org/getting-started/turn-server)、[WebRTC 安全架构 RFC 8827](https://www.rfc-editor.org/rfc/rfc8827)。
5. **与 F02 的关系**：复用设备授权、可信身份、控制入口和撤销规则；媒体通道由 F04 专项验证，F02 不宣称通用代理已覆盖 WebRTC。媒体拥塞不得挤占终端输入、会话命令和文件控制消息；带宽、丢包、重连和资源上限均需整体验证。
6. **复用与替换**：Demo 的采集／输入、多屏坐标、只读过滤、松键及标签生命周期可作参考；采用视频时 noVNC／自研 RFB 服务不预设保留。Demo 没有视频编码／WebRTC 实现，不能把换传输名称当成已完成适配。RFB 仅作对照方案，不预先增加双栈长期维护或静默降级。

F04 首版被控范围已确认为 macOS／Windows，不启用媒体中继。正式方案与计划已确认，M0—M2 当前交付获确认，M3 实现及测试包已交付；真实多屏／旋转／热插拔、跨 NAT、持续弱网及输入组合的剩余验证已于 2026-10-19 按用户要求转 v0.32.1 维护。当前结果与边界以 [F04 开发计划](features/F04-远程桌面查看与控制/开发计划.md)为准。

### 7.6 远程桌面连接与失败交互

以下为总体设计中的建议流程，具体超时、限额及字段留待 F01／F02／F04 方案共同确定，不新增独立的连接业务数据库：

1. 用户从设备入口打开桌面，本地标签立即绑定设备；本机 Host 校验当前用户，目标 Host 核对设备授权、桌面查看能力及系统权限。设备在线只表示可发现，不代表已能采集或连接。
2. 两端 Host 通过已认证的协商入口交换连接信息、检查路径。界面展示“正在连接”；连接过程可取消、等待有上限，取消后迟到结果不能重新激活标签或遗留采集资源。
3. 直连建立且收到可用首帧后展示桌面，初始只读；连接详情显示实际直连路径。用户显式开启控制后，目标再次核验控制权限，授权结果不沿用旧查看连接。
4. 无法直连时，提示“当前网络无法直连”，提供重试；仍可使用其他已经连通的项目与会话能力。本版不使用 TURN，不把整段媒体改走普通文件代理。
5. 网络变化或连接失败时立即停止输入，目标按连接失活规则释放按键；冻结画面须标明已断开，不能继续显示为实时画面。重连后恢复只读，不重放旧输入，不承诺无缝切换路径。
6. 关闭标签、撤销权限、退出登录时，收敛本机连接、远端查看者及其输入状态；共享采集器按剩余使用者管理。仅切换侧栏设备或隐藏标签不改变目标、控制授权和资源所有权；失焦仍释放当前按键。

中心的在线状态与数据通道状态分别处理。F04 沿 F01 现有取消与到期行为：控制连接已判定断开时立即取消所属访问，即使媒体尚通也停止查看与控制；静默故障以现有许可到期上限收敛。撤销通知到达时立即执行，不承诺网络尚未检测到失联时瞬时撤销；详见 F04 技术方案。

本版不纳入中继，界面不需要用户填写 ICE／SDP 参数。直连方式只在桌面连接详情展示。实际流量归属仍须验证，不能仅凭“已使用 WebRTC”认定媒体没有经过中心。

### 7.7 各类流量的统一范围

统一的是 UI → 本机 Host 的入口、目标身份、用户授权和取消／错误边界；普通业务流与视频不必采用同一种编码、可靠性或连接实现。现有 Command、SSE、文件上传下载和终端协议继续保留，不能为了共用 WebRTC 改写成另一套应用协议。

用户已确认以下范围，作为 F02／F04 的共同边界：

| 数据／操作 | 首版路径 | 负责 Feature |
| --- | --- | --- |
| 项目、会话、审批、SSE、附件、文件和交互终端 | UI → 本机 Host → 中心业务载荷转发 → 目标 Host | F02；F03 完成桌面接入 |
| 桌面打开、授权、连接协商与关闭 | 本机 Host 经中心协调，目标 Host 执行最终准入及清理 | F01／F02 提供身份与控制入口，F04 接入 |
| 桌面画面及键鼠输入 | 两端 Host 直连；失败提示不可连接，首版禁用 TURN | F04 |

因此中心仍承载附件／文件等普通业务流量，并非纯信令服务器；此次节省中心带宽的范围是远程桌面。文件大小与并发、普通桥接背压继续由 F02 验证。桌面直连失败不自动改变普通业务路由，普通业务桥接成功也不能冒充桌面已连通。媒体、文件和终端各自保持限额与取消边界，不新增自动跨通道搬运或无感业务重放。

## 九、兼容、实施约束与待细化项

- 当前 Desktop／Host 软件版本为 `0.32.0`。F05 M0 因新 Provider 枚举及旧 TS 消费者缺少未知类型拒绝逻辑，将应用兼容下限统一提升为 `0.32.0`；存储下限保持 `0.30.0`，企业协议保持 3。两种下限独立，旧正式 Host 仍由迁移账本检查阻止读取新版本库。
- 既有个人直连与本版“本机 Host 代理多个设备”是不同入口。新设备筛选不能复用旧全局切换并销毁连接／草稿的行为。新旧入口支持范围和 Web 退化行为须在 F03 明示，不隐式代理本机管理接口。
- 设备和用户关系是新增持久化候选，复用中心唯一升级账本与身份机制；具体表、密钥保存和撤销机制由方案论证。不得提前建库或修改用户数据。
- 置顶从 Runtime 事实改为本机偏好，必须完成旧格式、分页、用户隔离、缺失设备引用、恢复和回滚方案；客户端现有偏好文件优先复用，不为快捷入口另建业务数据库。
- F01 技术方案确定登记者与审批入口、设备身份及重装规则、用户绑定证明、在线判断、撤销／中心重启后的恢复；不能把设备名、地址或 UI 用户编号作为身份凭据。
- F02 技术方案确定 WS 接入及可选 WSS 配置、设备认证、桥接流映射、连接与请求所有权、终端首帧鉴权、混合 `/commands` 路由准入、SSE 归属和错误映射。逐项列出所有可代理接口及本机专用例外，不创建另一套 Session／Run 协议。
- F03 功能设计先收敛管理页面作用设备与远端缺失智能体／插件的使用路径；技术方案再明确本机偏好存储、旧置顶过渡和新草稿默认。右栏持久化延续现有用户隔离，不引入跨客户端共享。
- 目标设备自身的路径解析、大小写、文件类型、权限和 Shell 差异由其 Host 处理。代理不得用本机平台重新解释远端路径。
- 依赖方向保持现有架构：组网与代理位于 Host／中心接入层，不进入 Agent Core；Runtime 仍只管理本设备用户域业务，不复制远端状态。是否需新增 crate 或公共类型，必须在核查复用后单独论证。
- F05 复用现有 Provider 配置和 Adapter，最小补充显式 OpenCode 身份与模型工厂的稳定会话路由输入；不增加会话映射表或 Core 专属分支。两端配置、企业下发及旧 Host 未知 Provider 的兼容影响在 F05 M0 收敛；未经真实路由验证，不推断 WS、续接、原生压缩或计量可用。

## 十、版本整体验收门禁

2026-10-19 范围调整：本节仍作为能力与风险核对维度；未完成部分统一转入 [v0.32.1](../../versions/v0.32.1/遗留事项.md)，v0.32.0 已按用户接受的实际范围与明确限制验收归档，不以转入替代未测项目验证通过。

以下是本版必须覆盖的结果，实际平台和未测限制在实施计划中维护，不预先宣称通过：

1. 两个内网执行设备经同一中心登记，授权用户能通过本机 Host 访问目标；未授权用户、伪造设备、错误中心／用户绑定均被拒绝，桥接不具有本机特权。
2. 中心只解析必要的连接、身份及路由／流控信息，不解析或记录普通桥接业务正文；WS 模式无证书前置且完整可用，WSS 按显式配置启用，不要求中心技术上不可读取内容；断连与撤销真正阻断相应数据通道，不破坏其他设备连接；设备心跳不替代用户身份复核，旧连接事件不能覆盖重连后的状态。
3. 同名项目、相似目录和设备重连下，项目查询、创建／编辑、会话及审批始终落在正确的设备与用户域。
4. 设备切换仅刷新项目与独立会话；本机置顶可引用多设备会话，远端置顶不会自动出现，当前会话和活动终端不会被侧栏切换停止。
5. 本机文件和剪贴板图片发送到远端，首次发送、已有会话上传、附件-only 输入、预览、缩略图、产物与下载完整可用；失败与未知结果不产生重复业务副作用。
6. HTTP、SSE、流式文件和终端 WS 经相同代理入口工作；慢消费者、大文件、取消和一个通道断开不引起无界缓冲或其他设备状态串写。
7. 终端输入输出、resize、关闭、登录撤销和断线回收符合目标 Host 既有语义；断线后不重复输入、不冒充恢复旧 Shell。
8. 同一远端会话在两个客户端打开时，各自右栏标签与置顶独立；文件与任务仍来自同一目标权威状态，界面缓存不会被误当成已保存事实。
9. 原本机使用、既有直接访问、企业用户隔离、应用／存储兼容与受控退出不回退；旧本机置顶和右栏偏好的处理符合已确认迁移口径。
10. 远程桌面经本机 Host 在两台真实设备间优先直连显示画面、正确映射多屏输入，并核验中心未承载该直连媒体流量；未授权／只读不能注入输入，断线与撤销释放按键，重连恢复只读。关闭一个标签不影响其他查看者和目标应用。若采用 WebRTC，媒体身份绑定、本地交付、直连失败反馈及禁用中继策略均须实际验证；直连状态下权限撤销仍有效。
11. 在确定的平台与网络条件下验证画面清晰度、输入延迟、带宽及 CPU／内存上限，并验证媒体繁忙时会话、文件和终端仍可用；无图形环境、系统权限缺失及多查看者行为符合已确认范围。
12. 心跳在 UI 关闭后随 Host 继续；Host 停止、睡眠、静默丢包、中心重启与重连状态正确，正常文件／终端负载不饿死心跳。未登记或心跳断开不新增本机功能门禁，终端／媒体与用户权限按各自生命周期处理。
13. 以正式 Host 和桌面端覆盖计划中确定的 macOS／Windows 交互及适用的服务器 Host 平台；隔离环境一律在项目 `.runtime-test/` 下新建。数据库按根规则核对，生产和共享数据操作另行授权。
14. OpenCode 在本地与企业模式均能完整配置，发现与推理路径正确；本机同一 Adapter 生成请求及稳定会话头，中心转发保持正文和必要头一致。跨 Run／恢复稳定、会话／子任务隔离，远端执行仍使用目标 Runtime 的 owner。公开列表、模拟上游与真实订阅验收结论分别表述，未测路由明确保留。

全部必需 Feature 按实际交付范围完成并经用户确认后，再执行跨 Feature 版本验收；F01／F02 采用上述连续开发与合并验证安排。总体设计确认不自动授权后续里程碑，版本归档不等于打包、部署、提交或发布。
