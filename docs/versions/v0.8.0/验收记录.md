## 三、实际能力验收

- 正式 `assistant-runtime` 持有 Session、规范 Conversation、Run、事件、取消、并发和关闭状态；
  Host 只负责顶层资源装配、Unix Socket 传输与进程生命周期，不保存第二份权威业务状态。
- 一个 Session 持有一个长期复用 Agent；同一 Session 的上下文变更 Run 串行，不同 Session 使用
  Tokio 异步并发，不创建会话级操作系统进程。
- `assistant-protocol` 只承载跨层 ID、Command/Result、Snapshot、Event 和安全错误 DTO，不依赖
  Tauri、Runtime 实现、数据库或具体 Provider。
- Host 使用内核实例锁解决单实例与异常退出恢复；稳定 lock 文件不是运行状态，进程结束后锁由
  内核释放，取得锁的新 Host 才能替换 stale Unix Socket。
- 私有 Ratatui Demo 可以自动创建/选择 Session、发送消息、观察 Run、取消、滚动、断线后手动
  重连、本地退出和确认关闭 Runtime；其 wire、状态与快捷键不构成正式产品协议。
- Host 只注册并允许无外部副作用的 `echo_text`；未匹配的已解析工具调用默认拒绝。本版本没有把
  文件、Shell、工作模式或审批规则提前接入 Runtime。

```text

cargo tree -p assistant-runtime-host --depth 2
```

Host 全功能测试为 **31 passed / 0 failed**，覆盖 CLI、frame、握手、权限、单实例、stale socket、
断线续跑、重连取消、受控关闭、TUI 状态和长文本滚动。依赖检查结果与设计方向一致。

### 5.3 真实 Provider 与跨进程链路

使用独立临时 Runtime 目录完成：

1. 创建两个不同 Session；
2. Session A 连续完成两轮上下文对话；
3. Session B 调用 `echo_text`，Run 快照为 `completed`，收到三个工具阶段事件；
4. 取消活动 Run，得到 `cancelled` 与 `cancel_requested = true`，随后同 Session 新 Run 完成；
5. 新 Run 接受后断开客户端，三秒后重连并查询到最终 `completed` 快照；
6. `ShutdownRuntime` 返回 `stopped`，Host 正常退出并移除 socket。

验证输出只保留状态、字符数和工具阶段，不保留 credential 或完整模型交互正文。验证专用 lock 文件
和临时目录已清理；用户原先启动的默认 Runtime 未被占用或关闭。
