## 二、版本目标与成功标准

用户能够连续阅读长会话、快速找到较早的输入和回复、修改历史输入重新执行，在运行过程中通过介入调整接下来的工作，并整理侧栏项目与会话顺序。

成功标准：

1. 一次历史加载取得若干完整轮次，同一轮不因工具调用多而反复触发分页 loading。
2. 宽窗口利用正文左侧留白提供缩略导航；未加载正文也能按需预览和定位，超长列表可独立滚动。
3. 用户消息具有可发现的复制与编辑入口；编辑提交在原会话可靠替换目标及尾段，刷新后仍反映相同结果。
4. Enter 的队列行为保持，Ctrl + Enter（macOS 兼容 Command + Enter）和队列项“介入”都立即打断当前 Run，保存已输出内容后换轮；旧轮保持真实终态、新输入仅启动一次。
5. 上述交互共用真实历史、身份和执行状态，保持组织、用户、设备与会话隔离，不产生第二份历史或调度权威。
6. Desktop／Web 的项目和会话默认按创建时间、新建在前；手动顺序由 Host 保存，分页遵守最终顺序，刷新和重新连接后仍可恢复。

## 三、范围与明确非目标

范围覆盖正式 Desktop 及复用同一前端的 Host Web，包含本机和已有授权的远端会话。服务端行为位于目标 Runtime；窗口关闭或客户端断开不改变已接纳输入的所有权。

本期只移除消息、处理过程、子任务中的重复“继承”文案；内部继承标记、只读限制及“截至分支点”“正文不可用”等真实状态继续保留。

以下不纳入：

- 超长会话复制分支性能及分支弹窗阶段反馈。
- 协作／助理双模式、整体布局重做、主题重做和品牌定制。
- 启动等待、远程桌面与终端稳定性等尚未纳入的遗留。
- 消息书签、AI 生成导航摘要、跨会话合并、消息版本切换和历史编辑撤销栈。
- 新建业务插件、手机原生 App 或 Computer Use。
- 将本轮 UI 优化扩大为数据库历史副本、常驻索引服务或另一套输入队列。

v0.33.0 追加修复及 v0.32.2 独立封版保持原归属与确认状态，不由本版设计推定验收完成。

## 五、产品规则与跨 Feature 基线

### 5.1 分页轮次、缩略条目与 Step

| 概念 | 本版语义 |
| --- | --- |
| 分页轮次 | 直接使用现有按 runId 合批后的运行条目；每页取若干完整批次，不按 User 消息位置、文本长度或底层记录条数切分 |
| 缩略条目 | 一条真实用户输入，以及紧跟其后 Run 的最后一段正文预览；不展示中间 Step 正文，最后一段正文可以没有，此时只显示用户输入。配对依据实际前后关系，不追踪 Goal 或跨 Run 合并 |
| 业务 Run | 沿用 Runtime 已有的独立 RunId、执行状态与归属，本功能不重新定义执行实体 |
| Model Step | 一次模型响应及该响应产生的整批工具交换；介入可取消正在执行的 Step，可靠保存已输出内容与实际工具结果 |

2026-11-10 用户最终明确“就按合批的 runId”，并说明缩略是“用户输入和紧跟着用户输入的 run 正文（也可以没有）”，随后补充只取最后一段正文，不显示中间 Step 正文。因此撤回此前的 User 位置分页、Goal 隐藏续跑归并、主 Run／原始输入运行段及特殊计数设计。

内部隐藏输入不作为真实用户输入展示或生成缩略项；不能由此推导按 Goal 合并不同 Run。压缩摘要、控制结果及既有历史保持原顺序与读取语义，不为本功能新增 Turn 表、Goal 查询或运行归属映射。介入成功后以已持久化消息直接参与历史分页与导航；接纳前只显示请求状态，已存在的真实用户消息不能因为缺少 Run 正文而从缩略列表消失。

### 5.2 按每页若干轮次读取

- 默认每页 **10 轮**，初次读取最新 10 轮，向前读取再取此前最多 10 轮；不足时按实际轮数返回。本期先作为产品默认参数，不增加用户设置项。
- 每页边界落在轮次之间。同一轮即使含大量 Step 或工具记录，也不要求用户再次加载才能读完该轮已产生的历史。
- 运行中最新轮次只包含当前已产生的内容，后续沿现有事件和快照补充，不等待结束后才显示。
- UI 可按可见区域控制挂载与资源加载，但不能把渲染优化变成轮内的第二套“加载更多”。单轮极大时的内存及传输策略在 F01 技术方案核实，不通过隐藏截断违背整轮读取。
- 首次视图、向前分页及 around 定位共用分组规则；未加载目标从当前最早正文边界按每页若干完整轮次顺序补齐，直到目标已加载再滚动定位。正文从该处到最新消息保持连续，只有顶部更早历史入口；加载过程保持阅读锚点，失败可重试，拼接不重不漏。

### 5.3 左侧缩略导航

- 正文左侧实际留白能容纳导航时显示；侧栏、资源栏、缩放或窗口宽度导致空间不足时隐藏，不挤压正文。
- **每条缩略以真实用户输入为主体**，下方预览紧跟该输入的 Run 的最后一段正文开头，不展示或拼接中间 Step 正文；没有最后一段正文时仅显示输入，不显示持续等待的助手 loading，不强制补齐问答对。
- 使用实际先后关系配对。连续用户输入时，不能越过下一条用户输入借用后面的 Run；一个输入后出现多个 Run 时，只预览紧跟它的 Run，不再按 Goal、重试或其他关联跨 Run 拼接正文。
- Host 条目沿用户原要求只返回 **user_message_id + 可选 assistant_message_id**，后者定位紧跟 Run 的最后一段正文；游标和现有历史代次在外层。撤回将额外主 Run ID 设为缩略必需字段的设计，不返回预览正文或另一份 Run 状态。
- hover 只读取缺失的短预览，已加载内容可直接复用；预览截取对应正文开头，不调用模型、不拿 reasoning 或工具参数替代正文。点击未加载目标时按序补齐中间完整轮次，加载到目标后再定位；不以孤立目标窗口替换正文。
- 缩略 ID 列表支持有界分批读取和可见区域渲染；不为绘制导航加载完整正文。具体批量大小、短文本长度和缓存上限归 F01 技术方案。
- 列表独立滚动，首次显示默认到底；上翻后保留位置，仅在底部跟随时随新条目移动。hover 不滚动正文，键盘焦点可触发相同预览与定位，浮层约束在窗口内。
- 对应 Run 的最后一段正文更新时只更新该输入的预览目标，不重建列表或抢回滚动位置；隐藏输入不生成新的用户缩略项。

### 5.4 用户消息复制与编辑

- 用户消息气泡下方提供复制、编辑图标，hover 或键盘焦点进入消息区域时显示，预留稳定布局空间。当前会话有活动 Run 时，所有用户消息只显示复制、隐藏编辑，结束后按资格恢复；无 hover 设备同样处理。按用户 2026-11-10 补充，操作栏样式与 assistant message turn 下方现有工具栏一致。复制针对该条输入文本，成功／失败沿现有轻量反馈。
- **完整输入编辑**：历史输入载入底部 Composer，原消息高亮；输入框外侧上方采用编辑抽屉，仅显示“正在编辑历史消息”和相邻的“返回原位置／取消”，去掉描述文字，提交复用现有发送按钮。编辑期间隐藏 Todo、Goal、队列等其他附属区域；取消或确认接纳成功后恢复普通草稿及有效抽屉展开状态，失败保留编辑稿。审批／问答保持现有处理优先级。本交互按用户 2026-11-11 的确认修订。
- 打开编辑不改变历史。提交后，Runtime 保留目标之前的历史，替换原用户消息、丢弃其后的消息与过程并开始新轮次，不为每次编辑增加新的多步审批流程。
- 正文、附件、引用、Skill／MCP 及输入变体完整载入并可修改；未改动内容保留原事实，新选内容按普通输入规则处理。仅修改附件或选择也可发送，最终保留的不可用内容须明确提示并阻止提交。
- 编辑仅适用于当前会话可改写的用户输入；继承历史、外部转达／会话报告、只读 child 及归档会话沿既有权限处理。复制仍按可读内容提供。
- 有活动 Run、排队输入、未结算子任务或交换时不直接裁尾；沿既有非空闲限制给出原因，不隐式取消任务或清掉队列。跨越 Goal 目标仍受原重入门禁约束。2026-11-11 用户明确新输入实际跑起来即自动延续同一 Goal，合法历史编辑也遵守这一规则；公共调度修订见[技术方案](features/F02-用户消息编辑重发/技术方案.md) 5.4，F03 的介入与运行打断仍独立落实。
- 提交前的校验失败保留编辑稿和原历史；提交后回执丢失通过既有幂等与快照核实，不能盲目重发。已执行的文件／外部工具副作用不因裁尾自动撤销。
- 成功后正文分页、缩略 ID 配对、预览缓存、当前定位、卡片及子任务展示统一刷新到新历史代次；目标之后的旧内容不得迟到回填。持久资源的保留／清理沿现有所有权，在 F02 核查实际效果。

### 5.5 Enter、介入与队列操作

2026-11-12 最终明确为阻塞式介入：同一次命令取消当前 Run，等待当前 Step 已输出内容可靠落盘，再提交介入消息并启动新 Run，最后返回结果。介入用于引导同一 Goal，不提供撤回，不建立后台介入任务或新增数据库字段。

| 用户操作 | 行为 |
| --- | --- |
| Enter／发送按钮 | 普通队列输入，沿 F02 Goal 与普通队列规则 |
| Ctrl + Enter；macOS 兼容 Command + Enter | 介入，立即请求取消当前 Run；空闲时直接接续 |
| 普通队列项“介入” | 复用原 Input 和完整载荷，进入同一介入流程 |
| 显式停止 | 停止执行、暂停后续接续，保留已接纳消息 |

Shift + Enter 换行，IME 不误触；编辑、Slash 和专用问答沿原入口。

介入复用普通发送，不另建发送流程。可靠顺序为：按输入幂等键查重并预检 → 把用户消息接纳到队首并取消当前 Run → 现有队列驱动结算旧 Run（已输出 reasoning／正文、实际工具结果及终态落盘），领取队首、写入用户消息并启动新 Run → 命令返回已持久化消息与 Run。输出保存失败时新消息不会被领取；新 Run 后续生成正常异步运行。客户端等待命令结果直接展示消息，不轮询异步接纳状态。

- 介入不区分旧 Run 以取消、完成还是失败结束，真实终态由通用结算记录；不补跑总结。旧输出落盘是硬前置，保存失败不提交新输入。取消与失败两类终止都保留当前 Step 已生成内容。
- 已写入会话文件的介入消息无撤回路径。等待期间用户停止则队列按原规则暂停，介入消息不执行、留在队首，恢复队列后照常执行；新 Run 已启动则按原规则停止它、保留已写入消息。
- 同端调用等待期间禁用再次提交，多端的介入命令按 Session 串行；介入消息位于队首，先于其他队列项执行。队列项介入复用原身份与输入类型，等同于“优先”加打断当前 Run；幂等属于输入，查重先于取消，同键重试不重复打断／发送。
- 介入消息进入后续 Run 上下文，引导同一 Goal；保留目标、累计进度与预算。运行中 Goal 被介入时先按现有“停止 Goal”暂停并取消其 Run，介入消息领取时按现有规则恢复同一 Goal，见 [F03 技术方案第六节](features/F03-介入与Step边界换轮/技术方案.md#六goal)。
- 审批、工具内等待与 child 沿取消协议清理；Run 已结束仍待回答的问题一并作废，介入不被其拦截，也不把介入正文当作答案。断线与重启的处理与普通发送一致，不盲目重放副作用。
- 已持久化介入消息直接参与 F01 分页与导航，无助手正文时保留用户单项；F02 编辑仍检查全部未完成控制。

终止内容留存要求见 [F03 功能规则](features/F03-介入与Step边界换轮/功能设计.md#35-终止时保留已生成内容)和[技术方案](features/F03-介入与Step边界换轮/技术方案.md#52-终止输出留存)。协议与存储改动见 F03 技术方案第七节，不改变 F01／F02 已验收边界。

### 5.6 侧栏列表排序、拖拽与分页

2026-11-10 用户确认留间隔整数排序方案并要求加入本版计划，同时明确 F01 已在开发。本项独立归入 F04，安排在原 F01 → F02 → F03 顺序之后，不修改 F01 的开发里程碑或完成边界。

- 项目和会话在 Desktop／Web 默认均按创建时间、新建在前，同时间使用稳定 ID；后续消息、Run 状态或改名不改变列表位置。
- 项目列表、每个项目内会话及独立会话分别构成排序与分页范围。Host 在实际范围内排序后取页，不能全局会话分页后由前端过滤来冒充项目内分页，也不能只重排已加载页面。
- 每项使用一个 64 位整数 `sort_order`，相邻值留固定间隔；项目沿现有 `workspaces`，会话优先沿已有 `session_resources` 项目归属行落表，不复制项目归属或建立通用排序服务。最终字段、索引与迁移由 F04 技术方案核实。
- 拖拽通常只更新移动项的排序值；间隔或整数边界不足时，在同一事务中保持现有次序重排当前分组后完成移动。不采用浮点排序、LexoRank、链表、独立稀疏覆盖记录或后台重排服务。
- 客户端提交移动条目与目标邻项，Runtime 按当前身份、分组和实际邻项校验，在 Host 提交；前端不计算排序值或上传全历史 ID。排序变化后刷新受影响分页，旧响应不能回填。
- 新建项加入当前分组最前；恢复默认按创建时间重新编号该分组，不改创建时间和消息正文。同组重排不等于跨项目迁移会话。
- Desktop／Web 使用同一目标 Host 的正式查询结果；具体拖拽入口、跨端刷新、归档／恢复及并发移动反馈在 F04 设计中细化。既有桌面跨设备置顶仍为本机快捷入口，不直接混入某个 Host 的普通列表排序。
- 2026-11-16 用户要求置顶区也支持拖拽排序，顺序跟随置顶数据现有的保存位置：Desktop 存本机偏好，Host Web 存目标 Host。置顶区顺序与分组内顺序相互独立，规则见 [F04 功能设计 4.6](features/F04-侧栏列表排序与分页/功能设计.md#46-置顶区)。
- 大列表通过分组查询、必要索引和按需分页读取，不为拖拽加载全部历史。分组重排是明确的批量写入成本，不能宣称每次拖动恒定开销；实现需验证实际查询计划与大分组重排成本。

## 六、架构、权威状态与兼容约束

| 所有者 | 职责 |
| --- | --- |
| Desktop／Web | 消息操作、Composer 普通／历史编辑草稿、滚动及缩略预览的短期投影；发送输入／读取意图 |
| assistant-runtime | 输入接纳、Run 与 Goal 调度、介入取消请求、正常／异常结算、历史改写与产品查询语义 |
| runtime-host 存储 Adapter | 在现有文件历史、位置索引及必要执行控制上实现读取和可靠提交；传输层不另持业务状态 |
| agent-core | 单次执行内的可靠 Step 与工具交换边界；通过既有控制／Recorder 接缝交还宿主，不依赖 InputId、队列或 UI |
| assistant-protocol／TS 投影 | 最小跨层查询与输入意图、事件和快照；不放 Core 内部句柄或数据库类型 |

F04 的正式列表顺序归目标 Runtime，排序元数据由 Host 存储 Adapter 可靠保存；客户端只提交移动意图和展示分页。已有桌面跨设备置顶偏好继续保持本机归属。

架构与恢复不变量：

- Desktop 与 Runtime 保持双进程，同一 Runtime 中会话并发、同一会话改变上下文的 Run 串行。
- 历史结构以会话文件为权威；缩略 ID、分组及预览可从历史推导，不落另一份正文或摘要库。2026-11-11 用户确认 F02 将已提交 Input 身份、顺序及幂等键一并迁入会话文件，SQL 只留暂存输入与未完成控制；裁尾、分支复制、重试及恢复统一使用该来源。
- 待执行输入复用既有 Input 身份、载荷与可靠接纳能力；普通队列与介入保持各自的调度语义，不新增独立队列服务。用户介入意图必须先可靠接纳，才允许触发旧轮结束。
- 工具调用／结果配对、权限、真实用量和子任务监督保持；不能用可丢弃的 UI 事件推断安全提交点。
- 读取及缓存始终绑定完整组织／用户域、设备、Session、owner 与已有历史代次；不只凭 MessageId 或 RunId 跨域复用。
- 已有 generation、幂等键、队列 revision 和串行 owner 优先复用。确需新增字段时在技术方案证明实际边界需求，不机械追加另一套 revision 或全局序列。

M0 将软件及应用最低兼容版本调整为 0.33.1，数据库目标与兼容下限沿用 0.33.0。分页 `limit` 当前表示记录数量，不能对已发布客户端静默改成轮数；F01 方案必须明确契约表达及新旧配套准入。F02 的附属输入与 F03 的介入意图也分别核对序列化、持久化及旧 Host 行为，不把不支持的介入静默降级成普通排队。

F01 M0 的数据库目标与最低 Host 保持 0.33.0 的既有结论不变。F02 单一输入来源方案新增旧键迁入文件、已完成 SQL 身份行释放及格式升级，拟将数据库目标与最低 Host 升为 0.33.1；迁移、配套备份与拒绝旧 Host 见其[技术方案](features/F02-用户消息编辑重发/技术方案.md)第八节，并回归 F01 阅读及分支复制。F04 的排序字段／索引独立评估；F03 阻塞式介入复用现有存储，不新增数据库迁移，不由此推定整版无迁移。本次仅更新设计，不执行迁移；导航和排序本身不要求全量改写消息正文。

## 九、已确认取舍、风险与下一步

2026-11-10 用户确认总体设计及原 F01～F03 基线；同日明确接受简单整数排序方案并要求纳入本版，追加 F04。统一边界及以下取舍作为版本基线：

1. 分页直接按现有 runId 合批结果取页，默认每页 10 轮；不按 User 消息位置切分，不增加 Goal 相关处理。
2. 缩略条目为一条真实用户输入和紧跟其后 Run 的最后一段正文预览；中间 Step 正文不显示，最后一段正文可缺失，按实际前后关系配对，预览按需读取。
3. 历史消息在底部 Composer 完整编辑，上方返回／取消，复用原发送按钮；暂存并恢复普通草稿，沿现有空闲／继承／Goal 门禁。
4. 介入命令顺序等待取消、输出落盘、发送与启动后返回，后续生成异步进行；输出保存不可省略，失败不发送。不提供撤回或后台介入任务，显式停止保持有效。
5. Goal 自动续跑不自动消费普通队列，暂停后走正常输入机制；新输入实际领取启动时自动恢复、自然延续同一 Goal。2026-11-12 用户明确 F03 介入是引导执行，介入消息作为上下文补充，Goal 身份、目标内容和累计进度／预算保留；介入取消当前 Run 不停止 Goal，也不表示 Goal 达成。具体交接及问答路径由 F03 细化。
6. F04 两端统一创建时间默认顺序；Host 保存留间隔的整数排序值并按最终顺序分页，间隔不足时事务内重排当前分组。原 F01 开发范围和里程碑不变，新增项目／会话列表与原正文轮次分页分别验收。
7. 已提交输入及请求键归会话文件；数据库只保留暂存／未完成控制，索引可重建。该调整由用户于 2026-11-11 确认纳入 F02，包含旧数据迁移与存储兼容评估，不追改 F01 已完成边界。
