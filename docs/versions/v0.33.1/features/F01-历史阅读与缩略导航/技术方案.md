### 2.2 最后正文的准确含义

“最后一段正文”指处理过程下方的最后回复区域，不是整轮第一段 text，也不是 Markdown 文本的最后一个换行段落。缩略取该回复的开头，保持原始顺序并截断。

- 以现有 `presentTurn(...).reply` 的消息选择为准，Host 在可靠历史投影中复用等价的选择规则。
- 终态批次按现有规则选最后一个具有正文的 Assistant；后面只有工具或 reasoning 时，不要求凭空出现一条新的纯文本消息。只有被选为 reply 的消息可进入预览，其余过程正文均排除。
- 活动批次遵守最新 Step 与工具状态的现有区分。尚未可靠提交、没有 MessageId 的流式回复不生成助手 ID；出现新 Step 时，已转入过程的旧正文不得继续当作最后回复缓存。
- 索引只保存可靠候选；Runtime 结合本次读取捕获的活动 Step／状态核对其是否仍为 reply。不能只看上一次提交的文件尾，把新 Step 开始后的旧正文继续当成最后回复。
- 继承、partial 和 child 使用各自已有的展示状态，不能通过预览补出分支点之后的正文或来源未来终态。
- 同一被选 Assistant 的多个 text 片段按原顺序组成这段回复；不跨 Assistant／Step 拼接，不包含工具结果、reasoning 或 ProviderState。

这项复用只决定读取与展示，不改变执行终态、工具结束行为或历史写入。Rust 与 TypeScript 用相同输入场景核对选择结果，避免形成两套不同的最后回复规则。

## 三、架构与所有权

```text
ConversationView：短线列表、浮层、滚动与锚点
    ↓ 用户读取意图
RootStore / RuntimeLifecycleCoordinator：作用域、请求预算、取消与投影安装
    ↓ 现有 HTTP Command（本机、远端、Host Web 共用）
assistant-runtime：授权后的 owner、generation、页边界与预览语义
    ↓ RuntimeStore 现有读取边界的必要扩展
Host Store Worker：文件位置、可丢弃索引、定点解码
    ↓
可靠 Conversation 文件及已有历史事实
```

批次和缩略项均为派生读取结果，不具有业务生命周期。Runtime 负责语义；Host 私有 Store 负责文件 I/O，Volatile Store 实现同一读取语义。分类、合批和最后回复选择的无 I/O 逻辑就近放在 Runtime 现有 Conversation 读取模块，供实际 Store 实现与产品投影复用；不建立通用分组框架，不把业务规则复制到 HTTP 层。

UI 只持有可恢复的正文窗口、导航 ID、短文本缓存及请求状态。继续使用现有 owner、generation 和连接身份；不新增 revision、全局轮数、持久阅读位置或全会话摘要。

## 四、读取与协议方案

### 4.1 整批分页与顺序定位

1. 从既有产品展示顺序构造批次边界，相邻同 run_id 的 Assistant 保持完整。元数据提交帧不是消息，隐藏输入不生成用户行或额外分页单位。
2. 每页默认 10 个完整批次，显式 `turn_limit` 允许 1～50。上限限制批次数，不限制批内消息数；单批不会因 Step／工具数量被拆开。
3. User、摘要和控制项按原顺序随正文读取：批次前的连续伴随项与后一个批次一起返回；末尾尚无后继批次的输入随最新窗口返回。仅有用户输入的尾部仍可读，不补造 Run。分页接缝不把输入留在上一页、把紧跟的批次留在下一页。
4. 旧历史或 child 缺少 RunId 时，保留现有显示合批行为和空身份，不制造 RunId，也不按 Goal 归属补齐。无可计数 Run 的历史保留原顺序完整读取，其成本纳入异常历史验证，不静默恢复按消息数截断。
5. 初次读最新 10 批；向前读严格早于当前窗口的 10 批。运行中最后一批只包含当前可靠内容，后续提交继续更新该批。
6. around-message／around-run 核对目标并保留原有精确锚点；返回页按完整批次扩展，保留目标前置输入。该结果用于定位校验，不作为孤立正文窗口安装。已有有效 ID 与同代页面足够时复用，不重复校验已加载目标。
7. 点击未加载目标时，从当前最早正文的 previous_cursor 开始逐页向前读取完整批次，直到包含目标；正文保持到最新消息连续。没有 Run 正文的用户项也能通过 MessageId 定位。“返回最新”滚动到底，不替换已读历史。

Store 内仍用原始／展示位置精确切片并包含完整工具交换，产品层保留 `items` 原形状，不向前端新增一份“轮次正文”包装。现有按展示数量核对投影完整性的断言继续保留，但不再将展示记录数与请求轮数混为一谈。

### 4.2 查询契约

以下是已确认的最终命名；本版本内部直接统一，不为草稿字段维护别名。

| 查询 | 请求要点 | 响应与用途 |
| --- | --- | --- |
| `list_conversation_page` | 现有 owner、cursor；`limit` 改为明确的 `turn_limit` | 现有 `ObservedSnapshot<ConversationPage>`；首次无 cursor 读最新页，其余使用 previous_cursor 向前读取 |
| `get_conversation_page_around_message`／`around_run` | 现有定位身份；`turn_limit` | 包含完整目标批次的校验页及原有 anchor_message_id；未加载正文仍通过普通分页按序补齐 |
| `list_conversation_navigation` | owner、cursor、limit；默认 128、最大 256 个用户条目 | `ObservedSnapshot` 内为 owner、generation、items 和双向 cursor；每项严格只有 user_message_id、可空 assistant_message_id |
| `get_conversation_message_preview` | owner、generation、message_id | `ObservedSnapshot` 内为 owner、generation、message_id、text、truncated；每次只取一条消息的有界原文 |

`ConversationPage` 保留现有 owner、generation、items、previous_cursor、has_more 形状；has_more 继续只表示有更早历史，不增加正文 next_cursor。SessionView、ChildTaskView 内嵌页同步采用整批语义。导航条目使用现有 MessageId，不要求 RunId，不返回正文、标题、时间或运行状态。

游标沿现有不透明编码方式扩展，内部绑定 owner、generation、读取种类与索引边界；只有独立导航 ID 游标需要区分方向，正文始终向前读取。客户端只原样回传。验证游标类型、作用域、位置范围和完整批次边界；拒绝正文游标用于导航、不同 owner 混用及落在批次中间的伪造边界。游标不是权限凭据，不持久化到用户配置。

导航 cursor 可以重放同一页查询，便于可靠变化后重读当前可见 ID 页；无 cursor 表示最新一页。响应按旧到新排列，不附全历史总数。列表滚动只对已加载范围提供位置，不伪造未读取条目。

### 4.3 缩略配对与短预览

- 在产品可见行中，以每条真实 User 建立一个导航项；只有紧跟的 Assistant 批次可提供其助手 ID。下一条 User 或其他独立可见行截断该配对，隐藏内部消息沿产品过滤规则跳过。
- `U1 → U2 → R2` 得到 `U1/null`、`U2/R2最后回复ID`；`U → R1 → R2` 只取 R1；R1 没有 reply 时返回 null，不借 R2 补位。
- User 分类复用现有产品投影，不能只检查原始 role=user：Shell 切换、MCP／Skill 控制结果已有独立展示类型，不冒充真实输入。控制项和摘要不产生导航标记。
- assistant_message_id 取 2.2 的可靠最后回复候选；空值表示当前没有可用于预览的助手正文，不表示查询失败。候选随可靠提交和已有 Run／child 状态变化更新。
- 预览固定每条最多 **160 个 Unicode 标量值**，读取第 161 个值决定 truncated；Rust 使用字符边界，TS 本地截取采用等价规则，不切断 UTF-8 字符或 UTF-16 代理对。不新增分词或摘要依赖。
- 用户预览取输入 text，助手预览取所选消息的 text 片段，保留顺序；原始 Markdown 作为纯文本展示。空正文返回空 text，由 UI 展示既定空态；附件不下载、不 OCR。
- 前端仅在 owner／generation 相符且已加载所选消息时本地截取。缺失用户／助手内容分别读取与反馈，没有助手 ID 就不发助手查询。
- 预览入口只允许当前 owner 的真实用户消息或有效最后回复候选；任意传入中间 Step、控制项、隐藏输入或其他 owner 的 ID 都不能绕过选择规则读取正文。

### 4.4 错误、权限与一致性

沿用 Runtime 的 Session mutation 与历史观察屏障，child 继续按完整 owner 核对 generation，遵守 parent → child → Store 的现有顺序。查询不安装历史 Run 为执行对象，不触发队列领取或恢复执行。

参数／游标错误使用现有 invalid_request；代次变化使用 snapshot_stale；组合读取繁忙使用 snapshot_busy；目标消失或正文不可用沿既有消息／child 错误返回。真实空助手、空文本、缺失消息、读取失败分别处理，不吞错返回空列表。

查询水位只用于本次读的一致性校验，不推进全局 SSE 消费游标。登录用户、组织、目标设备、Host 实例或 owner 切换时取消旧等待并隔离结果。新命令同步加入 [Desktop 远端命令集合](../../../../../apps/desktop/src/runtime-client/RuntimeClient.ts)和 [Host 代理允许集合](../../../../../apps/runtime-host/src/http/proxy/allowed.rs)，仍经过原认证、组织与资源权限检查。

## 五、Store 索引与读取成本

### 5.1 扩展已有索引

复用 `ConversationOffsets` 的 MessagePosition、display、locations 和 HistoryOffsets，增加只含位置／ID／必要分类的批次与导航索引。最后回复选择只需保存消息是否有 text、是否含工具、末尾非空片段类别及候选位置，不缓存正文、工具参数或预览字符串。Run 状态和消息归属继续读既有文件历史事实，不另存一套状态。

冷路径与现有 RecordReader 同次顺序扫描，收集最小消息分类；历史事实归一化及身份／工具交换校验完成后推导批次和配对。不能因后到元数据而提前安装错误归属，也不能按历史事实数组的结算顺序替代正文物理顺序。

热路径通过索引选批次、切 ID 页或定位目标消息，再调用现有定点解码。Host 只扩展原 Store Worker 命令与 Engine 读取，不新增线程、后台扫描器、全库预热或独立索引库。纯语义在 Runtime 读取模块复用，文件位置仍为 Host 私有类型。

Volatile Store 采用相同的分类／边界选择逻辑，从其权威快照与历史事实构造读取结果；它可以直接访问内存消息，但不能用不同分组规则模拟通过。只增加实际查询所需的 RuntimeStore 方法和返回值，不新增 Repository trait。

### 5.2 增量与失效

- 可靠追加沿 `record_committed_append` 更新受影响尾部批次、最后回复候选与用户配对；仅有 Run 状态变化的元数据帧也要重算相关候选，不能只监听新 User。
- 尚未提交内容不进入索引。提交失败不发布候选；提交成功后派生索引更新失败则丢弃缓存，由后续读取重建，不重放业务。
- generation 改变、文件替换、长度／mtime 不匹配沿原失效路径处理；新旧页、游标及预览不能跨代混用。
- 延用 32 文件 LRU。索引空间仍随消息和批次数量增长，属于 O(历史条数) 的位置元数据；32 是 owner 数量上限，不宣称总内存恒定。验收分别测索引、临时解码与正文响应的成本。

### 5.3 实际 I/O 边界

ID 页在热索引命中时不解码正文；短预览只定位所需消息所在的提交帧，不读取该目标之前所有正文页。相同帧内的两个目标可复用一次解码。

现有文件一帧可包含多条消息，RecordReader 的解码单位是完整帧。因此“返回 160 字”不等于“磁盘只读 160 字”，极大单消息／单帧仍有相应的临时内存成本。本文复用既有 codec，不为预览另写 JSON 流解析器或改写用户历史格式。

功能设计中“不为预览加载整轮／整条长正文”的限制落在产品响应与前端安装：不能调用完整正文页充当预览。后端只读取所需物理帧这一限制单独验证并如实保留，不承诺无法由当前格式实现的恒定字节 I/O。

整批正文查询本来就需要读取该批可靠展示记录；单个超大 Run 可能超过普通页成本。工具详情、图片、附件和卡片资源仍按需加载；不得以消息上限静默截断 Run。若实际超出既有读取预算，先解决已定位的重复解码／序列化／渲染问题；无法解决时报告证据，再调整方案，不自行改变分页定义。

## 六、前端状态、请求与展示

### 6.1 连续正文与顺序定位

- 保留现有 `ConversationHistoryProjection` 的向前 cursor、加载与错误状态，不新增正文双向窗口或平行正文 Store。
- 定位已加载消息直接用原锚点；未加载时复用 RootStore 的顺序加载路径。每次读取前校验当前连接、owner、generation、previous_cursor 和定位意图，只在上一页已可靠合并后请求下一页。
- around 查询沿原用途核对消息存在性／generation 或解析 Run 锚点；返回的孤立页不替换当前正文，也不跨过中间页面拼接。正文仍由普通整批分页按顺序补到目标。
- 循环遇到目标即停止并应用锚点；游标不前进、历史耗尽仍未找到、代次冲突、取消或预算耗尽时停止。不得无限补页，不把已删除目标替换成最近消息。
- 成功页面逐页前插到现有连续历史，并保持原可见锚点。失败保留已成功页面与当前 cursor；手动重试从该处继续，不重发成功前缀。新定位意图复用已加载内容，只允许最后意图应用滚动。
- 从已读最早位置到最新尾部始终连续。新可靠正文和流式接管沿原机制接到尾部；回看期间保持 `useOutputFollow` 的原阅读位置。返回最新结束旧定位等待并滚动到底，保留已读内容。
- 最新快照有连续重叠时合并；断线／历史换代沿已有快照恢复与锚点重验处理，需要补齐时仍按同一方向顺序加载。无法证明连续时不能把两个不相接窗口做并集，也不增加底部历史分页。
- 引用、搜索、通知、阅读位置恢复和主／child 入口使用同一顺序补齐路径，保留各自精确锚点及必要的过程展开。

正文沿已有按需累计方式管理，不为定位裁掉目标之后的消息。远距离定位的正文内存与耗时随加载距离增加，作为本次取舍明确验证；缩略 ID 与预览的缓存上限仍独立生效。巨大单批继续使用既有折叠和视区优化，不引入全局虚拟化框架。

### 6.2 缩略列表与预览缓存

| 数据／操作 | 本方案边界 |
| --- | --- |
| ID 分页 | 每次默认 128 条，Host 最大 256 条；客户端保留至多 512 条连续 ID，淘汰远端页时保留两侧重读 cursor |
| 标记 DOM | 固定行高的局部窗口渲染，仅挂载可见标记及上下各 8 条缓冲；行高和点击区域由交互指导固定 |
| 短文本 | 单个活动 owner 最多缓存 256 条消息预览，LRU 淘汰；不存 localStorage，不缓存错误为正文不存在 |
| 请求并发 | ID 翻页同一列表最多 1 个；预览最多 2 个（用户和助手）；定位最多 1 个有效意图，新意图取消旧等待 |
| 首次位置 | 读取最新 ID 页后到底；随后记录可见 User ID 与像素偏移，前插、淘汰或短暂隐藏后按锚点恢复 |

导航有独立滚动容器和 overscroll 边界。DOM 虚拟化只处理已加载的短线条目，不制造全历史占位数量；ID 页裁剪后以可见 User ID 保持位置，并支持反向加载被淘汰的一侧。

收到本 owner 的可靠提交、StepStarted 或 Run／child 状态变化时，标记已缓存 ID 页过期并失效其预览缓存，合并重读当前可见页；不可见页等滚入或 hover 前再重验。此策略无需为导航项增加 RunId，也不逐页立即刷新整份已读列表。只显示一个浮层时只更新该浮层所需预览；更新助手 ID 可覆盖旧 ID 或变为空，旧正文不得因缓存命中继续显示。没有浮层时不逐 token 读取预览，没有导航时不为该功能拉取 ID 页。

本地缓存键至少包括完整连接作用域、owner、generation、MessageId。相同 generation 下可靠内容／最后回复资格变化也会失效，不能只靠 generation 缓存到会话结束。静态历史复用短文本；断线恢复沿可靠快照重验，不能恢复上一个 Host 实例的旧结果。

### 6.3 读取生命周期

将 LifecycleCoordinator 已有只读预算执行逻辑供正文页、ID 页和预览使用；请求 loading 和错误分别写到对应局部投影，不改变已有会话生命周期所有权。每次用户读取意图共用 15 秒总预算，顺序补齐的所有分页与退避共享该预算，每个具体查询最多三次实际发送；snapshot_busy／snapshot_stale 的有限重读消耗同一预算，不嵌套第二套重试。超时后保留已合并的连续页面，手动重试以新预算从当前 cursor 续接，不自动续开预算。

切换标记取消旧预览等待，切换 owner／设备／组织取消相关读取；取消不是 CancelRun。Host Store Worker 仍使用既有有界队列和串行文件访问，前端并发上限防止扫过标记堆积请求。已经进入同步解码的任务可能完成，但过期回包不可安装；本文不新增后台 I/O 取消协议。

### 6.4 继承标签与交互落点

删除 [MessageViews](../../../../../apps/desktop/src/features/conversation/ConversationView/MessageViews.tsx) 的用户“继承”徽标、[ProcessingTurn](../../../../../apps/desktop/src/features/conversation/ConversationView/ProcessingTurn/index.tsx) 的标签前缀、[ChildTaskTree](../../../../../apps/desktop/src/features/conversation/ConversationView/ChildTaskTree.tsx) 的重复后缀。

`inherited`、`partial`、来源身份、分支点、正文不可用和操作资格保留；Inherited ProcessingTurn 仍不接入活动 Run。仅调整文案不改变协议或历史值，不增加同义替代徽标。

缩略组件置于现有 ConversationView 内，就近管理 DOM 测量、hover／焦点和可见窗口，数据通过原 Store 入口读取。显隐取决于正文容器的实际左侧余量，使用已有布局测量和浮层基础；具体留白阈值、样式、焦点顺序、预览浮层和加载反馈见已确认的[交互指导](界面交互设计指导.md)。

## 七、兼容、持久化与交付边界

### 7.1 已确认的兼容选择

本次页大小字段改为完整轮次，且新增 ID／预览查询；正文保留既有向前分页形状。采用 **Desktop、Client、Host 随 0.33.1 同步升级，应用最低兼容软件版本提高为 0.33.1**。旧新混连在现有双向兼容检查处明确拒绝，不让旧 limit 被静默解释成轮数，也不保留两套长期分页接口。

这项选择已于 2026-11-10 随本文确认；M0 将根 Cargo 发布事实、Rust／TS 兼容常量、Desktop、Client、Host 和协议包同步到 0.33.1，并补齐双向不兼容组合。

F01 不改变 Conversation 帧格式、SQL schema 或已落盘业务事实。数据库目标、最低 Host 版本和现有迁移清单均停留在 0.33.0；Host 初始化和构建检查以数据库目标校验清单。企业协议、模型协议与 Device Gateway 独立契约不因本 Feature 自动提高。

F01 本身的回滚只需恢复配套客户端／Host 并丢弃可重建缓存，无需回写历史。后续 F02／F03 如改变持久化须重新评估，不能以 F01 的无迁移结论代替整个版本的升级判断。

### 7.2 实施影响清单

- 协议：product DTO、Command/result、导出器及生成的 TS；Session／child 内嵌页和兼容向量。
- Runtime：产品分页／around／新查询、只读分类与最后回复选择、Store 契约、Volatile 语义。
- Host：Store Worker／Engine、现有索引的冷建与追加、定点预览读取、Command dispatch 与代理允许项。
- Desktop／Host Web：RuntimeClient、读取生命周期、正文投影、RootStore 定位、ConversationView 缩略组件与文案。
- Client：检查所有页 DTO 消费与共享协议构建；无聊天 UI 不意味着可跳过生成类型和版本准入验证。
- 不改 agent-core、模型执行循环、Goal 调度、工具执行、用户数据库或业务插件仓库。

删除拟新增机制后复核：现有分页接口缺少整批边界；现有完整页不能满足只取 ID／短预览。正文顺序定位复用已有逐页加载，不新增双向正文窗口。因此仅补这两类查询与必要派生位置，其他事实均复用。无需新的持久实体、摘要生成器、Goal 映射、执行状态或消息副本。

## 八、验证与风险

### 8.1 实现阶段的最小有效验证

| 边界 | 必须证明 |
| --- | --- |
| 完整批次 | 23 个 Run 分为 10／10／3；单批大量 Step 不拆页；向前翻页、around 校验、实时追加无遗漏重复，工具交换完整 |
| 缩略主体 | 连续 User、只有 User、一个 User 后多个 Run、隐藏输入、控制项和摘要均按实际相邻关系取 ID，无 Goal 特例 |
| 最后回复 | 多个中间文本 Step、最终回复、多 text 片段、工具结束无后继纯文本、空正文、活动 Step 变化、继承 partial；Rust 与现有 UI 的 reply 选择一致 |
| Host 索引 | 冷建与提交后增量结果一致；只改元数据也更新候选；换代／恢复失效正确；热 ID 查询不解码正文，预览只读所需帧 |
| 顺序定位 | 点击早期消息按当前游标顺序补齐中间整批页面，目标至最新内容连续；部分成功后失败／超时可续接，连续点击不误跳，返回最新不替换已读历史；引用、搜索、通知和 child 定位一致 |
| 请求隔离 | 快速扫过／连续定位、generation 更替、owner／设备／组织切换、断线重连；迟到回包不覆盖，失败可局部重试，无双层重试 |
| 长列表 | 至少 10,000 条真实用户导航项，ID 驻留与标记 DOM 遵守上限；前插／裁剪／反向重读保持锚点，首次到底且用户上翻不被抢位 |
| 大单批 | 至少 5,000 个 Step 的单批夹具，完整正文一次读取；独立记录冷索引、热 ID、单帧预览、正文响应与折叠／展开成本，不能用短示例代替 |
| 只读与兼容 | 继承操作限制保留；同版配套成功，旧新混连明确失败；原始历史与持久格式不因阅读而改写 |

夹具均在项目 `.runtime-test/` 下新建的一次性 Runtime Home，不使用用户历史。先验证纯选择与协议序列化，再覆盖正式文件 Store 和 Volatile，最后验证实际 Desktop／Host Web 的鼠标、键盘、滚动、窄窗和缩放。macOS／Windows 原生验证分别报告，浏览器不替代原生结论。

性能首先验证工作量而不是只比较一次耗时：热 ID 页不扫全历史，预览不加载中间正文；点击定位只按序读取尚未加载的页面，复用已成功前缀。导航内存／DOM 不随已访问历史无限增长。单次读取流程沿用 15 秒总预算；距离较远而未补齐时保留进度，明确超时并由用户重试续接，不要求任意距离都在一次预算内完成。冷扫描、极大帧、长距离补齐的耗时与正文内存分别量测，不能自动重置预算或切断 Run 来伪装通过。

实现涉及 Rust 公共协议和 Store，按规范执行格式、相关定向回归、workspace clippy／test；前端执行正式 build 及相关交互回归，独立 TS 协议生成一致性与 Client 构建一并核对。仅本技术方案交付执行文档检查，不运行应用构建或数据库操作。

### 8.2 保留的风险与下一步

- **物理帧成本**：短响应不能消除大帧解码，先复用 codec 并测量；不承诺恒定 I/O 或秘密增加新存储格式。
- **跨语言选择一致性**：最后回复的活动／终态规则必须与现有 UI 对齐，尤其工具结束、partial 和新 Step 到来时，不能把中间正文恢复进预览。
- **顺序补齐成本与快照衔接**：越早目标需要加载越多中间正文，保留逐页锚点与成功前缀；最新快照合并须证明连续性，不能替换掉已补齐的同代历史或用去重掩盖缺口。
- **配套升级限制**：应用最低兼容版本变更意味着旧客户端需升级；实现阶段按已确认选择调整。
