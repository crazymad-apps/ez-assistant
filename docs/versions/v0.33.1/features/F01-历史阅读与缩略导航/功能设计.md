## 二、背景与目标

目前历史按展示记录数量截取，前端拿到页面后再按 Run 聚合处理过程。一轮含多个 Step、工具或助手消息时，会跨过多个页面，用户读完同一轮也需要反复 loading。聊天正文左侧的留白尚未提供定位入口，寻找较早消息需要长距离滚动；当前定位链路已有从最新页按序补拉到目标的路径，本版沿用并改为完整轮次分页。

F01 形成以下完整能力：

1. 首次读取及普通翻页默认每页 10 个完整阅读轮次，同一轮已产生的展示内容一次纳入页面。
2. 左侧空间充足时提供细线标记组成的缩略导航，每条以真实用户输入为主体，悬停查看该输入与紧跟其后 Run 最后一段正文的开头；不显示中间 Step 正文，没有最后一段正文时仍显示用户输入。
3. ID 列表、缺失预览和正文分别按需读取；点击很早的消息时自动按序加载完整轮次到目标，正文保留到最新消息的连续历史。
4. 正文和缩略列表分别保留阅读位置，长列表可以独立滚动，新增消息不打断主动回看。
5. 去掉重复“继承”文案，保留原有只读、来源、截至分支点和正文不可用等真实语义。

## 三、范围与非目标

适用于正式 Desktop 与同源 Host Web 的会话正文；主会话和已打开的子任务详情按各自 ConversationOwner 独立读取。归档及继承历史仍可阅读。当前会话无 User Message 时正文正常展示，缩略导航不伪造输入条目。

本 Feature 不实现用户消息复制／编辑（F02）、介入／队列调度（F03），不改变模型上下文、Run 或 Goal 的执行边界，不改善复制分支本身的性能。不新增书签、AI 摘要、全局时间线、历史内容副本、持久化轮次实体或导航设置页；用户参考图中的其他操作不自动纳入。

## 四、功能规则与使用路径

### 4.1 直接复用 runId 合批，缩略按实际前后关系配对

本节以 2026-11-10 用户最新明确口径为准：分页直接使用现有按 runId 合批后的运行条目；缩略就是用户输入及紧跟该输入的 Run 的最后一段正文，中间 Step 正文不显示，最后一段正文也可以没有。此前按 User 位置分页、按 Goal 隐藏续跑合并不同 Run、推导主 Run／原始输入运行段的规则全部撤回。

- **分页**：每页若干完整 Run 批次。合批身份沿用实际 runId，本功能不新增业务运行实体、Goal 映射或特殊轮次计数。
- **缩略**：每条真实用户输入一个主体，配对紧跟它的 Run 的最后一段正文；没有这段正文就仅保留用户输入，不用中间 Step 正文补位。
- **配对**：按现有历史的实际先后关系确定，不跨过下一条真实用户输入借用回复，也不将后续其他 Run 合进紧跟的 Run。Run 正文沿现有展示投影读取，不再为预览发明“选择其他 Run 的最后一条 Assistant”的规则。
- **隐藏输入**：不成为用户缩略项，不出现在用户输入预览中；不据此改变 Run 合批结果。
- **既有附属历史**：摘要、控制结果、继承、半轮分支和 child 保持原有读取及归属，不能伪造 RunId，也不为了导航重新组织执行历史。
- **队列**：尚未领取的 Input 不是已提交历史，不提前加入导航；已经存在的真实用户消息即使没有对应 Run 正文也必须保留。

```text
用户 U1 → Run R1 的正文              缩略：U1 + R1 最后一段正文预览
用户 U2 → 用户 U3 → Run R3 的正文    缩略：U2（仅输入）、U3 + R3 最后一段正文预览
用户 U4 → Run R4 → Run R5            缩略：U4 + 紧跟的 R4 最后一段正文预览

分页依据 R1、R3、R4、R5 的现有 runId 合批结果；
缩略以 U1、U2、U3、U4 为主体，两种列表各自沿上述规则取数。
```

### 4.2 初次打开与向前加载

- 首次打开最新历史，默认读取最新 **10 轮**，不足 10 轮则返回实际内容；新会话保持现有空态。已有有效阅读位置时沿现有恢复规则，不强行跳到底部。
- 向前加载取得当前最早轮次之前的最多 10 轮。加载前后的首个可见消息及其视口内偏移保持稳定，不能因顶部插入内容把用户推离原位置。
- 用户看到的完整轮次包含该段已产生的消息和处理过程展示项；工具详情、附件、图片及卡片资源继续沿原按需加载，不要求为整轮分页提前下载所有资源。
- 超长轮次也不能在中间插入“加载更多历史”。处理过程原有折叠、视区外不挂载及资源懒加载可以继续使用，但展开后不应因消息条数阈值再补齐该轮的展示记录。
- 活动末轮返回读取时已可靠提交的内容，实时部分沿已有流式投影更新。不能等整轮结束才显示，也不提前制造最终回复或 completed 状态。
- 重复加载由同一有效边界合并处理；失败保留已显示内容，在对应边界提供重试，不清空聊天。不再有旧页时移除加载入口。
- 向前分页期间的新消息追加不改变旧页分界；轮次必须既不重复也不遗漏。历史代次已改变时不拼接旧页，按 4.7 刷新。

### 4.3 缩略导航的显隐与条目

- 导航位于聊天正文左侧留白，每条真实用户输入使用一个短横线标记，整体轻量。依据聊天容器的实际剩余空间决定显隐；不挤压既有正文宽度，不占用会话侧栏，不覆盖底部输入区。
- 窗口缩放、左右栏开合、切换子任务和系统缩放后重新判断可用空间。空间不足隐藏导航；正文阅读、输入和既有回到底部入口正常可用。
- Host 的导航条目只包含 `user_message_id` 和可缺失的 `assistant_message_id`，后者定位紧跟 Run 的最后一段正文。用户输入是条目主体；owner、游标及 generation 放外层，不加入摘要、标题、时间、Run 状态或完整正文。撤回额外主 Run ID 为缩略必需字段的设计。
- 助手预览只截取紧跟用户输入的 Run 的最后一段正文开头；中间 Step 正文不显示、不拼接，也不在缺少最后一段正文时用来补位。缺失正文与加载失败分别表达；不跨 Run 借回复，不取 reasoning 或工具结果代替。
- 初次显示读取靠近末尾的一批条目，列表默认滚动到底。向上接近列表边界时再读更早条目；每条真实用户输入一个标记，隐藏输入不生成标记，不按总高度压缩成无法点击的一根线，不为未知早期数量画假标记。
- 导航独立滚动，滚轮停留其区域时不带动正文；到达边界也不把一次滚动突然传递给正文。长列表只挂载可见项及必要缓冲；ID 也分批读取，不要求一次返回全会话。
- 用户上翻后保留其位置；仅在导航已跟随底部时，新条目才使其继续到底。前插旧 ID 同样保持原标记位置；短暂隐藏后再显示恢复原位置，首次显示才默认到底。
- 正文和导航分别保留滚动位置。点击导航时目标标记保持可见。

显隐阈值、横线尺寸、悬停样式、键盘焦点、浮层位置和可点击面积以交互指导为准。

### 4.4 悬停预览：文本也按需加载

1. hover 或键盘聚焦某条标记时打开预览浮层；悬停触发可作短暂防抖，避免扫过列表产生大量请求。
2. 当前 owner、generation 下已可靠加载的消息正文可以直接取开头；缺失的用户和助手预览分别按对应 ID 读取。预览查询只返回有界开头文本及必要读取结果，不为预览加载整轮、整条长正文或所有中间页面。
3. 浮层按用户在上、助手在下展示。用户文本来自输入正文；助手文本只来自紧跟 Run 的最后一段正文，不拼接中间 Step 的正文。纯文本展示，不执行 Markdown 内嵌内容、不加载图片，也不以 reasoning、工具参数或工具输出代替助手正文。
4. 任一部分已取得即可展示，另一部分单独显示 loading 或重试；没有 Assistant ID 就省去助手区，不显示助手 loading，不推断“助手正在思考”。有 ID 但无文本时显示“暂无正文”；仅附件的用户输入显示“无文本输入”，不触发 OCR 或下载附件。
5. 文本截取自开头，超出上限用省略号，保留可读词序；不调用模型生成摘要。预览长度、折行上限与 Unicode 截断规则在技术方案和交互指导中统一。
6. 移到另一条目后，迟到结果不能覆盖新浮层；离开浮层与标记区域、按 Escape 或关闭导航时收起。移入浮层期间保持可读，不因离开细线立即闪退。
7. 单次预览失败只影响该部分；正文及其他标记仍可操作。请求合并、并发、缓存与淘汰均有界，反复 hover 已缓存静态消息不重复读取；读取失败不缓存成“消息不存在”。

预览是只读行为，hover 不滚动正文、不改变阅读锚点，不领取输入或触发执行。可见 ID 不构成额外授权，Host 仍核对当前连接与完整 owner。

### 4.5 点击定位与定位后阅读

2026-11-10 用户要求“不要出现加载后续消息，按序加载到对应位置”。本节据此撤回孤立目标窗口和正文双向续读设计。

- 点击标记或在聚焦标记上确认，定位到该条**真实用户输入**。已加载时直接滚动；未加载时从当前已加载正文的最早边界，按每页最多 10 个完整 Run 批次依次向前加载，直到目标及其所在批次已加载，再应用锚点。
- 已加载正文始终保持从最早已读位置到最新消息的连续区间。加载的中间页面保留，不用仅含目标附近内容的窗口替换；目标之后的消息可直接向下阅读，正文不提供底部历史分页入口。
- around-run／around-message 继续用于目标校验和锚点解析；引用、搜索、通知及阅读恢复同样通过顺序补齐到达目标，保留各自的实际锚点，不统一改成 User 锚点。
- 补页期间只显示一次定位进度，成功前保留原阅读位置。每页可靠合并后保持原可见消息与像素偏移；失败或超时保留已成功加载的连续内容，手动重试从当前游标继续，不重读已成功前缀。
- 正文只有顶部“加载更早消息”；右下“返回最新”滚动到连续正文末尾并恢复跟随，不替换掉已加载历史。
- 活动 Run 的状态与新输出沿现有实时机制更新到最新尾部，回看时保持滚动位置，不抢到底部。断线换代沿原恢复规则核对连续性，不能用 ID 去重掩盖历史缺口。
- 连续点击多个条目以最后一次定位意图为准；复用已加载页面，旧请求返回不得拉走阅读位置。悬停期间只请求短预览，不触发正文补页。
- 页面挂载和视区渲染完成后才应用消息锚点；折叠过程内的引用沿既有规则展开必要范围，不为一次定位展开所有处理过程。
- 目标被编辑删除、owner 不可读或正文不可用时显示明确反馈，不跳到邻近消息假装成功。F02 裁尾后的主动定位仍由 F02 决定，F01 提供失效处理。

正文顺序分页与缩略 ID 列表的独立滚动分开处理；缩略列表仍可重读被淘汰的 ID 页，不因此增加正文的后续加载入口。

### 4.6 去掉重复“继承”标签

| 展示位置 | 本期调整 | 必须保留 |
| --- | --- | --- |
| 用户消息 | 移除气泡旁独立“继承”标签 | 原附件、引用、来源、时间与 inherited 只读资格 |
| 处理过程 | 移除“继承 ·”前缀 | 真正的状态、截至分支点、已知时间／耗时及对应未知态 |
| 子任务列表／树 | 移除重复“· 继承”文案 | 名称、可靠状态、层级、正文不可用及只读访问限制 |

不删协议或历史中的 inherited／partial，不恢复来源会话的活动控制，也不因没有标签开放重试、继续、编辑等入口。需要解释操作限制时可给出对应原因，不重新在每条消息上放置同义徽标。

### 4.7 增量、失效与异常

读取共用当前连接、组织／用户、目标设备、Host 实例、完整 ConversationOwner 与已有 generation；MessageId 不能脱离该作用域单独作为缓存身份。正文页、导航 ID、预览和定位响应分别核对其当前读取意图，不以历史查询回包水位跳过实时事件。

| 变化或异常 | 用户结果与一致性要求 |
| --- | --- |
| 紧跟用户输入的 Run 最后一段正文更新 | 更新该输入对应的预览；中间 Step 正文不进入预览，不借用后续其他 Run 的回复，不只在 generation 改变时失效 |
| 尚未可靠提交的流式片段 | 正文沿现有实时视图显示；导航不据此伪造历史 ID 或最终回复。可靠提交后再更新配对及缺失预览 |
| 新真实用户消息可靠提交 | 追加用户缩略项，紧跟 Run 尚无最后一段正文时仅显示用户输入；隐藏输入不新增缩略项，手动阅读位置保留 |
| 历史裁尾、压缩换代或其他 generation 变化 | 旧页游标、配对和预览失效，旧请求丢弃；重读有效窗口。原锚点仍在则恢复，否则回到最新有效内容并提示原位置不可用 |
| 正在定位期间历史换代 | 不应用旧锚点结果；在现有请求预算内重新核实目标，失败保留当前有效视图，允许用户重试 |
| SSE 缺口、断线重连或 Host 重启 | 沿既有可靠快照和失效规则恢复，不仅凭旧浮层缓存猜测。离线保留的可读内容不意味着仍可发送新查询 |
| 切换组织、用户、设备或 owner | 取消或隔离旧在途结果，复用前重新核对作用域 |
| 导航 ID 读取失败 | 在导航边界重试；已加载标记与正文可继续阅读，不把正文变成整页错误 |
| 单个预览或历史目标读取失败 | 局部反馈，不清空其他有效内容，不自动反复请求，不把错误转换为不存在的助手消息 |
| 继承 child 正文不可用 | 沿既有正文不可用状态；不创建空历史、假预览或指向来源执行的控制入口 |

客户端与 Host 的短期缓存均不成为第二份历史权威；没有正在显示的浮层时不为每个新 token 拉取所有预览。

| runtime-host Store | [历史窗口](../../../../../apps/runtime-host/src/storage/conversation.rs) 已按文件位置读取展示记录，可靠历史仍在会话文件 | 复用并扩展位置读取以取得 Run 合批边界、目标邻域及用户输入与紧跟 Run 的配对；不为每页重新扫描完整正文，不为导航复制历史或新增 SQL 摘要库 |
| assistant-protocol／TS | [产品 DTO](../../../../../crates/assistant-protocol/src/product.rs) 已有 owner、generation、分页和 around 查询 | 明确轮数与记录数区别，补足有界导航、预览及定位续读契约；Rust 为源，TS 走既有生成链 |
| Volatile Store | 同样持有可靠会话历史与查询边界 | 保持与正式文件 Store 一致的轮次、配对和异常结果，不能仅由测试 Store 模拟满足 |
| agent-core | 执行 Step 与上下文能力 | F01 不修改执行循环或引入分页、缩略业务类型 |

现有 `limit` 为记录条数、现有历史页主要提供 `previous_cursor`，不能把新语义仅藏在前端补拉或换名中。技术方案明确轮数请求、目标之前的顺序补齐和协议准入，检查 Session／child 初始快照、直接分页、around、阅读恢复及 Client 消费方；不将 Recall 检索片段窗口等不同用途的 `limit` 一概改成轮数。

最小新增复核：分段、ID 配对和预览均从现有历史可推导，不引入 TurnId、独立生命周期、持久预览或全局轮数计数。必要新增仅是现有产品查询缺失的结果形态及 UI 交互；位置索引具体是否需要扩展、如何有界保存由技术方案基于实际读取成本说明。F01 不预设用户历史迁移。

## 六、关键取舍

| 取舍 | 原因及边界 |
| --- | --- |
| 现有 runId 合批，默认每页 10 轮 | 直接复用已有运行批次，单个批次不因 Step 或工具数量拆页，不引入 Goal 归并 |
| 缩略以真实用户输入为主体 | 用户消息 ID 作为条目身份与定位锚点，紧跟 Run 的最后一段正文可缺失；隐藏输入不冒充用户输入 |
| 紧跟用户输入的 Run 最后一段正文作为预览 | 中间 Step 正文不显示；按实际前后关系配对，缺少最后一段正文仍保留输入，不跨 Run 拼接或补配 |
| ID 列表、预览、正文分开按需读取 | 快速扫过超长导航不应变成整份历史加载；已有正文允许本地复用 |
| 点击未加载目标时按序补齐 | 复用现有向前分页与锚点路径，目标到最新消息连续可读；正文只有顶部历史入口，返回最新只需滚到底 |
| 两个滚动区各自保持位置 | 用户可在回看正文时浏览其他缩略项，新消息仅在既有底部跟随状态下带动列表 |
| 保留继承事实，仅简化可见文案 | 展示简洁不能改变权限、历史真实性与执行归属 |

本文按用户最新要求直接复用 runId 合批及实际相邻配对。定位按用户最新要求改为顺序补齐；默认页大小、预览懒加载与独立滚动保持；本 Feature 不承担 Goal 归属、跨 Run 合并或重定义轮次的工作。

## 八、风险、兼容与后续设计

- **超长 Run 批次**：单个 Run 可能含大量 Step 和消息。技术方案核对完整批次的读取、序列化、渲染和资源懒加载成本；不得暗中恢复按消息条数或 User 位置截断。如无法满足，先报告证据并重新确认产品取舍。
- **查询成本**：配对 ID 和文本开头不能靠每次读取全部历史；冷启动索引建立、后续增量及有界淘汰应复用现有文件位置机制，不扩展为全库常驻扫描服务。
- **兼容影响**：已发布客户端的 `limit` 和 previous-only 阅读行为具有既有含义。技术方案须评估所有生产者／消费者及同版升级、拒绝不兼容组合或必要兼容机制，再明确提交确认；本功能设计不决定兼容下限，不改源码版本，不预设迁移或双协议长期维护。
- **远距离定位成本**：按序补齐到很早目标会读取中间完整轮次，耗时和内存随距离增长。复用已加载页面、同一读取预算与失败续接；保留引用、搜索、通知及阅读恢复各自锚点，不重新从最新页重复拉取已读内容。
- **可靠历史与流式输出**：活动内容更新不能使静态预览永久缓存，也不能把每个 token 当成历史全量刷新；具体刷新信号与快照一致性归技术方案。

本 Feature **需要技术方案与界面交互设计指导**。总体设计、总计划与功能设计均已确认，本次按用户补充修正轮次口径。[技术方案](技术方案.md)已基于源码与依赖核查形成，明确现有 runId 合批复用、最后回复选择、查询契约、窗口／索引、缓存与失效、兼容选择及性能边界，已由用户确认；[界面交互设计指导](界面交互设计指导.md)已确认；[开发计划](开发计划.md)已确认，M0～M2 已由用户确认，M3 已完成本地验证，平台遗留待确认。
