### 2.2 正文入口

- 首次进入按现有恢复逻辑显示正文；没有阅读位置时打开最新 10 个完整 Run 批次并到底。
- 历史加载入口只在正文顶部。点击未加载目标时按序向前补齐到目标，保留目标之后到最新的全部已加载消息。
- 点击缩略标记定位对应用户输入。搜索、引用、通知和 Run 定位仍保留各自原目标，不能都改成用户输入锚点。

## 三、布局与信息结构

### 3.1 左侧留白与显隐

以下尺寸均为 CSS px，随应用／浏览器缩放变化，不按屏幕物理像素计算。

- `L` 为聊天正文内容左边缘到聊天视口左边缘的距离，依据实际 DOM 几何测量；左右侧栏、资源面板和正文宽度设置都会影响它。
- 首次 **L ≥ 88px** 时可显示导航；已显示后 L < 80px 才隐藏，避免边界附近反复闪动。聊天视口高度小于 192px 时隐藏。
- 导航距聊天视口左边缘 24px，宽 40px；与正文保留至少 16px 间隔，通常至少 24px。显示与隐藏不移动正文、不修改其最大宽度。
- 导航在标题和连接提示下方的完整内容区垂直居中，参考高度包含正文、Composer 和审批工作区。短列表按内容高度展示，长列表最高为该区域高度的 60%。
- 隐藏时取消悬停预览并移出键盘访问顺序；保留同一会话的导航阅读位置，重新显示时恢复。没有真实用户条目时不显示空导航框或假短线。

```text
会话标题
┌───────────────────────────────────────────────────────┐
│  24px  40px 导航       居中的原正文区域                  │
│         ─             加载更早消息                      │
│         ─                       用户输入气泡             │
│         ───           处理过程                          │
│         ━━━━━         最后一段回复                      │
│         ─             ……                              │
│                                                       │
│         ─             最新消息                   ↓      │
│                      Composer／审批工作区                │
└───────────────────────────────────────────────────────┘
```

图中箭头沿既有右下位置，短线不是正文高度的等比例地图。窗口足够宽但左侧没有实际留白时仍隐藏导航；不使用整窗宽度断点猜测是否可用。

### 3.2 标记尺寸与状态

缩略栏采用 12px 行距。每条真实用户输入对应一个 40 × 12px 点击单元，短线垂直居中、左边缘对齐，厚 2px，两端圆润。整个单元均可点击。

| 状态 | 短线与单元表现 |
| --- | --- |
| 普通 | 8px 长，使用 35% 不透明度的 `--ez-text-secondary`，点击单元背景透明 |
| hover | 指针下短线伸至 32px，上下各三条依次为 24、19、15px，移开后平滑恢复。仅指针下短线使用实色 `--ez-text-secondary` |
| 键盘焦点 | 单元显示 2px `--ez-primary` 轮廓，内缩以免裁切 |
| 正在定位 | 目标单元右侧显示小号加载图标，定位完成后收起 |
| 预览读取失败 | 保持正常短线，在浮层局部提供重试；不把消息标为运行失败 |

有无助手正文使用相同标记。导航隐藏滚动条，长列表支持滚轮、触控板和键盘独立浏览。

### 3.3 预览浮层

- 优先放在标记单元右侧，间距 12px，垂直中心对齐标记；默认宽 360px，受聊天可视区域和窗口安全边距约束，必要时缩窄并上下平移。
- 浮层与窗口边缘至少相距 8px，并限制在聊天正文视口的上下边界内；不得落入 Composer 或盖在模态对话框之上。若空间不足以展示可操作预览，则收起预览，标记定位仍可用。
- 使用 `--ez-surface`、`--ez-border`、`--ez-shadow-popover`，圆角 `--ez-radius-medium`（11px），内边距 12px；不使用 Tooltip 的深色底，不加装饰箭头。
- 上方是用户输入开头，最多两行，正文色、500 字重；下方是最后回复开头，最多四行，次级文字色、400 字重。两部分间距 8px，无可见角色标题；为辅助技术分别标注“用户输入”“助手最后回复”。
- 两部分使用现有 14px 正文字号和 1.5 行高。短文本自然收缩；超出接口的 160 字符上限或显示行数时在末尾显示省略，不提供浮层内“展开全文”。阅读完整内容通过点击标记定位。
- 只有用户 ID 时完全省去助手区，包括其空白、分隔和 loading。最后回复不存在与读取最后回复失败不同。
- 浮层内容可选择复制，但不增加复制／编辑／书签按钮；原始 Markdown 仅按纯文本显示，不激活内嵌链接、图片或代码执行。

```text
─  ┌──────────────────────────────────────┐
   │ 应用详情默认显示未来几天的数据        │  用户输入，最多两行
   │                                      │
   │ 详情页已调整为默认显示未来几天的      │  最后回复，最多四行
   │ 数据，无需额外点击。                  │
   └──────────────────────────────────────┘

─  ┌──────────────────────────────────────┐
   │ 下一步先调整消息分页。                │  仅用户输入
   └──────────────────────────────────────┘
```

浮层最大高度受聊天可视高度限制。文本放大后仍超出高度时允许浮层内部滚动以访问错误与重试控件，不缩小字体；常规尺寸下按上述行数截断，无内部滚动条。

## 四、交互流程

### 4.1 首次打开与列表续读

1. 正文按完整批次读取；导航满足显隐条件后独立读取最新 ID 页，两者分别反馈加载状态。
2. 首次导航读取未完成时，只在可用区域中间显示一个小号加载图标。短列表读完后居中，长列表从最新位置开始浏览。
3. 向上滚动接近导航顶部 96px 时读取前一批 ID；向下浏览已被裁剪的较新范围时，对称读取下一批。一次只发一项列表请求，失败后停止自动重试。
4. 插入旧条目或裁剪远端 ID 时，保留首个可见用户标记及其像素偏移；用户应看到内容接续，而不是列表突然跳到开头或底部。
5. 用户主动上翻即退出底部跟随。只有用户主动回到距底部 24px 内且已经读到最新条目，才重新跟随新输入；程序性插入和尺寸变化不改变跟随意图。
6. 正文和导航各自滚动，导航到边界也不把滚轮或触摸滚动传递给正文。使用同一事件隔离覆盖鼠标滚轮、触控板和键盘。

导航按已确认技术方案分批取 ID 和可见区域渲染，用户没有“缩略页码”或页大小设置。无论历史总长如何，短线间距保持一致。

### 4.2 悬停与键盘预览

- 鼠标停留同一标记 150ms 后打开浮层并读取缺失内容；快速掠过不逐项发请求。已有有效短文本可直接展示。
- 键盘聚焦标记立即打开浮层，缺失读取在焦点稳定 150ms 后发起；连续方向键移动只保留当前项的读取意图。
- 用户与助手分别加载。先返回的部分直接显示，加载中的部分用骨架线占位并向辅助技术提示“正在加载…”。没有助手 ID 时只显示用户区域。
- 鼠标从标记移入浮层时保持打开；离开标记与浮层联合区域后延迟 150ms 收起，间隙内移动不闪退。文本选区或浮层控件仍有焦点时保持打开。
- 切换标记立即切换浮层归属并清掉上一条显示内容，旧请求迟到不能覆盖新项。按 Escape 立即关闭，并抑制同一悬停／焦点自动重开，直到离开后重新进入或焦点移走再回来。
- 滚动导航或正文时收起当前浮层；滚动停止后只有新的明确悬停／焦点意图才重新打开，不能在鼠标未动时不断触发下一条预览。
- 窗口缩放时重算浮层位置；导航因空间不足隐藏、会话切换或打开模态界面时收起并结束旧读取意图。

悬停触发峰形和预览。正文位置由定位操作改变。

### 4.3 点击定位

1. 点击标记或按 Enter／Space，目标始终是该条真实用户输入。触摸设备轻点也直接定位，不要求先触发 hover。
2. 目标已在正文内时直接滚动；未加载时从当前最早边界按每页 10 个完整 Run 依次向前补齐，直到目标出现。全过程保留原阅读位置，目标标记显示局部忙碌；超过 150ms 仍未完成时统一显示“正在定位…”，不逐页弹出反馈。
3. 每页加载成功后连续前插并保留原阅读锚点；目标所在完整批次加载后，再将该用户输入顶部放在正文视口顶部下方约 32px；靠近历史边界时允许浏览器按实际可滚动距离夹紧。一次定位不自动展开全部处理过程。
4. 使用直接滚动，避免长距离平滑动画经过大量无关消息。定位后用户气泡短暂使用主题色细轮廓强调 1.2 秒；减少动态效果模式下取消淡入淡出，仅保留静态强调。
5. 鼠标定位不主动把焦点转到正文或 Composer，保留正常指针操作的焦点行为；通过键盘定位后焦点仍留在导航标记，辅助技术通过一次 polite 状态通知“已定位到消息”。用户可继续移动标记或 Tab 离开。
6. 连续点击以最后一次有效意图为准，复用已加载页面。加载失败或超时保留已成功补齐的正文、原阅读位置和标记，在当前浮层显示对应错误与“重试”；重试从当前加载边界继续，不从最新页重新开始。

成功定位后收起预览，并将定位所用的标记保留在可见范围。用户再次悬停标记时打开预览。

### 4.4 正文分页与返回最新

2026-11-10 按用户补充调整：正文保持连续历史，不出现“加载后续消息”；定位时按序加载到对应位置。

| 场景 | 交互 |
| --- | --- |
| 接近顶部 160px | 自动读取更早的最多 10 个完整批次；顶部仍保留可点击“加载更早消息” |
| 正在定位未加载目标 | 顺序读取必要的更早页面，复用同一分页在途请求，不并行重复翻页；统一反馈“正在定位…” |
| 顶部正在读取 | 顶部入口变为“正在加载更早消息…”，避免重复提交；正文可继续阅读 |
| 顶部读取失败 | 就地显示失败原因和“重试”；停止自动重发，保留已加载正文和当前阅读位置 |
| 到达历史起点 | 移除顶部加载入口，不常驻“没有更多了”占位 |
| 点击右下箭头 | 以“返回最新”为 Tooltip 和可访问名称；结束未完成定位等待，滚动到连续正文末尾并恢复跟随，保留已加载历史 |

普通自动翻页由用户接近顶部触发；点击未加载目标则明确授权顺序补齐到目标。初次布局和锚点恢复不会另行启动无目标的连续补页循环。每页前插保持原可见消息位置，直到目标完整加载才应用最终定位。

正文底部直接衔接最新消息和实时输出，没有历史分页按钮或加载分界。返回最新只改变正文位置，导航继续保留自身滚动位置与跟随意图。

### 4.5 实时更新与历史变化

- 正文和导航各自保留滚动位置。用户点击或移动键盘焦点时，目标标记保持在导航可见范围内。
- 新输入可靠出现后追加真实标记；隐藏输入不增加标记。最后回复更新只改变预览内容，不改变标记位置或数量。
- 预览资格失效时移除旧助手部分并重验；不能把转入中间 Step 的正文继续显示，也不能用缓存假装最后回复仍有效。
- 历史改写后，失效条目与预览退出。原阅读目标仍在则按原位置恢复；已移除则回到最新有效窗口并提示“原位置已不可用”。不同会话、child、设备或组织的内容不串用。
- 正文回看期间新消息接在连续历史的最新尾部，保持当前滚动位置；返回最新只需滚到底，不重新裁成最新一页。

## 五、视觉、焦点与组件规范

### 5.1 主题与文字

默认浅色的校准值如下，实际组件只消费已有语义变量；四套主题沿同一语义切换，不硬编码此表颜色。

| 用途 | 语义变量 | 默认浅色 |
| --- | --- | --- |
| 浮层表面 | `--ez-surface` | `#ffffff` |
| 用户预览／主要文字 | `--ez-text` | `#252932` |
| 普通短线／助手预览 | `--ez-text-secondary` | `#5f6673` |
| 浮层边框 | `--ez-border` | `#e2e5eb` |
| 键盘焦点 | `--ez-primary` | `#496cf2` |

继承现有 Inter／系统无衬线／中文系统字体栈，不下载新字体。正文用 `--ez-font-base`（14px）；边界按钮和次要反馈用 `--ez-font-small`（12px）。加载与错误说明使用可读的次级文字色，不用低对比度弱化到难以辨认。

悬停通过短线长度和颜色表达，键盘焦点通过轮廓表达。短线和浮层沿用约 110～120ms 的过渡，减少动态效果时取消过渡。

### 5.2 键盘与辅助技术

导航使用有名称的 `nav`，每条标记为原生定位按钮。通过 roving tabindex 保持单一 Tab 入口。

| 输入 | 结果 |
| --- | --- |
      | Tab 进入导航 | 优先恢复上次仍可见的焦点，否则聚焦可见范围内的最新项。焦点移动只打开预览 |
      | ↑／↓ | 移到相邻标记并预览；到已加载边界时读取相邻 ID 页，成功后继续，失败保留焦点 |
      | PageUp／PageDown | 按一个可见导航高度移动焦点；只加载所需相邻范围，不触发正文翻页 |
      | Home | 移到当前已加载最早条目，不宣称已到会话起点 |
      | End | 定位导航最新 ID 页并聚焦最新标记；只移动导航，不移动正文 |
      | Enter／Space | 定位对应用户输入；阻止 Space 误滚动正文 |
      | → | 预览有“重试”等操作时进入第一个浮层控件；纯文本预览无需增加焦点停靠点 |
      | ←／Escape | 从预览操作返回原标记；Escape 同时关闭预览 |
      | Tab／Shift+Tab 离开 | 沿正常界面顺序退出，不把焦点困在导航或浮层 |

预览是非模态有名区域，不使用带交互按钮的 `role=tooltip`。标记通过 `aria-describedby` 关联当前预览文本；文本尚未取得时，accessible name 为“查看消息”，加载后可追加该输入的短开头，不暴露原始 ID 或未知全局序号。加载／错误通过局部 polite 状态告知，不逐 token 或逐次滚动朗读。

导航隐藏或当前聚焦条目被删除时，先把焦点移到正文消息区域并保留滚动，再移除 DOM；焦点不能遗失到 body。虚拟化裁剪即将移除焦点标记时，先将焦点转到仍可见的邻近标记，再移除旧节点；该转移不定位正文，也不自动打开预览，下一次明确键盘或指针操作才恢复预览。

浮层复用 AnchoredOverlay 的 Portal、Presence、外部点击与视口校准；右侧放置能力在原组件上按实际需要扩展。现有 Tooltip 仍用于“返回最新”等简短说明，不统一修改其行为。导航触发器与浮层共同处理鼠标进出，不复制一套全局 Overlay 管理器。

### 5.3 继承标签

用户气泡旁移除独立“继承”徽标，处理过程标题移除“继承 ·”前缀，子任务行移除“· 继承”后缀。其他布局不补空位或替代徽标；“截至分支点”、真实运行状态、正文不可用、来源和既有操作限制继续展示。

标签移除后，消息操作、分支与子任务控制仍使用原只读资格。若原交互会解释操作不可用原因，保留该说明；本步不提前加入 F02 的编辑入口。

## 六、状态与异常文案

| 状态 | 展示位置与文案 | 恢复行为 |
| --- | --- | --- |
| 没有用户缩略项 | 导航隐藏；正文正常展示 | 新真实输入出现后按首次规则显示 |
| 初次 ID 读取失败 | 导航区域居中显示“重试消息导航”图标按钮，悬停或聚焦时说明“消息导航加载失败” | 点击重新读取，正文保持 |
| 早／晚边界 ID 读取失败 | 对应导航边界显示重试按钮；不替换已有标记 | 手动重试，成功后恢复锚点 |
| 用户预览失败 | 用户区域“输入预览加载失败”与“重试” | 只重读失败部分；助手部分可继续显示 |
| 助手预览失败 | 助手区域“回复预览加载失败”与“重试” | 只重读失败部分；用户输入保持 |
| 只有用户 ID | 只显示用户区域 | 不显示“暂无回复”或助手 loading |
| 有 ID 但文本为空 | 用户区域“无文本输入”；助手区域“暂无正文” | 不自动下载附件或寻找中间 Step 替代 |
| 定位失败 | 当前预览显示“定位失败”与“重试”；目标已删除时显示“这条消息已不可用” | 失败不移动正文；重试重新核对目标 |
| 读取超时／断线 | 对应局部入口显示已有友好错误与重试 | 保留当前可读内容，不无限重试或把整个聊天清空 |
| 历史变化导致原锚点消失 | 既有消息提示位置显示“原位置已不可用” | 恢复到最新有效窗口 |
| 子任务正文不可用 | 沿既有子任务不可用界面 | 不创建假标记或跳到来源会话冒充本地正文 |

导航宽度不足以放长错误文本，因此列表边界使用带说明和可访问名称的图标重试；浮层空间充足时使用文字按钮。错误不另弹阻塞对话框，不把读取失败写成运行失败。

| 回看历史同时有新回复；点击返回最新 | 新消息接到正文尾部但不抢阅读位置；返回最新只滚到底，保留已补齐历史，导航仍保留自己的阅读意图 |
| 纯键盘、触控板、触摸宽窗、文字放大 | 单一导航 Tab 入口、焦点可见且不丢失；键盘／滚轮不误滚正文，重试控件可达 |
| 四套主题、减少动态效果、窄窗 | 短线、正文、浮层与焦点可辨认；不依赖动画；窄窗隐藏导航后正文仍正常使用 |
