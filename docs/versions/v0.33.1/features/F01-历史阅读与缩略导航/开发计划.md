# v0.33.1 F01 开发计划：历史阅读与缩略导航

## 一、计划信息与设计依据

- 日期：2026-11-10。
- 版本／Feature：v0.33.1／F01；版本状态为 **开发中**。2026-11-10 用户要求开始 F01 开发并推进至人工验收，确认本计划并启动 M0。
- 上位依据：[总体设计](../../总体设计.md)、[版本总计划](../../开发计划.md)。
- 已确认基线：[功能设计](功能设计.md)、[技术方案](技术方案.md)、[界面交互设计指导](界面交互设计指导.md)。用户于 2026-11-10 在顺序加载调整完成后回复“继续”，确认交互指导并进入本计划。
- 流程依据：[开发流程规范](../../../../specs/开发流程规范.md)。本计划只安排实施与确认，不重新定义协议、轮次、配对或交互参数。

最终结果：用户按完整 Run 批次阅读历史，在左侧留白通过用户输入缩略条目预览、定位；未加载正文按序补齐到目标，目标到最新消息保持连续。预览只取紧跟 Run 最后回复的开头，允许没有助手正文。重复“继承”文案移除，原只读语义保持。

## 二、台账原则

- 按能力链路串行推进：先使正式正文读取和定位可用，再贯通导航与预览读取，随后接入交互，最后完成 Feature 验收。每个实现里程碑包含其生产者、消费者和必要验证，不遗留只定义类型却没有真实读取的空实现。
- M0 开始前确认本计划并将版本状态改为 `开发中`。M0～M2 各自完成实现与验证后先记为 `🟨 待确认`，获得用户确认才进入下一项；M3 验收同样需用户确认。
- 每步先核查现有实现，按根约束读取对应语言、架构与模块规范；复用现有 runId 合批、文件索引、读取生命周期、消息锚点、浮层与主题。新增机制必须有已确认的实际缺口。
- 技术方案与交互指导为具体实施依据；发现假设不成立时先报告影响并修订相应设计，不在计划中另造一套行为。大 Run、远距离定位的成本不能通过拆轮、孤立正文窗口或无限续开预算规避。
- 只推进 F01；F02 编辑裁尾与 F03 介入保持后续 Feature 归属。F01 验证现有历史换代与读取失效，真实编辑和 Step 换轮的联合验收在相应 Feature 完成后执行。
- 计划只保留状态、用户确认、完成结论及必要遗留；过程恢复写入忽略的 `docs/开发进度.md`，不另建验证报告或登记内部工作文件为产物。

## 四、里程碑实施与完成判定

### M0 完整 Run 分页与顺序定位

**目标／前置**：本计划确认后，使现有聊天历史读取、引用／搜索／Run 定位直接获得完整批次，并保持目标到最新消息的连续正文。

**交付范围**：

- 贯通协议、Runtime 产品查询、Store、正式 Host 文件读取及 Volatile 的整批页边界；同步主会话／child 初始快照、普通分页和 around 查询。原始记录读取及 Recall 窗口保持各自用途。
- 在原文件位置索引内维护批次边界，覆盖冷建、可靠追加及换代失效；新增导航配对与预览读取留 M1。读取不得改写原始历史或安装历史 Run 为执行对象。
- 同步 Desktop／Host Web 消费与 RootStore 既有顺序加载路径；逐页合并保持阅读锚点，定位失败保留成功前缀，重试从当前边界继续。回看时新输出接在尾部，返回最新只滚到底。
- 按已确认方案完成软件版本及应用最低兼容版本配套调整、Rust 到 TS 的正式生成、Desktop／Client 等消费者及相关锁文件同步；数据库最低兼容版本与持久格式保持原基线。版本内后续 M1 查询直接增补到同一契约，不保留草稿别名。

**验证入口**：复用 [Runtime 历史查询测试](../../../../../crates/assistant-runtime/src/runtime/product/history_tests.rs)、[Host Conversation 测试](../../../../../apps/runtime-host/src/storage/conversation/tests.rs)、[前端分页测试](../../../../../apps/desktop/tests/unit/conversation-paging.test.ts)、[历史投影测试](../../../../../apps/desktop/tests/unit/runtime-projection-store.test.ts)及既有兼容测试。

验证完整批次、仅用户尾部、旧历史／partial／child、运行中追加；验证顺序定位部分成功后失败、总预算耗尽、无进展游标、连续点击、历史换代、重连快照衔接与返回最新。先做定向回归及构建，再完成本节末列出的共享 Rust 变更门禁；正式 Host 的隔离会话需经产品查询和实际聊天入口读取，不能仅用前端假页通过。

**完成判定**：功能设计 F01-01、F01-02、F01-04 的正文侧及 F01-08、F01-09、F01-14 的既有定位入口通过；默认页数、单批完整性、页面接缝及故障续接正确，正文无底部历史加载入口。同版配套接入成功，旧新混连按已确认方案拒绝，原持久历史可读。大单批成本在本步验证，不留到导航完成后才发现正文无法加载。

**Review 重点**：批次数和记录数没有混用；没有按用户位置或 Goal 重定义轮次；游标与读取预算有终止边界；快照合并保持可证明的连续性；取消读取不取消 Run；索引失败不重放业务提交；全部消费方与生成协议一致。

### M1 缩略 ID 与预览读取

**目标／前置**：M0 经用户确认后，贯通“真实历史 → ID 配对 → 所选消息短预览 → 客户端局部投影”的正式读取链路。

**交付范围**：

- 在既有派生索引中补齐相邻用户／Run 配对及最后回复候选，正式文件 Store 与 Volatile 使用同一语义；覆盖只变运行状态的更新与新 Step 导致旧回复失效。
- 接通技术方案确定的导航列表和单消息预览查询，包括协议生成、Runtime 授权与代次检查、Host Worker／dispatch、远端命令与代理允许集合。
- 接入客户端既有读取生命周期、导航 ID 页及预览缓存，处理局部 loading／错误、并发上限、有限重试、缓存失效和过期回包。缺失助手 ID 不发助手查询；已加载正文可按同一截取规则复用。
- 用正式命令链路和客户端 Store 验证读取意图，不新增调试页面或提前接入 M2 导航 UI；本步结果是可由实际调用方消费的完整查询能力。

**验证入口**：扩展 M0 的 Runtime／Host 测试、协议序列化和客户端生命周期测试；以现有 [处理过程测试](../../../../../apps/desktop/tests/unit/processing-turn.test.tsx)的 reply 语义核对跨语言选择。查询同时覆盖主会话与 child、本机及远端允许路径、合法缺失与真实错误、错误 owner／generation、控制项／隐藏输入／中间 Step ID 拒绝、Unicode 截断及仅附件输入。

以至少 10,000 个真实用户条目的隔离夹具核对 ID 分页、裁剪与反向重读；核对冷建和可靠增量结果、热 ID 不解码正文、预览定点读帧及大单帧成本。运行状态更新必须使失效预览退出，悬停读取意图不得触发中间正文补页或推进全局事件消费水位。执行相关生成检查、构建与共享 Rust 变更门禁。

**完成判定**：F01-03、F01-05 及 F01-06、F01-12、F01-13 的数据与生命周期侧通过；列表每项只有用户 ID 和可选助手 ID，预览准确取紧跟 Run 的最后回复，读取／缓存工作量遵守技术方案。无助手、空文本、不可用消息和查询失败可区分，正式产品链路没有绕过授权的读取入口。

**Review 重点**：运行状态与历史事实没有第二份权威来源；无额外 Run／Goal 关联实体；选择结果与 UI reply 一致；索引只存派生元数据；短预览响应与物理帧解码成本分别核验；缓存不能只靠 generation 永久有效；没有嵌套重试或取消后的迟到安装。

### M2 缩略导航交互与继承文案

**目标／前置**：M1 经用户确认后，将已验证的读取能力接入正式聊天界面，完成可操作的导航与预览体验。

**交付范围**：

- 按交互指导接入左侧留白显隐、紧凑标记、悬停反馈、浮层与局部失败重试；复用现有主题、图标和 AnchoredOverlay。布局参数、焦点规则及文案以交互指导为唯一依据。
- 接入独立滚动、默认到底、主动上翻保持、局部窗口渲染与 ID 页淘汰／重读；缩略滚动、预览与正文滚动互不冒用意图。
- 点击用户标记使用 M0 顺序定位，hover 只使用 M1 预览；完整接通实时变化、历史换代、切换 owner、浮层关闭和键盘焦点恢复。
- 去掉用户消息、处理过程和子任务中的重复“继承”文案；保留 inherited／partial、分支点、正文不可用及原操作资格。

**验证入口**：扩展现有 ConversationView、ProcessingTurn、浮层及读取投影回归，执行前端 lint、定向测试和正式构建。通过正式 Host Web 和适用原生 Desktop 验证交互指导第七节，重点覆盖窄窗／侧栏／缩放、四主题、纯键盘、滚轮与触控板、连续 hover／点击、浮层内重试、虚拟化裁剪焦点、返回最新及新输出不抢位。

在长导航上验证 DOM 与缓存边界、前插／裁剪／反向读取锚点；以继承和 partial 历史核对三处文案及只读操作。文案删除复用既有行为验证，不为删除字符串单独新增低价值测试。原生构建复用已有流程，打包与验收运行不得争用同一构建产物。

**完成判定**：F01-06～F01-13 的完整交互及 F01-11 只读边界通过；导航可发现、可预览、可定位、可重试，长列表不丢位置或焦点。目标到最新正文连续，无“加载后续消息”；组件隐藏后不继续为导航读取，不挤压正文或遮挡输入区。

**Review 重点**：UI 仅持有可恢复投影；测量、浮层及焦点复用既有基础；长列表没有全量 DOM 或伪造总数；合法无回复不显示永久 loading；预览过期及时清除；标签删除没有放开历史操作。

### M3 F01 独立验收

**目标／前置**：M2 经用户确认后，结合已有有效验证结果，完成 F01-01～F01-14 的正式链路验收。

**交付范围与验证入口**：贯通长会话、超大单批、主会话／child、运行中更新、历史换代、断线重连及 Host 重启；从真实聊天入口验证 ID 列表、缺失预览、顺序定位、返底与只读历史。复用 M0～M2 结论，只补跨步骤组合、实际发现缺陷与最终候选受影响检查。同步本 Feature 改动涉及的长期模块文档，完成本计划与版本总台账的一致性核对。

Host Web、macOS 与 Windows 原生结果分别报告，未验证平台单列。设备与组织切换场景检查正文、导航和预览的读取作用域隔离。按用户确认，F01 人工验收聚焦阅读和缩略导航，移除双机组网验收项。按用户要求提供 macOS 本地测试包。

**完成判定**：所有 F01 验收点已满足，或用户明确接受范围调整且设计同步；核心读取、权限、数据完整性和实际可用性问题已解决。记录实际覆盖、未完成项和必要成本限制，完成结论经用户确认后将 F01 记为完成，向 F02 交付轮次、定位、失效与只读边界。

**Review 重点**：没有把仅单测、短列表或单一平台结果冒充完整验收；没有把未实现的 F02／F03 联合场景记为通过；版本仍保留跨 Feature 验收、用户文档与发布门禁。

### 验证命令与执行边界

以下均为实现阶段入口，本计划交付只做文档检查。测试过滤按实际修改及用例名称选择，不能以过滤后零用例视为通过。

| 用途 | 已有命令／入口 | 使用阶段 |
| --- | --- | --- |
| Rust 定向回归 | `cargo test -p assistant-protocol`；`cargo test -p assistant-runtime history`；`cargo test -p assistant-runtime-host storage::conversation`，并补所改模块对应过滤 | M0、M1 先执行；失败修订后复测 |
| Rust 共享边界门禁 | `cargo fmt --all --check`、`cargo clippy --workspace --all-targets --all-features -- -D warnings`、`cargo test --workspace` | M0、M1 共享协议／Store 改动完成后按技术方案执行；后续只有相关新改动或失败证据时重跑 |
| 协议与前端 | `npm --prefix apps/desktop run check:protocol`、`npm --prefix apps/desktop test -- <相关测试路径>`、`npm --prefix apps/desktop run lint`、`npm --prefix apps/desktop run build` | 各实现里程碑按涉及范围；协议生成调用现有 `generate:protocol`，不手改生成内容 |
| Client 配套 | `npm --prefix apps/client run build`；`npm --prefix apps/client test` | M0 验证版本与兼容，M1 验证新协议投影；仅构建检查不足以替代实际相关准入用例 |
| 正式 Host Web | `npm --prefix apps/desktop run test:e2e:web -- <相关场景>`，使用其既有 Host 构建与隔离启动链路 | 对应能力就绪时执行；先核对测试配置和 Runtime Home |
| 原生 Desktop | 在 `apps/desktop` 执行 `npm run tauri -- build --no-bundle`，使用 `tauri.dev.conf.json` 隔离偏好的原生运行流程 | M2／M3 的实际平台交互；构建与使用同一产物的运行串行 |

自动化与验收仅使用项目 `.runtime-test/` 下按场景新建、核实无用户数据的独立 Runtime Home；启动前核对实际连接、数据库及读取表，不复用已有测试库或用户 Home。数据库操作遵守根安全规则。失败先核对目标与影响，不能扩大到共享数据或通过放宽断言、超时、lint 来宣称通过。

### 当前结论

- M0 完成完整 Run 分页、顺序定位及应用版本 0.33.1 配套准入。数据库使用 0.33.0 的结构和账本。用户于 2026-11-10 确认 M0。
- M1 完成正式 Host、Volatile 和 Desktop／Web 的导航 ID 与预览读取，覆盖配对、定点读取、缓存、失效和远端命令准入。用户于 2026-11-10 回复“继续”确认 M1。
- M2 完成缩略栏、预览、顺序定位、键盘焦点及局部重试，移除三处重复继承文案并保留只读资格。Host Web 通过布局阈值、四套主题、长列表滚动与裁剪、定位失败续接、返回最新和分支历史回归。macOS 原生窗口通过核心交互实测及开发构建。用户于 2026-11-10 确认 M2，进入 M3。
- 按验收反馈将缩略标记行距收紧为 12px，默认短线长度缩至 8px。悬停通过短线长度和颜色反馈。
- 按后续验收反馈，短列表按内容高度垂直居中，长列表限高滚动，预览文字加载时分区显示骨架。Host Web 定向回归和 macOS 原生布局复测通过。
