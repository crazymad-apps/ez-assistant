## 二、已核对的现状

| 事项 | 现状 |
| --- | --- |
| 项目查询 | `ListWorkspaces` 一次返回全部活动项目，按 Workspace ID 排序，没有分页 |
| 会话查询 | `ListSessions` 是全局查询，按“置顶在前、最近活动时间、Session ID”排序，以 offset／limit 分页；没有按项目筛选的条件 |
| 侧栏数据来源 | 应用快照带回全部项目和全局会话第一页；侧栏在前端按项目过滤分组，底部只有一个全局“加载更多” |
| 刷新 | 重连或刷新时按已加载数量整段重取，不退回第一页 |
| 会话归属 | 会话的项目归属记在 `session_resources.workspace_id`，创建后没有修改路径；项目与会话都有 `created_at_ms` |
| 置顶 | Desktop 置顶是本机偏好，可跨设备，按加入顺序展示，不回写 Runtime；Host Web 使用 Runtime 的 `is_pinned`。两端都把已置顶会话从分组中隐藏，只在置顶区展示 |
| 归档视图 | 与活动视图共用同一套分组，只是换成归档会话；无置顶与项目操作 |
| 搜索对话框 | 无关键词时直接展示侧栏已加载的全局列表，有关键词时走 `ListSessions` 的标题筛选 |
| 主控会话 | 侧栏以固定的“助理会话”入口展示，前端从分组中过滤掉 |
| 身份隔离 | 每个用户使用各自的数据域，列表查询不跨用户；远端设备的列表来自该设备的 Host |
| 拖拽 | 侧栏目前没有任何拖拽排序 |

全局会话查询另有四处内部调用，改动排序或分页时必须逐一核对，见[第六节](#六模块职责与契约影响)。

## 三、目标与非目标

**目标**：项目和会话默认按创建时间排列、新建在前；用户可以在同一列表内拖动调整顺序，顺序由目标 Host 保存，换端、刷新和重启后一致；项目列表和每个分组内的会话各自按最终顺序分页读取。

**非目标**：

- 跨项目拖动会话、把独立会话拖入项目，或以任何方式迁移会话归属。
- 改变置顶数据的现有归属：Desktop 跨设备置顶仍是本机偏好，Host Web 置顶仍归 Runtime。
- 把会话拖入或拖出置顶区来置顶、取消置顶。
- 按更新时间、名称等其他排序方式的切换。
- 归档视图、搜索结果中的拖拽。
- 多选拖动、分组折叠状态的跨端同步。

## 四、功能规则

### 4.1 列表范围

排序和分页各自在下列范围内进行，范围之间互不影响：

| 范围 | 内容 |
| --- | --- |
| 项目列表 | 当前 Host、当前用户的活动项目 |
| 项目内会话 | 属于同一项目的会话 |
| 独立会话 | 不属于任何项目的会话 |
| 置顶区 | 已置顶的会话，跨项目；规则见 [4.6](#46-置顶区) |

主控会话保持为固定入口，不进入任何范围。已移除项目的会话沿现有规则不显示。

### 4.2 默认顺序与入列

- 默认按创建时间排列，新建在前；创建时间相同时按稳定 ID 决定先后。Desktop 与 Host Web 一致。
- 新建的项目进入项目列表最前；新建会话和分支（Fork）出的会话进入所属范围最前。
- 发送消息、Run 开始或结束、改名、切换模型或模式、F02 编辑重发、F03 介入都不改变位置。
- 升级后，已有项目和会话按上述默认顺序排列，等同于从未手动调整过。

### 4.3 拖动调整

- 只在活动视图中可用：拖动项目调整项目列表顺序，拖动会话调整其所在项目内或独立会话内的顺序。
- 只能落在同一范围内。拖出所属范围时不接受放置，松手后回到原位，不提示迁移。
- 运行中的会话可以拖动。拖动只改顺序，不影响 Run，也不改变最近活动时间。
- 浏览远端设备时，拖动结果保存到该设备的 Host。
- 未连接、已有会话或项目操作在进行、或当前身份无权修改时不可拖动。
- 结果以 Host 返回为准：成功后按 Host 的最终顺序展示；失败时恢复拖动前的顺序并提示。
- 只能放到已加载的条目之间。拖到分组末尾时按需加载下一页，不为拖动预取全部历史。
- 拖拽手势、放置指示和自动滚动由界面交互设计指导确定。本期不提供键盘移动。

### 4.4 恢复默认

每个范围各有一个“恢复默认顺序”入口，只影响自己的范围：

| 范围 | 入口位置 |
| --- | --- |
| 项目列表 | “项目”标题行 |
| 项目内会话 | 该项目的操作菜单 |
| 独立会话 | “独立会话”标题行 |

- 执行前需二次确认，因为手动顺序无法找回。
- 执行后该范围回到创建时间顺序，不改创建时间、标题和消息内容。
- Host 不记录“是否手动调整过”，入口始终可用；对已是默认顺序的范围执行不产生可见变化。

### 4.5 分页

- 项目列表按页读取，列表末尾提供加载更多。
- 每个展开的项目读取自己会话的第一页，并在该项目末尾提供加载更多；独立会话同理。折叠的项目不读取会话。
- “该分组没有会话”与“尚未加载”分别展示，不用其他分组的加载结果推断。
- Host 先按最终顺序排序再取页。把靠后的条目拖到前面后，刷新首屏即可读到它。
- 刷新和重连按各分组已加载的数量重取，不退回第一页。
- 新建、分支、归档、恢复、移除项目、拖动和恢复默认之后，刷新受影响的分组；较早发出的请求晚到时丢弃，不覆盖新顺序。

### 4.6 置顶区

2026-11-16 用户要求把置顶区排序纳入本 Feature，顺序保存的位置与置顶数据现有的保存位置一致。

| 端 | 置顶数据现在保存在 | 置顶区顺序保存在 |
| --- | --- | --- |
| Desktop | 本机偏好中的置顶列表，可包含多台设备的会话，按列表先后展示 | 同一份本机偏好：拖动即调整列表先后，不经过 Host |
| Host Web | Runtime 的会话置顶标记 | 目标 Host，与置顶标记放在一起 |

- 置顶区内可以拖动调整顺序，只能落在置顶区内。
- 新置顶的会话排在置顶区最后，与 Desktop 现有行为一致。
- 置顶区顺序与分组内顺序相互独立：拖动置顶区不改变会话在项目内的位置，反之亦然。
- 已置顶会话沿现有规则只在置顶区展示；其组内位置保留，取消置顶后回到原位置。再次置顶时重新排在置顶区最后。
- 置顶区不分页、不提供恢复默认。
- Desktop 的置顶顺序只在本机生效，不同步到其他设备或 Host Web；Host Web 的置顶顺序对访问该 Host 的各浏览器一致。

### 4.7 归档与移除

- **归档**：会话归档后保留位置。归档视图按同一顺序只读展示；恢复归档后回到原位置。
- **移除项目**：项目移除后保留位置，恢复后回到原位置，其会话顺序不变。

### 4.8 其他入口

- **搜索对话框**：跨分组展示，有无关键词都按创建时间新建在前，由 Host 分页，不反映手动顺序，也不可拖动。
- **选择项目的入口**（如新建会话时选择项目）：按项目列表的顺序展示。
- **已移除项目对话框**：沿现有展示。

### 4.9 并发与失败

- 多端同时拖动时按 Host 收到的先后依次处理，后到的请求基于当时的实际顺序执行。
- 拖动提交时，被移动的条目或参照的相邻条目已不存在、已归档或不在同一范围：本次失败，界面刷新该范围并提示列表已变化，不自动重试。
- 请求中断、结果未知时，界面重新读取该范围的顺序，不自动重发移动。
- Host 重启后顺序与重启前最后一次成功的结果一致。
- Desktop 置顶区的拖动沿本机偏好现有的保存规则：保存成功才更新显示，失败时保持原顺序并提示。

## 五、关键取舍

| 取舍 | 理由 |
| --- | --- |
| 归档、恢复、取消置顶、恢复已移除项目都回到原位置，而不是置顶到最前 | 这些动作都不需要写分组排序值；规则与“默认按创建时间”一致，不引入“最近恢复”这类第二种排序依据 |
| 置顶区顺序跟随置顶数据的现有保存位置，两端不统一 | 用户要求保持一致；Desktop 的置顶列表本身有先后，拖动只是改写它，不新增存储；统一到 Host 会改变 Desktop 置顶的本机归属 |
| Host 分组查询不按置顶过滤，由客户端沿现有方式隐藏已置顶会话 | Desktop 置顶是本机偏好，Host 不知道；两端用同一查询，避免为 Web 单独维护一套分组结果 |
| 搜索对话框不反映手动顺序 | 搜索结果跨多个范围，各范围的排序值之间不可比较 |
| 不记录“是否已手动调整” | 避免为一个入口的可用状态新增持久状态；多执行一次恢复默认没有副作用 |
| 归档视图不可拖动 | 归档视图是低频的查找入口；活动与归档共用同一排序值，在活动视图调整即可 |
| 只支持同范围拖动 | 会话归属目前没有修改路径；跨项目拖动等于新增迁移能力，属于另一项需求 |

## 六、模块职责与契约影响

| 模块 | 职责 |
| --- | --- |
| Host 存储 | 保存每个项目和会话的排序值，以及 Host Web 置顶会话的置顶区顺序；按范围、生命周期和最终顺序查询取页；在事务内完成移动、间隔不足时的分组重排和恢复默认 |
| Runtime | 校验身份、范围和相邻条目，执行移动与恢复默认，发布列表变化；不让排序变更推进会话的最近活动时间 |
| 协议 | 增加按范围分页的查询、移动和恢复默认的命令；排序值不出现在协议中 |
| Desktop／Host Web | 按范围加载与刷新，提交移动意图，展示 Host 返回的顺序；不计算排序值，不上传完整 ID 列表。Desktop 另在本机偏好中调整置顶列表的先后 |

依赖全局会话查询的现有调用，技术方案必须逐一给出处理：

| 调用方 | 依赖点 |
| --- | --- |
| 待办通知同步 | 以全部生命周期遍历全局列表 |
| 智能终端取主控会话 | 在全局列表默认第一页中查找主控会话 |
| 启动时的默认选中 | 取已加载活动会话的第一条 |
| Desktop 旧置顶导入 | 依赖“置顶在前”的排序，遇到未置顶会话即停止翻页 |
| 选中会话的补入 | 选中的会话不在已加载列表时，前端把它追加进活动列表 |

兼容与迁移：排序字段和索引需要数据库迁移，并为已有数据初始化排序值。本版存储目标与最低 Host 已因 F02 升为 0.33.1，F04 作为同一未发布版本内的增量迁移评估，不为版本内的中间形态保留兼容。具体字段、索引、迁移步骤、备份与旧 Host 准入由技术方案确定，实施前确认。

## 八、风险与待确认

**风险**：

- 分组重排和恢复默认是批量写入，成本随分组大小增长，需要用大分组实测。
- 侧栏从“一份全局列表”改为“多份分组列表”，刷新、重连和迟到响应的处理面变大，是前端主要改动风险。
- 全局查询的排序一旦调整，上节所列调用方可能静默出错，尤其是依赖“置顶在前”提前停止的旧置顶导入。
- Host Web 置顶区跨项目，不能复用会话的分组排序值，需要在 Host 上为置顶另存一个顺序，是分组排序之外的一处新增存储。
- 默认展开全部项目时首屏需要为每个项目读取第一页，项目很多时的请求数量需要在技术方案中控制。

**已确认的取舍**（2026-11-16）：

1. 归档后恢复、取消置顶、恢复已移除项目都回到原位置（4.6、4.7）。
2. 置顶区排序按 4.6 纳入：Desktop 存本机偏好，Host Web 存 Host 并为此新增置顶顺序的存储；新置顶排在最后。用户回复“Web 也支持”。
3. 搜索对话框统一按创建时间排列，不反映手动顺序（4.8）。
4. 恢复默认的三个入口位置及二次确认（4.4）。
5. 分组拖动仅在活动视图可用，归档视图只读（4.3）。
6. 选中的会话不在已加载页时不再追加进列表，侧栏不显示选中态，由交互指导细化。
