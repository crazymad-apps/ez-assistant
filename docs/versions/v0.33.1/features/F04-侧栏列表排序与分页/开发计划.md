排期说明：

- M0 先行：迁移、查询计划和大分组重排成本是本 Feature 的主要风险，需要在接入界面前用隔离库实测。M0 不改协议和界面，产品行为不变。
- M1 一次改完应用快照的结构及其全部使用方。快照结构是直接替换，不保留旧字段，所以后端与前端的读取路径必须在同一个里程碑内贯通，中途不存在可运行的中间形态。
- M1 结束时侧栏已是新顺序和分组分页，但还不能手动调整；移动与恢复默认的命令、事件和界面全部放在 M2。
- 拖动的实现方式（自行用指针事件实现或引入依赖）在 M2 开始时按交互指导评估后决定，引入新依赖需先确认。

M0、M1 已分别随用户“继续”确认。M2 已接通四类同范围拖动、三个恢复默认入口、事务写入与独立变更事件；Desktop 置顶只保存到本机，Host Web 置顶保存到 Host。采用现有 Pointer Events，未增加依赖；临时排序按范围隔离，失败回退，结果未知只重取。Rust／前端回归、正式 Host 构建、Chromium／WebKit 页面及 macOS WKWebView 原生鼠标、Esc、窗口失焦检查通过，2026-11-16 用户复测确认 M2。

代码仍位于独立工作树 `codex/f04-sidebar-storage`，尚未合入主工作树或提交。仅使用新建隔离测试库，无用户数据迁移。验收结果及尚未实测的场景见第三节。
