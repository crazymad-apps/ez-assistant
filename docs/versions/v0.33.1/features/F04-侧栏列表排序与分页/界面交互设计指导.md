# v0.33.1 F04 界面交互设计指导：侧栏列表排序与分页

## 一、设计信息

- 日期：2026-11-16。状态：**已确认**。2026-11-16 用户回复“确认并编计划”。
- 依据：[功能设计](功能设计.md)、[技术方案](技术方案.md)，均于 2026-11-16 确认。适用 Desktop 与 Host Web。
- 复用现有侧栏的行样式、标题行图标按钮、项目操作菜单、文字按钮和 `SessionActionDialog` 确认框；不新增页面或窗口。

## 二、侧栏结构

```text
  置顶                                            ⌄
    会话 A                                      [📌]
    会话 B                                      [📌]

  项目                           [＋] [↺] [⇅]     ⌄
  ▸ 📁 项目甲                                [⋯]  ⌄
        会话 1                              3 分钟
        会话 2                              昨天
        加载更多
  ▸ 📁 项目乙                                [⋯]  ⌄
        暂无会话
  ▸ 📁 项目丙                                [⋯]  ›
       加载更多

  独立会话                            [＋] [⇅]    ⌄
    会话 9                              11 月 2 日
    加载更多
```

- `⇅` 是新增的“恢复默认顺序”图标按钮，位于标题行现有按钮之后、折叠箭头之前，与现有按钮同尺寸、同显隐规则。
- 项目列表和各会话分组在自己的末尾提供“加载更多”。
- 行的时间、运行指示和置顶按钮保持现状。

## 三、拖动

### 3.1 可拖动的对象

| 对象 | 可放置的位置 |
| --- | --- |
| 项目行 | 项目列表内，其他项目之前或之后 |
| 项目内的会话行 | 同一项目内 |
| 独立会话行 | 独立会话内 |
| 置顶区的会话行 | 置顶区内 |

归档视图、搜索对话框、未连接、有会话或项目操作在进行时，行不可拖动，表现与现在完全一样。

### 3.2 手势

| 输入方式 | 开始拖动 | 取消 |
| --- | --- | --- |
| 鼠标、触控板、触控笔 | 在行上按住至少 120ms 后移动，位移达到 8px 时进入拖动。短按或小幅位移按普通点击处理 | 按 Esc，或在可放置范围之外松手 |
| 触控 | 长按 400ms 后进入拖动，进入时行有一次轻微放大提示 | 在可放置范围之外松手 |

- 行内的置顶按钮、项目菜单和折叠箭头上按下不触发拖动。
- 使用指针事件实现，不使用浏览器原生拖放，避免与 Desktop 的文件拖入处理冲突。
- 拖动期间禁用文本选中，窗口失去焦点时取消拖动。
- 本期不提供键盘移动（2026-11-16 用户确认去掉）。

### 3.3 拖动中的表现

- 被拖动的行跟随指针纵向移动，带轻微阴影；原位置保留完整行的半透明虚影（35% 不透明度与现有悬停底色），保留文字、图标和原行尺寸，不直接隐藏。
- 其他行不实时让位，用一条 2px 的强调色横线标出松手后的插入位置。横线的缩进与该范围的行一致。
- 拖动项目时只有项目标题行跟随指针；该项目展开的会话列表在拖动期间收起，松手后恢复原展开状态。
- 指针移出可放置范围时横线消失，光标显示为禁止，此时松手即取消。
- 指针靠近侧栏滚动区上下边缘 32px 内时自动滚动，越靠近越快。
- 拖动中指针停在本范围的“加载更多”上超过 600ms，自动加载下一页，加载完成后可继续向下拖动。

### 3.4 松手之后

1. 落点与原位置相同时不发请求。
2. 落点有效时，行立即显示在新位置，同时提交移动。请求期间该范围不接受新的拖动，其他范围不受影响。
3. 成功后不再有额外提示，顺序以随后刷新的结果为准。
4. 失败时行回到拖动前的位置，侧栏顶部显示一条错误提示：列表已变化时为“列表已更新，请重试”，其他情况为“顺序保存失败，请重试”。提示沿用侧栏现有的错误提示样式。

### 3.5 置顶区

- 手势、表现和松手后的处理与上面相同。
- Desktop 的置顶顺序保存在本机，保存期间置顶区不接受新的拖动；保存失败时沿用置顶区现有的错误提示。
- 置顶区包含其他设备的会话时，这些行同样可以拖动，设备离线不影响调整顺序。

## 四、恢复默认顺序

| 范围 | 入口 | 确认框标题 |
| --- | --- | --- |
| 项目列表 | “项目”标题行的 `⇅` 按钮，Tooltip 为“恢复默认顺序” | 恢复项目的默认顺序？ |
| 项目内会话 | 项目操作菜单中的“恢复默认顺序”，位于“编辑项目…”之前 | 恢复“项目名”内会话的默认顺序？ |
| 独立会话 | “独立会话”标题行的 `⇅` 按钮 | 恢复独立会话的默认顺序？ |

- 确认框正文：“将按创建时间重新排列，新建的在前。手动调整的顺序无法找回。”确认按钮为“恢复默认”，不使用危险样式。
- 请求期间确认按钮显示进行中并禁用；成功后关闭确认框，列表刷新；失败时确认框保留并显示错误。
- 入口只在活动视图显示，未连接或有操作在进行时禁用。

## 五、分页与加载

| 状态 | 展示 |
| --- | --- |
| 列表还有更多 | 项目列表、项目内会话和独立会话使用相同的整行“加载更多”按钮。文字颜色稍淡，与各自列表名称左对齐，行高和悬停样式沿用列表 |
| 正在加载更多 | 按钮文字变为“加载中…”并禁用 |
| 加载更多失败 | 按钮下方显示“加载失败”，按钮恢复可点 |
| 展开一个尚未加载的项目 | 展开区域显示两行骨架占位，加载完成后替换 |
| 分组已加载且没有会话 | 显示一行弱化文字“暂无会话” |
| 项目处于折叠状态 | 不加载、不显示任何会话相关内容 |
| 整个侧栏没有任何项目和会话 | 沿用现有的“暂无会话” |

- 已置顶的会话沿现有规则不在分组里显示。一个分组已加载的会话全部被置顶时，分组内只显示“加载更多”或什么都不显示，不显示“暂无会话”。
- 刷新和重连后保持各分组已加载的条数和滚动位置，不回到第一页。

## 六、选中的会话不在已加载页

- 侧栏不为它插入行，也不高亮任何行；对话区照常显示该会话。
- 不自动展开项目、不自动加载或滚动去寻找它。用户自己加载到包含它的那一页时，该行按正常规则高亮。
- 选中的会话已置顶时，置顶区中的行照常高亮。

## 七、其他入口

- **搜索对话框**：列表按创建时间新建在前，行不可拖动，其余不变。
- **移除项目确认框**：去掉“已有 N 个会话会一并从侧栏隐藏”中的数量，改为“该项目的会话会一并从侧栏隐藏，重新添加此目录后恢复显示。”
- **新建会话时选择项目**：选项顺序与侧栏项目列表一致。

## 八、动效与适配

- 同一列表中已有条目的相对顺序变化时，行移到新位置使用 120ms 的位移过渡。展开、收起和续页引起的布局变化不触发排序动画。系统开启“减少动态效果”时跳过位移过渡。
- 触控设备上行的操作按钮保持常显（现有规则），长按拖动不与点击打开会话冲突。
- 侧栏宽度不因拖动改变，拖动的行不超出侧栏范围。
- 深色、浅色及各配色主题下，插入横线使用主题强调色，占位使用现有悬停底色。

## 九、验收口径

- 点击行仍然打开会话；只有移动超过阈值才进入拖动，行内按钮不触发拖动。
- 四种范围内的拖动都有插入横线，移出范围时横线消失且松手不生效。
- 拖动项目时其会话列表收起，松手后恢复。
- 松手后行立即到位；失败时回到原位并有提示。
- 每个分组独立显示“加载更多”、加载中、失败、空分组和未加载占位，互不影响。
- 三个恢复默认入口都经过确认框，确认框文案与本文一致。
- 归档视图和搜索对话框中的行不可拖动。
- 选中的会话不在已加载页时侧栏没有高亮，也没有被追加的行。
- Desktop macOS、Windows 和 Host Web 上表现一致；触控长按拖动在 Host Web 移动端可用。
