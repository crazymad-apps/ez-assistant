## 二、目标与范围

用户可以在消息气泡下方复制自己的输入，或载入底部 Composer 修改后重新发送。提交后仍在同一会话内，保留该条之前的历史，用修改后的输入重新开始执行，原目标消息及其后续历史不再属于当前会话历史。

本 Feature 覆盖正式 Desktop 与 Host Web，使用同一 Runtime 业务规则，包含复制、完整输入编辑、取消、可靠裁尾重发及正文／缩略导航刷新。

本期编辑范围：**正文、附件、引用、显式 Skill／MCP 选择及输入变体**。初始完整载入原输入，允许增删／替换；未修改内容保留原事实。普通草稿暂存，取消或确认提交成功后恢复。上方“取消”紧邻“返回原位置”，提交复用现有发送按钮。

2026-11-11 用户确认同步收敛输入存储：已进入可靠历史的输入、幂等键及 Run 历史以会话文件为唯一来源；数据库只保留暂存输入和未完成执行控制。裁尾和分支复制不再维护另一份 SQL 历史身份；旧数据迁移、交接恢复及重试纳入 F02，见[技术方案](技术方案.md) 2.1、5.5 和第八节。

本期不增加助手消息编辑、历史分支切换、撤销裁尾、自动备份会话、外部文件回滚或运行中强制改写；介入及队列项转换归 F03，列表排序归 F04。

## 四、用户路径

### 4.1 复制与编辑入口

1. 鼠标进入用户消息区域，或键盘焦点进入操作区时，在气泡下方显示操作 icon；当前会话有活动 Run 时，所有用户消息只显示复制，隐藏编辑按钮。Run 结束后按编辑资格恢复入口；键盘及无 hover 设备遵守同一规则。指针移到按钮期间保持可操作，显隐不改变消息布局。
2. 样式与现有 assistant message turn 下方的[工具栏](../../../../../apps/desktop/src/features/conversation/ConversationView/ProcessingTurn/index.tsx)一致，复用其图标与按钮尺寸、间距、颜色、圆角、hover 和禁用样式。按钮只显示 icon，“复制”“编辑”用作操作提示与可访问名称；键盘及无 hover 设备仍可通过聚焦／点选访问。这一视觉基线已按用户 2026-11-10 的补充确定。
3. 复制取当前已提交用户消息的正文文本，保留换行，不拼入时间、来源标签、附件路径、引用原文或隐藏指令。编辑稿尚未提交时不替换复制内容。
4. 复制成功／失败沿现有轻量反馈；无正文的附件／引用输入不写入空剪贴板，显示不可复制文本的原因。
5. 可读的继承、归档及只读内容仍允许复制。编辑资格独立判断，不因复制可用而允许裁尾。

### 4.2 打开编辑与草稿

- 查询成功后，将原正文、附件、引用、Skill／MCP 及变体载入底部 Composer；原消息高亮，阅读位置保持。编辑期间可继续阅读历史，不预先隐藏尾段。
- 输入框外侧上方以现有附属抽屉样式展示编辑栏，仅保留“正在编辑历史消息”和相邻的“返回原位置”“取消”，去掉下方描述文字；返回只定位原消息，取消退出编辑。
- 编辑期间隐藏 Todo、Goal、队列等附属区域及浮层，不留占位；编辑稿的附件、引用和选择器保留。退出后按最新数据恢复有效的抽屉展开状态，不改变业务状态。新出现的审批／问答沿用现有工作区优先级，保留编辑稿，处理结束后重新核对编辑资格。
- 使用现有发送 icon 提交，提示／可访问名称为“发送修改”，不增加“保存并重新运行”按钮。Enter 同样提交编辑，Shift + Enter 换行，输入法确认不提交；Ctrl + Enter 不提交，编辑模式不走普通队列或介入。
- 普通草稿的正文、附件、引用、Skill／MCP、变体和 Goal 标记暂存；编辑修改只作用于历史编辑稿。取消或确认接纳成功后恢复普通草稿，明确失败时保留编辑稿；已发送但刷新失败仅重试读取。
- 同时仅保留一份活动编辑稿。切换会话可挂起；更换编辑目标或退出身份前处理未保存内容。草稿只保存在内存，普通断线不丢失。
- 提交及结果未知期间禁用取消和重复发送，先核实接纳结果。仅打开、修改和取消均不改变历史；取消只释放编辑新增的临时资源，不删除原输入及普通草稿资源。
- 会话控制命令和 Goal 创建入口不参与编辑提交；模型、工具授权等会话设置仍按当前配置执行。

### 4.3 提交与新一轮

提交时再次由 Runtime 核对会话、目标、当前历史及附属输入，而非仅依赖按钮打开时的状态。一次提交对应一次意图；提交中禁用重复发送，正文保留到可靠结果明确。

例如原历史为：

```text
用户 A → Run A → 用户 B → Run B → 用户 C → Run C
```

编辑 B 并提交为 B′ 后：

```text
用户 A → Run A → 用户 B′ → 新 Run
```

- 会话身份保持不变；原 B、Run B、C、Run C 从当前历史移除。目标是最后一条消息、尚无助手正文或相邻存在多条用户输入时，仍按目标消息的实际位置裁尾。
- B′ 是新用户消息，拥有新的 Input 与 Run 身份；不能原地篡改已完成 Run 的输入或把旧回复重新挂到 B′。
- 新轮读取保留下来的前文与 B′，不继续使用已删除尾段构造的执行上下文；已有摘要、压缩及工具调用／结果配对按现有重建规则保持合法。
- 新轮在可靠接纳后按既有调度执行。后续模型失败、工具失败或用户停止不恢复旧尾段，也不把此次编辑标为“未提交”。
- 空白文本与普通输入采用相同有效性原则：至少有非空文本、有效附件或引用之一；仅 Skill／MCP 标签不构成有效输入。纯空拒绝且保留编辑稿。
- 原输入有效且会话可编辑时，可以不改正文或附属项直接重发。原样重发沿同一编辑提交入口裁尾并启动新一轮。

## 五、附属信息与执行设置

初始载入原输入；用户可以移除或替换附属内容。保留项在新 Input 下具有完整内容和正确归属，新增项按普通输入规则接纳。

| 内容 | 本期规则 |
| --- | --- |
| 文本 | 使用用户修改后的完整正文，沿普通输入的大小及合法性约束校验 |
| 附件／图片 | 原附件按已上传项载入，允许移除／新增／替换；发送最终有序列表。保留项无需重传，新项沿现有上传流程；保留的不可用项阻止提交 |
| 引用 | 允许移除及重新引用，保留项沿用冻结原文、来源和顺序；不直接编辑引文。来源不可定位时仍保留原文并显示来源不可用 |
| 用户显式 Skill | 未改动时保留原冻结内容；移除后不附带；主动选择时按当前 Skill 内容冻结，包括重新选择同名项。新输入形成新的激活归属 |
| 用户显式 MCP 选择 | 未改动时保留原 key／冻结名称；允许移除或重新选择，实际执行仍受当前连接、可用性及权限约束 |
| Agent 变体 | 默认原输入变体，允许在编辑草稿中调整；不因编辑选择而改写普通草稿或 Session 默认变体 |
| 模型、工具授权与会话配置 | 新 Run 按当前有效配置装配，不恢复旧凭据、旧授权或已失效的执行连接；必要配置无法成立时按现有接纳／执行边界报告真实失败 |
| Run 过程与来源 | 不保留旧 Run 的中间 Step、模型临时激活、审批答案或工具结果作为新输入附件；新输入来源按本次编辑发起路径记录，不伪装成原设备／外部系统重发 |

原输入无法完整还原时不进入编辑，允许复制。能够识别但当前不可用的附件或选择保留提示，用户可移除或替换；提交校验最终保留的内容，失败时保留编辑稿，校验通过前不裁尾。

## 六、可编辑范围与运行门禁

| 当前条件 | 行为 |
| --- | --- |
| 当前可写会话中有可靠 Input 归属的真实用户输入 | 满足空闲与其他门禁后允许编辑；是否有助手回复不影响资格 |
| 继承消息、外部转达／会话报告、隐藏输入、只读 child 历史 | 不提供可用的编辑入口；继承标记仍参与判定，不恢复重复“继承”标签 |
| 归档会话、无当前操作权限、来源身份无法确认 | 保留可读及复制能力，编辑不可用；不自动恢复归档或切换身份 |
| 有活动／未终结 Run、排队输入或命令、待处理反馈、压缩等非空闲状态 | 有活动 Run 时隐藏全部用户消息的编辑按钮，复制保留；其他非空闲限制沿用禁用提示。编辑提交不可用，不代为停止 Run、清队列或完成反馈。已打开编辑后发生这些变化时保留稿件并提示原因 |
| 有未结算子任务或交换关系，可能继续写入受影响历史 | 不允许裁尾；技术方案核对既有完整空闲判定和关联生命周期，不能只看聊天页是否停止流式输出 |
| 目标处于当前 Goal objective 或之前 | 沿用既有拒绝规则，说明需由用户另行停止并清除 Goal；编辑入口不自动代办 |
| Goal 存在，目标在 objective 之后，且其他条件满足 | Goal 已暂停时，编辑后的真实输入领取启动即自动恢复同一 Goal，按修正内容继续；无需额外恢复操作。运行中仍不隐式停止或裁尾，不直接修改 objective 或认定完成 |
| 编辑期间历史追加、裁尾、目标变化或会话归属变化 | 拒绝基于旧历史直接提交，保留稿件并提示重新核对；不能让用户未看过的新尾段被静默丢弃 |

客户端展示可用性，Runtime 在真实提交边界重新验证并处理竞争。失效的目标不按文本相似度或列表位置重新绑定；仅预览缓存存在也不构成可编辑的完整输入。

历史编辑保留既有 objective 和空闲门禁。公共输入机制同步调整：Goal Running／自动续跑期间普通队列等待，Paused 时按正常顺序及运行门禁领取，实际领取的新输入恢复同一 Goal；仅入队不提前恢复，剩余普通队列不被顺带消费。F03 介入在 Step 结束后优先接续并延续 Goal，仍属于独立的介入功能。本次不改变 F01 分页或缩略配对，也不增加 Goal 归并机制。

## 七、可靠提交与失败恢复

| 结果 | 用户可见行为与允许的后续操作 |
| --- | --- |
| 提交前明确校验失败 | 原历史不变，保留编辑稿和附属信息，指出目标失效、非空闲、资源不可用等具体原因 |
| 已明确可靠提交 | 退出编辑，展示新用户消息和新 Run，按新代次刷新；接纳成功不等于 Run 执行成功 |
| 请求超时、断线或回执丢失，提交结果未知 | 显示“正在确认发送结果”；保留本次提交身份并通过既有幂等机制与权威快照核实，不创建新意图盲目重发。无法核实时保留待确认状态和稿件 |
| 已提交，但页面读取或刷新失败 | 明确提示已发送、展示刷新重试；重试只恢复读取，不再次裁尾或创建新 Run |
| 断线重连或 Host 重启 | 以可靠历史及 Input／Run 结果收敛；相同意图至多接纳一次。客户端不能凭本地 loading 消失或旧消息仍可见认定提交失败 |
| 用户切换 Host、组织、账号或会话 | 旧请求不能写入当前展示或跨身份重试；核实结果始终绑定原意图归属，不混用另一连接的同名资源 |

继承现有历史改写的可靠边界：新的正文、输入、Run 及必需附属信息一致提交，读取只能确认旧历史或已提交的新历史，不能暴露“尾段已删但新输入没有接纳”的半成品。具体幂等查证、客户端重开后的恢复入口和必要契约补足由技术方案落实；不得以测试中网络始终正常代替恢复设计。

## 八、裁尾后的阅读与资源

- 成功后按同一 owner 的新历史代次更新正文页、缩略 ID 列表、预览、定位、处理过程、卡片和子任务投影。被删除目标的旧消息 ID 与助手 ID 均不得继续使用。
- 缩略列表为 B′ 形成新条目；新 Run 没有最后一段正文时只有用户输入，后续按 F01 规则更新可选助手正文，不使用旧 Run B 的回复或新 Run 的中间 Step 补位。
- 当前客户端定位到替换后的新用户消息并进入新轮展示，恢复底部普通草稿；正文读取沿 F01 连续历史、按序补齐的规则，无“加载后续消息”入口。
- 其他正在阅读同一会话的客户端也要失效旧代次；原阅读锚点仍存在时尽量保持位置，锚点被删则提示历史已更新并回到有效位置，不能持续展示已不存在的尾段。
- 在途旧翻页、预览、定位与卡片请求不得把旧代次内容回填。取消编辑、提交前失败则保留原阅读窗口和导航，不冒充成功触发裁尾刷新。
- 只移除当前历史不再拥有的尾段关联；前缀与新输入仍引用的附件、引用内容和必要资源必须可用。会话资源、工具输出文件、子任务和卡片按既有所有权清理，不新增全局垃圾回收机制，不删除其他会话或分支仍持有的内容。
- 编辑仅改变会话历史及其上下文，不回滚已执行的文件写入、Shell 命令、远程请求等外部效果，不能以旧工具过程不再可见宣称外部操作已撤销。
- 保持原会话、项目归属与创建时间。F04 的手动顺序不因编辑重发变更；本 Feature 不改侧栏现有排序实现。
