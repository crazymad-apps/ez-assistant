## 二、台账原则

- 按“存储 → 公共领取 → 编辑后端 → 界面 → 联合验收”串行推进。每步形成可验证的完整结果，完成后标记 `🟨 待确认`，用户确认后才进入下一步。
- 优先复用现有历史索引、提交回执、重入、抽屉及草稿能力；不引入第二份历史、独立索引文件或临时兼容路径。细节以技术方案为准。
- 测试与迁移演练使用 `.runtime-test/` 下新建并核实无用户数据的隔离环境；开发新迁移不授权升级用户数据库。真实数据操作另按仓库数据库规则核对、备份及确认。
- 计划只维护里程碑状态、确认和必要遗留；恢复信息写入本地开发进度，不另建验证报告。不得覆盖其他 Feature 的既有改动，不自动提交、推送或发布。

## 四、里程碑实施与完成判定

### M0 输入历史单一来源与迁移

**目标／前置**：计划及 F01 验收确认后，普通输入、命令和历史操作均可脱离已完成 SQL 身份行工作。

**交付范围**：

- 完成文件输入／键的保存、可靠发布交接、终结后控制清理，以及文件中的接纳结果回读；正式 Store 与 Volatile 采用同一语义。已有历史重入、重试、分支、压缩、清空和启动恢复一并改用对应事实来源。
- 将键映射并入已有有界内存索引，覆盖冷建、可靠追加、换代及淘汰后重建；普通发送和历史读取不重复扫描或复制整份历史。
- 按技术方案第八节接通启动迁移、配套备份／恢复和旧 Host 准入；数据库目标／最低 Host 升为 0.33.1，历史格式升为 2。软件版本保持 0.33.1，F01 既有验收记录不改写。

**验证入口**：扩展 [Host 历史文件测试](../../../../../apps/runtime-host/src/storage/tests/history_files.rs)、[输入身份测试](../../../../../apps/runtime-host/src/storage/tests/input_identity.rs)、[迁移测试](../../../../../apps/runtime-host/src/storage/migrations/tests.rs)及 Volatile、Runtime 历史重试测试，执行本节末 Rust 门禁和协议／版本配套检查。覆盖暂存、已领取未发布、活动 Run、零输出失败／取消、命令及继承历史；在文件同步、事务发布及清理边界注入故障，验证重开和配套恢复。迁移后经正式查询回归 F01 分页／导航，并核对长历史冷读、热命中及额外磁盘需求。

**完成判定**：F02-13 的存储与迁移要求通过；已完成输入无需 SQL 身份行仍可读取、去重及合法重试，未完成工作可恢复，分支不继承请求键或执行控制。旧新配套拒绝正确，迁移失败可恢复完整旧状态或可靠新状态，无常态双读／双写。

**Review 重点**：可靠发布边界与控制清理时机；缓存未命中不能当作未提交；仍有依赖的行不能提前删除；备份覆盖数据库与关联文件，继承身份和命令顺序不误映射。

### M1 公共输入领取与 Goal 延续

**目标／前置**：M0 确认后，先通过普通输入验证技术方案 5.4 的公共领取规则，再供编辑及 F03 复用。

**交付范围**：

- 修正 Goal Running／Paused 下的队列选择、阻塞投影及暂停／恢复条件；自动续跑保留普通队列，Paused 按正常机制领取。
- 将 Goal 上下文准备、恢复及输入绑定落实到实际领取的可靠边界；正式 Store 与 Volatile 同步，重复唤醒和重试不重复恢复。
- 普通 Composer 发送使用正常输入入口，不再依赖暂停快照自动切换为 `resume_goal`；保留显式 Goal 控制和真正的暂停／恢复门禁。

**验证入口**：扩展 [Goal 输入测试](../../../../../crates/assistant-runtime/src/runtime/tests/goal_input.rs)、[输入测试](../../../../../crates/assistant-runtime/src/runtime/tests/input.rs)、[领取测试](../../../../../apps/runtime-host/src/storage/tests/queue_claim.rs)及 Composer 测试。覆盖自动续跑与新输入竞争、预编译失败、显式队列暂停、审批／反馈、重启及重复领取；执行相关 Rust 门禁、前端定向测试和构建。

**完成判定**：F02-08 的普通输入路径通过；仅接纳／等待不恢复 Goal，实际领取恢复同一目标且其他队列项保留。Goal 已完成或清除时不重开，普通输入可通过正式 Desktop／Web 入口验证。

**Review 重点**：普通队列、Goal 续跑及实际领取的职责没有混用；恢复与新 Run 同一可靠边界；不预先实现 F03 介入意图、优先级或 Step 结算。

### M2 完整输入编辑后端

**目标／前置**：M1 确认后，通过正式命令完成“准备完整输入 → 校验 → 裁尾 → 启动新轮”的闭环。

**交付范围**：

- 接通编辑准备查询及完整重入请求，统一资格检查、历史前置条件和原输入解析；同步 Rust／TS、HTTP 分发、代理准入及所有调用方。编辑 capability 在 M3 完整链路接通后开启。
- 完成正文、附件、引用、Skill／MCP 与变体的保留／增删／替换和预编译；重入沿 M0 文件事实与 M1 领取规则提交，维护资源、引用定位及子任务关系。
- 打通可靠结果回读、内存安装与事件发布；分别处理拒绝、未知结果、接纳后刷新／执行失败。正式 Store 与 Volatile 的输出和拒绝条件一致。

**验证入口**：扩展 [Runtime 会话管理测试](../../../../../crates/assistant-runtime/src/runtime/tests/session_management.rs)、[输入选择测试](../../../../../apps/runtime-host/src/storage/tests/input_selections.rs)及重入／协议／HTTP 测试，执行相关 Rust 门禁和协议生成检查。覆盖首中末条、连续用户／无回复、仅附属输入变化、冻结选择与重选同名项、来源与 Goal 边界；验证同代追加／换代竞争、回执丢失、同键重投、裁尾后重投及文件／事务／内存／唤醒故障。

**完成判定**：F02-04～10、12 的后端要求通过；预编译失败保留旧历史，接纳后只产生一份新输入与首次 Run，历史变化不能被静默覆盖，已接纳重试不再裁尾或恢复 Goal。保留资源可用，其他会话／分支不受影响。

**Review 重点**：幂等回读先于首次提交资格；expected 使用可靠完整历史计数；冻结内容不由客户端伪造；提交后错误不伪装成未接纳；旧客户端不能绕过新请求要求。

### M3 消息操作与编辑界面

**目标／前置**：M2 确认后，将后端能力接入正式 Desktop 与 Host Web。

**交付范围**：

- 实现用户消息复制／编辑操作栏，与 assistant turn 样式一致；当前会话有活动 Run 时所有用户消息隐藏编辑、保留复制。
- 复用底部 Composer 完整编辑及双草稿隔离。上方编辑抽屉仅有标题与返回／取消；编辑时隐藏其他附属区域，退出后恢复有效状态，审批／问答保持现有优先级。发送、快捷键、焦点和上传归属按交互指导执行。
- 接通取消、失败保稿、未知结果核实、接纳后普通草稿恢复，以及正文／缩略／预览／卡片／子任务刷新；返回原位置及新消息定位沿 F01 顺序补齐。完整链路验证后开启编辑 capability。

**验证入口**：扩展 [Composer 测试](../../../../../apps/desktop/tests/unit/composer-dock.test.tsx)、[会话视图测试](../../../../../apps/desktop/tests/unit/conversation-view.test.tsx)、生命周期及导航测试，执行前端 lint、定向测试和正式构建。使用真实 Host 验证编辑与新轮，覆盖身份／会话切换、上传迟到、历史变化、断线核实、Run 状态变化及草稿恢复；在 Host Web 和可用原生平台核对抽屉、窄窗、主题、剪贴板、IME、键盘与触摸。

**完成判定**：F02-01～03、05、06 及 07～11 的界面要求通过；复制不受运行影响，编辑稿和普通草稿不串状态，不误入队列／介入，旧历史与迟到响应不回填。编辑抽屉没有描述段落，其他抽屉隐藏不改变业务状态。

**Review 重点**：客户端只持有草稿与投影；取消请求不等于取消提交；未知结果不生成新意图，接纳后失败只恢复读取／执行；保留已有阅读位置和资源归属。

### M4 F02 独立验收

**目标／前置**：M3 确认后，收口 F02-01～13 及与 F01 的联合行为。

**交付范围与验证入口**：复用 M0～M3 已有效的验证，只补最终候选的受影响检查与组合场景：旧格式隔离迁移后编辑、长历史编辑并重新定位、未知结果期间 Host 重启、跨客户端追加与裁尾、暂停 Goal 编辑后实际领取、分支／资源保护。核对冷索引重建与热路径成本，确认存储调整没有增加分页／预览扫描或全局启动扫描。同步长期模块约束、用户操作文档和 Feature／版本台账。

Host Web、macOS 和 Windows 原生覆盖分别记录；未测平台或受限场景明确列为待验收项，不能以浏览器结果代替。原生构建与运行串行使用产物；本步骤不默认打包或发布，若用户要求测试包则沿已有本地打包流程。

**完成判定**：功能验收点全部满足，或用户明确接受剩余限制且文档同步；迁移／恢复、权限及历史完整性问题已解决。用户确认 M4 后，F02 才标记完成；v0.33.1 仍需 F03、F04 和版本整体验收。

**Review 重点**：没有用 UI 隐藏代替真实裁尾，没有将未来 F03 联合场景计为通过；实际存储格式、能力准入、错误反馈和计划一致。
