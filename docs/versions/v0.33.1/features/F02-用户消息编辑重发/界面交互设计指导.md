## 二、消息操作栏

用户消息下方采用现有 [assistant turn 工具栏](../../../../../apps/desktop/src/features/conversation/ConversationView/ProcessingTurn/index.tsx)及其[样式](../../../../../apps/desktop/src/features/conversation/ConversationView/index.module.scss)，排列为“复制 icon、编辑 icon、时间”，整体与用户消息右边缘对齐。来源、附件及 Skill／MCP 展示保持原位置。

- 复用现有小号按钮、15px 图标、2px 按钮间距、圆角、颜色和 hover／禁用样式；工具栏预留高度，按钮显隐不移动正文或时间。
- 鼠标在消息与工具栏联合区域内，或焦点进入操作区时显示按钮；移向按钮不消失。无 hover 设备直接显示操作，不要求先长按或选中文字。当前会话有活动 Run 时，所有用户消息只显示复制，编辑按钮不渲染、不进入焦点顺序；Run 结束后按资格恢复入口。
- 提示与可访问名称分别为“复制用户消息”“编辑用户消息”。复制只取已提交正文，成功显示“已复制”，失败显示“复制失败，请重试”；附件／引用输入无正文时提示“这条消息没有可复制的文本”。
- 活动 Run 的隐藏规则优先；无活动 Run 时，继承、归档、只读或其他已知非空闲状态下，编辑不可用并提示对应原因，禁用原因可通过键盘访问。不增加常驻“继承”标签。Host 不支持编辑时提示“当前 Host 不支持消息编辑”。
- hover 不读取完整输入。点击编辑才查询资格与原输入，编辑按钮局部显示忙碌并防重复点击；失败就地反馈，普通草稿及正文保持。查询成功时挂起当时最新的普通草稿，再进入编辑。

## 三、底部 Composer 布局

沿用现有 [ComposerDock](../../../../../apps/desktop/src/features/composer/ComposerDock/index.tsx)。编辑期间隐藏 Todo 摘要、Goal、队列等附属区域及其浮层，不留占位；输入框外侧上方展示编辑抽屉，与输入区衔接。抽屉仅保留“正在编辑历史消息”和“返回原位置／取消”；编辑稿的附件、引用、选择器和底栏保持可用。

```text
  ┌────────────────────────────────────────────────┐
  │ 正在编辑历史消息           返回原位置   取消    │
┌─┴────────────────────────────────────────────────┴─┐
│ 原附件／引用、Skill／MCP 选择                       │
│ 可编辑的完整输入正文                               │
│                                                    │
│ ＋   执行设置                  模型设置    原发送 icon│
└────────────────────────────────────────────────────┘
```

- 编辑抽屉复用现有 [ComposerSecondaryDrawer](../../../../../apps/desktop/src/features/composer/ComposerDock/ComposerSecondaryDrawer.tsx)的外壳、标题栏样式及与输入框的圆角接缝；左侧标题，右侧“返回原位置”“取消”相邻。仅有标题栏，无展开内容或折叠箭头，不显示描述段落。
- 隐藏仅控制展示，保留原抽屉展开状态，继续接收业务更新；退出编辑时按最新数据恢复仍有效的展开项。隐藏不发送暂停、清空或取消命令；其他会话保持普通布局。
- 审批／问答仍按现有优先级占用输入区，保留编辑稿，处理结束后可继续编辑并重新核对资格；既有待处理入口保持可达。
- 原发送 icon 是唯一提交入口，Tooltip／可访问名称改为“发送修改”；位置、尺寸与主色保持。不增加“保存并重新运行”按钮。
- 原消息在整个编辑期间使用主题色边框、内描边及加深的气泡底色，不改变气泡尺寸，也不预先隐藏后续历史。
- 窄窗中标题自然换行，两项操作整体换到下一行且相邻；不横向溢出或藏入更多菜单。输入区继续使用已有高度上限及内部滚动，长正文不撑满窗口。
- 错误使用现有语义色及文字，四套主题、缩放和减少动态效果设置保持可用。对外文案不展示 Input ID、幂等键、代次或 SQL 等内部概念。

## 四、操作与草稿

### 4.1 进入与修改

查询成功后完整载入正文、附件、引用、显式 Skill／MCP 及原变体。普通草稿的正文、附属内容、变体和 Goal 标记同时挂起。聚焦底部输入框，光标置于正文末尾；使用不滚动页面的聚焦方式，原阅读位置保持。

| 内容 | 编辑方式 |
| --- | --- |
| 正文 | 原输入框直接修改，或保留全部原内容直接重发 |
| 附件／图片 | 原项按已上传状态显示，可移除或新增；新增上传失败只标记该项并提供原重试／移除操作，不重复上传原附件 |
| 引用 | 保留原文及来源，可移除或重新引用；不在引用卡片内编辑冻结原文。来源无法定位时仍能阅读引文 |
| Skill／MCP | 沿用现有标签和选择器，支持移除／重新选择；未改动项保留原冻结内容，主动重选同名项按当前定义使用 |
| 变体 | 沿用执行设置入口，编辑期间只修改当前编辑稿的变体，不改 Session 默认值或挂起的普通草稿 |
| 模型、权限等会话设置 | 展示和使用当前会话配置，继续沿用原权限和可用性限制，不恢复历史配置 |

可识别但不可用的保留项展示原因，允许移除或替换；最终输入中仍包含不可用项时不能发送。仅改变附件、引用、选择或变体也可构成修改；至少包含正文、有效附件或引用之一。新增上传和选择回调只作用于所属草稿。

编辑模式停用会话控制指令及 Goal 创建入口；以 `/` 开头的历史正文仍按编辑文本处理。发送按钮不会因其他客户端开始运行而变成停止按钮；此时提示会话非空闲并禁用编辑提交。取消编辑后恢复普通运行控制，审批／问答按上述优先级展示。

### 4.2 返回、取消与切换

- **返回原位置**：定位正在编辑的用户消息，保持编辑模式和稿件；未加载时按 F01 顺序补齐，提示“正在定位…”，失败可重试。不跳到最新消息，不增加“加载后续消息”。
- **取消**：退出编辑，恢复完整普通草稿及有效的抽屉展开状态；无审批／问答占用时焦点回到普通输入框，正文阅读位置保持。只释放编辑新增的临时选择，不改历史，不再增加二次确认。
- **再次编辑同一条**：保留当前编辑稿并聚焦输入框，不重新载入覆盖修改。
- **更换编辑目标**：无修改时直接切换；有修改时复用现有 Dialog，提供“继续当前编辑”“放弃修改并切换”，确认后才替换稿件。已挂起编辑的目标切换遵守同一规则。
- **切换会话**：挂起编辑，返回原会话可继续；其他会话不显示或提交该稿件。断线保留内存稿件，关闭／刷新后不承诺恢复。身份或 Host 切换停止旧请求自动重投，旧回调不能写入新界面。

### 4.3 键盘与焦点

| 操作 | 编辑模式行为 |
| --- | --- |
| Enter／点击原发送按钮 | 校验并提交同一次历史编辑，不走普通队列 |
| Shift + Enter | 换行 |
| Ctrl + Enter | 不提交；F03 介入只用于普通模式 |
| 输入法确认 Enter | 只确认输入，不发送 |
| Escape | 优先关闭附件／选择器浮层，不清空或退出编辑 |
| Tab | 可访问消息操作、返回／取消、附属项、设置及发送；焦点轮廓沿用现有样式 |

返回定位不抢走操作按钮焦点；加载、发送和结果通知使用已有 status／alert 机制，避免反复播报整段正文。

## 五、提交状态与反馈

| 情况 | 提示及允许操作 |
| --- | --- |
| 正在提交／上传新增附件 | 提示“正在发送修改…”；稿件冻结，禁用重复发送、取消及目标切换。正文仍可阅读 |
| 明确校验失败 | 显示具体原因，保留完整编辑稿并恢复可编辑状态；原历史不变 |
| 会话出现运行或队列 | 提示“会话当前无法编辑历史消息”；保留稿件，允许取消，不代为停止或清队列；恢复空闲后重新核对资格 |
| 新增待处理审批／问答 | 沿用现有处理工作区，保留普通及编辑草稿，编辑提交不可用；处理结束后恢复编辑展示，重新核对资格 |
| 历史被追加或改写 | 提示“历史已更新，请重新核对后发送”；保留稿件，禁用提交。用户查看最新历史并点击“重新核对”后刷新资格与依据，不覆盖稿件、不自动重发 |
| 原目标被删除／变成不可编辑 | 说明目标不可用，保留稿件供复制或取消；不按相似文本或位置换绑另一条消息 |
| 断线／超时，发送结果未知 | 提示“发送结果尚未确认”；冻结稿件及发送意图。重连后按技术方案确认一次，仍未知时提供“重试原发送”，明确继续同一次发送；取消和新提交保持禁用 |
| 已接纳，读取新历史失败 | 退出编辑、恢复普通草稿；提示“修改已发送，消息刷新失败”，提供“重新读取”，不重发修改 |
| 已接纳，启动或执行失败 | 新消息与真实错误保持，普通草稿已恢复；后续沿正常执行恢复处理，不恢复原尾段或返回可重发的编辑状态 |
| 正常接纳并刷新 | 退出编辑、恢复普通草稿，定位新用户消息并展示新轮；不额外弹成功确认框 |

确认接纳后退出编辑，同取消一样恢复仍有效的抽屉展开状态。用户主动“重新核对”才可取得新的历史依据；发送结果未知时不能改成新请求绕过确认。网络请求取消不等于服务器取消编辑，这一区别由状态和按钮可用性表达。

## 六、阅读、导航与 Goal 衔接

- 编辑打开、输入或取消时，正文与缩略仍展示已提交历史。点击其他缩略、查阅引用或返回原位置不会改变编辑目标。
- 提交成功后统一刷新正文、缩略、预览、卡片及子任务；旧尾段和迟到响应不能重新出现。新缩略条目为新用户输入及紧跟 Run 的可选最后一段正文，未生成时保留用户单项。
- 发起端按序定位到新用户消息；其他客户端保留有效阅读锚点，被删时提示“历史已更新”并回到有效位置。恢复普通草稿不覆盖并行到达的输入资源。
- 不增加 Goal 恢复开关。合法编辑的真实输入实际启动时自然延续当前 Goal；仅打开编辑或等待发送不提前恢复，受限目标说明原因，不代为停止／清除 Goal。
- 普通模式的 Enter 排队语义保持，F03 后续负责 Ctrl + Enter 和队列项转换。编辑成功或取消后恢复原普通输入行为。

| 返回定位、取消、换目标、换会话、关闭及断线符合稿件生命周期；隐藏不改变业务状态，审批／问答可处理，权限／非空闲／Goal 门禁准确 | F02-03、07、08 |
