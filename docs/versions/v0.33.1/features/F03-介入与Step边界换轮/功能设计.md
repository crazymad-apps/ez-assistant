# v0.33.1 F03 功能设计：介入与运行打断

## 一、设计信息

- 日期：2026-11-12。状态：**已确认**。2026-11-12 用户回复“确认并编计划”。
- 依据：[总体设计 5.5](../../总体设计.md#55-enter介入与队列操作)、[版本总计划](../../开发计划.md#f03-介入与运行打断)。F01、F02 已独立验收。
- 范围：Desktop／Host Web 输入入口、Runtime 介入命令、Core 终止输出保留。发送沿用普通队列路径。

## 二、目标与范围

介入以新用户消息引导当前任务：让正在运行的 Run 立即停下，保存它已输出的 reasoning／正文和实际工具结果，再由新 Run 结合原上下文继续。

介入不是一套新的发送流程，而是两个已有动作的组合：

```text
把这条用户消息放到队首（普通接纳，再执行队列现有的“优先”）
→ 取消当前 Run
```

之后的事情全部由现有队列驱动完成：旧 Run 结算落盘后，驱动领取队首，写入用户消息并启动新 Run。发送代码只有一套。

本期包含介入提交、普通队列项转介入、终止输出留存。介入消息被领取后即写入会话文件，作为真实用户消息展示，**不提供撤回**；尚未被领取时它是普通队列项，可按队列原有方式移除。历史编辑沿 F02 的资格检查，不扩展为运行中编辑。

## 三、介入行为

### 3.1 入口与完整输入

| 操作 | 行为 |
| --- | --- |
| Enter／点击发送 | 普通队列输入 |
| Ctrl + Enter；macOS 兼容 Command + Enter | 提交介入 |
| 普通队列项“介入” | 复用原 Input、正文、附件、引用、Skill／MCP 和变体，进入同一介入命令 |
| 显式停止 | 沿现有规则停止执行并暂停接续；已持久化用户消息保留 |

Shift + Enter 换行，IME 确认候选不发送。macOS 提示 Command + Enter，其他平台提示 Ctrl + Enter。历史编辑模式、Slash 和专用问答沿原入口；归档、只读、无权限或 Host 不支持时不接纳介入，不静默降级为普通队列。

介入只决定“何时发”，不改变这条输入“发什么”：队列项原有的输入类型和全部载荷保持。

### 3.2 一次阻塞命令

```text
提交介入命令，界面等待结果
→ 按输入幂等键查重，再做预检
→ 普通接纳后“优先”到队首（队列项介入直接“优先”原条目）
→ 有活动 Run 则请求取消
→ 驱动结算旧 Run 并落盘，领取队首，写入用户消息、启动新 Run
→ 命令返回已持久化的用户消息及新 Run，界面直接展示
```

- **发送复用普通路径**：接纳、领取、写入用户消息和启动 Run 都是普通发送的同一套代码，介入只多了队列现有的“优先”和“取消当前 Run”。
- **不区分旧 Run 如何结束**：被取消、恰好自己完成或失败，驱动都按真实终态结算后领取队首。没有活动 Run 时无需取消，驱动直接领取。
- **旧输出落盘先于新消息发送**：这是驱动原有的顺序，落盘失败时驱动停止，新消息不会被发送。
- **待回答问题一并打断**：Run 内的审批、工具内等待和 child 随取消清理；仍待回答的问题直接作废。介入不被“请先回复当前问题”拦截，也不把介入正文当作答案。
- 新 Run 启动后命令即返回，后续生成异步进行。旧输出归原 Run，新输出归新 Run，不补跑总结。

### 3.3 等待期间的停止

用户在命令等待期间按了停止，表示不希望继续执行。现有停止会暂停队列，驱动因此不再领取：旧 Run 照常落盘，介入消息**不执行**，以普通队列项留在队首，命令返回“已停止，消息保留在队列”。

- 这是停止的原有效果，介入不做额外判断。之后用户恢复队列则照常执行，也可以按队列原有方式移除它。
- 命令返回后新 Run 已启动的，按原规则停止新 Run，已写入的介入消息保留。
- 运行中 Goal 下的表现相同，见第四节。

### 3.4 幂等、连续介入与队列转换

- **幂等属于输入**：同一幂等键对应同一条 Input，重试返回它当前的结果（已启动的消息和 Run，或仍在队列中）。查重先于取消，因此重试不会再次打断任何 Run。介入必须携带幂等键。
- **连续介入**：同端请求期间禁用再次提交；多端的介入命令按 Session 串行，前一条返回后才处理下一条。A 打断 R0 启动 RA，B 再打断 RA 启动 RB，A、B 两条消息各自保留；RA 尚无输出时不补空助手消息。
- **队列项介入**：等同于现有的“优先”加上取消当前 Run，复用原 Input、输入类型和全部载荷；其他条目相对顺序不变。

### 3.5 终止时保留已生成内容

这是通用的终止处理，不限于取消：Run 被取消或中途失败（如模型流出错）时，当前 Step 已生成的内容都保留。普通停止、介入打断和失败终止共用同一处理。

- 已生成的 reasoning 和正文可靠保存；只有 reasoning、尚无正文时也保留。没有任何输出时不生成空助手消息。
- 内容及 Run／Step 归属写入同一会话文件，刷新、重连及重启后仍可读，不依赖 UI 缓存。
- 已完成的工具交换不重复追加；未完成的工具参数不当作有效调用；已执行工具的结果保留，不重跑副作用。
- 保存失败不发布可靠终态。进程在内容进入可靠追加前崩溃时，最后一段尚在内存的输出不承诺留存。
- 压缩、续接等执行交接不是终止，不在本条范围。

### 3.6 结果与失败出口

命令只有三种结果：

| 结果 | 含义 |
| --- | --- |
| 已启动 | 介入消息已写入会话文件，新 Run 已启动；响应带回消息和 Run |
| 已入队、未执行 | 消息已在队首，但驱动没有领取：用户停止，或旧 Run 结算／输出落盘失败。消息保留在队列，按队列与故障的原有规则处理 |
| 未接纳 | 预检或接纳失败（权限、只读、归档、输入不合法、Host 不支持）。不取消当前 Run，保留草稿 |

请求连接中断、回执丢失和 Host 重启的处理与普通发送完全一致：用原幂等键核实；重启后尚未领取的消息仍在队列，按队列原有的恢复规则处理。不增加介入专属的恢复机制。取消清理迟迟不结束属于通用取消机制的问题，不在本 Feature 处理。

## 四、Goal

介入消息用于引导，同一 Goal 的目标、累计进度与预算保留；介入打断 Run 不等于 Goal 完成或被替换。介入不为 Goal 增加新的状态或领取规则，只是两个现有动作的先后组合：

```text
运行中的 Goal：介入先执行现有的“停止 Goal”（Goal 暂停，它的当前 Run 被取消）
→ 介入消息作为普通队首输入被领取，按现有规则自动恢复同一 Goal
```

- **为什么要先暂停**：运行中的 Goal 只执行它自己的续跑输入，不领取普通队列；它的 Run 也不允许被单独取消，否则 Goal 仍是运行中却没有 Run 在执行。停止 Goal 是现有唯一能让它的 Run 停下的动作。
- **恢复沿用现有规则**：已暂停的 Goal 在真实用户输入被领取时自动恢复，这是 F02 已确认的公共规则，对任何暂停原因都相同。介入消息与普通发送在这一点上没有区别；介入前 Goal 已经是暂停的，也按同一规则恢复。
- **Goal 的停止与 Run 的停止各自独立**：等待期间用户按停止时，Goal 已被介入暂停，这次停止作用于正在收尾的 Run 并暂停队列。结果与 3.3 相同：介入消息留在队首不执行，Goal 保持暂停；之后恢复队列，消息被领取时 Goal 随之恢复。
- **其他队列项不受影响**：Goal 恢复运行后，排在介入消息之后的普通队列项继续按原规则等待，不会被运行中的 Goal 消费。
- 已完成的 Goal 和没有 Goal 的会话不涉及本节。

## 五、跨 Feature 边界

已写入会话文件的介入消息沿 F01 的历史分页、runId 合批和 ID 导航读取；没有助手正文时允许用户单项，缩略只取紧跟 Run 的最后一段正文。仍在队列中的介入消息不进入历史或导航。

F02 编辑资格检查活动执行及全部未完成控制；介入消息在队列中或命令执行中均不可裁尾。已提交正文和幂等身份归会话文件，不增加第二份永久输入正文。

| 编号 | 可验证结果 |

| F03-01 | Enter 普通排队，Ctrl／macOS Command + Enter 介入；Shift、IME、编辑和专用输入不误触 |
| F03-02 | 模型输出期间立即取消，不等待完整 Step；工具／child 按取消协议收尾，旧 Run 不继续执行 |
| F03-03 | 队列项介入复用身份、输入类型与完整载荷，移到队首后被领取；同端防重复、多端串行，介入消息先于其他队列项执行；A／B 连续介入均保留，RA 无输出时不补空消息 |
| F03-04 | 等待期间用户停止则介入消息不执行、留在队首，恢复队列后照常执行；命令返回后可停止新 Run 且消息保留 |
| F03-05 | 运行中 Goal 被介入后暂停并取消当前 Run，介入消息领取时恢复同一 Goal，目标、累计进度与预算保留；等待期间停止则 Goal 保持暂停、消息留在队首；其他队列项不被 Goal 消费 |
| F03-06 | 旧 Run 保持真实终态，旧输出与新消息／回复归属正确；待回答问题被作废且不被当作答案；编辑门禁有效 |
| F03-07 | 介入与普通发送走同一套接纳、领取和启动代码；旧输出可靠落盘、介入消息写入及新 Run 启动后命令才返回“已启动”，响应直接展示正式消息，不轮询 |
| F03-08 | 已写入会话文件的介入消息没有撤回按钮或后端撤回路径；仍在队列中的可按队列原有方式移除 |
| F03-09 | 同键重试返回同一输入的当前结果，不重复接纳、不再次打断；断线与重启表现与普通发送一致 |
| F03-10 | 空闲及新会话直接发送；只读／归档、不支持介入及编辑模式不误接纳，预检失败不打断当前 Run |
| F03-11 | 取消与失败两类终止下，仅 reasoning、混合部分正文、仅正文均保留；刷新及重启后一致 |
| F03-12 | 终止与正常完成竞争不重复消息，工具交换完整且不重跑，未完成参数不形成悬空调用 |
| F03-13 | 旧输出落盘失败时不误报成功，介入消息不执行并留在队列；分页、导航与历史编辑读取同一份消息事实 |

按核心风险使用隔离 Runtime、可控模型／工具及 Desktop／Host Web 验证。实施见 [Feature 开发计划](开发计划.md)。
