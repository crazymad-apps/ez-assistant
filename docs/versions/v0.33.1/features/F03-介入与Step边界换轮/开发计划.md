## 三、Feature 验收与完成结论

三个里程碑确认后按流程规范执行 Feature 验收：逐项核对 F03-01～13，以及与 F01 分页导航、F02 编辑门禁的联合结果，对应总体设计 A07、A08 和适用 A04、A09、A10。

2026-11-16 已完成下列联合检查，macOS arm64 队列对齐修复包已通过用户复测。同日用户追加反馈原生压缩会话编辑后的接续与手动压缩失败，已归入 [F02 补修](../F02-用户消息编辑重发/开发计划.md#当前结论)，待补修回归与用户确认后再关闭联合验收。

- F03-01、03、07～10：Desktop／Host Web 快捷键与队列介入接通。普通发送仍排队；队列转换保留原 Input，空闲和新会话可直接发送。回执先于历史快照显示正式消息，同键核实和 Host 重启回读收敛至原 Input／Run，已提交消息不可从队列撤回。
- F03-02、04～06、11～13：旧轮取消与结算、Goal 暂停与恢复、停止时保留队首、待回答问题作废及工具／审批／子任务取消的核心回归通过。取消和失败中的部分输出经刷新与重启可读，完成竞争不重复提交，结算故障时输入留队且无新 Run。
- F01／F02 联合：同一隔离会话连续介入的消息 ID、顺序及代次在正文分页、缩略和历史编辑中一致；没有正文的轮次保留用户项；运行期间编辑被拒绝，停止结算后恢复资格。旧版 v0.33.0 Web 页面被 v0.33.1 Host 的准入门禁拒绝。
- 未执行 Windows 原生及真实跨设备／跨组织联调。F02 原生压缩补修及用户复测尚未收口。

2026-11-16 版本收尾：F02 补修与 F04 已汇入同一候选。终止输出留存、介入及历史编辑的正式 Host 页面回归通过；手动排序后的同一会话完成分页、编辑、介入和重启联合验证。此前因 F02 代码补修未整合而保留的联合项已完成，纳入版本整体验收。Windows 原生、真实跨设备／跨组织联调及原用户会话真实模型续聊仍未测，限制统一见[版本总计划](../../开发计划.md#五跨-feature-版本验收)。
