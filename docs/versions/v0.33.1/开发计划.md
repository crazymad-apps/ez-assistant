## 一、计划信息与设计基线

- 日期：2026-11-10。
- 版本状态：**已完成／已归档**。2026-11-16 用户确认整体验收结果及保留限制。F04 已合入主工作树，保留后续的原生压缩重建与文件字符分页修复；实际完成范围及限制见第五节。
- 版本目标：改善聊天历史阅读、历史输入编辑、执行期间的介入，以及侧栏项目／会话列表的排序与分页体验。

## 二、拆分原则与推进顺序

四个 Feature 分别围绕历史读取、历史改写、运行调度和侧栏列表形成独立闭环。它们涉及共享协议、RootStore 和 Runtime；实现及验收按以下顺序串行推进，F04 追加在原顺序之后。2026-11-10 用户要求“准备开始 F02 的设计工作”，据此提前开展 F02 文档设计，不变更 F01 的实施与确认记录；F02 代码实现仍以 F01 独立验收通过为前置。

```text
总体设计已确认
→ 版本级总开发计划已确认
→ F01：功能设计已确认 → 技术方案已确认 → 交互指导已确认 → 开发计划已确认 → M0 实现及验证
       → 分里程碑实现与确认 → 独立验收与确认
→ F02：功能设计 → 技术方案 → 交互指导 → 开发计划
       → 分里程碑实现与确认 → 独立验收与确认
→ F03：功能设计 → 技术方案 → 交互指导 → 开发计划
       → 分里程碑实现与确认 → 独立验收与确认
→ F04：功能设计 → 技术方案 → 交互指导 → 开发计划
       → 分里程碑实现与确认 → 独立验收与确认
→ 跨 Feature 版本验收 → 用户确认 → 版本归档与发布准备
```

2026-11-16 用户回复“直接开发吧”，调整 F04 的串行前置：允许在独立工作树提前实施 M0，F02 补修与 F03 联合验收结论保持独立，后续仍逐里程碑确认。

每一类设计文档分别确认。总计划确认只固定推进顺序与门禁，不替代 Feature 的设计、计划、里程碑或验收确认。首个 Feature 开发计划确认后，才将版本状态改为 `开发中` 并开始其第一个实现里程碑。

每个里程碑完成实现与必要验证后先记为 `🟨 待确认`，用户确认后才进入下一里程碑；Feature 全部里程碑完成后仍需独立验收。Git 提交不作为切换 Feature 的条件，未授权不执行提交或推送。

### 跨 Feature 契约

| 契约 | 首次确定与维护 | 后续约束 |
| --- | --- | --- |
| 阅读轮次、正文窗口、导航配对与定位 | F01 | 分页复用现有 runId 合批；缩略按真实用户输入与紧跟 Run 的最后一段正文配对，正文可缺失，中间 Step 正文不显示。F02 裁尾和 F03 换轮后按同一规则刷新，不增加 Goal 归并逻辑 |
| owner、generation、旧请求和缓存失效 | F01 | F02 必须清掉被改写的旧历史投影；F03 新内容可靠提交后按同一规则更新 |
| 继承／只读及已有操作资格 | F01 保留事实，F02 接入编辑门禁 | 标签去除不改变权限；F03 不得恢复来源执行或借历史身份控制当前轮次 |
| 历史改写与输入附属信息保留 | F02 | 不撤销已执行的外部副作用；不得为支持 F03 绕过空闲、队列、Goal 等已确认限制 |
| 已提交输入的单一来源 | F02 | 文件保存 Input、幂等键及 Run 历史，SQL 只留暂存／未完成控制；统一裁尾、分支、重试和恢复，迁移后回归 F01 读取；F03 沿用可靠输入交接 |
| Goal 与新输入的自然延续 | F02 修正公共领取规则，F03 接入介入 | Goal 自动续跑不消费普通队列，暂停后走正常机制；真实输入领取启动时自动恢复同一 Goal。F03 介入以用户消息引导后续执行，Goal 身份、目标及累计进度／预算保留，Run 结束不等于 Goal 完成；运行中 Goal 被介入时先暂停、介入消息领取时恢复，见 [F03 技术方案第六节](features/F03-介入与Step边界换轮/技术方案.md#六goal) |
| 介入、终止输出留存与新发送 | F03 | Runtime 为权威；介入复用普通发送路径，不另建发送流程、专用队列或撤回；取消与失败终止共用输出留存。机制见 [F03 技术方案](features/F03-介入与Step边界换轮/技术方案.md) |
| 协议、持久化及兼容准入 | 各 Feature 技术方案分别明确，版本验收统一核对 | 只为真实影响调整；分页不得静默重解释旧客户端 `limit`，介入不得静默降级为普通队列 |
| 侧栏顺序、分组范围与列表分页 | F04 | 与 F01 正文轮次分页分开；创建与分支按新建规则加入，F02 编辑及 F03 换轮不改变排序值；沿用身份隔离，迁移与兼容独立评估 |

后续 Feature 如需改变已完成的契约，先说明原因、影响与重验范围，重新打开受影响 Feature 并取得确认；不得到版本末尾才发现阅读、编辑与调度各自采用不同规则。

## 四、各 Feature 的进入与退出条件

### F01 历史阅读与缩略导航

**能力结果**：长会话按完整阅读轮次加载；宽窗口左侧通过轻量条目预览和定位历史；超长导航可独立滚动，重复继承文案移除后仍保持只读。

状态：✅ 已完成。各项设计、里程碑和独立验收均已确认，结论见 [F01 开发计划](features/F01-历史阅读与缩略导航/开发计划.md)。验收范围为 F01-01～F01-14 及总体设计 A01～A05、A09～A10 的阅读侧要求；Windows 原生未测。

向后续 Feature 交付：稳定的轮次／定位查询和历史失效规则，以及标签简化后不变的操作资格。

### F02 用户消息编辑重发

**能力结果**：悬停或聚焦用户消息可复制、载入底部 Composer 完整编辑；框外上方编辑抽屉仅显示标题及返回原位置／取消，原发送按钮提交。编辑时隐藏其他附属区域，取消或接纳成功恢复普通草稿及有效抽屉展开状态；提交在原会话保留前文、替换该条并丢弃后续历史，重新执行。

原独立验收及平台限制确认记录保留，2026-11-16 原生压缩重建补修已通过整合候选回归，实际用户会话续聊仍未复测；重开范围与回归结论见 [F02 开发计划](features/F02-用户消息编辑重发/开发计划.md#当前结论)，当前状态以总台账为准。验收覆盖总体设计 A06、A09、A13 及适用 A04、A05、A10。

向 F03 交付：稳定的编辑与调度互斥边界、普通输入领取时自然延续 Goal 的共用规则，以及 F01＋F02 的真实历史改写联合结果。

### F03 介入与运行打断

**能力结果**：Enter 保持普通队列；Ctrl + Enter、macOS Command + Enter 或队列项“介入”立即打断当前 Run，由这条用户消息接续新轮。旧轮已生成的 reasoning／正文及真实终态保留，新输入只执行一次；普通队列继续使用抽屉。取消或失败后已输出内容丢失的修复于 2026-11-11 随用户要求纳入本 Feature。

进入实现前必须落实：

- Feature 开发计划确认；协议变更与兼容准入以技术方案为准。
- 实施顺序先完成终止输出留存，再接入介入命令和界面。

独立验收条件：功能设计 F03-01～F03-13 逐项收口，总体设计 A07、A08 和适用 A04、A09、A10 满足；与 F01 分页导航、F02 编辑门禁的联合结果一致。

### F04 侧栏列表排序与分页

**能力结果**：Desktop／Web 的项目和会话默认按创建时间、新建在前；用户可整理同组顺序，目标 Host 持久保存并按最终顺序分页，刷新／重启仍能读到正确位置。

**进入条件**：四份 Feature 文档已于 2026-11-16 确认；同日用户授权“直接开发吧”，允许隔离实施 M0，不以 F02 补修与 F03 联合验收收口为启动条件。其他 Feature 的确认记录与版本联合验收要求保持。

进入实现前必须落实：

- 采用每项一个留间隔的 64 位整数排序值。普通移动更新移动项，间隔或整数边界不足时在事务内重排当前分组；项目沿现有 workspaces、会话优先沿已有项目归属记录落表，最终字段与索引由技术方案核查。不引入通用排序表、稀疏覆盖记录、浮点排序、LexoRank 或后台维护服务。
- 项目列表、每个项目内会话和独立会话分别确定查询范围与分页；Host 排序后取页，不能仅前端重排当前页。拖拽提交移动意图，不上传全历史 ID；目标失效、并发移动、旧分页及迟到响应明确处理，复用现有事务与事件机制。
- 默认创建时间、新建置前、恢复默认重新编号；消息／Run 更新和改名不改排序值。旧数据初始化、必要字段／索引迁移、事务重排与大分组耗时需验证；F01 的既有无迁移结论不能代替本项评估。
- 明确 Desktop／Web 拖拽入口、跨端刷新、归档／恢复、搜索与项目选择入口，以及现有桌面跨设备置顶的独立语义；同组排序不扩大为跨项目迁移。
- 功能设计、技术方案、交互指导及 Feature 开发计划分别形成并确认。迁移、备份、旧 Host 准入与回滚边界在实施前确定，本次加入版本不执行数据库操作。

**独立验收条件**：总体设计 A11、A12 及适用 A10 收口；默认、拖动、跨页读取、刷新／重启、恢复默认和间隔耗尽重排结果一致，原创建时间与正文不变。实际查询计划使用有效索引，长列表按需读取，批量重排成本明确；新建／分支正确入列，编辑和换轮不抢手动位置，主机／用户／组织隔离与兼容升级得到验证。

**完成交付**：稳定的侧栏列表查询与排序变更能力，及 F01～F03 联合使用时的列表刷新边界。完成结论留 F04 独立开发计划，之后进入跨 Feature 版本验收。
