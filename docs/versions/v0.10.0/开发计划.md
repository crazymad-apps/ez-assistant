# v0.10.0 开发计划：可靠会话与持久化执行

## 一、计划信息与设计依据

- 版本：`v0.10.0`
- 状态：✅ 已完成并归档（2026-08-08）
- 当前阶段：M0–M5 和版本验收均已完成
- 功能范围：[`v0.10.0 功能设计`](功能设计.md)
- 实现依据：[`v0.10.0 技术方案`](技术方案.md)
- 版本状态：[`docs/版本管理.md`](../../版本管理.md)
- 实际实施记录：[`v0.10.0 开发进度`](开发进度.md)

本计划只维护里程碑顺序、状态、交付范围、验证入口和确认门禁。数据格式、schema、协议字段、
状态转换、一致性算法与异常恢复细节均以已确认技术方案为准，不在本文重复。

本版本没有正式桌面页面，不单独安排界面交互设计或桌面 UI 里程碑。

## 二、台账原则

1. M0 至 M5 顺序推进；每个里程碑完成实现和验证后先标记 `🟨 待确认`，只有用户明确确认后
   才改为 `✅ 已完成`并进入下一里程碑。
2. 每个里程碑都必须保持规范 Conversation、SQLite 结构化状态和 Runtime 内存投影的权威边界，
   不引入 Message/Part 关系表、第二套 Conversation 或持久 RuntimeEvent。
3. 自动测试只使用 `tempfile` 创建的隔离 Runtime Home、SQLite 数据库和正文文件，不读取或修改
   用户真实 `~/.ez-assistant` 数据，也不访问真实 Provider。
4. 跨 SQLite 与正文文件的写入必须通过已确认的一致性方案完成；不得为赶进度临时使用不可恢复
   的双写流程，也不得把 pending 或 staged 数据暴露成规范 Conversation。
5. 协议、Runtime、Host 和现有私有客户端同步演进，保持当前 `PROTOCOL_VERSION = 1`，不维护
   并行协议代际或旧 `StartRun` 双轨入口。
6. 实际实现与设计假设不符时停止扩大改动，先修订设计并重新确认；不在实现中静默改变重启、
   幂等、工具副作用或破坏性重新输入语义。
7. 实际产出、验证结果、偏差、遗留和风险写入 `docs/开发进度.md`；本计划只维护里程碑状态。
8. 不主动执行 Git 暂存、提交或推送。

## 四、里程碑台账

### M0：可恢复的本地存储底座

- 前置：`v0.10.0` 功能设计、技术方案和本开发计划均已确认。
- 目标：建立可独立验证的产品存储能力，使结构化状态与每 Session 顺序正文能够可靠创建、读取、
  提交并在中断后恢复，但暂不接管 Runtime 主流程。
- 交付范围：
  - RuntimeStore 端口、Host 本地存储实现和存储 worker 生命周期；
  - 空数据集初始化、结构化状态读写与 Conversation JSONL round-trip；
  - 普通正文 staged append、历史替换所需 generation 切换及其启动恢复；
  - 单 Session 正文读取失败的隔离与脱敏错误；
  - 临时数据集上的约束、回滚和中断点集成测试。
- 验证入口：

  ```bash
  cargo test -p assistant-runtime -p assistant-runtime-host --all-features
  cargo clippy -p assistant-runtime -p assistant-runtime-host --all-targets --all-features -- -D warnings
  cargo fmt --all --check
  ```

- 完成判定：隔离 Runtime Home 可以从空状态初始化并重开；规范消息内容和物理顺序完整往返；
  staged append 与 generation 切换在设计列出的中断点后都只恢复出一个权威正文；损坏正文不会被
  空文件覆盖，也不阻断无关 Session。
- Review 重点：Store 端口是否保持基础设施中立，正文是否直接复用规范 Conversation，SQLite 是否
  只保存结构化关系，存储 worker 是否有明确所有者和可观察终态。
- 技术依据：技术方案第三、四、5.1、5.5、6.3 和 8.1 节。

### M1：Runtime 持久化启动与会话恢复

- 前置：M0 已确认。
- 目标：让 Runtime 正式接管持久化 Session、Conversation 和 Run，在开放客户端连接前恢复权威
  状态，并继续以 Runtime 作为唯一业务所有者。
- 交付范围：
  - Session 创建、摘要、Conversation、Run 与关联投影的持久化读写；
  - Runtime registry 从 RecoveredRuntime 建立、Conversation lazy load 和单 Session 不可用状态；
  - 启动恢复顺序、未可靠终结 Run 的 interrupted 收敛与派生计数维护；
  - 相关公共入口 async 化以及 Host 启动、关闭和错误传播接入；
  - Session、Conversation 和 Run 跨重启回归。
- 验证入口：

  ```bash
  cargo test -p assistant-runtime -p assistant-runtime-host --all-features
  cargo test -p assistant-protocol
  cargo clippy -p assistant-runtime -p assistant-runtime-host -p assistant-protocol --all-targets --all-features -- -D warnings
  cargo fmt --all --check
  ```

- 完成判定：Runtime 重启后能够列出并查询既有 Session、Conversation 和 Run；完整消息、Run 终态
  与关联保持不变；启动恢复完成前 Host 不接受客户端请求；单 Session 错误不会形成第二份空状态。
- Review 重点：Runtime/Host 所有权、恢复顺序、lazy load 边界、`message_count` 只作为列表派生
  投影，以及持久化成功和事件发布的先后关系。
- 技术依据：技术方案 3.1、3.3、5.4、5.7、6.1、6.3 和 8.1 节。

### M2：可靠输入、幂等排队与串行执行

- 前置：M1 已确认。
- 目标：形成“输入先持久化、再唤醒执行”的可靠路径，使同 Session 输入可排队、客户端重试保持
  幂等，Runtime 重启后由用户显式恢复而不自动续跑。
- 交付范围：
  - SubmitInput、CancelQueuedInput、ResumeSession 与 RetryRun 的 Runtime 行为；
  - 同 Session 幂等 key、持久 queue order、单执行器串行领取与跨 Session 并发；
  - User Message、Run 创建、最终 Assistant Message 和 Run 终态的一致提交；
  - queued、running、cancelling 等重启状态的 interrupted/resume_required 收敛；
  - 相关协议意图、投影、错误分类和私有客户端适配。
- 验证入口：

  ```bash
  cargo test -p assistant-runtime -p assistant-protocol -p assistant-runtime-host --all-features
  cargo clippy -p assistant-runtime -p assistant-protocol -p assistant-runtime-host --all-targets --all-features -- -D warnings
  cargo fmt --all --check
  ```

- 完成判定：重复幂等 key 只产生一个 Input 和首次 Run；同 Session 多输入按接收顺序执行且不同
  Session 可并发；正常同进程提交自动唤醒，重启后的队列在 ResumeSession 前不执行；取消排队输入
  不触发模型，重试中断 Run 创建新 attempt 且不重复 User Message。
- Review 重点：接受成功是否表示已经持久化、幂等范围是否只在 Session 内比较 key、队列顺序是否
  没有进入 Message 正文，以及执行器是否避免 missed wakeup 和同 Session 双 start。
- 技术依据：技术方案 5.2、5.4、6.1、7.1、7.2 和 8.2 节。

### M3：工具交换与异常任务收敛

- 前置：M2 已确认。
- 目标：保证工具副作用边界和异步任务退出始终形成可解释终态，崩溃恢复后不出现孤立 Tool Call、
  部分 Tool Result、自动重放副作用或被吞掉的 panic。
- 交付范围：
  - PersistentJournal 的 begun/ready pending tool exchange 与整批正文提交；
  - 正常提交后的 pending 清理及重启时 outcome unknown 修复；
  - Agent Core 对正常完成、受控取消和 panic/JoinError 的显式观察；
  - Runtime supervisor、存储 worker 和 Host 连接子任务的异常传播与关闭回归；
  - 工具交换后继续失败、取消和重启的完整性测试。
- 验证入口：

  ```bash
  cargo test -p agent-core -p assistant-runtime -p assistant-runtime-host --all-features
  cargo test -p assistant-protocol
  cargo clippy -p agent-core -p assistant-runtime -p assistant-runtime-host -p assistant-protocol --all-targets --all-features -- -D warnings
  cargo fmt --all --check
  ```

- 完成判定：工具执行前已有可恢复 pending 事实；完整工具批次进入正文后 pending 被清空；begun 和
  ready 两类重启恢复都得到完整配对且不再次执行工具；Core task panic 返回稳定 Failed(Internal)，
  CompletionFuture 不 panic，Host 不静默吞掉子任务异常。
- Review 重点：pending 是否仅为临时状态、多个 Tool Call 是否按整批提交、unknown 结果是否明确且
  不伪造未执行，以及所有异步任务是否都有明确所有者和终态观察。
- 技术依据：技术方案 5.3、6.2、6.3、8.1 和 8.3 节。

### M4：会话生命周期与历史重新输入

- 前置：M3 已确认。
- 目标：在可靠持久化和执行基础上补齐用户可见的会话管理意图，同时保证破坏性历史替换不会留下
  隐式分支、旧任务回写或悬空引用。
- 交付范围：
  - Session 归档、归档列表过滤、只读查询与恢复；
  - 空闲状态下显式切换 model key；
  - 从历史 User Message 重新输入、尾段销毁和新 generation 原子切换；
  - 被销毁尾段的 Input、Run 和关联收敛；
  - ListRuns 及相关协议命令、状态、错误和 Serde 回归。
- 验证入口：

  ```bash
  cargo test -p assistant-runtime -p assistant-protocol -p assistant-runtime-host --all-features
  cargo clippy -p assistant-runtime -p assistant-protocol -p assistant-runtime-host --all-targets --all-features -- -D warnings
  cargo fmt --all --check
  ```

- 完成判定：只有空闲且无 pending/queue 的 Session 可归档或切换模型；归档状态可只读并可恢复；
  历史重新输入只保留目标之前的正文，创建全新 User Message 和 Run，旧尾段不会重新提交且不产生
  隐式分支或 undo；协议生产者和消费者同步通过测试。
- Review 重点：mutation gate 的并发复核、归档不等于删除、System Prompt 不随模型切换改变、历史
  替换的破坏性语义及 generation 切换失败恢复。
- 技术依据：技术方案 5.5、5.6、7.1、7.2、8.1 和 8.2 节。

### M5：Host 端到端接入、全量回归与验收准备

- 前置：M4 已确认。
- 目标：通过正式 Runtime Host 和私有验证入口回证完整持久化闭环，完成 workspace 回归、长期
  文档同步和版本验收证据准备。
- 交付范围：
  - 正式 Runtime Home 下 Host 初始化、锁、恢复、请求分发和受控关闭的端到端路径；
  - 复用并扩展 Runtime Host 现有私有 Ratatui Demo 作为人工验收客户端，不新建独立 Demo 或第二套
    Session/Run 实现；
  - 可重复的离线验收场景负责启动临时 Provider、两次正式 Host 进程和私有协议客户端，覆盖创建、
    提交、排队、重启、显式恢复、取消、工具、历史重新输入、归档与模型切换；
  - 断线重连通过权威快照恢复且不依赖事件重放；
  - 存储、协议、日志和错误的敏感内容泄漏检查；
  - 模块约束、Agent 系统架构、版本文档与实际实现同步；
  - 功能设计验收标准到自动化及人工证据的映射。
- 验证入口：

  ```bash
  cargo fmt --all --check
  cargo clippy --workspace --all-targets --all-features -- -D warnings
  cargo test --workspace
  cargo doc --workspace --no-deps
  cargo metadata --format-version 1 --no-deps
  ```

- 人工核对：通过现有 Runtime Host Ratatui Demo 观察权威快照；只使用隔离 Runtime Home 和临时
  loopback fake Provider，执行两次正式 Host 启动之间的 Session、Conversation、Run、队列和
  pending 恢复路径；不得连接真实 Provider，不得修改用户现有数据集。
- 完成判定：功能设计 14 条验收标准全部具有实际证据；全 workspace 回归通过；数据文件、SQLite、
  Runtime 快照和 Host 返回分别核验且结果一致；未执行项、偏差、遗留和风险已经明确记录，可进入
  正式版本验收。
- Review 重点：验证是否覆盖真实进程重启而非只重建内存对象，客户端断线是否不影响 Run，错误
  是否脱敏，以及证据是否清楚区分数据库、正文文件、Runtime 状态和协议结果。
- 技术依据：功能设计第七节，技术方案第五、七、八和九节。
