## 三、实际能力验收

- `assistant-runtime` 持有 Session、Conversation、Input、Run、排队、恢复和生命周期的唯一业务
  状态；Host 本地存储模块实现 RuntimeStore 端口，不在传输层维护第二份权威状态。
- SQLite 保存 Session、Input、Run、消息引用、派生计数和短生命周期一致性事实；规范消息正文只在
  Session 对应的顺序 JSONL 中保存，reasoning、Provider State 和 Tool Call/Result 直接复用规范类型。
- 同一 Session 的幂等 key 只命中首次 Input/Run；输入按持久接收顺序串行执行，不同 Session 可并发。
- 重启后未开始的输入保持排队，非终态 Run 收敛为 interrupted；只有显式 Resume/Retry 才能继续，
  不自动重放 Provider 或工具副作用。
- 工具副作用前保存临时 pending exchange；完整 Tool Call/Result 批次进入正文后清空 pending；异常
  重启将结果未知的交换收敛为完整、可解释且不会再次执行的批次。
- Session 支持严格归档/恢复、空闲时切换 model key，以及从历史 User Message 破坏性重新输入；
  本版本没有任意消息编辑、隐式分支、旧回答选择或通用 undo。
- Core、Runtime、Store worker 和 Host 连接任务均由明确所有者观察异常；取消、panic/JoinError 和
  有界关闭形成稳定领域结果。

## 五、实际执行的验证

### 5.1 Workspace 质量门禁

```text
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-features --quiet
cargo doc --workspace --no-deps --quiet
cargo metadata --format-version 1 --no-deps
git diff --check
```

结果全部通过。Workspace 测试为 **741 passed / 0 failed / 4 ignored**。4 项 ignored 分别是：

- DeepSeek 真实 API thinking/tool-call smoke；
- 临时目录中的真实 `rg` 搜索；
- Shell 后台进程树取消；
- detached loopback 服务的真实启动与显式停止。

### 5.2 正式 Host 双进程端到端验收

```text
cargo test -p assistant-runtime-host --test v0_10_offline_acceptance --all-features
```

结果为 **1 passed / 0 failed**；在 M5 稳定性核对中连续重复 20 次，全部通过。该用例实际启动两次
`ez-assistant-runtime` Host 进程和临时 loopback Provider，并通过私有 Unix Socket 协议覆盖：

1. 创建 Session、正常执行、幂等重试、活动 Run 后输入排队和客户端断线；
2. 强制结束第一次 Host 后重新启动，核对 completed、interrupted 与 accepted 状态；
3. 显式恢复队列，完成工具交换、取消、模型切换、历史重新输入、归档与恢复；
4. 受控关闭第二次 Host 后，以只读连接核对 SQLite，并直接读取权威 JSONL。

最终物理状态核对为：Session 保持 active 并使用替代 model key；权威 generation 已切换，
`message_count = 2`；SQLite 中只保留重新输入后的 1 个 Input、1 个 Run 和 2 条消息引用；
`pending_tool_exchanges = 0`、`body_appends = 0`；权威 JSONL 只有替换后的 User/Assistant 两条消息。
Host stdout/stderr 还对 API key 和测试正文 marker 做了泄漏断言。

### 5.4 依赖方向检查

```text
cargo tree -p assistant-runtime --depth 2
cargo tree -p assistant-protocol --depth 2
```

依赖方向符合约束：`assistant-runtime` 与 `assistant-protocol` 不依赖 `rusqlite` 或具体 Provider；
bundled SQLite 和 OpenAI-compatible Adapter 由顶层 Host 装配。Axum 只作为 Host 测试用
loopback Provider 的 dev-dependency，不进入产品运行依赖。
