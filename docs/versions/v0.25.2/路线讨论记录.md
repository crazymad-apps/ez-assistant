#### Client 与 Desktop 共存：已确认约定与待明确细节

用户已明确两个产品同级、各自分发包内置 Host，并于 2026-09-10 接受共享实例方向，进一步
确认以应用协议最低兼容版本双向检查替代软件版本完全相同的要求；不兼容时只提示当前客户端
启动／连接失败。以下约定待 v0.25.2 实现；具体装配、重启和卸载路径仍由技术方案明确。

- **安装与运行分开**：各产品保留自己的随包 Host 文件；同一操作系统用户、同一 Runtime Home
  默认共用一个运行实例和业务数据。首次启动方可使用自己的随包 Host，之后的入口发现并复用它。
- **启动竞争**：复用 Host 已有内核独占锁，竞争失败方重新发现获胜实例并校验后连接。已有 Host
  正在初始化时等待其状态；端口被其他程序占用、发现文件失效或校验不通过时给出准确诊断，
  不以更换端口、清除锁文件或另开同库实例作为自动补救。
- **双向最低兼容版本（已确认）**：Client、Desktop、Host 内部均维护当前软件版本与最低
  兼容软件版本号，例如 `0.25.2`，不另设协议版本号；同一发布版本的三个组件使用一致的最低兼容版本定义。该下限只表达应用协议层
  兼容范围，不以 UI、内部实现或数据库格式变化直接决定。每次连接 Host 初始化时双向比较，
  客户端版本必须不低于 Host 的最低兼容版本，Host 版本也必须不低于客户端的最低兼容版本；
  Desktop 按相同客户端规则处理，两种客户端之间无需直接比较。该检查覆盖本机、远端直连、
  断线后重新初始化，以及并发启动后重新发现实例。
- **不兼容处理（已确认）**：任一方向不满足时，直接提示当前客户端启动／连接失败，显示
  对端当前版本与未满足的最低版本要求，结束本次初始化；保留已有 Host 及任务，不自动启动
  另一实例、停止／替换旧 Host、升级／降级或进入修复流程。软件版本不同但双向条件满足时
  允许连接，不再要求完全同版本。
- **数据库兼容下限（已确认）**：数据库独立持久保存最低兼容 Host 版本，Host 版本达到下限
  才能继续存储初始化，与应用协议下限无须相同。先取得实例锁并只读核查，再进入迁移、业务
  写入和修复；不兼容时保留原数据并报告初始化失败。下限随破坏存储兼容性的变更原子提升，
  不随客户端版本或每次 Host 启动覆写。具体维护方向与现有迁移保护的衔接见
  [数据库兼容决策](../../重要决策与变更记录.md#260910--数据库独立维护最低兼容-host-版本--已确认方向待实现)。
- **技术方案落点**：最低兼容版本作为一份发布事实供三个组件使用，由现有版本与协议生成流程装配。
  用户已明确使用软件版本号，技术稿据此移除独立 `protocol_version` 及整数相等检查；
  能力检查按入口需要保留。首个下限、旧端处理、版本解析及验收矩阵见技术方案第四节，
  M1／M2 实施，不承诺兼容所有已发布旧端。
- **停止与升级**：退出任一客户端只断开该客户端。显式停止或切换共享 Host 时应说明对全部
  连接和运行中任务的影响；升级切换须明确目标可执行文件，保留既有数据升级检查，不自动恢复
  被中断任务。普通重启按技术方案保持当前 Host 来源和版本，M3 实施并核验。
- **卸载与多实例**：卸载某个产品不得删除共享数据或另一产品文件；活动 Host 来自该安装目录
  时，需明确停止／切换与后续启动路径。真正需要隔离实例时，必须显式指定不同 Runtime Home
  和不冲突的监听端口，不能让多个 Host 共同打开同一份存储。

现有依据：[`endpoint.rs`](../../../apps/runtime-host/src/endpoint.rs) 按 Runtime Home 持有
`run/runtime.lock` 并发布私有发现文件；[`startup.rs`](../../../apps/runtime-host/src/startup.rs) 在
业务存储初始化前取得锁；[Desktop bootstrap](../../../apps/desktop/src-tauri/src/runtime_bootstrap.rs)
先发现后启动，并校验协议和必要能力。M2 已接入双向软件版本准入，M3 固定原实例和来源重启；
M4 已通过正式 Client 的双启动与 Desktop 原生协同隔离验收，完整 GUI／系统服务验收另行记录。

数据库只读代码核查：[`storage/migrations/mod.rs`](../../../apps/runtime-host/src/storage/migrations/mod.rs)
的 `completed_prefix` 已拒绝高于 Host 目标版本的数据库，当前账本仅保存迁移版本与时间；
[`storage/engine.rs`](../../../apps/runtime-host/src/storage/engine.rs) 在日常业务连接、FTS 和恢复前执行
迁移入口。M1 已加入独立下限表、只读预检和已知旧库分类代码，保留高版本账本拒绝；
不允许仅凭下限满足就使用未知新库。macOS 隔离实测及真实 v0.25.1 Host 回退验证已通过；完整版本验收仍在 M7。

### 现有基础与无图形客户端（v0.25.2）

- Runtime 已独立运行，[Host 参数](../../../apps/runtime-host/src/config.rs)提供 `launch`／`serve` 与私有 `access` 短命令，
  尚不是完整会话 CLI；最小 CLI 复用应用协议、本机发现和 Runtime 能力，不再装配另一份业务 Runtime。
  Client 使用 TypeScript 与 Node.js；物理目录、可执行入口、服务管理及原生入口组合按两种应用形态和实际
  调用关系设计，不单独分发 Host。
- CLI 本版聚焦本机 Host 生命周期、运行状态、访问设置和 Web 入口；会话、模型管理、审批等
  Agent 使用主要交给随包 Web，先前终端会话操作及远端管理候选不作为当前范围。CLI 退出不
  停止 Runtime 任务，完整 TUI、补全及更多自动化输出留待后续。
- 当前应用入口绑定 IPv4 loopback，使用私有发现文件与进程 Bearer Token；启动时生成的
  `instance_id` 不能直接当作长期节点身份。当前 Host 限定 Unix，首批部署按 macOS／Linux 评估，
  Windows 支持另行核定。
- v0.20 会话代理限定同节点，v0.21 提供设备接入与语音路由，均不表示已有 Runtime 互联。
- v0.24 资源定位已有文件根与相对路径；远程客户端缓存需按节点和会话隔离。已发布版本的本地 Finder、
  用户浏览器和 PTY 属于桌面设备。v0.25.0 明确迁移用户 PTY 至 Host，文件选择与预览增加兼容，
  目录选择／工作区浏览／预览共用 Host 文件基础；用户浏览器保留 Desktop 实现，Web 隐藏入口。
