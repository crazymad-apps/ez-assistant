## 二、入口与命令

正式命令名为 `ez-assistant`。无参数、`--help` 或子命令 `--help` 显示帮助并返回 0，
不连接或启动 Host。`--version` 只显示当前 Client 软件版本，不依赖正在运行的 Host。

```text
ez-assistant — 本机 Host 管理

用法：ez-assistant [--runtime-home <绝对路径>] <命令>

start     启动或复用本机 Host，等待业务就绪
status    查询当前 Host、访问地址和开机自启
stop      停止共享 Host，影响全部连接和运行中任务
restart   按当前 Host 来源重启，影响全部连接和运行中任务
config    交互配置访问设置与开机自启
web       打开当前 Host 的 Web 登录入口

首次使用 Web：config 设置访问密码 → start → web
```

| 入口约束 | 交互规则 |
| --- | --- |
| 本机目标 | 显式 `--runtime-home`、环境配置、产品默认目录依次取值；显示最终绝对路径，沿用技术方案的规范化规则 |
| 参数错误 | 相对 Home、未知命令／参数、非法值返回 2，显示原因及相关用法；不执行管理操作 |
| 普通命令 | 一次执行、输出结果后退出；stop／restart 执行前再次打印共享影响说明，不弹确认选择，不要求额外 `--yes` |
| 等待参数 | start／stop／restart 支持 `--timeout <秒>`，仅延长操作等待；start／restart 不小于 60，stop 不小于 30，必须是有限正整数 |
| restart 等待 | 默认停止最多 30 秒、启动最多 60 秒；显式 timeout 分别用于两个阶段，帮助明确不是总耗时上限 |
| config | 需要 stdin、stdout 均为 TTY，且终端支持交互；不支持时立即提示在交互终端运行并返回 2 |
| 脚本环境 | 普通命令输出静态文本；本版不提供通用 JSON 输出、密码参数、配置管道提交或交互式主菜单 |

命令中的路径均按参数值传递；复制用法应正确引用空格、中文和特殊字符。管理其他 Home 时，
下一步示例沿用本次目标，不能提示用户对默认 Home 执行 stop／restart。

## 三、布局与信息结构

### 3.1 普通命令输出

按“目标 → 当前动作／查询结果 → 关键事实 → 下一步”组织；不铺完整面板、不清屏。
普通成功输出保留少量关键行，错误时补必要版本、来源和恢复动作，不倾倒原始堆栈。

```text
$ ez-assistant status
目标目录  /home/alex/.ez-assistant
Host      业务就绪
软件版本  0.25.2 · 与当前 Client 兼容
管理方式  手动运行
开机自启  已开启 · 下次系统启动生效
当前地址  http://127.0.0.1:7240/
访问范围  仅本机
```

运行状态与开机自启必须分行；允许“当前已停止／自启已开启”及“服务运行中／自启已关闭”。
Linux 输出可展开运行用户、unit、注册 Host 版本和路径。当前来源与注册来源不同则同时列出，
不能只显示“由 Client 启动”或“由 Desktop 启动”代替具体来源。

地址只使用当前监听事实。存在待重启配置时另列“待生效设置”，不要把预期地址显示为当前可访问地址。
需要其他机器访问时说明非本地开关和网络条件，不自动猜测公网 IP 或承诺访问可达。

### 3.2 config 结构

进入 config 先显示 Home、Host 状态、当前连接模式和保存边界，然后展示根菜单：

```text
本机 Host 配置
目标目录  /home/alex/.ez-assistant
Host      业务就绪 · 在线配置

选择配置范围
❯ Host 访问设置
  启动设置
  退出配置

↑↓ 选择 · Enter 确定 · Esc / Ctrl+C 取消配置
```

Host 访问菜单：访问密码、非本地访问、监听端口、协议与证书、允许的 IP 或域名、查看预览、
保存访问设置、返回。沿用原型字段组织；使用明确的“返回”菜单项导航，不将 Esc 同时定义为返回。

启动菜单：查看实际状态、开启／关闭开机自启、更新注册的 Host 来源、返回。
没有注册时不展示“更新来源”；macOS 或平台条件不可用时展示原因，禁用不支持的提交动作。
启动设置不加入访问草稿的统一保存按钮，密码也有自己的独立保存步骤。

### 3.3 config 模式与可操作范围

| 当前事实 | 访问设置 | 启动设置 |
| --- | --- | --- |
| 兼容且 Ready | 在线读取／保存 | 按平台实际能力查询与配置 |
| 已确认无活动 Host | 离线读取／保存；没有文件时显示默认值 | 按平台实际能力查询与配置 |
| Starting／Unavailable | 显示阶段或失败原因，禁用访问编辑；提示等待或显式停止后重新进入 | 仍可查询和关闭自启；其他动作须通过独立平台预检 |
| 版本不兼容 | 显示双向要求，禁止访问命令和离线写入回退 | 独立查询和关闭自启不受应用兼容失败阻止；不借此切换或停止活动 Host |
| 认证、发现、TLS 或目录状态无法核实 | 显示错误，禁止当作离线首次初始化 | 只能显示能独立核实的系统事实；来源或权限不明时禁止覆盖 |

重读是用户显式动作。在线／离线切换或配置冲突后不自动重放保存请求；重新进入配置先取得
真实现状，再由用户重新输入或预览确认。

## 四、交互流程

### 4.1 首次使用与 Web

1. 运行帮助了解命令；通过 `config → Host 访问设置 → 访问密码` 独立保存密码。
   普通 Web 登录在本机也需要密码；仅使用原生 Client 管理 Host 时可以暂不设置。
2. 仅本机访问保留关闭非本地访问、默认端口等设置。需要其他设备访问时，已有密码后显式开启。
3. 执行 start，业务 Ready 后输出当前地址及访问范围；start 不自动开浏览器或开启自启。
4. 执行 web，使用实际运行地址打开普通 Web 登录页，登录后沿用已有模型管理与 Agent 使用流程。
5. Linux 需要开机启动时再进入启动设置；开启后如需立即使用，另行执行 start。

web 不自动启动 Host。Host 尚未启动、未 Ready、不兼容或诊断失败时返回 1，给出对应下一步。
未设置密码时保留当前地址，提示先运行 config 设置密码，不打开无法登录的页面，返回 1。
密码判断来自受认证的 Host 状态，不试登录、不获取或打印密码。

无浏览器／无图形会话或浏览器调用失败时，保留已核实的登录地址并提示手动打开；地址交付成功
返回 0，但不显示“浏览器已打开”。系统接受打开请求时写“已请求浏览器打开”，不声称登录成功。
服务器 loopback 地址标注“仅此服务器本机”；非本地访问关闭时给出 config 设置路径。
不传递原生凭据、登录 token 或免登录 URL，不新增远端地址配置。

### 4.2 start、status、stop 与 restart

| 操作 | 等待与完成反馈 | 失败或竞争反馈 |
| --- | --- | --- |
| start 已有 Host | 发现 → 校验 → 等待已有初始化；Ready 显示“已复用现有 Host” | 不兼容立即失败；Unavailable 显示已有诊断，不启动第二份或再次迁移 |
| start 无 Host | 明确本次使用随包 Host 或已启用的服务来源，等待真实 Ready | 服务启动中等待已有操作；无权启动／端口占用／存储拒绝分别说明，不改端口或来源补救 |
| status | 一次查询，区分未启动、初始化中、业务就绪、初始化失败；不持续轮询 | 状态未知或必要诊断失败明确标注，不将其显示成“未启动” |
| stop | 先打印共享影响；受控停止后，确认原实例及所属服务已停止，再显示成功 | 已停止为无操作成功；期间出现新实例则说明目标变化、返回 1，不继续停止后继实例 |
| restart | 预检当前来源 → 受控停止 → 从原来源启动 → Ready；逐阶段输出 | 未启动时提示 start；缺失／变化的来源在停止前失败；停止后启动失败必须说明已停止，不能假装恢复 |

启动不显示虚构百分比，只显示 Host 已提供的真实初始化阶段。service active、PID 存在或端口
监听均不等同于业务就绪。服务开机启动失败和手动启动失败沿用同一诊断语义。

```text
$ ez-assistant restart
目标目录  /home/alex/.ez-assistant
注意：将停止共享 Host，所有客户端连接与运行中任务都会受影响。
重启来源  /opt/ez-assistant/0.25.2/host/ez-assistant-runtime
✓ 原 Host 已停止
✗ 新 Host 未能就绪：监听端口已被占用
结果：原 Host 已停止，本次重启未完成。
下一步：核对端口占用后显式执行 start。
```

成功停止服务后补充“开机自启仍开启”或“开机自启已关闭”，依据实际值输出。
restart 保持原管理方式与来源；服务 disabled 时重启当前服务也不重新启用开机自启。

### 4.3 访问草稿、预览与保存

编辑仅改变本次内存草稿，已保存值与待保存值分开。进入和只读预览不创建 Home、配置或数据库。
预览按字段列出“当前 → 修改后”；值未变化时显示“访问设置没有变化”，不发送写请求。

```text
访问设置预览 · 尚未保存
监听端口  7240 → 8240
访问范围  仅本机（不变）
生效方式  已运行 Host 需显式重启，当前地址保持 http://127.0.0.1:7240/

保存这些访问设置？  是 / 否
```

确认保存默认选择“是”，选择“否”返回草稿。执行期间禁用重复提交，先校验、再保存、再回读；
收到写入成功但回读失败时说明“已提交，当前生效状态未核实”，不能当作未保存自动重试。

| 项目 | 输入和保存反馈 |
| --- | --- |
| 非本地访问 | 默认关闭；未设置密码时给出密码入口，不代替用户设置密码或自动开启 |
| 监听端口 | 1–65535 整数；格式即时提示，端口可用性由 Host 预检；保存不保证下次启动仍可占用 |
| 协议与证书 | HTTPS 要求本机 Host 可访问的证书和私钥绝对路径；最终校验由 Host 完成，错误保留草稿供修正 |
| 允许的 IP 或域名 | 逗号分隔，最多 16 项；接受 IPv4、IPv6（可带方括号）、localhost、大小写和国际化域名；不含协议、端口或路径。仅用 IP 时也可留空；经转发访问 localhost 时仍须登记该域名 |
| 在线生效 | 非本地开关及域名即时生效；监听端口、协议和证书保存后待重启；只对已核实结果标记生效 |
| 离线生效 | 回读成功后显示“已保存，供下次启动使用”；不显示已监听，不启动业务或迁移数据库 |

在线非本地访问已开启时，监听字段显示受限原因和操作顺序：关闭非本地访问并保存 → 修改监听
并保存 → 退出 config 后显式 restart → 再进入 config 开启非本地访问。草稿里改为关闭尚未
提交时仍不可修改监听，不将数步操作合并成一次隐藏的启停流程。

配置冲突后保留草稿用于查看，但停止保存；显示“配置已被其他入口修改，请重新读取后确认”。
重读当前配置需要明确告知将丢弃该访问草稿，默认取消；不自动合并或替换 revision 重试。
离线编辑期间 Host 启动，返回同样的重读路径，不在后台切换为在线提交。

### 4.4 密码独立保存

输入新密码 → 再次输入 → 确认影响 → 独立保存 → 回读结果。输入遮罩，不回显原文、哈希或长度；
提示“不能为空或全空白，最多 1024 字节”，中文按 UTF-8 字节校验，不自动 trim 密码内容。
两次不一致时在第二次输入处修正；不增加显示密码按钮、命令行密码参数或持久草稿。

确认提示：“保存新密码后，已有普通登录将失效。其他访问设置仍需单独保存。”默认“是”；
用户选择“否”不修改密码。成功后显示“密码已更新，已有普通登录已失效”，当前其他访问草稿
继续保留，但重新读取配置基线，下一次保存需重新预览。

若密码保存期间其他配置也变化，按配置冲突处理，不以密码操作为理由静默覆盖。
结果不明时提示重新读取，不重新提交密码；后续取消访问草稿不会撤销已保存密码。

### 4.5 Linux 自启设置

启动设置首先展示：本机支持情况、开机自启、当前运行状态、运行用户、Home、注册 Host 来源，
必要时展开 unit 和最后失败原因。终端状态标签如下，不持久保存一份 Client 开关副本：

| 标签 | 显示条件 |
| --- | --- |
| 未配置（默认关闭） | 确认本 Home 无注册；不能从读取失败推断 |
| 已关闭 | 已有注册且实际 disabled；当前服务可能仍运行 |
| 已开启 | 实际 enabled、来源吻合、linger 可用；当前 Host 是否就绪另行展示 |
| 未完成／状态未知 | 部分操作失败、必要条件缺失或回读失败，分别列出已知与未知事实 |
| 本平台暂不支持／暂不可用 | macOS 不提供自启；Linux 无 systemd 用户管理器等条件时说明具体原因，保留手动管理路径 |

首次注册使用当前 Client 安装中固定版本的随包 Host，预览明确列出它与当前运行 Host 的来源。
已有注册保持其来源，不因 Client 新安装或升级自动改绑。注册不代表数据库已经通过准入，
下次真实启动仍执行存储检查。

开启流程：

1. 查询实际平台和来源，形成预览：运行用户、Home、Host 路径与软件版本、开机自启及 linger 变化。
2. 显示“只配置下次开机启动，当前 Host 保持现状”，默认选择“不开启”，由用户明确提交。
3. linger 未开启时说明“需要允许此用户在未登录时运行服务”，列出系统将执行的动作。
   通过操作系统权限机制处理；SSH 无法授权或系统拒绝时给出管理员操作和未完成状态。
4. 回读各项，全部满足后显示已开启；已有手动 Host 继续运行，不自动转交服务。

关闭流程：预览目标 → 默认选择“不关闭” → 明确提交 → 回读 disabled。
文案说明当前运行 Host 保持现状，当前用户已有 linger 保留。关闭可以在 Host 未运行、初始化
失败或版本不兼容时独立进行，但不能覆盖无法核实来源的 unit。

更新来源只在启动设置中显式执行，预览旧／新版本与完整路径，默认取消。有活动 unit 时提示先
显式 stop 后再配置；不自动停机。更新后保留原开关状态，不自动 start。手动实例转为服务管理
同样需用户显式 stop → start，不增加“保存并重启”按钮。

```text
✗ 开机自启配置未完成：无法确认用户的 linger 状态
服务文件  已写入
开机启用  已启用
未登录运行条件  未知
当前 Host  仍为手动运行
下一步：核对系统权限后重新进入“启动设置”读取实际状态。
```

失败后逐项显示实际结果，不自动撤销其他服务的 linger，不将部分成功写为全成功或全未修改。
关闭、来源变更和 linger 的真实操作顺序及冲突处理以技术方案第七节为准。

### 4.6 返回、退出、超时与取消

| 用户动作／阶段 | 结果 |
| --- | --- |
| 在访问菜单选择返回／退出且无草稿 | 返回根菜单或结束 config；正常结束返回 0 |
| 选择返回／退出且有草稿 | 询问是否放弃未保存访问设置，默认“继续编辑”；明确放弃后再导航，不撤销已独立保存项 |
| Esc／Ctrl+C，尚未提交 | 取消整个 config，丢弃未提交内容并返回 130；不追加确认对话，提示哪些独立操作此前已保存 |
| 取消 start／stop／restart 等待 | 停止 Client 等待并返回 130；已提交 Host 操作继续，给出 status 查询方式，不声称 Host 已停止或操作撤销 |
| 普通命令等待超时 | 返回 1，说明最后已知阶段与“结果待查询”；不自动重发写请求、重启或切换来源 |
| 密码／访问配置已提交后取消 | 停止交互输入，等待已有有界提交收敛并回读；离线 helper 等待上限沿用 15 秒，不强杀原子保存 |
| 服务提交期间取消 | 不再开始后续提交步骤，等待当前短步骤收敛并释放提交锁；回读能确认的事实，不能统称已撤销 |

所有取消最终恢复光标、输入模式与终端颜色。提交结果未知时明确提示，返回 130 不表示事务
回滚；关闭终端或 SSH 中断后重新执行 status／config 查询。已成功保存的密码、自启开关和
访问配置分别列明，绝不输出“全部修改已撤销”。

## 五、终端视觉与组件规范

- 沿用原型的 Commander、Clack 提示组件、Ora 动画与 Picocolors；不引入全屏 TUI。
  交互流程与终端库保持私有实现，不能把组件状态传给 Host 或作为共享协议字段。
- 中文短句、短标题，以“成功／注意／失败”等文字和符号共同表达状态，不能只依赖颜色。
  成功绿色、提醒黄色、失败红色、次要信息弱化；尊重 NO_COLOR、TERM 和终端能力。
- 一次只显示一个输入或选择；Clack 负责提示、Ora 负责进行中状态，不同时播放两个 spinner。
  每步结束保留一条结果，取消／错误输出以终态收束；重定向不输出动画控制符。
- 80 列使用纵向键值排版，48 列按文字显示宽度换行；路径、域名与 URL 可换行但不能裁掉
  关键值，尤其预览、来源变更和错误时必须能获得完整路径。窄终端不强行使用多列表格。
- 返回、保存和退出文案始终包含动作对象；未保存项用文字标记，不将保存密码或服务设置
  混称为“保存全部”。交互确认默认值按第四节，不沿用组件默认值猜测。
- 密码、token、证书／私钥内容不进输出。文件路径、Home、版本和失败阶段只在有助用户决定
  下一步时展示；对外部错误文本中的控制字符做安全显示，不能作为 ANSI 控制指令执行。

## 六、状态、异常与退出码

| 退出码 | 意义与边界 |
| --- | --- |
| 0 | 命令目标完成或查询成功；status 查到未启动／Starting／Unavailable 仍是成功查询，不能拿退出码当 Ready 探针；stop 已停止为成功 |
| 1 | 业务／连接失败、版本不兼容、超时、状态无法核实、restart 未启动、web 缺少登录条件等 |
| 2 | 命令用法错误、非法参数、config 不具备交互终端条件 |
| 130 | 用户取消，描述已发生的副作用或未知结果，不表示回滚 |

config 内部可修正的输入或保存失败留在交互中，不立即退出；正常退出为 0，用户取消为 130。
不可恢复且无法继续配置的失败返回 1；状态页不得用正常退出掩盖先前未完成操作，离开前保留结果。

| 异常 | 必须说明 | 可给出的下一步 |
| --- | --- | --- |
| 双向版本不兼容 | 当前 Client／Host 软件版本、双方要求及未满足方向 | 使用兼容版本；不自动停旧 Host、降下限或切换随包版本 |
| 旧端缺少兼容声明／声明非法 | 无法验证兼容性，当前操作未执行 | 使用可声明兼容性的版本；不将未知当兼容 |
| 数据库准入失败 | Host 软件版本及已知最低要求、实际启动失败阶段 | 使用兼容 Host，保留数据；不提供删库或自动修复快捷入口 |
| 来源缺失或已变化 | 路径及当前处于停止前／停止后的哪个阶段 | 恢复来源或按明确产品升级流程操作，不改用当前 Client 的其他 Host |
| 配置冲突／离线变在线 | 原草稿未提交，当前正式配置保持真实状态 | 显式重读、重新编辑和确认 |
| TLS、目录权限、端口占用 | 脱敏原因与可定位的字段／路径／端口 | 修改相应配置或系统条件，不关闭认证与证书校验 |
| 请求回执丢失、状态未知 | 哪一步已提交、哪些状态未核实 | 只读查询，不重放密码或重启操作 |
| 服务部分失败 | unit、enabled、linger、当前运行各自的已知事实 | 从实际状态继续，不自动覆盖或伪造关闭状态 |

Desktop／Web 沿用既有连接错误位置展示兼容失败；缓存旧 Web 页提示刷新以加载当前版本，
不自动提交草稿。Desktop 的关闭窗口、退出客户端和停止 Runtime 仍是三个动作；本版不因
Client 自启设置而新增桌面常驻代理。智能终端 Device Gateway 的版本交互不在本稿范围。
