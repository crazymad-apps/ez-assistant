## 二、台账与实施原则

1. 按 M0—M8 顺序推进。各项完成实现和验证后标记 `🟨 待确认` 并停止汇报；用户确认后标记
   `✅ 已完成`，取得下一里程碑授权再继续。计划确认不等于全部里程碑自动获批。
2. M0 完成实施前交互与验证条件准备；M1—M6 为实现及定向验证；M7 为版本验收；M8 为归档。
   第一个代码里程碑开始前改为 `开发中`，进入 M7 改为 `验证中`，用户确认验收且 M8 完成后才记为 `已完成`。
3. 发布版本提升、版本常量生成和数据库同版本 manifest 入口在 M1 一起落地。现有迁移器要求
   manifest 末项等于软件版本，不能先孤立提升 Cargo／应用版本，留下无法正常初始化的中间构建。
4. M2 一次同步应用协议生产者及 Desktop／Web 消费者，再由正式 Client 接入。中间构建只用于
   隔离验证，不当作可发布版本；不为未发布的中间协议保留旧字段、兼容别名或第二套状态。
5. Host 持有实例、配置和数据库的权威状态；Client 负责用户命令及平台适配。共享协议与构建任务
   不放在 Client 私有工程内；Host、Desktop 和服务运行不依赖 Client 入口、Node 或私有文件。
   每个相关里程碑 Review 此边界，M6／M7 以 A23 验证。
6. 所有 Host、配置、升级及卸载验证使用显式临时 Runtime Home、人工构造数据库和隔离安装目录。
   不默认读取、复制或启动用户 `~/.ez-assistant`／`.ez-assistant-dev`；实际数据库操作仍须遵守
   根 AGENTS.md 的核对、确认、备份和验证规则，本计划不代替数据库操作确认。
7. 系统服务验证使用专用 Linux 用户及实机／VM，核对 UID、Home、unit 和安装来源后操作。
   真实 Provider 验证仅使用已授权的测试连接，凭据不进入产物。条件缺失记为未执行和阻塞范围，
   不能用本机 macOS、容器或 Mock 替代开机、其他架构和真实产品验收。
8. 先执行直接覆盖改动的静态检查和必要定向验证；完整回归集中在 M7。已有结果未受后续改动影响时
   不重复扩大测试。过程、命令结果、偏差、遗留和风险只记入本地进度。
9. 同步受影响模块约束，保留已有工作树。Demo 在 M8 才删除；不自动提交、推送或公开发布。

## 四、里程碑明细

### M0：交互定稿与实施条件

**目标：** 在写正式代码前，将原型和已讨论的真实行为整理为可直接实施、可核验的交互基线。

**前置依赖：** 本计划已确认，用户授权进入 M0。

**交付范围：**

- 形成 `docs/design/v0.25.2-界面交互设计指导.md`，以现有原型为基础，补全真实连接／兼容失败、
  Starting／Unavailable、在线／离线 config、独立密码保存、自启状态、超时／取消及无浏览器反馈。
  访问设置、当前 Host 运行状态和开机启动设置分别呈现，落实非 TTY、窄终端和退出码。
- 核对技术方案中的固定 Node 与依赖组合、首批平台构建条件、v0.25.1 实际旧程序来源、
  Linux systemd 实机／VM、测试用户和 macOS 分发校验条件；记录每项可用性及后续取得方式。
- 明确独立构建和隔离测试入口，核对共享协议生成的实际消费者；不创建通用 SDK、常驻控制进程
  或替代 Client 框架，也不提升软件版本或启动实际 Host。

**验证入口：** 交互状态对照原型与功能设计逐项走查；检查文档链接、范围和验收映射。
依赖版本核查使用官方发布信息，不能把原型的 Node 22 验证当成随包 Node 24 验证。

**完成判定：** 交互指导可供评审，关键失败与取消分支无遗漏；平台及旧端验证条件清单明确，
影响选型或交付范围的缺口已报告。汇报并停止，M0 确认后才进入代码实现。

**Review 重点：** 普通命令保持命令式，只有 config 交互；自启不会被误解为立即启停；
本版范围没有扩展到智能终端协议或远端 Client 管理。

### M1：发布版本与数据库兼容保护

**目标：** 新版 Host 在任何业务写入前拒绝不安全的数据库，并保持现有升级和备份能力。

**前置依赖：** M0 已确认；具备人工新旧库夹具与隔离升级验证条件。

**交付范围：**

- 按[技术方案第四、八节](技术方案.md)同步软件版本、应用最低版本的发布源与常量生成，
  以及 v0.25.2 数据库 manifest 入口；本阶段不切换应用请求准入。
  版本校验按当前构建目标执行，不要求尚未创建的 Client 工程存在。
- 落实数据库独立下限、只读预检和启动诊断；保留高版本账本拒绝、已知旧库分类、备份验证、
  分版本事务和失败停止。下限与对应迁移原子提交，不在每次启动时覆盖。
- 覆盖预检前写入、损坏／缺失元数据、非法账本、WAL／热日志、迁移中断与旧 Host 回退，
  不增加修复命令或自动恢复用户库。

**验证入口：** Host storage／migrations 定向用例、协议常量生成检查及最小构建；隔离进程验证
不兼容拒绝前数据库及伴随文件未变。迁移夹具核验独立备份存在、可读、关键表精确数量和字段，
故障注入检查事务结果；实际 v0.25.1 Host 针对升级后的人工库回证已有高版本拒绝行为。

**完成判定：** A09–A10 的存储保护证据齐全，新库／已知旧库可按预期初始化或升级，非法与
过高版本库在写前失败；软件版本和 manifest 一致。无法取得旧二进制时，该项保持未验证并报告。

**Review 重点：** 预检不能隐式触发 journal 恢复、FTS 或模式切换；数据库下限与应用下限独立，
Client 内部技术变更不触发迁移；Host 的独立构建没有 Client 前置依赖。
