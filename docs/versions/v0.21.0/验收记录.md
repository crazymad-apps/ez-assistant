## 四、功能与跨层证据

### 4.1 Host、Gateway 与设备身份

- HostSupervisor 统一管理正式 Runtime、HTTP/SSE、Device Gateway 与 SpeechService 生命周期；
  关键、可降级和单连接故障保持分级，不把在线连接或媒体状态复制进 Runtime 权威业务状态。
- Device Gateway 形成 mDNS 发现、候选配对、六位配对码、SPAKE2、Ed25519 长期身份、WSS、心跳、
  重连、撤销、能力协商和有界背压闭环；长期身份只在人工验证配对成功后生成并持久化。
- Rust Host 与 Node 继续共享严格 JSON envelope、认证和 PCM fixtures；认证破坏、非法输出偏好、
  PCM sequence 错误和离线撤销均在正式对端链路中 fail-closed。

### 4.2 统一会话输入与输出路由

- Desktop 与已认证 Device 由 Host Channel Adapter 注入可信来源，统一进入 Session 顶层输入用例；
  Device 仍由 Host 产品策略路由到当前主控，但 Runtime 不再把顶层能力写死为 Controller。
- 所有显式输入与最终 Assistant Output 只进入既有 Conversation；Desktop 强制保留完整正文，
  Device、未来移动端或 IM 只是零到多个附加投递渠道。
- 输入来源优先于 PC 输出托管；Desktop 输入可托管到在线终端，设备来源请求冻结本轮合法输出偏好；
  解除配对同步解除托管。来源和投递失败不改变规范 Conversation 事实。
- Goal 自动推进、上下文变化、压缩和缺失播报提醒统一为同一产品 Run 内的多个 AgentExecution Loop；
  Run ID 与生命周期唯一，Step 和预算跨 Loop 累计，不再创建后继 Input、Run、Queue 或 continuation 表。

### 4.3 语音、播报与抢占

- 正式 PCM16/16 kHz/mono 上行由 Host 聚合，ASR 位于 Host SpeechService；ASR/TTS 使用平行 SPI，
  首个 Adapter 为 DashScope。配置或单项 Provider 不可用时不影响 Runtime 与文字交互。
- `speak` 支持最多 20 段有界 FIFO、自然分段和段间气口；H5 通过 AudioWorklet、预缓冲和同一播放
  时间轴消费下行 PCM。缺失播报只在本 Run 结束门禁内提醒一次，不伪装成真实用户输入。
- 正式 M8 E2E 以真实 Host、mDNS、WSS 和 fake Model/ASR/TTS 验证：两段连续语音经 2 秒窗口
  聚合后只提交一次 Runtime Input；收到 3 次 segment acknowledgement，跨 WSS 重传去重；PTT
  能取消活动 Run、中止尚未完成的 TTS 并抑制迟到播放。

### 4.4 Desktop、H5 与真实终端

- Desktop 设置页提供接入启停、候选配对、设备详情、重命名和解除配对；主控输入框保留唯一频道
  托管入口，菜单只显示 Desktop 和在线目标。用户消息来源位于消息下方，可打开详情，不污染正文。
- Node/H5 模拟终端覆盖文字输入、浏览器录音、PCM 上行、播放、播放取消、能力形态切换、协议监控和
  故障注入；H5 只通过 Node loopback bridge 操作正式设备对端，没有直连 Runtime Command/SSE。
- 用户已完成与 `agent-robot` ESP32-S3 正式终端的 S3.1 联调。`agent-robot` compatibility manifest
  记录 firmware implementation `b6992531e6e4495dfeccf249077a370db38be3d2`、archive
  `c847fc67e49f32e68eddcef5dc913451499e0668` 及 ez-assistant 最终工作树关键源码哈希。

## 五、故障、恢复与数据边界

- Runtime/Host 自动化覆盖旧 schema、设备与托管重启恢复、Host 重启、子系统降级、Store 故障、
  有界关闭、活动 Run 同 Loop 续跑、Goal 恢复和不补播旧输出；失败不会重放历史工具副作用。
- 配对候选、在线连接、心跳、音频流和播放状态只存在于 Host 易失状态；设备注册、来源、托管、
  Conversation 和投递事实仍由 Runtime/Store 持有。
- 语音聚合按 Device ID 跨 WSS 连接保存，分段确认与最终 Input 接受分离；Host 进程重启可以放弃尚未
  形成 Runtime Input 的聚合轮次，不伪造已接受事实。
- 全部自动化使用 `TempDir`、内存 Store 或隔离 Runtime Home；未读取、迁移或写入用户实际数据库。
- device protocol 1.0 三份 fixture SHA-256 未漂移。最终 Release Host SHA-256 为
  `48d7efba12a3cad091fb534dced2633cc6749b7b9d56f20282bc9fe2e9f60229`，兼容清单反向逐项核验通过。
