### M0 Host 运行框架

- 目标：建立 HostSupervisor、受控启动/关闭、子系统故障等级和任务回收框架，同时保持既有
  Desktop HTTP/SSE 与 Runtime 行为不变。
- 影响模块：`apps/runtime-host`
- 状态：✅ 已完成
- 实际结果：
  - Code review 补充收口：主控 `send_session_message` 增加必填 `start_goal`，可在目标普通 Session
    原子接受 `ControllerDelivery` Input、首次 Run 与 Goal。跨会话元数据收敛为
    `CrossSessionInputEnvelope { binding, reply_route }`，不再在 `ControllerDelivery`、`ProxyReport`
    两个来源 variant 中重复字段；首次 Goal binding、隐藏 continuation 和最终代理报告保持同一
    回复路径。本版本尚未发布，不保留开发阶段旧字段名或旧 JSON 形状兼容。
  - 新增 Host 私有 `HostSupervisor`，统一持有根取消令牌、子系统 child token、`JoinSet`、关键/降级
    故障策略和 15 秒 Host 子系统关闭 deadline；connection 短任务明确留给所属 transport/Gateway 管理。
  - Desktop HTTP 作为关键子系统进入 Supervisor；Ctrl-C 改由观察循环直接等待，不再创建并 abort
    临时信号任务。HTTP Host Command 使用根令牌请求整体关闭。
  - HTTP 子系统停止并释放 endpoint 后，由主编排无条件调用 Runtime shutdown；Supervisor 与 Runtime
    shutdown 同时失败时保留两侧诊断，没有复制 Runtime/Store 的任务和业务状态。
  - 新增 7 个 Supervisor 测试，覆盖正常取消回收、信号观察失败、关键故障、可降级故障、意外
    正常退出、panic 和 deadline abort。
  - `cargo test -p assistant-runtime-host`：151 个单元测试通过、1 个手工性能用例忽略；16 个离线正式
    Host 集成测试通过；15 个真实 Provider/计费用例按既有约束忽略。
  - `cargo clippy -p assistant-runtime-host --all-targets --all-features -- -D warnings` 通过；
    `cargo run -p assistant-runtime-host -- --help` 通过。

### M1 Runtime 设备与渠道领域

- 目标：在唯一 Session/Conversation/Run 中建立设备稳定事实、通用 Channel 输入来源、输出周期、
  零到多个附加 delivery 和 PC 输出托管，不建设第二套消息或投递存储。
- 影响模块：`crates/assistant-runtime`、`crates/assistant-protocol`、`apps/runtime-host`
- 状态：✅ 已完成
- 实际结果：
  - 新增 Runtime 稳定设备 Registry、paired/revoked 生命周期、重命名/撤销、DevicePublicKey 和
    Controller PC 输出托管；设备稳定变更由独立 mutation gate 串行化，撤销与解除托管保持原子。
  - 通用 `InputChannelSource` 进入既有 Input/Run/Conversation：Desktop 固定 Text/Text，Device 保存
    稳定 Device ID、client input identity、Text/SpeechTranscript 和本轮输出偏好；没有增加 Device
    Conversation、Reply Store 或第二套消息正文。
  - Host 私有 Session Channel 入口只接受已配对 Device，并由产品策略解析当前 Controller；Runtime
    派生幂等键，Runtime/Store 双重复核授权，重复设备请求复用首次 Input/Run。
  - 输出周期只保存来源 Input 和播报/补齐状态，Goal continuation 继承；逻辑周期结算后形成
    零到多个 `ChannelDelivery`，Device 来源优先、Desktop 按结算时 PC 托管、ProxyReport 按冻结依据。
    Dispatcher 失败不改写已结算 Run/Conversation，未增加投递持久表或 candidate revision。
  - SQLite 增量增加 `devices`、`sessions.pc_output_device_id`、`inputs.channel_source_json` 和 Goal
    报告返回依据；旧 User Input 缺省 Desktop Text/Text，旧 Runtime Input 无外部来源。设备重命名从
    Registry 解析当前名称，撤销保留历史 Input 来源。
  - 公共协议增加 DeviceId、Desktop/Device Conversation 来源、PC 托管投影及显式设置命令，并重新
    生成 Desktop TypeScript 绑定；Gateway 在线、capability、配对候选和媒体状态仍未进入 Runtime。
  - M1 复核期间将 1386 行的 Host storage worker 按 `command`、`client`、`thread` 拆分；保留单一
    阻塞线程与有界队列，并以私有 `request` 方法收敛 65 处重复的 oneshot 请求适配，不改变 Store
    trait、StorageEngine、SQL、事务或关闭语义。
  - `cargo test -p assistant-protocol`：32 个测试通过；`cargo test -p assistant-runtime`：233 个测试通过。
  - `cargo test -p assistant-runtime-host`：153 个单元测试通过、1 个手工性能用例忽略；16 个离线正式
    Host 集成测试通过；15 个真实 Provider/计费用例按既有约束忽略。
  - TypeScript 协议导出检查、三 crate 全 targets/features clippy、Desktop `npm run build` 均通过。
- 当前步骤：已按用户确认进入 M2。
- 续作点：M2 接入安全 Gateway、配对、长期认证与 Node 基础模拟器。

### M2 安全 Gateway 与基础模拟器

- 目标：建立可供真实终端复用的 mDNS/WSS 发现、配对、长期认证、能力协商与 Node/H5 基础对端。
- 影响模块：`apps/runtime-host`、`crates/assistant-protocol`、`tools/device-simulator`、开发文档与共享 fixture。
- 状态：✅ 已完成
- 实际结果：
  - Device Gateway 作为 HostSupervisor 的 `Degrade` 子系统接入；默认关闭，启用后生成私有安装
    TLS 身份、动态 WSS listener 与 `_ez-assistant._tcp.local.` mDNS 宣告。启动、刷新、自然过期、
    listener 异常和关闭都有明确状态收敛与资源回收。
  - 落地 64 KiB 严格 JSON envelope、消息重放窗口、heartbeat、单设备连接替换和稳定错误码；
    M2 只开放真实可用的文字/显示能力，不接受业务输入或 PCM。
  - 配对严格按“候选→Desktop 输入八位码→RFC 9382 SPAKE2 双向确认→设备生成 Ed25519
    长期密钥→bind commit→Runtime 登记”执行；配对窗口 5 分钟，同 request 最多 5 次尝试。
  - Host Command 提供接入启停、配对窗口、候选确认、重命名、撤销和组合快照；配对码使用
    `SecretValue` 脱敏，pending/连接状态仍只存在 Host，稳定设备记录仍只存在 Runtime/Store。
  - 新增 Node 24 `tools/device-simulator`：通过 mDNS 发现、原始 DER SHA-256 TLS pin、正式 WSS codec
    和重连状态机运行；H5 仅通过带动态 token/Origin/Host 校验的 loopback 桥交互与监控。
  - Rust/Node 共享 fixture 覆盖 RFC 9382 P256 SPAKE2、确认 MAC、认证 challenge transcript、
    Ed25519 签名、严格 envelope 和基础错误码。
  - 隔离端到端验证使用 `/tmp/ez-assistant-m2-e2e.MiA9RT` Runtime Home 与
    `/tmp/ez-assistant-device-simulator.Gefgi0` 模拟器 Home：Node 通过 mDNS 发现 Host，H5 发起配对，
    Host Command 确认后登记 1 个临时设备；验证长期认证重连、新连接替换旧连接、撤销通知、
    模拟器清除本地凭据与旧身份不可再认证。未读写用户实际 Runtime Home 或数据库。
  - `cargo test -p assistant-runtime-host`：159 个单元测试通过、1 个手工性能用例忽略；16 个离线
    正式 Host 集成测试通过，15 个真实 Provider/计费用例按既有约束忽略。Protocol 34 项、Runtime
    233 项通过；三 crate clippy、Rust fmt、协议导出和 `git diff --check` 通过。
  - 在 Node `v24.18.0` 下 `npm run typecheck`、`npm test`（3 项）、`npm run lint`、`npm run build`
    全部通过。
- 当前步骤：用户已通过“继续开发”确认 M2，现进入 M3。
- 续作点：M3 在已认证 Device WSS 上接入文字输入、唯一 Conversation 与零到多附加投递。
- 里程碑确认：用户于 2026-08-28 通过“继续开发”确认
- 遗留/风险：M2 不包含 Desktop 设备管理界面、业务文字输入或语音链路；设备接入默认关闭，
  当前由 Host Command 控制本进程启停，Desktop 设置展示与是否持久用户偏好在 M4 交互落地时再根据产品行为确定。

### M3 文字交互与回复路由

- 目标：在正式 Device WSS 上打通文字 Input、唯一 Controller Conversation、可靠幂等接受与附加
  Device 文字投递，不引入语音、Desktop 管理 UI 或第二套回复事实。
- 影响模块：`apps/runtime-host`、`crates/assistant-runtime`、`tools/device-simulator` 与模块文档。
- 状态：✅ 已确认
- 实际结果：
  - 已认证连接新增严格 `text_input`、`input_accepted`、有限 `state_changed` 和 `text_output`；Device ID
    来自认证 owner，设备 payload 不能选择 Session 或目标设备，非法能力/偏好在进入 Runtime 前拒绝。
  - Host 通过 Runtime 窄路由查询解析当前 Controller，再调用通用 Session Channel Input；提交时 Runtime
    再次核对 Controller 与 paired Device，相同 Device/client identity 重试返回首次 Input/Run。
  - 正式 Host 注入 `DeviceChannelOutputDispatcher`；Dispatcher 以弱引用绑定 Gateway，逐条读取当前在线
    连接、协商能力和偏好后用有界队列派发，不保存 delivery、正文、connection ID 或离线队列。
  - 来源 Device 使用 Input 冻结偏好并优先于 PC 托管；Desktop/默认代理报告继续按结算时托管形成附加
    delivery。断线、能力不足、背压或无 Assistant 正文只产生易失错误/脱敏诊断，不改写 Run/Conversation。
  - Node/H5 增加正式文字发送、同一 client input ID 重试、Input/Run/Queue 状态和文字回复监控；H5
    仍只操作 Node loopback bridge，没有接入 Runtime Command/SSE。
