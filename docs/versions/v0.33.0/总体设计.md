## 二、最终目标与成功标准

一个企业中心可以服务多个机构，各机构独立维护插件、智能体、模型与设备授权，用户和设备不会跨机构获得资源或权限。企业用户既能按机构策略选择模型，也能在自己的 Runtime 用户域配置并使用个人模型。

插件能够在消息流提供交互卡片，与右侧资源栏浏览器中的插件内置应用或外部 HTML 页面通过宿主桥接联动；页面自主组织业务，Agent 不负责管理应用实例或中转交互。卡片重载后恢复最近一次成功保存的展示和交互状态；插件仍拥有业务语义及实际操作结果。

成功标准是同一账号在两个机构中分别进入独立业务域、使用同名模型、智能体和插件可同时使用且互不串用；模型来源可明确选择与恢复；卡片和侧栏真实联动且恢复不重复执行业务。完成各 Feature 后，还须跨 Feature 联合验收。

## 三、范围与非目标

### 纳入范围

1. 机构生命周期、全局登录后选择机构、系统／机构权限、现有业务入口和后台任务的完整机构隔离，以及历史数据归属和配套升级。
2. 机构可用模型集合、默认模型和自主选择策略；企业用户个人服务商、密钥与模型；按会话双来源选择、执行重验和失效反馈。
3. 插件声明的卡片和应用入口、`publish_card` 工具、消息位置、隔离渲染、右侧资源浏览器承载内置／外部 HTML 页面、宿主通信及最新快照保存与恢复。

### 明确不做

- F04 构建品牌与首次交付定制：名称、Logo、品牌文案和默认 Runtime Home 的打包定制暂时废弃，本期沿用现有构建与交付能力。

- 机构自助注册／删除、组织间业务数据搬移、部门层级、SSO、计费套餐及通用细粒度 RBAC。
- 跨机构设备共享、平台公共模型／插件共享覆盖层、每机构独立数据库／中心进程、多实例中心与第二套登录体系。
- 个人密钥上传中心、个人模型自动跨设备同步、将中心调用统计宣称为包含个人直连调用。
- 插件统一业务对象、业务历史版本、通用业务状态机，或把 MCP 作为轻量卡片的必需依赖。
- 机构后台在线品牌编辑、机构自行发布安装包、品牌专属发行渠道、不同品牌并行安装、旧 Runtime Home 自动搬移／合并／回退读取。

以下为设计启动时核对的源码基线，不代表最终实现或线上状态；交付结果见版本开发计划。

| 现有实现 | 本版需要补足的边界 | 复用与新增依据 |

| `models/service.ts` 代理准入检查普通调用等于默认模型 | 多个可用模型及策略重验 | 改造现有准入与绑定，不建立第二条模型代理 |
| Runtime `config/external.rs` 按 Local／External 固定配置来源，外部只承载单模型及 `managed` 引用 | 同一企业用户域同时装配机构与个人模型 | 复用本地管理、外部配置发布及会话选择，不能只开放前端入口或堆叠另一份 Runtime |
| `plugins/entity.ts`、`agents/entity.ts` 以全中心名称为身份 | 机构内同名与受约束引用 | 扩展既有资源归属与引用；不复制市场或安装机制 |
| Host `access/enterprise/mod.rs` 的用户键为 center_id + user_id | 身份、凭据及本地业务域包含机构 | 域身份改为中心 + 机构 + 用户；旧域明确归默认机构，物理目录及资源迁移在 F01 技术方案定案 |
| Runtime 已有插件安装、工具执行、会话存储及资源工作区 | 可恢复的卡片发布记录与界面端点 | 卡片有独立持久引用和界面生命周期；优先扩展既有会话与资源机制，不重复保存 HTML／业务数据库 |

表中未带工程前缀的 TypeScript 路径相对 `apps/enterprise-center/src/`，Runtime 路径相对 `crates/assistant-runtime/src/`。

最小新增复核：去掉“机构”无法表达独立配置与停用；去掉成员关系无法表达同账号在不同组织的角色和撤权；去掉模型来源无法区分凭据与选择；去掉卡片持久引用无法可靠更新同一张卡片。除此之外，优先扩展现有事实，不为展示命名新增实体、缓存、队列或第二份权威状态。

## 五、产品边界与权威状态

| 位置 | 权威状态与职责 |
| --- | --- |
| 企业中心 | 机构、全局账号、成员关系、系统及组织角色、机构模型与密钥、智能体／插件目录、调用记录、反馈／审计、设备登记与授权；平台统一发行及公共配置 |
| Runtime Host | 身份与设备传输适配、机构凭据核验、用户域装配、个人密钥保管、中心代理与个人直连选择；不持第二份 Session／Run 状态 |
| assistant-runtime | 会话与 Run、实际模型选择、个人模型配置、插件安装与发布记录、卡片最新快照及持久化 |
| Desktop／Web／后台 | 展示身份与机构、发送用户意图、按授权装载界面；页面与草稿不是权限或业务权威 |
| 插件 | 业务数据、实际操作、业务防重复和界面恢复语义；宿主只管理通用入口、路由、生命周期与快照保存 |

保持桌面 UI 与 Runtime 双进程、同 Host 内多用户域及 Tokio 会话并发。企业中心不是 Session／Run 宿主，机构不引入新进程。Agent Core 仍只接收已解析的执行规格，不引入租户、插件 UI 或业务路由分支。

## 六、产品规则与全局不变量

### 6.1 机构、身份与权限

- 客户端按单窗口设计，当前只进入一个组织；不引入多窗口同时进入不同组织的能力或协调机制。切换时仍须隔离原请求与任务，拒绝迟到响应覆盖当前组织。

- 全局账号可加入多个机构，用户名保持全中心唯一、用户 ID 不可复用；机构角色归成员关系。登录按入口分流：客户端所有身份先认证再选择本人已加入机构；后台组织管理员选择其管理机构，系统管理员／超级管理员同样先选择管理范围，可选系统管理或任意机构；选定后才加载对应导航。系统管理只显示全局事务，插件、模型等业务页面必须先选机构；进入后台后统一通过顶部“切换组织”选择，系统管理员／超级管理员的选项包含“系统管理”，不提供独立返回入口；各页面不设独立机构选择器。机构编码用于识别，不作为登录必填项；系统管理不授予机构成员业务使用权。
- 同一 Host 的企业域以中心 + 机构 + 用户隔离，本地会话、文件、记忆、个人模型及插件配置不跨机构共享。切换前若有任务，须提示用户确认终止，由 Host 阻止原域新工作、终止并等待全部受管任务收尾后才进入目标组织；取消确认或终止失败／超时不切换。队列停止调度且保留内容，不自动重放；不迁移任务或回滚已发生操作。
- 切换组织或系统管理统一换发对应 Token：组织 Token 固定绑定组织 ID，系统 Token 明确绑定系统范围；后端统一从已验证 Token 获取当前范围，不接受页面、请求参数或请求头覆盖。登录未选范围 Token 无业务权限；换发成功旧 Token 及派生访问失效，不改写旧 Token 的范围。客户端必须先完成原域任务收尾再换 Token。
- 用户明确本期企业中心登录 Token 改为 JWT，组织 ID 写入签名载荷，未选／系统／组织范围均为签发后固定 7 天有效；普通请求不续期，到期重新登录。复用有效会话与撤销机制，切换后旧 JWT 立即失效，中心重启仍失效；Host Token 保持既有随机格式与 7 天有效期，LLM key／设备密钥不改格式，不新增第二套会话权威。Host 对外会话凭据、中心 Token、LLM key 与受控连接范围保持一致；角色与成员权限仍按当前事实校验，系统管理 Token 不凭组织参数直接操作组织业务。
- 现有管理员提升为系统管理员，维护全局账号、机构和成员、设备、安装包、官网、调用管理、反馈与审计；组织管理员是独立的成员角色，管理本机构插件、智能体、模型、设备审批／授权／注销、调用策略、记录／正文、反馈处理及组织审计；设备只能授权给本机构有效成员，不能借设备授权创建成员关系。组织管理员可只读查看本机构成员，系统管理员通过系统“用户管理”维护全局账号、通过组织“组织成员”维护成员关系；系统角色无需机构成员关系，超级管理员沿用相同管理入口与原保护属性。两类管理员均无隐式设备或他人本地业务域使用权。
- 系统管理员管理业务数据须显式选择目标机构；组织管理员仅管理本机构调用策略、记录／正文和反馈，只读查看本机构审计，系统级审计仍限系统管理员。两类管理员的正文读取均须显式操作并审计，不默认聚合业务正文；组织策略与清理不影响其他机构或全局资源上限。原 `is_super_admin` 保留受保护系统管理员语义，不授予普通业务与设备访问绕过权；系统管理员管理目标机构不等于具有该机构成员身份。
- 新机构无私有资源和密钥，不自动克隆默认机构。机构停用后中心拒绝成员进入该机构、代理与设备访问，保留系统管理员显式管理与恢复入口并撤销该机构凭据、结束受控连接；账号仍可登录并选择其他机构，本地历史保留。
- 中心已确认撤权与网络不可达是不同事实。Host 不能因暂时断网删除历史或冒充撤权；离线 Host 无法承诺同步获知停用，撤权传播及最长窗口必须在 F01 明确并验收，不能宣称全网瞬时撤销。
- 列表、详情、写入、关联引用、统计、下载、清理、缓存、异步回调和长连接全部受机构约束；平台管理入口不能成为普通用户跨机构访问路径。
- 一个 Host 的设备登记暂按单机构设计，但本机可以承载同账号多机构业务域；现有组网仅在当前机构与双方设备登记匹配时可用。更换登记须显式解除旧登记／授权和连接，不随用户切换组织静默重绑；此组网限制须在 F01 确认。

### 6.2 机构模型与个人模型

- 机构管理员维护可执行的可用集合、集合中的默认模型及自主选择开关；目录存在不等于获准调用。
- 开关打开时用户可按会话选择可用机构模型；关闭时机构来源仅有默认模型，个人模型仍可配置和选择，不额外引入禁用个人来源的开关。
- 无显式选择时跟随机构默认；显式选择属于会话，不改其他会话与机构默认。来源、Provider 身份和模型引用共同消歧，不按名称复用凭据。
- 机构模型经过中心代理；个人模型由实际承载用户域的 Host 直连。个人密钥只写入本人当前机构的用户域，不随账号自动跨机构共享，前端不持久保存、不自动跨设备同步。
- 配置同步只替换机构配置；个人配置与显式会话选择不被覆盖。所有执行入口（含辅助任务、压缩、排队和继续执行）遵循相同来源与授权规则。
- Run 内不动态换模型；保留活动 Run／排队期间切换限制。新请求发送前重验，已撤销、删除或不再允许的选择明确失败，不静默切源或更换付费凭据。已发上游请求无法承诺撤回费用。
- 续接和原生压缩状态绑定机构／用户／来源及有效配置；不能在切源后继续使用旧主体状态。源切换后的上下文可执行性与恢复策略须在 F02 验证，不能靠换 model_id 宣称兼容。

### 6.3 插件卡片与应用界面

- 卡片与应用采用 MCP Apps 通信基础；保留内置 `publish_card` 作为无 MCP 后端轻量插件的发布入口；MCP 工具关联 UI 直接展示，无需再次调用 publish_card，Skill 仅指导调用，普通工具结果的建议不自动执行。标准 MCP 工具关联 UI 与包内发布复用同一承载，具体持久化适配由 F03 技术方案明确。
- 工具绑定当前用户域、会话、Run 与插件入口，模型不能提交任意代码、页面地址或其他会话身份。成功表示发布记录已保存，不代表页面加载或业务成功。
- 卡片作为所属回复轮次的独立内容块，正文尾部展示为候选；具体多消息／子任务映射、排序与流式滚动在 F03 交互设计确认。
- 2026-11-05 用户明确卡片与右侧资源浏览器协同：支持插件内置应用及外部 HTML 页面，外部页面可接入宿主通信而无需包装为插件。宿主管理容器和连接，页面组织业务，Agent 不管理应用或中转每次操作。
- 插件入口与外部页面统一使用受限宿主桥接；端点绑定用户域、真实插件／页面来源和当前实例，外部页面按授权关联卡片，不能继承打开者的全部权限。导航或来源变化使旧连接失效；资源加载与下载沿 F01 边界，页面不能取得中心或 Host 通用凭据。
- 每张卡片仅保存最新一份插件上报快照；保存成功须代表 Runtime 已持久化，重载交回初始参数与最新已保存快照。快照不经 LLM、不追加消息、不替代实际业务核验。
- 卸载关闭端点，迟到旧实例不能覆盖新状态；多客户端并发、保存失败、限额、插件升级和缺失时的可用性须定案。重挂载不重放工具或业务操作；不引入通用快照历史。
- 2026-11-05 用户确认采用 MCP Apps 方向，替代此前“不预设 MCP Apps”的候选状态。标准初始化、工具调用及生命周期优先复用；右侧应用打开、外部页面接入和 Runtime 卡片快照保留为宿主扩展，不伪装为标准方法。F03 同一资源栏区分普通浏览器标签与受管应用标签；用户已确认以入口声明决定消息卡片／右侧应用位置，不由 Agent 猜测，同一 HTML 可复用到两个入口。具体交互和协议字段留后续设计。iframe／CSP、资源源站、原生适配及桥接仍需验证，不以存在 iframe 证明安全隔离。

## 八、跨 Feature 协议、迁移与恢复

- 企业协议须承载机构身份和多模型配置；应用协议须承载模型来源、插件入口与卡片投影。企业 OpenAPI 与 Rust→TS 投影沿既有生成方式维护，不手写第二套协议权威。
- 旧客户端不能忽略机构字段后继续访问。建议配套升级 Center／Admin／Host／Desktop／Web，并检查 Client 准入；具体协议号、最低兼容版本、旧会话转换及拒绝策略由技术方案明确并获确认，不在规划阶段提前改常量。
- 新版本内部的中间字段直接统一到最终形态，不为未发布开发状态添加双读双写。已有正式用户数据和客户端必须逐项评估迁移及回退。
- 旧中心业务数据建议整体归入一个明确指定的默认机构，账号保持全局身份并建立默认机构成员关系，保留 center_id、用户 ID、资源稳定引用及文件；不按名称猜测拆分。旧管理员提升为系统管理员、旧受保护标记保持，首位组织管理员明确指定；旧 Host 用户域只能绑定默认机构，不按首次选择归属。
- 模型旧 `managed` 会话引用、插件同名引用与既有安装包来源须单独核对；不能在新增机构后仅凭名称把历史指向另一资源。卡片涉及存储新增时复用正式迁移账本。
- 迁移先在项目 `.runtime-test/` 新建无用户数据的一次性场景演练；生产／共享库操作前核对真实连接、实际读取表、影响范围与文件存储，再取得写入确认。
- 破坏性迁移须停写、结束在途传输、建立独立备份，验证可读取、关键表精确数量及恢复可行性。优先事务；数据库外步骤明确恢复方式。恢复须匹配程序、数据库和文件，禁止旧程序忽略机构字段继续写新库。
- 后台切换机构卸载页面及草稿，旧响应不能覆盖新机构；已发写入仍绑定原机构，取消等待不代表回滚，未知结果先重读，不自动重发。
- 本期不新增品牌默认目录定制；实际部署、账号、素材和备份位置只留 `.local/` 私有资料。

## 九、版本验收与发布门禁

1. 同一账号在两个机构以不同角色进入独立业务域，同名模型、Agent、插件正常使用；用 A 的凭据请求 B 的 ID、关联对象、下载、快照、统计及设备均被拒绝且不泄露 B 的内容。
2. 机构管理员可以管理本机构设备审批、授权与注销，不能跨机构操作或向非成员授权；通过直接 API 仍无法管理全局账号、成员关系或安装包；机构调用策略、记录／正文、反馈与审计按组织开放；跨机构和系统级审计访问被拒绝，两类管理员敏感读取均有目标机构与审计。停用和撤权覆盖准入等待、在途连接及迟到结果，离线传播限制如实说明。
3. 修改／清理 A 的配置、记录和文件不影响 B；删除用户后历史仍保留原机构事实。
4. 开关开启／关闭、默认跟随／显式选择、同名双来源、个人配置增删、刷新、重启、排队及配置撤销均符合规则；机构密钥不出中心，个人密钥不越用户域，无静默付费来源回退。
5. 机构与个人模型均能通过既有工具循环发布卡片；卡片与侧栏联动、保存与重载恢复成立，不重复发布／执行业务，不借桥接越过机构或用户边界。
6. 迟到旧实例、多客户端写入、保存失败、插件卸载／升级、退出与设备切换均有可解释结果；资源限额有效，不以模拟页替代正式 Host 验证。
7. 迁移演练保持历史数量、关键字段和资源引用，正式登录、配置、代理、文件及设备接口可读；旧客户端明确升级提示，配套恢复可执行。
8. 本期必需 Feature（F01—F03）获确认后进行跨 Feature 验收；重点覆盖机构撤权时个人调用／插件界面行为、模型切换后卡片历史恢复，以及配套升级后的旧数据边界。

验证以核心风险为准，各 Feature 就近核验，版本阶段补跨 Feature 组合；不单独创建验证报告。构建、签名、公证、上传及正式发布按实际平台与授权另行执行；本次规划不包含任何部署或数据库写入。
