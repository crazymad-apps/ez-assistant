# v0.33.0 F02 界面交互设计指导

## 一、设计依据

2026-11-05：用户认可收敛后的[技术方案](技术方案.md)，明确客户端模型选择采用企业／个人纵向分组，中间使用横线 divider；只有一类时不分组。本文细化交互；用户已认可后台配置细化并要求进入开发计划，交互设计已确认。实施状态见开发计划。

范围沿[功能设计](功能设计.md)。复用客户端既有 ModelPicker／SettingsCascadePopover 和后台 Ant Design；模型管理首页按第三节的用户追加要求整理信息层级，不引入新组件库。界面“企业模型”对应数据中的当前组织模型。

## 二、客户端模型选择

**两类同时有展示项时，上方企业模型，下方个人模型，中间一条横线。** 使用轻量分组标题“企业模型”“个人模型”，不用页签、左右分栏或额外的来源选择步骤。

示意（沿用现有服务商 → 模型的二级选择）：

```text
跟随组织默认

企业模型
  企业服务商 A   ›
  企业服务商 B   ›
────────────────
个人模型
  个人服务商 C   ›
```

| 展示内容 | 分组行为 |
| --- | --- |
| 企业和个人都有 | 企业在上、个人在下，两个标题，中间一条 divider |
| 只有企业模型 | 直接显示企业项，省略来源分组标题和 divider |
| 只有个人模型 | 直接显示个人项，省略来源分组标题和 divider |
| 两类都没有 | 显示空态，不绘制空组或 divider；保留既有模型管理入口 |

沿用现有服务商层级及展开后的模型列表，不为来源再加一层子菜单。服务商／模型的真实选择仍含来源，只有一组也不能省略身份字段。同名服务商在双组下用分组区分，当前选择摘要必要时显示来源及服务商，避免同名歧义。

“跟随组织默认”作为固定选择项保留，表示当前会话跟随策略，不计作额外模型来源；无有效组织默认时显示不可用原因，不因此创建空企业组。辅助识图等不支持跟随的选择入口沿原用途规则，不额外加入该项。

分组按实际展示的来源计算；读取失败不是空集合，显示对应错误／重试而非伪装成只有另一来源。已选但失效的模型保留明确状态，不悄悄替换；分隔线仅分隔两组，不能成为可选项或键盘焦点。原有推理强度等菜单项保持既有位置和语义。

选择成功才更新显示；有活动任务／队列时沿既有禁止换模规则及提示。切源、失效恢复和队列处理遵循功能设计，不另加新的执行流程。

## 三、客户端模型配置

客户端“模型与服务商”保留企业只读、个人可编辑的边界。个人配置复用已有添加／编辑／删除、密钥和目录刷新表单；组织刷新不覆盖个人配置。选择器的“单来源不分组”不机械套用管理页面空态，个人配置为空时仍保留添加服务商入口。

2026-11-05 用户追加要求整理该首页。默认模型与默认识图模型合并为同一组紧凑设置行；企业与个人服务商分别使用独立边框容器，浅底标题栏与白底列表通过分隔线区分，刷新和添加操作放在所属组标题右侧。标题与首组内容的距离沿用共用设置页容器，模型首页不额外叠加顶部留白。企业列表不逐行重复管理员归属，最近获取时间放入刷新操作的提示；刷新失败、模型不可用及缺少默认等有效状态继续明确显示。仅调整首页层级与布局，原导航和配置流程保持。

来源路由由后端处理，选择界面不展示或要求填写企业代理 URL；个人服务商连接地址仍在原编辑表单配置。

## 四、后台组织模型配置

### 4.1 页面布局

仅在当前组织的“模型管理”页配置，系统管理员先通过顶部统一切换进入目标组织；页面不再增加组织选择器。沿用现有上下两张 Card，不新增独立策略页或发布流程。

```text
组织配置
  允许成员自主选择组织模型                     [开关]
  关闭时只提供默认企业模型，个人模型不受影响。

  可用模型                                    [添加模型]
  默认    模型名称      模型 ID       服务商        状态          操作
   ◉     Model A       model-a       服务商 A      可用       配置 / 移除
   ○     Model B       model-b       服务商 A      可用       配置 / 移除
   ○     Model A       model-a       服务商 B      待配置     配置 / 移除

  [保存配置] [取消修改]                       [清空可用模型]

服务商                                         [添加服务商]
  沿用现有名称、类型、服务地址、凭据、管理入口
```

可用模型表展示已纳入的集合，不直接展示全部 Provider 目录。2026-11-05 用户追加要求模型名称与模型 ID 分列，服务商目录、组织可用模型表与添加弹窗统一显示两列；没有独立显示名称时，名称列显示“—”。服务商单独一列以区分同名模型；状态为“可用”或具体失效原因，不能只用颜色。默认列用单选控件，只允许选可执行项；已失效的原默认保留标识并显示错误，不能自动勾选其他行。

表格沿现有小尺寸和操作列样式；集合列表不额外添加分页或排序配置。上游 API 地址／密钥仍在服务商详情维护，不要求为每个模型填写 URL。组织配置与服务商表单分别保存，添加服务商不等于把其所有模型开放给成员。

### 4.2 添加可用模型

点击“添加模型”打开弹窗，复用现有选择服务商和模型目录的读取能力：

1. 选择当前组织的一个服务商。
2. 展示其在线目录与手动固定模型，支持按名称／ID 搜索和多选；同一 Provider／model 只显示一行，沿现有固定参数优先规则解析。
3. 已在列表中的项显示“已添加”并禁止重复选择；配置不完整的项显示“待配置”及原因，不能勾选。
4. 点击“添加到列表”将本次勾选加入页面草稿并关闭弹窗；要添加另一服务商的模型再次打开。弹窗切换服务商时清除尚未添加的勾选，不跨服务商暗中保留选择。
5. 只有页面“保存配置”成功后才实际向成员开放；弹窗“取消”不改变草稿。

无服务商时提示先添加服务商；无目录／没有可选项时区分空目录、读取失败和全部已添加，失败提供重试。需完善模型参数时使用原模型编辑页，离开前沿统一草稿保护先保存或放弃当前组织配置，不能跳转时丢失草稿。

首次添加后不自动选中默认：明确提示“请选择默认模型”，由管理员选择后保存。列表中显示“新增”标记或统一未保存提示，不把草稿误示为已生效。

### 4.3 默认模型与自主选择开关

默认项直接在可用表中单选，替换现有独立“选择默认模型”弹窗及“清除默认”动作。非空集合须有一个可用默认才能提交；不存在单独清除默认却保留集合的正常保存路径。已有默认因外部配置变化失效时保持真实状态，需修复、选择替代或清空集合。

开关只改变页面草稿：开启后成员可选择集合中的有效项；关闭后仅提供默认，其他行仍留在管理列表，可编辑或移除。关闭时在非默认行显示“关闭自主选择后不向成员提供”，不假装它们已从集合删除。

单个模型时仍可显示和设置开关，不根据模型数量偷偷修改策略。空集合时显示“尚未配置企业模型”，开关保留值但不产生可调用项；个人模型不受此状态影响。

### 4.4 移除、清空与删除服务商

- **移除普通项**：从页面草稿移除，保存前仍未生效；可用“取消修改”恢复到最后已保存状态。仅移除成员使用授权，不删除模型参数、Provider、调用历史或客户端会话。
- **移除默认项**：草稿提示重新选择默认，未选择时禁止保存；若移除后集合为空，则按清空处理。不可默认换到第一行。
- **清空可用模型**：清空集合及默认进入草稿，保存时明确确认影响；不删除服务商和模型配置。
- **删除服务商**：仍在原服务商详情操作，原确认补充受影响的可用模型数量／名称及是否包含默认。删除成功后刷新集合与默认状态；默认引用失效如实显示，不自动替换。无法读取影响时禁止确认删除。

从列表“配置”进入原模型参数页。参数修改是原独立保存流程，返回后重新读取状态，不覆盖尚未处理的策略草稿；页面离开仍遵循统一 NavigationGuard。

### 4.5 保存、影响确认与失败

“保存配置”一次提交可用集合、默认和开关；无修改或有校验错误时禁用。“取消修改”恢复最后读取的服务端值，只撤销本区草稿，不回滚已保存的服务商参数。

保存前按本次实际变化合并为一份影响确认，不连弹多个框：

| 变化 | 确认说明 |
| --- | --- |
| 修改默认 | 跟随默认的会话在后续执行中使用新默认；显式选择不会随之改写 |
| 移除可用项 | 使用这些项的后续请求将被拒绝，用户需重新选择；不自动切到其他模型 |
| 关闭自主选择 | 成员仅可调用默认企业模型；原显式非默认企业模型将不可用，个人模型不受影响 |
| 清空集合 | 企业模型将不可用，个人模型仍可用；服务商配置和历史保留 |

仅新增非默认项、开启自主选择等扩大可选范围的普通保存不另加确认。影响摘要来自具体配置变更，不显示未经查询的“受影响用户数”或“运行任务数”，不承诺回滚已发送上游请求。

提交中锁定本区编辑及离开；成功回读并显示“配置已保存”。明确失败保留草稿和原因；权限变化按当前身份处理；结果未知先重新读取核对，不能自动重发。原配置被其他管理操作改变时提示冲突，由用户重新读取并重新编辑，不用旧草稿覆盖新值。定时刷新和手动读取不得直接覆盖未保存草稿。

模型下发、调用准入与中心连接处理沿技术方案；界面不新增“发布”“同步到所有客户端”按钮，也不把配置保存成功描述为每个离线客户端已更新。

## 五、实现入口与检查

现有 `apps/desktop/src/features/settings/ModelPicker/index.tsx` 生成服务商选择项，`apps/desktop/src/features/composer/ComposerDock/ModelSettingsPopover.tsx` 复用它。扩展已有选择组件的分组标题及 separator 能力，保持原有焦点、键盘导航和主题；不以新增第二个选择器解决分组。

交互检查聚焦双来源、仅企业、仅个人、两类为空、加载失败、同名项、失效选择及键盘跨 divider 导航。后台复用 `apps/enterprise-admin/src/features/models/ModelsRoute/index.tsx` 的组织配置和服务商卡片，调整 `DefaultModelDialog` 的选取能力承载添加流程。后台检查首次配置、多 Provider 同名模型、重复添加／待配置项、默认移除、关闭后集合保留、清空、删除服务商、草稿保护及未知结果；正式调用是否走正确 URL 仍按技术方案验收。
