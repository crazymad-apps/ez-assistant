## 二、台账原则

- 复用现有 Provider、固定参数、配置 Registry、模型选择器和代理，不增加模型路由服务、独立发布流程或执行生命周期。
- 每个里程碑完成实现和最小有效验证后记为“待确认”，用户确认后才进入下一里程碑。中间成果仅用于开发验证，全部收口前不作为配套产品发布。
- 协议、生成代码与读写双方在所属里程碑一并核对。企业协议以 F01 最终基线为准，按已确认技术方向统一到最终集合契约，不为本版未发布的中间格式保留双轨。
- 迁移与旧选择处理随对应改动验证，M3 做完整升级联验。测试使用新建隔离环境；核对实际连接和读写范围，遵循数据库安全规则，不操作用户数据或授权生产升级。
- 计划仅登记范围、状态、确认与必要风险；实现细节以设计为准，不另建验证报告。开始实施时重新核对工作树，保留其他任务改动。

## 四、里程碑范围与完成判定

### M0 后台多模型配置与中心准入

**目标／前置**：前置确认完成后，使组织管理员能在原模型管理页配置多个可用模型，并通过真实接口验证授权结果。

**交付范围**：

- 沿现有组织配置增加允许集合与自主选择开关；原默认成为初始集合唯一项，开关关闭，无默认组织保持空集合，失效默认保留原因。
- 后台添加弹窗、默认单选、移除／清空、草稿与统一保存；服务商管理仍用原入口，影响确认及保存冲突按交互指导落实。
- 配置下发改为 Provider／模型集合，代理按凭据组织、URL Provider 和请求 model 校验；HTTP、WS、压缩及输入计量一致，管理测试保持独立权限。
- 更新中心契约和生成 SDK；只下发安全参数，保留逐项失效与集合获取失败的区别。

**验证入口**：中心定向模型／代理单测、隔离数据库集成、后台真实页面；执行中心 `npm run typecheck`、`npm run openapi:check`，后台 `npm run build` 及相关单测。使用受控 Provider 检查同 Provider 两模型共用 URL、不同 Provider 同名模型隔离、绕过菜单直接请求仍受策略限制。迁移检查实际数据和接口回读。

**完成判定**：集合／默认／开关完整保存且刷新可恢复；关闭开关保留集合但仅默认获准；非成员、跨组织和未授权模型不能调用；后台不要求逐模型配置 URL。

**Review 重点**：集合唯一性和默认约束、保存原子性与冲突处理、失效引用、各代理入口权限一致、密钥不外泄；不复制现有模型配置。

### M1 Host 双来源选择与实际调用

**目标／前置**：M0 确认后，正式 Host 在企业用户域中同时加载组织与个人模型，并使会话选择决定实际执行。

**交付范围**：

- 扩展既有外部配置集合及完整模型引用，Rust／TS 投影和 Host 消费端同步；组织刷新不覆盖个人 Provider、配置或显式选择。
- 跟随／显式选择、保存与重启恢复、来源路由贯通正式 Runtime；组织项走中心，个人项走已有直连装配。
- 主调用、已有辅助调用、压缩／计量、继续与重试统一使用所选引用；沿用 Run 冻结、队列限制和续接绑定，不新增执行流程。
- 核对旧 managed 引用与持久化升级；有可证明归属才映射，否则保留历史并要求重选。同步实际协议兼容检查，拒绝不支持集合的旧端。

**验证入口**：正式 Host HTTP 命令与受控 Provider 请求观察、Runtime／Host 定向测试；执行 `cargo fmt --all --check`、`cargo clippy --workspace --all-targets --all-features -- -D warnings`、`cargo test --workspace`，并核对 TS 协议投影。验证个人请求不带中心凭据、组织刷新不覆盖个人配置、同名项不混用、重启后保持选择及原生状态不串用。

**完成判定**：跟随与显式选择均反映在实际 Provider 请求；失效不静默改模型或来源；纯本地模式保持原行为；历史不可兼容时明确阻止，工具副作用不重放。

**Review 重点**：配置与会话状态唯一所有者、Provider 身份消歧、凭据及续接绑定、旧数据可证明映射；本里程碑经正式协议即可验证，不等待 UI 掩盖执行问题。

**M1 当前结论**：Host 已接入协议 6，支持跟随组织默认、显式组织选择及个人直连，完成持久引用、撤权和原生窗口边界的定向验证。旧 `managed` 引用需重选，无法绑定的旧原生窗口需另开会话。全仓验证仍有既有格式、插件 lint 与旧 Host 夹具问题，随版本联合验收收尾。

### M2 客户端模型选择与个人配置

**目标／前置**：M1 确认后，在 Desktop／Host Web 现有入口中完成企业多模型选择与个人配置闭环。

**交付范围**：

- 扩展现有 ModelPicker：企业在上、个人在下，双来源有标题与一条 divider，单来源不分组；保留服务商到模型的原选择层级。
- 展示跟随默认、显式项、失效原因与保存反馈；失效选择不自动补选，活动任务和队列限制与 Runtime 一致。
- 设置页组织只读、个人可编辑，复用 Provider／密钥／固定参数表单；配置个人模型不自动切换会话，不增加企业模式个人全局默认。
- 覆盖空集合、单来源、加载失败、重名及组织切换后的显示，使用既有主题、焦点和键盘导航。

**验证入口**：客户端相关单测、`npm run build`；正式 Host Web 浏览器测试及 Desktop 原生交互。完成后台授权两模型 → 客户端选择 → 实际调用，再添加个人模型并切换直连；检查仅企业、仅个人、双来源和全部为空时的选择器。

**完成判定**：用户能在现有界面完成配置与切换；展示来源和实际调用一致，密钥不回显或落前端持久存储，单来源无多余分组，失败保留原状态和必要草稿。

**Review 重点**：复用选择组件而非建立第二份模型状态、可访问性、共享配置只读边界、无效选择及队列反馈；不能只靠前端限制权限。

### M3 升级、隔离与联合验收

**目标／前置**：M2 确认后，核对功能设计全部验收点，补齐真实跨层组合风险。

**交付范围**：

- 受支持旧数据到最终 F02 配置的升级与恢复；初始默认／开关、旧显式选择、个人配置及纯本地模式均有明确结果，不为本版临时协议建立兼容层。
- 正式中心、后台、Host、Desktop／Web 联验两组织与同名 Provider／模型；组织切换后个人配置和历史仍在原域。
- 策略变更、成员撤权、JWT 到期、中心断网、个人凭据失败、重启及迟到响应的核心组合检查；覆盖辅助调用和续接，不自动切源或重放。
- 核对调用记录只包含经中心的调用；同步受影响模块说明，在本计划记录完成结论及未测限制。

**验证入口**：复用前序已通过检查，仅补组合与变更覆盖；执行相关企业 E2E（Desktop `npm run test:e2e:enterprise -- <目标用例>`），使用新建隔离 Home／库进行升级与恢复，并实际验证接口及页面。覆盖当前可用原生平台；不可执行的平台或真实上游路径明确保留，不用受控 Provider 结果冒充实测。

**完成判定**：功能设计验收点均有结果，迁移和隔离无未解释偏差；未执行项与风险明确，向用户汇报并等待 M3 确认，再作 F02 完成判定。

**Review 重点**：F01 组织权限不被个人直连绕过、所有调用来源一致、升级失败可恢复、后台配置与执行结果一致；发现影响 F01 已确认边界时按流程重新核对。
