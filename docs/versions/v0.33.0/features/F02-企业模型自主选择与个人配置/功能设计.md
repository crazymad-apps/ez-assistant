## 二、目标与范围

组织管理员维护多个可用模型，指定组织默认模型并决定是否开放成员自主选择。成员在会话中选择获准组织模型，也可在当前组织的本人工作区添加个人服务商、密钥与模型，再选择个人模型执行。

同一会话任何一次实际调用都能明确区分使用的是组织配置还是个人配置；相同模型名称不能混用凭据、续接状态或费用来源。用户没有显式选择时继续跟随组织默认，保留现有使用习惯。

本 Feature 包括组织模型策略、配置下发和代理准入、个人模型管理、双来源会话选择、执行与辅助调用的一致解析、失效反馈及旧选择迁移。模型现有能力、固定参数、目录刷新、协议适配和密钥安全机制继续复用。

不包含组织共享个人密钥、个人配置自动跨组织／跨设备同步、全平台公共模型、配额／计费结算、自动模型路由／降级、供应商故障自动切源、统一禁止个人模型的开关、新 Provider 协议或通用权限矩阵。不把本 Feature 变成企业中心托管个人模型的功能。

## 三、模型来源与权限

| 事项 | 组织模型 | 个人模型 |
| --- | --- | --- |
| 配置归属 | 当前组织 | 实际承载用户域的 Host 上，当前中心＋组织＋用户 |
| 谁能维护 | 当前组织管理员；系统管理员须先切到该组织 | 当前有效成员本人，沿已有 Host 访问权限 |
| 密钥保存 | 企业中心，不下发成员或 Host | 对应 Host 用户域，不上传企业中心、不落前端持久存储 |
| 执行位置 | Host 经企业中心代理访问 Provider | Host 使用个人配置直连 Provider |
| 可选范围 | 组织允许集合及自主选择策略共同决定 | 本人当前用户域中可执行的个人模型 |
| 管理员查看权限 | 可管理本组织共享配置 | 管理身份不授予读取他人配置、密钥或本地会话的权限 |
| 中心统计 | 沿现有调用类型与采集策略记录 | 不经过中心的请求不纳入中心调用、用量或正文统计 |

“个人”指当前组织内本人的配置，不是跨组织通用配置。切换组织按 F01 先终止任务再换身份；返回原组织可继续读取原个人配置。切换实际执行 Host 不搬移密钥，目标 Host 未配置该模型时明确不可用。

个人模型仍需有效的企业用户域访问资格；组织停用、成员撤权或登录到期的处理继承 F01，不能借直连绕过身份检查。纯本地模式继续使用既有本地模型管理与默认选择，不强行归入某个企业组织。

## 四、组织模型管理

### 4.1 可用集合、默认与开关

组织“模型管理”页保留服务商及模型配置能力，增加“组织可用模型”“组织默认模型”和“允许成员自主选择组织模型”。服务商目录是配置候选，不等于可供成员调用的清单。

- 可用项由组织内 Provider 身份及模型身份共同确定，同名模型可以分别纳入，禁止重复添加同一项；不从其他组织复制连接或凭据。
- 新增可用项前须通过现有执行配置校验；能力不完整、连接缺必要密钥等问题在对应项标明并阻止加入。校验通过不承诺上游网络或额度永远可用。
- 非空可用集合必须有且只有一个默认，默认必须属于集合。移除默认项时须在同一次保存中指定替代项，或显式清空整组组织可用配置并确认影响，不能悄悄选第一项。
- 空集合允许保存，用于尚未配置或停用组织模型；此时没有默认，组织来源不可执行，个人来源仍可用。已有默认因 Provider 删除或配置变化失效时保留明确的失效引用和原因，不自动补选。
- 组织开关默认关闭，沿旧行为只提供默认模型。关闭开关保留可用集合；再次开启后恢复集合可选性，不自动修改会话。
- 开关打开时，成员可选择可用集合中的可执行项；关闭时组织来源只允许默认项。关闭不影响成员管理和使用个人模型。
- 策略保存作为一项完整操作校验，成功后刷新展示；失败保留草稿，结果未知先重读。影响现有显式选择时提供确认，不在客户端偷偷改成默认。

Provider／固定参数／模板或目录变更可能使多个可用项失效；列表逐项呈现原因。刷新目录不自动扩大允许集合，也不移除已保存手动固定项。删除 Provider 时列出影响的可用项及默认关系，按既有删除确认处理。

### 4.2 代理与下发边界

中心按成员的已验证组织范围下发允许使用的组织模型及有效能力参数，不包含上游密钥或未授权目录。管理员维护接口和配置测试仍走管理权限路径，不能把管理员目录响应作为成员配置。

中心每次普通模型请求都检查所选组织／Provider／模型、当前策略及成员资格；HTTP、WS、原生压缩、输入计量等入口一致。客户端伪造模型 ID 或直接调用代理不能绕过允许集合。配置测试按既有专用管理规则执行并保留独立调用类型。

## 五、个人配置与会话选择

### 5.1 配置入口

Desktop／Host Web 的“模型与服务商”按“组织模型”“个人模型”分区。组织配置只读，可刷新并查看可用性；个人区可添加／编辑／删除服务商、保存或替换密钥、刷新目录、维护模型固定参数，复用现有表单和错误反馈。

新增个人服务商不自动切换当前会话，不改变组织默认；密钥输入提交后清空，后续只显示“已设置／未设置”，不回显明文。中心管理员维护共享模型仍在企业后台，客户端不因为本人是管理员就混入共享编辑入口。

企业用户新会话的默认行为固定为跟随组织默认，不另加一个能覆盖它的“个人全局默认”。纯本地模式的全局默认保持。企业模式下既有辅助识图选择可选择获准组织或本人个人模型，需明确支持图片输入；清除后沿现有未配置语义，不自动挑选其他收费来源。

### 5.2 会话选择语义

复用会话输入区模型选择器，提供“跟随组织默认”及具体模型；企业与个人同时有展示项时纵向排列，以“企业模型”“个人模型”标题和中间一条横线分隔，只有一类时不显示分组标题或横线；每项显示模型名和服务商，分组区分来源，不能只用同名字符串识别。明确选中具体默认模型仍属于显式选择，与“跟随”不同。

| 会话状态 | 后续执行规则 |
| --- | --- |
| 跟随组织默认 | 新 Run 启动时解析当时的默认；默认变更可影响后续 Run，当前 Run 不改模型 |
| 显式组织模型 | 固定该 Provider／模型；策略允许且配置有效时使用，不跟随默认变更 |
| 显式个人模型 | 固定本人该 Provider／模型；不受组织默认和自主选择开关改变影响 |
| 显式选择失效 | 保留原选择并显示原因，阻止新的执行；用户明确选择其他项或恢复跟随后再继续 |

有活动 Run 或待处理队列时，沿用既有会话模型切换限制，不在本 Feature 放宽。提示先完成／停止当前执行及处理队列，不能通过重开选择器绕过后端约束。无效选择下的队列保持可查看、可取消；不得为了允许换模型直接丢弃排队输入。技术方案保留现有 idle 约束：可恢复原配置后显式恢复队列；需要更换模型时先保存所需内容，再由用户明确取消待执行输入／命令并结束活动工作，随后换模、手动重新提交；暂停队列不视为空闲。

选择保存成功后才更新当前模型展示，失败保持原值。重启、重新登录、历史加载继续保留“跟随／显式”语义；组织配置同步不得覆盖个人配置、显式会话选择或表单草稿。

## 六、执行、变更与异常

### 6.1 一次执行内的模型一致性

Runtime 在 Run 接纳／实际启动边界解析来源与配置并形成冻结执行规格；后台刷新、用户修改默认等不能在一个 Run 中动态替换供应商或密钥。执行路径中重试、继续、排队、Goal、子任务及辅助调用均通过同一来源解析和权限边界，不允许私有路径退回旧单模型配置。

中心仍对后续上游请求重验策略。已失效的组织配置或已撤销资格不因 Run 冻结而继续获准；已发送请求不能保证撤回费用。个人配置修改不热替换已冻结的 Run，后续 Run 使用新配置；删除操作须按现有在用约束说明影响，不承诺抹除已发上游请求。

辅助识图若有单独配置，按该明确选择使用相应来源，不能跟主模型的来源混用密钥；主模型及辅助模型均在实际调用前检验能力。上下文压缩、输入计量和续接必须与它们服务的执行上下文兼容，不能因主模型失效自动选择一个仍可用的辅助模型继续。

### 6.2 变化后的行为

| 变化 | 行为 |
| --- | --- |
| 组织默认 A 改为 B | 跟随型会话的后续 Run 使用 B；显式 A 仍在允许范围则保持 A |
| 关闭自主选择 | 显式组织模型等于当前默认时仍可用；其他显式组织模型标记不再允许，要求重新选择；个人选择不变 |
| 从可用集合移除所选模型 | 拒绝后续组织代理请求，显示“组织已停止提供此模型”；不切换到个人同名项 |
| 组织配置刷新失败 | 展示最近成功配置及失败状态，不伪称已更新；旧展示不保证中心仍准入 |
| 中心暂不可达 | 组织调用按现有失败策略处理；企业身份仍有效且 F01 允许保留本地域时，可显式使用已有个人配置，不自动切源 |
| 个人密钥错误、网络失败或模型删除 | 显示当前来源及对应原因，不改用组织默认或另一密钥 |
| 组织或成员撤权／JWT 到期 | 继承 F01 访问失效和收尾规则，不用个人直连绕过，不自动重放工作 |
| 保存或执行结果未知 | 先核对实际状态；不自动跨来源重试或重复产生模型费用 |

### 6.3 历史与续接

切换来源、Provider、模型或影响执行主体的配置后，不复用另一主体的服务端续接 ID／原生压缩状态。聊天历史保留，但“保留历史”不代表不同模型的上下文一定可继续执行。

若旧上下文依赖不可跨来源解释的原生状态，必须在切换或下一次执行前明确提示不可兼容；仅在已有可验证的本地历史重建路径可用时继续，否则阻止继续并提供新建会话，不丢弃上下文伪装为成功。不得自动重放历史工具副作用。具体兼容判定及绑定表达归技术方案，须用当前压缩／续接实现验证。

## 八、旧数据与兼容

1. F01 每组织原默认模型转换为初始允许集合中的唯一项，自主选择开关默认关闭；原默认失效则保留失效事实，不猜测可执行替代项。无默认的组织保持未配置。
2. 原跟随型会话继续跟随组织默认；旧 managed 显式选择须根据真实历史身份／绑定映射到对应组织模型，不按当前同名模型猜测。不能证明归属时保留历史并要求重新选择，不能悄悄改成跟随。
3. 不把组织密钥复制为个人密钥；个人配置不从另一组织、其他账号或纯本地模式自动导入。已有合法本地域数据按原归属保留。
4. 双来源引用、旧选择迁移及兼容门禁由技术方案按 F01 当前已实现形态确定；未发布的 v0.33.0 中间结构直接收敛，不额外维持双轨。生产迁移另行按数据库规则执行。

## 九、验收标准

1. 组织管理员可维护多个可用项、唯一默认和开关；目录未纳入、跨组织 ID 和非法默认关系由服务端拒绝。
2. 开关关闭仅允许组织默认，开启允许集合内模型，个人模型始终按本人配置可选；直接调用 HTTP／WS 代理不能绕过。
3. 普通成员能维护当前组织本人的个人配置；同账号另组织／另一 Host 不自动共享，管理员无法读取他人密钥。
4. 同名组织／个人模型明确消歧，实际调用分别走中心代理／Host 直连；组织密钥不下发，个人密钥不上中心、不回显、不持久化在前端。
5. 跟随默认和显式选择行为不同，默认变更、开关关闭、删除、刷新和重启后结果符合本文，不静默切源。
6. 活动 Run 和排队时切换限制前后端一致；无效选择不会触发排队重放、改模型或额外收费。
7. 正常生成、子任务、辅助识图、压缩、计量、继续及重试按正确来源和当前权限执行，当前 Run 不热替换配置。
8. 策略撤销、中心断网、JWT 到期、个人密钥失败及迟到配置都有可解释状态，旧请求不污染新组织或新选择。
9. 来源变更不复用错误的续接／原生压缩状态；不能兼容时明确阻止或要求新会话，不丢历史、不重放工具。
10. 中心统计仅反映经过中心的调用；当前会话实际模型与来源可辨，不宣称包含个人直连总量或费用。
11. F01 默认模型与旧 managed 选择迁移、纯本地模式回归通过；正式中心＋Host＋Desktop/Web 的双来源链路验证，不仅检查菜单。
