## 二、目标、范围与非目标

用户使用同一个中心账号登录；客户端选择已加入的组织后进入工作环境，企业后台则按系统管理或组织管理分流。切换组织不需要另注册账号，不混用另一组织的权限、会话或配置。同一用户可以在 A 组织是组织管理员，在 B 组织是普通成员。

系统管理员管理全中心账号、组织、成员关系及平台事务；组织管理员只拥有其所在组织的管理权限。F01 完整覆盖现有资源与设备入口，不留下“列表隔离但详情或下载可越权”的中间交付。

本 Feature 包括账号与组织成员关系、组织管理、登录选择与切换、权限、现有资源及设备隔离、Host 组织用户域、历史数据迁移和配套升级。机构模型在 F01 仍为每组织一个默认模型；多模型可用集合和个人配置入口在 F02 开放，但数据域边界由 F01 确定。

不包含组织自助注册／删除、邀请邮件、SSO、部门层级、计费、通用权限矩阵、跨组织共享资源或设备，以及 F02、F03 的新增能力。不为组织创建操作系统子进程或独立中心部署。

## 三、账号、组织与角色

### 3.1 三类事实

| 事实 | 定义与所有权 |
| --- | --- |
| 账号 | 全中心唯一的用户 ID、用户名、密码、显示名、启停及系统角色；同一用户不因加入组织复制账号。用户名继续全中心唯一，显示名可以相同 |
| 组织 | 稳定且不可复用的组织 ID、可识别编码、名称及启停状态；是共享业务资源的归属边界。编码不再是登录凭据的一部分 |
| 成员关系 | 一个账号在一个组织中的成员身份、角色和有效状态；同一账号可有多个关系，每个关系可分别授予普通成员或组织管理员 |

组织角色属于成员关系，不能继续塞进账号唯一的全局 role。全局账号启停影响全部组织；组织停用影响该组织全部成员；移除／停用成员关系只影响该账号在该组织的访问。重新授予成员关系不自动恢复已撤销的设备授权。

首版由系统管理员维护账号、组织和成员关系。组织管理员管理本组织插件、智能体、模型，以及设备审批、设备用户授权与注销、调用策略、调用记录／正文、反馈处理与组织审计；设备用户授权只分配设备使用权限，不授予组织成员身份。组织管理员不能因此创建全局账号、重置密码或管理其他组织。

### 3.2 权限矩阵

| 操作 | 系统管理员 | 组织管理员 | 普通成员 |
| --- | --- | --- | --- |
| 创建／启停组织，维护全局账号、系统角色、密码重置 | 系统管理入口 | 不允许 | 不允许 |
| 查看全系统用户 | 系统管理中的“用户管理” | 不允许 | 不允许 |
| 查看组织成员 | 显式目标组织的“组织成员” | 本组织只读 | 不新增成员目录入口 |
| 添加／停用／移除组织成员、指定组织管理员 | 在用户管理或目标组织的成员页维护关系 | 不允许修改 | 不允许 |
| 当前组织插件、智能体、Provider、默认模型 | 显式进入目标组织管理 | 仅本组织 | 只消费已发布且获准资源 |
| 设备审批、用户授权与注销 | 显式目标组织 | 管理本组织设备，仅向本组织有效成员授权 | 申请／使用本人明确获授权设备 |
| 调用策略、记录／正文、反馈处理与审计 | 显式目标组织；系统级审计由系统管理入口查看 | 管理本组织策略、记录／正文、反馈，查看本组织审计；敏感读取审计 | 本人反馈提交等原能力 |
| 安装包、官网、公共地址、模板等全局配置 | 系统管理入口 | 不允许 | 使用公开发行及内容 |
| 客户端工作区、个人模型（F02） | 仍须成为该组织成员；只访问本人域 | 本人当前组织域 | 本人当前组织域 |

本矩阵的系统管理员包含 `is_super_admin=true` 的超级管理员；二者使用同一套系统管理与组织管理入口，超级管理员保留原账号保护属性，不增加第三种管理空间。系统管理员身份不需要组织成员关系，也不自动创建关系；可以拥有零个组织成员身份。

系统管理员的“管理组织”不等于作为成员使用模型、读取其他用户本地会话或取得设备权限。管理界面明确区分“系统管理”和“组织管理”；无需伪造成组织成员执行管理操作，审计保存真实系统管理员及目标组织。

### 3.3 原管理员迁移与保护

- 现有 `role=admin` 账号统一提升为系统管理员，保留原启停状态；普通用户仍为普通账号。
- 现有 `is_super_admin=true` 的账号保留受保护系统管理员语义，即使原 role=user 也不得丢失管理权限；不因为新增组织管理员而降级或移除原保护。
- 组织管理员作为新增的组织成员角色显式授予，不将所有旧管理员静默改成组织管理员。
- 继续保护至少一名启用系统管理员及原受保护账号。组织初始化时由系统管理员指定启用成员担任首位组织管理员；后续降级、移除或停用最后一名有效组织管理员须先交接，组织整体停用除外。
- 全局停用／删除用户时同时检查其在各启用组织中的最后管理员责任，不因单组织校验遗漏而留下无管理人的组织。系统管理员可恢复停用组织并补齐管理员。

## 四、登录、选择与切换

### 4.1 登录按入口分流

以下为本轮结合界面提出的明确方案，纳入功能设计草案待确认：

| 入口与身份 | 登录后的落点 | 进入前的选择要求 | 可进入的组织范围 |
| --- | --- | --- | --- |
| 企业后台：系统管理员／超级管理员 | 管理范围选择页，不直接加载业务导航 | 必须显式选择“系统管理”或某个组织；进入组织业务必须选定组织 | 可选择任意组织管理，不要求成员关系；“系统管理”仅承载全局事务 |
| 企业后台：仅组织管理员 | 组织选择页 | 必须；只有一个也明确点击进入 | 仅本人有效成员关系中担任组织管理员的启用组织 |
| 企业后台：普通成员 | 无管理权限提示，可改密或退出 | 不进入组织管理 | 不提供管理入口，提示使用客户端 |
| Desktop／Host Web：所有身份，包括系统管理员／超级管理员 | 本人组织选择页 | 必须；只有一个也明确点击进入 | 仅本人具有有效成员关系的启用组织；系统权限不扩大业务使用范围 |

后台管理员登录后统一先选择范围，不按系统角色自动进入后台首页。系统管理员／超级管理员可选“系统管理”或任意组织，组织管理员只能选有管理权限的组织；选定范围后才加载相应导航。没有任何组织时，系统管理员仍可显式选择“系统管理”创建组织；客户端零可用组织显示空态，不能默认进入某组织。

账号认证成功后取得未选择范围的登录 Token，只能读取本人、查询可选范围、选择范围及改密／退出，不能调用系统管理或组织业务接口。选择“系统管理”后换取系统范围 Token，选择组织后换取固定绑定组织 ID 的 Token。即使账号是系统管理员，也须持对应范围 Token 才能访问该范围的接口；组织 Token 不自动授予成员业务权，系统管理员管理组织仍不伪装成成员。

选择组织时服务端重新核验账号、目标组织及相应权限：管理入口校验系统角色或组织管理角色，客户端入口校验成员关系。仅前端隐藏菜单不足以授权。切换统一换发 Token，后端从已验证 Token 获取当前范围；请求不能用组织参数覆盖 Token 范围。Token 采用 JWT，固定有效期 7 天；具体字段及接口由技术方案确定，复用现有身份及撤销机制。

客户端采用单窗口，当前只进入一个组织。每次请求与已接纳任务绑定发起时的组织；切换后的旧响应不得覆盖新组织。不会为后台模式切换增加客户端多窗口机制。

### 4.2 企业中心后台的空间与用户页面

使用同一个后台应用、现有布局和组件，选定范围后在顶部持续显示当前范围及真实操作者身份。顶部“切换组织”是进入后台后的唯一范围切换入口；系统管理员／超级管理员的选项包含“系统管理”和各组织，组织管理员的选项只包含本人可管理的组织；插件、模型、设备、调用、反馈等页面不再提供各自的组织选择器。整个页面树只消费一个已验证范围，不存在未选组织的插件／模型管理页，也不把“全部组织”作为这些页面的业务范围：

| 页面范围 | 顶部标识 | 主要导航 | 用户相关页面 |
| --- | --- | --- | --- |
| 系统管理 | “系统管理” | 组织管理、用户管理、安装包、官网／系统配置、系统审计 | “用户管理”展示全系统账号，可维护账号和系统角色 |
| 组织管理：系统管理员／超级管理员进入 | “组织：A”及“系统管理员／超级管理员”身份标识 | 组织成员、插件、智能体、模型、设备、调用、反馈、组织审计 | “组织成员”仅展示 A 成员，可维护 A 的成员关系；全局账号操作通过顶部统一切换进入系统用户管理 |
| 组织管理：组织管理员进入 | “组织：A”及“组织管理员”标识 | 同上，按实际权限提供操作 | “组织成员”仅展示 A 成员，只读，无新增、移除、角色调整、启停及重置密码按钮 |

系统管理员查看全系统用户的路径固定为：**顶部“切换组织” → 选择“系统管理” → “用户管理”**。从系统管理切到组织、从组织切到系统管理、组织之间切换，均使用同一选择器及相同的权限核验、草稿处理、请求清理和导航更新流程。不提供独立返回按钮或页面内快捷切换入口；组织管理员的选项中没有“系统管理”或“全部组织”。登录后的首次选择沿用同一组选项和范围语义。系统管理只是选择器中的系统范围选项，不是虚拟组织，不使用特殊组织 ID，不形成业务用户域。

系统管理员通过顶部“切换组织”选择任意组织。系统“组织管理”列表用于维护组织资料与状态，不另设“进入管理”切换操作。停用组织也可进入管理，以查看状态、排障和恢复；清晰显示“组织已停用”，不因此放开成员登录、模型调用或设备使用。进入和敏感管理动作记录真实操作者及目标组织。

系统管理范围的导航不出现插件、模型、设备、调用或组织反馈入口；组织范围的导航不出现全局用户管理、安装包和系统配置。未选择组织时访问组织业务深链接，返回范围选择页；已选组织但链接属于另一组织时，不静默换组织或加载数据，须显式经过全局切换。切换统一处理草稿、请求取消及旧响应丢弃，卸载旧范围页面后进入目标范围首页，避免旧详情 ID 沿用。

组织管理员在顶部“切换组织”中只能选择本人有管理权限的组织。若本人还属于其他组织但只是普通成员，这些组织不会成为可进入的后台管理目标；客户端组织选择仍按成员身份列出。

**两个用户页面按用途区分，不用一个含糊的“用户管理”页切换过滤范围：**

- 系统“用户管理”每个账号一行，包括尚未加入任何组织的账号。显示账号、显示名、账号状态、系统角色及组织归属摘要。组织筛选只过滤列表。点击组织数量可打开归属列表，直接添加或移除成员、修改组织角色，每次改动即时保存。
- 组织“组织成员”：显示账号、显示名、本组织角色、账号可用状态及本组织成员状态。相同账号在其他组织的角色、成员关系和全局敏感资料不展示；不因同名查询扩大到全系统用户。系统身份不自动列入组织成员，只有真实成员关系才显示。
- 组织管理员可以搜索、筛选、分页并查看上述只读信息。后端须提供限定本组织的安全投影和总数，不将完整全局用户响应交前端隐藏字段；任何成员写入及全局用户查询仍拒绝。
- 系统管理员在组织“组织成员”中进行添加成员、成员启停／移除及指定组织管理员；若需创建全局账号、修改系统角色、停用全局账号或重置密码，通过顶部“切换组织”选择“系统管理”，再进入“用户管理”，不另设快捷切换。界面明确区分“停用账号”和“停用本组织成员”。超级管理员保护及最后管理员校验继续在服务端执行。

刷新恢复先回读账号及所在范围的权限；后台可恢复仍有效的系统／组织页面，失权时清理旧投影并回到允许入口。重新登录按上表落点，不能用上次组织或 Cookie 绕过权限。切换范围前处理草稿和结果未知写入；旧响应不得覆盖新范围，不自动重发写入。

### 4.3 Desktop／Host Web

- 企业模式在左下角账号菜单内的用户姓名下方显示当前组织，点击组织名在菜单内展开列表。Host 地址由既有连接设置管理。纯本地模式隐藏组织选择。
- 既有中心地址／Host 选择和兼容检查保持；账号认证后展示组织选择，选择成功后连接该组织的本人 Runtime 用户域。前端继续通过 Host 处理凭据与业务，不直接持有中心 LLM key。
- 切换先预检目标组织，再按下节完成原组织任务终止；Host 确认全部收尾后才发起范围 Token 交换，目标组织重新核验并成功换发后，才启用新 Token 并替换会话列表、配置、插件投影、资源标签和 SSE 订阅。失败时保留原组织的有效访问或停止状态；原组织已失效则回到选择页，不回显无权访问的业务内容。
- 未发送输入和未保存配置按原组织保存或经用户确认舍弃，不能带入新组织。组织切换不搬移已有 Session、附件、记忆或卡片。
- 用户已明确：存在运行任务时提示是否终止，确认后由 Host 终止并等待全部任务结束，再切换组织。取消确认则留在原组织，任务继续原行为；不采用切换后保留原组织后台任务的方案。切换不退出全局账号，也不停止整个 Host。
- 客户端没有多窗口场景，不设计同时打开 A、B 组织的窗口或窗口间凭据协调。角色变化、账号退出和设备断开仍须明确作用范围。

### 4.4 确认终止后切换（2026-11-04 用户明确）

1. 用户选择目标组织，先处理未保存草稿并预检目标可访问性；Host 查询当前组织、当前用户业务域中的任务，覆盖所有会话，不仅当前打开的会话。无活动工作时仍由 Host 核验可安全切换，不以页面空闲代替判断。
2. 有活动任务或待执行队列时显示确认：“切换组织需要终止当前组织中的任务，是否终止并切换？”列出可核实的影响摘要，并说明未执行队列将停止调度、已发生操作不会回滚。按钮为“取消”和“终止并切换”；不提供保留任务继续切换的分支。
3. 用户确认后，Host 先阻止原域接纳新任务和继续出队，再调用 Runtime 既有取消与收尾机制。封闭准入、任务核查与停止必须协调，避免检查完成后又出现新任务；确认期间若工作范围出现新增，重新返回影响提示，不用旧确认静默扩大终止范围。
4. 终止范围是本次切换所连接 Runtime 中，原组织下本人用户域的受管工作，包括活动 Run、子任务、等待审批／用户输入、自动续跑及关联工具执行和辅助任务。其他用户、其他组织、其他独立 Host 不受影响；访问远端 Runtime 时由实际执行方收尾，不以本机断开连接代替终止。
5. 已排队但未执行的输入停止调度且保留内容，不能在界面切走后继续出队，也不能切回就自动重放；恢复须显式操作。具体存储状态与现有队列机制的复用归技术方案，不新增定时调度能力或静默删除输入。
6. 界面显示“正在终止任务”，等待期间不进入目标组织、不重复发起切换。只有 Host 确认任务终态、工具／受管子进程收尾及必要持久化完成，并保证原域不再自行接纳或派生工作，才能继续。取消请求已发送、SSE 断开或前端清空均不代表终止完成。
7. 超时、断网或部分任务未收尾时不切换、不声称全部停止；保留原组织上下文并提示实际状态。重新连接后先查询 Host 结果再决定下一步，不能盲目重发。停止一旦开始就不承诺撤回；取消等待或目标最终核验失败也不会恢复已停止任务。原域若已关闭，返回它须走正常初始化并保证不自动重放已取消工作。
8. 历史、附件、记忆、配置和已产生结果保留原归属；终止不回滚已执行的文件操作或上游调用，也不承诺撤回费用。无法确认停止的受管工作应阻止切换；已脱离 Host 控制的外部作业不能宣称已终止，技术方案须核对实际工具生命周期与可保证的边界。

此流程适用于客户端组织工作环境切换。企业中心后台仅切换管理范围时，仍按草稿与在途管理写入规则处理，不触发其他设备或用户的任务终止。

### 4.5 切换范围即切换 Token（用户已明确）

**唯一规则：Token 固定绑定当前范围，切换组织或系统管理都换发对应 Token，后端从 Token 取得范围。** 页面、请求头、请求体和 URL 中的组织值均不能独立决定或覆盖当前范围。

| Token 范围 | 绑定内容 | 允许访问 |
| --- | --- | --- |
| 未选择 | 已认证账号，尚无系统或组织范围 | 本人身份、可选范围、选择范围及改密／退出等登录流程能力 |
| 系统管理 | 已认证账号 + 明确系统范围，无组织 ID | 经系统角色校验的全局账号、组织、安装包、系统配置及系统审计等接口 |
| 组织 | 已认证账号 + 组织范围 + 固定组织 ID | 该组织内经当前角色／成员／设备授权进一步校验的操作 |

系统管理使用独立范围标识，不以缺少组织 ID 默认获得全局访问，不创建特殊组织或虚拟组织 ID。后台统一“切换组织”选项中的“系统管理”与普通组织走相同的 Token 交换流程。

**签发与验证（用户已明确）：**本期企业中心登录 Token 改为 JWT，未选、系统、组织范围均适用，组织 ID 直接放入签名载荷；每次成功签发后固定有效 7 天，普通访问和保活不续期，选择同一范围不重新计时。保留服务端有效会话和撤销机制，切换、退出或撤权后立即失效，不能只验签等到过期。到期要求重新登录，不引入静默刷新；中心重启仍使既有登录失效。

**两层凭据边界：**本项替换企业中心登录 Token；Host 会话 Token 保持现有随机格式及 7 天有效期，LLM key／设备密钥不改为 JWT。企业访问须同时满足 Host 会话与中心 JWT 有效，Host 换发不延长中心登录期限；中心 JWT 到期后，离线状态也不能继续授权。自然到期结束访问及关联中心连接，不等于确认终止全部 Runtime 任务；不删除历史，不自动重放工作。

**后端统一取范围：**鉴权入口验证 Token 后向业务服务提供可信范围。组织接口只能消费组织 Token 的组织 ID，系统接口要求系统 Token，系统管理员也不能用系统 Token 加参数绕过组织切换。系统“组织管理”维护组织资料时允许目标组织 ID 作为被管理资源标识，但不会将系统 Token 转成该组织的插件／模型／调用访问权。普通业务接口若同时含组织定位信息，必须与 Token 一致，否则拒绝。

**范围与权限分别校验：**组织 Token 只确定“当前是哪个组织”，不能永久冻结授权。账号启停、系统角色、成员状态、组织状态及操作权限继续由后端重验。系统管理员可换取任意组织的管理 Token，但没有有效成员关系时仍不得调用该组织成员模型或打开本人 Runtime；系统范围 Token 不签发组织 LLM key，也不能建立组织业务连接。

**统一交换过程：**

1. 当前 Token 认证操作者，目标范围仅作为交换接口的请求意图；服务端查询真实权限后决定是否签发，不能由前端提交角色或权限。
2. 后台先处理草稿和已发写入；客户端先完成前节确认终止与 Host 收尾。进入等待期间继续使用旧 Token 观察原域，不能提前替换 Token 造成任务停止结果不可查询。
3. 目标权限复核通过后，服务端在既有身份串行边界内提交新 Token 与本次旧 Token 失效；范围不在旧 Token 上修改。选择同一有效范围不重复交换。失败且未提交时原 Token 保持原范围，不自动恢复已经终止的任务。
4. 前端只接纳当前切换操作的成功结果，统一更新当前 Token 与身份投影，再卸载旧页面、订阅和加载目标范围；旧 Token 的迟到响应或鉴权失败不得覆盖／清空新 Token。界面展示的组织来自新 Token 的身份投影。
5. 交换提交后旧 Token 不再接纳新请求，关联旧 LLM key 和受控业务连接按原范围失效；已经接纳的管理写入始终归原组织，不能跨组织重试。仅撤销本次被替换 Token 及其派生访问，不全局撤销同账号其他独立登录或其他用户。
6. 若响应丢失而无法确定 Token 交换是否提交，停止业务导航并核验当前持有 Token；有效则仍按原范围处理，无效则重新认证及选择范围。禁止凭前端已选名称猜测成功、复活旧 Token 或自动重放业务写入。

**贯穿 Host 与代理：**Desktop／Host Web 仍只持本地 Host 会话凭据，中心 Token 和 LLM key 留在 Host。中心 Token 与 Host 对外访问凭据都必须固定绑定一致的中心／组织／用户范围，切换同步换发相关凭据，不把中心 Token 直接泄露给前端。LLM key 继承所属组织 Token 的范围，模型配置、续接、文件下载、SSE、WS、设备准入均不得脱离该范围。停机任务收尾继续由实际 Runtime 权威确认，Token 交换本身不能代替停止任务。

此处确定功能与鉴权契约；交换接口、凭据派生与清理细节、结果未知处理及现有退出路径如何复用，在 F01 技术方案中落实。后端不会维护独立于 Token 的另一份可变“当前组织”。

## 五、组织用户域与资源隔离

### 5.1 本地数据域

用户已经确认组织隔离：同一 Host 中，企业业务域由“中心 + 组织 + 用户”共同识别。每域独立拥有会话／Run、队列／定时任务、工作空间配置、托管文件与附件、记忆、个人模型配置及密钥、插件安装与设置、MCP／Skill 用户配置和资源标签。组织名称或编码变化不得改变域身份。

F02 的“个人模型”表示当前组织下本人配置，对组织其他成员不可见，也不因同一账号自动共享到其他组织。F03 的卡片与快照继承其所属 Session 的组织用户域。

工作空间目录不等于组织实体；一个组织用户域仍可有多个 Workspace。托管文件和路径引用按域鉴权，但用户显式选择的外部目录仍属于操作系统文件系统，不复制或搬移，不宣称 Shell／任意本机文件获得强沙盒隔离。首版不建立跨组织自动导入、共享或同步。

### 5.2 中心资源归属

| 数据 | 归属与校验 |
| --- | --- |
| 账号、密码、系统角色 | 中心全局；账号管理不能随当前组织切换变成另一份账号 |
| 成员关系、组织角色 | 组织 + 用户；请求时校验有效状态，不能只看登录时角色快照 |
| Provider、密钥、固定参数、默认模型 | 组织；公共代理地址／全局模板另属系统；F01 保持每组织单默认模型 |
| 智能体、插件、包与引用 | 组织；允许不同组织同名，引用解析、安装与下载均核对来源 |
| 调用、正文快照、用量、反馈、审计 | 发生时冻结组织及操作者身份，历史不从当前成员关系反推；系统级审计明确系统范围 |
| 设备登记、授权、桥接与远程桌面信令 | 设备归属组织，授权用户必须是该组织有效成员，实际访问仍校验具体权限 |
| 官网、安装包、协议、中心身份、存储根与全局资源限额 | 系统级；组织管理员不能修改全局基础设施 |

详情 ID、查询、分页总数、统计、创建／更新、关联引用、下载、快照、后台清理、异步回调和撤销通知都检查同一范围。子表可从受约束父资源推导归属，历史记录必须独立保留组织事实；不为每表机械加字段，也不以无组织条件的 ID 查询代替授权。

### 5.3 调用、反馈与审计的组织管理

组织管理员可配置本组织既有调用录制／保留策略，查询本组织调用记录、用量及正文快照，处理本组织反馈，并只读查看本组织管理审计。策略生效、正文读取、反馈处理及清理都必须按组织限制；更改 A 的策略不能改变 B 或平台全局资源上限。

系统管理员显式进入目标组织后拥有同类管理能力；其在该组织内的管理操作同样记录到该组织审计，组织管理员可见经脱敏的操作人及动作。全局账号、系统角色、平台配置等系统级审计只在系统管理入口查看；跨组织成员变更只向受影响组织投影必要的本组织事实，不暴露其他组织信息。

正文仍须显式按需读取并记录访问审计，不因开放组织管理而默认采集或加载全部正文。沿用现有策略变更确认规则；审计只读，不授予任意修改或删除审计记录的能力。账号或成员被删除后，历史权限依据事件发生时保存的组织归属，不按当前成员关系重新归类。列表、统计、详情及文件读取均在服务端验证组织，不能仅靠菜单或筛选条件隔离。

此范围仅包括中心已有的调用记录和正文快照，不授予读取成员 Host 本地会话、文件或个人模型密钥的权限，也不把个人直连调用纳入中心统计。

### 5.4 设备与多组织账号

设备审批、用户授权与注销按组织管理：组织管理员只查看和处理本组织设备及登记申请，授权候选仅包含本组织有效成员。设备详情、审批、授权变更和注销均由服务端重验操作者组织角色、设备归属及目标成员身份；不能通过更换设备 ID 或用户 ID 跨组织操作。注销和撤权沿既有机制结束相应受控访问并记录操作人、组织及设备，不清理用户本地历史。系统管理员可显式进入目标组织执行同类管理；两类管理员的管理身份均不自动产生设备使用权。

本草案保留一个 Host 设备登记属于一个组织的首版范围，但**设备登记不等于本机账号可进入的组织**：同一 Host 可持有同一账号多个组织的独立本地业务域，登录或选择组织不会自动重绑设备。

现有桥接依赖来源与目标设备登记。首版只允许当前组织与双方设备登记组织匹配时使用远程设备／桌面；本机登记在 A 而用户进入 B 时，本地 B 用户域仍可使用，基于该登记的 B 远程访问显示不可用。更换登记须显式结束旧授权和受控连接；不在切换组织流程中自动注销登记。

这是需要在功能设计确认时评估的产品限制。若要求同一设备无需重登记即可在多个组织组网，须扩展独立登记／授权生命周期并更新总体设计，不仅扩展组织选择器。

## 六、失效、撤权与失败行为

| 变化 | 影响范围与结果 |
| --- | --- |
| 账号停用／删除 | 全部组织访问及账号登录失效；结束该账号受控连接，保留历史，不自动删本地文件 |
| 组织停用 | 此组织成员访问与受控连接失效；账号仍可登录及选择其他组织，不能沿旧表述拒绝全局登录 |
| 成员停用／移除 | 仅对应组织／用户失效；撤销其设备授权，重新加入须重新授权；其他组织不受影响 |
| 组织管理员降为成员 | 管理权限立即失效；有效成员身份不因降级变成其他组织权限；后台回到选择页或无管理权限状态 |
| 设备撤权 | 仅相关设备访问及通道失效，不自动撤销其他组织成员关系 |
| 组织切换 | 有任务先提示，确认后 Host 封闭原域新工作并终止、等待收尾；全部结束才切换。取消确认、超时或失败不切换；不全局退出账号，不迁移任务 |
| 中心暂不可达 | 不能新登录或新选择组织；未到期的既有访问遵循临时故障保留规则，已知 JWT 到期仍须失效，不冒充已确认撤权 |
| JWT 到期 | 签发后 7 天失效，拒绝新准入并关闭关联中心连接；提示重新登录，普通请求不续期，Host 凭据不能绕过中心到期 |

中心收到已提交的停用／撤权后立即拒绝后续准入，并通知其在线 owner 关闭相关连接；已发送上游请求不能保证无费用。离线 Host 无法同步得知撤权，技术方案必须给出已有保活／重连下的传播语义与可测试窗口；不在功能设计中虚构全网即时停止或未经授权新增租约机制。

返回身份变化后迟到的配置、登录、快照或资源响应不能重新激活已失效域。写入结果未知时先读取核对，禁止自动切换机构后重试原写入。

## 七、历史迁移与兼容方向

1. 保留中心身份、全局用户 ID、用户名、密码和启停状态；新建默认组织，把旧业务资源整体归属该组织，并为旧用户创建相应成员关系。不为用户复制账号，不猜测拆分旧历史。
2. 旧管理员按本轮要求升为系统管理员；默认组织的组织管理员由系统管理员明确指定。旧超级管理员保护继续存在；迁移不擅自激活停用账号。
3. 现有 Host 域只含中心和用户，必须明确归入默认组织；不能把首次选择的任意组织作为旧数据接收方，也不能将旧历史复制到所有组织。新组织域默认空白。
4. 技术方案选择保留旧物理目录并固定绑定历史默认组织，避免搬移已有绝对资源引用；新组织使用独立目录，纯本地模式历史不纳入企业迁移。归属不明、重复目标或已存在冲突数据时停止，不自动合并。旧数据必须能继续被原用户在默认组织读取。
5. 中心、后台、Host、Desktop/Web 及 Client 配套检查协议；不支持组织的旧客户端明确要求升级，不默认落入默认组织。旧程序不得忽略成员或组织字段继续写新库。
6. 中心资源迁移与 Host 本地数据域迁移都需要独立核验和恢复路径；数据库与文件无法同事务的步骤必须先解释。生产／共享数据前按根 AGENTS 取得明确写入确认及已验证备份，本次设计不授权执行迁移。
7. 迁移演练使用 `.runtime-test/` 新建场景，核验账号角色、成员、组织归属、关键引用与精确数量，并通过正式登录、切换、资源和设备接口验证；程序、数据库与文件成套恢复。

## 九、可验证的验收标准

1. 一个账号加入 A、B，客户端登录后选择，组织管理员后台登录后选择管理组织；A 为管理员、B 为成员时角色独立；无成员关系、停用组织及伪造目标组织均不可进入。
2. 客户端和组织管理员后台仅一个可用组织时仍需明确进入，零组织有可恢复空态；系统管理员／超级管理员后台也必须先选择范围，选择系统管理后只出现全局导航，选定组织后才出现组织业务导航；零成员关系仍能管理组织；刷新仅恢复仍有效上下文，不以 Cookie、URL 或上次选择绕过权限校验。
3. 原管理员成为系统管理员，受保护账号及停用状态正确；组织管理员无法通过 API 创建全局账号、改系统设置或发布安装包。
4. 系统管理员／超级管理员可管理任意组织（包括停用组织的管理及恢复），不需要成员关系；客户端仍只能进入已加入的启用组织，不具有隐式用户历史或设备使用权。管理行为记录真实操作人及目标。
5. 同账号 A、B 的会话、托管文件、记忆、配置、插件与个人密钥分离；同名资源不串用，返回 A 可恢复其原历史。
6. 单窗口从 A 切换到 B：有任务必须确认；取消确认不终止也不切换，确认后由 Host 结束本人 A 域全部受管工作才进入 B。覆盖多个会话、审批等待、子任务、排队和确认期间新增工作；无任务路径也保证准入竞态不导致遗漏。切回 A 保留历史且不自动重放已取消或尚未执行的工作，迟到响应不覆盖 B。
7. 停用账号、组织、移除成员、角色降级、撤销设备分别只影响规定范围；跨组织权限、正文、下载、统计与异步任务不能绕过隔离。
8. 终止超时、部分失败、结果未知、断网及目标最终核验失败均不提前切换；重连先查询结果，已结束任务不被自动恢复，不误报工具停止或副作用回滚。临时故障不误删数据，已确认撤权不被旧结果恢复。
9. 组织管理员能审批、授权和注销本组织设备；仅可向本组织有效成员授予设备权限，跨组织详情及写入、非成员授权均被拒绝；系统管理员须显式指定目标组织。设备登记与当前组织不匹配时远程访问明确不可用，不静默重绑；管理员未被分配设备也不能使用。重新加入成员不自动复活旧设备授权。
10. 迁移只把旧资源／用户域归默认组织，新组织空白；旧用户名、密码、关键引用与历史可读，冲突不会被合并，旧端得到明确升级提示。
11. 最后一名有效系统管理员和各启用组织管理员的保护覆盖全局停用／删除及跨组织关系变更；系统管理员有明确恢复路径。
12. 组织管理员能配置本组织调用策略、查看记录／正文、处理反馈和只读查看组织审计；跨组织查询、统计及正文访问和系统级审计访问均被拒绝。敏感读取有审计，策略及清理不影响其他组织，历史不随成员删除而改归属。
13. 所有管理员登录后都先选范围；“系统管理”与各组织通过顶部“切换组织”的同一组选项切换，无独立返回或页面内切换操作；每个业务页无独立组织选择器，深链接不能绕过全局范围校验，切换不会复用旧组织详情或迟到响应。系统“用户管理”展示所有全局账号且不按组织重复，组织“组织成员”仅展示本组织成员；组织管理员只读且无法查询其他组织或系统用户，分页总数及详情同样隔离。系统管理员能维护成员关系，账号级操作进入系统用户管理；超级管理员使用相同导航并保留原保护规则。
14. 登录未选 Token 无业务权限；系统及组织 Token 只访问对应范围，伪造组织参数不能覆盖 Token。系统管理员也遵守范围约束，组织管理 Token 不绕过成员业务授权。切换成功旧 Token／派生 key 失效，失败不换范围；响应丢失、重复切换、旧响应及旧 401 不污染新身份，Host 凭据与中心范围一致；JWT 篡改／错误签名被拒绝，7 天到期（含离线与长连接）、中心重启失效及请求不续期均可验证。
15. 正式 Host／后台／Desktop-Web 的代表链路通过，不以菜单隐藏、前端模拟或仅数据库字段存在作为验收。外部文件与 Shell 的 OS 权限限制如实说明。

## 十、关键取舍与待确认项

**已由用户明确**：一账号多组织、登录后选择、系统／组织管理员分层、当前组织下本地数据与个人模型隔离，客户端仅有单窗口场景，以及切换前确认终止、Host 全部收尾后再切换，以及切换范围必须换 Token、组织 ID 固定绑定 Token、系统管理也使用对应 Token；企业中心登录 Token 本期改为 JWT，有效期 7 天。这些替代旧单机构方案，不再作为开放问题。

用户已明确设备审批、用户授权与注销，以及调用策略、记录／正文、反馈处理与组织审计均归组织管理员管理。修订后的界面方案：系统管理员／超级管理员后台同样先选范围，可选系统管理或任意组织；只有选定组织才显示插件、模型等业务导航，各页面不独立选组织。组织管理员只读查看本组织成员，成员关系仍由系统管理员维护。该界面方案和设备单组织登记限制随功能设计确认。原“切换后保留后台任务”建议已由用户明确替换为确认终止、等待收尾后切换。

成员关系和组织实体无法用现有账号单角色表达，具有明确权限与生命周期边界；其余尽量复用现有登录、事务、撤销、用户域和存储。不新增重复会话权威、客户端多窗口协调、通用 RBAC、额外租户进程或为将来用途设计的版本字段。
