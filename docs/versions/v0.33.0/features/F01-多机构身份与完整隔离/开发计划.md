## 二、台账原则

- 每个里程碑交付可通过真实接口或产品入口核验的闭环，中心、Host、UI 按交付需要协同，不按前后端目录机械分阶段。
- 未完成隔离的既有入口必须明确拒绝调用，不能用仅隐藏菜单的方式临时开放。中间里程碑只用于隔离环境验证，F01 全部完成前不作为可发布多组织产品。
- 数据迁移随所属模型改造在隔离夹具中验证，M4 完整演练升级与恢复；不把首次数据核验推迟到最后。未发布的新迁移随最终方案收敛，不改已发布迁移，也不为中间状态建立长期兼容。
- 测试采用 `.runtime-test/` 下每场景新建的独立 Runtime Home／隔离库，不使用用户 Home 或共享真实数据；实际连接、读表、影响和确认遵循根 AGENTS。
- 每个里程碑实现与验证完成后标记“🟨 待确认”并停止汇报；用户确认后才进入下一项。计划只维护结论与确认，过程记入本地开发进度，不新增验证报告。

## 四、各里程碑交付

### M0 中心身份与组织管理

**目标／前置**：按本计划启动授权，在当前源码基线上形成身份和管理闭环；采用技术方案中的内存有效会话、签名及兼容方案，不扩大成多实例认证平台。

**交付范围**：

- 组织、成员与全局账号分层，默认组织及旧账号归属的迁移基础；保留旧管理员提升、super 保护和启停状态。
- 中心 JWT 签发、7 天到期、作用域交换、撤销、动态权限复核和到期调度；改造既有 LLM key／连接 owner 的会话关联，未适配业务入口拒绝访问。
- 后台登录先选范围，顶栏统一切换；系统组织／用户管理及组织成员页可实际使用，组织管理员只读成员，最后管理员责任由服务端核验。
- 配套 OpenAPI／SDK 与必要协议门禁同步；普通账号具备组织管理角色时可登录对应后台范围，不再只认全局 admin。

**验证入口**：中心定向身份单测及隔离 PostgreSQL 集成；实际后台登录、零／单／多范围、成员只读及系统操作。执行中心／后台检查组，核验 JWT 篡改、到期、重启、并发换发、旧 401 和角色变更；对本阶段迁移核对旧账号及成员数量、字段与 API。

**完成判定**：三种范围不能互相冒充，JWT 到期／撤销确实拒绝访问，旧账号身份保护正确，用户与成员操作边界由接口执行；未适配的业务入口保持拒绝。

**Review 重点**：签名库和密钥生命周期、稳定撤销主体、同一 Token 交换原子性、系统角色与成员资格分离、全局停用时跨组织最后管理员检查。具体依赖版本在实现前核查，生产配置不写入公开文档。

**M0 完成结论**：中心身份、组织与成员接口、后台范围壳层和系统管理已实现，定向身份、隔离迁移和真实浏览器验证通过。默认组织成员按原账号建立，首位组织管理员由系统管理员显式指定。中心拒绝尚未组织化的业务入口，Host 配套、其他业务集成及生产升级留待对应里程碑。2026-11-04 用户确认 M0 后台验收通过，并授权进入 M1。

### M1 中心业务资源完整组织化

**目标／前置**：M0 获确认后，恢复并隔离全部现有中心业务入口，使组织管理员可管理本组织完整资源。

**交付范围**：

- 每组织单默认模型及 Provider／固定配置、代理准入、续接绑定、插件／包／智能体身份和下载发布；公共地址等平台配置留系统范围。
- 调用策略、统计、记录／正文、反馈和审计按组织；正文显式读取并审计，异步回调、清理和共享物理资源引用同样隔离。
- 设备申请、审批、用户授权、注销的组织归属与有效成员约束；后台对应页面接入现有组件和受限候选接口。
- 旧中心业务资源、历史记录及审计分类迁移在隔离旧版夹具上运行；不按当前成员关系猜测旧审计归属。远端 Host 尚未配套的连接继续拒绝。

**验证入口**：中心业务集成及后台实际页面；两组织同名资源、跨组织 ID／下载／关联对象／分页总数、正文审计、LLM HTTP／WS 与保留期清理。执行中心／后台检查组，检查历史数量、引用和正式 API 回读。

**完成判定**：已开放的中心资源与后台页面无全局漏读写，组织管理员能完成被授权管理操作且不能查询系统或其他组织数据；设备授权不能授予非成员。

**Review 重点**：Repository 可信范围来源、异步操作原归属、代理结算和到期连接、包字节清理不误伤其他组织、未知旧审计仅保留系统可见。

**M1 完成结论**：中心资源和对应后台页面已接入组织范围。迁移 014 在一次性旧版夹具上验证，默认组织继承历史资源和已知业务审计，未知历史审计保留在系统范围。两组织正式接口及实际浏览器验证通过。HTTP 续接以原组织、主体和配置绑定核验调用索引内的响应摘要，升级前的续接从完整上下文重新建立。设备远程连接进入 M2 后联调。2026-11-04 用户确认 M1 后台验收通过，进入 M2。

### M2 Host 组织工作区与设备接入

**目标／前置**：M1 获确认后，通过正式 Desktop／Host Web 登录进入指定组织，并与设备链路形成同一身份边界。

**交付范围**：

- Host 身份、域、凭据、存储、模型加载、插件同步、文件权限与资源绑定按中心＋组织＋用户隔离；Core 保持组织无关。
- 登录认证后先选本人有效成员组织；无组织、目标初始化失败、刷新恢复和 JWT／Host 会话到期都有真实状态投影。
- 旧企业目录固定绑定历史默认组织，新组织新目录；不搬移已有绝对引用，不自动合并冲突。纯本地模式保持原归属。
- 单组织设备登记、来源／目标／用户同组织准入、受控签发、撤权与离线到期检查；登记组织不匹配时组网不可用但本地组织域可用。
- Rust 协议与 TS 投影、Client 兼容及 Host 存储／布局门禁同步；在 M3 完成前不开放工作区内组织切换，只验证登录选择和重新登录进入。

**验证入口**：正式 Host＋稳定开发 Docker 中心＋Desktop/Web 登录，分别进入两组织并重启回读；验证旧数据仅在默认组织、共享文件访问边界、设备授权及到期／断网恢复。执行 Rust／Desktop／Client 受影响检查组，并核验旧 Host 对升级 Home 的拒绝。

**完成判定**：用户可进入独立组织工作区，历史与个人配置不串域，远端连接两端范围一致；管理员无成员或 grant 时不能借管理权使用业务域／设备。

**Review 重点**：域键传播完整性、旧目录可信绑定及冲突、稳定中心身份、Token 与 Host 会话双重期限、文件和远程资源 owner 不跟随 UI 选择漂移。

**M2 完成结论**：客户端登录后先选有效成员组织，Host 以中心、组织和用户隔离工作区，旧目录按中心确认的历史默认组织绑定。稳定开发中心联调核验了 macOS 与 Host Web 登录、两组织独立回读、设备同组织授权与断连恢复。旧 Host 升级准入及迁移回归通过。Windows 实机与完整升级恢复纳入后续联验。2026-11-04 用户确认 M2 并同意进入 M3。

### M3 任务收尾后切换组织

**目标／前置**：M2 获确认后，开放工作区内切换；只有原域全部受管工作确认收尾后才进入目标组织。

**交付范围**：

- Host 切换预检、确认快照、准入封闭、停止等待、严格收尾结果与范围换发；复用 Runtime 生命周期和受监督 owner，不另建任务账本。
- 覆盖所有原域会话、Run／子任务、Goal、审批、队列及工具／MCP／存储清理；未执行队列保留，切回和重启后必须显式恢复。
- 客户端左下角账号菜单内展开组织选择。草稿处理、终止确认、等待、断线查询、失败和目标初始化状态按交互设计落地。
- 后台范围切换与客户端场景联合复核：旧响应不污染新身份，选择同范围不换发／续期，失败不自动恢复已终止任务或重放写入。

**验证入口**：Runtime 定向取消／恢复与正式 Host 故障注入；实际客户端操作，覆盖空闲竞态、确认期间新增工作、待审批／排队、长工具、超时／强制 abort／未决交换、断网、Host 重启和目标初始化失败。执行受影响 Rust／Desktop 检查组及企业 E2E。

**完成判定**：无“任务尚未收尾就已进入目标”的路径；取消确认不停止，停止失败不换发，切回不重放，UI 等待与 Host 事实一致。

**Review 重点**：普通 shutdown 返回不等于严格成功，失败 owner 与 Store 独占、确认范围不被扩大、操作不阻塞整个 Host。实际工具进程和外部脱离控制作业的停止边界须在本里程碑实现前核清；无法证明受管工作已结束时阻止切换，不能靠文案宣称已全部终止。

**M3 完成结论**

Desktop 与 Host Web 已接入工作区内组织切换。Host 重新核对确认范围，在原域任务和资源确认收尾后换发组织凭据，待执行输入复用恢复态。稳定开发中心联调通过 macOS 与 Web 两组织往返、取消确认、终端收尾、旧凭据拒绝及浏览器回执丢失恢复。目标初始化失败通过客户端故障注入验证。Windows 实机和切换期间 Host 进程中断留待综合联验。2026-11-05 用户确认本轮验收并要求继续，进入 M4。

### M4 升级恢复与 Feature 验收

**目标／前置**：M3 获确认后，验证 F01 可作为完整多组织能力交付，为 F02 提供稳定边界。

**交付范围**：

- 在新建隔离环境完成旧版中心＋Host 数据整套升级及恢复演练；覆盖默认组织、旧账号／管理员／设备／审计、本地历史、文件引用和绑定冲突。
- 完成 Center/Admin、Host/Desktop/Web、Client 配套版本与协议准入；旧 Token 重新登录，旧端被拒绝且更新路径可达。
- 根据功能设计验收标准检查中心、后台、用户域、设备与切换的组合路径；补齐发现的归属或恢复缺口，同步模块约束及 Feature 完成结论。
- 形成可供后续实际迁移复用的步骤和恢复边界，保留在所属技术方案中；不创建单独验证报告，不执行生产迁移。

**验证入口**：已验证备份可读／可恢复，逐目标表精确数量与关键字段、文件存储及正式 API 分别核验；旧程序准入、登录选择、组织切换及撤权通过正式 Host 与浏览器验证。运行必要的综合编译／静态检查和核心回归；跨平台行为在对应原生环境验证，不以浏览器代替平台事实。

**完成判定**：M0—M3 已确认，功能设计验收项达到实际范围，升级和恢复不丢失／错分数据；未测限制明确，不存在开放的隔离、鉴权、迁移或任务收尾阻塞项。汇报后等待用户确认 F01 验收，不能直接启动 F02。

**Review 重点**：旧数据数量／引用／权限一致，恢复不是只回退程序；版本与 Host 布局门禁真实有效，无中间迁移兼容残留；源码基线与 v0.32.2 遗留归属清晰。

**M4 当前结论**

已在稳定开发中心的 PostgreSQL 容器内完成一次性旧库的备份、独立恢复和升级演练。正式中心接口验证了历史默认组织、成员修改与移除、最后管理员保护及撤权。使用真实 0.32.2 与 0.33.0 macOS Host 验证工作区保留、旧 Host 与旧客户端准入、备份恢复后旧 Host 可用。正式 Host Web 复验了历史工作区隔离、切换收尾、回执丢失与 Host 中断后的重新登录。

Windows 原生验证仍待补齐。开发中心的更新查询可用，当前无可下载的 0.33.0 更新，安装包下载及安装留待发布验证。2026-11-05 用户指定 M4 剩余验证及 F01 验收在版本联合验收时统一收尾。
