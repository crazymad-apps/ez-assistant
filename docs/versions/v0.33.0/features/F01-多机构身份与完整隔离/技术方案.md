## 三、身份、Token 与鉴权

### 3.1 Token 契约

用户明确本期将企业中心登录 Token 改为签名 JWT，固定有效期 **7 天（604800 秒）**；这取代此前保留随机 `ct_...` 的草案。未选范围、系统管理和组织管理均使用 JWT。Host 对客户端签发的随机会话 Token 保持既有 7 天机制，LLM key、设备 secret 和原生凭据不因本项统一改成 JWT。

JWT 载荷包含 `iss`（中心稳定身份）、`aud`（企业中心 API）、`sub`（字符串用户 ID）、`jti`（安全随机唯一 Token ID）、`iat`、`exp`，以及下面的 `scope`。组织 ID 直接写入受签名保护的载荷；系统范围不能省略范围字段后默认取得。

```ts
type AccessScope =
  | { kind: 'unselected' }
  | { kind: 'system' }
  | { kind: 'organization'; organization_id: string };
// exp = iat + 604800；organization_id 为不可复用 UUID。
```

中心使用成熟库签发及验签；本版仅中心验证中心 JWT，采用固定 HS256，启动时安全生成至少 32 字节进程私有签名密钥，不下发 Host／浏览器、不写日志、不持久化。保持中心重启后所有登录失效的既有行为，不为跨重启登录新增密钥配置或会话持久化。拒绝 none、算法替换、错误 iss／aud／类型、缺失或非法范围、非法时间及超期载荷。载荷不放密码、模型密钥、设备 secret 或可永久替代数据库权限的角色快照；签名不提供载荷保密。

复用现有唯一内存会话表，索引从完整 Token 调整为 `jti`；条目持有固定用户／scope／到期时间和原有稳定 LoginScope 对象。验签、有效期、有效会话存在且与载荷一致、当前账号／成员权限检查必须全部通过。范围只从已验证 JWT 提取；会话记录用于立即撤销及一致性检查，不提供可变“当前组织”。LLM key 关联 `jti`，其准入及到期服从对应 JWT 会话。

设备连接继续捕获会话表中的稳定 LoginScope 对象，不能每次解码 JWT 就创建新的撤销主体；退出、范围交换及到期统一移除会话并通知原有 owner。不是纯无状态 JWT，不新增数据库 Token 表、黑名单、刷新令牌或第二套会话账本。

每次成功新签发（含首次选范围和切换）从签发时计算 7 天；普通请求、保活和选择同一范围均不续期。到期后要求重新登录，无静默刷新。到期检查在每次准入生效，并由中心统一到期调度关闭关联 LLM／设备长连接、清理会话；不能等待下一次 HTTP 请求才处理已建立连接。中心过期错误须与临时不可达区分。

M0 使用 jose 6.2.15。登录、范围交换及 `/auth/me` 返回可信 `expires_at`（与 exp 一致），Host 在认证成功响应中保存它，不从未验签的 JWT 解码结果建立身份或到期授权。后台当前范围由 `/auth/me` 投影派生，组织名称只用于展示；旧 Token 不原位修改。

### 3.2 最小接口变化

身份契约由 Center DTO 导出 OpenAPI。M0 使用 `entry=admin/client` 缩小范围选择，切换请求由后端重新核验权限。

| 接口 | 作用与边界 |
| --- | --- |
| `POST /api/auth/login` | 沿用账号密码；只签发 unselected Token，不立即返回组织 LLM key |
| `GET /api/auth/me` | 返回账号安全投影及固定 scope；组织名称、本人组织角色和可用性为查询投影 |
| `GET /api/auth/scopes` | 返回当前账号可选范围；后台系统管理员可选 system／全部组织；客户端仅可选有效成员组织，入口参数只缩小结果，不授予权限 |
| `POST /api/auth/scope` | 输入目标 system 或 organization；用当前 Token 认证并重验权限，返回新 Token 及对应身份；无效目标不换发 |
| 既有 logout／password | 接受已认证 scope；退出撤销本 Token 及派生 key，本人改密保持既有规则 |

只有组织 Token 且具备有效成员业务资格才可获得 LLM key；系统管理员无成员关系仍可取得组织管理 Token，但不得借它调用成员模型、初始化用户域或使用设备。配置测试属于明确的管理权限，沿现有专用入口与记录类型，不借普通模型代理绕过成员要求。

### 3.3 交换原子性与失败

复用 IdentityService.write 串行边界：验证旧 Token → 在事务中复核账号／目标范围并写审计 → 先完成 JWT 签名及待发布会话准备，提交后一次同步发布新 jti／LoginScope、撤销旧 jti／LLM key并通知相关 owner。发布不跨 await，其他请求不能看到半更新状态；事务结果不明沿现有清空凭据与失败策略处理。

同一有效范围请求返回当前身份与凭据（不轮换）；同一旧 Token 的并发交换只有第一项成功，后续得到失效／冲突，不保留旧新双写窗口。仅替换这一 Token，不撤销同账号其他独立登录。调用方以原 Token 和当前操作对象匹配回执，旧 401 不能清理新身份。

响应丢失时先使用当前持有 Token 读取本人：仍有效则未切入新范围；已失效则重新认证和选择。中心不保存可再次领取的新 Token 副本，不自动重放业务写入。对后台这是可接受的重新登录恢复；对 Host，已停止工作不会因重登录自动恢复。

### 3.4 服务端权限入口

扩展现有 Guard／IdentityService 私有辅助方法，明确 account、system、organization-admin、organization-member 等操作策略；不要建立可配置权限引擎。组织范围业务的 Repository 参数中的组织 ID 必须来自鉴权上下文。系统范围管理显式目标组织时，须复核系统角色和目标组织。

- system Token 才能管理全局用户、组织、安装包、公开地址及系统审计。
- organization Token 才能访问插件、模型、设备、调用、反馈、组织成员等组织接口；系统角色可在该 scope 内行使管理权。
- 成员接口额外要求该组织启用、成员启用；设备访问再核验具体 grant。组织停用时仅系统管理员可进入管理／恢复路径，不能执行成员代理或设备访问。
- `/users` 保留系统账号管理。系统管理员可用系统 Token 调用 `/api/organizations/:id/members/:userId` 管理显式目标组织的成员关系。POST 新增成员，PATCH 只更新已有关系中请求携带的字段，DELETE 移除成员。系统与组织范围的写入路径共用最后一名管理员保护、设备授权撤销和目标组织审计。组织成员页的接口继续从 Token 获取组织，组织管理员只有只读权限。
- 系统管理中目标组织 ID 是被管理资源，不代表切换当前 scope。组织业务接口禁止用 body、header、query 改 scope；资源对象归属不匹配统一按不可访问处理，列表总数也限定组织。
- Guard 是初筛，事务写入和异步读返回前仍重新验证同一 Token 与真实角色；不能只在首次登录冻结角色。

不新增全局 revision／scope epoch。Token 对象身份已经提供换发隔离；组织／角色变更使用既有提交后撤销和在线复核，禁止为了可能的并发再引入第二组计数。

### 3.5 撤权传播与离线边界

中心在撤权事务提交后拒绝后续请求，并关闭自己持有的代理／设备连接。Host 复用现有 30 秒身份核验周期与 5 秒请求超时，核验有效范围和成员资格；正常调度且中心可达时，以提交后 35 秒内识别失效作为集成验证窗口，任务实际收尾耗时另计，不能将它写成所有任务已停止的时限。

网络不可达且中心会话尚未到期时保留既有本地域并显示中心不可用，不能登录、选择或切换范围；不增加独立离线租约。Host 必须按已认证响应记录的 expires_at 执行本地到期准入和连接关闭，不能把已知过期视为临时不可达而继续放行。撤权传播在离线时仍不即时，但该中心凭据授权最迟在自身 7 天期限结束时停止；提前恢复则首次成功核验必须识别撤权。在线周期、请求超时、原 Token 迟到结果和离线恢复均需故障注入验证；中心直连代理仍逐请求验权，不因 Host 离线状态放行。

## 四、中心数据结构与归属

继续一个 PostgreSQL、public schema、显式 SQL 迁移；下列是设计目标，不是本轮执行的 DDL。

| 对象 | 目标结构与约束 |
| --- | --- |
| `users` | 保留全局 ID／用户名／密码／启停。role 值为 user／system_admin（DTO 同步）；旧 admin→system_admin，旧 user 保持；is_super_admin 保留保护语义并参与系统权限判定，不当作组织角色 |
| 新 `organizations` | UUID 主键、唯一 code、name、enabled 与时间；ID 不随编码变化 |
| 新 `organization_members` | 复合主键 organization_id＋user_id，外键组织及用户，role=member/admin，enabled 与时间；不加额外 membership ID、角色字典或多角色表 |
| `center_identity` | 保持 center_id；增加默认历史组织 ID，作为旧域迁移的稳定来源；接收从 model_settings 移出的 public_origin，仍为平台字段 |
| `model_settings` | 主键由 singleton 改为 organization_id；默认 Provider／model 引用按组织校验。保留删除后失效引用的现有语义，不改成阻止 Provider 删除的硬外键 |
| `providers`／`model_fixed_configs` | Provider 增加 organization_id，UUID 保持；固定项从 Provider 外键推导组织，查询必须联查受限 Provider |
| `llm_recording_settings` | singleton 改为 organization_id，每组织独立模式及保留期，新组织默认不采集正文；平台内存／磁盘上限不下放 |
| `custom_agents`／`plugins` | 主键 organization_id＋name；内部按名称的插件／Skill／MCP 引用均在本组织解析 |
| `plugin_packages` | 主键 organization_id＋plugin_name＋version，复合外键指向本组织插件 |
| `llm_calls`／`feedback` | 新增不可随成员变更重算的 organization_id；调用历史不依赖当前 Provider 或用户是否存在；反馈幂等唯一条件包括组织＋原提交者＋submission_id |
| `management_audit` | system／organization 明确范围；组织事件存 organization_id，系统事件不存。CHECK 禁止模糊组合；现有 actor／target 历史字段保持 |
| `host_devices` | 新增 organization_id，设备 ID／安装 ID 保持；有效 installation 登记仍全中心唯一，体现首版一设备一组织 |
| `host_device_users` | 增加 organization_id，与设备复合键、组织成员复合键约束同组织；移除成员可删除 grant，停用成员同时撤销 grant，重新启用不自动恢复 |

新增 organization_members 的理由是同账号多组织和独立角色／撤权，不能用 users.organization_id 表达。公共地址复用现有中心 singleton，不为一项全局事实另建 settings 聚合。

为组织列表与时间分页补对应 `(organization_id, 时间, id)` 索引；唯一性和外键按真实引用设计，不给所有子表机械冗余 organization_id。业务查询与写入用已有 Repository／EntityManager，禁止从未受限实体读取后仅靠前端过滤。

系统管理员保护按全局计算；组织最后管理员按有效账号＋有效成员＋admin 角色计算，全局停用用户时检查其全部启用组织。系统管理员不自动计入组织管理员人数。已有超级管理员禁止停用／删除／降级规则保留。

## 五、资源、代理、记录与设备

### 5.1 模型与资源

F01 只改为每组织一个默认模型，F02 再扩展集合；Provider 管理、目录刷新、配置测试、LLM raw HTTP／WS、compact／input_tokens 全部复用既有路径并取得 Token 组织。

ModelsService 的默认模型准入仍有效，但配置查询、Provider 和固定参数必须属于同组织。historyBinding 的主体从 center＋user 扩为 center＋organization＋user，保留 Provider 周期／有效参数；不能只扩展 UI model 名。失效通知限定组织／Provider，A 的策略变化不回收 B 的连接。HTTP 续接同时验证调用索引内的响应 ID 摘要，摘要使用主体与配置绑定计算并随索引保留期清理；升级前的响应没有该归属证据，重新建立续接。WS 链由发起会话持有，注销、撤权及到期直接关闭。

Agent／插件名称、Host 已安装包 origin 及远端下载定位都带组织归属；旧中心插件 origin 显式迁到历史默认组织。包 SHA 可以继续共享物理字节，但下载先验证本组织资源关联，清理须检查所有现有引用，不因 A 删除而删掉 B 使用的字节。配置刷新、异步上传完成回调、临时文件发布均捕获原 Token／组织并在提交前重验。

### 5.2 调用、正文、反馈与审计

每次调用接纳冻结组织；请求中断及凭据撤销后的结算仍写原组织。记录、统计、正文读取、保留期和清理使用明确组织；后台任务从数据库真实组织枚举，不伪造系统管理员 Token 或借请求中的当前组织。

正文仍按需读取，内容返回前再次验权且审计成功；组织管理员只读组织审计。系统管理员以组织 Token 操作时审计落该组织，系统账号／角色操作落系统审计；成员变更同时留组织范围的最小事件，不将完整全局账号变更详情复制到所有组织。

### 5.3 设备与桥接

登记申请的组织从申请人组织 Token 获得；device secret 验证后从登记记录获得组织，不接受 WS 控制帧自报组织。审批、用户授权和注销允许本组织管理员，授权候选只查询有效组织成员。

来源设备、目标设备、用户 scope、授权关系必须同组织；组织管理身份不隐含设备使用权。Host 登记文件保留单中心单有效登记，在 Enrollment 增加固定 organization_id；切换用户组织不修改登记。进入与登记不匹配组织可使用本地业务域，组网入口明确不可用。

现有目标端受控签发 prepareLogin 必须生成与访问组织一致的 organization Token，不能生成无范围凭据；renew／ready、HTTP/SSE/WS 及远程桌面信令都复核原 scope。组织停用、成员移除、grant 撤销和 Token 交换在提交后通知 owner 结束对应访问，未知／迟到连接不能复活。

## 六、Host 组织域与切换编排

### 6.1 域身份与路径

UserKey 改为 `(center_id, organization_id, user_id)`，HostUserIdentity、Credentials.users、模型 loader、插件同步、用户域槽位、文件准入和设备访问统一使用此键。系统／unselected Token 不允许构造业务域 Key。Runtime 继续拥有 Session／Run，Host 只管理访问及资源生命周期。

新组织域采用扁平路径 `users/<center_uuid>_<organization_uuid>_<user_id>/`，由校验后的 ID 生成，不使用组织名称／编码；保留 UserPaths 对 users 父目录的保护结构。所有当前机构配置和本人模型密钥、记忆、MCP／Skill、附件与插件状态在该域。

旧路径 `users/<center_uuid>_<user_id>/` 仅绑定中心明确声明的历史默认组织，方案选择保留该物理目录，避免无必要搬移已有绝对资源引用。新 Host 在现有 Host 配置中持久固定该中心的 legacy_organization_id，首次仅信任配套中心认证响应中的稳定映射，后续冲突停止；没有可信映射时不得认领旧目录。默认组织不存在旧目录则可创建新格式路径；两种候选目录同时存在时拒绝自动合并。该兼容分支只服务真实旧数据，不依登录顺序或猜测目录归属。

旧 Host 必须由 Host 布局版本及数据库准入阻止运行；仅更改新目录名无法阻止旧 Host 打开旧目录。升级核验需覆盖旧 Host 对本 Home 的拒绝，以及配套恢复后旧程序可用性。具体布局版本字段按现有 host_configuration／host_layout 账本演进，不新增独立目录索引表。

### 6.2 分开中心 Token 与 Host 会话 Token

后台直接持中心 JWT；Desktop/Web 继续只持 Host 随机会话 Token，中心 JWT／LLM key 留在 Host。Host 登录后保存受监督的未选范围身份，查询可选范围不装配 Runtime；选择成功才发布组织 HostUserIdentity 并预热对应域。

切换时中心组织 Token 换发、Host 会话 Token 也换发，scope 必须一致。现有 UserState 按组织域持当前中心登录，客户端会话按自身 Token 持有固定 Key；旧会话不会因当前界面变化而自动指向新 Key。系统范围不进入客户端组织选择列表。Host 自身 7 天会话与中心 JWT 分别检查，企业访问必须两者都有效；Host 本地换发不能延长中心 JWT 的期限，中心到期后需重新认证。

不得直接调用现有 enterprise_logout 作为交换：它会 end_user 并提前丢失原域状态。原域停止、中心换 Token、发布新 Host 会话分别由现有 HostAccess／UserDomains owner 串行组织，业务任务事实仍由 Runtime 返回。

### 6.3 任务收尾后交换

拟新增 Host 访问层的切换预检／执行／状态查询能力，属于用户域访问生命周期，不作为普通 Agent 工具。现有 HostAccess actor 只接收和发布状态，网络与停止等待由其监督的单个操作 owner 执行，不长时间占住全 Host 配置 actor。每个原域最多一个切换操作，重复请求读取同一在途状态；不另建持久操作表。

流程为：

1. 核验目标组织可用，取得原域当前工作摘要；Host 暂存一次确认快照，绑定发起会话、原域和目标组织。
2. 用户取消则丢弃确认，无停止副作用。用户确认后 Runtime 在 operation_gate 独占边界重新检查工作集合；新增 Run／子任务／输入或其他需要终止的工作则要求重新确认，已有工作自行完成不扩大影响。
3. 确认吻合后，封闭原域新工作准入及队列驱动，再沿既有取消、审批清理、Goal 停止、工具与 MCP 收尾路径结束工作。该状态属于 Runtime 生命周期，不在 UI 保存副本。
4. 复用原域关闭和 Store flush／join，关闭这一个组织用户域，不停止 Host 进程。未执行输入保留；重新进入时复用恢复态／显式 resume，不自动出队。具体须检查所有恢复入口、Goal 和排队命令，不能只设置易失 queue_paused_by_user 后假定重启仍有效。
5. 严格核对没有受管运行任务、工具未决交换或未完成清理；得到成功结果后才向中心换 Token。普通 shutdown 发生强制 abort、unknown pending 或 Store/MCP 失败，均不得作为切换成功。状态查询留在 Host 层，原域关闭后不因查询进度重新初始化 Runtime。
6. 中心换发成功后提交新 Host 会话，关闭旧会话及其业务连接，初始化目标域；前端收到可信身份后重建投影和订阅。初始化目标失败则显示目标初始化错误，不能把旧 Token 恢复成有效或自动重启原任务。
7. 停止超时／失败则不换中心 Token，原域保持已停止或关闭失败的实际状态；重复查询可观察收尾，不承诺撤销停止。只有显式重新进入才可重新装配原域，且恢复不重放工作。
8. 中心交换响应未知或 Host 在交换后崩溃，按身份恢复／重新登录处理；不引入跨中心、Host、数据库和网络的伪原子事务，不后台自动重试 Token 交换。

原域成功关闭后清理既有缓存槽位；关闭失败保留阻塞 owner，禁止打开第二个 Store。Host 重启后不恢复未完成的 UI 切换操作，只按已持久任务事实恢复；用户重新登录选择范围。

确认快照使用既有任务身份和队列 revision 表达真实变化，不新增持久全局 generation。若为传输使用一次性确认引用，它只关联 Host 内存快照和 owner：不匹配即重新预检，过期／重启失效，不能作为身份授权；需覆盖新任务出现、旧确认重复、目标变化及迟到确认。实现不得把该引用扩展为第二套任务账本。

## 七、前端与协议投影

AdminStore 保持唯一当前 Token 与身份投影，scope 切换后卸载原范围路由树。顶部范围名称下拉菜单同时列出允许的系统管理选项；系统导航与组织导航互斥，不在业务页新增组织参数控件。页面请求捕获 Token，所有旧响应／错误在身份不匹配时丢弃；首次登录后未选范围 Token 只在内存保存，Cookie 在成功换发系统或组织范围 Token 后写入。

系统用户接口展示全局账号；组织成员接口仅返回 user ID、用户名、显示名、账号可用性、本组织角色与成员状态。组织管理员不能从该 DTO 获取其他组织归属或全局敏感信息，也不能调用成员写入。

ApplicationConnectionStore 承担客户端选择／确认／等待／发布新凭据投影，RootStore 只在成功后替换；停止期间保留原范围显示和 Host 层状态查询。既有 Web 同步通知不得把组织切换当成全账号 logout。所有 SSE、资源标签、插件与模型查询随身份范围重建。

前端以可信 expires_at 提示登录到期；后台会话 Cookie 仍沿现有保存策略，Cookie 存续不代表 JWT 有效。自然到期关闭访问和关联中心连接，不等同于用户确认组织切换，不自动清空队列、迁移任务或保证在途模型调用继续成功；Runtime 已接纳任务沿既有生命周期处理，重新登录不自动重放。

Center DTO 通过 Swagger/OpenAPI 生成后台 SDK；HostLogin、HostUserIdentity、Host 范围选择和切换结果由 Rust 协议导出 TS。Agent 模型类型不携带企业作用域；Client 只同步必要兼容与随包 Host 信息，不复制鉴权业务。

## 八、升级、历史归属与恢复

### 8.1 配套版本

本方案建议企业协议提升为 `[5,5]`，应用双向最低兼容版本及受影响 Host 存储最低版本为 `0.33.0`；Host 布局同步拒绝旧端。理由是登录结果、Token 范围和用户域形状不再允许旧客户端忽略。该数值为技术方案待确认项，本轮不修改常量。升级后不兼容旧 ct_ 登录凭据，统一重新登录取得 JWT，不增加双格式长期兼容。Center/Admin、Host/Desktop/Web 及随包 Client 必须配套，不增加旧客户端自动落默认组织回退。

### 8.2 中心迁移

新增迁移，禁止修改已发布 001—012。迁移创建固定默认组织，保存其 ID 到中心身份；旧账号保留身份并创建默认组织成员；旧 admin 提升系统角色、启停不变、super 保护不变。默认组织首位管理员必须明确指定，迁移不擅自提升所有旧管理员为组织管理员。

已有模型、插件、Agent、设备、调用及反馈归默认组织；保留 ID 和文件引用。旧管理审计混有系统及组织动作，按审计 action 的明确白名单及实际资源归属分类：账号／发行／全局动作留系统，明确组织业务动作归默认组织；不能可靠分类的留系统历史且标明旧记录，不向组织泄露未知范围正文。未知 action 数量和处理口径在演练时必须可核对，不能按当前用户成员关系猜测。

同一事务完成字段回填、约束与索引、singleton 拆分及唯一迁移账本；跨文件／Host 绑定无法与中心 DDL 同事务，配套恢复必须独立设计。启动自动升级开关不能替代生产确认。

### 8.3 执行前门禁与回退

先在 `.runtime-test/` 新建一次性场景演练。生产／共享环境实施前逐一核对真实主机、端口、库、表、文件根和实际 API 读表；停写，建立独立数据库及文件／Host 配置备份，验证可读取、关键表精确 COUNT 与恢复可行性，再取得执行确认。

先准备可升级客户端和中心完整制品，维护窗口结束在途连接并迁移中心；更新 Host 布局与配套应用、核验旧域绑定后再开放。任何数量／归属／引用异常停止后续共享数据写入；恢复用匹配程序、库、配置及文件，不能仅回退代码。

演练恢复按同一个停写时点保留中心库、文件根及 Host Home。先将中心备份恢复到空库并核对原表行数与关键字段，再验证升级。Host 回退时先停止当前进程，保留升级后的目录供核对，再将配置、SQLite 和关联文件恢复到原 Home 路径，以保持原有路径引用，最后由匹配版本的 Host 启动并验证工作区可读。

无用户数据的全新安装直接创建完整最终形态；默认组织未有明确管理员时先允许系统范围初始化管理，未完成初始化不宣称组织可交付。不删除旧 Runtime Home、不自动搬移任意用户文件，品牌默认目录定制已于 2026-11-06 随 F04 移出本期范围。

实现时按受影响模块运行定向单测、Center 隔离 PostgreSQL 集成、正式 Host 与浏览器链路，再完成必要编译／静态检查；文档阶段不运行应用测试，不连接用户数据库。性能关注组织索引、成员查询和停机上限，不增加无关全量压测。

本方案不建立额外服务、通用 RBAC、持久 Token 存储、任务账本、配置缓存或全局版本计数。新增实体仅组织与成员；新增 Host 切换 owner 对应必须跨请求存活的真实停止／交换操作，Runtime 任务与生命周期保持原权威。

## 十、确认与下一步

用户已明确：企业中心登录 Token 改用 JWT、有效期 7 天。需随技术方案确认的具体选择：进程私有 HS256 密钥及内存有效会话，保持重启失效；企业协议 5／最低 0.33.0；默认组织旧目录保留且固定绑定；切换复用域关闭但采用严格成功门槛；组织成员关系仍由系统管理员管理；设备登记仍单组织。旧审计分类与外部脱离控制作业的可保证停止边界，必须在相应实现里程碑前依据夹具及实际工具核查，不可无证据宣称全部收尾。
