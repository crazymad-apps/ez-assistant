## 二、入口与协议

### 2.1 插件包

带 UI 的包采用 `format_version=2`，保留原字段并增加 `ui.entries`；最低 Host 为 `0.33.0`。既有 v1 包按原规则读取，不改写历史包。中心与 Host 使用同一组清单样例校验，旧端拒绝新格式，不能忽略 UI 字段后假装完整安装。

入口最小结构如下，字段由实现时的 Rust／中心契约及生成类型统一：

| 字段 | 含义 |
| --- | --- |
| `id`、`title`、可选 `icon` | 包内唯一身份与展示信息 |
| `kind` | `card` 或 `app`；同一资源支持两种用途时分别声明入口 |
| `resource` | 包内 HTML 相对路径，或已声明 MCP server＋`ui://` URI；二选一 |
| `input_schema` | 初始化／定位参数约束，复用现有 JSON Schema 校验 |
| `capabilities`、`csp` | 请求的宿主能力、后端工具与网络范围；声明不等于授权 |
| `snapshot_schema`、`readable_snapshot_schemas` | 卡片当前写入格式及可读取格式，用于升级后判断快照兼容；应用入口无需声明 |

包内资源复用归档路径校验，禁止越界、符号链接逃逸和参数替换代码地址。首版 HTML 连同脚本、样式构建为单文件；图片等大资源通过声明且获准的资源地址引用。业务源码和打包样例归独立插件仓库。

MCP 工具继续使用标准 `_meta.ui.resourceUri` 关联 UI。项目扩展以工具 `_meta["ez-assistant/entry"]` 指明入口 ID 与 `card/app` 用途；包内入口与工具声明须一致。同一资源有两个入口时按入口 ID 选择，不按 URI 猜测。未声明项目扩展时，仅按标准 inline 卡片接入。独立 MCP 的应用目录通过 `resources/list` 的 `_meta["ez-assistant/entries"]` 入口数组发现；不能为了列出应用而执行业务工具。工具绑定的卡片资源仍可直接按 URI 读取，无需列在资源目录。

### 2.2 MCP Apps 接入

以稳定规范 `2026-01-26` 为首版基线；Desktop 引入官方 `@modelcontextprotocol/ext-apps` 的 `AppBridge`，页面使用 `App`。2026-11-05 核查 npm 发布为 `2.0.4`，M0 已精确锁定该版本，实际 peer 为 `@modelcontextprotocol/core/client 2.0.0`、`zod 4.2.0`，协商版本为 `2026-01-26`；上游随包许可证声明一并保留在 `apps/desktop/public/licenses/mcp-apps.txt`，不以 npm 元数据替代实际许可文本。[规范](https://github.com/modelcontextprotocol/ext-apps/blob/main/specification/2026-01-26/apps.mdx)、[SDK](https://github.com/modelcontextprotocol/ext-apps)。

- Host 在 MCP initialize 声明 UI 支持；`McpToolDefinition` 保留所需 UI 元数据与 visibility，`McpConnection` 增加受控资源列表／读取。只读取当前获准 server 的 UI 资源，不提供任意 URL 代理。
- `visibility` 同时约束目录披露与实际调用：app-only 工具不进入 Agent 目录，模型手填名称也不能调用；页面仅调用所属 server 中允许 app 访问的工具。
- 工具结果分成模型投影与 UI 载荷：保留既有 content／structuredContent 处理，页面专用 `_meta` 单独有界保存，不进入模型、普通日志或全文索引。[工具关联与可见性](https://apps.extensions.modelcontextprotocol.io/api/documents/overview.html)。
- 支持标准初始化、完整工具输入／结果、环境更新、资源读取、获准工具调用、尺寸及销毁；首版不依赖流式参数预览。只公布实际支持的能力，未知请求明确拒绝。
- 标准打开链接沿普通浏览处理。首版不支持自动发起推理、`ui/update-model-context` 或 fullscreen／pip；“交给 Agent”采用项目草稿能力，经用户发送，不能将草稿填入冒充标准消息已发送。

项目扩展统一置于 `ez-assistant/` 命名空间，在初始化时协商，不扩写标准显示模式：

| 扩展操作（拟定名称） | 输入与结果 |
| --- | --- |
| `open-app` | 目标入口／外部地址、定位参数、可选实例键；返回关联句柄及连接结果 |
| `post-message` | 关联句柄与有界业务载荷；目标关闭时失败，不排队重放 |
| `save-snapshot` | 当前卡片的预期修订及快照；返回已提交修订 |
| `set-composer-draft` | 有界文本；用户确认后发送，不创建 Run |

初始参数、容器用途、关联句柄和已保存快照通过项目初始化扩展交付；随后定位／消息使用同命名空间通知。扩展具体 Schema 在首个验证点随 SDK 类型固定，标准 MCP App 不需要依赖项目扩展。

## 三、发布记录与恢复

`publish_card` 在 Runtime 中实现，输入只有入口引用和参数；用户域、ConversationOwner、Run／子任务执行及工具调用身份由装配上下文绑定。MCP 卡片在既有网关取得结果后进入同一个发布操作，页面自己的交互调用不再次发布卡片。

新增用户域 SQLite 表 `message_cards`，因为卡片需独立于模型正文更新快照；不把 UI 状态写进 Conversation JSONL：

| 内容 | 保存方式 |
| --- | --- |
| 身份及归属 | card ID、现有 ConversationOwner、执行锚点、对应可靠 ToolExchange／调用身份 |
| 入口与初始数据 | 来源身份、入口 ID、发布时包摘要／资源 URI、显示名、初始参数、MCP UI 结果 |
| 最新快照 | JSON、格式标识、`snapshot_revision`；无快照时为 null／0 |
| 展示顺序 | 使用表的稳定递增主键顺序，不另建全局事件序列 |

发布事务用现有可靠工具交换及调用身份建立唯一约束，返回已存在记录即可处理重复回执。提交后才发送卡片变化事件；事件丢失后从查询恢复。MCP 业务已返回而卡片保存失败时报告“业务结果已返回，卡片未保存”，不自动重跑工具；不能用本地事务承诺远端副作用与卡片同时提交。

消息分页按实际 ConversationOwner 和已加载轮次查询卡片，并在该轮最后一段显示一次；纯工具／失败轮次也保留锚点。卡片查询与事件均不携带完整 HTML。子任务使用现有 child owner，不创建额外 Session。删除会话清理所属记录；分支复制的历史卡片仅复制截止点前已提交记录和快照，生成新 card ID，保留历史来源，不能重放原工具或继承活动端点。

快照使用 CAS，解决 Desktop 与 Host Web 基于同一旧快照更新的真实冲突：页面提交 `expected_revision`，Store 在事务内相等才写入并加一，首次为 0；不等返回冲突及当前修订，由页面重读并处理，不自动合并或覆盖。相同状态可 no-op；提交回执丢失先重读核对。修订随卡片持久恢复，旧数据没有卡片，无需回填。验证必须覆盖两端同修订竞争、旧值拒绝、回执丢失、重启续写和空库初始化。

挂载句柄与修订职责不同：句柄仅存 Runtime 当前连接上下文，绑定真实客户端、用户域、入口及页面实例；卸载或换域即失效，保存前校验。它阻止退役页面写入，CAS 阻止仍有效的两个页面互相覆盖，不再增加持久 generation 字段。

## 四、页面承载与资源栏

Desktop 和 Host Web 共用 React 页面容器及 AppBridge；`ResourceTab` 增加 `app` 分支，使用现有标签组与 20 页面 LRU。卡片使用同一承载组件，按可见性挂载；不把卡片页再塞入资源栏缓存。

标准 UI 采用隔离 iframe／sandbox proxy，HTML 通过受认证 RuntimeClient 读取后交付，不以带登录 Token 的 URL 加载。代理只转发绑定页面的消息；页面不取得主应用 DOM、Cookie、Tauri command 或通用凭据。CSP 按资源声明收紧，禁止默认外联、顶层导航及未批准浏览器权限。Web 的 proxy 必须与主应用不同源。[沙箱要求](https://github.com/modelcontextprotocol/ext-apps/blob/main/specification/2026-01-26/apps.mdx#sandbox-proxy)。

### M0 承载调整（已确认）

原首选 `data:` 代理已被否决：正式 CSP 禁止该 frame；仅放行 frame 后，代理仍继承主页面的脚本策略，子页面 meta 不能放宽它。不能为此开放主应用内联脚本。回归入口为 `apps/desktop/tests/e2e/web-mcp-apps-csp.spec.ts`；原生核对入口为 `apps/desktop/tests/native/mcp-apps-csp.swift`。这些检查用于否决原路径，不表示 M0 已完成。

用户确认改用**现有唯一监听上的匿名静态代理响应＋响应头 CSP sandbox**：

- 新增固定的 `/ui/sandbox-proxy` GET／HEAD 静态入口，不接收 HTML、URL 或用户参数，不鉴权、不取得用户服务、不访问数据库、不回传 Cookie／Token，也不返回 `Set-Cookie`。该入口只提供随构建发布的受信任代理代码，不是资源代理或第二个应用监听。
- 响应头 `Content-Security-Policy: sandbox allow-scripts; …` 强制代理获得唯一 opaque origin；外层 iframe 保留标准要求的 `allow-scripts allow-same-origin`，响应策略进一步限制有效权限。不能使用同源 URL 本身作为隔离证明，必须验证实际消息来源为 `null` 且父 DOM／Cookie 不可读。主页面脚本策略保持不变，仅为固定代理入口增加 frame 加载许可。
- 代理响应不继承主页面 CSP。代理的静态响应策略提供必要加载上界；内层页面必须在任何插件内容前安装按声明生成的更严格 CSP，默认禁止联网与嵌套 frame。声明范围校验、meta／base 注入、导航撤权及跨平台结果在产品实现中独立验证，不能把原型的握手通过当作全部完成。
- 标准 UI 经双 iframe 转发，仍使用精确 Window 引用与一次连接绑定，不能只检查 `origin=null`。关闭、刷新和重新加载均替换连接；不向页面公布尚未实现的工具或项目扩展。
- Windows WebView2 的原始 Wry 0.55.1 忽略 main-frame 初始化标记，导致 Tauri 核心与 IPC 凭据进入子页；响应 CSP 不能阻止原生注入。根 Cargo 通过 `vendor/wry` 覆盖同版本依赖，在初始化执行前落实主 frame 检查，all-frame 脚本保持原样。来源、许可证、块作用域兼容约束及移除条件见[受控依赖说明](../../../../../vendor/README.md)。不修改 registry 缓存，也不以删除页面变量或调用超时冒充隔离成立。
- 外部 HTTP／HTTPS 页面由独立 iframe 直接加载，通过 `allow-scripts allow-same-origin` 保留可核验的来源。主容器在交给 AppBridge 前核对当前 Window、完整 origin 和本次握手。Host API／登录来源拒绝接入。刷新或导航撤销旧连接，跨来源需重新授权。

独立原型已验证固定 SDK `2.0.4` 与其 `@modelcontextprotocol/core/client 2.0.0`、`zod 4.2.0` 能以 `2026-01-26` 完成初始化及完整输入／结果通知，代理有效来源为 opaque，页面不能读取父 DOM／Cookie。此后 M0 已接入产品依赖、资源 API、设置页预览与共用容器。**原型结果只证明方向；正式路由、资源 CSP、外部来源已完成本地核验，平台状态仍分别记录**。用户已确认按此方向继续 M0；若标准或目标 WebView 不接受该响应隔离方式，再评审独立沙箱域名方案，不静默退化。

外部 URL 接受 HTTP 和 HTTPS，浏览器直接加载用户指定的页面。Host 只提供宿主页和静态沙箱代理。连接前显示真实来源和请求能力，主容器校验实际消息来源、页面实例及握手。跨来源跳转需重新授权，同源新文档也需重新握手。外部页面的网络访问受其响应策略约束。Web 中的嵌入还受浏览器混合内容和外部站点的限制。

应用复用键为 Host／用户域＋现有资源组＋来源／入口＋实例键，浏览器 URL 不参与 app 去重。`open-app` 从发起卡片所属组打开，不能误用切换后的当前组；相同目标聚焦并交付新参数。每次打开返回独立关联句柄，复用应用可区分多个卡片来源，回传不能只指向“最后一个卡片”。用户直接打开时没有卡片访问权。

首次接入通过 UI 能力探测，旧客户端不展示不支持的 app 标签；配套 Host／Desktop 使用当前版本的统一协议生成物。标签恢复仅扩展现有资源快照中的入口描述，不保存桥接句柄、授权凭据、DOM 或业务数据；恢复后重新连接。卡片快照由 Runtime 保存，应用业务状态由自身后端保存。关闭、导航、LRU 淘汰、插件更新与组织切换统一撤销对应端点、待处理请求和关联，不等待页面配合才撤权。

## 五、页面工具调用与权限

AppBridge 不直接连接 MCP Server。请求经现有 RuntimeClient／Host 鉴权进入 Runtime，再复用 MCP Registry 的 Schema、连接租约、超时与调用实现。保留现有 `rmcp` 连接，不为每个页面启动 MCP 进程。

现有审批上下文依赖 Session／Run，不能直接拿历史 Run 授权，也不能伪造一个 Run。实施时为现有审批来源增加 `app` 分支，绑定用户域、真实挂载句柄、server／tool 和本次调用；复用规则匹配、待审批 Registry 和确认组件，页面调用不生成模型对话。会话内应用继承适用的当前会话规则；草稿直接打开的应用使用用户级规则，不擅自获得会话授权。显式 Deny 不可由页面授权覆盖。

页面调用按当前连接内请求 ID 去重；断线后结果未知不自动重试副作用，由应用核对自身后端。应用关闭时取消未执行审批并取消在途本地调用，外部已发生副作用仍可能存在。F01 切换组织的等待范围须纳入这些在途调用；Runtime 收尾完成后才换域，不让“没有 Agent Run”成为绕过切换门禁的理由。

## 六、改动与验证边界

- 协议：卡片查询／变化通知、挂载／释放、快照提交、应用来源审批及页面调用 DTO 放 `assistant-protocol`，TS 由既有导出器生成；SDK、连接和数据库类型不进入公共协议。浏览器内纯容器路由留客户端。
- 存储：沿 v0.33.0 迁移链新增卡片表与索引，写入当前 F01 用户域的 `runtime.sqlite3`；不扫描历史工具结果补造卡片。保留现有 0.33.0 存储下限，迁移只在已核验隔离库验证，正式库另按安全流程执行。
- 升级：沿现有插件写门和 MCP 退役流程关闭 UI 端点；读取资源时短暂占用包，不让长期 iframe 阻塞升级。当前包只在声明可读格式时恢复旧快照，否则占位；不缓存旧可执行代码作为回退。
- 限额：首轮建议 HTML 解码后 2 MiB、单次参数／消息／快照 256 KiB，复用 MCP 原调用结果上限；每页面有界在途请求，超限明确拒绝。容量值在首个验证点以实际包校准，不新增管理配置页面。
- 验证顺序：先验证官方 SDK＋双端沙箱＋外部页面握手，再验证双发布、离线恢复／CAS、页面调用审批及换域收尾，最后使用独立插件仓库样例完成正式 Host 联调。纯数据 MCP、普通浏览器和无 UI 的旧包必须回归。

### M0 实际能力与限额

- 已实现的应用命令为 `ListMcpUiResources`／`ReadMcpUiResource`，请求携带完整 MCP 来源目标；只读本人当前活动连接，URI 必须在目录中或由当前工具绑定。读取复用连接租约、调用限流、超时与退役取消，迟到旧连接结果不返回给新连接。
- 设置页的“界面资源”使用正式 RuntimeClient 与共用 `McpAppView`。它仅用于预览，不调用业务工具、不发布卡片、不保存页面状态；配置／目录快照变更或用户域退出时撤销预览。插件清单 v2、卡片发布与结果 UI 副本持久化继续属于 M1。
- M0 的 AppBridge `hostCapabilities` 为空，不公布工具调用、模型上下文写入、自动发消息或项目扩展请求。已支持初始化、完整输入／结果通知、主题上下文、受限尺寸和销毁；`ez-assistant/notifications/retired` 仅是代理内部的无载荷失效通知，不是页面授权接口。M1—M3 按实际实现再开放对应扩展 Schema。
- 固定上限：HTML 解码后 2 MiB；工具／资源 UI metadata 64 KiB；结果私有 metadata 256 KiB；页面单条消息 256 KiB、最多 8 个未答复请求；每类 CSP 来源最多 32 项，仅接受有界 HTTPS origin，连接额外允许 WSS。目录沿既有分页与总量预算，不抓取任意 URL。浏览器权限均拒绝，不因声明而授权。
- 主应用仍禁止内联脚本及 data frame。资源代理使用独立响应 CSP；资源自身策略在任何插件内容前安装，默认禁止联网。使用精确 Window／实际 origin 过滤及无正文日志的 transport，导航、再次初始化、关闭或容量超限均使本实例失效。
- 外部页面的实际来源保持可见；跨来源握手被拒绝。受浏览器安全限制，嵌入拒绝和没有通信协议不能始终可靠区分，统一显示“页面未完成应用连接，可能不支持通信或限制嵌入”，不冒充已连接或未经证实的具体原因。
- 已核验正式 Host Web 与 macOS 正式 Tauri CSP 探针。原生探针使用产品 security.csp、资产协议与共用容器，并从正式 Host 读取资源；其测试窗口与 WebView 存储独立，不等同于完整产品界面验收。Windows 按用户要求延后；全局检查未通过项仍按开发计划保留，不以定向结果替代。


### M1 已实现契约与限额

- 包格式 v2 的 `ui.entries` 在中心和 Host 扫描时验证；共用正反例夹具。Host 已安装插件摘要新增可选 `ui`，只投影当前声明，不返回 HTML。v1 包继续使用原契约，不接受 `ui` 字段；v2 最低 Host 为 0.33.0。每包最多 128 入口，包内 HTML 为有界 UTF-8 单文件，图标最多 256 KiB；复用包校验和正式安装收据。
- `publish_card` 输入固定为 `{plugin, entry, arguments}`，只发布当前已启用、配置完整插件的 `card` 入口；参数须符合入口 Schema。MCP 工具关联 UI 在业务调用返回后自动发布；结果 UI 副本连同私有 `_meta` 独立保存，最多 256 KiB，普通模型投影不携带它。UI 副本超限或发布失败只补充“业务结果已返回，卡片未保存”的提示，不重执业务工具。
- `ListMessageCards` 只查询 owner 和已加载的消息／Run；每页最多 100 项，稳定 `position` 游标。当前 child owner 查询其自己的卡片，在该子历史最后一段显示。卡片发布绑定持久化的真实 started 工具交换；同 owner、receipt、call 唯一。卡片表不参与模型正文或全文检索，运行控制释放后记录仍保留。历史清理和重写在原事务内同步清理；分支仅复制保留锚点，使用新 ID，并按原顺序保留最新快照。
- `MountMessageCard` 按当前入口读取代码，交付参数、UI 结果和最新快照；旧代码不作为恢复回退。包入口与当前输入／快照格式不兼容，或独立 MCP 配置身份变化时，显示不可用占位。页面工具调用仍未开放，标准 MCP inline 卡片未声明项目快照能力时只读已有输入／结果。
- 页面初始化的 `hostCapabilities.experimental["ez-assistant"]` 声明 `cardState:{version:1}`，仅获准的卡片另声明 `saveSnapshot:{version:1}`。初始化后按顺序发送标准输入／结果及 `ez-assistant/notifications/card-state`，后者参数为 `{revision, snapshot, schema}`；`snapshot` 是 `{schema,value}` 或 null，`schema` 是当前可写格式或 null。
- `ez-assistant/save-snapshot` 接受 `{expected_revision, schema, snapshot}`，响应 `{saved, revision, snapshot}`。受信客户端补齐 owner、card ID 与短期实例 ID，页面不能选择这些身份。保存使用 Session 门和 Store 事务 CAS；冲突返回最新已提交值，客户端保留当前页面并提示重新加载，不自动覆盖或重跑模型。相同快照可 no-op，过期回执须先重读核对。
- 短期端点绑定 Runtime 用户域、owner、卡片、客户端生成的临时实例标识及当前包／设置身份。端点仅存内存，最多 512 个，空闲 1 小时失效；同卡片同客户端重挂载替换旧端点，成功核验的保存延长有效期。导航、关闭、不可见卸载、重连、配置／来源变化撤销客户端连接；Runtime 在每次保存时独立核对当前身份，迟到事件不能绕过校验。客户端标识用于实例替换，不替代 HTTP 身份认证。
- 页面单条消息上限仍为 256 KiB、最多 8 个未答复请求，参数与快照值分别最多 256 KiB；消息封装也计入 transport 总量，超限必须由页面缩减。卡片 HTML、快照和 UI 私有结果不进入普通 Debug 或桌面偏好。

### M2 已实现契约与限额

- `ListUiApps` 汇总已启用且配置完整的包 v2 `app` 入口与当前独立 MCP 目录声明，不执行工具。独立 MCP 使用资源 `_meta["ez-assistant/entries"]` 的 `PluginUiEntry` 数组；入口的 `resource.server/uri` 必须绑定当前服务与该目录资源，已打包 MCP 应用沿包清单入口。无扩展的标准资源保留原预览／内联路径。目录最多 512 项、应用描述合计 2 MiB；MCP 来源失败保留其余项及重试提示。
- `ReadUiApp` 核验完整入口与初始化／定位参数，读取当前代码并返回来源身份；不读取卡片记录、不创建会话或 Run。包资源读取沿用短租约；MCP 读取核对同一连接与来源。暖页每次定位重新校验，身份及声明相同时保留现有 iframe，变化时撤销旧连接后重建。
- 挂载插件应用时，`ReadUiApp` 用同一包租约读取 `ui.entries[].icon` 声明的包内图片，沿用 256 KiB 上限。支持 SVG、PNG、JPEG、WebP、GIF 和 ICO。客户端仅将可选的 `icon_data_url` 用于右栏标签图片，缺省或解码失败时显示拼图。
- 应用标签复用每设备资源组、现有 20 页缓存和 Desktop 恢复记录。身份由 Host／用户域下的资源组、入口目标和可选实例键确定；同 URL 的浏览器与应用独立。已挂载页面按稳定键排列，LRU 访问顺序只决定淘汰，避免切换时移动 iframe 导致 WebKit 重载。Desktop 保存入口及实例键，不保存 HTML、定位载荷、关联、草稿或来源许可；恢复重新读取，若入口要求参数则由用户或卡片重新定位。Web 沿现有布局存储规则，不把会话资源标签写入浏览器缓存。
- 外部应用接受 HTTP／HTTPS 独立来源，拒绝 URL 内嵌用户名或密码、当前 Host 和主界面来源。用户查看 origin 和能力后确认加载。重连、恢复及来源变化重新确认，握手和跨来源拦截复用 M0 容器。
- 已授权页面通过 `hostCapabilities.experimental["ez-assistant"]` 协商 `openApp`、`postMessage`、`setComposerDraft`（各 `version:1`）。`ez-assistant/open-app` 接受 `{target, arguments, instance_key?}`，在发起方资源组打开／聚焦应用，校验并等待握手后返回 `{handle}`；目标收到 `ez-assistant/notifications/link-opened` 的 `{handle, arguments}`。目标可以是包入口、独立 MCP 入口或需用户确认的外部地址。
- `ez-assistant/post-message` 接受 `{handle, payload}`；对端收到 `ez-assistant/notifications/link-message` 的同形通知。关联仅存在于参与的两个实际页面端点，其他页面即使取得句柄也不能使用；每端最多 32 条关联，单次业务消息 128 KiB。关闭／淘汰／重连／来源变更撤销，存活对端收到 `link-closed`；不排队或重放。转发前即时核对客户端、资源组及来源代际，不依赖 React 清理时机。
- `ez-assistant/set-composer-draft` 接受最多 64 KiB 的 `{text}`，只交给当前来源对应的现有 Composer。已有内容时由宿主确认替换；确认期间输入变化、换域或来源退役使提议失效。不会自动发送，也不改变附件或引用。M2 不协商页面工具调用或模型上下文写入。

### M3 页面工具权限与任务收尾

- 标准 MCP Apps `tools/call` 通过 AppBridge 进入 `UiTool` 命令。运行时在挂载时绑定真实用户域、会话或草稿以及当前 MCP 连接。带 `call-tool` 的 MCP 应用和 MCP 资源型插件入口可以协商 `serverTools`。标准内联 MCP 卡片沿绑定服务协商。设置预览、外部 URL 和无绑定服务的包内文件页没有工具入口。
- 调用只接受当前服务的原始工具名及参数。两端分别校验 `visibility`，共用 MCP Schema、连接租约、单次调用和限额。页面专用结果只返回原实例。页面调用不创建 Run、消息或新卡片。
- 正式会话使用当前会话、工作区和用户级权限文件，草稿只使用用户级权限文件。显式 Deny 优先，显式 Ask 仍进入审批。同时覆盖 Build 和 Plan 的 Allow 可直接放行。没有匹配规则时，受信沙箱确认的真实点击默认允许它触发的单次工具调用，其余请求仍通过现有待审批 Registry 的 app 分支确认。点击标记仅在代理与客户端间传递，脚本生成的点击、缺少受信标记的请求和重复使用的标记都按普通请求处理。执行前由 Runtime 复核当前规则与来源。
- 页面请求 ID 在当前挂载内去重，每页最多 8 项未收结果及 1024 个请求 ID，当前 Runtime 同时最多 64 项。审批等待最多 60 秒，客户端停止查询一段时间后 Runtime 取消该调用。结果只交付一次，断线或执行后未能确认结果时提示核对业务结果。
- 导航、关闭、页面淘汰、连接替换和插件退役撤销原挂载。Runtime 跟踪页面在途调用直到本地收尾，计入 F01 换域预检和确认后的等待。终止超时使换域失败。外部副作用已发生时由应用或服务核实。
