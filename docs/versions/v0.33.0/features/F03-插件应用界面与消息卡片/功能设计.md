## 一、目标

支持插件提供消息卡片和完整应用页面，并在右侧资源栏接入外部 HTML 应用。卡片用于消息内交互，应用页面承载完整业务，二者可传递参数和结果。页面自行组织业务，宿主负责承载与通信，日常交互无需 Agent 中转。

## 二、开发内容

### 2.1 界面入口与卡片发布

插件可声明卡片入口、应用入口或两者，包含名称、界面资源、初始化参数约束及所需宿主能力。**UI 资源决定加载哪份 HTML，入口声明决定展示在消息内还是右侧应用标签。** 同一 HTML 可供两类入口复用，实例分别初始化。

| 插件形态 | 卡片发布方式 |
| --- | --- |
| 轻量插件：Skill＋包内 HTML＋入口声明 | Agent 调用内置 `publish_card`，传入卡片入口和初始化参数，无需独立 MCP 服务进程 |
| MCP 插件：工具＋关联 UI 资源 | 调用关联卡片 UI 的工具后由宿主展示，无需再调用 `publish_card`；可关联业务工具或独立展示工具 |

两条路径共用渲染、发布记录和快照机制。Skill 负责指导工具使用；普通 MCP 数据或链接结果不自动成为卡片。发布仅允许使用已安装／已连接、启用且兼容的声明入口，不接受模型生成的任意 HTML／JS 或替换代码地址。

中心与 Host 同步支持入口声明及校验，旧的纯 Skill／MCP 包继续可用。未声明侧栏扩展的第三方 MCP App 按支持的标准能力内联展示；不支持内联时提示不兼容，不猜测展示位置。

### 2.2 消息卡片展示

- 卡片位于所属 Run 的正文下方、消息操作栏上方。发布后即可显示，流式正文继续在上方更新，工具执行记录仍归处理过程。
- 同轮多张卡片按持久发布顺序排列；无正文或 Run 后续失败时，已发布卡片仍保留。
- Runtime 保存发布记录。发布成功表示记录已保存；页面加载与业务执行另行反馈。无客户端在线时也可发布，后续打开可见。
- 同一次工具执行的恢复或重复回执不重复创建卡片；独立发布允许产生不同卡片。加载失败只重试加载，不重调业务工具。
- 子任务卡片归自身会话／执行详情，不自动复制到父会话。删除会话同时清理卡片记录和快照，不撤销外部业务。

### 2.3 右侧应用标签

扩展现有单窗口资源栏，保留浏览器标签，增加应用标签：

| 项目 | 浏览器标签 | 应用标签 |
| --- | --- | --- |
| 内容 | 普通网页 | 插件／MCP 声明的应用，或显式接入的外部 HTML 页面 |
| 控件 | 地址栏、前进／后退、刷新 | 应用名称、图标、来源、连接状态，以及刷新、重连、关闭 |
| 宿主通信 | 无应用桥接 | 握手并授权后开放约定能力 |

资源栏“新增”菜单提供“应用”，可直接选择声明入口或输入外部 HTTP／HTTPS 地址。浏览器中的“作为应用连接”打开独立应用标签并保留原浏览标签。

卡片打开应用的流程：**点击打开 → 宿主校验入口与权限 → 展开资源栏并打开／聚焦应用 → 完成握手并交付定位参数 → 应用回传结果，卡片更新展示及快照。** 原卡片保留，应用是独立实例。

相同应用目标复用已有标签并更新定位参数；不同目标另开标签。复用范围为实际 Host、用户域、资源分组、入口来源与身份，以及可选实例键。关闭标签释放界面与连接，不等于终止应用后端任务；恢复标签时重新校验和连接。

### 2.4 页面与宿主通信

采用 MCP Apps 的 UI 资源关联、初始化、工具输入／结果、获准工具调用、环境上下文和生命周期能力。以下作为显式协商的宿主扩展：

- 在右侧打开／定位应用，以及向已绑定的卡片或应用传递参数和结果。
- 外部 HTML 页面通过地址接入、握手和授权；无需先包装为插件。
- 卡片最新快照的保存与恢复。

右侧应用不是标准 fullscreen，普通打开链接也不等于连接应用。内置页面与外部页面共用受限桥接；普通网页不自动获得权限。外部页面须主动支持通信，禁止嵌入时如实提示，系统浏览器仅作为普通浏览退路。

页面可访问自己的业务后端，或调用声明且获准的现有 MCP 等能力；纯展示页面无需后端。宿主只在已授权端点间转发消息，不解释业务字段、不提供持久消息队列。页面需要 Agent 时可填入输入草稿，由用户确认发送。

身份与权限由宿主绑定，页面不能读取通用登录 Token、模型密钥、未授权会话或文件。导航、刷新、关闭、组织切换及权限失效后旧连接失效，迟到消息不得进入新页面或新用户域；重新连接须重新核验。

### 2.5 快照、恢复与不可用状态

每张卡片保存初始参数和**最新一份成功保存的快照**，由 Runtime 持久化。页面直接上报，不经过模型、不新增消息；重新挂载时交付初始参数及快照，不重放工具、按钮操作或历史消息。

- 保存成功以持久提交为准；失败或结果未知时保留上次成功快照并提示，旧实例或并发更新不得静默覆盖较新状态。
- 快照只恢复界面，业务执行结果由插件向自身后端核对，不能靠快照判断是否应重复执行。
- 离屏卡片允许卸载，重新进入时恢复已保存状态，不保证界面持续运行或未提交状态不丢失。
- 插件更新、禁用或卸载后旧界面与连接退役。入口缺失、配置不全或快照不兼容时保留历史记录和不可用占位，不自动安装、清空快照或运行旧包代码。
- 快照继承会话访问权限，不保存通用凭据；大文件通过受权资源引用。断线重连后重新核验身份，从持久记录恢复。

## 三、模块分工与范围

| 模块 | 开发内容 |
| --- | --- |
| 企业中心 | 插件入口声明校验与分发，不存用户卡片状态 |
| Runtime／Host | 发布工具及 MCP UI 接入、发布记录与快照持久化、资源加载、通信和权限校验 |
| 共享协议 | 入口、卡片、应用通信与快照所需跨层契约 |
| Desktop／Host Web | 卡片渲染、应用标签、侧栏联动、连接状态和资源释放 |
| 独立插件仓库 | 业务页面、Skill、入口声明与验证包 |

复用现有工具循环、插件生命周期和资源栏。现有机制缺少 UI 入口、卡片发布记录与快照，因此补齐这三项；Agent Core 不增加业务分支。不新增插件后端执行框架、业务数据库、页面搭建器、快照历史、多版本插件运行池或客户端多窗口。

协议、承载与持久化见[技术方案](技术方案.md)；布局与操作反馈见[界面交互设计指导](界面交互设计指导.md)，用户要求继续，按当前设计进入开发计划。

## 四、验收标准

1. 轻量插件与 MCP 插件均可发布卡片，共用承载；入口决定展示位置，旧插件保持可用。
2. 卡片顺序、轮次及子任务归属稳定，重复回执不重复发布；离线发布、刷新和失败轮次均可恢复记录。
3. 用户或卡片均可打开内置／外部应用；同目标复用、不同实例分开，卡片与应用可直接交换参数和结果。
4. 浏览器与应用标签明确区分，未支持协议或未授权页面不能获得宿主能力；不支持的扩展或嵌入方式明确反馈。
5. 最新快照可持久恢复；失败、冲突及旧实例回写不丢弃已保存状态，恢复不重复执行业务。
6. 插件更新、缺失、禁用、卸载和快照不兼容保留可解释的历史占位；组织切换、导航及关闭使旧连接失效，跨用户／组织数据不串用。
7. 使用独立插件仓库验证包，在正式 Host 链路验证 Desktop 与 Host Web 的卡片、应用、焦点及资源释放。
