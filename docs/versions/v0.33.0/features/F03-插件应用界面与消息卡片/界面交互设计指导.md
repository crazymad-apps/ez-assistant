# v0.33.0 F03 界面交互设计指导：卡片与右侧应用

2026-11-06 用户确认 F03 本地范围验收完成，Windows 按用户要求延后。[验收结论](开发计划.md#六feature-验收结论)

交互沿用现有桌面布局、组件与主题。[功能设计](功能设计.md)和[技术方案](技术方案.md)

## 一、页面与入口

| 位置 | 调整 |
| --- | --- |
| 正文与消息操作栏之间 | 显示所属轮次的卡片列表 |
| 右侧资源栏 `＋` | 保留现有项目／浏览器／终端等项，增加“应用” |
| 卡片内部 | 插件可提供“打开应用”等业务操作，由宿主打开右侧标签 |
| 浏览器工具栏菜单 | 增加“作为应用连接”，保留原浏览器标签 |
| 原插件管理页 | 展示包提供的卡片／应用入口及不可用原因，安装配置仍沿原流程 |

Desktop 的资源 `＋` 同步修改原生菜单，Host Web 使用对应 Web 菜单；两端入口和文案一致。

## 二、消息卡片

```text
助手正文（继续流式更新）

┌ 入口名称                         插件／服务来源 ┐
│                                                │
│                 插件卡片内容                   │
│                                                │
└────────────────────────────────────────────────┘
  仅异常时显示：更改未保存 · 重试保存

消息操作栏（复制、分叉、时间）
```

卡片外框、来源、加载和错误提示由宿主绘制，业务按钮和内容由插件绘制。多卡片纵向排列，按发布顺序显示；宿主不重复添加业务标题或统一“确认”按钮。

- 卡片宽度跟随消息列。内容区域按插件上报的高度调整，使用固定的 600 CSS 像素上限，超出时在卡片内滚动。改变窗口高度只会改变会话可见范围。
- 手动刷新时保留卡片内容区的原高度。新页面加载后采用最新上报的高度，加载失败时显示可重试的错误提示。
- 发布即显示加载容器；无正文也保留卡片。正文流式更新不得反复重建 iframe，用户已向上阅读时不抢滚动位置。
- 点击卡片内输入控件时不抢回 Composer 焦点；离屏卸载后回到可见区恢复最新已保存状态。
- 子任务卡片显示在子任务详情，父会话不重复展示。分页接入时同轮卡片仅显示一次。
- 保存成功保持安静；保存中可用轻量状态，失败持续提示“更改未保存”。“重试保存”只提交快照，不重做业务操作。

## 三、打开与使用应用

点击资源栏 `＋ → 应用` 打开选择面板。上方列出可用应用的名称和来源，下方可输入 HTTP 或 HTTPS 地址并连接。

首次连接外部页面，在宿主面板展示地址来源及请求的能力，按钮为“连接”和“取消”。授权绑定当前用户域与本次页面连接；恢复／来源变化时重新核验，不把浏览器登录态当成授权。没有可用内置应用时保留外部地址入口；读取列表失败显示重试，不伪装为空列表。

```text
右侧资源栏
[上下文] [浏览器] [应用图标 应用名称 ×]                ＋
──────────────────────────────────────────────────────
应用名称 · 插件／服务来源         已连接     刷新  ⋯
──────────────────────────────────────────────────────
                    应用业务页面
```

应用标签不显示任意改址栏；菜单提供重连、查看来源与关闭。浏览器保留地址栏和导航控件。当前只有一个页面时也保留类型与来源区分，同一 URL 的两类标签分别存在。

从卡片打开时展开右栏并选中目标应用，原卡片留在消息中；同目标已有标签则聚焦并传入定位参数，不清空业务页。用户直接操作触发的打开可移动焦点到应用工具栏，自动恢复标签不抢焦点。

关闭应用只关闭该标签和通信，不删除卡片。应用回传结果后由卡片更新内容，不自动发送消息；“交给 Agent”先填写草稿，已有未发送草稿时询问替换或取消，不能覆盖用户输入。

## 四、权限与状态反馈

在卡片或应用内真实点击触发的单次工具调用默认直接执行。工具调用按规则需要确认时，宿主弹窗显示应用名称、真实服务、工具与参数，页面显示“工具调用等待确认”。会话和草稿使用各自的权限作用域。弹窗复用既有审批参数组件，提供“拒绝”和“允许本次”。

| 状态 | 显示与操作 |
| --- | --- |
| 加载／连接中 | 容器显示加载状态，可关闭；加载完成后等待握手，不提前显示“已连接” |
| 资源或通信失败 | 显示“加载失败”或“连接失败”，提供对应重试；保留卡片／标签 |
| 页面未完成连接 | “页面未完成应用连接，可能不支持通信或限制嵌入”；保留来源与重新加载入口，不声称已连接或已识别具体原因 |
| 权限被拒绝 | 显示拒绝原因，返回应用；不重复弹出确认或自动换通道 |
| 快照冲突 | “状态已在其他客户端更新”，提供重新加载；不静默覆盖 |
| 插件缺失／禁用／配置不全 | 保留名称和来源，显示具体原因及原插件管理入口 |
| 更新后入口或快照不兼容 | “当前版本无法恢复此卡片”，保留历史，不自动清空后重试业务 |
| 导航／断线 | 显示未连接，旧请求失效；重新握手后恢复可用状态 |

切换组织沿 F01 统一入口及终止任务确认；提示范围包含应用发起的在途工具操作。用户确认后等待 Host 收尾，成功才切换；失败留在原组织及原资源组，不出现新组织配旧页面的中间界面。

## 五、视觉与交互验收

复用现有颜色、边框、圆角、Icon、Button、Dialog 和菜单，不另建主题。通过 MCP Apps 环境上下文向页面提供主题、尺寸与语言；主题切换更新上下文，不重载业务页面。宿主菜单、审批及错误提示始终位于页面之上；原生浏览器遮挡沿现有处理。

重点验收：宽窄窗口下卡片尺寸与滚动稳定；正文流式不重挂载；键盘可进入／退出卡片及应用；关闭后焦点回到可用控件；两种标签容易识别；多卡片打开同一应用后结果回到正确卡片；重载／换域／页面导航后的状态和权限正确。Desktop 与 Host Web 均验证，原生菜单及正式 WebView CSP 单独实机核对。
