## 二、台账原则

## 四、里程碑范围与完成判定

### M0 MCP Apps 承载基线

**目标／前置**：实施前置满足后，先证明技术方案中 SDK、MCP 资源链路和沙箱能在正式产品约束下工作。

**交付范围**：接入官方 AppBridge，补齐现有 MCP 连接的 UI 协商、元数据和资源读取；实现共用隔离页面容器及最小初始化／销毁。用通用夹具验证包资源形态、标准 MCP HTML 和外部 URL 握手，固定实际 SDK 版本、扩展 Schema 与限额。仅开放本步实现并验证的能力。

**验证入口**：现有 Host MCP 协议测试扩展资源读取和 visibility 场景；Desktop 构建及正式 Host Web 页面验证；macOS／Windows 在正式 WebView CSP 下核对初始化、资源策略、页面来源、导航和释放。夹具走真实 Host 与客户端路径，不以独立宽松网页代替。

**完成判定**：声明与实际协商一致；标准页面可以加载，未授权来源及失效实例被拒绝；外部页面能识别真实来源，拒绝嵌入和不支持通信均有明确结果。沙箱方案在目标平台成立后更新技术方案定稿。不可验证的平台保留未完成项，不能用其他平台结果替代；承载方案不成立时先修订设计，不推进后续实现。

**Review 重点**：不丢失 UI 元数据、不向模型泄露页面私有载荷、AppBridge 不泄露宿主凭据；不同源隔离和导航失效有真实验证，保持唯一 Host 监听与原生浏览器既有边界。

**当前结论**：承载修订已确认并落实为正式 Host 静态代理、MCP UI 协商／元数据／资源读取、可见性限制与共用 AppBridge 容器；设置页提供资源预览。Host Web 与 macOS 正式 Tauri CSP 下的初始化、隔离、交互、外部来源及释放链路已通过，本地构建与相关回归通过，具体边界见[技术方案](技术方案.md#m0-实际能力与限额)。用户于 2026-11-05 在进度汇报后明确“继续”，据此确认本地交付并进入 M1；Windows 按用户最新要求延后，不记全平台验收通过。

**并行与遗留**：用户于 2026-11-05 明确要求 Windows 交由独立子任务、不阻塞主流程，随后要求继续收尾。Windows 原始探针虽完成握手，但子页可接触 Tauri IPC 调用凭据，隔离验收未通过；原生命令实际执行尚未证实。受控 Wry 修复副本已通过原生隔离及主／子 frame 兼容检查，现已通过根 Cargo 覆盖接入主工程，正式依赖快照的 Windows 复核尚未完成；用户已明确“windows 延后，继续开发”，停止本轮 Windows 跟进。原生测试驱动已补严成功回执判定，并验证假成功会被拒绝。标准全工作区 Clippy 被未改存储代码的枚举尺寸与嵌套条件 lint 阻断；仅在验证命令中放行这两项后其余 Clippy 通过，未修改代码 lint。全工作区测试在 Host 身份配置的既有路径遇到预期不符，后续组未以已通过计；与前序身份契约一并收口，不扩大本步产品改动。

### M1 消息卡片发布与恢复

**目标／前置**：M0 确认后，完成“插件声明 → 工具发布 → 消息展示 → 快照恢复”的闭环。

**交付范围**：中心／Host 新清单校验、UI 包分发与入口投影；轻量 `publish_card` 和 MCP 关联 UI 共用发布记录、查询和渲染。实现消息轮次与子任务归属、发布去重、最新快照提交及冲突处理；接入会话删除、历史分支与插件不可用占位。页面后端工具调用保持关闭，留 M3 开放。

**验证入口**：中心插件单测、隔离分发集成及 Host 安装测试；正式 Runtime 卡片存储／迁移测试；客户端消息与快照测试。覆盖无客户端在线发布、流式／失败轮次、多卡片分页、重复回执、Host 重启、两端快照竞争及退役实例写入。迁移使用新建隔离库和受控旧格式夹具，并检查实际接口返回。

**完成判定**：两条发布路径均产生稳定卡片，同一次执行不会重复发布；重载恢复已保存状态且不重复业务操作。快照保存失败、冲突和不兼容保持可解释；跨用户／组织读写被拒绝。中心与安装端清单判断一致，旧 Skill／MCP 包可用。

**Review 重点**：持久提交先于成功回执、可靠调用身份去重、主／子 owner 隔离、分页锚点和快照 CAS；远端工具已执行但卡片保存失败时不自动重试副作用。

**当前结论**：两种发布路径、v2 包校验与入口投影、独立卡片存储、真实主／子 owner、按轮次展示、分页、快照 CAS 与挂载失效已落实。无客户端发布、Host 存储重开、分支继承、来源／设置变化、过期回写和 UI 载荷超限后的不重执行为已通过定向验证；正式 Host Web 已贯通安装、发布、保存和刷新后重新选择会话恢复，macOS 正式 Tauri CSP 下的快照桥接／卸载通过。中心新包扫描与 Host 正式安装已验证，完整中心分发和跨组织组合按 M4 联合验收。Desktop／Host 构建和存储／协议回归通过；Windows 按用户要求延后，完整产品双端人工验收未冒充完成。

**遗留与下一步**：用户于 2026-11-05 明确“继续”，确认 M1 本地交付并授权进入 M2。标准全局门禁仍保留 M0 所述既有存储 lint／Host 身份用例问题；本轮命令级放行两项既有 lint 后工作区检查通过，源码未放宽 lint。额外前端回归发现账号菜单测试仍期待已移除的“本机 Host”文字，归前序身份界面收口。未操作用户库、未部署、未提交；所有新测试数据均为隔离场景。

### M2 右侧应用与卡片联动

**目标／前置**：M1 确认后，用户可直接打开应用，卡片可打开并关联完整业务页面。

**交付范围**：资源栏应用标签、应用选择面板、外部地址连接与来源授权；卡片打开／定位、应用复用、关联消息及草稿填入。同步 Desktop 原生菜单和 Web 菜单，沿现有资源组、缓存与恢复机制管理页面；导航、关闭、重连、淘汰和换域撤销关联。

**验证入口**：现有资源栏 Store／组件测试、正式 Host Web E2E 及 Desktop 实机操作。覆盖直接打开无需 Run、同目标复用、多个卡片关联同一应用、同 URL 两类标签并存、页面重定向、来源冒充、迟到消息、嵌入失败与标签恢复。

**完成判定**：卡片与应用各自保留实例，参数和结果回到正确来源；普通浏览器不获得桥接权限，直接打开应用不能读取已有卡片。恢复仅重建入口和连接，不恢复旧授权；业务交互不依赖 Agent 中转。原生菜单、焦点、滚动和遮挡行为可用。

**Review 重点**：复用现有资源栏，打开目标使用发起方 owner；关联句柄不能由页面猜测或任意绑定，跨来源导航撤权，填入草稿不覆盖用户未发送内容。

**当前结论**：应用目录与资源读取、Desktop／Web 应用入口、外部来源确认、卡片定位和双向关联、草稿确认已实现。正式 Host Web 通过直接打开、同目标复用、回传与快照、重连及跨来源导航回归；macOS 产品窗口实测通过原生菜单、弹窗遮挡、同 URL 双标签、切换保活、客户端重启恢复和关闭后焦点回退。切换过程中发现缓存顺序变化会重载 WebKit iframe，已修复并在真实窗口复验。原生探针通过主 frame IPC、子 frame 隔离和双页面关联回传。

用户补充确认外部地址可使用 HTTP。正式 Host Web 验证 HTTP 来源确认、重连及跨来源撤销，HTTPS 回归通过。macOS 原生探针验证 HTTP 握手和子页面隔离。

**遗留与下一步**：2026-11-06 用户回复“继续”，确认 M2 本地交付并进入 M3。Windows 继续延后。全局门禁既有问题见 M0、M1。

### M3 页面工具权限与任务收尾

**目标／前置**：M2 确认后，页面可在没有 Agent Run 的情况下调用获准后端，且仍受宿主权限与生命周期管理。

**交付范围**：页面工具请求复用 MCP Registry，增加真实 app 审批来源及宿主反馈；区分当前会话规则与草稿用户级规则。实现请求去重、取消、断线未知结果和连接退役；将应用在途调用纳入 F01 组织切换等待，覆盖插件更新／禁用／卸载与权限撤销。

**验证入口**：Runtime 权限、MCP 调用和取消测试；正式 Host 的审批命令与页面 E2E。覆盖 app-only／model-only 双向限制、显式拒绝、审批等待时关闭页面、插件更新中调用、仅应用任务运行时切换组织、终止超时以及迟到返回。

**完成判定**：页面不能通过工具名或页面授权绕过真实规则，不生成伪造 Run；未获准操作不执行。组织切换必须等待相关调用收尾，失败留在原域；关闭页面不会误报外部业务已撤销，未知结果不自动重执。

**Review 重点**：沿既有审批和连接所有权扩展，无第二套工具权限系统；任务取消有明确 owner，F01 切换屏障覆盖新调用类型，插件升级不被长期页面实例占用。

**当前结论**：标准 MCP 页面工具调用、来源和作用域校验、宿主一次性审批及 Runtime 收尾已落实。正式 Host Web 验证草稿应用与标准卡片调用、双向可见性、拒绝、导航撤权、重复请求、权限复核和 MCP 连接退役。macOS 原生探针验证标准调用、正式 Runtime 审批及私有结果回传。隔离模拟中心与正式 Host 验证仅有页面工作时的组织切换及旧句柄拒绝，Runtime 回归验证收尾超时会阻止换域。插件设置变更直接撤销页面许可，包替换和卸载沿原连接退役。

**遗留与下一步**：2026-11-06 用户回复“继续”，确认 M3 并进入 M4 联合验收。Windows 按用户要求延后。既有全局门禁问题见 M0、M1。

### M4 F03 联合验收

**目标／前置**：M3 确认后，按功能设计验收点完成正式链路核对及剩余组合验证。

**交付范围**：使用独立插件仓库的轻量插件、MCP 插件和外部页面样例，贯通中心上传／分发、Host 安装、两类模型发布、消息卡片、应用联动与最新快照。完成受支持升级、插件生命周期、组织隔离及跨端恢复，补齐开发者入口说明和受影响模块约束。

**验证入口**：复用前序有效结果，补齐中心／Host／Desktop／Web 组合验收；检查两组织同名插件、两用户、模型切源、JWT 失效、断网／重启及旧包回归。使用正式构建的 macOS、Windows 客户端及 Host Web 核对页面能力与已知平台限制；不为验收进行发布或生产迁移。

**完成判定**：功能设计全部验收点有实际结果，M0 遗留平台项已收口或取得用户明确接受的限制；升级和恢复不丢失已有数据、不重放业务。汇报实际交付、未测项与风险，等待 M4 及 Feature 验收确认。

**Review 重点**：正式链路与样例结果一致；应用关闭、卡片卸载、停止工具任务含义清晰；纯数据 MCP、普通浏览器和原有插件能力不回归。

独立插件仓库提供轻量和 MCP 计数样例，轻量样例的 HTML 也可用作外部应用。隔离环境的正式企业中心和 Host 已贯通上传、分发、安装、旧版 Skill 加载以及组织和个人模型发布。Host Web 与 macOS 产品窗口验证了卡片与应用回传、页面工具审批、焦点回退和已保存状态的读取。外部 HTTP 应用经来源授权后可交互，HTTPS 路径通过 Web 回归。开发者入口见[插件开发与打包](../../../../site/manual/plugin-development.md#ui-entries)。

兼容升级及 Host 重启后，两种卡片恢复已保存快照，模型与工具调用没有重放。Web 客户端断线期间 Host 可继续发布卡片，重连后客户端自动读取新卡片。插件禁用、卸载或升级到不兼容快照格式时，历史卡片和快照仍保留，页面提示不可用。两组织同名包独立安装和升级，跨组织及跨账号访问被拒绝。待审批工具在切换组织前完成撤销，旧中心 JWT 和旧 Host 页面句柄失效。

按用户实测反馈，真实点击触发的单次页面工具调用默认允许。显式询问、拒绝和无受信点击的请求沿现有规则处理。正式 Host Web 回归和 macOS WebKit 点击探针通过。

### 通用检查入口

各步按实际改动执行，不重复运行无新增覆盖价值的检查：

- Rust／跨层契约改动：仓库根执行 `cargo fmt --all --check`、`cargo clippy --workspace --all-targets --all-features -- -D warnings`、`cargo test --workspace`；定向调试可先使用 `cargo test -p assistant-runtime` 或 `cargo test -p assistant-runtime-host`。
- Desktop：在 `apps/desktop` 执行 `npm run build`、相关 `npm run test -- <用例路径>`；Web 场景用 `npm run test:e2e:web -- <用例路径>`，涉及 Tauri 装配时增加 `npm run tauri -- build --no-bundle` 与原生运行核对。
- 企业中心：在 `apps/enterprise-center` 执行 `npm run typecheck`、相关 `npm run test -- <用例路径>` 和已核验隔离环境下的插件集成测试；接口变化时执行 `npm run openapi:check`，涉及后台消费者时执行其 `npm run build`。

M0 已执行 Desktop 与 Tauri no-bundle 构建、正式 Host Web／macOS Tauri CSP 验证、相关单元测试及全工作区检查。未通过的全局门禁和 Windows 独立验证如上保留。隔离 Host 使用新建测试 Home，配置和夹具只经正式接口创建，资源预览不创建 Run；未迁移用户库或生产数据。

4. F03 完成不等于 v0.33.0 发布；F04 已于 2026-11-06 暂时废弃；后续进入版本联合验收，继续按版本计划收尾前序待确认及遗留项。

## 六、Feature 验收结论

2026-11-06 用户确认 F03 收尾，M0—M4 在已确认的本地范围内完成。交付覆盖两类卡片发布、消息归属及快照恢复、右栏内置与外部应用、卡片与应用联动、页面工具授权和组织隔离。

实测收尾覆盖卡片位于正文与操作栏之间、内容自适应高度、刷新时保留高度，以及右栏标签读取插件图标。天气详情的晴云图标已在 Docker dev 测试环境的 Host Web 从原会话验证，用户确认图标问题已解决。

Windows WebView2 使用正式依赖的原生隔离复核及完整产品验收按用户要求延后，保留为 Windows 发布前待核项。M0、M1 的全工作区检查遗留已在 2026-11-06 版本收尾修正并通过回归；上文对应描述保留为当时的阶段事实。
