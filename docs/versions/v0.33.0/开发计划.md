## 二、拆分原则与跨 Feature 契约

按独立能力闭环推进，默认串行 F01 → F02 → F03 → 版本验收。每个 Feature 自行完成设计、计划、里程碑和验收；不能用后续 Feature 补前一 Feature 的隔离漏洞。

- F01 固定中心／组织／用户身份、组织资源与本地域、凭据及迁移基础；中心模型暂为每组织一个默认模型。
- F02 在 F01 组织域上提供机构多模型和本人模型配置；个人密钥留 Host，不新增独立账号或模型调用权威。
- F03 的插件页面、消息卡片及快照继承组织用户域；重载不重放业务副作用。业务插件源码仍在独立仓库维护。
- 2026-11-06 用户明确 F04 暂时废弃，移出本期开发与验收，不自动安排后续版本。
- Center OpenAPI 与 Rust→TS 协议分别保持唯一来源；Agent Core 不承载企业组织逻辑，不增加产品进程。

## 四、独立验收条件

| Feature | 独立完成条件 |
| --- | --- |
| F01 | 两组织同名资源、多角色身份、中心／Host／后台／Desktop-Web／设备链路均不串域；旧数据仅归默认组织，JWT 及任务切换失败可恢复；不得残留未隔离的已开放入口 |
| F02 | 机构策略开关、默认跟随及显式选择、个人配置均在实际执行中生效；撤权及切源不复用错误凭据／续接状态，不把个人调用混入机构统计 |
| F03 | 正式插件可提供页面与卡片，外部 HTML 页面可按授权接入右侧资源浏览器和宿主通信；更新、导航、重载、卸载和缺失可解释，联动与快照恢复不重复业务操作，跨组织访问被拒绝 |

各 Feature 的未测项、平台限制及风险保留在其完成结论中。发现偏离总体身份、权限、存储或发行边界时先修订设计；不得静默改写已完成 Feature。

## 五、版本联合验收与发布

1. 组织切换／撤权覆盖机构和个人模型、插件页面与卡片、资源文件、设备及迟到响应；敏感读取可审计，历史保持原归属。
2. 从受支持旧版升级到配套新端，默认组织历史可读取，新组织独立；不支持组织的旧端被拒绝且具备更新路径，恢复程序、库与文件匹配。
3. 卡片重载与模型来源变化、组织域切换、配套升级后的历史恢复组合验证通过。
4. 完成受影响模块构建、静态检查、核心回归及必要原生验证。正式 Host 和浏览器链路分别验证，F03 延后的 Windows 原生验证列为待核项。[F03 验收结论](features/F03-插件应用界面与消息卡片/开发计划.md#六feature-验收结论)
5. F02、F03 验收后进入版本联合验收，按用户要求在此收尾 F01 M4 的剩余项及 F01 验收。版本确认通过后进入发布准备，生产迁移、部署、签名公证、上传与发布按实际授权和数据库规则执行。

本计划不含任何已获批生产迁移或发布操作，不主动提交、推送、打标签。每个实现里程碑完成后汇报并等待用户明确确认，才能进入下一里程碑；计划获批不取消该规则。

## 六、版本验收结论

2026-11-06 用户明确“本版本可以收尾了”，本版按已交付的本地范围验收并归档。F01 M4 与 F02 M3 的本地结果在此统一确认；F03 沿用同日已确认的 M4 与 Feature 结论。F04 暂时废弃，未实施、不计入验收。

复用已完成的中心／后台／正式 Host Web／macOS 联验：默认组织升级与恢复、两组织双来源模型、卡片与应用、撤权与终止后换域、断线与重启恢复均已覆盖。收尾修正严格静态检查中的枚举布局与条件分支，以及迁移、身份和界面测试夹具；Rust 全工作区回归已覆盖，发现的失败项修正后定向复验通过；严格检查、Desktop 全量单元回归、中心／后台单元回归、各端构建与协议快照核验通过。

Windows WebView2 正式依赖的原生隔离及完整产品验证仍按用户要求延后，不记为通过；发布 Windows 版本前须补验。受控模型端点不能替代真实外部服务商验收，安装包下载／安装、自动更新、签名公证及生产部署仍按实际发布安排执行。本次没有生产迁移、部署、打包、提交、推送或发布。

文档和本版本进度移入版本归档，更新说明及受影响用户手册同步完成。已核实停用的隔离测试环境按流程清理；仍运行或被开发环境挂载的场景、共享环境恢复资料保留，不操作其数据库和用户数据。下一目标版本未定，状态为待启动；v0.32.2 既有封版事项保持原归属。
