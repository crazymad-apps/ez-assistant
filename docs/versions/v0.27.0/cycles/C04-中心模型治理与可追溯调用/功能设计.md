## 四、中心模型管理

### 4.1 基础结构与来源规则

| 对象 | 保留的基础结构 | 中心特有差异 |
| --- | --- | --- |
| Provider 实例 | 稳定实例 ID、显示名称、类型、上游 endpoint、凭据、推理协议偏好、模型发现路径/格式 | 由管理员维护，真实连接只在中心使用 |
| 在线模型目录 | Provider 最近一次成功显式刷新的完整快照、刷新时间、连接变化提示 | 持久化到中心 PostgreSQL，重启后可读；下次成功刷新整体覆盖，Runtime 不下载目录 |
| 固定模型参数 | `(provider_instance_id, model_id)` 唯一，保留 online/manual 创建来源、参数和保存时间 | 企业共享管理；不按用户复制配置权威 |
| 内置参数模板 | 按服务商类型与真实模型 ID 精确匹配的参数参考、来源链接和核查日期 | 独立静态 JSON 文件，单独维护和加载，不写成固定配置或在线目录 |
| 默认选择 | 引用上述二元身份，允许清除；引用与当前是否可用分别表达 | 全企业只有一个默认模型，不提供独立辅助识图模型选择 |

模型 ID 使用服务商真实值，显示名称不能改变调用身份。在线模型与手动模型是同一身份空间；手动输入已有 ID 时编辑既有记录，不生成第二份同名模型，已保存来源不可随意改变。

参数沿用现有字段：上下文窗口、输入/输出上限、思考模式输入/输出上限、流式、图片输入、工具调用、工具选择方式、工具图片投影、思考能力、档位映射及默认档位。未知、不支持与非法值保持区别；不把未知能力默认开启。

来源顺序沿用现有逻辑：固定值优先；没有固定值时读取最近成功在线目录，模板只补充未知字段，不能覆盖明确不支持或非法值，也不能凭模板向目录增加模型。手动模型可在无在线目录时保存明确参数。详情继续显示预填来源、厂商参考及模板核查信息。

在线目录持久化不等于保存为固定配置。三类来源保持独立：在线快照保存上游返回的列表及其参数元数据，允许刷新替换；管理员显式保存的固定配置单独持久化，只由保存、重置或删除操作改变；内置参数模板用于补齐未知字段，不被在线刷新改写。模板补齐后的展示值也不反写成上游原始元数据。

中心模板使用独立静态 JSON 文件，不硬编码在 TypeScript 中，也不打包进必须随程序重建的资源。发行物提供初始文件，运行时读取部署配置指定的模板文件；运维可以替换该文件并在后台显式“重新加载模板”，无需升级或重启中心。程序升级不静默覆盖部署中维护的模板，不增加在线模板编辑器、自动下载或文件监听机制。

JSON 只承载现有程序支持的参数与参考信息，不承载密钥、上游连接或可执行规则。按 Provider 类型和模型 ID 精确匹配，不创建别名或用名称前缀猜能力。更改已有参数值、补充型号及参考信息只需更新文件；新增推理协议、参数语义或 Provider 方言仍需相应代码支持。

重新加载先完整读取并校验文件、重复键身份和参数形状，成功后一次替换内存模板；失败保留上一份有效模板并显示错误。首次启动没有有效模板时明确显示模板不可用，仍允许使用参数完整的在线目录或固定配置，不以隐藏的硬编码副本兜底。加载动作和结果进入既有管理审计，不额外维护模板历史库或动态配置 revision。

模板更新不修改 PostgreSQL 中的在线原始快照、固定配置和管理员未保存草稿，也不改变已冻结执行。之后读取配置时重新按来源优先级求有效值；Host 在下一次成功获取中心配置时生效，沿用同模型参数变更的刷新规则，不另做推送。企业 Host 使用中心已解析的有效参数，不再用本机旧模板二次补齐，以免独立更新失效。

Node 与 Rust 的发现格式、参数约束及模板数据如何保持一致由技术方案明确，优先共享可声明的数据和契约样例；中心 JSON 的初始内容以现有模板为依据，不维护另一份硬编码模板事实。个人 Host 的模板装配是否共用该 JSON 在技术方案核查，不把中心模板独立更新扩展为个人版新的在线更新系统。

### 4.2 服务商与目录操作

1. 管理员添加/编辑服务商，沿用现有类型、协议偏好和发现格式关系，不根据 URL 或模型名猜测协议。凭据只显示“已设置/未设置”，编辑明确区分保持、替换、清除，不回显已保存 key。
2. 打开服务商页面只读中心已持久化目录，页面重载或中心重启后仍可读取；点击“刷新在线模型”才访问上游。完整获取、校验并可靠落库后，整体替换该 Provider 的在线目录及刷新时间；本次未返回的在线条目从快照移除，成功返回空列表也允许覆盖。获取、校验或落库失败均保留上次成功目录与时间，显示本次错误，不以部分结果冒充成功。
3. 连接或凭据变化后，旧目录保留并标记需刷新；旧刷新响应不能覆盖新连接。刷新不覆盖固定参数、不自动改变默认模型。
4. 列表合并在线条目和未出现在在线目录中的固定条目，支持按 ID/名称搜索，保留在线/手动、已固定、使用模板、待配置及不在当前目录等状态。同一 ID 同时存在在线快照与固定配置时只展示一行，但参数来源分别保留；刷新移除在线条目后，其固定配置仍保留并显示为不在当前目录。没有固定值且已从目录移除的默认模型引用保留，状态改为不可用，不自动换模。
5. 删除服务商前展示中心能确定的影响：固定配置及企业默认引用。沿用 Host 删除连接与固定值、保留原选择身份的语义；默认引用失效后显示“原服务商已删除”，不自动选其他模型。中心不知道 Host 会话总数，不能复制 Desktop 的会话引用数量或声称已清理终端历史。
6. 不新增 Provider 或模型启停字段；取消默认、删除服务商与删除手动记录已覆盖当前管理需求。引用失效与“未选默认”在后台可区分，对新企业执行均为模型不可用。

### 4.3 参数编辑、测试与默认选择

- 在线模型打开统一参数页；手动添加先输入模型 ID，再进入同一参数页。保存时校验参数与协议组合；不可执行的配置不能设为有效默认。
- 固定配置页可刷新在线参考、对比当前值，并由管理员显式应用到草稿、保存；不自动覆盖未保存修改。
- 在线来源“重置配置”只删除固定值，重新按在线/模板求值；手动来源“删除模型”删除该固定记录。如果目录仍有同 ID，继续作为在线模型显示。引用与历史保留；无可用参数时明确提示重新配置。
- 保留“测试已保存配置”，有未保存草稿时先保存。测试由中心执行最小模型请求，不创建 Runtime 会话，不执行工具，不自动改默认或改协议；明确可能产生上游用量，并在调用记录中标为管理员测试。如何复用既有协议规则在技术方案收敛，不在 Node 重写 Agent/Provider 语义。
- 设置默认前确认目标参数可用于现有 Runtime；目录存在、参数有效、真实调用成功是不同事实。保存默认不暗中附带模型测试。
- 默认只决定后续配置获取及新请求准入，已被代理接纳的调用沿用接纳时的路由完成。新请求携带旧默认身份时明确拒绝。
- 模型写操作与必要管理审计可靠提交后才提示成功；超时或结果不明先重新读取，不自动重发写操作。

### 4.4 后台页面组织

沿用 Admin 的 PageLayout、路由、面包屑、身份守卫、列表加载与离开拦截，不复制 Desktop 的弹窗壳层、MobX 根 Store 或私有组件。

| 页面 | 内容与操作 |
| --- | --- |
| 模型管理首页 | 顶部企业默认模型及可用状态；下方服务商列表；添加服务商与选择/清除默认；模板加载状态及“重新加载模板”入口，与“刷新在线模型”分开 |
| 服务商详情 | 连接摘要、凭据状态、编辑/删除；模型搜索、刷新时间/状态、添加模型、在线与固定条目 |

## 五、配置分发与正式模型调用

### 5.1 Host 获取与使用配置

用户成功登录后独立加载中心默认配置；登录与本地用户域就绪不以中心模型可用为前提。配置失败时仍能查看本人会话、文件与账号，模型执行显示具体不可用原因。

中心只下发当前默认模型、代理 endpoint、执行编译所需的类型/协议/能力及有效参数；临时 key 使用本次登录已经签发的值，不再创建新 key 生命周期。Provider ID 仅在代理 URL 路径表达，Host 将其视为不透明连接地址；真实上游地址/key、全量目录不下发。

Host 在既有用户模型装配与 Runtime 编译边界发布当前有效投影，不写入可由用户编辑的第二份企业配置。所有实际模型请求发送时读取当前用户最新 key；PreparedModel、排队任务和长任务不固定某次登录凭据。主调用、标题、压缩、child 和视觉调用共用托管约束，缺能力时按原能力规则失败或不开放该能力，不绕行个人辅助模型。

企业 Desktop/Web 模型设置页改为只读当前模型、能力/参数摘要、获取状态和“刷新配置”；保留身份，不提供 Provider 编辑、默认/会话/辅助模型切换。服务端同样拒绝修改，不能只隐藏按钮。这里的刷新获取中心生效配置，不触发上游目录刷新。

### 5.2 变更与刷新

| 变化/故障 | 用户看到的结果 |
| --- | --- |
| 初次加载失败或无可用默认模型 | 模型不可用，可显式刷新；不退出登录、不使用个人配置 |
| 默认 Provider/模型变化 | 旧身份请求在上游前被拒绝，Host 合并同用户正在进行的刷新；当前调用失败并提示刷新结果，用户显式重试 |
| 同一默认模型只改参数 | 下次登录加载或显式刷新等成功获取时生效；不承诺后台保存后立即作用于已登录 Host |
| 上游 endpoint/key 修改 | 中心后续接纳的请求使用最新连接，Host 不必刷新；已接纳请求不换路由 |
| 已拒绝配置刷新失败 | 禁止用该配置接纳新执行，明确尚未取得有效配置；再次显式刷新成功后恢复 |
| 手动刷新临时失败，原配置未被中心拒绝 | 保留原有效配置并显示刷新失败；不伪称已取得新值 |
| 上游 401/403/409、限流或网络故障 | 按模型调用故障处理，不能仅凭 HTTP 状态码刷新配置或退出账号 |

中心自产控制错误须有不可与上游混淆的来源标记及稳定原因码；透传上游不得携带该保留标记。具体协议由技术方案定稿。

一次明确配置拒绝只触发一次获取尝试，不循环刷新或自动重发模型请求，不重放整段 Run 或历史工具。主调用及辅助调用各走已有失败路径，不因配置拒绝关闭整个人的 Runtime。晚到拒绝或刷新失败不能使已发布的新配置失效，也不能恢复已退出的用户域。

旧会话下一次新执行/显式重试必须使用新托管配置，不因原会话保存的模型选择继续锁定旧默认；重新准备、重新计算上下文预算，并按已有模型切换规则隔离 Provider opaque state，历史正文保留。活动执行的冻结规格不热替换；刷新期间的活动流继续，后续旧规格请求由中心准入决定。

### 5.3 代理与身份边界

中心依次校验临时 key、当前默认身份及允许的协议路径，再按管理员保存的连接替换上游认证，透明传输现有 Responses/Chat Completions 请求和响应。不能通过请求体、路径或转发头指定任意上游目标，也不能向上游泄露 Center/Host 登录凭据。

代理不重复校验每次推理请求的固定参数上限，不重新生成工具、reasoning 或正文，不自动重试、不自动切换模型/协议。传输可采用不同的网络分块，但不得改变 SSE 事件/正文顺序与有效载荷语义。连接、相邻数据等待和长流总时长分别处理；持续有输出的长流不被固定总时限误杀。

取消、下游断开和中心停止须终止关联上游并有界收尾。默认变更或凭据替换不追溯中断已接纳流；用户在 Host 统一退出仍由 C03 取消树中断本人全部工作，代理响应相应断连。账号停用/中心凭据失效拒绝后续请求并沿用 C03 身份核验与关闭规则；旧 key 晚到拒绝不得清除新登录。

模型网络失败不等同于身份核验失败；C03 已确认的中心身份不可达处理保持原边界。本循环不因代理新增第二套用户登录状态。

## 六、调用记录与内容快照

### 6.1 调用记录范围

一次中心实际收到的模型 HTTP 请求对应一条调用记录，包括已认证的准入拒绝、代理成功、上游失败、取消、中断及管理员配置测试。Runtime 的一次逻辑调用若有既有有限重试，中心分别记录实际请求，不冒充一条成功调用。无法认证的请求仅记录必要的脱敏拒绝信息，不信任请求提供的用户 ID。

记录中心调用 ID、已认证用户、Provider/模型身份、请求类型/协议、开始/结束时间、耗时、上游状态及稳定失败原因。中心生成的调用 ID 支持错误追查；可复用已有安全关联信息，但不为此要求注册 Host，不新增中心 Session/Run 表。Provider 或用户名称变化、Provider 删除后，历史记录仍能表达调用时身份。

管理员按时间、用户、Provider/模型、结果和调用 ID 查询分页列表，进入详情查看同次请求的结果及快照状态。普通用户无权访问中心调用列表或完整快照；所有现有管理员具备这些管理权限，不新建权限角色体系。中心只陈述自身观察到的结果，不能宣称完整审计了 Runtime 工具执行、后续提交或最终任务成败。

### 6.2 快照策略

| 项目 | 已确认策略 |
| --- | --- |
| 默认开关 | 关闭；管理员显式开启，提示正文可能包含提示词、文件内容及工具参数 |
| 保存范围 | 接纳时固定本次策略；保存代理实际看见的请求正文及响应正文，SSE 保留原始事件文本，不按 Agent 消息重组 |
| 目录与格式 | 中心显式配置的持久根目录，按日期和中心调用 ID 定位 UTF-8 文本；数据库只存索引、定位与完整性，不存正文；具体命名由技术方案确定 |
| 保留期 | 完整/部分快照默认 7 天，调用索引默认 90 天；部署可配置，后台明确显示当前值；管理操作审计不套用调用索引清理策略 |
| 单次上限 | 请求与响应各最多保留 8 MiB，超过时停止该侧采集并标记截断，继续代理 |
| 并发累积 | 全中心快照内存累积预算 64 MiB，待写内容计入；不足时停止相应采集并标记资源受限，不因此引入用户调用配额 |
| 失败/中断 | 保存已经采集的部分内容，明确中断/截断；响应完整与文件写入完整分别判断 |
| 查看与清理 | 仅管理员经受保护接口查看；禁止公开静态目录。按保留期有界清理，保留的调用索引显示内容已过期，清理失败不能伪称已删除 |

代理收敛后由 Center 统一落盘，不让 Runtime 承担快照保存。采集只保留正文与必要元信息，不保存 Authorization、Cookie、Provider key 或数据库连接信息；正文按原文保存，不能承诺自动识别并脱敏全部业务秘密。

开关变更对之后接纳的请求生效，关闭不会立即删除已有文件。快照保留期缩短会影响既有快照，保存前明确提示清理范围；索引清理不得留下无人管理的文件。手动批量删除、任意文件浏览、正文全文搜索及日志导出不作为首版范围。

### 6.3 记录失败与恢复

模型调用结果、索引记录状态和快照完整性分开：正常返回不能因随后磁盘满或快照落盘失败变成模型失败，页面也不能把“未采集”“截断”“写入失败”“已过期”统称为完整。

上游请求发出前先建立最小调用索引；索引无法建立时明确拒绝且不访问上游，避免中心明知无法追溯仍开始新调用。已发出请求后的索引完成更新/快照失败不改写已经返回的结果，留下脱敏运行诊断；恢复时不能据未终结索引推断成功，不自动重发模型请求。

文件与 PostgreSQL 无共同事务，技术方案须定义半写文件、文件成功但索引更新失败、进程中断及清理中断的确定性恢复。恢复只核对中心自有文件与索引，不扫描 Host 会话，也不新增持久化重试队列。本循环交付状态与恢复规则，整套数据库和快照备份恢复演练交 C06。

## 七、职责与最小新增审查

| 边界 | 责任 |
| --- | --- |
| Center | 模型配置权威、显式发现、管理审计、默认配置接口、LLM 准入与转发、调用索引/快照策略和生命周期 |
| Admin | 管理页面与草稿、筛选及加载；通过生成 OpenAPI SDK 访问，不直接连接数据库或 Provider |
| Host | 企业配置获取、当前用户凭据读取、中心错误识别和刷新协调、复用 Provider Adapter/传输 |
| Runtime | 托管模型投影接纳、现有模型编译/冻结规格、会话新执行与辅助调用、失败及显式恢复 |
| Desktop/Web | 只读模型状态、显式刷新和失败提示；其他业务保持既有用户域流程 |

新增模型持久化属于现有模型事实在 Center 的所有权落地；新增调用索引与快照有独立调用身份和保留生命周期，已有管理审计不能承载流式收尾和内容状态。除此之外不新增模型映射实体、凭据池、配置 revision、任务授权表、中心 Runtime 或全局用户模型缓存。

删除本次新增机制后，现有事实是否足够：模型管理结构、身份、用户域、编译及界面基础足够，应复用；中心缺少的模型存储、透明传输与调用记录无法由现有 Host 本地事实代替，才需在各自所有权边界补齐。

## 九、确认点与后续设计

2026-09-21 用户确认功能设计，授权继续技术方案与交互设计；确认范围包括：

已按用户意见固定：在线目录持久化且可由下次成功刷新覆盖；固定配置独立；内置模板使用可独立更新的静态 JSON。这些意见已纳入本次确认基线。

1. 保持 Host/Desktop 模型基础结构和操作语义，中心只保留一个企业默认模型；不增加模型启停、模型别名或单独辅助模型。
2. 管理配置变化只刷新，不自动重发失败调用；显式刷新失败与已拒绝配置失效分别处理。
3. 快照默认关闭、7 天内容/90 天索引保留、单侧 8 MiB 与整体 64 MiB 采集预算，以及调用索引建立失败时不访问上游。
