## 二、导航与页面关系

侧栏在“用户管理”后增加“模型管理”“调用记录”，既有“管理审计”保留。模型管理只有一个一级菜单，服务商与参数详情以面包屑表达层级；不为模板或每个 Provider 增加侧栏项。

| 页面/入口 | 路由与返回行为 |
| --- | --- |
| 模型首页 | `/models`；显示默认模型、模板状态及 Provider 列表 |
| 添加服务商 | `/models/providers/new`；取消返回首页，保存进入新 Provider 详情 |
| 服务商详情 | `/models/providers/:id`；返回模型首页 |
| 编辑服务商 | `/models/providers/:id/edit`；保存/取消返回详情 |
| 添加模型 | `/models/providers/:id/models/new`；先输入 ID，再在当前编辑页展示参数，不提前写数据库 |
| 模型参数 | `/models/providers/:id/models/edit?model_id=...`；ID 通过 URLSearchParams 编码，含 `/` 的 ID 不成为路由层级 |
| 调用列表 | `/llm-calls`；筛选和页码放查询参数，详情返回时恢复 |
| 调用详情 | `/llm-calls/:id`；直接按 ID 读取，不依赖当前列表内存 |
| 快照设置 | 调用列表右上角弹窗；草稿不写 URL/history |

页面私有数据由局部 hook 管理，复用 PagedList 的查询/身份守卫；模型读取与动作分别显示进度。写动作进入现有 AdminStore 的身份与写入锁，成功后由页面回调重载数据；列表、草稿、正文不进入全局 Store。没有版本计数或事件总线。

## 三、页面布局

### 3.1 模型首页

```text
模型管理                                      [添加服务商]
┌ 企业默认模型 ──────────────────────────────────────────┐
│ 服务商名称 / 模型 ID              状态        [选择] [清除] │
│ 必要时显示未配置、参数不完整或已删除服务商的具体原因          │
└────────────────────────────────────────────────────────┘
┌ 参数模板 ──────────────────────────────────────────────┐
│ 已加载 · N 个型号 · 最近加载时间             [重新加载模板] │
│ 加载失败时显示失败原因及“继续使用上次已加载模板”             │
└────────────────────────────────────────────────────────┘
┌ 服务商 ────────────────────────────────────────────────┐
│ 名称          类型          服务地址       凭据      操作  │
│ …             …             …            已设置    管理  │
└────────────────────────────────────────────────────────┘
```

默认区显示实际状态，不以引用存在就显示可用；服务商已删仍展示原引用对应的不可用信息，可重新选择或清除。未配置时主操作为“选择默认模型”，不自动选择列表第一项。

选择默认弹窗先选择 Provider，再从其当前目录/固定记录中搜索模型；不自动联网刷新。条目显示来源及待配置状态，不完整项可进入参数页处理，不能直接提交为默认。确认成功关闭弹窗并重新读取默认结果；失败保留选择。清除使用确认弹窗说明“新的企业模型请求将不可用，已接纳的流不因本次操作主动中断”。

模板区区分有效状态与最近加载动作结果：首次加载失败显示“模板不可用”；已有有效模板而重载失败时，继续显示原成功时间及失败提示。点击重载不触发在线模型刷新，不创建参数编辑器；提示“请先更新服务器模板文件，再重新加载”。不暴露服务器绝对路径、下载地址或软件版本升级按钮。

### 3.2 服务商详情

顶部为名称、返回、编辑和删除操作；连接摘要用 Descriptions 展示类型、服务地址、协议偏好、模型发现路径和凭据状态。真实 key 始终不回显。

下方单张模型表：工具栏为“搜索名称或模型 ID”“添加模型”“刷新在线模型”；状态行显示最近成功刷新时间、连接变化或本次失败。进入详情只读取持久目录；刷新期间保留原表格，禁用重复刷新，不用全页 loading 遮挡旧数据。

列为模型名称/ID、来源、配置状态、默认标记、操作。来源用“在线”“手动”，配置状态用“已固定”“使用模板”“待配置”；未在当前在线快照出现的固定条目补充“不在当前在线目录”。同 ID 只一行，状态可组合，不能把已持久化的在线条目标为已固定。

成功刷新后按新快照替换在线条目，空结果显示“本次在线列表为空”；保留的固定条目继续展示。失败保留旧列表和原成功时间，显示“刷新失败，当前仍为上次成功结果”及重试操作。没有任何目录时说明可显式刷新或手动添加，不能显示成功空列表。

删除服务商先查询影响后启用确认按钮，展示固定配置数量、是否被默认引用；不展示不存在的 Host 会话数量。查询失败可重试，不能跳过影响确认。确认文案说明历史与默认引用保留、失效引用需重新选择；提交成功返回首页，失败留在详情，不自动再次删除。

### 3.3 服务商表单

沿用 Desktop 字段顺序：显示名称、服务商类型、服务地址、API Key、协议偏好、模型发现路径。发现格式由服务商类型确定并展示说明，不增加与类型可矛盾的第二个自由选择。

编辑时 API Key 使用明确动作：“保持原值”（默认）、“替换”“清除”。只有替换时显示密码输入；输入框不预填星号作为值，不保存到浏览器存储。无凭据服务商按后端规则允许空值，不能所有类型一律必填。

协议选项只显示当前类型支持的 Auto/Responses/Chat Completions；Auto 显示当前解析结果，失败不会自动换协议。更换服务地址时显示辅助说明：同一服务连接维护可以编辑；迁移到另一不共享模型状态的服务应新建 Provider。

表单内联校验，服务端错误保留草稿；提交期间禁止离开、重复保存。底部固定“取消”“保存”，与可滚动表单区分开，窄屏不遮住最后字段。提交成功清空秘密输入后导航。

### 3.4 模型参数页

标题为真实模型 ID，副信息显示 Provider、来源、默认状态；参数字段和含义与 Desktop 对齐：

| 分区 | 控件与默认展开 |
| --- | --- |
| 基础参数 | 上下文窗口、输入/输出上限、思考模式输入/输出上限；数字输入允许明确“未知”，非法值就地报错；默认展开 |
| 基础能力 | 流式、图片、工具、思考的未知/支持/不支持选择；思考模式单列；默认展开 |
| 思考设置 | 已有档位到线上字符串的映射、默认档位；默认展开 |
| 高级能力 | auto/none/required/named 工具选择与工具图片投影；默认折叠 |
| 来源与参考 | 字段来源、厂商链接、模板核查日期，明确为参考而非实时规格保证 |

固定配置存在时展示“当前使用固定配置，刷新目录和模板不会覆盖”。无固定配置时按在线/模板预填，每个来源提示来自服务端，不由页面自行计算第二份参数优先级。

底部主动作“保存固定配置”；旁边“测试已保存配置”；online 来源显示“重置配置”，manual 显示“删除模型”。未保存或有脏草稿时测试不可用并提示先保存；测试期间显示进度，可取消等待，提示停止等待不保证上游未产生用量。测试结果只陈述连通性和调用 ID，不宣称模型所有能力都通过验证。

“刷新在线参考”位于参数区下方，展示当前草稿/本次在线值对照；点击“使用本次在线值”只改变草稿，仍需保存。不存在的在线值按未知展示，不能混入模板再称为上游值。模板重载、在线刷新和后台并发更新不覆盖当前脏草稿。

重置或删除在确认中说明来源差异和默认影响。重置后重新读取配置；删除手动记录后返回服务商详情。同 ID 仍在线时保留在线条目，不能文案宣称已从上游删除模型。

### 3.5 调用记录

沿用既有审计列表的筛选行、表格滚动与分页结构，筛选顺序为时间、用户、Provider/模型、调用结果、调用类型、调用 ID；窄屏自然换行。默认第一页展示最近调用，不自动轮询，不将新请求插入当前页打断阅读，提供“刷新”。

表格列：开始时间、用户、Provider/模型、类型、结果、耗时、快照状态、详情。结果使用技术方案口径：“处理中”“转发完成”“已拒绝”“上游 HTTP 错误”“已中断”“结果未确认”。不把 HTTP 2xx/EOF 标成“任务成功”。

快照状态独立显示未采集、待保存、完整、部分、失败、已过期或缺失；请求和响应状态不同时显示“部分可用”，详情分别解释。关闭快照时记录仍存在，不能显示为记录失败。列表不渲染 prompt、工具参数或返回正文。

顶部“快照设置”使用 Modal：开关、内容保留天数、调用索引保留天数，以及当前固定采集上限的只读说明。首次开启显示正文敏感信息提示；缩短保留期时在保存确认中说明既有过期内容将在清理中删除。关闭说明已有内容按保留期处理；不增加“立即全部清空”。

### 3.6 调用详情与文本查看

上方 Descriptions 显示身份、模型、时间、协议、HTTP 状态、原因码和调用 ID；下方请求/响应两个 Tab。默认只加载元信息，各 Tab 点击“查看内容”后按需取文本，显示采集字节数、完整性及限制原因。

正文使用纯文本查看区，保留空白、可切换换行，长行横向滚动；不执行 HTML、不自动加载正文链接、不将 SSE 解析成伪造对话。每侧最多 8 MiB，文本节点按需挂载；切 Tab 释放不需要的正文，卸载/身份变化全部释放。页头及状态说明保持可见，正文独立滚动。

处理中且文件未发布时显示“内容尚未保存”，手动刷新详情；不展示 `.part`。过期显示保留策略说明，写入失败/缺失显示原因和调用 ID；不存在的调用显示明确不可用页面，可返回列表。

## 四、Desktop/Web 托管模型状态

复用现有“设置 → 模型”页面及服务商 → 模型 → 参数导航，不建立托管专用卡片页。默认模型沿用同一选择展示，服务商名称和模型 ID 进入同一二级菜单；企业只读策略下可展开查看，但不能选择其他模型或清除默认。思考档位保持原菜单与读取接口。

配置只读时隐藏添加、编辑、删除、保存与在线发现按钮，参数表单只读；设置首页提供“刷新配置”和配置源的最近获取/失败状态。显示中心代理地址，不显示上游真实地址或 key。个人模式界面保留原行为；差异由通用只读策略承载，不由页面判断企业 mode。

| 场景 | 展示与下一步 |
| --- | --- |
| 登录成功、配置首次加载中 | 用户进入已有工作区，模型区显示正在获取；不假装模型可用 |
| 首次失败/中心无默认 | 显示原因和刷新按钮；账号/会话仍可用，需要管理员配置时直说 |
| 手动刷新失败、原配置仍有效 | 保留当前模型和成功时间，补充刷新失败提示 |
| 旧调用被拒绝、自动刷新成功 | 本次调用显示失败并提示“配置已刷新，请重试”；展示新模型，不自动点重试 |
| 自动刷新失败 | 显示模型不可用及刷新入口；不能继续用已拒绝配置提交新执行 |
| 上游认证/限流错误 | 显示模型调用错误，不返回企业登录页 |
| 当前中心身份确实失效 | 沿 C03 登录失效流程；旧 key 晚到失败不影响新身份 |

刷新期间已有有效模型时保留摘要；同用户各端通过现有 ConfigChanged 重读相同状态，不能各自维护成功配置。固定参数或模板更新的帮助文案说明“刷新后供新执行使用”，不承诺改变正在执行的任务。

## 五、通用状态、尺寸与可访问性

- 保留 48px 蓝色顶栏、现有侧栏、面包屑及主题 Token。卡片/表格/Modal 直接使用既有 Ant Design 配置，不复制 Desktop CSS，不覆写内部 DOM。
- 内容区卡片间距 16px；编辑表单建议最大宽 880px，连接表单约 760px；小于 720px 改为单列，表格保留必要横向滚动，不强行压缩长模型 ID。
- 页面列表滚动在表格体，表单在内容体，快照在文本区；不要同一操作区嵌套两层纵向滚动。测试 125%/150% 缩放和矮窗口底部操作可达。
- Label 与输入关联；状态同时提供文字，不只靠颜色；加载和错误使用可感知的状态区域。Modal 关闭后恢复触发按钮焦点，保存失败聚焦首个错误或错误摘要。
- 草稿统一登记到既有 NavigationGuard；返回、侧栏切换和默认弹窗跳转编辑都遵守放弃确认。提交中的离开被阻止；取消读请求不当作撤销服务端写入。
- 写入失败区分明确拒绝与结果未确认：后者提供重新读取，不自动重试。换身份整树卸载，旧响应不得恢复内容或清掉新身份。

## 六、交互验收与边界

以正式页面完成一条“添加 Provider → 刷新并持久化目录 → 参数保存 → 设默认 → Host 获取 → 调用记录查看”路径；补在线刷新覆盖而固定值不变、JSON 模板单独重载、删除默认引用及写入失败草稿保留。

浏览器重点检查凭据不回显、脏表单离开、目录旧数据/失败状态、默认变更后显式重试、快照截断和过期、普通用户访问拒绝。窄屏/缩放按受影响页面抽查，不新增逐字 CSS/文案快照或框架路由测试。

本文件只形成设计指导，没有创建页面或宣称实机通过。用户已确认继续，实施顺序见[开发计划](开发计划.md)；计划仍待确认，未开始实现。
