- 按可核验的能力结果分为四个里程碑；每个里程碑完成后汇报并等待用户确认，计划确认不自动授权跨里程碑实施。

- 验证按实际改动和核心风险执行，复用已有有效结果；不补完整测试矩阵、逐字界面快照或独立验证报告。计划只维护完成状态、用户确认及必要遗留。
- 隔离 Home 和临时产物放在 `.runtime-test/` 新建的 C04 场景目录；数据库先核实实际连接与调用表。已有库写入前按根规则完成独立备份及有效性核验，异常即停止；共享开发库的自动化写入暂停约束继续有效。
- 不主动暂存、提交、推送或发布；不修改 C01/C02 归档，不清理当前工作树的既有改动。

## 四、里程碑实施与验证

### M0 中心模型管理与静态模板

- **目标**：管理员通过正式后台配置可供中心分发的唯一企业默认模型，目录、固定值和模板各自保持明确来源。
- **交付范围**：按技术方案完成本循环数据库迁移及约束，包括后续调用索引和策略所需表；实现模型管理、显式发现/持久替换、参数求值、默认配置读取和能力声明。抽取现有 Rust 规格到唯一初始 JSON，接通中心独立加载/重载及个人 Runtime 的编译嵌入。同步 Admin 模型页、生成 SDK、制品资源复制和运行说明。
- **阶段边界**：配置测试与调用记录依赖 M1 的真实转发服务，在 M1 一并交付；M0 页面不暴露空实现或虚假的测试成功。Host 获取/执行与 Desktop 托管展示归 M2。
- **验证入口**：两端模板对照和既有型号/协议迁移等价；在线 Unknown/Invalid/Unsupported、思考档位冲突与固定值优先；目录重启恢复、成功空结果替换、失败保留及连接变更晚到结果；模板错误保留有效值。隔离中心与正式后台完成一次配置路径，检查直接 API 权限及凭据不回显。命令按下方对应工程入口选取。
- **完成判定与 Review**：C04-A01、A02 的目录/参数部分、A10 的升级及个人模板部分、A11 的中心侧成立；刷新不改固定值或模板，不维护第二份有效配置缓存。参数语义与现有 Host/Desktop 一致，独立 JSON 更新不需要升级中心；新增行为仍由代码负责。

M0 完成结论（2026-09-21）：中心模型管理、持久目录与固定参数、默认配置接口、正式后台及独立模板重载已实现。JSON 迁移保持原规格，Node/Rust 共享样例、目录替换/失败保留/迟到拒绝、固定优先与后台配置路径通过；受影响 Rust、Center、Admin、Desktop 检查通过。按用户最新意见统一 `xhigh`，按用户最新要求移除 `x_high` 兼容读取。仅使用隔离中心库，共享开发库未升级；尚无真实代理、Host 托管执行或付费模型验证，这些按原边界归后续里程碑。用户已确认 M0，授权进入 M1。

### M1 透明代理与调用追溯

- **目标**：中心可在当前身份与默认配置约束下透明转发模型请求，并留下可查询的实际转发及采集结果。
- **交付范围**：实现 Chat/Responses 代理、来源明确的控制错误、当前 key 与路由准入、背压/取消/超时及关闭收尾；完成管理员配置测试。实现索引建立/结算、快照采集/文件发布、恢复/保留期清理，以及 Admin 调用列表、详情、内容查看和策略设置。
- **验证入口**：最先核验锁定 Fastify 版本的 parser scope、断连/超时和大正文峰值，无法满足设计则先报告偏差。使用确定性上游比较原始请求与响应字节，覆盖两协议、流中断、取消、慢消费者及上游伪造控制头；用最少故障注入覆盖索引失败不转发、文件/索引半完成、磁盘失败与过期恢复。正式后台完成测试配置、查询结果和读取快照，验证普通用户无权访问。
- **完成判定与 Review**：C04-A02 的配置测试、A04/A08 的中心侧及 A09 成立；不隐藏重发、不聚合 SSE、不将 HTTP 转发完成标为任务成功；记录故障不改写已转发结果，资源及生命周期可收尾。配置测试不更改默认，正文及密钥不进入普通日志。

M1 完成结论（2026-09-21）：两协议透明代理、当前身份/路由准入、独立控制错误、取消/超时及关闭收尾已实现；索引、快照发布/恢复/保留期清理、配置测试和后台查询形成闭环。隔离 HTTP 与后台操作、字节保持、索引失败不发送、恢复/清理故障及受影响静态检查通过。文件发布采用同目录 hard link 防止覆盖，已同步技术方案和部署要求。未使用真实付费 Provider；正式 Host/客户端接入仍归 M2。M1 已获用户确认。

### M2 正式 Host 与客户端接入

- **目标**：企业用户从正式 Desktop/Web 使用中心模型，配置变化和身份变化具有可解释的失败与恢复路径。
- **交付范围**：接通 Runtime 唯一外部模型来源、Host 配置加载与发布、现有 Adapter 的可注入能力/Transport、最新 key 获取及控制错误处理；覆盖主调用、标题、压缩和 child 的共用准备路径。新增显式刷新命令及只读模型状态，更新协议投影和 Desktop/Web；保持个人模式管理与执行。
- **验证入口**：首先确认两种 Adapter 注入明确能力后仍保持原编解码行为；定向覆盖旧登录迟到响应、配置 Arc 失效与并发刷新、当前凭据更新和用户域关闭。使用 M1 中心与正式 Host 跑默认 A→B、仅参数/key 变化、默认不可用、刷新失败和显式重试，检查旧会话路由状态及新执行预算；执行必要的 Rust、协议与客户端门禁。
- **完成判定与 Review**：C04-A03/A05/A06/A07/A08 的 Host 部分、A10 的个人回归及 A11 的 Host 生效部分成立；无个人模型旁路、第二份 Host 权威配置或任务级登录绑定。中心明确拒绝不触发自动模型重发，旧请求失败不清新身份，界面准确显示当前可用性。

M2 实现结论（2026-09-21）：Runtime 唯一外部模型来源、Host 用户域加载与原子发布、每次发送获取当前凭据、控制拒绝处理及只读客户端已接通。确定性中心端点与正式 Host 覆盖配置/协议切换、失败保留、旧身份响应、并发刷新和关闭；正式 Web 页面覆盖模型切换、只读参数和不可用展示。参数编译与两种 Adapter 继续共用原路径，中心拒绝不自动重发模型请求。Rust 全量回归与静态检查、客户端定向测试和构建通过。此次未操作共享中心库或真实付费 Provider；真实 Center 与 Host 的完整组合路径尚未执行，明确保留为 M3 集成收口项，不将可控端点验证等同于该路径已通过。M2 已获用户确认，真实组合路径由 M3 收口。
