## 三、中心模型配置与模板

### 3.1 数据归属

新增 `src/models/`，私有组织 Controller、Service、Entity/Repository、参数/发现/模板逻辑；只有模块内出现真实复用时才继续拆文件。数据库是连接、在线快照、固定参数和默认选择的权威；模板文件是模板权威，内存只持已校验的只读模板快照。不维护第二份全量有效模型缓存。

新增 `002-models-and-calls.sql`，不修改已执行的 `001-initial.sql`：

| 表 | 字段与关键约束 |
| --- | --- |
| `providers` | UUID `provider_instance_id`；沿用 ProviderConnection 字段、`api_key`；可空 `model_catalog jsonb`、`catalog_refreshed_at`、`catalog_connection_changed`。目录与时间同时为空/非空；目录仅存发现得到的标准化原始元数据，不存模板合并结果 |
| `model_fixed_configs` | 主键 `(provider_instance_id, model_id)`；`origin`、`parameters jsonb`、`updated_at`；Provider 外键级联删除。来源保存后不可改变，不因目录刷新建固定记录 |
| `model_settings` | 单例行，默认 Provider/model 同空或同非空；不设 Provider 外键，保留删除后的失效引用；不增加独立 vision 默认 |
| `llm_recording_settings` | 单例行，快照开关、内容/索引保留天数；默认 false/7/90，要求 `1 ≤ 内容保留期 ≤ 索引保留期 ≤ 3650` |
| `llm_calls` | 见第六节，调用索引及文件完整性；不存内容正文 |

JSON 参数沿用 `ModelParameters` 的字段、枚举和数值范围。数据库校验必需形状、主外键及身份约束，完整参数组合由服务层入口校验；不开启 ORM synchronize。API 只返回 `has_api_key`，密钥的保持/替换/清除沿用既有契约。真实 key 持久于受限数据库，备份同样按秘密处理；首版不引入独立密钥服务或虚构加密保护。

管理写入复用 IdentityService 的短事务串行边界：事务内重验管理员、改业务记录并追加审计，提交后才返回成功。调用流水插入/结束不占用该管理串行段，使用同一 DataSource 的短事务。网络发现、模型测试及模板文件读取不在数据库事务/身份写锁中等待。

### 3.2 目录刷新与来源合并

1. Center 读取 Provider 连接快照，按四种现有发现格式调用上游。沿用 Host 的 5 秒连接、20 秒整次发现、单页 1 MiB、总 8 MiB、100 页/10,000 模型上限；无自动重试或路径探测。
2. 同一 Provider 的刷新由模块私有在途 Promise 合并；仅保存正在执行的动作，结束即释放。等待者取消不破坏其他等待者；中心关闭取消整个动作。
3. 网络完成后进入管理事务，重验发起者权限、Provider 仍存在及连接/凭据与捕获值一致；不一致返回 `MODEL_CONFIGURATION_CHANGED`，不覆盖新连接目录。无需增加 revision。
4. 完整结果和审计同事务替换在线快照/时间，允许空数组；失败保留旧值。删除 Provider 不等待旧发现，晚到结果因 Provider 不存在而失败。
5. 展示以在线条目加未出现的固定条目合并，同 ID 不重复；按固定 → 在线 → 模板补未知求有效参数，来源分别保留。新默认选择与配置分发复用同一求值函数。

固定值重置、手动删除及默认失效沿用功能设计。后台保存按服务端提交顺序生效；表单不引入伪 CAS。目录快照替换才需要比较真实连接输入，不能以更新时间承担版本锁。

### 3.3 独立静态 JSON 模板

选择 `packages/assistant-protocol/resources/model-templates.json` 作为仓库内唯一初始模板数据源，内容为现有模型参数契约下的静态参考，不含 Provider 实现或执行代码。Rust 构建嵌入此数据；Center 构建/装配将其复制为制品 `resources/model-templates.json`。这是同一数据资产的交付副本，不跨应用导入源码，也不新增 npm 包。

文件为 JSON 数组，每项包含：

```json
{
  "provider_type": "openai",
  "model_id": "<真实模型 ID>",
  "parameters": {},
  "protocol_parameters": {},
  "document": "<厂商 HTTPS 参考地址>",
  "checked_on": "YYYY-MM-DD"
}
```

上例只说明结构，不是可直接使用的模型规格。`parameters` 使用现有 ModelParameters 的部分字段，缺失归 Unknown；`protocol_parameters` 可按两个既有 ModelProtocol 分别提供参数覆盖，用于原有 Responses 原生工具图片等差异，不允许脚本、条件表达式、正则匹配或任意新字段。先选择协议覆盖，再按在线事实补未知；固定配置永远不参与模板覆盖。

2026-09-21 核对 `model_templates.rs` 后确认抽取边界：

- `specification()` 内按厂商/型号设置的规格、档位、文档和核查日期展开为精确记录；已枚举型号中的 `if`/前缀判断只是在压缩静态表，不迁移为 JSON 条件。相同参数的型号也使用明确身份，不向未来同前缀型号推断能力。
- 函数尾部为已知型号补上的 streaming、tool_choice 和图片投影写入各记录，避免加载器继续隐藏厂商规格默认值；未知型号仍不命中模板。
- 实际连接协议由代码解析，再选择记录内的协议覆盖。`configuration_detail()` 保留只补 Unknown、保留 Invalid/明确不支持、字段来源、在线禁用思考时的保护，以及默认档位必须属于最终档位集合等规则；不能用通用对象合并替代。
- 迁移保持缺失/Unknown、明确 Unsupported、空档位集合与未提供集合之间的区别，校验基础参数和每个协议覆盖后的有效组合。迁移前后对全部现有型号及支持协议组合做等价核对，并以在线冲突样例约束两端合并行为。

独立更新适用于现有契约内新增型号、修改额度和能力参数；新增协议、参数类型或调用行为仍需更新程序。JSON 不承载脚本或规则引擎，不能将所有服务商变更承诺为纯数据更新。

运行期 `CENTER_MODEL_TEMPLATES_FILE` 可指向制品外的部署文件；未设置时使用上述制品资源。按精确 `(provider_type, model_id)` 查找；重复身份、未知字段/枚举、不合法数字或冲突参数拒绝整份文件。文件最多 8 MiB/10,000 项；读取普通文件，完整解析与校验后才替换内存对象，不执行文件内容。

`GET /api/model-templates` 返回可用状态、有效项数、最近成功加载时间与安全失败原因；不返回服务器绝对路径或整份文件。`POST /api/model-templates/reload` 仅管理员可调用。文件读取在事务外；进入短管理串行段复核身份，审计提交成功后同步替换模板对象，再释放串行段。配置求值也在该发布边界取得一致模板/数据库快照，不能观察半次加载。

加载失败保留当前有效模板；初次无有效模板仅令模板状态不可用，在线/固定参数完整的模型仍可用。审计与内存发布不构成跨介质事务，若进程在审计提交后退出，下一次启动从当前文件重新加载；不以过去的成功审计代替当前加载状态。

模板更新不写目录或固定表，不主动覆盖页面草稿、不推送 Host。个人 Runtime 从同一初始 JSON 编译嵌入并保持原行为；仅中心具备文件替换及重新加载入口。Node/Rust 各保留本层纯求值代码，用同组参数样例约束结果，不复制硬编码型号数据。模板文件没有动态 revision；将来增加不认识的结构时明确拒绝，不伪装为纯数据兼容更新。

### 3.4 管理接口

所有接口默认管理员鉴权，写入有审计；继续 Nest DTO/Swagger 维护契约、Admin 生成 SDK。模型 ID 可能含 `/`，不直接拼进路径。

| 接口 | 语义 |
| --- | --- |
| `GET/POST /api/model-providers` | 列出脱敏连接/创建 Provider |
| `GET/PUT/DELETE /api/model-providers/:id` | 详情、编辑、删除；删除返回实际影响的固定记录数和默认引用状态 |
| `GET /api/model-providers/:id/usage` | 删除前影响查询，无 Host 会话计数 |
| `GET /api/model-providers/:id/catalog` | 读取已持久化的原始目录及来源投影 |
| `POST /api/model-providers/:id/refresh` | 显式发现及可靠替换目录 |
| `GET /api/model-providers/:id/fixed-configs` | 固定配置分页读取，offset/limit 沿用已有约束 |
| `POST /api/model-configuration/query` | body 为 selection/origin；查询详情不写入或联网 |
| `PUT /api/model-configuration` | 显式保存固定参数 |
| `POST /api/model-configuration/reset` | 删除固定记录；online/manual 决定界面反馈，服务端不接受改来源 |
| `GET/PUT /api/model-settings` | 默认引用及求值状态；PUT 支持 null 清除 |
| `POST /api/model-configuration/test` | 仅测试已保存/当前有效配置，不传草稿或任意 endpoint |

配置测试复用中心转发和记录服务，唯一特例是管理员可测试非默认模型。服务端自行构造无工具、无历史的短文本非流式请求，分别使用现有 Responses 或 Chat Completions 的最小形状；不实现 Agent 编解码或工具执行，也不把“HTTP 成功”当成完整能力认证。校验相应成功结果形状后报告连通性结果，返回调用 ID，限制 30 秒和 1 MiB 响应；输出预算及不支持该预算字段的方言规则与现有协议样例对齐，不失败后换协议重发。调用记录标记 `admin_test`，不使用/回传管理员的 LLM key。

## 四、Center ↔ Host 与 Runtime 接入

### 4.1 生效配置协议

新增 `GET /api/runtime/model-configuration`，要求当前 Center Token，普通用户可访问；不要求管理员。HTTP 200 返回下列二选一：

- 可用：`state=ready`、`center_id`、`endpoint`、`provider_type`、已解析 `protocol`、真实 `model_id`、完整 `parameters`。
- 不可用：`state=unavailable`、`center_id`、稳定 `reason`（未选择、Provider 已删除、模型不在目录且无固定值、参数无效）。不返回半份可执行配置。

endpoint 由配置中的可信 public origin 加 `/api/llm/providers/{uuid}/v1` 构造，不信任请求 Host/Forwarded。Host 校验中心身份、已配置 origin、协议/枚举与大小后才接纳；不从请求体或 URL 重新提取业务 Provider ID。key 仍从当前 CenterLogin 读取，不在这个接口重复签发。

企业协议当前为 1。本次属于新能力扩展：Center `/api/info` 增加静态能力列表 `managed_models`、`llm_proxy`，保留协议区间 1，不与软件版本号绑定，也不引入动态配置版本。新 Host 在模型加载前要求这两项能力；旧 Center 身份登录仍可用，但模型明确提示需升级中心。未知能力可忽略，未知协议仍按 C03 拒绝；新 Center 身份契约不破坏旧 Host。

### 4.2 Runtime 统一模型配置与来源适配

2026-09-21 用户明确收紧边界：个人与企业只有配置来源和编辑权限不同，不建立企业专用的模型业务、默认选择、查询协议或界面。

配置接入层区分 `Local` 和 `External`。个人来源从 Runtime Store 加载；远程来源由 Host 获取并校验后，规范化为已有服务商、模型目录、固定参数和默认模型结构，原子发布到同一 ConfigRegistry。远程来源不读取本地模型数据，也不把远程快照写回个人 SQLite。

`ExternalModelConfiguration` 仅为受信 Host 的进程内输入与请求归属凭证，复用 ProviderConnection/ModelParameters 校验。规范化后的服务商名称、代理连接、模型 ID 与参数由现有 `list_providers`、`list_provider_models`、`list_fixed_model_configs`、`get_model_configuration` 和 `get_model_settings` 返回；不存在另一套企业模型展示/参数接口。连接仅含中心代理地址，不含上游真实地址或 key。

配置层集中处理固定参数的来源选择及默认选择策略。主调用、连接测试、标题、压缩和 child 共用原模型准备与编译路径；最终接纳均核验已有 Provider Arc。远程刷新替换 Provider Arc 后，旧准备值不能接纳。Transport 所需的配置归属仍随编译结果捕获，仅用于中心拒绝的精确失效。

`ModelSettings.default_model` 保持唯一默认语义，`management` 只补充 `read_only`、不可用原因及刷新时间/错误，不携带另一份模型或参数。只读策略禁止配置编辑及模型切换，历史显式模型选择在配置层统一归到当前默认；无默认即不可执行。现有会话历史不迁移。

前端复用服务商列表、二级模型菜单、默认模型及参数页。显示模型和读取思考档位都走通用路径，不判断企业 mode；只按只读策略限制编辑/选择。源刷新由 Host 的刷新命令承接，随后重新读取相同业务接口。配置发布沿用 `ConfigChanged`，不新增企业事件。

### 4.3 加载、并发与生命周期

Host 在 `resources/model/` 下增加私有中心配置/Transport 实现，复用已有 CenterClient 和 Credentials。加载器由用户资源 owner 持有一个加载任务，通过 watch 合并最新刷新意图；空闲时等待刷新或登录变化，不保存另一份“当前生效配置”。Runtime 完成装配后用 Weak 引用接线，避免 Runtime → 工厂 → Runtime 强引用环；初始化失败与关闭都由已有用户资源 owner 收尾。

- 初次装配后由 Host 用户资源 owner 跟踪配置加载任务；不阻塞登录与用户域就绪。已有用户域的新登录触发同一加载入口，不能只在首次初始化加载。
- 同用户显式刷新、登录触发和模型拒绝共用在途请求；不同用户不共享凭据或配置。取消某个页面等待不取消其他等待者的加载；用户域关闭取消任务并等待，超时沿用现有关闭期限。
- 发送 GET 时捕获当前 `Arc<CenterLogin>` 和用户域实例；加载完成先编译校验，再取得 Runtime 现有模型发布门，最后短持 Credentials 锁核对登录/域仍有效并同步发布。获取门之前不持凭据锁，发布期间无网络、磁盘或 await，防止校验后被新登录抢先替换。
- 旧登录响应丢弃，不清新状态；新登录已要求的加载在旧请求结束后执行一次，不能让新请求永久复用旧凭据 Future。只允许有一个待执行的最新加载意图，不建无界队列。
- 默认未配置/无效是权威不可用结果，应清除旧有效投影；网络/格式错误若是手动刷新且原配置未被拒绝，保留原投影并记录刷新失败。
- 明确拒绝携带该 ModelService 创建时捕获的配置 Arc，先在同一门内仅使匹配的当前 Arc 不可用，再尝试刷新。旧 Arc 的失败不触碰已更新配置；如已有新配置直接报告已刷新，不再次失效/重复获取。数值字段相同的新 Arc 仍是一次新的有效接纳结果，不用内容相等推断请求归属。

Arc 是已有进程内对象身份检查，不进入网络、数据库或文件，不新增代次字段。Rust 受信发布 API 须暴露最小的门内提交能力以完成上述锁顺序，不能在 Host 先检查再异步无条件发布。

### 4.4 代理控制错误与重试

代理只接受 `POST /api/llm/providers/:id/v1/responses` 与 `.../chat/completions`。路径 Provider、请求顶层 `model` 和协议路径必须与当前有效默认一致；参数值不逐项比较。

中心自产控制响应带 `x-ez-center-control: 1`、中心生成的 `x-ez-call-id`（已建立索引时），正文仍用 `{error:{code,message,request_id}}`：

| HTTP/code | Host 动作 |
| --- | --- |
| 409 `managed_model_configuration_stale` | 按捕获配置失效并刷新一次；当前模型调用失败，不重发 |
| 409 `managed_model_unavailable` | 同样获取权威不可用原因，不误登出 |
| 401 `llm_key_invalid` | 使用发送时捕获的登录句柄复核当前身份；旧凭据拒绝不清新登录；当前凭据明确无效才沿 C03 关闭用户 |
| 400/413 `llm_request_invalid` / `llm_request_too_large` | 失败，不刷新或重试 |
| 503 `llm_record_unavailable` / `llm_proxy_unavailable` | 中心控制故障，失败，不自动重发；不改为身份失效 |

Host Transport 只有在配置 origin、保留标记、状态与原因码均匹配时才处理控制错误，最多读取 64 KiB 错误体。缺少/非法标记按普通上游错误处理；Center 必须剥除上游同名保留头，再设置自己的调用 ID，防止上游冒充控制响应。

现有 TransportError 只能表达网络失败，不能把配置拒绝伪装成 Timeout，否则会触发模型有限重试。因此增加通用 `TransportError::Rejected(ModelError)`，只承载已脱敏的规范模型拒绝；Chat/Responses 映射直接保留该错误。Host 将配置控制错误映射为已有 `ModelError::Config`，认证为 `Auth`，其他明确中心拒绝映射为不可重试 `Provider`，不把企业原因码或刷新逻辑下沉 Core。原始 HTTP 状态保留在 Provider 分支，不伪造为另一个状态。

扩展现有两个 Service 构造入口，使显式 ModelCapabilities 与自定义 Transport 可同时注入；不能因使用 with_transport 而丢失当前工厂提供的图片/工具能力。个人工厂继续原装配。包装 Transport 每次 execute 取最新 key并替换 Authorization，发送后捕获句柄只用于本次响应核验，不冻结到任务；未开始发送就已退出则直接 Auth 拒绝。

原始上游错误继续现有分类及建流前有限重试；代理不自行重试。Host 控制错误在泛化前完成处理，最终错误消息说明“已刷新，请重试”“刷新失败”或“未配置模型”；Runtime 根据规范错误结算，不解析展示文本。新增 TransportError variant 的所有匹配与私有回放序列化一起检查，既有记录不改写。

### 4.5 旧会话与路由状态

配置发布只影响新执行准备。排队输入在队首重新准备；child 与同一活动 Run 的辅助步骤仍遵守已冻结规格，若下一模型请求已不被中心允许则明确失败，不中途重装 Agent。

继续使用 Adapter 的 provider/protocol/endpoint/model 路由指纹。不同中心 Provider 的代理路径不同，旧 opaque state 不进入新路由；参数变化不会假装成新 Provider。历史正文和工具记录保持，新的上下文预算按当前模型重新计算，不直接复用旧 PreparedModel 或旧压缩请求。

中心同一 Provider 修改真实 endpoint 不会改变 Host 可见指纹，适用于同服务的连接维护；更换到不共享不透明状态的另一服务应建立新的 Provider 实例并切换默认。首版不通过动态 revision 解决这个隐藏上游身份问题，后台编辑连接需给出该提示。

## 五、Node 透明代理

### 5.1 HTTP scope 与原始正文

在同一个 Fastify 实例注册私有代理 scope，管理 API 保持原 JSON 解析和小请求限制。代理 scope 使用 buffer parser 保留请求原字节，最多 32 MiB；只为校验顶层 model/stream 解析副本，转发仍发送原字节，不 JSON.stringify 重写字段/数字。要求 UTF-8 application/json，拒绝压缩请求体、重复顶层 model 字段及非对象形状，避免准入判定与上游解释不一致；不做参数上限的第二套校验。

raw 路由不经过 Nest Guard，必须复用 `security.ts` 提取的来源/Bearer 基础检查，并调用同一 IdentityService.llmIdentity；不能标为公开后依赖 Controller 补鉴权。onRequest 先鉴权再接收大正文，进入实际转发前复核凭据仍有效、默认和当前路由。所有代理错误，包括 parser/hook 的 400/413，统一经过本 scope 的安全错误处理，不能遗漏来源标记。

当前 16 KiB 全局限制保留给管理接口。代理原始请求缓冲单次 32 MiB、在途原始正文累计 128 MiB；按已收字节预留，超额立即中止接收并返回明确资源错误，完成校验并发出后尽早释放不再使用的副本。该预算不等于整个 Node 堆内存保证，也不创建用户配额或等待队列；实施时验证 JSON 解析峰值和大请求取消。

Fastify 支持按 scope 配置 parser 及 buffer 解析，使用方式依据[官方 Content-Type Parser 文档](https://fastify.dev/docs/latest/Reference/ContentTypeParser/)，实现需以仓库锁定版本验证，不能仅改全局 bodyLimit。

### 5.2 路由、流与取消

复用 Node 24 `http`/`https` 出站，目标只由保存的 endpoint 和固定协议后缀构造；拒绝 endpoint 的用户名/密码、query/fragment，不自动跟随重定向。允许管理员配置内网或本地模型服务，不能套用只准公网的规则。目录发现路径仍使用现有安全约束。

出站请求头采用最小白名单：Content-Type、Accept 和已支持 Adapter 真正需要的协议头；Authorization 由中心覆盖，Accept-Encoding 固定 identity，不发送浏览器 Cookie、任意客户端秘密头、Host 或 hop-by-hop 头。入站仅转发必要 Content-Type、Retry-After 和安全上游请求标识，移除 Set-Cookie、hop-by-hop 及中心保留头；不透传可能改变访问目标的 Location。

上游正文按字节透传，不自动解压、聚合 SSE 或改写事件。若上游不遵守 identity 而返回压缩正文，转发保留 Content-Encoding，快照明确标记正文编码不支持，不能将压缩字节伪装 UTF-8 文本。数据转发写入返回 false 时等待 drain，停止读取上游；取消时销毁上游请求及响应流，不后台 drain。收到请求正文的正常 close 不等于下游取消，按请求是否完整、response 是否正常完成判定。

默认连接建立 10 秒、响应头及相邻上游 chunk 空闲 300 秒，下游持续不消费 300 秒也结束转发；长流无固定总时限。受背压暂停时区分下游等待与上游空闲，不能把主动暂停读取算成上游无输出。计时器结束须显式 abort/destroy，Node timeout 事件本身不会取消请求，见[Node 24 HTTP 文档](https://nodejs.org/docs/latest-v24.x/api/http.html)。

需同时处理 `app.ts` 已有 10 秒 connectionTimeout：代理路由覆盖套接字等待策略，不能只给出站请求设置 300 秒而让入站连接先被关闭；同一 keep-alive 连接后续转入管理接口时恢复对应策略。现有请求头/请求体完整接收期限与响应流空闲计时分别保留和验证，不能用关闭所有超时来支持长流。

响应头发出前的中心故障可返回结构化控制错误；已经发出流后只能结束/中断连接，不能把 JSON 错误拼进上游 SSE。on close/error/timeout/finish 多入口共用本次请求的单次 settle，避免重复记录或释放预算。

### 5.3 代理生命周期

Center 服务 owner 持有在途代理/配置测试/目录刷新的取消与收尾句柄。关闭先拒绝新工作、停止清理调度，取消在途网络，等待索引与快照最多 10 秒，随后释放 HTTP 和数据库；超时写脱敏诊断，未结算索引在启动恢复。不得先关闭 DataSource 再等待需要写记录的任务。

不新增持久化工作队列或自动重放。模型转发结束后的写盘 Promise 仍归本次调用及 Center owner 跟踪，不能 fire-and-forget。快照采集预算不足只影响快照，不阻断已经接纳的模型响应。

## 六、调用记录、文本文件与恢复

### 6.1 索引与结果口径

`llm_calls` 使用中心 UUID 调用 ID；保存 user_id（可空）、调用时 username/Provider 显示名、Provider UUID/model ID、`kind=proxy|admin_test`、protocol、开始/结束时间、HTTP 状态、固定原因码，以及请求/响应分别的快照状态、相对文件路径、字节数和摘要。记录不外键级联删除到 Provider；实际身份来自验证结果，不接受请求传 user_id。上游完整错误正文不进入索引。

`outcome` 为 `in_progress / forwarded / rejected / upstream_error / interrupted / unknown`。`forwarded` 仅表示上游 HTTP 2xx 正文转发到自然 EOF，不证明 Provider SSE 内部业务成功或 Runtime 任务成功；200 中的错误事件透明保留，中心不为统计重写一套解码器。界面称“转发完成”，能从快照追查流内结果。请求没有进入中心就无调用记录。

已认证请求在访问上游前创建最小索引；准入拒绝也结算该索引。索引建立失败返回 503 且不访问上游。无法认证/格式过早拒绝只写必要脱敏安全诊断，不将伪造用户信息落为可信调用；数据库不可用时不承诺每次拒绝都有持久记录。

普通列表按开始时间/ID 倒序，offset/limit（默认 50、最大 200），筛选时间半开区间、用户、Provider/model、outcome、kind、调用 ID。提供时间/ID及用户/时间组合索引，其他索引根据实际查询验证决定，不预建报表或 token 计费体系。

### 6.2 采集与文件发布

每次接纳时捕获当前策略。关闭即不保存正文；开启时每侧最多 8 MiB、全中心采集及待写缓冲共 64 MiB。保留所能获取的前缀，停止原因用 `size_limit`、`memory_limit`、`interrupted` 等稳定值表达，不继续积累。裁剪 UTF-8 尾部不完整字节并标记截断，不用替换字符把截断伪装完整。

`CENTER_SNAPSHOT_ROOT` 指定独立绝对持久目录，默认关闭策略下可不配置；开启前检查根已配置、可用且不位于 public 静态目录。目录 0700、文件 0600（平台支持时），不对外返回绝对路径。

文件布局为 `<root>/YYYY/MM/DD/<call-id>/request.txt` 与 `response.txt`，日期取调用开始 UTC；两侧状态独立，例如完整请求与中断响应。快照状态为 `disabled / pending / complete / partial / failed / expired / missing`，磁盘文件保存 UTF-8 正文，快照摘要/截断原因在索引，禁止输出秘密头。

收敛顺序：

1. 停止网络/采集，结算转发结果及快照 pending 状态；失败只记录安全诊断，不改写已返回流。
2. 在调用私有目录独占创建 `.part`，写入已采集文本、flush 后关闭，通过同目录 hard link 原子发布固定文件后移除 `.part`，不覆盖既有终态文件（POSIX rename 会覆盖目标，故采用不可覆盖的发布原语）；快照根文件系统需支持 hard link。
3. 两侧分别算字节数/摘要，将完整性及相对路径写回原调用行。某一侧失败不冒充另一侧失败，两侧都结束才释放全部采集/写盘预算。

第 1 步失败时仍可完成有界文件写入，但不宣称数据库已记录；文件永不作为模型成功结果的第二权威。文件成功而数据库更新失败，保留 pending/unknown 以待核对，不自动重试上游。

### 6.3 启动恢复与保留期

启动先处理非终态调用：上次进程未结算的 outcome 置 unknown，不能推断成功或重发。对于文件存在但完整性提交失败的调用，可核对固定位置文件并登记为 partial/recovered_unknown，不能仅因文件存在认定完整。已有 complete 文件缺失/摘要不符则标记 missing/failed，并保持已确认的模型转发结果。

恢复不覆盖原记录中已可靠提交的终态。`.part` 不对外展示，归本次调用恢复清理；文件和数据库一起恢复的完整备份才可能保持 complete。恢复/清理报错即停止该批处理并报告，不连续自动扩大修复范围。

保留期以调用结束时间计；unknown 使用开始时间作为过期基准。在 Center 内用受监督的定时批处理（每小时、单批 100 条）清理，不新增 Worker 产品或队列表。待写/活动调用不参与清理；先删除该调用可确认归属的文件，再将保留索引标为 expired。文件删除失败保留行和原因，下一次调度不反复尝试已报错批次，待管理员排查后重启/恢复。

索引过期先确认对应文件已删除或不存在，再删除调用行；不先删索引留下无人管理的正文。重启后文件已删但状态未写的情况按不存在完成 expired，不当成模型失败。只处理根内规范日期/UUID 路径，未知文件或符号链接明确报告，不能递归清理任意目录。

### 6.4 记录管理接口

- `GET /api/llm-calls`、`GET /api/llm-calls/:id`：管理员只读查询。
- `GET /api/llm-calls/:id/snapshot?side=request|response`：按索引和安全路径解析，返回受保护的 UTF-8 文本及状态；no-store、nosniff，不作 HTML，不开放静态目录。每次查看记录一条不含正文的管理审计。
- `GET/PUT /api/llm-recording-settings`：读取/修改快照开关及保留期，短事务与审计共提交；关闭不删除既有文件，缩短保留期需前端明确说明。

快照列表不携带正文；用户切换、退出或详情卸载清空浏览器内容。不存在、过期和损坏分别呈现，不以下载到空文本代替失败。

## 七、配置、兼容与交付

新增环境配置为 `CENTER_MODEL_TEMPLATES_FILE`、`CENTER_SNAPSHOT_ROOT`、`CENTER_LLM_CONNECT_TIMEOUT_MS`（默认 10000）和 `CENTER_LLM_IDLE_TIMEOUT_MS`（默认 300000）；超时只接受正整数，分别限制在 1—120 秒及 1—3600 秒。保留期和开关归数据库单例，不能再由 env 覆盖制造双权威。上述资源保护默认值先作为常量，不创建通用配额设置页面。

Center 装配脚本复制初始 JSON 为独立资源；正式运维更新外部文件后显式 reload。C06 需把模板、PostgreSQL、快照根都纳入部署与备份说明，分别说明模板恢复与模型数据/调用文件恢复，程序升级不覆盖维护文件。

数据库升级只新增本循环表，既有身份/密码/Token 规则不变。维护工具的精确计数表清单追加新增表；本次设计不连接数据库。实施前核实主机、端口、库、表及实际调用者，已有库写入前执行独立备份与可读/COUNT 验证，异常停止；生产按规则确认。不能以新增表“不影响旧表”跳过备份/准入。

不提供自动 down migration；旧程序看到新账本拒绝启动。回退需要停服并恢复匹配的数据库/模板/快照备份，不能只换旧二进制。隔离试验只使用 `.runtime-test/` 新场景与核实后的独立 Center 数据库。

2026-09-21 按用户要求核对 [OpenAI reasoning effort 定义](https://developers.openai.com/api/docs/guides/reasoning#reasoning-effort)，新配置、JSON 和应用协议统一序列化 `xhigh`；按用户最新要求，Rust 与 Center 均只接受 `xhigh`，不保留 `x_high` 别名或归一化分支。既有 SQLite 标量已使用 `xhigh`；JSON 固定参数、目录及会话快照不兼容旧拼写，本次不迁移或批量改写数据库。TS 投影及所有界面消费者同版本更新。上游 wire value 仍由厂商映射指定，不因标准档位改名而改写厂商值。`xhigh` 表示更高推理投入，不规定固定 token 预算；支持档位仍逐模型配置。

Host/客户端应用协议仍在尚未发布的 0.27.0 内统一生成；新增模型状态/刷新命令检查全部生产者、消费者和持久化转换，配置管理策略与刷新状态不被 SQLite ModelSettings 存储。Center 能力协商与 Host/客户端兼容分开，软件版本不机械锁步。

## 八、实现范围与验证重点

| 范围 | 必要修改 |
| --- | --- |
| enterprise-center | models、llm-proxy、llm-calls 私有模块；HTTP/安全与关闭装配；迁移/实体/计数；OpenAPI；资源复制及运行说明 |
| enterprise-admin | 模型与调用记录路由/页面及局部 hook；既有 Store 写入入口、SDK 重新生成；不动原型 |
| runtime-host | CenterClient 能力/配置读取、Credentials 当前 key、用户域加载生命周期、工厂/Transport、刷新 Command |
| assistant-runtime | ConfigRegistry 外部来源、统一准备/接纳、发布与失效、查询投影，现有旧会话及辅助调用适配 |
| assistant-protocol / TS 包 | 模型状态和刷新命令，静态模板数据资产；不纳入 Center 管理 DTO 或 ORM |
| agent-openai-compatible | Transport 的通用模型拒绝和携带明确能力的可注入构造，不理解 Center 码 |
| Desktop | 替换 C03 模型未启用提示为只读状态与刷新；保留个人管理流程 |

本方案无新增动态版本字段、中心 Session/Run/Token 表、持久化代理队列或模板历史。必要新机制的理由分别是中心模型数据权威、外部模型来源与调用文件独立生命周期；已有模型身份、事件、重试、用户域和事务应复用。

验证从直接改动开始：参数/模板同样例对照、目录替换与连接交错、配置 Arc 失效/旧登录响应、原始请求/流字节和取消、索引/文件故障恢复。再用隔离真实 Center + 正式 Host 覆盖一次完整工具往返与默认变更后的显式重试，复用 C03 登录/隔离结论，补真实模型凭据连续性。

必要门禁按范围使用 Center/Admin typecheck、lint、定向测试、OpenAPI/SDK 检查及构建；Rust 定向包测试、fmt/clippy，协议变化时重新生成 TS。仅在实际失败或未覆盖风险出现时扩大。具体命令、真实 Provider 的少量调用与里程碑划分见[开发计划](开发计划.md)，本轮不运行应用、迁移或付费模型。

设计核查仍有实施门禁：锁定 Fastify 版本的 parser 隔离/断连行为、两种 Adapter 注入能力的等价性、原始大正文解析内存峰值必须在最先涉及它们的里程碑验证；若无法满足本方案，先报告设计偏差，不静默改成改写请求、隐藏重试或丢失能力。
