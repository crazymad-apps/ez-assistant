## 二、目标与范围

长任务运行时，用户可以持续看最新输出，也可以自由翻阅历史、查看子任务，界面行为不被并发输出打断。个人模式和企业模式、本机 Desktop 与远程 Desktop/Web 共用相同语义。

| 能力 | 用户结果 |
| --- | --- |
| 稳定历史分页 | 当前任务、其他会话及其他用户持续输出时，仍能加载更早消息；不会因无关事件反复报错 |
| 输出跟随与自由阅读 | 看最新内容时继续跟随；主动上滚后停留在所读内容，回到底部恢复跟随 |
| 子任务上下文占用 | 能区分子任务当前窗口占用与累计消耗，正确观察压缩前后的变化 |

非目标：重做会话布局、引入虚拟列表或全文历史缓存、增加长任务监控页、修改压缩算法与执行调度、增加中心统计或计费、跨客户端同步阅读位置。也不新建子 Session、子 Composer 或子任务控制面板。

本文中的“子会话”对应现有 child task 二级消息视图，不改变其独立 Journal、归属父 Session 的产品模型。

## 四、历史分页

### 4.1 正常读取

1. 沿用消息列表顶部自动加载更早消息的入口，主会话和子任务一致。
2. 首次进入读取最近一页；向上加载只读取目标历史的前一段，不重新下载整份历史。
3. 当前会话追加正文、reasoning、工具进度，或其他会话/用户发出事件，不应仅因事件序号推进使旧页失败。
4. 前页与实时尾部独立接纳：前页只补充对应区间，不覆盖新尾部，不重复、不跳过消息，不倒退活动执行状态。
5. 成功插入更早消息后，用户正在看的消息及其视口位置保持稳定；同时发生的尾部输出、图片加载和布局变化不能被错误计入顶部补偿。
6. 同一列表不重复并发请求同一个前页；无更多历史后停止请求，保留已有内容。

### 4.2 一致性与失效

- 历史页的接纳取决于所属用户域、主/子 owner、正文 generation 和页边界是否仍有效，不要求整个 Runtime 静止。
- 清空、历史重写、正文 generation 切换或目标删除等真正影响读取合法性的变化，必须拒绝旧结果。不能为了消除报错取消这些检查。
- 压缩仍遵守 C02 的 generation 与完整产品历史契约。若压缩切换 generation，重新取得当前历史再定位，不跨 generation 拼接；不另建一个“压缩不失效”的历史版本体系。
- 事件水位仍用于既有实时观察与可靠投影协调；本循环不把历史页当作更新整份 Session 状态的快照，也不全局移除水位保护。
- 切换会话、子任务、Host、账号或退出后，旧请求不能更新新目标的内容、用量或滚动位置。

### 4.3 异常与恢复

| 场景 | 展示和恢复 |
| --- | --- |
| 网络失败或读取失败 | 保留已加载消息，在列表顶部显示简短中文说明及重试入口；不整屏清空 |
| 短暂读取冲突 | 仅允许有界恢复，不能持续轮询或要求任务停止输出；重试不能代替后端校验范围修正 |
| 游标实际失效 | 作废旧分页链，重新读取目标历史；原阅读消息仍存在时尽量恢复到该消息，否则显示最新有效页面并提示历史已更新 |
| 会话或子任务已删除 | 展示已有的不可用/返回路径，停止继续分页，不把删除当作空历史 |
| 身份失效或用户域变化 | 按 C03 既有登录和清理流程处理，不保留前一账号的内容与阅读状态 |

正常持续输出不能触发 `runtime state is changing; retry the snapshot` 一类历史加载错误。错误文案不暴露内部游标、generation 或存储路径。

## 五、正文与 reasoning 输出跟随

### 5.1 跟随意图

每个消息列表、每个 reasoning 滚动区各自维护“跟随最新”或“自由阅读”的界面意图。

| 情况 | 行为 |
| --- | --- |
| 首次进入且没有可恢复位置 | 定位最新内容并跟随 |
| 原本跟随，新内容增加或布局改变 | 继续到对应区域底部，不能把底部被推远误判为主动上滚 |
| 用户通过滚轮、触控板、键盘或滚动条主动向上阅读 | 暂停该区域跟随，后续输出不抢回视口 |
| 用户主动回到底部 | 恢复该区域跟随，允许小范围像素误差 |
| 点击消息列表现有“回到底部”按钮 | 明确恢复外层列表跟随；动画中继续输出不会再次误取消 |
| 程序定位、顶部分页补偿或浏览器布局修正 | 不作为用户主动切换跟随意图的依据 |
| 跳转到引用或历史来源 | 定位阅读目标并暂停外层跟随，不被后续输出拉走 |

判断依据是用户的阅读意图与实际操作；不按每次 scroll 事件的底部距离无条件覆盖意图。流式期间不逐段启动相互竞争的平滑滚动动画。

### 5.2 内外区域独立

- 正文随外层消息列表滚动；reasoning 保留原折叠入口与内部高度上限。
- reasoning 展开后首次观察默认跟随其最新内容；同一块已有阅读状态时恢复该状态。收起本身不改变意图。
- 内层上滚只暂停内层；外层上滚只暂停外层。嵌套事件不能误切换另一层；用户实际滚动到外层时，外层正常响应。
- 用户阅读 reasoning 旧内容时，其增量不抢回内层；若外层也在自由阅读，展开、收起和增高保持外层阅读锚点。
- 本循环不新增 reasoning 回底按钮，用户在内部滚到底即可恢复跟随；保留外层现有回底入口。
- reasoning 折叠、展开、Markdown 渲染、工具块变化、图片加载及窗口尺寸变化，都遵守同一意图规则。

### 5.3 会话切换与保存范围

- 当前客户端生命周期内，返回已访问的主会话或子任务时，恢复对应阅读位置及跟随意图；会话选择、主子切换和前进/后退保持一致。
- 离开时处于跟随状态，返回后显示最新内容；离开时处于自由阅读，返回后恢复阅读位置。
- reasoning 状态归属到对应 owner 下的具体块，不能按列表下标串到另一条消息。
- 优先复用现有导航和展示缓存，状态随既有视图缓存生命周期清理。目标失效、账号/Host 变化及退出时清理；不新增持久存储、跨重启恢复或跨端同步。
- 原位置因历史变化无法恢复时，按历史失效规则处理，不承诺恢复已删除的内容。

## 六、子任务上下文占用

### 6.1 数据含义

主会话压缩后占用修正属于 C02 已完成基线。代码核查显示子任务执行也通过 `compact_child_context` 接入既有压缩器；目前能确认的展示缺口是 `ChildTaskUsageSnapshot` / `project_child_usage` 仅提供累计消耗。C05 应先核实子任务有效上下文、压缩后修正及模型窗口来源，再接入既有计算和展示；本设计不预先认定子任务存在与主会话相同的计算缺陷，也不把新展示尚未验证等同于底层未修复。

| 指标 | 含义 |
| --- | --- |
| 当前上下文 | 子任务自己的当前有效上下文占用、对应模型窗口上限及占比，口径与 Runtime 窗口判断一致 |
| 累计消耗 | 子任务已记录模型调用的累计 token 用量，沿用现有统计；不与父会话或兄弟任务合并 |

- Runtime 从子任务自己的可靠对话、C02 压缩修正和实际适用模型事实产生投影。前端只格式化，不自行数文本、推断 token 或借用父会话数值。
- 模型调用和工具结果可靠提交后更新；没有新的可靠用量时保留最近可信结果，不宣称逐 token 精确变化。
- 压缩提交后，按新的有效上下文显示允许下降的占用；旧 generation 的 live usage 不能把它重新抬回压缩前数值。累计消耗不因上下文缩短而扣减。
- 子任务完成、失败或取消后仍能查看最终可靠占用；重新打开或 Host 重启后从已有可靠事实恢复，不依赖客户端曾经观看直播。
- 无可靠占用、窗口上限不可确定或旧任务缺少必要模型事实时，显示“上下文暂不可用”或 `—`。不按当前默认模型猜测历史任务上限，不把未知显示为零。
- 占用值与占比均按主会话既有格式和精度显示；必要的图形夹取不掩盖实际已用 token 数，不新增预警阈值或自动操作。

### 6.2 展示入口

1. **子任务二级消息视图的既有信息区**：显示“上下文：已用 / 上限（百分比）”及“累计消耗”，两者名称明确区分；复用主会话上下文环形指示的视觉规则。宽度足够时两项保持一行，仅空间不足时换行。
2. **消息中的子任务条目**：保持现有名称、状态、审批提示和累计用量，增加紧凑“上下文 xx%”；不可用时显示“上下文 —”，不隐藏为看似零值。窄宽度允许附属用量换行，任务名称与进入操作优先。
3. 主会话 Composer 和右侧上下文区域继续属于父 Session；进入子任务不把父会话指标替换成子任务指标，也不新增第二个右侧上下文 owner。

初次加载显示已有加载反馈；读取失败显示可恢复说明，不能把失败结果覆盖成零。子任务条目和详情消费同一来源的投影。

## 七、职责、契约与关键取舍

| 层 | 本循环责任 |
| --- | --- |
| assistant-runtime | 目标历史的一致读取、游标失效语义、子任务上下文投影及可靠刷新；复用已有上下文与存储端口 |
| assistant-protocol / TS 投影 | 在现有子任务观察契约中承载可缺失的上下文占用；统一生产者、消费者、序列化及兼容判断 |
| Runtime Host | 沿用当前用户域路由、认证和存储装配，不建立新的分页服务或统计数据库 |
| Desktop/Web | 分页接纳与恢复、用户阅读意图、位置恢复、子任务用量展示；不持有业务权威状态 |
| agent-context / Core | 沿用现有窗口判断和压缩语义，展示需求不改变执行策略 |

最小新增审查：删除拟新增机制后，现有事实是否足够？历史读取、任务身份、generation、可靠对话、导航和累计用量事实已经存在，应直接复用。缺口是子任务窗口的公开投影和界面阅读意图，允许在现有契约/组件中补齐；不增加业务实体、数据库表、持久化用量缓存、全局 revision、独立滚动服务或后台轮询。

本循环涉及应用观察契约，实施前需要简短技术方案固定读取边界、快照/事件协调、子任务模型窗口来源和协议兼容核查结果；沿用本设计与前序讨论，不再重新比较架构路线。界面布局沿用现有组件，本文件已覆盖入口、状态和异常，不单独创建交互指导。

## 八、验收标准

| 编号 | 场景 | 可观察结果 |
| --- | --- | --- |
| C05-A01 | 当前会话持续输出，同时反复向上分页 | 旧页可正常读取，无无关繁忙错误、重复或遗漏，阅读位置稳定 |
| C05-A02 | 同用户其他会话及同 Host 其他用户并发输出 | 不干扰目标分页，不串内容、游标、用量或阅读状态 |
| C05-A03 | 主会话和子任务分页过程中清空、重写、压缩切换 generation 或删除 | 拒绝真正失效的结果；不跨代拼接；重新读取和定位有确定反馈 |
| C05-A04 | 分页中断、重复触发、切换目标后迟到响应 | 既有内容保留，可重试；不重复合并，不污染新目标，不无限请求 |
| C05-A05 | 连续换行、大块正文增量、图片/工具块布局变化 | 原跟随状态持续有效，始终可看到最新输出 |
| C05-A06 | 滚轮、触控板、键盘及滚动条上滚，期间继续输出 | 停留阅读；主动回底或点击回底后恢复跟随，程序滚动不反向取消 |
| C05-A07 | reasoning 连续输出、展开/收起、内部上滚和回底 | 内外层独立跟随；自由阅读不被抢回，外层布局变化不丢阅读位置 |
| C05-A08 | 主子切换、切换会话、前进/后退、引用定位 | 恢复各自位置和意图；来源定位暂停跟随；账号/Host 切换清除旧状态 |
| C05-A09 | 核查子任务既有上下文/压缩事实，并验证多个子任务的工具增长及连续压缩展示 | 复用已修复的计算链路；各自窗口值正确，压缩后可下降，累计消耗保持原口径，旧事件不污染新代；主会话仅作受影响回归 |
| C05-A10 | 子任务未取得用量、窗口未知、终态后重开及 Host 重启 | 未知不显示零；可恢复事实正确恢复，缺失事实明确不可用；不猜历史模型上限 |
| C05-A11 | 子任务详情/列表、窄宽度、个人/企业与 Desktop/Web | 指标来源和标签一致，父会话上下文归属不变，现有操作可用 |

验证采用最小有效范围：确定性并发/失效检查、上下文投影与协议回归、真实浏览器滚动场景，以及正式 Host 的主子任务组合验收。原生 WebView 的布局/滚动行为须有实机验证，不能仅以 DOM 单元测试代替。版本跨平台交付与安装升级仍归 C06。

测试数据仅使用项目 `.runtime-test/` 下新建隔离环境；若实施中确需数据库操作，按根 AGENTS.md 核对、备份和验证。设计阶段不运行服务或操作数据库。

## 九、风险与兼容边界

- 后端消除全局静止要求后，前端也必须正确区分历史页和实时快照，不能绕过 C02 请求归属、generation 和迟到响应保护。
- 滚动事件顺序因浏览器和 WebView 而异，须覆盖程序滚动、用户输入、布局观察与平滑回底的交错。
