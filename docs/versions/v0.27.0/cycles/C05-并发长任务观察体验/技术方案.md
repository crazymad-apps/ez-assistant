## 三、历史分页一致性

### 3.1 Runtime 与 Store

`list_conversation_page` 沿用现有请求、游标和返回类型，按以下边界组织：

1. 经 C03 路由取得当前用户 Runtime，核实完整 owner；child 必须属于指定父 Session。只在目标 owner 上工作。
2. 获取当前正文 generation，并核对游标；已有游标换代立即返回 `snapshot_stale`，不把旧游标自动解释成新历史位置。
3. 沿用 `load_conversation_window`，由 Store Worker 在一次串行操作内校验目标存在、归属、generation、读取固定窗口。返回值中的 generation、边界和正文必须来自该次读取。
4. 主会话的消息归属/工具投影复用 `projection_context`。涉及内存 Run/Input 归属与 Store 正文的组合读取，用现有 Session mutation gate 保护这一小段读取，先完成按需加载，再进入 gate；不得持有同步 state 锁跨 await，也不能嵌套调用再次取得同一 gate 的高层命令。锁只覆盖当前 owner 的本地快照/窗口读取，不覆盖网络、模型执行或分页后的 UI 等待。
5. child 前页使用已有空投影上下文与 Store 窗口；不为只读分页把执行中的 ChildTaskRecord 暴露给 UI 或新增第二个子任务锁。对返回前可见的目标删除/换代作检查；相同 generation 的追加不使固定前页失效。
6. 去掉 `start == end` 的全局事件比较。`ObservedSnapshot` 外壳继续保留，历史页水位取读取开始时的保守观察值，不声称读取期间的所有事件均已进入该页；客户端不得用它推进业务快照/SSE 水位。

Store 窗口读取是历史正文的线性化点；读取后才发生的合法变化通过 generation/删除事件和请求接纳检查处理。不能要求在 HTTP 返回瞬间整个系统仍未变化。

无游标首次读遇到真实换代时，沿用现有 `SNAPSHOT_ATTEMPTS` 上限重读；持续换代耗尽后保留受控繁忙结果。已有游标冲突不循环重试。Store 错误不转换为成功空页，越界游标继续明确拒绝。

`get_conversation_page_around_run` / `get_conversation_page_around_message` 用于历史定位，复用相同的目标读取边界，避免失效恢复和引用定位重新落入全局静止检查。完整 Session/ChildTask 组合快照仍遵守原有水位语义，不全局移除其保护，不顺带重构所有查询。

### 3.2 前端请求与合并

- 发起前页请求时，闭包捕获实际 client、Host 实例/既有连接生命周期、完整 owner、generation、请求 cursor 与当时的页首边界；不新增服务端请求版本。
- 成功、失败及清理 loading 都必须确认仍属于这次请求。账号/Host 重置后的旧响应不得回写，新分页链不能被旧请求清除 loading。
- 同一 owner 当前只保留一个前页请求。最新页刷新与旧页仍连续且 generation 不变时，保留该请求的 loading 和前页 cursor；真正重建分页链时才作废。
- 只有当前 previous cursor 仍等于请求 cursor、owner/generation 一致、边界连续时才合并；child 同时检查父 Session ID 和 child ID。合法页仅前插，已有较新的同 ID 投影优先，不覆盖实时尾部。
- `applySessionSnapshot` / `applyChildTaskSnapshot` 的实体水位、最新页连续边界以及 C02 的归属校验保留；不把“旧页无需全局水位”扩展成“所有旧响应均可接纳”。
- `snapshot_stale` 使原链失效，先保存当前可见消息锚点，再复用既有快照/around-message 路径重建；锚点已不存在时回到最新有效页并给出中文提示。
- 网络/存储失败保留已加载内容和顶部重试；分页不新增自动退避服务。真实换代重读由 Runtime 的现有上限承载，客户端对最终繁忙提供手动重试，不在 scroll 回调中无限重发失败页。

## 四、输出跟随与阅读状态

### 4.1 组件内跟随

在 `ConversationView` 私有目录内提取一个主列表与 ReasoningBox 共用的局部 hook；两个实际消费者使用相同事件规则，各自持有 DOM ref、跟随意图、上次位置和程序定位目标。不放入全局通用服务，不进入 Runtime 协议。

- 将“当前是否近底”与“是否跟随”分开：底部距离只用于回底按钮和用户回底判定，内容增高不直接取消跟随。
- 用 wheel/touch、有效键盘滚动和 scrollbar 指针操作标识用户滚动过程；只响应所属滚动容器，输入控件中的按键不算滚动。结合实际位移判定离底/回底，不能仅靠 `scroll.isTrusted` 区分程序滚动。
- 用户主动向上立即释放跟随；惯性滚动延续该用户行为。内容布局或程序赋值产生的 scroll 不反向覆盖意图。外层忽略内层仍在消费的操作，发生实际滚动链传递时再处理外层位移。
- `useLayoutEffect` 与 ResizeObserver 只在跟随时安排至底部，合并同一帧更新；连续输出使用即时定位。显式回底可沿用现有动画，但动画期间跟随意图保持；新的用户上滚中断动画与跟随。
- ReasoningBox 将 ref 和事件绑定到实际 overflow 节点，不能误绑 Collapse 动画外壳；展开后再恢复/定位。observer、帧回调和短暂交互标记在卸载、owner 变化时释放。

### 4.2 分页与布局锚点

不用整个 scrollHeight 增量区分顶部和尾部变化。开始分页时保存首个可见可靠消息 ID 及其相对视口偏移；成功前插后的 layout 阶段测量同一锚点，只修正该锚点的位置差。流式尾部增高不会被计入补偿。

分页等待期间若用户继续滚动，更新到最近阅读锚点，不能把旧请求开始时的位置强拉回来。加载失败、请求作废、目标切换时清理对应补偿。自由阅读期间的图片、工具块和 reasoning 布局变化用相同锚点规则；避免与浏览器原生 scroll anchoring 双重补偿，所控容器只保留一个位置修正来源。

### 4.3 导航状态

扩展现有 `ConversationLocation`，将 follow、阅读消息 ID 与相对偏移作为可选的视图状态，原 offset 保留为同一历史内的兜底。导航历史中的定位目标和阅读锚点语义分开，不能把每次滚动变成一条新的导航记录。

普通会话选择、主子切换和前进/后退统一从 NavigationStore 恢复最近对应 owner 的查看状态；优先使用现有导航记录，不新增并行导航栈。reasoning 按 owner + 现有可靠 message/segment 身份保存有限展示状态；live 部分沿用现有 run/step/part 身份，在可靠提交映射明确时转接，无法映射则清理，不能按数组下标串块。

这些状态只在当前客户端内存中存在，随历史/视图缓存回收；删除、账号/Host 变更及退出清理。generation 变化时作废旧数值 offset，能定位的消息 ID 可用于重新定位；绝不跨 generation 恢复旧正文缓存。

## 五、子任务上下文投影

### 5.1 已有计算与缺失事实

子任务 `compact_child_context` 已调用 C02 的共用压缩器并提交 replacement；不重复修复主会话计算。当前 `child_task_conversation_snapshot` 读取的是完整产品历史，累计消耗应继续使用它；当前占用必须先通过 `execution_context_from_product_history` 取得有效上下文，再调用 `agent_context::context_token_usage(...).total_tokens()`。

现有子任务和 Run 记录都无法可靠恢复创建时的窗口上限，Session 当前配置也可能改变。因此本方案新增一个必要的冻结事实：`context_window_tokens`，放在已有 `NewStoredChildTask` / `StoredChildTask` 中；创建时从装配 child Agent 的实际 `compiled.model.context_window_tokens()` 取得，通过 `ParentDelegationResources` 传入，与子任务创建一起保存。它不从默认配置二次解析，不新增模型服务接口。

存储采用已有 `child_tasks` 表的可空正整数列；新任务写入实际值，旧行保持 NULL。只保存窗口上限，不保存 used_tokens、百分比、Provider 凭据、模型配置副本或统计快照。窗口上限在该任务生命周期内不变，压缩和状态结算不覆盖它。

最小新增理由：实时占用可从对话重建，无需持久缓存；创建时的模型窗口无法从当前配置或只有模型身份的历史响应重建。删除这个字段就无法同时满足重启恢复和不猜历史上限，所以该字段是必要执行事实，属于原子任务记录，不是新用量机制。

### 5.2 投影与刷新

在 `ChildTaskUsageSnapshot` 增加 `context: Option<ContextUsageSnapshot>`，复用已有结构。`project_child_usage` 接收该子任务的完整历史与冻结窗口；累计消耗维持原算法，上下文使用派生有效历史计算。将主会话已有“used + window → ContextUsageSnapshot”的纯投影复用给 child，不改主会话 live 合并算法。

可靠数据不足、窗口为空/无效或 C02 返回不可用时，context 为 None；不能创建零值伪装未知。图形比例沿用现有夹取规则，原始 used_tokens 保留。

`child_task_tree_item` 必须保证正文和所投影 generation 对齐：沿用目标记录前后核对与既有有界重读；遇换代重新取任务记录和正文，不将旧任务 metadata 与新摘要拼在一起。累计与上下文在一次投影中来自同一份可靠历史。组合快照仍按现有契约对齐，失败不覆盖最近可靠值。

沿用 `conversation_committed` / `step_committed` 与现有 ChildTask 事件触发的合并刷新。子压缩可靠提交并更新 registry 后，如当前路径没有发出对应历史变更通知，补发已有 `ConversationCommitted { owner, generation }`；不增加新事件类型或轮询。刷新后更新任务树与当前 child 详情，确保两处采用同一份最新可靠用量。

child 窗口展示直接消费可靠 context，不套用父会话 `effectiveContextUsage` 的 max 合并，也不用未带 generation 的 live usage 抬高占用。这样压缩后的下降不会被旧 usage 抹掉。纯文本增量继续走现有 live 投影，窗口值在可靠提交点推进。

### 5.3 展示落点

- `app/AppShell/ChildTaskSubheader.tsx`：现有子任务标题栏中分开显示上下文和累计消耗，保留返回/停止入口。
- `features/conversation/ConversationView/ChildTaskTree.tsx`：在现有任务条目增加紧凑占比/不可用标记；复用 `childTaskPresentation.ts` 的可靠/live 合并入口，live 状态覆盖时不能丢弃可靠 usage.context。
- 样式与格式复用现有环形/用量显示；需要共享的展示组件就近提取，不复制上下文计算。
- 父 Composer 和 ContextPanel 的 owner 不变，子任务显示不覆盖父指标。

## 六、协议、迁移与失败恢复

| 边界 | 方案 |
| --- | --- |
| 应用协议 | 原 ChildTask 用量增加可缺失 context；Rust 构造处、TS 生成、前端夹具与消费同步更新。不增加新命令或分页协议 |
| 软件兼容 | workspace 与最低应用兼容版本已为 `0.27.0`；C05 在同一未发布版本内统一到最终契约，不为 C03/C04 中间产物建立别名/双协议 |
| 本地存储 | 在现有 `v0_27_0` 迁移入口增加 child_tasks 可空正整数列及验证；新库和从正式旧版本升级均经同一版本链。软件/数据库最低 Host 不机械再提高 |
| 旧任务 | 冻结窗口列为 NULL，累计仍可查看，上下文明确不可用；不按当前模型回填、不重跑历史任务 |
| 未发布开发库 | 不增加跨中间 schema 的静默补丁或启动时 ALTER。检测到不满足最终 v0.27.0 结构时明确拒绝；本轮实施/验收使用新建隔离 Home，已有人工环境的处理另按数据库规则核对 |
| 回滚 | 沿用升级前独立备份与现有最低 Host 准入。旧程序不得绕过新账本写库；恢复时使用已验证备份及匹配程序，不手删新增列 |

协议缺失值只表示旧观察数据没有该信息，不是第二套统计语义。JSONL 正文格式、压缩 summary、中心 PostgreSQL 和用户身份均不变。

数据库迁移在现有控制器事务内执行，失败即回滚并停止启动，不连续自修复。创建子任务时窗口值与原关系记录一起提交，不能出现“已接受任务但冻结值稍后补写”的阶段。内存 Store 和 Host Adapter 同步实现新增字段，所有导出/导入、复制/删除和恢复调用方按现有 child 支持边界核对。

实施涉及数据库时，先报告实际 Host、数据库路径、表和范围；SQLite 无网络端口。仅使用 `.runtime-test/` 新场景目录；迁移旧夹具前独立备份、回读并核对关键表精确数量，事务后校验行数及新增值。设计阶段不执行数据库操作，不修改用户 Runtime Home。

## 八、方案收口

本方案沿用已确认方向，补齐三个落点：目标历史读取与前页请求边界、组件内独立跟随和消息锚点、子任务冻结窗口上限及既有上下文计算投影。没有新 revision/sequence/generation、实体、状态表、消息队列或全局用量缓存。

技术方案已确认，按用户要求采用一个实现里程碑，见[开发计划](开发计划.md)。实施若发现 owner 写入未经过既有串行边界，或必须修改 C02/C03 已验收语义，应先说明具体证据并修订相关方案，不能以减少分页错误为由放松一致性。
