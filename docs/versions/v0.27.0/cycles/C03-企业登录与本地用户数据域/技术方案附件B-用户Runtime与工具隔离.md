# C03 技术方案附件 B：用户 Runtime 与工具隔离

本附件属于[技术方案](技术方案.md)，已于 2026-09-20 随主方案获用户确认；M2 用户 Runtime、就绪及生命周期已完成并获确认，M3 完整资源入口与工具隔离已获用户确认。第 2.3 节为 C04 交接方向，具体接口由该循环定稿。身份与凭据见[附件 A](技术方案附件A-身份协议与客户端.md)，物理布局见[附件 C](技术方案附件C-配置与版本升级.md)。

## 一、用户域装配与生命周期

### 1.1 唯一装配

Host 私有 `user_domain` 模块只维护 `UserDomainKey → Arc<UserServices>` 的已初始化缓存，并按用户键串行化初始化与回收。回收依据有效 Host Token 及工作是否仍需使用，不依据无操作时长；没有单独的 Entry 状态枚举、空闲扫描器或额外的用户域租约体系。

`UserServices` 包含本人 `Arc<AssistantRuntime>`、用户配置源、Store/MCP/Gateway/Speech 生命周期句柄和用户根。用户根为不可变构造参数，不允许请求中途替换。两种模式经过同一装配函数；差异是认证来源和传入的目录/模型配置来源，不是两套用户服务清单。

M2 实现复用现有 `ReadyServices` 作为业务句柄，部分装配及关闭资源由私有 `UserResources` 持有，不额外新增同义公共类型。入口见 [user_domain](../../../../../apps/runtime-host/src/user_domain/mod.rs) 与[共用装配](../../../../../apps/runtime-host/src/user_domain/services.rs)；下文 `ensure_user_services` 对应 [HttpState::user_services](../../../../../apps/runtime-host/src/http/mod.rs) 调用用户缓存的 `ensure`。命令、快照和事件已使用该入口，其余资源路由已在 M3 接入。

按主方案第 3.1 节，普通业务只依赖这个用户服务句柄，不接收 `is_enterprise` 参数。实例内已有 Store、权限和工厂即可承载用户隔离，不额外创建 EnterpriseSession、EnterpriseMcp 或按模式选择的业务 dispatcher。

登录只完成认证并签发 Host Token/Cookie，不等待用户域装配。统一获取函数 `ensure_user_services` 负责以下流程：

1. 从已验证身份取得用户键，取得该用户的异步锁，确认本次访问授权仍有效，再检查缓存。服务获取与回收共用此锁，不能返回正在关闭的服务。
2. 已有服务则直接复用；没有则等待数据库准入、配置源、Recall 密钥、环境/工具工厂和 Runtime 等必要资源装配完成。
3. 全部成功且 Host 未停止时才放入缓存，向调用方返回服务句柄。
4. 失败先关闭本次已创建资源再释放锁，向调用方返回具体错误，不缓存失败条目、不发布半初始化 Runtime；初始化错误不撤销已经签发的登录凭据。

同用户并发调用在该异步锁上等待，成功后复用同一缓存实例，不能重复开库；失败调用返回错误，后续调用可重试。这里的等待是异步 `await`；磁盘/SQLite 工作仍由现有阻塞 worker 承载，不阻塞 Tokio 工作线程，也不持有全局缓存锁等待初始化或关闭。

初始化任务由现有 Host Supervisor 跟踪，调用方等待其结果。客户端断开不让半初始化资源脱离监督，也不打断其他等待者；清理完成前不释放同用户的初始化互斥。Host 停止时取消并收尾尚未完成的初始化，不发布晚到服务。尚未连接的外部 MCP、尚未就绪的中心模型等继续使用各自既有状态，不要求本地用户域就绪等待所有外部能力可用。

### 1.2 独立阻塞就绪接口

新增 `POST /runtime/ensure-ready`，个人与企业客户端共用。接口不接收用户 ID 或目录；使用普通 Host Token/Cookie 及既有来源、登录上下文校验，由认证结果选择本人用户域，调用 `ensure_user_services` 并等待完成。成功返回 `204 No Content`；已就绪时直接返回，未就绪时完成或等待初始化，不返回“初始化中”状态供前端轮询。

客户端在登录成功或恢复已有登录后，通过统一 RuntimeClient 调用该接口，等待期间显示 loading，成功后加载业务投影。失败显示具体错误并允许重试；登录仍有效时不要求重新登录。登录、身份查询、改密及退出不依赖用户域初始化，用户仍能查看身份或退出。

业务入口也统一调用 `ensure_user_services`，不能仅凭前端曾调用过就绪接口就跳过服务获取；普通 handler 始终接收已就绪句柄。等待中凭据失效或 Host 停止时，当前请求按既有认证/关闭规则结束，不因用户服务装配完成而恢复失效授权。

### 1.3 登录结束后的回收与关闭

主动登出或 Host Token 过期后，检查该用户域是否仍有有效 Host Token 或需要继续运行的工作：有则保留；都没有则关闭 Runtime、MCP/Gateway/Speech 和 Store worker，移除缓存，同时清理不再使用的 Host 当前凭据。回收只释放运行资源，磁盘上的会话、配置和个人数据保留。长时间无操作本身不是回收条件，页面关闭或网络断开也不等于登录结束。

两种登录结束原因的任务语义保持区别：主动登出结束该用户的统一登录状态，取消该用户工作并等待收尾；Host Token 过期只结束对应客户端访问，不清除 Host 当前企业凭据，也不取消已接纳任务。过期时仍有任务、队列、调度或设备工作需要运行就保留用户域，这些工作结束后再次检查同一回收条件，不能为了释放资源中断任务。

检查接在既有登出收尾、登录到期处理和工作结束路径，不增加定时空闲扫描或倒计时；未加载的域只清理不再使用的认证状态，跳过服务关闭，不能为了清理先初始化。初始化、获取服务和回收共用同用户异步锁；回收在锁内重新核对登录及活动事实，并通过 Runtime 既有关闭准入完成收尾。并发新登录仍可完成认证，业务就绪请求等待关闭完成后重新装配；已退出或过期登录的晚到请求不能重新打开用户域。关闭失败保留受监督资源并报告错误，不能提前移除后再开第二个 Store。

同一用户任一端主动退出会影响该用户在本 Host 的所有端；其他用户继续运行。Host Token 过期时，后台任务仍可使用 Host 当前企业凭据，不能误当成用户主动退出。两种模式共用上述回收条件；个人启动入口仍可通过同一装配函数打开默认域。回收后再次登录，通过独立就绪接口重新装配；Host 重启后也按需打开，不提前加载所有历史用户。一个域打开或运行失败仅影响本人；全局监听、布局、Host 配置失败仍属于 Host 故障。

Host 停止时沿用 Supervisor：停止全局准入及 Gateway 新连接/输入 → 关闭传输/PTY → 并行关闭各 Runtime → 关闭各 MCP/Gateway/Speech 服务及 Store worker → 释放发现信息与实例锁。沿用现有 Host 总关闭期限 15 秒、Runtime 关闭期限 10 秒，不按用户数量串行累加。超时明确记录未收敛资源，不能用 Drop 冒充成功 shutdown。

## 二、Host 统一用户状态与模型调用

### 2.1 每用户只有一份当前登录状态

Host 按 `UserDomainKey` 保存当前企业凭据，独立于用户 Runtime 是否已初始化。Desktop、Web 和设备都是同一用户服务的入口，不分别拥有后端执行身份。同一用户最近一次成功登录更新这份状态；不同用户分别保存，不能用整个 Host 的一个“当前用户”变量相互覆盖。

Host Token 只关联用户身份，不固定某次 Center 登录。已有客户端的 Host Token 仍有效时，继续访问同一用户 Runtime；后续 Center 请求统一使用该用户最新的 Center Token/LLM key。任务、排队输入、Goal、child 和辅助生成均不保存登录来源或凭据副本，不增加任务级授权参数、InputId 到登录的映射或授权继承链。

### 2.2 复用模型工厂，发送请求时读取最新凭据

这里的“最新”只指 Host 当前用户的 Center Token/LLM key，不代表每次调用都会获取最新模型配置。模型、协议、能力和固定参数来自最近一次成功获取并编译的中心配置，在执行准备时冻结；配置更新的发现和生效按第 2.3 节处理。

继续通过既有 `ModelServiceFactory` 装配用户模型服务。个人模型使用本人配置；企业模型的 Host Adapter 在每次实际发出模型请求时读取当前用户的最新凭据，包括运行中任务的下一轮调用、标题、压缩和子任务调用。Runtime/Core 只使用原有模型接口，不接收 Center Token/key，也不判断请求来自 Desktop 还是 Web。

长期缓存的 PreparedModel 或客户端不能冻结某次登录的 key。一次已经发出的 HTTP 请求使用发送时取得的凭据完成；新登录不撤回该请求，下一次请求读取最新值。凭据替换不改写已冻结的模型规格、不重放工具，也不因替换而追加 Center logout 中断旧请求；旧凭据不再作为后续调用来源。

C03 中心模型来源仍通过既有 `configuration_unavailable` 表达尚未启用，不增加任务级凭据参数或输入持久化字段。C04 还须实现配置获取、刷新后的模型重新准备及代理错误处理，不能把“复用工厂”理解为这些能力已具备，或预先断言配置/模型适配层无需改造。

### 2.3 中心配置变化与请求被拒绝（C04 交接草案）

以下细化[总体设计第 5.3 节](../../总体设计.md#53-模型托管与刷新)已有方向，交接方向已随本轮设计确认；C04 仍须定稿具体接口、控制错误标记及实现，不表示 C03 已接通真实模型代理。

Host 在登录成功后独立加载中心当前配置，另支持显式刷新和配置过期错误触发刷新；配置加载失败不撤销已经完成的登录。没有中心变更推送或后台配置轮询，不引入配置 revision。不同变更的可见时机明确如下：

| 中心后台变更 | Host 如何知悉及何时生效 |
| --- | --- |
| 默认 Provider 或默认模型变化 | 下一次携带旧 Provider 路径和旧 `model` 的调用被中心在转发上游前拒绝；Host 识别配置过期错误并获取当前配置。显式刷新也可提前发现 |
| 同一模型的固定参数变化 | 不能通过模型身份比较发现，也不保证下次 LLM 请求一定拒绝；按原约定，在重新登录后的配置加载或显式刷新等下一次成功获取配置时生效。当前冻结执行不热更新 |
| 真实上游 endpoint/key 变化 | Host 不持有这些值；中心下一次转发读取当前值，Host 无须刷新或重新登录 |
| 默认模型被删除、禁用或取消，当前无可用模型 | 中心明确拒绝；Host 刷新后将托管模型显示为不可用，保留登录、会话和文件，不继续把已拒绝配置用于新的执行，也不回退个人模型 |

固定参数不即时同步是当前取舍的实际限制；若要求后台保存后下一次执行必用新参数，需要另行改变配置获取时机或通知约定，不能声称读取最新 key 已经解决。

中心自产的配置过期拒绝拟沿用输入稿的 `409 + managed_model_configuration_stale`。中心控制错误必须与透传的上游错误可机器区分；C04 须明确保留的错误来源标记和原因码，透传上游时不得携带该保留标记。Host 不只凭 HTTP 409、401/403 或提示文本决定刷新和退出。

收到明确的配置过期拒绝后：

1. Host 模型适配层识别原因，使用当前用户的 Center Token 获取当前配置。同用户并发遇到拒绝时复用正在进行的刷新；一次错误触发一次刷新尝试，取消、退出或刷新失败即收尾，不循环刷新并重发模型请求。
2. 成功结果通过用户 Runtime 的配置/模型准备边界发布，后续新执行及显式重试重新准备模型，不能复用过期的 PreparedModel。已在执行的冻结规格不被替换；Provider 变化后的历史 opaque state 按现有隔离规则处理，不传给新 Provider。旧请求的拒绝或刷新失败不能使已成功发布的新配置失效，刷新结果也不能重新激活已经退出的用户域。
3. 本稿沿用“刷新配置，但不自动重发被拒绝调用”的建议：当前调用明确失败，提示“企业模型配置已更新，配置已刷新，请重试”。刷新失败则提示尚未取得新配置；无默认模型则提示联系管理员配置。不能在刷新失败后继续使用已被拒绝的配置接纳新执行；后续显式刷新成功后才恢复模型准备。
4. Runtime 按现有调用归属处理失败：主模型失败结束对应执行，标题、压缩和 child 走各自既有失败路径。配置拒绝不触发用户统一退出或取消整个用户域；其他正在进行的请求不被刷新动作主动中断。已经开始的流不因配置更新被截断或重放；后续调用是否仍可用由中心准入判断。用户重试仍走已有显式恢复/重试入口，不自动重放整个 Run 或已执行工具。

认证错误另行处理：只有确认是当前中心凭据无效，才按附件 A 结束该用户状态；旧 key 请求的晚到拒绝不能清除新登录，可按当前 Center Token 复核身份。上游 Provider key 错误是中心模型调用故障，不能当作用户退出。普通网络错误、上游限流或不可用沿用既有模型失败及有限重试规则，不触发配置刷新；流开始后的错误不自动重试。LLM 请求网络失败本身也不能代替附件 A 的身份核验结论。

实现接缝已有依据：[OpenAI-compatible Service](../../../../../crates/agent-openai-compatible/src/chat/service.rs)支持注入既有 `Transport`，可由 Host 私有适配在发送时替换 key、在通用错误转换前识别中心控制响应；现有转换会把普通 409 归为 Provider 错误，不保留中心错误码作为独立分类。C04 必须完成这一识别与刷新接线，再通过既有模型失败/配置投影向 Runtime 和客户端表达结果，不能依赖 Core 解析企业错误或解析展示文案。现有[模型重试](../../../../../crates/agent-model/src/retry.rs)不自动重试配置、认证及普通 Provider 拒绝，保持这一边界。

C04 验收须覆盖默认模型 A→B、同模型仅改参数、上游 key 变更、无默认模型、刷新失败、刷新后中心再次变化、上游同状态码、旧 key 晚到拒绝和流中配置变化；验证提示、任务终态、下次执行配置与不重放行为。具体配置接口及控制错误标记由 C04 定稿，本节不新增 C03 实现任务。

### 2.4 退出、失效和恢复

同一用户任一端主动退出，先按附件 A 告知全部任务中断及其他端退出的影响，用户确认后才结束该用户在本 Host 的统一登录状态：使该用户所有 Host Token 失效，关闭连接和 PTY，停止用户 Runtime 的新准入并按既有取消/关闭路径收尾队列、Run、Goal、child 和工具。整个用户域已是取消范围，不再按发起登录筛选任务。其他用户、其他 Host 和 Center 管理后台不受此本机退出动作影响。

Host Token 自然过期仅结束该访问凭据及对应传输，已有后台任务继续使用 Host 当前企业状态；不能把客户端 Token 到期信号接到 Runtime 任务取消树。没有有效 Host Token 且没有工作需要运行时，按第 1.3 节回收。中心当前凭据明确失效或临时不可达时，按附件 A 统一处理该用户，不能回退使用被替换的旧凭据。

新登录更新凭据时，正常运行的任务继续，后续调用自然使用最新值；已经取消或中断的任务不自动复活。Host 重启后企业凭据不在内存，恢复本人数据后，暂停的输入、Goal 和定时任务仍按既有显式恢复规则处理。用户明确恢复时使用当前用户模型服务，不重新绑定某次登录身份，也不重放已经执行的工具。

`InputChannelSource` 继续只表达 Desktop/Device 来源，不混入凭据或用户字段。每个 Runtime 已有唯一用户所有者，普通命令无需再传 user_id。凭据更新与退出的并发边界集中在 Host 用户认证状态，见附件 A。

## 三、传输入口和能力归属

Host 在 HTTP Adapter 内提供统一“认证并取得用户句柄”的流程；具体 handler 必须接收这个固定句柄，不读取模式决定是否调用 Center 或怎样查库。禁止在资源 resolver 内通过 SessionId 反查全 Host 用户目录。

| 入口 | 必须使用的用户事实 |
| --- | --- |
| `/commands` Runtime 分支 | 所有快照、历史、配置、权限、审批、Workspace、Recall、Skill、MCP 均调用本域 Runtime；归属失败统一资源不存在 |
| `/events` | 订阅本域 Runtime 广播，快照/重连游标也属于该域；Host 全局状态不夹带其他用户就绪或路径 |
| 附件上传、`/session-materializations` | 暂存目录改为本域 `data/staging/uploads`；从开始流入到提交始终持有固定用户句柄和登录取消保护 |
| 附件、Session/child 工具资源的预览/缩略图/下载/原生路径、`export.md` | 在本域 Store 校验完整父子归属链，再解析资源；不能仅验证文件存在 |
| `/host-files/*`、`/sessions/{id}/resource-files/*` | 先应用下节路径保护，再应用原有工作目录/文件权限；原生路径不是额外授权 |
| 既有浏览器资源/导出/下载入口 | 两种模式统一用 Host Cookie；比较页面期望的登录上下文，再使用上述同一资源 resolver，不新增企业专用 Token 下载接口 |
| `/user-terminals/socket` | 真实来源、首帧及统一登录核验后固定用户/登录；Center 当前状态复核留在认证入口，帧中 ID 不能改变用户域 |
| `/runtime/ensure-ready` | 认证后等待本人用户域就绪，成功返回 204，失败返回具体错误；与登录独立，不新增初始化状态轮询或全局用户列表 |
| `/health`、`/capabilities` | 公开 Host 模式与协议，不加载用户域或公开用户列表 |

PTY 继续使用 Host 级 `UserTerminals` Supervisor；`TerminalOrigin` 加 Host 私有用户键，Entry 保留既有 Host 访问凭据关联，仅用于访问到期及连接清理，不关联后端登录。创建、恢复、resize、输入、关闭、Session 删除后的清理都按 `(用户域, 既有资源 ID)` 判定。断线沿用原语义，Host Token 过期关闭对应访问创建的 PTY；用户统一退出关闭该用户全部 PTY。终端恢复仍按既有资源归属与准入规则，不根据后端凭据来自哪个端分支。

命令边界按职责处理，不建立企业模式禁用清单：

| 能力 | 服务端/原生层处置 |
| --- | --- |
| `HostAccessCommand::{GetStatus, SetPassword, Configure}` 及新增模式/中心配置，`ShutdownRuntime` | 必须真实 loopback + 本机 bootstrap；企业角色（包括管理员）不能代替 |
| `DeviceGatewayCommand`：快照、开关、配对窗口、确认、改名、撤销 | 取得本人 Gateway 句柄，调用同一命令实现；设备、配对、事件归属本人 Runtime |
| `SetCurrentControllerOutputHosting`、Gateway 输出 dispatcher、内置 Speak/语音服务 | 取得本用户/已绑定设备及当前可用服务；检查真实设备连接、配置和权限，不检查产品模式 |
| Tauri `create_resource_browser`、navigate、act、layout、capture、url 等资源浏览器操作 | 原生层使用已验证连接的用户上下文选择 Profile、检查窗口 owner；切换身份关闭旧窗口，两种模式共用 |
| 用户 Provider 创建/更新/删除、模型连接验证及默认/固定/会话模型变更 | 已明确的模型管理差异：在模型管理边界集中检查配置来源的可编辑性，普通会话业务不复制该判断；查询返回该来源的真实就绪/只读状态 |

具体复用方式：

- 现有 `DeviceGatewayService::new(runtime_home, runtime, dispatcher, speech)` 已接收完整域依赖；传入 user_root、本人 Runtime/dispatcher/Speech，设备登记仍在本人 Store。其已有按安装身份发布的临时 WSS 端点随对应 Gateway 管理，不为用户新增 Runtime 业务 HTTP 端口，不改设备侧为企业登录协议。
- `[speech]` 由本用户配置源读取，播放/识别任务和输出目标归对应 Gateway/连接。设备输入归本人 Runtime，模型调用同样使用 Host 当前用户状态；设备密钥只认证设备，不能替代企业登录。重启后没有企业凭据时，沿用登录及显式启用/恢复动作。
- 资源浏览器 manager 为窗口保存已验证的 Host/用户 owner；Profile 在原生连接装配时按该 owner 选择，旧 Profile 仅归原个人域，其他用户使用自己的 Profile。原生操作只查 owner 与平台能力，不读取 enterprise 标志。具体平台 Profile 隔离必须验证，无法形成独立上下文不能使用别人的 Profile 兜底，也不能据此宣布整类企业功能禁用。
- 录音/播放继续由实际客户端设备权限和连接归属约束，不因企业账号直接关闭；共享物理设备的占用冲突沿用设备不可用/忙的结果。资源清理、取消和关闭不受模型配置是否就绪影响。

这些都是同一功能的用户归属适配，不新增设备业务流程、第二套语音服务或企业浏览器类。

## 四、结构化文件与工具保护

在 Host resources 的文件能力装配和 HTTP 文件 resolver 共用同一私有路径策略，使用现有 FileSystemTool SPI。Core 不增加文件访问，也不识别用户身份。策略接收不可变 host_root/user_root 与本机管理秘密路径，不通过全局当前用户改变。

- 企业及个人普通业务调用均不得访问兄弟用户域、`host.toml`、`run/`、整套升级备份及 Host TLS 私钥；本人用户根内按既有权限操作，公共 `skills/` 只读。
- 校验标准化的路径组件和实际目标；读操作解析符号链接，创建/写入检查最近存在祖先与目标，rename 检查两端。不能使用字符串 starts_with 防穿越，不能允许公共 Skill 符号链接跳入他人私有目录。
- 列目录、递归搜索、导出目录等必须在遍历过程中跳过受保护子树；不能只检查请求起点。以操作系统 Home、磁盘根或 Host 根为工作区也不放开保护。列 Host 根/`users` 本身拒绝，不返回其他用户键；普通外部目录的正常内容仍可浏览。
- 注册 Workspace、附加工作目录、文件选择、工具权限放行和原生路径解析同样执行该保护；Allow-all 权限不能覆盖它。明确选择的外部目录不搬迁；不同用户选择同一外部路径时文件自然共享。
- Host 根和用户根创建沿用私有目录权限及非链接准入；打开资源后尽量持有文件句柄完成后续读写，避免检查后重新解析另一条路径。

这是应用结构化入口保护。Shell、PTY、MCP 和运行 Host 的操作系统用户仍拥有操作系统权限，同权限恶意进程或用户替换文件/硬链接不在强隔离保证内；不把工作目录称为沙盒。企业凭据不写入全局进程环境，子进程环境继续沿用敏感变量过滤。

## 五、MCP 与 Skill

每个用户装配独立的 MCP 配置源、服务注册/发现状态、连接工厂和清理 worker；传入的 Runtime Home 改为 user_root。因此 `mcp.json`、`mcp/<server_key>` 及凭据天然按用户分开。重连只操作当前域，同名 server_key 不跨域去重。临时测试连接归当前用户，结束必须关闭，不能成为额外常驻连接。

Skill 扫描参数从操作系统 Home 改为明确的有序根：

1. Session 冻结工作区有序根；每根 `.ez-assistant/skills` 在 `.agents/skills` 前。
2. 本人 `user_root/skills`。
3. 仅个人模式、自定义 Runtime Home 时仍保留的外部 `$OS_HOME/.ez-assistant/skills`。
4. `host_root/skills` 公共补充。
5. 仅个人模式的 `$OS_HOME/.agents/skills`。

按规范化真实根去重、保留首次位置；同层冲突沿用诊断，不能用遍历顺序随机决定。名称开关继续保存在本域 Store，禁用名称不回退低层同名包。新增协议来源 `HostSupplement`，用户域继续用 `UserEzAssistant`，旧外部个人来源增加可区分的 `LegacyUserEzAssistant`；工作区和 `UserAgents` 含义不改，不保存扫描排名或全局开关表。

个人历史根是否加入列表由用户域装配决定；扫描器只遍历传入的有序根、执行统一去重和优先级规则，不能在发现/启停/激活时再次判断个人或企业。

激活、输出、临时文件及相关事件全部属于本域/Session。公共包内容仅作为输入；默认 cwd 为本人工作目录，不能自动切换到公共包目录或将脚本缓存写回其中。既有冻结 Skill Activation 不在升级时重新发现或替换正文。

## 六、既有资源保护与本版范围

本版沿用已有资源保护，不新增用户域数量、初始化并发、Run/child、队列、模型请求、MCP、连接或上传暂存的 Host/用户配额。不引入共享额度对象、额外排队或满额拒绝流程，也不为用户域装配新增容量错误。

已存在的限制保持原作用范围和处理方式：[Host 登录表](../../../../../apps/runtime-host/src/access/credentials.rs)、[PTY/WS](../../../../../apps/runtime-host/src/user_terminal/mod.rs)、[HTTP 请求/附件大小及文件读取](../../../../../apps/runtime-host/src/http/mod.rs)、[文件预览](../../../../../apps/runtime-host/src/http/resources.rs)继续复用现有实现。原本属于 Host 的限制仍在 Host 共享，不能因逐用户装配而复制放大，也不叠加新的每用户限额。

同用户初始化互斥、资源归属校验、取消和关闭收尾是用户隔离与生命周期的必要部分，按前文保留；任务调度沿用 Runtime 既有语义。主动登出完成凭据撤销不等于用户域已经关闭，资源仍在收尾时继续由原 owner 监督。资源不足按现有错误处理，不删除旧数据救急。

新增并发限流需有实际需求与资源表现依据，再单独评估并确认；不作为本版实现或验收的前置条件。

## 七、重点验证

- 登录独立成功；首次就绪调用阻塞等待，同用户并发调用只形成一个 Runtime/Store，已就绪调用直接返回。初始化失败保留登录并可重试，另一域故障不扩散。
- 登录仍有效时，断连或长时间无操作不触发回收；主动登出或最后一个 Host Token 过期后，无有效 Host Token 且无工作需要运行时释放服务资源，重新登录通过就绪接口恢复原数据。
- Token 过期时已有后台工作继续，最后一项结束后重新检查回收；同用户仍有有效 Host Token 时保留；任一端主动退出则统一使该用户全部 Host Token 失效。登出/过期回收与初始化/新登录竞争时不重复开库、不复活失效请求。Host 停止时完整收尾，不发布晚到服务。
- 运行中再次登录后，主任务下一轮、Goal/child、标题和压缩调用均使用最新凭据，已发出的请求不被替换操作中断；任一端主动退出取消本人域全部工作，其他用户继续，关闭页面不取消任务。
- 两用户相同资源 ID/同名 MCP/Skill、全路由参数替换、递归路径及符号链接：结果只来自本人域。
- 既有 Cookie 大文件下载与上传撤销、WS 首帧、源 Session 删除后的 PTY 清理：用户归属和登录校验一致，已有资源保护不因多用户装配失效。
- 初始化失败及 Host 关闭失败：资源继续受监督，不重复打开同用户 Store；沿用既有关闭期限与错误报告。
- 同一组 Gateway/Speech/浏览器、会话、MCP/Skill、C02 恢复及可靠投影用例在两种用户装配下运行；差别来自用户数据和真实资源，不能来自额外企业禁用分支。明确的模型管理/选择限制从绕过 UI 的调用也要生效。
