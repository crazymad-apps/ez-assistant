## 二、台账原则与范围

里程碑按“配置基础 → 身份 → 用户运行 → 全入口隔离 → 客户端 → 循环验收”顺序推进，每个里程碑都包含必要的实现和验证。确认本计划后只进入 M0；每个里程碑完成后标记待确认并汇报，取得用户确认后才进入下一里程碑。

计划只记录交付结果、顺序与完成门禁，接口、目录、状态和异常规则以已确认方案为准。实施发现必须改变方案时先收口设计，不以实现便利扩展范围。

本循环保留的范围约束：

- 一个 Host、多用户独立 Runtime；同用户多端共享当前企业凭据，业务主干共用，仅保留已明确的模型管理/选择差异。
- 独立阻塞就绪接口；登录不等待初始化，不做空闲回收；主动退出中断本人在本 Host 的所有任务并回收，客户端 Token 到期不取消已接纳工作。
- 保留既有资源保护，不增加用户域数量、任务、模型、MCP、连接等配额或通用限流机制。
- C03 提供真实企业身份和数据/工具隔离。中心模型尚未启用时返回现有配置未就绪结果；隔离测试可注入确定性模型，产品不提供测试旁路。
- C04 实现模型配置获取/刷新、真实代理和拒绝处理；本计划不实现附件 B 第 2.3 节的代理闭环。C06 接入正式发包入口和完整平台制品验证；C03 先完成构建默认中心地址及配置初始化规则。

所有数据库/升级验证使用项目 `.runtime-test/` 下新建的独立 Runtime Home、历史布局夹具和已核实的隔离中心数据库，遵守根 AGENTS.md 的目标核对、备份及结果验证规则；不把测试指向用户 `~/.ez-assistant` 或既有共享开发库。保留工作树其他改动，不自动暂存、提交、推送或发布。

### M0 Host 配置与个人数据升级

- **目标**：建立后续多用户接入所需的配置和存储基础，升级后个人模式能沿用原数据。
- **前置**：计划确认；核对启动、实际存储路径及已有升级入口，按附件 C 使用隔离夹具。
- **交付范围**：拆分 Host/用户配置；实现 `host.toml` 版本分派、旧个人域迁入 `_personal`、配套文件和结构化路径重定位、失败后重新进入及整套恢复。内置构建默认中心地址，创建企业配置时显式地址优先并持久保存，升级保留已有地址/身份及运行模式。适配 Client 的在线/离线 Host 配置读取，避免管理入口跳过升级。同步方案要求的 Runtime 套件版本、应用兼容及数据库最低 Host 版本，Center 版本独立。
- **验证入口**：Host 启动/存储定向测试；空 Home、v0.26.0 标准与自定义 Home、外部工作目录和个人 Skill/MCP 数据；关键写入中断、目标冲突、损坏配置/库及恢复。核对实际数据库、文件与配置读取结果；验证无运行时环境变量也能采用编入地址，改用另一默认地址的制品不覆盖已有配置。
- **完成判定与 Review**：覆盖 C03-A11/A12/A13 的布局与配置部分；重复启动不重复迁移，不覆盖或误建替代库，个人业务可继续访问原数据。默认地址只由 Host 提供，升级不变成模式切换；Windows/Linux 真实升级矩阵明确交给 C06，不以本机结果代替。

**实施结论（2026-09-20，用户已确认）**：已完成 Host/个人配置分离、旧布局迁入 `_personal`、独立备份与中断重入、结构化路径及历史资源兼容、个人 Skill 优先级、停服管理入口和构建默认中心地址；Runtime 套件及兼容下限已对齐 0.27.0。个人业务、迁移失败边界、备份回读、换包保留中心地址及受影响 Rust/Desktop/Client 回归通过，原生应用构建通过。仅使用隔离 Home；企业模式暂不装配业务，M1/M2 接续登录和用户 Runtime。真实旧发布程序、Windows/Linux 安装升级及完整分发制品验证仍交 C06，真实外部模型用例未执行。未提交、推送或发布。

### M1 企业身份与凭据契约

- **目标**：Host 接通真实 Center 身份，并建立用户统一登录状态。
- **前置**：M0 确认；核实独立 Center 验证环境。按本节显式重开 C01 密码契约，不重写其原归档。
- **交付范围**：实现中心协议/稳定身份核验、每用户最新 Center Token/key、共用 Host Cookie/Bearer、本人查询/改密/退出和本机管理边界。保持普通 Host Token 期限及 Center 无 TTL，登录与 Runtime 初始化分开；落地附件 A 的核验、失效、暂不可达和迟到结果规则。扩展应用协议并通过既有生成器更新 TS 投影及消费者。
- **C01 定向重开**：本人改密和管理员重置成功后保留已有 Token/key；同步 API 说明、OpenAPI/Admin 生成契约和成功反馈。密码校验、事务/审计、账号停用、角色变更、当前 Token logout 及提交结果不明时的处理保持原规则；不修改用户表或初始化 SQL。
- **验证入口**：Center 真实隔离身份用例及 Host 可控身份端点测试；覆盖多 Token、密码前后登录、改密并发、管理员重置自己/他人、停用/角色撤销、中心重启、超时及乱序。确认旧响应不清除新凭据，失败登录不覆盖有效状态，bootstrap 不能代替企业用户身份。
- **完成判定与 Review**：C03-A01/A05 的身份部分、A06 的中心侧、A13/A14 的身份边界成立；用户身份仅由服务端校验结果决定，中心凭据不交给客户端。尚未完成用户路由的业务入口不能落到个人或他人 Runtime；任务连续性在 M2、正式客户端在 M4 补齐。

**实施结论（2026-09-20，用户已确认）**：已接通 Center 协议核验、中心 UUID 绑定、每用户最新凭据及共用 Host 登录表；本人查询、改密、统一退出、快捷 Cookie 兑换与 bootstrap 管理边界已实现。中心及管理后台两种改密成功均保留已有凭据，密码快照竞态、审计失败、启停/角色撤销及重启规则完成定向复验。可控 Center 的超时、旧响应、并发核验、到期和退出交错，以及真实 Center/Host 联调通过；受影响 Rust 回归和 Desktop/Client/Admin 静态检查、构建与测试通过。匿名 capabilities 的旧断言已按登录发现契约修正并复测。真实浏览器核对改密提示，并验证 API 改密/重置后已有 Cookie 可恢复后台；未通过浏览器提交密码表单。仅使用新建隔离库和临时 Home。用户 Runtime、阻塞就绪和任务取消/回收归 M2，正式客户端登录及确认交互归 M4；本阶段企业业务入口保持不可用，未接入个人业务域。未提交、推送或发布。

### M2 用户 Runtime 与任务生命周期

- **目标**：让已认证用户获得唯一、本人的 Runtime，正确处理后台任务和登录生命周期。
- **前置**：M1 确认；复用现有 Runtime、Store、Supervisor 及模型工厂边界。
- **交付范围**：按用户装配配置/Store/Runtime 和配套服务，提供独立阻塞就绪接口及共用服务获取流程；先接通命令、快照和事件的用户路由。实现初始化互斥、失败收尾、Host 停止、统一退出取消，以及 Token 到期后的按条件回收。模型工厂与任务不保存逐登录授权链，当前凭据由 Host 持有；中心模型未就绪仍走共用配置错误。
- **验证入口**：多用户真实 Host 集成与确定性模型用例；同用户并发首次进入、初始化失败重试、就绪等待中断连/退出、重复登录更新凭据、关闭与重新登录交错。覆盖任务运行中客户端 Token 到期、改密/重置后继续、任一端退出取消本人全部工作、工作结束后回收及再登录恢复。
- **完成判定与 Review**：覆盖 C03-A01/A02/A05/A06/A07/A15/A16 的运行部分；只产生一个同用户 Store/Runtime，其他用户不被取消。无空闲回收、任务登录映射、额外配额或 Host 第二份 Run 状态；已接纳工作不绑定页面和客户端 Token 期限。

**实施结论（2026-09-20，用户已确认）**：个人与企业用户复用同一 Store/Runtime 及配套服务装配；独立阻塞就绪接口、命令/快照/事件用户路由、同用户初始化互斥和失败重试已实现。主动退出取消本人全部工作并等待收尾，其他用户继续；客户端 Token 到期保留已接纳工作及中心复核，工作结束后按登录状态回收，没有空闲回收或新增配额。初始化断连、退出/重登交错、中心暂不可达与恢复、确定性任务连续性及真实 Host 多用户进程联调通过；相关 Rust 测试和 workspace 静态门禁通过。验证只使用临时 Home/SQLite 和可控中心端点，未操作用户目录或共享中心库。M3 补齐文件、终端及工具资源全入口隔离，M4 实现正式登录与确认交互；真实中心模型调用和各平台分发分别归 C04/C06。未提交、推送或发布。

### M3 全入口与工具资源隔离

- **完成判定与 Review**：C03-A03/A08/A09/A10/A14 及 A15 资源部分成立，未发现用户路由旁路。既有 Host 资源限制不因逐用户装配被放大，不新增限流；不把工作目录称为强沙盒，不将隔离困难改为整类企业功能禁用。
