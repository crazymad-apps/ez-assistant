## 三、目标架构与权威所有者

```text
Desktop / Host Web
  ├─ 本机管理入口：真实 loopback + bootstrap
  └─ 用户业务入口：Host 普通 Token → 用户身份 → Host 当前用户状态与服务
                            │
单个 Runtime Host / 单个业务 HTTP 监听 / 一个 Tokio Runtime
  ├─ Host 配置、网络准入、普通登录表、按用户的当前企业凭据、Center HTTP client
  ├─ 已初始化用户缓存：UserDomainKey → UserServices（按用户异步锁初始化）
  │   ├─ _personal ────────────┐
  │   └─ (center_id, user.id) ─┴→ 同一用户服务装配：Runtime / Store / MCP / 设备能力
  ├─ PTY Supervisor、HTTP 连接监督及既有传输保护
  └─ host.toml 与启动前版本升级
```

- `UserDomainKey` 是 Host 私有枚举：`Personal` 或已验证的 `Enterprise { center_id, user_id }`。不进入 Core，不作为客户端可选择的路由参数。
- 每个已加载用户恰有一个 `Arc<AssistantRuntime>`、一份 Store worker 和一组 MCP 资源；同用户多端复用它们。不同用户不复用权限、配置、事件广播或模型凭据。
- Host 缓存只拥有已初始化服务及生命周期句柄，没有初始化状态枚举或 Session/Run 列表副本；不按空闲时间回收，在登出、登录到期和工作结束时依据既有登录及活动事实回收不再使用的服务。
- Center 继续拥有身份和 Token/key 有效性；Host 为每个用户只保留最近一次成功登录的已验证状态，不保存企业密码、不签发新的中心身份。
- `assistant-runtime` 继续使用既有模型接口和取消/关闭机制，不识别 Center UUID、登录来源、HTTP 或 Token 文本。
- 文件保护、MCP 子进程、SQLite、Host HTTP 均由 Host Adapter 承载；依赖方向不变。

### 3.1 登录后共用业务逻辑

用户明确要求：登录后不在业务逻辑中铺开个人/企业判断，只有明确提出的产品差异保留。身份验证和首次装配得到固定用户句柄后，会话、Run、队列、Goal、child、记忆、Workspace、文件、MCP、Skill、审批、事件、上传下载和客户端业务投影均走同一套实现。

| 差异或事实 | 收敛位置 | 下游共用方式 |
| --- | --- | --- |
| 本地认证 / Center 认证、账号操作、后端凭据复核 | Host `access`、登录与本人账号入口 | 业务 handler 只取得已验证用户句柄，不自行请求 `/me` 或判断模式 |
| `_personal` / 企业目录、旧个人 Skill 来源与升级路径 | 启动/用户域装配/迁移 Adapter | 注入 Store、配置源和有序扫描根；业务服务不重新计算模式目录 |
| 模型管理、默认模型及会话模型选择 | 已明确的模型配置来源与管理入口 | 模型设置投影表达可编辑项，服务端在模型管理边界校验；会话执行统一消费准备好的模型规格和既有模型工厂 |
| 当前用户凭据与退出 | Host 按用户维护最新状态，模型 Adapter 发送时读取 | Runtime 继续调用同一模型接口；退出按本人 Runtime 收尾，不传任务级授权对象 |
| 资源归属、本机管理资格、设备/平台可用性 | 各自既有权限及 Adapter 边界 | 根据真实资源所有者、bootstrap 和可用资源处理，两种模式共用检查；不是企业产品限制 |

除明确的模型管理/选择规则外，不新增登录后普通业务的模式开关。不得把分散的 `isEnterprise` 换名成一组只与模式同值的 `canUseXxx` 来保留两套流程，也不为此建立通用策略引擎或双份业务服务。中心复核仍会在认证入口执行，不能误解为登录一次后不再验证授权。

此前草案提出的“企业统一禁用 Gateway、语音、资源浏览器”撤回；这些能力按同一用户归属规则适配。发现具体资源无法隔离时须收口该资源的实现边界，不能自行扩展为整类企业功能禁用。C03 尚无中心模型的阶段状态由配置源未就绪表达，C04 接入后业务主流程无需移除模式判断。

### 3.2 不采用的方案

| 方案 | 不采用原因 |
| --- | --- |
| 一个全局 Runtime，所有表和事件加 user_id | 需要改写几乎全部存储、缓存、查询与工具状态，而实例本来已有完整所有权边界 |
| 每个用户起一个 Host 进程/端口 | 改变已确认进程拓扑，增加端口、发现、关闭和资源控制复杂度 |
| 给 Host 加一份 Run 注册表来取消任务 | 与 Runtime 权威重复；用户退出直接使用本人 Runtime 的既有取消/关闭能力 |
| 全局“当前用户”或异步 task-local | 不同用户必须各有一份当前状态；通过用户装配选择，不能共用一个 Host 全局用户或依赖 HTTP task-local |
| JWT、刷新 Token、独立用户库目录账本 | Center 身份及现有 Host 登录表已足够；增加凭据或持久化生命周期没有必要 |

## 四、关键业务流

### 4.1 启动与登录

沿用实例锁 → 按 host.toml 版本完成布局升级 → 装配 Host 配置及监听 → 发布模式/登录能力 → 个人模式打开 `_personal`，企业模式等待登录后按需打开对应用户域。

企业登录为 Center 协议准入 → Center 登录 → 核对 center_id → 更新该用户唯一当前凭据 → 签发 Host Token/Cookie 并返回登录成功，不等待用户域初始化。

个人与企业客户端在登录成功或恢复已有登录后，独立调用 `POST /runtime/ensure-ready`。接口等待本人用户域装配完成，已就绪则直接返回 204；前端在等待期间显示 loading，失败显示具体错误并允许重试，不撤销有效登录、不回退其他库或新建空库兜底。用户域回收后再次登录也复用该接口，不做空闲回收。

### 4.2 用户请求

网络来源准入 → 统一认证入口校验 Host Token 及对应用户当前状态 → 等待取得已就绪用户域 → 共用资源归属与能力检查 → 调用该 Runtime/Adapter → 返回同域投影。Center 有效性复核封装在对应认证来源中，不在每个业务 handler 复制企业判断。业务入口与就绪接口复用同一服务获取函数，普通业务不处理初始化中间状态；登录、身份查询、改密及退出不依赖用户域装配。

长连接持有固定用户域及客户端访问凭据，不能每条消息读取一个可变“当前用户”。事件重连从该域权威快照恢复；其他域事件永不进入本流。

### 4.3 执行与登出

任务属于用户 Runtime，不绑定发起端或某次登录。新登录只更新 Host 当前用户凭据，既有工作继续；主调用、下一轮、子任务和辅助生成在发请求时读取最新值，不传递或持久化凭据。已发出的请求使用发送时的凭据完成，不因替换而重放。

任一端主动退出前，先明确提示会中断当前账号在当前 Host 的所有任务、使该账号其他端退出，由用户确认；取消不改变状态，更换账号通过退出后重新登录完成，不设单独菜单项。确认后结束该用户统一状态：所有相关 Host Token 失效，Runtime 停止准入并收尾该用户全部工作，关闭服务、释放资源，磁盘数据保留。其他用户和其他 Host 不受影响。退出、初始化和回收通过既有用户操作边界协调，不增加逐任务登录映射。

Host Token 自然过期只结束对应客户端访问，不清除仍被其他有效 Host Token 或后台工作使用的当前企业状态，不取消已接纳任务；最后一个 Host Token 到期且工作全部结束后检查回收。长时间无操作本身不触发回收。两种模式共用 Host Token 既有有效期，不增加企业专用永久凭据。

Center Token 和临时 LLM key 本身不设 TTL，不按时间自然过期；后者随关联 Token 撤销，中心进程结束也会使二者失效。该现状与 Host Token 有期限并不矛盾，不能把两层凭据的到期规则混用。

密码变更保留已存在 Token/key，没有新的取消事件。Center 暂不可达与明确 Token 无效分开处理，详见附件 A；不自动重放业务写入或模型输出。

## 六、配置、兼容与 C04 交接

- 布局版本使用用户明确要求的 `host.toml: version = "0.27.0"`；缺失文件进入 v0.27.0 升级。数据库账本及最低兼容 Host 独立维护。
- 企业发行包默认中心地址由构建变量 `EZ_ASSISTANT_DEFAULT_CENTER_URL` 提供，编入 Host；只在创建企业配置时作为默认值，不覆盖已有 host.toml。C03 交付默认值读取与初始化规则，C06 确保 Desktop/Client 各平台包实际携带对应 Host；仅在复制预构建 Host 的装包步骤设置变量不足以生效，详见附件 C 第 1.4 节。
- 本次登录 DTO、用户身份与权限语义属于应用协议变化；实施时 Runtime 套件当前版本/最低应用兼容版本统一为 `0.27.0`，通过现有版本源与生成流程更新，不在本轮改版本文件。
- Center C01 制品尚未发布。本版内直接统一密码操作语义，不保留旧撤销模式开关。复用 `/api/info` 的企业协议范围检查，Center 软件版本不与 Runtime 比较相等；不为未发布的 C01 中间实现再发明兼容代际。
- C03 必须真正接入企业登录、数据和工具配置；中心模型来源在 C04 前尚未就绪，统一模型准备入口复用 `configuration_unavailable`，由配置状态说明“中心模型能力尚未启用”，不增加 `enterprise_model_unavailable`，不接入个人 Provider。离线隔离测试可装配确定性工厂，产品不提供测试开关。
- 向 C04 交付的是 Host 每用户当前凭据及发送请求时读取该值的模型 Adapter 边界。“最新凭据”不等于“最新模型配置”；真实配置获取、代理、中心控制错误识别及刷新后的模型准备由 C04 实现。附件 B 第 2.3 节补充变更发现与拒绝处理草案：默认模型变化触发拒绝后刷新，当前调用失败并提示显式重试；同模型固定参数在下次获取配置后生效，上游 endpoint/key 由中心读取最新值。模型配置拒绝不触发用户退出，不自动重放 Run/工具。PreparedModel/Provider opaque state 的后续变化仍在 C04 收口，C03 不创建占位 Provider 行或伪造默认模型。
- Gateway、语音、资源浏览器与 MCP 统一按用户域/连接上下文取得资源；权限和资源不可用走既有错误，不增加企业禁用清单。原有个人配对/浏览器数据保持个人归属。

## 七、验证设计

验证以 [C03-A01—A16](功能设计.md) 为产品结果，以附件中的竞态、失败恢复与所有权为技术不变量。后续开发计划按实现边界安排，当前不设置已获批里程碑。

1. 身份：使用真实隔离 Center 验证登录/改密/重置/撤销；Host 单测用可控身份端点模拟 401、超时、乱序和取消。不会向已有开发库批量写数据。
2. 多域：登录与阻塞就绪分开；两个稳定用户、同用户多登录并发首次进入，验证只打开一个 worker、无事件/资源串域、A 故障时 B 可用、空闲不回收、登出/Token 过期后的按条件回收及再登录恢复、Host 关闭无泄漏。
3. 执行：确定性模型+屏障覆盖同用户新登录后的下一轮请求、Goal/child/controller 和辅助调用使用最新凭据，旧凭据晚到结果不覆盖当前状态，用户统一退出及改密后继续调用；已发出的请求不因凭据替换被中断。
4. 升级：使用 v0.26.0 格式夹具和临时 Home，逐个写边界注入中断；核验数据库、JSONL、附件、Skill、MCP、外部路径、重复启动和整套恢复。无用户目录读写。
5. 客户端：不同浏览器配置的企业用户并发、同源标签页共享账号、已登录快捷打开、刷新、晚到响应、大文件下载及 PTY；退出先明确影响，取消无副作用、确认才执行；两模式 Host Token 过期不取消已接纳任务，个人 Cookie 与本机管理回归；正式 CSP 下验证。
6. 静态与构建：按修改包运行 Rust fmt/定向测试/严格 Clippy；Protocol 生成一致性、Desktop/Client/Center/Admin 的类型检查、核心测试和构建。跨平台真实 PTY、文件原子性与安装包组合留 C06，不用本机通过代替 Windows/Linux 证据。
7. 共用路径：同一组业务用例分别注入个人和企业用户句柄运行，除明确模型管理/选择差异外结果一致；审查业务模块无散落模式判断，也无按模式换名的能力开关。鉴权、用户归属及取消校验不能因共用而减少。

本轮仅执行源码/依赖只读核查和文档链接、状态一致性、差异检查；未声称任何拟议 API 已编译、隔离或迁移测试已通过。

## 八、已确认取舍与后续边界

- 一用户一 Runtime 装配，按需加载；只取消按无操作时长触发的空闲回收；主动登出或 Token 过期后，无有效登录及工作使用时仍回收用户服务。独立阻塞接口负责等待就绪，登录不与初始化绑定，不新增用户进程。
- 用户已明确：登录后共用业务逻辑，差异集中在身份/资源装配和明确的模型管理、默认模型选择等边界，不自行添加企业功能限制。
- 用户已确认：企业与个人 Web 共用 Host HttpOnly Cookie，同源标签页共享账号；Center Token/key 只留 Host 内存。Host Token 沿用既有有效期，与 Host 当前企业状态及后台任务生命周期分开。
- 用户已明确：同用户各端只维护 Host 的统一状态，新登录更新当前凭据；任务不绑定登录来源。任一端主动退出结束该用户在本 Host 的统一状态，其他用户与其他 Host 不受影响。
- 将 C01 两种密码操作定向重开纳入后续实施，均保留已有 Token/key；保持 Center 停用/角色变更/当前 Token 退出规则；Host 端按用户统一退出。
- 用户已明确：本版不提前引入尚未评估清楚的并发限流；撤回草案新增的 Host/用户配额、额度对象及相关满额行为，只沿用既有资源保护。授权复核及网络超时按附件 A 实施，不作为新增业务限流的依据。
- Host 布局按版本自动升级；对已发布历史中的路径只保留附件 C 指定的窄兼容，避免改写对话或建立完整虚拟文件系统。

技术方案、[开发计划](开发计划.md)及 M0/M1 已获确认；M2 已获用户确认；M3/M4 已获用户确认，M5 集成验收已获用户确认，C03 待提交。C01 原归档事实保留，两种密码操作的定向重开和复验已在计划 M1 完成，不重写历史验收结论。
