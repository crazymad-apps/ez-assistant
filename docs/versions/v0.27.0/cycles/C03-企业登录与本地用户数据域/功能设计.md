## 二、背景、目标与现状

当前 Host 面向一个所有者：进程启动后装配一份 Runtime、配置和 Store，多客户端访问同一份业务状态。仅在数据库路径后增加用户名，无法隔离内存中的会话、事件、工具连接和上传下载。

本循环形成的用户结果：

1. 企业用户从 Desktop/Web 登录同一 Host，首次登录后通过就绪接口建立自己的本地数据域，以后登录恢复本人数据。
2. 多个用户可以同时在线和执行任务；同一用户多端共享本人状态，不同用户互不覆盖。
3. 配置、MCP、Skill 状态、工作目录、会话、记忆及配套文件具有一致的用户归属。
4. 个人模式数据完整保留，升级只调整布局，切换模式不触发搬迁或数据归属变化。
5. 企业用户可在 Runtime 查看本人身份、改密和退出，无需进入中心管理后台。

## 四、功能范围与使用路径

### 4.1 Host、用户与登录态

一个 Runtime Home 对应一个 Host 进程和一个 HTTP/HTTPS 监听。Host 在个人、企业两种模式中选一种运行；企业模式连接一个中心，允许多个用户同时登录。

各范围必须分清：

| 范围 | 所有内容 | 生命周期 |
| --- | --- | --- |
| Host | 监听、网络访问、运行模式、中心地址与身份绑定、实例锁、发现信息 | 随 Host 配置与进程 |
| 用户域 | 数据库、会话、配置、MCP、工作目录、记忆、Skill 启停 | 随稳定用户身份；退出不删除 |
| 客户端 Host 登录 | Host Token、Cookie/Bearer 访问及所属客户端连接 | 沿用 Host 登录期限；自然过期不撤销后端凭据 |
| Host 当前用户状态 | 每个用户唯一一份已验证身份、当前 Center Token 及 LLM key；Desktop/Web 共用 | 同用户新登录覆盖当前值；主动退出结束本 Host 该用户状态，与单个 Host Token 到期分开 |

同一用户多次登录汇入同一个用户域及 Host 当前登录状态，不按 Desktop/Web 或登录次数区分执行身份。MCP 连接和 Runtime 按用户共享；最近一次成功登录更新该用户当前企业凭据，所有任务后续调用统一使用最新值。不同用户的状态分别维护，不互相覆盖。

客户端访问 Host 使用 Host 签发的普通 Token；Host 访问企业后端使用 Center 签发的 Token，模型代理另用该次登录的 LLM key。两层凭据不能混用或共用生命周期。企业 Web 与个人 Web 共用 Host 登录机制，Center Token/key 不交给浏览器；Host Token 自然过期结束对应客户端访问，不因此撤销后端凭据或中断已接纳任务。

Center Token 和关联临时 LLM key 均不设 TTL，不会按时间自然过期，也不需要续期；“临时”指只在中心进程内存中保存、受撤销和进程生命周期约束。显式撤销、账号停用/角色变更、Center 关闭或重启及异常凭据清理仍会使其失效。现有代码的本人改密和管理员重置也会撤销凭据，前述保留方案尚待实施；不能把“不自然过期”理解为已经取消这些撤销路径。

不为用户或会话另启 Runtime Host 子进程。采用进程内多个 Runtime 装配还是 Runtime 内分区，由技术方案基于现有代码确定，不提前新增通用租户框架。

### 4.2 目录与归属

目标布局如下；`host.toml` 保存 Host 配置及已完成升级的版本号，作为 Host 布局升级的判断依据。用户域内继续复用现有文件布局。

```text
<Runtime Home>/                       # 默认 ~/.ez-assistant
├── host.toml                         # Host 级配置与 version
├── run/                              # 单实例、发现与进程信息
├── skills/                           # Host 公共 Skill 补充来源
└── users/
    ├── _personal/                    # 特殊个人域，与企业用户域同级
    │   ├── config.toml
    │   ├── mcp.json
    │   ├── mcp/                      # MCP 默认工作目录
    │   ├── skills/
    │   ├── recall-reference.key
    │   └── data/
    │       ├── runtime.sqlite3
    │       ├── sessions/
    │       ├── workspaces/
    │       ├── blobs/
    │       └── staging/
    └── <center_id 与 user.id 确定的目录>/
        └── 与 _personal 相同的用户布局
```

约束：

- 目录键由可信 Center 返回的 `center_id` 和 `user.id` 确定，编码合法且无碰撞。用户名、昵称、中心 URL、Token 都不作为数据身份。
- Host 固定已配置中心的稳定身份；相同 URL 返回不同 `center_id` 时拒绝自动切换，交由本机管理入口显式处理。中心地址变化但身份不变不应新建用户域。
- 不新增本地用户注册表来复制中心用户资料；界面身份来自已验证的中心响应，路径直接由稳定身份派生。
- `config.toml` 中模型、工具、权限及用户偏好按用户归属；监听、接入密码、TLS、中心地址等 Host 配置只保存一份。企业模型来源受 C04 管理，不因用户拥有配置文件而放开本地模型覆盖。
- 企业发行包通过构建环境变量内置默认 `center_url`，创建企业配置时无显式地址便采用该值并保存到 `host.toml`；安装后无需设置环境变量。已有配置优先，升级不覆盖地址或中心身份，不因包内默认值自动切换个人/企业模式；具体见[附件 C 第 1.4 节](技术方案附件C-配置与版本升级.md#14-发包时内置默认中心地址)。
- Recall 签名密钥、用户权限文件、浏览器专用配置、日志中含业务内容的部分等配套资源，同样归用户域；树未列出的文件必须在技术方案中逐项核查，不能默认保留全局。
- 首次打开用户域只初始化产品所需默认配置，不复制 `_personal` 的模型密钥、MCP、Skill、权限、记忆或会话。
- `--runtime-home` 及环境覆盖仍指向整个 Host 根；不通过给每个用户启动不同 Host 来实现隔离。

### 4.3 登录、并发和退出

首次路径：打开 Desktop/Web → 根据 Host 模式显示企业登录 → Host 向已配置 Center 验证账号密码及中心身份 → 返回登录成功与 Host 凭据 → 客户端独立调用阻塞就绪接口 → 打开或创建用户域，数据恢复完成后进入本人会话列表。

失败账号登录不创建用户库。登录只完成认证，不等待用户域初始化。个人与企业客户端在登录成功或恢复已有登录后，通过独立阻塞接口等待本人用户域就绪，前端显示 loading；已就绪则直接返回。同用户并发调用复用唯一 Runtime，不需要用户域状态轮询。用户域损坏、升级失败或资源不足时显示具体错误并允许重试，保留有效登录，仍可查看身份或退出；不能展示空的新账号或回退个人数据。

本人账号入口显示当前中心、账号及显示名称，提供改密和退出。本人改密要求原密码；已确认成功后只更新密码验证信息，旧密码不能再用于新登录，已有 Token 及其关联 LLM key 保持有效，各端不强制重新登录，已经运行的 Host 任务继续。Runtime 不提供中心用户管理或管理员重置密码入口。

用户主动选择“退出登录”时必须先显示确认框，明确影响的是当前账号在当前 Host 的所有任务和客户端，再由用户决定。建议文案：“退出登录将中断账号「{account}」在「{host}」上的所有运行中和排队任务，并使该账号在此 Host 的其他客户端退出。历史会话和文件会保留。”按钮为“取消”和“中断所有任务并退出”；默认焦点在取消，关闭确认框也视为取消。确认前不发送退出请求、不清除凭据、不停止任务；不依赖当前页面显示的任务数量来省略确认。

管理员重置密码采用相同的凭据保留规则，已随本轮设计确认；仍按 C01 校验管理员权限并记录独立审计，不要求原密码。这里的“保留”是已有登录继续正常有效，包括后续请求和模型调用，不是仅允许当前 HTTP 流结束，也不增加任务结束后自动撤销、宽限期或新旧 Token 两套状态。停用账号、角色权限变化及显式退出仍分别遵守自己的规则，不由修改密码隐式触发；本轮不改变这些 Center API 的撤销范围；Host 客户端统一退出范围按下表处理。

本稿提出以下生命周期规则：

| 动作或异常 | 行为 |
| --- | --- |
| 关闭页面、退出桌面客户端、网络断开 | 只结束客户端连接；已接纳任务仍归 Host，不等于登出 |
| Host Token 自然过期 | 客户端访问需重新登录；不撤销 Host 持有的 Center Token/key，已接纳任务继续使用 Host 当前企业状态并接受中心有效性复核。没有有效 Host Token 且没有工作需要运行时回收用户运行资源；仍有工作则在结束后重新检查 |
| 本人修改密码 | 保留全部既有 Token/key，其他 Host/客户端登录及任务继续；后续密码登录必须使用新密码 |
| 管理员重置密码 | 保留既有 Token/key，不把密码重置当作停用或强制退出 |
| 任一端显式退出用户 | 先告知所有任务中断及其他端退出的影响，用户确认后结束该用户在本 Host 的统一状态；所有相关 Host Token 失效，终止该用户连接和终端，本人域排队输入及活动任务受控取消，收尾后回收服务，保留磁盘数据。取消确认不改变状态；其他用户和其他 Host 不受影响 |
| 同用户再次登录 | 更新 Host 当前企业凭据，已有有效 Host Token 继续访问本人域；所有后续模型调用使用最新值，已发出的请求不因替换被中断，不追溯绑定发起端 |
| 中心撤销该用户全部凭据 | 该用户全部登录失效，相关任务受控收敛；数据保留，其他用户继续 |
| Center 重启 | 中心旧 Token/key 全部无效；重新登录恢复原用户域 |
| Host 重启 | 本机传输登录态重新建立；首版不把中心凭据写入本地库，用户重新登录；持久业务状态按现有恢复语义展示，登录后使用当前凭据，仍不自动重放旧执行 |
| 退出时 Center 不可达 | 本 Host 立即结束该用户统一状态并使各端失效；提示中心撤销未确认，不宣称中心 key 已成功撤销，不增加持久重试队列 |

关闭连接和显式撤销是不同原因，不能复用一个无条件取消全部用户任务的处理。已提交的文件、Shell 或 MCP 副作用不会因登出回滚；单个 Host Token 到期关闭对应 PTY，用户统一退出关闭该用户所有 PTY；资源归属始终按用户校验。

Center 没有撤销推送。本稿建议新受保护请求和新执行准入在线核验身份；活动长连接及执行也做有界周期复核，建议最大复核间隔 30 秒，单次核验超时上限由技术方案确定。不能只在登录时验证一次。明确无效时撤销本地授权；中心暂不可达时停止新的受保护操作，活动访问在复核期限与超时上限内收敛，界面区分“中心不可用”和“登录已失效”。可合并该用户当前 Token 的并发核验，旧凭据的晚到结果不能覆盖新状态，但不另建离线授权或续期体系。

### 4.4 Web/Desktop 多账号体验

- 不同浏览器、不同电脑及 Desktop/Web 可同时以不同用户使用同一 Host。
- 企业与个人 Web 统一使用 Host HttpOnly Cookie；同一浏览器配置、同一 Host 来源的标签页共享当前账号，不支持这些标签页同时登录不同账号。这是用户明确选择的简化行为，不影响 Host 接受不同浏览器、浏览器配置或设备上的多个用户并发。
- 刷新当前页面按共享 Cookie 重新核验 Host 身份；不在 sessionStorage/localStorage 保存企业专用 Token，Center Token/key 不交给浏览器。
- 需要更换账号时，先点击退出登录，不设单独的切换账号菜单项；按同一确认流程告知原账号任务中断及各端退出的影响，确认后退出原登录，再建立新身份；取消则保留原账号及任务。同源标签页共同清理旧用户的会话投影、草稿、搜索结果、附件预览及待处理异步响应，重新读取当前登录。切换失败停留登录页；旧页面在 Cookie 已切换后提交的操作必须拒绝，不能误作用于新账号。
- 同一用户所有端共用 Host 当前状态，无论快捷登录还是再次输入密码。任一端明确退出会使该用户在本 Host 的其他端失效并停止其任务；不同用户及其他 Host 不受影响。
- Desktop 本机 bootstrap 只证明 Host 管理能力，企业模式仍要登录企业账号；本机管理与企业业务权限分别判定，不能自动合并。
- “打开 Web”始终打开当前连接的 Host 提供的 Web 页面。当前客户端已经登录企业用户时，允许携带绑定该用户的 Host 普通登录 Token 完成快捷登录，直接进入同一用户的数据域，无需再次输入账号密码；只有尚未登录、凭据无效或仅持有本机管理 bootstrap 时，才进入企业登录页。
- 快捷登录复用现有 fragment 传递与 Host 验证/兑换 Cookie 入口，页面接收后立即移除 fragment；企业身份、所属中心和用户域由 Host 从有效登录上下文取得，不能由 URL 中的用户 ID 或本机管理凭据推导。成功后同源标签页共享兑换后的登录，按账号变化流程清理旧投影；不能把切换客户端连接目标前的凭据带到另一个 Host。

凭据存放、刷新恢复、WS 首帧及带身份的预览/下载统一复用 Host Web 机制；快捷入口携带的是绑定企业身份的 Host 普通凭据，不是本机管理 bootstrap、Center Token 或 LLM key。后三者不放入快捷 URL，LLM key 不发给浏览器页面，所有凭据不进入普通日志或 SSE。快捷登录只建立到同一用户域的客户端访问，不重新登录 Center；后端调用与所有其他端共用 Host 当前企业凭据，按用户统一退出。两种模式的 Cookie 登录与同源标签页共享行为一起验收。

### 4.5 MCP 完全归个人

每个用户有自己的 `mcp.json`、服务列表、启停状态、凭证、连接、进程和默认工作目录。修改、重连或删除 MCP 只影响当前用户；不同用户配置相同服务名称也互不覆盖。

不提供 Host 级 MCP 配置、不做配置继承，不共享不同用户的 MCP 连接或 stdio 子进程。已有系统程序及依赖可以自然复用，不为安装的同一可执行文件制造用户副本，但程序的数据目录和环境必须按用户核查。

凭证及服务返回内容不进入其他用户的列表、工具发现缓存、事件或日志。用户显式配置同一远程账户时，该外部账户的数据权限由远程服务决定；产品不承诺外部系统的独立身份。关闭页面或单个 Host Token 到期不关闭仍被该用户工作使用的 MCP；用户主动统一退出时，随 Runtime 收尾关闭本人 MCP，其他用户不受影响。

### 4.6 Skill 以个人为主，公共来源补充

个人 Skill 位于当前用户域的 `skills/`；公共 Skill 位于 `<Runtime Home>/skills/`，仅共享说明、脚本和静态资源。启停、发现投影、激活账本、调用上下文、输出及临时数据全部属于用户域，不建立另一套“全局 Skill 开关”。

优先级从高到低：

1. 当前 Session 冻结的有序工作区：保持根顺序优先，每个根内 `.ez-assistant/skills` 高于 `.agents/skills`。
2. 当前用户域 `skills/`。
3. `<Runtime Home>/skills/` 公共补充。
4. 仅个人模式继续兼容操作系统 Home 下的 `.agents/skills`，作为最后补充；企业用户不自动继承运行 Host 的操作系统账号的此目录。

同名 Skill 选最高优先级的有效候选；沿用现有按名称启停语义，禁用名称后不回退启用低优先级同名包。文件缺失、解析失败及来源不可读沿用现有诊断，不将不完整扫描伪装成完整列表。没有同名候选时，公共 Skill 可以被发现和使用。

Skill 设置页清楚展示来源及当前生效项，启停仅影响本人。公共目录通过本机文件维护，不新增包管理界面；普通用户通过产品的结构化文件入口不能修改公共包或他人私有 Skill。公共脚本输出应写入当前用户工作目录，不写回公共包目录；代码本身不支持这一约定时，由维护者调整后再共享。

现有操作系统 Home 下的 `.ez-assistant/skills` 与 Runtime Home 不一定相同：默认目录重合时旧 Skill 迁入 `_personal/skills`；自定义 Runtime Home 时不能顺手搬走外部目录，只在个人模式保留明确的旧个人来源，排在域内个人 Skill 之后、公共来源之前。企业模式不自动扫描该外部个人来源。具体根去重与现有 SkillSource 协议适配由技术方案收口。

### 4.7 全入口隔离与工作目录

| 入口或资源 | 隔离要求 |
| --- | --- |
| 会话列表、正文、Run、队列、主控会话、子任务、导出/导入及 Fork | 先选认证用户域，再查资源；不能用另一个用户的 ID 访问，也不能把用户 ID 放请求体中当作授权依据 |
| 记忆、Recall、历史搜索与引用 | 使用本人 Store、索引及引用密钥；引用跨域不可用 |
| 配置、工具权限、审批与 Skill/MCP 管理 | 只读写本人状态；同用户多端同步，不跨用户广播 |
| HTTP Command、SSE、上传、下载、预览、工具图片 | 认证、资源查找、暂存及返回流都绑定用户；不可只隔离列表 |
| 文件读取、写入、列目录、搜索及原生路径入口 | 阻止通过路径、符号链接、ID 替换读取他人托管数据或 Host 秘密；不能以宽泛工作区授权放开其他用户域 |
| WS/PTY | 握手及首帧认证绑定用户和登录；创建、输入、调整尺寸、重连、关闭均核验所有权 |
| 客户端缓存与异步响应 | 缓存按 Host/中心/用户分区；迟到响应、事件、Blob URL 不得进入后来登录的账号 |
| 调度、Goal、排队输入与后台触发 | 归属于本人 Runtime，后端调用读取 Host 当前用户凭据；当前状态无效时不能执行，也不能借其他用户凭据或回退旧值 |

默认工作目录放在本人域内。用户显式选择的外部工作目录保持原地址，不自动复制、搬迁或改名；两人选择同一个外部目录时，其底层文件会共享，界面不能称其为独立沙盒。产品托管的其他用户域和 Host 敏感目录不能伪装成普通外部工作区绕过检查。

原生浏览器 Profile、桌面录音/播放、Gateway 配对设备等按用户域及实际客户端/设备归属适配，复用现有功能逻辑。撤回此前草案建议的“企业模式统一禁用这些入口”；是否可用由资源是否属于本人、是否已配置/连接及既有权限决定。无法形成安全用户归属的具体实现须收口，不能自动扩大为整类企业功能限制，也不能将他人资源当作可用兜底。

Shell、PTY 和 MCP 子进程仍使用 Host 的操作系统权限；应用层检查不能阻止恶意外部程序直接读取同机文件。该边界沿用总体设计，不宣称为安全沙盒。

### 4.8 升级与模式切换

目录迁移是版本升级动作，不由首次企业登录、账号切换或模式切换隐式触发。升级既有数据必须保留原个人归属：原配置拆出 Host 项，个人项及 MCP、Skill、数据库、Journal、附件、工作目录和私有密钥一并归入 `_personal`。根公共 Skill 目录从明确的公共内容开始，不能把原个人 Skill 原地当作公共包。

2026-09-20 用户明确采用与数据库升级类似的版本分派，不设置人工识别布局、逐项确认后再迁移的产品流程。Host 启动沿用现有实例锁，在业务服务开放前读取 `host.toml` 的 `version`，自动选择对应升级程序。

| 检测结果 | 启动行为 |
| --- | --- |
| 不存在 `host.toml` | 按 v0.27.0 之前的布局进入 v0.27.0 升级程序；有旧数据则迁移，没有旧数据则直接初始化新布局 |
| `version` 低于当前要求的布局版本 | 按版本顺序执行尚未完成的升级程序 |
| `version` 已达到当前要求的布局版本 | 直接使用当前布局，不重复迁移 |
| 版本高于当前程序支持范围，或文件无法读取、解析、缺少合法版本 | 明确报错，不按旧版本重建，不覆盖已有文件 |

以本版本为例：缺少 `host.toml` → 执行 v0.27.0 升级程序 → 拆分 Host/个人配置并将原个人数据归入 `_personal` → 校验成功 → 原子写入含 `version = "0.27.0"` 的 `host.toml` → 开放业务服务。

`version` 表示已完成的 Host 配置/目录升级版本，不是每次启动都覆盖的软件版本，也不作为用户配置并发控制字段。后续有布局变化再增加相应版本升级程序，不另建布局版本表或长期双读双写。用户数据库仍沿用现有数据库迁移与兼容检查，不能以 `host.toml` 的版本代替每个用户库的实际版本。

备份、必要的数据与文件校验在升级程序内部完成，复用数据库升级已有机制，不增加人工前置流程。升级仅调整受托管根变化影响的资源定位；外部工作区路径保持原样，历史正文不全局字符串替换。数据库操作继续遵守根 AGENTS.md，跨文件步骤的中断处理由技术方案落实。

失败不推进版本、不开放半完成布局、不自动创建空库兜底。升级程序须能识别自己已完成的步骤，重启再次进入同一版本升级时不得覆盖已迁移数据；未知目标冲突明确报错，不能仅凭缺少 `host.toml` 就反复搬移。首版无需另建通用迁移任务系统。

升级后不支持直接换回不认识新布局的旧二进制；回退使用升级前的整套备份。不能声称 `host.toml` 能阻止 v0.26.0 旧程序写入，也不为其新增一套目录兼容层；C06 的安装、升级与恢复说明需明确这一边界。

模式或中心切换由本机 Host 管理者显式操作，首版通过受控停止/重启生效，展示对所有在线用户和任务的影响。原用户目录全部保留；切回个人模式继续使用 `_personal`；切换中心后同数值用户 ID 不得访问原中心数据。普通企业账号和中心管理员身份都不自动获得此操作权限。

### 4.9 生命周期、故障和 C04 边界

Host 启动不为所有历史用户提前打开数据库或启动 MCP；通过已认证的就绪接口或业务请求按需加载。只取消按无操作时长触发的空闲回收：登录仍有效时，断连或长时间无活动不触发回收；主动登出或 Host Token 过期后，没有有效 Host Token 且没有工作需要运行时，回收 Runtime 及配套服务、释放资源，保留磁盘数据。任一端主动登出统一结束该用户状态并取消本人域工作；Token 过期不取消已有工作，继续运行至结束后再检查回收条件。回收或 Host 重启后，下次通过就绪接口按需重新装配。沿用已有资源限制、错误处理和关闭机制，本版不增加用户域数量上限或跨用户业务限流。单用户数据故障不阻止其他已就绪用户服务，Host 级配置/监听故障仍影响整体。

C03 使用真实中心完成身份链路，但中心模型来源在 C04 前尚未就绪，模型设置显示“中心模型能力尚未启用”；会话、重试、标题、压缩等统一经过既有模型准备流程得到配置未就绪结果，不逐入口增加企业判断，也不读取 `_personal` 模型配置兜底。多用户执行隔离可在隔离测试环境装配确定性模型验证，不能把测试 Adapter 变成正式产品旁路。

C03 向 C04 交付已认证用户域、Host 每用户当前凭据、用户级取消及恢复边界；C04 再形成真实企业模型执行闭环。凭据更新与中心模型配置更新分开：后者如何发现、拒绝后刷新、失败提示及显式重试见[技术方案附件 B 第 2.3 节](技术方案附件B-用户Runtime与工具隔离.md#23-中心配置变化与请求被拒绝c04-交接草案)，作为已确认的 C04 交接方向，具体接口由该循环定稿；不能用“每次取最新 key”代替配置同步。C03 完成不等于企业版可对外发布。

## 五、模块边界与契约影响

| 模块 | 本循环职责 |
| --- | --- |
| Center | 复用 C01 登录、本人身份、改密、登出与稳定中心身份；密码变更的撤销规则需显式重开评审，不新增身份表、凭证类型或续期机制 |
| Runtime Host | 中心接入、按身份装配用户域、目录升级、传输认证与路由、用户资源生命周期及本机管理 |
| assistant-runtime | 保持会话/Run/队列/审批/配置等权威；提供满足用户装配及按用户取消/关闭所需的最小能力，不增加任务登录归属 |
| assistant-protocol 与 TS 投影 | 表达客户端需要的模式、身份、登录结果、独立阻塞就绪接口及错误；不增加用户初始化状态，不暴露私有路径或中心数据库实体 |
| Desktop/Web | 企业入口、本人账号操作、Host 用户状态与客户端访问上下文、用户投影清理、公共 Skill 来源与受限能力展示 |
| Client | 保持 Host 生命周期管理职责；适配 Host 配置与模式，不直接读写用户数据库，不扩展成账号管理客户端 |
| Agent Core/工具 SPI | 不引入企业账号或 Center 依赖；使用已经绑定用户环境和权限的现有能力 |

协议设计必须检查 Command、SSE、上传、下载、WS、启动诊断及生成类型的全部生产者与消费者。旧客户端不能凭个人 bootstrap 访问企业用户域；实际协议破坏时提升应用兼容下限。目录与数据库兼容分别处理，不能以提高客户端版本号代替存储准入。

## 六、关键取舍与最小新增检查

- 选择每用户数据库和文件域，避免在所有既有业务表与 JSONL 中重复加入用户字段；是否复用完整 Runtime 装配在技术方案核查。
- 用户身份直接使用中心既有稳定事实，不新增本地账号、密码、工作站注册或权限角色。
- MCP 完整归个人，取消全局/个人合并和共享连接的复杂度；Skill 只增加来源补充，不增加全局启停或安装账本。
- Host 与个人配置分开，因为监听和模式确实有独立所有权；普通用户配置文件不能修改 Host。
- 同用户后端登录状态由 Host 统一维护且只保留最新值；任务不绑定登录来源。客户端 Host Token 仍按既有规则保存和过期，不把客户端访问期限当作后端任务期限。
- 登录后复用同一业务主干；差异集中在认证、资源装配和明确的模型管理/选择边界。不以企业标签禁用其他功能，不通过改名能力开关掩盖重复业务分支。
- 登录与初始化解耦，独立阻塞就绪接口等待初始化，前端显示该请求的 loading/结果；服务端保留成功服务缓存和按用户的异步锁，不增加用户域四态模型。不做空闲回收，登出、登录到期及工作结束时按使用情况检查回收，并与初始化共用该锁。
- 迁移仅为已发布的 v0.26.0 个人数据提供升级路径，不为本版设计过程中的临时布局保留兼容分支。

“删除新增机制后现有事实是否足够”的核查结果：稳定用户身份、Skill 开关、Store、审批与执行状态已有事实，直接复用；缺少的是可信身份到用户域的选择、资源归属和 Host/用户配置边界。因此不新增用户业务目录数据库、共享资源平台或第二套 Run 生命周期。

## 七、验收标准

| 编号 | 场景与必须结果 |
| --- | --- |
| C03-A01 | 企业 Desktop/Web 完成登录、本人查询、改密和退出；登录独立成功，就绪接口在初始化期间阻塞且前端 loading，已就绪直接返回；初始化失败保留有效登录并可重试；普通用户无需后台；失败认证不创建用户域 |
| C03-A02 | A/B 同 Host 同时登录并使用；同用户多端及并发首次登录只形成唯一有效用户域，配置和任务不互相覆盖 |
