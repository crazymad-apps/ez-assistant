# v0.27.0 C06 技术方案：企业交付与独立发布

- 日期：2026-09-21；依据：[功能设计](功能设计.md)与[总体设计](../../总体设计.md)。
- 当前实施入口为用户指定的 Windows 远程打包；后续中心与其他平台交付在对应里程碑细化。

## Windows 构建路径

复用 `apps/desktop/scripts/release-windows.mjs`，依次调用既有 Tauri 构建、Host 编译与 sidecar 装配。默认生成 x64/arm64；远端需核对 Node/npm、Rust 两种 MSVC target、Visual Studio C++/Windows SDK 及 ARM64 Clang 工具。构建变量 `EZ_ASSISTANT_DEFAULT_CENTER_URL` 必须传入实际 Host 编译，不只传给装包步骤；地址待用户提供，不猜测远端可用服务地址。

源码来自当前工作树（包含未提交实现），以逐文件摘要清单和归档摘要固定输入；排除用户数据、凭据、依赖目录及构建产物。远端使用独立构建目录，先检查已有工具和磁盘空间，不覆盖既有源码或已发布制品。保留锁文件，安装前核对所需依赖及受支持工具版本。

复用 `verify-windows-release.ps1` 检查 MSI 版本、当前用户安装范围、两份 PE 架构、GUI 子系统、外部 VC++ 依赖及 Host 内嵌 Web；制品回传后再次核对 SHA-256。本步骤只读 MSI 容器，不安装软件、不改应用数据。构建后的安装/升级采用项目测试目录下独立 Runtime Home；涉及数据库遵守根安全规则。

## 后续交付

Center/Admin 沿用同源装配，外置模板与快照目录保持独立，升级不覆盖维护文件。其他 Runtime 平台复用现有发布脚本；Client 装包前先编译带正确默认地址的 Host。兼容核查区分应用协议、用户数据库、Host 布局与 Center 协议，不以软件版本相等替代判断。正式发布需在版本验收后另获授权。

## Desktop 安装更新后的本机交接

2026-09-22 用户要求解决新版 Desktop 遇到后台旧 Host 只能报不兼容的问题。纳入本次 macOS 候选修复：自动识别本安装来源的 0.26.0 Host，入口提供“更新并重启”，明确会中断该 Host 上的任务；用户操作后自动完成受控关闭、启动随包新版及既有备份迁移，不要求用户判断版本或手工处理进程、数据库。旧 Host 没有原子“仅空闲时关闭”契约，因此不静默中断任务。

普通连接和普通重启的兼容、来源规则保持。升级是独立的原生生命周期意图：只接受私有 discovery、loopback 认证且来源规范路径与当前随包 Host 相同的已发布 0.26.0 实例；候选可执行文件在停止前后核对摘要及当前构建版本对。不接管其他安装来源，不降级较新 Host，不向远端发送升级请求。

旧版交接仅支持已核实的 `shutdown_runtime` wire 契约：该窄请求仍声明真实 Desktop 软件版本，单独声明此命令支持的最低 Host 为 0.26.0，不降低业务请求的 0.27.0 下限、不读取旧业务快照。请求固定已认证实例的地址和凭据，等待原 PID 退出及实例锁释放；遇后继实例、拒绝、超时或来源变化即停止，不强杀、不向后继实例补发关闭。原生生命周期意图串行；数据备份、事务迁移和布局提交继续由新版 Host 执行，Desktop 不读写数据库。

验证覆盖真实版本声明、仅同来源旧实例可升级、取消/不点击无副作用、重复点击串行、停止失败/后继实例/来源变化保护、成功重启以及入口按钮与失败重试。macOS 实测与 Windows 尚未实测分别记录。

实际日常数据的整套备份核验会超过原生原有 60 秒等待。启动前 60 秒沿用普通预算；之后只有安全的实例锁仍被占用时继续等待，最多 15 分钟，页面说明首次更新可能需要几分钟。超时不终止 Host、不回滚迁移，后续重试重新发现。锁释放或无法安全核验则结束等待，避免因无进程而无意义延长。

## 2026-09-22：用户目录默认权限规则收敛

按用户反馈，将 C03 用户目录保护从独立 `UserPathPolicy` 收敛为 Host 注入的 `PermissionDocument`。
规则来源只返回规则数据；Runtime 在每次调用及审批返回后加载，与三层用户规则合并，统一执行
Deny > Ask > Allow。父子执行共享同一来源，默认规则不落盘、不进入设置列表。

既有文件 matcher 增加仅供内存注入的例外子树，以表达 Host 根拒绝范围中的本人目录及公共
Skill 只读例外；不扩展权限 JSON 或应用协议，禁止将带例外的默认文档保存成用户文件。
逻辑路径与物理目标均参与同一匹配器，待创建文件解析最近存在祖先。HTTP 文件入口与文件 I/O
复核复用相同默认规则和匹配器，递归搜索从规则提取排除范围后再遍历。公共 Skill 只读、兄弟
用户与 Host 私密资源保护语义保持；Shell/PTY/MCP 仍不是操作系统沙盒。

验证覆盖普通允许规则和自动模式不能覆盖默认拒绝、本人目录例外不授予额外 Allow、图片批量
路径、链接目标、审批等待期间规则变化，以及既有 HTTP/目录搜索保护。此次不操作日常数据库。

## 2026-09-22：企业中心单容器部署

用户授权将 Center/Admin 发布到 172.16.20.4，默认使用 HTTP，HTTPS 作为扩展选项。
复用现有同源装配，独立构建前后端后在 Docker 外安装生产依赖，镜像只复制完整制品。
默认同一 Node 24 进程在 7320 提供 `/admin/` 与 `/api/`，不增加前端服务器或第二个端口。
HTTP/HTTPS 均通过精确 public origin 校验，不再保留仅限 loopback 的 HTTP 放行开关。

应用容器以普通用户运行，使用服务器既有 PostgreSQL 16；应用使用独立库；本次用户指定沿用现有 postgres 账号，不创建新账号。
模型模板与调用快照通过独立目录持久化，发布不覆盖维护文件。Compose 默认只检查数据库版本，
数据库初始化/升级作为独立运维步骤，按数据库规则核对目标并确认。保留版本镜像与制品用于回退。

## 2026-09-22：系统提示词补充个人目录

Host 沿用既有 runtime_directories 段，从当前用户服务装配的 UserPaths 注入
user_data_directory 与 user_skills_directory 的真实绝对路径，并说明创建、安装技能优先使用
个人 skills/<skill-name>/SKILL.md。目录描述不是授权，文件操作继续走现有统一权限路径。
个人与企业模式共用组装；分叉重建目录段，委派子任务继承父会话系统提示词。
保持会话系统提示词冻结机制，不迁移或改写既有会话；更新 Host 后新建或分叉会话可获得新提示。
