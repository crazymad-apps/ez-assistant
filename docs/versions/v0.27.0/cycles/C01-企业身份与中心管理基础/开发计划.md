## 四、分里程碑实施与验证

### M0 服务与存储基础

- 目标：真实 Center 工程和存储准入可独立运行，不提前实现登录/用户业务。
- 交付：独立 Node 24/TypeScript/NestJS/Fastify 包、私有锁文件、后端模块约束和根映射；配置校验、错误脱敏；`db:check`/`db:upgrade`；node-pg-migrate、单账号与自动升级开关；四张表（未发布阶段已移除会话表）及首次超级管理员初始化；`GET /api/info`；关闭连接池的有界生命周期。
- 启动模式：开发期允许仅 API 启动，不能把空后台或原型打包为正式制品。正式静态资源检查和合并制品验证在 M3 完成。
- 用户追加接口交接：M0 接入 Swagger UI、在线 OpenAPI JSON 和无数据库离线导出/一致性检查；只公开已实现接口，由前端会话接入代码生成，不提前实现 M1/M2 API。
- 验证：类型/lint/构建、Fastify HTTP 注入测试；真实 PostgreSQL 16.14 空库初始化、按版本补齐升级 SQL、幂等、更高版本/断裂账本拒绝、失败整体回滚、数据库不可用不监听；验收时核对受影响表的精确数量与关键字段，不维护生产字段快照比对。同时覆盖自动升级开/关、单账号、初始化与升级失败不监听、并发/重复初始化不覆盖凭据。相关写入只在明确隔离库执行。
- 完成判定：实际服务能返回真实软件/协议信息，数据库准入失败可观测且不误写；升级事务、开关两种模式、超级管理员初始化幂等和关闭行为有证据。不以仅创建目录或返回固定健康成功作为完成。
- Review：对照 Host 升级职责而非照搬 SQLite；没有自动认领非空库、默认连接秘密、通用 Repository 或模型占位接口；按用户追加要求将首次超级管理员初始化纳入本轮 M0，不提前实现登录 API。M2 后续按用户确认采用 TypeORM，升级职责不变。

### M1 统一身份闭环

- 目标：同一套账号与内存 Token 支持后台/Runtime 统一 Bearer，用户自身身份路径可通过真实 API 验证。
- 交付：复用 M0 初始化与密码摘要格式，补齐密码验证及有界资源保护；登录、本人信息、当前退出与本人改密；Token/key 仅内存保存、用途隔离；全局 Bearer/权限/来源检查；身份成功/失败审计及提交后内存变更。
- 验证：默认初始账号可登录、改密后重启不重置；普通用户与管理员共用身份 API，管理权限单独校验；多次登录秘密不同、退出局部撤销、改密全量撤销、原密码错误不变更；中心重启后旧 Token/key 失效；审计失败回滚、密码计算拥塞和秘密排除。
- 完成判定：通过真实 PostgreSQL/API 的身份闭环；交付真实响应与错误夹具，不实现假的 Host 或 LLM 代理。
- Review：两种凭证不同用途、一个 Token 生命周期；不新增 JWT、TTL、刷新令牌、Redis 或第二份身份状态。只实现本人改密，管理重置留 M2。

### M2 用户管理与后端交接

- 目标：不依赖页面即可验证完整账号管理与审计能力。
- 交付：用户创建、检索/筛选/分页、编辑/启停/角色变更；管理员为任意用户（包括自己）重置密码；只读管理审计查询；契约导出、使用说明和可供前端/C03 消费的真实夹具。
- 验证：直接 API 越权、未知字段和超级管理员标记注入、账号唯一、最后管理员并发保护、两种改密操作区别；登录/停用、改密/登录、操作者降权等受控交错；事务/审计/提交异常及 SQL/日志秘密排除。执行适用的真实备份恢复对照，不用 pg_dump 命令成功替代恢复证据。
- 完成判定：功能设计 C01-A01—A10/A12/A13 的后端部分有逐项结果、后端接口可独立使用；前端相关项明确保留，不能标记 C01 完成。
- Review：没有 DELETE、通用权限引擎、配置 revision、模型代理或跨工程源码导入；临时 key 不可用作身份凭据，按已确认标记规则验证数据库赋予的第二个超级管理员。
