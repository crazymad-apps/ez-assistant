## 二、背景、最终用户结果与成功标准

当前桌面已具备会话、工作空间、MCP 和 Skill 使用能力，企业中心已具备身份与模型管理基础。
本版将已有能力组织成更清晰的工作台、可复用的 Agent 配置和统一交付的插件，减少用户手工配置及准备运行环境的负担。

| 目标 | 最终用户结果 | 成功标准 |
| --- | --- | --- |
| G1 工作台易用 | 左侧组织会话，左下角统一账号与 Runtime 入口；常用会话独立置顶 | 原工作空间归属不变，置顶不重复，账号与窗口操作始终可达 |
| G2 初始化清晰 | 新会话直接选择/清空工作空间、使用快捷入口、选择 Agent；工作空间可只使用私有目录 | 首次发送前选项明确，切换不静默丢草稿，创建不强制选择用户工作目录 |
| G3 Agent 可复用 | 保存完整提示词及默认 Skill/MCP；个人管理本地配置，企业使用中心配置 | 新会话按所选配置执行，既有会话不随配置编辑变化；不引入新执行引擎或权限体系 |
| G4 插件装完可用 | 个人上传包，企业从市场获取包；安装、配置与使用流程一致 | 包内具备所需运行环境，用户无需另装语言运行时或依赖库；专业软件缺失有明确指引 |
| G5 依赖自动准备 | 选择 Agent 后自动解析并安装缺失插件，展示准备结果 | 不依赖模型生成安装命令；名称引用在删除重传后仍可解析；失败不伪装就绪 |

既有 UI-001—UI-007、历史分页和 Workspace 多目录能力已在前序版本完成，作为回归基线保留，不重复计作新增能力。

## 三、总范围与明确非目标

### 3.1 纳入范围

| 领域 | 本版范围 |
| --- | --- |
| 桌面布局 | 移除现有顶部菜单栏，macOS 红绿灯融入侧栏顶部；用户信息与 Runtime 状态移至左下角；设置、修改密码、退出登录等在二级菜单平级展示 |
| 会话组织 | 固定会话统一称为置顶；在工作空间上方独立折叠分组；取消置顶回原分组并遵循原排序 |
| 新会话 | 工作空间选择/清空、Agent 选择、快捷入口、依赖状态；继续首条消息发送时物化会话 |
| 工作空间 | 先显示创建窗口，再按需选择目录；工作目录可为空，仅使用 Host 管理的私有目录 |
| 自定义 Agent | 名称、描述、完整长文本提示词及默认启用的 Skill/MCP；本地与企业中心两个配置来源；名称依赖与自动安装 |
| 插件 | 一个条目组合 MCP/Skill；管理员管理中心内容；按版本上传不同平台安装包，自动匹配目标 Host；个人上传包与企业下载包共用安装使用逻辑 |
| 插件生命周期 | 安装、配置、启停、中心更新、删除、来源识别和中心废弃标记；用户凭证与包内容分离 |
| 中心分发 | Agent 配置读取，市场发现，版本完整包查询、下载及下架状态查询；复用现有企业身份和管理员权限 |

### 3.2 非目标

- 统一配色、主题市场及主题导入。
- 以自定义 Agent 为由新增独立记忆、长期任务、会话生命周期、模型治理或 Agent 专属能力授权层。
- 普通用户发布中心插件、投稿审批、公开社区市场、付费交易、评级和推荐系统。
- 快捷入口管理后台或远程分发；本版使用客户端本机配置文件声明入口，企业版构建自动嵌入本机模板，通用版仍按需显式嵌入，允许模板、MCP、Skill、Agent 等装配方式。
- 插件安装后在用户机器运行 npm/pip 补装依赖；插件不能以环境准备未完成冒充安装成功。
- 引入另一套 MCP/Skill 执行机制、通用包依赖求解器、每个 Agent 独立安装副本或插件多版本并行运行。
- 由截图自动引入 Git 分支选择、工作树管理、执行位置切换或其他未提出的能力。
- 改变既有 Shell/MCP 的操作系统权限边界，或宣称私有目录是强沙盒。

## 四、产品边界、运行拓扑与权威状态

保持 Desktop/Web → Runtime Host → assistant-runtime → Agent 能力的现有拓扑。
企业中心提供身份、模型以及本版配置/插件分发；不运行用户 Agent，也不持有本地会话的第二份状态。

| 事实 | 权威归属 | 其他层职责 |
| --- | --- | --- |
| 中心 Agent 配置、插件名称/版本/当前完整包、上下架 | 企业中心；元数据由 PostgreSQL 管理，包文件由中心受保护存储管理 | Admin 发送管理意图；Host 读取和下载 |
| 本地 Agent 配置 | 当前 Host 的当前用户域，由 Runtime 管理 | Desktop/Web 编辑和展示；不只保存在 WebView |
| 安装插件、所装版本、取得来源及包文件 | 当前 Host 的当前用户域 | Runtime 编排安装业务，Host 执行文件、归档和网络操作；中心不回写本地安装事实 |
| 用户填写的密钥、路径与插件运行数据 | 当前 Host 的当前用户域；插件自行定义配置文件名、格式与结构，Host 管理目录隔离和生命周期 | 与包内容及独立 MCP 配置分开；包更新不得覆盖，不上传到中心配置或混入发布包 |
| MCP/Skill 启停、发现与调用 | 独立能力沿用既有开关；插件能力由当前用户的插件整体开关控制；发现与调用复用既有机制 | 管理入口分开，包内能力不可单独编辑、删除或启停，不复制运行状态机 |
| 会话所用 Agent 提示词与默认配置 | 现有会话持久化/冻结上下文 | 配置源后续编辑不改写；UI 读取投影 |
| 工作空间、会话归属、置顶业务事实 | 既有 Runtime/Store | 客户端改变展示位置，不创造另一份会话 |
| 未发送草稿、快捷入口和布局 | 客户端既有草稿/展示机制 | 发送意图通过正式应用协议，核心不感知快捷入口类型 |

用户从远程 Desktop/Web 上传包时，目标仍是所连接 Host 的当前用户域；不能安装到发起操作的桌面机器。
不同用户的凭证、配置、MCP 连接与运行数据继续隔离，不因安装相同插件而共享业务状态。

## 五、架构原则与最小新增约束

1. Agent 是配置，完整提示词作为一段长文本编辑和装配；不拆成角色、步骤、工具说明等必填字段。
2. 名称是 Agent 依赖和插件内容引用的依据，不使用上传记录的数据库 ID。安装来源信息只用于更新及废弃判定，不替代名称引用。
3. 插件是交付单元。内部仍为既有 Skill 目录和 MCP 服务声明，运行时沿用原有机制。
4. Core 不认识企业账号、插件市场或 Agent 配置来源。Runtime 在既有装配边界形成单一执行规格。
5. 同一用户安装的插件供多个 Agent 复用；保存必要的安装归属、版本、来源和整体启用事实；包内能力有效状态由其派生，不同时维护可独立修改的两级开关，不再保存一套工具目录。
6. 草稿不提前成为 Session，快捷入口不成为新的任务类型；私有目录工作空间不成为新的工作空间类型。
7. 安装失败不影响已有可用版本；中心刷新失败不等于中心下架，配置失败不静默切回另一来源。
8. 优先复用现有身份、OpenAPI、上传传输、模型来源接缝、工作空间编辑、草稿、工具配置与存储升级机制。

最小新增核查：仅靠现有 MCP/Skill 配置无法表达中心发布版本、完整包、安装归属和来源，也无法保存可复用的完整 Agent 配置，
这些是本版需要补齐的事实；现有会话、执行、权限、工具目录和用户域已经足够，应复用。
是否新增文件、表或接口类型在对应循环技术方案中按调用方和生命周期确定，不预设新的 crate、通用插件框架或配置同步服务。

C01 交付中心后端、管理页面及可调用的分发接口，使用真实包验证，不以原型或依赖 C03 的占位接口结项。
C03 内按插件安装使用、Agent 配置及依赖、UI 集成安排里程碑，暂不另拆第四个循环。

| 并行边界 | C01 | C02 | 约束 |
| --- | --- | --- | --- |
| 业务状态 | 中心配置、发布目录、版本和包 | Host 工作空间、会话归属、客户端草稿/展示 | C02 不读写 C01 新状态 |

实现时优先隔离 checkout/worktree；若发现实际状态、文件或环境重叠，先协调归属，不能静默扩大并行范围。

## 七、跨循环共同契约

本节固定能力语义和交接约束。具体 DTO、URL、表结构、归档压缩格式、目录物理位置与依赖库由所属循环技术方案确定，
不得以局部实现决定改变本节语义；C01 实现前须定稿 C03 将消费的包格式与中心接口，不能等接入时再补猜测规则。

### 7.1 名称、版本与引用

- Agent 记录使用名称、描述、完整提示词、默认 Skill/MCP 名称列表。默认列表是配置，不是 Agent 专属权限白名单。
- 依赖可以包含所属插件名称以确定安装来源；插件、Skill、MCP 都按名称引用，不引入包内能力 ID。只有原有独立能力而没有插件时，复用现有能力，缺失后不猜测所属包。
- 中心插件名在该中心内唯一，包内同类能力名唯一；Skill 名称沿用既有格式，MCP 复用现有配置中的名称键。名称不是上传记录 ID，删除重传后按同名重新解析。
- 跨插件或既有本地内容出现同名冲突时，展示来源并停止自动覆盖，不擅自加前缀改名。Agent 明确依赖某插件时，其他来源同名内容不能无提示冒充其依赖。
- 工作区/个人/公共 Skill 的现有来源优先级保留；安装来源与实际生效来源不一致时说明冲突，不另建隐式覆盖顺序。
- 一份插件包含多个版本，每个版本在中心当前只对应一个完整归档，归档内声明并携带该版本支持的全部平台内容；不再按平台分别上传、补包或做跨包一致性比较。上传同名同版本且内容不同的新归档时允许覆盖当前版本记录，以支持测试阶段频繁修订；同 SHA 重传视为无变化。上传者负责避免对已实际分发的版本随意换包，本版不增加客户端同版本更新检测、自动重装或版本内容历史。
- 本稿建议 Agent 首版只声明名称依赖，不引入每个 Agent 独立的插件版本范围；同用户使用一个生效版本。已安装版本包含所需能力时复用，首次安装选择该 Host 平台可用的最新兼容版本；不自动降级或替换既有版本。

### 7.2 插件包交付与运行环境

跨循环包组织沿用前序讨论：根清单、`skills/<名称>/`、`mcp/<名称>/`、所需运行环境及共享资源。
这是包的逻辑组织；2026-09-22 用户明确要求首版同时支持 ZIP 和 TAR.GZ，两种归档共用内容、运行环境和名称依赖契约。相对路径解析与精确清单在 C01 技术方案定稿，C03 的个人上传和中心安装均消费两种格式。

| 包需要表达的事实 | C01 发布端保证 | C03 安装端使用 |
| --- | --- | --- |
| 插件名称、版本、支持系统/架构及兼容要求 | 手动选择发布平台并校验所需入口，包内平台声明只作参考；市场统一展示 | 按目标 Host 匹配并校验，不依据 Desktop 系统选包 |
| Skill 名称及入口 | 正常 Skill 目录，包含 SKILL.md、脚本和资源 | 接入已有扫描/加载，不把内容复制成另一种能力 |
| MCP 名称、传输、入口与默认参数 | 服务声明可解析；本地入口能定位到包内程序 | 映射为现有 MCP 配置和连接，不自行创造新执行通道 |
| 用户需填的配置 | 声明必需项及是否敏感，不带真实凭证 | 引导填写，保存于当前用户域，脱敏展示 |
| 外部软件要求 | 声明名称、适用平台及检查/安装指引 | 显示缺失原因，AI 可解释安装方式；不要求先成功运行该 Agent 才能看到指引 |
| 包大小、内容校验信息及实际文件 | 发布完整包及对应校验信息，失败上传不对外可见 | 校验下载完整性、解包边界和所需入口，再允许生效 |

语言运行时、库和服务程序由发布方准备好；不依赖系统预装 Node/Python，不在安装后再联网补依赖或现场编译。
纯 Skill 或远程 MCP 不强制附带无用运行时，但其本地脚本所需环境必须齐全。Blender 等专业软件按已确认规则作为外部依赖。
本地启动入口、脚本和运行环境通过包内路径关联，不依赖发布者机器的绝对路径；可执行权限及重定位在各支持平台验证。
单个 SHA 对应的包内容保持不可变，用户配置和运行数据放包外；同版本替换只切换中心当前包引用，不改写原 SHA 文件，也不允许更新覆盖密钥或删除用户产物。

上传后以“一个版本一个完整归档”为准。发布端只解析本次 ZIP/TAR.GZ 内的统一清单、共享 Skill/MCP 和各声明平台的入口、运行环境及资源，不再拿多个平台包互相比较。`plugin.json` 中的平台列表是该归档的权威支持范围；每个声明平台都必须在同一归档内具备可解析的对应或共用入口，任一平台校验失败则整个归档不接纳，不能发布一个只有部分声明有效的版本。

同一归档内允许不同平台使用不同的可执行文件、运行时目录、启动参数、动态库、执行权限、平台专属资源及外部软件说明，但对外 Skill/MCP 名称和用户配置声明只定义一次，不能按平台改变 Agent 依赖语义。不同插件版本可以改变能力集合、配置、支持平台和目录，但每个版本都必须完整自描述，中心按 Agent 所需能力和目标 Host 平台筛选可用版本。

同名同版本重传时，中心完整校验新归档后允许将该版本的当前归档引用替换为新 SHA；同 SHA 为无变化。替换只影响替换完成后的发现和下载，不撤销已经完成的下载，也不通知或更新已安装客户端；上传者负责在测试便利与已分发版本稳定性之间自行判断。本版不保存同版本历史归档、不比较新旧包内部差异，也不增加客户端同版本更新处理。C03 下载后仍对取得的原始归档独立复核并按当前 Host 平台加载对应内容。

### 7.3 Agent 来源、提示词与会话

以下三项已由用户确认：企业模式整体使用中心 Agent 列表、本地配置保留但不参与；新建时选择 Agent；修改只影响新会话。

- 本地与中心保存同一种配置内容；个人模式读写本地，企业模式读取中心，企业管理员在中心编辑。客户端不逐字段混合，不用本地条目补齐中心空列表。
- 登录/刷新取得完整有效中心结果才替换当前目录；失败保留可用的当前结果并显示刷新失败，未取得过有效配置时不可选择中心 Agent，不回退本地。
- 新会话可选择“不使用自定义 Agent”，继续现有基础助手。选择 Agent 后先准备依赖，缺包时确认后自动下载；首次发送前自动核对当前有效配置并重新检查依赖，不要求用户手工刷新。首次发送冻结实际检查通过的完整提示词和默认配置；客户端未提交的草稿不形成会话。
- Agent 长文本作为完整段落进入现有系统提示词装配，与基础环境和必要内置说明组合；不将长文本拆成结构化角色/步骤字段，也不以它替换权限执行逻辑。
- 已有会话继续用创建时配置；编辑或删除配置源不改写历史，Fork/恢复/压缩续接沿用现有冻结上下文语义。本版不增加已有会话切换 Agent 或应用配置更新入口。
- 冻结 Agent 配置不表示冻结插件二进制或复制 Skill 目录：后续新执行沿用现有当前工具/Skill 定义规则，运行中执行与已激活历史内容不被热替换。显式插件更新前提示其会影响后续使用。
- 默认 Skill/MCP 作为当前会话配置和依赖准备输入；经用户确认新安装并完成必要配置的插件默认整体启用，对当前 Host 当前用户所有会话可用，不按 Agent 隔离。Skill 内容沿用按需加载，不把全部全文一次塞入上下文。
- 默认列表不排斥原有方式使用其他能力，也不增加权限放行；提示词可强调特定插件。用户已明确禁用的依赖显示需启用，不能由 Agent 默认项悄悄覆盖。切换/删除 Agent 不卸载、停用已安装插件。

| --- | --- | --- |

| 浏览市场和查询版本完整包 | 已登录企业用户的 Host | 按名称识别插件；提供目标平台可用版本和兼容信息 |
| 下载包 | 已登录企业用户的 Host | 下载时重新核对上架状态和所选包；不通过公开静态路径绕过下架 |
| 查询已装市场插件状态 | 其来源中心的已登录用户/Host | 按名称返回在架、已废弃或无法确定；不将网络错误、列表分页遗漏或当前包不支持目标平台当作下架 |

Admin 继续从 Center OpenAPI 生成请求代码；Host 消费中心协议，由 C03 实现适配。
C01 只将已实现接口加入 OpenAPI；管理端与 Host 所需 DTO 语义一致，不跨工程导入中心 ORM/业务源码。

### 7.5 共用安装、更新、废弃和删除流程

1. 取得包：个人上传文件；企业从中心发现和下载。个人缺少依赖包时提示上传，不能声称能够从不存在的包源自动下载。
2. 解析名称依赖：复用已满足条件的插件，缺失且可取得包时弹窗列出待安装项，用户确认后自动下载和安装；弹窗显示进度与处理阶段，执行中禁止关闭但允许取消，成功/失败/取消收尾后可关闭。依赖安装由 Runtime 确定性编排，不由模型生成命令。
3. 准备：校验平台、包内容和入口；在隔离准备位置完成解包，不覆盖已生效版本或用户配置。
4. 接入：通过既有机制发现 Skill、注册 MCP，收集所需配置及专业软件缺失信息；满足条件才显示 Agent 可用。
5. 失败：给出所缺插件/配置及可执行的恢复动作，保留输入；不把下载完成或目录存在等同于安装就绪，不自动发送等待中的消息。

安装保存必要的包归属、版本、来源和插件整体开关，Skill/MCP 运行事实仍由既有机制维护；独立能力与插件分开管理，插件内部不可单独删除或编辑包内容。来源区分用户上传与中心取得；
两者即使同名也不自动改写来源或覆盖已安装内容，先提示冲突并让用户显式处理。
插件自身配置由插件定义，不固定为 JSON 或统一结构；Host 提供当前用户的持久配置/数据目录，安装管理事实独立于插件文件内容。C01 根清单及已有配置声明不因此改变，具体目录传递与配置交互由 C03 技术方案核对。

更新规则已按用户 2026-09-24 指示调整：插件页读取中心目录时自动发现已安装项的新版本并开始更新；用户也可显式检查更新。仅当中心包版本更高且 SHA 不同才自动进入更新并展示进度，其余情况提示已是最新版本，不重复安装或降级。更新查询仍在市场/已安装页面打开或显式刷新时进行，不新增常驻轮询任务。过程文件清理失败保留诊断，应用启动和后续包操作结束时自动重试，不全局阻止其他插件操作。
同一插件仍有活动使用时，更新/删除提示稍后重试；不热替换活动进程或自动中断任务。更新准备失败保留旧版本，成功后保留用户配置，按新包重新检查就绪条件。
更新移除智能体所需能力时展示缺项，不自动改写智能体配置或降级。单个能力运行故障不连带禁用其余正常能力，智能体就绪按实际声明依赖判定。
个人上传新包也走相同校验与替换流程，但没有中心发现和自动更新机制。

| 情况 | 行为 |
| --- | --- |
| 中心确认下架对应市场插件 | 已安装项标记“已废弃”，允许继续使用与删除；中心不再提供下载、手动更新或自动更新 |
| 个人上传插件与下架插件同名 | 不标废弃，不因中心状态改变其来源或可用性 |
| 中心不可达/状态查询失败 | 显示状态暂不可刷新，保留已知事实；不据此新增或清除废弃标记 |
| 已废弃插件被删除 | 相关 Agent 依赖缺失，不能从中心自动补装；已有历史保留 |
| 中心重新明确上架同名插件 | 成功查询后恢复在架展示；已安装项在插件页发现新包后自动更新，未安装项仍由用户操作 |
| 删除 Agent 配置 | 不自动卸载可能被其他 Agent 使用的插件 |
| 删除插件 | 展示受影响的 Agent，默认仅移除该插件拥有的安装内容和接入项，保留用户配置及运行数据；提供同时清除选项，不删除工作空间产物、无关手工配置或其他用户内容；同名不同来源不自动继承遗留凭证 |

中心元数据与包文件、Host 安装记录与文件不是同一事务资源。C01/C03 分别设计失败后可检查和恢复的发布顺序，
不得因数据库一处成功就返回整包成功；不建立跨中心与 Host 的分布式事务。下载中途遇到下架或故障时，失败结果不能触发安装成功。

### 7.6 C02/C03 界面与工作空间交接

- 整体布局：侧栏顶部整合 macOS 控制按钮，底部显示账号与 Runtime；Windows 保留可达的窗口控制。
  侧栏收起和窄窗口仍能展开导航、操作窗口、进入账号菜单；Web 不显示虚构原生窗口按钮。
- 侧栏高频入口：会话列表前使用“新建会话”“助理会话”快捷菜单；“助理会话”复用既有主控会话，不新增会话类型。移除常驻“会话/已归档”页签，默认展示活动会话，归档历史仅在搜索/筛选中显式进入；归档业务动作和持久事实不删除。
- 置顶：沿用现有固定事实改称置顶；置顶分组位于工作空间上方，原列表抽出，同一会话只出现一次；归属不变，取消后回原分组。
- 新会话从上到下组织快捷入口、工作空间/Agent 选项、输入和既有工具栏。此为功能布局基线，视觉尺寸与响应方式由 C02 交互稿细化。
- 快捷入口由客户端本机配置文件声明，文件不纳入版本控制，正式包默认不嵌入；按需构建时才打入模板，可装配模板、MCP、Skill、Agent。点击只展示选中配置或预填可编辑内容，不自动发送；已有文本不得静默覆盖。通用 Composer 不写入特定业务流程。
- C02 不具备自定义 Agent 时不显示无功能入口；C03 在统一选项行接入 Agent 选择、来源、依赖准备及待配置提示，复用已有输入与状态区域。
- 工作空间选择支持清空，清空仅解除草稿归属；切换保留输入，对附件/引用重新核查，不覆盖目标工作空间已有草稿。
  C02 必须明确当前按工作空间保存草稿的选择/移动行为及冲突交互，不能以第二套草稿系统规避。
- 新建工作空间先打开窗口，名称与可选目录同窗编辑；取消目录选择不关闭窗口。未选工作目录时显示“仅使用私有目录”，由 Host 建立私有目录。
- 仅私有目录的工作空间仍是普通工作空间，保留名称、会话归属及列表；没有用户工作根时使用该私有目录作为默认文件/Shell 工作位置，不退回用户 Home 或进程 cwd。
- 有目录的工作空间沿用原主目录/附加目录组织方式。现有“同主目录恢复”不适用于无工作目录的多个工作空间，C02 需避免把它们误认成同一个。
- C02 同步核查工作空间编辑、冻结会话环境、终端/文件、权限、Skill 扫描和恢复；已有会话继续保留其冻结环境，不因编辑工作空间改变。

- 支持平台沿用产品已交付范围；不要求每个插件支持全部平台，没有匹配包时清晰展示不支持。具体平台验证矩阵在循环计划与版本验收中按发布范围确定。

## 九、补充取舍、风险与变更规则

### 9.1 确认状态与本稿补充取舍

已确认事项不再重复开放讨论：三个循环及并行顺序；企业整体使用中心 Agent；新建选择并冻结 Agent 配置；在架插件页发现新包后自动更新；
完整长文本提示词；名称依赖；每版本单一多平台完整包；快捷入口客户端预设；个人上传与企业市场共用业务；已废弃可用可删且无中心下载。

以下补充取舍已于 2026-09-22 随总体设计整体确认；插件作用范围一项按 2026-09-23 用户确认更新，作为后续循环细化的约束：

| 取舍 | 理由及边界 | 细化归属 |
| --- | --- | --- |
| Agent 配置在会话冻结；插件整体启用后对当前用户所有会话可用；Skill 按需加载 | 2026-09-23 确认不按智能体隔离插件，提示词可强调使用；保留审批和激活机制，显式禁用需用户处理 | C03 |

| 同版本重传完整包，允许替换当前归档；客户端不处理同版本更新 | 支持测试阶段频繁修订并避免多平台补包/跨包比较；上传者自行避免改写已实际分发版本，已安装端不会因同版本换包收到更新 | C01；C03 只按正常下载校验，不增加更新语义 |

C02 对窗口控制、草稿切换及仅私有目录执行的方案先核查现有实现，再进入开发，不由布局图代替可行性验证。

### 9.2 主要风险

- 完整语言运行时的重定位、动态库和执行权限可能因平台不同而失败；上传验证与真实运行验证必须分别完成。
- 名称引用遇到同名来源、改名或不同内容重传时可能解析错误；沿用现有优先级、展示来源并阻止静默覆盖，不用新增 ID 绕开用户要求。
- 工作目录可选会触及必填目录、权限和恢复假设；C02 必须完整闭环，不能只做 UI。
- 会话冻结的 Agent 配置与可更新插件是不同生命周期；旧提示词不变不代表旧工具版本被永久保留，更新交互须说明影响。
- 中心与 Host 都有数据库/文件组合状态；发布、安装、更新及恢复不能仅以单边写入成功判定完成。

### 9.3 总体设计变更与下一步

总体设计已获用户确认，版本整体开发中，使用[版本级开发计划](开发计划.md)维护实现循环总台账。
C01/C02 实际验收及提交状态以总台账为准；用户已确认 C03 主要功能规则，并明确要求开始开发。[技术方案](cycles/C03-插件与自定义Agent完整接入/技术方案.md)、[界面交互设计指导](cycles/C03-插件与自定义Agent完整接入/界面交互设计指导.md)与[开发计划](cycles/C03-插件与自定义Agent完整接入/开发计划.md)作为实施依据；当前 M0 已确认，M1—M4 内部验收完成、M4 待用户确认，前序未收口事实保留。

2026-09-23 修订原因：用户指出将独立能力与插件混合管理会导致编辑/删除语义不清，并确认插件启用后默认全局可用。

影响已收口循环时显式重开，保留原结论；不能由后续接入静默改写已确认边界。
