## 三、模块与权威状态

```text
Desktop / Web
  └─ HTTP Command + SSE + Streaming Upload
      └─ Host 用户域准入与 I/O Adapter
          └─ assistant-runtime
              ├─ 插件安装/启停/卸载编排、智能体目录与依赖检查
              ├─ RuntimeStore → 既有用户 SQLite worker
              ├─ 既有 MCP Registry / Skill Catalog / 权限
              └─ Session 冻结 → 唯一 ExecutionSpec → Agent Core
```

Runtime 私有 `plugin/` 维护包领域值、安装操作与派生可用性，`custom_agent/` 维护配置来源、名称依赖和冻结装配。
公共命令薄转发放在 `runtime/plugins.rs`、`runtime/custom_agents.rs`，不建立宽泛的 common/service 层。
Host 的 `plugins/` 实现归档、受管路径、下载流与文件操作，`storage/plugins.rs` 和 `storage/custom_agents.rs` 接入原 worker。
这些是拟新增职责位置，不要求提前创建空目录。

| 边界 | 最小能力及理由 |
| --- | --- |
| `RuntimeStore` | 扩展智能体、插件和安装操作的业务存取；SQL 与文件路径不会进入 Runtime |
| 外部智能体来源端口 | 提供完整目录读取、当前来源可用性；真实企业网络与确定性测试分别实现，本地来源直接读 Store |
| 插件分发端口 | 市场目录、状态、resolve 和指定原包下载；凭据只在 Host，个人模式无远端源 |
| 插件文件端口 | 接收临时包、检验/解包、准备稳定目录、删除指定受管内容、配置文件上传；阻塞 I/O 与平台安全封装留在 Host |

端口直接使用该能力领域的类型及取消/进度回调；不得传 reqwest、数据库连接、归档库对象或 UI 状态。
Host I/O 句柄不保存“已安装/已启用”的第二份权威状态；配置清单与原包校验结果转换一次后交 Runtime。

## 四、持久化与配置目录

### 4.1 目录及数据归属

以现有用户域 `<user-root>` 为根，全部操作在所连接 Host 上进行：

```text
<user-root>/
├── data/runtime.sqlite3
├── mcp.json                         # 独立 MCP，不加入插件展开结果
├── skills/                          # 既有独立 Skill
└── plugins/
    ├── .staging/<operation-id>/      # 原始归档、待发布解包内容
    ├── .trash/<operation-id>/        # 卸载已脱离接入的受管内容，等待删除收尾
    └── <plugin-name>/
        ├── config/                  # 插件自定义一个或多个配置文件，格式不限
        ├── data/                    # 插件持久运行数据
        └── packages/<sha256>/       # 已验证的不可变包目录；只有一个生效引用
```

插件 `name` 使用 C01 的 ASCII 编码，不拿中文 display_name 或未校验路径拼目录。
sha 是原包完整性与目录寻址，不用于能力引用、不检测同版本更新。过渡期保留旧目录只为收尾恢复，不支持多版本同时生效。
无数据库生效引用的目录不得被扫描、启动或因“目录存在”重建成已安装插件。

`.staging` 和 `.trash` 是过程目录，不是下载缓存或回收站，不按历史操作长期保留内容：

- 成功、失败或取消后，待文件句柄与受管任务退出，清理该项原包、未生效解包内容及待删除文件；操作结束时删除空的 operation 目录，顶层空目录可保留。
- 批量安装逐项处理并清理，前一项收尾成功后才接收下一包，不先下载整批；临时空间随单包限额受控，不随已完成操作次数增长。
- 崩溃残留在用户域启动时核对持久收据、当前生效引用和文件归属后自动清理；后续包操作结束时再尝试一次未完成的清理。
- 清理失败立即停止当前批次，并在操作记录中保留残留占用和原因；不全局阻止其他插件的上传、安装、更新或卸载。后续操作仍须通过各自的文件归属、无覆盖和运行使用保护校验。
- 无法确认归属的残留不按目录年龄直接删除，进入待处理状态；不靠后台无限重试或定时删除掩盖故障。保留的 config/data 与数据库操作收据不属于临时目录清理范围。

### 4.2 最小持久记录

复用当前用户 `data/runtime.sqlite3`，所有新增表均在同一个 Store 事务边界：

| 记录 | 必须保存的事实 | 不保存的事实 |
| --- | --- | --- |
| `custom_agents`，name 主键 | description、完整 prompt、Skill/MCP 名称及所属插件引用；本地创建/修改时间 | 中心 Agent 副本、版本历史、模型/权限白名单 |
| `plugins`，name 主键 | 来源（upload / center_id）、可空生效包 version/sha/清单、整体 enabled、确需 Host 装配的连接参数、最近成功获知的市场状态 | Skill 正文副本、派生 MCP 文档、运行状态机、插件自定义配置文件内容及外部软件路径 |
| `plugin_operations`，现有 IdempotencyKey 作为操作身份 | 操作种类、确认的包清单及预期旧包、逐项提交/清理事实、cancel_requested、终态和安全错误 | 逐字节进度、日志历史、安装命令、会话或模型任务 |
| `sessions.custom_agent_json`，可空 | 来源、name、description、prompt 与默认能力引用的冻结快照 | 当前中心目录、插件二进制版本副本 |

`plugins.active_package` 为空且保留配置/数据时，只是可恢复归属，不在已安装列表伪装安装成功。
来源绑定随保留配置留下；同名不同来源必须显式处理旧数据，不能自动把遗留凭据提供给另一包源。
安装操作只是一条有终态的工作记录，可批量含多个插件，不为每个下载分片建实体、表或事件序列。
首版持久保留操作收据以支持重启后的 key 查询，不提供历史管理页；后续需要保留策略时另按实际量评估，不在本轮加清理调度器。

Host 连接参数仅指必须由 Host 为 MCP 的 env/headers 装配的字段值，例如远端鉴权凭证；存在受保护用户库的插件记录中。这不是插件配置文件 schema，不要求插件把自己的 TOML/YAML/INI 等改成 JSON，也不把相同秘密再次写入 `mcp.json`。
外部软件路径由插件自行生成和读取 `config/` 内原生文件，不再进入 Host 的 `software_paths_json` 或通用设置表单；Host 不解析、合并或重写任意格式。确需人工提供的凭证在首次调用失败后给出指引，不把预填所有字段作为安装或发送门槛。

### 4.3 插件如何取得配置和数据位置

本方案复用现有目录契约，但外部软件路径改由插件管理，须同步收敛 C01 `format_version=1` 中依赖 Host 软件路径的包声明：

- 本地 MCP 在确定性展开既有声明后，Host 只向这个插件的 stdio 进程注入 `EZ_ASSISTANT_PLUGIN_ROOT`、
  `EZ_ASSISTANT_PLUGIN_CONFIG_DIR`、`EZ_ASSISTANT_PLUGIN_DATA_DIR` 三个绝对目录变量，不携带秘密。
- 这些名字是 Host 运行约定，包不能提供不同值覆盖；出现同名声明返回明确配置冲突，不能静默接纳发布者路径。
  C01 上传端不执行包，本轮以相同样例复验契约差异；如需将保留名拒绝前移到 Center，先定向确认 C01 变更。
- Skill 脚本通过自身文件位置找到包根，再按本节稳定布局访问包外 `config/`、`data/`；技能说明必须以自己的源位置为起点，不能假定任务 cwd 是插件目录。
  继续通过现有 Shell 调用，不注入全局插件环境、不添加 Skill 专用执行器。插件的 `SKILL.md` 可指导 Agent 调用包内脚本，但不让模型猜测、生成或修改软件路径。
- 纯远程 MCP 只使用清单参数/headers，不向远端服务发送本机配置目录或无关用户数据。
- 本地 MCP 的启动命令必须先启动包内自包含程序，使插件在首次调用时可以读取或创建原生配置、探测外部软件并持久化有效路径；`${software.*}` 不能再作为 MCP 启动命令/参数/env 的必需输入。`external_software` 可保留软件名称、平台和安装指引等元数据，但不投影成 Host 管理的 `is_set` 或就绪门槛。需同步调整 Host 与 Center 的包校验及已有样例包，不为未发布的中间形态保留双轨路径存储。
- 不新增 `postinstall`、配置迁移脚本、任意检测命令或 `${config_dir}` 等未定义占位符。初始化属于插件正常运行；插件在自动发现失败时返回可操作的诊断，不能把安装成功伪装成外部软件已就绪。
- 不向通用系统提示词注入插件路径或配置内容：提示词无法为 MCP 进程建立可靠的启动环境，也会把私密配置暴露给模型。三个目录环境变量只传给所属本地 MCP 进程；Skill 依据自身位置定位，远端 MCP 使用自身鉴权流程。

设置页移除通用“外部软件路径”表单；保留真正需要 Host 装配的连接参数入口，以及供高级用户按插件说明明确指定相对文件名的原生配置上传/替换，原样保存字节。默认使用流程不要求用户理解配置文件路径或格式。
不假定插件一定有一份可编辑文本，不新增通用配置编辑器。单文件上限 16 MiB，路径限制在本插件 `config/`，不能覆盖包、管理元数据或其他用户文件。
配置目录和文件按私密内容保护；列表可返回相对文件名/大小，不通过普通文件预览把秘密正文传回客户端。
已有明确的字段 secret 只返回“已设置”，修改采用 keep/set/clear，不以脱敏星号回写。
原生配置上传先写同目录临时文件，完整接收和校验后原子替换；失败保留原文件。写入复用用户插件变更门和插件使用写保护，有受管活动时返回 Busy。
同文件并发替换以读取时的文件摘要作为 expected 值，创建使用“预期不存在”；摘要仅用于拒绝过期覆盖，不解析配置格式，也不记录正文到日志。

Host 创建私有目录、校验归属及 no-follow 路径；Unix 目录 0700、配置文件 0600，Windows 复用现有原生保护。
`UserPaths` 扩展按子树保护 `config/` 和 Host 元数据，保留包目录读取、拒绝 Agent 结构化文件工具改写包；普通 HTTP 文件/搜索走同样规则。
目录权限不构成强沙盒：所属 MCP 需要读取自身配置，Shell/用户启动程序仍按当前 OS 权限运行。

## 五、智能体来源、依赖和冻结

### 5.1 来源及刷新

个人模式从 Store 读写本地配置，校验与 C01 相同：名称 NFC、1—64 字符且不能原位改名，prompt 保留原始空白、非全空且 UTF-8 不超过 256 KiB，默认引用按同类名称去重。
企业来源经现有 Credentials 每次取得当前登录；登录/打开选择器/显式刷新/首次发送前读取完整 `runtime/agents`，同用户同时读取合并为一次在途请求，无常驻轮询。
完整验证成功才替换 Runtime 内存目录；有效空数组替换为空，网络失败保留同一当前用户域最后有效目录并显示刷新失败。
重启不恢复未知授权状态的中心缓存；首次未成功获取、旧中心无 managed_agents、明确身份失效分别投影为不可用，不回退本地列表。
复用现有登录 Arc/用户域 Arc 比较拒绝晚到结果，身份锁只短持提交，不能跨网络 await；不新增登录 generation 或第二个企业 Token。

### 5.2 依赖准备

检查输入只有当前智能体名称/来源、workspace_id 和原有执行选项，不接受客户端提交 prompt 作为企业权威配置。
Runtime 取得完整配置后按插件归组，合并同一插件所需 `required_skills`/`required_mcp`；无 plugin 的引用只检查当前独立能力，不能猜测包名。
已安装同来源且包含能力时复用；禁用、同名来源冲突、必需参数缺失、软件缺失或能力连接失败返回具体诊断。
缺参数、缺软件、能力缺失和运行环境/连接不可用属于非阻塞诊断；客户端发送预检与 Runtime 物化均允许继续。缺包、显式禁用和名称/来源冲突仍阻止物化，权限与审批规则不变。
缺包且可取得时生成安装确认摘要（来源、name、version、sha、大小），确认后交安装操作；未确认不下载或运行。
已有版本缺能力时提示手动更新，不将“自动补依赖”扩展成自动替换已安装版本。个人缺包进入上传，中心下架/不兼容分别报错。
检查结果不是持久会话或长期授权票据；确认包摘要与开始安装时实际选择不一致，返回需重新确认的最新清单，不能下载额外插件或更大新版本来代替用户选择。

### 5.3 首次物化与重试

`SessionMaterializationManifest` 增加可空智能体选择（name 与来源标识），不新增客户端配置 revision。
处理顺序：

1. 先按原 materialization key 查询提交事实。已提交且原始用户意图一致，直接返回原 Session/Input/Run；配置随后变化不参与此次重试。
2. 未提交时在 Workspace/Session 写门之外刷新企业目录、准备模型和依赖；客户端正常情况下先预检，减少重复上传附件，但最终准入仍由 Host 决定。
3. 进入短提交段前取得当次配置的不可变值和插件绑定读保护，复核来源仍有效、工作空间与实际依赖一致；变化可重新准备，最多两次，持续变化保留草稿并提示稍后重试，不忙循环。
4. 配置正文变化且没有阻塞项时自动继续；新增下载仍返回安装确认所需信息，参数/软件缺失仅保留配置入口，不拦截本次发送，不弹“刷新智能体”确认。
5. 使用检查通过的同一值组装 system prompt、智能体快照和首次 Input，在既有物化事务中一次提交；并发同 key 仍由 Store 唯一约束及语义比较收敛。

同 key 不同智能体选择或不同正文/附件仍冲突；比较的是原始意图，不把服务端后来抓到的 prompt 纳入幂等相等条件。
Store 的物化语义比较补齐智能体来源/name；已经提交的冻结正文不能被候选新正文覆盖。上传途中断线沿用 C02 原 key 查询，不自动换 key 或创建第二会话。
自动依赖安装完成仅恢复准备结果/草稿，不自动发送消息；不需要用户介入的配置刷新可以继续已经明确发起的本次发送。

### 5.4 系统提示词与既有会话

保留基础 Persona、Pinned Memory、必要工具与权限说明，插入一段完整智能体 prompt 和默认依赖名称说明，再保持既有 Skill Catalog 与最后的目录环境 Part 约定。
能力说明明确声明的名称不保证当前可用；智能体可检查环境、使用实际可用工具解决或绕过问题，仍遵循权限与审批。不将一次环境预检结果冻结成永久状态，也不把未接入的 MCP 注入工具列表。
不把智能体全文切成字段，不把默认 Skill 全文预加载，不将 AgentVariant Plan/Build 当自定义智能体 ID。
冻结快照承担配置事实，system prompt 是创建时渲染产物；后续普通执行不再回源重新渲染。
旧会话字段为空保持原行为；Fork 复制智能体快照和冻结提示词前缀，Clear 用原快照重建，压缩/恢复/Goal continuation 均保留。
既有会话不增加切换或应用更新入口。后续插件版本变更只影响当前能力实现，不回写历史激活正文或冻结配置。

## 六、插件 Skill/MCP 接入

### 6.1 Skill

扩展 `SkillScanRequest` 携带 Runtime 已确认的生效插件包根，Host 仍负责读取/解析，不能自行遍历 `.staging` 或猜测已安装项。
在候选、定义和投影上保留插件归属；`SkillSource`/协议来源增加受管插件来源，插件名称为归属字段，不靠路径字符串反推。
独立能力先按原目录优先级与名称开关求解；插件能力不写入/继承 `skill_states` 的个人名称开关，而由插件整体开关派生。

同名处理：独立目录之间原优先级保持；插件与独立候选冲突时不覆盖原独立能力，插件对应能力不可用并给出来源冲突。
两个启用插件出现同名能力时不得按安装先后或枚举顺序选胜者，冲突能力均不进入生效 Catalog，插件其余无冲突能力可用。
安装/启用预检已知冲突并提示处理；Workspace 后续文件变化仍须每次扫描核查，不能仅靠安装时检查保证全局无冲突。
依赖明确指定插件时必须匹配实际定义归属，不接受其他同名 Winner。

`ListSkills` 通过可选 `include_plugins` 区分范围：缺省保持独立技能管理；Composer、草稿能力校验与当前上下文面板显式传 `true`，包含已启用插件的技能。技能摘要和 MCP 可选服务摘要以可选 `plugin_name` 返回明确归属；选项按“插件名 · 能力名”展示并参与搜索，实际激活仍使用原技能名或 MCP server key，不改名称冲突及权限规则。
单项编辑/删除/开关命令在 Runtime 校验目标归属，不能只在 UI 隐藏按钮。显式 `/skill`、`load_skill`、Activation ledger 与当前 Catalog 继续共用。
累计扫描/有效技能上限仍执行原限制；包清单允许 256 项不意味着用户总 Catalog 无上限，超限显示准确诊断。
原扫描器对链接较严格；包内已经归档校验的相对链接按受管包根再次解析，仅允许根内目标，不通过放宽独立 Skill 根校验接入。

### 6.2 MCP

保留 `McpConfigStore` 的独立文档读写与 CAS；增加 Runtime 私有候选组合入口，把手工候选与启用且参数齐备的插件 MCP 按名称合并。
插件项由受管清单和 Host 参数一次展开形成既有 `McpServerConfig`，不落成第二份 `mcp.json`。
所有 refresh 路径（启动、手工刷新、Session refresh、配置更改和插件操作）必须调用同一组合入口，避免下一次普通刷新把插件服务当作 removed。
给 Registry 配置/投影保留归属，插件字段编辑、导入覆盖与单项禁用在 Runtime 拒绝；插件详情触发的连接重试仍用原能力。
MCP 同名冲突处理与 Skill 一致，不悄悄加前缀；合并后执行原启用服务数、调用并发、schema 和输出限额。

沿用 `McpRegistry` 的连接身份、调用 lease、退役及审批失效机制；不复制连接状态到插件表。插件详情的在线/失败状态从 Registry 派生。
禁用插件立即阻止新调用/新 Skill 激活，已经开始的调用按原 lease 收尾；在途审批指向旧连接时失效，不能转移到同名新连接。
当前 Run 的模型工具定义不热改；后续尝试调用已退役能力返回现有不可用工具结果，下一执行边界使用新目录。

## 七、下载、安装、更新与恢复

### 7.1 接纳与进度

同一用户最多一个改变插件文件/配置的操作，批量依赖按确定顺序逐包处理；并发写请求返回 Busy，不建立排队调度器。
读取目录/会话不被下载锁阻塞；Host 归档阻塞工作额外使用最多 2 个任务的进程级 semaphore，满时拒绝接纳，避免多用户压满 blocking pool。
安装 supervisor 由 RuntimeTasks 跟踪、继承用户域取消；Desktop/Web 断开不取消已确认的中心下载/安装；主动退出账号或 Host 关闭按既有用户生命周期取消。
个人上传尚未收全时客户端断开只能终止接收，不能声称 Host 可以继续取得剩余字节。

持久阶段是恢复事实：已接纳、准备中、提交/清理待收尾、成功、失败、已取消、被关闭中断；逐项保存原包选择与是否已提交。
下载字节和阶段进度用内存 watch 合并、最多每 250ms 投影一次，SSE 只通知变化；不逐块写库。
查询从操作持久事实及当前受管任务生成快照；重启后不伪造历史下载进度，不通过丢失的 SSE 推断成功。
取消是设置 `cancel_requested` 并通知任务，重复取消 no-op。提交前取消清理未生效内容，已提交项保留。
取消与提交在同一短门禁内裁决：提交已完成则返回已完成事实，不报“已取消”掩盖实际安装。
同一操作 key 重试先比较已保存的操作意图和确认清单；相同返回原收据，不同明确冲突，不重新执行已提交项。
清理失败保留“需要清理”诊断并解除弹窗强制锁定；应用在启动和后续包操作结束时自动重试，失败记录不阻止其他插件的文件变更。提交前失败若已成功丢弃过程文件，只记录原操作错误，不标为需要清理。

### 7.2 流式上传与中心下载

新增专用原包上传路由，以 operation key 关联 Runtime 接纳记录；归档字节不进入 JSON Command，也不占用会话附件目录。
鉴权、用户域、来源、版本准入先于正文读取；只对包路由放开默认正文限制。复用 streaming/backpressure 模式，不复用附件实体。
与 C01 对齐：压缩包不超过 2 GiB，单文件 2 GiB、总解压 8 GiB、10 万条目；接收/下载 60 秒无进展、30 分钟总时限，扫描准备 5 分钟，整包操作最多 35 分钟。
普通 Command/登录的时限和正文上限不变；取消检查贯穿网络 chunk、文件 copy、逐条解析与等待 semaphore。

Center Adapter 使用 `/api/info` 能力 `managed_agents`/`plugin_market`；Agent 完整目录和市场 JSON 使用专用有界读取（建议 16 MiB、15 秒），超限返回不完整目录错误，不部分替换。
下载独立使用流式 Client/请求时限，保持禁止重定向、禁止隐式重试，不用当前 5 秒总时限的身份方法直接接包。
每次请求读取当前 Bearer，LLM key 不参与；来源由稳定 center_id 判定，URL 只用于连接，路径参数逐段 URL encode。
resolve 使用 Host 自身系统/架构/版本和所需能力。下载携带选中 sha 的带引号 If-Match，验证长度、响应 sha 与本地实际 SHA-256 三者一致；不只信响应头。
412 PACKAGE_CHANGED 只表示当前下载选择失效，重新 resolve 并回到确认；不扩展为已安装同版本更新检测。410 下架、401/403 身份、平台缺包和网络故障分别处理。
只在市场/安装列表打开、显式刷新和依赖准备时查询，不常驻轮询或自动降级。插件页读取中心目录后对已安装项自动检查；用户也可点击“检查更新”重查。中心包版本更高且 SHA 不同时立即自动执行更新并展示进度；其余情况不创建安装操作，显式检查时提示已是最新版本。

### 7.3 验证、文件发布与提交点

1. 持久接纳记录先于副作用，Host 在本用户 `.staging/<key>` 中接收原包、计数并校验 SHA。
2. 完整扫描后确认 manifest、平台、名称引用、路径/权限/链接、限额和入口；只解包到新目录，不运行安装脚本或 MCP。
3. 完整包保留各声明平台内容，Host 只接入当前平台；不裁剪出新包、不调用系统 unzip/tar 或 npm/pip。
4. 安装新插件创建独立 config/data 目录；有原来源保留数据时先匹配，不覆盖。准备好的包 rename 到唯一 `packages/<sha>`，flush 文件及必要目录元数据。
5. 取得发布门，重新检查来源、预期旧包、能力冲突及活动使用；Store 事务切换生效包、整体开关/配置事实及操作项提交记录。此事务是安装事实的唯一提交点。
6. 释放数据库事务后，在发布门内更新可重建的 Skill/MCP 运行投影，再发事件；运行连接实际就绪之前不显示“可使用”。
7. 清理不再生效的旧包与临时内容；失败保留明确收尾记录，不谎报全部完成。只有无引用、归属/类型核验通过的受管项能被清理。

未配置必需字段时可提交已安装包，整体 enabled 默认 true 表达用户启用意图，但有效能力仍由配置/冲突/运行就绪派生，UI 显示待配置；主动禁用设 false，补齐配置不反向启用。
已有版本的更新在必需配置未满足时保持旧版生效，先完成参数准备，再进入切换事务；不让新字段缺失直接破坏旧版。
发布前失败/取消只处理新准备内容，旧生效包与用户文件不变；任一业务写入失败或结果异常停止后续写操作，不循环补救。

必须区分安装事务失败与运行故障：包静态准入/文件/事务失败保留旧版；提交后 MCP 网络或启动故障投影为已安装但能力异常，不冒充就绪。
任意插件程序启动可能写原生配置/数据或调用外部服务，Host 无法承诺用 SQLite 回滚这些行为。因此不在提交前偷偷启动候选包来“证明原子就绪”，也不自动恢复用户文件覆盖运行产物。
如需要把“新版本运行探测失败自动回退”纳入承诺，必须另设计插件作者配合的检查/数据兼容契约；本稿明确不把它假装成现有安装事务能力。
这是对功能设计中“更新失败保留旧版”的范围细化，待本稿评审确认；未确认前不能把运行启动失败排除在外视为既定产品结论。

### 7.4 卸载与重启恢复

卸载先试取插件发布写保护，有活动使用立即 Busy；撤销新能力准入、退役并回收受管 MCP，成功后以 Store 事务清除生效引用并记录待清理目标。
移动受管包到 `.trash/<key>` 后删除，config/data 默认保留；勾选清除时同样只移动/清理本插件归属目录，并清掉 Host 参数和来源残留。
数据库提交与文件删除无法合为一个事务，故卸载只在清理结果可核验后返回完整成功；故障保留安装引用已撤销与文件残留的区别。

用户域启动恢复发生在插件接入前：

| 持久事实与现场 | 恢复行为 |
| --- | --- |
| 未提交操作 + staging 或无引用新目录 | 标记被中断，不自动继续下载；核对归属后清理未生效内容；旧版仍有效 |
| 提交已完成 + 所引用包完整 | 从该包重建派生目录/连接，完成已记录收尾；不重复创建安装项 |
| 所引用包缺失或校验不符 | 该插件不可用并报损坏，不从残留目录自动猜测版本或恢复成旧版 |
| 卸载提交完成 + trash/原位置仍有内容 | 继续已明确记录的安全清理；类型/来源不符立即停止该插件写操作 |
| config/data 保留但无生效包 | 保留来源绑定，只作为重新安装可恢复数据，不注册能力 |

重启不恢复在途网络传输、不做分片/Range 下载；重试由用户发起新操作，已安装满足项自然复用。
关闭先拒绝新操作、发取消并等待受管任务；提交段收敛或超时中止都由持久操作记录恢复。blocking 解包逐块协作取消并由 Host 等待其退出，不能因为 abort Tokio future 就假设磁盘写已停。

## 八、并发、活动使用与版本字段

每个插件的 Runtime 内存生效描述持有读写使用保护：Run 准备当前能力时，对进入本次 Catalog/工具集的插件取得读 lease，持有到 Run 及其受管子任务结束。
插件是全用户可用，所以 lease 按本次实际装配的能力集合取得，不能只看会话是否选择该智能体。Skill 激活/独立连接测试等短操作也须受对应保护。
安装新名称不阻塞其他 Run；更新/卸载同一插件只用 try-write，冲突即 Busy，不在用户确认后偷偷等待很久再更换。
多插件 lease 按插件 name 排序取得；批次只逐包提交，已完成项不随另一项失败反向卸载。
整体禁用不删除/替换包文件，不等待上述使用写保护；它在短发布门内提交开关并关闭新能力准入，旧调用按 lease 收尾。
包更新、卸载和配置文件替换仍必须取得使用写保护；再次启用先复核当前包、配置和冲突，不能绕过尚未收尾的变更。

锁顺序：Runtime 生命周期准入 → 单用户插件 mutation gate → 按名称排序的插件发布/使用保护 → Workspace/Session 既有门 → MCP refresh gate → Store worker。
网络和完整解包不持有 Workspace/Session 门或数据库事务；运行循环不能持 Session state lock 等待插件写保护；Registry 回调不得反向获取 plugin mutation gate。
Run 先捕获并保护插件绑定，再取得 Workspace/Session 门；若排队期间绑定失效，释放门后重新准备，不在 Session 锁内补取插件锁。单纯 refresh 读取已发布的不可变候选，不升级当前 Run 的读 lease。
首次配置刷新在以上门外完成，短提交仅核对捕获的当前来源与值；具体调用链在实现 Review 中检查所有 refresh/clear/fork/queue 入口。

现有 Shell 有显式 Detached 交接，交接后的 OS 程序不受 Runtime 跟踪；手工终端也可能直接执行包文件。
本方案保证受管 Run/调用/进程的活动保护，不声称能探测所有外部进程；不能扫描进程名猜测“无使用”，也不为此新增常驻进程监控系统。
显式脱管使用需由用户停止后再更新/卸载；文件仍被占用时返回诊断并保留现场。此实际边界需在相关操作提示和验收说明中保留。

不添加 plugin revision/generation 或进度 sequence：mutation gate、预期生效 sha 和操作 key 已足够。
本地智能体编辑及 Host 参数表单存在两个窗口旧值覆盖的真实问题，沿用内容散列 CAS：读取返回规范业务内容的摘要，写入带 expected 值；不匹配保留草稿并提示重读。
摘要由已有内容计算，不建 revision 列、不自增；秘密只参与 Host 内摘要，界面不拿脱敏投影重算。原生配置文件只使用文件内容摘要，重启重新计算；冲突保留待上传文件，重读元数据后由用户决定是否再次替换，不强加 schema/revision。
中心包 sha If-Match、既有 MCP CAS 和现有 SSE sequence 保持各自职责，不互相借用。

## 九、正式应用协议与前端接入

在 `assistant-protocol` 增加面向产品的 DTO/Command/Result，Host wire DTO 留在 Host。建议命令分组如下，具体 Rust 名称按实现保持一致：

| 能力 | 请求与结果要点 |
| --- | --- |
| 列表/编辑智能体 | 当前来源、完整配置详情、依赖摘要；本地 CRUD 带内容 CAS，企业写入明确拒绝 |
| 准备智能体 | name/来源/workspace → 当前配置摘要、缺失插件的确认清单、禁用/参数/软件/冲突诊断 |
| 插件目录/详情/市场 | 生效版本与来源、整体开关、派生能力状态、参数已设置标记；不返回秘密或原始配置全文 |
| 开始安装/更新 | 操作 key、用户确认的精确包清单及预期旧包 → 受管操作快照 |
| 查询/取消操作 | 同用户 operation key → 当前进度/终态；重复查询/取消幂等 |
| 设置插件参数/整体开关 | 插件来源与当前包、显式目标值；设置同值 no-op，参数旧表单 CAS 冲突不覆盖 |
| 卸载 | 插件、预期当前包、是否清除数据 → 操作快照及实际终态 |

新增原包流上传与配置文件流上传路由；原包流只认已接纳且属于当前用户的 operation key，不接受客户端绝对服务器路径。
配置上传按相对路径映射到受管 config/，防止链接/盘符/路径穿越，配置内容不进入事件或日志。
RuntimeEvent 增加插件操作/目录变化和智能体目录变化通知；复用现有事件序号与掉线快照重建，进度可合并丢弃而终态可回读。
命令 JSON 仍用既有 1 MiB 上限，但本地智能体创建/编辑/详情需专门评估最坏 JSON 转义后的 256 KiB prompt，建议仅该类命令提升到 2 MiB；不得全局无上限。
错误沿用 RuntimeErrorInfo 分类，增加明确插件不可用、来源冲突、Busy、取消、操作中断、配置缺失、能力缺失和中心能力不支持等可映射原因。

Desktop 的 SettingsStore 增加页面枚举；插件/智能体各自的 feature Store 只维护请求、表单和权威投影，不复制安装业务判断。
依赖弹窗复用 Dialog：receiving/downloading/verifying/installing/cancelling 时 `dismissible=false`，隐藏关闭入口并提供取消；失败/成功/已取消允许关闭。
重连查询进行中操作并恢复显示，不能把端上 HTTP abort 当作服务器取消。切换登录/目标清空旧域投影，迟到响应必须匹配当前连接上下文。
草稿增加可空智能体选择；移动仍遵循 C02 冲突规则，目标工作空间改变后重新核查能力和附件，旧准备结果不能覆盖新选择。
新会话快捷入口以本机 `ComposerDock/quick-actions.json` 为声明源。文件被 Git 忽略；开发预览存在时读取，通用版正式构建默认注入空列表。企业版构建设置 `EZ_ASSISTANT_DEFAULT_HOST_MODE=enterprise` 时自动嵌入本机模板；其他按需分发也可显式设置 `EZ_ASSISTANT_BUNDLE_QUICK_ACTIONS=1`。模板缺失时仍为空。单项可包含智能体名称及个人/中心来源、Skill 名称、MCP server key、模板和可选的原选择器入口。点击时先从当前 Host 目录解析所有固定引用，全部可用后才写入现有草稿；来源身份由实际目录确定，不在配置中写死中心 ID。异步查询结束后复核草稿 owner、用户编辑内容和连接，冲突时由统一确认弹窗处理，既不产生新的 Session 类型，也不将快捷入口配置传入 Runtime。
运行进度页面不展示内部路径/锁/数据库等实现细节；详细视觉和响应方式在下一步交互指导中确定。

## 十、归档依赖与安全校验

Host 已有 reqwest、sha2、tempfile、serde-saphyr、semver 和平台路径保护。锁文件含 flate2/crc32fast 的传递依赖，但 Host 还没有 ZIP/TAR 解析器。
拟为 Host 增加 tar、zip 和明确的 flate2/CRC 直接依赖，并补 Unicode NFC 校验依赖；不在 Runtime 增加归档、网络或数据库库。
官方文档核对的候选为 tar 0.4.46、zip 8.6.0；zip 8.6.0 声明 Rust 1.88，低于 Host 当前声明的 1.89。
zip 关闭默认特性，只选 Store/Deflate 所需 Rust 解压后端，不引入不接纳的加密/LZMA/Zstd 编解码；最终锁定、MSRV 与平台编译在实现准入验证，不把文档查询当作已构建通过。

TAR 顺序遍历原条目；ZIP 随机读暂存归档并遍历条目，均不使用无条件 extract/unpack。库提供格式解析，不代替 C01 安全策略。
特别是 `ZipFile::enclosed_name()` 允许归档内部的 `foo/../bar`，而 C01 禁止任何 `..`，因此仍须对原始路径做更严格检查，不能“规范化后看起来安全”就接纳。
统一复核：NFC/大小写冲突、重复路径、父子文件冲突、Windows 保留名、原始编码、PAX、ZIP64/偏移/重叠与实际解压长度/CRC；链接在完整索引验证后最后创建，Windows 声明包按 C01 要求不接链接。
Center 与 Host 共享语言无关正反样例：同一包的接受/拒绝必须一致，差异先定位契约而不是新增兼容回退。

外部依据：[tar Archive](https://docs.rs/tar/0.4.46/tar/struct.Archive.html)、[zip ZipFile](https://docs.rs/zip/8.6.0/zip/read/struct.ZipFile.html)、
[zip ZipArchive](https://docs.rs/zip/8.6.0/zip/read/struct.ZipArchive.html)、[zip Cargo/MSRV 与特性](https://docs.rs/crate/zip/8.6.0/source/Cargo.toml)。
资料获取时 Jina 超时，使用官方 docs.rs 页面完成核查；未安装依赖或改写 Cargo.lock。

## 十一、兼容、迁移与备份

- 当前软件与应用协议最低版本已经是 0.28.0，C03 沿用本版最终协议，不为循环单独升版。新增 DTO 的 Rust/TS 导出、Host dispatch 和所有消费者一起生成/校验。
- 当前数据库最低 Host 也已为 0.28.0；在同一 v0_28_0 迁移中加入新表和 sessions 可空列，保留前序 Workspace 迁移与校验，不为开发中间形态写补丁链。
- 正式升级从已发布库经唯一迁移入口、独立备份及事务进入最终 schema；当前本机开发旧版 0.28.0 试验库不能直接当最终 schema 使用。自动验收建新隔离 Home；用户现有开发数据如需续用，单独核查备份后制定一次性处理方案，不自动重建或覆盖。
- 同版开发旧二进制无更细的软件版本门禁，不能承诺可回退写入新增字段；联调必须配套 Host/Desktop，恢复按整套备份并使用匹配二进制。对已发布旧 Host 的拒绝仍由现有最低版本机制保证。
- 旧 Session 智能体为空不回填；Fork/Clear/恢复与会话投影验证旧字段兼容。旧中心不支持新能力时插件市场/中心智能体不可用，身份/模型维持原规则。
- Center 格式/API 保持 C01，Host 新运行目录变量是本方案运行约定，真实样例必须复验；若产生实际 C01 接纳语义变更，定向重开而不静默改写其契约。
- Host 备份需同时覆盖 SQLite、插件 config/data 和被引用包；先暂停插件变更并等待受管使用收敛，核验独立备份可读及关键表精确数量，再执行破坏性变更。任意外部程序持续写数据时不能声称获得一致备份。
- 所有测试只用项目 `.runtime-test/` 下新场景；不访问或清理 `~/.ez-assistant`，不写 C01 固定手工测试库。本轮没有数据库操作。

## 十二、验证范围、风险与确认点

| 核心风险 | 必须覆盖的验证 |
| --- | --- |
| 包解析与跨语言一致 | ZIP/TAR.GZ、多平台运行时、相对链接、畸形/超限/CRC、目录逃逸、Center/Host 相同样例 |
| 生命周期 | 上传/下载/解包取消、提交与取消竞态、断线重连、重启前后每个发布点、正常终态无过程残留、批次逐项清理、清理失败不阻止其他包操作且自动恢复、跨用户 key 拒绝 |
| 能力管理隔离 | 插件包内不能单项编辑/删/关；普通刷新不丢插件；独立开关不污染插件；同名和 Workspace 后加冲突 |
| 会话冻结 | 选择后中心变化自动处理、变化增依赖需确认、同 key 重试不换 prompt、Fork/Clear/恢复/压缩保留配置 |
| 来源与秘密 | 中心空列表/失败/401/旧登录迟到、同名来源保留配置、脱敏字段更新、任意配置文件原样保存且不进入普通搜索、双窗口 CAS 冲突和重启后重读 |
| 更新与卸载 | 受管活动 Busy、旧版本准备失败保留、能力运行故障独立展示、默认保留和显式清除、残留文件与 DB 状态分开 |
| 实机运行 | 自包含 CAD 等代表性包无需预装语言运行时，缺专业软件诊断；macOS arm64、Windows x64/arm64 及声明支持 Linux 的相应包按产品发布矩阵执行 |

最小开发验证先走受影响模块；跨 Runtime/协议/并发的里程碑收口执行规范要求的 `cargo fmt --all --check`、workspace clippy/test、协议投影校验和 Desktop build，必要平台与真实进程补定向验收。
方案编制阶段只做源码/依赖/契约及文档检查；后续 M0—M4 的实现和验证结论记录于[开发计划](开发计划.md)，不新增验证报告。

本稿需要审阅的主要取舍：三个定向目录变量与原生配置上传入口；生效包/操作收据的最小持久化；安装提交和运行故障的区别；脱管程序不在活动保护范围；同版开发库不自动迁移。
上述点是本轮基于实现核查给出的方案，不把“功能规则已确认”视为这些技术细节已获确认。
用户随后明确要求开始开发；M4 已完成内部验收，M5 实际插件联调仍待用户确认后开展。界面交互指导已补齐；C01/C02 原收口状态不因此改写。
