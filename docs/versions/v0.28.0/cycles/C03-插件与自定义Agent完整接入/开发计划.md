## 二、台账原则与实施边界

按“包可信接收 → 安装生命周期 → 真实能力 → 智能体执行 → 产品交互 → 循环验收”依次推进。
每个里程碑形成可检查的实际结果并完成必要验证。用户先授权 M1—M4 连续实施及中间自验，随后明确要求继续 M5 实际插件联调；该授权不包含提交、推送或发布。

- 复用当前 Runtime 用户域、Store、任务管理、MCP Registry、Skill Catalog 与首次发送链路；不新增执行引擎、独立插件进程或第二套能力管理。
- 独立 Skill/MCP 与插件分开管理；插件整体启停，对同用户会话可用，内部能力不可单项编辑、删除或启停。
- 插件原生配置格式自行定义；包、配置、运行数据分离。外部软件路径由插件首次调用时发现并写入自有配置，Host 只向所属本地 MCP 进程提供配置目录；确需 Host 装配的连接参数仍按技术方案处理。
- M0—M3 通过正式 Host/Runtime 入口及隔离场景验证，界面集中在 M4 接入；不把测试适配器通过等同产品可用，不提前展示空功能入口。
- `.staging` / `.trash` 随操作收尾，批次逐包清理；清理失败保留诊断并自动重试，不全局阻止其他包操作，也不把残留当缓存长期堆积。
- 安装提交与运行故障、活动使用保护、同版开发库处理依技术方案评审结果执行；影响 C01 契约或 C02 恢复语义时定向更新设计并确认。
- 自动化和故障注入仅使用项目 `.runtime-test/` 下新场景与已核实非生产数据，不访问用户 `~/.ez-assistant` 或 C01 固定手工测试库。数据库写入仍遵守备份、事务、异常停止及实际结果核验要求。
- 计划只保存里程碑状态、完成结论和确认；验证过程不堆入流程文档，不另建验证报告。

## 四、分里程碑实施与验证

### M0 包校验与用户存储基础

- **目标**：建立可信包输入与用户归属，后续安装只消费已校验内容。
- **前置**：用户已明确要求先启动 M0；Rust 编程/架构规范与相关模块约束已读取，C01 实际包契约和当前工作树已复核。交互指导和前序循环收口仍按台账跟进。
- **交付范围**：Host ZIP/TAR.GZ 解析与限额、平台入口及完整清单校验；受管目录和私密配置路径保护；插件/操作最小存储、SQLite 与易失 Store 一致性及本版最终迁移。按真实调用接入所需领域端口，不建立空公共框架。
- **验证入口**：Center/Host 同一组正反包样例；真实文件解包、链接/路径/大小/CRC 边界；插件 Store、迁移、失败回滚和重启读取定向测试。新增归档依赖核对许可证、MSRV、特性及目标平台编译可行性。
- **完成判定**：两种合法包可独立复核，异常包不进入生效目录，跨用户路径不可串用；旧版本隔离库可安全升级，失败不开放不完整状态。此时不宣称完成安装或能力运行。
- **Review 重点**：C01/Host 准入是否一致、文件与数据库权威边界、路径安全、资源上限、未发布 v0.28.0 schema 与既有开发库的区分。

### M1 安装、更新与卸载生命周期

- **目标**：完成正式 Host 上从接收包到提交、取消、恢复和清理的闭环。
- **前置**：M0 确认；核对用户域任务 owner、Streaming Upload、SSE 和中心身份适配。
- **交付范围**：个人流式上传、企业市场/resolve/条件下载；安装与更新操作、精确包确认、进度查询/取消及幂等收据；发布提交、默认保留数据的卸载、显式清除和重启恢复；包活动使用门及运行投影接入边界供 M2 使用。补齐正式应用协议与 TS 投影。
- **验证入口**：隔离正式 Host 接收真实包；隔离中心执行发现、下载、来源隔离和废弃状态；在网络中断、取消与提交竞争、进程重启、文件发布/清理故障点验证实际状态，覆盖跨用户操作 key 拒绝。
- **完成判定**：相同操作不会重复提交，准备失败保留旧版；正常终态无过程内容残留，批量逐项收尾，清理失败留存诊断但不阻止其他包变更，应用自动重试恢复。断线不误报取消或成功；安装完成与尚未验证的能力就绪明确区分。
- **Review 重点**：DB 与文件不是同一事务、已提交批次项不倒退、任务真正停止后才清理、关闭/登出取消、残留归属不明时停止而非猜测删除。

### M2 插件 Skill/MCP 真实接入

- **目标**：让已安装插件通过原有 Skill/MCP 体系真实运行，并与独立能力分开管理。
- **前置**：M1 确认；核对全部 Registry refresh、Catalog 扫描、工具调用与受管子任务生命周期入口。
- **交付范围**：插件来源及管理范围投影、统一候选组合、同名冲突与名称依赖；整体启停、必要连接参数、任意格式配置文件原子上传及过期覆盖保护；目录传递、部分能力故障诊断；Run 及受管使用保护接入更新/卸载，保留现有权限与审批。移除 Host 软件路径事实和 `${software.*}` 启动依赖的收敛工作需同步处理现有 C01 包契约。
- **验证入口**：隔离 Host 实际启动自包含 stdio MCP、连接受控远端 MCP、加载 Skill 并执行；覆盖普通刷新/重启不丢插件、冲突不冒充依赖、双窗口配置冲突、禁用与在途调用、长 Run/子任务下更新卸载 Busy。
- **完成判定**：独立配置不被插件改写；包内单项写操作在服务端拒绝；整体禁用阻止新使用且不热删除活动文件；缺参数或局部故障准确投影，配置/数据跨更新和默认卸载保留。
- **Review 重点**：没有第二套 Registry/Catalog、来源不靠路径猜测、秘密不进入普通文件搜索/事件/提示词、锁顺序和连接退役、脱管程序边界如实表达。

### M3 智能体配置与首次发送

- **目标**：完成个人与企业智能体的来源、依赖准备及会话冻结，不破坏 C02 草稿和幂等恢复。
- **前置**：M2 确认；核对 Center 完整目录接口及全部 Session 创建、Fork/Clear、恢复和压缩消费者。
- **交付范围**：本地配置 CRUD、企业目录及来源失效处理；依赖归组与确认清单、已安装复用、禁用/缺参/缺软件诊断；首次发送前自动核对，新增缺包仍需确认；持久冻结完整配置和提示词，原物化 key 优先回读。此阶段补齐智能体表与 Session 快照迁移及协议消费者。
- **验证入口**：本地与受控中心来源定向测试；正式 Host 物化与恢复场景，覆盖选择后修改/删除、空目录/断网/身份失效、旧登录迟到、发送结果未知、同 key 不同意图和重启；核对 Fork/Clear/压缩后的冻结内容。
- **完成判定**：使用实际检查过的同一配置创建会话；新下载不静默授权，安装完成不自动发送；同 key 重试不重复创建或改用新提示词，旧会话不随来源变化改写；默认依赖不成为工具白名单。
- **Review 重点**：用户意图与服务端当前配置的区分、来源覆盖不回退、没有新的草稿/执行引擎、长网络操作不占 Session 写锁。

### M4 Desktop/Web 产品交互

- **目标**：在 C02 现有壳层和 Composer 中交付完整插件与智能体使用入口。
- **前置**：M3 确认；C03 界面交互指导已确认且与当前接口一致，复用现有设置页、Dialog、草稿与连接上下文管理。
- **交付范围**：独立插件/智能体设置页、个人上传与企业市场、详情/配置/整体启停/更新/卸载；本地智能体编辑和企业只读详情；新会话选择及管理入口；依赖确认与真实进度弹窗、取消收尾、失败重试/清理入口；重连恢复和账号/Host 切换隔离。
- **验证入口**：Store/组件测试与正式 Host 上 Desktop/Web 操作；重点核对鼠标、Esc、遮罩、焦点、中文输入、窄窗口，及下载中断线/重连/取消/清理失败。原生弹窗与 child WebView 遮挡按受影响路径实机核对。
- **完成判定**：用户可从入口独立完成主要流程；执行中不可直接关闭但可取消，终态可退出；安装与能力就绪不混淆；切换智能体/工作空间保留草稿，迟到结果不覆盖新选择，安装/配置后不自动发消息。
- **Review 重点**：UI 不持有权威安装状态、没有空入口、参数秘密不回显、操作范围清晰、Web/远端路径均指向目标 Host。

### M5 实际插件联调与循环验收

- **目标**：证明从中心发布或个人上传，到选择智能体、准备依赖和真实执行的完整链路可用。
- **前置**：M4 确认；使用新的隔离 Center/Host、可分发素材和可重现的代表性包，保持 C01 固定手工环境不动。
- **交付范围**：核对代表性插件包包含自有运行时并具备可分发性；同一完整包走个人上传和企业分发；核验插件首次调用自行创建配置、发现外部软件、路径失效后重新检查，以及自动发现失败时的指引；实际 Skill/MCP 工作流、原生配置、更新/卸载/重装与故障恢复联合验证；同步模块约束、循环完成结论和跨循环交接。
- **验证入口**：按功能设计第七节与总体设计 A04—A12 对照验收，并回归受影响的 C02 草稿/工作空间和 C01 分发契约；执行真实进程及已声明支持平台验证。受专业软件安装限制的 CAD 场景明确所需平台与环境，不以模拟工具替代实际执行结论。
- **完成判定**：核心链路无占位，临时目录不随重复操作累积，配置保留/清除与来源隔离均可观察；已覆盖平台与未覆盖风险清楚列明，用户确认循环验收后才进入阶段收口和跨循环版本验收。
- **Review 重点**：不将上传/安装成功当运行成功、不将某平台成功推广到全部平台、不将 C03 验收当版本发布；分发前核对 MCP 源码、解释器与依赖库的再分发许可，不补写未执行结果。

## 五、验证命令与循环完成条件

命令按受影响范围选择，测试过滤器使用实施时实际测试名，不在计划中虚构用例。各阶段优先执行相关包定向测试；跨 Runtime/协议/并发的阶段收口执行规范要求的工作区检查，已有有效结果可复用，变更或新风险才扩大重跑。

| 范围 | 验证入口 |
| --- | --- |
| Rust 定向 | `cargo test -p assistant-protocol`、`cargo test -p assistant-runtime`、`cargo test -p assistant-runtime-host`，按阶段选相关测试 |
| Rust 阶段收口 | `cargo fmt --all --check`、`cargo clippy --workspace --all-targets --all-features -- -D warnings`、`cargo test --workspace` |
| 协议与前端 | 在 `apps/desktop` 执行 `npm run check:protocol`、`npm run lint`、相关 `npm run test -- <实际测试路径>` 和 `npm run build` |
| 正式界面联调 | 在 `apps/desktop` 按实际场景选择 `npm run test:e2e`、`npm run test:e2e:web`、`npm run test:e2e:enterprise`；先核对目标均为新隔离环境 |
| 原生及平台 | 涉及原生构建执行 `npm run tauri -- build --no-bundle`，并在相应平台核对真实进程、路径权限与窗口交互 |

C03 完成条件：M0—M5 各自获确认；功能设计验收口径逐项有明确结论；实际包执行、安装恢复、用户数据归属、旧会话兼容和平台边界已交接；未完成项不得标为通过。
循环验收后按总台账完成提交准备和阶段归档，再进入 v0.28.0 跨循环验收；Git 动作和发布均需对应明确授权。

M0 完成结论：Host 独立校验 ZIP/TAR.GZ 并仅在隔离目录解包；用户域插件目录的私密文件与过程目录受普通文件能力保护。插件/操作事实已通过类型化 RuntimeStore 接入 SQLite 与易失实现，操作相位和插件行同事务提交；v0.27.0 隔离库升级、独立备份校验、失败回滚及重启恢复通过。Center/Host 同包准入对照发现并修复 C01 TAR 符号链接误拒，合法与越界样例结果一致。M0 仅完成准入与存储基础，正式安装 owner、过程目录收尾和能力运行属于后续里程碑；当前开发机验证为 macOS，Windows/Linux 实机边界保留。

同为未发布 `0.28.0`、但在本轮插件表加入前已记账的开发库不能当作旧版本自动升级；现有准入会拒绝缺表结构，不能静默补表或改写用户目录。后续实际启动或迁移这类开发库前，必须先核对具体库、独立备份并制定显式兼容处理；本轮未访问用户 `~/.ez-assistant`。
