## 三、目标架构与模块归属

```text
Admin ── OpenAPI 生成请求 ── Center HTTP
                               ├─ agents：可复用配置与审计
                               └─ plugins：发布目录、包校验/文件、分发
                                         ├─ 同一 PostgreSQL
                                         └─ 独立受保护包目录
C03 Host ── 同一 Bearer 身份 ── runtime/agents、runtime/plugins
```

新增 `src/agents/` 和 `src/plugins/`，分别承载配置生命周期和包发布生命周期，采用现有 Controller/Service/Repository/Entity 布局。
包解析与文件 owner 位于 plugins 私有模块；不新增通用插件框架、执行器、共享业务 SDK、Worker 或消息队列。
必要请求/响应 DTO 放既有 `src/contracts/`；参数校验仍在业务入口执行，不靠 Swagger 注解做运行时校验。

Center 不执行上传内容，不探测目标 Host，不持有本地安装、密钥或 Agent 会话副本。C03 将包内 Skill/MCP 接入既有运行机制。

## 四、统一插件包契约

### 4.1 归档与目录

2026-09-22 用户明确要求首版同时支持 ZIP 和 gzip 压缩的 TAR，两种格式使用同一份插件内容契约。

| 归档格式 | 扩展名 | HTTP Content-Type |
| --- | --- | --- |
| ZIP | `.zip` | `application/zip` |
| TAR.GZ | `.tar.gz` | `application/gzip` |

格式以实际文件签名和完整结构校验确认，不能仅信任扩展名或 MIME；声明与内容不符则拒绝，不自动转码或重新打包。
使用 UTF-8 文件名，归档直接包含以下根路径，不包额外的父目录：

```text
plugin.json
skills/<skill-name>/SKILL.md
skills/<skill-name>/scripts/…       # 可选
skills/<skill-name>/references/…    # 可选
mcp/<server-name>/server.json             # 共用配置，可选
mcp/<server-name>/server.<os>-<arch>.json # 需要时提供平台配置
mcp/<server-name>/…                 # 程序及其依赖
runtimes/<os>-<arch>/…             # 合包可按平台组织完整运行环境
resources/…                        # 共享只读资源，可选
licenses/…                         # 随包依赖许可证，可选
```

`plugin.json`、SKILL.md 和 server.json 必须是普通文件。至少有一个 Skill 或 MCP；清单声明与对应目录一一匹配，不接受未声明的可发现能力。
除这几个约定目录外不接受未知根入口；不定义安装脚本、postinstall、卸载脚本或远程依赖下载钩子。

两种归档统一允许普通文件、目录和包内相对符号链接（Windows 制品须由发布方展开链接）。拒绝硬链接、设备/FIFO、稀疏文件及非约定类型。ZIP 的 Unix 文件类型和权限取自其 Unix external attributes，符号链接目标取自有界条目内容，不能把链接按普通文件绕过路径检查。
相对链接允许完整 POSIX 运行时保持原布局，但需在完整文件索引上解析：不逃逸根、不循环、不悬空、不通过链接写子条目；C03 最后创建链接。
禁止绝对路径、盘符/UNC、反斜杠、NUL、`..`、重复规范化路径和大小写/Unicode 规范化后的冲突；路径每项有界。
Windows 包另校验保留名、尾随点/空格、非法字符。PAX 仅接受路径、链接目标和时间/大小元数据，应用扩展后的最终路径再次校验。
文件权限只保留普通读写及执行位，忽略 owner，拒绝 setuid/setgid；C03 不恢复包内用户/组或宽于受管目录的权限。ZIP 未携带 Unix mode 时按普通文件/目录的受管缺省权限处理；POSIX 制品中需执行的运行时入口必须携带执行位，不能安装后对整个包递归 chmod。

ZIP 支持 Store/Deflate 与限额内的 ZIP64；不支持加密、分卷、自解压前缀或其他压缩方法。使用 central directory 定位条目，校验条目边界、实际解压长度及 CRC-32；UTF-8 名称声明或有效 Unicode 路径字段按规范解析，纯 ASCII 名称可无 UTF-8 标记，其余旧编码名称拒绝。数据描述符和 ZIP64 不得绕过大小检查，不能只按头部声明计数。

中心先将上传流完整暂存，再按识别格式扫描条目并读取受限描述文件，不把包解压到中心目录。ZIP 从暂存文件随机读取目录、逐条流式解压校验；TAR.GZ 顺序扫描。两者均不把整包加载到内存，原始压缩包完整保存并计算 SHA-256；C03 对原始字节再次核对并执行相同解包校验。

### 4.2 根清单

```json
{
  "format_version": 1,
  "name": "document-tools",
  "display_name": "文档工具",
  "description": "读取和整理文档",
  "version": "1.0.0",
  "platforms": [
    { "os": "macos", "arch": "arm64" },
    { "os": "windows", "arch": "x64" }
  ],
  "min_host_version": "0.28.0",
  "skills": ["document-review"],
  "mcp": ["document-reader"],
  "configuration": [
    { "name": "api_token", "label": "服务令牌", "required": true, "secret": true }
  ],
  "external_software": []
}
```

| 字段 | 校验/含义 |
| --- | --- |
| format_version | 固定 1，未知格式拒绝；这是外部包格式，不是数据库或修改纪元 |
| name | 稳定引用名称，1–64 ASCII 字符，小写字母/数字/单连字符，首尾无连字符；不加架构后缀 |
| display_name / description | 用户显示名和说明，分别最多 128/4096 Unicode 字符；引用使用 name；中心可单独调整展示文案 |
| version | 严格稳定 SemVer `major.minor.patch`，每段非负安全整数，无前导零；本版不接预发布/构建后缀，不按字符串排序 |
| platforms | 必填、非空且不重复的平台权威列表，os 为 macos/windows/linux，arch 为 x64/arm64；该版本只向列表中的目标 Host 提供，中心逐项校验包内对应或共用入口 |
| min_host_version | 严格三段版本；依赖已有 Host 软件版本准入，不引入第二套版本范围求解 |
| skills / mcp | 名称列表，可空但不能同时空；同类不重复；Skill 沿用 SkillName，MCP 沿用 McpServerKey 校验 |
| configuration | 用户输入的字符串配置声明：name、label、required、secret；不含默认秘密或真实账号；name 使用 MCP 名称键语法 |
| external_software | 每项为 name、display_name、instructions、可选 download_url 和可选 platforms；name 唯一，指引最多 4096 字符，URL 只允许 http/https，中心不访问；platforms 必须是根 platforms 的非空子集，缺省表示适用于全部声明平台 |

外部软件配置由 C03 提供执行文件路径输入；清单不能提供自动执行的探测或安装命令。显示指引无需先运行 Agent。
平台 ABI、最低 OS 和所需专业软件版本写入说明，发布方负责制品兼容；`min_host_version` 不能证明操作系统 ABI 可用，真实运行归 C03 验证。
一个插件版本只保存一个当前完整归档，`platforms` 是该归档的权威支持范围；不再从上传 query 手动勾选平台，不允许同一版本并列多个平台包，也不做跨包公共字段比较。归档可以只支持一个平台，也可以在 `runtimes/<os>-<arch>/` 和平台 MCP 配置中同时携带多个平台内容。
中心对 `platforms` 中每一项检查对应或共用 MCP 配置、入口和所需运行时。任一声明平台无效时整个归档拒绝，不部分接纳；归档未声明的平台不进入该版本支持范围。包内所有平台共用同一组 `name/version/display_name/description/min_host_version/skills/mcp/configuration`，平台差异只能存在于入口、运行时、资源和适用外部软件说明。
中心的可编辑展示文案与包原文分开；首包用于初始化，后续上传不能反向覆盖管理员已经编辑的中心文案。

#### 4.2.1 同版本重传与不同版本差异

每次上传归档都必须完整读取 `plugin.json`、Skill/MCP 入口、相对路径、各声明平台运行时和资源，完成格式签名、路径安全、限额、清单、入口存在性和 SHA-256 校验。一个版本当前只引用一个通过校验的原始归档及其解析结果。

同名同版本重传按原始 SHA 处理：

- SHA 相同：返回 unchanged，不重复写文件或业务记录。
- SHA 不同：允许用新归档替换该版本的当前 `archive_format/sha256/size_bytes/manifest`；新包必须先完整校验，失败时保留原记录和原文件。

此可变规则服务于测试阶段频繁上传。中心不判断该版本是否已被客户端安装，不保存同版本历史归档，不生成内容修订号，也不比较新旧包内部差异。上传者需自行注意已分发版本；正式交付后建议递增 SemVer，但服务端不强制。替换成功后新发现和新下载取得新归档，已经完成的下载及已安装内容不变；C03 暂不检测同版本 SHA 变化、不提示同版本更新，也不自动重装。

不同版本允许改变 Skill/MCP 集合、配置声明、最低 Host 版本、支持平台、目录和入口，但每个版本必须由自己的单一归档完整自描述；既有 Agent 名称引用不会因此改写。`resolve` 必须以目标平台、Host 版本和调用方要求的 Skill/MCP 名称过滤候选版本，不能只因版本号更高就返回一个不再满足依赖的新版本。

### 4.3 Skill、MCP 与路径装配

Skill 保留原格式：目录名、frontmatter.name 与清单名称一致，description 非空且不超过 1024 字符；文件不超过 256 KiB，frontmatter 不超过 32 KiB。
不扩展 SKILL.md 为插件配置语言，不替换提示词内容。脚本通过技能所在目录的相对布局定位包内运行时，不能假设任务 cwd 是插件目录；作者应在技能说明中明确调用相对技能文件的位置。
C03 继续提供实际技能文件位置、按需读取与现有 Shell；不为 Skill 引入单独的脚本执行通道。带脚本的 Skill 同样必须附带其所需环境。

每个 MCP 至少提供一份配置：按 Host 的 `<os>-<arch>` 优先读取 `mcp/<name>/server.<os>-<arch>.json`，没有时读取共用 `server.json`；不合并两份配置、不增加继承规则。配置使用既有 `mcpServers` 包装，且只有对应的一个名称键，例如：

```json
{
  "mcpServers": {
    "document-reader": {
      "command": "${plugin_root}/runtimes/macos-arm64/node/bin/node",
      "args": ["${plugin_root}/mcp/document-reader/main.js"],
      "cwd": "${plugin_root}/mcp/document-reader",
      "env": { "SERVICE_TOKEN": "${config.api_token}" }
    }
  }
}
```

- 本地 command 必须定位包内可执行文件，或完整引用 `${software.<name>}` 对应的专业软件；不能写 `node`、`python`、`npx`、`uvx` 等系统搜索/安装入口。脚本解释器及库由包内程序自行按相对布局定位。
- 占位符只支持 `${plugin_root}`、`${config.<name>}`、`${software.<name>}`，由 C03 确定性展开一次，无 Shell 求值、环境变量继承模板或递归展开。
- plugin_root 仅用于 command/args/cwd/env；config 只用于 env/headers，不允许秘密进入命令行或 URL；software 用于 command/args/env。
- cwd 缺省为插件根；声明时必须在包内。需要读写用户文件的 MCP 通过现有工具参数和工作空间上下文取得位置，不能把发布方机器路径写入包。
- 远程服务沿用 url/headers 与 streamable-http，不同时出现 command/url。URL、保留 header、超时和大小校验沿用现有 MCP 规则；不开放旧式 SSE 或新传输。
- server.json 不声明用户级 enabled，也不携带授权策略；C03 安装后沿用默认启用规则及原有禁用事实，Agent 默认项不覆盖显式禁用。
- 用户配置只写入当前用户域的运行配置；包目录保持不可变。Skill 需要秘密时通过其声明的 MCP 服务使用，本版不向通用 Shell 全局注入插件秘密，也不将秘密替换进技能文本。

中心对 `platforms` 声明的每个平台检查对应或共用 MCP 配置能解析、占位符有声明及入口存在；声明平台缺少入口则整个归档拒绝。中心不会访问远程 MCP、执行程序或证明所有系统 ABI 兼容。完整包整包下载/解压，Host 只加载自身平台配置，不启动其他平台程序；首版不裁剪安装内容。声明 Windows 的包需遵循 Windows 路径及无符号链接要求，发布方可提前展开 POSIX 运行时链接。

### 4.4 包大小、依赖与一致性

两种格式共用本版固定上限：压缩包 2 GiB、解压字节总计 8 GiB、单文件 2 GiB、条目 100000、规范化路径 1024 UTF-8 字节；plugin.json 1 MiB、单 server.json 256 KiB、Skill/MCP 各不超过 256 项、配置/外部软件各不超过 128 项。
这些是资源限额，不表示实际平台已验收；与完整运行时的代表性包一起验证，不能只测空壳示例。

TAR.GZ 解析拟新增直接依赖 `tar`，使用其流式 list/Parse 能力与严格错误模式，不调用自动解包入口；不自写 TAR 格式解析器。
其官方文档明确提供流式条目和严格警告处理，文件路径政策仍由产品单独校验，见 [node-tar 文档](https://github.com/isaacs/node-tar)。
ZIP 解析拟新增直接依赖 `yauzl`，从暂存文件读取 central directory，启用 lazyEntries、validateEntrySizes 和 strictFileNames，逐条消费解压流；它不自动核对 CRC，需用 Node 24 的 zlib.crc32 按 chunk 计算并与条目声明比较，见 [yauzl 官方文档](https://github.com/thejoshwolfe/yauzl)。两种解析结果在 plugins 私有模块归一化为同一条目校验流程；共用路径、类型、限额及清单检查，不创建通用归档框架。
YAML 使用 `yaml` 的受限文档解析，禁用自定义标签和别名扩张，并与 Host 解析规则用相同样本交叉检查，见 [YAML 文档](https://eemeli.org/yaml/)。
版本比较只处理上述三段整数，无范围运算，不新增 semver 求解库。Node 的 crypto/zlib/stream/fs 承担散列、gzip/Deflate、CRC、背压和文件操作。

当前 Center 未直接依赖归档/YAML 解析库；实现时添加直接依赖、锁定精确发布版本并检查其传递依赖和发布记录。
已核查 node-tar 官方源码包版本为 7.5.22，但不将仓库版本当成已验证可安装版本；锁文件和生产打包是落地门禁。
`package:docker` 当前拒绝目标平台原生依赖；新增库应保留纯 JS 生产依赖，不能为图省事删除该门禁。

## 五、Agent 配置契约

```json
{
  "name": "文档审阅助手",
  "description": "按团队要求审阅文档",
  "prompt": "完整提示词长文本……",
  "skills": [{ "name": "document-review", "plugin": "document-tools" }],
  "mcp": [{ "name": "document-reader", "plugin": "document-tools" }]
}
```

Agent name 支持中文，NFC、无控制字符、无首尾空白，1–64 Unicode 字符；创建后不原位改名。描述最多 4096 字符。
prompt 非全空，UTF-8 不超过 256 KiB，保持正文原始换行和空格，不做 trim 后保存或自动改写。每类默认列表最多 256 条。
引用去重按同类能力名；同一 Agent 不能同时要求两个不同插件的同名同类能力，因为既有目录只允许一个生效来源。
有 plugin 时名称表示所属插件；无 plugin 时仅查 Host 既有能力，不进行同名插件猜测安装。

服务端校验名称和结构。初次新加中心插件引用应在中心至少一个已上传版本中找到能力，否则拒绝该新引用；下架、目标平台缺包只返回诊断。
编辑时保留已有但已不可用的引用并警告，不能因为依赖后来变化就强迫删除默认项。无 plugin 的引用允许保存并标为待 Host 核对。
中心不保证版本号最高的完整包一定包含依赖；C03 安装解析传递 required_skills/required_mcp，按目标平台和所需名称过滤候选版本，不能下载后假定依赖已满足。

所有有效保存项直接进入企业列表。企业模式使用完整返回列表，包括有效空列表，不合并本地；Session 快照及来源覆盖在 C03 实现。
本循环不增加模型、Plan/Build、权限、记忆、工具白名单或 Agent 配置版本历史。

## 六、中心存储、发布顺序与并发

### 6.1 必要业务数据

拟追加 `src/database/migrations/003-agents-and-plugins.sql`（实施前核对迁移序号是否仍空闲）：

| 表 | 主键及主要字段 | 理由 |
| --- | --- | --- |
| custom_agents | name 主键；description、prompt text；skills、mcp jsonb；created_at/updated_at | 可复用整体配置，与模型/身份无从属关系 |
| plugins | name 主键；display_name、description；publication（unpublished/listed/deprecated）；created_at/updated_at | 发布身份和当前上架事实；区分从未上架与已废弃 |
| plugin_packages | 联合主键 plugin_name/version；manifest jsonb、archive_format（tar_gzip/zip）、sha256、size_bytes、created_at/updated_at | 每行表示一个版本当前唯一完整归档；manifest 内含权威平台范围，同版本重传可替换该行 |

不新增 plugin_versions 表：版本没有独立审核/生命周期，当前包记录已经承载版本事实；不增加平台映射表、包修订号或同版本历史表。
引用不设到插件/能力的强制外键，避免依赖下架/变化阻止配置读取；package→plugin 使用 FK 保证归属。
name 使用精确、区分大小写的身份比较；已有 ASCII 名称不能做有损重命名。byte size 用数据库 bigint，API 在限额内为安全整数。
时间字段只用于展示/审计，不作为排序版本或并发令牌。审计沿用 management_audit，target_id 留空，details 使用名称、版本、支持平台、结果及替换时的新旧 SHA 等固定脱敏信息。

### 6.2 文件存储与发布

新增 `CENTER_PLUGIN_ROOT` 绝对路径配置，默认 `<cwd>/data/plugins`，容器部署显式挂载 `/data/plugins`；与 Admin 静态目录、调用快照目录互不包含。
启动前校验目录权限和真实路径，不跟随被替换的目录链接。根目录只允许中心进程用户写入，不提供静态路由。

```text
<plugin-root>/staging/<random>.part
<plugin-root>/packages/<sha256>.tar.gz   # TAR.GZ
<plugin-root>/packages/<sha256>.zip      # ZIP
```

散列是文件完整性/内部寻址，不是插件依赖 ID；同名同版本重传不会改变 Agent 名称引用。不维护单独 blob 表、包修订历史或下载令牌表。
同一内容重复上传复用文件；不同内容以新 SHA 发布为独立文件，绝不覆盖旧 SHA 文件。文件写入、close/sync、同文件系统不可覆盖发布完成后，才在事务中将版本记录指向新 SHA。

1. HTTP 收正文前校验管理员，独立临时文件按 chunk 写入并计数；不将整个包聚合到 Buffer。
2. 接收完成后有界扫描包，计算原始压缩包 SHA-256、检查实际 ZIP 或 TAR.GZ 结构、能力声明、权威平台列表和每个平台入口；任一项失败关闭句柄并处理本次临时文件，原版本记录不变。
3. 校验通过后先将新 SHA 文件在数据库事务外不可覆盖地发布完成；同 SHA 文件已存在则复用。此时仍未改变对外版本记录。
4. 在身份 `write` 短事务中重验管理员和现有元数据。同名同版本同 SHA 返回 unchanged；SHA 不同则将该版本记录和审计一起更新为新 manifest/SHA/格式/大小。两个并发上传按进入短提交段的顺序生效，后提交者成为当前包。
5. 新插件 publication=unpublished；已有插件保留状态。成功返回名称、版本、支持平台、原包校验信息和 result（created/replaced/unchanged）；replaced 明确提示同版本内容已变化且客户端不会收到同版本更新。
6. 数据库提交成功后，旧 SHA 文件可能成为无引用完整文件；不在请求内删除，避免破坏已经准入的下载或提交结果不明时误删。后续只允许显式维护核查引用后清理。

文件发布与数据库事务无法整体回滚。失败后可能留下无元数据的完整孤儿文件；不可下载，不立即删除可能仍被下载或被其他记录引用的文件。
提交结果不明沿用身份失效规则，禁止自动重发/自动删文件；重新登录后按名称和版本读取当前 SHA 确认。

| 中断位置 | 对外事实与恢复 |
| --- | --- |
| 临时文件未完整 | 无 package 新值，不可发现；关闭后清理本请求临时文件 |
| 校验完成、尚未 DB 提交 | 当前版本不变；可能留完整孤儿包，只允许显式维护核查后清理 |
| DB 提交完成、HTTP 回包丢失 | 查询可见当前 SHA；重传同 SHA 返回 unchanged，不能宣称取消已回滚 |
| 已引用文件缺失/大小或校验错误 | 该版本读取/下载报 PACKAGE_UNAVAILABLE，不能作为可安装候选；不自动下架整个插件、不标已废弃 |

中心启动在接纳流量前清理 staging 中自身遗留临时项，异常停止插件文件准入；不自动删除 packages 中无引用文件。
已发布文件的全量散列核验用于备份恢复/维护验证，常规读取检查文件存在、类型和长度，传输由 Host 对 SHA 复核；不在每次列表读取全量散列大包。

### 6.3 管理并发与状态

写入均复用 `IdentityService.write`，每次短事务内重验身份；上传接收/校验不占此串行段。
Agent 修改/删除、插件说明修改采用 HTTP If-Match：GET 返回由当前可编辑业务字段规范化计算的 SHA-256 ETag，不新增数据库 revision。
两个管理员/标签页编辑同一 Agent 是实际旧表单覆盖问题；单一提交队列不能识别过时读值，故条件写有明确消费者。
不匹配返回 412 `CONFIG_CHANGED`，保留表单、提示重新读取对照；缺少条件返回 428，删除后返回 404。身份变化首先返回 401/403。
刷新、重启根据现有值重算，恢复到同样内容仍可匹配；ETag 不承担跨实例同步、事件排序或安装版本，测试覆盖两个旧表单先后提交。
插件 ETag 包含可编辑展示字段和上下架事实，不因包上传而失效；上/下架请求也带条件，重复目标状态是无副作用 no-op。两个同名同版本异 SHA 上传都在短串行段按提交顺序替换当前记录，后提交者生效；Admin 明确展示最终 SHA，不增加上传 ETag、包修订号或锁定流程。
新建按名称唯一冲突返回 409。包发布使用 `plugin_name/version` 唯一键和 SHA 判断 created/replaced/unchanged，不叠加版本计数或持久幂等请求表。

新插件 publication=unpublished，上架变为 listed，下架变为 deprecated，重新上架变回 listed；对从未上架项重复下架保持 unpublished。单一发布状态区分未曾分发和已废弃，不叠加 ever_listed、deleted 或历史状态表。
依赖诊断按 Agent 名称引用现查，不建依赖图表或缓存。插件不提供永久删除，Agent 可删除。

## 七、HTTP 与 OpenAPI 契约

### 7.1 接口表

所有路径均在已有同一 Center 监听 `/api` 下，除 info 外使用普通 ct_ Bearer；不接受 Cookie、LLM key 或 URL token。

| 方法与路径 | 权限 / 请求 | 成功结果与用途 |
| --- | --- | --- |
| GET /agents | admin | Agent 摘要列表，不默认分页 |
| POST /agents | admin，AgentConfig | 201 AgentConfig，Location/ETag |
| GET /agents/:name | admin | AgentConfig 与当前依赖 diagnostics，ETag |
| PUT /agents/:name | admin，AgentConfig，If-Match | 200 当前配置；name 必须与路径一致 |
| DELETE /agents/:name | admin，If-Match | 204，只删除配置并记审计 |
| GET /plugins | admin | 含未上架/已下架的完整插件摘要 |
| GET /plugins/:name | admin | 说明、发布状态、每个 version 的当前完整包与包内支持平台、依赖 Agent 摘要，ETag |
| PUT /plugins/:name | admin，display_name/description，If-Match | 200 当前说明，不改包字节 |
| PUT /plugins/:name/publication | admin，listed，If-Match | 200 当前状态，首次上架须有有效包 |
| POST /plugin-packages | admin，application/gzip 或 application/zip 二进制 | 新版本 201；同版本替换或同 SHA 无变化 200；返回 created/replaced/unchanged、包内支持平台和当前 SHA |
| GET /runtime/agents | authenticated | 完整 AgentConfig 数组，空数组有效 |
| GET /runtime/plugins | authenticated | 仅在架的插件摘要，版本/平台支持；不下载包 |
| GET /runtime/plugins/:name | authenticated | 存在的插件状态 listed/deprecated/unpublished 与在架版本信息；未知 404 |
| POST /runtime/plugins/:name/resolve | authenticated，见下文 | 满足目标平台、Host 版本和能力名称的具体包，或明确无法选择原因 |
| GET /runtime/plugins/:name/versions/:version/package | authenticated，携带 resolve/detail 返回 SHA 对应的 `If-Match` | 在架版本的当前原始完整包字节；仅当前 SHA 匹配时准入，按 archive_format 返回 Content-Type/文件后缀，并返回 Content-Length、ETag、X-Plugin-SHA256 |

上述 name 路径参数必须单独 URL encode；后台 hash 路由可用查询参数，不能拿 display_name 拼物理目录。
resolve 是只读计算，无副作用：请求包含 `os/arch/host_version`、可选 `installed_version`、`required_skills/required_mcp` 名称数组（默认空）。
返回 `package`（name/version/platforms/min_host_version/archive_format/size_bytes/sha256）及 `update_available`；只有存在 installed_version 且候选版本号更高时为 true，同版本 SHA 变化不计更新。
按每个版本当前完整包的 `platforms`，从高到低选择支持目标 Host、满足最低 Host 版本且包含所有必需能力的版本；不自动降级已安装包，不处理同版本内容更新。
无候选返回明确原因 `PLATFORM_UNSUPPORTED`、`HOST_VERSION_UNSUPPORTED`、`CAPABILITY_MISSING` 或 `PACKAGE_UNAVAILABLE`；按平台→Host→能力→文件逐步过滤定位。下载时 `If-Match` 必须对应 resolve/detail 返回的包 SHA；若同版本已被替换且当前 SHA 不同，返回 412 `PACKAGE_CHANGED`，调用方重新 resolve 后再决定是否继续本次安装。这只保护正在进行的选包/下载，不构成已安装客户端的同版本更新检测。
已废弃返回 410 `PLUGIN_DEPRECATED`，从未上架返回 409 `PLUGIN_UNPUBLISHED`；目录详情的状态查询仍可成功区分两者。

API 错误沿用 `{error:{code,message,request_id}}`；参数 400、身份 401/403、名称不存在 404、冲突 409、请求过大 413、存储不可用 503。
业务响应声明有限错误码，不回显路径、数据库异常、包原始内容或秘密。SHA 用响应字段/头传递，不作为访问凭据。

Swagger 元数据继续是唯一 OpenAPI 源：所有新路由均由 Nest Controller 注册，upload 在同一 operation 中声明 application/gzip、application/zip 两种 binary body 和真实结果 DTO，不另外注册 raw handler。
已核查本地 Nest Fastify adapter：`@RouteConfig` 写入 Fastify `config`，不会直接设置顶层 bodyLimit。使用其路由配置标识正文种类（普通 JSON / Agent JSON / resolve JSON / 插件归档），初始化时 `onRoute` 将限额写入真实 route options，`onRequest` 据同一标记在正文解析前校验媒体类型、来源和身份。
为 `application/gzip` 和 `application/zip` 注册同一接收逻辑的流式 parser（不设置 parseAs），返回受控 payload stream；仅标为插件归档的路由可使用，其他路由在读取前拒绝这两种媒体类型。HTTP Content-Encoding 只允许缺省/identity，避免服务器透明解压改变原包散列。Controller 仍通过 Nest Guard，并由服务在提交段重验身份。没有第二份路由路径清单、双重注册或手写 OpenAPI schema。
离线 export 不初始化文件存储或数据库，只构造契约；无已准入依赖的运行请求明确 503。

### 7.2 流式接收、限额与关闭

包上传不使用 multipart、不新增上传会话/分片/断点续传；一次只传一份完整原包，支持平台完全取自受限 `plugin.json`，query 不再传平台列表。身份/来源在 onRequest 校验通过才读取正文。
解析器返回受控 Readable，由 Controller/Service 持有直到文件完成；正文中途错误统一销毁链路并释放资源。
接收结束后的结构扫描最多 5 分钟，整个上传/校验/提交最长 35 分钟；超时取消未提交工作，已提交结果不逆向撤销。普通管理路由仍只接受 JSON；Agent 写入 JSON 上限 2 MiB（容纳 JSON 转义后的长文本和默认项），prompt 自身另按解码后 UTF-8 256 KiB 校验；resolve 请求最多 64 KiB。其余路由继续 16 KiB。

Fastify 当前 server.requestTimeout=10000 是整段接收超时，单改 socket timeout 不能支持大上传。
本方案将底层接收超时改为适合包上传的 30 分钟上限，同时在普通 JSON 路由以请求级定时器保留原 10 秒正文接收约束；包上传路由采用 60 秒无进展/30 分钟总时限。
请求头保持有限接收时限；每条 timer 和取消句柄绑定 request，所有完成/异常路径释放，不能让旧请求 timer 影响 keep-alive 新请求。
LLM scope 维持其既有接收限额及执行空闲超时，必须补回归，不把普通接口一并无限延长。

最多同时接收/校验 2 份包，超额直接 429；最多 8 个包下载，背压写文件/网络，拒绝无限排队。
可用磁盘不足、中断、身份撤销、校验超限时明确终止；不能在失败后继续发布。代理/部署上传限制须同步至少允许本版包限额并具相应超时。
关闭时插件 owner 停止准入、取消传输和扫描、等待临时文件收尾，然后关闭 HTTP/业务池；沿用整体关闭入口，不另起常驻任务。

### 7.3 下载与下架竞态

下载准入在复用的短串行段中检查当前用户、publication=listed、包记录、请求 `If-Match` 与当前 SHA、受保护文件，登记绑定该 SHA 文件的下载取消句柄后流式发送；不在数据库事务内传输整个包。
下架事务成功后，在提交回调中取消该插件尚未完成的下载；后来的准入看到下架并拒绝。
已经发送给客户端的字节无法收回，已完成下载不假称可撤销；未完成下载断流，Host 必须检验完整长度及 SHA 才能进入安装准备。
同版本替换在新文件完整发布并提交记录后生效；替换前已经携带旧 SHA 通过准入的下载继续读取其旧文件，替换后的新准入必须携带新 SHA。尚未准入的旧 SHA 请求返回 `PACKAGE_CHANGED`。中心不取消旧下载，也不向已安装端发送同版本变化通知；旧文件在活动下载结束且显式维护确认无引用前不得删除。
上传中新包不会自动上架已经下架的插件；上传提交段读取当前状态，不能用接收开始时状态覆盖。
下载不开放 Range/断点续传/公开签名 URL，所有再次下载重新认证；旧链接无法绕过下架。

## 八、Admin 接入与跨循环交接

Admin 新增 Agents/AgentEditor、Plugins/PluginDetail 路由页面；UI 的具体布局和文案见交互稿。
后台名称路由、查询参数与异步请求捕获同一身份；页面卸载后丢弃响应，未保存 form 不写入 URL 或浏览器存储。
列表/详情沿用 useResourceQuery，生成 SDK 负责字段和接口；上传用生成请求的二进制 body，Axios onUploadProgress 仅反映传输进度，随后显示“中心校验中”。
已核查 Admin bootstrap 的 Axios 全局 timeout=10000；上传单请求改为 36 分钟（覆盖接收和校验），传入原 File/Blob、所选格式对应的 application/gzip 或 application/zip、发起时 Token 及 AbortSignal，不读成 ArrayBuffer/JSON。支持平台由包内清单提供。普通请求仍保持 10 秒，不能全局放宽。
ETag 从读取响应保存于表单局部 state，写入 If-Match；412 保留草稿并展示读取最新内容动作，不自动覆盖或重发。
取消上传是取消等待/传输，不保证服务端未提交；返回详情按名称、版本和当前 SHA 核对。用户核对后仍无法确认时，可关闭结果窗口并重新打开上传、显式重传同一原包；同 SHA 返回 unchanged，异 SHA 会再次替换当前版本，因此 UI 不自动重发，亦不能把未找到直接称作未提交。

后台下载需要携带 Bearer，不能用普通 a 链接或将 Token 写进 URL。下载使用现有生成请求与 Axios 的 fetch adapter、responseType=stream（已核查本地 adapter 支持），复用身份拦截器，并携带详情中当前包 SHA 对应的 `If-Match`；`PACKAGE_CHANGED` 时先刷新详情，不自动改下新包。请求层对实际 ReadableStream 做类型收窄，不手改 SDK。
点击后先在用户手势内调用 showSaveFilePicker，再发请求、检查状态/长度，逐块写入 FileSystemWritableFileStream；读取完且长度匹配后 close，失败/取消 abort，页面不宣称半文件已保存。按当前 Token 处理身份失效，单请求最长 35 分钟、无进展 60 秒，用户取消及页面卸载释放句柄。
文件保存 API 依赖浏览器能力和安全上下文，不能将它假定为所有浏览器都有，见 [浏览器官方说明](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)。缺少该能力时，仅对不超过 128 MiB 的包提供有界 Blob 下载；按实际读取字节再次限额，并释放 object URL。更大包显示“当前浏览器无法保存此大小的文件，请使用支持文件保存的浏览器并通过 HTTPS 或本机地址访问”。这仅限制 Admin 的手工下载，不限制管理上传或 C03 Host 流式安装；不新增 Cookie 鉴权、公开地址或 Service Worker 下载代理。
Admin 表示完整保存，不声称执行环境或 SHA 已在浏览器验证；SHA 供人工核对，C03 安装前必须自行流式散列校验原包。

C01 向 C03 固定交付：format_version=1 清单及 ZIP/TAR.GZ 两种包样本、能力名称语法、MCP 占位符、受保护下载、resolve 与状态错误语义、完整 AgentConfig。
C03 的个人上传与中心下载安装均同时支持 ZIP/TAR.GZ 及包内多平台布局。中心安装按版本当前完整包的 `platforms` 选择，个人上传面向当前 Host 使用；安装时独立校验归档、散列和当前平台入口，清单声明与入口必须一致。中心同版本替换不形成 C03 更新事件，只有后续显式下载才取得新 SHA。个人使用不新增平台发布目录；按 center_id 及来源类型区分本地上传。
中心不替 Host 决定原有 Skill 优先级，也不把成功下载当成 Agent 就绪；未知来源、同名冲突、用户禁用、配置和专业软件由 C03 给出实际状态。

## 九、兼容、升级与运维

Center 软件拟升 `0.2.0`，Admin 对应 `0.2.0`；与 Runtime 套件 v0.28.0 独立。企业协议保持 1/min=1，因为原接口未破坏且新增能力可显式检测。
实现并验收后新增 capabilities `managed_agents`、`plugin_market`；旧 Host 忽略新能力，C03 遇到旧 Center 缺少能力明确不可用，不回退个人列表。
包格式版本只管理清单可解释性；包内 SemVer 管理版本选择，但中心允许同版本替换当前归档；ETag 只保护旧表单条件写，三者不混用。

升级新增 SQL 表和 TypeORM 注册、counts 维护列表；现有迁移保持原样。旧 Center 发现新 migration 名称即拒绝准入，禁止用旧程序写新库。
回退须停写后恢复升级前独立数据库和匹配包目录，再运行旧二进制；不自动 down migration、删除新表或只回滚代码。
容器新增插件目录持久卷及环境变量，正式 assemble 不把用户插件复制进镜像或静态资源；备份停写并覆盖数据库与插件根。
恢复检查 package 每行对应文件存在、字节数及 SHA 一致，插件状态、Agent 名称引用与实际 API 一致；孤儿文件不能反向生成发布记录。

所有真实升级、备份、清理和恢复遵循根数据库规则：操作前核对主机/端口/库/表及实际读取入口，验证独立备份，异常停止并汇报。
本轮未对任何数据库执行操作，也没有宣称包目录备份已完成。

## 十、验证重点与最小新增核查

| 直接风险 | 实施时最小有效验证 |
| --- | --- |
| 包格式/入口/链接/压缩边界 | 分别用 ZIP/TAR.GZ 含运行时包检验；覆盖 ZIP64、CRC/长度错误、加密/分卷拒绝、格式伪装、符号链接/执行位、逃逸、重复及实际解压超限；中心无代码执行，原始字节未修改 |
| 单包多平台、同版本重传和名称引用 | 包内单/多平台声明、任一声明平台入口缺失整体拒绝、同 SHA unchanged、异 SHA 原子替换、替换失败保留旧包、不同版本能力筛选、无匹配平台和缺能力，验证不误选且不产生平台子包 |
| Agent 长文本与名称 | 临界字节、中文名称、整体 prompt 回读、空默认项、依赖变化和旧编辑 ETag 冲突 |
| 身份/发布/审计/文件一致 | 真实隔离 PostgreSQL 验证原子写、断开/提交未知、权限撤销、磁盘失败、半包和孤儿不分发 |
| 下载/替换/下架/关闭 | 同版本替换前后携带新旧 SHA 的下载准入、`PACKAGE_CHANGED`、已准入旧下载完成、在途下载下架取消、旧链接、重新上架、慢上传、管理 JSON 超时、LLM 原行为及 owner 清理 |
| Admin 正式业务 | 真实 API 流程、进度与校验分离、取消/未知结果、身份切换、412 保留草稿、列表不按架构拆分 |
| 部署/兼容 | OpenAPI 离线导出一致、SDK 生成/构建、生产依赖装配、新挂载、旧库升级/备份恢复 |

与现有自动化命令结合执行 typecheck/lint、相关 Vitest 和正式 Admin 构建；测试库与目录位于新建隔离场景，不操作用户现有数据。
C01 不执行插件运行环境，不以假 MCP 或中心校验替代 C03 的真实跨平台运行验证。验证结论进入循环计划，不单建报告。

新增事实仅为 Agent、插件和版本当前完整包；支持平台从包清单派生，依赖诊断从名称引用派生，上下架使用唯一发布状态，安装状态不属于中心。
仅包文件 owner 有传输生命周期，不增加后台队列/上传记录表；没有新 revision 列、通用配置同步层或跨工程源码共享。
实施与验收结论见[开发计划](开发计划.md)和[阶段总结](阶段总结.md)。C01 验证包格式、中心接纳和受保护分发契约；具体插件包的正式封装、Host 安装与实际使用由 C03 完成。
