## 二、现状、入口与导航

### 2.1 沿用现有页面体系

已核查正式 [PageLayout](../../../../../apps/enterprise-admin/src/app/PageLayout/index.tsx)、[路由](../../../../../apps/enterprise-admin/src/app/routes.tsx)、[导航菜单](../../../../../apps/enterprise-admin/src/app/PageLayout/NavigationMenu/index.tsx)、[服务商编辑页](../../../../../apps/enterprise-admin/src/features/models/ProviderEditor/index.tsx) 与 [请求读取 Hook](../../../../../apps/enterprise-admin/src/request/useResourceQuery.ts)。
继续使用 React Router Hash 路由、身份守卫、Ant Design、Card/Table/Form 及现有唯一离开拦截；不新建应用壳或弹窗管理中心。

| 入口 | 页面形式 | 路由与导航行为 |
| --- | --- | --- |
| 智能体管理 | 列表页 | `/agents`；新增侧栏菜单，放在模型管理之后 |
| 新建智能体 | 独立编辑页 | `/agents/new`；菜单仍选中智能体管理 |
| 编辑智能体 | 独立编辑页 | `/agents/edit?name=…`；名称按 URL 查询参数编码，支持中文，不携带提示词 |
| 插件管理 | 列表页 | `/plugins`；侧栏放在智能体管理之后 |
| 插件详情 | 独立详情页 | `/plugins/detail?name=…`；使用稳定插件名称，菜单仍选中插件管理 |
| 上传插件包、编辑插件说明 | 当前页面 Modal | 不增加路由或 history；关闭后返回原位置 |

保留用户管理、模型管理、调用记录、管理审计及账号入口。新路由继续位于既有身份守卫和 PageLayout 下；普通企业用户不获得管理导航，服务端仍独立判定权限。
页面刷新和浏览器前进/后退按 URL 读取中心事实；不存在的名称显示“智能体不存在”或“插件不存在”，提供返回对应列表的按钮，不展示空白编辑器。

面包屑依次为“企业中心 / 智能体管理 / 新建智能体（或编辑智能体）”以及“企业中心 / 插件管理 / 插件详情”。列表段可返回，当前段不可点击；返回、侧栏导航和浏览器后退均经过同一离开拦截。

### 2.2 状态归属

- 读取结果、筛选条件及加载失败态归各页面；列表完整读取，不默认增加分页、全局统计或轮询。
- 表单草稿、已选上传文件和弹窗开关只在当前页面内存；不放入 URL、Cookie、localStorage 或全局 Store。
- 所有管理写入使用现有 AdminStore 身份与写入门；详情、列表刷新走现有请求取消和代次守卫。
- 包状态、引用问题、当前版本以及上传完成以中心响应为准。UI 可以表示“正在上传”等临时反馈，不能创建第二份发布生命周期。

## 三、布局与视觉基准

外壳沿用 48px 顶栏、200px 侧栏及内容区 16px 结构间距；品牌、账号菜单、背景和字体均保持既有基准。
列表使用单张 Card：卡片标题与主操作同一行，下面为筛选行和表格；不额外叠加大标题、介绍卡片或欢迎区。
详情按卡片纵向排列。编辑页内容最大宽度 960px、左对齐，为完整提示词保留阅读宽度；页面自行纵向滚动，外壳不滚动。

| 部位 | 落地要求 |
| --- | --- |
| 控件 | 使用 AntD Form、Input、Select、Table、Modal、Alert、Tag、Button 等；普通控件使用默认 32px Token，表格操作使用 `size="small"` |
| 文字与状态 | 标题 16px、正文 14px、辅助 12px，均取现有 Token；状态同时有文字和语义颜色，不只靠颜色 |
| 卡片与间距 | 卡片 padding、圆角、标题高度由既有 Token；结构分区间距 16px，操作按钮间距 8px |
| 表格 | 操作列固定右侧且居中；名称可进入详情/编辑，说明省略时可查看完整内容；不把整行做唯一点击目标 |
| 列表滚动 | 筛选行留在表格外，表格使用剩余高度内部滚动；最窄宽度不足时横向滚动，操作仍可达 |
| 编辑与详情滚动 | 页面单一纵向滚动；长提示词输入自身可滚动，不在 Card 内再套多个同向滚动区 |
| 弹窗 | 上传宽度 680px，说明编辑宽度 520px；最大宽度不超过视口减 32px，长内容在正文滚动，原生 footer 始终可达 |

智能体、插件列表优先按约 920px、960px 的内容宽度安排列。窗口缩小时筛选控件自动换行，名称可折行或省略，不能压掉操作按钮。
长名称、中文、125%/150% 缩放及键盘焦点可见性必须在真实浏览器检查；不借此修改整站主题或重做侧栏响应式体系。

## 四、智能体管理

### 4.1 列表

卡片标题“智能体”，主按钮“新建智能体”。筛选行提供可见 Label“搜索”、输入提示“搜索名称或描述”、查询及重置。
完整已读列表可做页面内筛选，列表读取失败不能伪装成“没有智能体”。

| 列 | 展示 | 操作规则 |
| --- | --- | --- |
| 名称 | 完整名称优先；长文本截断时可查看 | 点击进入编辑 |
| 描述 | 简短摘要，空时显示“—” | 不拿提示词正文填充摘要 |
| 默认能力 | “Skill 2 · MCP 1”等计数，均为空时“未设置” | 不展示整包权限或模型配置 |
| 依赖提示 | 中心可确定的问题摘要，未知 Host 项为“需在目标 Host 核对” | 不显示笼统“运行正常”徽章；问题详情在编辑页 |
| 操作 | 编辑、删除 | 删除使用 danger 样式；提交中禁用重复写入 |

初次成功读取为空时显示“暂无智能体”，保留“新建智能体”；筛选无结果显示“没有符合条件的智能体”，提供重置。

### 4.2 编辑页与完整提示词

编辑页按“基础信息 → 提示词 → 默认启用能力 → 操作”纵向组织。新建与编辑复用同一页面结构，标题分别为“新建智能体”“编辑智能体”。

| 字段 | 控件与提示 | 校验与行为 |
| --- | --- | --- |
| 名称 | 单行 Input；“例如 文档助手” | 必填、中心内唯一，遵循技术方案 1–64 字符规则；编辑时只读，说明“名称用于引用，创建后不可修改” |
| 描述 | 多行 Input；“简要说明这个智能体适合处理的任务” | 可选；不自动从提示词生成，不影响提示词正文 |
| 提示词 | 一个完整 TextArea；“填写完整提示词” | 必填且不能全空；保留换行、空白与用户文本，不按职责/步骤/输出拆字段 |
| 默认启用的 Skill | 已选名称列表和添加入口 | 可为空；按下一节处理名称及插件来源 |
| 默认启用的 MCP | 已选名称列表和添加入口 | 可为空；不展示 MCP 连接凭据或启动参数编辑 |

提示词默认至少 14 行，增长至约 24 行后内部滚动，允许在页面可用高度内手动拉高；不是代码编辑器，不引入语法编辑器、富文本格式工具栏、模板变量系统或执行测试按钮。
只在字段下展示与保存有关的长度状态；上限为技术方案规定的 256KiB UTF-8，按实际字节校验，不误用字符数替代。粘贴或输入超限后保留原文、显示错误并禁止保存，不静默截断。
普通 Enter 在 TextArea 中换行，不触发表单保存；输入法组合输入不触发快捷提交。提示词不默认渲染为 HTML 或 Markdown。

操作区使用“保存智能体”“取消”。保存后提示“智能体已保存”，回到智能体列表并重新读取；不额外增加启用或发布按钮。
编辑页操作区显示简短说明“修改仅影响后续创建的会话”，不暗示中心能够查看或改写现有会话。

### 4.3 按名称添加默认能力

两组列表分别使用“添加 Skill”“添加 MCP”。点击在当前分区展开选择行，选项来自中心已接纳的完整包（含未上架和已下架）的内容声明，插件名称与能力名称同时可见。
若有 `display_name`，插件可先显示中文名称，但同一选项中始终保留稳定插件名称，不能仅用显示名保存引用。

1. 默认方式“从插件选择”：使用单行级联选择，先选插件，再选包内对应类型的能力名称；可搜索插件名称/显示名及能力名称。选择插件并不自动选中包内全部能力。
2. 选项说明展示中心实际掌握的平台覆盖和上架情况；同一能力名称出现在不同插件时分别显示来源供选择，不替用户选来源。同一 Agent 的同类能力名称只能选一个生效来源。
3. 增加低频入口“引用 Host 已有能力”：输入能力名称，标记“需在目标 Host 核对”。此入口不创建中心插件，不把未知名称当成缺失插件自动补全。
4. 点击“添加”形成一条已选项，展示能力名称、所属插件名称或“Host 已有能力”，以及必要的问题说明；末尾“移除”只修改表单草稿。
5. 同类能力按名称去重：同来源重复显示“该能力已添加”；已有同名能力但来源不同则阻止添加，显示“已从「现有来源」选择同名能力，请先移除后再选择其他来源”。Host 已有能力引用也参与相同检查，不等保存后才暴露冲突，不自动替换。
6. 已保存依赖变为下架或内容缺失后，回读仍保留原引用，显示具体问题；不自动清空、不用同名另一插件替换，也不把下拉选项缺项当成空配置。

中心能够确认的下架、内容缺失提示在对应行展开，不使用“已安装”“可运行”“有权限”等 Host 侧结论。
人工引用的未知 Host 能力可以按契约保存；语法错误、重复项或无法解释的引用阻止保存。已存在且后来失效的引用是否构成写入错误按技术方案返回处理，前端不自行改变业务约束。
选择和添加只装配默认配置，不修改提示词，也不自动生成或插入一段工具使用说明。

### 4.4 保存、离开与删除

本地校验失败滚动并聚焦首个错误字段；中心唯一性或引用错误尽量落到对应字段，其他错误在操作区上方使用 Alert。
保存中冻结本次提交内容、显示 loading，禁止重复提交和站内离开；读取刷新不能覆盖已修改的表单。

有未保存修改时返回/导航/取消使用既有确认：“放弃尚未保存的修改？”按钮“放弃修改”“继续编辑”。无修改直接离开；浏览器刷新沿用原生离开提示，不承诺刷新恢复草稿。
保存成功后先释放 dirty 登记再导航，不能出现成功后又要求放弃修改的确认。

删除确认标题“删除智能体「名称」？”正文“删除后，企业中心不再提供此智能体供新会话选择。已有会话及已安装插件不受影响。”按钮“删除智能体”“取消”。
成功后保留列表筛选并重读，不假造受影响会话数量；删除失败保留原条目及错误提示。

## 五、插件管理与版本完整包

### 5.1 插件列表

卡片标题“插件”，主按钮“上传插件包”。筛选为搜索名称/说明、上架状态、查询及重置。
一个插件只有一行，列为名称、编码、说明、上架情况、版本概况、操作；名称显示 `display_name`，编码单独显示稳定的 `name` 字段，不叠在名称下方。
平台支持可以压缩为一行摘要，不把 macOS ARM、Windows x64 等变成不同插件名称或顶层条目。

上架情况直接映射中心唯一 `publication` 状态：`unpublished` 显示“未上架”，`listed` 显示“在架”，`deprecated` 显示“已下架”。前者表示从未上架，后者表示已经停止分发；UI 不根据版本列表、时间或本地历史推断。只有“上架 / 下架”动作：在架可下架，其余状态可上架，不再建立额外发布步骤。
版本概况只表达中心已接纳的版本，不声称所有 Host 均可安装列表中最高版本；详情展示每版平台覆盖。
操作列提供“详情”及“上架/下架”，不提供插件/历史版本永久删除、强制更新或远程卸载。

### 5.2 插件详情

顶部操作 Card 展示显示名称、编码和当前上架情况；主操作“上传插件包”，其次“编辑说明”“上架/下架”，左侧有返回列表入口。
下面依次为插件说明、版本列表。说明按安全纯文本展示；不执行包中的内容、不自动嵌入远程页面。

版本列表按技术方案的版本比较顺序展示，初始展开最新版本，其余可展开。每个版本展示唯一当前完整包：

| 信息 | 展示方式 |
| --- | --- |
| 支持平台 | 按包内 `platforms` 展示明确的操作系统/架构；不能用浏览器操作系统替代，也不拆成多个包行 |
| 包大小与上传时间 | 当前完整包的可读体积、当地时间；原始精度下沉到详情，不单列下载热度 |
| 压缩格式 | 包详情展示 ZIP 或 TAR.GZ，下载保留对应扩展名；不作为插件列表分类或平台子包条目 |
| 内容 | 按该版本的 Skill/MCP 名称清单展示，可折叠；不要拿最新版本清单覆盖历史版本 |
| 完整性 | 正常行不堆叠长校验值；包详情可复制校验信息用于核对结果 |
| 操作 | 在架且完整可下载时显示“下载”；未上架时禁用并说明“上架后可下载”，已下架时说明“插件已下架，无法下载” |

“上传新版本”与“替换同版本包”使用同一个上传组件。版本区域入口可带入当前插件/版本上下文用于上传后的核对，名称、版本和支持平台均取自包内；上传区固定提示同版本异 SHA 会替换中心当前包，客户端不会收到同版本更新。
包内声明的运行环境、外部软件要求和配置项名称下沉在对应版本内容详情，敏感配置只显示需求和用途，不显示或收集用户密钥。
只呈现“包校验通过”等中心事实；不出现“运行已验证”“所有设备可用”等结论。

下载通过带身份的请求进行，不是公开文件链接。请求携带详情当前 SHA，若同版本包已被替换则显示“包内容已变化，请刷新后重新下载”，不静默切换到新包。支持浏览器文件保存能力时，点击后先选择保存位置再传输，显示实际进度并可取消；完整保存后才提示完成。缺少该能力时，128 MiB 以内使用有界下载；更大文件保持可见并说明“当前浏览器无法保存此大小的文件，请使用支持文件保存的浏览器并通过 HTTPS 或本机地址访问”。不把浏览器限制写成插件不支持该平台，不显示已验证运行/完整性结论。上传不受这项浏览器保存限制。

### 5.3 上传插件包

使用 Modal，标题“上传插件包”；正文为单文件选择区（可拖放）、文件名/大小、上传结果和进度，footer 按状态提供操作。
同时接受 `.zip` 和 `.tar.gz`，选文件/拖放提示明确显示这两种格式；首次选择不自动上传。文件后缀和浏览器 MIME 仅用于前端预检与请求声明，最终以中心实际内容校验为准。单文件上限以中心配置/契约为准，前端预检仅帮助尽早反馈，不能取代中心校验。
不提供平台多选控件。支持平台完全由包内 `plugin.json` 提供，中心在完整上传后解析并整体校验；Admin 不在浏览器解析整个压缩包，也不允许用界面勾选覆盖包内声明。

选包区说明：“包需包含声明的运行环境和依赖；Blender 等外部软件在包中声明。”不提供 npm/pip 安装按钮或中心构建步骤。

| 状态 | 文案与可见结果 | 操作 |
| --- | --- | --- |
| 未选文件 | “选择或拖放插件包” | “选择文件”；“上传”禁用；可关闭 |
| 已选待上传 | 文件名、大小；插件名称、版本和支持平台在中心解析前不猜测；固定提示“同名同版本的不同内容将替换中心当前包，已安装客户端不会收到同版本更新” | “更换文件”“上传”“取消” |
| 传输中 | “正在上传”；可测得时显示实际字节进度 | 禁止更换/重复上传；提供“取消上传” |
| 字节已发送，中心未返回终态 | “正在校验和保存”；100%不显示成功 | 禁止重复提交；提供“停止等待” |
| 新版本成功 | “插件包已上传”，展示中心确认的名称、版本、支持平台和 SHA | “查看插件”“关闭”；新插件追加“当前未上架，检查后可上架” |
| 同版本已替换 | “已替换版本 1.0.0 的中心当前包”，展示旧/新 SHA 摘要、支持平台，并提示“客户端不会收到同版本更新” | “查看插件”“关闭”；不声称已安装端已更新 |
| 同一包已存在 | “该插件包已存在，中心内容未变化” | 可查看中心对应版本，不作新的发布成功计数 |
| 声明平台无效 | 明确指出哪个声明平台缺少入口或运行时，并说明“整个插件包未接纳，原版本保持不变” | 保留原文件，可修正包后显式重传；不提供部分平台接纳 |
| 明确失败 | 具体原因及 request_id（有则提供复制）；同版本替换失败明确说明原包仍有效 | 保留选中文件；按错误提供重选或显式重试 |
| 结果未知 | “上传结果未确认，请按名称、版本和当前 SHA 核对中心记录” | “核对结果”“关闭”；不能自动重发 |

这是一次显式上传请求，不加入预上传会话、云端草稿或二次提交发布按钮。接收、校验、发布各阶段只在中心提供实际信号时细分；不模拟定时进度。
成功返回后刷新来源列表/详情，并保持成功结果直至用户关闭或查看插件。已有在架插件上传新版本或替换同版本包后，中心当前完整包立即可供后续下载；文案明确同版本替换不会通知或升级已安装客户端。

传输中点击取消，确认文案：“停止本次上传？若中心已接收完整包，仍需核对最终结果。”；进入中心校验后的停止等待使用同样的结果边界，不声称回滚。
上传中遮罩与 Escape 不直接关闭；窗口右上角关闭应走取消/停止等待流程。站内导航由既有写入门阻止，不通过新建全局上传任务机制维持后台发布。
取消完成后按服务端明确结果显示“已取消”或“结果未确认”。一旦已收到发布成功，迟到的取消不能把成功改为失败。

### 5.4 编辑说明、上下架

“编辑说明”弹窗展示只读编码，编辑显示名称/说明等技术方案明确允许的展示字段；包内容清单、版本、当前 SHA 及包内支持平台只读，不增加在线改包能力。
footer 为“保存修改”“取消”，未保存关闭沿用放弃确认。说明保存不改变包字节、版本或依赖引用名称。

上架确认显示插件名称和现有可分发版本/平台概要，文案“上架后，企业用户可发现并下载匹配的插件包。”；完整包不足时阻止并指出原因。
下架确认标题“下架插件「名称」？”，正文说明：“下架后停止下载和更新。已经从本中心安装的插件将标记为已废弃，仍可继续使用或删除。”
中心可确定的依赖智能体名称在确认框内列出；列表为空写“未发现中心智能体的名称引用”，不能写“无人使用”。
依赖读取失败时明确“暂时无法读取依赖引用”，提供重读，不把空白视为零影响；下架是否可执行由技术方案确定的必要事实决定，不伪造安装量。

确认按钮“下架插件”使用 danger。成功后重读详情/列表，反馈“插件已下架”，下载按钮立即按新事实不可用。
重新上架沿用“上架”动作，说明状态恢复后由 Host 后续成功查询发现；不展示自动更新开关或重新安装任务。

## 六、身份、并发与异常反馈

### 6.1 通用读取和写入

| 场景 | 页面行为 |
| --- | --- |
| 首次读取中 | Card/Table loading，禁用依赖当前记录的写入，不先闪现空状态 |
| 读取失败 | Result/Alert 显示具体原因及“重试”；已有成功数据可保留并标明读取失败，不按旧数据宣称最新状态 |
| 明确校验失败 | 字段级错误或页面 Alert；保留草稿、文件和焦点上下文，不自动关闭 |
| 并发冲突 | `412 CONFIG_CHANGED` 提示“内容已变化，请重新读取后再保存”；保留当前草稿，提供“查看最新内容”，明确选择放弃草稿重载前不覆盖，不自动重试 |
| 写入结果未知 | 明确“结果未确认，请先核对，不要重复提交”；与明确失败区分，不自动重试 |
| 当前身份失效/管理员权限撤回 | 沿用身份守卫处理，遮蔽并卸载旧身份页面；不把旧草稿、文件或响应交给新身份 |
| 旧请求迟到 | 当前身份、页面和请求代次不匹配则忽略，不覆盖新表单、不登出新的登录身份 |
| 资源被删除/已下架/包 SHA 已变化/文件不可用 | 保留不同原因；包 SHA 变化先刷新详情，不静默下载替代内容；其他情况提供返回列表或刷新，不能全部显示“暂无数据” |

读取失败与写入失败使用既有 `failure()` 文案映射和 request_id 追踪，不把原始服务端堆栈、路径或完整提示词写入 Toast、日志和审计。
成功后列表刷新失败时同时保留已确认的保存结果并提示“已保存，列表暂未刷新”；不能把读失败改成写失败后要求再保存。

Agent 编辑/删除、插件说明与上下架写入按技术方案使用读取响应的 ETag，通过 If-Match 提交；令牌留在对应页面/表单内存，不作为用户字段显示。
出现 412 时，“查看最新内容”通过当前页只读区域或 Modal 展示重读结果，原草稿保持可复制；“放弃草稿并重新读取”需确认，重新载入后才使用新 ETag。不能只更新 ETag 然后自动重发旧草稿。
删除/上下架确认期间遇到 412，保留名称与错误提示，重新读取实际记录及影响后由管理员重新确认；不能继续执行旧确认。缺少条件的 `428` 显示“请重新读取后操作”，不伪装成网络失败。

### 6.2 结果未知的核对

同一身份下保留已提交内容的内存快照与请求标识，只用于核对结果，不新建持久化草稿或任务队列。
Agent 保存/删除和上下架通过重新读取对应名称核对当前事实；存在并发修改时不能仅凭内容相似认定原操作成功，应明确当前记录并按技术方案支持的审计信息核对。
核对不会把当前草稿直接覆盖成中心内容；需要放弃草稿重载时沿用确认。

插件上传优先按已知插件/版本读取当前完整包并核对 SHA。全新包如果尚未收到解析结果，只能进入插件列表/既有审计核查，或由管理员按包内声明定位；不从文件名猜插件名称，也不凭列表中最新的一条判定上传成功。
找不到记录但请求可能仍在中心处理时维持“结果未确认”，不把一次未找到称为未提交。核对仍无法确认时，用户可关闭结果窗口并重新打开上传框，显式选择同一原包重传；同 SHA 返回 unchanged，异 SHA 会替换同版本当前包，因此页面不自动重试，也不声称原请求已经取消。

### 6.3 键盘、焦点与可访问性

所有字段有可见 Label 和可访问名称，输入有非空 placeholder。按钮文字说明动作；纯图标操作必须有名称，Tooltip 只补充截断内容或原因。
选择器、表格内按钮、版本展开、上传选文件均可用键盘操作；原生文件选择取消不清除既有已选文件。
Modal 使用原生焦点约束，关闭后回到触发按钮；删除当前记录后焦点回列表标题或相邻可用动作。错误摘要可被辅助技术获知，错误字段与错误说明建立关联。
插件正文与提示词均按文本处理；不让名称、描述或压缩包提供的文字进入 HTML 注入、动态脚本或未经确认的自动外链打开。

## 七、交互验收与阶段边界

| 功能设计对应项 | 本稿增加的观察口径 |
| --- | --- |
| C01-A02/A03 | 中文名称、完整长提示词、纯提示词 Agent 可编辑回读；提示词不截断、不拆字段；同名能力来源明确、未知 Host 项不会假装已验证 |
| C01-A04/A05 | 同一插件的版本及每版单一完整包在详情组织；支持平台取自包内；ZIP/TAR.GZ 均可上传并保留原格式；同 SHA 无变化，异 SHA 替换同版本当前包，失败保留旧包，并明确客户端不处理同版本更新 |
| C01-A06/A11 | 上传进度到 100%不算成功；取消/断连/结果未知均不自动重传；身份切换和迟到响应不污染页面 |
| C01-A07/A09 | 新包上架操作清楚；在架新版本及同版本替换后的当前包可供后续发现，但无自动升级或同版本更新文案；下架影响仅限中心分发及其安装来源，没有永久删除/远程禁用入口 |
| C01-A10/A12 | 空、读取失败、失效身份、无包和下架可区分；直达/刷新/后退有效，草稿离开和保存后的焦点反馈正确 |
| 整体布局 | 沿用后台 Token；表格操作固定右侧且小尺寸；长文本、窄窗口、键盘及 125%/150% 缩放可操作，没有浮层或按钮裁切 |

以上为待实施时的定向验证口径，不是已执行的测试结果。不为文案、菜单顺序或 CSS 数值增加快照/源码扫描测试；关键身份、写入结果、取消和竞态在最有效层验证，核心页面用真实浏览器检查。
本指导已用于正式 Admin 的智能体与插件管理页面；后台能力的实施和验收结论见[开发计划](开发计划.md)及[阶段总结](阶段总结.md)。具体插件包的正式封装和实际使用不属于本循环页面验收。
