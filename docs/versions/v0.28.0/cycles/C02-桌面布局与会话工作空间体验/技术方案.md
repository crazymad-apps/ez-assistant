## 三、权威状态与总体实现

```text
Desktop/Web：布局、当前未发送草稿与资源组
      │ 正式 Command / SSE / 首次物化上传
Runtime：Workspace Registry、Session 冻结环境、权限与 Run
      │ RuntimeStore / SessionEnvironmentFactory
Host：单用户 SQLite worker、用户域私有目录、文件/Shell/PTY/Skill
```

当前 Workspace 保存在 Store 并投影到 Runtime Registry；Session 目录冻结在既有 session_resources，执行只读该冻结环境。UI 不能直接创建目录或猜测保存成功。用户选择路径、Host 文件系统、原生窗口、Web Cookie/Bearer 为既有信任边界，不增设直连数据库或绕过权限的通道。

所有新增后台工作仍属于现有 RootStore/请求、Runtime operation gate、Store worker 或 Host PTY supervisor。没有新轮询服务、队列或线程；列表读取复用当前限流和快照，工作空间写操作复用既有串行 gate。

## 四、工作空间协议、存储与恢复

### 4.1 可空目录的最小表达

| 类型/字段 | 拟议最终形态与语义 |
| --- | --- |
| `RegisterWorkspaceRequest.primary_directory`、`UpdateWorkspaceRequest.primary_directory` | `Option<String>`；客户端完整表单发送字符串或 `null`，空串非法；反序列化缺失按无目录处理，不能表示局部保留 |
| `WorkspaceSummary.user_directory` | `Option<String>`；`None` 表示确实没有用户工作根，不是加载未知 |
| `StoredWorkspace.user_directory`、注册/更新 Store 输入 | `Option<String>`，与实际保存事实一致 |
| `WorkspaceEnvironmentSource.user_directory` | `Option<&str>`；不携带数据库对象 |
| `SessionExecutionEnvironment.working_directory` | 保持 `String`，永远是已解析的有效默认工作位置 |
| `SessionWorkspaceSnapshot.primary_directory` | 保持冻结实际工作位置字符串；补正文档语义，可为工作空间私有目录。无需另存同义 cwd 字段 |
| `additional_directories` | 保持有序数组；没有主目录时必须为空，有主目录时总数仍不超过 16 |

主目录为 Some 时仍要求绝对 UTF-8、存在、可读、canonical 去重及 UserPaths 准入；Some 空白不归一化成 None，以免错误表单静默改变语义。None 不调用空路径 canonicalize，也不把私有路径写入 user_directory。

有效工作位置统一为 `user_directory.unwrap_or(agent_directory)`。在 `StoredWorkspace` 所属模块提供最小的只读方法供 Runtime 使用；Host 协议投影调用点就近同义转换，不新增通用路径服务。主/附加根集合由现有 `workspace_directories` 装配入口收敛，禁止各消费者自行回退 OS Home。

### 4.2 列表与明确恢复

- `ListWorkspacesRequest` 增加 `lifecycle: Option<WorkspaceLifecycle>`；缺省为 Active，恢复窗口显式请求 Removed。复用原 `ListWorkspacesResult`，ApplicationSnapshot 继续只含活动项，不扩大日常快照。
- 新增 `RestoreWorkspaceRequest { workspace_id }` 和 `RestoreWorkspaceResult { workspace }`，接入现有 RuntimeCommand/Result、dispatch、Runtime Client、协议导出和 Store 操作分发。
- RuntimeStore 增加恢复方法，参数只需 WorkspaceId 与变更时间；不为此复制一份 Workspace 定义。实际 SQLite 和 VolatileStore 都实现同一行为。
- 恢复只改变目标记录 lifecycle/updated_at/removed_at；名称、用户目录、私有目录、Session 和正文不改写。目标已 Active 时返回当前事实，为同一意图重试提供幂等结果；不存在时沿用现有未找到错误。
- 有目录的恢复需检查当前目录仍可用；无目录的恢复核验其受管私有布局并使用现有目录准备流程。错误不改为 Active，不以创建新记录代替恢复。
- 同主目录注册保留现有恢复行为；无目录注册不执行按目录查询，每次明确新建分配新 ID。VolatileStore 查重同样仅在 Some 时执行，禁止把两个 None 认成相同。
- UI 创建请求在途禁止重复点击；创建响应不明确时停止自动重发，重新读取列表供用户检查实际结果。无目录创建不是按名称幂等；本循环不为此新增创建 receipt 或“猜测最新记录”的自动认领机制。

权限作用域注册、Store 提交、Registry 发布沿用现有顺序；新增恢复必须说明 Store 已提交而后续投影失败的恢复路径：重复按 ID 恢复读取已 Active 的可靠事实，重新补齐 Registry/权限投影并发布 WorkspaceChanged，不再次修改原记录内容。内存锁不跨 Store I/O 持有。

### 4.3 SQLite 迁移

现有 `workspaces.user_directory TEXT NOT NULL UNIQUE` 无法保存真实的无目录，需在新增 `storage/migrations/v0_28_0/` 中重建该表，移除这一列的 NOT NULL，保留 UNIQUE 和其他列/约束。SQLite UNIQUE 允许多个 NULL；非空目录的唯一约束继续覆盖活动及已移除记录，保持现有行为，不改为仅活动记录唯一。

新表额外校验无用户目录时附加目录数组为空；JSON 合法性沿用现有解码/迁移校验，不能仅靠字符串空值判断。保留全部 workspace_id、标签、目录、时间与生命周期；不修改 `session_resources.working_directory`，不回填冻结历史、不迁移私有文件。

`session_resources.workspace_id` 引用 workspaces，现有迁移控制器在事务前开启外键。不能直接在版本回调里关闭外键或删除被引用表：

1. 在私有 `Migration` 描述中增加仅用于已核实表重建的能力标记（拟名 `rebuilds_referenced_tables`）；其他入口均为 false，v0.28.0 为 true。它表示本次真实 DDL 需求，不是另一套迁移系统。
2. 控制器先完成既有准入、独立备份及只读回读验证，再在专有迁移连接、事务开始前暂时关闭外键 enforcement。
3. 进入现有 Immediate 版本事务：创建临时新表、显式列复制、核验逐行内容/数量、删除旧表、将新表重命名为 workspaces；保持原关联 ID，不重建 Session。
4. 提交前使用同一事务执行 `foreign_key_check` 和现有完整性校验，确认没有临时表残留；账本与数据库最低 Host 版本同事务提交。
5. 无论成功或回滚，控制器重新开启并核实 foreign_keys；无法恢复时关闭连接并阻止业务初始化。不得把禁用状态带入业务 worker。

迁移 authorizer 继续保护账本和兼容元数据，版本回调不能修改它们或自行切换 PRAGMA。表重建步骤和 SQLite 关联完整性须在隔离迁移测试中实际证明，本稿没有执行数据库操作。失败立即停止版本链；恢复使用已验证备份，不能自动逆向覆盖可能新增的数据。

### 4.4 冻结环境及 Home 重定位

- 创建与首次物化：在现有工作空间读取/写 gate 下取得一致记录，生成非空 cwd、附加根、workspace_private_directory；Store 的新会话校验比较有效 cwd，不再直接比较可空 user_directory。
- 载入历史：`load_session_environment` 目前把 LEFT JOIN 的 user_directory 为 NULL 当作记录不存在，必须改为验证关联 Workspace ID/私有目录；NULL user_directory 是合法事实。读取当前目录只用于投影，不覆盖冻结 cwd。
- `directories_match_current` 比较当前有效 cwd+附加根与冻结环境；名称变化仍可实时显示。UI 用当前 user_directory 判断当前“仅使用私有目录”，历史环境从已投影的冻结 cwd 与已知私有目录解释，不新增持久模式位。
- Fork 保留来源 Workspace cwd/附加根，仅更新子 Session 自有目录；Clear 保留原冻结工作位置并按既有规则重建提示词和 Skill 上下文，不承诺 Clear 前后完整提示词字节一致。无目录分支不得从当前 Workspace 编辑结果重取目录。
- `repair_workspace_resources` 当前先于 Session 恢复执行。重定位工作空间私有目录时，必须在同一 Store 事务核验旧私有路径符合该 Workspace 的既有布局，只更新 `workspace_id` 相同且 `working_directory` 精确等于旧 agent_directory 的 session_resources；然后更新 agent_directory。外部用户路径和不匹配的历史 cwd 原样保留。
- 后续 `rebase_moved_session_resources` 继续负责 Session 私有/附件目录；新增的 Workspace cwd 处理不能依赖当前 user_directory 是否为空，因为该工作空间可能已从私有目录改为用户目录。
- 冻结提示词和已提交正文不做全局字符串替换；沿用既有受管资源恢复和新轮执行环境处理，技术回归核查可用路径与历史展示的既有边界，不能声称历史绝对链接自动全部迁移。

## 六、草稿移动、资源归属与首次发送

### 6.1 唯一草稿容器

保留 NewSessionDraftStore 的现有 map。新增同步 `move(sourceKey, targetKey)` 操作，检查源存在、目标无自定义内容、双方没有 unresolved materialization、RootStore 没有在途首次发送；在同一 MobX action 内移除源并写入目标，不先清源再 await。

目标冲突复用 `isDraftCustomized` 并补检查 `materialization_attempt`；还要检查目标 ResourceTabGroup 是否有非默认标签/活动终端或待完成资源请求，不能只保护输入框而覆盖另一组资源。冲突只打开目标或取消，不合并。

移动保留文字、quotes、attachment selection、模型/档位、变体、审批模式、Goal 与 Skill/MCP 选择；能力选项缓存失效并按新工作空间重新查询。不得复用旧 workspace 的 skill_options 标记为 ready，也不因查无结果自动删除原选择；保留标签并显示不可用，阻止提交直到明确移除或重新选择。

移动期间不调用释放附件 selection；只有明确移除、草稿清空、发送成功或原有清理时释放。引用按原有来源身份校验，不把引用文本改成新工作空间文件路径。

### 6.2 异步 owner 与资源组

- RootStore 编排草稿与 ResourceWorkspaceStore 的移动，沿用现有 `transferDraft` 改名为支持目标 scope 的内部转移能力；不创建第二份浏览器/终端实例。
- 资源组对象身份保留，scope key 改为目标；workspace 标签的当前路径重置为目标有效位置，文件引用继续指向其实际来源，已有终端保留创建 cwd并可查看；不能把旧终端伪装成在新目录启动。
- 附件/目录系统选择器、图片暂存等仍在进行时暂缓移动，待结果返回再允许；上传/首次发送期间禁止移动。此选择避免新增跨 owner 文件选择迁移协议。
- Skill/MCP 查询和普通资源读取可取消并重发；回调核对连接 owner、草稿 key及请求对象身份。源 key 被移除后晚到结果直接丢弃，不因同 key 新草稿重开写进去。不新增持久 generation/revision；使用现有请求取消与对象 identity 即可隔离。
- 调整 `DraftComposer` 卸载时清 MCP 选择的现有逻辑：移动导致的卸载不清除已转移选择，也不清除 unresolved manifest；真正销毁仍按原清理规则处理。
- 对资源组迁移前后的缓存 page key、workspace location、浏览器控制器、terminal.source、view_state 与保存快照逐项核对；终端原创建来源不被改写，scope 仅表示展示归属。

### 6.3 物化结果未知

现有 `SessionMaterializationManifest.idempotency_key` 及 Host `/session-materializations` 已承担幂等提交；保留该唯一机制，不增加另一个查询票据或 Session 状态。当前重试必须先重收附件并校验当前模型/能力，不能直接取回旧结果，故本稿拟补必要的只读查询：

- `GetSessionMaterializationRequest { idempotency_key }`，返回 `GetSessionMaterializationResult { materialization: Option<SessionMaterializationResult> }`，通过现有 RuntimeCommand 接入；不用新增专用 HTTP 路由。
- RuntimeStore 增加按现有 key 查询 `StoredSessionMaterialization` 的只读方法，SQLite 使用 `sessions.materialization_key` 唯一索引关联既有 Input/Run/附件；VolatileStore 同义实现。不重新产生 Input/Run，不执行历史模型或工具。
- Runtime 在现有 operation/workspace gate 下读取与恢复该 Session 的必要进程内投影；按 Store 返回的真实 Session ID 复用既有加载/恢复口径，不使用本次新分配 ID。已在 Registry 的 Session 直接返回当前 Run 快照；未在 Registry 时从持久 Session/Input/Run 构造定位结果，接入原恢复入口，不再次调用正常首次提交中的 `project_accepted_input`/`wake_queue` 来重跑历史任务。查询不把终态 Run 改回 queued，也不重新申请附件或模型执行。
- 该查询只属于当前 Host 当前用户域，返回与正常物化成功相同的脱敏附件投影。返回 None 只证明查询时尚无提交，不证明先前上传不会晚到；客户端不得据此解除原意图冻结。

- 发送前一次冻结 manifest。发送中禁止编辑相关载荷、清空、快捷装配及工作空间移动。
- `materialization_response_unknown` 时保留原 manifest 和 selection，状态由现有 attempt + 非 pending 推导；页面显示“发送结果待确认”，按钮为“重试确认”。禁止普通 `#patch` 清除该 attempt。
- “重试确认”先查原 key；已提交则采用原结果，否则仍以相同 manifest/key 进入原提交入口。网络再次失败继续保留，不自动新建 key。用户可以离开查看其他草稿，但不能移动、覆盖或清空该待确认草稿。
- 初次明确未提交的校验/资源错误可以解除冻结，保留内容后由用户修改；一旦曾有未知结果，后续附件 selection 失效、模型/能力变化或单次查询 None 均不能证明未提交，仍保留原 manifest 并显示具体原因。若附件失效且无已提交结果可读，本循环不以重建 key 自动恢复，界面明确尚无法确认，避免双发。
- 成功只把当次源资源组交给返回的 Session；若用户已导航到其他草稿，不强制覆盖新导航，但列表展示新会话结果。连接/账号已换 owner 的响应不得改动新 RootStore。

### 6.4 快捷入口

配置位于 Composer 功能内的代码常量，表示文案、可选模板和现有 Skill/MCP picker 意图；本版不持久化、不暴露协议、不增加通用装配 DSL。C03 再增加 Agent 意图分支，不预埋空接口。

模板预览后追加到已有文字；空输入可直接填入。Skill/MCP 均通过现有选择器读当前 Host 的实际可用项；缺失引导设置，不自动启用全局开关。应用操作受与用户直接编辑相同的 materialization/owner 门禁。

## 七、布局、置顶与原生适配

AppShell 取消固定顶栏 grid row，左侧 Shell 区包含顶部控制、快捷菜单、导航滚动区、底部账号入口；会话标题与资源标题各自占局部顶部。原 AccountMenu/RuntimeStatus 的身份和连接读取复用，统一入口组合菜单内容；不复制 ConnectionStore。

SessionSidebar 移除常驻“会话/已归档”页签和顶部工作空间下拉。“新建会话”直接调用现有无工作空间草稿入口；工作空间定向新建仍由 WorkspaceGroup 与初始化页承担。“助理会话”读取 `ApplicationSnapshot.controller_availability` 并选择现有 Controller Session，复用当前不可用、加载中和权限状态；删除列表中的独立 ControllerSection 展示，不能创建新的助理会话集合或持久字段。

NavigationStore 的活动/归档 `list_mode` 与 Host 分页接口继续作为查询事实使用，但常规侧栏固定为活动范围；搜索/筛选浮层按用户显式选择切换活动或已归档，并在关闭后恢复常规活动列表。归档会话动作、恢复/打开行为与服务端状态均不删除。实现优先复用现有 `listSessionPage`、`loadMoreSessions` 和搜索 query，不为隐藏页签新增归档缓存或路由。

置顶基于当前已加载可见 SessionSummary 的 is_pinned 过滤。Store 当前排序为 `is_pinned DESC, updated_at_ms DESC, session_id ASC`，保持该排序和一次分页；取消置顶后重新加载受影响视图，不能在加载未完成时宣称所有历史项均已获取。搜索走现有列表而不额外复制置顶组；Controller 继续从普通结果排除，仅由“助理会话”快捷菜单打开。

macOS 已配置 Overlay、hiddenTitle 和 trafficLightPosition `{x:14,y:23}`，优先通过布局预留完成整合，保持静态定位，不引入 Cocoa FFI 或新增 unsafe。折叠轨宽保留红绿灯空间；全屏后按系统真实显示变化留白，不绘制仿制按钮。Windows/Linux 复用 DesktopWindowControls 与已有 native-bridge 生命周期，不重新实现最大化、关闭或 glyph。

Web 原生控件不渲染。拖动区只覆盖空白，不包裹按钮；窗口双击现有平台语义保留。NavigationStore 保留既有左右宽度偏好字段：左栏使用固定像素宽度，右栏字段作为默认 1280px 窗口下的比例基准，拖拽时换算后保存；实际右栏宽度由当前剩余空间、比例和最小宽度计算。两栏最小宽度不能同时满足时只隐藏右栏，不改变左栏显隐偏好；展示层保留两栏 DOM，通过宽度过渡与 inert 完成显隐。

Dialog、SelectionPopover、DropdownMenu、Collapse、Tooltip 和 overlay root 继续复用。原生浏览器 child WebView 的遮挡检测读取同一 overlay root 和实际矩形，布局移动后重算，不靠 z-index 代替原生隐藏。

## 八、兼容、失败与安全

| 边界 | 本方案选择 |
| --- | --- |
| 应用软件兼容下限 | 建议套件 `min_compatible_version` 提升至 0.28.0：旧客户端按 String 消费 user_directory，旧 Host 不接受 None/恢复意图，不能假装只加可选功能。遵循现有套件统一下限，不另造整数协议版本 |
| 数据库最低 Host | v0.28.0 同事务提升至 0.28.0：旧 Host 无法读取 NULL、识别恢复和正确装配私有 cwd；即使数据库当前尚无 NULL，也不能依赖未来数据碰运气 |
| Center 协议/版本 | 不因 C02 调整；C01 独立决定中心兼容 |
| Host layout / 配置格式 | 不提升：沿用用户域路径与既有配置，没有新增布局代际 |
| Rust API / TS | 公共类型按新形态一次统一所有生产/测试消费者，用既有 export_typescript 生成投影，不手改生成文件 |
| 未发布中间形态 | 不保留双字段、空串兼容或两套恢复命令；v0.28.0 迁移入口由后续 C03 同版补充最终内容，不再虚构 C02/C03 软件版本 |

目录失败沿用 InvalidRequest/WorkspaceUnavailable/Store Conflict 等已有错误族；没有“空字符串成功”降级。认证、Path/UserPaths 准入、保护其他用户目录、敏感环境过滤和 Shell 的操作系统权限保持原状。

数据库升级只在实例锁/专用 Store 启动边界执行；备份、数量/关键内容回读、事务与失败停止遵循根规则。升级回退需要停止所有相关客户端/Host，恢复配套验证备份；不自动丢弃升级后数据。日常工作空间移除是逻辑状态改变，不递归删除文件。

草稿、账号菜单、窗口调整的失败仅影响对应客户端；不能因此停止整个 Runtime 或其他用户。Store 已提交但客户端断开后通过快照/幂等恢复，不以缺少 SSE 判定未保存。

## 九、验证与实施约束

按[功能验收](功能设计.md#七可观察验收点)执行最小必要验证：

- 协议 round-trip：Some/None、完整表单与空串拒绝、Removed 列表、恢复响应和 TS 生成一致；旧版本双向准入拒绝。
- Store/Runtime：多个 NULL 工作空间独立、同目录恢复、按 ID 重复恢复、目录编辑冻结、Volatile/SQLite 行为一致、权限未扩大。
- 迁移：带既有会话/removed/同名记录的旧库，表重建前后精确行数及内容、外键、回滚、备份读取、最低版本，失败不继续初始化；全部在新建隔离环境进行。
- 环境：私有 cwd 实际文件/Shell/终端/Skill/AGENTS，Fork/Clear/恢复，先私有后外部和反向编辑后的 Home 移动；不使用真实用户 Runtime Home。
- 前端：快捷菜单不会创建重复助理会话；归档页签移除后活动列表和显式归档筛选正确；草稿目标冲突包含设置与资源组；延迟查询/选择器/上传、物化未知重试、不串用户和不会双发；置顶分页/搜索/归档。
- 实机与浏览器：macOS 红绿灯/拖动/全屏/原生浏览器遮挡；Windows/Linux 控件；Web/远端目录与窄屏、键盘/焦点。

实现时最低命令遵循模块矩阵：协议生成检查、`cargo fmt --all --check`、涉及公共 Runtime 时 workspace clippy/test、Desktop `npm run build` 与相关测试；原生改动需 `npm run tauri -- build --no-bundle` 并实机验证。已有测试不足时只补上述不变量，避免机械用例或另外创建测试报告。

本轮仅阅读源码、Cargo metadata 与编制文档，未构建、未运行产品测试、未操作数据库。后续循环开发计划在本方案与交互指导确认后拆里程碑；根版本/下限修改由协调方统一负责，不能与 C01 抢写。

## 十、主要风险与否决方案

- **表重建外键：** 不能直接套用 ALTER/DROP；控制器能力必须以失败回滚和重新开启外键的测试证明，迁移回调不获任意 PRAGMA 权限。
- **历史私有 cwd 重定位：** 只按 Workspace ID 与旧私有路径精确匹配，不能根据当前目录为空批量猜测。
- **未知物化：** 普通 patch 目前会清 attempt，必须改 Store 门禁并验证原生/Web 两条入口；只禁 UI 按钮不够。补充查询依赖既有 key/事实，None 不是撤销保证；不得为此另建全局请求注册或取消协议。
- **资源页归属：** 目标资源组也参与冲突检查；已有终端继续原 cwd，界面必须让用户可识别，不能后台重开终端。
- **平台窗口：** 优先已有配置与安全 API；如实机证明需要新增 unsafe，超出现有例外，必须另行说明并取得明确授权，不自行扩大 FFI 范围。

否决：用私有路径伪装 user_directory；新增 WorkspaceKind；另建通用草稿/快捷入口服务；新权限模式；只改表单让后续 C03 收尾；为所有对象添加 revision；为置顶另存排名和列表；用空按钮为 Agent 占位。
