## 二、台账原则与实施边界

里程碑按“工作空间数据基础 → 真实执行环境 → 草稿与首次发送 → 工作台导航 → 初始化体验 → 循环验收”推进。每个里程碑完成实现和最小有效验证后标记为 `🟨 待确认`，汇报实际结果并停止；只有获得用户明确确认，才进入下一里程碑。计划确认不等于授权连续实施全部里程碑，也不包含 Git 提交、推送、阶段归档或发布授权。

计划只记录实施顺序、能力结果和门禁。字段、迁移算法、锁顺序、窗口尺寸、交互状态及失败恢复细节以已确认技术方案和交互指导为准；实施中发现现状不符或必须改变协议、数据归属、兼容策略时，先停止扩大并更新设计，不能以局部实现静默改变基线。

本循环保持以下范围约束：

- 不新增 Workspace 类型、草稿持久化系统、快捷入口服务、权限模式、通用装配 DSL、Core 执行分支或第三方依赖。
- “助理会话”只复用现有 Controller Session；移除的是常驻归档页签，不删除归档业务、历史数据或现有归档/恢复语义。
- 无用户工作目录的 Workspace 使用既有受管私有目录作为实际工作位置；Session 冻结 cwd 始终非空，已有会话不随 Workspace 编辑改写。
- 首次发送结果未知时只复用既有 materialization idempotency key 和可靠持久事实，不产生新的 Session、Input 或 Run。
- Agent 选择、插件安装和依赖状态属于 C03；C02 不显示无功能占位，也不提前接入中心接口。
- 自动化、迁移和集成验收只使用项目 `.runtime-test/` 下按场景新建的隔离 Runtime Home；不读写用户 `~/.ez-assistant` 业务数据。保留工作树其他改动，不自动暂存、提交或清理。

## 四、分里程碑实施与验证

### M0 工作空间协议与存储基础

- **目标**：先稳定可空用户目录、生命周期查询和明确恢复的跨层事实，并完成旧数据安全迁移，为后续执行与 UI 提供唯一语义。
- **前置**：开发计划已确认；实施前复核 Workspace 协议生产者/消费者、RuntimeStore、SQLite migration controller、VolatileStore 和软件/数据库兼容下限的当前实现。
- **交付范围**：
  - 将工作空间主目录及投影统一调整为真实可空表达，保持附加目录、实际 Session cwd 和私有目录的不变量；空字符串继续拒绝。
  - 接通按 lifecycle 查询已移除 Workspace 和按 Workspace ID 恢复的 Command/Result、Runtime dispatch、Client 与 TypeScript 投影；恢复复用既有 Registry、权限及事件发布流程。
  - 统一 RuntimeStore、SQLite 和 VolatileStore 的创建、更新、查重、移除和恢复行为；无目录创建始终分配新身份，有目录继续按规范化主目录保持既有唯一/恢复语义。
  - 在既有迁移控制器内重建 `workspaces` 表，使 `user_directory` 可为 NULL；保留 ID、生命周期、时间、目录 JSON、外键和非空目录唯一性，同事务提升数据库最低 Host 版本并同步套件兼容下限。
  - 补充协议、Store、迁移及失败恢复测试；不修改私有目录文件或历史 `session_resources.working_directory`。
- **验证入口**：协议 round-trip 与 TS 生成检查；`assistant-protocol`、`assistant-runtime`、`assistant-runtime-host` 的定向测试；旧库夹具覆盖 active/removed、有会话引用、同名记录、多个 NULL、回滚、备份可读、外键及最低版本拒绝。数据库测试只在新建隔离 Home 中运行。
- **完成判定与 Review**：覆盖 C02-A09/A12/A13 的协议和存储部分；多个无目录 Workspace 不合并，按 ID 重复恢复幂等，迁移失败不开放业务服务且外键不会遗留关闭状态。重点 Review 表重建事务、Store 已提交后投影失败的恢复路径、Option 语义和旧客户端拒绝；不得用空字符串或私有路径伪装用户目录。

### M1 私有工作目录与冻结执行环境

- **目标**：让仅私有目录 Workspace 在所有真实消费者中与普通 Workspace 一样可执行，同时保持 Session 冻结和受管资源恢复边界。
- **前置**：M0 获确认；复核环境工厂、Session 创建/物化、Fork/Clear、历史加载、资源修复、文件/Shell、PTY、Skill/规则和原生打开目录的当前调用链。
- **交付范围**：
  - 统一有效工作位置为用户主目录或既有 Workspace 私有目录，Runtime/Host 消费者不得自行回退 OS Home 或进程 cwd。
  - 创建和首次物化冻结非空 cwd、附加根及 Workspace 私有目录；历史载入不再把 NULL 用户目录误判为关联缺失，Fork/Clear 继续读取来源 Session 冻结环境。
  - 接通文件、Shell、Workspace/Session 终端、Skill/AGENTS 发现、权限根、目录打开/复制及上下文展示；Web/远端 Desktop 继续针对目标 Host，不误用客户端路径。
  - 完成 Workspace 私有目录随 Runtime Home 合法重定位时的精确修复，只更新同 Workspace 且 cwd 精确等于旧私有目录的历史资源，不改写外部路径或冻结正文。
  - 恢复无目录 Workspace 时准备并校验原受管目录；不可创建或不可读时显式失败，不自动换用其他位置。
- **验证入口**：Runtime/Host 环境与资源定向测试；正式 Host 隔离场景中实际执行文件、Shell、终端、Skill/AGENTS；覆盖目录从空到有、有到空、替换主目录、重启、Fork、Clear、移除/恢复和 Runtime Home 移动。涉及原生目录打开时执行 Desktop 构建及对应 Tauri 定向验证。
- **完成判定与 Review**：覆盖 C02-A08—A14 的执行、冻结和隔离部分；新会话使用当前有效目录，旧会话保持原冻结位置，同一 Workspace 共享 Workspace 私有目录但 Session 私有目录/附件仍独立。重点 Review 权限未扩大、兄弟用户/Workspace 不可访问、重定位只改可证明受管路径，以及 Shell 仍按当前用户权限运行而非强沙盒。

### M2 草稿迁移与首次发送可靠性

- **目标**：在不新增草稿系统的前提下完成工作空间切换、资源归属迁移和结果未知的首次发送确认，确保不丢内容、不串 owner、不双发。
- **前置**：M1 获确认；核查 NewSessionDraftStore、RootStore、ResourceWorkspaceStore、附件 selection、Skill/MCP 查询及现有 materialization key/Store 恢复路径。
- **交付范围**：
  - 在现有草稿 map 内实现原子移动：目标无自定义内容且双方无未解决物化/在途选择或发送时才允许；冲突只取消或打开目标草稿，不覆盖、不合并。
  - 同步转移草稿资源组，保留实际文件引用、终端原 cwd、文字、附件选择、引用和执行设置；能力缓存按新 Workspace 失效重查，不可用选择保留并阻止发送直至处理。
  - 所有异步回调核对连接 owner、草稿 key 和请求对象身份；文件选择/上传/首次发送期间禁止移动，源对象销毁后的迟到结果直接丢弃。
  - 增加按原 materialization idempotency key 读取可靠结果的 Command/Store 查询及必要 Runtime 恢复投影；查询只读，不重建 Input/Run、不重新执行模型或工具。
  - 发送结果未知时冻结原 manifest；“重试确认”先查询再以同一 key 重试，单次 None、配置变化或附件失效都不能自动换 key。普通草稿 patch 不再清除未解决 attempt。
- **验证入口**：Desktop Store/组件定向测试与 Runtime/Host materialization 测试；覆盖文字、附件、引用、非默认模型/档位、Skill/MCP、资源标签、已开终端、延迟响应、结果未知、导航离开、账号/Host 切换和重复确认。执行协议生成检查、相关 Rust 定向测试及 Desktop `npm run test`/`npm run build`。
- **完成判定与 Review**：覆盖 C02-A04—A07 的草稿与发送可靠性部分；无冲突时完整移动且原 key 移除，有冲突时两份草稿都保留，任何路径不会把原物化意图提交到另一 Workspace 或产生第二个 Session。重点 Review materialization 查询不重跑历史副作用、selection 生命周期、资源组目标冲突和晚到回调隔离。

### M3 工作台壳层与会话导航

- **目标**：完成移除旧通栏后的桌面壳层和高频导航，使窗口、账号、会话与历史查找在展开、折叠和窄窗口中均可达。
- **前置**：M2 获确认；复核 AppShell、SessionSidebar、NavigationStore、AccountMenu、RuntimeStatus、DesktopWindowControls、macOS Overlay 和原生浏览器 overlay 遮挡机制。
- **交付范围**：
  - 移除整条旧顶部菜单，建立左侧顶部控制/快捷菜单、中部滚动导航、底部账号与 Runtime 入口；中栏会话标题和右栏资源标题各自保留局部操作区。
  - 实现“新建会话”“助理会话”快捷项；前者直接进入无 Workspace 草稿，后者选择既有 Controller Session，并移除列表中重复的主控分组。
  - 移除常驻“会话/已归档”页签，常规列表固定活动范围；搜索/筛选显式进入已归档并在关闭后恢复活动列表，继续复用现有分页查询和归档业务动作。
  - 将现有置顶事实投影为“置顶”独立分组，保持工作空间归属、一次展示、搜索/分页/归档和取消后的原排序。
  - 账号、Host、连接状态、设置、改密、打开 Web、重连和退出迁入左下统一菜单；保持身份失败、初始化失败和权限边界。
  - 完成 macOS 红绿灯预留/拖动/全屏、Windows/Linux 窗口按钮与折叠轨、Web 无伪原生控件、窄窗口及原生 child WebView 浮层重算。
- **验证入口**：SessionSidebar/AppShell/Navigation/账号菜单组件与 Store 测试；Desktop `npm run lint`、`npm run test`、`npm run build`。原生改动执行 `npm run tauri -- build --no-bundle`；macOS 实机核对展开/折叠、最小窗口、全屏、拖动和原生网页遮挡，Windows/Linux 按可用环境完成窗口控制验证，未执行平台如实保留。
- **完成判定与 Review**：覆盖 C02-A01—A03；旧通栏和常驻归档页签不存在，快捷项不会新建重复 Controller Session，每个普通会话只出现一次，窗口和账号操作始终可达。重点 Review 搜索/筛选关闭后的状态恢复、分页范围、键盘/焦点/可访问名称和平台原生热区，不能只凭截图验收。

### M4 新会话与工作空间产品闭环

- **目标**：在新壳层中完成可直接开始任务的新会话页面，以及先开窗口、目录可选、可明确恢复的 Workspace 全流程。
- **前置**：M3 获确认；复用 M1 的真实环境和 M2 的草稿门禁，不提前接入 C03 Agent/插件状态。
- **交付范围**：
  - 实现统一的新会话初始化布局：快捷入口、Workspace 选择/清空、Composer 和既有执行设置；全局与 Workspace 入口沿用各自草稿，首次发送前不创建 Session。
  - 实现“整理文档”“使用技能”“使用 MCP 服务”首批快捷入口；只预填或打开现有选择器，不自动发送、不静默覆盖正文、不修改全局启停。
  - 切换 Workspace 时使用 M2 的移动/冲突流程；明确展示能力不可用、文件选择/发送门禁及结果待确认状态。C02 不渲染 Agent 空框。
  - 调整 WorkspaceEditorDialog 为先显示名称和可选目录；目录选择取消保留表单，允许移除最后一个用户目录并显示“仅使用私有目录”，保存失败不丢内容。
  - 增加已移除 Workspace 恢复窗口，按原记录 ID 恢复并展示名称、目录摘要/仅私有目录及移除时间；创建结果未知不自动重发，无目录新建不冒充恢复。
  - 当前有效目录与 Session 冻结目录在选择器、详情、右栏和终端信息中正确区分；同名无目录 Workspace 可识别。
- **验证入口**：WorkspaceEditor、恢复窗口、新会话 Composer、快捷入口、SelectionPopover/Dialog 和焦点行为的组件/Store 测试；正式 Host + Desktop/Web e2e 覆盖创建、编辑、移除/恢复、草稿冲突、快捷装配及首次发送。执行 Desktop lint/test/build，并按受影响原生范围执行 Tauri 构建和真实页面验证。
- **完成判定与 Review**：覆盖 C02-A04—A12 的产品交互部分；创建窗口先出现，无目录可成功创建和真实执行，同名项不会合并，冲突与失败不丢草稿，快捷入口最终只落到现有实际控件。重点 Review Web/远端路径属于目标 Host、200% 缩放/窄屏/中文输入法/长错误文案、浮层遮挡和键盘焦点。

### M5 C02 精简收口与 C03 交接

- **目标**：依据 M0—M4 已有结果完成一次交接检查，让后续 C03 联调直接使用稳定的布局、草稿和 Workspace 边界，不重复开展全量回归。
- **前置**：M0—M4 均获用户确认；已知 C02 缺陷必须修复或明确记录影响，不能将未完成实现伪装成 C03 联调事项。
- **交付范围**：用现有设计、定向测试和隔离场景逐项复核 C02-A01—A14 的结论；只补最后变更与高风险交界的短链路冒烟，重点是新会话首次发送、Workspace 创建/移除/恢复、仅私有目录执行和协议兼容。核对 C01 并行改动没有改变 C02 权威状态与 UI 入口。向 C03 明确交付初始化选项区域、草稿 owner/冲突规则、Workspace 有效目录及恢复契约，不实现 Agent/插件。
- **验证入口**：复用已通过的 Desktop/Web、Runtime/Host 定向结果，执行改动覆盖所需的构建/静态检查及少量正式 Host 集成场景；不为 M5 重跑全仓测试或完整平台矩阵。涉及数据库的新增场景仍只用 `.runtime-test/` 新建隔离 Home，遵守备份和逐项核验。
- **完成判定与 Review**：A01—A14 各有已验证、未覆盖或风险结论；交接契约没有歧义，已知失败不留给 C03 猜测。macOS 原生窗口/child WebView 与 Windows/Linux 未实测项明确列为后续联调或版本验收门禁，不写成已通过。用户确认 M5 后才整理阶段总结并进入提交准备；提交、阶段归档和进入 C03 仍分别等待明确授权。

## 五、共用验证门禁

以下是实施时的验证入口，不表示本计划编制阶段已经执行。每个里程碑先运行覆盖改动的定向检查；涉及公共协议、Runtime、持久化或原生窗口时按风险扩大，循环收口执行完整必要门禁。

| 范围 | 验证入口 |
| --- | --- |
| Rust 格式、公共协议、Runtime 与 Host | 根目录 `cargo fmt --all --check`、`cargo clippy --workspace --all-targets --all-features -- -D warnings`、`cargo test --workspace`；定向使用 `cargo test -p assistant-protocol`、`cargo test -p assistant-runtime`、`cargo test -p assistant-runtime-host` |
| 协议 TypeScript 投影 | `cd apps/desktop && npm run generate:protocol` 后 `npm run check:protocol`；生成物只由正式导出器更新，不手改 |
