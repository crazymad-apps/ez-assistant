# v0.18.0 版本总结：Todo、Goal 与 Composer 执行入口

## 一、版本结论

`v0.18.0` 于 2026-08-22 完成开发、验证、用户验收与归档。本版建立了与 Goal 正交的
Session WorkPlan、由 Runtime 持有的持久 Goal 跨 Run 自动续跑控制器，并重组 Desktop Composer
执行入口，形成长任务从计划、自动续跑、阻塞恢复到可靠终止的产品闭环。

## 二、主要交付

1. **Session WorkPlan**：总体目标和 Todo 独立于 Goal 持久存在；父 Agent 通过不暴露内部 ID 的
   `update_plan` 完整替换计划，Runtime 负责 ID 调和、revision CAS、重启/Fork 和全完成自动清除。
2. **持久 Goal 控制器**：一次性 `/goal` 把完整 UserMessage 标记为 objective；Runtime 管理 GoalId、
   generation、turn、Run/token/失败预算，以及 complete、blocked、Stop、Resume、Clear 和恢复状态。
3. **原子跨 Run 续跑**：首次 Goal Input/Run 原子接受；每次可靠结算与 Goal 转换、预算累计和隐藏
   Runtime continuation 创建处于同一事务，世代门禁阻止停止后的迟到信号重新启动 Goal。
4. **规范消息与产品投影**：UserMessage 新增来源和 transcript 可见性；内部 continuation 以 user role
   进入模型上下文和审计，但不进入产品气泡、用户轮次、标题、搜索、Recall 或导出。
5. **协议与正式 Host**：应用协议提供 WorkPlan/Goal/held Queue 快照、控制命令、稳定错误和失效事件；
   正式 Host 离线场景覆盖四 Run、blocked/resume、Stop/cancel、重启恢复及 SQLite/JSONL 物理事实。
6. **Composer 重组**：底栏收敛为五项常驻入口；执行设置和模型设置使用二级级联；Todo 使用紧凑浮动
   检视层，Goal 与 Queue 使用一致的内联二级抽屉，Approval 与 Queue 保持已确认层级关系。
7. **产品补充**：工作空间支持确认后移除、隐藏关联会话及同目录恢复；DeepSeek V4 Flash Vision
   Experimental 纳入原生多模态目录；`read_image` 详情以原图预览为主体并移除实时缩略图生成。
8. **版本同步**：Rust workspace、npm 和 Tauri 产品版本统一为 `0.18.0`。

## 三、验证摘要

- Rust workspace 格式、全目标全 feature Clippy `-D warnings`、全量测试与版本同步后的全目标检查通过；
- Desktop lint、20 个 Vitest 文件共 106 项、生产构建、正式 Host Playwright E2E 和 Tauri release
  `--no-bundle` 构建通过；
- 正式 Host + fake Provider 跨 Run Goal 场景通过，并核对 SQLite、JSONL 与产品 Conversation；
- 经用户授权，正式 Host 真实 Provider Goal 用例 1 项通过：`update_plan` 后跨 Run 自动续跑，
  `update_goal complete` 可靠清除 Goal，全程无 Judge，日志无凭据和目标正文泄漏。

详细命令、环境、人工核对与完成判定见 [验收记录](验收记录.md)。

## 四、偏差、遗留与非目标

- 100%/125%/150% 缩放、中文输入法和高 DPI 没有独立自动化，保留为后续视觉回归基础设施事项。
- 真实 Goal 只覆盖当前配置的默认 Tool Call 模型，其余 Provider 由双协议 fixture 和离线 Host 回归保障。
- Windows Runtime Host、PowerShell 默认 Shell 及 Windows/Linux 安装包仍为非目标。
- Vite 生产构建仅保留既有 chunk-size warning，无已知功能或运行阻断。
