## 四、真实 Provider Goal 验证

用户明确授权后执行：

```bash
cargo test -p assistant-runtime-host --test v0_18_real_goal \
  configured_model_auto_continues_a_goal_across_runs -- --ignored --exact --nocapture
```

结果为 1 项通过、0 项失败，耗时 9.80 秒。测试使用正式 Runtime Host，只读复制现有模型配置到
隔离临时 Runtime Home，不写入用户实际 Runtime 数据或 Workspace。配置的默认 Tool Call 模型先成功
调用 `update_plan`，Runtime 至少跨一个业务 Run 自动续跑，再以独占工具批次调用
`update_goal complete` 并清除 Goal。测试未观察到 Judge 工具；Host 输出未包含 access token、
模型 credential 或测试目标正文。

## 五、功能与兼容验收

1. WorkPlan 与 Goal 保持正交：非 Goal 会话也可持久维护总体目标和 Todo；Goal 生命周期不会复制、
   改写或清空计划，完成 Todo 和完成 Goal 分别按自身规则自动清除。
2. `/goal` 是一次性草稿标签，指令字面量不发送；只能点击标签 `×` 取消，`Esc` 不取消，提交失败
   保留正文、附件和标签。
3. Goal objective 来自首次完整可见 UserMessage，正文、图片和文件引用保持有序载荷；Goal 注入与
   Runtime continuation 只追加为模型可见、产品转录隐藏的 user role 消息，不修改 System Prompt
   或任何历史消息。
4. Runtime 以 GoalId、generation、turn 和冻结预算持有权威控制状态；Run 可靠结算、Goal 转换与
   continuation 创建处于同一事务边界，complete、blocked、预算暂停、Stop、Resume、重启恢复和
   迟到信号均有世代门禁。
5. Goal 运行期间的普通用户输入保持 held，不打断、不丢失、不自动消费；Goal 完成或清除后也不会
   无确认批量执行。Fork 后 WorkPlan 和 Goal 都是独立副本。
6. 正式 Host + fake Provider 场景完成四 Run Goal、WorkPlan 更新、blocked/resume、Stop/cancel 和
   杀 Host 后 recovery/resume；只读物理核验确认 SQLite 为 1 条用户 Input + 3 条 Runtime Input、
   4 条 completed Run，当前 JSONL 为 1 条 visible user + 3 条 hidden runtime user，产品 Conversation
   只投影 1 条用户消息。
7. Goal 中的工具继续遵守 Plan/Build、Ask/Auto、Deny、审批、取消和审计边界；`update_goal` 必须
   独占工具批次，Tool 执行只记录信号，状态转换等待所属 Run 可靠结算。
8. Desktop Composer 已收敛为添加、执行设置、上下文用量、模型设置和发送/停止五项；执行模式与
   审批模式、模型与 reasoning effort 分别通过二级级联保持正交，识图能力移入 Context Panel。
9. Todo 以内容自适应且有最大宽度的浮动状态条和紧凑检视层展示；Goal、Queue 复用内联二级抽屉，
   展开互斥并保留层级、接缝覆盖与有限高度；Approval 收起入口位于 Queue 上方。
10. 工作空间移除前二次确认，不删除本地目录或历史会话；移除后目录及所属会话从侧栏、搜索和新会话
    候选隐藏，重新添加同一路径恢复原 Workspace ID 和关联会话，不额外创建空 Session。

## 六、安全、隐私与持久化核对

- Runtime continuation 的来源和 transcript 可见性保存在规范 Conversation 与 JSONL 中，但 Provider
  Adapter 只发送受支持的 role/content，不泄露产品元数据。
- Objective 恢复载荷、内容哈希、Goal generation 和内部 Todo ID 不进入 Desktop 投影；模型侧
  `update_plan` 不依赖 Todo ID，Runtime 继续以 CAS 与 ToolCallId 保证持久更新一致性。
- SQLite/JSONL staged append、Goal settlement、WorkPlan receipt、重启、Fork、Context replacement、
  Recall 排除和 Session 删除均有故障/恢复测试，历史工具副作用不会因恢复而重放。
- `read_image` 详情直接预览首次物化的原图；预览读取继续校验普通文件、MIME、内容哈希和 16MB
  响应上限，不再为每次预览实时生成 320px JPEG。
