# v0.18.0 界面交互设计指导：Todo、Goal 与 Composer 执行入口

## 一、设计信息

- 版本：`v0.18.0`
- 状态：已确认（2026-08-20）
- 影响页面：Desktop 主会话中栏 Composer、右侧 Context Panel
- 关联设计：[`v0.18.0 功能设计`](功能设计.md)、
  [`v0.18.0 技术方案`](技术方案.md)
- 视觉基线：[`Desktop 设计语言`](../../resources/桌面端设计语言.md)

本文只收口 Composer 重组所需的布局、层级、焦点、窄宽度和状态反馈。
WorkPlan、Goal、Queue 和 Approval 的权威语义以 Runtime 快照为准，Desktop 不自行推导。

## 二、页面与入口

1. 本版本不新增页面，所有入口均位于现有主会话 Composer 和 Context Panel。
2. `/goal` 从现有 Slash Command 列表选择；选择后转换为输入区内的一次性
   `Goal` 标签，指令字面量不保留在正文。
3. Todo 由 Agent 的 `update_plan` 维护；存在 WorkPlan 时才出现顶边摘要。
4. Goal 状态行只在 Session 存在未清除 Goal 时出现。
5. 识图路径移入右侧 Context Panel 的当前模型能力区，不再占用 Composer 底栏。

## 三、布局与信息结构

### 3.1 纵向排布

Composer 自上而下的固定层级为：

```text
Todo 摘要锚点（浮动，不占布局高度）
Goal 状态行（存在时占一行）
待审批收起入口（存在时占一行）
Queue 入口（存在时占一行）
完整 Approval Workspace 或 Composer Input（互斥）
```

- Todo 摘要与 Composer 顶边对齐，以 overlay 形式向上展开，不挤压输入区。
- Goal、Approval Restore 和 Queue 都是普通布局行，不互相覆盖。
- Goal 与 Queue 共用的二级抽屉相对输入框左右各内收 `8px`，通过露出输入框两侧
  边界形成层级差；收起与展开使用同一外壳尺寸，底部仍用负距离覆盖中部接缝。
- 完整审批打开时替换输入框，但顶部 Todo 摘要与 Goal 状态行仍可见；Todo 浮层需关闭，
  Goal 与 Queue 的内联抽屉可以保持展开。

### 3.2 Todo 摘要与详情

- 收起态是内容驱动宽度、最大宽度 `360px` 的单行实时状态条；短步骤时随文字自然收窄，
  仅在长步骤达到上限后截断。状态条只显示 loading 状态、当前进行项（无进行项时
  回退到首个待执行项）的缩略文字和展开箭头；不重复工作计划 objective 或 Todo 计数。
  文字超出时省略，不通过增高解决，避免鼠标横向经过时频繁误触 hover。状态条使用浅色
  primary surface；详情使用接近白色的实色面板和略加强的阴影。会话区背层使用覆盖完整横向
  范围的白色透明渐变，不使用 `backdrop-filter`；遮罩位于详情、状态条和 Composer 二级抽屉背后，
  底部持续铺到会话区底边，顶部依据详情实测高度上移并预留渐隐缓冲。标题换行或列表高度变化时
  遮罩同步适配；底部仍保留部分透明度，使背景消息隐约可辨，既不在状态条处截断，也不形成
  可交互的模态蒙层。
- hover、键盘聚焦或点击均可展开详情；详情使用 `pointer-events: none`，不形成可停留区域，
  鼠标离开摘要后立即触发隐藏。详情与白色渐变使用 `110ms` 淡入淡出，详情同时带轻微纵向位移；
  退出动画期间只保留视觉节点，不保留可访问或可交互状态。键盘焦点离开摘要或按 Esc 时隐藏。
- 详情显示 objective 正文和有序 Todo，不额外显示“总体目标”提示词；使用状态图标区分
  pending、in progress、completed，不提供前端直接编辑、关闭或清空计划按钮。
- 详情最大宽度放宽到 `640px`，objective 标题允许自动换行并随内容增高，Todo 项保持单行省略；
  不跟随 Composer 拉满，以状态条中线居中，超出视口时再按实测 DOM 尺寸夹取。
- 至少一个 Todo 全部完成后 Runtime 自动清除 WorkPlan，摘要与已展开详情随下一份权威快照移除。

### 3.3 Goal 状态行与详情

- 状态行显示 Goal 主状态、一行 objective 摘要和主操作；主状态固定不换行，空间不足时由
  objective 摘要优先收缩和省略。运行中使用蓝色小型加载状态，
  暂停/等待用户使用橙色。完成 Goal 在可靠结算中自动清除，不保留绿色完成行。
- 只有点击或键盘激活才展开详情，不响应 hover，避免执行中频繁误展开。
- 展开方式与 Queue 保持一致：详情在状态行下方内联向下展开，参与正常布局并下推后续区域，
  不使用 portal 或悬浮覆盖会话内容。
- 详情最大高度为 Composer 当前可用高度的有界子集，正文内部滚动并设置
  overscroll containment；摘要行已经展示 objective，详情只保留当前轮次、预算和暂停原因，
  不再重复标题、objective、世代或操作 footer。
- Running 提供“停止”；Paused 提供“继续”，并在摘要行右侧以 `×` 退出 Goal。点击 `×` 必须二次
  确认，确认文案说明只清除自动续跑控制状态，Todo 与排队输入保留。
- Goal 与 Queue 复用同一个二级抽屉 header 和外壳；header 不为 Goal 单独增加局部 hover 色块。
  收起和展开都用 10px 外壳底部 padding 配合 10px 负 margin 覆盖下一区域的圆角接缝；展开态把
  外壳 padding 增至 16px，并由正文自身再保留 10px 底部 padding。外壳使用低于输入框和浮层的
  轻量向上阴影强调层级；状态切换不能重新露出页面底色。
- Goal 与 Queue 共享单一展开状态，同时最多展开一个；打开任一抽屉必须自动收起另一个，避免两份
  长列表同时挤压消息区和 Composer。

### 3.4 Composer 底栏

标准宽度下仅保留五个常驻视觉项：

```text
[+]  [Build · Auto]  [Context usage]  [Model · effort]  [Send/Stop]
```

- `+` 点击后直接选择附件，不打开二级菜单；Slash Command 通过正文键入 `/` 触发。
- 执行设置触发器同时显示 variant 和 approval 当前值，不隐藏 Auto 等安全事实。
- 上下文用量保留独立视觉和可访问名称。
- 模型设置触发器同时显示模型与有效 effort；过长模型名优先省略。
- 发送与停止共用右侧主操作位，按 Runtime 状态切换语义，不同时显示两个按钮。

## 四、交互流程

### 4.1 `/goal` 提交

1. 用户输入或选择 `/goal`。
2. Composer 清除指令字面量，保留已输入正文与附件，显示 `Goal` 标签。
3. 标签只能通过自身 `×` 取消；`Esc` 不取消标签。
4. 提交成功后才清空正文、附件与标签；提交失败完整保留草稿并展示可操作错误。
5. 已存在 Goal 或当前模型不支持 Goal 时，Slash 项禁用并给出原因；Runtime 仍最终校验。

### 4.2 停止、暂停与恢复

- Goal Running 且当前无可提交草稿时，主操作位是停止 Goal；操作后保留持续状态，
  直到 Runtime 快照确认 Run 已收敛。
- Goal 因 blocked、预算、重启或用户停止进入 Paused 后，状态行明确显示原因。
- 无正文恢复由 Runtime 生成隐藏 continuation；选择 held 用户输入恢复时，
  必须由用户在 Queue/Goal 交互中显式指定，不自动批量消费。
- “退出 Goal”只清除 Goal 控制状态，不清空 Todo 或 held 用户输入。

### 4.3 设置分类级联

- 执行设置一级面板两行：“模式 Build/Plan”、“权限 Ask/Auto”；激活一行时在右侧打开二级候选。
- 模型设置一级面板两行：“模型”、“推理强度”；两者是平级分类，不建立模型到强度的级联依赖。
- 一级面板保留当前值和右向指示；二级列表保留选中态、可用性说明和有界滚动。
- 键盘左/右在一、二级间移动，上/下移动候选，Enter 选择，Esc 先退回一级、再关闭面板。
- 选择成功后关闭面板并把焦点返回触发器；失败时保留当前有效值，不乐观伪造新状态。

### 4.4 移除工作空间

- 活动工作空间的更多菜单增加“移除工作空间…”，使用危险色但不表述为删除目录。
- 执行前使用二次确认，明确说明不删除本地目录或历史会话；已有会话时显示会话数量，
  并说明它们将一并隐藏。
- 移除后整个工作空间分组及其会话从侧栏和标题搜索隐藏，不显示“已移除”占位分组。
  重新添加同一目录时只恢复原工作空间与关联会话，不新建第二个 Workspace 记录，
  也不额外创建空会话。

## 五、浮层、抽屉、焦点与快捷键

1. Todo 详情和两类设置级联共用同一 overlay root，同时只有一个前台浮层。
2. Goal 与 Queue 都是正常布局中的向下内联抽屉，各自保持展开状态，不加入浮层互斥。
3. 打开新浮层时关闭前一个；完整 Approval Workspace 展开时关闭 Composer 浮层，不强制收起
   Goal 或 Queue 抽屉。
4. 浮层关闭后焦点返回原触发器；触发器被 Runtime 快照移除时，焦点回到 Composer 输入框。
5. `Esc` 只关闭当前最前浮层或级联层级，不取消 `Goal` 草稿标签，不触发停止 Goal。
6. 焦点环、ARIA 名称、菜单角色和 reduced motion 遵循现有 Desktop 设计语言。

## 六、响应式与视觉约束

- 标准 Composer 宽度沿用中栏最大 `820px`，不改变消息与输入的对齐基线。
- `720px` 及更窄可用宽度下，五个常驻项仍保持单行；优先压缩文本触发器并省略模型名，
  不隐藏发送/停止、权限状态或上下文用量。
- 底栏不产生水平滚动，不使用 JavaScript 宽度分支渲染两套 DOM；通过 Grid/Flex、
  `min-width: 0`、省略与有界面板完成适配。
- Todo 浮层不超出中栏可见边界；Goal 内联详情采用有界高度和内部滚动；二级面板在右侧空间
  不足时可向左翻转，但一、二级关系和键盘方向语义保持一致。
- 视觉密度沿用现有 `13px` UI 文字、小圆角、`1px` 边框和克制阴影；不引入大型彩色卡片。

## 七、状态与异常

| 状态 | 用户可见反馈 | 交互约束 |
| --- | --- | --- |
| Goal Running | 持续加载状态、轮次/预算可在详情查看 | 可停止；新用户输入只 held |
| Goal Paused(Blocked) | 等待用户及 Agent summary | 可携带新输入或选择 held input 恢复 |
| Goal Paused(预算/失败/重启) | 明确原因，不只用 Toast | 只能显式恢复或退出 |
| Goal 完成结算 | 状态行随权威快照自动移除 | 不自动消费 held input；普通队列仍需显式恢复 |
| 待审批 | 收起入口在 Queue 上方 | 完整审批与输入框互斥 |
| 连接中断/快照 stale | 沿用现有断线状态 | 禁止伪造 Goal/Todo 转换，等待快照恢复 |
| 命令失败 | 就地错误或现有持续错误入口 | 保留草稿和当前权威状态 |

## 八、验收口径

1. 组件测试覆盖 `/goal` 标签、提交失败保留、Todo hover/focus/click 与离开摘要立即关闭、
   Goal 点击后内联向下展开、Approval/Queue 顺序与完整 Approval 互斥。
2. 级联测试覆盖鼠标与键盘路径、二级边界翻转、选择失败和焦点返回。
3. Playwright/macOS `WKWebView` 验证 `720px` 及更窄宽度、长模型名、
   100%/125%/150% 缩放、中文输入法、Goal 详情滚动和审批切换。
4. Context Panel 能查看当前模型的图像理解路径，Composer 底栏不再存在识图常驻项。
5. 任何 UI 操作都不会在 Runtime 快照前本地伪造 Goal 或 WorkPlan 权威结果。
