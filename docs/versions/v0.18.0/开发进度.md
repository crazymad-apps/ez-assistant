### M4：原子续跑、停止与恢复

- 目标：建立跨业务 Run 的可崩溃恢复续跑链，使 Run 结算、Goal 转换、预算和下一轮创建没有半状态
- 影响模块：`assistant-runtime`、`runtime-host`
- 状态：✅ 已完成
- 实际结果：Runtime 已在单一 Store settlement 中原子结算当前 Run、应用 Goal signal、累计
  Run/token/连续失败预算，并完成 Goal、暂停 Goal 或创建绑定下一 turn 的隐藏 Runtime
  continuation。Stop 会先持久化 UserStopped、递增 generation、删除未领取 continuation 并记录活动
  Run 的取消意图，Store 成功后才发布取消 token；Clear 只移除已暂停/完成且无活动 Run 的控制器，
  保留 Conversation、WorkPlan 和 held Queue。Resume 同时支持无正文隐藏续跑、带新可见用户消息恢复，
  以及复用已有 held Input/Run，均显式进入新 generation，且不会复制 Input/Run。
- 修正：complete 转换在同一 settlement 事务中形成终态回执并立即删除 Goal 控制行；Runtime 内存
  与 SessionView 直接变为无 Goal，不再保留需用户手动退出的 Completed 控制器。
- 实际结果：启动恢复会把 Running Goal 原子暂停为 RecoveryRequired、递增 generation 并删除旧
  continuation；Fork 只在 objective 位于复制前缀内时建立新 GoalId 的 Forked 快照；历史重入在
  objective 处或之前拒绝，在其后则随 Conversation generation 切换原子暂停 Goal。Goal-bound 活动
  Run 不能走普通单 Run cancel，必须 Stop 整个 Goal，迟到回调受 generation fencing 限制。
- 实际结果：Host staged append 在写 JSONL 前以同一结算逻辑执行可回滚事务预检，避免 Goal effect
  非法时出现“Conversation 已追加、SQLite 未提交”的半状态；正式 finalize 仍在单一 SQLite
  transaction 中提交 Run、Goal、预算与后继 Input/Run。Fresh schema 不再让历史 Input 的 GoalId
  外键阻止 Clear，但 Session 删除仍按 Session 级联清理。
- 验证结果：`assistant-runtime` 182 项全部通过；Host 单元 121 项通过、1 项手工性能基线 ignored，
  离线正式 Host 集成全部通过；需凭据或费用的真实 Provider 用例保持 ignored。专项覆盖 Complete、
  Blocked/新消息 Resume、无消息 Resume、held Input Resume、Stop/Clear、Run/token/连续失败预算、
  Fork、历史重入、重启清理陈旧 continuation，以及非法结算的 SQLite/JSONL 整体回滚。
  两包 clippy `-D warnings`、`cargo fmt --all --check` 与 `git diff --check` 通过。
- 当前步骤：M4 实现、事务边界反查、恢复/竞态专项、全量回归和模块约束同步已完成
- 续作点：用户确认后由 M5 增加 Goal/WorkPlan 快照、Stop/Resume/Clear 命令、稳定错误、事件和
  正式 Host HTTP/SSE 闭环
- 里程碑确认：用户于 2026-08-21 确认继续开发
