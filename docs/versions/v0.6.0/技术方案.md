## 二、现有实现核查

### 2.1 可直接复用的边界

| 现有能力 | 位置 | 本版本用途 |
| --- | --- | --- |
| `ModelService::stream` | `agent-model` | `Err` 是唯一可透明重试的建流前边界，`Ok(stream)` 后不重试 |
| `ModelCallContext` / `TraceContext` | `agent-model` | 复用已有控制面类型；本版本首次接通逻辑模型调用、attempt 与 Provider wire 的生产链路 |
| `ModelRequest` / `ModelEvent` | `agent-model` | 直接记录完整规范输入和输出，不复制 Trace 版本 |
| `LifecycleValidator` | `agent-model` | Wire Replay 后继续校验唯一终态与事件顺序 |
| `TransportRequest` / `TransportResponse` / `BodyStream` | OpenAI-compatible Adapter | 在编码后请求和实际响应字节边界进行透明观察 |
| `AgentEvent` | `agent-core` | 直接记录 Agent 事件，不新增 TraceAgentEvent |
| `ObservedModelService` 与三通道调试 payload | Runtime Harness / debug-viewer | 复用“完整请求、建立结果、逐个模型事件”的语义；不建立依赖 |
| `RecordedTransport` / `ScriptedModelService` | `agent-testkit` | 复用故障脚本思路和断言能力；Demo 不把 testkit 作为生产依赖 |

### 2.2 当前缺口

1. `ModelCallContext.trace` 当前只有类型和单元测试，没有生产调用方；Runtime Harness 的
   correlation 走独立 `DebugClient` 字段。本版本需要从 ObservedModelService 开始建立新的
   trace 传递链，并让 `TransportRequest` 携带 trace/attempt，Provider wire 才能与并发调用
   稳定关联。
2. OpenAI-compatible Service 当前把 `TransportError` 直接转成展示字符串，Connect、Timeout、
   Interrupted 分类在 Model 边界丢失；`Transport(String)` 和 `RateLimited(String)` 也不足以
   无字符串解析地决定重试，HTTP `Retry-After` 也没有进入规范错误。
3. 当前没有 retry attempt 的原生事件。
4. debug-viewer 的发送允许丢弃，不能证明记录完整。
5. `RecordedTransport` 到 Provider `Transport` 的实现只在 Provider crate 测试中存在，不能直接
   作为独立 Demo 的离线 Transport。
6. `ModelError` 经 `ModelEvent::TurnFailed` 进入 debug-viewer wire JSON；结构化错误会改变该
   开发协议的 JSON 形状和 serde round-trip 测试。当前不存在需要兼容的正式产品协议或历史
   Trace，但仓库内生产者、消费者和测试必须同步迁移。

因此本版本只新增 Provider wire 事件、retry attempt 事件、结构化模型错误事实和必要的关联字段。

## 三、总体装配

真实调用的装配顺序如下：

```text
Agent Core
  → Demo/未来 Runtime 的 ObservedModelService
      记录完整 ModelRequest、建立结果、完整 ModelEvent
      为逻辑模型调用生成 correlation_id
  → RetryingModelService
      记录 attempt，且只处理 stream() 直接返回的 Err
  → OpenAiCompatibleService
      编码真实 Provider 请求、解码真实响应
  → ObservedTransport
      记录不含 credential 的编码请求、响应头、raw chunks 和 TransportError
  → ReqwestTransport
```

各观察点只把所属层已有事实交给宿主提供的观察器。公共 crate 不创建目录、不打开 Trace 文件、
不决定保留周期，也不知道 Session 或 Run。

Reliability Demo 私有实现一个 Collector，将上述事实与 `AgentEvent`、Demo 宿主事件汇入同一条
有序记录流并落盘。正式 Runtime 本版本不接入。

## 四、调用关联

### 4.1 `TraceContext`

复用现有 `TraceContext` 作为控制面容器，增加可选的 1-based attempt。这里复用的是类型，
不是既有生产链路；当前生产代码尚未传递该字段：

```rust
pub struct TraceContext {
    pub correlation_id: String,
    pub attempt: Option<u32>,
}
```

- `correlation_id` 由最外层宿主为每个逻辑模型调用生成；它仍不是业务 `RunId`。
- `ObservedModelService` 在调用下层前写入唯一 `correlation_id`。
- `RetryingModelService` 每次调用真实 Adapter 前只更新 `attempt`。
- `OpenAiCompatibleService` 把上下文复制到 `TransportRequest`，但不会把它编码成 HTTP header。
- 未启用观察或由普通调用方直接使用时，`trace` 继续允许为 `None`。

`attempt` 使用 `Option` 并带 serde 默认，保持既有只含 `correlation_id` 的序列化输入可读。所有新建
attempt 都从 1 开始；0 视为非法观察数据。

### 4.2 `TransportRequest`

增加仅供进程内关联的字段：

```rust
pub struct TransportRequest {
    pub method: String,
    pub url: String,
    pub headers: Vec<(String, String)>,
    pub body: Vec<u8>,
    pub trace: Option<TraceContext>,
}
```

`ReqwestTransport` 忽略 `trace`，网络请求保持不变。测试 Transport 和观察包装器读取该字段，但
不得把它注入请求。这样并发调用不依赖全局“当前 attempt”状态，也不需要解析关联字符串。

## 五、Provider wire 观察

### 5.1 公共类型

在 OpenAI-compatible Adapter 的 transport 模块增加：

```rust
pub enum ProviderWireEvent {
    Request {
        trace: Option<TraceContext>,
        request: RecordedWireRequest,
    },
    ResponseStarted {
        trace: Option<TraceContext>,
        status: u16,
        headers: Vec<(String, String)>,
    },
    ResponseChunk {
        trace: Option<TraceContext>,
        bytes: Vec<u8>,
    },
    ResponseFailed {
        trace: Option<TraceContext>,
        error: TransportError,
    },
    ResponseFinished {
        trace: Option<TraceContext>,
    },
}

pub struct RecordedWireRequest {
    pub method: String,
    pub url: String,
    pub headers: Vec<(String, String)>,
    pub body: Vec<u8>,
}

pub trait ProviderWireObserver: Send + Sync {
    fn observe(&self, event: ProviderWireEvent);
}
```

`ProviderWireEvent`、`RecordedWireRequest` 和 `TransportError` 补齐 `Clone`、`Debug`、比较与 serde
能力，确保 native wire 事实可以直接进入宿主记录。`TransportError` 的文本已经受 Transport
契约约束为脱敏诊断，因此不再复制一套只用于序列化的错误枚举。

内存类型继续持有原始 `Vec<u8>`。serde 时，`RecordedWireRequest.body` 与
`ProviderWireEvent::ResponseChunk.bytes` 通过字段级 Base64 serializer 编码成字符串，反序列化
时无损还原；避免 JSON byte array 的明显体积膨胀。该实现只改变 wire 观察类型的 JSON 表示，
不改变 Transport 的原始分块。

`RecordedWireRequest` 是有意存在的安全记录类型：它不是第二套业务请求，而是从
`TransportRequest` 构造时就排除了 credential 的 wire 快照。`TransportRequest` 本身永远不能
直接序列化为 Trace。

观察器为同步通知接口，只允许快速复制到宿主队列，不返回错误、不阻塞网络流，也不参与调用
结果。实现若无法接收事件，应自行把 Trace 标为 Incomplete。

### 5.2 credential 与 header 规则

请求侧在构造 `RecordedWireRequest` 时完全删除以下 header，不写占位值：

- `authorization`
- `proxy-authorization`
- `x-api-key`
- `cookie`
- `set-cookie`

响应侧只记录明确允许的 header：

- `content-type`
- `retry-after`
- `request-id`、`x-request-id`
- `ratelimit-*`、`x-ratelimit-*`

名称按 ASCII 小写判断，原值只在允许列表中保留。完整 request body 和 response chunks 按功能
设计保留，因此整个 Trace 仍是高敏数据。

认证排除还覆盖 URL：OpenAI-compatible Service 构造时拒绝包含 userinfo、query 或 fragment 的
base URL，本版本的 credential 只能通过专用 credential 配置注入认证 header。这样
`RecordedWireRequest.url` 可以保留实际 scheme、authority、path，又不会把 URL 中潜藏的 key
写入 Trace。未来确需 query 参数的 Adapter 必须使用类型化非认证配置并单独制定记录规则，不能
绕过当前构造边界。

### 5.3 `ObservedTransport`

新增透明 `ObservedTransport`，内部持有下层 `Arc<dyn Transport>` 和
`Arc<dyn ProviderWireObserver>`：

1. 转发前发送安全的 `Request` 快照；
2. 建立失败发送 `ResponseFailed`，原样返回同一个 `TransportError`；
3. 收到响应头后发送 `ResponseStarted`，传给 Adapter 的原响应头不裁剪；
4. 包装 `BodyStream`，逐项先观察再原样产出 chunk 或错误；
5. 下层流自然结束时发送 `ResponseFinished`。

观察前后必须保持相同分块、顺序、取消和错误。上层在收到协议终止标记或错误采样完成后可能
主动停止消费 BodyStream；Trace 表达的是 Adapter 实际观察到的字节，而不是假设服务器后续还会
发送的未消费内容。精确回放复现相同的已观察输入。

## 六、结构化模型错误

### 6.1 类型调整

在 `agent-model` 增加稳定事实类型：

```rust
pub enum ModelTransportErrorKind {
    Connection,
    Timeout,
    Interrupted,
}

pub enum ModelError {
    // 既有 Config / Auth / Provider / ContextOverflow / Protocol /
    // ToolArguments / Cancelled 保持原语义
    Transport {
        kind: ModelTransportErrorKind,
        message: String,
    },
    RateLimited {
        message: String,
        retry_after_ms: Option<u64>,
    },
    Unavailable {
        message: String,
        status: Option<u16>,
        retry_after_ms: Option<u64>,
    },
}
```

这里不新增跨领域错误父类型。`Unavailable` 只描述 Provider 当前暂时不可用，和普通拒绝请求的
`Provider` 分开；错误本身不声明“必须重试”。

这些变体继续派生 serde。变体从 tuple 改为 struct 会改变 `ModelEvent::TurnFailed` 以及
debug-viewer 开发 wire JSON 的形状；本版本同步更新双方和 round-trip fixture，不为尚不存在的
正式持久化格式增加兼容分支。

### 6.2 OpenAI-compatible 映射

- `TransportError::Connect` → `Transport(Connection)`
- `TransportError::Timeout` → `Transport(Timeout)`
- `TransportError::Interrupted` → `Transport(Interrupted)`
- HTTP 429 → `RateLimited`
- HTTP 408、425、500–599 → `Unavailable`
- HTTP 401、403 → `Auth`
- 已识别的上下文窗口错误 → `ContextOverflow`
- 其余 HTTP 拒绝 → `Provider`

`Retry-After` 首期接受非负十进制秒数，并安全换算为毫秒；非法值或 HTTP-date 不进行猜测，保留
在 wire header 中但规范错误的 `retry_after_ms` 为 `None`。Provider 特有的 reset header 不在
Adapter 内推断为通用等待时间。

以上映射同时用于建流前 HTTP 错误与流内 Transport 终态；是否能重试仍由错误出现的边界决定。
其中 5xx 从当前 `Provider { status: Some(5xx) }` 改为 `Unavailable` 是有意的可观察行为变化，
必须迁移相关匹配与测试，不能当作纯内部重构。

## 七、模型建立重试

### 7.1 类型与归属

在 `agent-model` 新增 `retry` 模块。该能力包装任意 `ModelService`，不依赖具体 Provider：

```rust
pub enum ModelRetryReason {
    Connection,
    Timeout,
    RateLimited,
    Unavailable,
}

pub struct ModelRetryPolicy {
    pub retry_on: BTreeSet<ModelRetryReason>,
    pub delays: Vec<Duration>,
    pub max_retry_after: Duration,
}

pub enum ModelAttemptEvent {
    Started { trace: Option<TraceContext>, attempt: u32 },
    EstablishmentFailed {
        trace: Option<TraceContext>,
        attempt: u32,
        error: ModelError,
        retry_reason: Option<ModelRetryReason>,
        will_retry: bool,
    },
    RetryScheduled {
        trace: Option<TraceContext>,
        next_attempt: u32,
        delay_ms: u64,
    },
    StreamEstablished { trace: Option<TraceContext>, attempt: u32 },
}

pub trait ModelAttemptObserver: Send + Sync {
    fn observe(&self, event: ModelAttemptEvent);
}
```

`delays` 是每次失败后、下一 attempt 前的显式等待表。例如 `[100 ms, 500 ms]` 表示最多三个
attempt；空表表示不重试。这样没有隐藏退避公式，最大 attempt 数恒为 `delays.len() + 1`。

`RetryingModelService` 持有下层服务、策略和可选观察器，并透明委托 capabilities 与 context
window。只有上层显式装配该包装器时才启用重试。

### 7.2 算法

每个逻辑调用执行：

1. 复制完全相同的 `ModelRequest`；
2. 设置当前 1-based attempt，发送 `Started`；
3. 调用下层 `stream`；
4. 若返回 `Ok(stream)`，发送 `StreamEstablished` 并立即把原流交给上层，之后永不重试；
5. 若直接返回 `Err`，只根据结构化错误得到可选 `ModelRetryReason`；
6. 仅当 reason 在 `retry_on`、等待表还有下一项且未取消时安排下一 attempt；
7. 有 `retry_after_ms` 时，有效等待为 `max(策略等待, Retry-After)`；若 Provider 要求的等待超过
   `max_retry_after`，不缩短等待去重试，而是直接返回原错误；
8. 等待使用取消敏感的异步计时；等待中取消返回 `ModelError::Cancelled`，不再启动请求。

`Interrupted` 代表已经建立响应正文后的传输中断，不进入重试 reason。即使某个自定义 Adapter
在产生 `ModelEvent` 前发生流错误，只要 `stream()` 已返回 `Ok`，包装器也看不到并且不得重试。

### 7.3 Core 边界

Core 不感知 attempt，也不新增重试状态机。它只调用装配后的一个 `ModelService`：

- 重试链成功时，Core 只看到一个成功建立的模型流；
- 最终建流失败时，Core 只看到一个 `ModelError`；
- Core step 预算仍只增加一次；
- 流内 `TurnFailed` 继续按既有终态处理。

`agent-model` 为取消等待增加对 workspace Tokio `time` 的直接依赖。workspace 已经统一使用
Tokio，这不会引入第二套运行时，但会让 `agent-model` 及其下游构建图新增一条 Tokio 依赖边；
不引入后台线程或常驻任务。测试使用暂停时间或零延迟脚本，不执行真实 sleep。

## 八、Reliability Demo 私有 Trace

### 8.1 工程定位

新增 workspace package `tools/reliability-demo` 和对应 `docs/modules/reliability-demo.md`。
它是开发者显式启动的 CLI 验证宿主，不监听端口、不属于正式 Runtime，不向
`assistant-protocol` 暴露 DTO。

Demo 普通依赖 Agent/Provider crate；`agent-testkit` 只作为测试依赖。离线 Wire Replay 使用
Demo 私有 `ReplayTransport`，避免让生产 Provider crate 反向依赖 testkit。

### 8.2 文件布局与提交点

用户必须显式提供数据目录。每次录制创建一个随机 trace id：

```text
<data-dir>/
├── <trace-id>.incomplete.jsonl
└── <trace-id>.jsonl
```

文件由版本头、事件记录和完成尾组成。每行一个 JSON 值；Provider wire 的 body/chunk 在其 native
事件 serde 边界使用 Base64 字符串，不把 Demo 格式提升为公共 Runtime 类型：

```text
TraceStarted(format_version, trace_id, provider_metadata, started_at)
TraceRecord(sequence, observed_at, layer, correlation, native_payload)
...
TraceCompleted(last_sequence, record_count, completed_at)
```

其中 `native_payload` 直接包裹 `ModelRequest`、`ModelEvent`、`AgentEvent`、
`ModelAttemptEvent`、`ProviderWireEvent` 或 Demo 私有宿主事件。它只解决异构落盘，不重新定义
这些事件的字段。

写入流程：

1. 先创建 `.incomplete.jsonl` 并写入版本头；
2. 各观察器只尝试把事件送入有界队列，writer 按接收顺序分配连续 sequence；
3. 队列满、序列化失败、写入失败、容量上限或宿主提前结束时设置共享 Incomplete 状态，不能
   影响 Agent/模型返回值；
4. 首次置为 Incomplete 后 Collector 拒绝所有新记录；writer 继续排空已经接收的队列。若属于
   队列或容量问题，尽量写完此前已接收记录并 flush；若文件或序列化已经失败，则停止文件写入并
   丢弃队列余项；
5. Incomplete 永远不写 `TraceCompleted`，也不执行完成文件 rename；
6. 正常结束时 writer 写完成尾并 flush；只有 flush 成功且未出现缺口，才原子 rename 为
   `.jsonl`，否则保留 `.incomplete.jsonl`。

Demo 构造时显式设置队列容量和单 Trace 最大文件字节数，并在启动信息中展示。最大字节数按
实际序列化后的 JSONL 文件计算，已经包含 Base64 膨胀；超限后停止继续录制并标为 Incomplete，
不截断后冒充 Complete。

Loader 校验格式版本、开始/完成记录、trace id、sequence 连续性、record count、调用关联、
attempt 递增和必需模型终态。Timeline 可读取 Incomplete；Wire/Model Replay 只接受 Complete。

### 8.3 Demo 宿主事件

Demo 只定义验证所需的少量宿主事件：AgentExecution 开始/结束、取消请求、Journal begin/
commit 结果、Trace 状态变化。它们不使用正式 `RunId` 或 Runtime DTO，也不成为产品契约。

## 九、三种读取方式

### 9.1 Wire Replay

Demo 私有 `ReplayTransport` 按一次 correlation + attempt 提取：

- 安全请求快照；
- response status 与允许的 headers；
- raw chunks 或 TransportError。

Replay 使用 trace 中不含 credential 的 Provider 配置快照重建同一种 OpenAI-compatible
profile，并注入占位 credential；它不会访问网络。`ReplayTransport` 校验新的编码请求与录制
请求 method、URL、非敏感 headers 和 body 完全一致，然后把录制响应逐项返回给真实
Provider Decoder。最终 `Result<Vec<ModelEvent>, ModelError>` 必须与录制结果一致。

精确 request bytes 比较只适用于相同 Trace 格式版本和兼容 Adapter/profile。当前编码请求由
固定 struct 字段和 `BTreeMap` 组成，不依赖 `HashMap` 迭代顺序；Provider 编码测试必须证明同一
`ModelRequest` 与相同 Provider 配置重复编码得到完全相同的 bytes。未来编码器若有意改变 wire
格式，应提升 Demo Trace 格式或明确报告 AdapterVersionMismatch，不能把差异误报成响应回放失败。

Provider 配置快照只保存重建 Decoder 所需的 adapter/profile 标识、endpoint、model、context
window 和非敏感选项，不保存 API key 或环境变量值。

### 9.2 Model Replay

Demo 私有 `ReplayModelService` 以录制的逻辑模型调用为脚本：

- 当前 `ModelRequest` 必须完整相等；
- 建立前失败在 `stream()` 的 `Err` 边界重现；
- 成功建立后按录制顺序返回 `ModelEvent`；
- 当前取消令牌可在建立前取消，流内取消产生规范取消终态；
- 脚本耗尽、请求不符、事件损坏都返回明确 ReplayMismatch。

该服务不连接真实 Provider。涉及 Tool Call 的 Core 测试只装配 fake/recorded 工具，Demo 的
普通 Model Replay 命令不会把历史事件交给真实 Tool Dispatcher。

### 9.3 Timeline Playback

按 sequence 展示时间、层级、correlation、attempt 和事件摘要。正文默认只显示类型和长度，
用户显式要求时才显示完整高敏 payload。Timeline 只读 JSONL，不构造 ModelService、Core、
Tool、Authorizer 或 Recorder。

## 十、Demo 命令与真实使用闭环

首期 CLI 保持四个直接命令：

```text
reliability-demo record --data-dir <DIR>
reliability-demo replay-wire --trace <FILE>
reliability-demo replay-model --trace <FILE>
reliability-demo timeline --trace <FILE> [--full]
```

- `record` 从标准输入读取任务，使用真实 OpenAI-compatible Provider，装配一个无外部副作用的
  Demo 工具，以便验证 Tool Call 事件闭环；API key 只从进程环境读取。
- `replay-wire` 和 `replay-model` 不读取 API key，也不访问网络。
- `timeline` 默认不打印 prompt、reasoning、工具参数和 raw chunks 正文。
- 录制结束始终打印文件路径、Complete/Incomplete、逻辑调用数、attempt 数和各层事件数。

确定性故障注入由 Demo crate 测试完成，不额外建设一套交互式故障 DSL。

## 十一、测试与故障矩阵

### 11.1 `agent-model`

- 允许和禁止的错误类型；
- 最大 attempt 数与相同请求；
- Retry-After 合并、超过上限时不重试；
- 等待中取消、attempt 前取消；
- `Ok(stream)` 后任何 `TurnFailed` 均不重试；
- capabilities/context window 透明；
- 并发调用的 trace/attempt 不串线。

### 11.2 OpenAI-compatible Adapter

- 请求观察中完整 body 存在且 credential header 永久缺失；
- URL userinfo/query/fragment 在 Service 构造边界被拒绝；
- 响应 header 白名单；
- wire body/chunk Base64 serde 无损往返；
- chunk 分块、顺序、失败位置和未观察时一致；
- 429、408、425、5xx、连接、超时、中断的结构化映射；
- Retry-After 数字、非法值和溢出；
- Wire Replay 经过真实 Decoder 后事件完全一致；
- 相同规范请求和 Provider 配置重复编码的 request bytes 完全一致；
- 多个并发 Transport 请求互不污染。

### 11.3 Collector 与回放

- Complete commit、`.incomplete` 保留和 Incomplete 后停止接收/排空行为；
- 队列溢出、写入错误、容量超限、缺尾、断行、未知版本和 sequence 缺口；
- Incomplete 可查看但拒绝精确回放；
- ModelRequest 不一致与 wire request 不一致；
- 建立失败、流中失败、唯一成功终态；
- Timeline 不调用网络或工具；
- 一个 Trace 失败不影响并发调用和 Agent 结果。

### 11.4 回归

- Agent Core Recorder begin/complete 失败、取消竞争、普通事件丢弃与可靠终态；
- Provider Codec 与真实 smoke；
- Runtime Harness `verify v0.2` / `verify v0.3`；
- Safety Demo、Memory Demo 编译与既有测试；
- debug-viewer 线格式与显示行为。

只在两个以上生产测试出现相同断言代码时，才把生命周期或 credential 断言提取到
`agent-testkit`；不预建 Conformance Kit。

## 十二、迁移范围

1. `ModelError` 变体变化会机械迁移 Core、Context、Provider、Harness、Demo、testkit 和序列化
   fixture 的所有构造与匹配点；同时更新 `ModelEvent::TurnFailed` 经 debug-viewer wire JSON 的
   生产、消费和 serde round-trip 测试，不增加旧形状兼容层。
2. `TraceContext` 新字段使用 serde 默认；仓库内结构字面量补 `attempt: None` 或改用构造函数。
3. 所有 `TransportRequest` 构造补 `trace`；Reqwest 发送逻辑不读取该字段。
4. OpenAI-compatible Service 的 Transport 建立错误不再 `to_string()` 后丢失分类；HTTP 5xx
   从普通 `Provider` 重分类为 `Unavailable`，两处均同步更新测试。
5. `ProviderWireEvent` 与 `TransportError` 增加 serde；Provider crate 增加 Base64 依赖，只用于
   wire body/chunk 的紧凑 JSON 表示。
6. debug-viewer 继续使用现有 `DebugPayload`，只适配新的错误序列化结果，不承载
   `ProviderWireEvent` 的权威录制职责。
7. Runtime Harness 可继续使用既有 ObservedModelService；是否额外展示 attempt 只作为机械适配，
   不改变其私有 Run/Journal 语义。
8. `agent-model` 增加 workspace Tokio time 依赖；`assistant-runtime`、`assistant-protocol` 和
   Desktop 不增加源代码或持久化迁移。

## 十三、安全与失败语义

- Full Trace 默认关闭，只能由 Reliability Demo 的 `record` 或未来 Runtime 显式启用。
- credential 在记录类型构造时排除；不允许先序列化完整 TransportRequest 再文本替换。
- OpenAI-compatible base URL 禁止携带 userinfo、query 和 fragment，避免认证信息经 URL 进入
  Trace；当前认证只允许走不会被记录的 credential/header 边界。
- Trace 路径、权限、保留与删除由宿主负责；Demo 只写用户指定目录。
- Trace 失败只改变 Trace 完整性，不覆盖、替代或伪造 Journal 状态。
- 重试不能提供 exactly-once 保证；建流前失败仍可能发生在 Provider 已经收到请求之后，attempt
  事件必须把这一费用与重复请求风险暴露给宿主。
- Replay 一律不使用真实 credential，不访问网络，不连接真实副作用工具。

## 十四、验收标准映射

| 功能设计验收项 | 技术落点 |
| --- | --- |
| 1、2 完整交互与认证排除 | ObservedModelService、ObservedTransport、安全 wire 类型、header 规则 |
| 3 完整性且不影响执行 | Demo 有界 Collector、`.incomplete` commit 协议、无返回值观察器 |
| 4 Wire Replay | Demo ReplayTransport + 真实 Provider Decoder + LifecycleValidator |
| 5 Model Replay | Demo ReplayModelService + 完整 ModelRequest 比较 |
| 6 无副作用 | 三种读取命令均不装配真实 Tool 执行链 |
| 7、8 有限重试边界 | RetryingModelService、结构化错误、显式等待表、取消测试 |
| 9 并发隔离 | TraceContext attempt、无全局当前调用状态、并发故障测试 |
| 10 Demo 闭环 | `record`、`replay-wire`、`replay-model`、`timeline` |
| 11 既有行为回归 | workspace 与累计 Harness/Demo 验证矩阵 |
| 12 Core/Runtime 边界 | Core 不持久化、不管理 attempt；正式 Runtime/Protocol/Desktop 不改 |

## 十五、最终技术结论

1. 录制继续以各层原生事实为主，只新增 Provider wire 与 retry attempt 两类缺失事件。
2. `ObservedTransport` 是透明观察接缝；安全记录类型从构造时就不存在 credential。
3. `RetryingModelService` 属于 provider-neutral `agent-model`，但只能重试 `stream()` 的直接错误。
4. 显式等待表同时表达退避与最大 attempt，不提供隐藏默认重试。
5. Core 只看到一个逻辑模型调用，不保存 Trace、不管理重试、不改变 step 预算。
6. Reliability Demo 私有负责 Collector、JSONL、Complete/Incomplete 和三种读取方式；其格式不是
   正式 Runtime 契约。
7. Wire Replay 重走真实 Decoder，Model Replay 重现规范模型服务，Timeline 只读；三者都不执行
   历史副作用。
8. 本方案没有遗留开放问题；确认后可直接据此编写开发计划。
