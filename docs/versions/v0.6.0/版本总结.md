## 三、形成的核心能力

- `agent-model` 使用结构化 `ModelError` 表达 Transport、RateLimited 与
  Unavailable 等事实；`TraceContext` 以 correlation 和 1-based attempt 串联逻辑调用。
- `RetryingModelService` 只处理 `ModelService::stream()` 直接返回的建流前错误；
  允许原因、等待序列、Retry-After 上限和取消均显式可观察，已建流不重试。
- OpenAI-compatible Adapter 通过 `ObservedTransport` 记录编码请求、允许的响应头、
  raw chunks 和 Transport 失败；认证数据在记录类型构造前已排除。
- Reliability Demo 使用各层原生 `ModelRequest`、`ModelEvent`、`AgentEvent`、attempt
  和 wire 事实组成 Trace；记录失败只将 Trace 降级为 Incomplete，不改写 Agent 结果。
- Wire Replay 重走真实 Provider Decoder，Model Replay 重现规范模型服务，Timeline
  只读展示；三者均不重新执行工具、审批、Journal 或其他历史副作用。

## 四、偏差与边界

- 实现与已确认功能设计和技术方案无范围偏差。
- 正式 `assistant-runtime`、`assistant-protocol` 和 Desktop 没有 Trace 代码、依赖或行为接入。
- Trace JSONL、Provider metadata、Replay、Timeline、Host 事件和 CLI 均为
  Reliability Demo 私有验证实现，不是产品协议或持久化契约。
- 完整 Trace 包含 prompt、reasoning、工具参数和响应正文，属于高敏本地数据；
  credential、Authorization、Cookie 和代理认证信息不进入 Trace。
- Provider crate 中独立的联网 ignored smoke 未重复执行；Reliability Demo 已提供
  更完整的真实 Provider 工具闭环。Desktop/Tauri 未构建，因为产品代码与直接
  manifest 未修改。

## 五、遗留与后续入口

- v0.6.0 无已知功能 blocker；真实 Provider 闭环和自动故障矩阵已完成。
