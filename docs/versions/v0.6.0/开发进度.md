- 实际产出：
  - OpenAI-compatible Adapter 新增可序列化 `ProviderWireEvent`、`RecordedWireRequest`、同步
    `ProviderWireObserver` 和透明 `ObservedTransport`；`TransportError` 同步补齐 serde；
  - wire 请求正文和响应 chunk 在内存中保持 `Vec<u8>`，JSON 字段使用 Base64，对空内容、UTF-8、
    任意二进制和 64 KiB chunk 均无损；

    不写占位值；响应事件只保留 content-type、retry-after、request-id/x-request-id 及

## M3：模型建立前有限重试

- 状态：✅ 已完成（2026-08-03，用户确认）
- 目标：实现 provider-neutral、显式、有限、取消敏感且可观察的建流前重试，不重试流内失败。
- 实际产出：
  - `agent-model` 新增 `ModelRetryReason`、无 `Default` 的 `ModelRetryPolicy` 和
    `RetryingModelService`；可重试原因、每次等待和可接受的最大 `Retry-After` 均由上层显式给出，
    `delays.len() + 1` 是严格 attempt 上限；
  - 包装器只处理 `ModelService::stream()` 直接返回的建流错误；Connection、Timeout、
    RateLimited、Unavailable 只有命中显式集合才重试，Interrupted 与其他错误不进入重试；一旦下层
    返回事件流就原样交还，后续 `TurnFailed` 不会触发第二次模型调用；
  - 每个 attempt 复用相同 `ModelRequest`，从 1 开始覆盖 `TraceContext.attempt`；策略等待与
    `Retry-After` 取较大值，Provider 建议超过显式上限时直接返回原始错误；
  - pre-cancel、建流期间取消和等待期间取消均不会产生后续调用；实现不派生后台任务，并透明委托
    capabilities 与 context window；
  - 新增可序列化 `ModelAttemptEvent` 和可选同步 `ModelAttemptObserver`，报告开始、建流失败、安排
    重试和建流成功事实；观察器不返回结果，不参与模型调用判定；
  - `agent-core` 只新增集成测试，证明一次逻辑 Model Step 内可以发生两个真实 attempt；生产执行
    循环没有重试分支或行为改动，正式 Runtime 与应用层也未接入配置。
- 实际验证：
  - `cargo test -p agent-model retry`：13 项通过，覆盖四类候选错误、非候选错误、有限次数、相同请求、
    attempt Trace、Retry-After 合并与上限、三个取消时点、流中失败、无观察器和并发隔离；
  - `cargo test -p agent-core establishment_retry_remains_one_core_model_step`：1 项通过，两个下层 attempt
    对 Core 仍是一个 Step；
  - `cargo test -p agent-model`：42 项通过；
  - `cargo test -p agent-core -p agent-provider-openai-compatible`：Core 34 项、Provider 99 项通过，
    1 项真实 API smoke test按既有约定 ignored；
  - 三个受影响 crate 的全 targets/features 严格 Clippy、`cargo fmt --all --check` 和
    `git diff --check`：通过。
- 偏差：无。
- 未执行：未调用真实 Provider，未运行 workspace 全量测试；真实录制闭环属于 M6，全 workspace

- 遗留：M4 在 Reliability Demo 中消费 attempt 与 wire 原生事实，实现 Collector、完整性状态和

## M4：Reliability Demo Collector、完整性与 Timeline

- 状态：✅ 已完成（2026-08-03，用户确认）

- 实际产出：
  - Reliability Demo 私有新增 `TraceStarted`、`TraceRecord`、`TraceCompleted`、非认证 Provider
    metadata、少量宿主事件和 `NativeTracePayload`；payload 直接包裹现有 ModelRequest、ModelEvent、

## M5：Wire Replay 与 Model Replay

- 状态：✅ 已完成（2026-08-03，用户确认）
- 目标：只基于 Complete Trace 私有实现两层确定性离线回放，并保持精确匹配、取消和无副作用边界。
- 实际产出：
  - Demo 私有 Trace 增加最小 `ModelCallEvent`，显式记录 ModelService 建流成功或原始建立错误；这是
    `ModelEvent` 无法表达的建流边界事实，不修改 `agent-model` 公共契约；
  - Provider metadata 补齐 adapter version、profile、provider id 和 protocol 等非认证重建信息；
    当前只接受版本匹配的 OpenAI-compatible generic 或 DeepSeek profile，其他 Adapter/Profile
    明确报 mismatch；
  - 私有 `ReplayTransport` 按 correlation + optional 1-based attempt 选择脚本，精确比较重新编码的
    method、URL、非敏感 headers 和 body；真实 Authorization 继续由安全请求快照永久排除，回放只
    注入占位 credential 且唯一 Transport 为内存脚本，不构造网络客户端；
  - Wire Replay 重建真实 `OpenAiCompatibleService`，把录制 status、允许 headers、原始 chunks 与
    TransportError 重新送入现有 SSE Decoder 和 LifecycleValidator，再与录制的 ModelError/
    ModelEvent 全序列比较；支持多个 retry attempt、建流失败、非 2xx、任意 chunk 边界和流中断；
  - 私有 `ReplayModelService` 完整比较 system、conversation、tools、tool choice、generation、
    reasoning 与 provider options，在原边界重现建立错误或事件流；当前取消令牌可在建流前或流中
    终止本次回放，录制 Trace 保持只读；
  - 损坏生命周期由 LifecycleValidator 转成受控失败并由结果比较拒绝；请求不符、脚本耗尽、关联、
    Adapter/Profile 和结果不符均返回不包含正文的明确 ReplayError；Loader 新增损坏 Base64 和每个
    started attempt 必须恰有一个建立结果的严格校验；
  - 新增 `replay-wire --trace <FILE>` 与 `replay-model --trace <FILE>`。两者只调用 Complete Loader，
    不加载 `.env`、credential、网络、Core、Registry、Dispatcher、Authorizer、Recorder 或 Journal；
    Tool Call 始终只是 ModelEvent 数据，没有副作用执行入口；
  - 正式 Runtime、Protocol、Desktop 和所有产品 crate 均无改动。

## M6：真实 Provider 录制与离线回放闭环

- 状态：✅ 已完成（2026-08-03，用户确认）

  Wire Replay 与 Model Replay 闭环。
- 实际产出：
  - 新增 `record --data-dir <DIR>`，只在该命令中加载 `.env`、DeepSeek credential 和真实
    `ReqwestTransport`；缺 credential、空任务、非法 context window、非法数据目录及不完整 retry
    配置在模型执行前失败；三个读取命令仍不触碰环境或网络；
  - 私有 `ObservedModelService` 位于最外层，为每次逻辑调用生成 correlation，完整记录
    `ModelRequest`、建流结果及调用方实际消费的每个 `ModelEvent`；可选
    `RetryingModelService` 位于其内，`ObservedTransport` 位于 Provider 与 Reqwest 之间，装配顺序与
    技术方案一致；
  - 装配真实 `AgentExecution`、可靠 AgentEvent drain、Ctrl-C 取消记录、私有内存两阶段 Journal、
    显式 AllowAllAuthorizer 和固定 `reliability_probe`。该工具只返回确定性 JSON，不访问外部资源；
    Demo 显式限制最多 4 个 Model Step 和 1 次工具执行以约束实际费用；

    不装配包装器，部分配置明确拒绝；
  - 模块文档补齐环境变量、真实录制、离线 Timeline/Replay、重试和高敏 Trace 使用说明；正式
