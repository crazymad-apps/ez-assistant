## 二、背景与版本目标

当前系统已经具备 Provider-neutral `ModelRequest` / `ModelEvent`、强类型 `AgentEvent`、
Runtime Harness 的 LLM/Agent/Runtime 三通道调试链路，以及 Provider 测试使用的离线
Transport fixture。现有链路能够实时观察模型与 Agent 行为，但仍有以下缺口：

- 看不到 Provider 编码后实际发出的请求和原始响应 chunks，无法完整回溯线上协议交互；
- debug-viewer 是允许丢弃的开发观察通道，不能作为可验证的回放记录；
- 建立前瞬态模型错误没有显式、有限、可观察的重试能力；
- 真实断流、重试、取消和并发问题仍需要大量手写脚本，缺少统一的故障复现闭环。

本版本目标如下：

1. 以各层现有原生事件和事实为记录点，完整观察一次真实 LLM 调用从规范请求、Provider
   wire、规范模型事件到 Agent/宿主事件的变化。
2. 建立可验证的 Wire Replay 与 Model Replay，使真实问题可以脱离网络确定性复现。
3. 只在模型事件流建立前提供显式配置、有限次数、取消敏感的重试。
4. 通过独立 Reliability Demo 模拟 Runtime 完成完整录制、落盘、完整性校验和回放，不在
   本版本固化正式 Runtime 或产品持久化契约。
5. 补齐录制、回放、重试涉及的断流、取消、背压、并发隔离和敏感信息测试。

## 三、版本边界

### 3.1 本版本包含

- 完整规范 `ModelRequest` 和完整规范 `ModelEvent` 的观察与录制边界。
- OpenAI-compatible Adapter 编码后请求、响应头、原始响应 chunks 和 Transport 失败的
  wire 观察边界。
- 模型逻辑调用、attempt、重试调度和最终结果之间的稳定关联。
- Runtime 可装配的事件观察能力；公共下层不负责文件、数据库或产品日志生命周期。
- Trace 的 Complete/Incomplete 完整性语义和严格回放校验。
- Wire Replay、Model Replay 与只读 Timeline Playback。
- 模型事件流建立前的有限重试和支撑策略判断的结构化错误事实。
- 独立 Reliability Demo 和少量可复用的测试辅助能力。

### 3.2 本版本不包含

- 正式 Runtime、应用协议、桌面 UI、产品日志数据库和历史数据迁移。
- 从 Trace 自动重新执行完整 AgentExecution 或业务 Run。
- 重新执行历史文件、Shell、Memory 或其他工具副作用。
- 回放历史 Authorizer 决策、审批交互或 Journal 写操作。
- 模型流建立后的透明重试、流式内容拼接或静默替换。
- Tool、Recorder、Pinned Store 的通用自动重试或幂等性推断。
- Context Overflow、Length 或任务未完成后的正式 Runtime 续跑。
- 同批 Tool Call 并行执行、同一 Session 并发 Run 或正式 Runtime 调度。
- 新的通用背压系统、统一 Adapter 父接口、统一跨领域错误类型或动态插件系统。
- Tool Result 裁剪、自动记忆观察、Embedding 或其他与录制可靠性无关的能力。

Reliability Demo 可以私有定义临时 Run、记录目录和文件格式，但这些类型和格式不构成
正式 Runtime、Protocol 或产品兼容契约。

## 四、分层记录原则

### 4.1 原生事件和事实直接作为记录点

本版本不建立与现有类型重复的 Trace 业务事件体系。各层继续使用自己已经拥有的事实：

| 层级 | 记录事实 |
| --- | --- |
| Model | 完整 `ModelRequest`、建立结果和完整 `ModelEvent` |
| Provider | 编码后实际请求、响应状态与允许记录的响应头、原始响应 chunks、Transport 失败 |
| Agent Core | 既有 `AgentEvent` |
| Runtime/Demo | Run、取消、重试关联、Journal commit 和 Trace 完整性状态 |

只有当前不存在原生表达的 Provider wire 和 retry attempt 边界可以新增所属层事件。不得为了
统一序列化而复制 `ModelEvent`、`AgentEvent` 或规范对话类型。

### 4.2 Runtime 所有权

正式产品中，Runtime 负责：

- 为 Session、Run、AgentExecution、模型逻辑调用和 attempt 建立业务关联；
- 为接收到的分层事件分配可检测缺口的顺序；
- 选择关闭、元数据观察或完整回放录制；
- 决定落盘位置、加密、访问权限、保留周期和删除；
- 将录制标记为 Complete 或 Incomplete；
- 提供回放数据源和审计入口。

Core、Model、Provider Adapter 和工具能力均不直接写文件或数据库。本版本不修改正式
Runtime，只由 Reliability Demo 私有模拟上述责任。

### 4.3 与 debug-viewer 的关系

debug-viewer 继续是 best-effort 开发观察工具：允许队列背压丢弃、客户端断开和内容脱敏，
不成为权威事实源，也不承诺精确回放。

完整录制可以复用相同原生类型和记录位置，但必须使用独立 Collector。不能从 debug-viewer
或普通 AgentEvent UI 队列反向收集 Full Replay，因为这些通道允许丢弃。

## 五、完整 LLM 交互数据

### 5.1 完整录制内容

Full Replay 至少保留：

- 完整 System Prompt、Conversation History、Tool Definitions、生成参数和 Provider Options；
- Provider Adapter 编码后真正发送的请求 body；
- 实际 endpoint、protocol、provider 和 model 标识；
- 响应 status、内容类型、request ID、Retry-After 等允许记录的响应头；
- 保序的原始响应 chunks 和 Transport 错误位置；
- 完整 reasoning、text、Tool Call arguments、usage、finish reason 和 Provider State；
- 解码后的全部 `ModelEvent`；
- 同一执行中 Runtime 实际观察到的 `AgentEvent` 和宿主事件。

请求指纹可以作为输入一致性校验字段，但不能代替完整请求和响应。

### 5.2 永久排除的敏感认证数据

以下数据不得进入 Full Replay、Metadata、Debug 或错误内容：

- Authorization、API key、Cookie、代理认证和其他 credential；
- credential 文件路径或环境变量值；
- Transport/HTTP 客户端可能包含认证信息的原始 Debug 输出。

排除必须发生在记录类型或构造边界，不能依赖“先完整序列化、再用字符串替换”的事后脱敏。
Full Replay 仍包含完整 prompt、对话、reasoning 和工具参数，因此整体始终按高敏数据管理。

### 5.3 完整性与记录失败

Trace 具有明确状态：

- `Complete`：开始、结束、顺序和所有必需层级数据均完整，可用于精确回放。
- `Incomplete`：写入失败、队列溢出、顺序缺口、进程提前退出或任一记录层中断，只能用于
  部分排障，不能冒充精确回放数据。

Trace 记录是辅助能力，不是 Conversation Journal 等权威业务事实。记录失败不得使正常
模型调用或 AgentExecution 失败；宿主只将本次 Trace 标记为 Incomplete。Journal begin/
complete 失败仍按既有规则阻断副作用或受控终止，不能与 Trace 失败混同。

## 六、回放能力

### 6.1 Wire Replay

Wire Replay 读取一次已完成的 Provider attempt：

```text
录制的 response status / headers / raw chunks / Transport error
→ 同一 Provider Decoder 与生命周期验证
→ 新的 ModelEvent 序列
→ 与录制时的 ModelEvent 比较
```

Wire Replay 不访问真实网络、不使用 credential、不重新向 Provider 计费。它用于判断问题
来自 Provider 原始响应、Transport 分块、SSE 解析、Codec 聚合还是协议生命周期校验。

### 6.2 Model Replay

Model Replay 使用录制的完整 `ModelRequest`、建立结果和 `ModelEvent` 形成可替换的模型服务：

- 当前请求必须与录制请求一致，不一致时明确返回 ReplayMismatch；
- 建立前失败和流内失败在原边界重现；
- ModelEvent 的内容、顺序和唯一终态保持一致；
- 回放不访问 Provider，不产生真实费用；
- 取消仍由当前回放调用的取消信号控制。

Model Replay 可以用于模型层和 Core 的确定性测试，但本版本不承诺单凭一份 Trace 重新执行
完整 Agent。测试若涉及 Tool Call，只能装配 fake/recorded 工具能力，不能连接真实副作用工具。

### 6.3 Timeline Playback

Reliability Demo 可以按顺序只读展示录制的 Provider、Model、Agent 和宿主事件，用于人工
排查。Timeline Playback 不调用 Core、Provider、Tool、Authorizer 或 Recorder，不产生任何
业务副作用。

## 七、模型建立前有限重试

### 7.1 唯一允许的通用重试边界

现有 `ModelService` 已区分：

- `stream` 直接返回错误：事件流建立前失败，没有产生任何 `ModelEvent`；
- `stream` 返回事件流：后续以 `TurnFinished` 或 `TurnFailed` 收敛。

只有第一种情况可以进入显式重试策略。一次重试链仍属于同一个逻辑 Model Step，复用完全
相同的 `ModelRequest`；Core 的 step 预算只计算一次，没有新的规范消息、Tool Call 或工具
副作用。每次 attempt 和等待都必须对 Runtime Collector 可观察。

### 7.2 策略边界

- 重试默认关闭，只能由上层显式装配。
- 最大 attempt 数必须有限且显式配置。
- 等待策略和 Provider Retry-After 必须有明确、可测试的合并规则。
- 等待和下一次 attempt 都必须观察取消；取消不再发起新请求。
- 错误只提供结构化事实，不替 Runtime 决定最终策略。
- Config、Auth、Protocol、ToolArguments、ContextOverflow 和 Cancelled 不进入通用重试。
- 连接失败、建立超时、RateLimited 和 Provider 暂时不可用可以由显式策略考虑。
- 不通过解析错误展示文本或猜测模型名称判断是否重试。

### 7.3 不属于同一步重试的情况

一旦事件流建立，任何 TurnFailed 都结束当前 Model Step 和 AgentExecution，不透明重试，
即使失败前只产生了 `TurnStarted`。原因是流式 delta 已可能对外可见，重新请求可能生成不同
内容、ID 和 usage，无法无损回滚或拼接。

Context Overflow 继续交接压缩；完整 Turn 的 Length 结束、流中失败和任务未完成后的续跑，
均由未来 Runtime 在同一业务 Run 中显式启动新的 AgentExecution，本版本不实现。

## 八、错误、背压与并发边界

### 8.1 错误模型

技术方案应补足模型建立错误中供重试策略判断的稳定事实，例如连接、超时、限流、暂时
不可用、状态码和 Retry-After，但不建立跨 Model、Tool、Recorder、Memory 的统一错误父类型。

Tool 可能已经产生副作用；Recorder 代表权威 Journal；Pinned Store 修改具有提交语义；
这些边界继续使用各自错误类型和既有失败处理，不因模型重试能力获得通用自动重试。

### 8.2 背压

- 现有 AgentEvent 普通观察通道继续允许背压丢弃，并由可靠终态报告 dropped count。
- ModelEvent 继续由 Stream pull 模型自然施加消费背压，不增加第二套通用队列。
- debug-viewer 继续 best-effort。
- Full Replay Collector 的容量或写入失败由宿主标记 Incomplete，不改变 Agent 结果。

本版本不尝试用一个全局背压抽象统一网络流、AgentEvent、Trace、Shell 输出和 Runtime 事件。

### 8.3 并发安全

本版本的并发安全只指：共享 ModelService、Transport 观察器、重试包装器和 Collector 被多个
独立调用并发使用时，request、attempt、原始 chunks、ModelEvent、取消和错误不会跨调用
污染；一个调用的取消或记录失败不影响其他调用。

它不表示同批 Tool Call 并行、同一 Session 并发 Run、跨进程文件锁或正式 Runtime 调度。

## 九、Reliability Demo

新增独立 Reliability Demo，作为开发者显式启动的验证宿主。它不属于产品进程、正式
Runtime、sidecar 或 daemon。

Demo 至少支持以下闭环：

1. 使用真实 OpenAI-compatible Provider 完成一次模型或工具调用交互；
2. 模拟 Runtime 收集 Provider wire、Model、Agent 和宿主记录点；
3. 把完整 Trace 写入用户显式指定的本地数据目录；
4. 展示 Complete/Incomplete、调用关联、attempt 和事件数量，但不在普通控制台默认打印
   credential 或完整敏感正文；
5. 断网后执行 Wire Replay，重新经过真实 Provider Decoder；
6. 断网后执行 Model Replay，重现建立失败或完整模型事件流；
7. 使用确定性故障脚本验证建立失败、限流、Retry-After、取消、流中断、记录失败和并发隔离；
8. Timeline Playback 只读展示分层事件，不执行历史工具副作用。

Demo 的本地文件格式只用于本版本验证。正式 Runtime 未来可以采用数据库、事件文件或其他
持久化方案，不受 Demo 格式约束。

## 十、Adapter 验证原则

本版本不创建名为 Conformance Kit 的公共框架，也不定义统一 Adapter trait。仅在已有两个
以上实际调用点时，把重复的生命周期、取消、唯一终态、并发隔离和敏感信息断言提取为
普通 testkit 辅助函数；具体 Adapter 仍在自己的 crate 内准备 fixture 并编写测试。

最低验证重点如下：

- Model Adapter：建立前无事件、建立后唯一终态、取消、生命周期、错误分类和并发隔离；
- Provider Adapter：真实 wire 分块、错误位置、请求编码、解码一致性和 credential 排除；
- 重试包装器：有限次数、允许/禁止错误、Retry-After、取消和 attempt 事件；
- Collector/Replay：顺序、完整性、损坏输入、版本不兼容和多个并发调用隔离；
- Core：Recorder begin/complete 失败、取消竞争、观察者断开和历史 Harness 行为不回归。

## 十一、当前已确认的设计结论

1. 正式录制数据由 Runtime 关联业务状态并落盘，Core 与 Adapter 不直接持久化。
2. v0.6.0 不修改正式 Runtime 和应用层，使用独立 Reliability Demo 模拟装配。
3. Full Replay 必须保存完整真实 LLM 语义与 wire 数据，请求指纹不能代替正文。
4. credential 和认证信息从记录构造边界永久排除，Full Replay 其余内容按高敏数据管理。
5. ModelRequest、ModelEvent、AgentEvent 和 Journal 事实直接作为记录点，不复制平行事件。
6. 只新增当前缺失的 Provider wire 与 retry attempt 边界事件。
7. Trace 写入失败不影响 Agent，录制标记 Incomplete，不能用于精确回放。
8. Wire Replay 重新执行 Provider Decoder；Model Replay 重现规范模型调用；Timeline 只读展示。
9. 回放不重新执行完整 Agent、真实 Tool、副作用、审批或 Journal 写入。
10. 通用自动重试只允许发生在模型事件流建立前，并且必须显式、有限、可取消、可观察。
11. 流中失败、Context Overflow、Length 和业务任务续跑由未来 Runtime 显式组织。
12. Tool、Recorder、Pinned Store 不获得通用自动重试。
13. 不建设新的统一背压、Adapter 父接口、跨领域错误父类型或大型 Conformance 框架。
14. 并发安全只保证共享下层能力的独立调用隔离，不引入 Runtime 调度或 Tool 并行语义。

## 十二、技术方案约束

技术方案必须基于真实代码核查落实以下要求：

- 优先复用 Runtime Harness 已有 ObservedModelService、debug-viewer 分层 payload 和
  agent-testkit RecordedTransport 的成熟语义，不复制第二套几乎相同的事件类型。
- 保持 debug-viewer 为独立开发工具；产品和底层 crate 不得反向依赖它。
- Provider wire 观察必须转发与未观察时完全相同的请求、响应 chunks、取消和错误；观察
  包装器不能改变分块、时序或生命周期结果。
- Full Replay 数据必须能够检出缺失开始/结束、顺序缺口、未知版本、损坏记录和不完整写入。
- 回放只能读取 Complete 记录；Incomplete 数据允许查看但必须明确拒绝精确回放。
- 重试包装器必须保持 ModelService 的 capabilities、context window、请求和成功事件透明；
  每次 attempt 使用相同语义请求，取消后不等待或发起新 attempt。
- 建立错误的结构化演进必须迁移所有生产者、消费者、序列化测试和错误映射，不保留字符串
  解析旁路。
- Demo 的文件写入需要明确 commit point 和损坏恢复语义，但不得把私有格式提升为正式
  Runtime 契约。
- 技术方案必须核查 AgentEvent、ModelEvent、Transport、DebugClient、Recorder、现有
  Provider fixtures 和 Harness 消费路径，说明哪些类型直接复用、哪些只新增观察接缝。

## 十三、风险与兼容性

- **高敏数据**：完整 prompt、reasoning、工具参数和 Provider raw response 会形成可读的
  隐私副本；只能显式启用，由宿主控制访问与生命周期，认证信息永不记录。
- **观察改变行为**：复制 raw chunks、异步写入或锁竞争可能改变流时序；以透明包装、并发
  隔离和观察前后等价测试控制。
- **错误重试扩大费用**：建立失败可能发生在 Provider 已接收请求之后；有限 attempt、显式
  策略、Retry-After 和 attempt 可观察性用于暴露重复费用风险，不宣称 exactly-once。
- **残缺录制误用**：进程退出、磁盘失败或队列溢出可能留下部分数据；以完整性状态和严格
  loader 拒绝避免冒充精确回放。
- **回放副作用**：历史 ModelEvent 可能包含 Tool Call；回放默认不连接真实工具，Timeline
  永不执行，涉及 Core 的测试只使用 fake/recorded 能力。
- **既有调试兼容**：debug-viewer 与 Harness 已有线格式不能被产品 Trace 反向污染；技术
  方案应以适配或机械迁移保持既有调试行为。

## 十四、验收标准

开发计划必须覆盖以下可观察行为：

1. 真实模型调用可以完整记录规范 ModelRequest、Provider 编码请求、响应 status/允许的
   headers、原始 chunks、ModelEvent、AgentEvent 和宿主事件，并保持稳定关联与顺序。
2. Full Replay 中不存在 credential、Authorization、Cookie 或认证 Debug 内容；完整 prompt、
   reasoning、工具参数和响应正文能够按显式录制要求回溯。
3. 正常记录形成 Complete；写入失败、顺序缺口、进程中断或容量溢出形成 Incomplete，且记录
   失败不改变原模型调用和 AgentExecution 的结果。
4. Wire Replay 不访问网络即可从原始响应数据重新产生与录制一致的 ModelEvent；损坏、缺失
   或不完整记录明确失败。
5. Model Replay 不访问 Provider 即可校验完整请求并重现建立失败、流内失败或成功事件序列；
   请求不一致明确失败。
6. 回放和 Timeline 不执行真实 Tool、审批、Journal 写入或其他历史副作用。
7. 建立前允许的瞬态错误可以在同一逻辑 Model Step 内按显式有限策略重试；attempt、等待、
   Retry-After、最终成功或失败均可观察，取消后不再发起请求。
8. Config、Auth、Protocol、ToolArguments、ContextOverflow、Cancelled 和任意流中失败不发生
   透明重试；Tool、Recorder 和 Pinned Store 行为不因本版本产生自动重试。
9. 多个并发模型调用的 request、attempt、wire chunks、ModelEvent、取消和完整性状态互不
   污染；单个记录失败不影响其他调用。
10. Reliability Demo 可以用真实 Provider 录制到显式目录，并在断网条件下完成 Wire Replay、
    Model Replay 和只读 Timeline Playback；其文件和命令不进入产品协议。
11. 既有 debug-viewer、Runtime Harness、Safety Demo、Memory Demo、Provider Codec、Core
    Tool Loop、Recorder、取消、背压终态和上下文压缩回归均不受破坏。
12. Core 不增加 Trace 持久化、Runtime Run、完整 Agent 回放或业务重试状态机；正式 Runtime、
    Protocol 和 Desktop 不产生代码或行为变更。
