## 二、实施原则

1. M0 → M7 严格顺序实施。每个里程碑完成实现和验证后标记为 `🟨 待确认`并停止，获得用户
   明确确认后才进入下一里程碑。
2. 开发计划确认只授权开始 M0，不授权连续执行后续里程碑。
3. 公共错误、Trace、Transport 和 ModelService 契约必须在所属里程碑一次性迁移全部生产者、
   消费者、serde fixture 和测试，不保留新旧并行变体或字符串解析旁路。
4. Trace 记录继续以 `ModelRequest`、`ModelEvent`、`AgentEvent` 等原生事实为主，只新增当前
   缺失的 Provider wire 与 retry attempt 事件。
5. Core 不持久化 Trace、不知道 attempt、不实现重试状态机；Provider、Model 与工具层不写
   Trace 文件。文件和回放编排仅存在于 Reliability Demo 私有模块。
6. 只有 `ModelService::stream()` 直接返回的结构化瞬态错误可以重试；一旦返回事件流，任何流内
   失败都不透明重试。
7. credential 必须在记录类型构造前排除；自动测试、回放和 Timeline 不读取 credential、不访问
   网络，也不连接真实副作用工具。
8. Full Trace 写入失败只能把记录标为 Incomplete，不得改变模型或 Agent 结果；Journal 失败仍
   按既有权威提交语义处理。
9. 自动测试使用 scripted transport/model、暂停时间、gate、tempfile 和受控 I/O failure，不用
   不稳定 sleep 推断顺序，不访问用户应用数据。
10. 真实 Provider 只在 M6 显式执行；完整 prompt、reasoning、工具参数和 raw response 不在普通
    控制台默认展示，API key 永不进入 Trace、fixture 或错误。
11. `assistant-runtime`、`assistant-protocol` 和 `apps/desktop` 保持零代码、零依赖变化；只允许
    在长期架构文档中记录未来 Runtime 所有权。
12. 每个里程碑开始前重新核对工作树和对应 Rust/module 规范；若真实代码与已确认技术方案不符，
    停止扩大改动并先修订设计。
13. 每个里程碑完成后只挑选公共契约、核心语义、安全性、并发或后续依赖中的重点供用户 Review；
    若没有重要 Review 点，直接说明，不人为制造问题。
14. 不主动执行 `git add`、`git commit` 或 `git push`，不清理与本版本无关的已有工作树改动。

## 六、M1：结构化模型错误与 Trace 关联基础

### 目标

建立重试与并发关联所需的稳定事实，完整迁移现有错误和 serde 消费方，但不实现 wire observer
或自动重试。

### 前置依赖

M0 已确认。

### 实施内容

- `agent-model` 增加 `ModelTransportErrorKind`，把 Transport 与 RateLimited 改为结构化变体，
  新增 `Unavailable`，保留既有脱敏 Display 与 serde 能力。
- `TraceContext` 增加 serde 默认的可选 1-based attempt，并补构造/更新方法，避免调用方重复
  构造非法 attempt。
- `TransportRequest` 增加不进入 HTTP 的可选 TraceContext；Reqwest 与测试 Transport 明确忽略
  或只观察该字段。
- OpenAI-compatible Service 保留 TransportError 分类，不再先 `to_string()`；HTTP 429、
  408、425、5xx 和 Retry-After 按技术方案映射。
- 5xx 有意从普通 Provider 拒绝改为 Unavailable；数字 Retry-After 安全换算，非法/溢出值不猜测。
- 机械迁移 agent-model、agent-context、agent-core、Provider、testkit、runtime-harness、
  safety-demo、examples、debug-viewer payload 和全部测试构造/匹配点。
- 同步 ModelError、TraceContext 与 TransportRequest Rustdoc，不保留 tuple 旧变体或错误文本解析。

### 自动测试或人工核对

- 每个 TransportError 分类无损进入 ModelError；错误文本不含 request/response body 或 credential。
- 429、408、425、5xx、普通 4xx、ContextOverflow 和认证错误映射稳定。
- Retry-After 的正常值、非法值、负数/溢出和缺失分别覆盖。
- 新 ModelError 经 ModelEvent、DebugPayload 完整 JSON round-trip；旧 JSON 兼容不进入范围。
- TraceContext 不带 attempt、合法 attempt、反序列化旧缺省字段和 attempt=0 拒绝均有测试。
- 既有 Core 只对 Cancelled/ContextOverflow 的分支行为不变。

## 七、M2：Provider wire 透明观察与认证排除

### 目标

在真实 Transport 边界完整观察编码请求、响应头、raw chunks 和失败，同时证明观察不会改变
请求、分块、取消、错误或生命周期。

### 前置依赖

M1 已确认。

### 实施内容

- 增加可序列化 `ProviderWireEvent`、`RecordedWireRequest` 和同步 `ProviderWireObserver`。
- wire body/chunk 内存保持 `Vec<u8>`，serde 使用字段级 Base64 无损编码。
- 安全请求快照在构造时删除认证 header；响应只保留技术方案列出的 header allowlist。
- OpenAI-compatible base URL 构造拒绝 userinfo、query 和 fragment，认证只允许走 credential/header。
- 实现透明 `ObservedTransport`：请求、响应头、每个 chunk、TransportError 和自然 EOF 原样转发。
- OpenAiCompatibleService 把 ModelCallContext.trace 复制到 TransportRequest，不编码为 HTTP header。
- 增加相同 ModelRequest/Profile 重复编码 byte-for-byte 相同的确定性测试。
- 并发测试按 correlation/attempt 区分多个请求，禁止使用全局“当前调用”状态。

### 自动测试或人工核对

- 记录请求含完整真实 body，但不存在 Authorization、API key、Cookie、代理认证或 URL credential。
- Base64 serde 对空、UTF-8、任意二进制和大 chunk 无损往返。
- 响应 header allowlist 大小写稳定，未允许 header 不进入事件。
- 观察前后请求 bytes、响应 chunk 边界、错误位置、取消结果和 ModelEvent 完全一致。
- 建立失败、流内中断、自然 EOF 和消费者提前停止分别可观察且不派生后台 drain。
- 多个并发调用的 wire 数据不串线，单个 observer 丢弃不改变 Transport 返回值。

### 验证

```bash
cargo test -p agent-provider-openai-compatible transport
cargo test -p agent-provider-openai-compatible stream
cargo test -p agent-provider-openai-compatible
cargo clippy -p agent-provider-openai-compatible \
  --all-targets --all-features -- -D warnings
cargo fmt --all --check
```

### 完成判定

- Provider wire 事实可被 Runtime/Demo 安全观察并稳定序列化；
- 观察包装器与未观察路径行为等价；
- 尚未实现重试和文件落盘。

### Review 重点

重点 Review credential 永久排除、URL 约束、header allowlist 与透明流包装。

## 八、M3：模型建立前有限重试

### 目标

实现 provider-neutral、显式、有限、取消敏感且可观察的建立重试，并证明任何已建立事件流都不
进入透明重试。

### 前置依赖

M2 已确认。

### 实施内容

- 在 `agent-model` 新增 `ModelRetryReason`、`ModelRetryPolicy`、`ModelAttemptEvent`、
  `ModelAttemptObserver` 和 `RetryingModelService`。
- `delays` 明确决定每次等待和最大 attempt；`retry_on` 明确允许错误，不提供默认策略。
- 每个 attempt 复制相同 ModelRequest、更新 TraceContext.attempt，并记录 Started、失败、等待与
  StreamEstablished。
- Retry-After 与策略 delay 取较大值；超过 max_retry_after 时直接返回原错误，不缩短等待重试。
- 等待与下一 attempt 使用 cancellation 竞争；取消后不发新请求。
- capabilities/context_window 完全委托下层；observer 无返回值，不能改变调用结果。
- Core 不增加分支；通过装配包装后的 ModelService 证明同一 Model Step 只计一次。

### 自动测试或人工核对

- Connection、Timeout、RateLimited、Unavailable 可按显式集合重试；其余错误永不重试。
- 空 delays 只执行一次；等待表长度与实际最大 attempt 精确一致。
- 每次 attempt 的 ModelRequest 完整相同，Trace attempt 从 1 严格递增。
- Retry-After 合并、超过上限、等待前取消、等待中取消和成功前取消均确定性覆盖。
- `stream()` 一旦返回 Ok，后续 TurnFailed、Interrupted、Protocol、Cancelled 均不重试。
- 多个并发逻辑调用的策略、attempt、取消和 observer 事件互不污染。
- observer 丢弃或不存在时，模型结果不变。

### 验证

```bash
cargo test -p agent-model retry
cargo test -p agent-model
cargo test -p agent-core -p agent-provider-openai-compatible
cargo clippy -p agent-model -p agent-core \
  -p agent-provider-openai-compatible \
  --all-targets --all-features -- -D warnings
cargo fmt --all --check
```

### 完成判定

- 建流前瞬态错误可以按显式策略有限重试并完整观察；
- 流建立后没有任何透明重试入口；
- Core step、消息、工具和 Recorder 语义不变。

### Review 重点

重点 Review 重试资格、等待合并、取消竞争以及 Core 完全不感知 attempt 的证据。

## 九、M4：Reliability Demo Collector、完整性与 Timeline

### 目标

在 Demo 内私有实现有界异步 Collector、JSONL commit、严格 Loader 和只读 Timeline，先验证记录
可靠性，不接真实 Provider，也不实现 Replay Service。

### 前置依赖

M3 已确认。

### 实施内容

- 私有定义 TraceStarted、TraceRecord、TraceCompleted、Provider metadata 和少量 DemoHostEvent；
  payload 直接包裹 native Model/Provider/Agent/attempt 事实。
- 用户显式数据目录内先写 `<id>.incomplete.jsonl`；writer 按接收顺序分配连续 sequence。
- Collector 使用显式队列容量和最大文件字节数，观察入口只做非阻塞 try-send。Demo 默认队列
  为 4096 条、单 Trace 最大文件为 64 MiB；两者均可由正整数 CLI 参数覆盖，并在启动时展示。
- 首次队列/容量/serde/I/O 失败后原子置 Incomplete、拒绝新记录，并按技术方案排空已接收队列。
- 只有完成尾写入和 flush 成功后才 rename 为 `.jsonl`；Incomplete 永不写完成尾或 rename。
- Loader 校验版本、头尾、ID、sequence、count、correlation、attempt 和模型终态。
- Timeline 默认只展示元数据与摘要，`--full` 才展示高敏正文；读取不构造 Provider/Core/Tool。
- 使用 tempfile、受控 writer failure 和并发生产者验证，不访问用户目录。

### 自动测试或人工核对

- 正常记录形成 Complete；缺尾、断行、未知版本、sequence 缺口和 count 不符被拒绝。
- 队列溢出、最大字节、serde/I/O failure 和提前结束保留 `.incomplete.jsonl`，Agent 模拟结果不变。
- Incomplete 后新记录被拒绝，已接收队列按失败类型写完或丢弃，不发生死锁。
- 同时写入多个 correlation 时全局 sequence 连续、各调用内部顺序稳定。
- Timeline 能查看 Complete/Incomplete，默认输出不含 prompt/reasoning/tool args/raw bytes。
- `--full` 只改变展示，不修改 Trace 或触发网络/工具。

### 验证

```bash
cargo test -p reliability-demo collector
cargo test -p reliability-demo trace
cargo test -p reliability-demo timeline
cargo test -p reliability-demo
cargo clippy -p reliability-demo --all-targets --all-features -- -D warnings
cargo fmt --all --check
```

### 完成判定

- Demo 能可靠区分 Complete/Incomplete，并严格拒绝残缺精确读取；
- Trace 失败与模拟执行结果隔离；
- 尚未接真实模型或构造回放服务。

### Review 重点

重点 Review commit point、Incomplete 后行为、敏感正文默认隐藏和私有格式边界。

## 十、M5：Wire Replay 与 Model Replay

### 目标

基于 Complete Trace 私有实现两层离线回放，证明 Decoder 和规范模型事件都可确定性复现，且历史
工具副作用永远不会执行。

### 前置依赖

M4 已确认。

### 实施内容

- 私有实现 `ReplayTransport`，按 correlation + attempt 重放 status、允许 headers、raw chunks
  和 TransportError。
- 重建兼容 OpenAI profile 时只读取非敏感 metadata 并使用占位 credential，不创建网络客户端。
- 校验重新编码的 method、URL、非敏感 headers 和 body；版本/profile 不兼容返回明确 mismatch。
- 让录制响应重新经过真实 Provider Decoder 与 LifecycleValidator，比较完整结果和 ModelEvent 顺序。
- 私有实现 `ReplayModelService`，完整比较 ModelRequest，并在原边界重现建立失败或事件流。
- Replay stream 继续尊重当前 cancellation；损坏脚本、请求不符和脚本耗尽明确失败。
- 提供 `replay-wire`、`replay-model` CLI 读取 Complete 文件；Incomplete 在构造回放前拒绝。
- 回放入口不装配 Registry、Dispatcher、Authorizer、Recorder 或真实工具。

### 自动测试或人工核对

- 成功、建流前失败、非 2xx、分块变化、流中断和唯一终态均可离线复现。
- Wire Replay 产生的 Result/ModelEvent 与录制完全一致，不访问网络或 credential。
- Model Replay 对完整请求一致时成功，对 system/history/tools/options 任一差异明确 mismatch。
- Incomplete、未知版本、Adapter/profile 不匹配和损坏 Base64 明确失败。
- 回放包含 Tool Call 时只返回事件，不产生工具、Journal 或文件副作用。
- 回放取消只影响当前回放，不修改原 Trace。

### 验证

```bash
cargo test -p reliability-demo wire_replay
cargo test -p reliability-demo model_replay
cargo test -p reliability-demo replay
cargo test -p reliability-demo
cargo clippy -p reliability-demo --all-targets --all-features -- -D warnings
cargo fmt --all --check
```

### 完成判定

- Complete Trace 可在断网、无 credential 条件下完成 Wire/Model Replay；
- mismatch 和损坏数据不会伪装成成功；
- 历史副作用没有执行入口。

### Review 重点

重点 Review 两层回放的区别、精确匹配边界和无副作用保证。

## 十一、M6：真实 Provider 录制与离线回放闭环

### 目标

完成 `record` CLI 的真实 Agent 闭环，并用同一份 Trace 在断网、无 credential 条件下执行两层
回放和 Timeline。

### 前置依赖

M5 已确认。

### 实施内容

- 实现 Demo 私有 ObservedModelService，为每个逻辑模型调用生成 correlation，记录完整
  ModelRequest、建立结果和每个 ModelEvent。
- 装配 RetryingModelService、ObservedTransport、Collector、Agent Core、可靠 AgentEvent drain、
  私有 Journal 和一个固定无外部副作用工具。
- 记录 AgentExecution 开始/结束、取消、Journal begin/commit 与 Trace 状态等宿主事件。
- `record --data-dir` 从标准输入读取任务；只有该命令加载 `.env` 和 Provider credential。
- `--trace-queue-capacity` 与 `--max-trace-bytes` 使用 M4 的显式默认；重试由
  `--retry-on`、可重复的 `--retry-delay-ms` 和启用时必传的 `--max-retry-after-ms` 共同表达。
  未指定 retry reason/delay 时不装配重试包装器；配置摘要在启动时脱敏展示。
- `record` 完成后打印路径、完整性、逻辑调用、attempt 和各层事件计数，不默认打印正文。
- `timeline`、`replay-wire`、`replay-model` 在移除 credential 后读取同一 Complete Trace。
- 补齐启动文档、环境变量、临时数据目录和人工验证步骤。

### 自动测试或人工核对

- CLI 参数错误、缺 credential、非法目录、非法容量和非法 retry 配置尽早脱敏失败。
- 非 record 命令不加载 `.env`、不要求 API key、不会构造 ReqwestTransport。
- 真实一次纯文本或工具调用完整包含 Provider/Model/Agent/Host 四层事实且形成 Complete。
- 控制台默认不出现 credential、完整 prompt/reasoning/tool args/raw response。
- 删除进程 credential 或断网后，三种读取命令仍对同一文件成功。
- 真实 Tool Call 仅调用固定无副作用 Demo 工具；回放阶段不再次调用它。

### 验证

```bash

cargo clippy -p reliability-demo --all-targets --all-features -- -D warnings
cargo run -p reliability-demo -- --help
cargo run -p reliability-demo -- record --data-dir <TEMP_DATA_DIR>
cargo run -p reliability-demo -- timeline --trace <COMPLETE_TRACE>
env -u DEEPSEEK_API_KEY cargo run -p reliability-demo -- \
  replay-wire --trace <COMPLETE_TRACE>
env -u DEEPSEEK_API_KEY cargo run -p reliability-demo -- \

cargo fmt --all --check
```

人工验证使用 `mktemp -d` 创建专用目录，不使用仓库、用户主目录或应用数据目录。真实 Provider
执行会产生一次实际模型费用，执行前只展示脱敏配置摘要。

### 完成判定

- 一次真实 Provider AgentExecution 可以完整录制并在无网络/credential 条件下两层回放；
- Full Trace、控制台和回放均满足敏感信息与副作用边界；
- Reliability Demo 命令和文件保持私有开发工具契约。

### Review 重点

重点 Review CLI 装配顺序、真实 correlation、Agent/Journal 记录点和默认脱敏展示。


里程碑都不需要正式 Runtime 或应用层参与，也不会在回放中执行历史副作用。
