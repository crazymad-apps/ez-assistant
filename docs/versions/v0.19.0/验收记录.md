## 四、功能与跨层证据

### 4.1 Skill 发现、冻结与启停

- 正式 Runtime Host 与隔离文件夹测试覆盖四个固定 Root，以及“工作区 `.ez-assistant` >
  工作区 `.agents` > 用户根目录 `.ez-assistant` > 用户根目录 `.agents`”的确定性同名优先级。
- YAML 可缺省字段、有界解析、无效候选跳过、同级冲突和诊断均有自动化覆盖；发现阶段只保留
  Skill 源目录，不读取普通资源，也不在 Session 下复制 Skill 包。
- 名称启停只以校验后的 Skill `name` 作为 SQLite 键；禁用全部同名候选且不回退下层，
  启用不新增 Skill 级权限判断，后续文件与 Shell 操作仍由具体工具授权。
- Session 创建时冻结 Catalog、`SKILL.md` 定义和 System Prompt 投影；文件或名称开关变化
  只影响新 Session。Fork、归档恢复、Host 重启和 child 所有权均由离线测试覆盖。

### 4.2 用户与模型激活

- Composer 只保存一个待发送技能，再次选择直接替换；技能和完整 Input 在 accepted 边界
  原子冻结，成功发送后清空草稿，失败保留正文、附件、Goal 和技能标签。
- Queue、置顶、取消、Goal held input、恢复和用户消息均使用同一个冻结 Activation；
  Goal objective 不混入技能内部指令。
- `load_skill` 始终使用稳定字符串参数，不随 Catalog 动态改变工具 schema；unknown、不可调用、
  已激活和空 Catalog 使用稳定 Tool Result 表达。
- 正式 Host fake Chat Provider 验证模型先调用 `load_skill`，Runtime 原子落账 Tool Result、
  InternalContext 和 Activation 后，在同一个业务 Run 继续。第二次模型请求实际读取冻结正文；
  SQLite 可靠 step 为 `[1, 2]`，Host 重启后仍可恢复模型触发的活动技能。

### 4.3 内插时间线与恢复

- 脱敏结构夹具覆盖 `read_image -> Tool Result image -> request-only user-role envelope ->
  reasoning / Tool Call`，并覆盖 Chat/Responses、主 Run/child、相同 PartId 跨 step、分页、
  事件缺口、断线、快照重读和 Runtime 重启。
- 同一 Run 内 step 由 Core 全局单调递增，Desktop 只以 `run_id + step` 分组，以
  `run_id + step + call_id` 定位工具，不再依赖 Assistant 数量、当前活动 step 或 segment 映射。
- Skill、Goal、WorkPlan、压缩 continuation 与委派共用规范内部消息和统一边界协调器；
  Provider request-only 图片信封只在请求期生成，不进入规范 Conversation。
- 可靠消息、边界、Activation ledger、Run/message 引用和 staged append 的故障恢复均在
  TempDir、易失 Store 或隔离 Runtime Home 中验证；恢复不会重放历史工具副作用，
  未读取或写入用户实际 Runtime 数据库。

## 五、Desktop 与交互证据

- 设置导航及本版触达的固定文案已统一为中文；技能设置支持工作区范围、当前技能、诊断、
  名称启停、详情、覆盖关系和打开来源目录。
- 设置页每次重新进入“技能”或切换范围时重新读取管理投影；没有刷新按钮、文件 watcher，
  也不会替换已有 Session 的冻结 Catalog。
- `/skill` 支持搜索、键盘选择和单标签替换；Queue 技能标签位于右侧操作区左侧；
  用户消息、加载技能工具行和右侧当前上下文均只读取结构化快照。
- 设置一级页和二级页共用统一容器：页头固定且无底边框，返回按钮由容器参数统一渲染，
  页头操作紧凑布局，页头下方只保留一个整体滚动区；长 Skill 正文不再形成嵌套滚动。
- 单元测试覆盖中文输入法 composition 事件、单技能替换、提交成功/失败、设置容器、返回焦点、
  空状态和错误状态；Playwright 覆盖正式 Runtime Host 的基础产品链路。
- 验收期间修复 WKWebView 跨消息选区把块级边界绘制成整行蓝色的问题：会话结构、技能标签、
  工具行、状态和操作默认不参与文本选择，仅用户正文、助手 Markdown 和展开的思考正文允许选择；
  Markdown 内操作按钮保持不可选。Composer 结构同步禁止外部文档选区穿过，空 textarea、工具栏和
  模型选择不再被整块高亮；textarea 只在获得焦点后恢复原生文本选择能力。Desktop lint、
  ConversationView/ComposerDock 共 28 项测试、生产构建和 Tauri release `--no-bundle` 构建通过。

## 六、用户实机核验结论

验收期间提供以下真实 macOS Desktop/WKWebView 核验清单；用户完成当前版本实机使用后明确表示
“本版本没什么问题了”并要求归档，据此接受整体实机核验结论为通过：

- 中文输入法处于组合状态时，回车只确认候选，不误触发送；直接输入英文词组后不会按拼音拆分。
- `/skill`、级联菜单、详情返回和弹窗关闭后的键盘焦点回到合理触发点。
- 长 Skill 正文和大量技能/诊断下，页头保持固定，内容区只有一层纵向滚动。
- `720px` 及更窄窗口下可完成设置、技能选择、发送和诊断，无不可达操作或横向溢出。
- 100% / 125% / 150% 缩放下标题、标签、操作区和正文没有遮挡或错位。
- 系统开启“减少动态效果”后，设置、选择器和抽屉仍可用且没有依赖动画才能理解的状态。
- 技能设置重新打开后取得最新文件与启停状态；已经存在的会话仍保持原冻结 Catalog。
- 从技能标签、工具行、消息间空白或输入框外围拖动不会产生整行蓝色选区；正文和代码仍可正常
  选择复制，输入框获得焦点后可正常选择、编辑其中的文本。
