## M5 Agent `load_skill` 与同 Run continuation（2026-08-25）

- `load_skill` 复用既有 `Serial`，不新增 Tool Batch 调度模式，也不关闭同批其他
  `ParallelEligible` 工具的并行能力；上下文一致性只由整批 Recorder 原子提交和 continuation 保证。
- `assistant-runtime::skill` 按稳定职责拆为 `types`、`discovery`、`catalog`、`activation` 四个
  子模块；crate 根公开导出和 `crate::skill::*` 调用路径保持不变，未新增领域抽象或行为差异。
- Core Recorder 完成结果新增通用 `continuation_required`，并增加可靠的
  `ExecutionContinuationRequired(ContextChanged)` 终态。Core 不识别 Skill/Run；Runtime 使用可靠
  consumption 在同一业务 Run 中推进下一全局 step。`ToolCompleted` 只在整批 Recorder 提交成功后发布，
  Recorder/Store 失败不会先产生伪成功事件。
- Runtime 对支持工具的模型稳定注册 `load_skill`，参数始终是普通字符串，不生成 Catalog enum；空目录、
  unknown、不可由模型调用和 already active 均返回稳定工具结果。`load_skill` 不进入 Skill 权限审批，
  后续真实文件/Shell 工具仍走既有 Authorizer。
- 主 Run 与每个 child 使用独立 Activation latch。成功调用按 ToolCallId 暂存，Recorder 再以统一内部边界
  构造隐藏 Runtime UserMessage，并把完整 Tool Results、Activation Message 和 ledger 作为同一事实提交；
  Store/Journal 成功后才提交 latch 并启动 continuation。用户显式 Activation 不执行空 `load_skill`。
- Host pending ready 载荷同时冻结 Tool Results、可选 Activation Message 与 ledger；parent/child staged
  append 在同一 SQLite transaction 内完成引用和 ledger。启动恢复不能只恢复成功工具结果而遗漏激活，
  并交叉校验 owner、Session、parent Run、message、trigger 和 retention key。
- 回归覆盖稳定 schema、unknown/not-invocable/staged/active、现有串行/并行批次语义、Store/Recorder 失败不发
  ToolCompleted、同 Run step 单调递增、下一请求读取激活、压缩保留 retention key、父子 latch 隔离和
  Host 崩溃恢复原子性。所有 SQLite/文件验证均使用临时目录或易失 Store，未访问用户实际 Runtime Home。
