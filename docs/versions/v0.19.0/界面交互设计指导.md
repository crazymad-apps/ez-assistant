# v0.19.0 界面交互设计指导：本地技能与执行时间线

## 一、设计信息

- 版本：`v0.19.0`
- 状态：已完成并归档（2026-08-25）
- 影响页面：Desktop 设置对话框、主会话 Composer、Queue、消息时间线与右侧“当前上下文”
- 关联设计：[`v0.19.0 功能设计`](功能设计.md)、
  [`v0.19.0 技术方案`](技术方案.md)
- 产品基线：[`v0.18.0 界面交互设计指导`](../v0.18.0/界面交互设计指导.md)
- 视觉基线：[`Desktop 设计语言`](../../resources/桌面端设计语言.md)

本指导只收口用户能直接看到和操作的布局、状态、焦点、文案和错误反馈。
Skill Catalog、Activation、Run 内全局 step、持久化和恢复契约以技术方案为准。
Desktop 只提交用户意图并展示 Runtime 权威快照，不解析 Skill 文件、
注入正文、工具结果或内插消息来猜测状态。

## 二、页面与入口

1. 现有设置导航收口为“运行时 / 模型 / 记忆 / 权限 / 技能”，新增“技能”页。
2. Composer 不增加底栏常驻按钮；用户输入 `/skill` 后进入单选技能选择器。
3. 右侧“当前上下文”新增紧凑的“技能”分区，只展示当前会话的冻结目录和激活摘要。
4. 用户消息和 Queue 项展示已冻结的单个技能标签；智能体自主激活显示为
   一行“加载技能 · <技能名>”工具事件。
5. 右侧技能诊断入口打开设置并定位“技能 > 诊断”；不在 Context Panel 内复制管理列表。

## 三、统一中文界面口径

### 3.1 固定产品文案

本版本对设置、Composer、Context Panel 和消息时间线中触达的固定文案执行中文审计：

| 现有或内部名称 | 界面文案 |
| --- | --- |
| Runtime | 运行时 |
| Workspace | 工作区 |
| System Context | 系统上下文 |
| Agent | 智能体 |
| Skill / Skills | 技能 |
| Active Skill | 已激活技能 |
| Slash Command | 斜杠指令 |
| Build / Plan | 构建 / 规划 |
| Ask / Auto | 询问 / 自动 |

用户安装的技能原始名称、模型名、服务商名、文件名、目录路径和
`/skill`、`SKILL.md`、`load_skill` 等稳定语法可保留原文。技术标识不作为页面主标题、
状态名或操作名。

### 3.2 状态不只依赖颜色

- “已启用 / 已禁用”、“正常 / 有警告 / 不可用”和“用户可用 / 智能体可用”
  均显示文字，颜色只做辅助。
- 稳定错误 code、YAML 字段名和内部枚举默认不直接显示；详情先给出中文原因，
  只在“技术详情”中保留稳定 code。
- 运行中、连接中断和命令失败都使用持续可见反馈，不只显示瞬时 Toast。

### 3.3 设置内容区统一容器

- “运行时 / 模型 / 记忆 / 权限 / 技能”的一级页面，以及模型编辑、技能详情等
  内容替换式二级页面，共用同一个设置页容器；
- 容器统一渲染标题、可选说明、右侧操作和可选返回按钮。二级页面只传入返回意图与
  无障碍名称，不自行拼接返回按钮；
- 页头固定且不显示底部分隔线；页头下方是唯一纵向滚动区，页面正文不再创建嵌套纵向滚动；
- 页头高度、左右留白、标题字号和操作间距保持一致，窄窗口下只由统一容器负责收缩。
- 权限范围 Tab 属于页头操作，不占用正文首行；按实际标签宽度紧凑排列，不等分或自动撑满可用宽度。

## 四、设置“技能”页

### 4.1 页面结构

沿用现有设置对话框的左侧导航和右侧内容区，不新建第二个管理窗口。
“技能”页从上到下为：

```text
页头：技能｜无可见字段标签的工作区范围选择器｜打开来源目录
分段入口：当前技能｜诊断
可滚动列表或对应空状态
```

- 工作区范围默认使用当前会话绑定的工作区；从右侧诊断入口打开时固定为该会话工作区。
- 没有当前工作区时使用“仅用户根目录”；下拉列表只包含已登记且未移除的工作区。
- 工作区范围使用 Desktop 通用选择器，以无障碍名称表达字段语义，不额外显示“工作区范围”标签。
- 页面没有“刷新”按钮、文件 watcher 或自动替换当前 Session Catalog 的交互。
- 每次“技能”页从未激活变为激活时，Desktop 都向 Runtime 重新请求所选工作区范围的
  最新管理投影；触发场景包括打开设置并进入“技能”、关闭设置后重新打开，以及从其他
  设置项切回“技能”。组件重渲染、窗口重新聚焦或设置窗口仍停留在“技能”页时不重复请求。
- 切换工作区范围时立即请求新范围的最新管理投影；名称启停成功后使用该命令返回的最新
  投影更新当前页面，不再额外发起一次读取。
- 页面保持打开期间，外部文件变化不自动跳动列表。用户修改技能文件后，可切到其他设置项
  再返回“技能”，或关闭设置后重新打开，以获取最新扫描结果。
- 重新读取只更新技能管理页；当前 Session 已冻结的 Catalog、Activation 和 Composer
  可选列表不变，最新文件和名称启停状态只供后续新 Session 使用。

### 4.2 当前技能列表

列表按技能名确定性排序，每行保持紧凑，不使用大型彩色卡片：

```text
[状态点] 技能名称                  [已启用 开关]
           一行描述
           工作区 .ez-assistant · 用户可用 · 智能体可用
```

- 名称保留技能原文；过长时单行省略，完整值通过 title 和详情可读。
- 描述最多两行；资格与来源使用弱化文字，不直接显示
  `user_invocable`、`model_invocable`、`winner` 等字段名。
- 开关是按名称的全局状态。切换期间只禁用该行；Runtime 成功后使用命令返回的投影替换当前行。
- 禁用后保留该名称和诊断，行内明确显示“已禁用”，并说明“所有同名来源都将被屏蔽”。
- 切换失败不乐观保留目标值；恢复原开关并在该行显示可操作错误。
- 点击行中非开关区域进入详情；详情复用设置内的内容替换和返回按钮，不再叠加模态对话框。

### 4.3 技能详情与覆盖关系

详情显示：

- 页头只显示技能名称，不在名称下重复摘要；
- 完整摘要放入信息区的“描述”字段，随后显示当前状态、当前生效来源和调用资格；
- 信息区下方展示当前管理范围重新读取到的 `SKILL.md` 正文，并使用安全 Markdown
  渲染。正文不建立独立的纵向滚动区；详情页名称栏固定，名称栏下方的描述、状态、
  正文和诊断共用设置内容区的单一滚动容器；
- 相关诊断继续显示同名候选的覆盖、冲突或禁用关系；打开或复制目录仍统一使用
  页面级“打开来源目录”菜单。

详情正文属于设置页的当前管理数据，不代表已有 Session 的冻结版本。详情不显示
激活账本、共享 Skill 源的绝对路径、资源文件内容或 SQLite 键值。

### 4.4 诊断列表

- 诊断按“错误优先、警告其后”和确定性路径排序，页签显示计数。
- 每项显示中文原因、技能名（能确定时）、来源层级和受限路径摘要。
- 无效 YAML、缺失必填字段、同级冲突、不可读、特殊文件和超限使用不同中文说明。
- 被高优先级候选项覆盖属于说明性诊断，不使用错误红色。
- 诊断不提供“强制加载”、“自动修复”或“忽略所有错误”操作。

### 4.5 打开来源目录

页头菜单按固定优先级显示四项：

1. 工作区 `.ez-assistant/skills`；
2. 工作区 `.agents/skills`；
3. 用户根目录 `.ez-assistant/skills`；
4. 用户根目录 `.agents/skills`。

未选工作区时，前两项禁用并显示“请先选择工作区”。目录不存在时不自动创建，
菜单显示“目录不存在”，详情仍可复制应创建的完整路径。

## 五、Composer 技能选择与提交

### 5.1 `/skill` 入口

- 一级斜杠指令项主标题为“选择技能”，快捷语法 `/skill` 作为次要信息。
- 选择该项后清除 `/skill` 字面量，打开锚定在 Composer 上方的技能选择器。
- 选择器只使用当前 Session Catalog 中“用户可用”的项，不读取设置页的当前扫描结果。
- 无可用技能时保留 `/skill` 入口，项目禁用并显示“当前会话没有可供用户选择的技能”；
  提供“打开技能设置”次要操作。

### 5.2 单选选择器

```text
[搜索技能…]
技能名称
技能描述 · 来源摘要
```

- 搜索匹配原始名称和描述，不暴露隐藏指令正文。
- 键盘上/下移动，Enter 或 Tab 选择，Esc 关闭；关闭或选择后焦点回到输入框。
- 中文输入法组词期间 Enter 不触发选择或提交。
- 候选项较多时列表有界滚动；键盘活动项始终滚入可见区。
- 草稿已有技能时，再次选择直接替换，不追加第二个标签，不弹二次确认。

### 5.3 草稿标签

- 标签位于输入框内、正文上方的草稿上下文行；Goal 与技能同时存在时，
  固定为“目标”在前、技能名在后。
- 技能标签只显示原始名称和移除 `×`；不显示来源、版本或资格字段。
- `×` 只清除 Composer 草稿选择；Esc 不移除标签，也不更改历史 Activation。
- 切换 Session 时清空原 Session 的草稿技能选择，不把一个 Session Catalog 的名称带入另一个 Session。

### 5.4 提交与保留

- 技能标签本身不是任务。没有正文、附件或 Goal objective 时发送保持不可用，
  可访问说明为“请输入要使用该技能完成的任务”。
- 提交携带正文、附件、Goal 模式和单个技能名，Desktop 不提交路径、digest、正文或 Catalog revision。
- Runtime 接受成功后才清空正文、附件、Goal 标签和技能标签。
- 上传、连接、资格校验或 Runtime 接受失败时，完整保留草稿，并在 Composer 持续错误入口中显示中文原因。

## 六、Queue、消息时间线与当前上下文

### 6.1 Queue 与用户消息

- Queue 项的弱化技能标签放在条目右侧操作区的左边，与置顶、取消等操作按钮同一行，
  只显示冻结名称，不占用正文摘要下方空间。标签设置最大宽度并单行省略；窄宽度下优先
  压缩标签，不能挤压或换行移动操作按钮，也不能回落到正文摘要下方。
- 置顶、取消、Goal held input、重启恢复和 Queue 抽屉收起/展开都保留该标签。
- 取消排队不删除其他消息上的 Activation；前端不把同名标签合并或换成当前设置 winner。
- 发出后的用户消息在气泡下方、时间/重输操作之前显示弱化标签，只显示冻结技能名称；
  标签不承担详情入口，不显示 Catalog revision、激活正文或来源路径。

### 6.2 智能体激活

- `load_skill` 的时间线主文案为“加载技能 · <技能名>”，并复用现有紧凑工具行。
- 展开工具详情时可显示“已激活 / 已是当前版本 / 未找到 / 不允许智能体调用”等中文结果，
  不显示 Skill 正文或共享 Skill 源的绝对路径。
- 成功激活后的 Runtime hidden UserMessage 不显示用户气泡，不计入用户消息数。

### 6.3 执行时间线

- 同一 Run 的 step 从 1 全局单调递增，但界面仍遵循现有设计语言，不显示“步骤 1”标题。
- 内插消息、图片兼容信封、Skill Activation、压缩和新 AgentExecution 都不新建用户气泡，不让 step 回退。
- `StepStarted` 即使丢失，reasoning、text 和工具事件也使用自带的 `run_id + step` 定位；
  前端不按 Assistant 数量、隐藏消息数量或当前活动容器猜测。
- 可靠消息到达后，只用相同 `run_id + step + part/call ID` 替换实时投影；
  不用文本相等、到达顺序或工具名去重。
- 重连、序号缺口或未知事件触发快照重读，重读期间不把已提交段移入其他 step。

### 6.4 右侧“技能”分区

```text
技能
skill-name  · 用户激活
查看 3 项技能诊断 >
```

- 标题不附加技能数量；分区只列出当前 Conversation 已激活的技能。
- 不展示 Catalog revision 或“可选技能”数量：前者是内部冻结身份，后者属于 Composer
  选择器数据，两者都不是当前上下文中需要用户理解或操作的状态。
- 已激活列表按规范 Conversation 顺序展示，同名新 digest 只标识当前生效版本。
- 无 Activation 时显示“尚未激活技能”，不隐藏整个分区。
- Catalog unavailable 时显示“当前会话的技能信息不可用”和诊断入口，不用当前文件扫描结果替换。

## 七、焦点、浮层与响应式

1. 技能选择器复用 Composer 单前台 overlay root；打开时关闭 Todo、执行设置、模型设置和其他选择器。
2. 完整 Approval Workspace 打开时关闭技能选择器，不清除已选技能标签。
3. 设置技能详情返回后，焦点回到原列表项；该项因范围变化不存在时，回到页头范围选择器。
4. `720px` 及更窄中栏不增加底栏项；Composer 技能标签可换行，但不把发送/停止按钮挤出
   可见区；Queue 技能标签保持在右侧操作区左边并单行省略，不回落到正文摘要下方。
5. 设置对话框变窄时，技能列表只收缩文本列，开关和状态仍可见；详情字段改为单列，不产生水平滚动。
6. 覆盖 100% / 125% / 150% 缩放、长技能名、长中文描述、256 项列表与“减少动态效果”。
7. 符合 `prefers-reduced-motion` 时只保留焦点、选中和必要加载反馈，不使用弹性位移。

## 八、状态与异常

| 状态 | 用户可见反馈 | 交互约束 |
| --- | --- | --- |
| 管理投影读取中 | 页内骨架/“正在读取技能…” | 不清空上一个有效范围的展示后伪装新范围 |
| 未发现技能 | 四个固定目录与 `SKILL.md` 最小说明 | 不引导市场、远程安装或刷新 |
| 只有诊断 | “未找到可用技能”并显示诊断数 | 可进入诊断，不强制加载 |
| 启停提交中 | 当前行加载状态 | 其他行仍可阅读；禁止重复提交当前名称 |
| 启停成功 | 开关与“对新会话生效”说明更新 | 不修改已有 Session Catalog |
| 启停失败 | 行内中文错误 | 恢复原权威开关，保留详情和范围 |
| 当前 Session Catalog 不可用 | Composer `/skill` 禁用，右侧显示诊断入口 | 不使用最新文件列表替代冻结事实 |
| 草稿技能校验失败 | Composer 持续错误 | 正文、附件、Goal 和技能标签全部保留 |
| 事件缺口/断线 | 沿用现有连接恢复状态 | 从快照按 `run_id + step` 收敛，不在 UI 猜测段落 |

## 九、验收口径

1. 设置导航、页头、列表、状态、按钮、帮助和错误使用中文；
   技能原名、模型名、路径和稳定指令只在必要位置保留原文。
2. 设置“技能”页覆盖工作区范围、当前技能、名称启停、候选覆盖、诊断、
   打开/复制路径、空状态和失败回滚，不存在刷新或强制加载操作。
3. `/skill` 只展示当前 Session Catalog 中用户可用项；选择器可搜索、可键盘操作、
   兼容中文输入法，再次选择只替换单个草稿标签。
4. 没有任务时不能单独提交技能标签；成功提交清空草稿选择，失败保留；
   Goal、附件、Queue、重启恢复和用户消息标签语义一致。
5. 智能体 Activation 只显示“加载技能”工具行，内部消息和 Provider request-only
   user-role 信封都不生成用户气泡。
6. 丢失 `StepStarted`、相同 PartId 跨 step、多次内插、断线重连、分页和快照重读后，
   reasoning、text 和工具仍按 `run_id + step` 归属，不闪烁、不重复、不串位。
7. 右侧“技能”分区始终使用当前 Session 冻结投影，可进入对应工作区的诊断，
   不展示正文、资源字节、共享 Skill 源的绝对路径或启停开关。
8. 组件测试和 Playwright 覆盖鼠标、键盘、焦点返回、长文本、空/错误状态、
   `720px` 及更窄宽度、100% / 125% / 150% 缩放、中文输入法和减少动态效果。
