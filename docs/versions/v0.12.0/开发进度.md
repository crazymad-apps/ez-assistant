## 当前范围

- 路线主题：Plan/Build、分层权限与正式工具策略。
- 功能设计已确认，覆盖固定 Agent 变体、持久化注入、Ask/Auto、Session/
  Workspace/Global 三级权限文件、变体化授权、显式重载、审批生命周期、工具
  中断恢复与 Runtime Host Web Demo 验证。
- 技术方案已确认，明确模式冻结位置、JSON 权限文件与 CAS 写入、Runtime
  Authorizer、审批状态机、pending tool start 最小恢复事实、SQLite 增量迁移和验证边界。
- 已确认开发计划，按 M0–M5 拆分模式与注入、权限源、Authorizer、审批、
  中断恢复和 Web Demo/验收。
- 已补充缓存稳定性约束：Plan/Build 共享完全相同的 Tool Definition，变体差异只进入
  持久注入与 Runtime 执行授权，不由 Host 裁剪工具注册。
- Plan 的结构化修改按路径区分：Agent 私有目录内进入普通权限决策，用户
  Workspace、附件和其他路径在 Plan 下硬拒绝；Shell 仍非强沙箱。
- 正式桌面 UI、自定义 Agent 变体、OS 强沙箱、子 Agent、后台调度和 Artifact 不进入本版本。

## 最近完成

- M0 已实现：公共模式枚举、Session 模式切换、Input/Run 冻结投影、持久 Injected Part、
  SQLite 四列幂等迁移、Host/Volatile Store 恢复以及 HTTP Demo 默认 Build 提交。
- M0 验证通过：目标五个 crate 的完整测试；目标五个 crate 的全 target/all feature clippy；
  `cargo fmt --all --check`。真实 LLM smoke 保持 ignored，本里程碑不需要产生费用。
- M1 已实现：严格 `permissions.json` 领域模型与稳定格式化、规则校验/去重，
  Global/Workspace/Session 固定路径，原始字节 SHA-256 revision、双重核对的 CAS 原子替换，
  不可变 Permission Registry、Session cohort 显式 reload 与安全诊断。
- M1 验证通过：Protocol/Runtime/Host 共 142 项自动测试通过，1 项真实 Provider 测试按设计
  ignored；目标三个 crate 的 all-target/all-feature clippy、fmt 和 diff check 通过。
- M2 已实现：Host `RunToolBundle` 只输出稳定 ToolSet 与 Continue/Deny 基础设施策略；Runtime
  组合 Plan 能力硬边界、三级动态规则、Ask/Auto fallback 和 typed facts matcher。Plan
  结构化 mutation 仅允许 Session/Workspace Agent 私有目录，并检查已存在路径组件的 symlink
  逃逸；Build 继续进入完整权限决策，二者工具定义一致且 Shell 都保留。
- M2 已将全局 Guardrail 配置编译进每个 Run，缺省 repeated invocation=4、consecutive
  failures=5，支持 off/observe/enforce，并把触发事实投影为公共 Runtime 事件。M2 的 Ask
  仍经脚本化过渡接缝维持 v0.11 Host 行为，真实 pending approval 留在 M3。
- M2 验证通过：计划指定的 Agent Core/Tools/Runtime/Host 测试共 209 项通过，Host 两项离线
  acceptance 通过，1 项真实 Provider 测试按设计 ignored；Protocol 23 项测试通过；目标 crate
  all-target/all-feature clippy、fmt 和 diff check 通过。
- M3 已实现：Runtime 内存 Approval Registry、查询/决策命令与 requested/resolved/cancelled
  事件；AllowOnce、Deny、Session/Workspace exact Allow；持久 Allow 采用读取、严格校验、
  单次冲突重试、CAS、Registry 更新、Core 唤醒的固定顺序。无 Workspace、写入失败、请求中断、
  Run 取消、Runtime 关闭和重启均保持 fail-closed，Global 没有交互写入口。
- M3 已删除 `--unsafe-unrestricted-local-tools` 和 Host 双工具模式；正式 Host 默认注册稳定一致的
  文件/Shell 工具集，由 Runtime Authorizer 唯一决策。离线正式 Host 验收覆盖 Ask 挂起、
  AllowSession 持久化及后续自动命中。
- M3 验证通过：Protocol 24 项、Runtime 85 项、Host 单元 45 项和三项离线正式 Host
  acceptance 共 157 项通过；1 项真实 Provider smoke 按设计 ignored。目标三个 crate 的
  all-target/all-feature clippy、fmt、diff check 与 Host 两级 `--help` 均通过。
- M4 为 Core Recorder 增加副作用前 started 可靠点；started 写失败不调用 Tool SPI，并形成
  可配对错误 Tool Result。Host 新增与 `pending_tool_exchanges` 级联的 `pending_tool_starts`，
  正式 Tool Result 结算后同步清理。
- M4 恢复区分未出现 started 的 `not_started`、已出现 started 的 `outcome_unknown`
  和 ready 实际结果；begun/ready 与 staged append 均有确定性修复，不重新执行工具。
- M4 经重新评估后移除了永久 Tool Audit DTO、`facts_json`、SQLite 审计表和公开查询；
  持久权限由 JSON 规则表达，正式工具历史由 Conversation 表达，审批只保留实时投影。
- M4 验证通过：目标五个 package 共 275 项自动测试通过，1 项真实 Provider smoke 按设计
  ignored；workspace all-target/all-feature clippy、完整测试、fmt 和 diff check 通过，workspace
  全 target/all feature check 通过。测试只使用临时 Runtime Home/SQLite/Workspace，没有访问用户默认数据。
- M5 已实现：私有 Web Demo 支持 Plan/Build、Ask/Auto、权限显式重载、pending approval
  快照与四种服务端可用决策，以及“继续调整计划”“开始实施”快捷输入；提交始终携带页面当前
  variant，刷新或 SSE 重连后从 Session、Run、Conversation、Attachment 和审批快照重建。
- M5 正式 Host 回证新增模式只切换、SQLite 持久化、双进程恢复、有效/无效 Global JSON reload、
  Build 提交覆盖旧 Plan 状态、Injected Part 持久化，以及 Workspace Allow 的 Build/Plan 隔离。
- M5 真实浏览器验收通过，覆盖模式切换、快捷输入、Ask/Auto、reload 和页面刷新后的状态恢复，
  Console 无错误；临时 Host 和配置副本已删除。
- M5 真实 LLM smoke 已显式执行并通过：隔离 Runtime Home/Workspace 中先完成 Plan，再由 Build
  触发真实 Shell 审批，AllowOnce 后创建并验证文件；Host 输出未泄漏 credential、Bearer Token、
  Prompt 或测试内容，产生少量模型费用。
- M5 全量回归通过：workspace fmt、all-target/all-feature clippy、完整测试、Host all-features 与
  no-default-features、Rust doc/metadata、Web Demo JS 语法、Desktop/Vite 与 Tauri no-bundle 构建、
  diff check 均通过。一次并行执行两种 Host feature 的构建竞争导致错误二进制被短暂调用，改为
  串行后同一 all-features 套件全部通过，不构成产品失败。
- M5 长任务渲染修复：移除正文/reasoning 的逐 chunk `textContent` 全文替换和逐 chunk 同步
  `scrollHeight` 读取，改为 `requestAnimationFrame` 批量增量追加、工具输出逐帧合并和每帧最多
  一次自动滚动；用户离开列表底部后不再强制抢回滚动位置。
- 历史 Conversation 使用 `DocumentFragment` 离屏构建后一次挂载；Demo 最多同时渲染最近
  400 条消息，单条正文和 reasoning 设展示上限并明确提示省略，Runtime 权威 Conversation
  不裁剪。修复后 Host all-features、clippy、JS 语法、diff check 和真实浏览器加载均通过。
- M5 长模型流修复：只读诊断确认两个失败 Run 均在 `request_timeout_ms = 300000` 后约
  300 秒结束，错误为建流后 Timeout、已有输出、未重试，不是 Step、工具或审批上限。根因是
  reqwest 总请求 timeout 覆盖了完整 SSE 生命周期。
- `request_timeout_ms` 保持配置兼容，现改为等待响应建立及相邻正文 chunk 的空闲上限；每个
  chunk 重新计时，持续输出不再因总时长被切断。建流前 Timeout 仍可按有限策略重试，建流后
  Timeout 仍结束当前 Step 且不透明重试。
- 新增真实 loopback Transport 回归，覆盖响应建立超时、持续 chunk 总时长超过配置仍完成、
  相邻 chunk 空闲超时；Provider 102/102、Runtime 85/85、Host 单元及 v0.10–v0.12 验收测试
  通过，相关三包及 workspace all-target/all-feature clippy、workspace 完整测试、fmt、diff check
  通过，真实 API/LLM smoke 按设计 ignored。
