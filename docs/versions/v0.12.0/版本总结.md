## 三、形成的核心能力

- Plan/Build 是固定 Agent 变体。Session 保存用于 UI 重建的最新变体；每次提交仍携带实际变体，
  Input 与 Run 冻结该次选择。
- 两种变体共享完全一致的 Tool Definition，避免切换模式导致模型工具缓存失效；差异由持久注入
  和 Runtime 授权执行。
- Plan 可使用 Shell，并可在 Session/Workspace 的 Agent 私有目录执行分析性动作；对用户
  Workspace、附件及其他路径的结构化修改保持硬拒绝。Shell 使用当前 OS 用户权限，不宣称强沙箱。
- Ask/Auto 与 Plan/Build 正交；权限规则按 Session、Workspace、Global 分层读取，并可按变体
  区分。Global 规则只允许用户手工维护，修改后由 Runtime 显式重载。
- 审批支持 Deny、AllowOnce、AllowSession 和 AllowWorkspace。等待审批时仍在执行前复核最新
  硬限制、基础设施策略和显式 Deny，避免旧审批绕过新规则。
- Core Recorder 在真实工具副作用前建立 started 可靠点；Runtime 持久化最小 pending tool
  start，与正式 Tool Result 结算后清理。重启恢复区分未开始、结果未知和已有结果，不擅自重放副作用。
- Web Demo 可验证变体、权限、审批、Conversation、工具活动、reasoning 与 token usage；流式
  DOM 更新采用逐帧批处理，历史对话使用离屏构建和展示上限，避免超长任务拖垮页面。
- Provider 的 `request_timeout_ms` 保持配置兼容，语义收敛为等待响应建立和相邻响应 chunk 的
  空闲上限；建流后失败不透明重试。

## 四、偏差、边界与遗留

- 实现未偏离已确认功能范围。规则 JSON、SQLite 投影、pending tool start 和 Demo HTTP DTO
  均按现有层级归属，没有形成第二份业务权威状态。
- Web Demo 是默认关闭的私有验收客户端，不构成正式桌面 UI 或公共产品协议承诺。
- pending approval 不持久化；Runtime 重启后不会恢复审批或自动续跑中断 Run。
- Global 权限没有交互写入口；权限修改后不会热监听，必须显式重载 Runtime 权限快照。
- 正式桌面 UI、自定义 Agent 变体、OS 强沙箱、后台调度、Artifact 与子 Agent 不进入本版本。
