# v0.15.0 开发计划：记忆与长期助手

## 一、计划信息

- 目标版本：`v0.15.0`
- 状态：已确认（2026-08-17）
- 功能基线：[`v0.15.0 功能设计`](功能设计.md)
- 技术基线：[`v0.15.0 技术方案`](技术方案.md)
- 架构依据：[`Agent 系统技术架构`](../../modules/agent-system.md)
- 产品基线：[`v0.14.2 版本总结`](../v0.14.2/版本总结.md)
- 视觉基线：[`桌面端设计语言`](../../resources/桌面端设计语言.md)

本版本沿用现有设置页、弹窗、工具详情、分页消息、通用下拉选择器和桌面导航样式，不另建
界面交互设计文档。Session 创建后 Workspace 不可更换；用户需要切换目录时新建 Session，
不保留隐藏的重绑定入口。

## 二、实施原则

1. 按 M0—M5 依次实施；每个里程碑完成实现和验证后停止，取得用户确认后才进入下一里程碑。
2. Runtime 始终持有 Persona、Pinned Memory、System Context、Recall 和 Conversation 的权威状态；
   Desktop 只持有表单草稿、弹窗和导航 History 等视图状态。
3. Persona、Pinned Memory、Workspace 根 `AGENTS.md` 只在 Session 创建时装配并冻结；恢复、压缩、
   Fork 和子 Agent 不读取全局最新值来静默改写既有 Session。
4. Conversation JSONL 是正文权威存储；SQLite FTS 是可删除、可重建的派生索引。Runtime 启动不得
   扫描或加载全部历史会话正文。
5. 记忆与 Recall 工具必须走现有工具解析、权限、审批、可靠 Tool Exchange 和审计链路，不建立
   特权旁路。
6. Recall 只提供搜索和有界续读，scope 仅为 `session`、`workspace`、`global`；不会自动写入
   Pinned Memory，也不会把 UI 浏览行为注入模型上下文。
7. 搜索结果跳转使用 Desktop 内存栈模拟浏览器 History；它不是 Runtime 业务状态，也不持久化。
8. 存储变更只采用向前兼容的增量迁移；测试必须使用隔离 Runtime Home，不修改用户真实数据。
9. 本版本不复活验证 Demo 或临时 Mock，不在里程碑实现过程中主动执行 Git commit/push。

## 四、里程碑明细

### M0：记忆权威状态与冻结 System Context

前置条件：本开发计划已确认。

目标：先建立正式状态所有权和 Session 创建边界，使后续 UI、工具和检索都落在稳定事实之上。

实施范围：

- 在 `assistant-runtime` 定义 Persona、Pinned Memory、修订号、CAS 更新和冻结上下文所需的业务端口；
- 扩展 Runtime Store 与 Host SQLite Adapter，使用增量 schema migration 保存正式结构化事实；
- Session 创建时读取全局 Persona、当时的 Pinned Memory，以及已绑定 Workspace 根目录的
  `AGENTS.md`，按确定顺序渲染并持久化最终 `SystemPromptSnapshot`；
- 对 `AGENTS.md` 设置字节/字符上限，处理不存在、非普通文件、不可读、非法编码和路径越界；
- 独立 Session 不装配 Workspace/`AGENTS.md`；子 Agent 继承父 Session 冻结上下文；Fork 继承
  原冻结前缀，只重建新 Session 私有目录和附件目录相关 Part；
- 移除 Session Workspace 重绑定的协议、Runtime、Store、Host 与 Desktop 调用链；旧 Session
  保持原绑定或未绑定状态，不做隐式迁移。

最小验证：

- Runtime/Store 单元测试覆盖迁移、CAS 冲突、创建、恢复、Fork、子 Agent 和独立 Session；
- `AGENTS.md` 覆盖正常、缺失、超限、不可读、非法编码和逃逸路径；
- 搜索确认生产调用链中不存在 Session Workspace 重绑定入口；
- `cargo fmt --all --check`，以及受影响 crate 的 `cargo test`、`cargo clippy`。

完成标准：同一 Session 在恢复、压缩和 Fork 语义下得到确定且可解释的冻结上下文，修改全局
Persona、Pinned Memory 或 `AGENTS.md` 只影响未来新建 Session。

### M1：Persona 与 Pinned Memory 产品闭环

前置条件：M0 已确认。

目标：让用户和 Agent 都能通过正式产品链路管理长期偏好与显式记忆。

实施范围：

- 在 `assistant-protocol` 增加 Persona、Pinned Memory、修订和能力 DTO/Command；
- 在 Runtime/Host 提供查询、启停、创建、更新、删除及 CAS 冲突响应；
- 正式装配 `list_pinned_memories`、`pin_memory`、`update_pinned_memory`、
  `unpin_memory` 四个普通工具，并复用当前权限、审批和审计机制；
- 在 Desktop 设置中实现单份全局 Persona 和 Pinned Memory 管理，复用既有通用表单、Select、
  确认弹窗和错误呈现组件；
- 右侧“当前上下文”展示当前 Session 已冻结的 System Context 摘要；点击后用只读弹窗显示
  持久化的完整原文，不额外伪造来源级还原；
- 明确区分“全局最新配置”和“当前 Session 冻结内容”，编辑不刷新既有 Session。

最小验证：

- 协议序列化、Runtime Command、权限审批、CAS 冲突和恢复测试；
- Desktop Store/组件测试覆盖新增、编辑、删除、冲突、空态和只读原文弹窗；
- `cd apps/desktop && npm run test && npm run build`；
- 受影响 Rust crate 的格式、测试和 Clippy。

完成标准：Persona 与 Pinned Memory 可通过正式 UI 和 Agent 工具管理，既有 Session 的冻结上下文
不会被后台最新值替换。

### M2：Conversation 派生检索索引

前置条件：M1 已确认。

目标：在不改变 Conversation 权威存储的前提下，建立可恢复的历史正文检索底座。

实施范围：

- 为 SQLite 增加 FTS5 派生表、索引 generation/head、脏状态和必要映射；
- 仅索引允许 Recall 的主会话与子会话用户/助手正文，过滤 reasoning、工具原始输出、审批载荷、
  密钥和其他不应暴露内容；
- Conversation 可靠提交后增量更新索引；提交与索引更新不一致时标脏，不阻断正文落盘；
- 首次搜索或后台有界任务按需重建脏/缺失索引，支持部分可用和诊断，不在 Runtime 启动全量扫描；
- 实现 trigram 能力探测、查询规范化、参数绑定、确定性排序、短查询降级和结果上限；
- 正确处理 Conversation generation 变化、归档、删除和子会话归属变化。

最小验证：

- 中英文、路径、代码片段、短查询、空查询、特殊字符及参数注入测试；
- 增量更新、崩溃窗口、脏索引、懒重建、部分失败、generation 变化和删除过滤测试；
- 启动性能测试证明不会读取全部 Conversation JSONL；
- Store Worker 并发和受影响 crate 门禁。

完成标准：索引可以删除后重建，索引损坏不破坏 Conversation，首屏启动成本不随全部历史正文线性增长。

### M3：Agent Conversation Recall

前置条件：M2 已确认。

目标：让 Agent 通过受控普通工具检索和续读既有会话正文。

实施范围：

- 扩展 `agent-memory` 的 Recall 契约：`MemoryRecall` 负责 `session`、`workspace`、`global` scope
  搜索，可选的 `RecallReferenceReader` 负责稳定引用和有界 before/after/around 续读；
- `session` 覆盖当前 Session 主会话及其子 Agent 会话；`workspace` 限定同一绑定 Workspace；
  `global` 覆盖允许检索的全部会话；
- Runtime 为每次调用注入真实 caller Session/Conversation/Run 身份，不接受模型伪造调用方；
- 返回签名不透明引用，续读时重新校验 caller、scope、归档/删除状态和 generation；
- 正式装配 `recall_memory` 工具 schema，搜索和续读均限制结果数、单条长度、总字符/Token 和超时；
- 结果作为普通 Tool Exchange 进入当前轮次，不自动 Pin，不修改来源会话；
- 工具详情展示 scope、查询、截断、部分失败和来源引用，不泄漏签名密钥或私有存储路径。

最小验证：

- 三档 scope 正反例、主/子会话归属、归档/删除、跨 Workspace 和独立 Session 测试；
- 引用篡改、过期 generation、跨调用方复用、边界续读和预算截断测试；
- Ask/Auto、批准/拒绝/恢复、可靠工具交换和审计测试；
- 隔离 Runtime Home 下的真实模型最小 Recall 链路。

完成标准：Agent 只能在请求 scope 与权限允许的范围内搜索、续读，任何 UI 浏览动作都不会隐式进入模型上下文。

### M4：Desktop 历史搜索与来源导航（已完成，已确认）

前置条件：M3 已确认。

目标：为用户提供与 Agent Recall 共享检索底座、但语义独立的历史搜索与可返回导航。

实施范围：

- 增加 `SearchConversationHistory`、`GetConversationRecallWindow`、
  `GetConversationPageAroundMessage` 和 `GetSystemContext` 等产品 Command/DTO；
- Desktop 搜索按会话分组展示标题命中与正文命中，支持 scope、加载、空态、部分结果和错误重试；
- 搜索结果弹窗只呈现只读命中片段；用户可打开来源会话并定位稳定消息锚点；
- 在 `NavigationStore` 建立仅内存的后进先出 History，记录 Session、子 Agent、消息锚点和必要滚动位置，
  提供返回/前进；直接切换普通会话时按已确认规则更新栈；
- 目标已归档时只读打开，目标已删除或 generation 失效时给出友好提示并保留当前页面；
- 消息分页使用 around-message 定位，不为跳转一次性加载完整 Conversation；
- 复用现有 Dialog、Dropdown、Select、加载态和消息定位组件，不使用原生 Select 或新造交互体系。

最小验证：

- Desktop Store/组件测试覆盖分组、scope、弹窗、来源跳转、返回、前进、重复跳转和栈清理；
- Playwright 覆盖从会话 A 搜索会话 B、定位、返回 A，以及子 Agent 来源；
- 归档、删除、过期锚点、分页 prepend 和窄窗口回归；
- Desktop 测试、构建和受影响协议/Host 测试。

完成标准：用户可以从搜索结果钻入来源会话并可靠返回原页面；该导航不改变 Runtime 权威状态或 Agent 上下文。

### M5：恢复、性能与版本验收

前置条件：M4 已确认。

目标：完成跨模块回归、故障恢复和版本级验收，确认功能可归档。

实施范围：

- 用 `v0.14.2` 数据副本验证增量迁移、旧 Session、归档、Fork、子 Agent、附件和权限兼容；
- 验证 Persona/Pinned CAS、配置损坏、索引损坏、索引重建中断、部分搜索结果和 Runtime 重启恢复；
- 对比新旧 Session 的冻结 Prompt，验证压缩、恢复、Fork、子 Agent 和根 `AGENTS.md` 规则；
- 建立 Runtime 启动、首次搜索、增量索引、批量检索和 Desktop 大列表的性能基线；
- 使用隔离配置执行一次真实 Provider 的 Pinned Memory/Recall 最小闭环；
- 补齐功能设计验收项、文档、开发进度、兼容边界和版本验收记录。

版本门禁：

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace

cd apps/desktop
npm run test
npm run build
npm run tauri -- build --no-bundle
```

如 Desktop 已有稳定的 lint/e2e 命令，还需执行对应命令；真实 Provider 与性能验证单独记录环境、
数据规模、结果和未执行原因。不得使用用户真实 Runtime Home 做破坏性恢复测试。

完成标准：功能设计的全部验收标准均有可复查证据，无已知阻断缺陷，文档与实现一致，用户确认后
进入版本验收归档。

本里程碑的环境、命令、性能数据和兼容性结果见
[`v0.15.0 验收记录`](验收记录.md)。技术门禁与用户验收均已完成，版本进入归档。

## 五、版本完成判定

| 判定项 | 要求 |
| --- | --- |
| 功能闭环 | Persona、Pinned Memory、冻结 System Context、根 `AGENTS.md`、Agent Recall 与 UI 历史搜索均走正式链路 |
| 权威状态 | Runtime 是唯一业务权威，Desktop 无第二份可写业务状态 |
| 数据安全 | Conversation JSONL 权威不变；迁移增量兼容；FTS 可重建；测试不触碰用户真实数据 |
| 权限安全 | 所有记忆/Recall 工具复用既有权限、审批、审计和可靠 Tool Exchange |
| 性能 | Runtime 启动不全量加载历史；索引与搜索有界且有基线记录 |
| 交互一致 | 使用现有设计语言和通用组件，来源跳转可返回，错误与部分结果可理解 |
| 验证 | M0—M5 均经用户确认，版本门禁和验收记录完成 |

本计划确认后，`docs/版本管理.md` 进入“开发中”，从 M0 开始实施；确认计划本身不代表自动批准
后续里程碑。
