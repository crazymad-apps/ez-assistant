# v0.15.0 功能设计：记忆与长期助手

## 一、设计信息

- 版本：`v0.15.0`
- 状态：已确认（2026-08-17）
- 影响模块：`crates/assistant-runtime`、`crates/assistant-protocol`、
  `apps/runtime-host`、`apps/desktop`，以及既有 `crates/agent-memory`、`crates/agent-tools`
- 需求来源：[`版本管理`](../../版本管理.md)中的后续能力地图、
  [`v0.5.0 可插拔记忆系统`](../v0.5.0/功能设计.md)及正式桌面 MVP 的既有产品边界

本文只定义正式产品需要形成的能力和用户可观察行为。存储表、索引、检索算法、协议字段、
前端组件和迁移实现由后续技术方案基于真实代码确定。

## 二、背景与目标

`v0.5.0` 已完成 Pinned Memory、RecallSource、统一召回能力和普通记忆工具的候选契约，
但只在独立 Memory Demo 中验证；正式 Runtime、应用协议和桌面端尚未装配这些能力。
当前 Session 虽然会冻结 System Prompt，但用户不能管理长期偏好、查看当前冻结原文，也不能让
Agent 从历史会话中按需召回信息。

`v0.15.0` 的目标是将既有记忆契约产品化，形成以下闭环：

1. 用户能够维护少量、长期有效的 Pinned Memory，并明确知道修改影响哪些会话。
2. Agent 能在权限约束下使用普通工具检索历史会话，也能按用户明确意图维护 Pinned Memory。
3. 用户能够设置一份全局 Persona，作为未来新会话的助手行为偏好输入。
4. 新建 Session 将 Persona、Pinned Memory 和既有运行环境信息组合并冻结为
   System Context；恢复、继续、压缩和分支不被后续全局修改静默改写。
5. 桌面端提供简洁的记忆管理、历史检索和当前会话上下文说明，不把记忆状态复制成前端权威状态。
6. 绑定 Workspace 的新 Session 自动读取其根目录 `AGENTS.md`，将项目约束随其余 System Context
   一起冻结；Session 创建后不允许更换 Workspace。

## 三、非目标

本版本明确不包含：

- 自动观察所有对话、自动提炼、自动合并、自动淘汰或后台学习；
- Embedding、向量数据库、远程记忆服务和跨设备同步；
- Skills、MCP、插件安装或由插件动态提供 RecallSource；
- 后台自动化、定时整理、计划任务和主动通知；
- 多 Persona 模板市场、角色社区和复杂 Prompt 编辑器；
- 把整个历史会话或全部记忆常驻注入模型上下文；
- 热更新活动 Session 的 Persona、Pinned Memory 或 System Context 快照；
- Session 创建后重新绑定、移除或更换 Workspace；
- 全局 `AGENTS.md`、`CLAUDE.md`、`.hermes.md` 等兼容文件，以及运行中按子目录动态加载规则；
- 为记忆建立绕过普通工具授权、审批、审计和 Run 记录的特殊执行通道；
- macOS 对外分发、签名、公证、自动更新、Windows 正式支持等发布事项。

## 四、核心概念

### 4.1 Pinned Memory

Pinned Memory 是少量、长期有效并值得在新会话中直接提供给模型的信息，例如用户偏好、稳定约束、
常用背景和明确要求记住的事实。它不是完整历史记录，也不是搜索索引。

- Store 保存最新状态；
- 新建 Session 时渲染并编译进冻结的 System Context；
- 修改只影响之后新建的 Session；
- 当前 Session 内通过工具刚刚写入的内容仍可从工具结果获知，但不会重写当前快照。

### 4.2 Conversation Recall

Conversation Recall 是对既有会话正文的按需检索。结果只作为一次普通工具结果进入当前上下文，
不会自动写入 Pinned Memory，也不会修改历史会话。它和 Pinned Memory 使用不同生命周期：
Pinned Memory 保存少量、长期有效并需要随新 Session 固定提供的信息；Conversation Recall 面向
数量不受 Pinned Memory 容量限制的历史正文，只在 Agent 明确检索和续读时临时进入当前轮次。

Conversation Recall 采用“检索发现 → 命中上下文续读”的两阶段交互。首次检索只返回有界候选和
命中片段；需要确认上下文时，再围绕稳定消息引用读取有限窗口，不一次性把完整历史会话加入模型上下文。

### 4.3 Persona

Persona 是用户维护的一份全局助手行为偏好，描述称呼、语言、表达方式、协作习惯和长期响应约束。
它不保存项目事实、模型密钥或权限规则，也不能覆盖应用安全策略。

首版只提供一个全局 Persona；修改只影响未来新建 Session。

### 4.4 System Context

System Context 是 Session 创建时冻结的系统上下文总和。构建时至少考虑：

- 应用内置 Agent 基线；
- 当前 Persona 快照；
- 当前 Pinned Memory 快照；
- 当前 Workspace 根目录 `AGENTS.md`（绑定 Workspace 且文件存在时）；
- 当前 Session/Workspace 运行环境信息；
- Runtime 已有的其他系统信息。

Session 只冻结模型可见的最终 `SystemPromptSnapshot`，不额外建立来源级投影，也不从
成品文本反解析 Persona、Pinned Memory 或运行环境。用户查看的是当前 Session
实际冻结的 System Prompt 原文；界面必须防止凭据等敏感配置被编译进该快照。

`AGENTS.md` 用于项目结构、开发约束、验证方式和协作规则，不代替 Persona 或 Pinned Memory，
也不能覆盖 Runtime 的权限、审批和安全策略。首版只读取用户创建 Session 时明确选择的 Workspace
根目录文件；独立 Session 不读取项目规则。文件后续变化只影响新建 Session，当前 Session、恢复、
继续、压缩和子 Agent 均继续使用已冻结内容。

## 五、功能范围与使用路径

### F01 Pinned Memory 管理

用户在设置中进入“记忆”页面，可以：

- 查看置顶记忆列表及其分类、正文、来源和更新时间；
- 新增、编辑、取消置顶；
- 搜索和按分类筛选；
- 查看容量占用及明确的容量超限提示；
- 看到“仅影响新会话”的持续说明。

列表使用简洁的一行或两行信息结构；编辑需要连续输入时进入表单，不在列表内堆叠完整正文。
删除采用可确认但不过度打断的交互，成功后以 Runtime 返回状态为准。

### F02 Agent 记忆工具

正式 Runtime 装配既有普通工具：

- `pin_memory`
- `update_pinned_memory`
- `unpin_memory`
- `list_pinned_memories`
- `recall_memory`

工具沿用普通 Tool Call、权限匹配、审批、执行记录和详情交互。模型不能仅凭自然语言声明“已经记住”；
只有工具成功并由 Runtime 持久化后，UI 才展示成功状态。

Agent 工具只处理模型需要的稳定 ID、分类和正文，不接收也不返回 `attributes`。`attributes` 仅作为
Runtime 业务元数据使用，不能由 Agent 根据记忆正文再次结构化生成，也不进入新 Session 的
System Context；Desktop/Runtime 业务接口仍可按业务需要维护该字段。

写入、修改和取消置顶属于持久数据变更，必须能由权限规则约束；默认行为和是否询问由技术方案结合
现有 Ask/Auto 装配规则确定，不能在 Core 内写死。

### F03 历史会话召回

首个正式 RecallSource 为本机 Conversation History。Agent 调用 `recall_memory` 时必须使用
`scope` 控制检索范围，支持：

- `session`：当前 Session 的完整历史，包括主会话和所属子 Agent 会话；
- `workspace`：当前 Workspace 下的全部 Session 及其子 Agent 会话；
- `global`：本地当前用户可访问的全部 Session，包括其他 Workspace 和独立会话。

默认范围为 `session`。Agent 可以根据用户意图显式选择 `workspace` 或 `global`，但无必要时不得因
当前范围无结果而自动逐级扩大检索范围。独立会话没有 Workspace 范围；请求无法成立时必须返回明确状态，
不能把 `workspace` 静默等同为 `global`。

首次检索为“检索发现”。Agent 提交查询、`scope` 和有界结果数量，Runtime 返回：

- 来源 Session 的稳定身份和标题；
- 命中时间与有限正文片段；
- 可定位到原消息的不透明稳定引用；
- 实际采用的检索范围；
- 部分失败、截断或无结果的明确状态。

第二阶段为“命中上下文续读”。Agent 使用首次结果中的稳定引用，可以：

- 围绕命中消息读取前后有限消息；
- 从当前边界继续向前或向后读取；
- 获得到达会话开头或结尾的明确边界状态。

每次续读都受消息数量、正文长度和模型上下文预算约束。续读必须继承首次检索的 `scope`，Runtime
每次重新校验稳定引用及访问范围；不能借助引用越过首次检索范围。相邻窗口允许重复一条边界消息，
帮助模型确认连续位置，但不得重复返回整段已读内容。

正式索引默认只包含已可靠提交的用户消息和 Assistant 最终可见正文，并覆盖主会话与子 Agent
会话。Reasoning、工具调用与输出、审批、System Context、运行状态以及未完成的流式内容不进入
默认检索正文。检索覆盖活动和已归档会话，但不跨用户、不访问已删除数据。

#### F03.1 工具结果详情

消息列表中的 Recall 工具行只展示查询完成状态、命中数量和“查看详情”入口。详情弹窗展示本次查询、
实际 `scope`、候选会话、命中时间和片段，并允许用户在弹窗内展开命中消息附近的有限上下文。

弹窗中的展开、分页和滚动只是用户查看行为，不触发新的 Agent Tool Call，不把额外内容加入当前
Agent 上下文，也不改变当前 Session。Agent 需要更多历史内容时，仍须显式执行命中上下文续读。

每条结果提供明确的“在原会话中查看”操作。点击后关闭弹窗，进入正式会话页面并定位到命中消息；
不在弹窗中复制一套完整消息阅读器。

#### F03.2 来源会话导航

来源会话跳转使用 Desktop UI 内部的轻量 History 栈，行为参考浏览器 History：

- 打开来源会话或普通切换会话时，将目标 Session 和可选消息锚点压入栈；
- 后退返回上一会话及原滚动位置，前进重新进入后一个会话位置；
- 后退后再打开其他会话时，截断原前进记录；
- 来源为已归档会话时沿用既有只读规则；来源不存在、已删除或不可访问时显示明确提示；
- 首版 History 只保存在 Desktop 内存，不要求客户端重启后恢复。

该 History 栈只服务 UI 会话切换，不属于 Runtime 权威状态，不进入 `assistant-protocol`，也不改变
任何 Session 的 Agent 上下文。当前查看会话切换后，左右侧栏和输入区按目标 Session 的既有规则更新。

桌面端的会话搜索同步支持“标题”和“消息内容”两类结果，并清楚区分普通导航搜索与 Agent 的
`recall_memory` 工具调用；两者可以复用 Runtime 检索能力，但不共享前端临时状态。

### F04 Persona 管理

设置页新增 Persona 管理入口，提供：

- 启用或停用全局 Persona；
- 编辑一份有明确字数上限的 Persona 正文；
- 查看最近更新时间；
- 预览其将如何参与新 Session，而不是展示尚未创建的最终 System Prompt。

Persona 为空或停用时，新 Session 只使用其余 System Context 输入。保存失败不得留下一份 UI
自认为成功的 Persona。

### F05 Session System Context 快照

新建 Session 时，Runtime 读取当时有效的 Persona 和 Pinned Memory；绑定 Workspace 时同时读取
Workspace 根目录的 `AGENTS.md`。这些输入与既有环境信息共同构建并持久化一份冻结快照。
以下场景必须保持语义稳定：

| 场景 | System Context 取值 |
| --- | --- |
| 新建 Session | 使用创建时最新 Persona、Pinned Memory 和 Workspace `AGENTS.md` 并冻结 |
| 恢复或重启 | 使用原 Session 快照 |
| 同一 Session 继续执行 | 使用原 Session 快照 |
| 上下文压缩 continuation | 使用原 Session 快照 |
| Fork / 分支 | 继承源 Session 的 Workspace 与冻结上下文，仅为新 Session 生成私有目录信息 |
| 子 Agent | 继承父 Session 已冻结快照 |
| 用户明确创建新 Session | 重新读取最新状态和目标 Workspace `AGENTS.md` |

当前会话不提供“刷新记忆”或“重载项目规则”热更新按钮。需要使用最新 Persona、
Pinned Memory 或 `AGENTS.md` 时，用户新建会话；产品必须清楚说明该行为，避免用户
误以为修改会追溯改变历史会话。

Workspace 在 Session 创建时一次确定，创建后不可重新选择、解绑或改绑；原有空 Session 更换
Workspace 的入口和产品命令不再对外提供。用户需要切换目录时，应在目标 Workspace 下新建 Session。
这保证 Workspace 规则、目录环境、权限作用域与模型缓存基线始终属于同一份冻结快照。

### F06 当前会话的上下文说明

右侧“当前上下文”中的会话区块增加简洁的 System Context 入口，展示“已冻结”和
快照创建时间（或 Session 创建时间），不再区分 Persona、Pinned Memory、Workspace/运行环境
等来源状态。

点击后打开只读的“System Context 原文”弹窗，按 `SystemPromptSnapshot.parts`
的冻结顺序展示模型实际可见的完整文本。弹窗不为 Part 推断或补充来源名称，不反解析
Persona 或 Pinned Memory，也不使用全局最新状态重建当前快照。

弹窗保留 Part 边界和文本换行，但不添加会被误认为 Prompt 原文的标题或分隔内容；长内容在弹窗内
自动滚动。该弹窗只用于查看，不允许修改当前 Session 快照，也不提供跳转编辑某个来源的入口。

### F07 记忆错误与诊断

记忆 Store 不可用、快照损坏、历史索引不可用、检索部分失败和容量超限均使用稳定错误分类。
界面保留可阅读的失败状态和重试/查看详情入口，不使用一闪而过的 Toast，也不暴露数据库语句、
绝对内部路径或模型凭据。

历史检索加速数据可以重建；权威 Conversation 和 Pinned Memory 正文不可因索引损坏被静默清空。

## 六、权威状态与模块边界

### 6.1 `agent-memory`

- 继续承载 Pinned Memory、RecallSource 和统一召回的实现无关契约；
- 不依赖 Runtime、协议、数据库或 UI；
- 不增加自动学习阶段。

### 6.2 `assistant-runtime`

- 持有正式 Pinned Memory Store、Persona、历史 RecallSource 和 Session System Context 快照语义；
- 在创建 Session 时编译完整冻结上下文；
- 固化 Session 与 Workspace 的一次性绑定，不提供创建后的目录重绑定；
- 将记忆工具作为普通 ToolSet 能力装配；
- 负责权限、持久化、迁移、检索范围、稳定引用校验、上下文续读和错误分类。

### 6.3 `runtime-host`

- 提供正式本地 Store/索引 Adapter 和 HTTP transport；
- 不复制 Session 或记忆权威状态；
- 不把 Memory Demo 的 JSON、CLI 或私有 DTO 直接提升为产品契约。

### 6.4 `assistant-protocol`

- 只提供跨层需要的记忆、Persona、检索和冻结 System Prompt 只读投影；
- 不公开 Store trait、数据库表或索引实现；
- 协议继续在现有版本内演进，不引入“Protocol v2”概念。

### 6.5 Desktop

- 发送用户意图并展示 Runtime 快照；
- 使用现有设置、列表、搜索、弹窗和详情组件；
- 使用内存 History 栈统一普通会话切换与 Recall 来源会话跳转，并恢复消息定位和滚动位置；
- 不在 `localStorage` 保存第二份 Persona、Pinned Memory 或召回索引；
- 不自行合并全局最新状态与 Session 冻结状态。

## 七、关键取舍

1. **先产品化既有契约，不重做 Memory Core**：`v0.5.0` 已验证领域边界，本版重点是正式
   Runtime、协议、持久化和 UI 闭环。
2. **Pinned 与 Recall 保持分离**：常驻少量稳定信息与按需检索大量历史使用不同生命周期，避免
   上下文无限增长。
3. **首版不自动学习**：自动提炼涉及置信度、冲突、隐私和删除语义，不能混入首次正式接入。
4. **Session 快照不可热更新**：保证历史重放、恢复、Fork 和上下文压缩语义稳定。
5. **Persona 是行为偏好，不是 Agent Profile**：首版只有一份全局行为偏好，不引入配置继承和模板市场。
6. **历史会话是首个正式 RecallSource**：先利用现有权威 Conversation，外部数据源等待
   Skills/MCP 版本再接入。
7. **检索与续读分阶段**：首次只返回有界候选，确认相关后再围绕稳定引用续读，兼顾可判断性与
   上下文成本。
8. **检索范围由 scope 明确表达**：默认局限于当前 Session，Workspace 和 Global 必须由 Agent
   按用户意图显式选择，不能静默扩大边界。
9. **检索结果必须可追溯**：Agent 可以续读来源上下文，用户可以跳转来源会话；两种操作互不替代，
   也不因 UI 查看而改变模型上下文。
10. **首版使用本地正文检索**：本版本不引入 Embedding 或向量数据库；具体索引与中文检索实现由
    技术方案在不改变上述产品语义的前提下确定。
11. **项目规则随 Session 冻结**：参考 OpenCode/Hermes 的项目上下文能力，但首版只读取 Workspace
    根目录 `AGENTS.md`，不引入运行期子目录发现，避免破坏快照与模型缓存稳定性。
12. **Workspace 创建后不可变**：切换目录通过在目标 Workspace 新建 Session 完成，不维护旧 Session
    的目录、规则、权限和缓存重绑定状态机。

## 八、验收标准

- [x] 用户可在设置中新增、编辑、搜索、分类和取消置顶记忆，重启 Runtime 后状态保持一致。
- [x] Pinned Memory 容量限制、并发修改和持久化失败均产生明确结果，不出现部分成功。
- [x] Agent 的五个记忆工具经过普通权限、审批、Run 记录和 Tool Detail 链路。
- [x] 新建 Session 包含创建时 Persona 与 Pinned Memory；修改全局状态不改变既有 Session。

## 九、风险、兼容性与待确认项

### 9.1 主要风险

- 向桌面端展示 `SystemPromptSnapshot` 时必须保留 Part 顺序和边界，避免客户端二次拼接改变原文。
- `AGENTS.md` 可能过大、编码无效、不可读或通过符号链接逃逸 Workspace；读取必须有界、可诊断，
  不能静默忽略或把外部文件自动注入 System Context。
- Conversation JSONL 与分页投影已是权威正文，历史内容检索不能在启动时把全部会话加载进内存。
- 记忆写工具必须和现有 Session/Workspace/Global 权限装配一致，不能额外维护一套审批语义。
- 历史命中可能包含敏感信息；检索范围、片段长度和结果展示需要默认最小化。
- 稳定消息引用可能因来源删除或权限变化而失效；续读和 UI 跳转必须重新校验并返回可理解状态。
- 中文、路径、错误码和自然语言查询对索引策略的要求不同；技术方案必须验证检索质量，但不能把
  首版描述为尚未实现的语义检索。

### 9.2 兼容性原则

- 既有 Session 直接沿用已保存的 `SystemPromptSnapshot`，不需要来源元数据迁移，也不用最新全局状态重建；
- 既有 Session 保留原 Workspace 绑定；移除空 Session 换 Workspace 能力不改写历史资源记录；
- 既有 Conversation 与归档会话继续可读；新增索引只是可重建加速数据；
- Memory Demo 继续作为历史验证包，不成为正式 Store 格式或产品接口依赖；后续可按既定清理计划删除。

### 9.3 设计确认点

本草案建议直接确认以下产品边界：

1. `v0.15.0` 只支持一个全局 Persona；
2. 首个 RecallSource 只包含本机历史会话；
3. Pinned Memory 和 Persona 修改只影响新 Session；
4. 不做自动观察、自动提炼和后台学习；
5. Conversation Recall 使用 `session`、`workspace`、`global` 三档 scope，默认 `session`；
6. Recall 包含检索发现和命中上下文续读，续读继承首次 scope；
7. 历史消息内容搜索同时提供给用户导航和 Agent Recall，但 UI 查看、来源会话跳转和 Agent 续读
   保持独立交互；
8. 来源会话跳转使用 Desktop 内存 History 栈实现返回、前进、消息定位和滚动恢复，不新增 Runtime
   路由状态或复杂产品协议。
