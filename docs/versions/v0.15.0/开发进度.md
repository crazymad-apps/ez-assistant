### M2：Conversation 派生检索索引

- 状态：已完成（已确认）
- 已完成：
  - 在 Host SQLite 中增加外部内容 FTS5 trigram 派生索引、owner head、generation、索引进度和
    `ready/dirty/rebuilding/unavailable` 状态；Conversation JSONL 仍是唯一正文权威；
  - 增量索引仅收录用户可见正文、文件原名和 Assistant 正文，明确排除 injected、reasoning、
    工具调用/结果、审批及系统上下文；索引失败只标脏，不阻断权威 Conversation 提交；
  - 查询支持 `session/workspace/global` scope、Unicode 规范化、参数绑定、trigram 最短三字符、
    最多 100 项结果和确定性排序；主会话、子会话及归档会话按 scope 正确归属；
  - 搜索时按需以每批 256 条消息、每次最多 8 个 owner 重建脏索引；单个 owner 损坏时返回其余
    可用结果并标记 partial，不在 Runtime 启动阶段扫描全部 Conversation JSONL；
  - FTS 能力缺失时自动重建派生 schema 并标脏；中断的 rebuilding 状态可恢复；generation 变化、
    历史重写、Fork、子会话更新及删除均维护索引一致性，旧 generation 不会泄漏；
  - Store Worker 承载有界检索与重建，Conversation offset cache 同时支持展示分页和原始消息窗口，
    不缓存整份正文。
  - 将 Runtime Store 的错误、Workspace/Attachment、Session、Run/Input、子任务、Conversation
    DTO 与统一业务端口按职责拆分为内部模块；公开名称、单一 `RuntimeStore` 端口及调用关系不变。

  - 覆盖中英文、路径、代码片段、短/空/特殊字符查询、注入防护、结果上限与确定性排序；

### M3：Agent Conversation Recall

- 状态：已完成（已确认）
- 已完成：
  - 拆分 `agent-memory` 的 Recall 能力边界：`MemoryRecall` 只负责 `session/workspace/global` 三档
    scope 搜索，可选的 `RecallReferenceReader` 负责 `before/after/around` 有界消息窗口；工具层仍
    对模型保持统一 `search/read` 入口；
  - Runtime 为 Recall 调用绑定真实 Session、Conversation、Run 与 Workspace 身份；`session` 覆盖
    当前主会话和子 Agent，`workspace` 不越过绑定目录，`global` 仍受调用方与权限约束；
  - 使用 Runtime Home 中持久化的 0600 HMAC 密钥签发不透明引用；续读会复核调用方、scope、
    Workspace、来源消息和当前 Conversation generation，历史重写后按稳定消息 ID 重新定位，
    删除或无法定位时返回引用失效；
  - Store 与 Host offset index 增加按稳定消息 ID 定位和原始消息窗口读取，不为续读加载整份
    Conversation；搜索索引仍是派生数据，Conversation JSONL 仍是正文权威；
  - 搜索与续读统一限制结果数、单条可见字符数、总 UTF-8 字节数和 5 秒超时，并明确返回截断、
    部分结果及失效状态；
  - 正式注册 `recall_memory` 普通工具，默认只读规则为 Allow，继续复用标准工具解析、权限、
    审批、审计、可靠 Tool Exchange 和恢复链路，不自动写入 Pinned Memory 或修改来源会话。
- 待完成：无。
- 验证：
  - `cargo fmt --all --check` 与 `git diff --check`：通过；
  - `cargo clippy -p agent-memory -p agent-tools -p agent-testkit -p assistant-runtime -p assistant-runtime-host --all-targets --all-features -- -D warnings`：通过；
  - `cargo test -p agent-memory -p agent-tools -p agent-testkit -p assistant-runtime -p assistant-runtime-host`：
    通过，正式 Host 的真实 Provider 用例按约定忽略，未产生模型费用；其中 Engine Harness 57 项通过；
  - 定向覆盖签名引用往返/篡改、调用方与 scope 复核、有界窗口、UTF-8 预算、密钥持久化与
    软链接拒绝、三档索引范围、generation/删除失效、部分结果、启动不全量扫描及默认权限装配。
