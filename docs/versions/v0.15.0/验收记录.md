## 三、性能基线

手工性能用例使用 release 构建和隔离 Runtime Home，数据规模为 24 个 Session、每个 12 轮、共
576 条消息。命令：

```bash
cargo test -p assistant-runtime-host \
  v015_storage_performance_baseline_reports_reproducible_cases \
  --release -- --ignored --nocapture
```

| 指标 | 结果 |
| --- | ---: |
| Runtime 启动 | 14.858 ms |
| 首次 Session 搜索 | 3.265 ms |
| 增量一轮提交 | 11.941 ms |
| 100 次批量搜索总耗时 | 135.907 ms |
| 100 次批量搜索平均耗时 | 1.359 ms |

运行环境：Darwin arm64 25.0.0、Apple M4 Pro、48 GiB 内存、Rust nightly 1.99.0
（2026-07-09）、Node 22.16.0、npm 10.9.2。该数据是本机回归基线，不定义跨设备产品 SLA。

Desktop 大列表回归使用 500 条独立 Session 投影，组件测试通过；其目的为防止列表规模增加时出现
同步渲染错误，不把单次测试进程时间解释为 UI 帧率指标。

## 六、已确认边界

- Recall 首版为本地词法正文检索，不引入 Embedding 或向量数据库；
- `AGENTS.md` 首版只读取 Workspace 根目录，不做运行期子目录级发现；
- Session 创建后不支持 Workspace 重绑定，切换目录通过新建 Session；
- Windows 本版本只保留兼容口，不进行严肃开发与正式验收；
- UI History 仅为 Desktop 内存导航栈，不属于 Runtime 权威状态，也不持久化；
- 真实 Provider 和手工性能用例保持 `ignored`，由验收命令显式执行，避免日常测试访问外部服务或延长门禁。
