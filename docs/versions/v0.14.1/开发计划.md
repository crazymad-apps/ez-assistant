# v0.14.1 开发计划：会话资源与子 Agent

## 一、计划信息与设计依据

- 版本：`v0.14.1`
- 状态：已完成并归档；M0–M4 与版本验收均已通过
- 前置版本：[`v0.14.0 版本总结`](../v0.14.0/版本总结.md)
- 统一功能范围：[`统一功能设计`](../v0.14.0/功能设计.md)
- 统一实现依据：[`统一技术方案`](../v0.14.0/技术方案.md)
- 视觉依据：[`桌面端设计语言`](../../resources/桌面端设计语言.md)与已确认亮色 Demo
- 后续版本：[`v0.14.2 开发计划`](../../design/v0.14.2-开发计划.md)

本计划复用统一设计，不新增第二份 PRD 或技术方案。目标是在 `v0.14.0` 正式主会话闭环上补齐
Session/Workspace 的完整产品管理、附件与文件资源、右侧上下文，以及可进入的子 Agent 消息视图。

模型/权限编辑、完整窗口/菜单/托盘生命周期和发布级收口仍属于 `v0.14.2`。开始本版本前必须根据
`v0.14.0` 验收中的实际协议、迁移和 Desktop 边界复核本计划；若需要改变统一功能语义，先回到统一
设计文档确认，不在计划中静默修改。

## 二、推进原则

1. M0 至 M4 顺序推进，每个里程碑完成实现和验证后等待用户确认。
2. 只消费 `v0.14.0` 已形成的产品协议增量、Observed Snapshot、MobX Root Store 和正式产品接口；
   不为本版本重建传输层、第二套消息组件或子 Agent 专用审批队列。
3. Session/Workspace mutation 先由 Runtime 形成权威结果，再更新 Desktop；归档、删除、Fork 和资源
   操作必须覆盖失败与恢复路径。
4. 主/子 Conversation 复用同一分页、Reasoning、Tool 和消息组件；差异通过 owner 和 capability 表达。
5. 子任务 Usage 只放子任务卡片/子 Agent 视图，右侧当前上下文继续展示主 Session，不在 UI 聚合。
6. 文件选择、系统打开和导出只经窄 Tauri native bridge；WebView 不获得通用文件或 opener 权限。
7. 测试继续使用隔离临时数据；不主动执行 Git 暂存、提交或推送。

## 四、里程碑台账

### M0：Session/Workspace 导航与非破坏性管理

- 前置：`v0.14.0` 已完成并归档；本计划复核并确认；当前版本进入 `开发中`。
- 目标：让用户在 Workspace 分组中完整管理仍可恢复的会话状态，而不改写历史执行归属。
- 交付范围：
  - Session rename、pin toggle、archive/restore、反馈和对应 revision/冲突处理；
  - Workspace 分组展开、单行 Session 布局、固定图标位置、运行中时间 loading 和归档页；
  - 会话 Header 的最近会话选择、InlineEdit、更多菜单与自适应弹性宽度；
  - 新建会话时选择目录；有历史 Session 重新选择目录时创建新 Session；空 Session 才允许原位换目录；
  - Workspace 复制路径、受控系统打开和失败反馈。
- 验证入口：

  ```bash
  cargo test -p assistant-protocol -p assistant-runtime -p assistant-runtime-host -p ez-assistant-desktop --all-features

  cd apps/desktop
  npm run lint
  npm run test
  npm run build
  ```

- 完成判定：重命名、固定、归档、恢复和 Workspace 选择均以 Runtime 快照结算；历史 Workspace
  绑定不可被 UI 静默改写；列表布局符合设计语言且无独立“最近会话”大分组。
- Review 重点：乐观成功、标题来源覆盖、归档后活动 Run、已有历史换目录和 native path 泄漏。
- 技术依据：功能设计 F03–F05、F22；技术方案第七节和 17.1。
- 实现结果（2026-08-14）：
  - Runtime 新增重命名、固定、空会话换目录和消息反馈的权威 mutation；SQLite 与内存 Store
    一致持久化 `title_origin`、固定状态与反馈，首条输入只覆盖自动标题；
  - 会话列表按固定优先、最近一次 Run 终结活动时间倒序投影；重命名、固定、模式等元数据变更
    不推进活动时间，Run 活跃期间以 loading 替代时间；归档/恢复沿用 Runtime revision 冲突检查，Desktop
    mutation 完成后统一刷新权威快照，不保留本地假成功状态；
  - Desktop 完成 Workspace 分组、归档页、Header 最近会话选择、标题行内编辑、固定/换目录/
    归档菜单、目录选择式新会话和 Workspace 打开/复制；有历史会话换目录会创建新会话，只有
    完全空会话允许原位重新绑定；
  - 系统打开只接受 `WorkspaceId`，由 Tauri 向 Runtime 查询并打开登记目录，WebView 不传入
    任意本地路径；
  - Host 能力声明新增 `session_management`，Desktop 发现不支持该能力的旧 Runtime 时直接报告
    组件不匹配，避免会话管理命令被旧 Host 误报为通用 JSON 解析错误；
  - 重命名与固定属于非执行元数据操作，即使 Session 因上一轮执行失败进入 faulted 状态仍可使用；
    归档、恢复和会影响执行归属的操作继续受健康状态约束；
  - 单元测试、正式 Host E2E、完整 Workspace 测试、Clippy、前端构建与 Tauri 无打包构建均通过。

### M1：Fork、永久删除与跨介质可靠边界

- 前置：M0 已确认。
- 目标：完成不可逆或跨介质 Session 操作，并用失败注入证明不会留下假成功状态。
- 交付范围：
  - 指定 Assistant Message 的 Fork 预览、确认、generation/cursor 冲突与新 Session 导航；
  - Prepare/Delete 短期确认 token、影响摘要、活动状态阻塞和 Desktop 确认弹窗；
  - SQLite 关系、主/子 JSONL、附件引用、导出临时文件和索引缓存的 staging/发布/回滚边界；
  - 归档、删除、Fork 的历史模型身份、消息 owner、运行定位和旧数据兼容；
  - 删除失败、进程中断、残留 staging 和重复请求的恢复测试。
- 验证入口：

  ```bash
  cargo test -p assistant-protocol -p assistant-runtime -p assistant-runtime-host --all-features
  cargo clippy -p assistant-protocol -p assistant-runtime -p assistant-runtime-host --all-targets --all-features -- -D warnings
  cargo fmt --all --check
  ```

- 完成判定：Fork 生成独立且可读的新 generation；永久删除只有在影响确认后执行；任一失败点不出现
  UI 已删除而介质未收敛的假状态；Workspace 用户文件不受影响。
- Review 重点：是否把删除误当单一 SQLite 事务；附件引用计数/归属；临时文件清理；删除确认 token
  是否可跨 Session 重用。
- 技术依据：技术方案 7.3–7.4、15.1–15.2 和第十六节。
- 实现结果（2026-08-14）：
  - Protocol、Runtime、正式 Host 与 Desktop 已形成 `ForkSession`、`PrepareDeleteSession`、
    `DeleteSession` 完整闭环；Desktop 先展示影响，再持确认 token 执行，不做本地乐观删除；
  - Fork 只接受当前 generation 内的完整 Assistant Message，复制其规范对话闭包和历史模型/
    Workspace/模式事实，不复制 Run，不重放工具；历史前缀中的附件建立新 Session 引用，复用内容
    Blob，并把消息内可读路径改写为新 Session 的稳定视图；
  - Fork 是对已可靠提交前缀的只读派生，不因源 Session 有后续 Run 或进入 faulted 状态而失效；
    Session mutation gate、generation 和工具闭包校验共同防止读到半成品；
  - 永久删除仍要求目标 Session 完全空闲且无活动子任务；短期 token 绑定 Session、精确影响摘要和
    过期时间，并在首次尝试时消费，不能跨 Session 或重复使用；
  - Host 先把完整 Session 私有目录改名到 deletion staging，再提交 SQLite 级联删除；提交失败恢复
    原目录，启动时根据数据库权威事实恢复或清理中断残留，提交后的清理失败不制造假失败；
  - 删除不触碰 Workspace 用户文件或其他 Session 仍在引用的 Blob；当前产品尚未实现导出临时文件，
    因此 M1 没有可清理的导出产物，导出及其同目录临时文件归 M2 实现和验收；
  - 正式 Host 浏览器场景已覆盖可靠历史 Fork、进入新 Session、精确删除预览、永久删除和列表收敛。

### M2：附件、文件预览、系统打开与导出

- 前置：M1 已确认。
- 目标：通过受控原生桥完成从选择附件到查看或导出资源的正式桌面链路。
- 交付范围：
  - Tauri 原生文件选择、Rust 流式上传与取消，API Key/Runtime token 不进入文件流程日志；
  - Session 附件与工具文件引用的稳定身份、可用状态、大小/类型和安全预览；
  - Range、大小上限、文本/图片等允许类型与不可预览回退；
  - Runtime 回查后的受控系统打开、复制安全路径；WebView 不传任意 path 给 opener；
  - Session Markdown 导出、保存对话框、同目录临时文件与原子替换；
  - Composer 的附件状态、上传失败、删除引用和提交冻结事实。
- 验证入口：

  ```bash
  cargo test -p assistant-runtime -p assistant-runtime-host -p ez-assistant-desktop --all-features
  cargo clippy -p assistant-runtime-host -p ez-assistant-desktop --all-targets --all-features -- -D warnings

  cd apps/desktop
  npm run test
  npm run build
  npm run tauri -- build --no-bundle
  ```

- 完成判定：选择、上传、预览、取消、超限、打开和导出均通过正式接口；取消或失败不留下目标文件；
  WebView capability 中没有通用 filesystem/opener 权限。
- Review 重点：symlink/path traversal、资源身份与显示路径混用、导出覆盖、远程图片或任意 MIME 放行。
- 技术依据：功能设计 F17、F22；技术方案第十三、14.1、17.1 和 18.4。
- 实现记录（2026-08-14）：
  - Tauri 只把临时选择 ID、文件名和大小交给 WebView；实际路径保留在 Rust 侧，上传以文件流
    直达正式 Host，支持 operation ID 取消，成功后只向输入提交稳定 Attachment ID；
  - Runtime 的 Attachment 事实继续作为权威来源，产品 Session 投影不再携带 Agent 可读路径；
    消息列表和右侧上下文可按 Attachment ID 打开受控文本/图片预览或调用系统应用；
  - 工具文件改为 `ResourceRefId` 稳定引用；WebView 只提交 Session、Message 和 Resource ID，
    Runtime 回查可靠 Conversation 后才由 Host 解析真实文件，工具详情内支持预览、系统打开和
    复制安全显示路径；子任务临时空间文件在任务终结后明确投影为不可用；
  - Host 资源路由只允许 UTF-8 文本、Markdown、JSON 和 PNG/JPEG/GIF/WebP，HTML/SVG 及未知
    类型拒绝；文本 4 MiB、图片 16 MiB，单 Range 同样受大小约束；文件必须最终解析为普通文件；
  - Session Markdown 导出只包含用户正文、附件名称、Assistant 正文和工具调用摘要，不包含
    Reasoning、Provider 私有状态、隐藏注入或完整工具输出；保存采用目标同目录临时文件、
    `flush + sync_all` 后原子替换，失败清理临时文件；
  - Composer 已提供选择、待上传、上传中、失败重试、取消/移除和成功引用状态；上传期间冻结
    本次提交，失败项保留供用户重试，不会把本地路径放入正文或 Runtime command。
  - Attachment Blob 目标保留原始安全扩展名，系统打开仍直接使用 Runtime 回查所得稳定路径；
    Host 启动会把旧的无扩展名 Blob 原地改名并修复已知软链接，不引入额外展示副本及清理周期。
  - 不支持预览或超过预览上限的资源改为明确的中文能力回退说明，不向用户暴露 Host 原始错误；
    附件预览和工具文件详情均提供“在目录中打开”，Tauri 仍按 Session、Message、Attachment 或
    Resource ID 向 Runtime 回查真实路径，不开放通用 path reveal 能力。
  - 用户消息中的附件组位于消息正文上方，正文下方只保留发送时间，附件与正文之间使用紧凑间距。

### M3：子任务树、子 Agent 消息和审批归属

- 前置：M2 已确认。
- 目标：在父 Session 中观察、进入和控制单层子 Agent，不创造子 Session 或第二套消息语义。
- 交付范围：
  - `GetChildTaskView`、Child Conversation 分页/Run 定位/Tool Detail 与自身 Usage 投影；
  - 主消息中的连续分叉任务树、状态、紧凑 Usage、pending approval 和取消能力；
  - 点击任务后以二级消息列表替换主列表，淡色返回按钮、任务标题/角色/状态和只读约束；
  - 主/子共用消息、Reasoning、工具详情、折叠和时间操作组件；
  - 子 Agent 审批继续进入父 Session 同一队列，默认可在主界面处理；从子消息恢复同一审批工作区；
  - 子任务取消与父 Run 状态、重连和历史终态的一致性。
  - 主/子产品投影与替代测试均完成后，删除私有整份 Conversation 命令、`web-demo` feature、CLI、
    路由、静态资源、状态字段、capability 和专用测试接缝。
- 验证入口：

  ```bash
  cargo test -p assistant-protocol -p assistant-runtime -p assistant-runtime-host --all-features

  cd apps/desktop
  npm run lint
  npm run test
  npm run build
  ```

- 完成判定：任务树连线连续，子视图可完整查看真实消息和工具；子 Agent 没有 Composer 或独立
  Session 生命周期；审批归属、取消和重连结果与父 Session 权威快照一致；默认和 all-features
  构建均不再包含 Web Demo。
- Review 重点：主/子组件分叉、子审批重复列表、子 Usage 与主会话聚合、进入子视图后右栏错误换 owner。
- 技术依据：功能设计 F14–F15；技术方案第九–十和 6.5。
- 实现结果（2026-08-14）：
  - 产品协议和 Runtime 已提供 `GetChildTaskView`、Child Conversation 游标分页、Tool Detail、
    独立 Usage、pending approval 数量和取消能力；子任务按 `child_task_id` 进入，不把 child
    伪装成独立 Session，也不暴露存储路径；
  - Desktop 主消息列表展示连续子任务树，点击任务后复用主消息组件进入只读二级列表；支持返回、
    历史分页、Reasoning、工具详情、任务状态和取消，右侧上下文继续展示父 Session；
  - 子审批复用父 Session 唯一队列和底部审批工作区，从主/子视图均处理同一事实；实时 child 事件、
    重连和权威快照已进入同一 Root Store，不建立子审批 Store 或子 Composer；
  - 私有整份 child Conversation 命令、`web-demo` feature、CLI、路由、静态资源、状态字段、
    capability 和专用验收测试已删除；正式 Host/桌面只消费产品协议；
  - Rust fmt、定向 Clippy、protocol/runtime/runtime-host 测试、Desktop 39 项单测、生产构建、
    Playwright 正式 Host E2E 和 Tauri no-bundle 构建通过；真实 Provider 测试继续按约定忽略。
