# v0.33.2 总体设计：后台运行管理与定时自动化

- 2026-11-19 更新。**总体设计已确认**，含 F02 的两种执行类型、无人值守与可选主控汇报。
- 来源：用户讨论、[版本路线](../../版本管理.md#其他候选及既有完成项)、[Shell 后台存活问题](../../inputs/260826-shell后台进程存活机制调研.md)。
- Feature 状态与确认统一见[版本开发计划](开发计划.md#二feature-台账)；本稿只维护方向与跨 Feature 边界。

## 一、目标与现状

本版让 Shell 在工具返回后继续运行，并能查询、查看输出和停止；在此基础上增加定时计划，由 Runtime 到时执行，结果可回查。

当前已有 [Runtime 任务监督](../../../crates/assistant-runtime/src/runtime/tasks.rs)、会话／Run、权限和通知能力，尚无完整定时计划。[现有 Shell](../../../crates/agent-tools-local/src/shell.rs)的 `managed`／`detached` 受单次工具清理与交接条件约束，缺少返回后的统一后台管理。

## 二、Feature 范围与顺序

| Feature | 交付能力 | 跨 Feature 契约 |
| --- | --- | --- |
| [F01 后台运行管理](features/F01-后台运行管理/功能设计.md) | Shell 后台启动；列表、输出读取、停止三个工具；右栏管理；滚动临时日志与自动回收；长列表分页。 | 提供运行标识、用户与来源归属、活动状态、退出结果和停止能力。Run 结束不终止后台进程。 |
| [F02 定时任务与自动化](features/F02-定时任务与自动化/功能设计.md) | Agent 型与脚本型计划、执行历史、按计划选择向主控汇报，以及聊天管理。 | Agent 型复用 Session／Run 与 F01，脚本型复用受管 Shell。两类共用调度及结果投递。 |

按 **F01 → F02** 独立设计、实施和验收，最后做版本联合验收。F01 内将长列表分页单列实施里程碑，扩展已有列表接口。

F02 的使用流程与验收标准见[功能设计](features/F02-定时任务与自动化/功能设计.md)。

- **计划管理**支持一次、每日、每周多选。用户选择执行类型、时间、可选项目，以及是否将执行结果返回主控会话。权限模式仅由 Agent 型计划配置。到点和「立即执行」使用同一配置，已接纳的执行不受后续编辑或暂停影响。
- **执行归属**。Agent 型用独立临时会话执行指令，由任务 Agent 撰写汇报和声明交付文件。脚本型直接运行指定 Shell 命令，结果取标准输出、标准错误和退出状态。两类均从计划执行记录查看或停止。
- **错过与失败**。错过时间不补跑，失败保留原因。无人值守执行时，缺少必要输入或权限则结束当次，按启动时的汇报开关处理。
- **界面与聊天**。Desktop、Host Web 和聊天工具管理同一份计划。结果始终保存到执行记录，开启汇报时另送主控，脚本输出保留原文。删除计划立即停止活动执行及关联后台进程，清除计划、历史和专属文件，保留已送达主控的消息与文件。首版默认限制定时执行自行创建周期计划。

## 三、共同边界

保持客户端与独立 Runtime Host 的现有拓扑。`assistant-runtime` 持有计划及后台运行业务状态；Host 负责用户域、传输与装配；本地 Adapter 管理真实进程和输出。`agent-tools` 承载能力契约，`assistant-protocol` 及 TS 投影承载应用协议。UI 展示和操作同一份 Runtime 状态，Agent Core 不增加业务调度。

- **归属**：计划归一个用户、一个 Runtime；后台运行、Agent Run、计划分别表达状态。不新增通用 Job 系统或会话级操作系统进程。
- **接纳与防重叠**。同一计划时间点只接纳一次，结果未知先回查。同一计划仍在执行或后台未收尾时，跳过下一次定时触发并说明原因，立即执行也遵守此检查。
- **生命周期**：客户端断开、Run 结束不停止已托管后台进程。注销、身份失效及正常停止 Runtime 时先回收；异常退出后，下次启动核对登记的主 PID、所属用户及创建时间，匹配才终止。仅补清登记主进程，不恢复存活任务或追踪其残留后代，清理失败不虚报成功。
- **定时等待**：有效且启用的计划应参与用户域存活判断，避免无客户端时被当作空闲域释放；不能阻碍显式退出或强留失效身份。Runtime 停止、主机休眠期间不承诺准点执行。
- **结果与恢复**：计划定义及触发关联持久保存，重启不重放未知副作用。执行记录区分 Agent 状态与关联后台状态；F01 结束时向 F02 交付退出结果，由关联执行记录保存最小结果或未知原因；后台条目及临时日志立即清理，不另存后台历史。暂停计划允许当前执行继续。删除计划显式调用 F01 的停止能力回收该计划关联的活动后台进程。
- **权限与容量**：沿用用户、设备、资源和 Shell 权限，不提权或自动续期身份。输出及列表有界；后台日志滚动保留最新内容，输出工具负责字符分页。

## 四、不纳入范围

- 工作流画布、DAG、Webhook、任意 cron、高频调度、历史周期批量补跑。
- 跨 Host 重启接管、自动重跑／保活、新增守护进程、任意系统进程管理、stdin／PTY；GUI 转交操作系统后的应用不保证受管。
- 子任务后台运行：本版仅允许子任务使用 `managed`，其目录生命周期支持留待后续。
- 云端代跑、跨设备迁移、远程唤醒、无人登录时恢复企业身份，以及系统推送、IM／邮件投递。

## 五、版本验收与后续

1. **后台管理**：工具返回及 Run 结束后仍可查询、读输出和停止；右栏与工具状态一致。输出按字符限量、滚动后可续读并提示丢失，任务结束后条目与日志立即清理；尚未结束的运行丢失标识可由列表找回。
2. **生命周期**：正常退出实际回收，异常退出后的启动补清不误杀、不虚报；子任务后台请求被拒绝。关闭页面／仅退出客户端保留后台与停止 Runtime 的行为明确区分。
3. **分页**：各长列表按页请求，不影响页外审批、介入、消息定位、技能装配和执行。
4. **计划闭环**。验证两类计划的时间规则、权限和结果来源。开关开启时主控收到当次结果，关闭时只在执行记录查看。Agent 临时会话可回收，脚本可直接运行。删除计划后仍能从主控打开已送达的文件。
5. **联合场景**：定时触发 → 后台命令 → Run 结束、进程继续 → 下周期跳过 → 手动停止 → 后续周期恢复。重启不重复执行，用户与 Runtime 不串数据。

发布须完成两项 Feature、联合验收及协议／数据兼容评估，覆盖正式 Host、Desktop／Web、个人／企业模式和适用平台；未验证限制如实记录。范围、归属、生命周期、权限或兼容边界变化时，先确认影响及重验范围。

F01 的实施顺序与验收见[开发计划](features/F01-后台运行管理/开发计划.md)。F02 的触发规则、会话生命周期和交付流程见[功能设计](features/F02-定时任务与自动化/功能设计.md)。
