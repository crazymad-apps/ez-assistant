# F02 功能设计 · 定时任务与自动化

v0.33.2 · 2026-11-19 · **方案已确认**

创建计划时先选执行类型。两类共用执行设备、时间规则、可选项目和执行记录。[版本总体设计](../../总体设计.md#二feature-范围与顺序)

| 类型 | 用户填写什么 | 本次结果 |
| --- | --- | --- |
| Agent 型 | 任务指令、智能体、模型及工具权限模式，例如「整理昨天的提交，生成日报」。 | 每次启动独立临时任务会话，由该 Agent 撰写最终汇报并声明交付文件。 |
| 脚本型 | Shell 命令或脚本内容，也可用命令调用设备上已有的脚本。 | Runtime 直接执行，记录标准输出、标准错误及退出状态。无需模型、任务会话或 Agent 权限模式。 |

**「将执行结果返回主控会话」**是每个计划独立的开关，新建时默认开启。开启时，成功、失败或单独停止的结果作为来源输入发给主控一次，由主控整理后向用户汇报。关闭时只保存在计划的执行记录中，失败也遵守开关。编辑开关只影响之后启动的执行。

Agent 型按所选模式调用工具，必要授权或输入缺失时，本次执行以失败收尾，无需人工值守。脚本型由 Runtime 以执行设备上运行 Host 的系统账户权限执行用户配置的命令，到点直接运行。两类计划的失败原因都写入执行记录，按本次开关决定是否送到主控。

## 一、创建与管理

Desktop 和 Host Web 的左侧导航提供「定时任务」。列表按当前用户和所选 Runtime 展示计划名称、执行类型、时间规则、启用状态和下次执行时间。点击计划可编辑配置、查看进展和历次执行记录。执行记录随计划删除。

| 用户操作 | 行为 |
| --- | --- |
| 创建 | 选择类型、填写相应内容和时间，确认执行设备、汇报开关及下次时间。需要项目时，从执行设备上有权访问的项目中选一个。从项目会话发起可预填并允许清空。 |
| 编辑、暂停、恢复 | 修改只作用于将来的触发。暂停取消下次自动执行，恢复从下一个未来时间点开始。已接纳的执行继续使用当时的配置。 |
| 立即执行 | 使用当前配置立即尝试一次，沿用相同的权限和防重叠检查。暂停中的计划也可手动运行，执行后仍暂停。原定时间保持不变。 |
| 删除 | 取消后续触发，立即停止活动的 Agent Run 及其后台进程，或停止正在执行的脚本。清理临时会话、计划空间、仅在记录中保存的结果及所有执行记录。已送达主控的消息和文件继续可用。 |
| 聊天管理 | Agent 可查询计划和执行记录，也可按用户明确意图创建、修改、暂停、恢复、删除或立即执行。写操作沿用权限与审批，返回计划名称、变更结果和下次时间。定时执行本身默认不能派生周期计划。 |

## 二、何时执行

- 支持一次、每日、每周多选。工作日用周一至周五表示。统一按执行设备的本地时间排程和展示。例如规则显示「周一至周五 09:00」，下次执行显示「11 月 20 日 09:00」。
- 一次性计划选择未来的日期和时间，触发后结束。
- Runtime 在线且用户身份有效时，即使关闭客户端也照常执行。启用且仍有下次时间的计划参与用户域存活判断。主机休眠、Runtime 停止或身份失效期间错过的时间点不补跑。一次性计划显示「已错过」，周期计划直接显示下次时间。
- 同一计划的同一时间点最多接纳一次。前次仍在运行，或仍有关联后台任务（含清理未确认）时，定时触发记为「已跳过」并给出原因；手动执行提示冲突并提供前次执行入口。下个正常时间点重新判断。

## 三、一次任务从执行到交付

1. **执行。** 到点和「立即执行」走同一入口。接纳时固定类型、配置与汇报开关。Agent 型创建临时会话，脚本型在选定项目目录运行，项目留空时使用计划的工作目录。用户可以在记录中查看进度或停止本次执行。
2. **形成结果。** Agent 型保存任务会话撰写的汇报。若 Agent 结束后仍有关联后台进程，等进程收尾后再确定最终状态和文件。Agent 未能写出汇报时，由 Runtime 附上实际失败或停止原因。脚本型保留 stdout、stderr 原文及退出码，输出超过上限时标明截断；没有输出也能看到退出状态。
3. **按开关交付。** 先将结果和已声明文件保存在本次执行记录。开关开启时，主控收到计划名、时间、状态、来源正文和附件，排队后整理为助理回复。聊天默认折叠来源正文，保留文件下载。长输出在会话中展示节选，执行详情保留完整结果。关闭时，本地保存完成即可回收临时资源。因前次仍在工作而跳过的时间点仅写历史。
4. **收尾。** 开启汇报时，主控可靠接纳后回收临时会话和目录。文件保存或投递失败只重试未完成步骤。删除计划时取消尚未送达的报告。

### 哪些内容留到下一次

| 内容 | 归属及生命周期 |
| --- | --- |
| 所选项目中已有的脚本和文件（选了项目时） | 任务按该项目原有授权使用这些文件。文件归项目所有，删除计划或清理任务会话时保留。 |
| 计划需要复用的脚本或状态 | 按需保存在计划自己的工作空间，下次执行可读取。删除计划时随计划清理。 |
| 本次交付物 | Host 将 Agent 声明的最终文件复制到 `<用户根>/data/scheduled-runs/<本次执行ID>/artifacts/`。计划存在时可从执行记录打开，开启汇报后主控消息引用同一份文件。删除计划时，只保留已送达主控的副本。多个交付文件可按需整体下载。脚本型的结果为命令输出，输出中的路径按文本显示。 |
| 本次对话和临时文件 | Agent 会话只服务当次任务，释放后不可续聊。脚本型只清理其临时执行资源。 |

例如，日报任务可复用项目中的脚本，用计划空间保存上次提交号。连续两天都生成 `日报.md`，用户仍能从各自的执行记录或主控消息打开对应日期的版本。

首版覆盖一次、每日、每周多选，以及同一设备上的 Agent 型和脚本型执行。任意 cron、工作流编排、设备唤醒和外部通知投递留在版本范围之外。

## 五、验收

1. 同一计划可从界面创建、在聊天中修改或暂停，两端显示一致的规则、目标设备和下次时间；不同用户和 Runtime 的数据隔离。
2. 三种规则的下次执行时间与执行设备的本地时间一致。覆盖客户端关闭、设备离线错过和手动执行后仍按原计划触发。
3. 同一时间点重复送达或与手动执行并发，最多启动一个活动执行。客户端离线时可自动完成，权限不足时记录失败原因，后续触发照常判断。
4. 编辑、暂停计划时，已接纳的执行继续使用当次配置。分别删除正在运行的两类计划，确认进程停止，计划及其历史清理，迟到回执不会恢复记录。
5. 同一 Agent 型计划连续执行两次，普通会话列表不出现任务会话。两次报告由各自的任务会话撰写，同名交付物可分别打开。
6. Agent 先结束、后台后写完文件时，等后台收尾后再保存与投递。删除计划后，已送达主控的消息和文件仍可打开，仅保存在执行记录中的结果随计划清除。
7. 两类计划各验证开关开、关。脚本执行阶段覆盖成功、非零退出、无输出、截断和单独停止，均无需任务会话或模型。关闭汇报时主控无消息，开启时同一次执行只送达一份，由主控整理后回复。覆盖执行途中修改开关及重启恢复。

页面流程见[界面交互设计指导](界面交互设计指导.md)，可在[交互原型](交互原型.html)中试用。实施顺序与验收安排见[开发计划](开发计划.md)。
