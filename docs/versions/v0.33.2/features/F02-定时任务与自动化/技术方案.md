# F02 技术方案 · 定时任务与自动化

v0.33.2 · 2026-11-19 · **方案已确认**。产品行为以[功能设计](功能设计.md)为准。

## 一、谁调度，存什么

每个用户 Runtime 负责自己的计划。Host 使用该用户现有 SQLite 和文件根保存数据，Desktop、Host Web 和聊天工具调用同一组 Runtime 操作。首版用计划表和执行记录表分别保存两类业务记录。

| 持久记录 | 内容与用途 |
| --- | --- |
| 计划 | 名称、类型（`agent` / `script`）、时间规则、设备内可选项目、启停状态及布尔开关 `report_to_controller`（新建默认开启）。Agent 型配置含指令、智能体、模型和工具权限模式。脚本型配置只含 Shell 命令文本。Runtime、界面和聊天使用同一类型契约。切换类型时整体替换专属配置，保存为脚本型时清除原 Agent 指令、模型、智能体及权限模式。历史执行保留接纳时的配置。 |
| 计划执行 | 接纳时冻结类型、有效载荷及汇报开关。两类共用执行标识、时间、状态和结果。Agent 型关联临时会话、汇报正文及声明文件；脚本型关联受管进程，保存有界 stdout、stderr、截断标记和可取得的退出码。历史随计划删除。 |

**每个有待触发计划的用户域只等待最近一次到期。** 保存、编辑、启停或删除计划时唤醒等待并重算；没有到期安排时释放等待。按执行设备本地日历计算一次、每日、每周多选。进程启动或系统从休眠恢复时跳过已错过的时间点，再等待下一个。普通调度唤醒的短延迟按原时间点接纳。实现时需用可控时钟分别验证短延迟与休眠跨过触发点。

本地时间落在夏令时跳过的分钟时，周期计划跳到下一个匹配日期，一次性计划保存时要求选择实际存在的时间。时钟回拨使同一分钟出现两次时，只取第一次。Host 返回带执行设备 UTC 偏移的下次时间，远程客户端可据此显示设备当地时间。

M1 将脚本计划的下一次到期与执行记录一同提交。Host 默认沿用受管 Shell 的 30 秒和 stdout、stderr 合计 1 MiB 上限。定时等待以墙钟复核到期，允许 5 秒普通延迟。检测到休眠或时钟跃迁越过的时间点时跳过。启动也按当时的本地日历重算。结果未知或进程回收未确认的执行继续占用该计划的名额，避免重启后与可能仍存活的进程重叠。

启用且有下一次触发的计划参与用户域存活判断。计划变化须通知 Host 重读工作状态，暂停最后一个计划后允许空闲域释放。Runtime 关闭时先封闭触发入口并取消等待，企业身份失效沿现有注销边界处理。[Runtime 工作状态](../../../../../crates/assistant-runtime/src/runtime.rs) · [Host 用户域](../../../../../apps/runtime-host/src/user_domain/mod.rs)

## 二、从触发到执行

1. **先接纳，再运行。** 定时与「立即执行」进入同一计划的串行检查。在同一 Store 事务中复核计划状态、检查前一次是否仍占用执行名额、写入本次记录。定时触发同时推进下次时间，以计划及原定时间唯一识别该次触发；手动调用复用请求身份，保留原定时间。暂停的计划仅允许手动触发，仍保持暂停。前次仍在运行或后台清理未确认时占用名额。冲突时，定时记跳过，手动返回正在执行的那一条。
2. **Agent 型。** 用执行标识派生内部幂等键，复用「创建会话并提交首条输入」，在同一提交中绑定计划执行与会话。启动中断后先查接纳结果。复核失败且尚未创建会话时，直接记录原因。[会话物化](../../../../../crates/assistant-runtime/src/runtime/materialization.rs)
3. **脚本型。** Runtime 以执行标识管理取消和完成，核验用户身份、目标设备、工作目录及适用的 Host 执行限制，随后以 Host 系统账户直接运行计划中的命令。该路径复用本地受管 Shell，独立于 Agent 工具授权器。复用环境过滤、超时、取消、输出限制与审计。入口在计划执行记录，无需建立 Session 或调用模型。进程启动结果不明时禁止自动重放命令，恢复后据实记录未知原因。[本地 Shell](../../../../../crates/agent-tools-local/src/shell.rs) · [输出采集](../../../../../crates/agent-tools-local/src/shell/output.rs)
4. **执行入口与收尾。** Agent 临时会话须在普通侧栏、搜索、主控可管理会话和直达查询中由服务端过滤，分页计数使用同一条件。普通发送、复制和续聊入口拒绝任务会话。用户经执行记录查看进度或停止。Run 结算后，等关联的 F01 进程全部收尾，再保存最终状态及文件。依据 Runtime 的进程结束结果结算，缺失退出信息记为未知。脚本型在受管命令退出并回收输出后直接结算。[F01 收尾](../../../../../crates/assistant-runtime/src/runtime/background.rs)

**无人值守。** Agent 任务及其派生执行按计划所选模式核验工具授权，需要人工确认时拒绝该操作。任务会话不装配 `ask_user`。脚本按上文的受管 Shell 路径运行。必要权限或输入缺失时以失败收尾。聊天中管理计划仍走发起会话的授权流程。[工具授权](../../../../../crates/assistant-runtime/src/permission/authorizer.rs)

## 三、保存结果与可选汇报

1. **先保存执行结果。** Agent 型取任务会话的最终汇报文本，复核声明文件的路径、权限与归属，完整复制到本次执行目录后登记。失败且尚无汇报时用 Runtime 已知的原因。脚本型保存 Shell 的实际输出、退出状态及截断信息，按原文显示，空输出也要保留状态。脚本输出作为结果数据传递，不能作为主控指令提交。[产物声明](../../../../../crates/assistant-runtime/src/artifact.rs) · [文件读取边界](../../../../../apps/runtime-host/src/http/resources/artifacts.rs)
2. **按本次执行的开关投递。** 关闭时，持久化结果及声明文件即可进入清理，恢复时同样跳过投递。开启时，用执行标识去重，将本次结果和文件清单可靠交给主控。结果入队与去重回执共用事务，沿用主控队列受控串行。主控使用纯文本推理轮整理，不装配工具。脚本执行没有源 Run，主控接纳按计划执行标识校验归属。主控消息与执行记录引用同一份文件，主控消息可独立访问。只有来源已写入历史时，执行详情才提供消息定位入口。[主控报告](../../../../../crates/assistant-runtime/src/runtime/controller/mod.rs)
3. **清理与恢复。** 释放当次临时资源和 Agent 会话。复制或投递中断后只补做未完成的步骤，按标识核对回执，保留必要材料直至完成或删除计划。

## 四、删除与交付同时发生

删除先标记计划正在删除，关闭后续触发和新投递。对 Agent 型取消活动 Run 及关联后台进程，对脚本型取消该执行的 Shell 并确认进程停止。随后清理临时资源、专属工作空间、全部执行记录及未归属主控消息的文件。停止失败时保留重试所需信息，中断恢复后继续删除。[会话删除门禁](../../../../../crates/assistant-runtime/src/runtime/session_management.rs)

M3 使用独立的持久删除标记和执行后处理游标。受管脚本启动身份随执行登记，Host 重启时先补清可核验的旧进程，再释放执行名额。进程身份或回收无法确认时保留删除标记和材料，等待后续核验。历史通知仍可按原回执定位和下载文件，主控整理从新投递开始。

**以主控队列是否已接纳结果为界。** 删除和报告提交在同一用户 Store 中按计划串行裁决。删除先提交，复制中的交付须结束写入并清除未送达副本。主控接纳先提交，则保留已入队的结果和它绑定的文件。迟到的进程结果或复制回执仅更新仍存在的执行。删除项目计划只清理应用拥有的目录。

## 五、接入与验证

- **入口。** Desktop、Host Web 与聊天工具共用计划管理和分页历史。提供 `list_schedules`、`get_schedule`、`create_schedule`、`update_schedule`、`run_schedule_now`、`delete_schedule`。创建和修改支持类型、对应内容及汇报开关，详情返回同一配置。M1 提供 `list_schedule_executions`、`get_schedule_execution` 与 `stop_schedule_execution`。分页返回摘要，详情回读冻结配置和输出。停止返回当前状态，回收完成后可查到最终结果。权限和目标 Runtime 沿用现有边界，远程访问同步调整命令白名单和文件读取权限。
- **兼容。** M0 通过 Host 现有迁移在 0.33.1 用户库追加 `schedules`，登记 schema 0.33.2 和数据库最低兼容 Host 0.33.2，旧 Host 在写入前拒绝已升级的库。客户端与 Host 的应用协议下限沿用 0.33.2。计划定义的 Rust／TS 投影同源，Volatile Store 实现相同操作，M1 在同一版本迁移链追加执行表 `schedule_executions` 与计划到期游标，保留 M0 计划定义。[迁移入口](../../../../../apps/runtime-host/src/storage/migrations/mod.rs)
- **验收。** 在隔离 Runtime 验证两类执行分别开启和关闭汇报，覆盖失败、取消、无输出、截断、重启和交付回执丢失。重点核对脚本执行阶段无模型调用、开启汇报后主控能独立整理、关闭汇报后仍可从历史读结果，以及删除时停止真实进程并按消息归属回收文件。[功能验收](功能设计.md#五验收)
