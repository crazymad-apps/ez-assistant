# F01 技术方案：后台运行管理

- 版本：v0.33.2；更新：2026-11-18；状态：已确认。
- 依据：[功能设计](功能设计.md)、[总体设计](../../总体设计.md)。

## 一、现状与实现边界

已核对的复用点：

- [Shell 契约](../../../../../crates/agent-tools/src/capability/shell.rs)返回最终结果，[本地实现](../../../../../crates/agent-tools-local/src/shell.rs)持有进程及 stdout／stderr 管道。`managed` 在结束时清理可管理后代；`detached` 需主 Shell 退出且双流 EOF 后才交接，不能直接承载返回后查询和停止。
- [Host 工具工厂](../../../../../apps/runtime-host/src/resources/tools.rs)按 Run 装配能力；[RuntimeTasks](../../../../../crates/assistant-runtime/src/runtime/tasks.rs)已有监督及有界关闭。后台控制需要跨越单次 Run，不能由工具 future 独占。
- [现有列表协议](../../../../../crates/assistant-protocol/src/command.rs)已有运行、技能、子任务和附件查询；[会话快照](../../../../../crates/assistant-runtime/src/runtime/product.rs)及[右栏](../../../../../apps/desktop/src/features/context-panel/ContextPanel/index.tsx)仍传输／展示完整数组，[介入核实](../../../../../apps/desktop/src/stores/RunInteractionController.ts)依赖 `view.runs`，不能直接截断。

新增 Runtime 私有后台运行模块，持有业务登记、状态与监督任务；`agent-tools` 承载必要能力契约，本地 Adapter 持有进程及日志 I/O，由 Host 注入。Runtime 不依赖本地 Adapter，Host 不维护第二份业务表。无需新 crate、数据库表或产品进程。

## 二、启动与所有权

新增 `process_mode=background`。`wait_ms` 只决定首次等待多久，`timeout_ms` 是可选总运行时限；省略总时限时持续到自然结束、手动停止或 Runtime 关闭。旧模式保留原超时规则。参数含义及上限同步进入 Schema 和授权事实。

1. 装配时绑定真实用户域、主会话、Run 与工具调用，模型不能指定 owner。子任务仅接受 `managed`，不装配后台列表／读取／停止工具，不能借 `detached` 绕过该限制。
2. Runtime 先占用活动容量并登记启动意图；本地能力启动受管进程，向监督任务移交等待、停止及输出控制。继续复用进程组／Job Object、环境过滤和编码处理，不走脱管分支。
3. 返回成功前完成身份记录落盘及监督交接；失败清理已启动进程。交接和取消在同一记录内串行决定：交接前取消清理，交接后 Run 取消仅结束本次等待，后台控制随 Runtime 生命周期。
4. 通过既有 ToolCallId 与执行事实关联同一次启动，重复到达先查原结果；结果未知不得作为一次新调用重放。仍未结束的运行可由列表找回，不建立新的重试台账。

等待内结束则返回退出结果与有界输出，并完成条目和日志清理，不返回可继续读取的路径。仍在运行则附 `background_id`、`log_path` 及有界预览，预览的 `cursor`／`next_cursor` 与输出工具一致。日志读取失败时保留 `background_id` 并返回输出错误，仍可通过该标识管理进程。非零退出仍是命令退出结果，启动成功不表示服务就绪。

活动运行计入 `has_background_work`；会话／工作区删除与启动登记共用操作门禁。停止请求由同一监督任务处理，重复请求复用结果；自然结束也收敛当前可管理后代及输出后才发布结束结果并移除登记。停止失败保留状态及控制入口。Run 结束后不再写入已关闭的工具输出通道，查询与 UI 使用后台模块。

### 退出后的自动状态更新与清理

监督任务持续等待受管主进程退出。无论自然退出、应用内停止，还是用户在外部终端／任务管理器结束进程、Agent 通过 Shell 执行 `kill`，一旦观察到退出都自动进入同一收尾流程，不依赖列表查询或再次调用停止工具。

- 取得实际退出结果，收敛当前可管理后代和输出；收尾完成后向等待中的调用及已有业务消费者交付结果、发布结束事件，立即从后台登记中移除。右栏自动移除条目，已打开的输出弹窗自动关闭并提示结束；后续列表不含该项。
- 确认收尾完成后释放活动名额、删除进程身份记录及临时日志，不设置终态缓存或结束后的读取保留期。进程清理未确认时保留可重试项；仅日志删除失败时保留必要文件清理依据，不让已结束任务留在活动列表。
- 外部退出与停止请求并发时，由同一监督任务只结算、释放一次；并发等待者取得同一次结果；清理后的再次调用返回不存在或已清理，不重建终态缓存。单个后代退出但主进程仍运行时，不据此把整项标为已结束。

## 三、工具与输出契约

| 工具 | 输入 | 返回 |
| --- | --- | --- |
| `list_background_runs` | `offset`、`limit`，可选状态及 `background_id` | 归属范围内未结束任务的标识、命令摘要、目录、来源 Run、状态、日志路径及可用性、分页信息；不附日志正文。 |
| `read_background_output` | `background_id`、可选 `cursor`、`offset_chars`、`limit_chars` | `content`、实际起点 `cursor`、`next_cursor`、`dropped_chars` 及当前运行状态；任务已清理时明确返回不存在或已清理。 |
| `stop_background_run` | `background_id` | 有界等待后的真实结果；成功结束后条目及日志已清理；目标不存在时不虚构退出结果，失败明确返回未确认清理。 |

`cursor` 是从本次后台运行输出开始累计的字符位置，单位为 Unicode scalar value。`offset_chars` 是相对该指针的有符号偏移，默认 0；`limit_chars` 是本次字符上限，不能使用行数绕过。

- 未传 `cursor`：从当前保留内容中读取最近 `limit_chars` 字符，`offset_chars` 须为 0；首次读取不把主动跳过的旧内容算作丢失。
- 传入指针：请求位置为 `cursor + offset_chars`。小于 0 或超过当前末尾时拒绝；等于末尾时返回空内容及同一下一指针，仍可继续轮询。
- 请求位置早于保留起点：从保留起点读取，`dropped_chars` 返回差额；正常读取为 0。滚动不改变保留内容的逻辑编号。
- `next_cursor` 始终是本页实际末尾，即使暂时读到末尾也不置空。运行中空输出不代表结束；收到结束事件或目标已清理后停止续读。

例如已保留 `[10000, 18000)`：从 14000 读 2000 字符返回下一指针 16000；从 8000 读则返回实际起点 10000、丢失 2000、下一指针 12000。向前翻页可用上一页起点加负偏移；续读使用 `next_cursor`，无需先调列表或读取日志索引。

三个工具仅装配到主会话，执行时复核用户、会话及运行归属。启动沿 Shell 审批；列表／输出按只读能力、停止按写能力接入现有授权和审计，Plan 不获得停止权限。输出工具以运行标识授权，不接受任意文件路径。

## 四、滚动日志与回收

本地 Adapter 将 stdout／stderr 持续排空、解码并按采集顺序写入临时日志，不承诺双流真实发生顺序。日志在专用用户域／实例目录内，不登记为产物。

- 保留最新的有界内容，超限丢弃头部，不能达到容量后停止保存新输出。字节容量与单次字符返回上限分别约束，截取不拆开 UTF-8 字符。
- 正文保存在磁盘。内存保存稀疏字节／字符检查点和固定大小的读写缓冲。读取按检查点定位一页，滚动时按块把保留的尾部搬到文件头。写入、滚动及读取元数据由同一所有者协调，每次读取取得一致快照。
- 不保存每个读取者的游标，不向 Agent 暴露分段索引。`log_path` 指向当前保留内容，连续追读由输出工具处理。
- 任何方式结束都在收尾后立即关闭写入并删除日志，不保留终态条目、读取宽限期或回收定时器。读与结束并发时，在途请求最多返回已取得的有界快照，未取得内容则返回已清理；不能为读取重新创建日志。
- 初始化补清顺序见下一节。删除失败记录并保留清理依据，不能因为日志已删就宣称进程已结束。历史工具结果不改写，其中路径可能过期。

完整日志只作临时保留，不写入 SSE 事件历史；Shell 预览和 Agent 显式读取结果仍沿工具历史保存。任务结束清理或实例重建后，读取明确返回不存在或已清理，不提供永久审计日志承诺。

## 五、Runtime 退出与启动补清

桌面先核验发现记录、进程身份和实例锁，再走[已有本机关闭入口](../../../../../apps/runtime-host/src/http/commands.rs)。[Runtime shutdown](../../../../../crates/assistant-runtime/src/runtime/shutdown.rs)封闭启动入口，停止后台进程并等待回收及输出收尾。关闭请求未连通或超时时，桌面按原生身份执行强制停止，并报告后台回收未确认。

每个后台运行保留小型身份文件：系统 PID、操作系统用户、进程创建时间，进程名仅辅助诊断；应用归属沿用用户域和实例目录。正常完成后删除身份记录，不为残留清理新增数据库表。

初始化取得 Runtime Home 独占实例锁后，只处理旧实例登记：

| 核对结果 | 处理 |
| --- | --- |
| PID 存在，用户与创建时间匹配 | 停止前重核身份，平台支持时固定句柄；仅终止登记主 PID 并复查退出，再清理记录及日志。 |
| PID 不存在或身份不符 | 清理本程序对应的旧记录和日志，不操作身份不符的进程。 |
| 查询／终止失败，或无法确认退出 | 保留身份记录及有界日志，报告失败，供后续重试。 |

创建时间使用操作系统事实，不使用应用开始计时替代；进程名变化不等于 PID 被复用。重启后的目标不是本实例子进程，不依赖重新取得 `wait` 退出码；仅判断核验过的目标是否仍存活。处理身份记录后，再补清旧实例目录内无身份记录的遗留日志；失败记录关联的日志保留。清理目录不跟随链接，不删除本实例活动日志或用户文件。

正常管理继续复用现有进程组回收；**启动补清仅处理登记主 PID，不恢复后代关系，也不把主 PID 消失视为后代全部退出**。成功交接前的启动／身份落盘之间仍有异常中断窗口，不承诺清理未登记进程。本版不新增守护、全局按名扫描、进程接管或任务重跑。

关闭页面、客户端断线／崩溃和“退出并保留后台”不停止 Runtime；默认退出若要求停止 Runtime，则必须经过上述回收。注销、身份失效、更新和重启沿同一受控关闭边界验证。

参考取舍：[Codex 进程组实现](https://github.com/openai/codex/blob/18352dc4e8757d652e4102a17abc76601847b8da/codex-rs/utils/pty/src/process_group.rs)与 [Gemini CLI 退出清理](https://github.com/google-gemini/gemini-cli/blob/4f343cabc7b59ab990d7411e920094108524abff/packages/cli/src/utils/cleanup.ts)体现受管生命周期，但平台机制和退出回调均有覆盖限制。[Claude Code 后台会话](https://code.claude.com/docs/en/agent-view#the-supervisor-process)的交接依赖 supervisor／终端宿主，本版不引入该恢复架构。用户已明确选择正常退出回收、重启补清残留。

## 六、应用协议与分页实施

后台列表、读取、停止的应用命令与 Agent 工具委托同一 Runtime 能力；HTTP 路由、远程代理白名单和 TS 投影同步接入。UI 输出按后台标识读取，使用同一字符指针，不开放任意路径。列表行点击打开输出弹窗，复用现有 Dialog；应用用 `background_id` 和 `include_command` 查询对应条目的完整命令，普通分页和 Agent 列表仍返回摘要。弹窗展示命令、目录、来源和输出，输出在界面保留有界的滑动窗口。关闭弹窗或切换会话取消读取，不停止任务；结束事件触发列表移除及弹窗关闭提示，上翻暂停跟随。

输出区域以滚动触发字符分页：首次读取最近一页并定位底部；接近顶部时用当前起点向前读取，前插内容后保持原可见位置，同方向同时只发一个请求。位于底部时续读并跟随，离开底部保持阅读位置，滚回底部恢复跟随；不设置输出翻页按钮或切换最新／历史的入口。失败保留已读内容并在输出区提示，旧指针失效按缺失结果展示；关闭／换任务后丢弃迟到响应。

扩展既有 `ListRuns`、`ListSkills`、`ListChildTasks`、`ListAttachments` 等查询的分页参数和结果；产物沿既有资源来源分页，后台列表使用本 Feature 的查询。不新增 `list_context_items` 或统一列表存储，各区块独立翻页，刷新越界时退到最后有效页。

- 会话快照保留活动 Run、队列、审批和必要摘要，右栏不再同时接收完整数组与分页副本。
- 介入核实优先复用现有介入结果及按 ID 查询；发现缺少定位能力时仅补充必要查询参数，不预设新的通用状态接口。审批、通知、消息定位和执行控制不依赖当前页。
- 技能沿现有发现／激活规则排序后分页；完整模型装配和设置目录保持原有范围，传输分页不宣称减少目录发现扫描。

右栏请求统一传 `page.offset` 和 `page.limit`，响应给出实际偏移、页长和总数。运行记录读取可靠 Run 目录摘要，介入核实用 `ListRuns.input_id` 精确回查。子任务支持全会话分页，按父 Run 的查询继续可用。正文页只包含该页父 Run 的子任务，每条用户消息携带本条附件摘要。附件预览菜单随入口提供当前右栏页或该条消息内的附件。产物通过 `ListArtifacts` 从现有声明净状态取页。

分页在[开发计划](开发计划.md#二里程碑总览)中单列实施里程碑，覆盖页外消费者回归。

## 七、默认值、兼容与验证

以下参数随实施方案一并确认：

| 项目 | 取值与确认状态 |
| --- | --- |
| 首次等待 | 默认 1,000 ms，上限 10,000 ms；0 表示交接后立即返回。 |
| 输出读取／启动预览 | 默认 2,000 字符；单次读取上限 8,000 字符，启动预览最多 2,000 字符。 |
| 单运行滚动日志 | 磁盘上限 100 MiB。超限时分批淘汰最旧内容，保留约 75 MiB 后继续追加。2026-11-18 用户明确调整。 |
| 用户 Runtime 条目数 | 活动最多 16；满额拒绝启动，结束后立即移除。 |
| 后台列表界面分页 | 每页 5 条，随本次交互确认。 |
| 其余列表／工具分页与摘要 | 默认 10、最大 50 条；命令摘要最多 256 字符。 |

`managed` 默认语义保持。M1 新调用提供 `managed`／`background`，历史 `detached` JSON 保持可读，不静默映射或重放。M3 分页变更与应用协议最低兼容版本 0.33.2 同版交付，0.33.1 客户端连接新版 Host 将收到版本不兼容。F01 不新增数据库迁移；回退前停止后台运行，不重写历史结果。

验证聚焦：交接／取消及身份落盘失败；应用外终止（含 Agent 执行 `kill`）后无需查询即自动移除条目、释放活动名额和立即回收日志，以及与停止请求并发时只收尾一次；正常进程组停止与异常重启的主 PID 补清；PID 复用、名称变化及查询失败；Unicode、长单行、滚动缺失、重复读取／末尾续读及回收竞态；子任务禁用与越权；输出弹窗关闭不停止进程、结束后自动关闭，以及页外交互和断线重连。平台清理分别在 macOS／Windows 及支持的 Linux Host 验证，产品集成使用新建 `.runtime-test/` 隔离环境。

实施步骤见[开发计划](开发计划.md)，交互沿[功能设计](功能设计.md)。
