## M5 实际结果

- 状态：✅ 已完成（2026-08-03 用户确认）
- 产出：
  - `memory-demo` 私有新增 `atomic_json`、`DemoPinnedMemoryStore`、`DemoRecallSource`、
    Session 文件和 `DemoJournal`；没有向产品 crate 或公共协议导出这些类型。
  - 原子 JSON 更新在目标同目录完成临时文件 write、flush、`sync_all` 和 persist；Store 与
    Journal 都先修改副本，持久化成功后才替换进程内状态。
  - Pinned Store 使用版本、单调 `next_id` 和稳定 `pinned_0000000001` ID；构造时拒绝损坏
    JSON、错误版本、重复/非法 ID、错误序号和超限条目，删除后不回收序号。
  - Pinned 修改由单个 Tokio Mutex 串行；取消只在副作用开始前受理，原子写一旦开始便收敛
    到确定结果，避免文件与内存状态分叉。
  - Demo RecallSource 每次调用重新读取版本化 JSON，按去重后的 Unicode 空白 term 匹配
    content、reference 和 attributes，并按命中数降序、reference 升序稳定返回。
  - 新 Session 读取最新 Store 并冻结最终 `SystemPromptSnapshot`；恢复、branch 和
    continuation 只复制 Session 成品，不读取 Store 重建 Prompt。
  - Demo Journal 在工具副作用前原子保存 pending Assistant Tool Call；完整且有序的 Tool
    Result 批次提交成功后，才将配对消息投影进 `ConversationSnapshot`。

## 当前讨论结论

- Pinned Memory 作为固定 System Prompt Part；Store 持久化最新状态，会话保存冻结快照。
- 置顶工具支持添加、修改、取消置顶和查看；修改不刷新当前会话，查看只返回最新 Store。
- 置顶记忆保留稳定标识、开放归类、正文和字符串/数字扩展属性。
- 新建会话使用结构化输入生成快照；恢复、继续、压缩续接和分支使用原会话 Prompt 状态。
- 最终快照只保存精确渲染文本；`instructions` 与 Pinned Memory 统一视为会话冻结数据。
- Memory Recall 只通过普通 `recall_memory` 工具进入 Core；RecallSource 表示数据源适配器。
- Source 可见性由 System Prompt 或 Skill 决定，多来源协调与降级留在工具背后的实现。
- 自动观察、自动提炼、后台整合、自动淘汰和自动写入 Pinned Memory 均不进入本版本。
- 正式 Runtime、Protocol 和桌面应用不在本版本改动范围，可建立独立 Memory Demo。
- [`功能设计`](功能设计.md)已确认且不存在开放问题。
- [`技术方案`](技术方案.md)已确认。
- [`开发计划`](开发计划.md)已确认；M0–M7 与版本验收均已确认。
- 开发阶段每个里程碑结束后只提供关键 Review 点；没有重要判断项时直接说明。
