## 准备依赖与配置

Chrome 使用本机已有安装。将 MCP 安装到一个长期保留的依赖目录，例如自行选定的 `browser-mcp/deps`：

```sh
npm install --prefix /ABSOLUTE/PATH/TO/deps @playwright/mcp@0.0.80 --ignore-scripts --no-audit --no-fund --registry=https://registry.npmjs.org
command -v node
```

[配置样例](browser-validation/mcp.example.json)包含两个普通 MCP Server。
替换全部 `/ABSOLUTE/PATH/TO/...` 为本机绝对路径，再经“设置 → MCP”导入所需条目：

- `command` 填上面查到的 Node 可执行文件。使用 nvm 时，Node 升级后需核对该路径。
- `cli.js` 指向上述固定版本安装目录。
- 专用模式的 `--user-data-dir` 使用独立、可写且长期保留的目录，不能填日常 Chrome 的数据目录。
- `--output-dir` 用来保存 MCP 快照和截图；与浏览器登录数据目录分开。
- 样例保留实测的专用 15 秒、当前 20 秒工具超时。慢网站或人工连接确认可能超过此值，届时按需调大
  `toolTimeoutMs`；本轮没有验证所有网站和长时间连接等待。

2026-09-04 已将固定版本依赖安装到 `~/.ez-assistant/mcp-packages/playwright-mcp-0.0.80`，并把
“浏览器 · 专用”和“浏览器 · 当前”增量导入真实 `~/.ez-assistant/mcp.json`。原有 Blender、
Microsoft Learn 和 Pencil 配置完整保留；全局 npm registry 与项目依赖没有修改。当前使用的绝对
Node 和 CLI 路径已写入配置。若以后删除或移动该 Node 版本及包目录，需要同步更新 MCP 配置。

接入时已在独立的“浏览器 MCP 接入验证”会话完成 `/mcp refresh`，五个 Server 全部刷新成功。
后续配置变更仍执行现有 `/mcp refresh`。显示“已连接”或测试连接成功，表示 MCP 握手和目录发现成功；
浏览器通常到首次网页工具调用时才连接，不能据此认定扩展已安装或目标页面可控。

## 专用浏览器操作

1. 在输入框通过 `/mcp` 选择“浏览器 · 专用”，描述网页任务。
2. 首次实际调用会打开独立 Chrome 窗口。需要登录时，在这个窗口内手动登录。
3. Agent 导航后调用 `browser_snapshot` 获取页面结构，再使用其中的 `target` 操作。
4. 提交后重新观察页面确认结果；不因等待或网络异常自动重试提交。
5. 后续使用同一个数据目录可保留尚未过期的站点登录状态。实测重新启动后测试身份保留，未保存
   表单恢复默认值；这不代表所有网站永久免登录或标签自动恢复。

需要截图回传给模型及 Runtime 时，使用 `browser_take_screenshot({"scale":"css"})`，**不要传
`filename`**。0.0.80 中传文件名会只返回保存链接，省略文件名才返回 MCP image 内容。
`--image-responses allow` 不会改变这个条件。纯文本模型可使用 `--image-responses omit`，依赖
结构化页面内容；截图的现有主模型图片投影必须可用，不能假设 MCP 会自动调用辅助识图模型。

导航等动作在 0.0.80 中默认返回快照文件链接；显式 `browser_snapshot({})` 才直接返回 YAML。
切换标签后的结果也不保证自带页面结构，应重新读取快照，避免使用上一个页面的元素引用。
这些都是已固定版本的实际行为，当前无需为此修改产品 MCP 代码。

## 当前 Chrome 页面

Chrome 安装与 Playwright Extension 安装是两个条件。扩展安装后，Playwright MCP 曾因 macOS 拒绝
Runtime 读取 `~/Library/Application Support/Google/Chrome` 而误报“Extension not found”。固定版本会
在读取 Profile 成功后才使用 token，因此 token 不能解决目录扫描阶段的 `EPERM`。

本机 `browser_current` 现已增加 `--executable-path` 和 Chrome 绝对路径，使 MCP 跳过受保护的
Profile 扫描，直接打开扩展连接页；刷新后 `browser_tabs(list)` 成功返回 1 个标签，验证过程未记录
标签标题或 URL。修复证据见 [当前浏览器连接结果](browser-validation/current-browser-fix-results.json)。

使用“浏览器 · 当前”并按扩展界面确认连接、选择已有页面。先核对页面标题、地址和
预填内容，再继续操作。基本扩展连接已经实测；仍需用有预填内容的既有页面验证状态连续性，不能用另开同一 URL 代替。
本机配置保留扩展产生的 token；配置样例不包含任何真实 token。

## 停止与使用约定

- 同一个浏览器 Server/目标一次交给一个会话使用。现有 MCP 连接共享，单次工具串行不等于多步
  网页任务隔离；当前没有浏览器租约或跨会话调度机制。
- 要手动操作，先停止 Agent 并确认动作停止。停止不能撤销已经发生的提交。
- `browser_close` 和关闭本轮专用 MCP 进程后，测试专用窗口已退出，数据目录保留。
  活动浏览器调用期间取消、超时、刷新，以及扩展模式断开的具体页面影响仍待补验；通用 MCP
  故障回归通过不替代这部分实测。
- 遇到超时或连接中断，先确认页面是否已发生变化，再决定继续或刷新，避免重复提交。
- 右侧资源栏、内嵌浏览器和整个桌面 Computer Use 不属于本版使用路径。
