# v0.23.1 版本总结

## 版本结论

`v0.23.1` 用于验证通过现有 MCP 操作本地 Chrome，并修复验证中发现的 Runtime 恢复缺陷。
用户于 2026-09-04 明确本版本不发布，随后进入 `v0.24.0` 并要求补齐归档。由于浏览器与原生
Desktop 仍有未完成验收项，本版本记为 `已暂停`，不创建 `v0.23.1` 标签、安装包或 GitHub Release。

源码修复已经提交到 `bdd34b6962c29723aa97d29cb30c41497754ad91`，由后续发布版本继承。

## 已完成

- 固定并接入 `@playwright/mcp@0.0.80`，配置“浏览器 · 专用”和“浏览器 · 当前”两种普通 MCP Server。
- 专用 Chrome 完成页面导航、结构读取、输入、选择、提交、等待、截图、标签操作和 Profile 登录
  状态保留验证。
- 正式 Runtime 完成配置导入、刷新、审批拒绝与允许、图片物化和真实默认模型网页任务。
- 当前 Chrome 模式定位并绕过 macOS Profile 扫描 `EPERM`；加入显式 Chrome executable path 后，
  `browser_tabs(list)` 成功连接并列出一个标签。
- 修复 compact 后 ToolMessage ID 复用导致 ready pending 无法恢复、Runtime 启动失败的问题：Core
  使用 Exchange Receipt 与批内序号分配 ID，Host 启动时规范化旧 ready pending 且不重放工具。
- 用户确认后完成真实本地数据库恢复；操作前创建并验证 SQLite 与 Conversation 独立备份，目标
  pending 清零、Run 结算为 interrupted，新源码和已安装 Runtime 均成功启动。

## 验证结果

- Agent Testkit 91 项、`assistant-runtime` 313 项、Runtime Host 217 项通过。
- workspace 全量测试、受影响包严格 Clippy、Rustfmt 与 diff 检查通过。
- 通用 MCP 回归为 5 passed / 0 failed / 1 ignored。
- 真实默认模型通过正式 Runtime 发起 7 次浏览器工具调用，正确提交一次并完成截图与最终答复。

详细环境、数据库精确影响、备份位置和证据索引见[验收记录](验收记录.md)。

## 暂停时未完成

- 当前 Chrome 已有页面的预填状态连续性和完整任务。
- 原生 Desktop 的 `/mcp` 入口、审批、截图与详情人工验收。
- 真实浏览器活动调用期间的停止、超时、断线和刷新边界。

如恢复本版本，必须先核对届时的 Chrome、Playwright MCP、扩展和 Runtime 配置版本，再从上述三项
继续；不得复用已经删除的临时模型配置，也不得在未经重新确认和备份时覆盖真实 MCP 配置或数据库。
