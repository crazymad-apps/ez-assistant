   本轮用户已明确授权连续推进到 M2，M0/M1 完成有效验证后可继续，实际验收结果不得预填；
   M2 完成后汇报，M3 及后续仍按逐里程碑规则推进。
3. 本计划维护范围、状态与完成门槛；实际命令、证据、偏差、遗留和用户确认写入
   [本地开发进度](开发进度.md)。验收阶段再汇总到正式验收记录，不提前填写成功结果。
4. 每项开工前核对工作树、读取对应语言规范与模块约束，再检查真实调用链。依赖和共享类型
   随首次使用引入；协议版本在 M0 同步调整，后续新增能力仅在实现可用后声明，不预先报支持。
5. 复用现有 Command／Snapshot／SSE／Upload、配置 CAS、连接代次、文件读取、资源标签和
   PTY 基础。不增加多账号、节点协议、通用平台框架、持久终端或另一份 Runtime 业务状态。
6. 本版调整 Host 与 Desktop 的同版本契约，不新增旧 Desktop 兼容层；保留已有用户配置和
   会话数据。验证使用隔离 Runtime Home 和临时文件，不对用户实际数据库做迁移或批量修改。
7. 产品组成保持桌面级（Desktop + Host + Client）与服务器级（Host + Client）。本版交付包内
   Host 的 Web 能力与组件初始化基础，不另发 Host 产品，不提前实现 v0.25.1 CLI 或服务器级完整装配。
8. 各里程碑同步必要的边界注释和模块文档，区分已经实现的行为与后续设计；保留已有消息选区
   修复及其他任务改动，不主动暂存、提交、推送或发布。

## 四、里程碑明细

### M0：Host 监听与密码认证

前置依赖：本计划已确认，版本已进入 `开发中`。

目标：让现有 Host 在保留本机受信任入口的同时，安全地接受显式开放的外部客户端。

交付范围：

- 按技术方案第四、五节实现访问配置、普通登录、统一 HTTP／HTTPS 监听和脱敏状态查询，
  保留既有单 Runtime、配置 CAS 与本机发现路径。
- 完成设置／改密、启闭监听、配置重新载入及失败收口；空密码不能开放，访问开关不停止 Run；端口／协议变更由显式重启生效。
- 完成普通登录创建、退出、到期和改密撤销，覆盖现有 Command、SSE、上传及字节资源路由。
  后续新增的文件与 PTY 路由在所属里程碑接入同一认证，不另造身份机制。
- 增加包内 Host 的 stdin 初始化能力；同步当前协议版本、必要 DTO、生成类型与现有消费者。

验证入口：`cargo test -p assistant-runtime-host -p assistant-runtime -p assistant-protocol`，
再按第二节完成协议／Runtime 变更门禁；以隔离的正式 Host 进程验证认证、SSE 和外部监听。
覆盖配置缺失、并发保存冲突、端口冲突、错误证书、空密码、错误 Origin／Host、凭据混用、
登录到期／撤销以及长连接终止，HTTPS 使用可信测试链而非跳过校验。

完成判定：本机旧客户端链路在同版调整后正常；外部访问仅在配置与密码均有效时启用；
匿名请求失败、原生 bootstrap 不被外部入口接受；关闭远程访问不破坏本机入口与 Run；唯一监听启动失败不改随机端口。

Review 重点：是否复制业务状态、混用设备接入身份、遗漏字节接口认证；配置写入失败是否仍
开放端口；后台任务是否有明确 owner、取消与回收路径。

### M1：Web 入口与 Host 访问设置

前置依赖：M0 已确认；Host 设置与 Web 登录交互已收口。

目标：用户能够直接打开包内 Host 的正式 Web，并完成设密、开放访问和密码登录。

交付范围：

- 接入同源 Web 登录、Cookie、退出与失效处理，沿用订阅／快照与现有业务客户端；完成普通
  token fragment 的页面接入，为 M2 的 Desktop 快捷图标提供相同登录入口。
- 在既有设置中实现当前 Host 的访问表单，包括密码、访问开关、统一端口、可选域名及 HTTPS 证书路径。
  本机 Desktop 可完成首次设密，匿名 Web 无改密入口。
- 同一前端内嵌 Host，调整前端、Host、sidecar、Tauri 与 E2E 的构建顺序；保留开发态缺少
  页面时的明确响应，正式构建缺少页面或版本不符必须失败。
- 按能力加载原生桥，完成 Web 基础导航与桌面专属操作裁剪；后续文件／终端适配仍按 M3/M4
  验收，不能以本里程碑登录成功宣称全部 Web 兼容完成。

验证入口：Host 登录／静态路由集成测试，`npm --prefix apps/desktop run build`、
`npm --prefix apps/desktop run prepare:sidecar` 与新增 Web 登录定向 E2E；按第二节补齐
实际改动的门禁。关闭 Vite、断开 CDN 后访问正式包内页面，核对 API 路径不会落入 SPA fallback。

完成判定：Desktop 设置设密后，本机浏览器可按所选协议登录两个隔离 Host 进程中的目标 Host；设置反馈
与实际监听一致；退出／改密／到期清除旧业务展示；刷新有效登录可继续查询，未认证仍无业务权限。

Review 重点：页面是否暗中依赖 Tauri／Vite；Cookie、CSP 与资源路由是否按技术方案生效；
关闭远程入口后的反馈是否误报重启或自动重开；打包是否意外产生独立 Host 发行产品。

### M2：Desktop 入口与目标连接

前置依赖：M1 已确认；连接、切换与快捷入口交互已收口。

目标：Desktop 可手动进入本机或远端 Host，并始终将业务及原生请求绑定到所选目标。

交付范围：

- 实现入口页、静默本机启动、真实连接阶段与错误状态；接入已认可的 DOTS 背景及静态降级，
  火箭媒体留到 M5，当前连接就绪可直接进入工作台。
- 完成远端 HTTP／HTTPS、当前目标上下文、原生请求绑定与既有连接代次核对；重连只回到
  当前目标，不重放副作用请求，不静默回退本机。
- 设置内复用连接能力，切换丢弃草稿和临时资源；本机启停／托盘与当前远端连接分别管理。
- 完成可选 Keychain 记住密码，以及连接状态左侧的“打开 Web 端”图标；系统浏览器打开
  当前 Host，使用普通 token 快速登录。

验证入口：连接协调／草稿／原生生命周期定向测试、前端构建和 Tauri 门禁；在正式 WKWebView
连接两个隔离目录的 Host 进程，验证 HTTP／HTTPS、A→B→A 迟到响应、认证失败、断线重连、
Keychain 可用／不可用及系统浏览器快捷登录。记录 Rust 请求与 WebView 请求各自结果。

本轮结果（2026-09-06）：实现与本轮验证完成；用户随后已确认 M2。两个隔离 Host 的正式 Dev WKWebView
HTTP 本机／远端切换、错误密码、系统浏览器快捷登录及远端连接期间本机重启已验证；Keychain
私有测试条目读写／缺失处理通过。HTTPS 已验证 Native 请求默认拒绝不可信证书，以及显式测试 CA
下同一校验路径成功；未修改系统证书信任。正式 WKWebView 的可信 HTTPS 正向链路与真实跨机器
矩阵留到 M6，不以双进程或 Rust 测试替代。Rust 全量 1369 passed / 24 ignored，前端 320 项、
Web E2E 2 项、Desktop E2E 1 项、Clippy、fmt、协议检查及正式 Dev app 构建通过。
详细命令、原生检查与证据位置见[本地开发进度](开发进度.md)。

M2 反馈补充（2026-09-06）：按用户确认将内嵌网页遮挡收敛为浮层显式声明范围与矩形相交，

已验证设置遮罩内截图、上下滚动、关闭后原网页继续操作及窗口缩放恢复。非相交与移动浮层、
迟到截图通过定向回归；Windows／Linux 暂用普通占位，未记为截图实机通过。用户随后已确认 M2。

M2 设置整合：按用户确认将连接、运行时信息与 Host 访问合并为 Runtime 概览和二级页面，
复用现有导航与表单，区分当前 Host 和本机操作；交互口径见[界面交互设计指导](界面交互设计指导.md#四工作台内连接与-host-设置)。

完成判定：入口不自动连接上次目标；一个窗口同时只使用一个 Host；进入后通过设置切换；

Review 重点：是否新增第二份会话状态或全局代次；原生调用是否仍隐式 bootstrap 到本机；
