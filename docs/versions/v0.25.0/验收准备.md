## 环境和启动

- macOS arm64 的正式 Dev Release 包，应用标识 `com.ez-assistant.desktop.dev`；
  Cargo、npm、Tauri 与内嵌页面版本统一为 `0.25.0`。
- 本轮两个独立 Runtime Home：`/tmp/ez-assistant-codicon-ul6rOk/runtime-local` 和
  `/tmp/ez-assistant-codicon-ul6rOk/runtime-remote`。本机端口分别为 `61003`、`61006`，
  为避免干扰日常使用保留夹具端口；产品默认仍为 `7240`。
- Host 显式传 `serve --runtime-home <目录>`；Desktop 显式设置
  `EZ_ASSISTANT_RUNTIME_HOME` 和 `EZ_ASSISTANT_RUNTIME_BIN`，使用 `tauri.dev.conf.json` 构建。
  手工 Dev 验证保留正常 OS `HOME`，否则用户 Shell 配置和终端主题会缺失。
- 自动 E2E 自行创建临时目录、离线 Provider 和 MCP 夹具，退出后清理自有夹具。
  不用自动 E2E 的空用户 HOME 启动供用户实测的 Dev 应用。
- 验收启动前核对 Runtime 路径、PID、端口与 UI 诊断页。两目录两进程提供本机联调证据；
  独立机器、系统受信任 HTTPS 与 WKWebView 正向链路的待验范围保持明确。

## 媒体和依赖

火箭来源为用户委托的独立动画任务 `ez-assistant@v0.25.0 火箭动画` 的 v01 序列。
生产接入使用 10 张透明 WebP 图集、120 帧／30 fps／4 秒，压缩素材约 3.2 MiB；
只解码当前和下一张，像素缓存约 60 MiB。入口布局和实际工作台合成，按真实连接就绪启动。
具体导出方式、缓存和失败处理见
[转场说明](../../../apps/desktop/src/features/runtime-access/WorkspaceTransition/README.md)。

Vanta `0.5.24` 和 Three `0.134.0` 的 MIT 声明从已安装的固定版本包复制到
[入口视觉依赖声明](../../../apps/desktop/licenses/entry-visual.txt)，构建为带内容哈希的 HTML 声明，随前端和 Host 的 `assets/` 内嵌。
图集重导出才需要 Pillow，普通构建不增加 Python 依赖，不依赖 CDN 或动画任务的本地服务器。

## M6 按需加载补验

1. 使用包含多页历史会话的 Runtime 启动，入口就绪后首屏有界返回，“加载更多”和标题搜索可找到旧会话；
   主控仍在固定位置，重连保留当前选中的非首页会话。
2. 打开历史会话不自动继续执行。重启前的未决审批直接丢弃，旧 Run／子任务展示中断，Goal 暂停；
   手动继续／重试才能推进，不重放旧工具副作用。
3. 异常会话只影响自身，正常会话与摘要仍可访问。启动不全量清理历史文件；不要为验证删除或修复生产数据。
4. 最新包替换后复核实际启动体验；自动化与隔离证据见验收记录。单个目标会话内部 Input／Run 整组加载
   的范围保留，不将启动优化表述为所有详情都已分页。
