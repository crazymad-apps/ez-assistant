## 二、背景与目标

### 2.1 当前基础

正式产品已经采用独立 Runtime Host 和 Desktop 客户端。现有 Host 绑定动态 loopback 端口，
通过本机私有发现文件与进程 Bearer Token 接入；业务使用 HTTP Command、Snapshot、SSE 和
Streaming Upload。Desktop 的资源功能同时包含 Host 资源接口与 Tauri 原生实现。

设计阶段只读核查入口：

| 现状 | 代码依据 | 对设计的影响 |
| --- | --- | --- |
| 本机监听与发现 | [endpoint.rs](../../../apps/runtime-host/src/endpoint.rs) | 在既有 Host 上增加非本机访问配置，不新建节点网络 |
| Host／Origin／Bearer 校验 | [auth.rs](../../../apps/runtime-host/src/http/auth.rs) | 增加密码登录与适用的身份校验，保留本机原生认证边界 |
| 既有客户端命令与事件 | [RuntimeClient.ts](../../../apps/desktop/src/runtime-client/RuntimeClient.ts) | 复用业务客户端，支持指定目标地址与认证方式 |
| Host 会话资源列表与预览 | [resources.rs](../../../apps/runtime-host/src/http/resources.rs) | 复用文件访问基础，补充任意目录选择用途 |
| 工作区选择调用原生 dialog | [workspaceDirectory.ts](../../../apps/desktop/src/native-bridge/workspaceDirectory.ts) | Web／远程 Desktop 使用 Host 目录选择实现 |
| 附件、预览、系统打开依赖 invoke | [nativeResource.ts](../../../apps/desktop/src/native-bridge/nativeResource.ts) | 按入口增加兼容实现，保留可用原生路径 |
| 设计时用户终端依赖 Tauri Channel／invoke | [TerminalSocket.ts](../../../apps/desktop/src/runtime-client/TerminalSocket.ts)（M4 替代实现） | PTY 已迁到 Host，复用终端显示与操作体验 |
| Web 桌面偏好读取默认值、保存无操作 | [desktopPreferences.ts](../../../apps/desktop/src/native-bridge/desktopPreferences.ts) | Web 恢复能力需明确，不能宣称原生快照已可直接复用 |

这些是设计依据，不是本版实现或验证完成的证据。

### 2.2 版本目标

**开放当前 Host，让本机／非本机 Desktop 和浏览器都能直接使用同一个 Runtime。**

产品形态按用户最新确认分为两种：桌面级包含 Desktop、Host、Client；服务器级包含 Host、Client。
Host 随应用交付，不是独立分发的产品；独立进程运行不改变这一组成。两种形态的 Host 均提供 Web，
具体产品装配和 Client 交付安排沿对应版本设计，不因本条自动扩大 v0.25.0 的实现范围。

- 每个 Host 都能提供 Web，不因由 Desktop 启动或在服务器上运行而具有不同产品能力。
- Desktop 可通过目标 IP／地址、端口及密码直接连接其他主机上的 Host。
- 本机及其他机器上的浏览器可打开目标 Host 的 Web，并通过密码登录。
- 尽量保留既有 Desktop 实现和共享界面，通过兼容实现处理 Web 与远程资源访问。
- 会话、模型调用、工具执行、配置和文件始终归所连接的 Host／Runtime；客户端只表达意图与展示结果。

## 三、非目标

- 不实现 CLI 客户端，顺延至 `v0.25.1`；本版功能不得依赖未交付的 CLI。
- 不实现 Runtime 节点配对、组网、协调、中继、P2P、iroh 或新的节点外层协议。
  客户端直接访问可达 Host，与后续 Runtime 间通信是不同路径。
- 不实现手机原生 App；手机 App 单独规划，Web 适配不代替原生 App 交付。
- 不引入多账号、多租户、注册或细粒度角色体系。
- 不建设新文件管理系统、目录同步、融合文件空间或通用文件编辑器。
- Web 不提供内嵌浏览器，不以 iframe 等方式重建 Desktop 的原生网页功能。
- 不引入会话迁移、中心调度、持久自动化或终端命令的重启自动重放。
- 不借本版重做现有前端框架、Agent Loop、会话模型或所有原生能力。

## 四、功能范围与使用路径

### 4.1 Host 开放与统一 Web 入口

在当前 Host 服务上支持非 loopback 访问；本机发现与原生自动认证继续可用。本机与非本机共用一个固定端口，默认 `7240`，可修改；不以开放访问为由新建业务服务或复制 Runtime。

Web 页面由目标 Host 提供，复用现有前端业务界面与接口。目标 Host 无论是否伴随 Desktop
运行，都具备相同的 Web 能力。客户端需能直接到达目标服务地址，本版不负责打洞或中继。

设置页面提供访问密码、非本地访问开关、统一服务端口、可选访问域名及当前访问地址。非本地访问默认关闭；
密码为空或尚未设置时，Host 拒绝开启非本地来源访问，前端提示先设置密码。此规则由服务端
实际执行，不能仅禁用开关。

桌面级应用的本机 Desktop 通过原生认证完成首次设置，随后浏览器或远程 Desktop 可以登录。
服务器级应用通过其启动／配置入口初始化包内 Host，底层沿用既有 Host 启动与本机配置能力；
配置方式和监听变更生效方式见技术方案第四节，服务器级用户入口随对应 Client 方案设计；
不依赖 v0.25.1 的新 CLI，不另增忘记密码流程。

### 4.2 单密码访问认证

- 每个 Runtime 设置一个访问密码，不要求用户名和注册；按单所有者使用。
- 设置页面提供访问密码的设置／修改入口，作用于当前连接的 Runtime。本机 Desktop 可通过
  原生自动认证完成首次设置；已登录页面可进行密码管理。不向未认证 Web 开放首次设密权限，
  空密码也不构成本机 Web 免登录的例外。
- 所有 Web 入口均要求登录，包括 localhost 与同源页面。只有必要的登录页面／静态资源和
  登录相关公开接口可未登录访问，业务数据、文件、上传和终端都需要有效认证。
- 本机受信任 Desktop 继续自动认证；远程 Desktop 使用目标地址与密码认证，不能复用或分发
  本机 bootstrap 密钥。仅因请求最后一跳来自 loopback 也不能自动获得原生权限。
- 支持退出；密码直接在设置页面修改，不提供“忘记密码”、密码找回或独立重设流程。
  本机 Desktop 通过原生自动认证进入设置，已登录客户端通过现有认证修改；改密立即使普通登录失效。
- 登录后仍执行现有工具权限、Plan／Build 和审批规则。用户选择文件系统目录的权限不等同于
  给 Agent 无条件批准所有文件操作。
- 按用户最新确认，远程 Desktop 与 Web 均允许 HTTP，HTTPS 作为可选方式。HTTP 不需要证书，
  两种方式都需要密码／有效登录态；空密码禁止开放非本地访问的规则保持。
  选择 HTTPS 时正常准备和校验证书；HTTP／HTTPS 的登录、终端与浏览器能力差异见技术方案。

### 4.3 Desktop 直接连接 Host

#### 入口页与加载状态

Desktop 增加入口页，兼作启动和连接过程的加载页面，可选择本机或其他 Runtime。
入口页属于客户端，不承载 Runtime 组网管理。

- 提供“本机 Runtime”和“其他 Runtime”两种连接入口。本机使用既有发现／启动及原生自动认证；
  其他 Runtime 使用目标 Host 地址、必要端口和密码直接连接。
- 启动初始化、本机 Runtime 准备、远程连接与认证、初始数据加载的状态在同一入口页承载，
  成功取得目标初始状态后进入主界面，避免展示未连接或混入旧目标数据的工作台。
- 连接失败在入口页展示原因，允许重试或重新选择目标；不静默改连本机。
- 启动时不自动连接上次目标，由用户在入口页选择本机或其他 Runtime。进入主界面后不提供
  返回入口页的导航；设置页提供同等的 Runtime 选择与连接能力，用于切换目标。
- Desktop 进入入口页时静默启动本机 Runtime；已有本机实例时沿用既有发现机制，不重复启动。
  本机启动不等于自动选中或连接本机工作台，也不阻塞用户选择其他 Runtime。
- Desktop 同时只连接一个 Host，不支持同时打开多个 Host；不设计独立“取消连接”动作，
  仅通过选择／切换目标表达连接意图。
- Web 继续使用所访问 Host 的密码登录入口，不照搬 Desktop 的本机 Runtime 启动选择。

#### 连接后的工作台

连接成功后，既有会话列表、工作区、业务设置、输入、输出、审批、停止等作用于目标 Host；
界面显示当前连接目标，桌面原生设置仍属于客户端，避免混淆执行位置。

连接切换后，旧连接事件、文件响应和上传结果不得进入新目标的视图。客户端断开或切换不取消
原 Host 的 Run，不静默把失败的远程操作改在本机执行。本机 Runtime 的启停与当前连接目标
必须区分，不能将桌面退出流程误用为远程 Host 停止操作。

设置中将连接、运行时信息和访问配置归入同一个 Runtime 入口。概览显示当前连接，分别进入
切换 Runtime、访问设置、状态与诊断、本机与客户端二级页。访问设置与状态诊断明确当前目标，
本机与客户端页仅作用于这台电脑；Web 不显示切换和本机专属页面。
切换页与入口页复用连接能力，可选择本机或输入其他 Host 地址与密码，成功后回新目标概览，失败留在连接页。
切换不并行保留多个活动 Host 工作台，也不停止原 Host 的后台 Run。macOS 提供可选的记住密码，
通过 Keychain 保存对应目标的密码，仍由用户手动连接，不自动连接上次目标。
切换 Host 时直接丢弃当前未发送草稿，不增加保存或确认流程；同时释放草稿关联的客户端临时
附件和预览资源，不删除已发送消息或可靠会话数据。旧目标迟到的响应不得恢复已丢弃草稿。
本版不增加节点身份和发现网络。

#### 打开 Web 端快捷入口

在 Desktop 顶部标题栏右上角、运行时连接状态标识左侧增加“打开 Web 端”图标按钮。
该入口属于应用标题栏，不放到会话工具栏或资源栏内。

- 点击使用客户端系统默认浏览器打开当前所连接 Host 的 Web 页面；本机连接打开本机 Host，
  远程连接打开对应远程 Host，不固定指向 localhost，也不打开应用内嵌浏览器。
- 使用紧凑图标，提供“打开 Web 端”悬浮提示和可访问名称；具体图标与间距在交互指导中明确。
- 链接支持携带 token 快速登录：系统浏览器打开当前 Host 的 Web，Host 校验 token 后登录，
  无需再次输入密码；机制保持简单。
- 快捷登录使用普通登录 token，与密码登录共用认证机制；不增加一次性票据或刷新体系。
  使用范围与有效性见技术方案第五节，本机原生 bootstrap 凭据不放入链接或用于远程访问。
- 页面处理 token 后清除地址中的 token，日志不记录 token；无效时回到正常密码登录。
  普通 Web 访问仍需认证，快速登录不是免认证入口。
- 无可用 Web 地址时的禁用提示、系统浏览器打开失败的反馈归交互指导明确；不自动开启远程访问。
- Web 页面自身隐藏这个 Desktop 快捷入口。

### 4.4 Web 兼容范围

Web 复用现有会话、工作区与设置能力；不是仅提供发送框的另一个简化聊天产品。按客户端能力
选择兼容实现，隐藏不适用的原生入口；不让共享前端启动依赖 Tauri 可用。

| 能力 | 本机 Desktop | 远程 Desktop | Web |
| --- | --- | --- | --- |
| 会话、输入、审批、停止与业务设置 | 复用现有界面 | 同界面操作远端 Host | 复用同界面与业务接口 |
| 客户端文件选择／上传 | 保留原生选择 | 原生选择客户端文件，上传到目标 Host | 使用浏览器 File 选择与上传，不读取客户端物理路径 |
| 图片粘贴、上传前预览 | 保留既有实现 | 原生资源属于客户端，发送至目标 Host | 使用浏览器能力与临时对象，兼容既有附件体验 |
| 工作区目录选择 | 可保留适用的原生选择方式 | 通过目标 Host 目录选择 | 通过目标 Host 目录选择 |
| 工作区浏览、文件预览 | 保留适用实现、复用查看组件 | 从目标 Host 获取内容 | 从目标 Host 获取内容，复用查看组件 |
| 用户终端 | 连接本机 Host 的 PTY | 连接远端 Host 的 PTY | 连接页面所属 Host 的 PTY |
| 内嵌浏览器 | 保留客户端原生 WebView | 保留客户端原生 WebView，不代表远端浏览器 | 隐藏入口和不可用标签 |
| 系统打开／Finder | 资源确在客户端本机时保留 | 远端资源不交给本机路径解释 | 隐藏原生操作，提供适用的预览／下载 |
| 托盘、窗口、桌面专属设置 | 保留 | 保留客户端职责 | 隐藏 |

上传兼容须覆盖新会话首次物化、已有会话附件、取消、失败重试和粘贴图片，不仅覆盖文件选择
按钮。继续使用 Streaming Upload 和现有业务契约，不把客户端路径或文件字节塞进普通命令。
浏览器不能恢复的本地文件选择不得伪装成仍可上传，暂存对象与临时 URL 及时释放。

### 4.5 Host 文件系统：共享基础，按用途提供接口

Host 提供本机文件系统的目录结构，使 Web／远程 Desktop 能自由浏览并选择工作区。不是只
列出已登记工作区，也不要求先配置导出根。任意目录的实际边界为 Host 进程用户可访问的目录。

| 用途 | 可见范围与行为 |
| --- | --- |
| 工作区目录选择 | 从 Host 文件系统根或便捷起点逐级浏览，选择任意可访问目录；不受已有工作区限制 |
| 工作区／会话资源浏览 | 沿用工作区和会话冻结目录的归属规则，浏览相应文件与目录 |
| 文件预览 | 通过 Host 读取目标内容，供文本／代码、Markdown、图片和 PDF 查看组件展示 |

目录读取、路径处理、文件读取、错误与资源限制共用基础实现，接口仅按用途区分。目录选择
不能直接受限于会话资源根；反过来也不能为支持任意目录选择而取消原会话资源接口的范围约束。

用户可返回上级、查看当前位置并确认选择；无权限、目录消失或非目录返回可理解的反馈。
最终选择由 Host 核验，客户端路径字符串不作为可访问事实。目录映射是按请求浏览文件系统，
不表示把整个磁盘作为未认证静态网站公开，也不需要预扫描或复制全盘。

Assistant 文件链接、相对资源引用及下载须按当前 Host 解释，远端路径不落到客户端本机读取。
保留既有预览大小／类型边界；符号链接、隐藏目录、大目录及读取限制见技术方案第七节。

### 4.6 用户终端迁移

用户终端的 PTY、进程与输入输出承载迁至 Host，Desktop／Web 复用现有 xterm 显示和操作体验。
终端在目标 Host 的工作目录启动，保持用户终端与 Agent Shell 分开；此次迁移不赋予 Agent
控制用户终端的能力。

必须覆盖创建、输入、调整尺寸、流式输出、退出反馈、显式关闭、资源回收和背压。终端故障
不应停止 Agent Run 或破坏会话。禁止在重连或重启时自动重放先前输入的 Shell 命令。

刷新 Web 页面直接结束该页面所属的用户终端及 PTY，刷新后不恢复旧终端或
自动重建 Shell；需要使用时重新打开终端。此操作不影响其他客户端的终端和 Runtime 的 Agent Run。
页面刷新后的终端清理由 Host 保证收口，按技术方案第八节执行，不能仅依赖页面卸载通知成功。

关闭终端标签结束所属 PTY，Host 重启不恢复旧进程。终端仅按所属客户端／页面管理，不提供
跨客户端接管或无限离线保活，不沿用 Desktop 退出时清理整个 Host 所有终端的全局动作。
普通断线或主动退出均回收所属 PTY，不提供断线恢复；网络异常由 Host 有界检测与回收。

### 4.7 Web 查看状态与临时资源

Web 在本客户端保存轻量布局和资源标签描述，按 Host 与会话隔离，不同步不同客户端的个人标签。
刷新后从 Host 重新获取文件内容，不保存文件正文、终端输出或恢复旧终端。浏览器存储不可用时
使用默认布局和当前页面内状态，正常提供功能。

浏览器选中的未上传文件不跨刷新持久化；刷新后需要重新选择，不能保留失效的可上传标签。
未发送文字继续按既有草稿机制处理，本版不新增跨刷新持久化或跨客户端同步；切换 Host 时直接
丢弃未发送草稿。丢弃、关闭页面或资源失效时释放客户端临时对象，不删除已可靠提交的数据。

### 4.8 典型使用路径

1. 用户打开 Desktop，入口页静默启动本机 Runtime；用户选择本机，连接就绪后进入主界面，
   在设置中配置密码并按需开启非本地访问。
2. 本机 Desktop 继续使用；浏览器打开该 Host 的 Web 后输入密码登录，也可从标题栏快捷入口
   通过 token 快速登录。
3. 另一台电脑的浏览器打开同一 Host 地址，或在 Desktop 入口页选择其他 Runtime 并输入该地址与密码，进入同一 Runtime。
4. 用户通过 Host 目录选择器选定 Host 上尚未登记的目录，创建工作区与会话。
5. 从客户端选择文件上传，在 Host 上运行任务，查看文件产物，并打开 Host 用户终端。
6. 其他已登录客户端通过既有快照和事件看到会话变化；审批／停止以 Runtime 实际结果为准。
7. Desktop 通过设置切换 Host，丢弃未发送草稿；原 Host 的 Agent 任务继续。Web 刷新后重新
   查询原会话及文件，所属终端退出，不恢复旧 Shell。

## 五、职责与契约影响

- Runtime 仍持有会话、Run、配置和业务权威状态，Host 承载接入、认证适配、文件 I/O 与终端进程
  管理；Host 持有访问配置与登录状态，不复制到 UI。
- Desktop／Web 共享业务组件，原生与浏览器能力在实际调用边界适配；先复用现有封装，不提前
  建设通用平台插件框架或重写所有 native bridge。
- assistant-protocol 保持轻量，现有业务 DTO 与传输基线保留；认证、目录选择和终端所需新增
  接口按技术方案确定的最小增量调整。不将“保留基线”误解为禁止必要接口增量。
- 文件／PTY 的基础机制不进入 agent-core，不改变 Agent 工具 SPI 的依赖方向。
- 客户端查看偏好与业务状态分开；缓存按 Host 与会话隔离，任何凭据不进入日志或普通查看快照；
  打开 Web 快捷入口通过链接 fragment 传递普通登录 token，页面处理后清除，凭据边界见技术方案第五节。
- Host 与 Desktop 随同一版本发布，用户明确不要求新 Host 兼容旧 Desktop。接口与调用方可在
  本版同步调整，不为旧 Desktop 建立版本分支、旧接口转发或双协议兼容层。该原则不等于允许
  丢弃已有用户配置和会话数据，保留与调整范围见技术方案第十节，并在实现时验证。
- 本版不引入 Runtime 间外层传输；后续中继与业务解耦的原则继续有效，但不成为本版实现依赖。

现行模块文档中的“浏览器未来开放”“PTY 在 Desktop”“退出清理终端”等描述是已发布基线。
本版已确认的演进方向同步记录于[重要决策](../../重要决策与变更记录.md)；对应模块约束在技术方案／
实现阶段同步修订，不能将设计定稿当作新行为已落地的证据。

## 六、关键取舍

1. 在现有 Host 上增量开放，复用 HTTP／SSE／Upload，保持直连客户端与 Runtime 组网两个范围。
2. Web 增加兼容实现，Desktop 可用实现继续保留；终端属于明确的所有权迁移例外。
3. 上传文件来自客户端，工作区与运行文件属于 Host；使用同一资源查看组件不混淆路径归属。
4. 任意目录选择、工作区浏览、文件预览共享文件访问基础，接口目的不同不构成三套实现。
5. Web 隐藏内嵌浏览器和无意义的原生入口，不另建受限的网页嵌入替代品。
6. 只设访问密码，保留原生自动认证，不提前引入账号系统、联合身份或细粒度角色。

## 八、方案衔接与验证重点

以下技术选择已收口，具体接口与参数统一维护在技术方案。交互指导继续细化页面反馈，
实现阶段按验收条目核对真实行为，不把验证工作误列为尚未决定的功能范围。

| 事项 | 已定稿方案 | 实施验证重点 |
| --- | --- | --- |
| Host 配置生效 | 沿用配置文件与 CAS；密码即时生效；同一端口默认 7240；访问开关即时生效，端口／协议／证书关闭远程后修改并显式重启；服务器级可复用包内 Host 的 stdin 初始化 | 空密码禁止开放；占用不自动换端口；启动失败通过本机配置修正；切换不停止 Run。服务器级用户入口随对应版本交付 |
| 登录与连接体验 | 单 Host；本机静默启动、手动选择；设置切换并丢弃草稿；macOS 可选 Keychain 记住密码 | 加载／失败／切换反馈，目标及凭据隔离，旧响应不污染新目标 |
| HTTP／HTTPS 与登录态 | 远程 HTTP 正式支持，HTTPS 可选；普通 token 与 Web Cookie，fragment 快捷登录；有效期与撤销规则见技术方案第五节 | 两种协议真实跨机访问，证书信任、Cookie／WS、退出／到期／改密失效 |
| 文件与终端 | 共用 Host 文件基础，任意目录与会话范围分别校验；一个 socket 一个 PTY，断线回收、刷新不恢复 | 符号链接／无权限／大目录、跨机上传、流控及有界回收；不影响其他终端或 Agent Run |
| 协议与打包 | 同一前端内嵌 Host，随桌面级／服务器级应用交付；Host／Desktop 同版本调整，保留业务基线及用户数据 | 全部调用方、正式包内页面、CSP／Origin、偏好隔离与既有配置／持久数据，不增加旧客户端兼容层 |

主要风险及验证重点：

- “IP + 密码”必须覆盖真实跨机器 HTTP；选择 HTTPS 时同时验证正常证书信任路径，不能只在
  开发服务器或关闭证书校验的环境证明可用。HTTP 浏览器能力限制需兼容处理。
- 文件目录来自 Host，上传来源来自客户端；复用界面时必须覆盖路径归属和迟到响应隔离。
- 页面卸载通知不保证送达，终端必须由 Host 有界回收；断线后不恢复旧终端。
- 迁移 PTY 不能让客户端退出停止 Agent Run，也不能回收其他客户端的终端。
- 本版不兼容旧 Desktop，但不因此丢弃已有用户配置或会话数据；确有迁移影响时单独说明。
- 按现有受支持平台确定验收环境；新增 Web 要覆盖正式打包页面和真实跨机器访问，不能以独立
  验证页替代正式产品。平台与浏览器矩阵见技术方案第十一节。

## 十、M5 补充：会话刷新指令（2026-09-07）

用户确认指令命名为 `/mcp refresh` 和 `/skill refresh`。普通会话与主控会话均可使用；
刷新不需要选择模型、不创建 Agent Run。MCP 保留可选服务名，Skill 显式重读当前技能列表。

- `/skill` 每次呼出与右侧上下文技能栏均读取当前工作区和用户 Root 的最新列表，应用当前名称开关；无需先 refresh。`/mcp` 每次呼出读取当前 Runtime 服务列表。
- 会话不保存技能目录快照；新激活读取当前定义。系统提示词中的已冻结文本不随列表、开关或 refresh 改变。扫描失败显示不可用，不展示过期目录。
- `/skill refresh` 提交本次扫描结果，当前可用目录进入该控制结果的上下文，供后续模型工作参考。
- 已接受输入、历史技能正文和正在执行的 Run 不被改写；指令沿用 Session 控制队列，在可执行边界处理。
- 刷新结果在对话中独立展示，Desktop/Web 行为一致。刷新不增加权限，也不绕过现有登录与工具审批。

refresh 沿用已约定机制：插入一条 `user` role 消息，不触发 Run，不修改冻结系统提示词。普通目录查询不插入消息。


## 十一、M6 补充：按需加载与手动启动（2026-09-07）

用户明确：Runtime 启动不恢复执行历史任务，全部由用户手动启动。该约定覆盖进程重启、
客户端重连、打开会话和历史数据加载；这些动作都不构成继续执行的授权。

- Host 启动只完成提供服务必需的全局初始化，不全量装入历史 Session 的 Input、Run、正文、
  子任务及技能激活账本，也不扫描全部历史正文后才进入就绪状态。
- 会话列表按需分页查询摘要；打开会话按需读取该会话，消息与历史执行记录分页读取。
  UI 列表和应用快照不能通过逐个加载所有会话详情来实现摘要查询。
- 上次未开始的输入、未完成的任务、Goal 与会话控制指令等待用户显式操作，不自动出队、
  不自动重试、不重新执行工具，不因主控代理关系生成新的恢复报告任务。
- 标题等历史旁路模型任务也不在启动时补做。用户本次新建／执行任务触发的正常自动标题、
  当前已运行任务的内部步骤与 Agent Loop 不受影响；不将手动启动误解为每个工具都要手动启动。
- 历史运行状态不得在新进程中显示为仍在实际执行；显示中断／待用户处理，并保留原事实。
  “恢复存储完整性”不等于“恢复执行”，任何历史工具副作用都不重放。
- 会话局部加载或存储恢复失败，只使该会话不可执行并展示原因，其他会话继续可用。
  不删除异常记录，不静默跳过正文内容，不伪造空会话或成功结果。
- 历史图片等资源清理移出启动就绪路径，独立按需执行；引用无法完整确认时保留文件。

此项已完成实现、回归和安装包交付，并随本版获用户验收确认；具体边界见技术方案同名补充及验收记录。
