### M4：Provider 方言、Opaque state 与压缩

- 状态：✅ 已确认（2026-08-20）
- 目标：接入 DeepSeek/Qwen/Kimi 精确 Responses 方言，使 encrypted reasoning 可按精确路由
  保真续接，同时保持路由隔离、上下文预算和长期压缩能力。
- 实际结果：已加入三家精确 Adapter 与随包目录；DeepSeek 保存绑定 reasoning part 和路由指纹的
  完整 opaque item，Qwen/Kimi 的 null 状态不物化。精确相容状态原样回放，路由切换退化为规范
  ReasoningPart，相容损坏状态 fail-closed；Debug 不暴露 payload。ProviderState 具有单 item/
  Turn 上限并进入保守窗口预算，旧状态不再永久保护上下文 tail。
- 图片结果：Qwen 固定为整批 function output 后一个 wire-only 聚合 User Image；Kimi 固定为
  原生多模态 function output；DeepSeek 不启用图片。
- 实测修正：DeepSeek reasoning 支持通用 content-part 边界；兼容工具 Schema 为无字段 object
  显式补 `properties: {}`，满足 DashScope Responses 校验。
- 验证结果：五个规定离线入口通过；严格 clippy、workspace check、fmt 和 diff 检查通过。
  `v0_17_real_responses` 四项真实 Provider 用例已显式执行并全部通过。
- 续作点：M5 已获准开始。
- 等待/阻塞：无

### M5：工具图片产品投影

- 状态：✅ 已确认（2026-08-20）
- 目标：只在对应主/child 工具详情中展示 `read_image` 的稳定图片，不新增附件、Context
  文件或通用产物语义。
- 实际结果：公共协议新增 `SessionToolImage` 来源；Runtime 只从可靠 Tool Result Image Part
  生成 `tool-image-<call>-<part>` 引用，`read_image` 源路径不再被误投影为普通文件，并显式
  排除 Conversation file references。主会话和 child 使用带 owner 的独立资源路由；Host 每次
  重新校验普通文件、哈希、MIME 和解码限制，在内存生成最长边 320 JPEG，且拒绝 native-path。
  Desktop 复用工具详情显示加载、预览和局部不可用态，会话图片不显示系统打开或目录揭示操作，
  窄窗口布局已收口。
- Review 修正：`inspect_images` 不再只接受附件路径，现与 `read_image` 共用 Session 路径解析和
  文件 Read 权限；多图逐条应用规则并在持久批准时一次 CAS 写入全部 exact Read 规则。辅助视觉
  请求直接瞬时预处理已授权本地图片，不生成附件或 `tool-images/` 副本。`read_image` 已核对原本
  就支持工作区相对路径和绝对路径并使用单路径 `FileAuthorizationFacts::Read`，没有同类缺陷。
- 验证结果：Agent Model 43 项、Agent Tools 55 项、Protocol 32 项、Runtime 159 项、Host 单元
  测试 114 项通过/1 项忽略并通过全部离线集成测试；工具图片正式 Host 用例覆盖主/child owner
  路由、重启恢复、内存缩略图、同图去重、源图消失不回查，以及稳定副本缺失/损坏不可用；辅助
  识图正式 Host 用例覆盖相对/绝对本地路径、多路径审批和持久规则、两张图片实际进入辅助模型且
  不产生图片产物。Desktop Rust 12 项、前端 96 项通过；协议生成检查、前端 lint/build、格式/diff
  和相关 crate 严格 clippy 通过。未执行真实 Provider 测试，因为本次只改 Host 请求前资源准备和
  文件授权，不改变已验证的 Provider wire 编码，且真实测试会产生费用。
- 续作点：M6 已获准开始。
