# v0.17.0 版本总结：工具图片回流与 Responses API

## 一、版本结论

Provider-neutral 工具图片产物、`read_image` 稳定物化、三条图片投影路径，并在保留
Chat Completions 的同时新增独立 `openai_responses` 协议。

## 二、主要交付

1. **工具图片契约**：Tool Result 升级为兼容旧数据的有序 Text/JSON/Image Parts；
   Image Part 只保存 Session 相对引用和实际 MIME，不把 Base64、Data URL 或外部源
   路径写入 Conversation。
2. **`read_image` 与会话存储**：通过标准文件 Read 权限读取单图，安全校验后按
   字节哈希物化到 Session `tool-images/`；重复与并发读取不生成副本，恢复、Fork、
   Runtime Home 整体迁移与 Session 删除具有明确生命周期。
3. **三条图片投影**：Kimi 等已验证路由使用原生多模态 Tool Result；Qwen 等兼容
   方言在完整 Tool Result 批次后生成一个 wire-only 聚合图片输入；文本主模型继续
   通过 `inspect_images` 取得普通持久化 Text Result。
4. **Responses 首版**：新增独立 Protocol、Adapter、Codec、Service 和流状态机，固定
   `store: false`，以本地 Conversation 为唯一历史权威，覆盖文本、图片、function call/output、
   reasoning、usage 和首版终态，不使用远端会话句柄或失败回退。
5. **Provider 方言与 Opaque state**：DeepSeek、Qwen、Kimi 精确路由按真实证据编译；
   DeepSeek 需要的 opaque reasoning 只在相容路由保真回放，Qwen/Kimi 不伪造加密状态；
   旧 ProviderState 可随已结算头部离开活动上下文，不再永久阻断压缩。
6. **产品投影与辅助识图修正**：Desktop 只在对应主/child 工具详情中展示有界预览
   与局部不可用态，不进入附件栏、Context Panel 或通用产物栏。`inspect_images`
   与 `read_image` 统一使用文件读权限，支持已授权的工作区相对路径和绝对路径。
7. **版本与组件收口**：OpenAI-compatible 实现收入 `chat/`、`responses/`、`shared/`
   目录；Rust workspace、npm 和 Tauri 产品版本统一为 `0.17.0`。

## 三、验证摘要

- Rust workspace 格式、全目标全 feature Clippy `-D warnings` 和全量测试通过；
- Desktop 协议生成检查、lint、19 个 Vitest 文件共 96 项测试、生产构建、1 项
  正式 Host Playwright E2E 和 Tauri release `--no-bundle` 构建通过；
- 9 项显式真实 Provider 用例通过：Responses DeepSeek Flash/Pro、Qwen、Kimi，
  Chat `read_image` Qwen/Kimi，以及既有附件/辅助识图基线；
- 正式 Host 隔离用例覆盖旧数据、崩溃恢复、Fork/删除、Runtime Home 迁移、工具图片
  产品路由、opaque 重启回放和普通日志/产品投影隐私边界。

详细命令、环境、未执行项与完成判定见 [验收记录](验收记录.md)。

## 四、偏差、遗留与非目标

- OpenAI Responses 因本项目无可用项目 credential 未执行真实连接；已以官方方言
  fixture 覆盖 wire，且 OpenAI 未进默认启用目录。
- GLM Responses 的当前两个官方路径均返回 404，因此保持未启用。
- Windows Runtime Host、PowerShell 默认 Shell、Windows ARM64 发布、浏览器/CDP/
  computer-use 具体工具、Responses hosted tools 和远端 Conversation 均为非目标。
- Vite 生产构建仅保留既有 chunk-size warning，无已知功能或运行阻断。
