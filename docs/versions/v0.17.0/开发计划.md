- 目标版本：`v0.17.0`
- 状态：已确认（2026-08-19）
- 功能基线：[`v0.17.0 功能设计`](功能设计.md)
- 技术基线：[`v0.17.0 技术方案`](技术方案.md)
- 真实证据：[`v0.17.0 真实模型验证记录`](真实模型验证记录.md)
- 产品基线：[`v0.16.0 版本总结`](../v0.16.0/版本总结.md)
- 架构依据：[`Agent 系统技术架构`](../../modules/agent-system.md)
- 流程依据：[`开发流程规范`](../../specs/开发流程规范.md)

本版只在现有工具详情中增加有界图片预览，不增加新页面、产物栏或附件
管理交互，因此不单独编写界面交互设计指导。计划只维护实施顺序、可确认产出和
验证门禁；类型、wire、路由指纹、原子文件操作和目录结构以已确认技术方案为准。

## 二、台账与实施原则

1. 按 M0—M6 顺序实施。本计划获得确认后只开始 M0；每个里程碑完成实现与
   验证后标记为 `🟨 待确认`，获得用户确认后才进入下一里程碑。
2. 开始 M0 前将 [`版本管理`](../../版本管理.md) 从 `计划中` 更新为 `开发中`；
   计划整体确认不代表授权连续实施后续里程碑。
3. Runtime 仍是 Session、Conversation、Run、模型能力、工具注册、资源路由与
   持久化的唯一权威者；Desktop 只展示投影，Adapter 不读取本地文件或 Session 目录。
4. 结构化文件工具对 `tool-images/` 的写入、编辑和删除保持拒绝；只读权限不宣称
   能限制当前用户权限下的 Shell。
5. 本方案不新增 SQLite 表或列。存储和恢复测试只使用隔离临时 Runtime Home；
   如实现中发现必须做数据库迁移，立即停止扩大改动并重新确认方案。
   不读写用户实际 Runtime Home 中的数据。
6. Tool Result、ProviderState 和 Responses 历史的兼容只通过新老 fixture、临时数据集和
   正式 Host 端到端回证；不就地重写用户旧 Conversation。
7. 真实 Provider 测试默认 `#[ignore]`，只读复用当前本地配置的 credential；不输出
   API Key、完整 response/call ID、reasoning/opaque payload 或私有图片路径。
8. 不在运行时根据 HTTP 状态或自然语言答案切换图片投影、探测协议或修改能力目录。
9. 浏览器、CDP、Playwright 操作工具、computer-use、Responses hosted tools、远程
   Conversation 和单 Session 可恢复归档均不进入本计划。
10. 不主动执行 Git commit/push；保留用户已有改动，每个里程碑开始前重新核对
    工作树与对应 Rust/前端/模块规范。

## 四、里程碑明细

### M0：OpenAI-compatible 目录与命名收口

前置依赖：本开发计划已确认；版本状态已更新为 `开发中`。

目标：在新增 Responses 之前先完成纯结构重构，让两个协议各自有稳定目录，
并保证现有 Chat Completions 行为与原始 wire fixture 不变。

交付范围：

- 将现有 Adapter、Schema、Codec、流组装和 Service 收入 `chat/`，将协议无关且已在
  技术方案确认为双路基础的 credential、endpoint、Transport、SSE frame 与 tool schema
  收入 `shared/`；图片等尚未形成第二调用方的 helper 暂留 `chat/`，到 M3 再按真实复用上提；
- 把 `ProtocolAdapter` / `OpenAiCompatibleService` 更名为
  `ChatProtocolAdapter` / `OpenAiChatCompletionsService`，一次性修改 Runtime Host、demo、
  reliability replay 和测试调用方，不留模糊长期别名；
- 把白盒 Codec 测试收入 `chat/tests/`，crate 根 `tests/` 只通过公共
  Service/Transport 验证，fixture 迁入 `fixtures/chat/`；
- 保持 `lib.rs` 为薄 re-export，限定 `chat -> shared`，不为测试公开内部 Schema/Codec；
- 同步更新 `agent-openai-compatible` 模块约束与 crate 级文档，不改变
  Provider 方言、reasoning、usage、错误、重试和 wire observation 语义。

验证入口：

```bash
cargo test -p agent-openai-compatible
cargo check --workspace --all-targets --all-features
cargo clippy -p agent-openai-compatible --all-targets --all-features -- -D warnings
```

完成判定：仓库内不再使用模糊旧类型名；现有 Chat 请求 fixture、SSE、DeepSeek thinking、
Transport 错误/观测和所有下游 target 编译通过，wire 字节不因目录调整改变。

实施结果（2026-08-19）：Chat 实现、白盒测试与 fixture 已分别迁入 `src/chat/` 和
`fixtures/chat/`；credential、endpoint、Transport、SSE 与工具 Schema 降级器已迁入
`src/shared/`，图片 Data URL 编码仍留在 Chat。公开类型已更名为
`ChatProtocolAdapter`、`OpenAiChatCompletionsService` 和
`OpenAiChatCompletionsServiceError`，全仓调用方已同步。离线测试 110 项通过、1 项真实
DeepSeek smoke 按设计忽略；crate clippy 与全工作区 all-target/all-feature 编译检查通过。
M0 已于 2026-08-20 获得用户确认。

Review 重点：是否把 Chat 私有类型误升为公共 API，`shared/` 是否收入仅有单路调用方的
预抽象，重命名是否遗漏 demo/replay/Host。

### M1：Tool Result 与会话图片存储基础

前置依赖：M0 已确认。

目标：先建立不依赖具体模型协议的规范 Tool Result Image Part 和 Session 私有图片
存储语义，为后续工具与投影提供可恢复事实。

交付范围：

- 将 `ToolResultContent` 升级为非空有序 Text/JSON/Image Parts，引入只接受单层哈希文件名和
  实际 MIME 的 `ToolImageReference`，所有构造与反序列化重走验证；
- 手写 Serde 兼容旧 `Text/Json` 形状，新写入统一使用 Parts；修改现有工具、Core、
  Context、Recorder、Store 和 Adapter 消费方，不就地重写旧 JSONL；
- 从 Session ID 确定性构造与 `attachments/`/`private/` 同级的 `tool-images/`，
  不为可推导路径新增 SQLite 列；
- 实现可取消有上限的普通二进制文件读取、签名/MIME/解码验证、字节哈希、
  同目录临时文件与不覆盖原子提交，并保持已提交文件只读；
- 完成重复/并发物化、崩溃残留扫描、稳定孤儿保守回收、Fork 独立复制、
  Session 删除和结构化文件工具写入拒绝；
- 图片引用不复制外部源路径；源路径仅继续存在于规范 Tool Call 参数与授权审计。

验证入口：

另使用临时 Session 目录覆盖同图串行/并行、不同图、目标损坏、取消、超限、动画、
临时文件、提交后崩溃、Fork 失败回收和删除恢复注入。

完成判定：旧 Conversation 无需人工修改即可读；一个 Session 的同份图片只有一个稳定
文件；成功 Tool Result 不指向半成品；Fork/删除不影响其他 Session；不存在全局缓存、
引用计数或新数据库 schema。

实施结果（2026-08-20）：`ToolResultContent` 已统一为受控的非空有序 Parts，旧 Text/JSON
形状读取后归一化，新写入使用 Parts；Image Part 只保存校验过的单层哈希相对路径与实际

文件、启动 mark-and-sweep、Conversation 不可读时保守保留、主/child 引用扫描、Fork 独立
复制及失败回滚、源 Session 删除后 Fork 资源独立可用、结构化 mutation 拒绝均已落地。

验证结果：规定的七个 crate/Host 测试入口全部通过；M1 相关测试覆盖旧/新 Serde、非法引用、
空 Parts、二进制上限与取消、动画与损坏目标、同图串行/并发去重、临时文件与稳定孤儿恢复、

### M2：`read_image` 与 Chat 图片投影

前置依赖：M1 已确认。

目标：让图片 Chat Completions 模型能通过受控 `read_image` 读取图片，并在方言
不支持图片 Tool Result 时使用用户无感知的批次聚合投影。

交付范围：

- 在 `agent-tools` 实现严格单图 `read_image(path)` 工具壳、Read 授权事实、取消和
  `ParallelEligible`；通过物化端口调用 Host 基础设施，Core 不访问文件系统；
- 将图片预处理的请求期内存键区分为附件资源和 Session Tool Image 资源，
  分别从固定根解析，不改变 Image Part 契约或制造第二份图片；
- 扩展模型能力与目录 schema，在同一次 schema 升级中显式编译 `image_input`、
  Tool Image Projection 和 M3 将使用的 ToolChoice 支持集；
  只在图片输入、Tool Call 与已验证投影同时成立时注册 `read_image`；
- Chat Codec 先完整输出原 Tool Call 顺序的整批 tool messages，再为其中全部图片
  生成至多一条 wire-only user image message；不逐结果穿插、不按完成时间重排；
- 该兼容 user message 不持久化、不分配 MessageId、不进入 Journal/Recall/消息计数/
  Runtime 用户消息事件/UI；重试和恢复只从原 Tool Result 确定性重建；
- Qwen/Kimi Chat 只按真实证据启用聚合投影；DeepSeek 不注册 `read_image`；
  文本主模型的 `inspect_images` 注册、usage 和普通 Text Tool Result 持久化保持不变。

验证入口：

```bash
cargo test -p agent-tools
cargo test -p agent-model
cargo test -p agent-core
cargo test -p agent-openai-compatible
cargo test -p assistant-runtime
cargo test -p assistant-runtime-host
```

固定单调用/双调用、每结果单/多图、一成功一错误、并行执行乱序完成、重试、重启、
历史重入和无权限测试；通过正式 Host 的忽略真实测试分别回证 Qwen/Kimi Chat。

完成判定：Agent 可在受权限的图片 Chat 路由获得规范 Image Part；后续模型看到原顺序
工具文本和图片；用户从产品消息和事件中看不到伪 user message；附件原生视觉与
`inspect_images` 不回归。

实施结果（2026-08-20）：`agent-tools` 已增加严格单路径、Read 授权、可取消且
`ParallelEligible` 的 `read_image`；Host 通过既有 Session 图片物化设施生成唯一稳定
Image Part。模型请求预处理已将附件引用与 Tool Image 引用分为两个内存命名空间，后者
只从当前 Session 的固定 `tool-images/` 根读取，不复制第二份图片。模型目录 schema 已升级，
显式编译 Tool Image Projection 与 ToolChoice 支持集；只有图片输入、Tool Call 和已验证
投影同时成立时才注册工具，Qwen/Kimi Chat 使用聚合投影，DeepSeek 保持禁用。

Chat 编码器按规范 Conversation 中的 Tool 批次工作：先依 call 顺序完整输出全部 tool
messages，再按 result/part 顺序生成至多一条仅存在于当前 wire request 的 user image
envelope；原请求 Conversation 保持不变，错误结果与图片结果不会交错或按完成时间重排。
离线用例覆盖命名空间隔离、单/多 Tool Result、多图与重复图、一成功一错误、禁用投影、
缺少预处理资源、原 Conversation 不变和工具注册边界；正式 Host 新增 Qwen/Kimi 两项
`#[ignore]` 人工真实测试，验证 `read_image` 调用、Session 单份物化和识图结果，但本里程碑
未执行会产生费用的真实请求。

验证结果：`agent-tools` 55 项、`agent-model` 43 项、`agent-core` 38 项、
`agent-openai-compatible` 113 项通过且 1 项忽略、`assistant-runtime` 154 项通过；
Runtime Host 完整测试 120 项通过，10 项真实 Provider 测试按设计忽略。`agent-sdk` 定向回归、
规定范围严格 clippy、全工作区 all-target/all-feature check、fmt 和 diff 检查通过。
M2 已于 2026-08-20 获得用户确认。

Review 重点：工具注册是否过宽，请求期资源来源是否误进持久化，内部 user message 是否
泄漏到产品层，批次是否保持 call/part 顺序，是否存在运行时失败回退。

### M3：Responses 基础协议与独立 Service

前置依赖：M2 已确认。

目标：以独立协议目录和状态机实现 Responses API 首版通用契约，不与 Chat
Schema/Codec 混用，不依赖 Provider 远程会话。

交付范围：

- `ModelProtocol` 增加唯一配置值 `openai_responses`，与
  `openai_chat_completions` 并存；Host 依 Protocol 显式选择 Service，不自动升级、降级或试错；
- 在 `responses/` 实现私有 Schema、编码、解码、流事件状态机和
  `OpenAiResponsesService`，只向下依赖 `shared/`，不引用 `chat/`；
- 请求固定 `store: false`、`stream: true`，从本地 Conversation 完整重建 `input`，
  不发 `previous_response_id`、remote Conversation、background 或 CRUD 字段；
- 映射冻结 `instructions`、用户/助手文本、用户图片、Context Summary、工具定义、
  最小 function call 和 function output，只用规范 `call_id` 恢复工具配对；
- 引入可明确验证的 ToolChoice 支持集，当前 Agent 使用 `Auto`；不把官方全量形状
  无条件下发给未知兼容端点；
- 状态机覆盖 created/queued/in-progress、output item、text/refusal、function arguments、
  reasoning text/summary、usage 与 completed/incomplete/failed/cancelled/error，严格结算唯一终态；
- 实现保守 `openai_compatible` 方言与 OpenAI 官方离线 fixture；未取得本项目真实凭据前
  不把 OpenAI 路线加入默认目录。

验证入口：

```bash
cargo test -p agent-openai-compatible
cargo test -p assistant-runtime
cargo test -p assistant-runtime-host
cargo clippy -p agent-openai-compatible -p assistant-runtime -p assistant-runtime-host \
  --all-targets --all-features -- -D warnings
```

离线 fixture 覆盖完整本地两轮历史、单/双 function call、严格顺序、用户图片、
instructions、不完整 arguments、重复/缺失终态、未知可执行 item 和中途 transport 错误。

完成判定：通用 Responses 路由可从本地历史完成文本/图片/工具轮转；流式请求只有
一个规范终态；`incomplete` 不被误作传输错误；现有 Chat 协议请求字节和行为不变。

实施结果（2026-08-20）：`agent-openai-compatible` 已新增完全独立的 `responses/`，实现
字段私有的官方/保守通用 `ResponsesProtocolAdapter`、请求 Schema/Codec、非流式解码、
item 流状态机和 `OpenAiResponsesService`；只与 Chat 共享 credential、endpoint、Transport、
SSE parser、工具 Schema 降级器和已有双调用方的图片 Data URL helper。请求固定
`store: false`、`stream: true`，从本地 Conversation 编码完整历史，不发送远端会话句柄。

首版编码已覆盖冻结 instructions、Context Summary、用户/助手文本、附件图片、规范 Tool
Call/Result、ToolChoice、generation/reasoning 配置，以及原生 function output content parts 和
批次聚合两种已验证图片投影。流状态机覆盖 message、text/refusal、并行 function arguments、
reasoning summary/text、usage 及 completed/incomplete/failed/cancelled/error；按 output index
稳定完成，缺失终态、终态后数据、未知 item、身份冲突和坏参数均结算为唯一失败终态。

Runtime 已加入唯一精确配置值 `openai_responses` 和协议级保守目录基线；Host 模型工厂按
`ModelProtocol` 穷尽构造 Chat 或 Responses Service，不做请求期回退。正式 Host 离线验收同时
覆盖文本 Run 与完整 function-call → 本地工具 → function-call-output → 最终文本闭环，证明
第二次请求由本地规范 Conversation 重建。M3 未加入 DeepSeek/Qwen/Kimi 精确目录路由，也未
实现 Opaque State；历史 ProviderState 在本阶段建流前 fail-closed，保持 M4 边界。

验证结果：`agent-openai-compatible` 124 项通过、1 项真实 smoke 忽略，其中 Responses 新增
11 项离线契约测试；`assistant-runtime` 155 项通过；Runtime Host 121 项通过、10 项手工/真实
测试忽略。规定范围严格 clippy、全工作区 all-target/all-feature check、fmt 与 diff 检查通过，
未执行产生费用的真实 Provider 请求。M3 已于 2026-08-20 获得用户确认。

Review 重点：两个协议是否偶合为同一 Schema 枚举，本地权威是否被远程 ID 污染，终态、
取消和建流前重试是否重复结算，未知端点 override 是否越过保守基线。

### M4：Provider 方言、Opaque state 与压缩

前置依赖：M3 已确认。

目标：把已有真实证据的 DeepSeek、Qwen 和 Kimi Responses 方言纳入精确能力目录，
并让不透明 reasoning 状态可保真续接但不永久阻塞上下文压缩。

交付范围：

- 实现 DeepSeek Flash/Pro、DashScope Qwen `qwen3.8-max` 与 Kimi `k3` 具名
  `ResponsesProtocolAdapter`，固定 generation、effort、ToolChoice、usage、reasoning 与终态方言；
- Responses 工具图片中，Kimi 使用原生多模态 function output，Qwen 在整批字符串
  function output 后使用一个 wire-only 聚合 user image input，DeepSeek 不启用图片；
- 扩展 `OpaqueProviderState` 的 `related_part_id` 与精确路由指纹，安全实现 Debug、
  单 item/Turn 字节上限与上下文保守字节预算；
- 对 DeepSeek/OpenAI 类非空不透明内容保存完整 reasoning item；与
  `ReasoningPart` 绑定后只发一份 wire item；Qwen/Kimi `null` 不生成空状态；
- 只在 provider + protocol + normalized endpoint + model + state format 完全相容时回放
  opaque payload；不相容时跳过，相容但损坏/失配时 fail-closed；
- 移除 Context Layout 从最早 ProviderState 起保护全部尾段的行为；只保护 system、
  近期/活动 User Turn 和完整 Tool Exchange，压缩成功后旧 opaque state 随 head 离开活动上下文；
- 将真实验证通过的精确路由写入目录；GLM 保持不启用，OpenAI 保持 fixture-only
  直到有本项目真实连接证据。

再显式执行忽略的本地真实模型矩阵，不以 HTTP 200 代替内容断言。

完成判定：DeepSeek 可在本地权威模式下保真续接；Qwen/Kimi 不伪造状态；
三条路由按固定图片投影完成工具批次；切换路由不泄漏 opaque payload；长会话可继续压缩。

Review 重点：Opaque state 是否被误作思维正文/远程句柄/缓存，是否在日志或 Debug 泄漏，
相容性绑定是否过宽/过窄，压缩是否拆开 Tool Exchange，Provider 目录是否超越真实证据。

实施结果（2026-08-20）：已加入 DeepSeek Flash/Pro、DashScope Qwen `qwen3.8-max` 与
Moonshot Kimi `k3` 的具名 Responses 方言和随包精确目录；Qwen 固定使用整批
`function_call_output` 后的单一聚合 User Image，Kimi 固定使用原生 content-parts output，
DeepSeek 保持无图片能力。DeepSeek/OpenAI 类非空 encrypted reasoning 以完整原生 item 保存为
`OpaqueProviderState`；Qwen/Kimi 的 `null` 不生成状态。

`OpaqueProviderState` 已增加 reasoning part 绑定和基于 provider/protocol/规范 endpoint/model 的

fail-closed。Context Layout 不再从首个 ProviderState 起永久保护历史；旧状态可随压缩 head 被

真实 Runtime Host 矩阵全部通过：DeepSeek Flash/Pro 完成 Responses function call、结果续接和

### M5：工具图片产品投影

前置依赖：M4 已确认。

目标：让用户在原有工具详情中查看 `read_image` 的稳定图片，但不把它升格为
用户附件、Context 文件或通用产物。

交付范围：

- `assistant-protocol` 增加最小 Session Tool Image 资源来源/可用状态投影，
  不暴露内部 Image Part、Session 绝对根、源路径或 ProviderState；
- Runtime 从已持久化 Tool Result Image Part 生成详情资源，不再从 Tool Call `path`
  回查外部原文件；主会话与 child Conversation 使用 owner/message/call/part 定位；
- 资源路由每次重新校验相对文件名、普通文件、哈希和 MIME；缺失/损坏投影为
  `Unavailable`，不从原路径自动修复；
- 从稳定原图在内存中派生有界预览，不在 `tool-images/` 持久化缩略图；
- Desktop 复用现有工具卡片/详情/图片预览交互，覆盖加载、可用和不可用态；
- `project_conversation_file_references` 和 Desktop Store 明确排除 Tool Image，
  不进入附件栏、Context Panel、通用产物栏、附件数量或用户文件导出。

验证入口：

```bash
cargo test -p assistant-protocol
cargo test -p assistant-runtime
cargo test -p assistant-runtime-host

cd apps/desktop
npm run generate:protocol
npm run lint
npm run test
npm run build
```

使用正式 Host/Desktop 覆盖主会话、child Conversation、历史分页、重启恢复、缺失图、
损坏图、工具详情关闭/重开和窄窗口，并断言附件/Context/产物列表始终不新增该图。

完成判定：用户只在对应工具详情看到单个有界预览或不可用占位；预览不依赖
外部源图；不混入现有附件和通用文件语义；子 Agent 资源不与主会话误配。

Review 重点：Protocol DTO 是否泄漏物理路径，Runtime 是否又从 Tool Call 读取外部文件，
缩略图是否污染去重目录，Desktop 是否把图片加入其他资源投影。

实施结果（2026-08-20）：协议新增 `SessionToolImage`；Runtime 只从可靠 Tool Result Image Part
生成稳定详情引用，`read_image` 输入路径不再形成普通文件产物，并显式过滤 Conversation file
references。Host 为主会话和 child 增加不同 owner URL，每次重新校验图片并只在内存生成 320 px
JPEG，Session Tool Image 不开放 native-path。Desktop 工具详情复用现有预览，携带完整 owner，
覆盖加载、图片和局部不可用态，且隐藏系统打开/目录揭示；窄窗口布局已收口。

M5 Review 随后发现 `inspect_images` 仍残留 v0.16.0 的附件专用边界。现已与 `read_image`
统一为标准文件 Read 权限：支持工作区相对路径和绝对路径；多图逐条授权并原子持久化 exact
Read 规则；辅助模型只瞬时预处理授权后的本地图片，不向 `tool-images/` 或附件目录复制文件。

验证结果：Agent Model 43 项、Agent Tools 55 项、Protocol 32 项、Runtime 159 项、Host 单元测试
114 项通过/1 项忽略，并通过全部离线集成测试。工具图片正式 Host 用例覆盖主会话与 child 的
不同 owner 路由、重启恢复、320 px 内存预览、同图去重、源图消失不回查、稳定副本缺失与损坏
不可用，以及不进入附件和 Conversation file references；新增辅助识图正式 Host 用例覆盖相对与
绝对本地路径、多路径审批、Session exact Read 规则原子持久化、两图实际进入辅助模型，以及不
产生附件或 Tool Image 副本。Desktop Rust 12 项、前端 96 项通过，协议生成检查、前端 lint/build、
格式/diff 和相关严格 clippy 通过。M5 已于 2026-08-20 获得用户确认。
