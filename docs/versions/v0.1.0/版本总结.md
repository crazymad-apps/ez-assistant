# v0.1.0 版本总结

- 版本主题：基础类型与模型层——建立 Provider-neutral 的规范对话与单次模型调用基础，完成 OpenAI-compatible/DeepSeek 适配验证。
- 时间：2026-07-17 启动，2026-07-26 完成验收与归档（用户确认）。
- 关联文档：[`版本设计.md`](版本设计.md)、[`开发计划.md`](开发计划.md)、[`代码审查.md`](代码审查.md)。

## 二、验证结论

- `cargo fmt --all --check`、workspace clippy `-D warnings`、`cargo test --workspace` 全部通过：**128 通过 / 0 失败 / 1 ignored**（审查修复新增 9 个回归/契约测试，3.1 收敛删除 2 个 route 相关测试）。
- 默认测试集合完全离线、无凭据、无仓库外 I/O；唯一真实网络测试为 `#[ignore]` 的 DeepSeek smoke test，缺 key 时软跳过。
- 真实 DeepSeek API smoke test 实际运行通过（2026-07-23，用户提供 key）：两轮 thinking + tool call round trip。
- 命令行 demo（`examples/chat.rs`）+ debug-viewer 端到端实测通过（2026-07-23）：SSE 捕获完整链路（turn_requested + turn_established + 全部 model_event）。

## 三、与计划的偏差

- **M6a 调试查看器**为版本中途用户补充决策新增，不在原计划里程碑内（决策记录 260723）。
- **codex 代码审查**（2026-07-24）发现 3 高 + 3 中 + 1 低，逐项核实全部属实并于 M7 内修复；其中 3.1 经用户决策收敛到底：endpoint/credential/model 全部归服务构造期参数，`ModelRoute`/`check_route`/`ModelError::Route` 整体删除，`ModelRequest` 退化为纯语义输入（决策记录 260724「模型配置形态与调用目标归属」）。这改变了 M2 原设计中的 route 概念与错误分类，以归档代码与决策记录为准。
- 3.1 收敛改变调试线格式 `turn_requested` 快照形状（少 `route` 对象）；查看器按原始 JSON 展示，无字段依赖。

## 四、遗留事项

- 模型层 tracing 埋点：`v0.1.0` 未实施，按 260724 已生效约定在 `v0.2.0` Runtime 接入时补齐（字段限定模型标识三元组/耗时/计数，不含 credential 与正文）。
- `DebugChannel::Sched` 与 Runtime 侧 `DebugSink` 归 `v0.2.0`；debug-viewer 跨会话并发 Turn 的细粒度关联后补。
- DeepSeek smoke test 不进入默认 Harness，依赖用户自建 `.env`（`DEEPSEEK_API_KEY`）。
- `agent-model` 单测保留自带 mini fake（避免反向依赖 testkit），与 `ScriptedModelService` 少量逻辑重叠。
