## 三、审查发现与处理

### 3.1 中：展示用 URL 可能携带 credential 或敏感查询参数

#### 证据

Harness 原先把 Provider endpoint 与 debug URL 直接用于控制台提示和 Runtime
`run_started` 调试数据。虽然默认 DeepSeek 配置不含 credential，但调用方可以传入
带 userinfo、query 或 fragment 的 URL。

#### 影响

形如 `https://user:secret@example.test/v1?token=...#...` 的配置可能进入控制台或
debug payload，违反 credential 不进入输出和事件的边界。

#### 处理

- 增加统一的展示 URL 脱敏：移除 username、password、query 和 fragment；
- 网络连接仍使用调用方提供的原始 URL，不改变请求路由；
- 新增回归测试，覆盖 Provider endpoint 与 debug URL 的展示投影。

### 3.2 低：debug-viewer 暴露了内部时间函数

`now_ms` 只服务于 viewer 内部信封接收与发送，不是稳定公共契约。现已从 crate
re-export 中移除并收紧为 `pub(crate)`，保留必要的公开线格式、client 与 server
入口。

### 3.3 低：debug-viewer 的测试依赖进入正式依赖面

`agent-types` 只被 `#[cfg(test)]` 测试代码直接使用，却位于正式 dependencies。
现已移到 dev-dependencies；`-D unused-crate-dependencies` 检查通过，正式代码只直接
依赖 `agent-core` / `agent-model` 的规范类型。

### 3.4 低：公开 rustdoc 与设计状态文字落后

- crate 顶层公开 rustdoc 链接了私有 `wire` / `client` / `server` 模块，严格 rustdoc
  检查失败；现改为普通模块说明。
- 功能设计仍将已经确认的技术细节写成“技术方案阶段需进一步确定”；现统一为已确认
  状态。
- debug-viewer 模块约束已同步正式依赖与测试依赖边界。

## 四、关键路径审查

### 4.1 Journal 与 Run 状态

- exchange 先进入 pending，只有完整 Tool Result 批次到齐后才在同一 Mutex 临界区
  原子投影到 completed Journal；
- complete 失败不会产生部分可见投影；
- receipt 绑定创建它的 Run recorder，不能由其他 Run 完成；
- pending exchange 会阻止新 Run，`reset` 可清理临时会话状态；
- 只有 Completed outcome 追加最终 AssistantMessage，Failed/Cancelled 不伪造成功输出。

### 4.2 取消、退出与事件终态

- 活动 Run 中普通输入和 `/reset` 被拒绝；
- `/cancel` 只发起取消，最终状态由 Core 的唯一 terminal outcome 收敛；
- `/quit` 先取消活动 Run，再等待 Core 和 Journal 清理完成；
- event stream 观察端断开不影响 completion；
- 取消期间未完成 Tool Call 会结算为受控结果，不向下一轮暴露未配对消息。

### 4.3 调试链路

- 每个 Run 只创建一个共享 `DebugClient`，三通道共用 correlation、递增序号、有界
  队列和静音状态；
- `post` / `post_on` 只做非阻塞入队，独立任务负责带短超时的 HTTP 发送；
- 队列满、发送失败或 viewer 断开后仅令本 Run 调试静音，不改变 Agent outcome；
- ModelService decorator 原样转发 request、context、建立错误和规范事件流，不吞掉
  取消或 terminal event；
- `provider` / `agent` / `both` 只控制装配的观察层，不改变实际模型与 Agent 执行。

### 4.4 CLI、离线性与敏感信息

- 参数或配置错误退出码为 2，场景失败退出码非 0，全部通过为 0；
- `.env` 只在显式 `chat` 路径加载；`list`、`verify` 和默认测试不读取 Provider
  credential；
- 离线场景只使用 scripted model/tool/authorizer 和内存 Journal，不访问网络、数据库、
  用户文件或真实 Shell，也不依赖 sleep 判断顺序；
- state 投影不包含消息正文或 credential；错误、事件和 URL 展示均经过受控投影。

## 六、实际验证


- 当前版本相关 9 个 Markdown 文件的相对链接全部可解析；
- `git diff --check` 通过。
