### M5：Runtime 分层调试推送与端到端联调

- 目标：由 Runtime 选择 provider、Agent 和 Runtime 事件，并在 viewer 中按同一 Run 关联。
- 影响模块：`tools/runtime-harness`、`tools/debug-viewer`。
- 状态：✅ 已完成（2026-07-28 用户确认）
- 实际结果：每个 Run 创建一个共享 `DebugClient`，三通道共用 `<session>/<run>` correlation、单调 `seq`、队列和静音状态；`ObservedModelService` 原样转发 request/context/error/cancel/事件流，并发送 `TurnRequested`、建立结果和每个规范 `ModelEvent`。Harness 事件消费路径发送强类型 `AgentEvent`，Runtime 发送 user message appended、run start/cancel/terminal/journal updated；`provider`、`agent`、`both` 和无 URL 四种装配规则均已落实。按用户验收反馈，页面改为左侧固定模型输出、右侧集中事件，右侧顶部使用 `LLM / Agent / Runtime` 单选 Tab；Agent/Runtime 时间线已移到右栏并可展开原始 JSON，不再使用通道复选。Session Tab 进一步改为按 correlation 的 session 部分聚合，同一会话的多个 Run 共用一个 Tab，但模型流卡片仍按完整 correlation 隔离。用户输入在写入 Journal 后由 Runtime 发送一次 `user_message_appended` 并渲染为独立卡片，Provider `TurnRequested` 不再重复展示输入。
- 自动验证：`cargo test -p runtime-harness` 通过（35 unit + 3 binary integration，0 failed），`cargo test -p debug-viewer` 通过（8 passed / 0 failed）；覆盖 decorator 透明性、建立错误、建立前/流中取消、终态、三种通道选择、无 URL 不装配、多通道 correlation/seq、本地 viewer router 的 POST→SSE 以及 viewer 失败静音不改变 Run outcome。`cargo clippy -p debug-viewer -p runtime-harness --all-targets --all-features -- -D warnings`、`cargo fmt --all --check`、`git diff --check` 均通过。
- 人工验证：使用 7332 独立实例注入同一 Session 的 LLM/Agent/Runtime 及另一 Session 的 Agent 事件。浏览器确认宽屏为 60% 模型输出 + 40% 事件栏；默认只显示 Agent，切换 Runtime/LLM 时右栏只出现对应通道，左侧模型输出保持可见；Session 单选可与当前通道联动过滤；三个 Tab 始终只有一个 `aria-selected=true`。临时实例已停止。
- 聚合验证：再次使用 7332 注入同一 session 下交错到达的 `run_1` / `run_2` 模型事件及另一 session 的 Agent 事件；页面只生成两个会话 Tab，目标会话 Tab 不含 Run 后缀，选中后同时显示两个 Run 的独立模型卡片及正确文本，证明会话聚合未破坏 Run 级流状态。临时实例已停止。
- 用户消息验证：在 7332 注入一次 `user_message_appended`、`run_started` 和同一 Run 的两个模型 Turn；左侧只出现一个“用户输入”卡片及两个不含用户文本的模型卡片，用户文本出现次数精确为 1；切换 Runtime 后可见 `user_message_appended → run_started`，证明展示来源和事件顺序符合 Runtime 权威边界。临时实例已停止。
- 当前步骤：已确认。
- 里程碑确认：已于 2026-07-28 确认。
- 未执行项：未再次调用真实 DeepSeek，也未执行真实 Provider + viewer 人工联调；M4 已验证真实两轮 Provider/工具闭环，本次若需观察真实三通道仍须用户另行明确授权。
