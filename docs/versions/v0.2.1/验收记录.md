## 六、人工核对结果

- Harness 保持单 binary 私有实现，不向 `assistant-protocol` 或正式
  `assistant-runtime` 输出临时 Session/Run/Journal 类型。
- 产品依赖方向未改变；`agent-testkit` 普通依赖只对 Harness 这个开发工具例外。
- 默认 `list`、`verify` 和测试不加载 `.env`，不访问网络、数据库、用户文件或真实
  Shell。
- 两阶段 Journal 在完整 exchange 完成前不产生部分投影；取消与退出最终由 Core
  唯一终态收敛。
- DebugClient 使用共享有界队列、短超时与一次性静音，viewer 不可用不改变 Agent
  outcome。
- Provider/Agent/Runtime 三通道共享 Run correlation 和单调序号；`provider`、
  `agent`、`both` 装配符合设计。
- viewer 按 Session 聚合，同一 Session 的多个 Run 保持独立模型流；用户输入只由
  Runtime `user_message_appended` 形成独立卡片。
- 右侧 `LLM / Agent / Runtime` 为单选 Tab，左侧模型输出不随通道切换隐藏。
- endpoint 和 debug URL 的展示投影会移除 userinfo、query 与 fragment。

## 九、偏差、遗留与风险

### 已吸收的实施修订

- debug-viewer 从原先模型/Sched 预留调整为 LLM/Agent/Runtime 三通道，并允许独立
  开发工具直接依赖 Agent Core；
- viewer 展示从通道复选调整为左侧固定模型输出、右侧单选事件 Tab；
- Session 筛选从完整 `<session>/<run>` correlation 调整为按 Session 聚合，同时
  保留 Run 级模型流隔离；
- 用户输入改为 Runtime `user_message_appended` 权威事件，不再从 Provider request
  重复推导；
- Harness 的展示 URL 补充 userinfo/query/fragment 脱敏。

上述修订均已同步设计、计划、模块约束、重要决策、代码审查和回归测试。

### 遗留与风险

- Harness 是临时开发工具，不替代未来正式 `assistant-runtime` 的持久化、调度、
  恢复与产品协议设计。
- 真实模型行为和外部服务可用性存在天然不确定性；离线 scripted 场景是稳定回归
  基线。
- viewer payload 包含本地调试所需的消息正文和工具参数，只允许推送到用户显式配置
  的 loopback viewer；credential 与请求 header 仍禁止进入 payload。
- 当前无阻断版本完成的遗留问题。
