  `DEEPSEEK_API_KEY` 的真实 DeepSeek API smoke test。
- `cargo run -p runtime-harness -- verify v0.2`：6 passed / 0 failed。
- workspace Clippy `-D warnings`、`cargo fmt --all --check`、目标工具 rustdoc
  `-D warnings`、production `unused_crate_dependencies`、Cargo metadata/tree、

- M4 经用户授权完成真实 DeepSeek 两轮工具闭环；第二轮继承完整
  `user → assistant → tool → assistant → user → assistant` Journal，最终

- M5/M6 使用本地 viewer 完成三通道、Session 聚合、Run 隔离、用户输入独立卡片和

  npm/Vite 和 Tauri bundle 构建。

## 三、主要能力与取舍

- Harness 是开发者按需启动的独立 binary，不属于产品进程或正式
  `assistant-runtime`；临时 Session、Run、Journal 和 CLI 类型保持私有。
- `agent-testkit` 的普通依赖只对 Harness 这个开发工具例外，产品 crate 不依赖
  Harness 或 debug-viewer。
- 默认 `list`、`verify` 与测试不加载 `.env`，不访问网络、数据库、用户文件或真实
  Shell；真实 Provider 只在显式 `chat` 路径启用。
- 每个 Run 共享一个 `DebugClient`，LLM/Agent/Runtime 三通道共用 correlation、
  单调序号、有界队列和静音状态；viewer 故障不改变 Agent outcome。
- viewer 按 Session 聚合顶部筛选，但模型流仍按完整 Run correlation 隔离；用户输入
  只由 Runtime `user_message_appended` 权威事件展示。
- endpoint 与 debug URL 的展示投影移除 userinfo、query 和 fragment，credential
  不进入控制台、错误、模型/Agent 事件或 debug payload。

## 四、主要修订与偏差

- 原预留 `DebugChannel::Sched` 在首次接入前更名为语义更完整的 `Runtime`，并新增
  独立 `Agent` 通道。
- viewer 通道交互从复选组合收敛为左侧固定模型输出、右侧
  `LLM / Agent / Runtime` 单选 Tab。
- Session Tab 从完整 `<session>/<run>` correlation 调整为按 Session 聚合，同时保留
  Run 级流状态。
- 用户消息从 Provider `TurnRequested` 推导改为 Runtime
  `user_message_appended` 独立事件，避免输入和模型输出混杂或重复展示。
- M6 收紧了 viewer 公共 API、正式依赖与 rustdoc，并补充展示 URL 脱敏。

上述修订均已同步功能设计、技术方案、开发计划、模块约束、重要决策、代码审查和
回归测试，不构成未解决偏差。

## 五、遗留与后续入口

- Harness 不替代未来正式 Runtime 的持久化、并发调度、重启恢复、权限与产品协议。
- 真实模型与外部服务存在不确定性；离线 scripted 场景继续作为稳定累计回归基线。
- 后续 Core 版本应在 Harness 的版本 registry 中保留既有场景并增加新版本能力入口。
- 下一目标版本为 `v0.3.0`（上下文系统）：从 Prompt Compiler、上下文组装、token
  预算、工具输出裁剪与压缩恢复的功能设计开始，确保 reasoning、Provider State 和
  Tool Call/Result 配对不被破坏。
