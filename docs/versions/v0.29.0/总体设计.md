## 二、版本背景、最终目标与成功标准

现有企业模式已有身份、模型代理、插件分发和用户管理，但尚未形成 Desktop 安装包的中心
管理与客户端升级闭环；桌面长路径、终端选择、重复启动和消息过程展示影响日常使用。
用户还需要把使用问题直接提交中心，并完成账号删除。模型调用目前从本地发送完整有效
上下文，需要在保持本地可恢复的前提下，为支持的接口增加服务端历史续接。

本版本完成后：

1. 管理员能够发布适用的 Desktop 安装包；用户自动获知更新，主动确认后完成下载安装。
   明确不兼容时回到登录页，持续显示原因与恢复提示，有可用兼容包时显示升级按钮，不能跳过兼容门禁。
2. Windows/macOS 文件和终端长路径不再挤压主要操作区域，终端选项与实际 Host 一致；
   Windows 重复启动只唤起已有应用，窗口装饰和文字快捷菜单符合已确认的展示要求。
3. 每轮处理过程可折叠，用户始终知道处理耗时，能查看进展、工具详情和需要处理的事项；
   最终回复独立呈现，消息通知能直接读到会话标题及消息正文；其他会话需要审批或回答时，
   应用内通知可点击定位处理入口，侧栏状态保持原状。
4. 手动、用户委托 Agent、Agent 自主发现问题三种方式能够进入同一个企业反馈中心；
   管理员可处理，提交者可确认提交结果及处理状态。
5. 管理员可以真正删除账号，删除与停用具有不同语义，凭据失效与历史记录归属一致。
6. 支持的接口可按配置增量续接；压缩或切换模型后自动从本地有效上下文重建，用户无需
   新建会话，历史工具不被重新执行，不依赖服务商永久保存历史。

7. Agent 一次调用可提交单文件多处修改或多个文件的修改，保持文件权限与可靠工具记录，
   失败时能够辨认已修改和未修改范围，避免反复调用单次 edit。

成功标准以第八节的行为闭环为准，不以页面存在、接口返回成功或单平台构建通过替代。

## 五、架构原则与全局不变量

1. **先复用已有事实。** 兼容沿用两层检查，通知沿用投递通道，预览沿用更多菜单，反馈
   复用中心身份和工具装配，模型复用连接身份、协议解析及上下文压缩。不得为展示增加第二份历史。
2. **兼容门禁与升级动作分开。** 网络/认证错误不是明确不兼容；不兼容必须阻止业务准入，
   但下载安装仍由用户点击。退登录页不隐含取消 Run、停止 Host 或远端升级。
3. **本地历史可独立恢复。** 压缩摘要、保留消息及完整工具交换是重建输入；服务端续接状态
   丢失不等于用户会话丢失。重建不重新执行已提交工具，不跨身份、服务商或会话复用游标。
4. **过程展示不改执行。** Turn/Step 折叠、summary 选择和最新文本滚动只改变投影；不因 UI
   收起删除 reasoning、工具结果或 Provider 所需状态，不额外调用模型生成展示摘要。
5. **身份变化具有一致结果。** 用户删除后旧 Token/key 和后续中心访问失效；反馈、审计、
   用量及调用历史仍可解释原归属，重建同名账号不能继承旧账号数据。
6. **真实结果才表示成功。** 上传不等于发布，下载不等于安装，安装器退出不等于兼容恢复；
   反馈超时不等于未创建，删除事务未知不能伪报成功，模型流未完成不能提前提交有效续接点。
7. **避免重复副作用。** 重试、重连、升级唤起不能重复创建反馈、重复执行工具或启动多个
   Desktop/Host；复用已有提交与串行边界，新增状态须有明确 owner 和生命周期。

最小新增判断：现有机制足以承载 UI 展示和通知；安装包发布事实、反馈记录及删除语义是
现有业务缺口，需要在各自既有模块内扩展。续接确需跟踪远端响应与本地上下文的对应关系，
但不因此另建通用会话服务、跨 Provider 状态库或缓存平台。具体字段与持久化由技术方案证明必要性。

### 6.7 F07 的评估、范围与完成边界

2026-09-29 用户反馈现有 edit 一次只能修改一处，要求评估并加入本版。现有
[edit 输入](../../../crates/agent-tools/src/standard/fs/write.rs)只包含一个文件和一组替换，
replace_all 仅能处理同一旧文本的重复出现；[本地 Adapter](../../../crates/agent-tools-local/src/filesystem.rs)
已有路径锁、写前内容复核、UTF-8/BOM/换行处理，可继续复用。

| 路线 | 评估与本版取舍 |
| --- | --- |
| 扩展现有 edit，支持多个文件、每个文件多组替换 | 纳入 F07，直接解决模型往返次数多的问题；继续归文件能力，避免新建通用执行层 |
| apply_patch 多文件补丁 | 能力可行，但增加解析语法、增删移动权限和模型适配范围；本版先不纳入 |
| 模糊匹配/模型辅助纠错 | 与批量是不同问题，会增加误改风险；本版保持精确匹配及已有换行兼容 |

调研依据：OpenCode 当前 [edit](https://github.com/anomalyco/opencode/blob/7945de208964a49300d7f770d1a71d078db9a4c4/packages/opencode/src/tool/edit.ts)
仍是替换式，[apply_patch](https://github.com/anomalyco/opencode/blob/7945de208964a49300d7f770d1a71d078db9a4c4/packages/opencode/src/tool/apply_patch.ts)
支持多文件且先计算后逐文件写入；旧 multiedit 已删除，不能作为当前可用能力。
[Gemini CLI edit](https://github.com/google-gemini/gemini-cli/blob/fe6350238c1862dade66a9dea9080c6508475bec/packages/core/src/tools/edit.ts)
也采用一文件一组替换，允许多次匹配不等于多组编辑。参考其输入表达，不照搬其模糊匹配策略。

完成边界：

- 一次调用可修改同一文件的多个位置，也可提交多个文件；单文件仍可使用。组内顺序语义、
  重复路径和修改重叠规则在 F07 设计时明确，不能靠数组循环隐式决定。
- 复用现有多路径文件授权事实，写入前完整授权整批目标；包含拒绝目标时不先写其他文件。
  路径解析、目录保护、审批与审计继续走现有链路，edit 仍按写工具调度。
- 同一文件先在内存验证全部替换，再提交结果；匹配失败不留下该文件的前几处修改。
  必须保留写前内容变化检查，评估一次提交在 Windows/macOS、符号链接及写入失败时的实际保障，
  不把一次 write 宣称为原子或崩溃安全。
- 跨文件执行遇到失败或取消，停止后续修改，按文件返回成功、失败/结果未知、未执行及替换数量；
  不承诺全部回滚，不自动重放整批。崩溃后副作用不明时沿用现有 unknown 恢复语义。
- 工具结果与持久化保持真实状态；模型可据结果重新读取失败目标并修正。限制文件数、替换数、
  总输入/输出与文件大小，防止批量绕过现有限额或结果被截断到无法判断修改范围。

评估为中等规模：主要改动归 agent-tools、agent-tools-local 和 Runtime 文件授权/结果链路，
Host 装配及客户端现有工具展示按消费者同步；不预设新增数据库表、持久任务或产品进程。
主要风险是部分成功、取消/写入结果未知和多路径授权，不能仅给输入加数组就视为完成。
具体工具 Schema、历史调用兼容和文件提交方式在独立设计确认，当前只纳入版本范围。

- 不兼容登录页必须在旧业务 API 无法使用时仍可获取升级所需最小信息；鉴权、签名、
  下载来源和安装完整性在 F01 技术方案中落实，不能将受保护管理接口直接改为匿名开放。
- 安装文件替换与 Host 数据迁移是不同恢复边界；F01 明确旧版到新版路径、安装失败、
  Host 启动失败和数据库不兼容的处置，不把复制旧二进制当作通用恢复。

### 7.2 身份、反馈与模型链

- 中心用户身份为历史引用依据，不能以显示名称或账号字符串重新绑定反馈/用量/模型链。
  F04 先按不可复用身份建引用；F05 的删除设计不得静默改写已完成反馈边界。
- 中心权限、管理审计、身份串行段与事务继续复用；新增迁移使用唯一现有账本，Admin
  请求契约仍由 OpenAPI 生成。正式开发前再核对所有历史引用和实际读表。
- 续接绑定具体连接、模型、协议、身份作用域及有效上下文，主会话/子任务/摘要调用分别
  隔离。企业代理继续做既有准入与转发，不新增中心 Agent Loop 或第二份会话状态。
- 删除账号、退出或切换身份后旧异步结果不得回写当前 UI/连接或恢复已失效访问。

### 7.3 展示与上下文

- F03 折叠和 reasoning summary 是展示规则；F06 重建只能读取可靠 Conversation/压缩
  事实，不能读取折叠组件中的文本充当上下文。
- 时间、通知消息和反馈来源必须指向同一会话/Run 的可靠事实；不以当前聚焦页面猜测归属。
- Shell 能力来自目标 Host；Logo、单实例和本机安装来自客户端平台。远端路径只能走
  已有远端资源能力，不能按字符串在本机打开。

### 7.4 批量编辑与执行事实

- F07 的一次批量调用仍保持一个 Tool Call 与对应完整 Tool Result；逐文件结果属于该结果，
  不拆出无法配对的虚构调用。F06 续接/压缩不得重放已执行编辑或丢失部分成功事实。
- F03 折叠可收起编辑详情，但失败、结果未知和未执行范围必须可见，审批须能查看全部目标。
- F07 后续若改动共享 Schema/权限/结果，定向回归 F06/F03；不得静默改写其完成边界。

## 八、版本级验收与发布门禁

每个 Feature 独立完成设计、计划、里程碑确认和验收后，仍须完成以下跨 Feature 场景：

| 验收场景 | 必须成立的结果 |
| --- | --- |
| 企业包发布 → 普通更新 → 下载校验 → 安装重启 | 只发现适用已发布包；未经确认不下载；完成后真实版本与运行 Host 一致，失败可解释 |
| 中心明确不兼容 / 无可用包 / 网络失败 | 前者阻止准入且登录页可升级；无包不绕过；网络失败不误判为强制升级 |
| Windows 快速重复启动、最小化/托盘、升级重启 | 一个桌面实例，唤起正确窗口；新版本不被旧实例锁阻塞；不额外停止 Runtime |
| 活动 Run、用户终端、本机 Host 交接及远端连接 | 更新确认后受控停止当前本机 Host；不按原安装来源拒绝，安装后使用同一 Runtime Home 的新版随包 Host；停止失败不安装，远端实例不受影响 |
| Windows/macOS 长路径、默认 Shell ↔ 其他可用 Shell、远端 Host | 显示、真实进程及资源目标一致；未安装类型隐藏；命令/输出和用户全局配置不被破坏 |
| 新消息、流式增量、手动收起、完成、重连和历史加载 | 折叠触发正确，耗时稳定，summary/原文互斥，工具/审批可达，最终回复独立 |
| 多会话通知与后台运行 | 标题和正文匹配来源；其他会话审批/问答通过应用内通知定位处理入口，侧栏不变；系统通知关闭、项目收起、重连及事项已失效均有正确行为；推理和工具日志不充当正文 |
| 三种反馈来源、超时重试、中心不可达、身份切换 | 一套记录与真实提交结果，不重复建单、不跨身份、不妨碍原任务 |
| 删除有反馈/调用记录的用户、同名重建、管理员保护 | 凭据失效，历史可解释，新用户不继承旧数据，Host 本地内容不被清空 |
| 无状态/续接接口、压缩、切换模型及切回、续接过期 | 重建使用有效上下文，ID 隔离，工具不重放；服务端存储关闭后仍可正常执行 |
| 企业代理路由变化、账号失效、重启后恢复 | 同身份/绑定的重启恢复已提交 ID 并续接；真实变化不复用旧链，失败和未知状态不伪装为完成 |
| 多文件/多处 edit、混合权限、匹配失败、外部修改、取消及写入错误 | 授权完整，文件内匹配失败不落半套替换，逐文件结果真实，不盲目重放整批 |
| 批量工具结果 → 折叠/重连/压缩/续接 | Tool Call/Result 配对完整，部分成功仍可解释，已有文件修改不重复执行 |

发布条件：全部必需 Feature 验收获用户确认；跨 Feature 验收通过；Windows/macOS 对应
安装制品和关键原生路径有实际验证；Center/Host/Desktop 的接口、配置和数据兼容声明一致；
未完成项和平台限制明确记录并获接受。仅构建通过不能替代安装、通知、终端或重启实测。
验证结果留所属开发计划结论，不新建验证报告。生产/共享数据库操作仍须执行项目确认、
备份和核验规则；本次文档设计未进行数据库操作。
