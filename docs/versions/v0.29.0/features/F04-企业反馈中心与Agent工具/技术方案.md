## 一、现状核查与最小新增

以下路径均相对仓库根，已核查实际源码；`cargo metadata --no-deps` 确认 Host 已依赖
`agent-tools`、`assistant-runtime` 和 `assistant-protocol`，本方案不新增 crate 或第三方依赖。

| 实际入口 | 核查结论与本次使用 |
| --- | --- |
| `apps/enterprise-center/src/identity/service.ts` | `write` 串行覆盖事务与提交后身份变更；事务内 `requireUser/requireAdmin` 重验，提交不明清凭据，回滚失败关闭连接池；直接复用 |
| `apps/enterprise-center/src/database/{source,migrations,counts}.ts` | 单 DataSource、显式 SQL/pgmigrations、维护计数清单；增加一个反馈 Entity/表，迁移编号接入时协调 |
| `apps/enterprise-center/src/audit/{entity,repository}.ts` | `target_user_id` 只指用户，反馈编号放 `details.feedback_id`；不能把反馈 UUID 填入用户列 |
| `apps/enterprise-center/src/plugins/entity.ts` | 插件主标识是 `name`，包按 `plugin_name + version` 定位；不造第二套插件 ID |
| `apps/runtime-host/src/access/enterprise/{mod,client,agents}.rs` | `Credentials + UserKey(center_id,user_id)` 持有当前中心访问；已有发送前取凭据、返回后核对当前凭据的模式 |
| `apps/runtime-host/src/user_domain/services.rs`、`resources{.rs,/tools.rs}` | 用户域已有 Credentials/UserKey 装配上下文；`RunToolFactory` 按 Run 冻结工具，不需要向 Core 注入企业身份 |
| `crates/agent-tools/src/tool.rs` | 普通 Tool 自动生成 `GeneralAuthorizationFacts`，支持无 I/O resolve、固定 Schema、串行执行和取消；可直接实现 Host 私有工具 |
| `crates/assistant-runtime/src/permission/{authorizer,matcher}.rs` | General matcher 按工具名匹配，Deny > Ask > Allow；Host 默认规则可注入，普通工具不能伪装成 `ask_user` 私有免审批 facts |
| `apps/runtime-host/src/http/commands.rs` | 已有插件市场 Command 在 Host 转发到 Center；反馈采用同类薄适配，不在 Runtime 建工单 Store |
| `apps/enterprise-admin/src/{app/routes.tsx,request,stores/AdminStore.ts}` | 路由、分页请求、身份切换和写入守卫已有；Center Swagger/OpenAPI 是 Admin SDK 唯一来源 |

新增反馈记录具有独立提交身份与处理生命周期，现有审计或问答记录不足以承载。
除此之外复用现有工具、身份、权限、分页、事务和传输；不增加反馈同步服务、任务队列、知识库目录、
回复表、独立幂等表或统计缓存。知识库接口在当前产品模块中尚无正式契约，不能假设存在可查询的目录。

## 二、调用链与所有权

```text
Desktop/Web 反馈面板 → RuntimeClient Command → Host 当前用户访问 ┐
Agent → Registry/Dispatcher → Host submit_feedback 工具 ───────┼→ Center 反馈服务 → PostgreSQL
Admin → 由 OpenAPI 生成的 SDK ─────────────────────────────────┘
```

Center 负责身份授权、反馈事实、提交去重、处理结果与审计。Host 负责当前主体绑定、固定中心地址、
有界请求和工具适配；UI 只保存草稿及读取投影。无新增 Session/Run 状态、SSE 事件或 Host 数据库迁移。
Agent Core、agent-tools 通用 SPI 和已有问答工具不变；Host 的工具实现与 Center 客户端留在产品层。

计划在 Center `src/feedback/` 放置 Controller、Service、Entity、校验和必要查询；DTO 放现有
`src/contracts/`。Host 的反馈传输放 `access/enterprise/client/feedback.rs`，用户访问逻辑就近放
`access/enterprise/feedback.rs`，工具实现放 `resources/feedback.rs`。按实际复杂度拆文件，不创建通用反馈框架。

## 三、契约与输入约束

### 3.1 反馈内容与目标

手动创建和 Agent 共享一个反馈内容 DTO。所有字符串先按字段约定 trim，空可选值统一为 null；
正文内部换行保留，不改变大小写或擅自归并目标。未知字段拒绝，边界同时由 Host 和 Center 检查。

| 字段 | 语义与限制 |
| --- | --- |
| `target.kind` | `platform / plugin / knowledge`，必填 |
| `target.reference` | 对象的稳定引用，可空；平台固定为 `ez-assistant`，插件必须使用已有插件名称标识；知识来源应使用包含来源范围的引用，不能只填容易冲突的局部数字；最多 512 字符 |
| `target.name` | 提交时名称，必填、最多 120 字符；平台由服务端固定；仅用于展示 |
| `target.version` | 可选实际插件版本，最多 64 字符；非插件拒绝非空值 |
| `target.content_ref` | 可选具体文档/条目的来源标识，最多 512 字符 |
| `target.location` | 可选工具/功能/页面/文档章节说明，最多 512 字符 |
| `title` / `description` | 分别最多 120 / 4000 个 Unicode 字符，trim 后非空 |
| `reproduction` / `expected_result` | 可选，各最多 2000 个 Unicode 字符 |

知识库没有稳定引用时允许 `reference=null`，但必须填写明确名称；此时为“手动描述的对象”，
而非已解析的知识库身份。针对具体内容时填 `content_ref` 或 `location`；表单通过“整个知识库/具体内容”
控制必填，工具描述同样说明，不能从任意正文可靠推断用户是否针对具体内容。
来源给出的非空引用是定位线索，不表示 Center 已核验存在；不增加“已验证”字段或状态。
插件选择复用用户可见的已安装清单/市场；旧版本、下架对象仍可提交已知引用，保存原名称，
不把当前目录存在作为反馈能否创建的前提。用户填写内容与来源标识均按诊断输入对待，不授予资源访问权限。

每份规范化反馈内容的紧凑 JSON 最多 12 KiB，补齐提交标识和环境后的请求仍须在 Center 既有
16 KiB 上限内；字段字符上限与总字节上限同时适用，界面展示超限错误，不静默截断。
这样允许简短中文反馈，无需因各字段上限理论相加而扩大通用 HTTP 限制。

### 3.2 环境、来源与提交标识

Host 创建请求补 `source=manual|agent`、Host 版本/OS/架构；Desktop 自报客户端类型与真实版本/OS，
Web 仅报 web 与已知版本，Agent 报 agent 和 Host 环境。未知项为 null，不从 User-Agent 猜原生系统。
环境固定为 `host_version/host_os/host_arch/client_kind/client_version/client_os/client_arch`；
除枚举客户端类型外，各字段最多 128 个 Unicode 字符，可空，合计不超过 2 KiB，不传任意 metadata、绝对路径、会话正文、Token 或完整日志。

`source` 和客户端环境是诊断信息；普通 Bearer API 没有能够证明“人工操作”的独立凭据，不能将来源字段作为权限依据。
owner 永远由中心当前认证用户决定，禁止请求指定用户、状态、处理者或中心地址。
创建请求还包含 `submission_id`（UUID），只标识一次提交；反馈编号 `id` 由 Center 创建。

### 3.3 Center HTTP

| 接口 | 权限与行为 |
| --- | --- |
| `POST /api/feedback` | 当前启用用户；创建或取得同次提交记录，返回 200 和当前详情，重试也返回同一 `id` |
| `GET /api/feedback` | 仅本人；按时间/id 倒序分页，可按状态、目标类型/引用及 `submission_id` 精确查询 |
| `GET /api/feedback/:id` | 仅本人；不存在或不属于本人均返回相同 NOT_FOUND |
| `GET /api/admin/feedback` | 管理员；状态、来源、提交者 ID、目标类型/引用、标题筛选 |
| `GET /api/admin/feedback/:id` | 管理员详情 |
| `PATCH /api/admin/feedback/:id` | 管理员；提交期望的原状态/说明与新的状态/说明 |

列表沿用既有 limit/offset 及 items/total 响应约定，本入口 limit 默认及最多 20 条，offset 沿用现有上限；摘要仅含 ID、标题、目标类型/名称、状态、来源、
提交者与时间，不含完整目标引用、环境、正文/处理说明，按字段上限核验整页小于 64 KiB。
标题搜索使用参数化、转义后的字面包含匹配；未知筛选值拒绝，不拼接 SQL。对象筛选按类型和引用精确匹配；
无引用知识目标以 `target_kind=knowledge&target_unresolved=true` 筛出“手动描述”记录；
`target_unresolved=false` 筛出有引用记录，该条件与精确引用互斥，名称不当作稳定聚合键。
首版不提供统计汇总接口、目标枚举目录、记录删除或用户改正文接口。

新增 Center 能力字符串 `feedback`，只有实际接口/迁移可用的制品才宣告。反馈读写错误使用固定原因码：
参数/过大、未登录、无权限、未找到、提交标识冲突、处理内容冲突、中心不可达与提交结果未知。
响应包含现有 request_id，不记录原始 SQL、请求体、身份凭据或自然语言正文。

### 3.4 Host 应用协议

在 `assistant-protocol` 新增纯 DTO，并给既有 RuntimeCommand/Result 增加
`GetFeedbackSupport`、`SubmitFeedback`、`ListSubmittedFeedback`、`GetSubmittedFeedback`。
命名与现有 `ListFeedbackRequests/AnswerFeedback` 分开，避免把企业问题记录混同于会话提问。
这些命令像现有插件市场入口一样在 Host 分派，Runtime 不实现反馈 Store。

`GetFeedbackSupport` 从当前用户对应 Center 的 info 读取支持情况；不把一次网络失败当成永久不支持。
UI 打开时查询，支持才显示创建操作；创建/工具执行前再次检查当前中心支持，避免依赖陈旧 UI 状态。
个人模式返回不可用；本机管理凭据不能替代企业用户提交。

DTO 通过既有 Rust → TypeScript 导出同步 Desktop/Client，Center DTO 则由 Swagger → Admin SDK 生成。
Host 的 Center DTO 转换留传输边界，不能让 Center 导入 Rust 源码或让 Admin 手写另一套请求契约。
已确认业务拒绝与提交未知应在结果中可区分；不能一律映射为登录失效或通用成功。

## 四、数据、事务与统计维度

新增 `public.feedback` 一张表：

- `id uuid` 主键；`owner_user_id integer`、提交时 `owner_username/owner_display_name`，以及 `submission_id uuid`。
- 来源和三种目标类型；目标引用、名称、版本、内容标识和位置为独立列，正文各字段为文本。
- 固定环境信息存一个 JSONB 对象；不把目标全部藏进自由文本或环境 JSON。
- `status=pending|processing|resolved|closed`，`handling_note`，最后处理者 ID/名称快照，创建/更新时间。
- `UNIQUE(owner_user_id, submission_id)`；状态、来源、类型和空值组合有 CHECK，长度/字节也在服务层校验。
- 主要索引为 `(owner_user_id, created_at, id)`、`(status, created_at, id)`、
  `(target_kind, target_reference, created_at, id)`；不提前建立全文搜索或统计专用索引。

owner 与处理者 ID 是提交/处理时经鉴权查得的不可复用 `users.id` 快照；本表不对 users 建阻止删除或级联删除的外键。
创建/处理只允许事务内当前有效用户，姓名不参与权限；删除后的历史依靠 ID 和名称快照展示。
F05 必须保持身份序列不重置、不按用户名重新归属，并处理既有审计外键；F04 不提前修改 users 或审计删除约束。
目标也不建外键，以便插件下架或知识内容移除后仍保留反馈。
插件和知识引用均按精确来源标识保存，名称相同不意味着对象相同；外部来源自行复用标识时，中心不能凭空识别为新对象。

创建流程：纯输入校验 → `IdentityService.write` → 事务内 requireUser → 按 owner/submission 查重
→ 新记录与创建审计一并写入 → commit → 回执。相同提交已存在时比较规范化内容与来源，
一致则直接返回原记录，不重复审计；不一致返回 409。名称/目标/正文属于提交内容，环境只保留首次快照，
重试不能借新版 Host 环境覆盖原记录，也不因版本环境变化把同次内容误判冲突。
进程串行段负责与注销/停用交错，唯一约束仍作存储防线；不在事务内进行网络或文件操作。

处理流程同样复用 write/requireAdmin：先读当前状态和说明；目标值已相同则 no-op，
否则比对请求的 `expected_status/expected_handling_note`，不一致返回 409 和重新读取提示，
一致才更新状态、说明、处理者和时间，并追加审计。
**不新增 revision/ETag/CAS 版本列**：要保护的是管理员实际编辑的两个值，串行段内原值比较已经足够；
期间修改后又恢复成完全相同值，不构成需要拒绝的业务差异。更新时间只展示，不作为有精度损失的 CAS 令牌。
已解决/已关闭说明必填，最多 2000 字符且请求整体有界。审计只记反馈 ID、动作和状态变化，不复制正文/说明。

后续统计以目标类型、稳定引用和具体内容标识聚合，插件版本可细分；未解析引用单列，
不能按名称猜测归一。首版只有可筛选的明细，不维护总量或物化聚合。

## 五、Host 身份与工具执行

### 5.1 用户访问

Host 反馈访问复用现有 Credentials/UserKey，按用户域装配可选的具体反馈客户端句柄。
将 `current_agent_center/current_plugin_center` 的相同取凭据逻辑收敛为产品内通用当前中心访问方法，
保持原调用者行为；不为反馈复制 Token Map、绑定表或长期成功认证缓存。
发送前取得当前登录，检查用户域取消；获取能力等 await 后再次确认主体和当前凭据，才允许发起写入。
网络请求不持 Credentials 锁；结合既有用户域取消信号与请求取消，中断等待并回收响应流。
Center 在自己的事务内再次重验 Token，形成最终写入授权边界。

返回后复查当前身份/登录，旧登录的迟到结果不投影到新身份；已发送请求可能已提交，
因此身份变化/断连不能宣称回滚。已完成事务属于原 owner，重新登录同主体可查询；新同名用户不可见。
复用现有登录失效/用户域撤销路径，不因 400/409/普通网络故障注销用户。

CenterClient 沿用固定配置地址、禁止重定向、3 秒连接/5 秒单请求期限和流式累计响应上限 64 KiB。
反馈能力检查与业务请求串行执行，各自有界；写入不使用 reqwest 自动重试。
列表只回摘要，详情内容受请求限额约束；收到错误/超限/非法回执均不能报告提交成功。

### 5.2 `submit_feedback`

Host 私有 `Tool`，模型输入仅为 3.1 的内容，不接收 owner、中心地址、环境、状态或提交标识。
Schema 使用普通对象、enum 和可选属性，避免提供商不支持的复杂联合；支持性检查沿用真实 Host 工具 Schema 验证。
`resolve` 只做规范化、尺寸和组合校验，采用普通 GeneralAuthorizationFacts，不在 resolve 联网。
`execute` 使用用户域中心访问；工具保留默认 Serial，不放到并行执行组，不建立后台任务。

企业用户域注册固定工具定义，Plan/Build 保持相同；个人域不注册。
对旧中心，调用前能力检查返回明确不可用，不进行 POST，也不把新增反馈能力列为登录必要条件。
工具支持变化不动态重写当前 Run 的 Schema，保持 F06 已有上下文事实和续接规则。

在现有 Host 默认权限规则来源中，合并一条 General `submit_feedback` Allow，覆盖 Plan/Build；
复用已有文件保护规则，不覆盖它们。默认 Ask/Auto 模式下都可自主提交，不新增逐次确认。
用户/项目/Session 显式 Deny 仍优先；显式 Ask 走既有 Ask/Auto resolver，其行为与其他普通工具一致。
不能通过硬编码直接 Allow 绕过规则，不能使用当前问答工具的私有免审批 facts。
此工具虽会向中心写记录，但不修改项目文件；允许 Plan 提交属于本产品工具的明确设计选择。

每次 `execute` 分配一个 UUID 提交标识，在本次 HTTP 操作期间保持不变，不让模型生成或更换。
成功输出反馈 ID、目标摘要、当前状态和创建时间；执行错误使用固定码和真实结果类别。
发出 POST 后无可靠回执时，输出“提交结果未知”及提交标识，禁止模型将再次调用当作安全重试：
新 tool call 是新提交，可能重复；由本人反馈列表刷新核对，必要时以提交标识精确查询。
不增加工具专用重放命令或本地持久队列，也不保证跨 Host 重启恢复尚未返回的工具结果。
中心按同一标识去重的保证依然覆盖请求重送和中心重启；单次工具不自动重发，避免新的隐式副作用。
收到取消时遵循 ToolContext 的现有取消契约，清理网络资源后返回，不能把取消包装为“中心未创建”。

## 六、客户端与管理端组织

Desktop 使用独立 `features/feedback-center/`，不放入现有向用户提问的 `features/feedback/`。
面板生命周期随当前 RootStore/身份，复用 Dialog、Button、SelectionPopover 与现有表单样式。
草稿、分页和结果未知标识只在当前身份内存保存，关闭/切换时按交互指导释放，
不进入 localStorage、会话事件、全局待办或 F03 通知 Store。
RuntimeClient 用上述 Commands；菜单只负责打开面板，F01 顶部升级入口保持其独立 owner。

手动提交在首次点击时冻结内容与 UUID；失败后未改内容的显式重试复用这份请求。
网络结果未知时先按 submission_id 查询，查到则显示原记录；暂未查到可显式重试原请求，
即使旧请求随后提交也由唯一约束收敛。同一草稿修改后需作为新反馈重新提交，并提示原请求仍可能存在。
创建成功后重读本人列表；只在当前身份和当前查询代次发布响应，不乐观插入虚构成功记录。

Admin 新增 `/feedback` 和 `/feedback/:id`，用既有 PagedList/useResourceQuery、AdminStore 写入守卫、
NavigationGuard 与 Ant Design。列表/筛选归页面 hook，处理草稿归详情，不上提 PageLayout。
写入后由详情回调重读；冲突或未知保留草稿并提供重读，不自动覆盖他人修改。
正文、目标和说明按纯文本渲染；即使包含 URL/HTML，也不自动访问、执行或加载远端内容。

## 八、验证与方案确认点

实现后按里程碑风险验证，不新增独立验证报告：

1. Center 真实隔离 PostgreSQL/API：本人/管理员权限，用户停用或注销与写入交错，审计失败事务回滚；
   重复/并发/回执丢失后同标识重试及重启查询，内容冲突、处理冲突与 no-op；精确表计数及目标字段核验。
2. DTO/目标：三种目标、未解析知识引用、同名不同来源、名称变化、内容定位、中文字节上限，分页摘要和响应限额。
3. Host/工具：真实 Registry Schema 与 General 规则，Plan/Build、默认 Ask/Auto 与显式 Deny/Ask；
   主/子 Agent 的用户域隔离，能力缺失、身份换代、取消和未知回执，不递归反馈、不误停原任务。
4. Desktop/Web/Admin：创建/详情/处理完整路径，失败草稿、同标识重试、分页筛选、冲突恢复、身份切换迟到响应，
   菜单与 F01 入口共存、键盘焦点、窄屏、缩放及目标平台 WebView。
5. Center/Admin 类型检查、生成契约检查、构建和核心测试；Rust 格式/涉及包静态检查与定向测试，
   协议导出与 Desktop/Client 消费编译；必要的正式 Host 端到端，避免用模拟通过替代数据库/权限结论。

本方案已确认的具体取舍为：普通权限默认 Allow（显式规则仍生效）、单表幂等与不自动重放、
无知识库目录时接受未解析引用、原值比较防覆盖、可选能力增量及无 Host 数据迁移。
技术方案、交互指导和开发计划已确认。M0 已完成中心与管理端实现及隔离验证，结果待确认；具体完成结论与后续边界见[开发计划](开发计划.md)。

### M1/M2 实现落点补充

反馈 Command 使用 `FeedbackResponse<T>` 返回独立业务结果，保留明确拒绝与 `submission_unknown` 的差别；
不为这些中心业务错误扩展 Runtime 会话错误或把普通读取失败归为注销。`feedback_center` 纯 DTO 和生成 TS 同源。
Credentials 的 `current_center_login` 同时供 Agent、插件和反馈读取当前登录；反馈在此基础上保留代际引用做回执复核。
手动调用附带原 AccessPermit 的取消边界；工具按稳定用户域逐次获取最新登录。面板另有有界等待，停止等待不撤销中心事务。
客户端原生 OS 使用已有 `desktop_platform` 桥接，架构不可得时为空；Web 不根据 UA 猜测系统。
