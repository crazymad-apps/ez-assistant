## 一、入口与组件基线

Desktop/Web 企业用户账号菜单中，在“设置”后增加“反馈中心”，图标复用 Icon 中可区分的反馈语义图标。
菜单顶部用户信息右侧留给 F01 升级入口；反馈入口是普通菜单行，点击关闭菜单并打开一个反馈 Dialog。
个人模式不显示入口。登录有效但 Host 暂不可达时保留入口和明确故障状态；创建操作须等能力检查成功。
中心明确不支持时显示“当前中心暂不支持反馈”，网络失败显示“暂时无法连接反馈中心”并允许重试。
两者不能混淆，也不由反馈面板触发强制升级或注销。

面板以“反馈中心”为标题，默认展示“我的反馈”；新建、详情在同一 Dialog 内切换，
使用返回按钮回到列表，不叠加第二个业务弹窗。关闭后焦点回到账号菜单触发按钮。
沿用 Dialog、Button、SelectionPopover（field 变体）、既有输入框/textarea 和主题 Token；
不引入 Admin 组件库或重设 Desktop 配色。

Admin 在现有导航增加“反馈中心”，使用 `/feedback`、`/feedback/:id` 路由。
布局、面包屑、表格、卡片、表单和状态色沿用 Ant Design 与现有 ConfigProvider Token，
不改 PageLayout，不新增页面副标题或统计概览卡片。

## 二、Desktop/Web 信息布局

面板建议宽 760px，最大宽度为视口减 32px，最大高度为视口减 48px；
小窗口保持标题/底部操作可见，正文独立滚动，不使用固定高度挤掉按钮。
宽度不足 640px 时筛选和双列表单改为单列；长引用允许换行，不撑宽窗口。
尺寸属于反馈面板的布局建议，实际实现依据现有 Dialog 样式核对，不能扩大公共组件 API 只服务此页面。

| 视图 | 顶部 | 主体 | 底部/操作 |
| --- | --- | --- | --- |
| 我的反馈 | 标题、刷新、“新增反馈”、关闭 | 目标类型与状态筛选；列表行显示标题、目标、状态、来源、时间 | 既有分页样式，默认每页 20 条 |
| 新增反馈 | 返回、标题、关闭 | 目标区 → 标题与问题描述 → 可选复现/期望 → 将附带的环境信息 | 取消、提交反馈 |
| 反馈详情 | 返回、标题、状态、关闭 | 目标和编号/时间/来源 → 原始正文 → 处理说明 → 环境信息 | 刷新当前详情 |

列表标题是主要可点击项；目标显示为“平台 / 文件预览”“插件 / 插件名称”“知识库 / 名称”，
列表不铺完整标识和正文，细节进入详情。状态同时显示文字，不只用颜色。
详情中的目标名称、对象引用、具体内容位置均可选中复制；环境信息默认折叠，但新建页可展开预览。
没有处理说明时显示“暂无处理说明”，不能将无说明当作未读取或失败。

## 三、目标表单

目标类型必选，初始未选择，选项为“平台”“插件”“知识库”；避免默认平台造成统计误归类。
切换类型只清除该类型不适用的目标字段，标题、描述、复现和期望保留。
不从标题关键字自动识别类型，也不把目标输入替换成任意标签。

### 平台

对象固定显示“EZ Assistant”，不要求用户再次填写。可选“功能或位置”，例如“会话 / 文件预览”。
版本和系统信息从当前实际环境附带，不能把远程 Host 版本当作本机 Desktop 版本。

### 插件

复用当前用户可见的已安装插件/市场清单提供可搜索选项，显示名称与标识，选择后记录实际对象标识。
可选实际版本与“工具或功能”；如果用户有多个版本或未拿到版本，不默认猜测。
清单加载失败或对象已下架时保留“填写插件标识与名称”的方式，提示用户填实际使用的对象。
手填不表示中心验证过存在；名称仅展示，不能用名称替代已有标识。

### 知识库

填写知识库名称，可选来源提供的“知识库标识或引用”；没有统一目录时不展示假的选择树。
提供“整个知识库 / 具体内容”选择：后者展开“文档/条目标识或位置”和可选章节说明，
至少填写一个能定位具体内容的引用或位置。前者允许仅反馈整个知识库的问题。

未填写稳定引用时，表单就近提示“将按名称记录，后续可人工核对”；详情显示“手动描述的对象”。
有引用时显示“来源引用”，不显示“已验证”徽标。URL 只作为定位文字保存，不自动预览或抓取。
不提供文件选择、截图上传或自动读取文档按钮。

## 四、提交、重试与离开

标题和描述必填；目标按类型校验。错误贴近对应输入，提交后焦点移到第一个错误项。
字段字符上限与整份内容字节上限见技术方案；接近总上限时显示剩余空间，超过时说明“内容过长，请精简后提交”，
保留全部草稿，不静默截断。多行输入 Enter 换行；不设置容易误触的全局 Enter 提交快捷键。

点击提交后冻结本次内容并显示“提交中…”，禁用重复提交和目标编辑。
单次等待有界；等待期间防止返回/关闭误丢回执，应用窗口关闭或身份切换仍可能发生，不能宣称会回滚中心。
收到中心可靠回执后进入详情，显示“反馈已提交”及真实编号；单纯发出请求或接收 HTTP 连接不显示成功。

| 结果 | 页面行为 |
| --- | --- |
| 字段/内容错误 | 保留草稿，定位错误；修改后再提交 |
| 明确未发送或中心明确拒绝 | 保留草稿和原因，允许修正或重试；同内容重试复用原标识 |
| 已发送但结果未知 | 保留冻结内容，显示“尚未确认提交结果”；主操作为“检查提交结果” |
| 检查查到本人原记录 | 转详情，显示中心事实 |
| 检查暂未查到 | 显示“暂未查到，可重试本次提交”，重试仍用相同标识和内容 |
| 身份失效 | 交给既有身份失效流程；旧草稿和回执不进入新身份 |

结果未知时不把“暂未查到”写成“提交失败”。如需修改未知请求的内容，明确提示会作为新反馈，
原请求仍可能已提交，优先先核对列表。用户主动关闭有草稿/未知结果的面板时用现有确认交互说明放弃本地草稿；
未知结果额外说明可稍后在“我的反馈”核对。确认关闭才清草稿；不创建离线暂存。
身份切换强制清空页面，旧请求取消只是停止等待，中心归属仍由原身份决定。

## 五、Admin 列表与处理详情

列表沿用现有 Card + Table：筛选项有可见 Label，包括目标类型、对象、状态、来源、提交者和标题搜索。
“对象”按稳定引用精确筛选；无引用知识记录可选“手动描述”，不自动按相似名称合并。
不为筛选单独新增目标目录服务，可从详情复制目标引用后填入筛选框。
分页采用服务端结果，切换筛选回第一页；显示空结果与读取失败的不同提示。

建议列：标题、目标、提交者、来源、状态、提交时间、详情。编号放详情，避免挤占常用列表信息。
详情列固定右侧居中，按钮 size=small；长标题省略，保留可访问完整文字，不重复常驻 Tooltip。
窄窗口允许表格区域横向滚动，页面外框保持可操作。

详情按“反馈内容”“处理”两块组织；宽窗口可左右排列，窄窗口垂直排列。
原始目标/正文只读，处理区只有状态和处理说明，默认载入中心当前值。
说明标注“提交者可见”；选择已解决或已关闭时说明必填。
支持重新打开为待处理/处理中，不另设隐藏状态或指派人。

保存时显示“保存中…”，使用 AdminStore 写入门，禁止并发提交。
成功后读取最新详情；无实际变化则不制造新的处理记录。
发生原值冲突时保留草稿，显示“反馈已被其他管理员更新，请先读取最新内容”，提供“读取最新内容”，
让用户对照最新状态/说明后主动再次保存，不自动把旧草稿套到新数据上。
提交结果未知时先读取最新详情；若当前状态/说明与意图一致，只说明“当前结果已更新”，
不能推断最后一次一定由本人保存成功。
未保存草稿/提交中离开沿用现有 NavigationGuard，不再创建第二个路由 blocker。

## 六、Agent 调用展示

复用现有工具调用行、参数和结果详情。面向用户的名称可显示“提交反馈”，模型正式名称为 `submit_feedback`。
参数详情展示目标与总结，成功详情显示真实反馈编号、目标和状态。
未知结果清楚标为“提交结果待核对”，用户可从反馈中心查看；新调用可能重复，不能显示“自动重试中”。
不产生 `ask_user` 待回答卡片，不增加待办数或全局通知。
显式权限规则要求审批时复用现有审批区，默认权限不新增“是否允许向企业中心提交”的额外确认弹窗。

## 七、视觉、可访问性与验收

- 保留现有字体、字号、间距和状态 Token；新增页面不改变全局主题或 sidebar 玻璃效果。
- Desktop 的类型/状态选择使用 SelectionPopover，Admin 使用 Ant Design Select；各自沿用键盘与焦点机制。
- 图标按钮有可访问名称；返回、刷新和关闭可由键盘操作；加载与结果提示使用既有 status/alert 语义。
- 长正文按文本保留换行，链接/HTML 不自动执行；长对象引用、中文、emoji 不破坏布局。
- 验收覆盖 Desktop/Web 新建 → 详情 → 列表，Admin 处理 → 本人刷新可见，三种目标、字段联动与目标筛选。
- 检查草稿离开、重复点击、未知回执核对、管理员冲突、身份切换迟到响应以及能力缺失/网络失败的不同状态。
- 检查窄窗、125%/150% 缩放、键盘与焦点、独立滚动及 F01 升级入口共存；真实目标 WebView 与浏览器分别说明结果。

技术方案与本稿已确认。M0 管理端实施与当前浏览器验证结论见[开发计划](开发计划.md)；Desktop/Web 用户入口和 Agent 展示仍待后续里程碑。
