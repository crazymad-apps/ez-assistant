# F02 终端技术方案

> 2026-10-10 用户明确“macos 升级暂时搁置，可以封版了”。v0.29.0 按已确认的用户实测结果封版；macOS 升级暂缓并保留为后续补验项，未补写为通过。版本已完成、未公开发布。下文保留设计与实施历史，最终结论以[版本总结](../../版本总结.md)为准。

## 一、现有调用链与状态所有权

依据[功能设计](功能设计.md)。M1 改造前 `TerminalController.#prepare` 调用 `get_agent_shell_settings`；UI 使用其中的固定 Agent 目录。`TerminalSocket` 用 `UserTerminalControl::Open.shell` 创建连接；Host `user_terminal/socket.rs` 和 `shell.rs` 负责解析与启动，PTY 归现有 Supervisor。

改造前 Unix 默认通过 `CommandBuilder::new_default_prog()`，显式 sh 通过 `/bin/sh -i`；Windows 默认在 socket 中具体化为 PowerShell 5.1，启动使用固定白名单程序。原 `Created.shell` 不足以同时表达“用户选了默认”和“真正启动了什么”。

终端选择属于客户端标签的短期意图，实际程序与可用性归 Host；Agent Shell 配置、会话冻结目录与 Runtime 业务状态均不迁入终端。继续单连接单 PTY，关闭完成前不创建替代进程。

## 二、M1：目录、协议与选择（原阶段方案，统一类型调整见第五节）

1. 优先在现有 `user_terminal` 和 HTTP 资源路由内增加只读交互 Shell 目录；复用业务认证、账号上下文、兼容及 Ready 准入。不能为终端查询增加 Runtime 权威配置或借用 Agent 设置语义。
2. 目录与启动共用同一 Host 解析函数和固定白名单，包含可靠的默认来源；过滤不适用、不可执行的程序。启动时再次检查，目录查询成功不保证稍后程序仍存在。
3. 保留 `null` 表示默认的既有意图。新增 zsh/bash 等交互选项时优先评估独立交互枚举，避免扩大 Agent 非交互 `ShellKind` 的执行面；只有这处实际能力差异构成拆分理由。
4. `Created` 返回实际解析的显示信息，客户端分别保存选择意图和创建结果，不用空字符串或首项冒充默认。具体字段在 M1 修改前核对所有 WS 生产者、消费者和 TS 生成器。
5. `SelectionPopover` 未匹配值显示现有占位语义，焦点起点与选中值分离；回归全部调用方，不把这一修正当作代替 Host 目录的完整方案。
6. Shell 切换复用产品 Dialog 确认和既有终端 close/restart；等待回收期间禁用重复选择，保持旧 socket 回调身份校验、背压和取消边界。

M1 已核查所有 WS 生产者、消费者、Windows 终端测试及 TS 生成器。兼容影响：当前 `0.29.0` 为在途版本，不为本版中间字段增加双读双写；若实际涉及已发布外部契约或需要调整兼容下限，先列明影响并取得用户确认。资源快照仍只存启动来源，不增加数据库字段或 Shell 配置迁移。

### M1 已落地契约

- `GET /user-terminals/shells` 返回 `UserTerminalShellEntry[]`，每项 `{ shell, name }`；`shell: null` 是可用的默认入口，`name` 是该入口实际解析的程序名。只返回可执行项，不暴露程序路径；探测复用 Host 有界资源读取预算。
- `UserTerminalShell` 独立承载原终端类型及 `bash`、`zsh`。Agent 的 `ShellKind`、`get_agent_shell_settings` 和存储不变。Open 保留 `shell: null` 默认语义；Created 的 `shell` 是实际识别类型，新增 `shell_name` 描述实际程序，未知默认类型保持 null。
- Unix 先读 Host 的 `SHELL`，缺失才查询系统用户登录 Shell；来源存在但无效时拒绝，不静默回退。默认以确切程序及 `-l` 启动；显式 zsh/bash 按 Host PATH 后 `/bin`、`/usr/bin` 探测，sh 固定 `/bin/sh`，显式使用 `-i`。Windows 默认仍为 PowerShell 5.1，复用既有固定程序探测与启动参数。未知默认程序保留名称，登录参数支持仍受该程序自身约束。
- Desktop 分开保存请求意图、最后成功选择和实际回执。每次重启重新查询同一 RuntimeClient 的目录；创建/发现期间连接换代阻止继续打开，迟到创建会回收。替代 PTY 必须等原连接清理完成，失败保留错误和可重试状态。
- 选择器触发文字使用最后成功回执，默认标签仍标为默认；标签徽标使用实际类型。切换活动进程先用现有 Dialog 确认，新标签不继承上次选择，资源快照不新增 Shell 状态。

## 三、M2：进程局部提示符适配

提示符在 Host 创建交互进程时装配，禁止在 xterm 侧裁剪。先核对实际 portable-pty 默认程序解析、用户启动文件顺序及可执行来源，再确定各 Shell 的有限适配。

| Shell | 方案方向与约束 |
| --- | --- |
| PowerShell 5.1 / 7 | 保留现有 NoLogo/NoProfile 基线，通过启动脚本定义进程局部 prompt；使用当前 Location 的目录尾部、主目录/盘符/UNC 根处理，保留 `PS …>`；用户路径不得拼入可执行脚本文本 |
| bash / Git Bash | 加载原有交互环境后设置局部路径显示；优先替换标准路径提示片段并保留分支/输入标记；动态主题不能无条件用一条 PS1 覆盖，无法可靠适配时明确边界 |
| zsh | 保留登录/交互启动文件顺序，使用 zsh 原生目录提示语义及可用截断能力；如需临时启动文件，只使用本次受管私有文件并随终端生命周期清理，不改全局 ZDOTDIR 或用户文件 |
| POSIX sh | 使用该实现支持的简单局部 PS1；不假设 bash 专用变量、数组或 PROMPT_COMMAND 可用 |
| CMD | 优先内建 PROMPT 的盘符和输入标记；不为显示目录尾部引入驻留程序、命令别名劫持或屏幕输出改写 |
| 其他默认 Shell | 保留真实默认程序及原提示符；不把可执行的默认 Shell 错误映射到已知语法 |

Shell 名称不能由提示符猜测；目录和分支内容要作为数据安全转义，避免含 `$()`、反引号、控制字符等名称触发额外执行或终端注入。保留命令退出码与现有初始化环境，初始化失败给出真实错误。

### M2 实施选择

- 仅在实际 spawn 前配置提示符，目录查询不创建文件。PowerShell 使用固定 UTF-16 EncodedCommand 定义局部 prompt，按文本元素将目录尾名截到 32 字符；CMD 使用 PROMPT 环境变量；不拼接用户路径进入代码。
- bash/Git Bash 保留已有登录/交互启动参数，注入进程局部 PROMPT_COMMAND，只替换标准 \w/\W 目录片段。目录文本通过变量展开传入并清除控制字符，支持时截到 32 字符，保留命令退出状态。启动配置若重写 PROMPT_COMMAND 或禁用 promptvars，以用户配置为准；动态主题不强行接管。
- zsh 在私有临时目录提供 .zshenv/.zprofile/.zshrc 转发文件，按原顺序读取原 ZDOTDIR/HOME 的用户配置；在 .zshrc 后还原真实 ZDOTDIR，使登录后续 .zlogin/.zlogout 保持原目录。precmd 尾部钩子只改标准 %~/%d/%/ 及带目录层数的路径片段，使用原生目录与截断扩展；保留原有 precmd 和主题其他部分。启动文件主动改写流程、关闭 RCS 或主题在钩子之后重绘时保留其行为，不承诺强制适配。
- POSIX sh 通过局部 PS1 按当前 PWD 显示目录尾部、主目录与根目录；用标准 tr 清理控制字符，不假设 bash 专用语法。无可移植字符截断能力时保留完整目录尾名。
- 临时文件归既有 PTY 监督任务所有，创建失败回收、正常/异常退出后显式清理；不增加全局状态、协议或持久化结构。
- 官方语义依据：[Bash 启动文件](https://www.gnu.org/software/bash/manual/html_node/Bash-Startup-Files.html)、[Bash 提示符](https://www.gnu.org/software/bash/manual/html_node/Controlling-the-Prompt.html)、[zsh 启动文件](https://zsh.sourceforge.io/Doc/Release/Files.html)、[zsh 提示符](https://zsh.sourceforge.io/Doc/Release/Prompt-Expansion.html)、[PowerShell prompt](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_prompts)、[CMD prompt](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/prompt)。

## 四、验证边界

- M1 定向覆盖目录与 spawn 一致性、默认往返、显式不可用拒绝、远端平台、连接换代、并发切换、关闭/取消及未匹配选择器值。
- M2 以真实 PTY 验证不同 Shell 的 cwd/退出码/命令输出保持，核对用户启动文件未修改；探测与文本单测不能代替真实 Shell。
- 集成测试只使用项目 `.runtime-test/` 下新建隔离 Runtime Home；不停止用户终端，不写日常数据库，不借机重新部署 F06。
- Windows 平台缺失、未知主题或平台原生验收未执行时，作为明确遗留提交确认。M0 展示工作不以这些后续实现细节为前置。


## 五、M2 补充：统一可选类型与 Agent 入口

用户于 2026-09-30 明确默认 Agent Shell、会话上下文与交互终端的显式类型应一致。最终契约统一采用已有 ShellKind，新增 bash/zsh，移除 M1 在途的 UserTerminalShell 枚举；null 仍只在交互入口表达系统登录 Shell。UserTerminalShellEntry、AgentShellSettings 继续服务各自已有投影，不新增同版别名。

Host resources::shell 持有唯一固定程序目录与可执行检查，交互终端只从同一目录构建选择项。Unix 优先 PATH 后 /bin、/usr/bin 探测 bash/zsh，sh 固定 /bin/sh；非绝对或不可执行文件不接受。Agent bash 使用 --noprofile --norc -c，zsh 使用 -f -c，模型收到对应方言与实际路径快照；原有环境过滤、权限、串行队列、失败保持绑定、Run/child 冻结均复用。交互启动参数和提示符适配保持原语义。

两个 Agent 入口移除 Unix 平台禁用及排除 sh 的过滤，只展示可用类型；已绑定但不可用的值仍保留真实标签与错误。设置页只改变后续新会话的默认，会话页通过既有 agent_shell_switch 切换/刷新，不乐观伪造成功。Unix 未设置默认与旧无绑定会话仍保持 /bin/sh，不跟随系统登录 Shell 变化。

持久化保持既有字符串/JSON 与表结构字段，v0.29.0 最终迁移仅扩展三处 CHECK 白名单，逐列复制与核对后替换原列，整体事务和独立备份归现有迁移执行器。旧值、NULL、input_kind 限制、主外键与账本保持。应用/数据库最低兼容仍为 0.29.0；正式旧版本升级复用正常版本迁移。已记账为 0.29.0 的旧在途用户库须单独对齐，不引入永久同版修补分支；最终校验会拒绝该旧结构，不能直接用新 Host 重启并假称可用。

当前 17241 使用的既有用户库曾为上述旧在途结构；2026-09-30 经用户确认，已完成独立数据库与会话文件备份核验、事务内白名单对齐及 Host 重启，原有数据保持。代码在新建隔离 Runtime Home 中完成默认/会话切换、目录一致与真实执行验证；用户已确认当前客户端重新登录并进入项目成功。
