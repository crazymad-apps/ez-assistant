## 四、里程碑安排

### M0 基础续接与恢复

- **目标与前置**：设计和计划确认后，完成个人连接可使用的基础闭环。涉及持久化变化时，先核清历史数据及旧 Host 读写影响，确定并确认兼容处理后再实施。
- **交付范围**：连接能力与开关、个人设置入口、首次全量与后续增量发送；响应 ID 随可靠消息保存；Host 重启后恢复。工具调用与结果保持配对，不重复发送或执行历史工具；默认关闭和不支持的接口保持原行为。
- **验证入口**：Adapter 请求测试、Runtime 消息落账与重启恢复测试、个人设置操作；重点覆盖功能验收 A01—A05、A11 的个人模式部分。
- **完成判定 / Review**：同一会话完成文字及工具交互后，重启仍能使用已保存 ID；未完成响应或落账失败不能产生有效续接点。状态随现有消息保存，不新增第二套会话存储。

### M1 上下文重建与隔离

- **目标与前置**：M0 获确认后，完成续接失效与上下文变化的处理。
- **交付范围**：压缩成功后用摘要和保留消息重建；模型切换自动重建，覆盖 A→B→A 无中间调用；配置、身份、历史变化使旧链失效。隔离主会话、子任务、Fork 和辅助调用；明确旧 ID 不可用时最多自动重建一次。
- **验证入口**：Runtime 确定性测试及隔离 Host 场景；重点覆盖 A06、A07、A09、A10，以及部分流、取消和预算保持。
- **完成判定 / Review**：重建输入来自本地有效上下文；失败压缩和普通重启不误清旧链；网络、认证或流中断不被误当作续接失效，不重放工具副作用。

### M2 企业模式接入

- **目标与前置**：M1 获确认后，让企业托管连接具备相同能力及中心侧约束。
- **交付范围**：管理员连接表单、配置保存与下发、企业用户只读展示、发送前身份/策略/配置校验。中心上游模型、地址或密钥改变时拒绝旧绑定；关闭策略不能被客户端绕过；同主体重新登录及中心重启可恢复有效续接。
- **验证入口**：Center 定向单元/集成测试，Admin 表单测试，Host 经代理调用；覆盖 A01、A08、A09、A11 的企业模式部分。中心迁移先评估旧数据和部署影响，验证仅使用已核实的隔离库。
- **完成判定 / Review**：管理配置到模型请求的整条链路一致，失效请求在转发上游前被拦截；代理地址不变不能掩盖上游变化，登录 Token 更新也不能误判为换模型。

### M3 F06 整体验收

- **目标与前置**：M2 获确认后，按功能设计 A01—A12 完整验收 F06。
- **交付范围**：回归个人/企业配置、增量工具结果、重启、压缩、模型切换及失败恢复；核对持久化兼容、协议生成与长期模块约束。确认现有消息展示不改变模型输入，不依赖尚未开发的 F03/F05。
- **验证入口**：隔离 Host + Desktop/Web + 企业中心联调；使用获授权凭据，对 OpenAI 和百炼适用路由分别验证续接与重建。检查不支持续接的接口仍正常工作，用量仍以服务商返回为准。
- **完成判定 / Review**：A01—A12 均有实际结论；真实接口或平台无法验证时明确记录限制，不能用模拟结果代替。必要检查通过、遗留获用户接受并确认后，F06 才标记完成；不代表 v0.29.0 可发布。
