## 二、背景、目标与非目标

目前 Responses 每次发送完整本地有效上下文，固定 `store: false`。部分服务商支持
`previous_response_id`，允许上传新增内容；其他接口即使使用 Responses 格式，也不能省略历史。

本 Feature 的结果是：用户或管理员按服务商连接启用续接，程序在合适的请求中只上传增量，
本地仍完整保存可重建的有效上下文。压缩、模型切换及确实失效时自动重建；普通应用/Host
重启后恢复已保存的续接状态，状态一致时继续使用。

不纳入：Conversations API、服务端自动压缩或 `/responses/compact`、个人直连 WebSocket 模型传输、
新的压缩算法、轮内剪枝、远端历史管理/删除页面、跨服务商迁移加密状态、运行中即时热换模型。
“增量”指网络请求历史部分，不承诺历史 Token 免费、窗口变大或缓存必然命中。

## 三、能力与配置

### 3.1 归属

- 服务商身份与选定协议提供能力默认值；HTTP 原生能力表示接口支持响应存储和按响应 ID 续接；企业 WebSocket 桥接表示连接内接续可用，
  仅接受 `store` 参数不足以声明支持。
- 具体服务商连接拥有“使用服务端历史续接”开关，默认关闭，延续现有行为。
- 高级配置提供“续接能力：使用服务商默认 / 明确支持 / 明确不支持”。用于代理或自定义
  接口的显式差异，不依据请求成功自动推断，也不因模型名称相同继承其他部署能力。
- 不给每个模型重复增加 store 开关，不暴露原始响应 ID 或允许通过通用 Provider Options
  绕过策略。首版模型不支持时返回可解释错误；用户可关闭该连接的续接，不自动切换协议。
- 企业连接由管理员设置，普通企业用户只读；个人连接由现有 Desktop/Web 模型管理维护。
  CLI 若消费共享连接 DTO，须保持读写完整性，但不新建专用 CLI 续接控制命令。

### 3.2 首版默认能力

以下是 2026-09-28 官方文档核查及本版默认策略；账户、区域、套餐和代理差异仍需真实接入验证。

| 接口身份 | 默认判断 | 原因 |
| --- | --- | --- |
| OpenAI Responses | 支持 | 官方提供保存响应和 `previous_response_id` 续接 |
| 百炼 API 的 Qwen Responses | 支持 | 官方声明保存响应后可续接；不泛化到 Coding Plan 或任意兼容部署 |
| 百炼 Coding Plan | 未知，默认不启用 | 不把 API 渠道能力复制到不同套餐端点 |
| DeepSeek Responses | 不支持 | 官方声明无状态；不支持历史续接，部分未知参数会被忽略 |
| Kimi Responses | 不支持 | 当前字段说明中 store 固定 false，previous_response_id 固定 null |
| GLM 普通 Chat Completions | 不支持本功能 | 当前接入协议携带 messages，不使用 Responses 续接 |
| Local / vLLM / 未核实代理 | 未知，默认不启用 | 不从 OpenAI-compatible 名称推导支持 |

官方依据：[OpenAI 会话状态](https://developers.openai.com/api/docs/guides/conversation-state)、
[百炼 Responses](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-responses)、
[DeepSeek Responses](https://api-docs.deepseek.com/guides/responses_api/)、
[Kimi Responses](https://platform.kimi.com/docs/api/responses)、
[GLM 对话补全](https://docs.bigmodel.cn/api-reference/模型-api/对话补全)。
自定义 endpoint 不属于已核实的服务商部署时，默认能力降为未知，需显式声明；地址校验只
确认既有服务商接入配置是否匹配，不引入模型名前缀猜测或新的协议自动回退。

### 3.3 配置交互

在现有服务商连接表单的协议设置附近增加开关；高级配置中放能力覆盖和解析结果。

| 状态 | 展示及行为 |
| --- | --- |
| Responses 且能力支持 | 开关可操作，说明“开启后由服务商保存响应，用于后续增量续接；本地仍保留会话” |
| Responses 但未知/不支持 | 开关关闭且不可开启，显示原因；高级覆盖可显式声明实际接口能力 |
| Chat Completions | 不可启用；不能通过能力覆盖绕过协议限制 |
| 企业托管普通用户 | 显示“由企业管理员管理”及当前有效状态，不提供本地覆盖 |
| 编辑时从支持协议切到不支持 | 草稿同步关闭并提示；保存前可撤销，不静默保留无效开启值 |
| 保存失败/旧服务端不识别配置 | 保留草稿并显示错误，不假装保存成功或静默丢弃新字段 |

启用属于一次配置选择，不要求每条模型请求再次确认。关闭后下一次允许执行的请求使用
本地有效上下文，不再引用旧 ID；再次开启建立新链，不捡回关闭前的链。关闭功能不承诺
删除服务商已有数据，数据保留规则由服务商决定。

## 四、正常调用、重建与重启

### 4.1 首次与后续调用

1. 首次调用发送完整有效上下文并启用接续；HTTP 原生要求保存响应，Center WebSocket 按连接内状态建链。
2. 完整响应及其续接凭据随本地 Assistant 消息可靠提交。工具调用仍先落账再执行，工具
   结果齐备后形成完整交换；模型返回 ID 不能替代这些可靠点。
3. 下一次调用校验身份、连接、模型、上下文及已提交边界；一致才发送旧 ID 和新增消息/
   工具结果。请求中的当前 instructions、工具定义及生成参数仍按接口要求发送。
4. 没有可用续接凭据时使用完整有效上下文建立新链，不要求用户新建会话。

完整有效上下文包含当前指令、压缩摘要、保留消息、完整工具交换及目标方言需要的状态；
不等同于从会话开始至今的全部未压缩历史。

### 4.2 触发规则

| 事件 | 处理 |
| --- | --- |
| 关闭/重开窗口、Desktop 重启 | 不影响 Host 上的有效续接事实 |
| Host 重启后恢复同一用户/会话 | 从可靠消息恢复凭据，边界一致就续接；不以重启为失效原因 |
| Center 重启、同一用户重新认证 | 先通过现有身份校验；仅 Token 字符串变化不等同于上游模型身份变化。Center 重启丢失的 WebSocket 链按明确失效重建，HTTP 原生链仍尝试旧 ID |
| 本地压缩成功提交 | 新上下文不再引用压缩前链；发送摘要和保留消息重建 |
| 压缩取消或未提交 | 旧上下文仍是权威，不仅因为尝试过压缩而销毁可用链 |
| 切换模型，包括同服务商切换和 A→B→A | 切换成功即使旧链失效；下次调用自动重建，中间没有调用也不能恢复旧链 |
| 更换上游 endpoint/密钥、协议、有效连接或身份主体 | 旧绑定失效，重新检查配置和权限后重建 |
| 更改影响请求的指令、工具、reasoning 或输入投影 | 无法证明旧前缀等价时重建，不把新历史追加到不相容的链 |
| 会话 Fork / 历史重写 | 仅使用新 owner 和当前有效上下文，不能凭复制过来的 ID 延续源会话 |
| 服务端明确报告旧 ID 不可用 | 未开始本次生成的可识别拒绝可触发一次自动重建；不把任意错误都当作过期 |
| 流中断、取消或响应结果不明 | 不采纳不完整响应的新 ID；按既有失败/恢复规则处理，不透明重放 |

模型切换沿用当前接纳限制：活动执行或排队输入不允许切换时仍保持禁用；本 Feature 不
擅自中断当前 Run。企业默认模型变化沿用中心配置失效流程，原任务是否自动重新接纳不扩大。

### 4.3 压缩与辅助调用隔离

摘要生成、标题生成、辅助识图和连接测试都是独立调用，首版不启用服务端续接或存储。
这些调用不读写业务续接凭据，不能把摘要请求 response ID 作为主会话链头。
主会话与每个子任务独立保存/校验续接事实；并发子任务即使共享模型服务对象也不共享链。

### 4.4 失败及可观察结果

- 认证、限流、网络故障、上下文超限保持现有错误分类，不能通过删除 previous_response_id
  重发来掩盖问题。窗口超限仍交现有压缩流程。
- 服务端明确拒绝历史续接且尚未产生模型输出时，Runtime 可在同一逻辑 Run 中一次重建；
  重建仍失败则返回明确错误，不能无限循环或改走其他接口。
- 诊断记录区分完整发送、增量续接及重建原因，复用既有观察/调试入口，不新增面向用户的
  常驻状态面板。不显示原始响应 ID、密钥、完整 prompt 或未经脱敏的服务商错误。
- 用量继续以 Provider 返回为准；不能将增量请求体大小当作上下文占用或扣减历史计费。

## 五、持久化、权限与兼容边界

- 续接凭据复用已有 `AssistantPart::ProviderState`，随 AssistantMessage/工具交换进入
  既有可靠存储，不维护独立 response 表或第二份消息记录。
- 凭据只有在可靠 Conversation 边界中出现才可使用；仅在内存收到、pending 未闭合或
  部分 SSE 输出都不能成为可续接历史。重启先执行既有 pending 恢复，再决定能否续接。
- 需要保存必要的配置与失效标记来识别切换和后台路由变化；具体字段在实施前确定。
  不能把内存 Arc 地址或进程启动时间作为持久化身份。
- 企业中心必须检查续接请求对应当前已授权配置。只在 Host 做能力判断不构成策略执行，
  普通用户不能用手工构造 store/previous_response_id 绕过管理员关闭的策略。
- 既有本地/中心持久化数据需要默认关闭新功能的迁移；所有新旧读写方都纳入评估。
  本稿不直接抬升软件或协议兼容下限，不授权操作生产/共享数据库。
