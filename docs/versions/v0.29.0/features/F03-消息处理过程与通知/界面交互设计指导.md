# F03 界面交互设计指导

> 2026-10-10 用户明确“macos 升级暂时搁置，可以封版了”。v0.29.0 按已确认的用户实测结果封版；macOS 升级暂缓并保留为后续补验项，未补写为通过。版本已完成、未公开发布。下文保留设计与实施历史，最终结论以[版本总结](../../版本总结.md)为准。

## 一、依据与视觉方向

依据[功能设计](功能设计.md)。沿用现有 Desktop 字体、三档字号、灰阶文本、表面与焦点 Token；应用内过程是低干扰的纵向信息层级，最终回复保持正文视觉权重。设计重点是“过程可收、结果易读、待办可达”，不改变页面壳层或侧栏。

## 二、消息布局

```text
用户输入
处理过程  等待审批  1分24秒
  summary 最新文本…
  思考过程       普通 reasoning 最新文本…
  [文件图标] 读取文件
  中间说明
最终回复正文
复制  分叉                         完成时间
```

外层头部为语义按钮，包含处理过程、状态与耗时，不显示箭头。过程标题、reasoning 与工具组使用正文标准字号；状态和耗时紧跟左侧标题排列，工具折叠标题仅显示类型图标与最后一条动作，不显示数量、状态。耗时数字等宽且不因每秒增长推挤标题；窄宽度状态可换行，时间保持可见。完成收起不收走最终回复。失败和中断原因放在折叠外可读区域，取消只在头部显示“已取消”，不另加重复提示；审批/问答继续使用底部现有唯一面板，不嵌入不可见折叠内容。

处理过程、工具组及 reasoning 原文标题均不显示展开／收起箭头，仍支持点击和键盘切换。reasoning 原文模式按钮可展开、内容独立滚动；summary 模式复用现有安全 Markdown 渲染，支持加粗、斜体和行内代码，沿用单行局部跟随；仅直接显示摘要内容，不显示“思考过程／思考摘要”标题、箭头或内层折叠区域。右侧最新行局部跟随末尾，减少动态效果下直接显示最新片段。两者不抢主消息列表的滚动位置。手动收起优先于同消息增量；真正新中间消息自动展开。所有展开动画沿用 Collapse，首次呈现不补播。

过程／工具／原文头部沿用小尺寸控件的最小高度，并允许内容自然撑开。展开工具内容顶部留 6px，明细之间留 4px；不同过程条目使用下述 12px 间距。

过程条目间距为 12px，保持正文标准字号。工具组默认收起，仅连续调用合组，标题采用最后一条动作与类型图标，不显示数量或状态。展开项取消内层竖线与缩进，图标和文字与标题左对齐，统一 16px 图标、14px 常规字重正文；状态保留在具体工具明细中。工具明细 hover 与组头一致，仅加深文字与图标颜色，不显示背景色，保留键盘焦点轮廓。展开后沿用详情入口、完整授权范围及子任务导航，不能把“组收起”解释为操作取消或结果成功。

## 三、通知入口

系统通知由平台决定外观，M0 只统一会话标题与可读正文；没有自制系统横幅。失败/审批/问答的动作原因写在正文前部，正文尾部截断不丢失状态。

应用内待处理入口位于工作台壳层顶部可用区域，与侧栏显隐无关。存在事项时显示“待处理 N”，展开紧凑列表，来源会话标题在前、审批/待回复及操作摘要在后。沿用现有 AnchoredOverlay/Popover 的定位、键盘与焦点恢复；窄屏限制到视口内，内部列表滚动。新事项短提示只占少量空间，可关闭且不抢焦点；关闭后待处理入口保留。无事项时隐藏入口，不新增空白通知中心。

点击条目后复核并进入唯一操作区，已失效显示最新状态提示；查询中保持禁用反馈，失败允许重试。子任务审批明确其来源但定位父审批区。当前正在阅读来源会话时不重复弹出短提示。

## 四、交互验收

检查键盘 Enter/Space、aria-expanded/controls、焦点恢复和长中文/代码/路径；100%、125%、150% 缩放及窄窗口无水平溢出。验证手动自由滚动、历史补页与引用定位不因折叠丢失锚点。原生资源 WebView 的浮层遮挡遵循既有 overlay root 规则。

M0 不改变 DOM 布局；M2 过程展示和 M3 应用内提醒已完成当前环境验证，用户反馈的布局修正已纳入最终实现。浏览器及组件验证不替代原生平台验收；收尾结论与未实测范围统一见[开发计划](开发计划.md)。
