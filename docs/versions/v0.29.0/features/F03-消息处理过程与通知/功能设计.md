## 二、目标与非目标

用户能看见每轮处理进展与耗时，收起细节后仍能阅读最终回复、发现异常并处理审批/问答；在其他会话阅读时，也能进入正在等待自己的事项。系统消息通知直接展示来源会话标题和对应回复。

不改 Agent 执行、可靠对话、上下文重建或侧栏状态；不额外调用模型生成摘要，不新增通知数据库、历史通知中心或业务阻塞状态，不改系统权限和前后台投递规则。

## 三、功能路径

### 消息与处理过程

- 一轮展示以可靠 Run 为主边界；同一 Run 的模型 Step 是内部过程，不能把 Provider 的单次 Turn 当作用户轮次。不同 Run 不强行合并；压缩分隔、重试和子任务保持既有归属。
- 中间正文、reasoning、工具和委派入口按发生顺序进入“处理过程”。终态保留最后一条含正文的助手消息独立展示，即使该消息包含 ask 等工具调用或后续只有工具/思考片段；运行中的最新正文先正常可见，后续工具调用证明其为中间输出时再纳入过程，不能为了猜测最终回复而隐藏全部输出。
- 新的中间消息到达自动展开；同一消息的 token 或工具输出增量不撤销手动收起。可靠完成后自动收起。历史加载默认收起，不当作新消息；失败/取消收起，允许再次展开；取消仅在头部显示状态，不重复显示取消提示，失败原因仍常驻。
- 头部一直显示状态和经过时间；从 Run 接受到终态，包含排队、重试和等待。活动等待注明“等待审批/等待回复”。Run 已完成但问答仍 pending 时耗时冻结，等待入口继续保留。
- 有明确 summary 来源时直接显示 summary 文字，不显示标题、箭头或 reasoning 内层展开；否则原文可展开。收起行显示最新可读文本并仅滚动该行。外层处理过程始终可展开。
- 连续工具显示默认收起组，组头仅含最后一条工具动作名称与类型图标，不显示数量和状态；正文/reasoning 截断分组，不跨内容重排。原参数、结果、子任务与父审批入口保持可达。

### 系统通知内容（M0）

| 触发 | 标题 | 正文 |
| --- | --- | --- |
| Run 正常完成 | 来源会话标题 | 该 Run 最后一条可靠助手消息的正文；没有正文则“本轮已完成，暂无文字回复。” |
| Run 失败/中断等非取消终态 | 来源会话标题 | 固定状态提示，附同一 Run 最新可靠助手正文（如有）；不显示原始异常 |
| 工具审批 | 来源父会话标题 | “需要审批：工具名称。点击查看并处理。”；不展示命令/参数 |
| 用户问答 | 来源会话标题 | “等待回复：”与该 request 的第一题，有多题时附题数 |

取消继续不发系统通知；end_turn 问答继续抑制重复完成通知。正文只用 text，不把 reasoning、工具结果或用户输入作为回复。无标题用“未命名会话”。标题最多 64 个 Unicode 码点，正文最多 180 个（含省略号）；Markdown 取可读文本，不显示图片/链接目标或 HTML 标签。系统实际容量仍由平台决定。

按事件冻结 Session/Run/事项身份，异步内容查询不使用当前阅读会话，也不使用更晚 Run 的结果。归属校验失败丢弃；正文读取失败使用状态兜底，来源会话不可读则不投递。前台事件正常消费、不转后台补发，内容查询完成后再次核对开关、身份、事项及焦点。

### 应用内通知（M3）

应用壳层提供独立于侧栏的“待处理”入口，仅在存在事项时显示数量。列表按来源会话聚合、事项逐项定位；新发生且来自其他会话时弹出短提示，关闭提示不移除未处理事项。后台系统通知与应用内入口彼此独立，不以系统通知开关控制应用内可达性。

点击复核当前身份与权威事项，再打开来源会话；子任务审批进入父会话唯一审批区。已处理/失效显示最新状态，不复活旧操作。启动、重连和事件缺口以权威快照恢复 pending 列表，不重放历史提示。退出/切换 Host 或账号清除旧投影。

## 四、边界与验收

UI 仅持有折叠、定位和通知投递状态。审批、问答、Run 时间与消息归属由 Runtime 决定；不将 UI 文本写回 Conversation，不影响 F06 续接。

验收覆盖：多会话/连续 Run 不串内容；无正文、失败、权限关闭、前台、异步切换、已解决事项；过程新消息/增量/终态、重新挂载/历史分页/压缩/子任务；系统通知关闭、项目收起、侧栏隐藏、重连、过期事项点击。平台通知横幅与原生点击必须分别报告实测结果，不能用浏览器构造成功替代。

## 五、风险与后续门禁

M1 实施前 reasoning 只有 text，没有可靠 summary 类型；消息投影开始时间为空。不得通过猜测 part ID、文字内容或组件挂载时间补造事实。M1 先补齐最小投影及来源契约并确认兼容影响，M2 再完成折叠 UI。具体见[技术方案](技术方案.md)与[开发计划](开发计划.md)。
