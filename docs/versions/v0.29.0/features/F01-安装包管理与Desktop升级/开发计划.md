## 二、台账原则

1. 2026-10-02 用户授权自主推进到 M2，本轮连续实施 M1、M2 并分别验证和报告；M3 仍需另行确认。未获跨里程碑授权时，每个里程碑完成实现与验证后先标为 `🟨 待确认`，用户明确确认后标为 `✅ 已完成`，再进入下一步；M3 同时承载 Feature 验收。
2. 每步交付可运行、可独立验证的结果。本步涉及的权限、持久化、进程交接与失败恢复在本步验证；M3 只补平台和联合场景，不收纳未验证骨架。
3. 具体接口、字段、状态、依赖和页面布局以已确认设计为准，本计划不重复展开。优先复用现有能力，校验只做必要的一次处理，不增加全量解包、试运行或反复扫描。
4. F01/F04 已获并行排期授权。接入前读取共享文件最新内容，重叠修改串行整合；重点核对 Center 注册/OpenAPI、Admin 导航/生成 SDK、Host/共享协议、AccountMenu。F04 已使用 `006-feedback.sql`，F01 按实施时最新账本分配独立迁移编号。
5. 验证使用项目 `.runtime-test/` 下新建的独立目录、数据库、端口和 Runtime Home。首次写入前核对实际主机、端口、库、表、影响范围及应用读取路径；遵守根 AGENTS 对一次性隔离库的持续授权和异常处理规则。
6. 本计划不包含更新现有 7320 Center、17241 Host 或日常用户目录。数据库实际目标、影响、备份情况和验证结果在会话中汇报，不把数量、日志或快照堆入计划，不另建验证报告。
7. 开发夹具使用隔离测试签名材料；正式发布公钥及私钥保管必须在候选包验证前落实，不能把测试密钥带入正式产品。未执行的平台安装如实保留，不以构建成功代替。
8. 保留已有工作树改动，不主动提交、推送、部署或发布。发现设计假设不成立时先停止扩大改动，修订对应方案并确认。

## 四、M0 企业安装包发布闭环

**目标**：企业后台可以管理真实发布文件，后续 Desktop 直接接入可用分发能力。

**交付范围**：

- 在现有平台发布脚本中生成最终制品、小清单及签名；统一随包 Host 发布信息的取值，校验成本随上传流合并处理。
- 版本与平台记录、独立增量迁移、私有文件存储、管理权限和审计接入；支持草稿上传、按平台发布、撤回和更新说明编辑。
- 登录前最小只读发现与已发布文件下载，HTTP/HTTPS 均可使用；隐藏草稿与撤回内容，保留已发布制品不可覆盖的边界。
- 正式 Admin 的安装包导航、列表、详情、文件上传和发布操作；同步 OpenAPI 与完整生成 SDK，不覆盖 F04 已接入契约。

**验证入口与必要命令**：

- 使用实际构建生成的清单和隔离签名夹具，交叉验证签名格式、文件错配及元数据篡改；覆盖流式上传中断、超限、失败清理和并发草稿修改。
- 新建隔离 PostgreSQL + Center，通过真实 API 和 Admin 页面完成上传—发布—发现—下载—撤回；核对匿名/普通用户/管理员边界、审计一致性、重启持久化和文件可用性。
- 在 Center 执行 `npm run typecheck`、`npm run lint`、`npm run openapi:check` 及相关单元/隔离集成测试；在 Admin 执行 `npm run build`、`npm run lint` 和相关单元测试。构建脚本与 Host 发布信息改动执行相应定向检查，不为无关模块重复全量测试。

**完成判定**：管理员操作能够改变真实发布状态，发现接口只选出适用且可下载的已发布包；文件、数据库和接口结果一致。篡改、越权及发布竞态不产生可见坏包；发布和定时发现不重复扫描整个安装包。当前环境已完成实际页面及分发验证，其他平台制品验证范围如实说明。

**Review 重点**：技术字段来自受信构建产物；文件和数据库各自失败边界明确；不新增通用包管理平台、上传任务表或后台扫描服务。发布签名与操作系统代码签名不混为一谈。

## 五、M1 Desktop 普通更新与本机交接

**目标**：用户看到更新入口后，一次确认即可完成下载、安装、重启和原数据接续。

**交付范围**：

- Host 登录前更新上下文、共享协议及原生更新管理接入；企业中心确定后检查一次，运行期间每 5 分钟检查，休眠恢复和并发检查合并。
- 账号菜单有可用更新时显示按钮，独立面板展示更新说明及“更新并重启”；下载进度、取消、收起重开和失败重试沿用同一操作。
- 有界下载与必要校验完成后，受控停止当前在用本机 Host，确认退出再安装；新版使用同一 Runtime Home 启动随包 Host，重启后核对实际结果并处理失败恢复。
- Windows 单实例与安装器重启接入；重复启动恢复原窗口，开发/正式隔离，与 F02 窗口生命周期保持一致。

**验证入口与必要命令**：

- 定向验证检查调度、来源切换后的迟到结果、入口显隐、下载取消/损坏、停止失败和恢复记录；模拟时间用于检查调度，不靠等待多轮五分钟完成测试。
- 使用新建隔离 Runtime Home 和真实 Host，在当前可用原生平台完成一轮签名旧候选到高版本候选的实际更新，核对下载失败不停止 Host、本机不同安装来源交接、原数据保留及随包 Host 实际启动。远程连接确认不会停止远端 Host。
- 执行涉及 Rust 包的测试和 Clippy、`cargo fmt --all --check`；Desktop 执行 `npm run build`、`npm run lint` 及相关测试，核对共享协议所有实际消费者。当前平台原生构建使用 `npm run tauri -- build --no-bundle`，实际安装另用对应发布脚本生成候选包。
- Windows 实际验证并发冷启动、隐藏/最小化后唤起和安装重启；若当前没有相应设备，明确列为 M3 必补平台项，不宣称单实例实测通过。

**完成判定**：当前可用平台的普通更新完整跑通，重启结果来自实际版本和 Host 状态；失败不会跳过校验、误停其他实例或以旧二进制访问不允许的数据。UI 没有手动检查按钮、无更新占位、版本/架构选择或额外 Host 接管确认。

**Review 重点**：更新操作由原生层唯一持有，关闭面板不重复启动；不将任务是否空闲、原 Host 来源变成升级门槛。进程退出、安装交接和原数据准入仍沿用现有可靠事实。

## 六、M2 登录前强制更新

**目标**：中心明确当前版本不能继续使用时，用户可以在登录前完成更新；普通故障不被误判为必须更新。

**交付范围**：

- 拆清 Center 明确不兼容、非法响应、网络失败和身份错误，贯通 Host、原生层与登录页；启动及运行中均使用同一准入判定。
- 门禁复用 M1 的更新发现、面板和安装操作，仅在有可用更新时显示更新按钮；未提供可用包时保留简短真实说明，不要求用户判断兼容细节。
- 登录前匿名发现/下载、当前来源切换、关闭面板及重新连接后的门禁保持；个人模式、旧 Host 和远程 Host 按既有设计处理。

**验证入口与必要命令**：

- 隔离 Center + 正式 Host + Desktop 验证启动和运行中触发、无可用包、撤回、断网、密码错误、非法协议声明和身份切换；完成一次门禁到升级后正常准入的实际闭环。
- 检查退出或重开面板不能恢复被禁止的业务，旧来源结果不能污染新连接；登录前发现不依赖已登录会话，也不泄漏管理数据。
- 执行受影响 Rust 包及前端定向测试、静态检查和 Desktop 构建，沿用 M1 验证入口；只有新增改动或未解决风险需要时才重复完整安装场景。

**完成判定**：只有明确不兼容触发更新门禁，其他错误仍走各自原有处理；无登录凭据时仍可完成允许的更新。普通更新和强制更新共用一条执行路径，门禁不因 UI 操作被绕过。

**Review 重点**：错误保真而不增加通用故障分类框架；用户只看到需要更新及下一步操作。不得把旧 Host 缺少更新上下文猜测为中心不兼容。

**目标**：完成剩余平台实测和跨 Feature 场景，按真实覆盖范围验收 F01。

**交付范围与验证入口**：

- Windows x64、Windows arm64、macOS arm64 分别核对最终制品、签名、安装身份、升级后实际版本和同一 Runtime Home 的随包 Host；真实设备或对应运行环境安装，不以交叉编译替代。
- 区分旧公开版首次手工升级与已支持更新版本的后续在线升级；macOS 覆盖签名公证后的原位替换及只读位置失败，Windows 覆盖单实例、当前用户安装及安装器重启。
- 结合 HTTP/HTTPS，补齐 M0—M2 尚未覆盖的安装失败、Host 停止超时、新版启动及数据准入失败恢复；已有有效验证不机械重跑。
- 回归 F02 窗口/终端、F03 待处理入口、F06 上下文恢复与历史工具不重放，以及 F04 账号菜单及共享契约共存。按其他 Feature 当时实际完成范围验证，不擅自改写其验收结论。
- 执行受最终整合影响的核心回归与发布检查；按[功能设计](功能设计.md)第九节逐项核对，并同步必要的模块约束、发布说明、Feature 与版本台账。

**完成判定**：各平台实际完成与未完成项明确，关键升级路径和失败恢复没有未说明的缺口。没有相应平台环境时保留具名限制，由用户根据实际结果决定验收，不将未执行项写成通过；用户确认后 M3 与 F01 才标为完成。

**Review 重点**：更新结果、用户数据、恢复状态与界面描述一致；校验保持轻量。收尾不扩大为灰度、差分、降级、CLI 更新、自动发布或新平台支持。
