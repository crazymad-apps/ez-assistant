## 一、设计原则与现有组件

用户只需要理解“有更新”和“更新并重启”。沿用现有 Desktop 与企业后台各自的视觉语言：更新入口安静、操作集中，技术字段只在管理员详情中按需查看。无新增主题、统计卡片、更新中心首页或版本选择器。

| 范围 | 复用与视觉约束 |
| --- | --- |
| Desktop | `AccountMenu`、`Dialog`、`Button`、`Icon`、既有 MarkdownContent；正文 14px、辅助文字 12px、标题 16px，系统字体 |
| Desktop 色彩 | 现有 Token：主色 `#496cf2`、正文 `#252932`、次要文字 `#5f6673`、表面 `#ffffff`、边框 `#e2e5eb`；代码引用 Token，不复制色值 |
| Enterprise Admin | Ant Design 6 的 Table/Form/Upload/Modal/Descriptions/Tag，既有 PageLayout 与面包屑 |
| Admin 色彩 | 现有主题：主色 `#2e81d8`、正文 `#26303c`、次要文字 `#687389`、背景 `#eff4fa`、表面 `#ffffff`；不改全局 Token |

布局以左对齐文字、一个主要动作和真实状态为中心。复核已确认需求后，删除技术分类、重复确认和常驻检查入口；不通过增加醒目装饰表达更新的重要性。

## 二、Desktop 普通更新

### 2.1 账号菜单入口

位置固定在左下角账号菜单顶部用户信息右侧，保持原有账号、Host 地址和菜单顺序。图标操作可访问名称为“更新应用”，使用既有图标和紧凑按钮，悬停/焦点说明其含义。

```text
┌───────────────────────────────┐
│ 当前用户                  [更新] │
│ 当前 Host 地址                  │
├───────────────────────────────┤
│ 设置                           │
│ ……原有菜单及 F04 反馈入口         │
│ 退出登录                        │
└───────────────────────────────┘
```

- 自动检查仅在发现真实可用更新时显示按钮；无更新、无来源或检查失败不显示按钮及占位说明。
- 不增加“检查更新”、检查频率设置、架构选择或常驻版本文案。
- 正在下载时该位置显示进度入口；失败后保留本次操作入口，供用户查看原因与重试。后台检查不能把进行中的操作藏掉。
- 点击先关闭菜单，再打开独立更新 Dialog；关闭菜单不会卸载更新状态。

### 2.2 更新面板

沿用账号 Dialog 的结构，建议宽 440px，最大宽度为窗口减去两侧各 20px，正文可滚动、footer 始终可达。标题“有新版本可用”，正文直接展示管理员更新说明，单一主按钮“更新并重启”。不展示版本列表、兼容矩阵、架构、Host 来源或内部签名字段。

```text
┌──────────────────────────────────┐
│ 有新版本可用                       │
│                                  │
│ 更新说明                          │
│ · 本次发布的实际改进内容             │
│                                  │
│ 更新会重启应用，进行中的本机任务       │
│ 和终端会中断。                     │
│                                  │
│                  [稍后] [更新并重启] │
└──────────────────────────────────┘
```

点击“更新并重启”即确认本次影响并开始下载，不再弹第二个 Host 接管确认。远端连接的影响文案为“更新会重启应用”，不声称停止远端任务。更新说明使用现有安全 Markdown 渲染，不执行 HTML 或脚本；无说明时只省略该内容区。

| 真实阶段 | 正文/状态 | 操作 |
| --- | --- | --- |
| 有可用更新 | 更新说明与中断提示 | 稍后、更新并重启 |
| 下载中 | “正在下载更新…”及实际百分比/已下载大小 | 收起、取消下载 |
| 校验/准备 | “正在准备更新…”；无可靠百分比时用不定进度 | 可收起，取消只在原生仍允许时可用 |
| 停止与安装 | “正在更新，应用将重新启动…” | 禁用取消和连接切换；不显示虚假的完成百分比 |
| 失败 | 简短原因及明确下一步 | 按失败阶段提供重试或关闭 |

下载期间业务继续可用，关闭面板仅收起；显式“取消下载”才停止本次下载。校验完成后自动停止本机后台并安装，不加等待所有任务空闲的页面。Windows 接入系统安装进度后应用退出，不能把退出表现为更新成功；macOS 使用相同面板文案并在安装后重启。

## 三、登录页必须更新

使用现有 `DesktopEntryPage / RuntimeEntryLayout / RuntimeConnectionForm` 的紧凑布局，不增加一套欢迎页。在登录操作区显示：

```text
需要更新后继续使用

[更新并重启]
```

只有存在可用更新时显示按钮；暂时取不到更新时显示“暂时无法更新，请稍后重试”，继续每 5 分钟自动检查。密码或网络错误沿用原有处理，不显示必须更新。已有连接重试可以保留，但不新建“检查更新”按钮。

点击后打开同一个更新面板，说明相同的重启影响；普通更新的“稍后”在此改为“关闭”，关闭仍停留在登录入口，不恢复业务。可切换其他连接目标，切换会结束当前尚未安装的更新上下文；停止/安装期间暂时禁用切换。

重启后先显示现有连接/初始化进度；需要重新登录时回到原目标登录表单。不能仅凭 Desktop 窗口打开就宣称后台和用户数据已恢复。Web 页面不显示本机安装按钮；需升级远端服务时保留简短的联系管理员提示。

## 四、管理员安装包管理

### 4.1 列表与详情

Admin 新增“安装包”导航，路由 `/desktop-releases`，详情 `/desktop-releases/:version`。复用现有侧栏、面包屑和主内容容器，保留 F04 的反馈导航。

列表顶部只有标题、上传按钮和必要筛选。表格每行一个版本，列为“版本、更新说明摘要、平台发布情况、操作”。平台状态分别展示 Windows x64、Windows arm64、macOS arm64，不用一个“已发布”代表全部平台。首版与插件列表一样完整加载，不额外增加分页或统计。

操作列固定右侧并居中，按钮使用 small；详情页复用返回及面包屑导航，分为更新说明和平台制品两部分。每个平台一行展示状态与发布/撤回操作；文件用途、大小和验证信息在该目标详情展开，散列与兼容信息不占主列表。

### 4.2 上传与发布

1. 点击“上传安装包”，多选构建输出的清单、签名和制品文件。界面自动显示版本、平台和文件用途；不让管理员手填“兼容”或下载地址。
2. 上传时显示实际进度；接收完正在提交时显示“正在保存…”，不以 100% 字节传输冒充已创建草稿。失败保留原因和重新选择/上传操作。
3. 成功后进入该版本详情，维护更新说明，再对对应平台点击“发布”。上传成功不自动发布。
4. 发布确认简短列出版本、平台和“发布后用户可发现并下载安装”；确认按钮名“发布”。首次发布后制品只读，更新说明仍可编辑。
5. 撤回确认说明“撤回后不再提供此平台更新，已安装的应用不受影响”；确认按钮名“撤回”，沿用危险操作样式。撤回保留文件，重新发布只能使用原制品。

不出现独立“开始校验”按钮、兼容覆盖开关、逐平台试运行步骤或上传任务中心。签名/文件匹配自动完成，平台安装验收由发布流程负责。

写请求结果不明时显示“结果尚未确认，请重新读取”，提供重新读取当前版本的动作；查询实际摘要和状态后才允许下一次写入，不自动重发。离开/取消上传沿用已有上传对话框和 NavigationGuard，说明停止等待不代表服务端回滚。

## 五、异常文案与可访问性

| 用户可处理的问题 | 建议文案/动作 |
| --- | --- |
| 下载断开 | “下载失败，请重试。”／重试下载 |
| 文件校验失败 | “更新文件校验失败，请重新下载。”／重新下载 |
| 当前发布已撤回 | “此更新暂不可用。”／关闭，等待后续自动检查 |
| 本机后台未能停止 | “暂时无法完成更新，请重试。”／重试更新 |
| 从 macOS 只读安装镜像运行 | “请将应用移到「应用程序」后重新打开。” |
| 旧版本重新启动 | “上次更新未完成。”／按实际状态重新更新或手工安装 |
| Host 初始化失败 | 复用现有初始化失败提示和重试入口 |

错误详情只进入内部日志；公开页面不展示原始地址、Token、兼容矩阵、栈或数据库字段。HTTP 与 HTTPS 不产生不同的用户步骤或特殊开关。

Dialog 复用焦点圈定、Esc、关闭后焦点恢复和减少动态效果设置；阶段切换用 status 提示，失败用 alert，下载百分比不过度播报。图标有可访问名称，进度有文字表示。窄窗口、长更新说明和 125%/150% 缩放下 footer、取消及重试仍可达。

## 六、验收范围

核对普通入口只在可用更新时出现、面板收起重开不丢进度、下载取消、失败恢复、强制更新无法进入业务、管理员上传/发布/撤回，以及 F04 菜单项共存。Windows 额外核对托盘隐藏、最小化和重复启动后的原窗口恢复；macOS 保持现有侧栏效果。

本稿为实现与验收指导，线框用于说明信息位置，不等于已实现页面或浏览器实测结果。后续按[开发计划](开发计划.md)分里程碑落实，不新增独立验证报告。
