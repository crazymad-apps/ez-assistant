## 一、计划信息与设计依据

- 所属版本：v0.29.0；Feature：F07 批量文件编辑。
- 依据：已确认的[功能设计](功能设计.md)与[技术方案](技术方案.md)，上位[总体设计](../../总体设计.md) R19、第 6.7 节及[Feature 总台账](../../开发计划.md)。
- 2026-10-04 用户确认本计划并要求开始，M0 已确认；2026-10-09 用户确认除 macOS 升级外均已实测，M1/M2 与 F07 按用户结果验收完成。版本已于 2026-10-10 按用户确认范围封版，macOS 升级暂缓。
- 目标：一次 edit_file 完成单文件多组或跨文件精确替换，先完整授权，保留真实逐文件结果，并可经取消、历史恢复、上下文续接和现有工具详情查看。
- 无需独立交互指导：复用现有 Files 审批与工具详情，理由和展示边界见技术方案第五节。

## 二、台账原则

1. 计划确认后仅开始 M0；每个里程碑实现与验证完成后标记“待确认”，用户确认后才进入下一步。M2 同时承载 Feature 验收，不另建重复验收阶段；最终仍需用户确认 Feature 完成。
2. 先解决取消结果保存，再交付完整批量编辑链路，最后完成联合验收。取消是批量副作用真实性的前提，不先暴露会丢失部分结果的工具；也不拆出临时单文件 Schema 或未完成的批量脚手架。
3. 类型、限额、身份判定、写入方式和错误语义沿用已确认技术方案；计划只管理交付与门禁，不复制实现细节。发现设计假设不符时停止扩大实现，修订对应设计并重新确认。
4. 保留现有工作树内容；每步动手前重新核查共享文件。F01/F04 的 Host 装配、Runtime 和已确认边界不覆盖、不推断为完成。重叠修改串行整合，不新增并行 Agent 或并行 Feature 实施。
5. 文件与应用测试使用项目 `.runtime-test/` 下新建的 F07 一次性目录/Runtime Home，不复用已有数据。需要数据库写入时先核对实际目标、表和接口读取路径，按仓库安全规则执行；不操作日常用户目录或重启现有用户服务。
6. 验证结论、未执行项和必要风险留在本计划及本地进度，不创建独立验证报告，不归档命令输出或测试数据。每步汇报实际验证，未知状态不得宣称成功。
7. 不提交、推送、部署、打包发布或修改其他 Feature 的验收结论；这些动作需要另行授权。

## 四、里程碑交付与完成判定

### M0 取消结果可靠保存

**目标**：工具已经返回的业务事实不因取消而丢失，后续调用不继续执行。

**前置依赖**：本计划确认；核对 Core、工具 SPI、Recorder 和 testkit 现状及涉及模块约束。

**交付范围**：

- 修正串行与并行工具取消结算，保留已返回的规范结果和原顺序，补齐未执行调用；继续等待资源清理后完成可靠 exchange，再发布取消终态。
- 保持取消优先，不继续模型调用，不把取消收敛计入结果型 Guardrail 连续失败；Recorder 失败仍按原可靠边界处理。
- 同步现有注释、规范与确定性测试；以受控工具返回部分结果验证事实保存，不提前修改 edit 输入或安装文件身份依赖。
- 定向检查 Runtime Recorder 消费与历史读取，维护 F06 已登记的追加重验边界，不调整续接协议或旧历史。

**验证入口**：Core/testkit 的串行、并行、Guardrail、Recorder 故障和取消测试；Runtime 可靠结果保存相关回归。公共 Core 调整按规范执行：

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace
```

**完成判定**：取消期间返回的结果可被可靠记录且不被 interrupted 覆盖；未执行位置完整补齐；清理、配对、顺序和唯一取消终态均正确；不改变正常工具执行。验证完成后汇报并等待确认，M1 不提前启动。

**Review 重点**：以已返回结果作为事实，不新增工具名判断、opt-in、缓存或状态字段；取消不能中途 drop 工具或触发后续副作用。

### M1 批量编辑完整链路

**目标**：正式工具一次调用可完成有安全边界和真实结果的单文件多组及跨文件编辑。

**前置依赖**：M0 已确认；重读所有文件能力实现、生产装配、Provider Schema 转换及输入/结果消费者。

**交付范围**：

- 按技术方案统一批量和旧平面输入，冻结完整多路径授权事实、默认值、指纹和有限输入/结果预算；同步全部真实与 fake 文件能力实现及仓库调用方。
- 本地 Adapter 实现整批别名/身份预检、顺序替换和文件内完整预校验；在已核验句柄上受限读取、写前复核与提交，保留 BOM、换行和链接语义。
- Host 在委托前复核整批用户域保护，Runtime 复用已有审批、规则合并及审批后重验；任何拒绝不先写其他文件。
- 返回完整成功/失败/未知/未执行清单，取消或首次失败停止后续；写入未知不自动重放，不提供虚假完成数量。
- 接通正常取消的可靠记录、Runtime Files 输入投影、历史结果/文件引用及现有工具详情；旧输入和历史结果继续可读，不新增协议 DTO 或数据库迁移。
- 本步即完成实际权限和取消链路验证，不留给 M2 补足；展示缺口只在现有组件补齐。

**验证入口**：工具输入与 Schema、所有限额及最坏转义预算；本地单/多文件替换、组内失败、别名、外部修改、取消、写入失败；Host 用户域保护与 Runtime 混合权限/审批重验、结果投影。使用新建隔离正式 Host 和受控模型完成一次批量调用与正常取消的结果回读。执行上述 Rust 公共契约检查；涉及 Desktop 前端修改时追加：

```bash
cd apps/desktop
npm run build
```

前端仅执行相关审批/工具详情测试；Provider Schema 兼容以现有转换及受控调用验证，不要求真实外网模型。

**完成判定**：功能设计验收点 1—6 形成完整可用链路；整批权限拒绝与重复目标无副作用，文件内失败不提交、跨文件失败保留先前成功，未知与未执行可区分；结果完整可靠保存，单文件旧输入可用。当前 macOS 文件行为实际验证，Windows 未实测项明确汇报。结果待确认时不得开始 M2。

**Review 重点**：无未经授权的前置写入；路径锁和句柄生命周期明确，写入开始后不丢弃 future；结果大小限制不靠执行后截断；部分失败不能显示为全部成功。

### M2 联合验收与 Feature 收尾

**目标**：核对完整使用路径、历史和恢复边界，形成可确认的 F07 完成结论。

**前置依赖**：M0/M1 均已确认；读取它们的实际验证和未完成项，只补充联合风险与未覆盖项。

**交付范围**：

- 在新建隔离 Runtime Home 验证完整批量结果落账、正常取消后再提问、Host 重启及崩溃未知恢复；不从历史文件副作用推测逐文件成功。
- 回归 F06 服务端续接和上下文重建中的新旧工具历史；回归 F03 审批长清单、实时与历史工具详情、部分失败状态及文件入口。
- 核对功能设计全部验收点、已确认技术方案和总体设计的 Call/Result、权限、副作用、轻量协议等契约。
- 验证当前平台实际文件/链接行为；Windows 专项需要可用实机，无法执行时记录具体影响并由用户确认接受，不能以编译或 macOS 结果代替。
- 修复本 Feature 验收缺陷并定向复验；若涉及已完成 Feature 的真实边界变更，记录原因、重开范围和验证结果，经用户确认，不静默改写结论。
- 汇总实际完成范围、未执行项与必要限制，更新本计划、版本台账和本地进度；不进行版本整体验收或发布。

**验证入口**：隔离 Host 的恢复/历史/续接集成场景、现有 Desktop 工具详情及审批测试与实际界面查看、平台条件文件测试。复用 M0/M1 已通过检查；新代码或失败证据触发对应检查，不为收尾无理由重跑全部验证。仅文档修改检查链接与一致性。

**完成判定**：全部验收点逐项核对，正常取消真实结果和异常崩溃 unknown 均成立，F06/F03 回归无未解释偏差；遗留平台/文件系统限制已明确。M2 完成结果及 Feature 验收结论获用户确认后才能标记 F07 已完成。

**Review 重点**：区分实际文件、可靠历史、客户端展示和未知恢复；不宣称跨文件事务、强沙盒或崩溃安全，不把 Feature 完成当作版本发布完成。

## 五、Feature 完成条件

- M0/M1 完成结果均已获用户确认，M2 验收和 Feature 完成结论获确认。
- 功能设计八项验收点和技术方案均符合，所有现存调用方与历史消费者同步，未完成项/风险没有被完成状态掩盖。
- F06 追加重验范围与 F03 定向回归结果已记录，原验收限制保留；整版联合验收仍由版本总台账管理。
- 开发计划、版本台账和本地进度一致，代码/注释与设计无矛盾；无未经授权的数据操作、提交或部署。

此前 M1 实施结论（当前验收以文首用户确认为准）：2026-10-04 M0 已获用户确认；M1 已实现并完成当前环境验证，结果待确认。批量和已发布平面输入统一为冻结请求，整批授权、Plan 硬边界与 Host 用户域/受保护资源复核均已接通；本地整批身份预检、文件内顺序预校验、核验句柄提交、首次失败/取消停止及完整逐文件结果已实现。正式隔离 Host 的权限拒绝、审批后重验、正常取消、可靠历史和部分成功文件入口可用；原始输入预算、Provider Schema 兼容、最大目标清单及失败/未知结果投影已核验。

现有 Files 审批和 JSON 详情足够承载展示，仅将详情的混合截断提示修正为“部分记录”以免把请求正文裁剪误称为结果裁剪。输入正文仍沿用既有安全显示预算，路径投影和批量结果保持完整，不新增协议 DTO、表或迁移。

格式、全工作区静态检查、按目标拆分的 Rust 回归及相关前端测试/构建通过。合并 workspace 测试仍有 Desktop updater/rustls 双加密后端选择冲突；拆分回归中因补充验证并行重建 Host 导致的一项启动保护失败，在停止并发构建后独立复验通过，未改变产品启动边界。当前 macOS 的实际文件、链接和取消行为已核验；Windows 实机、真实外部模型、原忽略用例和重新打包未执行。不提供跨文件回滚、外部竞态隔离或 fsync 崩溃安全的设计限制保留。

M2 尚未开始；新旧批量历史续接/重建、崩溃恢复和实际界面联合验收仍待 M1 获用户确认后实施。F06/F03 原验收结论和未实测限制保留，F07 尚未标记完成，版本整体仍在开发中。
