## 三、输入、能力请求与结果

### 3.1 模型输入

名称保持 `edit_file`，支持互斥的两种输入，禁止混合字段和未知字段：

```json
{"files":[{"path":"src/a.ts","edits":[{"old_string":"old","new_string":"new","replace_all":false}]}]}
```

```json
{"path":"src/a.ts","old_string":"old","new_string":"new","replace_all":false}
```

后一种是已有单文件使用方式，前一种为推荐批量方式。每组 replace_all 省略时为 false，使用 serde 默认及 schemars 默认注解公开嵌套默认；不使用只针对顶层字段的 ToolInputDefaults 为嵌套数组伪装默认。Schema 分支和旧分支缺省规则需覆盖现有 Provider Schema 转换测试。

resolve 统一为 `EditFileRequest { files }`，文件项携带绝对逻辑 path 与非空 edits，各组 replace_all 已落实。语义参数与请求保持相同结构并附 Edit 操作，全部 paths 生成一份 FileBatchAuthorizationFacts。单文件也沿同一链路，不保存第二份执行路径。resolve 只做纯校验与词法解析，不调用文件系统。

顺序替换基于前一组内存结果；CRLF 是否归一化由该文件原始内容确定并作用于所有组，BOM 单独保留。每组和最终内容均核对文件大小上限，后续失败不提交当前文件。

### 3.2 限额

首版使用固定工具契约上限，不新增用户配置项；在 Schema/description 公布，并在 resolve 与能力执行入口复核，防止直接调用 Adapter 绕过限制。

| 项目 | 上限 |
| --- | --- |
| 文件数 | 16，禁止空列表 |
| 每文件替换组数 / 整批组数 | 64 / 128，禁止空 edits |
| 原始输入紧凑 JSON UTF-8 字节数 | 256 KiB，包含路径和全部替换文本 |
| 解析后单路径 / 整批路径 UTF-8 字节数 | 1 KiB / 4 KiB，路径数组紧凑 JSON 另限 8 KiB（含转义），超限整批拒绝 |
| 单条结果错误原因 | 256 UTF-8 字节，按字符边界截断，不重复路径与输入文本 |
| 完整结果 pretty JSON | 64 KiB 以内；以最坏转义和最大条目验证预算，不执行后裁掉条目 |
| 每文件原内容、中间内容与最终内容 | 沿用 Adapter 配置；正式 Host 为 4 MiB |

原始完整 JSON 字节预算在工具输入反序列化核对，能力入口另核对编码替换正文、数量和路径预算；默认值补齐与绝对路径展开增加的字节不误算为原始输入。固定条目数同时约束冻结请求的结构开销。

批量文本逐文件处理；最多持有 16 个文件身份句柄，不同时读入全部文件内容。输入是已经进入模型规范 Tool Call 的 JSON，工具局部限制不替代 Provider/传输层总输入限制。

路径限额确保现有输入 Files 投影可保留全部目标。替换正文可沿现有请求脱敏/截断展示，但审批目标清单和逐文件结果不得因此缺失。

### 3.3 结果与工具状态

能力返回 `EditFileResult { files }`，文件结果包含绝对逻辑 path 和带 tag 的结果：

- `success`：包含实际提交的 replacements（整文件所有组之和）。
- `failed`：包含稳定错误类别、受限原因，明确尚未产生当前文件写入；匹配失败可含失败组索引。
- `unknown`：写入已开始但无法确认全部提交，不提供虚假的完成数量。
- `not_executed`：输入顺序中尚未执行的文件，包含 cancelled、previous_failure 或 preflight_failed 原因。

只有 success 提供 replacements；未提交的内存替换不计为完成。结果按原文件顺序且条目数恒等于输入数。别名/身份预检失败时，故障项 failed、其他项 not_executed，整批没有副作用。

FileSystemTool::edit 的 Result 外层 Err 保留给无可用文件清单的契约错误；有合法清单后的读取/匹配/写入/取消失败形成正常返回的业务结果。工具壳通过既有 output_status：仅全部 success 为 Success，其他为 Error，JSON 正文完整保留。取消仍由 token 和 ExecutionCancelled 表达，不新造取消 ToolError。

## 四、授权、文件身份与提交

### 4.1 完整授权

Runtime 按 Edit 的全部 paths 合并权限：任一 Deny 整批拒绝，存在 Ask 则审批完整清单，审批返回后复核当前规则与路径。Host UserFileSystem 在进入 Local edit 前依次复核所有目标的用户域写权限；任一失败不开始文件写入。路径保护与物理默认规则继续走现有链路，不移入工具壳。

F07 不改写权限模型；现有 UserFileSystem 的执行前复核与 LocalFileSystem 的身份复核分别解决用户域保护和重复目标，不把身份比较当作授权。

### 4.2 别名与文件身份

Local edit 在任何写入前完成整批身份预检：逐目标打开既有普通文件，保存 canonical path 与打开句柄身份。使用 same-file::Handle::from_file 比较句柄，捕获 symlink、hard link 与大小写别名；任一两项指向同文件即拒绝整批。canonical path 相等同样拒绝。身份读取失败、非普通文件、路径解析失败均拒绝，不能按“不同文件”继续。

打开和元数据操作在有界 spawn_blocking 工作中完成，最多 16 项，无新的长期任务；取消时等待拥有的工作收敛并释放句柄。仅支持现有 Unix/Windows 后端，其他无法提供身份判定的平台拒绝批量执行。

逐文件执行时，在取得逻辑路径锁后，重新核对路径解析与打开对象和预检对象一致。路径或对象变更则当前项 failed，停止后续；不按旧预检继续跟随新目标。句柄保留到批次结束，避免 Windows 文件身份在关闭后复用。

same-file 的 Windows 后端使用 volume/index；其源码注明特殊文件系统可能误判不同文件为相同，F07 采用保守拒绝，不声称支持所有网络/特殊文件系统。该机制防止核查时的重复对象，不承诺消除外部进程随后的所有路径竞态。

### 4.3 每文件提交

1. 按输入顺序取得现有逻辑路径锁；等待锁和首个副作用前观察取消。
2. 打开当前文件读写句柄但不截断，核对预检身份与普通文件类型；打开失败时当前项 failed。
3. 从该句柄受限读取原始内容，先在内存完成全部替换和大小校验。
4. 复核逻辑路径/身份，重新读取同一句柄内容，与原始字节精确比较；检测变更则 failed。
5. 再检查取消，随后对已核验句柄执行定位、截断、完整写入和 flush；开始截断后不以 select 丢弃写入 future，等待提交/清理结果。
6. 全部完成记 success；截断或写入开始后的错误保守记 unknown，停止后续文件。不靠读取一次相同内容推断持久落盘或跨进程无竞态。

跟随 symlink 编辑目标、保留链接本身和 hard link 关系；不采用临时文件 rename，因为它会改变链接/文件身份及元数据语义。flush 表示完成本次文件操作，不声称 fsync 后崩溃安全。外部写入仍可能发生在最终复核与提交之间，路径锁只协调同 Adapter 的同逻辑路径操作，跨别名并发与恶意竞态不是本版强隔离承诺。

一次只持有一个逻辑 mutation lock，不跨授权、审批或其他目标锁；锁内 I/O 是该锁保护的本地文件提交，不调用上层回调。整批在首个 failed/unknown 或取消后停止。

## 五、取消、持久化、续接与展示

### 5.1 Core 修正

现有串行与并行路径等待 execute future 后会将取消期间返回的结果覆盖成 interrupted。统一修正为：已等待返回的规范 ToolResult 保留，只有未执行的位置补 interrupted，然后原子完成 exchange 并以 ExecutionCancelled 终止，不发起下一模型调用。

无需新增工具名判断、运行时 opt-in、结果缓存、metadata 标志或新状态字段；返回结果本身就是完成事实。并行工具结果也按原位置保存，仍等待所有工具清理。取消收敛不执行结果型 Guardrail 失败计数，以免部分取消业务 Error 把 Run 终态改成 Guardrail 失败。尚未授权/尚未 dispatch 的位置仍沿现有 interrupted 语义。

同步更新现有“取消时结果不回喂”的注释与测试：取消期间不继续模型执行，但结果会可靠保存并进入后续上下文。取消前授权及 started 可靠点、Call/Result 配对和完整 exchange 不变。

### 5.2 可靠记录与恢复

完整批量结果通过现有 Recorder、Conversation JSONL、ToolCompleted 事件和历史详情保存；不新增数据库表、逐文件事件或中间完成日志。正常取消可保存已知的逐文件结果。若进程崩溃/Recorder 失败而未形成可靠结果，沿用整 Tool Call unknown 恢复，不能从 UI 输出或文件现状重建历史逐文件成功。

F06 续接/上下文重建使用保存的完整结果，历史旧调用/旧结果不被改写。ToolResultStatus Error 表示整批未全成功，逐文件信息仍以 JSON 正文为准。

### 5.3 Runtime 与 Desktop

Runtime 输入投影增加 edit_file.files 的路径提取，复用 ToolInputSnapshot::Files，不引入专用产品 DTO。旧平面输入继续投影为 File。现有 Files 审批主体包含完整目标；显示层要验证 16 项上限时可逐项查看，不能只展示第一个路径。

结果详情沿现有 JSON 代码块展示全部文件项，限制保证不触发 64 Ki 字符截断；摘要可缩短，摘要和工具状态必须表达未全成功。新数组结果适配现有文件资源引用提取，不能把未知或未执行项当成已产出文件；不增加新的批量页面。

无需独立交互指导：沿用已有审批、Files 输入、工具详情和文件入口，仅定向验证长清单、失败状态及完整结果；核查发现现有组件缺口时在原组件补齐，不另建展示生命周期。

## 六、兼容、依赖及协调

已通过本地 `git show v0.26.0:crates/agent-tools/src/standard/fs/write.rs` 核实公开版本存在平面 edit 输入；当前版本台账确认 v0.26.0 已公开。保留该输入是已发布调用契约和历史上下文的兼容需求，不是保留开发中间形态。两种模型输入都归一化到同一个能力请求，不双写，不迁移历史正文。

新调用结果统一为 files 清单；历史 `{path,replacements}` 继续作为不透明规范 Tool Result 读取和回喂，Runtime 文件引用同时理解历史结果和新清单。现有客户端使用通用状态/JSON 详情，F07 不新增应用协议字段；不承诺旧二进制支持新工具输入。Host 和 Desktop 仍依既有兼容契约发布。

Rust 公共 edit 请求/结果类型直接统一新形状，仓库内所有真实/fake 实现、示例、测试和宿主同步修改，不保留第二套 Rust API。仅依赖方向向下增加 same-file；Agent Core 不访问文件系统。

共享协调：F01/F04 现有 Host 注册与 Runtime 文件不覆盖；F07 无中心迁移或 F05 数据依赖。agent-core 取消结算属于必要跨 Feature 调整，须在本方案确认后同步 F06 台账的定向重验范围，原验收限制保留；不是重开续接协议或改变原身份/模型策略。F03 展示执行定向回归，发现真实缺陷再记录受影响边界。

## 七、验证与实施边界

技术方案阶段仅核对真实调用方、依赖、已有输入及文档一致性。代码实现按后续独立开发计划分里程碑，不在本阶段安装依赖或写库。

后续核心验证：

- 工具壳：两种输入、混合字段拒绝、嵌套默认 Schema、归一化/指纹、完整权限事实及全部限额边界；最坏转义结果预算。
- 本地 Adapter：顺序替换、单文件内失败不提交、文件间部分成功、BOM/换行、外部内容/路径变化、重复别名、取消等待和写入未知。失败注入走模块私有测试边界，不扩展公共文件能力。
- Runtime/Host：混合权限与审批重验、用户域整批保护、正常取消可靠结果、崩溃未知恢复、完整历史详情和文件引用。
- Core：取消时保存已返回串行/并行结果，未 dispatch 调用仍 interrupted，取消优先且无新增 Guardrail 失败；Recorder 故障保持现有可靠边界。
- F06/F03：新旧调用历史回喂、续接/压缩后重建、完整清单展示和错误工具状态。
- 公共 trait/Core 调整按规范执行 workspace clippy/test 与格式检查；前端改动时执行 Desktop 构建和针对性展示测试。

文件测试仅使用项目 `.runtime-test/` 下新建的一次性隔离目录，应用集成需要持久化时也创建独立 Runtime Home 并在写入前核对。macOS 当前环境实测，Windows 句柄/链接/取消按平台测试，无法实测时明确记录，不能以 macOS 测试替代。

主要限制：不提供跨文件回滚或崩溃安全，不消除外部进程竞态；身份预检可能使原本后续文件的缺失/打不开在整批副作用前被发现并拒绝；旧历史无逐文件清单不会被补造。本方案已确认，实施里程碑见[开发计划](开发计划.md)。
