## 二、目标与非目标

模型一次调用现有 `edit_file`，即可对一个文件提交多组不同替换，或对多个文件分别提交替换；结果完整表达实际修改范围，减少模型往返。仍只编辑既有 UTF-8 文件，保留 BOM、换行兼容与精确匹配规则。

不增加补丁语法、模糊匹配、AST 重构、文件创建/删除/移动、通用 batch 调度、跨文件事务、自动回滚或自动整批重试。工作目录不构成强沙盒。

## 三、使用路径与替换语义

1. 模型提交按顺序排列的目标文件，每个文件携带按顺序排列的替换组。
2. 工具先检查整批输入、数量与大小上限、路径及重复目标，再完成所有目标的文件写权限判定；审批展示完整目标范围。
3. 获得整批授权后按文件顺序执行，每个文件读取后在内存应用所有替换，全部有效才进入该文件的写入步骤。
4. 返回每个文件的状态及实际完成的替换数量；失败或取消后停止后续文件，模型根据结果重新读取并修正。

组内采用顺序语义：后一组在前一组的内存结果上精确匹配，可以修改前一组产生的文本。不存在隐式原文坐标或自动重叠合并；任何一组匹配失败，该文件均不提交，先前内存替换不计为成功。`replace_all` 仅作用于所属替换组，默认 false；空旧文本、无变化替换或多次匹配但未开启 replace_all 均拒绝。

同一批次不得重复提交同一目标。路径规范化后重复路径必须在写入前拒绝；不同路径实际指向同一文件的符号链接、硬链接及大小写别名也不得造成重复写入，识别方式和无法可靠识别时的拒绝边界由技术方案固定。不静默合并替换组。

文件内预校验不代表整批预校验：后续文件匹配失败时，之前成功写入的文件保留。输入结构、限额和整批授权失败则整批不执行。

## 四、权限、写入与结果

- 复用现有多路径权限事实、目录保护、审批及审计。任一目标拒绝或授权未完成时，不先写其他目标；禁止把批量拆成逐文件审批后立即写入。
- 每个文件复用路径锁、文件大小限制和写前内容复核。检测到外部修改时拒绝当前文件，不覆盖外部内容。锁只协调本地 Adapter，不承诺阻止外部进程竞态。
- 同一文件的全部替换完成预校验后一次提交；实际写入方式及平台保障由技术方案核查，不把一次 write 表述为原子、跨进程互斥或崩溃安全。
- 结果按输入文件顺序包含路径、成功/失败/结果未知/未执行、实际提交的替换总数与必要错误原因；错误文本受限，但不得丢失逐文件状态。未提交的内存替换不能计为完成。
- 写入前取消：当前文件未执行；写入已经开始时，应获取可确定的提交结果，无法确定则标记结果未知。已成功文件仍为成功，其余未执行，停止后续文件。
- 匹配与读取失败可明确表示未修改；写入错误不能默认等价于未修改，无法证明文件状态时返回结果未知。
- 崩溃恢复继续沿用既有工具 unknown 语义；没有可靠完整结果时不得推断逐文件成功或自动重放。

## 五、模块边界与契约

现有工具壳负责输入检查、解析和多路径授权事实；文件能力承担文件内替换及跨文件顺序执行；本地 Adapter 承担实际文件状态、锁、读写与取消处理。Runtime 继续持有审批、审计及工具记录，Agent Core 不直接访问文件系统。

保持一次批量调用对应一个 Tool Call 和一个完整 Tool Result。逐文件结果属于该结果，不创建额外 Run、任务、数据库表或第二份执行状态。F06 续接/重建应使用真实批量结果；F03 展示应能查看完整范围及错误，不将部分成功简化为全部成功。

当前单文件输入及历史结果的生产者、消费者、持久化和已发布使用情况须在方案中核查，再决定统一新 Schema 或保留必要兼容；本设计不预先授权兼容层或破坏性升级。工具名称保持 `edit_file`。

## 六、限额与关键取舍

为文件数、每文件/整批替换数、总输入字节、路径/错误输出和逐文件读写字节设定有限上限。具体数值在方案中结合现有模型输入及工具结果限额确定；超限须在副作用前拒绝，不能执行后截断状态清单。逐文件处理避免同时持有整批文件内容。

复用现有 edit 和多路径权限链路可承载目标；新增对象仅限表达多个替换和逐文件真实结果所必需的契约，不另建批量执行框架。顺序执行使部分结果和停止边界可解释，避免并发写入扩大取消范围。

## 七、验收标准

1. 单文件单组、多组及多文件均可完成，顺序替换和 replace_all 行为明确。
2. 单文件后续组失败时原文件未提交；后续文件失败时保留之前成功文件并列出未执行范围。
3. 混合权限、拒绝、审批取消和超限均不造成未授权写入；全部目标可在审批中核对。
4. 重复路径及同文件别名不会重复写入；外部修改不被静默覆盖。
5. UTF-8、BOM、LF/CRLF、符号链接及大小限制按设计保持；Windows/macOS 未实测项明确披露。
6. 取消、写入失败与崩溃恢复区分成功、未修改及未知，不自动重放副作用。
7. 完整结果通过 Host、持久化、F06 续接/重建和 F03 展示，部分成功不会被掩盖。
8. 历史调用/结果与新 Schema 的处理基于核查并获确认，所有现存文件能力实现和装配调用方同步。

## 八、后续与待确认
