## 当前设计范围

- 自动标题：自动与精确 `/title` 只使用不同 trigger，同一机制自行读取调用时最新 Conversation
  Snapshot；不限制 Session 运行状态，不新增标题专属装配/revision，clear 统一保留当前标题。
- 新会话临时草稿：每个 Workspace 一份外加一份未绑定草稿，仅当前进程保存，首次发送可靠接受后
  才物化 Session。
- Workspace：固定可读标签、主目录与有序附加目录、Agent 可见关联和冻结执行环境。
- 文本引用：同消息跨渲染元素 Selection、前端冻结纯文本 exact/每侧 128 字符前后文、直接来源范围、
  附件/引用 Tag 详情与可统一清理的来源高亮；点击引用不调用 Runtime，不签发 recall reference。
- 图片粘贴：Composer 从本次 paste 提取图片文件项，通过 Tauri 原生选择池转为普通附件；混合文字保留，
  新会话草稿、失败重试、预览和清理复用附件链路。
- 旁路推理：自动标题与上下文压缩共享生命周期；辅助识图保持为不继承 Conversation 的独立辅助推理。
- 页面交互：Desktop 自有弹窗、菜单、Popover、抽屉和 Collapse 统一过渡动画；左右侧栏支持独立
  拖拽/键盘调宽并保存设备本地偏好。

## v0.22.0 M2 实际结果（2026-09-01）

- Protocol 与 Host 新增 `session_materialization` capability、multipart manifest/result 和
  `POST /session-materializations` 专用入口；manifest 必须先到达，附件按 selection key、文件名、大小、
  哈希和媒体类型逐项校验，并继续使用既有上传上限、Blob 与 Session 稳定视图。
- Runtime 新增窄 `materialize_session` 用例，一次构造冻结 Workspace 环境、System Prompt、兜底标题、
  正式附件引用、结构化引用、可选 Goal/Skill、首个 Input 与 Run；Store 成功后才安装内存 Session、权限、
  Goal、队列并发布事件。
- `RuntimeStore::materialize_session` 在文件准备完成后使用一个 SQLite 事务提交 Session、资源、附件、
  UserMessage、Input、Run 及可选 Goal/Skill。提交前任一步失败都会回滚数据库并清理本次创建的 Session
  目录、Blob 和 staging 文件，不产生可查询的临时 Session。
- nullable unique materialization key 已用于响应丢失恢复：相同 key 与相同业务内容返回原
  Session/Input/Run，即使首条消息已从队列提交到 Conversation；相同 key 但内容不同返回 conflict，不会
  合并请求。未绑定 Workspace 的自动工作目录和内部生成 ID 不参与内容等价判断。
- Host 启动恢复会清理没有数据库 Session 的物化目录、没有附件元数据引用的 Blob 和遗留 `.part`
  staging 文件。旧 `create_session`、单 Session 上传与 `submit_input` 路径保持可用，Desktop 尚未切换到
  新入口。
- 测试覆盖无附件、多附件、Goal、用户 Skill、结构化引用、提交前 SQLite 失败、响应丢失重试、不同内容
  冲突和启动孤儿清理；全部使用内存 Store、`TempDir` 或隔离 Runtime Home，没有操作用户实际数据。

## v0.22.0 M4 实际结果（2026-09-01）

- Runtime 新增单一标题旁路：自动和手动调用只区分 trigger，由机制内部读取调用时最新
  稳定 Conversation Snapshot，选取首条用户意图与最新摘要/近期可见消息；调用方不装配对话内容。
- 标题请求使用当前 Session 模型的单轮调用，不主动请求 reasoning，只暴露一个
  `submit_session_title({ title })` 输出契约函数，不暴露业务工具。Runtime 按模型能力选择
  `Named` / `Required` / 单工具 `Auto` 中的最强约束，且只接受唯一匹配 ToolCall；普通文本回复和
  多次/错误调用均失败保留原标题，工具不执行、不持久化、不回传。请求仍使用固定 System Prompt、
  不超过当前模型上限的 `1024` token 有界输出和 `20s` 超时，有效 `title` 清理后最多保留 `80` 字符。
  全过程不创建 UserMessage、Input、Run、Queue 或第二类 Session，旁路 usage 原子累计。
- 新普通 Session/Fork 持久化自动标题 pending；首个用户 Run 成功产生非空 Assistant 最终消息后
  异步触发，先完成回复再更新标题。失败 Run 不消耗资格，启动恢复会重试已具备稳定对话的
  pending Session；旧 Session 和 Controller 不补生成。
- 自动结果仅在原 generated 兜底标题仍未变更时提交；精确 `/title` 可在活动 Run、Queue、Approval
  或 Compaction 存在时使用同一 Snapshot 机制并可替换任意当前标题。新 trigger、直接改名、clear
  和删除均取消迟到调用；clear 统一保留当前标题。
- Protocol/Host 新增手动标题命令、生成中 View 与 SSE 开始/完成事件；Desktop 增加 `/title`、
  生成状态、失败重试与标题淡入。新会话草稿明确提示首发后可用，Controller 明确提示标题固定。
- 同时修复了设置菜单关闭后延迟恢复焦点会抢走 Composer 新焦点的回归；仅在焦点仍无归属时
  恢复至触发按钮，连续执行 Slash 命令不再只输入第一个 `/`。
- 实机失败数据表明 DeepSeek V4 Flash 的两次标题旁路都刚好用尽原 `64` output tokens，但没有
  产生可用 Text Part；原因是 reasoning-first Provider 在未显式请求 reasoning 时仍使用默认推理。
  标题输出预算已改为不超过当前模型上限的 `1024` tokens；同时将失败提示的“重试 + 关闭”收进
  不收缩的右侧操作组，修复“重试”被 24px 图标按钮规则挤成两行的排版。
- 实机后续证据显示，放宽输出预算后模型把标题生成误解为对最新 Assistant 的接续输出，
  自由文本契约不足以区分“回答”和“标题”。已改为上述单函数输出契约并严格拒绝普通文本，
  确保接续句不再覆盖会话标题。
- 存储、恢复和 Host 测试只使用内存 Store、内存 SQLite、`TempDir` 或隔离 Runtime Home，没有读取或
  修改用户实际 Runtime 数据。

## v0.22.0 M5 实际结果（2026-09-01）

- Composer 已统一渲染附件 Tag：点击正文打开详情弹窗，移除按钮使用独立命中区；上传前 selection
  与上传后 Runtime 附件都可预览，详情只显示文件名、大小、媒体类型、来源和状态，不暴露物理路径。
- 本次 paste 只提取图片文件项；纯文本保持原生粘贴，图文混合按当前选区插入文字并按顺序增加图片
  Tag。图片批次中途失败会释放本批已创建 selection，既有附件与已插入文字保持不变。
- Tauri 原生桥接使用原始 `Uint8Array` 请求体和匿名临时文件，不把 Web `File`、Base64 或 Object URL
  保存进草稿；按 magic bytes 校验真实图片类型，并落实单图 32 MiB、单 Composer 32 项、进程内
  临时图片 256 MiB 的边界以及 TTL/显式释放清理。
- 每个 Workspace 与 unbound 草稿独立保存图片 selection，切换后不会串草稿；可靠首次物化成功才清空，
  失败继续保留可重试资源。普通已有 Session 也支持附件-only 输入，Runtime 仍拒绝文本和附件都为空。
- 标题旁路在附件-only 首轮中只使用原始文件名作为有限意图线索，不读取附件内容或路径，也不改变
  标题 trigger 和生命周期。

  ordinal 与 reference 均不进入产品界面。

  导航/owner 变化、失败和卸载均清理，不修改消息正文或持久状态。
