## 四、功能与跨层验收

- 新会话草稿仅在 Desktop 当前进程内按 Workspace 保留，发送前不创建 Session 列表记录；首次发送
  通过窄 materialization 入口一次提交会话、附件、引用和首个 Input。
- Workspace 名称、主目录和有序附加目录可在统一编辑弹窗修改；既有 Session 继续使用创建时冻结的
  Workspace/System Context，不被热更新。Runtime 内置冻结工作目录的缺省读/list 权限，不再维护
  `default-workspace-*` 规则。
- 自动标题与 `/title` 仅 trigger 不同，均由同一旁路机制读取调用时最新 Conversation Snapshot；标题使用
  结构化 tool call 收集，避免把模型接续输出当作标题。
- Composer 附件/引用 Tag 可查看详情；粘贴图片转为普通图片附件。引用在前端冻结 `exact`、前后文与直接
  来源定位信息，发送时作为结构化 UserPart 提交，不拼接整条 Assistant Message。来源高亮是可回收的
  Desktop 瞬时状态，发送时强制清理。
- 产品弹窗、菜单、Popover 和 Collapse 具有可中断过渡；分栏拖拽不使用缓动。左右栏宽度保存为设备
  偏好，窄窗口按“右栏先隐藏、左栏后隐藏”降级；右侧上下文宽时使用两条独立纵向列，不强制行对齐。

## 五、隔离、迁移与恢复

- 所有 Store、schema migration、首次物化幂等、附件失败补偿、历史权限清理和孤儿文件清理验证使用
  `TempDir`、内存 Store 或隔离 Runtime Home。
- 不读取、迁移、覆盖或删除用户实际 Runtime Home、数据库或附件目录。
- 旧 Desktop 可忽略 Host 新增的 `session_materialization` capability；新 Desktop 连接缺少该能力的旧 Host 时
  显示升级提示，不回退为可见空 Session。
