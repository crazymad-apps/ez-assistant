## 二、现状核查与最小改动结论

### 2.1 已核查的真实实现

| 能力 | 当前实现 | 本版本结论 |
| --- | --- | --- |
| Session 创建 | `assistant-runtime::Runtime::create_session` 先持久化空 Session；Desktop 新建入口立即调用 | 新会话 UI 不再调用；保留给 Controller、兼容入口和内部测试 |
| 输入接受 | `accept_session_input` 通过 Store 原子写入 Input、Run、Goal/Skill 和兜底标题 | 复用校验与构造逻辑；首次发送由窄的 `materialize_session` Store 操作一次提交 |
| 附件上传 | Host 接收流式 multipart，先暂存，再按已有 Session 生成 Blob、稳定视图与附件记录 | 复用流式校验、内容寻址 Blob 和稳定视图；增加“首次发送”批量 multipart 入口 |
| Workspace | `StoredWorkspace` 只有 `user_directory` 与 `agent_directory`；注册、查询、移除串行化 | 物理上保留 `user_directory` 作为主目录，新增 `label` 与有序附加目录 JSON，不建目录子实体 |
| Session 环境 | `SessionExecutionEnvironment` 冻结一个 `working_directory`，System Prompt 在创建时生成并持久化 | 保留主工作目录语义，新增冻结附加目录；Workspace 后续修改不重建 Prompt |
| 技能发现 | `SkillScanRequest` 扫描单个 Workspace 目录，`SkillCandidate` 已保留来源路径 | 扩展为按根目录顺序扫描，并给 Workspace 候选增加根目录序号用于冲突决策 |
| 文本选区引用 | Conversation Snapshot 已有规范消息身份；WebView 提供 Selection/Range | 采用前端冻结内容与直接来源范围；不复用 HMAC reference，不增加引用专属 Recall 工具 |
| 上下文压缩 | `RuntimeContextCompactor` 使用 `RollingSummarySameModel` 发起无工具流式模型请求 | 提取薄的单轮结果收集器，标题与压缩复用；领域快照、超时和提交仍各自负责 |
| 消息内容 | `agent-types::UserPart` 支持文本、注入上下文、内部上下文和文件引用 | 新增结构化 `QuotedText`，随 UserMessage 一起持久化与投影 |
| 本机附件选择 | `NativeResourceBridge` 只登记文件选择器返回的普通文件路径，selection 在发送后释放 | 扩展同一 selection 池以登记剪贴板图片 owned 临时文件，不新增附件类型或上传协议 |
| Desktop 偏好 | Tauri 的 `DesktopPreferences` 以 JSON 临时文件替换写入，已有左右栏开关 | 新增左右栏偏好宽度；不使用 `localStorage`，不写 Runtime |
| 浮层 | Dialog、菜单、Popover 和 Collapse 分别控制挂载，关闭多为立即卸载 | 增加共享 Presence 生命周期与 CSS Token，不引入动画库 |

### 2.2 最小改动原则

本版本明确不新增以下抽象：

- 持久化 Draft、Provisional Session 或第二类 Session；
- 通用上传租约服务、跨模块事务协调器或可编排的“旁路任务平台”；
- Workspace 目录独立表、目录 ID、Workspace revision 或 CAS；
- 标题 revision、标题专属 Conversation 装配器或标题来源状态层级；
- 引用独立表、裸 Message ID 工具或持久高亮状态；
- 多根目录文件系统 Adapter 或把工作目录包装成强沙盒。

首次发送的一致性由一个窄的 Host 入口和一个窄的 Store 方法完成。标题、压缩只复用“执行一次
模型交换并收集单轮结果”的底层能力，各自构造输出契约并校验结果，不共享彼此的领域状态机。

## 三、目标边界与依赖方向

```text
Desktop 草稿/交互
  -> Tauri 原生句柄与 Desktop 偏好
  -> Runtime Host HTTP Command / SSE / 首次发送 multipart
  -> assistant-protocol DTO
  -> assistant-runtime 领域校验、快照、调度与提交
  -> Store / agent-context / agent-model
```

- Desktop 只持有新会话草稿、选区和动画等临时 UI 状态，不持有正式 Session 事实。
- Runtime 是 Session、Workspace、Conversation、标题任务和已提交引用的权威所有者；Composer 引用草稿
  在发送前只属于 Desktop。
- Host 只负责 HTTP multipart、文件流暂存和命令转发，不持有第二份 Session 状态。
- Store 继续是持久化和文件布局实现；首次物化方法是具体业务操作，不上提为通用事务框架。
- `agent-model` 只增加 provider-neutral 的单轮结果收集能力，不依赖 Runtime、标题或压缩。
- `agent-context` 继续拥有压缩输入布局与 Summary 规则；标题不能进入该 crate。
- `agent-types` 承载 Provider-neutral 的结构化引用内容；应用来源导航 DTO 留在 `assistant-protocol`。

## 四、新会话草稿与首次发送物化

### 4.1 Desktop 草稿状态

Desktop 新增进程内 `NewSessionDraftStore`，key 为：

```text
WorkspaceId | unbound
```

每份草稿保存正文、文件选择器或剪贴板图片产生的原生 selection 句柄元数据、引用、模型、reasoning
effort、变体、审批模式、Skill 和 Goal 提交意图。草稿只存在 WebView/Tauri 当前进程内：

- 切换正式 Session 不删除草稿；
- Workspace 标签和目录修改不改变 draft key；
- 应用退出或 WebView 重建不恢复；
- Workspace 移除后立即使对应草稿不可发送，并在用户确认移除后释放文件句柄；
- 草稿绝不进入 Runtime Snapshot、Session 列表、搜索或本地恢复文件。

Session 选择状态允许 `selected_session_id = null` 并额外记录当前 draft key。点击“新对话”只切换该
状态，不再经过 `SessionManagementController.createSession`。

### 4.2 剪贴板图片登记到现有附件选择池

参考 `zx-scene-editor-mono` 的 `AgentChatPanel/input/InputBar.tsx`：Composer textarea 的 `onPaste` 只检查
本次 `ClipboardEvent.clipboardData.items`，筛出 `kind=file && type=image/*`，普通文字不走附件逻辑；
混合粘贴则同时保留 `text/plain`。ez-assistant 不直接把 Web `File` 留到发送阶段，而是接到现有 Tauri
资源桥接：

1. 没有图片项时 handler 直接返回且不 `preventDefault`，保留浏览器原生粘贴；
2. 有图片项时先读取 `text/plain` 与 textarea selection，`preventDefault` 后按受控输入规则替换选区；
3. 前端预检本次图片数量、单文件 `File.size` 和当前附件余量；剪贴板图片额外限制为 `32 MiB/张`，
   避免 Tauri raw IPC 和 WebView 同时复制超大字节；
4. 对每张图片调用 Tauri `stage_clipboard_image`：`invoke` 直接发送 `Uint8Array` raw body，MIME hint 放在
   request header；不转 Base64、不提交本地路径；
5. Tauri command 通过 `tauri::ipc::Request` 读取 raw body，用 `infer` 按 magic bytes 确认实际类型为
   `image/*`，生成安全文件名并写入 `tempfile::tempfile()` 创建的匿名临时文件；
6. 写入成功后把文件登记到现有 `NativeResourceBridge.selections`，返回与文件选择器一致的
   `AttachmentSelection`。前端按原顺序加入 `ComposerContextItem::attachment`；
7. 任一图片登记失败时，前端调用现有 release 命令回滚本 paste 批次已经登记的 selection；同次文字和
   paste 前已有上下文不回滚。

`SelectedAttachment` 的来源改为 `ExternalPath(PathBuf) | OwnedTempFile(Arc<File>)`，上传和预览通过统一
source reader 打开或 `try_clone`，其余名称、大小、TTL 和取消语义共用。匿名临时文件不暴露物理路径；
显式移除、成功上传/物化、TTL 淘汰、批次回滚、草稿清空、Workspace 移除或进程退出时，只要最后一个
owned handle drop 就由操作系统回收。外部文件选择路径只释放引用，永远不删除用户文件。

附件上限按语义分两层：Desktop 对每份 draft/当前 Session 维持最多 `32` 个待发送项；Tauri bridge 允许
跨多个 Workspace 草稿共存，但全进程最多 `256` 个 active selection，clipboard owned temp 总字节最多
`256 MiB`。达到全局上限只拒绝本次 paste/选择，不清理其他草稿。

剪贴板来源只在 Tauri-local `AttachmentSelection` 增加可选 `media_type`/`origin` 展示元数据，不进入
`assistant-protocol`，也不进入持久 UserMessage。Runtime Host 在真正上传时仍重新 sniff 媒体类型，不能
把 Web MIME 或 Desktop sniff 当成信任边界。

已有 Session 与新会话草稿都延迟到点击发送再上传/物化；paste 本身不创建 Session、不调用附件 HTTP
上传。Composer 发送条件调整为“正文非空或至少有一个有效附件”，从而允许图片-only 输入。

### 4.3 首次发送传输入口

Host 新增专用 multipart 入口：

```text
POST /session-materializations
```

multipart 第一部分是 `SessionMaterializationManifest` JSON，后续部分是草稿中仍有效的选中文件。Tauri
新增一个批量原生命令，直接用现有选择句柄串流这些文件；WebView 不接触物理路径。

Manifest 至少包含：

- Desktop 在点击发送时生成的 `idempotency_key`；只有响应结果不确定时才在重试间保持不变；
- Workspace、模型、reasoning effort、变体和审批模式；
- 首条消息文本、结构化引用、Skill/Goal 意图；
- 每个文件的 selection key、原始名称和声明大小。

Host 对 JSON 大小、文件数量、单文件与总字节数执行现有上限；逐文件计算内容哈希、检测媒体类型并写入
现有 upload staging。任一部分失败时删除本次 staging，不调用 Runtime。

### 4.4 Runtime 物化命令

Host 把经过校验的 manifest 与 `Vec<StagedAttachment>` 交给 Runtime 的
`materialize_session`。Runtime 复用现有创建 Session 和接受 Input 的领域校验，完成：

1. 依据 idempotency key 查询已完成结果；存在时直接返回同一 Session、Input、Run 和附件；
2. 解析 Workspace、模型、权限、Skill、Goal 和 System Context；
3. 冻结 Workspace 执行环境并生成 System Prompt；
4. 分配 Session、附件、Input、Run 等正式 ID；
5. 为附件计算确定的稳定视图路径，并构造 `FileReferences`；
6. 校验引用数量、大小与结构并构造最终 `UserMessage`；
7. 计算现有确定性兜底标题；
8. 调用一个 Store `materialize_session(NewStoredSessionMaterialization)`；
9. Store 成功后安装内存 Session、权限作用域与队列，再发布现有 Session/Input/Run 事件并唤醒执行。

返回 DTO 为 `SessionMaterializationResult`，包含完整 Session 摘要、Input ID、Run 摘要和附件快照。Desktop
收到成功结果后才切换为正式 Session、释放原生句柄并清空对应草稿。

### 4.5 Store 的窄原子操作

`AssistantRuntimeStore` 增加一个业务方法 `materialize_session`，不拆成公开的 prepare/commit 协议，
也不扩展为通用事务协调器。Host Store 的具体顺序为：

1. 校验 staging 文件仍存在、大小和哈希一致；
2. 创建本 Session 的私有目录、附件稳定视图和必要的 content-addressed Blob；
3. 在一个 SQLite 事务中写入 Session、Session Resources、附件/Blob 元数据、Input、Run、Goal/Skill、
   初始用量和 materialization idempotency key；
4. 提交事务后返回完整持久化投影；
5. 任一步失败则回滚数据库并清理本次 Session 目录、稳定视图与 staging。

文件系统与 SQLite 无法组成同一物理事务，因此采用“文件准备在前、数据库可见性提交在后”。数据库提交
前 Session 不可查询；崩溃留下的无引用 Blob 或临时目录由现有启动修复流程扩展清理。不得先提交一个
可见空 Session 再尝试删除。

`sessions` 新增 nullable unique `materialization_key`。该字段只解决首次发送响应丢失后的幂等重放，
不代表草稿实体。相同 key 且 manifest 业务摘要不同时返回 conflict；相同内容返回既有结果。Desktop
收到明确的提交前失败后允许用户继续编辑，并在下一次发送时生成新 key；只有响应结果不确定的自动重试
才沿用原 key 与原 manifest。

### 4.6 失败与恢复

| 失败位置 | 用户可见结果 | 恢复行为 |
| --- | --- | --- |
| 文件选择失效/流式校验失败 | 仍停留草稿，指出具体附件 | 保留其余草稿；用户移除或重选后下一次发送使用新 key |
| Runtime 领域校验失败 | 仍停留草稿，就地错误 | 未调用 Store，无 Session 记录 |
| Store 提交前失败 | 仍停留草稿 | 回滚并清理本次文件产物，无可见 Session |
| Store 已提交、HTTP 响应丢失 | Desktop 状态不确定 | 同 key 重试返回同一 Session，不重复创建 |
| 提交后进程崩溃、事件未发布 | 重连后从 Snapshot 看到正式 Session/Run | 启动恢复按现有持久 Run 规则继续，不依赖草稿 |

旧的 `create_session`、单 Session 附件上传和 `submit_input` 入口继续存在。新 Host 向旧 Desktop 兼容；
新 Desktop 首次发送必须检查 Host capability `session_materialization`，缺失时提示完成应用更新/重启，
不能退回“先建空 Session”的旧流程。

## 五、标题与旁路推理

### 5.1 只抽取薄的单轮模型执行能力

`agent-model` 增加一个小型异步 helper（名称在实现阶段按现有命名确定），输入现成的 `ModelService`、
`ModelRequest` 与取消信号，内部完成：

- 消费 stream；
- 经过现有 `LifecycleValidator`；
- 收集唯一最终 `AssistantMessage`、结束原因和 usage；
- 把协议错误、Provider 错误、取消和不完整流归一为现有模型错误。

它不负责读取 Conversation、不选择模型、不设置超时、不记录 Session 状态，也不知道标题、压缩或图片。
`RollingSummarySameModel` 改为使用该 helper；标题使用同一 helper。辅助识图可在不改变其输入语义的前提下
复用，但仍由图片工具独立构造请求。

不新增 `SideSession`、通用 SideTask Registry 或第二套 Run/Queue。

### 5.2 标题用例

`assistant-runtime` 新增 title 领域模块，核心入口语义为：

```text
generate_session_title(session_id, trigger)
trigger = automatic | manual
```

调用方只提供 trigger。标题模块在调用时自行取得该 Session 最新稳定 Conversation Snapshot；自动和手动
路径不得分别装配“首轮消息”“近期消息”或 Context Summary。读取只短暂进入 Session mutation gate，快照
完成即释放，不要求 Session idle，也不阻塞活动 Run、Queue、Approval 或 Compaction。

标题输入选择固定为：

- 可见 User 文本和结构化引用的 `exact`；
- 可见 Assistant 最终文本；
- 当前 generation 中最近的 Context Summary（如果存在）；
- 保持原顺序，优先保留首个 User 意图，再从最新完整 turn 向前装入，UTF-8 文本总量不超过 `12 KiB`。

Reasoning、ToolCall、ToolResult、Internal/Injected Context、附件字节、物理路径、引用来源 locator、凭据和
Provider State 全部排除。机制内构造固定目的说明，不主动请求 reasoning，且只暴露一个
`submit_session_title({ title })` 输出契约函数，不暴露任何业务工具。工具选择在标题模块内按模型已编译
能力使用最强约束：`Named` 优先，其次 `Required`，只声明 `Auto` 的路由使用单工具 `Auto`。部分
reasoning-first Provider 会在未指定 reasoning 时仍使用模型默认推理，因此输出预算上限为
`1024` tokens 且不超过当前模型已编译的最大输出；单次超时 `20s`。

Runtime 不注册、调度或执行该函数，不生成 Tool Result，也不把这个 ToolCall 写入 Conversation。结果只接受
唯一且名称匹配的 ToolCall：参数必须只有字符串 `title`，折叠空白、取第一个非空行、去除成对引号和
Markdown 标题符号，最终限制为 `1–80` 个 Unicode scalar。普通 Assistant Text、多次/错误 ToolCall、
空参数或模型失败均保留原标题，因此接续回答不再可能覆盖标题。

### 5.3 自动与 `/title` 触发

- 新建普通 Session 和 Fork Session 的 `automatic_title_pending = true`；Controller 为 false；迁移前既有
  Session 回填 false，避免升级后批量生成。
- pending 期间第一个成功且包含非空最终 Assistant Text 的用户来源 Run 启动 automatic trigger；失败、
  取消或可重试终态不提前耗尽资格。自动任务进行中不重复启动，任务成功或失败后统一置 false。
- 自动生成成功仅在当前标题仍是现有“生成态”时写入；用户通过现有编辑入口改名后，后台自动结果丢弃。
- 手动精确 `/title` 可替换当前任何标题；它不创建 UserMessage、Input、Run 或 Queue，也不消费 Composer
  的附件、引用、Goal 或 Skill。手动 trigger 接受时同步置 `automatic_title_pending=false`，避免随后到达的
  首轮回复再用自动结果覆盖用户刚刚主动生成的标题。
- 同一 Session 同时最多一个标题模型调用。新的自动/手动 trigger 取消并替换旧调用；使用现有
  `CancellationToken` 的当前任务身份判断迟到结果，不引入持久 title revision。
- 现有直接改名命令会同步取消该 Session 正在运行的标题调用；因此 `/title` 可以主动替换调用前的用户
  标题，但不能在用户随后又直接编辑标题时以迟到结果覆盖它。
- clear 和删除会按 Session 生命周期清理取消当前标题调用；clear 统一保留当前标题，不判断标题来源。
  普通 Run 或 Compaction 在快照之后提交不使标题结果失效，也不引入 generation/revision 比较。
- 自动与 `/title` 的成功结果都沿用现有 `SessionTitleOrigin::Generated`；只有直接编辑标题使用
  `SessionTitleOrigin::User`。该字段只复用现有用户改名保护，不增加新的来源层级。

`automatic_title_pending` 是唯一新增的自动资格持久状态。若 Runtime 在首轮 Run 已完成、pending 尚未结算
时崩溃，启动恢复检查这一个条件并重试；标题模型调用本身不持久化为任务。

### 5.4 状态、事件和用量

`SessionView` 增加可选的 transient `title_generation`，含 trigger、started_at 和当前状态；SSE 增加标题开始、
完成事件，使 Desktop 能显示 `/title` 状态并在事件缺口后由完整 View 收敛。自动触发默认不显示错误 UI。

Session usage 增加旁路请求聚合计数（请求次数、input/output/total tokens）。标题成功或失败后按 Provider
返回的 usage 累加；不为每次标题建立持久任务表。上下文压缩继续随 Context Summary 保存自己的 usage，
辅助识图继续归工具调用，不混进 Session 旁路状态。

## 六、Workspace 标签与多目录

### 6.1 存储模型与迁移

保留现有 `workspaces.user_directory` 物理列作为主目录，新增：

```text
label                       TEXT NOT NULL
additional_directories_json TEXT NOT NULL DEFAULT '[]'
```

Rust 和协议统一使用 `primary_directory`、`additional_directories`；Store 负责与旧物理列映射。迁移时：

- `label` 使用主目录 basename，无法取得时使用完整路径末段或“工作空间”；
- 附加目录回填空数组；
- 不改变 Workspace ID、私有目录、生命周期和原唯一主目录约束。

`session_resources` 新增 `additional_workspace_directories_json NOT NULL DEFAULT '[]'`。现有
`working_directory` 继续是冻结主目录。Session System Prompt 已持久化名称与目录描述，不额外建立
Workspace label snapshot 字段。

### 6.2 注册与编辑命令

协议新增/调整：

```text
RegisterWorkspaceRequest {
  label,
  primary_directory,
  additional_directories
}

UpdateWorkspaceRequest {
  workspace_id,
  label,
  primary_directory,
  additional_directories
}
```

两者都提交编辑弹窗的完整表单。新增 Workspace 时，Desktop 先用原生选择器取得首个目录，再打开
“新建工作空间”弹窗；只有点击保存才调用注册命令。更新由现有 `workspace_mutation_gate` 串行化，单一
Runtime owner 下不增加 Workspace revision/CAS。

校验规则固定为：

- label trim 后 `1–80` 字符，不允许控制字符；标签允许重名；
- 主目录加附加目录总数最多 `16`；
- 每条目录必须是现存、可读取、绝对 UTF-8 目录，Runtime canonicalize 后再比较与保存；
- 同一 Workspace 内不允许 canonical exact duplicate；允许用户显式登记祖先/后代目录，扫描指令和 Skill
  时按 canonical source path 去重；
- active Workspace 的 canonical 主目录全局唯一；附加目录可以出现在另一 Workspace，但 UI 与 Agent
  始终依赖显式 Workspace 身份，不能按路径反推唯一 Workspace；
- 恢复已移除 Workspace 时复用原 Workspace ID 和私有目录，同时采用本次提交的 label 与目录集合。

更新成功只改变 Workspace 当前元数据。任何既有 Session 的 `working_directory`、附加目录快照、System
Prompt、System Context 和权限上下文都不修改。

### 6.3 Session 冻结环境与 System Prompt

`SessionExecutionEnvironment` 扩展有序 `additional_workspace_directories`，主目录仍为 Shell cwd 与相对
路径解析基准。创建 Session 时：

- 从 Workspace 当前记录冻结 label、主目录和附加目录；
- System Prompt 明确 Workspace label、根目录顺序、主目录语义和“工作区不是强沙盒”；
- 每条根目录读取自己的根 `AGENTS.md`，按主目录、附加目录顺序组成 System Context，并标注来源根；
- Workspace 仍只有一个 `.ez-assistant` 私有目录；其中可选的 Workspace 权限文档只保存用户显式规则。

`agent-tools-local` 无需改成多根 resolver：相对路径和 Shell cwd 继续落在主目录；附加目录以明确绝对路径
使用。Runtime 按 Session 冻结的全部 Workspace 根目录提供结构化文件缺省能力：Plan/Build 允许
Read/List/Find/Search，Build 允许 Write/Edit/Delete；显式 Deny/Ask 优先于该缺省 Allow。Workspace
目录变动不创建或改写权限文件，既有 Session 继续使用原冻结根。Shell 不继承该缺省能力，文档与 UI
不得把登记目录描述为操作系统沙盒。

### 6.4 Skill、Controller 与投影

Skill 扫描依次遍历主目录和附加目录的现有两个 Workspace Skill 位置。`SkillCandidate` 对 Workspace 来源
增加 `workspace_root_order`：同名 Skill 先选更靠前根目录；同一根目录同一优先级仍按现有冲突规则报错。
User Skill 的来源优先级不变。

Controller 查询受管 Session 时返回 Workspace 当前 `label`，避免只暴露不透明 ID。右侧当前上下文同时
展示：

- 当前 Workspace label（可随编辑立即更新）；
- 当前 Session 冻结的主/附加目录；
- 当两者有差异时的“本会话继续使用创建时工作目录”状态。

这里的 label 更新只是元数据投影，严禁借此重算已有 Session 的 System Prompt 或冻结 System Context。

## 七、会话文本结构化引用

### 7.1 前端选区捕获

每条可靠 User/Assistant 消息正文提供一个标注 owner、generation、message identity 和 role 的可引用根
容器。Desktop 根据 Selection 的 anchor/focus 向上查找根容器；两端属于同一根即可引用，不要求落在
同一个文本节点或 Markdown 子元素。跨消息、工具块、附件标题、代码编辑器或交互控件的选择直接拒绝。

引用动作完全在 Desktop 内完成：

1. 用 TreeWalker 连接根容器内可引用文本节点，排除 `aria-hidden`、按钮和其他交互控件，建立
   `QuoteTextProjection` 及 DOM boundary map；不把 CSS 产生的隐式空白当成 source offset；
2. 克隆当前 Range，把 anchor/focus 规范化为投影中的 `text_start_utf16/text_end_utf16`；UTF-16 与
   Web Selection/编辑器惯例一致，Runtime 不用该数值直接切 UTF-8 字符串；
3. `exact` 使用 Range 的可见文本并统一换行符，`prefix/suffix` 从同一投影按 Unicode 边界截取；链接、
   行内代码和强调等渲染结构不反向转换为 Markdown；
4. 在 Composer quote store 中直接生成临时 `quote_id` 和来源 locator，不发送 command，也不等待 Runtime。

来源位置始终以消息可见文本范围为准。限制保持为：每条引用 `exact <= 8 KiB`、`prefix/suffix <= 128`
Unicode 字符，每条输入最多 `16` 条引用，
引用可见文本总量不超过 `32 KiB`。

### 7.2 Provider-neutral 消息类型

`agent-types::UserPart` 新增：

```text
QuotedText {
  quote_id,
  exact,
  prefix,
  suffix,
  source_owner,
  source_generation,
  source_message_id,
  text_start_utf16,
  text_end_utf16,
  source_role,
  source_label,
  source_created_at_ms
}
```

来源 Session/子任务标题作为冻结显示元数据，locator 只用于应用内导航，不是授权凭据。引用随所在
UserMessage 的 Conversation body 一起持久化，不增加 Quote 表。协议 `UserMessageSnapshot` 增加 `quotes`
投影，Desktop 已发送消息和 Composer 使用同一详情模型。协议只承载序列化后的范围，不承载 DOM Range。

OpenAI-compatible Chat/Responses Adapter 将引用稳定序列化为结构化文本块：正文只使用一次转义后的
纯文本 `exact`，并携带每侧最多 128 个 Unicode 字符的 `prefix/suffix`。`source_*`、text range 和
`quote_id` 均不进入 Provider 投影，也不提示模型调用引用专属工具。Desktop 仍不得把引用直接拼进用户
textarea Markdown。

### 7.3 提交校验与持久化

普通 `SubmitInputRequest` 和首次 materialization manifest 都携带结构化引用。Runtime 在接受输入时：

- 校验引用数量、总量、字符串字节上限、UTF-16 range 的非负/顺序/整数边界和结构字段，不接受超限或
  畸形载荷；Runtime 不用来源 range 对 UTF-8 字符串做切片；
- 来源 locator 若能在目标 Session 当前 Conversation 中核对，则保留为可定位；来源已 clear、generation
  已变化或身份不属于目标 Session 时，不用相似文本补救，只把来源状态降级为 unavailable；
- 无论来源是否仍可定位，都保存冻结 `exact/prefix/suffix`，因此来源失效不损坏用户内容；
- 不签发 HMAC reference，不新增 `read_message_by_id` 或引用专属 Recall 工具。

这一边界与常见开源 Agent 一致：引用本身带足选中内容和有界上下文，来源 identity/range 只供产品导航；
既有 Conversation Recall 仍按原机制工作，但不由 quote 创建、签名或授权。

### 7.4 来源解析与瞬时焦点

点击“查看来源”时，Desktop 直接使用 quote 中的 owner、generation、message identity 和 visible range：
先切换到对应主 Conversation/子任务，再通过现有 Conversation 投影或普通历史分页找到消息。这里不调用
引用专属 prepare/resolve command；来源无效只显示 unavailable，不修改引用正文。

Desktop 新增单实例 `TransientFocusStore`，只保存当前
`{owner, message_id, text_start_utf16, text_end_utf16, nonce}`。
消息组件只消费该临时投影，不写 Conversation 状态、不修改正文、不持久 class。不同 owner 通过可注册的
导航解析器定位，新增来源类型只扩展解析器。

以下路径必须统一调用 `clearTransientFocus()`：

- **点击发送的同步起始阶段（无论随后发送成功或失败）**；
- 新定位开始、详情关闭、用户滚动、切换 Session/子任务；
- `1600ms` 超时、定位失败、目标卸载或页面卸载。

高亮使用 overlay/data-state，并在清理时撤销计时器、observer 与 DOM 状态。来源不存在时只展示冻结预览，
严禁留下不可恢复高亮。

## 八、Desktop 交互实现

### 8.1 Composer 上下文区

Composer 使用有序 `ComposerContextItem = attachment | quote` 列表展示附件和引用 Tag；Skill/Goal 保持
独立提交意图。每个 Tag 主体打开详情，独立按钮移除。

- 未上传附件详情通过 Tauri 受控预览命令读取现有 selection handle，不返回物理路径；
- textarea paste handler 把图片批次登记结果交给和文件选择器相同的附件 reducer；混合粘贴用当前
  selectionStart/selectionEnd 更新草稿和光标，纯文字粘贴不接管；
- clipboard selection 的 generated name、`media_type` 和 `origin` 只用于 Tag/详情；附件正式名称和类型
  在 Host 上传校验后以 Runtime 投影为准；
- 已上传附件复用现有 Runtime 预览；
- 引用详情使用冻结内容；来源状态根据当前 Conversation 投影和直接 locator 惰性计算，不调用引用专属
  Runtime command；
- 发送失败保留上下文项；首次/普通发送可靠接受后统一清空并释放句柄；
- 退出动画只控制视觉生命周期，不延迟文件句柄释放和业务状态清理。

### 8.2 Workspace 统一编辑弹窗

不修改全局设置导航。左栏 Workspace 菜单和右侧“工作区”Section 的编辑按钮都打开同一个
`WorkspaceEditorDialog`；新建与编辑仅模式和初值不同。

弹窗内一份受控表单同时维护 Workspace 名称、主目录、附加目录、主目录切换和排序，保存时提交完整 DTO。
右侧正式 Session 打开弹窗时，保存后可刷新当前 label，但目录展示继续使用 Session 冻结快照，且不触发
System Prompt/System Context 更新。

### 8.3 Presence 与过渡动画

Desktop 不新增第三方动画依赖。新增共享 `usePresence`/`Presence`：

- open 时立即挂载并进入 entering/entered；
- close 时先置 exiting、`inert`、`aria-hidden` 和不可点击，等待 `transitionend` 或短 fallback 后卸载；
- 快速反向打开取消旧 timer，父级卸载统一清理；
- Dialog 退出期间继续保持背景锁定，完全退出后恢复 opener 焦点；
- Menu、Popover、Context Menu 按 placement 写入展开方向；
- 锚点浮层在 Presence 挂载 Portal DOM 后执行或重跑定位；只有位置 ready 后才进入可见态，不能让
  定位 effect 只跟随业务 open、早于实际 DOM 挂载而永久保持透明；
- Collapse 使用 CSS Grid 的自然布局过渡；展开态不锁定测量高度，嵌套内容变化直接参与父级布局，
  不把尺寸逻辑塞进 Presence。

SCSS 新增统一 motion token 和 `data-presence` 状态。`prefers-reduced-motion: reduce` 将时长压至近零，但仍
走相同清理路径，不能依赖动画事件才完成卸载。

### 8.4 左右分栏与偏好

AppShell 使用 CSS variables 表达左右栏实际宽度，新增两个 `SidebarResizeHandle`。Pointer Events 使用
pointer capture；拖拽时关闭文字选择和 width transition，`pointerup`、`pointercancel`、窗口失焦和卸载都
释放捕获。

宽度规则：

- 左栏 `220–420px`，默认 `286px`；
- 右栏 `220–800px`，默认 `326px`；
- 中栏至少 `500px`；左右栏显示时始终使用各自偏好宽度，不随窗口宽度临时压缩；默认在三栏固定
  宽度无法同时容纳时先隐藏右栏，连左栏偏好宽度与中栏也无法容纳时再隐藏左栏；
- 响应式 effective visibility 与用户 open preference 分开，窗口变宽后自动恢复；
- 键盘步长 `8px`，Shift 为 `24px`，Home/End 到当前有效边界，双击恢复对应默认值。

AppShell 横向骨架使用不换行 Flex；侧栏以固定 `width` 占位，中栏 `flex` 填充剩余空间，拖拽柄以负
margin 覆盖分界线而不占布局宽度。删除旧媒体查询中的并行 Grid 轨道规则，避免 DOM 增加拖拽柄后因
轨道数量不匹配产生隐式下一行。

右栏展开/收起入口属于 AppShell 会话标题栏的固定操作，始终排在“更多会话操作”右侧；ContextPanel
栏头只展示“当前上下文”标题。按钮只根据 effective visibility 切换展开/收起语义，不随右栏宽度移动，
因此响应式临时收起后仍可直接重新打开右栏。

右侧 `ContextPanel` 以自身容器宽度而非窗口宽度响应：低于 `620px` 时 Section 单列排列，达到
`620px` 时切换为两条独立纵向 Flex 列，卡片按原顺序交替分配，不要求左右卡片同行或底边对齐。
`ResizeObserver` 只负责切换展示布局并在卸载时释放；长路径和长文本只在卡片内部截断，不能反向撑宽
侧栏或产生水平滚动。

Tauri `DesktopPreferences` 新增 `left_sidebar_width`、`right_sidebar_width`，沿用现有 JSON 临时文件替换写入；
反序列化对缺字段使用默认值并 clamp 非法值。只在拖拽结束、双击、键盘调整 debounce 或“恢复默认布局”时
写盘，响应式显隐结果不回写。恢复默认布局同时恢复两栏默认宽度和用户 open preference。

## 九、协议、存储与兼容性汇总

### 9.1 主要协议增量

- Host capability：`session_materialization`；
- 首次 multipart manifest/result；
- Workspace label、主目录、附加目录与 update 命令；
- 纯文本引用快照和直接来源 locator；
- `generate_session_title` 命令、transient 状态与 SSE 事件；
- Session/Context 投影中的当前 Workspace label 与冻结目录；
- Desktop TypeScript bindings 继续由 `assistant-protocol` 生成，禁止手改生成文件。

新增字段尽量使用 serde default，保证新 Host 能读取旧数据和处理旧 Desktop 命令。首次 materialization 是
新 Desktop 的能力门槛，不通过旧命令组合模拟。

### 9.2 数据库迁移

| 表 | 变化 | 旧数据回填 |
| --- | --- | --- |
| `workspaces` | `label`、`additional_directories_json` | basename、`[]` |
| `session_resources` | `additional_workspace_directories_json` | `[]` |
| `sessions` | unique nullable `materialization_key`、`automatic_title_pending` | `NULL`、false |
| Session usage | 旁路请求和 token 聚合列 | `0` |

新普通/Fork Session 设置 `automatic_title_pending=true`，Controller false。所有 JSON 读取必须验证类型、数量、
绝对路径和顺序；非法持久值使对应 Workspace/Session 明确 unavailable，不静默换到其他目录。

### 9.3 安全与隐私

- Workspace 多目录只扩大显式告知 Agent 的工作上下文，不提升进程权限，也不是强沙盒；
- 引用创建不使用签名 key 或 opaque capability；直接 locator 只在应用协议内流转；
- 引用 provider 投影排除来源 identity、visible range、quote ID 和不必要元数据；
- 标题输入排除工具结果、内部上下文、文件内容和凭据，输出不执行为指令；
- Desktop 附件预览和首次发送继续基于原生句柄，WebView 不接触本地绝对路径；剪贴板图片通过 Tauri
  raw binary IPC 登记，禁止 Base64 持久化，并受 `32 MiB` IPC 上限、附件数量和 Runtime 最终校验约束；
- 所有新 HTTP 入口沿用 loopback Host、body limit、来源与错误映射约束。

## 十一、验证方案

### 11.1 Runtime/Store

- 首次发送无附件、多附件、Skill、Goal、引用组合均只生成一组 Session/Input/Run；
- 每个 Store 阶段失败注入后 Session 不可见、staging/视图可清理；提交后响应丢失重试返回同一结果；
- 新旧 Workspace 迁移、编辑、移除/恢复、目录排序和冻结环境正确；
- 既有 Session 在 Workspace 编辑前后 System Prompt、System Context 和冻结目录逐字不变；
- 根 AGENTS 与 Skill 按主/附加顺序生效，同根冲突和跨根覆盖符合规则；
- 自动标题资格、失败兜底、用户改名竞态、重复 `/title`、活动 Run/Approval/Compaction 下调用、clear
  保留标题和重启恢复均有确定性测试；
- 引用数量/大小/结构校验、跨 Session locator 降级、来源 stale 和消息持久化/恢复均覆盖；
- Chat/Responses 两条 Provider 投影都始终包含冻结内容和有界前后文，且不暴露来源 identity/range。

### 11.2 Desktop

- 多 Workspace 与 unbound 草稿切换不创建列表记录，进程退出不恢复；
- 首次发送失败保留全部 Composer 状态，成功才清空，重复响应不会插入两行；
- 单图、多图、图片-only、纯文字和文字+图片 paste 均有组件测试；超 `32 MiB`、伪造 MIME、超过附件
  余量和批次中途失败不留下半批 Tag 或 owned temp；
- 新会话草稿切换保留 clipboard selection，移除、发送成功、TTL、Workspace 移除与应用退出均清理；
- Workspace 同一编辑弹窗从左栏与右栏打开，名称与目录一次保存；既有 Session 右栏仍展示冻结目录；
- 同消息跨文本/行内代码/链接/强调的 Selection、重复短句范围和每侧 128 字符上下文边界；
- 点击引用不发生 Runtime 请求；原生右键不被拦截，Tag 详情、附件预览、来源不可用降级和发送起始
  强制清除高亮；
- Dialog/Menu/Popover/Collapse 的进入、退出、快速反向、焦点恢复、父级卸载和 reduced motion；
- 左右栏 pointer/keyboard 调整、宽度边界、响应式临时收起、重启恢复和默认布局。

### 11.3 最终命令

实现阶段至少执行：

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace

cd apps/desktop
npm run build
npm run tauri -- build --no-bundle
```

此外需要用真实 Runtime Host 做一次首发响应丢失重试、包含附件的首次物化、Workspace 编辑后新旧 Session
对比、跨元素短文本引用与来源定位，以及应用重启后分栏偏好恢复的人工验收。

## 十二、风险与明确取舍

| 风险 | 约束与处理 |
| --- | --- |
| 文件系统与 SQLite 不能真正原子 | 数据库最后可见，单 Store 方法负责补偿；启动恢复清理孤儿，不建立通用事务系统 |
| 多目录导致指令/Skill 歧义 | 固定主目录优先和附加目录顺序，来源显式标注，同一根冲突仍报错 |
| Workspace 编辑被误解为热更新 Session | Session 冻结目录与 Prompt 不变；UI 同时展示当前 label 和冻结目录说明 |
| 标题旁路与活动 Run 竞态 | 每次内部读取最新稳定 Snapshot；短锁后释放，只用当前内存任务身份阻止被新 trigger 替代的迟到结果 |
| 渲染选区与来源范围错配 | exact 始终冻结；范围从同一消息可见文本投影计算，跨 inline element 允许，跨消息拒绝；不反向搜索 raw Markdown occurrence |
| 剪贴板图片造成内存峰值或临时文件泄漏 | raw IPC 单图 `32 MiB`、全进程 owned temp `256 MiB`；整批回滚，selection source 区分外部路径/匿名 owned handle，TTL 与 handle drop 清理 |
| 退出动画残留交互/焦点 | exiting 立即 inert，统一 fallback 清理，reduced motion 也走相同完成路径 |
| 响应式显隐污染用户宽度 | preferred width 与 effective visibility 分离，只持久化明确用户动作 |

本方案没有待定的产品范围项。确认后，开发计划按“协议与存储基线 → Runtime 领域能力 → Desktop 草稿与
Workspace → 引用与 Composer → 动效与分栏 → 集成验收”拆分里程碑；每个里程碑完成验证后单独等待确认。
