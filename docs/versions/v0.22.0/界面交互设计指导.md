# v0.22.0 界面交互设计指导：会话、Workspace 与上下文交互优化

## 一、设计信息

- 版本：`v0.22.0`
- 状态：已确认（2026-09-02；文本引用按前端选区与直接来源定位收敛）
- 影响模块：`apps/desktop`，以及 Desktop Preferences 的 Tauri 原生读写适配
- 关联设计：
  - [`v0.22.0 功能设计`](功能设计.md)；
  - [`Desktop 设计语言`](../../resources/桌面端设计语言.md)；
  - [`desktop 模块约束`](../../modules/desktop.md)；
  - [`前端编程规范`](../../specs/前端编程规范.md)。
- 设计基线：保留现有左侧会话栏、中部 Conversation/Composer、右侧当前上下文三栏产品外壳，
  不为本版本创建新窗口、全屏路由或另一套导航体系。

> 本文固定真实页面入口、布局关系、操作路径、动画、键盘、状态和视觉验收口径。组件目录、状态
> 类型、协议字段、持久化结构和动画实现原语由技术方案确定。本文确认不等于授权进入代码实现。

## 二、页面与入口

### 2.1 入口总览

| 能力 | 主要入口 | 辅助入口 | 落点 |
| --- | --- | --- | --- |
| 新会话草稿 | 左栏顶部“新对话”菜单 | Workspace 行“在此新建会话”、`/new` | 中栏新会话页与 Composer |
| 自动标题 | 首轮可靠回复后的后台触发 | 无 | 会话 Header 与左栏会话标题 |
| 手动标题 | Composer 精确 `/title` | Slash Command 列表 | 会话 Header 与左栏会话标题 |
| Workspace 编辑 | 左栏 Workspace 菜单“编辑工作空间…” | 右栏“工作区”Section 编辑按钮 | 同一个“编辑工作空间”弹窗 |
| 文本引用 | 选中文本后的浮动“引用”气泡 | 无；保留 WebView 原生 Context Menu | Composer 顶部上下文区 |
| 图片粘贴附件 | Composer textarea 内粘贴 | 截图工具、浏览器或文件管理器复制图片 | Composer 顶部上下文区 |
| 附件/引用详情 | Composer Tag 主体 | 已发送消息中的引用摘要 | 详情弹窗 |
| 来源定位 | 引用详情“查看来源” | 已发送引用摘要的来源动作 | 当前 Session 消息流 |
| 左右栏调宽 | 两条栏间分隔条 | 键盘调整、布局菜单恢复默认 | 主窗口三栏布局 |
| 统一动效 | 所有 Desktop 自有浮层与 Collapse | `prefers-reduced-motion` | 原组件位置 |

### 2.2 新会话入口不再创建列表项

- 左栏“新对话”仍使用现有下拉菜单，但 Workspace 选项主文案改为固定 `label`，次级文案显示主目录
  basename；重名标签必须保留目录信息用于区分。
- “未绑定工作空间”替代当前容易与普通 Session 混淆的“独立会话”新建文案；会话列表中既有
  未绑定 Session 分组名称可继续使用“独立会话”。
- 点击 Workspace 或未绑定选项只进入对应新会话草稿，不在 Workspace 分组下插入临时会话行。
- 某分区已有非空草稿时，菜单项右侧显示弱化的“有草稿”文字；它只是新建菜单状态，不是会话记录、
  未读角标或搜索结果。
- Workspace 行“在此新建会话”和现有 Session 的 `/new` 都进入同一 Workspace 草稿；重复触发
  继续已有草稿，不静默清空。

### 2.3 Workspace 编辑弹窗入口

- Workspace 编辑不进入全局设置弹窗，不增加“工作空间”设置导航、Workspace 列表页或详情页。
- 左栏 Workspace 的 `…` 菜单在“复制目录路径”和“移除工作空间…”之间增加“编辑工作空间…”，
  打开该 Workspace 的统一编辑弹窗。
- 右侧当前上下文的“工作区”Section 标题行增加独立编辑按钮；点击只打开同一个 Workspace 编辑
  弹窗，不触发展开/收起。
- 编辑弹窗同时维护 Workspace 名称、主目录与全部附加目录，不拆分“重命名”和“目录管理”入口。
- 新增 Workspace 继续通过原生目录选择器取得首个主目录；选择完成后打开同一弹窗的“新建工作空间”
  形态，用户可以一起确认默认名称和目录。

## 三、应用壳层与分栏

### 3.1 三栏尺寸

保持现有中栏信息结构，新增用户偏好宽度：

| 区域 | 默认宽度 | 用户可调范围 | 说明 |
| --- | ---: | ---: | --- |
| 左侧会话栏 | `286px` | `220–420px` | 容纳 Workspace 标签、会话标题与操作 |
| 中部会话区 | 自适应 | 不低于 `500px` | Conversation 与 Composer 的主工作区 |
| 右侧当前上下文 | `326px` | `220–800px` | 容纳多目录、附件、Skills 与运行信息 |

- 用户保存的是左、右栏各自的偏好宽度；窗口实际宽度通过上述边界与中栏最低宽度计算。
- 左右栏关闭时不把 `0` 写成用户宽度；重新打开恢复最近偏好。
- 左右栏显示时始终使用保存的偏好宽度，不随窗口宽度自动压缩。窗口不足以同时容纳两栏偏好宽度
  和 `500px` 中栏时，右栏先进入临时收起；用户此时主动打开右栏，则临时收起左栏。窗口进一步
  缩小到无法容纳左栏偏好宽度和 `500px` 中栏时，再临时收起左栏。窗口恢复后自动恢复，不覆盖偏好。
- 临时响应式收起必须与用户主动关闭区分；只保存用户动作，不保存窗口尺寸导致的有效状态。
- 右栏展开/收起按钮固定在中栏会话标题栏的“更多”按钮右侧；这组按钮各自带有背景，因此保留
  小间距。右栏栏头只保留“当前上下文”标题。按钮不随右栏拖拽移动，右栏隐藏后仍在原位提供
  展开入口。
- 不增加水平页面滚动，不允许分隔条或侧栏覆盖 Composer、消息滚动条和浮层定位基准。
- 右侧上下文 Section 按右栏自身宽度响应：低于 `620px` 保持单列，达到 `620px` 自动排成两条
  独立纵向列；同列卡片自然紧邻，不等待另一列卡片高度，也不要求左右对齐。宽度再次缩小时恢复
  单列。切换只改变展示布局，不改变展开状态或业务数据。

### 3.2 分隔条

- 左分隔条位于左栏右边界，右分隔条位于右栏左边界，覆盖标题栏以下的完整应用主体高度。
- 可见线保持 `1px` 普通 Border；可命中区域为 `8px`，向两侧均匀扩展，不改变内容对齐。
- Hover 或键盘聚焦时线条使用 Primary Border，拖拽时使用 Primary 并显示 `col-resize` 指针。
- 拖拽过程中只改变目标侧栏实际宽度，另一侧不联动；中栏达到最低宽度后稳定停止。
- 拖拽期间关闭文字选择，并继续允许当前 Conversation 流式渲染；拖拽结束、`pointercancel`、窗口失焦
  或组件卸载都立即释放指针捕获。
- 双击某一分隔条只把对应栏恢复到默认宽度，不改变另一栏或开关状态。

### 3.3 键盘与布局恢复

- 分隔条使用 `role="separator"`、`aria-orientation="vertical"`、当前值与最小/最大值，并进入 Tab 顺序。
- 左分隔条：`←` 变窄、`→` 变宽；右分隔条方向相反，按视觉边界向外为变宽、向内为变窄。
- 普通方向键每次调整 `8px`，`Shift + 方向键` 每次调整 `24px`；`Home` 到最小，`End` 到当前窗口
  允许的最大值。
- 会话 Header 的布局操作区新增“恢复默认布局”，恢复左右栏默认宽度并展开两栏；若当前窗口太窄，
  仍按 3.1 临时收起规则展示。
- 调整完成后出现一次不抢焦点的可访问状态，例如“会话栏宽度 312 像素”；不显示持续 Toast。

## 四、新会话草稿

### 4.1 中栏空状态

进入新会话草稿时，中栏使用现有 Conversation 页面骨架，不创建营销式欢迎页：

- Header 标题显示“新对话”；标题下或相邻弱化区域显示 Workspace `label`，未绑定时显示“未绑定工作空间”。
- 消息区为空，只显示紧凑图标、“开始新会话”和“输入消息或使用 / 指令”。
- Composer 保持完整可用，包括模型、reasoning effort、Plan/Build、Ask/Auto、文件选择/图片粘贴附件、
  Skill、Goal 和引用 Tag。
- Composer 底栏使用内容驱动的自适应排列：可选的上下文用量环、托管入口等增减时，不能依赖
  子元素序号占用固定网格列。执行设置和模型名称按内容占宽，只设最大宽度并在空间不足时单行省略；
  只有纯图标按钮保留稳定点击尺寸。
- 右栏如果打开，显示“草稿设置”和当前 Workspace 信息；不显示 Session ID、Run、Token、附件历史、
  Skills Catalog 或其他尚不存在的 Runtime 事实。
- 新会话页不伪造会话状态、更新时间、标题编辑、归档、删除、导出、clear、compact 或代理入口。

### 4.2 草稿切换

- 从草稿进入已有 Session 时，正文、附件选择、引用和 Composer 设置留在原 Workspace 草稿中。
- 再次从“新对话”菜单选择该 Workspace 时恢复草稿，并把输入焦点放回 Composer；不自动打开附件
  或引用详情。
- 切换到其他 Workspace 草稿时，所有 Tag、输入文本和设置一起切换，不能只换文本却沿用附件或引用。
- Header 更多菜单在草稿非空时提供“清空当前草稿…”。正文、附件或引用存在时需要确认；纯默认
  设置的空草稿可直接恢复默认，不弹确认。
- 退出应用不提示保存这些草稿，也不承诺下次恢复；正常退出时只释放原生文件选择句柄。

### 4.3 首次发送

- 用户点击发送后，发送按钮进入现有 pending 反馈；页面仍保持草稿态，不先插入灰色或骨架 Session 行。
- 可靠接受成功后，会话行一次性出现在对应 Workspace 分组，中栏 Header 切换为兜底标题，随后显示
  正常 UserMessage、Run 和流式 Assistant 内容。
- 首次发送失败时保持在草稿页，正文、附件、引用和设置不变；Composer 上方显示可关闭的就地错误，
  输入焦点回到原位置。
- 客户端响应不确定并重试时不显示第二个“正在创建会话”，最终只落到同一会话行。
- 发送动作一开始就清除文本选区、引用浮动气泡和来源高亮；只有可靠接受成功后才清空附件/引用 Tag。

## 五、标题交互

### 5.1 自动标题

- 首次发送接受后立即展示确定性兜底标题，不显示“生成中”占位，避免列表宽度与排序跳动。
- 首轮可靠回复后，后台标题生成不阻塞 Composer，不打开弹窗，也不显示全局 Toast。
- 标题更新时，会话 Header 与左栏同一帧切换为新标题；允许一次 `110ms` 透明度过渡，不使用逐字动画。
- 自动生成失败保持兜底标题，不向用户展示持续错误；诊断信息留在 Runtime 可观测入口。
- 用户正在编辑标题时，不因后台投影更新关闭输入框或移动焦点。

### 5.2 `/title`

- Slash Command 列表新增 `/title`，说明为“根据当前对话更新标题”。
- 新会话草稿中该项显示禁用说明“发送第一条消息后可用”；Controller Session 显示“主控标题固定”。
- 普通 Session 中不因活动 Run、Queue、Approval 或 Compaction 禁用 `/title`。
- 执行精确 `/title` 后清空输入框中的命令文字；附件、引用、Goal 和 Skill Tag 保持原样，不参与生成。
- Composer 上方出现紧凑状态行“正在根据当前对话更新标题…”，不占用 Approval 或 Queue 的位置，
  也不禁用正文发送。
- 成功时状态行改为“标题已更新”，短暂保留后退出；失败时显示“标题更新失败，原标题已保留”与
  “重试”动作。重试仍调用同一个 `/title` 意图，不重放 Composer 文本。
- Session clear 后 Header 与左栏继续显示 clear 前的当前标题，不做来源区分或自动闪回兜底标题。

## 六、Workspace 标签与多目录

### 6.1 左栏与新会话菜单

- Workspace 行主文案一律使用 `label`，不再用目录 basename 代替名称。
- 有附加目录时，在 Hover Tooltip 和操作菜单中显示“主目录 + N 个附加目录”；常态列表不增加第二行，
  保持会话栏紧凑。
- 重名 label 在新会话菜单、编辑弹窗和会话搜索来源中同时展示主目录 basename；Sidebar 分组本身
  仍保持单行，完整 label 与主目录进入 Tooltip。
- Workspace 折叠只隐藏其正式 Session 行，不隐藏或删除对应草稿；草稿状态只在新会话菜单标记。

### 6.2 统一“编辑工作空间”弹窗

- 弹窗使用普通产品 Dialog，建议宽度 `640px`、最大高度 `min(80vh, 720px)`；编辑态标题为
  “编辑工作空间”，新建态标题为“新建工作空间”。
- Header 只保留标题和关闭按钮；Body 内使用一个表单同时编辑名称和目录，Footer 为“取消”“保存”。
- 第一块为“工作空间名称”：单行 label 输入，辅助说明“用于会话列表和 Agent 识别，不要求唯一”。
- 第二块为“工作目录”：按 Workspace 当前顺序展示目录行。每行包含拖拽柄、basename、完整路径、
  “主要”Tag 和更多菜单。
- 主目录固定在第一行。拖拽附加目录不能越过主目录；把附加目录设为主目录必须通过明确菜单动作
  “设为主目录”，执行后该目录移动到第一行。
- 目录更多菜单提供“在文件管理器中打开”“复制路径”“设为主目录”“移除目录”；主目录不能直接
  移除，必须先指定另一条主目录。
- “添加目录”调用原生目录选择器；重复、不可访问或冲突路径在目录块内显示就地错误，不关闭弹窗。
- 名称、目录新增、主目录切换、排序和移除都先进入弹窗内同一份表单草稿，点击“保存”后一次提交；
  关闭脏表单前使用产品 Dialog 二次确认，不使用 `window.confirm`。
- 弹窗顶部固定显示中性说明：工作空间名称保存后立即用于全局展示和 Agent 的 Workspace 识别；
  目录变化只影响之后创建的会话。无论从左栏还是当前会话右栏打开，保存都不会重建或修改任何
  既有 Session 的 System Prompt、冻结 System Context 或冻结目录。
- 移除整个 Workspace 使用产品 Dialog，明确不会删除本地目录和历史会话；若当前进程存在该
  Workspace 新会话草稿，额外说明草稿将被放弃。不得使用无法统一动效的 `window.confirm`。

### 6.3 右侧当前上下文

- 正式 Session 的 Workspace Section 标题仍为“工作区”，标题行在 Chevron 前增加 `28 × 28px`
  编辑图标按钮并提供 Tooltip“编辑工作空间”；编辑按钮与展开按钮是两个独立命中区。
- 正文首行显示 Workspace 当前 `label`。label 保存后这里可以立即更新显示，但这只是 Workspace
  元数据投影变化，不表示当前 Session 的 System Prompt 或冻结 System Context 被更新。
- 目录按 Session 冻结顺序展示：主目录带“主要”Tag，附加目录为紧凑可点击行；默认只展开前
  `3` 条，更多目录使用“显示其余 N 条”Collapse。
- 每条目录提供打开与复制动作；这些目录始终来自当前 Session 冻结快照。即使通过编辑弹窗保存了
  新目录集合，当前 Session 右栏仍保持原目录，并显示弱化说明“本会话继续使用创建时的工作目录”。
- 保留“命令行仍以当前用户权限运行，工作区不是强沙盒”说明，不因多目录改写为沙盒承诺。
- 新会话草稿右栏展示 Workspace 当前目录；正式 Session 右栏展示冻结目录，二者标题下分别标注
  “新会话将使用”和“本会话创建时使用”，避免用户误认为既有 Session 已跟随修改。

## 七、会话文本引用

### 7.1 可选文本与浮动气泡

- 只在当前主 Conversation 或当前打开子任务中的一条 User/Assistant 消息正文内选择非空文本时
  显示气泡。同一消息内允许跨普通文本、行内代码、链接、强调、列表项等渲染元素；跨消息、跨工具块、
  跨附件标题、跨交互控件或仅空白选区不显示。
- 气泡位于选区上方居中，视口不足时翻转到下方，距离选区 `6px`；采用单个“引用”动作和 quote 图标，
  高度 `30px`，不展示解释文字。
- 鼠标释放或键盘完成选区后显示；继续拖动、选区折叠、滚动消息列表、点击外部、切换 owner 或发送
  时立即关闭。
- 点击“引用”后立即在前端把引用加入当前 Session Composer，不显示网络 pending，也不因 Runtime
  连接状态失败；随后清除浏览器选区并聚焦 Composer。在子任务视图中引用时返回父 Session 主
  Conversation，再聚焦同一个父 Session Composer。
- 引用加入失败时保留原选区到错误反馈出现为止，随后清理；不能留下只有气泡、没有有效 Selection
  的悬浮控件。

### 7.2 原生 Context Menu

- 消息正文不提供 Desktop 自有右键菜单，不拦截 `contextmenu`、`Shift + F10` 或键盘 Context Menu 键。
- 复制等操作沿用 WebView/控件原生 Context Menu；引用只使用选区上方的浮动气泡，避免两个浮层竞争。

### 7.3 图片粘贴为附件

- 只有 Composer textarea 获得焦点并收到用户 paste 事件时才读取该次 `clipboardData`，不申请持续
  剪贴板权限，也不监听全局粘贴。
- 剪贴板含一个或多个图片文件项时，按原顺序在上下文区生成普通附件 Tag。已有可用名称时保留；
  没有名称时显示受控生成名，例如 `clipboard-image-1.png`。
- 同次粘贴还含 `text/plain` 时，文字替换当前 textarea 选区并把光标移到插入内容之后，图片同时加入
  上下文区。没有图片时维持浏览器原生文字粘贴和撤销行为，不显示任何附件反馈。
- 图片登记期间对应 paste 批次显示一个紧凑 pending 状态，不插入无法操作的永久空 Tag；成功后正常
  显示附件，失败时保留已插入文字和原有上下文，只显示“无法添加剪贴板图片”就地错误。
- 本次图片数量会使待发送附件超过上限时，整批图片不加入；同次文字仍照常插入。大小超限或真实内容
  不是图片时采用同一规则，不保留半成功批次。
- 图片-only 草稿可以直接发送。新会话粘贴图片在 Tag 状态中显示“将随首条消息发送”；已有 Session
  与文件选择器附件一样在点击发送后上传，不因 paste 提前创建 Session 或单独上传。
- 粘贴生成的附件 Tag、详情、预览、移除、发送失败保留和发送成功清理均复用普通附件交互，不增加
  “剪贴板图片”专属详情弹窗或消息样式。

### 7.4 Composer 上下文区

- 现有附件列表与新增引用合并为 Composer 文本域上方的“上下文区”，按加入顺序展示可换行 Tag。
- 附件 Tag：paperclip 图标、文件名、状态；引用 Tag：quote 图标、单行 `exact` 预览、来源角色。
- Tag 最大宽度 `min(280px, 100%)`，正文单行省略；多项换行时上下间距 `6px`，不让单个长引用撑宽 Composer。
- 点击 Tag 主体打开详情；独立 `×` 只移除对应项。按钮命中区至少 `24 × 24px`，不能把整个 Tag
  同时当成移除动作。
- Goal 与 Skill 仍是提交模式 Tag，位于上下文区下方、文本域上方；不与附件/引用混成同一种内容身份。
- 发送失败保留所有上下文 Tag；可靠接受成功后统一退出并清空。退出动画不延迟原生文件句柄释放。

### 7.5 附件与引用详情

- 附件 Tag 复用现有附件预览能力。尚未上传的本地选择显示名称、大小、媒体类型和本地预览能力；
  不支持预览时显示正常说明，不暴露物理路径。
- 引用详情使用普通 Dialog，建议宽度 `560px`、最大高度 `min(76vh, 680px)`。
- Header 显示“引用内容”和关闭按钮；Body 先显示冻结可见文本，再以弱化上下文展示 `prefix/suffix`。
  链接、强调和代码等渲染结构统一显示为纯文本。正文使用 Primary Soft 背景，不把三部分拼成同色长文。
- 元信息只显示来源角色、来源 Session/子任务标题和时间；不展示内部 Message ID、可见文本范围或
  Conversation generation。
- Footer 提供“查看来源”和“关闭”。来源不可用时禁用“查看来源”，正文仍可阅读，并显示“来源已
  不可定位，引用内容仍可使用”。
- 已发送 UserMessage 在正文上方展示引用摘要块；点击摘要打开同一详情 Dialog，不重新生成引用内容。

### 7.6 来源定位与高亮

- 点击“查看来源”使用引用中保存的消息身份和可见文本范围，先关闭详情 Dialog，再通过现有
  Conversation 导航滚动到来源消息；不触发引用专属准备、签发或 Recall 请求。定位完成后将键盘焦点
  放到消息容器或紧邻的可访问锚点，不把焦点塞进正文文本节点。
- 高亮使用 `Primary Soft` 背景、`Primary Border` 外描边和约 `1600ms` 淡出，不改变消息正文布局、
  border 宽度或持久 class 状态。
- 同时最多一个来源焦点。新定位开始前先清理旧高亮。
- 点击发送必须同步清除当前高亮；关闭弹窗、用户滚动、切换 Session/child、超时、定位失败或组件
  卸载同样清理。
- 来源不存在时只在引用详情中给出降级说明，不尝试用相似文本搜索并高亮其他消息。

## 八、统一动效

### 8.1 动效 Token

| 类型 | 进入 | 退出 | 位移/缩放 |
| --- | ---: | ---: | --- |
| Hover、颜色、箭头 | `110ms` | `110ms` | 只变颜色或旋转 |
| Menu、Popover、Context Menu | `120ms` | `90ms` | 沿展开方向 `4px` + opacity |
| Dialog 遮罩 | `140ms` | `110ms` | opacity |
| Dialog 内容 | `160ms` | `120ms` | `translateY(6px)`、`scale(.985)` + opacity |
| Collapse、二级抽屉 | `150ms` | `120ms` | 内容尺寸 + opacity，箭头同步旋转 |
| 左右栏展开/收起 | `160ms` | `140ms` | width + opacity |

- easing 统一使用现有 Standard Ease-Out；退出可以略快，但不能瞬间卸载。
- 拖拽分栏期间关闭宽度 transition，直接跟随指针；松手后不做二次回弹。
- 标题、列表排序、流式文字、Token 数字和输入高度变化不套用浮层动效。
- 不使用弹跳、长距离滑入、模糊内容运动、彩色光效或循环装饰动画。

### 8.2 Dialog

- 所有产品自有确认和详情使用统一 Dialog 行为，包括当前仍使用 `window.confirm` 的 Workspace
  移除与未保存表单确认；原生目录/文件选择器不在此范围。
- 打开时遮罩与内容同时进入；关闭时先让交互状态关闭、内容退出，动画结束后卸载 Portal。
- 退出期间 Dialog 不进入 Tab 顺序、不接受按钮点击，背景也不能提前变为可交互；焦点只在完全
  退出后恢复到 opener。
- 快速 Esc/重新打开、Dialog 堆叠和父页面切换必须以最上层 Dialog 为准，不残留遮罩或恢复到已卸载元素。

### 8.3 Menu 与 Popover

- `DropdownMenu`、`SelectionPopover`、Composer 上拉选择器、级联设置菜单、Slash Menu、Skill Picker、
  Todo 浮层和引用气泡共享进入/退出状态语言，但保持各自 menu/listbox/dialog 语义。
- 定位完成前保持不可见且不可交互；定位完成后从实际展开方向进入，避免先在 `(0, 0)` 闪现。
- 点击选项后业务动作立即触发，菜单执行退出动画；需要异步等待的动作在来源页面显示 pending，
  不让菜单悬停等待 Runtime。
- 打开另一个同层浮层时，旧浮层先进入关闭状态；视觉上可以短暂交叠退出，但只能有一个可交互层。

### 8.4 Collapse

- Workspace 分组、右栏 Context Section、Reasoning、长消息、Queue/Goal 二级抽屉和“更多目录”使用
  一致的 Chevron 旋转与内容尺寸过渡。
- 内容在退出期间设置为不可聚焦；动画完成后才卸载。展开时先挂载和测量，再开始进入。
- Collapse 内有滚动区域时只动画外壳，不把内部滚动位置重置为顶部。
- 流式 Reasoning 或 Queue 内容变化不能反复重启动画；只有用户改变 open 状态时播放。

### 8.5 Reduced Motion

- `prefers-reduced-motion: reduce` 下，位移、缩放、尺寸与 Chevron 旋转都即时完成；可保留不超过
  `40ms` 的 opacity 以避免闪烁。
- 加载 Spinner 保留必要状态表达，但不使用额外脉冲；来源高亮直接显示后按相同清理节点移除。
- 自动化测试启用 Reduced Motion 后仍按显式状态或 transition end helper 等待，不写固定 sleep。

## 九、状态、异常与清理

### 9.1 状态矩阵

| 场景 | 界面状态 | 用户下一步 |
| --- | --- | --- |
| Workspace 草稿为空 | 新会话空状态、完整 Composer | 输入并发送 |
| Workspace 草稿非空 | 恢复文本与 Tag，新会话菜单标“有草稿” | 继续或清空草稿 |
| 首次发送中 | 草稿页保留、发送 pending | 等待，不产生列表行 |
| 首次发送失败 | 就地错误、草稿完整保留 | 修改或重试 |
| 标题自动生成中 | 无阻塞 UI | 继续工作 |
| `/title` 生成中 | Composer 顶部紧凑状态行 | 继续输入或发送 |
| `/title` 失败 | 原标题保留、状态行提供重试 | 重试或关闭 |
| Workspace 路径无效 | 设置目录块就地错误 | 修复或移除该路径 |
| 引用来源不可用 | 冻结引用可读、来源按钮禁用 | 关闭详情 |
| 剪贴板图片登记中 | Composer 保留焦点、上下文区显示批次 pending | 等待，不重复发送 |
| 剪贴板图片登记失败 | 文字与原上下文保留、就地错误 | 继续输入或重新粘贴 |
| 分栏偏好损坏 | 使用设计默认宽度 | 正常使用或重新调整 |
| 动画被中断 | 立即收敛到最新 open/closed 状态 | 无需恢复操作 |

### 9.2 统一清理规则

- Session/child 导航清理：选区气泡、引用详情、来源高亮和当前 owner 的短期定位状态。
- 点击发送清理：选区、气泡、来源定位和高亮；可靠成功后再清草稿正文与上下文 Tag。
- Overlay 关闭清理：Document 监听、ResizeObserver、Animation Frame、Pointer Capture 和 Focus Trap。
- 窗口失焦清理：拖拽和选区气泡；普通 Dialog 保持打开。
- 应用退出清理：所有新会话草稿、未上传文件句柄和剪贴板图片 owned 临时文件；分栏宽度等 Desktop
  偏好已按正常节流写入。

## 十、键盘与可访问性

- 新会话菜单、Workspace 管理、Slash Menu 和 Tag 详情全程可由键盘完成。
- 消息正文的 `Shift + F10` 与键盘 Context Menu 键保持 WebView 原生行为，不额外打开引用菜单。
- 引用 Tag 主体和移除按钮是两个独立焦点；读屏名称分别为“查看引用：<预览>”和“移除引用”。
- 图片粘贴成功或失败通过低优先级 status 报告，例如“已添加 2 张图片”或“剪贴板图片过大”；不抢走
  textarea 焦点。键盘用户粘贴后可按正常 Tab 顺序进入附件 Tag 与移除按钮。
- Workspace 目录拖拽必须有等价键盘重排入口，例如更多菜单“上移/下移”；拖拽柄不能成为唯一方式。
- 分隔条按 3.3 提供 separator 值语义；宽度变化通过低优先级 live region 报告。
- Dialog 保持标题关联、最上层 Focus Trap、Esc 和 opener 恢复；退出动画不能延迟语义关闭。
- 所有 Collapse 按钮具有 `aria-expanded` 和稳定 `aria-controls`；内容关闭后不进入 Tab 顺序。
- 动效不是状态唯一线索；Reduced Motion、键盘焦点和高对比环境下仍能区分打开、选中、错误和禁用。

## 十一、视觉与交互验收口径

- [ ] 新对话入口恢复每 Workspace 与 unbound 草稿，但左栏、搜索和最近会话不出现草稿记录。
- [ ] 新会话 Header、空状态、Composer 和右栏只展示真实草稿/Workspace 信息，不伪造 Session 事实。
- [ ] 首次发送成功前没有会话行；失败后草稿和所有 Tag 保持，成功后只出现一条正式 Session。
- [ ] 自动标题静默更新；`/title` 在 Run 活动时仍可用，并走相同 Snapshot 机制与轻量状态反馈。
- [ ] Workspace label 成为左栏主名称；重名时在菜单和编辑弹窗中能通过主目录区分。
- [ ] 左栏 Workspace 菜单和右栏“工作区”编辑按钮打开同一个弹窗；弹窗内可一起完成名称、添加目录、
  明确设主目录、排序、移除和错误修复。
- [ ] 从既有 Session 右栏保存 Workspace 变化后，当前 label 投影可以更新，但当前 Session 的
  System Prompt、冻结 System Context 和冻结目录完全不变。
- [ ] 右栏能区分新草稿当前目录与既有 Session 冻结目录，并保留非强沙盒说明。
- [ ] 有效单消息文本选区显示引用气泡；同消息跨行内元素仍可引用，右键与 `Shift + F10` 保持 WebView
  原生行为，点击气泡时没有 Host/Runtime 请求。
- [ ] 粘贴单张/多张图片生成普通附件 Tag；普通文字粘贴不生成附件；文字与图片混合粘贴两者都保留。
- [ ] 图片-only 可发送；新会话粘贴不会预建 Session，失败后对应 Workspace 草稿仍保留图片附件。
- [ ] 超限、伪图片或登记失败不产生半成功 Tag、不吞同次文字，移除/发送/退出后临时资源可清理。
- [ ] Composer 附件/引用 Tag 可点击详情且可单独移除；Goal/Skill 不与内容引用混淆。
- [ ] 一词短引用仍清楚展示 exact，来源不可用时保留冻结内容且不错误定位相似消息。
- [ ] 来源高亮在发送、滚动、关闭、导航、超时、失败和卸载路径全部恢复，无持久 DOM 标记。
- [ ] Dialog、Menu、Popover、Context Menu、抽屉和 Collapse 均有匹配的进入/退出过渡。
- [ ] 快速反复开关、Esc、外部点击和路由切换不残留透明遮罩、错误焦点或不可见可交互元素。
- [ ] Reduced Motion 下所有能力完整可用，无依赖动画完成的业务动作。
- [ ] 左右栏可独立指针/键盘调宽，双击单栏复位，恢复默认布局回到 `286px / 326px`。
- [ ] 右栏可扩展到 `800px`；达到 `620px` 时上下文 Section 自动从一列变为两条独立纵向列，
  左右卡片不做同行高度对齐，缩回后恢复一列，且长路径不会撑出水平滚动。
- [ ] 收起再展开、应用重启和窗口缩放不会覆盖用户偏好；`720px` 最小窗口仍保留 `500px` 中栏且
  能通过临时单侧栏策略访问两侧内容。
- [ ] 流式输出、长会话、多个 Workspace 和多目录下拖拽/Collapse 动画无明显掉帧、横向滚动或布局抖动。

## 十二、阶段边界

- 本文确认后进入技术方案，技术方案必须基于现有 `Dialog`、`DropdownMenu`、`SelectionPopover`、
  Composer、AppShell、NavigationStore 和 Desktop Preferences 核查最小复用路径。
- 技术方案需要明确退出动画的挂载状态、单消息可见文本范围与跨元素 Selection、剪贴板图片到原生
  附件句柄的字节与清理边界、分栏偏好/实际宽度分离、新会话草稿所有权与首次发送最小物化链路，但不得在交互指导中
  预先承诺具体 Hook、组件或协议字段。
- 技术方案与本文均确认前，版本保持 `设计中`；不创建开发计划，不开始代码里程碑。
