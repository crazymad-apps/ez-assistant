## 三、功能与架构验收

- `agent-sdk` 作为薄 Facade 提供 Builder、冻结的单会话 Agent、显式 Recorder 与临时
  Recorder 两类入口；不持有动态 Conversation、Run 或 Journal。
- `ExecutionSpec::model_request` 在每个 Model Step 机械投影 tool choice、generation、
  reasoning 与 Provider options，默认值保持迁移前行为。
- 不同 Session 可异步并发并共享线程安全底层资源；同一 Session 由 Demo 宿主串行化，事件
  观察断开或落后不阻塞可靠 Completion。
- Core Demo 完成真实 DeepSeek、文件、Shell、安全审批、Pinned Memory、RecallSource、取消、
  Context replacement/continuation 和浏览器刷新恢复权威快照的闭环。
- Plan 对无法识别的授权事实最终拒绝；supervisor panic 会把 Run 收敛为 Failed 并释放 Session
  闸门。`data-dir` 明确不是文件或 Shell 的安全隔离边界。
- 候选公共 API、依赖方向和公共文档已核对；具体 Provider、本地 Adapter、Demo 私有协议及产品
  Runtime 类型没有进入 SDK。

功能设计 15 条验收标准的逐项证据见
[`兼容性与性能基线`](兼容性与性能基线.md#七功能设计验收证据映射)，结论全部满足。


结果全部通过。外部 Review 修正后的 workspace 测试为 **598 passed / 0 failed / 4 ignored**；
ignored 项包括一个需要真实 DeepSeek 凭据的独立 smoke 和三个真实本地系统能力 smoke。

### 4.2 示例、基线、真实本地能力与历史回归

```text
cargo run -p agent-sdk --example minimal
cargo run -p agent-sdk --example custom_controls
cargo run -p agent-testkit --example engine_demo

cargo test -p agent-tools-local -- --ignored --nocapture
```

结果：SDK 与 Engine 示例通过；release 基线完成 Context、ToolSet、事件观察、双 Agent 共享模型
和 SDK/Core 路径测量，没有发现数量级额外开销；真实 `rg`、process-tree cancellation 与 detached
loopback service 共 3/3 通过；Harness v0.2 为 6/6，v0.3 为 14/14。

### 4.3 真实 Provider 与浏览器闭环

M7 使用用户现有 DeepSeek 配置和专用临时目录完成真实 reasoning → `write_file` → tool result →
final answer；页面刷新后权威快照恢复。双 Session 验证中，短 Session 在另一 Session 的 managed
`sleep 20` 运行期间完成。真实 Context 组合在 6000-token 声明窗口下发生一次 handoff，并从
replacement 正常续跑。

实际 credential 未进入全局快照、专用 workdir 或 data-dir，专用验证目录已移入系统废纸篓，
验证 Server 已停止。M8 与外部 Review 修正没有重复产生真实 Provider 费用。
