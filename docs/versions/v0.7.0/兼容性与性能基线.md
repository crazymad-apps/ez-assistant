# v0.7.0 兼容性与性能基线

## 一、文档定位

本文记录 Core 候选版在当前主机上的首份可重复性能结果、跨平台与能力兼容证据，以及功能设计
15 条验收标准的实现映射。它不是跨硬件 SLA，也不把源代码中的条件编译、确定性测试或协议
fixture 冒充为对应平台和 Provider 的真实运行结果。

证据等级固定为：

- **实测**：在所列 OS、Provider 或真实 Adapter 上实际运行；
- **编译或确定性测试**：只证明当前 target 编译、协议 fixture 或 scripted 行为；
- **未验证**：本版本没有可复核的对应环境证据。

## 三、性能基线

### 3.1 方法

执行命令：

```bash
cargo run -p core-demo --release --example core_baseline
```

实现位于 `tools/core-demo/examples/core_baseline.rs`，只使用内存 fixture、scripted Model 和
当前线程 Tokio Runtime，不访问网络、用户数据文件或 Agent 工具；启动时只调用 `rustc -vV`
记录工具链。每项先预热，再以 `Instant` 测量固定迭代，关键结果经过 `black_box`；输出为每行
一个 JSON 对象，并包含 `case`、`input_size`、`iterations`、`elapsed_ns`、`target`、`profile`
和 `rustc_version`。

这组数据用于发现数量级回归，不适合比较数个百分点的波动。真实 Provider、文件、Shell 和
浏览器时间不计入 Core 性能。

### 3.2 记录结果

下表记录第二次连续运行；第一次运行的相邻结果用于确认量级可复现。

| Case | 输入规模 | 迭代 | ns/iteration | 首次复跑范围 | 说明 |
| --- | ---: | ---: | ---: | ---: | --- |
| `context_layout` | 576 messages / 256 turns | 2000 | 83014 | 83014–89546 | 含完整文本 Turn 与 Tool Exchange |
| `tool_set_freeze` | 128 tools | 200 | 97670 | 97046–97670 | 注册、Schema 冻结与索引构造 |
| `event_stream_connected` | 4096 deltas | 20 | 380987 | 380987–385027 | 消费 AgentEvent 并等待可靠 Completion |
| `event_stream_disconnected` | 4096 deltas | 20 | 355977 | 347783–355977 | 立即丢弃观察流，Completion 仍完成 |
| `two_agent_shared_model` | 2 Agents | 250 pairs | 18438 | 17406–18438 | 两个独立 Agent 共享线程安全 ModelService |
| `core_direct_execution` | 1 text turn | 500 | 16309 | 16309–16842 | 直接构造 `ExecutionSpec` 启动 Core |
| `sdk_explicit_execution` | 1 text turn | 500 | 16251 | 16251–16336 | SDK + 显式 Recorder/Authorizer |
| `sdk_ephemeral_execution` | 1 text turn | 500 | 16013 | 15560–16013 | SDK 每次创建临时 Recorder |

第二次运行中 SDK 显式路径 / 直接 Core 的总耗时比例约为 0.996。当前噪声下二者不可区分，且
明显不存在数量级额外开销。连接与断开事件消费者都能可靠完成；双 Agent case 没有按 Session
复制 ModelService。功能上的取消、结果隔离和慢消费者正确性仍以 barrier/channel 单测为准，
不从微基准时间反推。

## 六、候选公共 API 与产品边界核对

- 普通入口仍只有 `agent-sdk::{AgentBuilder, Agent, AgentBuildError}` 及启动路径所需精选重导；
  Provider、文件/Shell、Memory、策略和 testkit 没有被批量重导进 SDK。
- `cargo tree -p agent-sdk --depth 3` 证明生产依赖只指向抽象 Agent crate；testkit 仅为
  dev-dependency。
- `cargo tree -i agent-sdk` 只有 Core Demo；`cargo tree -i core-demo` 没有上层调用方。
- `git diff --name-only -- crates/assistant-runtime crates/assistant-protocol apps/desktop` 为空；本版本
  未修改正式 Runtime、Protocol 或 Desktop 源码。
- workspace package version 继续为 `0.1.0`；没有发布 crates.io、增加 MSRV 或作出 SemVer 稳定
  承诺。

## 九、结论

当前基线没有暴露数量级性能开销、共享资源按 Session 线性复制或 UI 观察反压执行的问题。
候选 API、文档、兼容证据和 15 条验收映射已经形成；Linux、Windows、另一家真实
OpenAI-compatible Provider 与正式 Runtime/Desktop 集成仍需由后续版本提供新证据。
