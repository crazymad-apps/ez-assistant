## 三、形成的核心能力

- `ExecutionSpec` 通过冻结的 `ModelRequestConfig` 向每个 Model Step 投影模型请求配置，Provider
  私有值仍保持命名空间隔离。
- `agent-sdk` 提供普通宿主所需的薄构建和启动入口；一个 Agent 对应一个会话的冻结能力配置，
  动态 Conversation、Run、Journal 和并发调度仍由上层拥有。
- Recorder 可由普通调用方缺省使用临时实现，也可由 Runtime 风格宿主显式注入；可靠 Completion
  与可丢观察事件保持分离。
- Core Demo 证明 SDK 可装配 Provider、本地工具、安全、Memory、Context 与多 Session I/O，且不把
  Demo 私有协议提升成 Core 或产品契约。
- 公共 SDK 导读、离线 examples、真实 Demo 启动方式、性能基线和兼容矩阵共同形成候选版使用入口。

## 四、偏差与边界

- 实现与已确认功能设计、技术方案和开发计划没有范围偏差。
- 正式 `assistant-runtime`、`assistant-protocol` 和 Desktop 没有本版本业务代码或直接依赖接入。
- Core Demo 的 Session、Run、Journal、Store、策略、HTTP DTO 和 CLI 均为私有验证实现；
  `data-dir` 与 workdir 不是安全隔离边界，Shell 以当前用户权限运行。
- Linux、Windows 和第二家真实 OpenAI-compatible Provider 未验证，不作通过声明。
- Desktop/Tauri bundle 未构建，因为产品层不在本版本目标；workspace Rust 门禁已通过。
