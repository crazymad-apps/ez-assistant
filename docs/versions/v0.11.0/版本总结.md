## 三、形成的核心能力

- Workspace 成为独立持久化业务对象：以 canonical 用户目录识别，可被多个 Session 复用；假删
  只阻止新绑定，不删除用户目录、Agent 私有目录或既有 Session 关系。
- Session 创建时冻结用户工作目录、Workspace 私有目录、Session 私有目录和附件目录；不提供
  普通换绑，不枚举 Workspace 文件，也不自动注入 Workspace Instructions。
- 任意文件统一通过 multipart 流式上传成为 Session 静态附件。原始文件名与内容共同决定 Blob
  身份，业务 Attachment、稳定 Agent 可读视图与物理 Blob 分离。
- File References 作为可见、持久化但不混入正文的 User Part 保存原始名称和稳定路径；不包含
  文件正文、Base64、Hash 或内部物理路径，Agent 使用工具按需读取。
- Runtime Host 统一提供 Command、SSE 与 Streaming Upload；私有发现文件、进程级 Token、
  Host/Origin 校验和精确 CORS 构成本地 HTTP 入口边界，不保留 UDS 双轨。
- SSE 仍是可丢弃观察流，但积压时显式发送 `stream_gap` 并断开；客户端自动重连后通过
  Workspace、Session、Run、Conversation 与 Attachment 权威快照校准，不依赖事件重放。
- 每个 Run 根据冻结 Session Environment 编译工具与 Authorizer；默认产品入口只开放低风险
  `echo_text`，完整本地文件与 Shell 仅用于显式危险验证模式，不宣称 OS 沙箱。
- DeepSeek 缺失 `reasoning_content` 的 Tool Call 在规范层保持原事实；仅在后续 DeepSeek wire
  回放时补占位，不伪造或持久化 Reasoning Part。

## 四、偏差、边界与遗留

- 实现未偏离已确认功能范围。HTTP 路由、SQLite 表、Blob 布局、符号链接视图、wire 占位和
  SSE gap 保持为技术实现或传输适配，没有新增 Artifact、Instructions 或其他业务对象。
- M5 根据真实链路修复了跨 Run Message ID 冲突、工具活动延迟、reasoning 展示遗漏、模型失败
  诊断、DeepSeek 缺失 reasoning 兼容和 SSE 静默丢事件，均服务原验收标准。
- 本版本没有附件主动删除与定时清理、正式远程 HTTPS、Workspace Instructions、产品级 Internal
  Injection、Artifact、正式桌面业务页面或 Plan/Build 与 Ask/Auto 权限体系。
- 结构化文件 Authorizer 不是 OS 沙箱；Shell、同一用户进程和 symlink 可绕过逻辑路径规则。
- 启动恢复不在每次启动或 Run 前重新 Hash 全部历史大文件，这是已确认的性能与恢复取舍。
- 真实 smoke 早期一次 TOML 解析诊断曾把配置源文本带入本地开发会话工具输出；实现已经固定
  脱敏、带凭证临时副本已删除，相关凭证仍建议轮换。
- 浏览器人工验证留下的无凭证临时 Runtime 数据未随版本归档擅自删除；其清理属于独立破坏性操作。
