# v0.11.0 M5 验证与验收准备

## 一、结论

M5 计划范围已经完成实现、验证和里程碑确认。本记录保留正式版本验收前的证据索引；
`v0.11.0` 的最终结论以同目录 [`验收记录`](验收记录.md) 为准。

本轮验证同时覆盖三条链路：

1. 正式 Runtime Host 的离线双进程端到端验收；
2. 私有 Web Demo 的真实浏览器人工验收；
3. 默认忽略、显式触发的真实 LLM 文件工具 smoke。

## 二、端到端验证结果

### 2.1 正式 Host 离线验收

`apps/runtime-host/tests/v0_11_http_acceptance.rs` 启动两次正式 Host，并且只通过正式
HTTP Command、SSE 和 Streaming Upload 接口操作。测试实际覆盖：

- HTTP 发现、Bearer Token、Host/Origin/CORS、请求上限和 opt-in Web Demo；
- Workspace 登记、Session 绑定、假删、重新登记和跨进程恢复；
- 附件独立上传、名称与内容联合去重、源文件变化后的静态附件；
- 上传部分成功、后续上传失败和消息提交失败均不回滚成功附件；
- File References 持久化、同一 Session 连续两次真实 `read_file` 工具调用及 Tool Result
  回传，并核对所有持久化 Message ID 唯一；
- Session 归档、Host 关闭、第二次 Host 启动和 Session 恢复；
- SQLite、Conversation JSONL、Blob、Session 稳定视图和可读路径的分层只读核对；
- Host 输出中不出现访问 Token、测试文件内容、Prompt、完整回复或 API Key。

### 2.2 Web Demo 人工验收

实际浏览器页面完成了 Workspace 登记、绑定 Session 创建、Attachment 列表与选择、
带可见文件组件的消息提交、流式 Assistant 消息、真实文件工具调用、归档、恢复和页面
重载后的权威快照恢复。页面新增最近一次模型请求的 Input、Output、Total、Cached token
展示，并同时支持 usage SSE 实时更新和 Conversation usage 恢复。浏览器 Console 没有
warning 或 error。

验收复查后，Demo 已补齐按 `call_id` 的工具 proposed/running/output/completed 实时状态，
不再等整个 Run 终结后才显示工具活动；模型建立重试同时展示 attempt、等待和脱敏失败分类，
最终失败显示可持久恢复的安全诊断摘要。

全版本 Review 又补齐了事件丢失恢复：SSE 订阅者落后时，Host 发送 `stream_gap` 后结束本次流；
Demo 自动重连，并重新加载 Workspace、Session、Run、Conversation 和 Attachment 权威快照，
避免漏掉 `run_finished` 后把页面永久留在运行中。快速切换 Session 时，过期的 Run 查询结果
也不再覆盖当前 Session 状态。

当前 Chrome 自动化扩展没有开启 `Allow access to file URLs`，因此原生文件选择器被浏览器
权限拦截。该次人工验收改用同一正式 HTTP 上传接口导入临时附件，再回到页面验证其余完整
交互。应用内“先上传附件，任一上传失败则不提交消息”的行为由正式 Host 端到端测试和
Demo 静态能力检查共同覆盖；这是自动化环境限制，不是产品上传失败。

### 2.3 真实 LLM smoke

`apps/runtime-host/tests/v0_11_real_llm.rs` 默认忽略，仅在显式命令下执行。本轮只读使用
`~/.ez-assistant/config.toml` 中的现有模型配置，在临时 Runtime Home 和 Workspace 中：

- 验证默认模型连接；
- 上传随机内容附件并提交 File References；
- 要求真实模型调用 `read_file`；
- 验证 Run 完成、工具调用完成且最终回复包含随机文件内容；
- 验证 Host 输出不包含 Token、Prompt、文件内容和已配置 API Key。

本次调用成功，产生了少量真实模型费用。首次运行时，TOML 解析失败诊断意外携带了整份
配置源文本，使 API Key 出现在本地开发会话工具输出中；未发送给额外第三方服务。实现已改为
固定脱敏错误，带凭证的临时配置副本已删除。该凭证仍建议轮换。

### 2.4 DeepSeek reasoning/tool-call 兼容回归

真实长工具链路暴露出 DeepSeek 偶发返回不带 `reasoning_content` 的 Tool Call：
旧解码器会在 `TurnFinished` 前拒绝该轮次，导致 Run 以协议错误失败。现已改为：

- 保留 Provider 返回的 Tool Call，不伪造规范 `ReasoningPart`；
- 在后续回放给 DeepSeek 时由 Codec 补入仅用于 wire 的单空格
  `reasoning_content`，避免污染 Conversation、UI 和 Journal；
- 普通 OpenAI-compatible Profile 不补该字段。

流式、非流式、缺失/空字符串/`null` reasoning、DeepSeek 回放编码以及普通
Profile 隔离均已有离线回归。

## 五、验收前说明

- Web Demo 是默认关闭的私有验收客户端，不是正式桌面 UI 或第二套 Runtime。
- `--unsafe-unrestricted-local-tools` 只用于显式测试，使用当前用户权限且不是 OS 沙箱。
- 人工连续工具 Run 暴露出 Core 在每个 Run 中从 `toolmsg_1` 重新编号的问题：第二个 Run
  的工具结果与历史 Message ID 冲突，使 ready tool exchange 无法提交且 SQLite Run 留在
  `running`。现已改为相对完整 Conversation 分配唯一 ID，并由 Core 回归和正式 Host
  同 Session 连续两次文件工具验收共同覆盖。
- 本版本不实现附件清理、用户主动删除附件、正式远程 HTTPS、Workspace Instructions 或 Artifact。
- 人工浏览器测试留下无凭证的临时 Runtime 数据库与文件目录。由于清理涉及数据库删除，未在
  未经再次确认的情况下擅自删除。
