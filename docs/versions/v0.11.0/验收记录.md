## 三、实际能力验收

- Runtime 持有 Workspace、Session 绑定、Attachment、Conversation 和 Run 的权威业务状态；
  Host 只负责 HTTP、安全入口、文件系统与 SQLite Adapter，不复制业务状态机。
- Workspace 使用 canonical 用户目录作为身份，支持登记、查询、列表、假删与重新登记恢复；假删
  不删除用户目录、Workspace 私有目录或既有 Session 关系。
- Session 创建时冻结用户工作目录、Workspace 私有目录、Session 私有目录和附件目录；不提供普通
  换绑，不枚举 Workspace 文件，也不自动注入 Workspace Instructions。
- 附件通过 multipart 流式上传，原始文件名与内容共同决定 Blob 身份；Session 业务关系、稳定
  Agent 可读视图与物理 Blob 分离，原始用户文件变化不影响已上传附件。
- File References 作为独立、可见且持久化的 User Part 保存原始名称与稳定可读路径，不包含正文、
  Base64、Hash 或内部 Blob 路径。
- 每个 Run 根据冻结的 Session Environment 编译工具与 Authorizer；默认 Host fail-closed，只有
  显式危险验证模式开放当前用户权限下的本地文件与 Shell 能力。
- Runtime Host 只通过动态 IPv4 loopback HTTP 提供 Command、SSE 与 Streaming Upload，并使用
  私有发现文件、进程级 Bearer Token、Host/Origin 校验和精确 CORS 白名单。
- SSE 允许丢失但不能静默失序：订阅积压时 Host 发送 `stream_gap` 并关闭当前流，客户端重连后
  从 Workspace、Session、Run、Conversation 与 Attachment 权威快照恢复，不取消业务 Run。
- DeepSeek 偶发缺失 `reasoning_content` 的 Tool Call 保留为规范 Tool Call；后续回放只在
  DeepSeek wire 层补单空格占位，不伪造或持久化 Reasoning Part。

`apps/runtime-host/tests/v0_11_http_acceptance.rs` 实际启动两次正式产品 Host，并只使用正式 HTTP

2. Workspace 登记、Session 绑定、假删、恢复和跨进程重建；
3. 附件独立上传、联合去重、失败不回滚和稳定路径；

7. 检查 Host 输出不包含 Token、API Key、Prompt、测试文件正文或完整模型回复。

少量模型费用。验收前 SSE 修复没有改变模型、工具、附件或 Provider 路径，因此本轮没有重复产生
费用；对应离线、双 Host 和全工作区回归已重新通过。

私有 Web Demo 已在真实浏览器中完成 Workspace、Session、附件、流式正文、reasoning、工具状态、

   当前只在显式危险验证模式开放，正式权限策略属于后续版本。

   这是已确认的性能与恢复取舍。
