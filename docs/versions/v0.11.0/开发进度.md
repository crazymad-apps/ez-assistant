- 状态：✅ 已完成

    `SessionEnvironmentFactory`，创建 Session 时同时冻结目录环境与 `SystemPromptSnapshot`；

    Workspace 假删不删除目录，再登记恢复原 ID；

### M2：Attachment 存储、流式上传与恢复

- 目标：建立独立于 Message 的 Session Attachment 事实，完成 HTTP 流式上传、内容去重、
  稳定 Agent 可读路径和启动恢复。
- 影响模块：`assistant-protocol`、`assistant-runtime`、`apps/runtime-host` 及对应模块文档。
- 状态：✅ 已完成
- 实际结果：
  - `assistant-protocol` 增加 Attachment ID、状态/摘要、查询/列表命令、Host 上传能力和稳定错误码；
  - `assistant-runtime` 增加 Attachment Registry、Session 准入、staging 完成提交以及
    跨 Session 隔离查询；查询不机械下沉到阻塞 Store；
  - Host 增加独立 multipart 流式上传路由，按 chunk 写入 staging 并同步计算 SHA-256，单文件
    上限 1 GiB，不把文件正文塞入 JSON 或一次性加载到内存；
  - SQLite 保存 Blob/Attachment 结构化关系，文件系统保存只读内容 Blob 和 Session 稳定软链接；
    同一 Session 同名同内容返回首次业务事实，不同 Session 可复用同名同内容 Blob 但保持独立 Attachment；
  - 启动恢复会补建缺失的已知视图；Blob、大小或链接异常时保留记录并投影为 `unavailable`，
    不覆盖未知文件；
  - Runtime、Host 单元测试和真实 Host HTTP 验收覆盖上传、列表、名称+内容 Hash 去重、稳定路径与恢复。
- 当前步骤：实现与验证完成。
- 续作点：已进入 M3 File References 持久化与模型编码。
- 里程碑确认：用户已确认。
- 遗留/风险：M2 不把 Attachment 写入 User Message；上传成功后的 Message 引用属于 M3；
  本版本不清理合法未引用附件或孤立 Blob。
- 关联版本文档：[`开发计划`](开发计划.md)。

### M3：File References 持久化与模型编码

- 目标：让 User Message 以独立、可恢复的 File References Part 引用 Session Attachment，
  并按稳定格式编码给模型，不自动读取正文。
- 影响模块：`agent-types`、`agent-provider-openai-compatible`、`assistant-protocol`、
  `assistant-runtime`、`apps/runtime-host` 及对应模块文档。
- 状态：✅ 已完成
- 实际结果：
  - `agent-types` 新增持久化 `FileReferences` Part，只保存原始文件名和稳定可读路径，
    不保存 Attachment ID、Hash、文件正文或解析结果；
  - SubmitInput 和历史重新输入支持有序 Attachment ID，Runtime 在入队前整批解析，
    保序固化文件引用，并拒绝重复、跨 Session 和 unavailable 引用；
  - Conversation 的排队 JSON 和正文 JSONL 都保留 Text/FileReferences 类型、顺序和内容；
    历史重新输入只替换尾段消息，不删除 Session Attachment；
  - OpenAI-compatible Adapter 把 File References 编码为独立、保序、XML 转义的
    `attached_files` 文本 Part，不伪造 Tool Call/Result，也不声称已读取文件。
- 验证结果：

  - M3 相关五个 crate 的 `clippy --all-targets --all-features -- -D warnings`：通过；

  - `git diff --check`：通过；
  - 数据库、Conversation 和文件测试只使用临时 Runtime Home，未读写用户真实
    `~/.ez-assistant` 数据。
- 当前步骤：实现与验证已完成。

### M4：按 Run 工具编译与真实文件验证

- 目标：基于 Session 冻结环境为每个 Run 独立编译工具集与 Authorizer，并在显式
  危险验证模式中回证 Agent 能读取真实附件。
- 影响模块：`assistant-runtime`、`apps/runtime-host`、`agent-tools-local` 装配与对应模块文档。
- 状态：✅ 已完成
- 实际结果：
  - Runtime 以 `RunToolFactory -> RunToolBundle` 取代全局 ToolSet/Authorizer；每个 Run
    根据 Session 冻结环境同时固定工具集、路径 resolver 和 Authorizer；
  - `assistant-runtime` 不直接依赖 `agent-tools-local`，绑定 Workspace 的工作目录不可用时
    在 Run 开始前返回 `WorkspaceUnavailable`，其他工具构造错误保持脱敏；
  - Host 默认模式仅提供 `echo_text` 并 fail-closed；显式
    `--unsafe-unrestricted-local-tools` 才注册全部标准文件工具和 Shell，CLI help 与启动
    stderr 均明确 Workspace 不是沙箱；
  - 显式验证模式复用本地文件/Shell Adapter，但为不同 Run 分别冻结工作目录；结构化
    Write/Edit/Delete 拒绝 Runtime Home 下任意 Session 附件目录，普通工作目录仍可写；
  - scripted fake Provider 会主动调用 `read_file`，通过真实 LocalFileSystem 读取 File
    References 指向的临时附件，并在下一次模型请求中观察到真实 Tool Result。
- 验证结果：
  - `cargo clippy -p agent-tools -p agent-tools-local -p assistant-runtime -p assistant-runtime-host --all-targets --all-features -- -D warnings`：通过；
  - `cargo test -p agent-tools -p agent-tools-local -p assistant-runtime -p assistant-runtime-host --all-features`：通过；
  - `cargo test -p assistant-runtime-host --no-default-features`：通过；
  - `cargo clippy --workspace --all-targets --all-features -- -D warnings`：通过；
  - `cargo test --workspace --all-features`：通过；
  - `cargo fmt --all --check` 与 `git diff --check`：通过；
  - 所有真实文件、Host 与 Provider 回证都使用临时目录和离线 scripted/loopback Provider，
    未读写用户真实 `~/.ez-assistant` 数据，也未发起真实 LLM 请求。
- 当前步骤：实现与验证完成。
- 续作点：已进入 M5。
- 里程碑确认：用户已确认。
