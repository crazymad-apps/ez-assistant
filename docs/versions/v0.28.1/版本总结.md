## 实际交付

- LLM 请求异常可安全有限重试，重试进度、失败与取消有明确状态；运行中上下文与累计用量按各自口径展示。
- 正式产物由执行过程明确声明，能与中间资源区分，并支持打开、下载、失效提示和恢复。
- Windows、macOS 与 Chrome 接入统一系统通知来源；`ask_user` 支持轮内等待与轮后回复两种语义，通知可返回对应会话。
- 修复跨平台资源路径、图片预览、右栏预览与下载，并使用对应平台的文件管理器文案。
- 企业中心按实际代理请求记录 Token 用量，后台提供个人/全部、时间、服务商与模型联合维度统计及调用下钻；正文采集策略与用量独立，7320 测试环境的新请求和响应快照均已验证可读。

## 验证与限制

Rust 全量测试、格式与 Clippy，Desktop、Client、Enterprise Center 和 Admin 的构建与相关检查，协议/OpenAPI 一致性、隔离正式 Host 浏览器链路、Desktop no-bundle Release 构建均通过。F06 的隔离数据库与本地 7320 测试环境完成真实代理、用量和双侧正文快照核验。7320 是本地测试部署，不代表公开发布。

Windows 原生保存对话框、Windows/macOS 原生问答与系统横幅、Chrome 受信任 HTTPS 后台通知，未取得完整逐项实测结论；模型异常后经通知、反馈到正式产物的单条任务，以及正式 Runtime 重试经过 Center 代理后的逐次用量，也未单独完成端到端验证。用户同意按这些已知限制验收。历史未采集的正文及已清理数据无法恢复，上游未返回 usage 的调用保持未知。后续补测不得追写为本版已执行。

本版未执行 Git tag、推送或公开发布；后续版本目标尚未确定。

## 发版前补充：macOS 插件安装性能

`warehouse-cad-guidance` 的约 130 MiB 安装包包含大量小文件；原解包流程逐文件同步磁盘，实际耗时明显过长。现改为在完整校验和解包后、发布暂存目录前统一同步文件与目录，并在传输结束后显示独立的处理阶段。相同安装包在本机调试构建中的准备耗时由约 99.36 秒降至 14.86 秒；插件相关测试及桌面端测试通过。已重新构建、签名、公证并校验 v0.28.1 macOS arm64 安装包；此项归入 v0.28.1，不另起补丁版本。

用户进一步明确同名 Skill 应优先使用已启用插件。此前 v0.28.0 技术方案和实现将插件与独立 Skill 同名视为冲突，与该要求不符；现修正为插件覆盖独立 Skill，保留被覆盖诊断。独立 Skill 之间的既有顺序和两个插件同名时的冲突规则不变。此项同样并入尚未公开发布的 v0.28.1。

桌面侧栏顶部补充“智能体管理”和“插件管理”两个独立快捷入口，分别直达现有设置页面；隔离 Host Web 的实际点击和页面跳转已通过验证，并已重新构建、签名、公证和校验 macOS arm64 安装包。

Windows x64 MSI 同步按当前源码构建，修正插件解包代码在 Windows 上的未使用参数警告；安装器结构、版本、PE 架构和 Host 内置 Web 校验通过。本轮未执行安装后的运行验收，Windows MSI 仍未签名。

2026-09-28 经用户确认，将企业中心镜像 `ez-enterprise-center:0.1.0-20260928-v0281` 部署到 `172.16.20.4:7320`，生产数据库完成 004 用量迁移并保留历史调用。数据库与外置文件已备份并恢复核验，管理页面、登录和用量接口通过部署检查。正文采集沿用原关闭设置，新请求的 Token 用量独立统计；历史调用不补算用量。企业中心的软件版本仍独立保持 `0.1.0`，本次部署不代表桌面版公开发布。

Windows 使用 `gorag-knowledge` 与 `autocad-ai` 时报告找不到可执行文件，检查发现 Host 将插件包内的 `/` 路径直接拼接到 Windows canonical 根，产生不受 verbatim 路径支持的混合分隔符。现改用原生路径拼接，保留长路径前缀，并覆盖插件启动命令、参数和工作目录。本机相关测试、格式与 Host Clippy 通过；在用户指定的 Windows 主机上复现旧路径错误，修复后回归测试与 Host Clippy 通过，两个插件的实际 Windows MCP 启动和工具发现通过。已仅构建并校验更新后的 Windows x64 MSI，修复继续归入 v0.28.1；未执行安装后的完整运行验收，安装包仍未签名。

用户随后报告 GoRAG 单次调用失败后被持续判为不可用。检查确认 Runtime 将所有 Adapter 调用错误统一退役连接；现区分单次请求失败、取消、不支持的扩展与连接/协议故障，前者保留连接供后续显式调用，后者继续关闭并发布诊断，均不重放失败请求。相关本机回归、正式 Host 的断流/超时/取消验证、格式和 Clippy 已通过；Windows 相关 Host 与 Registry 回归、Host Clippy 及 GoRAG 连续检索通过。既有包含 `npx` 的 Windows 启动矩阵测试仍未通过，未据此宣称完整矩阵验收。原始 GoRAG 单次失败未复现，旧通用诊断无法还原其底层原因。含修复的 Windows x64 MSI 已构建并完成安装器校验，交付到用户指定主机桌面；按用户要求由其手动执行安装后验收。此修复继续归入 v0.28.1，安装包仍未签名。

AutoCAD 的后续握手失败单独定位为 Windows 深层插件目录下 Python 原生模块导入失败；模块存在，但普通模块路径超过 Windows 长路径限制。`warehouse-cad-guidance` 0.3.5 在导入第三方库前为绝对模块路径保留长路径前缀，合成包同时覆盖两平台运行时中的当前 MCP 源码。Windows 正式 Host Adapter 工具发现、实际新包在深目录下的启动与工具发现，以及 macOS 离线握手和调用检查通过。插件包与 MSI 一起交付，AutoCAD 使用方须独立更新插件；本轮未执行真实 CAD 绘图或安装后的完整桌面验收。

Windows 打开软件时额外出现控制台，源码核查发现 MCP 子进程启动缺少无窗口标志；已沿用本地 Shell 的最终启动处理，隐藏控制台并保留 Job Object 所需的挂起标志。此修改已纳入本轮重新构建并校验的 Windows x64 MSI，无窗口效果待用户手动验收。

发版前补充桌面默认行为：客户端启动进入独立的新建会话草稿，不自动选中助理会话或恢复上次会话选择；历史会话的资源标签仍保留。未保存审批偏好的新草稿默认 Auto，已保存选择与已有会话模式保持原值，Web 同样使用 Auto 默认。业务及测试通知发送前核对当前窗口焦点，前台不投递，失焦后不补发旧事项。相关前端构建与回归、正式 Host Web 的启动定向场景、Rust 偏好测试和 Desktop Clippy 通过。既有较宽登录回归在旧标题栏可见性断言上失败，未扩大本轮修复；本轮已重新生成并完成 Windows x64 MSI 安装器校验，交付到 `172.18.0.46` 桌面的 `EZ-Assistant-0.28.1-0928-Defaults` 目录；原生系统通知与安装后的运行验收待用户手动执行。

按用户反馈移除会话历史和实时消息中的 `ask_user` 定制问答卡片，统一使用普通工具记录和详情入口；输入区答题面板继续承载回答交互，轮后答案沿用已有 user message 展示。该界面调整已随本机最新 macOS 候选包构建；Windows 候选包尚未同步这一界面调整。

用户实测 Windows 前台仍收到通知，macOS 也要求同样处理。原判定读取 Tauri 窗口控件焦点，现改为读取应用前台状态：macOS 主线程读取 AppKit 应用激活状态，Windows 同步读取系统前台窗口所属进程。两端在原生通知提交前再次检查，跳过投递作为正常消费处理，不要求输入框有焦点，也不在切到后台后补发。用户已明确批准 Windows 只读查询函数的局部 FFI 例外；其余通知权限和业务来源判定保持原规则。相关前端回归、类型与静态检查、两端 Desktop Clippy 和格式检查通过。已重新构建并校验 Windows x64 MSI 与已签名、公证的 macOS arm64 DMG，分别交付到 Windows 验收机和本机桌面的 `EZ-Assistant-0.28.1-0928-ForegroundFix` 目录，版本保持 0.28.1；安装后的前台/后台通知效果仍待用户手动验收。
