# v0.28.1 F05 技术方案：跨平台资源预览与下载修复

- 状态：2026-09-27 M1 已实现并完成自主测试，待人工确认。
- 功能与验收依据：[版本总体与功能设计](../../总体设计.md)。
- 实施步骤：[开发计划](开发计划.md)。

## 现状与复用

- `apps/desktop/src/runtime-client/hostFilePath.ts`、`components/MarkdownContent/index.tsx` 和 `features/resource-workspace/resourceWorkspaceSnapshot.ts` 涉及 Host 路径、消息图片与资源恢复。
- `features/resource-workspace/ResourcePreview.tsx`、`native-bridge/` 与 `apps/runtime-host/src/http/resources/` 分别承载展示、桌面适配与 Host 读取。
- 初步检查发现 Windows 盘符路径可能被只接受 `/` 绝对路径的分支拒绝；这是待复现线索，尚不能解释右栏下载所有故障。

## 拟采用方案

1. 分别复现消息图片、右栏预览和下载，记录故障落在引用解析、请求、响应或保存哪一步；使用 Windows 桌面与连接 Windows Host 的 Web 两条真实链路。
2. 在现有 Host 路径解析处统一处理盘符、分隔符、file URI、中文与空格；会话资源优先使用已有根身份与相对定位，不由浏览器操作系统推断远端文件路径。
3. 预览和下载继续使用授权的 Host 资源入口。浏览器下载走现有 HTTP/Blob 路径，原生保存走适用的桌面适配；远端 Host 文件不能当成本机路径直接打开。
4. 统一图片/文档的失败反馈和重试入口，复用顶部消息机制。按实际执行文件定位的系统显示“资源管理器”或“Finder”；Web 无本地定位能力时隐藏/禁用对应操作，提供下载。

## 修改边界与验证

- 主范围：Host 路径辅助函数、Markdown 图片、资源预览与下载、Native 文件定位文案；只有定位到后端问题才修改 Host 读取链路，不放宽资源授权边界。
- 与 F02：共享资源打开/下载入口归此项修复；F02 新增产物分组调用同一入口，联合验证。
- 覆盖盘符与 URI、中文空格、缺失文件、越界路径、图片及文档、下载内容/文件名；同时回归 macOS。
- Windows 桌面、Windows Host Web 与 macOS 都需实测。真实环境不可用时明确保留未验证状态，不以路径单测代替验收。

## 实施核查

- 已复现前端把 Windows file URI 错转为 `/C:/…`、反斜杠 Host 路径无法构造 URI、下载名未取 Windows basename，以及恢复索引拒绝盘符路径；原生 `display_path_segments` 丢弃 Prefix，导致本地资源恢复失去盘符。
- 复用既有 Host 路径辅助、资源索引、HTTP/Native 下载入口与客户端平台事实修复，不新增资源实体、协议或数据库迁移。文件 URI 仍拒绝远端 authority、query/fragment 与编码分隔符；Host 授权保持原样。
- 当前 macOS 与 Windows 测试机可用，验证使用项目 `.runtime-test/` 下新建隔离环境；共享资源展示文件保留 F02 实现。

- Host 会话 locator 预览和下载在两平台正式入口回归通过，未发现需要修改读取/授权后端的缺陷，因此不扩展 Host 改动。Windows Desktop 原生保存对话框保留人工核验；其余完成边界见开发计划。
