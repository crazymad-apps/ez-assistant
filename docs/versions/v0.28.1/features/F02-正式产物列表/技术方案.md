# v0.28.1 F02 技术方案：正式产物列表

- 状态：2026-09-27 M1 实现与本地自主验收通过，待人工测试确认；F05 跨平台联合回归保留。
- 功能与验收依据：[版本总体与功能设计](../../总体设计.md)。
- 实施步骤：[开发计划](开发计划.md)。

## 现状与复用

- `crates/assistant-protocol/src/resource.rs` 已有 Session 资源定位与预览契约；`crates/assistant-runtime/src/runtime/resource.rs` 负责解析会话资源根。
- `apps/desktop/src/features/resource-workspace/` 已有资源列表、预览与操作；Host 的 `http/resources/` 承担受控读取。正式产物列表复用这些入口。
- 文件被引用或存在于目录，不能证明它是用户要求的交付物；需要补充“已明确交付”这一事实，不能靠扩展名或扫描结果猜测。

## 采用方案

1. 主 Agent 通过 `declare_artifact` 声明、更新或撤销交付项；Runtime 绑定当前会话和 Run，将成功工具结果记录到既有完整会话历史。SessionView 从该历史派生产物清单，不另设产物服务或存储。
2. 交付项最少表达所属会话、来源 Run、标题和资源定位。优先沿用现有资源身份；同一资源重复声明更新原项，不重复列出。撤销只取消交付身份，不删除文件。
3. 声明时验证文件存在且可受控读取；后续预览/下载再次校验。文件移动或删除时保留可辨识的失效项，不能仍显示可下载，也不扫描其他目录寻找替代文件。
4. 在会话现有资源区域提供“产物”分组；中间文件仍在资源工作区查看。卡片及条目样式对齐工作区，条目只显示文件图标和标题，不显示路径副标题，长标题单行省略；刷新按钮置于标题栏收起按钮左侧。沿用标准预览与下载交互，保留文件检查中与失效状态提示。

## 修改边界与验证

- 主范围：Runtime 工具装配与会话事实、共享资源投影、资源工作区的产物展示；工具壳与 Runtime 业务状态保持既有依赖方向。
- 与 F05：F02 负责“哪些文件是产物”，F05 负责打开、预览、下载和平台路径。先协调资源操作入口，避免各写一套路径解析。
- 验证正式文件、辅助脚本和临时文件混合任务；重复声明、撤销、缺失、跨会话隔离及重连恢复。打开/下载与 F05 联合回归。
- 实施前落实：结构化声明接入点和持久化落点；若必须新增存储或迁移，先说明现有记录为何不足、评估已发布数据影响，再确定方案。

## 实施核查结论

- 采用 `declare_artifact`，每次声明或撤销一个路径。Runtime 绑定当前 Session/Run；主 Agent 装配，子 Agent 交由父 Agent 确认交付。
- 完整产品 Conversation 在压缩时保留旧工具记录，因此成功工具结果已足够承载交付事实。SessionView 从该记录按定位顺序归并；不新增表、存储字段、持久化文件或 revision。只有完整 tool exchange 可靠提交后产物才出现，失败/中断结果不改变清单。
- 声明由 Host 按冻结 Session 根校验可读普通文件；撤销允许原文件已缺失，仅撤销身份。工具不会创建、复制或删除文件。资源存在性由现有受控路径及打开句柄检查；列表刷新、窗口重新激活和操作前重新检查。
- 新协议字段为增量投影，旧记录自然产生空列表；不迁移数据库。清空历史会清空产物声明；历史重入和 Fork 沿保留的 Conversation 前缀派生，私有资源仍绑定目标会话根，未复制的文件显示失效。
- F05 尚未实施，先回归当前 macOS/Web 资源入口；Windows 与 F05 的联合验收明确保留，不冒充完成。
