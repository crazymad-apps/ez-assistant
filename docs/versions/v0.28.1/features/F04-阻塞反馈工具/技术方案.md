## 二、模型可见工具：ask_user

采用一个工具、一套问题结构。模式使用“继续等待”与“结束本轮”两个直接动作，不暴露 Runtime 状态机术语，不使用容易让模型理解成继续后台执行的 async 标志。默认使用轮内等待，只有需要结束当前工作、等用户下一次回复时才显式选择 end_turn。

### 参数

| 字段 | 类型与约束 | 含义 |
| --- | --- | --- |
| questions | 必填数组，1—4 项 | 同一次交互的问题；优先只问当前阻塞的一个问题 |
| mode | 可选，`wait` / `end_turn`，默认 `wait` | wait：本工具等待答案并继续当前执行；end_turn：本工具登记问题后结束当前执行，答案成为下一轮 user message |
| questions[].question | 必填非空字符串 | 自包含的完整问题，必要背景写在此处；使用用户语言 |
| questions[].header | 可选短字符串，建议不超过 16 字符 | 多问题切换标签；不填时 UI 显示“问题 1”等，不重复生成问题摘要 |
| questions[].options | 可选数组；省略或空数组表示文本输入，非空时 2—4 项 | 可供选择的答案；UI 始终允许自由输入 |
| questions[].multiple | 可选布尔值，默认 false | 有选项时是否允许多选；没有选项时不得设为 true |
| options[].label | 必填非空字符串，同题唯一 | 简短、语义明确的答案，不使用 A/B 等代号代替内容 |
| options[].description | 可选字符串 | 只有确有必要时说明取舍；无说明不必填占位文本 |

模型不填写 request_id、Session/Run/owner、tool_call_id、callback、超时、通知渠道、答案 schema 或布局。默认自由输入，不提供 allow_custom 开关；“其他/自行输入”由 UI 提供，不要求模型枚举。推荐项可以排第一并在标签加“（推荐）”，但 UI 不预选，也不自动提交。

Schema 保持 object/array/string/boolean/enum 的固定层级，不引入 oneOf 条件表单、任意 JSON Schema 或嵌套 actions。沿用 Rust 类型 + schemars 生成，并在工具注册时公开 mode/multiple 的真实默认值；不同 Provider 的 schema 约束沿既有 Adapter 处理，不改变工具语义。各对象拒绝未知字段；resolve 对空问题、重复标签、非法枚举及数量进行校验，提供具体错误路径，不静默截断/改写问题。

### 最小调用：默认轮内、纯文本

```json
{
  "questions": [
    { "question": "这份方案面向哪个客户，预计何时交付？" }
  ]
}
```

### 单选与多选组合

```json
{
  "questions": [
    {
      "header": "交付格式",
      "question": "最终交付使用哪种格式？",
      "options": [
        { "label": "PDF（推荐）", "description": "适合直接审阅和打印。" },
        { "label": "可编辑文档", "description": "方便后续修改内容。" }
      ]
    },
    {
      "header": "包含内容",
      "question": "交付内容需要包含哪些部分？可以多选，也可以补充。",
      "multiple": true,
      "options": [
        { "label": "方案说明" },
        { "label": "设备清单" },
        { "label": "预算估算" }
      ]
    }
  ]
}
```

### 轮后等待

```json
{
  "mode": "end_turn",
  "questions": [
    { "question": "初稿已完成。请审阅后告诉我需要调整的地方，我会在收到回复后继续。" }
  ]
}
```

此时工具只返回登记回执，用户未回答前没有答案；Runtime 保证本轮结束。正文可以在调用前正常输出，工具参数不再带另一份 summary/result。

### 提供给模型的工具说明草案

```text
Ask the user for missing information, preferences, or feedback needed to proceed.
Prefer one question; ask up to four related questions together.
Use complete questions in the user's language. Omit options for a text answer,
or provide 2–4 concise choices. Users can always type their own answer.
Set multiple=true only when more than one choice can apply.
Do not add an Other option or invent an answer for the user.
mode=wait (default): wait for the user's answers as this tool's result, then continue.
mode=end_turn: present the questions and end this turn; the reply starts a new turn
as a user message. Use this when handing work back for later feedback.
Call this tool on its own, without other tool calls in the same response.
Do not use it to bypass tool permissions or runtime approval.
```

模型不必理解进程挂起、持久化或通知机制。工具说明和参数描述要使用同一术语，不能同时出现 async、轮外回调等另一套命名。是否容易理解仍需用现有模型接入做小样本调用验证。

## 三、回答组织与轮次语义

### UI → Runtime

问题集合按原始顺序冻结。Runtime 生成请求身份并绑定当前用户、Session、Run、执行 owner 和 tool call。UI 提交请求身份及每题的选中选项位置、自由文本；这些是内部 Command 字段，不要求模型生成。Runtime 从冻结问题恢复标签并校验，不能信任 UI 自报的题目或选项标签。

同一请求只接受一次答案；相同内容重试返回既有结果，不同内容的迟到提交返回已处理冲突。接受轮后答案、追加 user message 和解除会话等待必须作为同一个可靠变更提交，失败时不能留下“已回答但没有消息”的状态。

### wait：答案作为 tool result

建议固定返回 answered + 按题目顺序的答案数组；选中内容和补充文字分开，不把多选拼成难以区分的逗号字符串：

```json
{
  "status": "answered",
  "answers": [
    {
      "question": "最终交付使用哪种格式？",
      "selected_options": ["PDF（推荐）"],
      "text": "请同时保留源文件。"
    },
    {
      "question": "交付内容需要包含哪些部分？可以多选，也可以补充。",
      "selected_options": ["方案说明", "设备清单"],
      "text": ""
    }
  ]
}
```

纯文本题返回空 selected_options 和用户原文 text；不由另一次模型调用总结或解释答案。该结果只绑定原 tool call，不额外追加一条 user message。

### end_turn：回执与答案分开

登记成功时的 tool result：

```json
{
  "status": "waiting_for_user",
  "message": "Questions presented. This turn ends now; the user's reply will arrive as a new user message."
}
```

该回执先与工具调用闭合，再结束当前执行，不发起下一次模型请求。UI 将其展示为“等待你的回复”，不能显示“任务全部完成”。用户回答后新增一条正常可见的 user message，例如：

```text
回复助手的问题：
问题：初稿已完成。请审阅后告诉我需要调整的地方，我会在收到回复后继续。
回答：请缩短方案说明，并在设备清单中补充数量。
```

问题和原始答案一并进入新消息以保留上下文，关联身份留在 Runtime 元数据，不要求模型解析特殊 XML 标记。历史 tool result 保持登记回执，不事后改成答案。反馈消息触发新 Run/turn；继续使用现有 Session 输入路径，不构造后台恢复调用。

## 四、Runtime 实施边界

- 已核对 `agent-tools/src/tool.rs`、`dispatch.rs`：有类型化参数、无副作用 resolve、稳定 call_id 及默认串行执行。反馈工具注册为串行，等待通过异步 future，不能持锁等待或占用会话进程。
- 已核对 `assistant-runtime/src/permission/approval.rs`：可参考它的等待与重复处理协调；反馈不是审批或 `MessageFeedback` 消息评价，不复用审批决定枚举，不绕过现有工具授权。
- 反馈调用必须独占一个工具批次。复用整批解析/authorizer 边界，在任何工具执行前检查；模型把反馈和其他工具混发时，整批产生逐 call 配对的错误结果并提示单独调用，不能先执行相邻副作用。多个问题放同一次 questions，不同时发多个反馈工具。
- end_turn 的停止属于执行控制：现有 `agent-core/src/engine.rs`、`engine/tool_batch.rs` 与 `execution.rs` 需落实“工具结果已可靠记录后交还 Runtime”的类型化边界。不得解析回执字符串判断停机，不用取消信号伪装正常交接，也不能依赖模型看到回执后自觉停止。已落实为 Recorder 的 `ExchangeCompletion::ReturnToHost` 与 Core 的 `ContinuationReason::ReturnToHost`；Runtime 仅在成功闭合工具交换后正常结算本轮，不再次调用模型。
- 同一 Session 的上下文写入仍串行。轮内等待暂停当前执行；轮后待反馈虽没有活动执行，已有排队输入也不得自动绕过等待。用户可以明确发送新指令替代等待：先取消旧等待，轮内停止旧 Run，再按现有输入流程处理新消息；不自动把普通输入当答案，不悄悄丢弃已有队列，保留现有用户队列控制入口。
- `ask_user` 的 wait/end_turn 均必须接入 F03，遵循 [ask_user 通知接入契约](../F03-通用通知/技术方案.md#f04-ask_user-接入契约)：Runtime 先登记可查询问题再发布事实，客户端统一通知适配触发系统通知；回答/取消/失效同步更新，点击定位原问题。一组 questions 仅一条通知，不由模型选择是否通知，不在工具内部判断平台。通知发送失败或拒绝权限不能影响等待/回答；轮后只发待反馈通知，不重复报任务完成。
- 客户端断线或切换会话不取消等待；面板抢占输入区，不提供收起。默认无自动超时。Host 重启后旧轮内 Run 按现有策略中断，对应等待失效；轮后问题和关联关系从可靠会话事实恢复，但不自动开始执行。明确取消后不接受迟到答案。
- 复用现有会话记录/存储边界承载轮后问题与已接受答案；不预设独立反馈数据库。已在同一用户域 SQLite 中增加 `session_feedback`，由 Session/Run 外键管理生命周期；轮后答复与新 Input、Run 在原接纳事务中同时提交。该表保留独立于工具回执的待答/已答事实，历史回执不改写，不引入独立数据库。轮内等待只用异步通知唤醒，不将通知作为权威状态。
- 若向子 Agent 暴露工具，必须绑定已有 owner 并明确其 end_turn 只结束子执行；不能误结束父 Run。本次只向主会话 Agent 注册整个 `ask_user`，子 Agent 不暴露该工具。

### 已落实的恢复与兼容边界

- 问题发布前先可靠登记；回答与取消使用 pending 状态比较更新，答案只接受冻结题目中的选项位置和用户原文。轮后回复优先于既有排队输入，既有队列保留。取消轮内等待会等待原执行退出后返回，Goal 同步进入用户暂停状态。
- Host 重启时，轮内等待失效；只有已正常完成来源 Run 的轮后问题恢复为待答，不重放旧工具。终态 Run 的 pending 清理随原结算事务完成；清空、删除和重入沿用原会话边界与级联清理。
- `FeedbackPublished` / `FeedbackChanged` 和按会话查询命令共享同一快照。`RunFinished.awaiting_feedback` 明确表示轮后待答，客户端即使错过发布事件也不能发送完成通知。刷新恢复不重新发布通知。
- 迁移账本增加 `0.28.1`，复用现有独立备份、核验和事务迁移流程；数据库最低 Host 版本提升至 `0.28.1`。应用最低兼容版本同样提升至 `0.28.1`，避免旧客户端因不识别问答契约而无法处理等待。Cargo、Desktop、Client 和 TS 协议版本同步。
- Desktop 问答草稿仅保存在当前 Runtime 实例、用户、Session 和请求的内存范围，切换会话保留，切换实例/用户清空；旧异步响应不能覆盖新状态。失败保留填写，整组显式提交，无预选。按 2026-09-27 用户澄清，面板抢占输入区并隐藏普通输入，不允许收起；提交或取消命令尚未确认时即便先收到终态事件仍保留面板，避免提前恢复普通输入。取消成功后手动发送新消息，不提供取消并发送的复合操作。
- 题目导航只更新本地草稿位置，下一题及快捷键不提前恢复执行；最后一步校验整组答案，有遗漏时定位未答题。选项清除保留补充文字，切题恢复已选项或输入框焦点，输入期间不因完成状态变化抢焦点。

## 五、模型可用性与验收

- 参数样例覆盖默认 wait、纯文本、单选、多选、组合问题和 end_turn；验证派生 schema 与真实默认值一致。空问题、五题以上、同题重复标签、非法 mode、无选项 multiple=true 均返回可修正的具体参数错误，不创建半成品等待项。
- UI 覆盖选择后修改、自由输入、选项加补充文字、键盘与中文输入法、切换问题、重复点击、发送失败保留原输入和跨会话草稿隔离。交互细则集中在版本功能设计。
- 执行覆盖两模式消息角色、批次混发零副作用、登记失败、回答/取消竞争、队列等待、断线重连、Host 重启及轮后提交失败；不得通过恢复重跑已执行工具。
- 通过现有模型接入做少量代表性任务验证，观察模型是否正确选模式、生成问题/选项，以及答案是否被正确理解；包括信息缺失继续执行、初稿交给用户审阅后结束本轮。确定性测试验证契约，真实模型验证表达可用性，不能互相替代，也不据此宣称所有模型都能稳定调用。
- 该步骤只调用隔离的无副作用测试工具，不执行真实外部任务；没有可用模型或适用平台时明确保留未验证项，不在本轮文档准备中发起模型请求。
