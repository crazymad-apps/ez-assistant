## 二、代理观察与结算

### 解析位置与边界

在 `src/llm/` 内增加私有用量解析模块，由 `CallRecording` 持有单次解析状态。`ModelProxy.execute` 在收到响应头和数据块时同步馈入，处理后继续原始数据块转发；不修改、重新序列化或重发请求/响应。解析异常转为用量原因码，不抛入网络链路；结果写库仍由既有 owner 等待。

- 正文采集的 `Capture` 与用量观察独立；关闭正文、正文超限或文件保存失败不影响正常大小响应中的 usage 提取。
- 根据响应 Content-Type 选择 SSE 或 JSON；不支持的类型/编码只令用量不可用，保持转发。上游忽略 identity 返回压缩内容时，本期不新增解压路径。
- SSE 增量处理 UTF-8、跨 chunk 字符、LF/CRLF、空行事件边界、多行 data 和 `[DONE]`；忽略注释及与 usage 无关的事件。不能逐网络 chunk 执行 JSON.parse，也不能遇到 finish_reason 就停止读取流末 usage。
- 缓冲上限：单 SSE 事件 1 MiB、单 JSON 响应 8 MiB，用量解析共享内存预算 16 MiB，与正文快照预算独立。超大 SSE 事件丢弃至下一事件边界后继续找 usage；JSON 超限或预算不足停止该次解析，记录明确原因。缓冲释放覆盖正常、异常、取消与关停；不缓存整个 SSE 会话。
- 未知 SSE 事件不致失败；相关 usage 事件损坏、缺少终态或资源超限时，不宣称完整。无法可信提取的数字不进入汇总，已获得但不完整的数字可保留并明确标注。

### 字段口径

| 指标 | Chat Completions usage | Responses usage |
| --- | --- | --- |
| 输入 | `prompt_tokens` | `input_tokens` |
| 输出 | `completion_tokens` | `output_tokens` |
| 总量 | `total_tokens` | `total_tokens` |
| 缓存命中输入 | `prompt_tokens_details.cached_tokens` | `input_tokens_details.cached_tokens` |
| 推理输出 | `completion_tokens_details.reasoning_tokens` | `output_tokens_details.reasoning_tokens` |

Chat 非流式读取顶层 usage，流式读取 chunk 顶层 usage（含空 choices 的流末块）。Responses 非流式读取顶层 usage；流式读取 `response.completed/incomplete/failed/cancelled` 中存在的 `response.usage`，对终态成功与失败一视同仁地保留实际数字。没有 usage 不自行推算。DeepSeek 仅在准入时确认 provider_type 为 deepseek 且嵌套字段缺失时识别 `prompt_cache_hit_tokens`，其他私有字段不猜测。

输入、输出、总量分别保存上游提供值；总量不通过字符估算，缺失时不自动补成 0。缓存是输入子项，推理是输出子项，不再次加总。字段须为非负安全整数，超出 JavaScript 精确整数范围的字段标为无效；主项不一致（如总量不等于输入加输出）或子项超过父项，保留可信字段并标记部分可用，不隐藏差异。

每个响应的 usage 是累计快照：重复值不相加，后续有效快照整体替换前值，不拼接不同快照字段。已知字段回退或响应 ID 冲突标为不完整，不以取最大值掩盖协议问题。Chat 有效 usage 后仍等 `[DONE]`；缺少结束标识或中断时按部分可用记录。Responses 有合法终态 usage 时即使下游随后断开，usage 完整性仍由上游已观察事实判定，与转发结果分开。

### 持久化与恢复

扩展 `CallEntity` 与 `public.llm_calls`：

- 五个 nullable bigint：`input_tokens`、`output_tokens`、`total_tokens`、`cached_input_tokens`、`reasoning_tokens`。
- `usage_state`：`pending`（新调用待结算）、`available`（完整观察且三个主项有效）、`partial`（存在可信数字但主项缺失/观察不完整）、`unavailable`（没有可信用量）；可选明细缺失不降低三个主项的完整性。
- nullable `usage_reason`：固定原因码，覆盖 historical、not_forwarded、not_reported、interrupted、invalid_usage、unsupported_content、unsupported_encoding、parser_limit、parser_budget、process_restarted；不包含正文或原始解析错误。

旧行设为 unavailable/historical，数字保持 NULL；新行显式 pending。单次结算在更新 outcome、ended_at 的同一 UPDATE 写入 usage，沿用现有 settled Promise 保证重复结束不重复入账。持久化失败不把响应重发给上游，不新增无限重试；调用留为未结算并沿现有诊断暴露，统计计入未知/待结算，不宣称用量已落库。启动恢复将未结算调用及 pending usage 标为未知结果/不可用，不从不完整快照推测成功。

Token bigint 经 ORM/DTO 输出十进制字符串（缺失为 null）；SQL SUM 使用精确数值再转字符串，前端精确格式化，只有图表比例换算使用 Number。次数也采用可精确表达的十进制字符串，避免大量记录聚合溢出。

## 三、聚合查询与历史范围

新增管理员只读 `GET /api/llm-usage`，位于既有 calls 管理契约内。查询参数复用 `from/to/user_id/kind/outcome`，增加 `granularity=hour|day|month`、`group_by=user|model`；模型过滤必须同时提供 `provider_instance_id` 与 `model_id`。现有调用明细接口保留单字段查询能力，统计 UI 只提供联合选择器。

- 管理页默认全部用户、今天、小时粒度、业务代理、全部转发结果；个人指选中用户 ID。首次进入及手动刷新查询，不新增后台轮询任务。
- 以 started_at、Asia/Shanghai 分桶；API 输入输出使用 UTC ISO 时间并返回分桶时区，采用 `[from,to)`。当前未结束的小时/天/月标记“进行中”，其数据可变化。
- 单次最多 1000 个时间桶，超限明确提示切换粒度/缩短范围；分组结果按总 Token 降序、稳定 ID 次序分页，每页默认 20、最多 100。汇总、趋势计算全部匹配行，不受分组页码影响。
- 一个响应返回查询口径、汇总、趋势、所选分组页和分组总数；用单条聚合 SQL 或只读可重复读事务保证同次结果一致。参数化 SQL，不拼接客户端列名、排序表达式或时区；沿用数据库查询超时。
- 汇总含调用次数、各 usage 状态次数、各指标已知和及已知样本数、转发结果分布和已结束调用平均耗时。有效历史范围内确无调用时，主项合计与次数为 0；有调用但指标无任何已知样本时为 null。部分已知时显示“已知合计”，不能宣称整个范围的真实总消耗。可选缓存/推理各有独立覆盖数，不将其 null 当作 0。
- 分组以用户 ID 或服务商实例 ID + 模型 ID 聚合，展示保留记录中的历史名称；名称不参与分组。删除服务商或停用用户后仍能查历史；缺失身份进入明确的“未知”组，不 INNER JOIN 当前目录导致漏数。
- 模型筛选选项使用保留调用中的联合键与名称，不能只依赖当前在线模型目录；提供同样管理员权限的按用户/时间等当前范围查询的搜索分页选项入口，避免一次加载全部历史键。用户选择优先复用现有用户查询，历史缺失用户支持按 ID 查询。
- 点击分组/趋势进入既有 `/calls` 路由，并传递所有已应用筛选；列表初始化读取这些参数，详情返回保持条件。不同时间发起的查询可能新增结算，页面展示查询时间并允许刷新，不承诺跨请求静态快照。

首期继续使用现有索引保留期，默认 90 天，可经记录策略改至最多 3650 天；正文默认 7 天、默认不采集。增加 `llm_recording_settings.usage_available_from` 对外只读的时间字段，由升级事务初始化，表示本中心可完整查询用量记录的最早边界，不能用“第一条有 usage 的调用时间”冒充统计起点。没有调用时这个边界仍存在，故现有调用行不能替代它。

复用这个边界表达历史缺口：有效边界取当前起点与当前索引保留窗口起点的较晚者；缩短保留期时将边界单调向后推进，延长保留期不退回，避免把已删历史重新标成完整。未曾运行清理的边缘记录可作为保留明细展示，但不据此扩大完整范围。首尾部分时间桶标注不完整；完整范围内没有调用的桶可以显示 0，范围外用缺口标识。用量可用率仍按实际行计算，不将时间范围完整误解为所有上游都返回了 usage。

## 四、后台交互与调用采集修复

新增导航“用量统计”及 `/usage` 路由，复用 PageLayout、Ant Design、主题 Token 和页面级 `useResourceQuery`。筛选、加载、结果均留路由页面，不放进 AdminStore；记录策略写入继续走原有身份/写入守卫。

页面顺序：

1. 筛选条：用户（全部/指定用户）、时间范围、小时/天/月、一个可搜索的“服务商 / 模型”选择器、调用类型和转发结果；联合选项重名时附服务商实例短 ID。提供查询、刷新、重置。
2. 汇总：顶部显示已知总 Token、调用次数和缓存命中率；下方按总输入 Token、缓存命中 Token、新增输入 Token、总输出 Token 排列。新增输入为总输入减缓存命中，仅在两项样本数一致且缓存不超过输入时显示，否则为未知。缓存命中率为缓存命中输入 Token ÷ 输入 Token，仅在两项样本数一致且输入大于零时计算，否则显示未知。推理输出保留采集字段，但不在首期页面展示。旁边展示已知覆盖、待结算/缺失数量、时区及历史范围，缺失不用绿色成功态或数字 0 掩盖。
3. 时间趋势：按用户追加要求使用 ECharts 平滑面积图，支持总览/总量/输入/缓存命中/输出切换、悬浮提示、点击时间桶下钻，以及长时间范围内缩放；图下提供可展开的精确数值表。总览从下到上只将新增输入（输入减缓存命中）、输出和缓存命中堆叠，避免总 Token 曲线与堆叠顶部重合；总 Token 保留独立切换查看。缓存用量未知时不伪造新增输入。无调用的时间桶绘制为零，整段无调用时显示平坦零线；存在调用但缺失用量的时间桶保留空值，曲线跨空值连接仅用于趋势展示，提示与明细仍为未知；全部调用都无已知用量时显示明确空状态。只引入所需的折线图、提示、缩放和 Canvas 模块，跟随页面主题色并在容器变化时重排。
4. 分组表：切换“用户”或“服务商 / 模型”，显示各项用量及覆盖率；服务商与模型共同显示在同一列，不再提供独立服务商分组。详情操作固定右侧、居中、小按钮，进入调用记录。

加载失败保留上一次成功数据并标明旧结果对应条件；新筛选仅在成功后成为结果口径，避免旧数字配新条件。身份切换清空页面，迟到响应不得覆盖新身份。无调用、全无 usage、部分未知、超出留存范围、查询失败分别展示。

调用记录修复：

- 列表顶部显示当前“正文采集已开启/未开启”，保留“记录策略”入口；disabled 展示“当时未启用正文采集”，避免与当前开关混淆。
- 详情在独立区域展示该调用的 Token、usage 状态及原因；快照仍单独显示请求与响应状态。“用量不可用”和“正文未采集”不得共用一个状态。
- 策略弹窗说明用量统计持续工作、正文开关只影响新调用，正文可能含敏感信息；沿用现有显式启用/缩短保留期确认。调用已开始后切换策略不追溯改变其采集决策。
- `complete/partial/failed/expired/missing` 分别保留状态；保存中可刷新，不因响应 EOF 先于文件结算而提前报错。未知字节数用“—”，不伪装成 0 字节。
- 实施时在核实的隔离环境覆盖默认关闭、开启后新请求、运行中切换开关、快照超限及文件异常；现场已开启仍失败时再按证据修复原写入/读取路径，不批量改历史状态。正文仍由受保护接口按需读取和审计，不放静态目录、不扩展采集 Authorization/Cookie。

- 最小修改范围为 Center `llm/`、calls 契约、迁移和定向测试，Admin 新统计路由/页面、calls 展示、生成 SDK 和相关请求层。正式 Host、Agent Core 与 Runtime 无新增协议；F01 仅联合核对重试次数与用量。

## 六、验证与完成边界

- 解析：两协议 JSON/SSE、跨 chunk/UTF-8/CRLF、多行 data、流末空 choices、重复累计快照、无 usage、异常主项/子项、大整数、超限与未知事件；验证原转发字节不变。
- 结算：正文关闭仍计量、配置测试分离、失败/取消前已报告用量、不同重试独立调用、重复 settle 不重复记账、写库失败及进程恢复不伪造完整。
- 聚合与权限：真实 PostgreSQL 对个人/全部、联合模型键、同名不同服务商、名称变化/停用、跨日/月、左闭右开、分页与明细总和进行核对；覆盖新旧数据、零值/null、部分数据、保留期缩短后延长及管理员权限。
- 浏览器：筛选、趋势与精确值、分组下钻、历史范围提示、正文开关和新请求真实正文、加载失败与身份切换；沿用现有 UI，不新增结构扫描或逐字文案测试。
- F01 联调：同一任务触发多次中心代理尝试，每次实际返回的 usage 只计一次；不将会话累计用量叠加到中心。确定性上游验证不替代真实兼容服务的代表性流式取数核验，未具备条件时列为待验收。

验证结论记在开发计划，不另建报告。Center 与 Admin 实现、隔离库升级、备份恢复、有数据集成及浏览器验证已完成；本地 7320 测试中心完成迁移、真实代理用量及双侧正文快照复核。正式 Runtime 的 F01 跨进程联调仍归版本验收。
