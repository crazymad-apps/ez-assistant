# v0.20.0 界面交互设计指导：主控会话与上下文控制

## 一、设计信息

- 版本：`v0.20.0`
- 状态：已确认（2026-08-26）
- 影响页面：Desktop 会话侧栏、Session Header、Conversation、Composer、Queue 和会话操作确认框
- 关联设计：[`v0.20.0 功能设计`](功能设计.md)、
  [`v0.20.0 技术方案`](技术方案.md)
- 产品基线：[`v0.19.0 界面交互设计指导`](../v0.19.0/界面交互设计指导.md)
- 视觉基线：[`Desktop 设计语言`](../../resources/桌面端设计语言.md)
- 源码基线：2026-08-26 当前 `SessionSidebar`、`SessionHeader`、`ConversationView`、
  `ComposerDock`、`QueueDrawer` 和 `SessionActionDialog`

本指导只固定用户能看到和操作的入口、布局、状态、文案、焦点与异常反馈。Session role、proxy、
跨会话来源、clear、compact 和 Queue 的权威语义以技术方案为准。Desktop 只提交用户意图并展示
Runtime 快照，不按标题、列表位置、消息文本、generation 数字或本地计时器猜测业务状态。

## 二、交互目标与边界

### 2.1 本版本需要建立的用户心智

1. **主控会话是固定协调入口**：它与普通会话并列存在，但在侧栏中有稳定、可识别的位置。
2. **主控代理是普通会话的显式状态**：默认关闭；开启后才允许主控投递任务并接收该会话的
   Run/Goal 终态报告。
3. **用户随时拥有最终控制权**：用户在被代理会话中直接发送消息即接管该会话，成功接受后
   自动退出代理。
4. **清空与压缩是不同操作**：清空会删除产品历史并重建系统上下文；压缩只把较早上下文替换为
   摘要并保留近期轮次。
5. **压缩是 Session 的临时运行状态**：自动与手动使用同一可见口径；只有手动压缩提供独立取消。

### 2.2 本版本不设计的界面

- 不提供主控仪表盘、会话矩阵、批量控制、拖拽编排或任务拓扑图；
- 不在主控报告上提供“继续执行”“转发给其他会话”等自动控制按钮；用户需要在主控 Composer
  中写出新的指令；
- 不设计未读数、系统通知、通知中心、IM 渠道或外部消息回执；
- 不提供创建第二个主控、选择当前主控或切换主控的设置项；
- 不把代理状态保存到 Desktop preference、localStorage 或连接状态中。

## 三、页面信息架构

现有三栏结构不变。本版本只在已有入口内增加信息：

```text
左侧 SessionSidebar              中栏 Session                    右侧
┌──────────────────────┐       ┌──────────────────────────┐     ┌──────────┐
│ 新对话          搜索  │       │ 标题 / 身份 / 状态 / 代理开关 │     │ 当前上下文 │
│                      │       ├──────────────────────────┤     │          │
│ 会话｜已归档          │       │ Conversation             │     │ 保持现状   │
│ 主控                 │       │ 来源消息 / 报告 / 压缩边界    │     │          │
│  ◉ 主控会话           │       │                          │     │          │
│                      │       ├──────────────────────────┤     │          │
│ 工作区与普通会话列表    │       │ 压缩状态 / Queue / Composer  │     │          │
│                      │       └──────────────────────────┘     └──────────┘
└──────────────────────┘
```

主控入口不进入工作区分组，只在“会话”页签中显示；切换到“已归档”时与普通 active Session
列表一起隐藏。右侧“当前上下文”本版本不新增主控管理区；代理开关属于当前 Session Header，
压缩状态属于中栏运行态。

## 四、侧栏中的主控会话

### 4.1 固定位置

- 在“会话 / 已归档”页签下方、工作区与普通会话列表上方增加紧凑的“主控”分区；
- 分区只展示 Runtime 当前 `ControllerAvailabilitySnapshot` 指向的 Session；不按标题为
  “主控会话”或列表第一项推断；
- 主控行复用普通会话行的高度、选中态、运行状态和键盘导航，不使用大型彩色卡片；
- 主控不属于工作区分组。它可以继续使用自己的 Session 配置，但侧栏位置不随 Workspace 改变；
- “会话”页签内打开搜索或普通列表为空时，主控分区仍保持可见；切换到“已归档”时隐藏整个
  主控分区，主控不会作为归档结果出现。

### 4.2 主控行

```text
主控
[主控图标] 主控会话                         [运行状态]
```

- 使用产品内已有单色图标和文字“主控”，不依赖颜色表达角色；
- 标题仍可按现有方式由用户编辑。角色识别始终来自 `role`，标题改名后入口不丢失；
- 主控行不显示归档入口，也不出现在已归档列表；
- 主控运行、等待审批、Queue 和压缩状态沿用普通 Session 的状态语义；压缩中显示文字
  “压缩中”，不能只显示旋转图标；
- 点击主控行只切换当前 Session，不自动创建指令、不打开管理面板。

### 4.3 主控准备失败

Runtime 启动时尚未返回快照，主控区域显示一行不可交互骨架“正在准备主控…”。若快照明确为
`Unavailable`，替换为：

```text
主控
[警示图标] 主控暂不可用
           请查看运行时状态后重试
```

本版本不提供“创建主控”或定时重试按钮。连接恢复或应用快照刷新后自然替换该状态；普通会话仍可使用，
代理开关因没有可用主控而禁用并给出原因。

## 五、Session Header 与代理切换

### 5.1 身份、状态和操作布局

Header 保留现有标题编辑、状态、更多菜单和右栏开关，增量布局为：

```text
返回  会话标题  [主控 / 主控代理]  [会话运行状态]      [主控代理 开关]  …  右栏
```

- Controller 在标题后显示静态身份标签“主控”，不显示代理开关；
- Standard 且代理开启时显示静态身份标签“主控代理”；关闭时不显示“普通模式”标签，减少噪声；
- Standard 的 Header 操作区显示“主控代理”文字和开关。开关使用 `role="switch"`、
  `aria-checked` 和完整状态名称；
- 身份标签表达当前权威状态，开关表达可操作意图，两者不能合并成一个仅靠颜色变化的图标；
- Controller 的 Header 更多菜单隐藏“归档”和“永久删除”；Conversation 中的 Assistant 消息隐藏
  “从此消息分叉”。Runtime 仍对这些角色限制作权威拒绝。

### 5.2 开启与关闭代理

- 开关只提交目标终态，不做乐观切换；提交期间保留原状态，禁用当前开关并显示紧凑加载反馈；
- 开启、关闭都不弹确认框，也不向 Conversation 插入系统消息；
- 成功后以命令结果或最新 Session 快照替换 Header 与侧栏状态；
- 失败时恢复权威状态，并在 Header 下方显示持续可见、可关闭的中文错误；
- 有无 queued Input 都允许切换代理状态；Queue 不禁用开关，也不产生“待生效”视觉状态；
- 没有可用主控、Session 已归档、Session faulted 或同一 Session mutation 正在提交时禁用开关，
  `title`/无障碍说明给出具体原因；
- 开启后若仍有 Queue，在 Header 身份标签下显示“现有队列处理完毕后报告最新结果”；主控投递在
  此期间返回目标忙碌，但代理开关保持开启；
- 活动 Run 中允许切换。界面不声称“只对下次运行生效”，是否报告以 Run 结算时的权威代理状态和
  结算后 Queue 是否排空为准。

### 5.3 用户直接接管

代理开启时，在 Composer 输入区上方显示一行弱提示：

> 当前由主控代理；发送消息后将由你接管并退出代理。

- 用户仍可正常编辑正文、附件、Goal 和 Skill；不要求先手动关闭开关。即使活动 Run 使新输入进入
  Queue，本次提交也会先退出代理；
- 发送前不弹确认框，Desktop 也不先把开关改为关闭；
- Runtime 接受用户输入成功后，Desktop 重读 SessionView，代理标签和开关自然关闭；
- 接受失败时完整保留草稿，代理状态不变，不能显示“已接管”；
- Runtime 删除尚未开始的主控投递时，目标和主控均不显示“已取消”或“用户已接管”消息。

## 六、跨会话消息与代理报告

### 6.1 三种可见消息来源

Conversation 依据 `UserMessageSnapshot.source` 区分以下呈现，不能解析正文猜测：

| 来源 | 所在会话 | 主标签 | 视觉语义 |
| --- | --- | --- | --- |
| User | 任意 | 无 | 沿用当前用户气泡 |
| ControllerDelivery | 被代理会话 | 主控转达 | 中性转达消息，不伪装成用户本人 |
| ProxyReport | 主控会话 | 会话报告 | 中性结果卡，不伪装成用户本人 |

Skill 标签仍按冻结事实显示，但来源标签排在 Skill 与时间之前。来源不是普通正文的一部分，复制正文时
不自动把“主控转达”“会话报告”等界面标签写入剪贴板。

### 6.2 主控转达

在目标 Session 中使用与用户气泡相同的信息密度，但改为中性色 surface 和一条弱化左边线：

```text
主控转达 · 主控会话
请继续检查登录流程中的刷新问题……
[Skill（如有）] · 14:32
```

- 来源标题根据 `controller_session_id` 从当前应用快照解析；主控改名后显示当前标题；
- 来源标题是按钮，点击后通过现有会话导航打开主控；不自动定位某个 Run；
- 主控暂不可用或来源无法解析时显示“主控转达”，不展示原始 Session ID；
- 该消息与随后 Assistant Turn 按正常时间线排列，附件本版本不属于主控投递范围。

### 6.3 会话报告

主控 Conversation 中的 ProxyReport 使用紧凑结果卡：

```text
会话报告 · 登录问题排查                         [已完成]
关联目标（仅有 Goal 时）

已确认刷新令牌在并发请求时被重复消费……

[打开来源会话]                                  14:38
```

- 终态固定显示“已完成 / 失败 / 已取消 / 已中断”，颜色只作辅助；
- 报告正文显示 Runtime 已冻结的最终 Assistant 回复或稳定失败事实；不展开 reasoning、工具详情、
  审批、附件或原始 Provider 错误；
- 有 Goal 只显示一行“关联目标”，不默认暴露 Goal ID；无 Goal 时整行省略；
- “打开来源会话”根据 `source_session_id` 导航到来源 Session，不创建后续指令；
- 来源 Session 已删除或不可访问时，按钮禁用并显示“来源会话不可用”，报告本身继续保留；
- Run ID 仅用于协议归因和测试，不作为普通界面正文展示；
- 报告卡不提供“继续”“重试”“转发”“关闭代理”等快捷按钮。用户要继续管理时，在主控 Composer
  输入明确指令。

### 6.4 排队中的来源

Queue 中若存在尚未开始的 ControllerDelivery，条目在正文摘要前显示“主控转达”弱标签；普通用户
输入不显示来源标签。ProxyReport 只会进入主控自身的可靠输入队列，若真实等待则显示“会话报告 ·
来源会话”，但不能获得主控跨会话工具或特殊操作按钮。

## 七、清空会话历史

### 7.1 操作入口与可用性

- 在 Session Header 的更多菜单中增加“清空会话历史…”，放在导出之后、归档/永久删除之前，
  并用分隔线与普通操作分组；
- Standard 和 Controller 均可清空；Controller 只是不允许归档、删除和分叉；
- 仅 active、healthy、完全空闲的 Session 可执行。忙碌时菜单项禁用，说明“请等待运行、审批、
  队列或上下文压缩结束”；
- Desktop 的禁用只用于减少误操作，Runtime 提交时仍重新核验。

### 7.2 二次确认

复用现有 `SessionActionDialog` 的危险操作框架：

```text
清空这个会话的历史？

这会永久删除当前产品中的对话消息、运行记录、目标、工作计划和检索历史，
并按当前设置重建系统上下文。此操作无法撤销。

会保留：会话身份、工作区、模型与运行设置、附件、权限和会话私有目录。
[主控会话：主控身份及其他会话的代理关系也会保留。]
[普通代理会话：清空后将退出主控代理。]

                         [取消] [清空历史]
```

- 标题显示当前会话名，长标题单行省略并可通过 `title` 读取完整值；
- 不要求用户输入会话名；一次明确的危险确认已经构成二次确认；
- 主按钮使用危险样式，提交中改为“正在清空…”，两个按钮都禁止重复提交；
- 对话框打开后焦点落在“取消”，Esc 等同取消，提交期间 Esc 不关闭；
- 提交前若 Session 变为 busy，保留对话框并显示“会话正在运行，结束后再试”，不产生部分清理。

### 7.3 成功、待清理和失败

- `Completed`：关闭确认框，重读 ApplicationSnapshot、SessionView 和 Conversation，显示空会话状态
  “历史已清空，可以开始新的对话”；
- `CleanupPending`：同样按空会话快照重建，并显示持续警告“历史已从产品中清空，部分本地文件将在
  运行时恢复后继续清理”；不能把旧历史重新展示为可恢复内容；
- 准备或提交失败：保留原 Conversation 和确认框，在框内显示中文错误；
- clear 后用户自定义标题保留；Runtime 生成标题由快照决定，Desktop 不自行改成“新会话”；
- 附件管理、私有目录和权限入口保持可用，但旧消息不再通过 Conversation、Recall 或导出出现。

## 八、`/compact` 与统一上下文压缩状态

### 8.1 指令入口

- 斜杠菜单新增“压缩上下文”，快捷语法 `/compact`，说明为“将较早对话压缩为摘要并保留近期轮次”；
- 只有输入框去首尾空白后精确等于 `/compact` 才转换为 `CompactSession` Command；
- 它不是 UserMessage，不上传附件、不调用 `submit_input`、不创建 Queue 项、Run 或 Goal continuation；
- 与任意其他正文、附件、已武装 Goal 或已选 Skill 组合时不执行，完整保留草稿与标签，并显示：
  “`/compact` 需要单独发送，请先移除正文、附件、目标和技能”；
- Session busy 时直接拒绝，不排队。草稿保留为 `/compact`，方便用户在空闲后重试。

### 8.2 统一运行态

手动和自动 parent compaction 共用一条 Session 级状态条，位于 Composer 上方、Approval 与
Queue 之后：

```text
[旋转图标] 正在压缩上下文
           手动压缩较早对话

[旋转图标] 正在压缩上下文
           运行中自动压缩较早对话
```

- Header 同时把 Session 状态显示为“压缩中”；若自动压缩与 active Run 并存，Conversation 仍保留
  Run 的实时内容和停止入口，状态条补充表达压缩阶段；
- `trigger = Manual` 显示“手动压缩较早对话”；`Automatic` 显示“运行中自动压缩较早对话”，
  不向普通用户展示阈值枚举或 Provider overflow 技术名；
- `cancellable = true` 时复用 Composer 输入框现有的发送/终止主按钮槽位：按钮切换为终止图标，
  无障碍名称为“取消压缩”，点击调用 `CancelSessionCompaction`；状态条内不再增加操作按钮；
- 自动压缩的 `cancellable = false` 不改变按钮语义，Composer 仍显示关联 Run 原有的“停止运行”；
  停止的是 Run，不是一个独立的压缩操作；
- 手动压缩期间禁用正文提交、附件、Goal、Skill 和模型变更，输入框占位为“正在压缩上下文…”；
  代理开关仍可按明确终态提交，因为它不改写 Conversation，且代理报告本来就以 Run 结算时状态为准；
- 状态来自 `SessionSummary/SessionViewSnapshot.active_compaction` 和开始/结束事件，不写入
  localStorage，不在客户端刷新后续时长，也不用超时器自行结束。

### 8.3 完成反馈

| 结果 | 用户反馈 | 草稿与 Conversation |
| --- | --- | --- |
| Compacted | “上下文已压缩，较早内容已替换为摘要” | 清除已接受的 `/compact`；重读新 generation |
| NoOp | “当前无需压缩” | 清除 `/compact`，焦点回输入框 |
| Cancelled | “已取消压缩，历史未更改” | 清除 `/compact`，沿用旧 generation |
| Failed | 持续错误“压缩失败，历史未更改”及稳定中文原因 | 保留 `/compact` 供重试 |

- Desktop 以相同 operation ID 的 Started 事件或命令成功接受为准清除 `/compact` 草稿；连接/门禁失败
  时不提前清除；
- 完成消息使用 Composer 持续反馈区，不作为 Conversation 消息，不触发主控报告；
- 成功 replacement 后更新上下文用量，但不显示“释放了 N token”等估算值；
- 手动取消提交中禁用输入框终止按钮，无障碍名称改为“正在取消压缩”；不乐观移除状态条。
  若 replacement 已提交，则以最终 Compacted 结果为准。

### 8.4 “较早内容已压缩”边界

Context Summary 复用规范 Conversation 中已有的压缩结果，并作为 ConversationItem 中的内联分割项
进入 Desktop 消息序列。Desktop 在压缩 generation 切换时保留当前已加载的原消息、去重近期保留
消息，因此分割项自然位于旧消息与近期轮次之间：

```text
──────── 查看上下文摘要 ────────
```

- 边界默认收起；点击文字在分割线下方展开摘要正文，再次点击收起；
- 摘要正文只读，使用普通 Markdown 正文样式，不提供复制原历史、恢复上下文或编辑操作；
- 自动和手动 compact 使用同一分割项；Desktop 不通过 `generation > 1` 推断，因为 clear 也会
  切换 generation；
- 没有 Context Summary item 时不显示。clear 后空 generation 也不显示；
- 不为该交互新增摘要 DTO、边界计数、历史存储或分页拼接机制。

### 8.5 断线、事件缺口与 Runtime 重启

- Started/Finished 只用于低延迟更新。SSE gap、未知事件或重连后立即以 Session 快照覆盖本地状态；
- Runtime 重启后 `active_compaction` 必然为空。Desktop 不因缺少 Finished 事件保留“压缩中”；
- 重启恢复到旧 generation 时只显示普通 Conversation，不伪造“已取消”；恢复到已提交新 generation
  时按其中已有的 Context Summary item 显示分割线；
- 事件到达顺序异常时以 compaction ID 匹配当前操作，不让旧 Finished 清除新 Started。

## 九、Queue 待发送区闪现修复

### 9.1 单一展示选择器

Queue Drawer 的可见性、条目和数量必须消费同一个 `queuePresentation` 结果：

```text
automatic Queue
+ 无 active Run
+ 队首未被 Goal hold
=> 仅从展示列表隐藏正在交给 Run driver 的队首
```

- 过滤只影响 Desktop 展示，不修改 Runtime Queue、durable count 或生命周期统计；
- 若过滤后没有条目，整个待发送区不挂载，因此不会出现空框或“一闪而过”；
- 若后面还有条目，只隐藏队首，后续真实等待项和数量继续显示；
- Queue 非 automatic、已有 active Run 或队首被 Goal hold 时不应用过滤；
- Queue 项的取消、置顶和来源标签只针对 selector 返回的可见项。

### 9.2 禁止的掩盖方式

不增加 debounce、最短显示时长、淡入延迟、setTimeout 或本地“正在发送”伪状态。事件 gap 或快照重读后
重新从同一 selector 计算，不把历史可见性作为下次判断输入。

## 十、状态优先级与操作矩阵

### 10.1 Header 状态优先级

同一 Session 可能同时存在 Run 与自动压缩。Header 的单个主状态按以下顺序显示：

1. 已归档；
2. 故障 / 连接不可用；
3. 压缩中；
4. 等待审批；
5. 正在运行 / 正在停止；
6. 有待发送项；
7. 空闲。

“压缩中”成为主状态时，自动压缩关联 Run 的详细状态仍在 Conversation 实时行和停止按钮中可见，
不能让用户误以为 Run 已结束。

## 十一、焦点、键盘、响应式与动效

1. 在“会话”页签中，主控行进入现有侧栏 roving focus 顺序，位于页签之后、普通会话之前；
   搜索不改变顺序。切换到“已归档”后主控行退出可见区域和焦点顺序。
2. 代理开关可由 Space 切换，提交期间保持焦点；成功后焦点不跳到 Conversation。
3. 来源标题和“打开来源会话”使用按钮语义；导航后浏览器式返回仍回到原会话和滚动位置。
4. clear 确认框遵循焦点圈定；关闭后焦点回到 Header 更多菜单按钮。
5. `/compact` 斜杠菜单兼容中文输入法组词；指令开始后关闭菜单，焦点保留在 Composer 区域。
6. `720px` 及更窄中栏中，Header 的“主控代理”操作可缩为保留文字的紧凑开关，不退化为无标签图标；
   身份标签可移到标题下一行，但不能隐藏代理状态。
7. 长 Session 标题、150% 缩放下优先省略标题和来源名称，不挤掉代理开关、更多菜单和输入框
   终止按钮。
8. 遵循 `prefers-reduced-motion`：状态变化使用颜色/文字替换，不依赖滑动或弹性动画；旋转加载图标
   可以降为静态图标加“压缩中”文字。

## 十二、错误与恢复文案

稳定错误码先转换为用户可操作的中文原因，技术 code 只在现有“技术详情”中显示：

| 场景 | 主文案 | 用户下一步 |
| --- | --- | --- |
| 主控不可用 | “主控暂不可用” | 检查运行时连接后重试 |
| 目标未开启代理 | “请先为目标会话开启主控代理” | 在目标 Session 开启，或让主控先切换状态 |
| 代理切换失败 | “未能更新主控代理状态” | 保留原状态后重试 |
| 主控投递时目标有 Queue | “目标会话仍有待执行输入，本次未投递” | 保持代理状态，等待队列排空后的最新报告 |
| Session busy clear | “会话正在运行，暂时不能清空” | 处理审批或等待任务结束 |
| compact busy | “会话正在运行，暂时不能压缩上下文” | 保留 `/compact`，空闲后重试 |
| compact 模型不可用 | “无法生成上下文摘要，历史未更改” | 检查模型设置后重试 |
| clear cleanup pending | “历史已清空，部分本地文件等待继续清理” | 可继续新对话；运行时恢复时收尾 |
| 来源 Session 不可用 | “来源会话不可用” | 仍可阅读已保存报告 |

错误不能用 Toast 作为唯一反馈。命令成功提示可短暂显示，但代理权威状态、压缩运行态、
cleanup pending 和需要用户处理的失败必须持续可见到状态变化或用户关闭。

## 十三、验收口径

1. 主控会话在“会话”页签中始终位于工作区列表上方的固定分区，不受工作区和搜索影响；
   “已归档”页签隐藏该分区，改标题后仍按 role 识别。
2. Controller 不显示代理、归档、删除或分叉入口；普通 Session 的代理开关提交明确终态且不乐观切换。
3. 有无 queued Input 都能立即切换代理状态，且不增加待生效状态；Queue 未排空时不接受主控投递、
   不生成中间报告，最后一项排空 Queue 后只报告最新结果。
4. 代理 Session 发送用户消息前有接管说明；成功接受后退出代理，失败保留草稿和代理状态，
   新输入因活动 Run 入队也不例外。
5. ControllerDelivery 和 ProxyReport 不伪装成用户消息，来源、终态和来源 Session 可辨认；报告卡
   没有自动继续控制按钮，也不展示 reasoning、工具详情、审批或原始 Provider 错误。
6. clear 只在空闲 Session 可用，确认框明确删除与保留范围；成功后按 Runtime 空快照重建，
   cleanup pending 不重新暴露旧历史。
7. `/compact` 精确识别且必须单独提交；busy 直接拒绝，手动压缩复用输入框终止按钮取消，自动压缩
   不提供独立取消；两者共用“正在压缩上下文”状态和 Context Summary 分割项。
8. SSE gap、重连和 Runtime 重启后，压缩状态以快照收敛，不留下永久“压缩中”，也不伪造取消结果。
9. automatic Queue 交接窗口只隐藏正在 dispatch 的队首，Drawer 可见性、条目和数量来自同一 selector，
   不使用计时器或动画延迟掩盖闪现。
10. 组件测试和 Playwright 覆盖鼠标、键盘、焦点返回、长标题、来源失效、空/错误状态、
   `720px` 及更窄宽度、100% / 125% / 150% 缩放、中文输入法和减少动态效果。
