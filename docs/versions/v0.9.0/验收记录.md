## 三、实际能力验收

- Runtime Host 默认使用 `~/.ez-assistant`，仍可通过绝对 `--runtime-home` 显式覆盖；
  可管理目录和普通配置文件在初始化/读取时收紧为当前用户私有权限。
- `assistant-runtime` 持有唯一配置源、不可变快照、串行 reload 和按 Run 编译权威状态；
  Host 只实现平台文件读取与具体 Provider Adapter 装配。
- 配置使用用户 `model key` 作为唯一稳定引用，`provider` 表示供应商，
  `protocol = "chat_completions"` 表示 wire 契约；Runtime 内部将 DeepSeek 绑定到其具名 Profile。
- Session 保存显式或默认 model key，并独立冻结 `SystemPromptSnapshot`；活动 Run 使用
  启动时冻结的模型规格，同 key reload 只影响后续 Run。
- 配置缺失、顶层失效和单模型失效均可安全查询；顶层失效会 fail-closed，
  单模型错误保留 `Degraded` 隔离语义，不回退旧 credential。
- 私有 Demo 提供模型选择、显式连接验证和真实请求费用提示；这些快捷键、
  状态与界面不构成桌面产品契约。

## 五、实际执行的验证

cargo fmt --all --check

结果全部通过。Workspace 测试为 **685 passed / 0 failed / 4 ignored**；ignored 项分别依赖真实
DeepSeek API、系统 `rg`、真实进程树清理和 Python loopback 环境，不是本版本阻断项。

### 5.2 Host 与依赖检查

```text
cargo clippy -p assistant-runtime-host --all-targets -- -D warnings
cargo test -p assistant-runtime-host
cargo tree -p assistant-runtime --depth 2
cargo tree -p assistant-protocol --depth 2
cargo tree -p assistant-runtime-host --depth 2
```

默认 feature Host 测试为 **26 passed / 0 failed**；默认与 all-features 严格 Clippy 均通过。
依赖检查证明 `assistant-runtime` 和 `assistant-protocol` 不依赖具体 Provider Adapter，
OpenAI-compatible Adapter 只由顶层 Host 装配。

### 5.3 真实 Provider 与跨进程链路

在用户明确确认凭据来源、可能费用和脱敏记录方式后，使用默认
`~/.ez-assistant` 与隔离的临时 Unix Socket 完成：

1. 显式验证 `deepseek-flash` 连接；
2. 按该 model key 创建 Session；
3. 同一 Session 两轮真实 Run 均结算为 `Completed`；
4. 第二轮以 `hello-v090` 参数执行 `echo_text`，工具与最终回复闭环完成；
5. Demo 和隔离 Host 均受控退出，socket、lock 和临时目录已清理。

记录未保留 API Key、认证 header、完整配置、完整 prompt 或 Provider 响应正文；
验收结束后核对无残留 Runtime Host 进程。
