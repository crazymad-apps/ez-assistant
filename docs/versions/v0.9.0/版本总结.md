## 三、形成的核心能力

- Runtime Host 默认使用用户可见的 `~/.ez-assistant`，保留绝对 `--runtime-home` 覆盖；
  初始化和读取阶段为可管理目录/普通配置文件收紧当前用户权限。
- `assistant-runtime` 持有唯一配置源、快照、reload 与按 Run 编译权威状态；
  Host 只负责平台读取和具体 Provider Adapter 装配。
- 模型以用户 model key 唯一引用；`provider` 表示供应商，`protocol` 表示
  Chat Completions wire 契约，Profile 与 Provider 在 Runtime 内部绑定。
- Session 保存 model key 并独立冻结 `SystemPromptSnapshot`；活动 Run 冻结启动时规格，
  reload 后的新配置只影响后续 Run。
- 配置失效保留 fail-closed 和单模型 `Degraded` 隔离语义；credential 不从环境变量、
  `.env` 或 CLI 读取，也不进入应用协议读响应、普通日志和调试输出。

## 四、偏差与边界

- Review 中将默认 Runtime Home 收敛为 `~/.ez-assistant`，并明确供应商、协议和内部
  Profile 的术语边界；功能设计、技术方案、模块文档和长期决策已同步。
- 桌面端配置 CRUD、Keychain、reasoning 展示和 Session 运行中切换模型未进入本版本。
- Linux、Windows 和第二家真实 OpenAI-compatible Provider 未实测，不作通过声明。
- 用户当前 `default_model` 没有对应已定义条目，Runtime 正确诊断为 `Degraded`；
  显式 `deepseek-flash` key 已通过真实联调，不代表 credential 失效。
