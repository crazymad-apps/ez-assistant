# v0.9.0 功能设计：Runtime Home、配置与模型装配

## 一、设计信息

- 版本：`v0.9.0`
- 状态：已确认（2026-08-06）
- 影响模块：`assistant-runtime`、`assistant-protocol`、`apps/runtime-host` 及模型装配链
- 需求来源：Runtime 阶段路线、`v0.8.0` 启动配置遗留与 2026-08-06 的版本范围讨论
- 关联技术方案：[`v0.9.0 技术方案`](技术方案.md)

输入池中的持久输入、排队、恢复和上下文压缩不进入本版本；本版本只建立
模型静态上限与现有 Agent 请求、执行配置的正确组合关系。本版本无正式页面变更，
不单独形成界面交互设计指导。

## 二、背景与目标

`v0.8.0` 已建立正式 Runtime、应用协议、独立 Host 和真实 Agent 执行闭环，但 Host
仍依赖启动参数与环境变量装配唯一 DeepSeek 模型；缺失 credential 时进程直接退出，
Runtime 无法独立提供配置查询和诊断，Session 也无法选择多条模型配置。

`v0.9.0` 的目标是形成第一个由正式 Runtime 持有的全局配置与模型装配闭环：

1. 建立当前用户私有、位置稳定的 Runtime Home 和可演进的配置文件。
2. 允许用户手工维护一个或多个模型，每条模型直接保存其 API Key。
3. Runtime 在没有有效模型时仍可启动，并提供脱敏查询、诊断和显式重载。
4. Session 稳定保存用户选择的模型 key，每个 Run 使用该 key 的当前配置并冻结本次
   执行规格；Session 的 System Prompt 仍独立冻结。
5. 按模型静态事实、Runtime 通信策略、Agent 请求默认值、Agent 执行限制和业务流程
   分维度管理配置。
6. 提供不创建 Session、Run 或 Conversation 的显式模型连接验证能力。
7. credential 不进入环境变量、应用协议读响应、日志、错误、事件或调试输出。

## 三、非目标

以下内容不进入 `v0.9.0`：

- 正式桌面模型管理页面、配置表单、错误引导和 reasoning 展示设置。
- Runtime 或应用协议内的模型创建、修改、删除、重命名、默认模型修改、配置写回、
  revision 和冲突合并；这些与桌面管理入口一起进入 `v0.14.0`。
- 从环境变量、`.env`、命令行、Keychain 或独立 Credential Store 读取 Provider API Key。
- 独立 credential 实体、跨模型引用、凭据去重和相同 API Key 检测。
- Session 中途切换模型；Runtime 能力进入 `v0.10.0`，正式桌面入口进入 `v0.14.0`。
- Session、Message、Run、配置历史或事件的数据库持久化。
- 自动监视配置文件、自动探测 Provider 模型列表或猜测模型上下文和输出上限。
- 用户自定义 Provider Codec/Profile、第二种模型协议或 Provider 插件系统。
- Plan/Build、Ask/Auto、正式文件/Shell、Workspace、审批、记忆和上下文压缩编排。
- 连接验证的正式 UI；本版本只供 Runtime/协议能力和私有验证入口。

## 四、功能范围与使用路径

### 4.1 Runtime Home 与手工配置

Runtime Home 是当前用户的 EZ Assistant 全局数据根目录，默认固定为
`~/.ez-assistant`；`~` 在 Host 启动时解析为当前用户主目录下的绝对路径，测试和开发可
显式覆盖。配置文件带有 schema version，是本版本的唯一配置事实源。

配置由用户手工维护，Runtime 只负责读取、静态校验、脱敏查询和显式重载，不写回、
修复或覆盖配置内容；程序初始化或读取时可以收紧敏感目录和文件的访问权限。外部修改只在
成功 reload 或 Runtime 重启后生效。

配置文件直接包含 API Key，因此必须被视为当前用户私有的敏感文件。Unix/macOS
下用户对目录可读写进入、对配置文件可读写；不允许其他用户访问。这不表示
文件只读，也不把 Runtime Home 宣称为操作系统沙箱。精确路径、文件形式和权限处理
由技术方案定义。

### 4.2 配置维度

每条模型由用户输入的 model key 唯一标识，不再建立额外内部 ID。模型配置保存完整
调用目标、直接属于该配置的 API Key、模型上下文窗口硬上限和模型单次输出硬上限。
不同模型可以填写同一 API Key，Runtime 不去重、不建立引用，也不做额外相同性校验。

本版本首期支持 Chat Completions 协议。每条模型配置保存实际供应商标识；Runtime 将已知
供应商绑定到对应的内部兼容 Profile，其他供应商使用标准兼容 Profile。Profile 不作为独立
用户配置字段。工具调用、reasoning 和 streaming 能力从 Adapter/Profile 推导，不让用户
重复配置布尔值。

其他配置按所有权拆分：

- 模型通信超时和建流前有限重试属于 Runtime 全局通信策略。
- generation 默认值属于 Agent 全局请求配置。
- 模型 Step 数与工具调用数属于 Agent 执行限制，不是模型上下文窗口。
- `tool_choice` 和是否启用 reasoning 属于 Run 的业务流程决策，不是静态模型字段。
- reasoning 是否展示属于未来桌面 UI，不改变模型请求。

模型单次输出硬上限与 Agent 请求值同时保留，实际生效值取两者较小值；Agent
未设置时使用模型上限。正常上限收敛不作为配置错误。各字段、默认值、数值约束与编译
规则统一放在技术方案。

### 4.3 配置生命周期

Runtime 启动不再以“已有可用模型”为前提。配置缺失、不可读、格式错误、版本不支持、
顶层无效或暂无可用默认模型时，Runtime 仍保留查询、诊断、reload 和受控关闭能力。
只有 Runtime Home 或本地通信入口本身无法安全建立时，Host 才在进入可诊断状态前退出。

配置加载和 reload 默认只做离线静态校验，不访问 Provider。顶层配置无法解释时采用
fail-closed：活动 Run 继续使用已冻结规格，全部新 Run 停止使用旧配置。只有单条模型语义
无效时，其他有效 model key 仍可用，无效 key 单独受阻。Runtime 不自动回退默认模型，
不保留旧 credential 供新 Run 静默继续使用。

### 4.4 Session 与 Run 绑定

创建 Session 时，客户端可显式选择 model key，未选择时使用当前默认模型。创建成功后：

- Session 在模型配置维度只保存 model key，不复制整条模型配置或 API Key。
- Session 在 System Prompt 维度保存创建时已经渲染完成的 `SystemPromptSnapshot`。
- 配置 reload、API Key 修改和后续 Run 都不重新渲染 System Prompt。
- `v0.9.0` 不允许修改既有 Session 的 model key。

每个 Run 开始前，Runtime 使用 Session 的 model key 解析当前有效配置，复用冻结的 System Prompt，
合并全局策略和本次业务流程决策，再冻结完整执行规格。具体规则是：

- 同 key 配置在 reload 后的新值对既有 Session 的下一个 Run 生效。
- 正在执行的 Run 不受 reload、模型删除或 API Key 修改影响。
- key 不存在或当前无效时，新 Run 在写入 UserMessage 前失败，不回退默认模型，也不使用
  上一次成功配置。
- Provider 拒绝 API Key 时，Run 以脱敏的结构化认证失败结算；正式错误引导留给桌面端版本。
- 同一 Run 的所有模型 Step 使用同一份冻结配置。

### 4.5 查询、诊断与连接验证

应用协议提供配置总体状态、模型列表、指定模型的脱敏详情与错误、显式 reload
和指定模型连接验证。查询可展示 model key、调用目标、静态上限、有效性与凭据是否
已配置，但不返回 API Key、认证 header、完整 TOML 或底层错误链。

连接验证只在客户端或开发者显式调用时执行，不在启动、reload、Session 创建或每个
Run 前自动访问 Provider。它使用不含用户会话、System Prompt、工具或文件内容的最小真实
模型请求，覆盖 endpoint、credential、model 和基本协议响应；不只依赖兼容性不稳定的
`/models` 端点。调用可能产生少量费用，未来客户端必须由用户手动触发并明确提示。

首次使用的完整路径为：

```text
启动 Runtime（允许暂无配置）
→ 用户在 Runtime Home 中手工编辑配置
→ 显式 reload 并查看脱敏诊断
→ 可选地显式验证模型连接
→ 使用显式或默认 model key 创建 Session
→ Run 开始前解析当前配置并冻结执行
```

## 五、模块边界与契约影响

- `assistant-runtime`：成为配置生命周期、模型目录、默认模型解析、安全诊断和 Run 前
  执行编译的权威业务层；不直接依赖具体 Provider Adapter。
- `apps/runtime-host`：解析 Runtime Home，提供本地配置读取和具体 OpenAI-compatible
  ModelService 装配；继续承载 Unix Socket、lock 和私有验证客户端，不保存第二份
  配置业务状态。
- `assistant-protocol`：承载用户输入的 model key、脱敏配置投影、查询、reload、连接验证
  和稳定错误；不承载配置写入、Provider SDK 类型或 credential。项目仍处早期阶段，直接
  更新当前协议契约，不划分协议代际或建立并行兼容层。
- Agent/Core：继续只消费已编译的冻结 `ExecutionSpec`，不读取应用配置、不处理默认值
  或按 Provider 分支。
- OpenAI-compatible Adapter：继续负责 Profile 能力、wire 字段和响应差异。DeepSeek
  按现有 thinking-enabled Profile 运行，只接受 `ToolChoice::Auto` 默认语义；其他供应商
  使用现有标准兼容 Profile，不强行启用 reasoning。

跨模块 trait、内部状态、应用协议 DTO、配置编译和具体 Profile 映射均在技术方案中定义。

## 六、关键取舍

### 6.1 人工配置优先于提前建设 CRUD

本版本先稳定配置读取、诊断和 Run 装配语义。没有正式桌面调用方时不提前建设写协议、
revision 和 TOML round-trip 编辑。

### 6.2 API Key 与模型放在一起

每条模型直接包含 API Key，不建立 credential 间接层。代价是配置文件和任何副本都属于
敏感数据；必须以用户私有权限、严格脱敏和禁止回传作为边界。

### 6.3 Session 分维度冻结，Run 冻结完整执行

Session 的模型选择保持稳定，但同 key 的 endpoint、model 或 API Key 修复可在下一 Run
生效；System Prompt 仍按 Session 冻结。单次 Run 内的完整调用目标和执行规格不变。

### 6.4 无有效模型也允许 Runtime 启动

配置管理和诊断必须先于模型可用性存在。可修复的模型配置问题不升级为整个产品进程
不可用。

### 6.5 配置按所有权分维度

模型静态事实、Runtime 通信策略、Agent 请求默认值、Agent 执行限制和业务流程分开
管理，最终只在 Run 前编译到现有下层契约。

## 七、验收标准

1. Runtime 默认使用 `~/.ez-assistant` 且允许显式覆盖 Runtime Home；程序自动将可管理的目录与普通配置
   文件权限收紧为只允许当前用户访问，无法安全处理时形成诊断或启动错误。
2. 配置缺失、不可读、格式错误、版本不支持、顶层无效和单模型无效都形成稳定、
   脱敏的可查询结果；模型配置问题不阻止 Runtime 进入诊断状态。
3. Runtime 不从环境变量、`.env` 或 CLI 读取 Provider API Key；不同模型可重复填写同一
   Key，不触发额外校验。
4. 模型以用户 model key 唯一标识，供应商身份与 Chat Completions 协议分别表达；DeepSeek
   绑定其具名兼容 Profile，其他供应商使用标准兼容 Profile，无需用户额外选择方言。
5. 模型上下文窗口、模型输出硬上限、Runtime 通信策略、Agent generation 与执行限制分维度
   生效；实际单轮输出上限始终取模型硬上限和 Agent 请求值的较小者。
6. Session 创建时保存显式或默认 model key，并独立冻结 `SystemPromptSnapshot`；
   reload 和后续 Run 不重新渲染 System Prompt。
7. 同 key reload 后，既有 Session 的下一 Run 使用新配置，活动 Run 使用原冻结规格。
   key 无效或顶层 reload 失败时，受影响的新 Run 在写入 UserMessage 前 fail-closed。
8. Runtime 提供配置状态、模型脱敏查询、显式 reload 和显式连接验证；连接验证不创建
   Session、Run 或 Conversation，并可按稳定类别返回失败。
9. API Key、认证 header、完整配置文本和 Provider 原始错误正文不进入应用协议读响应、
   事件、普通日志、错误或调试输出。
10. `tool_choice` 与 reasoning 启用由业务流程决定且受 Profile 约束，不作为静态模型字段；
    reasoning 展示不进入本版本。
11. 当前协议新增契约、serde round-trip、任意版本不匹配路径，以及 Runtime 的并发、取消、
    断线、受控关闭回归通过自动验证。
12. 自动测试不访问用户真实配置目录、不使用真实 credential、不访问真实 Provider；真实
    连接验证只在显式人工入口执行。

## 八、风险、兼容性与待确认项

### 8.1 风险与缓解

- **明文 API Key 文件**：配置和副本都是敏感数据。通过当前用户私有权限、禁止回传/日志、
  测试假值和泄漏检查降低风险，不宣称明文文件等价于 Keychain。
- **手工编辑破坏配置**：通过显式 reload、定位诊断、Runtime 可独立启动和新 Run fail-closed
  控制；Runtime 不自动修复用户文件。
- **同 key 变更影响既有 Session**：只在下一 Run 边界生效，活动 Run 保持冻结，诊断显示
  Session key 的当前可用性。
- **Provider 兼容差异**：首期只开放已有两种 Profile；静态校验与显式真实连接验证各自
  承担可验证的边界。

### 8.2 兼容性

- `v0.8.0` 的模型 CLI/环境变量属于初始化入口，不继续作为 `v0.9.0` 产品配置源；
  私有 Demo 客户端只保留本地连接所需参数。
- `v0.8.0` Session/Run 只存在于进程内，无数据迁移；但必须完整回归多 Session 并发、
  同 Session 串行、取消、断线和受控关闭。
- 实现时需同步修订 `agent-system.md`、`assistant-runtime.md`、`runtime-host.md`、
  `assistant-protocol.md`、受影响的 Agent SDK 导读与敏感配置规范。
- macOS-first Unix Socket 继续使用；其他平台的 Runtime Home 与 transport 不在本版本作验收
  通过声明。

### 8.3 待确认项

功能范围、使用路径和关键取舍已收敛，没有阻止确认功能设计的产品问题。配置字段、
文件权限异常策略、内部状态、协议 DTO、装配边界、连接验证请求和依赖变化统一由
关联技术方案承接。
