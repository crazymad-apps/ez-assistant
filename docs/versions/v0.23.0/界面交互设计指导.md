# v0.23.0 界面交互设计指导：MCP 管理与使用入口

## 一、设计信息

- 版本：`v0.23.0`
- 状态：已确认（2026-09-02）
- 影响模块：`apps/desktop`
- 关联设计：
  - [`v0.23.0 功能设计`](功能设计.md)；
  - [`v0.23.0 技术方案`](技术方案.md)；
  - [`Desktop 设计语言`](../../resources/桌面端设计语言.md)；
  - [`desktop 模块约束`](../../modules/desktop.md)；
  - [`前端编程规范`](../../specs/前端编程规范.md)。
- 设计基线：复用现有宽设置弹窗、一级导航、`SettingsPageContainer`、二级详情页、产品 Dialog、
  Switch、设置消息区和脏表单离开确认；不新增独立窗口、全屏路由或另一套管理壳层。

> 本文固定 MCP 管理页、导入、测试、配置生效反馈及 `/mcp` 使用入口的交互口径。Runtime 状态、
> 配置写入和连接结果始终以正式协议返回为准，Desktop 不直接访问 `mcp.json` 或 MCP Server。

## 二、页面入口与信息架构

### 2.1 设置导航

- 现有“设置”左侧一级导航在“技能”之后增加“MCP”，图标使用用户提供的拼图式 plugin SVG，随界面继承颜色；不把
  MCP 放进“运行时”或“模型”二级表单。
- 一级页标题固定为“MCP”，列表页及新增/编辑详情页均不显示副标题。配置作用域只在业务文档与必要的
  影响提示中表达，不在导航、页标题、按钮或状态前重复“全局”。
- 打开页面时读取一次 Runtime 脱敏管理快照；切换到其他设置页后释放导入预览、测试结果和未提交
  secret 草稿。存在未保存详情表单时复用设置弹窗现有离开确认。
- 当前版本没有 Workspace/项目级来源切换器。以后增加 `.mcp.json` 时再引入来源筛选，不提前展示
  无效的“全局/项目”控件。

### 2.2 页面层级

```text
设置 / MCP
  ├─ Server 列表
  ├─ 新增 Server（二级页）
  ├─ Server 详情与编辑（二级页）
  └─ 导入 MCP 配置（Dialog）
```

连接测试在新增或编辑二级页内就地完成；删除使用确认 Dialog；配置刷新不创建新的设置层级。

## 三、Server 列表页

### 3.1 页头与配置读取

- 页头右侧只放“导入配置”和主操作“添加服务”，避免三个同权按钮挤占标题。
- 读取动作由列表右上角紧凑刷新图标提供，Tooltip 为“重新读取配置”；它只重新取管理快照，不连接
  Server，也不等同 `/mcp refresh`。按钮与输入框均使用默认 32px 总高度（包含边框），按钮等宽高，图标水平、垂直居中。
- 设置页不显示刷新队列状态条，不提供“加入刷新队列”或“查看队列”；配置待应用只保留行内状态。
- 工具说明超过建议长度时使用 Warning soft 信息区与“警告”前缀，不能用失败色或把连接标为失败。

### 3.2 列表行

列表使用连续行而非独立大卡片。每行从左到右包括：

1. Runtime 状态点；
2. display name、Server key 和一行 description；
3. transport 与当前 tool 数；
4. 进入详情的 Chevron（属于行主体）；
5. 独立的配置启停 Switch。

- 主名称单行，description 最多一行省略；没有 description 时显示“未配置业务范围”。
- Server key 使用弱化等宽文字。display name 重复时不隐藏 key。
- transport 固定显示“本地 stdio”或“Streamable HTTP”，不在普通列表暴露完整命令、路径或 URL。
- tool 数只表示活动 Registry 当前目录；尚未刷新时可以显示旧数量，同时附“配置待刷新”，不能把
  配置状态误画成已生效。
- 整行主体进入详情；Switch 是独立命中区，不因点击启停同时打开详情。
- 技能列表以此为视觉基准，复用设置内的列表排版：行上下留白 8px、主体留白 8px/6px，名称 14px，
  描述和辅助信息 12px，文字层间距 4px；状态点、Chevron 与独立 Switch 对齐，悬停背景和键盘焦点一致。
  技能仍展示自己的来源、调用资格和健康状态，保留工作区范围、诊断与详情功能，不复制 MCP 的业务字段。

### 3.3 状态语言

| 状态 | 表现 | 文案 |
| --- | --- | --- |
| 已连接且有 Tools | Success 点 | `已连接 · N 个工具` |
| 已连接但无 Tools | 中性点 | `已连接 · 无工具` |
| 配置已禁用且 Runtime 未连接 | Muted 点 | `已禁用` |
| 配置与 Runtime 不一致 | Warning 点 | `配置待刷新` |
| 从未连接成功 | Danger 点 | `连接失败`，详情中查看稳定诊断 |
| Runtime 已断开 | Muted 点 | `运行时不可用` |

状态不能只依赖颜色；状态点旁必须存在文字或可访问名称。底层异常、stderr 和响应正文不进入 Tooltip。

### 3.4 空状态与不可用

- 没有 Server 时显示紧凑空状态：“还没有 MCP 服务”，提供“添加服务”和“导入配置”。
- Runtime 版本不支持 `mcp_management` 时显示持续错误与“重启升级运行时”，不渲染可写假表单。
- 管理快照读取失败时保留最近一次列表为只读并标记过期；没有旧数据时显示就地重试，不关闭整个设置。

## 四、新增与编辑二级页

### 4.1 基本结构

- 使用设置二级页统一返回按钮。新增标题为“添加 MCP 服务”，编辑标题使用 display name；不加副标题，
  Server key 保留在基本信息字段中。
- 表单分为“基本信息”“连接方式”“环境与请求头”“高级设置”四块。只有存在真实字段的块才渲染，
  不为分组套多层卡片。
- 页面底部操作顺序为“测试连接”“取消”“保存”；保存是唯一主按钮。已有服务的“删除服务…”放在
  Header 右侧扩展操作区，复用删除样式；新增页不显示，测试或保存期间禁用，底部不重复放置。

### 4.2 基本信息

- Server key 创建时必填，按稳定身份规则就地校验。保存后不可直接修改；说明文字为“用于工具身份和
  权限规则，创建后不可修改”。不提供看似普通、实际会重建身份的重命名输入。
- display name 可选，缺省实时预览为 Server key；description 可选但建议填写，说明它用于模型选择
  业务范围，不接受 Server 返回内容自动覆盖。
- “启用此服务”控制配置中的 `enabled`，不承诺保存后立即连接。

### 4.3 连接方式

- 使用 Radio 在“本地 stdio”和“Streamable HTTP”中二选一。
- stdio 字段为 command、args、cwd；command 单行，args 使用可增删的有序行，cwd 使用单行路径输入，
  不调用任意目录读取或自动探测可执行文件。
- HTTP 字段为 URL。非 loopback HTTP、userinfo、fragment 或旧 SSE 地址在输入下方就地报错。
- 连接字段的“保持原值／替换／移除”统一使用通用 `SelectionPopover` 的表单变体，与输入框等高，
  不使用原生 select；启动命令和 URL 不提供移除，工作目录允许移除。
- Desktop 单行控件统一采用 small 24px、默认 32px、large 40px 高度 Token，所有 padding/border 都计入
  总高度；设置表单默认 32px，业务页面不得另加几像素。复合可编辑选择框按外框计算，内部填满内容区。
- 通用选择浮层的纯文字单行选项最小高度为 32px；带图标或辅助说明的选项保留 46px 最小高度并按
  内容撑开。密度由公共组件根据选项内容统一决定，不在 MCP 或其他页面分别覆盖选项样式。
- 编辑已有 Server 时切换 transport 会清空另一 transport 的当前草稿；若另一侧已有值，先使用产品
  Dialog 说明将清除哪些字段，取消后保持原 transport 和焦点。

### 4.4 env、headers 与已有 secret

- stdio 显示 env 键值行，HTTP 显示 header 键值行；键和值分别输入，支持添加、移除和 `${VAR}` 引用。
- Runtime 快照只返回既有键名。已有值显示不可复制的“已配置，留空保持”占位；用户未编辑时发送
  Keep，输入新值时发送 Replace，点击明确移除时发送 Remove。
- 不提供“显示已有 secret”、复制已有值或把脱敏占位写回的动作。用户刚在当前草稿输入的新值可用
  普通密码输入显隐按钮检查，但关闭页面后立即丢弃。
- URL query、args 或其他被 Runtime 判定为潜在敏感且未回显的字段同样使用“保持/替换”语义，不能
  因页面重开而用空数组覆盖。

### 4.5 高级设置

- 高级设置默认收起，只包含 Server 级连接超时和工具调用超时；输入为空表示使用全局默认值。
- 工具超时填写后覆盖全局默认，可延长或缩短，不设 10 分钟等业务上限；只接受正的安全整数毫秒值。
  清空恢复继承，零不表示无限等待。连接超时仍只能收紧到 Runtime 连接上限内。
  并发、消息大小、Schema 上限等安全硬限制不提供 UI 开关。

### 4.6 保存

- 保存前进行一次本地基础校验，但 Runtime 仍执行权威规范化、字段校验和 expected revision 检查。
- 保存成功返回列表并保持该行可见，行内显示“配置待刷新”；不显示全局状态条、不自动连接或弹 Toast。
- 保存失败停留原页、保留全部草稿并聚焦首个错误。revision conflict 显示“配置已被其他窗口修改”，
  提供“重新载入”与“复制当前草稿”，不自动覆盖或静默合并 secret。

## 五、批量导入

### 5.1 输入

- “导入配置”打开宽 Dialog，标题为“导入 MCP 配置”，正文使用等宽多行输入，支持完整
  `{ "mcpServers": { ... } }` 和裸 Server map。
- Dialog 打开后焦点进入输入区；提供最小占位示例，不自动读取剪贴板或扫描其他 Agent 配置文件。
- “预览导入”先发送 Runtime 解析请求，不持久化。无效 JSON 或字段冲突在输入区下方显示，保留原文、
  Selection 和滚动位置。

### 5.2 预览与冲突

- 预览按 Server 行显示名称、transport 和结果：新增、同名冲突、警告。
- 同名冲突默认选择“跳过”；用户必须逐项切换为“替换”才能覆盖。提供“全部跳过”，不提供默认危险的
  “全部替换”。
- 未知扩展字段显示“将保留但本版本不使用”；旧 SSE、同时包含 command/url、非法 key 或字段类型
  错误属于阻塞错误，不能通过警告继续。
- 点击“导入 N 个服务”后一次提交整批。任一条目或 revision 校验失败时整批不写入；成功后关闭 Dialog、
  返回列表，待应用的配置使用行内状态表示。

## 六、连接测试

- “测试连接”使用当前未保存草稿，明确文案为“测试不会保存或应用配置”；目录和 Schema 校验与实际
  刷新一致。
- 测试前表单持续显示即将启动的 command 或连接 URL；secret 仍只显示用户本次新输入或“已配置”状态，
  不在测试确认区复制一份。
- 测试状态在按钮上使用小型 spinner，正文固定一行“正在连接并读取工具目录…”。取消页面或关闭设置
  会取消测试并关闭临时候选连接。
- 成功结果显示 transport、握手耗时和 tool 数；零 Tool 显示成功的“已连接，但没有工具”，不能标红。
- 长说明警告单独显示 Tool、字段、实际大小和建议阈值，仍显示测试成功及完整 tool 数，不禁用保存。
- 失败只显示稳定阶段：启动、连接、授权、协议、工具目录、Schema 或超限，并提供针对性短建议。
- 测试不展示完整工具 Schema、Server stderr、HTTP body 或 credential；不创建审批、Run、Conversation
  消息或活动 Registry 状态。

## 七、启停、删除与刷新关系

### 7.1 启停

- 列表 Switch 直接可靠写入用户级配置，pending 时只禁用该行。成功后显示配置状态和待刷新提示；失败时
  恢复 Runtime 返回的权威值并显示就地错误。
- 禁用不立即终止正在使用的连接；执行刷新后 Runtime 才 retire。文案不得显示“已断开”直到 Registry
  确认。

### 7.2 删除

- 删除确认标题为“删除 MCP 服务？”，正文显示 display name 与 Server key，并明确：服务将从本机用户
  配置中删除，不删除外部数据或安装包；当前连接将在刷新后关闭。
- 确认按钮使用“删除服务”，Danger 样式。删除成功返回列表；失败保留详情页。
- 删除配置不自动删除既有权限规则、Conversation 工具历史或审计记录；确认文案不承诺清理这些事实。

### 7.3 应用配置

- 设置保存与 Runtime 应用是两个清楚阶段：保存负责 `mcp.json`，刷新 Command 负责连接与目录。
- Composer `/mcp refresh` 产生结构化 Command。存在活动 Run、审批或前置消息时，它作为普通可见
  队列项等待；设置页不提供刷新队列入口、旁路或“立即应用”。
- refresh 完成且设置页仍打开时，Desktop 根据控制结果或失效事件重新读取管理快照；部分失败继续显示
  对应 Server 的旧 Runtime 状态和安全诊断。

## 八、`/mcp` 与 Composer

- `/mcp` 仍是本次输入的 Server 选择器，不跳转设置页，也不修改用户级配置。选择器空状态提供
  “前往 MCP 设置”，打开同一个设置弹窗并定位“MCP”页。
- `/mcp refresh` 仍转换为结构化 Command；设置页不提供刷新 Command 入口。
- Conversation 中 MCP 控制结果的展开正文左侧使用 1px 中性竖线，对齐标题图标中心；正文保持与标题
  文字左对齐。空结果、多服务和错误说明共用这条归属线，收起时随正文隐藏，不改变展开与滚动行为。
- Composer 顺序固定为“附件与引用 → Goal/Skill/MCP 标签 → 文本输入框 → 工具栏”；MCP 标签只包含
  display name，重名或 Tooltip 中补充 Server key。

## 九、键盘、焦点与响应式

- 设置导航、列表主体、Switch、返回、导入和表单操作均进入稳定 Tab 顺序；行主体使用 Button 或 Link
  语义，不能在可点击 `div` 中嵌套另一个 Button。
- Dialog 使用统一 focus trap；关闭后恢复到触发按钮。删除确认取消后恢复到“删除服务…”，导入取消
  后恢复到“导入配置”。
- 列表搜索、Radio、args/env/header 有可访问名称；错误通过 `aria-describedby` 关联字段，测试结果使用
  `aria-live="polite"`，失败不抢焦点。
- 设置内容区宽度不足时列表元信息换到第二行，Switch 与 Chevron 保持右侧稳定命中；不引入水平滚动。
- 所有过渡使用既有 `100–120ms` Token，并遵循 `prefers-reduced-motion`。

## 十、视觉与安全验收

1. “MCP”是现有设置弹窗的一级页，列表、二级详情和 Dialog 没有另起视觉体系。
2. 空列表、读取中、读取失败、Runtime 不兼容、已连接、零 Tool、待刷新和连接失败均有持续可识别状态。
3. 标准 `mcpServers` 多条配置能一次预览；同名默认跳过，阻塞错误不会半批写入。
4. 新增与编辑可测试未保存 stdio/HTTP 草稿；测试不保存、不换入活动连接，退出后无遗留子进程。
5. 保存、启停和删除后活动连接不会在页面动作中被绕过队列修改；会话 `/mcp refresh` 在 Queue 中可见。
6. 已有 secret 只显示键名与配置状态，Keep/Replace/Remove 不会互相误用；协议响应、DOM、错误和 Tooltip
   不包含既有值。
7. 删除 Dialog 明确配置、连接、外部数据、权限与历史记录各自影响范围。
8. 键盘可以完成列表进入、transport 选择、字段编辑、导入预览、冲突选择、测试、保存和取消；焦点恢复
   与脏表单离开确认符合现有设置行为。
9. `/mcp` 选择、`/mcp refresh` 与设置页配置职责清楚，用户不会把“已保存”误解成“已连接”。
