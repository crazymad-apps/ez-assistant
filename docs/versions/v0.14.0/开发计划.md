# v0.14.0 开发计划：正式主会话闭环

## 一、计划信息与设计依据

- 版本：`v0.14.0`
- 状态：已完成并归档
- 当前阶段：用户已确认最终验收（2026-08-14）
- 统一功能范围：[`功能设计`](功能设计.md)
- 统一实现依据：[`技术方案`](技术方案.md)
- 视觉依据：[`桌面端设计语言`](../../resources/桌面端设计语言.md)与已确认亮色 Demo
- 后续实施计划：[`v0.14.1`](../v0.14.1/开发计划.md)、[`v0.14.2`](../../design/v0.14.2-开发计划.md)
- 版本状态：[`docs/版本管理.md`](../../版本管理.md)
- 实施记录：[`开发进度`](开发进度.md)

统一功能设计和技术方案覆盖 `v0.14.0`–`v0.14.2`，不按补丁版本复制。本计划只负责第一个
可交付闭环：让正式 Tauri Desktop 能可靠启动或连接 Runtime，以真实产品快照展示 Workspace、
Session 和主 Conversation，提交输入、观察流式执行、管理队列并处理审批。

会话的完整资源管理、子 Agent 二级视图进入 `v0.14.1`；模型/权限设置、完整原生生命周期和
发布级收口进入 `v0.14.2`。本计划不重复协议字段、并发算法、页面尺寸或组件内部状态，细节以
统一技术方案为准。

## 二、版本切片与推进原则

### 2.1 连续版本边界

| 版本 | 可独立回证的能力 | 不提前实现的后续范围 |
| --- | --- | --- |
| `v0.14.0` | 正式主会话读取、提交、流式执行、队列和审批闭环 | 完整会话资源管理、子 Agent 视图、设置和发布收口 |
| `v0.14.1` | 会话/Workspace/文件资源与子 Agent 观察闭环 | 模型/权限编辑、完整窗口与托盘生命周期 |
| `v0.14.2` | 设置、原生生命周期、安全、性能和目标平台发布闭环 | Windows 正式支持及统一设计列明的其他非目标 |

### 2.2 台账原则

1. M0 至 M4 顺序推进；每个里程碑实现和验证完成后标记 `🟨 待确认`，获得用户明确确认后
   才标记 `✅ 已完成`并进入下一里程碑。
2. M0 先锁定依赖与现有协议的单一类型源；M1 才实现 Runtime/Host 权威投影；Desktop 不以
   Mock Store 抢跑业务页面。
3. M2 先让 React 外壳消费真实 Application/Session 快照；M3 才接主 Conversation；M4 才开放
   会产生业务变化的输入、队列和审批操作。
4. Web Demo 的主、子私有 Conversation 接口分别在对应产品投影和替代测试具备后删除；本版本先
   完成主投影替代，整个 Web Demo 在 `v0.14.1` 子投影切换后立即退役。
5. 新依赖在 M0 锁定具体版本并核对许可证、Rust/MSRV、目标 WebView 和 bundle 影响；不得在后续
   里程碑静默更换核心依赖。
6. 所有测试使用临时 Runtime Home、SQLite、Workspace 和 loopback Host，不触碰用户真实业务数据。
7. Windows 仅检查平台边界没有侵入 Protocol/Runtime，不设置编译、打包或实机门槛。
8. 不主动执行 Git 暂存、提交或推送。
9. `v0.14.0` 归档时统一功能设计和技术方案随其进入 `docs/versions/v0.14.0/`；同时把
   `v0.14.1`、`v0.14.2` 计划中的依据链接改到该归档，不复制新的功能设计或技术方案。

## 四、里程碑台账

### M0：依赖基线、产品协议增量与生成类型

- 前置：统一功能设计、技术方案和本计划均已确认；`docs/版本管理.md` 已进入 `开发中`。
- 目标：先形成跨 Rust、HTTP 和 TypeScript 的稳定产品契约及可重复前端工程基线。
- 交付范围：
  - 锁定 React、MobX、Sass、Streamdown 及插件、Vitest、Testing Library、Playwright、`ts-rs`
    和所需 Tauri 插件版本；补齐 Desktop 的 lint/test/test:e2e/build 脚本；
  - 在现有协议中增加当前主会话闭环所需的 event envelope、observed snapshot、Application/Session
    组合投影、Conversation Page、Tool Detail、Usage、Queue 和 Approval DTO；
  - 新增当前闭环的查询/mutation Request/Result 形状、结构化错误和 capability；对应
    `RuntimeCommand`/`RuntimeCommandResult` variant 与 M1 权威实现一起启用，避免出现 Host 可路由但
    Runtime 尚无实现的死命令；启用后继续保持 tagged enum 一一对应；
  - 生成并提交只读 TypeScript binding，增加重新生成后 diff 门禁；
  - 核对 additive schema patch，不在本里程碑实现页面或 Runtime 业务逻辑。
- 验证入口：

  ```bash
  cargo test -p assistant-protocol --all-features
  cargo clippy -p assistant-protocol --all-targets --all-features -- -D warnings
  cargo fmt --all --check

  cd apps/desktop
  npm run lint
  npm run test
  npm run build
  ```

- 完成判定：协议 wire fixture、TS 生成 diff 和旧可选字段兼容均通过；生成类型没有凭据字段；
  依赖和脚本可在干净环境重复安装与执行。
- Review 重点：Protocol 是否混入页面状态、Tauri 或 Runtime 私有类型；凭据是否进入安全投影；
  是否一次性引入未在统一技术方案确认的组件库或样式体系。
- 技术依据：技术方案 3.2–3.4、5.5、18.1、19.1 和风险 7。

### M1：Runtime/Host 观察快照与主会话产品投影

- 前置：M0 已确认。
- 目标：让正式 Host 提供不会因 SSE 丢失而失真的主会话产品查询和执行控制基础。
- 交付范围：
  - `ObservationCoordinator`、严格递增事件 envelope、组合快照水位、gap 与 instance 换代恢复；
  - `GetApplicationSnapshot`、`GetSessionView`、Conversation 分页/Run 定位、Tool Detail 和主
    Session Usage 安全投影；
  - 主消息多 step 分组、活动 Run 观察层与可靠历史的服务端归属；
  - Queue/Approval 有序快照、修订和本版本所需 prioritize/interrupt/resume/reject-and-stop mutation；
  - Store Worker 的 additive migration、Conversation 懒索引和有界缓存；
  - Host `/commands`、SSE 与必要资源路由的薄适配、鉴权和上限。
- 验证入口：

  ```bash
  cargo test -p assistant-protocol -p assistant-runtime -p assistant-runtime-host --all-features
  cargo clippy -p assistant-protocol -p assistant-runtime -p assistant-runtime-host --all-targets --all-features -- -D warnings
  cargo fmt --all --check
  ```

- 完成判定：重复、乱序、跳号、lag、断线和实例更换都能以快照恢复；分页锚点、旧消息缺字段、
  Queue/Approval 竞态与旧 schema additive migration 有自动证据；HTTP handler 不拼业务状态。
- Review 重点：快照是否可能漏掉已提交 mutation；SSE 是否被误作权威存储；Store I/O 是否被
  长锁包围；主 Usage 是否错误聚合子任务。
- 技术依据：技术方案第五、6.1–6.5、8.2–8.3、第九、15.1–15.2 和第十六节。

### M2：Tauri Runtime bootstrap 与 React 产品外壳

- 前置：M1 已确认。
- 目标：用真实 Runtime 快照替换当前连通性页面，形成可恢复的正式桌面外壳和会话导航。
- 交付范围：
  - Tauri Rust 的 discovery 校验、Runtime Host 启动收敛、bootstrap 和 Runtime Client 凭据边界；
  - React Root、Error Boundary、MobX Root Store、`RuntimeProjectionStore`、`LiveExecutionStore`
    与显式 dispose 生命周期；
  - Sass Token、reset、AppShell、顶部连接状态、左右栏/专注模式和本机展示偏好；
  - Workspace 分组、Session 单行列表、展开/收起、搜索入口、新建和切换会话；
  - 首次连接、启动中、重连、断开、随包组件 capability 缺失和配置无效的稳定页面状态；
  - 当前目标平台的基础窗口布局和窄窗口响应式行为，不提前实现完整托盘/退出矩阵。
- 验证入口：

  ```bash
  cargo test -p ez-assistant-desktop -p assistant-runtime-host --all-features
  cargo clippy -p ez-assistant-desktop -p assistant-runtime-host --all-targets --all-features -- -D warnings

  cd apps/desktop
  npm run lint
  npm run test
  npm run test:e2e
  npm run build
  npm run tauri -- build --no-bundle
  ```

- 完成判定：Desktop 能启动或连接临时正式 Host，展示真实 Workspace/Session，断线后禁止 mutation
  并在重连后恢复快照；Runtime token 不进入 observable、日志、URL 或持久化存储。
- Review 重点：是否存在全局可变 Store 单例、深层 observable 大对象、未释放 reaction/SSE，或
  在 WebView 读取 discovery/Runtime Home 的越权路径。
- 技术依据：技术方案第三、第四、5.1–5.4、14.2–14.3、17.1 和 18.4–18.5。

### M3：主消息列表、流式内容与主投影替代

- 前置：M2 已确认。
- 目标：以正式产品投影完整呈现主 Conversation，并移除主会话历史验证私有传输接口。
- 交付范围：
  - Conversation 最近页、向上分页、视觉锚点、Run 定位和稳定 message/part key；
  - 用户/助手消息、Reasoning disclosure、工具单行事件与详情、消息反馈/折叠基础操作；
  - Streamdown 流式/静态模式、Code/Math/Mermaid 按需增强、安全链接与失败回退；
  - rAF 批量 delta 合并、终态回收临时流投影、主 Session Usage 与上下文环图；
  - 按 Demo/设计语言完成消息区、Header、底部工作区宽度基准和低干扰状态；
  - Desktop 和正式 Host 测试停止使用主 Conversation 私有整份快照；保留仍被子 Conversation
    历史验证使用的 Demo 接缝，待 `v0.14.1` 子投影完成后整体删除，不新增兼容调用方。
- 验证入口：

  ```bash
  cargo test -p assistant-protocol -p assistant-runtime -p assistant-runtime-host --all-features

  cd apps/desktop
  npm run lint
  npm run test
  npm run build
  ```

- 完成判定：主消息能从可靠快照和流增量一致重建；历史大 Conversation 可分页定位；未闭合
  Markdown 和插件失败安全降级；正式 Desktop 不再请求主 Conversation 私有整份快照。
- Review 重点：是否在每 token 重渲染整棵列表；Markdown 是否获得任意 HTML/URL 能力；删除 Demo
  是否误删 Runtime 内部规范 Conversation 或降低正式 Host 测试覆盖。
- 技术依据：技术方案第六、14.1、18.2–18.5、19.1–19.3。

### M4：Composer、队列、审批与主会话端到端回证

- 前置：M3 已确认。
- 目标：完成从用户输入到真实 Agent 执行、排队、手动中断、恢复和审批决策的主会话闭环。
- 交付范围：
  - 两行起始、自增高、Enter/Shift+Enter、附件入口占位边界和可靠输入提交；
  - Slash Command、模型/Build-Plan/Ask-Auto 共用上拉选择器及键盘滚动；
  - 队列二级抽屉、行级优先/移除、自动串行、用户中断后的暂停与指定恢复；
  - 主/子 Agent 共用的 Session 审批队列和底部工作区，默认抢占、最小化、恢复详情、Radio 范围、
    拒绝与“拒绝并停止本轮”；本版本即使尚无子视图也必须正确标注 child 归属；
  - Workspace 首次注册和旧数据恢复时生成缺失的默认权限文件，使 Ask 下的 Workspace 结构化读写
    按变体直接执行；保留既有权限文件，Shell 与 Workspace 外访问继续审批；
  - mutation pending/失败/冲突反馈与权威快照纠正；
  - Playwright 连接临时正式 Host 的新建、提交、流式消息、排队、中断、审批和重连纵向场景。
- 验证入口：

  ```bash
  cargo fmt --all --check
  cargo clippy --workspace --all-targets --all-features -- -D warnings
  cargo test --workspace

  cd apps/desktop
  npm run lint
  npm run test
  npm run test:e2e
  npm run build
  npm run tauri -- build --no-bundle
  ```

- 完成判定：用户可在正式 Desktop 完成真实主 Agent 任务；同 Session 队列按规则自动串行；审批
  不重复、不越过队首，重连后与 Runtime 一致；生产 bundle 不包含 Mock/fixture 业务数据。
- Review 重点：Enter 重复提交、重试幂等、队列乐观状态、审批越队首、后台 Session 抢占当前工作区，
  以及模型/模式切换是否错误改写已接受输入。
- 技术依据：功能设计 F09–F14，技术方案第八–九、17.3 和 19.3。

## 五、版本级完成条件

| 验收方向 | 主要里程碑 |
| --- | --- |
| 产品协议增量、生成类型、观察水位和正式 Host 产品投影 | M0、M1 |

验收通过不代表统一桌面 MVP 全部完成；子 Conversation 替代和整个 Web Demo 退役由 `v0.14.1`
继续完成，其他能力按 `v0.14.1`、`v0.14.2` 计划推进。
