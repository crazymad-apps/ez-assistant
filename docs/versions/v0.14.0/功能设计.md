后续范围继续由 `v0.14.1`、`v0.14.2` 落实。

## 二、背景与问题

前续版本已经把 Agent 主循环、模型调用、工具、上下文、持久化 Session/Run、
Workspace、附件、Plan/Build、Ask/Auto、分层权限、正式审批和单层子 Agent 收敛到
独立 Runtime Host 中。当前正式桌面端仍主要承担连通性验证，用户不能通过一个
稳定的产品界面管理会话、发起任务、处理审批、观察子任务或管理模型。

桌面端 Demo 已经完成了信息架构、交互模式和亮色视觉的多轮评审，但它的数据、
切换按钮和反馈是模拟的。`v0.14.0` 需要把这些已确认的产品模式转化为正式桌面端
能力，并确保界面不持有 Runtime 业务状态的第二份权威副本。

## 三、版本目标

1. 建立可长期使用的正式桌面应用外壳，完成 Runtime 启动、连接、重连、停止和诊断闭环。
2. 让用户以 Workspace 为导航入口创建、切换、搜索、归档、恢复和管理 Session。
3. 完成真实消息列表、流式输出、Reasoning、工具事件、附件和详情查看。
4. 完成可靠输入、队列、中断、恢复、模式切换、权限切换和 Slash Command 交互。
5. 将主 Agent 与子 Agent 的审批统一到同一底部工作区，让阻塞原因和审批归属清晰可见。
6. 让用户能在主会话中观察子任务，并进入与主消息列表一致的子 Agent 消息视图。
7. 提供模型列表、新增、编辑、删除、默认模型、连接测试和配置冲突处理的正式入口。
8. 将已确认的桌面端设计语言用于所有空、加载、运行、阻塞、失败、中断和恢复状态。

## 四、非目标

以下内容不进入 `v0.14.0`：

- 后台自动化、定时任务、调度中心和历史补跑；Demo 中不保留相关占位。
- Pinned Memory、历史 Recall、Persona 和记忆管理页；右侧栏不显示无实际产品能力的
  “记忆已启用”或占位区块。
- Skills、MCP、插件安装、启停和连接管理；设置页不保留无效入口。
- 远程 Runtime、多用户、多设备同步、浏览器端和移动端。
- Windows 正式产品支持、安装包和实机或 CI 验收；本版本只要求协议与业务状态保持平台中立，
  并为后续 Host、Desktop 平台适配保留明确边界。
- 多层或递归子 Agent、独立子 Agent Session、向运行中子 Agent 追加用户输入。
- 子 Agent 独立的模型、预算、Workspace 或权限层级。
- 把 Workspace 表述或实现为阻止 Shell 越界的强沙盒。
- 通用 Artifact 管理、文件版本、Diff Review、Git 操作中心和并发文件冲突解决。
- 完整 Markdown 编辑器、富文本文档协作和通用文件编辑。
- 暗色主题、主题市场和用户可编程样式。本版本以已确认的亮色 Demo 为唯一样式验收基准。
- 在 PRD 中决定 React、组件库、CSS 组织、路由、状态容器或其他工程实现。

## 五、用户与核心场景

### 5.1 目标用户

首版面向在本机代码仓库、文档目录或其他工作目录中使用 Agent 的单用户。用户愿意
审查 Shell 和文件访问权限，并需要在同一桌面端中管理多个 Workspace 和多个并行 Session。

### 5.2 核心使用场景

1. 用户打开应用，桌面端连接 Runtime，在已登记 Workspace 中继续会话或新建会话。
2. 用户附加文件、选择 Build/Plan、Ask/Auto 和模型，提交任务并观察流式执行。
3. 当同一 Session 已在执行时，用户继续输入后续要求，输入进入可见队列并默认串行执行。
4. 工具需要授权时，审批面板自动占据底部工作区；用户查看完整内容和范围后决策。
5. 父 Agent 委派子任务时，用户查看连续的任务树，进入子 Agent 消息列表，并在主界面
   处理子 Agent 审批。
6. 用户在右侧上下文区查看模型、Token、窗口占用、Workspace、附件、运行记录和子任务。
7. 用户在设置中管理模型和权限，并处理 Runtime 断开、配置无效或连接失败。

## 六、产品原则与权威状态

1. **Runtime 权威**：Session、Run、队列、审批、子任务、模型配置和 Workspace 以 Runtime
   快照为准。界面只发送意图并展示事件，不因乐观切换就宣称操作已完成。
2. **快照恢复**：SSE 用于及时通知，不是唯一数据源。首次加载、重连、事件缺口和页面恢复都必须
   重新查询权威快照。
3. **意图幂等**：发送消息、审批、取消、恢复和其他可重试操作不得因断线重试重复追加
   消息或重复执行工具副作用。
4. **冻结事实**：Workspace 是 Session 的执行历史事实；已接受输入冻结 Agent 变体和审批模式。
   模型只允许在 Session 完全空闲且没有排队输入时切换，因此活动 Run 与既有队列不会被后续
   模型设置静默改写。
5. **不隐藏阻塞**：等待审批、断线、失败、中断和队列暂停必须保留持续入口，不只用 Toast。
6. **无死控件**：没有产品语义或 Runtime 支撑的按钮、下拉箭头、状态 Tag 和设置入口不进入正式界面。
7. **原位完成**：短操作使用菜单、选择器和就地编辑；需要连续阅读或表单输入时才进入弹窗。
8. **桌面边界**：关闭窗口、退出桌面客户端和停止 Runtime 是三个不同动作，不能互相暗示或代替。

## 七、功能范围

### F01 应用启动与 Runtime 连接

**用户目标**：打开桌面应用后能明确知道 Runtime 是否可用，并能处理启动或连接失败。

**界面与流程**：

- 应用启动后立即显示桌面外壳，顶部状态区呈现“启动中”、“已连接”、“重连中”、
  “已断开”或“停止中”。
- Runtime 未运行时，桌面端按正式产品启动流程拉起 Runtime Host；已运行时连接既有实例。
- 连接短暂中断时自动尝试重连，界面保留已加载内容但禁用会产生业务变更的操作。
- 连接失败不只弹 Toast；状态区提供“重新连接”和“查看详情”，详情进入 Runtime 设置页。

**业务规则**：

- 桌面端只连接本机正式 Runtime Host，不提供远程地址编辑。
- 重连后必须重新查询当前 Session、Run、队列、审批和子任务，不依赖断线期间丢失的事件。
- Runtime 进入 `shutting_down` 后拒绝新工作，界面只显示收敛进度和安全退出入口。

### F02 桌面外壳与布局

**用户目标**：在会话导航、执行主区和当前上下文之间稳定切换视线。

**界面与流程**：

- 主界面为顶部系统栏、左侧会话栏、中部消息区和右侧当前上下文栏。
- 左右边栏可独立收起；专注模式同时收起两侧；恢复布局回到上次非专注状态。
- 窗口缩小时先收缩边栏宽度，再将右栏转为可呼出面板；中部消息和输入区不得出现水平错位。
- 会话 Header 保持紧凑。无必要副标题；确实需要副标题时使用最小高度并随内容自动撑开。

**状态保留**：边栏开关、专注模式和窗口尺寸在本机保留，重启后恢复。

### F03 Workspace 分组与会话导航

**用户目标**：通过工作目录快速找到会话，不在“Workspace”和“最近会话”两套列表中重复寻找。

**界面与流程**：

- 左侧顶部提供“新对话”和搜索，下方为“会话 / 已归档”切换。
- 活动会话按 Workspace 分组；Workspace 和其内部列表均可展开、收起。
- Workspace 行显示目录名；会话行仅显示单行标题、可选固定图标和时间。运行中用加载环替代时间，
  不再添加状态圆点或状态文字。
- 会话列表使用内边距形成层级，列表宽度与 Workspace Header 一致，会话标题与父级文字对齐。
- 固定会话优先显示；固定图标紧跟标题，不挤占时间区。
- 不再设置独立“最近会话”分组。会话 Header 左侧的下拉箭头打开最近会话切换器。
- 搜索至少匹配会话标题和 Workspace 目录名；结果保留 Workspace 归属，选中后打开会话。

**Workspace 操作**：

- Workspace 行 Hover 或键盘聚焦时显示更多菜单：在此新建会话、打开工作目录、复制路径、
  从新会话选择中移除。
- 移除 Workspace 只影响新会话选择，不删除本机目录，不破坏历史 Session 的冻结绑定。
- 历史会话继续显示其已移除 Workspace，并允许 Runtime 支持的显式恢复。

### F04 新建会话

**用户目标**：选择工作目录和模型后快速进入可输入的新 Session。

**主流程**：

1. 用户点击“新对话”或 Workspace 下的“在此新建会话”。
2. 全局入口先显示最近 Workspace，并允许通过系统目录选择器登记新目录；Workspace 行入口
   直接冻结绑定该 Workspace。
3. 用户可使用默认模型，也可在创建前选择其他已配置模型。
4. Runtime 创建空 Session 后进入会话页，标题使用默认名称；首次提交后可由产品规则更新
   标题，但不覆盖用户手工命名。

**业务规则**：

- Session 创建后的 Workspace 是执行历史事实，不能把既有会话直接“移动”到其他已有 Workspace。
- 对从未提交输入的空 Session，可重新选择本机目录后替换该空会话。
- 已有历史的 Session 选择新目录时，产品应在新目录创建新会话，原会话及原 Workspace 绑定
  保持不变。

### F05 会话 Header 与会话操作

**用户目标**：在不离开会话的情况下完成命名、切换、固定、归档、导出和删除等常用操作。

**Header 结构**：

- 左侧淡色背景下拉箭头打开最近会话选择器，选中后替换中部当前会话。
- 中间是单行会话标题。点击标题进入简化的就地输入框，Enter 或失去焦点保存，Esc 取消。
- 标题输入框宽度随可用空间收缩，不挤压状态和右侧按钮组；不添加额外侧边装饰条。
- 标题后只显示必要的会话状态，不显示可由其他内容推断的副标题。

**更多菜单**：

- “固定会话”为带 Toggle 的菜单项，成功后改变左侧分组内排序。
- “重新选择工作目录”打开系统目录选择器，并遵循 F04 的空会话替换/历史会话新建规则。
- “归档会话”把会话移到已归档列表，已归档会话为只读，可显式恢复。
- “导出 Markdown”通过系统保存器导出用户/助手正文和工具摘要；默认不导出 Reasoning 正文、
  凭据、内部路径或工具完整原始输出。
- “删除会话”是危险项，打开确认弹窗。弹窗明确删除 Session 历史、Run、子任务和附件引用，
  但不删除 Workspace 内的用户文件。

**操作限制**：

- 活动 Run、非空队列或待审批时，归档、删除和 Workspace 变更入口禁用，菜单解释原因。
- 归档是可恢复操作，不使用危险色；删除不可恢复，使用危险色和对象明确的确认文案。

### F06 消息列表与流式执行

**用户目标**：按实际执行顺序阅读用户输入、Agent 正文、Reasoning 和工具活动。

**呈现规则**：

- 用户消息右对齐且使用紧凑浅色气泡；助手消息不使用头像或机器人图标，正文直接融入消息流。
- 用户和助手正文字号一致。消息列表与底部工作区使用同一内容宽度和水平内边距。
- 一个助手回合按事件顺序显示 `Reasoning → 正文 → 工具列表`，该组合可重复多次。
- 不显式渲染 Step 编号、“本步将做什么”或并不存在的摘要。
- 流式输出按 Runtime 事件逐段追加；页面刷新后从 Run 快照重建相同顺序。
- 助手正文支持 GFM、代码语法高亮、数学公式和 Mermaid 图表。代码和图表在未闭合或仍处于流式
  尾块时先稳定显示源码/占位，完整后再增强渲染，不能因高亮或绘图造成正文闪烁或输入卡顿。
- Mermaid 只把围栏内容作为图表描述渲染，不执行脚本、点击回调或外部资源；渲染失败时保留原始
  代码。公式或代码高亮失败同样降级为可复制文本，不阻断整条消息。

**助手消息操作**：

- 操作在助手消息左下统一排列：复制、赞同、不赞同、Fork、展开/收起和时间。
- 复制只复制当前助手正文，不复制 Reasoning 和工具原始输出。
- 赞同/不赞同是互斥状态，作为本地会话反馈保留；本版本不自动上传到外部服务。
- Fork 以该消息之前的可见会话事实创建新 Session，原 Session 不变；新 Session 继承原 Workspace、
  当时可恢复的冻结对话事实和当前可用模型，不重放已执行工具。
- 收起后保留一行浅色盒子，显示“已收起”以及 Reasoning 和工具数量；展开/收起按钮与 Fork 相邻。

**重新输入**：用户消息的“重新输入”将该条内容回填到输入框供用户修改，不直接
替换历史、不立即执行，不暗示 Undo，也不调用会删除目标消息及其后续历史的破坏性重入能力。

### F07 Reasoning 折叠盒

**用户目标**：默认低干扰地知道 Agent 正在思考，需要时查看完整的可见 Reasoning 内容。

- Header 只包含有色状态点、“思考过程”和折叠箭头，不包含摘要 Title 或“思考了多少秒”。
- 整体使用灰色系；执行中和完成只通过蓝色/绿色圆点区分，不使用显眼紫色背景。
- 点击 Header 在原位展开，不打开“摘要”弹窗。展开区设最大高度，超出后盒内自动滚动。
- Reasoning 不可用时不生成空盒子。历史数据只保留了摘要时，必须使用真实数据类型的文案，
  不冒充完整 Reasoning。

### F08 工具事件与详情

**用户目标**：在不打断正文阅读的前提下知道 Agent 做了什么，并在需要时查看输入、输出和安全范围。

**列表形态**：

- 工具活动作为消息流中的一行文字事件，字号与助手正文一致，不使用大型工具卡片。
- 一行包含状态点、动作名、目标或短结果、弱化元数据和“查看详情”。
- 完成标题用深绿，执行中用深蓝，普通元数据用深灰；不使用鲜蓝链接抢占正文注意力。
- 子 Agent 消息中的工具行与主 Agent 完全一致，也可点击。

**详情弹窗**：

- Header 显示工具名和状态；正文按“请求内容”、“执行范围”、“结果或错误”分区。
- Shell 必须展示完整命令、工作目录、超时和可用 stdout/stderr；文件工具必须展示操作和解析路径。
- 大输出使用弹窗内滚动和安全复制，不让弹窗超出窗口。
- Footer 不使用额外背景色或分隔线；只有存在实际动作时才显示 Footer。

### F09 输入框与提交

**用户目标**：以键盘为主快速输入，不因多行内容破坏页面稳定性。

- 输入区默认最小两行高，随文字行数自动变高，达到约八行后在输入区内滚动。
- Enter 直接发送，Shift+Enter 插入换行。输入法组合期间的 Enter 不触发发送。
- 发送按钮为 `30 × 30px`，宽高一致；发送中防止重复点击，失败时保留未被 Runtime 接受
  的输入和附件。
- 底部操作按钮和选择器使用紧凑尺寸；模型显示名在发送按钮左侧，字号比普通弱化说明稍大。
- 附件按钮打开系统文件选择器；已选附件在提交前可移除，上传、不可用和超限都有行级状态。
- 已归档 Session 不显示可编辑输入框，改为一行只读说明和“恢复会话”。

### F10 Slash Command 系统

**用户目标**：通过键盘快速进入常用选择和会话操作，不记忆完整指令也能发现。

**交互规则**：

- 在行首输入 `/` 打开指令面板；继续输入实时过滤名称、别名和简短说明。
- 面板浮动在输入框上方并与输入内容区对齐，不被队列二级抽屉遮挡。
- 上下键改变活动项时，列表必须同步滚动让活动项完整可见；Enter 选择，Esc 关闭。
- 选中需要二级选择的指令后，原位进入对应选择器，不把不完整命令作为普通消息发送。

**首版指令**：

| 指令 | 产品语义 |
| --- | --- |
| `/model` | 切换当前 Session 之后提交所使用的模型，与发送按钮左侧模型选择器复用同一数据和选择结果。 |
| `/mode` | 选择 Build 或 Plan，与底部模式选择器一致。 |
| `/approval` | 选择 Ask 或 Auto，与底部权限选择器一致。 |
| `/new` | 进入新建会话流程。 |
| `/help` | 打开指令列表及键盘说明，不发送给模型。 |

未识别的 `/xxx` 在用户明确按 Enter 后作为普通文本发送，界面不自行猜测指令。

### F11 模型、模式与审批模式选择器

**用户目标**：以一致的上拉交互切换下一次输入的执行环境。

- 模型、Build/Plan 和 Ask/Auto 使用同一类选择器，面板浮动在按钮上方并相对按钮居中。
- 模型项显示展示名、Provider、模型 ID 和上下文窗口；当前选中图标保持完整，不被边缘裁切。
- 上下键选择时活动项自动滚动入可见区；Enter 确认，Esc 关闭，点击外部关闭。
- 模型只允许在 Session 没有活动 Run、排队输入和待恢复输入时切换；非空闲状态下选择器禁用并说明原因。
  切换成功后成为该 Session 后续输入使用的模型。
- Build/Plan 和 Ask/Auto 在输入被 Runtime 接受时冻结到对应 Run；切换只影响之后接受的输入。
  切换失败时回到 Runtime 快照，不保留仅存于 UI 的假状态。
- Auto 对未命中规则的请求默认允许，但仍受显式 Deny、必须询问规则、Plan/Build 能力上限和
  Guardrail 约束，不等于获得不受限制的全权限。

### F12 上下文占比与模型用量

**用户目标**：不占用大面积即可判断当前会话的上下文压力，需要时查看精确数字。

- 输入区模型名左侧显示小型环状占比图，只表达大致上下文占用，不显示未配置的费用数据。
- Hover 或键盘聚焦显示居中 Tooltip，包含已用 Token、窗口上限、占比和最近一次更新时间。
- Runtime 无法提供上限或 usage 时显示中性空环，Tooltip 说明“暂无用量数据”，不用 `0%` 误导。
- 右侧会话区只显示主会话的累计 Token、上一轮输入/输出、缓存命中和上下文窗口占比，不包含
  子任务用量，也不在 UI 层计算父子合计。
- 每个子任务的 Usage 放在对应子任务卡片中；进入子 Agent 视图后仍只展示该子任务自身数据，
  不与主会话或其他子任务聚合。数据缺失时保持未知状态，不以 `0` 补齐。

### F13 待执行队列与运行控制

**用户目标**：在 Agent 执行时继续追加需求，了解后续顺序，并在手动中断后选择优先恢复的输入。

**界面与流程**：

- 当队列非空时，在输入框上方显示二级抽屉，它是用户输入的延伸，不在页面其他位置再创建重复列表。
- 抽屉可收起，Header 显示“待执行队列”和数量。展开后每行显示顺序、单行输入、时间、
  “优先执行/恢复”和移除。
- 抽屉底部必须保留完整内边距，不得被输入框边框遮住最后一行像素。
- 输入框不再设置单独的“执行队列”大按钮，行级动作负责优先级或恢复。

**执行规则**：

- 正常情况下，同一 Session 的已接受输入自动按顺序串行执行，不需要用户逐行启动。
- 只有用户手动中断当前轮次时，自动取出下一项才暂停。此时每行“恢复”可以选择任意待执行输入，
  从而支持乱序继续。
- 运行中点击某行“优先”只改变当前 Run 结束后的下一项，不并发修改主 Conversation。
- 移除只对尚未开始执行的输入有效，必须经 Runtime 确认后才从列表消失。
- 页面刷新或普通网络重连后从 Runtime 恢复队列和暂停状态。
- Runtime 进程重启后，即使队列在持久化状态中可恢复，也不得自动继续执行；界面必须显示
  “需要恢复”，由用户显式恢复后才重新进入串行调度。

### F14 审批阻塞与底部授权工作区

**用户目标**：不需要在消息流中寻找待授权项，并能在做决策前看到请求、范围和影响。

**单一来源、两种展示**：

- 消息列表保留一条“等待执行授权”工具事件，用于表达它在执行时序中的位置。
- 每个审批对应一个独立 Tool Call。新的审批事件进入所属 Session 的有序审批队列，不合并成
  “同批审批”，也不因同时到达而共享一个决策。
- 当前 Session 的审批队列从空变为非空时，队首审批默认抢占底部输入区作为审批工作区。
  后续审批只追加到队尾，不替换正在处理的审批，也不重复打开第二个面板。底部不再另外显示
  “阻塞列表”，避免与消息列表重复。
- 面板一次只展示一个队首审批，并显示剩余待审批数量和切换入口。当前项完成后自动切换到
  下一项，默认顺序以 Runtime 接收审批的先后为准。
- 点击消息中的“查看详情”打开或恢复同一底部审批工作区，不创建第二份审批状态。
- 用户可最小化审批区。最小化不解除阻塞；普通输入区可重新出现，但必须保留明确的
  “等待审批”和待处理数量恢复入口。面板已最小化时，后续入队事件不强制重新展开。
- 后台 Session 的新审批进入各自队列，并在会话列表中持续显示等待状态，但不得抢占当前导航
  或底部工作区；用户切换到该 Session 后，队首审批自动成为底部当前项。

**面板内容**：

- Header 显示盾牌图标、“允许执行 Shell 命令？”等具体问题、可选请求者和 Workspace 路径，
  右侧只保留最小化。
- “请求内容”和“授权范围”上下分区。Shell 命令使用单独深色代码行；长内容可滚动和复制。
- 授权范围按 Runtime 返回的 `available_decisions` 渲染成三行或更少的 Radio，每行包含名称和简短影响说明。
- 底部主要操作为“拒绝”和“允许执行”；另提供低频但可发现的“拒绝并停止本轮”。未选有效
  允许范围时不允许提交；提交中防止重复决策。

**范围规则**：

- 所有决策只能来自 Runtime 返回的 `available_decisions`。界面将允许类决策映射为 Radio 范围，
  将拒绝类决策映射为独立操作；不得在桌面端自行增加仅本次 Tool Call、当前 Session 或当前
  Workspace 等未获 Runtime 授权的选项。
- Global 允许不在临时审批中产生，只能手工维护并显式重载。
- 子 Agent 的审批使用同一面板，显示子任务名和“由子 Agent 请求”。子 Agent 不增加“当前子任务”
  持久权限层；主 Agent 与子 Agent 的审批按到达顺序进入父 Session 的同一队列，选择项仍以
  Runtime 有效决策为准。
- “拒绝”只拒绝当前 Tool Call，其他待审批项继续保留，Agent 可以在该调用失败后调整方案继续。
- “拒绝并停止本轮”拒绝当前 Tool Call，并由 Runtime 原子停止其所属 Run、关闭该 Run 的剩余
  待审批项；不得影响其他 Session 的 Run 或审批队列。
- 选择当前 Session 或当前 Workspace 的允许范围后，Runtime 必须使用更新后的权威规则重新核验
  队列中其他待审批项；只有精确命中新规则的请求可以自动通过，其余请求继续等待用户决策。
- 审批决策成功后才从队列移除。重复提交、已被其他客户端处理或所属 Run 已结束时，以 Runtime
  返回的最新队列快照纠正界面，不在桌面端推测结果。
- 审批在 Runtime 重启后失效时，面板关闭并说明相关 Run 已中断，不重用旧决策。

### F15 子任务树与子 Agent 消息列表

**用户目标**：了解父 Agent 委派了哪些任务、哪些已完成或阻塞，并查看单个子 Agent 的完整执行过程。

**主会话中的任务树**：

- 父 Agent 委派后，消息流中显示一行“子任务已委派”摘要，其下为连续分叉线条和子任务列表。
- 分叉主干和各项横向连线必须视觉相连；第一项、中间项和最后一项使用正确线段，不出现悬空短线。
- 任务树容器底部保留足够内边距，不紧贴后续子 Agent 列表或消息操作。
- 每个子任务显示状态点、标题、单行执行信息和该任务自身的紧凑 Usage；等待审批为由待处理审批
  派生的展示状态，不改写子任务基础生命周期。卡片不得展示前端计算的父子合计。
- 点击子任务进入子 Agent 消息列表，不打开只有摘要的普通详情弹窗。

**子 Agent 视图**：

- 子视图直接替换中部主消息列表，左右边栏和顶层会话归属不变；右侧“当前上下文”仍展示主会话，
  不随子任务切换为子任务 Usage。
- 顶部仅保留淡色背景返回箭头、子任务标题、标题右侧的“子 Agent”身份说明和状态。不使用
  “返回主会话”长文案，不再单独强调“主 Agent/可靠性 Agent”作为消息标题。
- 子 Agent 的用户任务、Reasoning、正文、工具行、时间和折叠方式与主消息列表一致。
- 子 Agent 工具行可点击进入 F08 工具详情；子 Agent 待审批行可恢复 F14 底部审批区。
- 子 Agent 视图展示当前子任务自身的 Usage；不混入主会话或兄弟任务用量。
- 子 Agent 只读，不提供独立输入框、归档、模型切换或继续对话。底部仍属于父 Session 工作区。
- 父 Run 活动时可单独取消未完成子任务；取消后保留终态记录，不从树中消失。

### F16 右侧“当前上下文”

**用户目标**：在不离开会话的情况下查看影响当前执行的主要事实和运行摘要。

**区块与信息**：

1. **会话**：状态、当前默认模型、Build/Plan、Ask/Auto，以及仅属于主会话的累计 Token、
   上一轮输入/输出、缓存命中和上下文窗口占比。
2. **Workspace**：用户目录、复制路径、打开目录和重新选择目录入口；说明文案明确 Shell 仍以
   当前用户权限运行，Workspace 不是强沙盒。
3. **附件与文件引用**：Session 附件和工具事件明确产生的文件引用，显示名称、大小或类型与可用状态。
4. **子任务**：当前 Session 中与所选父 Run 相关的子任务标题和状态，点击进入子 Agent 视图。
5. **运行记录**：按时间倒序显示当前 Session 的 Run 类型、时间、终态和工具数量，点击定位到对应消息。

**交互规则**：

- 每个区块的展开/收起必须有真实作用；Header 保留标题和箭头，不放“已启用”等重复 Tag。
- 空区块使用紧凑一行空状态；没有能力的区块直接不渲染，不放不可点击的占位项。
- 区块内不放没有后续动作的下拉箭头。
- 附件或文件引用点击后进入 F17 预览；无法预览时提供在系统中打开或复制安全路径。

### F17 附件与文件预览

**用户目标**：确认附件和工具产生文件的基本内容，不需要先离开应用。

- 支持安全预览纯文本、Markdown、JSON、常见图片和可稳定获取的小型日志文件。
- 预览弹窗 Header 显示文件名、大小和状态；正文可滚动，提供复制、在系统中打开或显示所在目录。
- 超限、二进制、不受支持、路径失效或无权读取时，显示原因和可用的系统操作，不尝试转码或修复文件。
- 预览是只读的，不在本版本提供编辑、保存、Diff 或文件版本。
- 附件可读路径和 Workspace 用户路径的展示必须区分，不把 Agent 私有副本误表述为用户原文件。

### F18 设置外壳

**用户目标**：在一个稳定的设置弹窗中管理 Runtime、模型和权限，不离开当前会话。

- 左下角“设置”行没有外层 Padding 和额外圆角 Hover，默认、Hover 和选中状态均保持完整行宽度。
- 点击后打开设置弹窗，左侧只保留 Runtime、模型和权限三个本版本有效页。
- 弹窗主 Header 只显示“设置”和关闭按钮，不放不必要副标题。
- 各设置页顶部使用统一最小高度。进入新增/编辑页时，返回图标使用淡色背景，但不改变 Header 高度。
- 弹窗正文默认不小于 `14px`；Footer 不使用额外背景色和顶部分隔线。

### F19 Runtime 设置与诊断

**信息与操作**：

- 显示 Runtime 生命周期、本地连接地址的脱敏投影、配置版本、最近连接时间和最近错误分类。
- 提供“重新连接”、“重启 Runtime”、“重载配置”、“复制诊断”和“打开 Runtime Home”。
- 提供桌面生命周期偏好，明确主窗口关闭时是隐藏还是退出客户端，以及退出客户端时
  Runtime 是否继续运行；不把这些偏好表述为开机自启或系统守护。
- 诊断内容不包含 API Key、完整 Prompt、工具敏感输入、未脱敏 Provider 响应或进程敏感环境变量。
- 有活动 Run 时重启或停止 Runtime 必须明确说明将导致哪些任务中断，并经用户确认。
- 配置重载得到无效结果时采用失败关闭：页面展示新的无效配置状态和结构化诊断，新 Run 不得
  回退使用旧凭据或旧模型配置。上一份有效配置只能作为只读诊断参考，不能继续服务新请求。

### F20 模型管理

**用户目标**：在不手工编辑配置文件的情况下完成常见模型配置和连接验证。

**模型列表**：

- 每行显示展示名、Provider、模型 ID、上下文窗口、默认状态和有效/无效状态。
- 行级操作为测试连接、编辑和更多；页面主操作为“添加模型”。
- 连接测试明确显示验证中、成功或结构化失败，不回显 Provider 敏感响应。

**新增与编辑**：

- 表单至少包含展示名、Provider、模型 ID、上下文窗口、Base URL、API Key 和“设为默认模型”。
- API Key 输入可显示/隐藏当次输入，保存后不再通过查询接口回显原文；编辑时留空表示保留既有凭据。
- 必填项、URL、上下文整数和唯一模型 key 在保存前校验；连接测试不代替保存，保存也不默认发起计费请求。
- 返回按钮使用淡色背景，页面 Header 与列表页等高，避免进入表单后整体跳动。

**删除与默认值**：

- 内置或不可编辑投影不显示删除；当前默认模型必须先选择替代默认值。
- 被活动 Session、队列输入或未终结 Run 冻结引用的模型不能直接删除，界面列出阻塞原因。
- 删除不改写历史 Run 中的模型事实；历史页仍显示已保存的脱敏模型识别信息。

**配置冲突**：

- 打开表单时记住配置修订。保存前发现 Runtime 配置已改变时，不静默覆盖。
- 冲突弹窗提供“重新加载最新配置”和“复制本次输入”。本版本不建设通用字段级自动合并。

### F21 权限设置

**用户目标**：了解当前 Session、Workspace 和 Global 权限文件的有效状态，并安全管理可交互范围。

- 页面按 Session、Workspace、Global 显示当前文件状态和诊断，不回显不必要的内部物理路径。
- Session 和 Workspace 规则提供列表、新增、编辑和删除；规则表单只展示 Runtime 实际支持的工具、
  匹配条件、效果和作用域，不发明第二套通配符语义。
- Global 规则在本版本只读，提供“在系统中打开”和“重新加载”；临时审批不能写入 Global。
- 首次注册 Workspace 时，在 Runtime 私有目录生成该 Workspace 的默认权限文件：Plan 与 Build
  默认允许递归读取、列目录、查找和搜索 Workspace，只有 Build 默认允许递归写入、编辑和删除。
  该默认值是可查看、可编辑的普通规则，不是 Authorizer 中的隐式放行；Shell、Workspace 外路径、
  显式 Ask/Deny 和 Plan 写入硬边界仍按原规则处理。
- 已存在的 Workspace 权限文件绝不被默认值覆盖；历史 Workspace 仅在权限文件确实缺失时于恢复阶段
  补建同一默认文档。
- 保存规则前先校验整份权限文档。校验失败不替换当前有效快照，页面定位到具体规则并显示
  稳定错误。
- Ask/Auto 只决定是否交互询问，不改变 Plan/Build 能力上限、显式 Deny、必须询问规则或 Guardrail。
  Auto 下未命中任何规则的请求默认允许；界面必须明确这一语义，不能把 Auto 描述成“仅自动套用
  已有 Allow 规则”。

### F22 归档、删除、Fork 与数据边界

**用户目标**：清楚区分可恢复、不可恢复和创建分支三种操作，避免误会对 Workspace 文件的影响。

| 操作 | 结果 | 是否影响 Workspace 用户文件 |
| --- | --- | --- |
| 归档 | Session 转为只读并进入已归档列表，可恢复 | 否 |
| 恢复 | Session 恢复为活动状态 | 否 |
| Fork | 从指定历史点创建新 Session，原会话不变，不重放工具 | 否 |
| 删除 | 删除会话领域记录及其引用，不可在产品内恢复 | 否 |

- 不可恢复操作必须使用明确对象的确认弹窗，标题、正文和主按钮都包含对象名称或类型。
- 弹窗 Header 使用最小高度并自动撑开；Title 在单行和带副说明时都必须垂直居中。
- 弹窗 Footer 无额外背景色和边线，取消和确认保持标准间距。

### F23 窗口、托盘与退出

**用户目标**：在关闭界面后允许 Runtime 任务继续运行，并能清楚选择退出客户端或停止 Runtime。

- 标题栏采用平台自适应方案，不强求不同平台绘制完全相同的窗口装饰：
  - macOS 保留系统原生窗口装饰和红黄绿交通灯，通过透明或 Overlay 标题栏让应用内容与 Header
    融合，不使用 Web UI 重画交通灯。
  - Linux 使用与当前 Demo 一致的自定义 Header 和窗口按钮；按钮只承担展示和输入，
    最小化、最大化/还原和关闭必须调用 Tauri 的原生 Window 能力，不通过 Runtime 或普通业务事件模拟。
- Linux 标题栏拖动、双击最大化/还原、最大化状态图标和键盘可访问名称必须完整；窗口按钮
  的可用状态以原生窗口状态为准，不能由前端自行推测。
- Windows 后续可复用同一窗口生命周期和平台适配边界，但不属于本版本的界面实现或验收范围。
- 左上角应用内菜单按钮属于 Web UI，只控制边栏和应用导航。macOS 应用菜单、系统窗口菜单和托盘
  菜单使用 Tauri Native Menu；复制、粘贴、撤销和窗口等标准操作优先采用原生预定义菜单项。
- 自定义关闭按钮、系统关闭按钮、`Alt+F4`、`Cmd+W` 和原生菜单关闭入口统一进入同一个窗口关闭
  生命周期，再按平台常规和用户偏好决定隐藏或关闭客户端，不能出现不同入口产生不同业务结果。
- 窗口关闭按钮关闭或隐藏当前窗口，具体平台表现遵循该系统常规；用户偏好要求退出客户端时进入
  同一退出确认，任何路径都不默认停止 Runtime。
- 托盘或系统菜单入口提供显示主窗口、Runtime 状态、重新连接、退出桌面客户端和停止 Runtime，
  不提供含义重叠的“退出 Assistant”。
- “退出桌面客户端”打开简洁确认，并提供默认不选中的“同时停止 Runtime”。未选中时只退出客户端进程，
  Runtime 继续运行；选中后主按钮改为“退出并停止 Runtime”。
- “退出并停止 Runtime”复用停止流程。有活动 Run、队列或待审批时必须列出影响并确认；Runtime
  停止失败时不退出客户端，以便用户查看错误和诊断。
- Runtime 本版本只是由产品管理的本机进程，不因有托盘入口就宣称已成为系统 daemon 或开机常驻服务。

### F24 加载、空、失败、中断与可访问性

**必须覆盖的状态**：

- 首次启动无 Workspace、Workspace 无 Session、Session 无消息、无附件、无子任务和无运行记录。
- Session/Run 列表加载、消息恢复、附件上传、模型验证、配置保存和审批提交。
- Runtime 断开、配置无效、模型不可用、附件不可读、工具失败、Run 失败/取消/中断和子任务失败/取消/中断。
- 请求已被其他客户端处理、配置修订冲突、幂等重试后已存在结果和快照版本过期。

**反馈规则**：

- Toast 只用于已完成的轻量反馈，如“已复制”；阻塞、失败、中断和冲突在相关区域保留持续入口。
- 错误文案包含当前事实、影响对象和可执行下一步，不直接显示底层错误链或凭据。
- 所有图标按钮有可读名称和 Tooltip；键盘焦点可见；菜单、选择器、Reasoning、右栏和审批可用键盘完成。
- 动效简短且遵循 `prefers-reduced-motion`，不使用大幅位移、弹性回弹或持续呼吸动画。

## 九、关键数据与契约影响

本节只说明产品能力所需的跨层契约，不定义具体 DTO、HTTP 路由或存储结构。

### 9.1 可直接复用的现有契约

- Runtime 生命周期、配置状态、模型脱敏列表/单项查询、重载和连接验证。
- Workspace 登记、列表、查询、移除和恢复。
- Session 创建、列表、查询、归档/恢复、空闲时模型切换、Agent 变体和审批模式切换。
- 可靠输入提交、Run 查询/取消/恢复/重试、附件上传和列表。现有破坏性重入能力不直接作为
  用户消息“重新输入”的产品交互。
- 待审批列表和单项原子决策；子任务列表、详情、执行记录和单独取消。

### 9.2 为完成本 PRD 需要补足的产品契约

- Session 重命名、固定、删除和从指定消息 Fork。
- 排队输入的列表管理、移除、优先顺序、手动中断后的任意项恢复，以及 Runtime 重启后的
  显式恢复状态。
- 可稳定查询的有序消息 Part 投影，能够在刷新后按原顺序重建重复出现的 Reasoning、正文和
  工具活动；同时包含助手消息操作所需定位信息和会话反馈事实。
- 模型配置新增、编辑、删除、默认值、修订检测和冲突处理。
- Session/Workspace 权限规则管理与 Global 只读/重载入口。
- 可稳定查询的按 Session 有序审批队列、队列修订信息，以及“拒绝当前 Tool Call 并停止所属 Run”
  的原子意图；支持在重连、并发决策和规则变更后重建权威状态。
- 主 Session 累计 usage、上一轮输入/输出/缓存命中、当前上下文用量和窗口上限，以及每个
  Child Task 自身 usage 的可展示投影；不要求父子合计投影。
- 工具活动与子 Agent 消息列表的完整可重建查询投影。
- 会话中可预览文件引用的稳定身份、可用性和安全读取能力。

技术方案必须逐项核对现有生产者、消费者、序列化兼容、持久化影响和 Runtime 权威边界。
不能为了还原 Demo 而在桌面端本地伪造这些业务状态。

## 十、模块职责

- `apps/desktop`：承载 WebView、桌面平台适配、Runtime Client、桌面导航和本机视图偏好；
  只发送用户意图和展示权威快照/事件。
- `apps/runtime-host`：正式 Runtime 产品进程入口和 loopback HTTP/SSE/Streaming Upload 适配层；
  负责进程级启停配合与传输，不持有第二份 Session/Run 状态。
- `assistant-runtime`：持有 Session、Run、队列、审批、Workspace、模型配置、子任务、持久化和
  恢复的业务权威，对桌面端意图做原子校验和结算。
- `assistant-protocol`：承载桌面端与 Runtime 之间的轻量稳定 DTO、事件和标识，不依赖 UI、
  具体 Provider、存储实现或 Tauri。

## 十一、关键取舍

1. **以 Demo 作为样式基准，不作为数据契约**：避免重新设计已确认的视觉，同时防止把模拟开关
   和静态数据直接带入产品状态。
2. **会话以 Workspace 分组，不再设“最近”大列表**：避免重复导航；最近切换收敛到 Header。
3. **审批占据底部工作区**：审批是当前会话的主要阻塞，应抢占下一步输入位置；消息列表
   只保留时序事件，不复制第二份阻塞列表。
4. **子 Agent 进入二级消息列表**：中间过程需要与主 Agent 一致的阅读和工具详情，普通摘要
   弹窗无法满足。
5. **队列默认串行自动执行**：队列是可靠输入的自然延伸，不应要求用户每行点击；只在用户
   手动中断后才进入可乱序恢复状态。
6. **归档、Fork 和删除明确分离**：分别对应可恢复收纳、新建分支和不可恢复删除，不把三者混为
   一个“整理”操作。
7. **既有 Session 不静默换绑 Workspace**：Workspace 是已执行历史的冻结事实。用户选择新目录时，
   对有历史的 Session 创建新会话，不伪造原历史曾在新目录执行。
8. **设置只放本版本已定义能力**：不为记忆、Skills、MCP 和后台自动化保留无效入口。
9. **模型仅在 Session 完全空闲时切换**：避免既有队列中的输入因执行时才解析模型而发生隐式变化，
   也与当前 Runtime 的一致性边界保持一致。
10. **Runtime 重启后的队列显式恢复**：进程重启不同于页面刷新或短暂重连；可能丢失临时审批和
    执行环境，不能因持久化队列存在就自动恢复副作用。
11. **无效配置失败关闭**：新配置重载无效时不继续使用旧凭据执行新 Run，避免界面显示配置已失效
    而 Runtime 仍以旧配置产生副作用。
12. **Auto 保留现有默认允许语义**：未命中规则时默认允许，但始终服从 Deny、Ask、Plan/Build 和
    Guardrail 等更高优先级约束。
13. **审批按 Tool Call 入队，拒绝与中断分离**：并行产生的审批仍是独立请求；当前 Session 在底部
    逐项处理，后台 Session 不抢占导航。“拒绝”只结算当前调用，“拒绝并停止本轮”才停止所属 Run，
    避免把普通拒绝隐式扩大为批次或 Session 取消。
14. **窗口装饰平台自适应，窗口能力保持原生**：macOS 保留原生交通灯和系统窗口行为；Linux
    可使用与 Demo 一致的自定义按钮，但所有窗口动作映射到 Tauri Window API。视觉统一不能以丢失
    平台惯例、辅助功能或造成关闭语义分叉为代价。

## 十二、验收标准

### 12.1 Runtime 与外壳

- [ ] 桌面应用可启动或连接正式 Runtime，并完整呈现连接、重连、断开、停止和失败状态。
- [ ] 断线重连和页面刷新后，当前 Session、Run、队列、审批和子任务与 Runtime 快照一致。
- [ ] 左右边栏、专注模式和响应式布局可用，消息列表与底部工作区水平对齐。
- [ ] 窗口关闭、退出桌面客户端和停止 Runtime 的行为和提示不混淆，界面中不存在独立的
  “退出 Assistant”概念。
- [ ] 退出确认中的“同时停止 Runtime”默认不选中；选中后按钮显示“退出并停止 Runtime”，并在
  Runtime 成功停止后退出客户端。
- [ ] macOS 保留原生交通灯和窗口菜单，并通过透明或 Overlay 标题栏与应用 Header 融合，不绘制
  仿原生交通灯。
- [ ] Linux 自定义窗口按钮调用原生最小化、最大化/还原和关闭能力；拖动、双击标题栏、
  最大化状态图标、Tooltip、键盘焦点和可访问名称均可用。
- [ ] 自定义按钮、系统按钮、快捷键和原生菜单触发关闭时进入同一生命周期，并且都不默认停止 Runtime。
- [ ] 应用内菜单与系统菜单职责清楚；原生菜单的标准编辑和窗口操作符合对应平台习惯。

### 12.2 会话与 Workspace

- [ ] 左侧会话按 Workspace 分组并可收起，无独立“最近会话”大分组。
- [ ] 列表缩进、固定图标、时间/加载环和标题对齐符合设计语言。
- [ ] 新建、搜索、切换、重命名、固定、归档、恢复、导出和删除都有明确成功、禁用和失败反馈。
- [ ] 有历史的 Session 选择新目录时创建新 Session，不改写原 Workspace 绑定。
- [ ] 归档、删除和 Fork 的产品结果与 Workspace 文件影响符合 F22。

### 12.3 消息、输入与队列

- [ ] 真实用户/助手正文、多轮 Reasoning 和工具事件可按事件顺序流式显示和快照重建。
- [ ] Assistant 流式 Markdown 在未闭合粗体、链接、代码围栏、公式和 Mermaid 图表时保持稳定；
  完成后可高亮或渲染，失败时安全降级为可复制文本。
- [ ] Reasoning 为灰色折叠盒，无摘要标题和秒数，展开内容超高后在盒内滚动。
- [ ] 主/子 Agent 工具行都为低干扰单行事件，均可打开真实详情。
- [ ] 助手消息操作位于左下，Fork 与折叠相邻；整条收起后仍保留一行标识盒。
- [ ] 输入框默认两行、自动增高、超限滚动，Enter 发送与 Shift+Enter 换行符合约定。
- [ ] Slash Command 和三类上拉选择器支持键盘选择、跟随滚动、完整选中图标和与触发器居中。
- [ ] 队列正常自动串行，只在用户手动中断后暂停；二级抽屉最后一行不被输入框遮挡。
- [ ] Runtime 重启后的持久化队列显示“需要恢复”，不会自动继续执行；普通页面刷新或网络重连
  不额外改变原有暂停状态。

### 12.4 审批与子 Agent

- [ ] 新审批按 Runtime 接收顺序进入所属 Session 的权威队列；主/子 Agent 使用父 Session 的同一队列。
- [ ] 当前 Session 队列从空变为非空时默认抢占底部工作区；面板一次展示一项并显示待处理数量，
  完成后自动切换下一项，消息列表只保留对应时序事件。
- [ ] 审批可最小化但仍明确阻塞；后续入队不强制展开，消息详情能恢复同一审批工作区。
- [ ] 后台 Session 的审批不抢占当前导航或底部工作区，切换会话后能处理其队首审批。
- [ ] 请求内容和授权范围分区显示，Radio 只渲染 Runtime 允许的决策，子 Agent 不伪造新权限层。
- [ ] “拒绝”只拒绝当前 Tool Call；“拒绝并停止本轮”原子关闭所属 Run 的剩余审批，且不影响
  其他 Session。
- [ ] Session/Workspace 允许规则更新后，只有经 Runtime 重新核验并精确匹配的待审批项自动通过。
- [ ] 刷新、重连、重复决策或多客户端竞争后，审批顺序、当前项和数量都与 Runtime 快照一致。
- [ ] 子任务树连线连续，列表底部留白正确；子任务卡片显示自身 Usage，点击任务以二级消息列表
  替换主列表。
- [ ] 子 Agent 视图无独立输入和会话生命周期，可查看工具详情、处理审批和取消未完成任务。

### 12.5 上下文、设置与配置

- [ ] 右侧会话区显示模型、执行方式及仅属于主会话的 Token、上一轮输入/输出、缓存命中和上下文
  占比，不在 UI 层聚合子任务用量。
- [ ] 输入区环状图位于模型名左侧，Tooltip 相对触发器居中并显示精确数字。
- [ ] 右栏的会话、Workspace、附件/文件引用、子任务和运行记录均能真实展开/收起，无无效 Tag 或箭头。
- [ ] 附件和支持的文件引用可只读预览，不可预览时给出安全的系统操作。
- [ ] 设置只包含 Runtime、模型和权限，各页 Header 高度一致，弹窗正文字号和 Footer 符合设计语言。
- [ ] 模型新增、编辑、删除、默认值、连接测试和配置冲突流程可完整操作。
- [ ] 模型选择器只在 Session 完全空闲时可切换；Auto 明确呈现“未命中规则默认允许”及其上层约束。
- [ ] 配置重载无效后新 Run 失败关闭，不回退使用旧凭据；诊断仍可查看上一份有效配置的只读投影。
- [ ] Session/Workspace 权限规则可管理，Global 保持只读与显式重载，无越权的“全局允许”交互。

### 12.6 样式、简洁性与可用性

- [ ] 正式界面逐页对照当前 Demo 和设计语言完成视觉验收，不另外创造一套样式。
- [ ] 页面不包含后台自动化、记忆、Skills 或 MCP 占位入口。
- [ ] “已可靠记录”、“已启用”等无操作价值的重复文案被删除。
- [ ] 所有弹窗、菜单、选择器和核心会话操作都可用键盘完成，焦点清晰且不出现裁切。
- [ ] 动效低干扰，有动效降级，没有大幅弹性、闪烁或无意义的持续动画。

## 十三、风险与兼容性

1. **桌面端范围较大**：主界面、Runtime 生命周期、模型 CRUD、权限管理和子 Agent 观察均涉及正式
   契约。技术方案和开发计划需将必要契约与纯 UI 工作分开里程碑验收。
2. **现有契约不足**：重命名、固定、删除、Fork、队列调整、模型 CRUD、权限编辑和用量投影不能仅靠
   前端模拟。技术方案必须确认最小正式契约，不得将它们留成死控件。
3. **历史兼容**：旧 Session 可能缺少 Reasoning 分段、缓存用量、上下文窗口或子任务记录。界面必须显示
   “暂无数据”而不伪造零值，且不为了新 UI 破坏旧数据可读性。
4. **配置与凭据**：模型 CRUD 涉及配置冲突和凭据输入。技术方案必须定义唯一配置源、修订策略、
   脱敏和平台安全存储边界。
5. **事件丢失与重连**：SSE 断线不能导致重复消息、重复审批或错误子任务状态。完整快照重建是桌面
   验收的必要部分。
6. **平台差异**：托盘/菜单栏、窗口装饰、关闭、文件选择和系统打开在 macOS 和 Linux 上表现不同。
   界面文案保持相同产品语义；技术方案必须核对 Tauri 能力权限、macOS 标题栏样式和 Linux 无边框
   窗口行为，不能只在浏览器 Demo 中验收。Windows 本版本不做正式实现或验收，也不得因此把 Unix
   类型和假设扩散到 Runtime、Protocol 或跨平台 Desktop 业务层。
7. **不可恢复删除**：Session 永久删除涉及持久化和文件引用生命周期，必须在技术方案中给出原子边界、
   影响范围和失败恢复，不得仅删 UI 列表项。

## 十四、已确认结论

无遗留待确认项。D09 已确认采用“单项审批、按 Session 入队、底部逐项呈现、拒绝与中断分离”的产品语义，
具体协议和持久化实现进入技术方案核查。平台范围已确认不把 Windows 纳入 v0.14.0 的正式开发、
打包或验收，只保留后续适配所需的架构边界。
