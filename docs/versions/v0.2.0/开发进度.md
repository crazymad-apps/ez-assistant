### M4：引擎状态机与 Harness

- 状态：✅ 已确认（2026-07-28）
- 实际结果（2026-07-27）：
  - 产出：
    - `agent-core/execution.rs`：`AgentExecution{events, completion, control}` + `start(spec, input, context)`（单一 tokio 任务驱动，无后台辅助任务）；`ExecutionOutcome::{Completed, Failed, Cancelled}`（与三终态镜像）；`ExecutionControl::cancel`（`context.cancellation` 子令牌，父取消自动传播）。
    - `agent-core/engine.rs`：状态机全量——`max_steps` 模型调用前预检（step 从 1）→ 纯机械投影组装 `ModelRequest` → `model.stream`（`LifecycleValidator` + `ModelCallContext` 子令牌）→ delta 桥接事件 → `TurnFinished` 分支 → 无工具调用直接 `ExecutionCompleted`（最终消息 Core 不落账）→ `begin_tool_exchange(Assistant)` → 按批 `ToolProposed` → 逐 call `authorize(call, batch)`（biased `select!` 与取消 race）→ Deny 转错误 `ToolResult`（不执行、不计预算、循环继续）/ Allow → `max_tool_calls` dispatch 前预检（同批超额先结算未执行调用、整批完成 exchange 再 `BudgetExceeded`）→ `dispatch`（等待取消清理完成；`ToolOutput` 桥接）→ 整批按序 `complete_tool_exchange`（`toolmsg_{n}` 从 1 确定性序号）→ 下一轮；取消三处收敛前补记 interrupted 错误 `ToolResult` 保证配对，`ExecutionCancelled` 唯一终态；唯一终态经独立 oneshot 可靠交付并携带 `dropped_events`。
    - `agent-testkit`：`order.rs`（`OrderLog`/`LogEntry` 共享顺序日志）、`tool.rs`（`ScriptedTool` + `ToolBehavior::{Succeed,Fail,Hang}` + `with_entered_signal`）、`recorder.rs`（`InMemoryRecorder`，`failing_at(n)` 失败注入）、`authorizer.rs`（`ScriptedAuthorizer` + `AuthorizeGate` 挂起/释放，Notify 语义无 sleep）；`Cargo.toml` 新增 `agent-core` 依赖。
    - Harness：`agent-testkit/tests/engine_harness.rs` 25 测试，行为矩阵全覆盖（纯文本/单工具/Allow+Deny 同批/多轮回填含 reasoning+ProviderState 保真/模型失败两形态/工具失败/未知名+空快照幻觉/ToolOutput 桥接/顺序日志/Recorder begin/complete 两处失败与 pending 恢复/预算两类各四边界/Deny 不计预算/取消三处含同批第二工具执行中取消的清理与配对快照/事件顺序/真实 Engine 队列拥塞下可靠终态/drop receiver 两方向）。
    - Example：`agent-testkit/examples/engine_demo.rs` 离线展示两轮工具循环，输出事件、最终回答、`begin → authorize → execute → complete` 顺序、Recorder completed 投影和模型请求回填；无需网络、凭据、文件系统或数据库。
  - 验证：2026-07-28 修订后 `cargo test --workspace` ✅（220 passed / 0 failed / 1 ignored；agent-core 24、agent-tools 27、agent-testkit unit 29、Harness 25）；`cargo clippy --workspace --all-targets --all-features -- -D warnings` ✅ 0 警告；`cargo fmt --all --check` 与 `git diff --check` ✅；`cargo run -p agent-testkit --example engine_demo` ✅，实际输出 `Completed`、工具结果回填与 `pending exchanges: 0`。
  - 偏差：
    - `AgentEventSender` 增加 `Clone` 派生（M3 类型最小扩展；`ToolOutput` 桥接闭包需持有发送端副本，克隆体共享丢弃计数）。
    - 取消/预算结算的未执行调用补发 `ToolCompleted{Failed}`（规格只显式规定 Deny；为 `ToolProposed → ToolCompleted` 观察者侧配对补齐，与 Deny 一致）。
    - `serde_json` 从 testkit dev-dep 提升为正式依赖（`ScriptedTool` 公共 API 使用 `Value`）。
    - 模型流中挂起桩 `PausedModel` 放在 Harness 文件内（仅一处消费，`ScriptedModelService` 未动）。
  - 实现修复记录：`InMemoryRecorder` 失败注入按调用次数计（含失败尝试自身，初版按成功落账数实现导致失败粘连）；`AuthorizeGate::wait_entered` 在 authorize future 首次 poll 前调用的死锁已修。
- 审查修订（2026-07-28，用户确认修改方案）：
  - 工具取消不再通过丢弃 dispatch future 抢占返回；Engine 等待 cancellation-aware 工具完成资源清理后再结算，Harness 用 `ToolCleanup` 顺序日志和通知信号验证。
  - Recorder 改为 `begin_tool_exchange` / `complete_tool_exchange` 两阶段协议；pending 不进入规范投影，完整 ToolMessage 批次原子完成，complete 失败保持可恢复 pending。
  - Dispatcher 校验擦除工具返回的 `ToolResult.call_id`；不一致时转换为绑定原调用 ID 的错误结果。
  - 普通观察事件仍使用有界丢弃队列，唯一终态改由独立 oneshot 可靠且最后交付；`ExecutionCompleted` 同步补齐 `dropped_events`。
- 遗留/风险：无。
