## 六、人工核对结果

- 依赖方向符合 `agent-tools → agent-types`、
  `agent-core → agent-model / agent-tools / agent-types`、
  `agent-testkit → agent-core / agent-model / agent-tools / agent-types`。
- `agent-tools` 不依赖模型、Engine、Runtime 或 Tauri；`agent-core` 不依赖
  Runtime、Tauri、数据库或具体 Provider。
- Core 只负责一次 `AgentExecution`；Runtime Run、Session、调度和持久化边界未进入
  Core。
- Tool Call/Result ID、顺序和 pending/completed exchange 语义与文档一致。
- 普通事件与权威 Recorder 记录保持分离，唯一终态可靠交付。
- 公共 API 已在 M5 逐项核定；内部事件发送管道和无调用方实现类型不再暴露。
- 默认测试不访问真实文件系统、数据库、Provider 或用户凭据，不依赖 sleep
  判断并发顺序。
- 本版本没有修改 `assistant-protocol`、`assistant-runtime` 或桌面应用接线。

## 八、偏差、遗留与风险

### 已吸收的设计修订

- `ExecutionPlan` 更名为 `ExecutionSpec`，本版本为四字段。
- Recorder 从逐条增量提交修订为 pending/completed 两阶段 tool exchange。
- 工具取消等待 cancellation-aware dispatch 完成资源清理，不直接丢弃 future。
- 普通观察事件使用有界队列，唯一终态使用独立 oneshot。
- Dispatcher 校验擦除工具返回的 `ToolResult.call_id`。

上述修订均已同步功能设计、技术方案、开发计划、架构/模块文档和回归测试，不是
未解决偏差。

### 遗留与风险

- 真实 FileSystem/Shell 实现、权限策略、审计、Runtime Recorder 持久化与 pending
  恢复实现属于后续 Runtime/Adapter 版本；本版本只定义并验证契约。
- 工具实现必须遵守取消契约：收到取消后完成资源清理再解析执行 future。
- Core 公共 API 在 v0.7.0 前仍允许按后续真实调用方反馈渐进演进。
- 当前无阻断版本完成的遗留问题。
