## 二、实施原则

- 里程碑门禁按规范"逐步确认规则"：实现与验证完成后状态改 `🟨 待确认`，用户明确确认才进入下一里程碑。
- 先搜后写：复用 `agent-types`/`agent-model`/`agent-testkit` 既有类型与模式（手写 boxed-future、`CancellationToken`、`LifecycleValidator`、`EventCollector`）。
- 不为假想需求提前抽象：四字段 `ExecutionSpec`、两变体 `ToolError`、不引入 `jsonschema` 校验器、不引入 async-trait。
- **测试宿主规则**：被 `agent-testkit` 依赖的 crate（`agent-tools`/`agent-core`）不反向 dev-depend testkit，避免 dev-dep 环——`agent-tools` 单测自带 mini fake；引擎 Harness 集中于 `agent-testkit/tests/`。
- 文档同步随里程碑完成：工程与文档登记集中在 M0，其余文档修正不积压到版本尾。
- 里程碑实际结果与开发过程记录写入 `docs/开发进度.md` 对应里程碑小节；本计划只维护里程碑状态。

## 六、M1：`agent-tools` Tool SPI 与 Registry/Dispatcher

### 目标

类型化 Tool → 类型擦除 → 注册快照 → 单次派发的完整链路打通。

### 前置依赖

M0 确认。

### 实施内容

- `tool.rs`：`Tool` trait（`Input: DeserializeOwned + JsonSchema`、`Output: Serialize`、`definition()`、boxed-future `execute`）；`ErasedTool` 对象安全擦除（`execute_json`：serde 反序列化校验 → 类型化 execute → 序列化 → `ToolResult`）；`ToolContext`（`cancellation` + `ToolOutputSink`）；`ToolError`（`InvalidInput`/`Execution`）。
- `registry.rs`：`ToolRegistry`（重名拒绝）→ `ToolSetSnapshot`（不可变定义列表 + 名称索引）。
- `dispatch.rs`：`Dispatcher::dispatch` 一次一个 Tool Call；未知名 → 错误 `ToolResult`；校验/执行失败 → 错误 `ToolResult`。

### 测试（自带 mini tool 单测）

- `input_schema` 派生与 `Input` 类型同步（schemars 输出含声明字段）。
- 非法 JSON 直返错误 `ToolResult` 且不进入实现；执行错误映射为错误 `ToolResult`。
- 未知名调用返回错误 `ToolResult`；重名注册拒绝；快照定义顺序稳定。

### 验证

```bash
cargo test -p agent-tools
cargo clippy -p agent-tools --all-targets --all-features -- -D warnings
cargo fmt --all --check
```

### 完成判定

测试全绿；`agent-tools` 无 async-trait、`jsonschema` 依赖。

## 八、M3：`agent-core` 执行契约类型

### 目标

`ExecutionSpec`/`ExecutionInput`/`ExecutionContext`/Recorder/Authorizer/事件/错误类型与 SPI 就位。

### 前置依赖

M2 确认（`ToolSetSnapshot`、Dispatcher 可用）。

### 实施内容

- `agent-core/Cargo.toml`：按技术方案 §3.2 加依赖。
- `spec.rs`：`ExecutionSpec` 四字段 + `ExecutionBudget{max_steps, max_tool_calls}`（全 `Option`）。
- `input.rs`：`ExecutionInput{conversation, user_input}`。
- `context.rs`：`ExecutionContext{cancellation, recorder, authorizer}`——必传字段。
- `recorder.rs`：`ExecutionRecorder` 两阶段 tool exchange SPI（begin pending / complete whole batch）+ `ExchangeReceipt` + completed `ConversationDelta` 投影视图 + `RecordError`。
- `authorizer.rs`：`ToolAuthorizer` SPI（`authorize(call, batch)` 携本轮批次上下文）+ `ToolAuthorization`（`Allow`/`Deny{reason}`）+ `AllowAllAuthorizer`。
- `event.rs`：普通事件 bounded mpsc（256）+ `try_send` 丢弃计数，唯一终态独立 oneshot 可靠交付；三种终态携带 `dropped_events`。
- `error.rs`：`ExecutionError`（`Model`/`Record`/`BudgetExceeded`）。
- 重组空占位 `agent.rs`/`model.rs`/`tool.rs`；数据类型补 serde 派生（纯增量）。

### 测试

- 类型构造与预算默认；`ExchangeReceipt`/`ConversationDelta`/`AgentEvent` serde 往返。
- 事件通道背压：填满后普通事件丢弃计数递增、终态仍可靠且最后交付；receiver drop 后发送方不阻塞。

```bash

```

## 九、M4：引擎状态机与 Harness

### 目标

完整 Agent 循环落地，版本完成门槛的行为矩阵全绿。

### 前置依赖

M3 确认。

### 实施内容

- `execution.rs`：`AgentExecution{events, completion, control}` + `start(spec, input, context)`；单一 tokio 任务驱动，无后台辅助任务。
- `engine.rs` 状态机循环：`max_steps` 预检 → 请求组装 → `model.stream`（套 `LifecycleValidator`）→ delta 转发事件 → `TurnFinished` 分支 → `begin_tool_exchange(Assistant)` → 逐 call `authorize(call, batch)`（与取消 race）→ Allow → `max_tool_calls` 预检 → `dispatch`（`ToolOutput` 桥接）/ Deny 转换错误 `ToolResult` → 整批 `complete_tool_exchange` → 下一轮；工具取消等待 dispatch 完成清理后再结算，三处取消在收敛前为未结算调用补 interrupted 错误 `ToolResult`（配对不破坏）后归为 `ExecutionCancelled` 唯一终态；预算到达先结算未执行调用再 `BudgetExceeded`；`ToolMessage.id` 执行内确定性序号。
- `agent-testkit`：`ScriptedTool`（可观察取消清理）、`InMemoryRecorder`（pending/completed exchange + 可注入第 N 次失败）、`ScriptedAuthorizer`（可挂起）；三者共享顺序日志。
- `agent-testkit/examples/engine_demo.rs`：无需网络和凭据即可运行的两轮工具循环演示，输出事件、最终回答、副作用顺序、Recorder 投影和两次模型请求投影。

### Harness（宿主 `agent-testkit/tests/`）

- 纯文本完成（空工具集）；单工具；同批多工具（逐一过闸，含 `Allow + Deny` 混合：放行执行、拒绝转换错误结果、循环继续）；多轮工具（顺序脚本 + `take_requests` 断言 ToolResult 回填）。
- 模型失败（建立前/流中）→ `ExecutionFailed{Model}`；工具失败 → 错误 `ToolResult` 回喂；未知名/空快照幻觉 → 错误 `ToolResult`。
- 取消三处：模型流中 / 工具执行中 / 授权挂起中 → 工具取消清理完成 → 未结算调用补 interrupted 错误 `ToolResult`（含同批第二个工具执行中取消、批次内剩余调用结算）→ `ExecutionCancelled` 唯一终态；取消后新 `ConversationSnapshot` 配对完整。
- 顺序日志断言 `begin(Assistant) → authorize → execute → complete(batch)`；begin 失败时无工具执行，complete 失败时保留 pending 且规范投影无未配对消息，均 `ExecutionFailed{Record}`。
- Deny → 工具未执行、错误回喂、循环继续；`max_steps`（模型调用前预检）/`max_tool_calls`（dispatch 前预检）：0 / 刚好等于上限 / 同批跨越上限（未执行调用结算后 `BudgetExceeded`）/ `None` 不限制四类边界。
- 事件顺序断言；普通队列满时终态仍可靠且最后交付；drop receiver 后执行照常完成。

```bash

```
