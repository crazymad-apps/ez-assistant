## 三、主要修订与偏差

- `ExecutionPlan` 更名为 `ExecutionSpec`，保持四字段规格，避免与任务规划产物混淆。
- Recorder 从逐条记录调整为 pending/completed 两阶段 tool exchange，保证规范投影不出现部分批次。
- 工具取消改为等待 cancellation-aware dispatch 完成资源清理后再结算。
- 普通观察事件采用有界队列，唯一终态使用独立 oneshot 可靠交付。
- Dispatcher 校验擦除工具返回的 `ToolResult.call_id`；Registry 定义在注册时冻结，类型化输入 schema 由擦除层固定派生。
- M5 删除 `agent-tools` 未使用的 `futures-core`，并将 `agent-core` 仅测试使用的 `serde_json` 移入 dev-dependencies。

上述修订均已进入实现、设计文档、模块约束和回归测试，不构成未解决偏差。

## 四、遗留与后续入口

- 真实 FileSystem/Shell 机制实现、Runtime 权限策略与审计装饰器、Recorder 持久化和 pending 恢复属于后续 Runtime/Adapter 版本。
- 工具实现必须继续遵守取消契约：收到取消后完成资源清理，再解析执行 future。
- Core 公共 API 在 v0.7.0 前仍可根据 Runtime 和真实应用调用方反馈渐进演进。
- 下一目标版本为 `v0.3.0`（上下文系统）：从 Prompt Compiler、上下文组装和 token 预算的功能设计开始，继续保证 reasoning、Provider State 与 Tool Call/Result 配对不被裁剪或压缩破坏。
