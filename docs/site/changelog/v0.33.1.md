# v0.33.1

本版本改善长会话阅读、历史消息编辑、运行中介入，以及项目和会话列表的整理体验。

## 历史阅读与定位

- 消息历史默认每页加载 10 个完整轮次，工具调用较多的单轮不再被拆到多页。
- 聊天区域左侧空间充足时显示缩略导航。悬停可预览用户输入及其后最后一段助手正文，点击可定位；未加载内容按需读取，超长列表可独立滚动。
- 去掉消息、处理过程和子任务中重复的“继承”标签，原有只读规则保持。

## 编辑与介入

- 用户消息下方新增复制、编辑图标，样式与助手消息工具栏一致。空闲时可把历史输入载入底部输入框，修改文字、附件、引用等内容后重新发送，替换原消息并移除其后的会话记录。
- 编辑时只保留编辑抽屉，可返回原位置或取消；运行中不显示编辑入口。
- Enter 保持普通发送和排队；Ctrl + Enter、macOS Command + Enter 可介入当前运行，队列中的消息也可通过“介入”提前接续。
- 修复取消或失败时已输出的思考内容和正文丢失的问题，终止后仍可查看已保存的内容。

## 项目与会话列表

- Desktop 和 Web 的项目、会话默认按创建时间排序，新建在前；继续聊天或改名不会让原条目跳动。
- 支持同组拖拽排序和恢复默认顺序。项目、项目内会话、独立会话分别分页，默认每页 10 条。
- 置顶区也可拖动排序。桌面置顶顺序保存在本机，Web 置顶顺序保存在所连接的 Runtime。
- 统一“加载更多”样式，修复项目展开、收起时的列表回跳，并减少拖动误触。

## 稳定性与升级

- 修复部分 OpenAI Responses 兼容服务在连续请求中缓存复用率偏低的问题。
- 修复编辑原生压缩会话后上下文重建错误，保留已有压缩状态用于继续运行。
- 文件读取支持按字符分段，限制超长单行的单次返回量，降低工具结果撑满上下文的风险。
- 改善历史编辑、裁剪、分支复制和断线重试时的数据一致性。
- 客户端与 Runtime 需配套升级至本版，勿混用本版早期测试包。升级前保留完整 Runtime 数据目录备份；升级后如需回退，应恢复配套备份，不能只替换数据库或程序。
