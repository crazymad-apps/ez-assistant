Host 内置 skill-creator，可按需加载来创建和更新技能。把反复使用的周报整理、资料检查或报告流程保存为 Skill，下次遇到相同任务时继续使用。

## 先把方法说清楚 {#prepare}

准备一个已经比较稳定的工作方法：什么时候使用、需要哪些资料、输出什么结果，以及哪些步骤或格式必须保留。可以引用本次会话中已经满意的成果，也可以提供有权复用的模板。

无需安装插件或额外运行环境。在设置的“技能”中可以查看内置 skill-creator；已有同名自定义技能优先，按名称禁用后不会回退到内置版本。

## 创建和使用技能 {#use}

1. 新建会话，描述想要保存的工作方法，以及适用范围和交付要求。
2. 助手检查是否有同名技能，并整理技能说明；必要时附带可复用的脚本、参考资料或模板。
3. 未指定位置时，优先保存到当前登录用户的个人技能目录；如果 Runtime 无法确定该目录，需要先确认保存位置。
4. 完成后核对技能名称、保存位置和触发方式，刷新技能列表后使用新技能；也可以新建会话试用。
5. 用一份代表性资料试用，发现缺漏后明确要求更新同一个技能。

## 位置、来源与更新 {#scope}

未指定位置时，使用当前会话提供的 `user_skills_directory/<name>/SKILL.md`，不要猜操作系统 Home 或写入来源目录。项目专用技能按用户选择放在工作区的 `.ez-assistant/skills/<name>/SKILL.md`。内置来源标签 `builtin:<name>` 是标识，不是可读写的磁盘路径。

同名来源沿现有发现优先级选择：工作区先按主目录、附加目录的顺序，在每个根内 `.ez-assistant/skills` 优先于 `.agents/skills`；之后依次为当前用户 `skills`、旧共享目录、Host 补充目录、用户 `.agents/skills`、插件、内置。按名称禁用后不回退到内置版本；多个插件同名等冲突以设置中的诊断为准，不通过重命名来源或改安装包绕过。

列表读取会扫描当前文件；Run 开始时扫描并冻结本轮目录，用户选择或模型 `load_skill` 只激活实际选中的定义。更新后可在后续 Run 发现和加载，无须把“只能新建会话”作为通用规则；原历史激活保持原正文。`ez-assistant-guide` 用于查询产品运行与配置规则，编制具体技能的方法按需加载 `skill-creator`。

## 可以这样说 {#examples}

> 把刚才的周报整理方式保存为“项目周报”技能。以后收到项目进展时，按本周完成、风险、下周计划输出，缺少的信息先列出来。

> 更新已有的项目周报技能，增加“需要协同的事项”，保留原有结构和模板。

> 用项目周报技能处理这些资料，先告诉我是否缺少关键输入，再生成周报。

## 会保存什么 {#result}

主要成果是包含 `SKILL.md` 的技能目录，按需要附带资源。新技能写入获授权的目录，不会改写安装包里的只读技能。

更新已有技能通常保留原位置。技能是可复用的方法，不会自动成为企业统一分发的插件，也不会自动发送给其他成员。

## 常见问题 {#faq}

- **创建后当前会话没出现新技能。** 重新打开技能列表或显式刷新后选择；已加载的历史正文不会被更新后的文件改写。
- **已有同名技能。** 指明要更新哪一份，或使用不同名称，避免误覆盖。
- **不知道保存到了哪里。** 让助手返回实际保存位置，不要根据操作系统用户名猜个人技能目录。
- **写入被拒绝。** 核对目标目录与写入权限；读取到了公共技能，不代表可以修改它。

技能中不要保存账号密码、访问密钥或仅用于某次任务的敏感资料。日常执行仍遵循客户端的权限与确认流程。
