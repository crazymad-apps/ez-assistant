MCP 为当前连接的 Runtime Host 提供外部工具。先核对目标 Host／用户域、服务名称和来源，再配置相应字段；远端服务是否能访问文件或网络，以实际执行端为准。

## 来源与可编辑范围 {#sources}

| 来源 | 管理方式 |
| --- | --- |
| 独立服务 | 在 MCP 设置页添加或导入，维护该服务的启动／传输与连接配置 |
| 插件服务 | 启动定义由插件维护；详情编辑启停、环境变量或请求头，绑定插件参数的字段由原参数入口保存 |
| 内置服务 | 定义随 Host 交付，用户只维护可覆盖字段；不需要插件安装或另建原生 JSON |

父 Agent 当前有 `get_mcp_configuration`、`configure_mcp`、`refresh_mcp` 时，沿实际工具定义操作；查询适用于 Plan／Build，配置与刷新要求 Build 并遵守当前权限。child 不因读取本说明取得父 Agent 管理能力。独立服务的新增／导入、未暴露的绑定参数操作使用现有设置页，不虚构管理工具或用原生令牌回环请求。

## 分别核验结果 {#results}

1. **查询与保存**：核对来源、字段归属及是否设置，按工具提供的当前身份／修订保存；失败或过期时先重新查询，不盲目覆盖其他修改。
2. **临时测试**：检查启动和 MCP 协议握手、工具目录；不保存配置，不改变启用意图，不执行搜索或其他业务操作。
3. **主动启用**：由用户明确选择启用并保存；写入 Key 不代表已启用。插件整体停用时，单个服务的开关不会绕过它。
4. **目标刷新**：对目标服务应用已保存配置，分别查看已保存状态与当前连接状态；不以旧连接仍存活替代新配置已生效。
5. **实际调用**：业务工具在本轮开始时冻结，新启用服务的工具从后续 Run 使用。只有实际调用才能验证 API、Key、目标网络与业务结果。

同名服务同时启用时，按“用户添加 > 普通插件 > 内置资源”选用；多个插件同名时按插件标识升序选择。其他条目显示优先使用的来源，仍可进入详情和配置。停用高优先级条目后刷新，就会选用下一份启用配置；不合并定义、复制 Key 或删除其他配置。连接协议或依赖错误分别处理，不把缺少 Key 当作所有启动失败的原因。

## 配置插件 MCP

在设置的 MCP 列表选择插件服务，或在插件详情点击 MCP 名称，均可进入同一服务详情；未连接或缺少参数时也能进入。
启动命令、参数、地址由插件维护，详情中只修改该服务的启停、环境变量或请求头。已有凭据只显示是否设置。

直接覆盖保存后，点击“刷新此服务”应用；“测试连接”只临时连接并读取工具目录，不保存配置或执行搜索。
“移除”会屏蔽定义中的该变量，“恢复默认”则重新使用插件定义。绑定到插件参数的字段使用原参数单独保存，
会影响共用该参数的服务。插件整体停用后，单个服务的启用设置不会绕过它。

父 Agent 可查询 MCP 配置状态，在 Build 模式按当前权限修改及刷新；Plan 模式只能查询。
优先在详情中输入 Key；如果直接在对话中提供凭据，原始消息和工具调用可能保留在会话历史中。


## 使用内置搜索 {#builtin-search}

Runtime 0.32.1 起，DeepSeek 搜索随 Host 交付，首次显示但默认禁用，无需安装插件或创建原生 JSON。

1. 在设置的 MCP 列表进入“DeepSeek 搜索”，填写环境变量 DEEPSEEK_API_KEY；DEEPSEEK_BASE_URL 可留空，使用默认服务地址。已有秘密不回显。
2. 保存只更新配置，不会自动启用或搜索。“测试连接”仅检查进程与工具目录，不能验证 Key 或搜索服务是否可用。
3. 需要使用时主动启用、保存，再点“刷新此服务”。真正执行搜索后才会访问搜索 API。

插件 MCP 的直接变量覆盖保存在原插件配置目录；内置服务覆盖保存在当前用户的 mcp.json 内置分区。移除变量会抑制默认值，“恢复默认”会重新使用产品定义。旧独立服务及其 Key 不会自动迁入内置服务；同名来源同时启用时按上述优先级选用；若想使用内置服务，先停用同名的用户或插件服务，再刷新。

父 Agent 也可在 Build 模式按当前权限配置和刷新；不会读回已有 Key。若在对话中直接提供新值，该值仍可能保留在原消息和工具调用历史中。

MCP 工具范围在每轮执行开始时确定。Agent 在没有连接时仍可配置和刷新；新启用服务的搜索等业务工具从下一轮执行起可用。
