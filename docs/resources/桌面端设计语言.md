# ez-assistant 桌面端设计语言

## 一、文档定位

- 适用产品：ez-assistant 正式桌面端。
- 当前用途：作为 `v0.14.0` 正式桌面端 MVP 的视觉与交互设计输入。
- 样式基准：`tmp/product-experience-demo/` 当前亮色 Demo。
- 基准原则：本文不重新设计一套样式。颜色、字号、密度、圆角、层级、布局和交互表现均从
  当前 Demo 提炼；本文与 Demo 表现冲突时，以最后获得用户确认的 Demo 为准，并同步修订本文。
- 实现边界：本文不规定前端框架、组件封装、组件复用、目录结构、状态管理或协议映射；这些内容
  由 `v0.14.0` 技术方案决定。
- 产品边界：Demo 中的静态数据、状态切换入口和模拟反馈不是 Runtime 或应用协议契约。正式 UI
  只展示 Runtime 权威状态，并通过意图命令触发操作。

## 二、设计气质

### 2.1 核心关键词

克制、清晰、紧凑、安静、可追踪。

界面首先服务于长时间阅读和复杂 Agent 执行观察。视觉层级应让用户依次看到正文、当前阻塞、
工具与思考过程、辅助上下文，不让装饰、状态色或大面积卡片抢夺正文注意力。

### 2.2 基本原则

1. **正文优先**：助手正文使用页面最高的内容对比度；工具、时间、状态和说明逐级减弱。
2. **少用容器**：普通内容不为分组而套卡片。只有需要边界、折叠、阻塞或独立操作时才使用盒子。
3. **颜色表达状态，不表达装饰**：蓝色用于主操作和执行中，绿色用于完成，橙色用于等待，红色
   用于失败或危险；普通信息保持灰色系。
4. **紧凑但不拥挤**：工具行、菜单和元信息使用较小密度；正文、输入和弹窗正文保留正常阅读尺寸。
5. **就地进入详情**：概览保持一行或短块，需要更多信息时点击进入弹窗或二级消息列表。
6. **状态持续可见**：运行、审批、断线、失败和中断不能只依赖瞬时 Toast；必须在相关区域保留
   可恢复、可检查的状态入口。
7. **动效克制**：只使用短促的颜色、透明度、位移和箭头旋转反馈；不使用弹跳、放大、浮夸光效。

## 三、视觉基础

### 3.1 字体

默认字体序列：

```text
Inter, ui-sans-serif, -apple-system, BlinkMacSystemFont, "Segoe UI",
"PingFang SC", "Microsoft YaHei", sans-serif
```

等宽内容使用：

```text
SFMono-Regular, Consolas, monospace
```

字号基准：

| 层级 | 字号 | 主要用途 |
| --- | ---: | --- |
| Caption | 11px | 时间、计数、极弱说明、Tooltip |
| Meta | 12px | 工具元信息、菜单补充、状态说明 |
| UI | 13px | 菜单、按钮、工具行、表单标签 |
| Body | 14px | 用户消息、助手正文、弹窗正文、思考正文 |
| Session title | 15px | 当前会话标题及标题编辑框 |
| Title | 16px | 面板标题、弹窗标题、设置页标题 |

文字颜色和字重：

- 主正文：`#252932`，正文常规字重。
- 次级文字：`#5f6673`，用于说明、非关键标签和行级操作。
- 弱化文字：`#9299a6`，用于时间、路径补充和占位提示。
- 标题通常使用 `600–650`；状态或重要操作不依赖超粗字重强调。
- 用户消息与助手消息正文统一使用 `14px`，不因角色改变字号。
- 弹窗正文不得降到 Caption 或 Meta，应保持 `14px / 1.7` 的阅读尺度。

| Primary soft | `#edf1ff` | 选中背景、轻量执行中背景 |
| Primary border | `#dce4ff` | 主色轻边框、焦点辅助 |

| Surface | `#ffffff` | 主内容、弹窗、输入框 |
| Surface subtle | `#f8f9fb` | 轻量分区、只读内容、空状态 |
| Surface muted | `#f1f3f6` | Hover、选中前景、弱控件背景 |

工具与思考过程使用专门的弱化色：

- 工具普通文本：`#5a606a`。
- 已完成工具标题：`#2f4d40`，深绿色但不高亮。
- 执行中工具标题：`#30445b`，深蓝色但不高亮。
- 思考标题：`#707783`；背景 `#f7f8fa`；边框 `#e1e4e9`。
- 工具状态允许使用彩色圆点，但整行文字不能使用鲜蓝色或鲜绿色。

### 3.3 圆角、边框与阴影

- 小圆角：`7px`，用于按钮、菜单项和行级容器。
- 中圆角：`11px`，用于浮层、设置区块和二级抽屉。
- 大圆角：`15px`，用于应用外壳或大型输入区域；当前输入框实际为 `13px`。
- 普通边框统一 `1px`，避免通过粗边框制造层级。
- 小阴影：`0 1px 2px rgb(24 32 56 / 4%)`。
- 浮层阴影：`0 12px 36px rgb(37 45 70 / 12%)`。
- 输入框阴影：`0 10px 26px rgb(31 42 73 / 8%)`。
- 应用外壳阴影：`0 18px 56px rgb(30 38 61 / 16%)`。
- 阴影只用于浮层、输入框和应用外壳；消息正文、工具行和普通分区不使用阴影。

### 3.4 图标与状态点

- 使用线性图标，默认 `stroke-width: 1.8`，圆角端点和连接点。
- 常规图标 `18px`；工具栏和紧凑行多使用 `12–16px`。
- 图标按钮默认 `32 × 32px`；消息操作为 `28 × 28px`；发送按钮为 `30 × 30px`。
- 状态点直径 `7px`，仅表示状态，不附带重复的状态文字时也必须能通过上下文识别。
- 加载状态用小型环形旋转图标；会话列表运行中以加载图标替代时间，避免额外增加状态文案。

### 3.5 动效和焦点

- 常规状态过渡控制在 `100–120ms`。
- 展开/收起只旋转箭头或切换内容，不做大幅高度弹性动画。
- 加载旋转周期约 `800–900ms linear infinite`。
- 遵循 `prefers-reduced-motion`，减少或关闭非必要动画。
- 键盘焦点使用主色低透明度 `2px` 外描边和 `2px` 间距；自定义输入编辑状态可以改为
  `1px` 主色边框，但不能出现输入框两侧的额外装饰条。

## 四、应用壳层与空间关系

### 4.1 主框架

- 正式 Desktop 的应用外壳铺满 WebView，不保留网页 Demo 用于模拟浏览器画布的 `12px` 外边距、
  `16px` 外壳圆角或外层阴影；窗口自身的圆角和阴影由操作系统负责。
- 顶部融合标题栏高度 `48px`。macOS 使用原生 traffic lights 与 overlay title bar，页面在左侧
  为按钮组保留安全区；不在 WebView 内伪造红绿灯。
- 主体为左侧会话栏、中部会话区、右侧当前上下文三栏布局。
- 常规宽度：左栏 `286px`，右栏 `326px`，中间区最小 `500px`。
- 窗口宽度不超过 `1180px` 时，左栏缩为 `252px`，右栏缩为 `294px`。
- 左右边栏均可独立收起；专注模式同时收起两栏；恢复默认布局重新显示两栏。

### 4.2 顶部区域

- 顶部标题栏只保留产品名、Runtime 状态和窗口操作，不堆放业务入口。
- 会话 Header 高度 `56px`，左右内边距分别约 `26px / 18px`。
- 会话标题单行省略，普通状态下点击标题直接编辑；编辑框高度 `28px`，宽度随可用空间收缩，
  不挤压右侧操作组。
- 会话切换使用标题左侧下拉箭头；箭头按钮使用淡色背景以形成稳定对齐基准。
- 会话操作、布局和更多菜单在标题右侧统一排列。
- 页面顶部区域保持紧凑，不用大面积空白分隔标题、导航和内容。

### 4.3 中部内容与输入对齐

- 消息列表和底部输入区使用同一内容宽度：最大 `820px`，水平居中。
- 两者使用相同的响应式水平留白：`clamp(24px, 4vw, 64px)`。
- 消息列表顶部留白 `24px`，底部留白 `12px`；输入区底部留白 `18px`。
- 滚动条保留稳定槽位，避免消息区域与输入框因滚动条出现而横向错位。

## 五、导航与列表语言

### 5.1 会话侧栏

- 顶部为“新对话”和搜索入口，下方为“会话 / 已归档”切换。
- 会话按 Workspace 分组；Workspace 和其会话列表均可展开收起。
- Workspace 标题和下属会话标题遵循同一列表语言：一行文本、统一 Hover、无嵌套卡片。
- 会话项内部通过 `padding-left` 形成层级，列表自身宽度与 Workspace 标题一致，不以外部 Margin
  缩窄列表。
- 会话标题保持单行省略；固定图标紧跟标题，不占用时间区域。
- 空闲会话显示更新时间；运行中以加载环替代时间；不额外显示状态文字或状态圆点。
- Workspace 行级操作仅在 Hover、键盘聚焦或菜单打开时显示，提供在此新建会话、打开工作目录、
  复制路径等操作。
- “最近会话”不在侧栏重复占据独立分组；当前会话标题左侧下拉菜单提供最近会话切换。

### 5.2 下拉菜单与选择器

- 短操作和上下文相关操作使用下拉菜单，不打开弹窗。
- 菜单项保持单行、左图标、右侧可选 Toggle 或状态；危险操作用红色文字并以分隔线隔开。
- 模型、Build/Plan 和 Ask/Auto 使用同一种上拉选择器样式。
- 输入区选择器浮动在触发按钮上方并相对按钮组居中；不能被二级抽屉或输入框边缘遮挡像素。
- 选择器每项包含图标、主名称、必要的短说明和完整选中图标；选中图标必须完整落在安全内边距中。
- 键盘上下选择时，活动项必须自动滚动进入可视区域；Enter 确认，Esc 关闭。

## 六、消息与 Agent 执行语言

### 6.1 用户消息

- 用户消息右对齐，最大宽度 `620px`。
- 正文 `14px / 1.65`，内边距 `8px 11px`，使用浅蓝背景和轻蓝边框。
- 消息盒子保持紧凑，不能以过大内边距形成卡片感。
- 时间和重输操作位于消息下方；重输按钮默认弱化，Hover 或键盘聚焦时出现。

### 6.2 助手消息

- 助手消息不使用头像或机器人图标。
- 正文直接落在消息流中，不套白色气泡；`14px / 1.75`。
- 一个 Agent 回合按真实事件顺序呈现：思考 → 正文 → 工具列表，可重复多轮。
- 不显式渲染“Step 1”等步骤名称，也不为步骤生成并不存在的总结标题。
- 每条助手消息的操作统一位于左下：复制、赞同、不赞同、Fork、展开/收起、时间。
- 展开/收起使用图标按钮并与 Fork 相邻；收起后保留一行浅色盒子，说明该消息已收起并显示
  思考段数和工具调用数，不能让消息完全消失。

### 6.3 思考过程

- 使用灰色系折叠盒，不使用紫色背景或高饱和标题。
- Header 最小高度 `34px`，内边距 `6px 10px`；只显示状态圆点、“思考过程”和折叠箭头，
  不显示摘要性 Title，也不显示“思考了多少秒”。
- 展开内容最大高度 `180px`，超出后在盒内纵向滚动。
- 内容内边距 `9px 10px 10px`，正文 `14px / 1.7`。
- 完成圆点为绿色，执行中圆点为蓝色；颜色只落在圆点，整体仍保持灰色。

### 6.4 工具事件

- 工具调用在消息列表中呈现为一行文字事件，不使用大型工具卡片。
- 行高最小 `30px`，内边距 `4px 9px`，横向内边距明显大于纵向内边距。
- 工具标题、目标、结果摘要和“查看详情”在同一行；过长目标省略。
- 普通工具文字使用深灰；完成标题用深绿色，执行中标题用深蓝色，等待用橙色，失败用红色。
- 颜色必须比正文更克制，不能使用鲜蓝高亮抢夺正文注意力。
- Hover 只增加浅灰背景和轻微下划线提示，不做漂浮或缩放。
- 点击整行打开工具详情弹窗；详情展示状态、完整目标和字段，不在消息流中展开大型卡片。

### 6.5 待执行队列

- 队列是用户输入的衍生，作为输入框上方的二级抽屉，不单独占据消息列表区域。
- 抽屉左右相对输入框缩进 `10px`，与输入框重叠 `7px`，形成连续层级；底部必须预留该重叠量，
  不能遮住最后一行像素或造成上下不对称。
- 每行显示序号、输入文本、进入时间、执行/优先按钮和取消按钮。
- 正常情况下队列按顺序串行自动执行；只有用户手动中断当前轮次后，队列暂停。
- 暂停队列允许逐行直接执行，支持乱序恢复；不再提供占空间的全局“执行队列”按钮。

### 6.6 子 Agent

- 父消息中的子任务使用一棵连续分叉线连接的紧凑任务树；根节点和各分支之间不能断线。
- 子任务行显示状态点、任务标题和一行弱化详情；点击进入二级消息列表。
- 二级消息列表直接替换主消息列表，不以弹窗或侧栏展示。
- 二级列表 Header 使用淡色图标返回按钮；标题右侧可放 Agent 类型作为弱化文本，不单独强调
  “主 Agent”或具体 Agent 的身份标题。
- 子 Agent 消息、思考过程和工具行与主消息列表使用相同视觉语言；子 Agent 工具同样可点击查看。
- 子 Agent 审批到达时也可在主 Agent 界面处理，审批归属必须清晰显示请求者。

## 七、输入与命令语言

### 7.1 输入框

- 输入框最小高度 `88px`，整体内边距 `11px 12px 10px`，圆角 `13px`。
- 文本域默认至少两行，最小高度 `49px`，最大高度 `144px`；随内容自动增高，超过约六行后
  在输入框内部滚动。
- Enter 直接发送；Shift + Enter 换行；输入法组合状态下不误发送。
- 工具栏控件高度 `28px`；发送按钮单独保持 `30 × 30px`，宽高一致。
- 模型名称使用 `13px`，位于发送按钮左侧；上下文占比环位于模型名称左侧。
- 上下文环直径 `15px`，只表达大概占比；Hover 或键盘聚焦时在环正上方居中显示完整 Token 数字。

### 7.2 Slash Command

- 输入 `/` 后在输入框上方打开指令列表。
- 列表显示指令、中文名称和一句用途说明；活动项使用浅灰背景，活动图标可使用浅蓝强调。
- 支持键盘上下移动、自动滚动、Enter 或 Tab 执行、Esc 关闭。
- `/model` 切换当前会话模型，并与发送按钮左侧模型选择器复用同一种交互表现。
- 未知指令给出轻量反馈，不把未知文本当普通消息直接发送。

## 八、审批与阻塞语言

### 8.1 阻塞入口

- 新审批进入所属 Session 的有序审批队列。当前 Session 的队列从空变为非空时，队首审批默认
  抢占底部输入区，用户无需再点击消息中的事件才能处理。
- 同一队列后续审批只追加，不替换当前面板；面板显示待处理数量，当前项完成后自动切换下一项。
- 后台 Session 的审批不得抢占当前导航或底部输入区，只在对应会话入口持续提示；切换到该
  Session 后再呈现其队首审批。
- 消息列表中仍保留一条“等待授权”的工具事件作为时间线事实，但输入框上方不重复显示第二份
  阻塞列表。
- 点击消息中的等待授权详情时，仍打开或恢复同一个底部审批区。
- 用户可以最小化审批区；最小化只改变展示，不解除阻塞。此时普通输入区可以重新显示，但必须
  保留明确的等待审批状态和数量入口；后续审批入队不强制重新展开。

### 8.2 审批面板

- 审批面板与输入框使用同一最大宽度和底部位置，成为当前工作区，而不是居中弹窗。
- Header 显示盾牌、问题、可选请求者和工作目录；右侧只有最小化按钮。
- Shell 命令使用独立的浅灰等宽行完整显示，不能截断关键脚本语义。
- 授权范围纵向三行排列，使用原生 Radio：本次请求/Run、当前子任务或会话、当前会话或 Workspace。
- 每个选项由标题和一句作用说明组成；默认选择满足当前操作的最小范围。
- 底部保留“拒绝”和“允许执行”两个主要决策，并以较低视觉权重提供“拒绝并停止本轮”；三个
  操作不得因颜色或位置让用户误解普通拒绝会停止整个 Run。
- “拒绝”只结算当前 Tool Call；“拒绝并停止本轮”才关闭所属 Run 的剩余审批。
- 子 Agent 审批与主 Agent 审批进入父 Session 的同一队列并使用同一面板，只通过请求者和范围
  文案区分。

## 九、右侧当前上下文

- 右栏标题区高度 `56px`，内容区横向内边距 `12px`。
- 信息按会话、Workspace、文件与产物、子任务、运行记录、记忆分区。
- 分区使用统一的展开/收起逻辑；标题行和箭头在收起后继续保留。
- 无实际动作的箭头、Tag 或状态说明不得出现。
- 会话区显示状态、模型、执行方式、累计 Token、上一轮输入/输出、缓存命中和上下文窗口占比。
- Workspace 区提供路径、复制、打开和重新选择目录；文案不得暗示工作目录是强沙盒。
- 文件和产物行可点击预览；产物可使用低饱和 Tag 区分。
- 没有数据时使用一行虚线边框空状态，不渲染空白卡片或“已可靠记录”等无行动价值文案。

## 十、弹窗与设置语言

### 10.1 弹窗

- 普通弹窗最大宽度 `520px`，宽弹窗最大宽度 `760px`，最大高度 `min(86vh, 760px)`。
- 弹窗圆角 `13px`，背景遮罩 `rgb(21 27 40 / 28%)`，轻微 `2px` 模糊。
- Header 最小高度 `54px`，内边距 `10px 14px`；标题垂直居中。
- Header 有副标题时由最小高度自动撑开，标题组整体居中，不使用固定高度裁切。
- 不必要的副标题应删除；只在解释状态、对象或范围时出现。
- Body 内边距 `16px`；正文 `14px / 1.7`。
- Footer 不使用独立背景色和顶边框，只用 `6px 16px 16px` 留白承载按钮。
- 普通操作用弹窗，短列表选择和上下文操作用下拉菜单；不要用弹窗替代所有操作。

### 10.2 设置页

- 设置使用宽弹窗；左侧导航宽度 `180px`，右侧内容区内边距 `20px`。
- 各设置页 Header 使用一致的最小高度和占位关系，是否带返回按钮或主操作按钮都不能导致内容跳动。
- 返回按钮统一使用淡色背景的方形图标按钮，标题与其他设置页标题对齐。
- 列表页优先呈现状态和直接操作；编辑页保持简单表单，不堆叠说明和装饰。
- 模型列表提供状态、连接测试、编辑、删除和新增入口；删除受内置配置及会话引用约束。
- 视觉稿可展示 Skills 与 MCP 的列表、连接、编辑和开关语言，但是否进入 `v0.14.0` 功能范围由
  功能设计决定，不能因 Demo 存在而自动纳入。

## 十一、Runtime、错误和空状态

### 11.1 Runtime

- 顶栏 Runtime 胶囊持续展示已连接、重连中、已断开或启动失败。
- 重连中使用蓝色加载环；已断开使用灰色；启动失败使用浅红背景和红色文字。
- Runtime 异常时，消息区顶部出现持续状态条；输入区被禁用并显示与状态一致的占位文案。
- 历史会话仍可阅读，不能用全屏错误页遮挡全部内容。
- 已断开提供“重新连接”；启动失败提供“查看详情”，进入 Runtime 设置页查看错误代码、地址、
  诊断复制和重新启动操作。
- Demo 中的四态切换器只用于视觉确认，正式产品不展示“状态预览”。

### 11.2 空状态

- 新会话空状态居中显示对话图标、“开始新会话”、输入或 `/` 指令提示和当前 Workspace。
- 不提供大面积推荐 Prompt 卡片，避免新页面显得像营销页。
- 文件、运行记录和记忆为空时，使用紧凑的一行空状态。
- 搜索无结果显示“没有匹配的会话”，保留搜索输入和关闭入口。

### 11.3 错误与危险操作

- 可恢复错误优先提供就地恢复操作，不只显示 Toast。
- Toast 只用于短期成功反馈或无需持续处理的结果。
- 删除、替换历史消息等不可逆操作使用红色说明区，并明确影响对象和不会影响的对象。
- 归档是可恢复操作，使用普通主操作；会话运行、排队或等待审批时说明为何不可归档。
- 危险确认弹窗不通过夸张插画或大面积红色制造压力，只强调事实、范围和确认按钮。

## 十二、文案规则

- 优先描述当前事实和下一步动作，例如“等待执行授权”“重新连接”“恢复会话”。
- 删除没有操作价值的文案，例如“已可靠记录”“已启用”等可由当前状态直接推断的重复说明。
- 不为思考过程或步骤虚构摘要性标题。
- 不用“主 Agent”“可靠性 Agent”等身份标题占据消息层级；必要的 Agent 类型作为弱化元信息。
- 中英文产品术语保持当前 Demo 口径：Runtime、Workspace、Run、Build、Plan、Ask、Auto、Fork、
  Token、Skills、MCP。
- 按钮使用动作短语；危险按钮必须明确对象，例如“删除会话”“删除模型”。

## 十三、键盘与可访问性

- 所有可点击行使用原生 Button；选择使用原生 Select、Radio 或具备等价键盘语义的列表框。
- 图标按钮必须有可访问名称和 Tooltip，不以图标形状作为唯一说明。
- 展开控件提供 `aria-expanded`；选择项提供选中状态；上下文占比提供可读 Token 数字。
- 弹窗具有标题关联和模态语义；Esc 关闭非阻塞浮层，点击遮罩可关闭普通弹窗。
- 审批、删除和其他关键决策不能因误触遮罩直接执行。
- 内容滚动与键盘活动项滚动必须保持同步。

## 十四、v0.14.0 使用约束

`v0.14.0` 的功能设计和界面交互设计指导应引用本文，并按真实产品范围选择页面和状态。落地时：

1. 视觉验收直接对照当前 Demo 和本文记录的精确基准，不重新发明另一套风格。
2. Demo 中存在的入口不等于版本范围；特别是后台自动化已从基准中移除，Skills 与 MCP 是否纳入
   由 v0.14.0 功能设计单独确认。
3. Demo 的 React、类型和 Mock 状态不进入正式架构承诺。
4. 正式 UI 必须区分 Runtime 权威事实、前端短生命周期视图状态和纯演示状态。
5. 组件封装、复用层次、正式样式组织和技术栈迁移全部在技术方案中决定，不写入本文。
