## 数据变更、校验和恢复

| 当前语句／调用 | 分类 | M3 执行要求 |
| --- | --- | --- |
| DELETE session_work_plans 中所有 item 已完成记录 | 旧开发控制状态清理，一次性 | 初始版本逐表记录精确预期影响；不删除正文、Run 或历史 receipt |
| DELETE session_goals WHERE state='completed' | 旧控制状态清理，一次性 | 同上，备份前后能核验；不当作每启动恢复 |
| backfill_workspace_labels：空 label 按持久化 user_directory 的 basename 回填 | 一次性数据回填 | 保留非空标签，不访问工作目录，不重新覆盖用户命名 |
| INSERT OR IGNORE session_usage SELECT sessions | 一次性派生记录补齐 | 只补缺失 Session 行；实际 usage 正文回填仍归启动恢复 |
| CREATE UNIQUE INDEX sessions_materialization_key | 一次性结构 | 在 materialization_key 列之后创建 |
| CREATE UNIQUE INDEX inputs_goal_turn | 一次性结构 | 在 goal_id/generation/turn 列之后创建；冲突停止 |
| validate_queue_payloads 的 Input 形状与 MCP 关系两项只读查询 | 持续有效性检查 | 迁移提交前和每次启动均检查；异常不自动删除／修补 |
| REQUIRED_PROJECTIONS 的各读取投影 prepare | 持续结构检查 | 迁移事务内验证目标投影，版本已对齐也检查；新模型引用替换旧 model_key |
| UPDATE conversation_recall_heads rebuilding → dirty | 每启动中断恢复 | 移至迁移后的恢复阶段，不只在升级时执行 |
| initialize_recall_fts：虚拟表及三个触发器的 IF NOT EXISTS | 每启动派生设施探测 | 保留 FTS 不可用时仅降级 Recall 的既有边界；不将 FTS 能力变成独立 schema 版本 |
| FTS 不存在时 DROP 三个旧触发器、DELETE recall_documents、UPDATE recall_heads | 派生索引重建 | 保留在每启动 FTS 恢复事务，正文不变；不能放进只执行一次的版本入口 |
| engine::open 设置 busy_timeout、journal_mode、synchronous、foreign_keys | 连接设置 | 与版本账本无关；打开既有库和备份的顺序由迁移入口统筹，不在备份前改 journal |
| engine::open 中 recover_session_deletions、repair_workspace_resources | 每启动文件恢复 | 数据库／TOML 就绪后执行，不伪装成数据库 SQL 迁移 |
| load_runtime 的 materialization/resource/attachment/history/append/child/tool/goal/usage 恢复 | 每启动业务可靠点恢复 | 沿用既有顺序，包含 child 先于 parent；版本账本不替代可靠点恢复 |

## M1 验证与剩余边界

M1 新增私有 storage/migrations，测试 manifest 验证版本前缀、逐版本原子提交、失败停止与备份。
现有完整 schema 的会话行通过同一增量列／DROP COLUMN 夹具，验证正文 generation、数量、标题和
提示词等字段保留。测试 SQL 只包含验证需要的目标投影，不冒充正式 0.25.1 初始 SQL。

实际数据库读取仍由 StorageEngine、session_loading 等原消费者承担。M1 模块由 cfg(test) 隔离，
产品版本仍为 0.25.0；M2 建立启动诊断与测试接入，M3 才注册生产 manifest、完整 SQL 和新消费者。
迁移器不能替代 M3 对未知旧表约束、索引／触发器、全部业务表数据保留与 JSONL 引用的版本级检查。
