## 二、背景、现状与版本目标

### 2.1 背景

当前正式产品采用 Desktop 与 Runtime Host 双进程架构。Desktop 安装包内置 Host，Desktop 通过
本机发现、进程级凭据和统一 HTTP／SSE／Upload／WebSocket 应用协议连接 Host；Host 内承载
Runtime、数据库、Agent、文件、Shell、MCP、用户终端和随包 Web。

现有业务层已经具备较完整的桌面使用闭环，但实现和发布仍以 macOS／Unix 为主。Windows 不能只
增加一个 MSI 外壳：用户安装后必须能够启动内置 Host、进入工作台并使用当前 Desktop 的主要能力。
同时，Windows 命令方言、路径、PTY、进程树、文件权限和安装方式与 Unix 不同，必须把平台差异
显式收敛在所属 Adapter，不能让 UI 假报成功或让 Agent 依据 Unix 历史猜测命令。

第二套会话／队列、Windows Client、独立 Host 产品或另一套应用协议。

### 2.3 版本目标

本版形成以下闭环：

```text
下载对应架构 MSI
→ 以当前用户安装 Desktop 与内置 Host
→ 首次启动并安全建立本机 Runtime
→ 进入现有工作台并完成主要 Agent 使用流程
→ 按需选择交互终端与 Agent Shell
→ 正常关闭窗口／退出 Desktop／停止 Runtime
→ 升级或卸载 Desktop 时保留用户数据
```

成功标准：

1. 同时交付 Windows x64 与 arm64 Desktop MSI；x64 支持 Windows 10 1809 及以上，arm64 支持
   Windows 11 及以上。
2. 两个 MSI 均包含可用的同架构 Runtime Host，安装后不是空壳；无需 Windows Client、npm 附件或
   另装独立 Host。
3. Windows 覆盖第六节定义的主要功能闭环，平台依赖能力能够明确报告可用、不可用或失败，不静默
   降级。
4. 交互终端与 Agent Shell 分别选择，固定支持 Windows PowerShell 5.1、CMD、PowerShell 7 和
   Git Bash；首次默认使用 Windows PowerShell 5.1，不按机器偶然安装的软件改变默认值。
5. Agent Shell 成为 Session 权威绑定，按现有输入队列有序切换；活动 Run、前序输入、切换输入和
   后续输入的 Shell 边界可验证，每个 Run 获得冻结且对模型明确的命令环境。
6. MSI 升级和卸载均不删除 Runtime Home、会话、Workspace、模型、MCP、Skills 或其他用户持久数据。
7. macOS 和现有 Linux／Host 能力不因 Windows 适配回退；平台专属实现留在 Adapter，不把 Windows
   条件分支扩散到 Agent Core。

## 三、明确非目标

v0.25.3 不包含：

- Windows Client、Windows 独立 Host 安装包或 npm win32 Host 附件；
- NSIS 安装包；
- Windows 开机／登录自启；
- Windows Credential Manager，或用普通配置文件、Desktop 偏好和明文缓存代替安全凭据存储；
- 用户填写任意可执行文件、参数或命令模板的自定义 Shell；
- WSL、WSL 发行版选择、Windows／Linux 路径映射或 WSL 文件域；
- 首版必须完成 Windows 代码签名；
- 为 Windows 重建会话、消息、Run、应用协议、关闭窗口或 Runtime 生命周期语义；
- 保证任意第三方 Skill、MCP Server、外部命令或用户已有 Unix 脚本自动跨平台可用；
- 借 Windows 适配重做 Desktop 信息架构、主题或与平台无关的业务功能；
- 施工级、企业集中部署、组策略、Microsoft Store、自动更新器或 MSI 系统级批量部署承诺。

## 四、产品、系统与分发范围

### 4.1 产品组成与架构

Windows 只交付一个 Desktop 产品，安装内容为同架构的 Tauri Desktop 与 Runtime Host。Host 继续是
独立产品进程，但不是独立分发产品。Tauri 只承载 WebView、桌面能力和 Runtime Client；Runtime Host
继续持有业务服务，`assistant-runtime` 继续持有 Session／Run 权威状态。

Windows Desktop、随包 Web、本机 Host 和远程 Host 连接继续使用同一应用协议与版本兼容判断。
Windows 不新增客户端名称白名单、开发构建豁免或平台专属认证协议。本机权限仍必须由真实本机来源、
实例私有凭据和接口权限共同证明。

### 4.2 系统和架构矩阵

| 架构 | 最低系统 | 交付物 | 人工运行验收 |
| --- | --- | --- | --- |
| x64 | Windows 10 1809 | x64 MSI + SHA-256 | 用户现有 x64 Windows 环境安装、升级、使用和卸载 |
| arm64 | Windows 11 | arm64 MSI + SHA-256 | 用户本机安装的 ARM Windows 11 虚拟机安装、升级、使用和卸载 |

一个安装包不得混入另一架构 Host，也不能以 x64 仿真启动成功替代 arm64 原生产物验收。构建流程须
可重复产出两个明确命名、版本一致的 MSI；具体构建主机、目标工具链和是否交叉编译由技术方案核验。

### 4.3 MSI、WebView2 与权限

- 只生成 MSI。安装范围以当前用户为目标，尽量不触发管理员授权；安装位置、快捷方式和升级行为由
  技术方案基于 Tauri／WiX 实测确定。
- 如果 Tauri／WiX 或 WebView2 的真实限制无法满足当前用户安装，必须在技术方案中给出证据、影响和
  可选调整并重新取得用户确认，不能静默变成系统级安装。
- WebView2 使用联网引导下载，不把完整 WebView2 Runtime 离线嵌入 MSI。离线或下载失败时给出可理解
  的安装失败／修复提示，不能让安装成功后只出现空白窗口。
- 首版允许 MSI 和可执行文件不签名。GitHub Release 与安装说明必须明确未签名及可能出现的
  SmartScreen 提示，不提供绕过系统安全检查的脚本或误导文案。
- MSI 升级保留 Desktop 偏好和 Runtime Home。卸载只移除本次安装的程序文件、快捷方式和注册信息，
  默认保留全部用户数据；不得将“卸载应用”复用为“清空数据”。
- Windows 安装包只通过 GitHub Release 分发；npm 发布范围保持 v0.25.2 的非 Windows Client／Host
  附件，不为本版新增 win32 包。

## 五、Windows Shell 目录与可用性

### 5.1 固定 Shell 类型

Windows 首版只允许以下四种类型：

| Shell 类型 | 可用条件 | 交互终端 | Agent Shell | 初始默认 |
| --- | --- | ---: | ---: | ---: |
| Windows PowerShell 5.1 | Windows 内置 `powershell.exe` 可用 | 支持 | 支持 | 是 |
| CMD | Windows 内置 `cmd.exe` 可用 | 支持 | 支持 | 否 |
| PowerShell 7 | 检测到可执行的 `pwsh.exe` | 支持 | 支持 | 否 |
| Git Bash | 检测到 Git for Windows 可嵌入 PTY 的 `bash.exe` | 支持 | 支持 | 否 |

Git Bash 不使用 `mintty.exe`，因为它会建立独立 GUI 终端且不能作为 Agent 非交互 Shell。Shell 发现只
判断固定类型的真实可执行性，不允许用户提交任意路径、参数或命令模板。可执行文件发现顺序、可信
路径和 Git Bash 参数归技术方案。

PowerShell 7 或 Git Bash 未安装时，入口显示“未安装／不可用”并禁止选择为新的实际执行环境。
已经持久绑定的可选 Shell 后续变为不可用时保留原选择并明确报错，要求用户显式切换；不得自动回退
到 PowerShell 5.1、CMD 或机器上的其他程序。重新安装并通过检测后可恢复选择。

### 5.2 交互终端

交互终端属于用户直接操作的 Host PTY 资源，与 Agent Shell 完全独立：

1. 新建终端时用户选择一个当前可用的固定 Shell；首次建议值为 Windows PowerShell 5.1。
2. 每个终端进程在创建时冻结自己的 Shell 类型。改变下一次选择不影响已经运行的终端；需要更换时
   新建终端或关闭后以另一类型重建，不在同一 PTY 中途替换解释器。
3. 终端标签、重启和 Desktop 轻量恢复记录原 Shell 类型；同一客户端切换 Session 不结束 PTY，
   Desktop 重启只按既有语义新建进程，不宣称恢复旧命令。
4. xterm 的输入、UTF-8 中文、ANSI／truecolor、尺寸变化、复制粘贴、Ctrl+C、Ctrl+D／EOF、退出码、
   输出背压和断连清理在 Windows 实机验证。
5. 关闭标签、连接失效、退出 Desktop 或停止 Host 时，Host 回收该终端可管理的完整进程树；隐藏窗口
   不关闭终端。回收失败必须可见，不能只因根进程退出就报告完成。

交互终端选择是客户端创建 Host 资源时的显式参数，不进入 Session／Run／Conversation 业务状态，
也不能改变 Agent 的执行 Shell。

### 5.3 Agent Shell 的全局默认与 Session 绑定

Agent Shell 影响模型生成命令和 `shell` 工具的真实执行，权威状态属于 Runtime：

- Windows 全局设置提供“默认 Agent Shell”，首次值为 Windows PowerShell 5.1。
- 全局值只用于创建新 Session；修改后不改写已有 Session、活动 Run、排队输入或历史消息。
- 每个 Session 持久保存自己的 Agent Shell 绑定；右侧 Session 上下文可查看并切换。
- 新建 Session 从当时有效的全局默认初始化；Fork 继承源 Session 的绑定并在之后独立变化；Clear、
  归档／恢复和 Runtime 重启保留原绑定，不重新读取全局默认。
- 平台不支持或 Shell 已丢失时，不把持久绑定解释为另一个 Shell。跨平台移动数据时遇到当前 OS
  不可执行的绑定须明确要求用户选择，不能静默改写；既有 macOS／Linux Session 的当前 Shell 行为
  必须保持。

全局默认和 Session 绑定不能放在 Desktop `localStorage` 或普通偏好里，因为随包 Web、重启恢复和
其他客户端必须观察同一 Runtime 事实。具体存储字段、迁移和跨平台表示归技术方案。

### 5.4 通过现有 Session 输入队列切换

右栏切换 Agent Shell 产生一条带结构化变更意图的可见 User Message，进入现有 Session FIFO，
不建立绕过队列的即时设置通道。产品顺序固定为：

1. 当前活动 Run 继续使用已经冻结的旧 Shell。
2. 排在切换消息之前的普通输入或控制指令继续使用旧 Shell。
3. 切换输入到达队首时，Runtime 重新核验目标 Shell 可用性，并在可靠提交边界更新 Session 绑定。
4. 切换消息对应的 Agent Run 以及排在它之后的输入使用新 Shell。
5. 目标不可用、持久化失败或并发状态不一致时，不写入成功绑定、不启动一个假定新 Shell 已生效的
   Run，并在 Conversation 中形成明确失败结果；旧绑定继续有效。
6. 重复请求遵守既有幂等语义；历史分页、上下文压缩、Runtime 重启和事件断流都从持久 Session 绑定
   恢复，不能依赖那条消息仍在当前可见窗口。

上述是产品顺序要求。现有系统在输入接纳时已建立 Accepted Run，因此“Run 创建时冻结”如何与队列
中的 Shell 变更原子衔接，必须在技术方案核对现有 Input／Run／Session mutation gate 和 Store 事务；
不得为方便实现而新增第二队列、客户端预测状态或与 Session 绑定并行的 Shell 真相。

### 5.5 Run 冻结与模型上下文

每个 Run 使用创建／装配边界冻结的单一 Shell 执行环境，至少包含：

- 当前操作系统为 Windows；
- 固定 Shell 类型及可执行命令方言；
- 路径分隔、盘符、引号、转义、环境变量和多行命令约定；
- 本 Run `shell` 工具实际使用的 launcher；
- 当前工作目录仍来自 Session 冻结 Workspace 环境。

模型上下文和真实 Shell launcher 必须由同一份冻结事实派生，不能出现“提示是 PowerShell、执行却走
CMD”或相反情况。活动 Run 不因全局设置、Session 切换或软件安装状态变化中途更换解释器。
Shell 事实必须在每次 Run 装配时可靠提供，不能只依赖历史聊天文字猜测；具体采用现有内部上下文、
ExecutionSpec 扩展还是等价的最小承载方式，由技术方案基于现有边界确定。

## 六、主要功能一致性

“主要功能一致”表示 Windows Desktop 可以完成当前产品的主要工作闭环，并非所有平台专属细节完全
相同。以下能力均须核查、适配和回归：

| 能力组 | Windows 交付口径 |
| --- | --- |
| 会话与执行 | 新建／首次物化、消息、流式响应、队列、审批、停止、失败、重试、恢复、Fork、Clear、归档／恢复、标题和引用可用 |
| 模型与设置 | 服务商、在线模型、固定参数、默认／会话模型、思考强度、连接验证、配置重载和错误反馈可用 |
| 权限与记忆 | Plan／Build、Ask／Auto、Session／Workspace／Global 权限、审批、Persona、Pinned Memory 和 Recall 可用 |
| Workspace 与附件 | 中文、空格和盘符路径可登记；多目录、附件上传、图片粘贴、下载、系统打开和目录揭示按客户端／Host 边界正确 |
| 文件与预览 | Host 文件列举、文本／图片／PDF 预览、file URI、工具文件和会话资源可用；不支持类型明确回退 |
| 用户浏览器 | WebView2 多标签、导航、前进／后退／刷新、弹窗、下载、缓存、遮挡和重启恢复按既有产品语义工作 |
| 交互终端 | 四种固定 Shell 的可用项可创建，PTY 输入输出、尺寸、取消和进程清理可靠 |
| Agent Shell | 全局默认、Session 绑定、队列切换、Run 冻结、模型上下文和四种方言执行闭环可用 |
| MCP | Streamable HTTP 保持；stdio 覆盖 Windows 常见 `.exe`、`.cmd`、`.bat`、`node`、`npx`、Python 启动形态并正确清理进程树 |
| Skills 与 Agent | Skills 发现／启停／激活、主控 Session、子 Agent、WorkPlan、Goal 和长任务继续使用正式 Runtime |
| 本机接入 | 内置 Host 静默启动、本机 discovery、自动认证、版本准入、启动诊断、打开 Web、受控停止／重启可用 |
| 远程接入 | Windows Desktop 能连接既有 HTTP／HTTPS Host；未接入 Credential Manager 时不假报记住密码 |
| 生命周期 | 托盘、显示窗口、关闭行为设置、退出 Desktop、退出并停止 Runtime、单独停止／重启 Runtime 边界一致 |
| 持久化 | 新库、既有兼容库升级、独立备份、启动失败诊断、重启恢复及用户数据保留可用 |

平台相关第三方能力必须如实报告：例如系统缺少 `rg`、PowerShell 7、Git Bash、某个 MCP 命令或某个
Skill 依赖时，显示具体平台／依赖不可用，不把“没有结果”“连接中”或泛化 Agent 失败冒充成功。

### 6.1 Windows 路径与文件

- 默认 Runtime Home 继续位于当前用户主目录下的 `.ez-assistant`，不因 Windows 再建 AppData 数据副本；
  开发和自动化仍使用显式隔离 Home。若技术验证发现系统约束要求调整，须作为数据迁移决策重新确认。
- 产品自身支持盘符绝对路径、反斜杠、中文、空格和大小写不敏感语义；长路径、UNC、目录联接、
  junction 和其他 reparse point 以安全核查结果明确支持或拒绝，不能按 Unix symlink 规则猜测。
- Windows ACL 和当前用户身份替代 POSIX mode／uid 检查，但安全目标不降低：Runtime Home、discovery、
  token、配置、数据库、日志和 staging 文件不能被不应访问的其他用户轻易读取或替换。
- 文件工具、Host 文件浏览、附件、Skills、MCP cwd 和 Desktop 系统打开使用一致的 Windows 路径事实；
  Git Bash 如需路径转换，只限 Shell Adapter，不改写 Workspace 的规范 Windows 路径。

### 6.2 用户浏览器与 WebView2

Windows 使用系统 WebView2 承载主 WebView和用户浏览器 child WebView。网页仍不得获得主 WebView 的
bootstrap、Tauri command 或本机文件权限。平台适配须覆盖窗口缩放、原生子视图遮挡、关闭后媒体／
下载停止、URL 读取和弹窗处理；若 Windows 无法提供 macOS 同等截图能力，可以保留中性占位，但不得
导致正常网页被销毁、错误或重新登录。

### 6.3 生命周期和无自启状态

Windows 继续使用现有 `close_behavior`：隐藏到托盘或退出 Desktop 由用户设置决定，不按平台写死。
退出 Desktop 默认不停止 Runtime；“退出并停止 Runtime”和“停止 Runtime”继续明确展示对活动 Run、
排队输入和审批的影响。

Windows 本版不做自启。若共享界面或跨平台接口需要显示该能力，必须显示“不支持／本版未提供”或
隐藏不可操作入口，不能保存一个不会生效的成功状态。系统注销、关机和 MSI 升级触发的进程终止须
尽可能进入现有受控关闭，并在无法保证时依赖既有恢复语义，不宣称所有未完成工具会自动重放。

### 6.4 远程密码限制

Windows 远程 Host 连接允许用户当次输入密码并正常连接，但不提供“记住密码”。界面采用隐藏、禁用
还是带说明的不支持状态，由交互指导结合现有入口确定。无论采用哪种形式，都不得把密码写入
Desktop 偏好、`localStorage`、日志、URL、命令行、环境变量或普通配置文件。

## 七、模块边界与契约影响

| 模块 | 本版职责 | 不应承担的内容 |
| --- | --- | --- |
| `apps/desktop` Web UI | 展示 Windows 平台、Shell 可用项、Session 绑定、切换队列结果和平台诊断；复用现有工作台 | 不自行发现 Shell 可执行文件，不预测绑定成功，不保存 Runtime 权威 Shell 状态 |
| `apps/desktop/src-tauri` | Windows 窗口／托盘、Host discovery／启停、系统打开、文件选择、WebView2 child WebView 和 MSI 桥接 | 不装配 Runtime、Agent 或第二份 Session；不保存远端密码 |
| `assistant-protocol` | 承载固定 Shell 身份、可用性投影、全局默认／Session 绑定、切换意图和必要终端参数 | 不承载可执行文件任意路径、进程句柄、Windows API 对象或 Tauri 类型 |
| `assistant-runtime` | 持有全局默认和 Session 绑定；按 FIFO 原子切换；为每个 Run 冻结 Shell 执行事实；处理 Fork／Clear／恢复 | 不直接调用 Windows API、ConPTY、注册表或扫描 PATH |
| `apps/runtime-host` | 实现 Windows Home、锁、discovery、ACL、存储、文件、Shell 目录、PTY、MCP stdio、信号／关闭和具体工具装配 | 不复制 Session Shell 状态机，不建立 Windows 专用 Runtime 业务层 |
| `agent-tools-local` | 按上层传入的 launcher 执行命令，维护输出、超时、取消、环境过滤和 Job Object 进程树语义 | 不决定全局默认、Session 绑定、UI 选项或模型提示；不解析／重写模型命令 |
| Tauri／发布脚本 | 构建同架构 sidecar、两个 MSI、WebView2 联网引导、版本与 SHA-256 清单、GitHub Release 附件 | 不发布 Windows Client／npm Host，不自动修改或删除 Runtime Home |

Agent Core、模型 Provider、Conversation 类型和工具调用协议原则上不增加 Windows 分支。若模型需要
Shell 环境，应由 Runtime 在现有执行规格／内部上下文边界形成一份冻结事实；Core 只消费已经编译的
结果。Shell 切换的可见消息与 Session 绑定是两个用途：消息记录用户意图和上下文变化，绑定才是
执行权威，二者不得互相反推。

### 7.1 最小新增结论

本版确需新增或扩展的事实只有：

1. 固定、平台可判定的 Shell 类型与可用性；
2. Windows 全局默认 Agent Shell 和每 Session 权威绑定；
3. 经现有 FIFO 处理的 Shell 切换意图及结果；
4. 每个 Run 的冻结 Shell 执行上下文；
5. 用户终端创建时的 Shell 类型；
6. Windows 平台基础 Adapter 和 MSI 构建／发布入口。

不新增 Shell 配置文件、可执行模板、第二队列、Session Shell 事件日志、后台 Shell daemon、Windows
专用数据库、客户端绑定缓存或独立 Host 控制服务。技术方案必须再次回答：删除任一新增机制后，
现有事实是否已经足够；答案为是时删除该机制。

## 八、关键取舍

| 取舍 | 理由 |
| --- | --- |
| Desktop + 内置 Host，而非先做空壳 MSI | Windows 交付必须能完成主要业务闭环，符合现有正式产品架构 |
| x64／arm64 同版交付 | 用户明确要求并具备对应手工验收环境；架构产物不能互相替代 |
| 仅 MSI、当前用户安装优先 | 收敛首版安装面，减少 NSIS 与系统级安装的并行语义 |
| WebView2 联网引导 | 避免把完整 Runtime 嵌入安装包；离线限制通过安装反馈明确表达 |
| 首版允许不签名 | 先完成真实兼容闭环；风险通过 Release 和 SmartScreen 说明显式承担 |
| 交互终端与 Agent Shell 独立 | 前者是用户 PTY，后者影响模型和工具执行；强制联动会破坏正在运行的终端或 Session 可重复性 |
| 四种固定 Shell、PowerShell 5.1 初始默认 | 提供可验证的命令方言，不因机器偶然安装项改变行为，不开放任意执行模板 |
| Session 持久绑定、Run 冻结 | 保证重启、压缩、排队和设置变更后执行环境仍可解释 |
| Shell 切换复用现有 FIFO | 保持同一 Session 输入排序和可靠提交，不引入即时旁路或第二状态通道 |
| 可选 Shell 消失时失败而非回退 | 避免模型提示、用户预期和真实命令解释器不一致 |
| Windows 平台差异限制在 Adapter | 保持 Runtime／Core 业务边界和 macOS／Linux 行为稳定 |
| Windows 暂不记住远程密码 | 没有 Credential Manager 时宁可空置，也不降低凭据存储安全性 |
| 升级／卸载保留数据 | 程序生命周期与 Runtime 用户数据生命周期分离，防止卸载误删业务内容 |

## 十、风险、兼容性与后续设计要求

### 10.1 主要风险

| 风险 | 处理要求 |
| --- | --- |
| Host 大量使用 Unix 文件与进程语义 | 技术方案按 Home、锁、discovery、配置、文件、数据库和子进程逐项建立 Windows 等价安全目标；不能只移除 `cfg(unix)` |
| 当前用户 MSI／WebView2 行为受 WiX 和系统状态影响 | 在代码开发前以最小原型核验安装范围、升级码、联网引导和双架构；不成立时先修订设计并确认 |
| ConPTY／portable-pty 在取消和关闭时只杀根进程 | 实测 Ctrl+C、前台子进程、后台后代、断连和 Host shutdown；必要时由明确 owner 使用 Job Object，不以 `kill()` 返回成功作为完成证据 |
| 四种 Shell 的命令与编码差异 | 每类固定 launcher 和模型方言，覆盖中文、引号、管道、环境变量、多行、退出码与路径；不做文本互译器 |
| Session 切换与既有 Accepted Run 时机冲突 | 技术方案核对 Input／Run 创建、Queue claim、Store 原子操作和恢复；维持功能顺序，不新增第二队列或客户端预测 |
| Windows 路径和 reparse point 容易越界 | 使用 Windows 文件身份／句柄语义设计；盘符、UNC、junction 和长路径分别测试，不把 canonicalize 当永久授权 |
| `rg` 和第三方 MCP 命令不是系统内置 | 明确随包、检测或不支持策略及诊断；不得静默下载安装，也不得借 Client npm 附件提供 |
| WebView2 child WebView 与 HTML 浮层关系不同 | 实机验证遮挡、下载、弹窗、媒体和释放；平台能力不足时采用可见降级，不制造第二浏览器实现 |
| 未签名 MSI 影响安装信任 | 发布页明确风险并记录实机路径；本版不把签名假装已完成，后续可独立加入签名流程 |
| arm64 构建成功但运行环境差异未覆盖 | 强制用户 ARM Windows 11 虚拟机手工安装验收，不能用编译、单测或 x64 仿真替代 |
| Windows 改造破坏 macOS／Linux | 平台 Adapter 分层、共用契约测试与原平台回归共同作为版本门禁 |

### 10.2 必须进入技术方案的核查项

## 十一、当前待确认结论

本功能设计将输入讨论收敛为一个完整 Windows Desktop 版本，建议确认以下基线后再进入技术方案：

1. Windows 交付物固定为 x64／arm64 两个 MSI，Desktop 均内置同架构 Host；
2. 初始交互终端和 Agent Shell 都以 Windows PowerShell 5.1 为建议／默认，但两类选择完全独立；
3. 交互终端按每个新建进程冻结类型；Agent Shell 则为 Runtime 全局默认 + Session 持久绑定；
4. 成功的 Session Shell 切换消息自身对应一次使用新 Shell 的 Agent Run，失败时不启动假定已切换的 Run；
5. Fork 继承 Agent Shell，Clear／归档／恢复保留绑定，可选 Shell 消失或跨平台不可用时不自动回退；
6. Windows 默认 Runtime Home 继续使用当前用户主目录下 `.ez-assistant`；
7. 功能设计确认后，下一步先编写并确认技术方案，再编写并确认界面交互设计指导，之后才进入开发计划。

当前没有代码实现授权；本稿确认也不等于授权开始任何开发里程碑。
