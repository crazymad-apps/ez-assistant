## 二、台账与实施原则

1. 按 M0—M8 顺序实施。开发计划确认后，开始 M0 前才把版本状态从 `计划中` 更新为 `开发中`。
2. 每个里程碑执行“核查 → 实现 → 最小有效验证 → 记录实际结果 → 标记 `🟨 待确认` → 汇报 → 等待
   用户确认”；未确认不得开始下一里程碑。
3. 每个里程碑开始前重新读取涉及语言规范、模块约束和 `Agent 系统技术架构`，核对当前工作树与用户已有
   改动；不主动 commit/push，不清理无关文件。
4. Runtime 持有 MCP 配置解释、活动 Registry、权限决策、Session 队列与 Conversation 权威事实；Host
   只持有安全文件、Transport、子进程、HTTP 和图片物化 Adapter；Desktop 只发送意图和展示脱敏投影。
5. `rmcp` 与进程监督依赖只进入 Runtime Host，JSON Schema 实现只进入 Runtime 私有 MCP 模块；不新增
   MCP crate，不改 `agent-core`、`agent-model` 或 `agent-types` 契约；`agent-tools` 只增加通用输出状态钩子，
   不引入 MCP 类型或特判。
6. 模型原生 ToolSet 始终只增加固定的 `discover_mcp_tools` 与 `call_mcp_tool`；不平铺实际 MCP Tools，
   不做跨 Server 搜索，也不引入加载账本、目录 revision 或活动 Run 自动通知。
7. `call_mcp_tool` 必须在远端调用前解析成实际 Server + Tool 授权事实，并经过现有权限、审批、审计和
   started receipt；Server 自报注解只能展示，不能自动放行。
8. `/mcp refresh` 复用 Session 可靠队列并严格服从阻塞顺序，不创建 Run、不越过审批、不支持轮内插入；
   配置保存和活动连接刷新保持两个阶段。
9. 所有 SQLite migration、权限文件升级、`mcp.json` 替换、失败注入和恢复测试只操作 `TempDir`、内存
   Store 或隔离 Runtime Home。本计划不授权打开、迁移、覆盖或删除用户实际 Runtime Home；如后续需要
   实机验证真实数据，必须先逐项核对目标、独立备份并再次取得用户确认。
10. 自动测试优先使用确定性 ModelService 与本地受控 MCP fixture。访问公网、调用真实 Provider 或使用
    第三方 credential 只在版本验收阶段另行取得明确授权，凭据不得进入仓库、命令输出或测试快照。
11. Resources、Prompts、OAuth、旧 HTTP+SSE、项目级 `.mcp.json`、插件市场和刷新自动监听不进入任何
    里程碑；若实现中出现这些能力，视为范围偏离。
12. 跨持久化事实、Registry 交换、连接 retire、Command 提交和权限重校验的非显然逻辑必须同步补充中文
    注释，写清 owner、可靠点、失败恢复、取消和锁顺序，不能留到最终 Review 再补。

- 保持 message 与 command 载荷互斥、Command 不创建 Run、Selection 不复制动态目录的存储不变量；
- 覆盖旧 schema、重复 migration、协议 JSON 往返、默认字段、无效组合和 Store 恢复测试；
- 新 capability 在对应实现可用前保持关闭，Desktop 和现有 Host 行为不发生切换。

Review 重点：additive migration 是否仍会覆盖旧行；Command 是否被伪装成 Run；Selection 是否复制 Catalog；

### M1：配置管理与双 Transport 候选连接

前置依赖：M0 已确认。

目标：完成独立 `mcp.json` 的安全管理和 Host 私有连接 Adapter，使同一候选连接流程同时支持 stdio 与

交付范围：

- 按已确认 feature 引入并固定 `rmcp`、`jsonschema` 和 `process-wrap`，第三方类型不越过 Host/Runtime
  私有边界；
- 实现 `McpConfigSource` 与 `McpConfigStore`，覆盖常见 `mcpServers` 导入、规范化、未知字段保留、
  expected revision、批量原子写入和 secret Keep/Replace/Remove；
- 复用 Runtime Home 安全文件约束实现 `mcp.json` 原子替换与权限校验，管理读响应和诊断全部脱敏；
- 实现 Host 私有 `McpConnectionFactory` 与连接对象，完成 current/legacy 生命周期建立、有界
  `tools/list` 分页和受控关闭；
- stdio 使用无 Shell 启动、受控环境、行大小限制、stderr drain、进程组或 Job Object；HTTP 实施
  HTTPS/loopback、禁 redirect、受控 header、消息大小和不自动重放边界；
- 管理 API 可用当前未保存草稿建立临时候选、返回脱敏测试结果并立即关闭，不保存或换入连接；
- 使用本地 fixture 覆盖正常、零 Tool、分页、非法配置、超限、取消、超时和关闭。

建立、全部 Tool 列举和有界关闭；测试连接不留下配置、活动 Registry、子进程或 credential 泄漏。

Review 重点：是否经 Shell 启动 stdio；是否隐式继承 Runtime secret；HTTP 是否允许 redirect/非安全地址；

### M2：Registry、Schema 与连接生命周期

前置依赖：M1 已确认。

目标：建立 Runtime 唯一的 MCP 活动目录与连接 owner，完成候选构建、Schema 编译、原子交换、调用租约、
结果转换和受控退出，为模型网关提供稳定执行底座。

交付范围：

- 实现进程内 `McpRegistry`、启动 bootstrap、全量/单 Server 内部刷新入口和安全诊断投影；
- 对 Tool 目录实施分页循环、重复名称、数量、Schema dialect/外部 ref、节点、深度、正则和总大小限制；
- JSON Schema 编译与输入/输出校验使用有界 blocking 并发和超时，不触发网络或文件 resolver；
- 候选完整成功后才按 Server 原子换入；失败保留旧连接与目录，禁用/删除明确移除，零 Tool 仍是有效连接；
- 通过 lease + retire 保证旧调用完成、新调用只取新连接，所有锁内不 await，Runtime 关闭顺序可收敛；
- 实现单次 Tool 调用的文本、JSON、图片、ResourceLink、嵌入文本资源、空结果、远端错误和不支持内容转换；
- 图片复用现有 Session 私有 tool-image 生命周期，不新增 MCP 附件或资源存储；
- 覆盖并发刷新、部分失败、连接失效、调用取消/超时、旧 lease 释放和子进程树清理测试。

验证入口：


开始调用可完成，待开始调用只用新状态；所有内容都有明确安全映射或错误，关闭后无孤儿连接与子进程。

Review 重点：目录或连接是否出现第二 owner；是否持锁执行 I/O；候选失败是否误替换旧状态；超时后
blocking 工作是否无限累积；投影失败是否错误宣称远端未执行。

实际结果（2026-09-03）：

### M3：MCP 调用权限与审批闭环

目标：让固定 `call_mcp_tool` 在现有工具循环内解析实际 MCP 身份、完成参数校验和权限审批，并只在获得
授权且可靠记录 started fact 后调用远端。

交付范围：

- 实现 `call_mcp_tool` 的无副作用 resolve、披露 scope 校验、当前目录查找、输入 Schema 校验和
  `McpAuthorizationFacts`；
- 权限 schema 1 继续读取；首次写入 MCP 规则时在现有 CAS/原子替换路径升级为 schema 2，并支持设计
  确认的 exact Server/Tool 与手工通配范围；
- 复用 Plan/Build、Session/Workspace/Global、Deny/Ask/Allow、Auto fallback、AllowOnce 和持久审批顺序；
- 审批默认只生成精确 Server + Tool 规则，明确后续所有参数；Delegation 继续使用 General；
- execute 前重校当前目录并取得 lease，成功交换/删除 Server 时只失效该 Server 尚未获准的审批；
- Approval、Tool Activity、历史工具详情和审计投影携带实际 Server、原始 Tool、arguments 与不可信注解，
  日志和错误只保留稳定脱敏事实；
- 覆盖猜测网关参数、非法 Schema、Deny、Ask/Auto、Plan/Build、精确规则升级、审批中刷新和 started receipt
  顺序测试。

验证入口：

```bash
cargo test -p assistant-protocol -p assistant-runtime -p assistant-runtime-host
cargo run -p assistant-protocol --example export_typescript -- --check
cargo clippy -p assistant-protocol -p assistant-runtime -p assistant-runtime-host \
  --all-targets --all-features -- -D warnings
```

完成判定：任何 MCP 调用在远端前都能证明实际身份、参数有效、Assistant ToolCall 已落账且权限已通过；
拒绝、刷新竞态和持久规则均不扩大授权范围，稳定错误可区分远端是否可能已执行。

Review 重点：是否按通用网关名授权；是否相信 Server annotations；是否出现 Any Server + Exact Tool；
是否在审批前取得连接 lease；是否把 credential 或完整远端错误写入审批以外的普通投影。

实际结果（2026-09-03）：

- 固定 `call_mcp_tool` 已按当前目录解析真实 Server + raw Tool 身份并冻结披露范围，权限 schema 1 保持可读，
  首次持久化 MCP 精确规则才原子升级为 schema 2；Plan/Build、Deny/Ask/Allow、Auto 与现有作用域均复用；
- 参数在权限判断前校验，审批后和取得执行 lease 前再次校验；刷新只取消目标 Server 尚在等待的审批，非法
  参数、显式 Deny 和刷新竞态均已回证不会调用远端；
- Approval、活动与历史详情投影实际 MCP 身份、arguments 及不可信 annotations；远端 `isError` 保留原始
  多段内容并以失败状态结算，事件测试确认 ApprovalResolved → ToolStarted → ToolCompleted 顺序；
- 协议生成检查、三包全量测试和三包 all-target/all-feature 严格 Clippy 全部通过。

### M4：按服务发现与 Run 级模型披露

前置依赖：M3 已确认。

目标：完成默认 Server 目录、单 Server 工具发现和用户手选 Server 定义注入，使模型在不平铺动态工具的
前提下完成“选 Server → 发现 → 调用”或“用户手选 → 直接调用”两条 Runtime 路径。

交付范围：

- 在 Runtime `RunToolAssembly` 中按 Run 冻结两个固定网关和 `McpDisclosureScope`，父 Agent 与该 Run
  派生子 Agent 复用同一贡献；
- 默认 Run 只注入当前可披露 Server 的隐藏 `InternalContext` 目录，不写 Conversation 或 System Prompt；
- 实现 `discover_mcp_tools` 的单 Server summary/full、可选 query、稳定排序、Deny 过滤和有界分页；
- Runtime 接受可选 MCP Selection，与 Input/UserMessage/首次 Run 原子绑定，并在 Run 编译时生成
  256 KiB 内的 full 或 summary 定义上下文；
- 手选 Run 只允许所选 Server，提交前/Run 前失效明确失败，不自动改选；

## 七、计划风险与调整规则

- 若 `rmcp 3.2.0` 的生命周期、取消、Streamable HTTP 或 stdio 关闭事实与技术方案不一致，M1 停止并以

  真实调用方和失败证据；不得直接新增通用任务平台、第二权限系统、Catalog 或 Agent 公共 SPI。
