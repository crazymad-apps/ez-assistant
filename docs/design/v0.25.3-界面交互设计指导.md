# v0.25.3 界面交互设计指导：Windows Desktop 兼容

## 一、设计信息

- 版本：v0.25.3；状态：已确认（2026-09-11 用户确认）；日期：2026-09-11。
- 依据：[功能设计](v0.25.3-功能设计.md)（10.3 节清单）、[技术方案](v0.25.3-技术方案.md)。
- 影响：现有 Desktop 工作台的少量新增控件（终端 Shell 选择、Agent Shell 设置与切换、
  平台诊断展示）与 Windows 平台状态投影；不重做信息架构、主题或导航。
- 本文固定用户可见行为、状态与验收口径；协议字段、存储与 launcher 细节以技术方案为准。
  示例为设计示意，非实际运行结果。

## 二、页面与入口

本版全部交互落在现有入口内，不新增顶层页面：

| 入口 | 位置 | 本版变化 |
| --- | --- | --- |
| 新建交互终端 | 资源工作区终端面板（`ResourceTerminal`）的新建流程 | 新增 Shell 类型选择步骤 |
| 终端标签 | 终端面板标签 | 展示该终端冻结的 Shell 类型徽标 |
| 全局默认 Agent Shell | 设置 → Runtime（本机与客户端附近） | 新增"默认 Agent Shell"设置项 |
| Session Agent Shell | 右栏上下文面板（`ContextPanel`）"会话"分区 | 新增当前绑定展示与切换入口 |
| 切换结果 | 会话消息流 | 复用现有控制指令结果消息形态 |
| 记住密码 | 远程连接表单（`RuntimeConnectionForm`） | Windows 无变化（现有代码已仅 macOS 渲染），本文仅固化口径 |
| 平台诊断 | 设置 → Runtime 诊断页 + 各能力内联状态 | Windows 平台缺失项的明确展示口径 |

## 三、布局与信息结构

### 3.1 交互终端工具栏

2026-09-13 用户修订：新建资源标签 → 终端，立即使用 Host 平台默认交互 Shell 打开；
不展示创建表单，不记忆上次选择，不读取默认 Agent Shell。Windows 沿用 Host 默认 PS5.1，
Unix 沿用现有系统默认登录 Shell。

终端内容上方使用与浏览器相同的 42px 工具栏，左侧紧凑 Shell 选择控件展示 Host 确认的类型。
可用类型可切换；未安装项禁用并给出原因。切换说明明确“结束当前终端进程并重新打开”。
启动/切换/关闭期间禁用选择，旧进程清理成功后才用所选类型在原标签、原来源目录重建；
清理失败显示错误，不创建并行 PTY。清空旧终端输出，不把旧命令或运行状态迁移到新 Shell。

### 3.2 终端标签与类型徽标

每个终端标签在标题旁显示 Shell 类型短徽标：`PS 5.1`／`CMD`／`PS 7`／`Bash`。
悬停展示完整类型名称；切换操作放在终端顶部工具栏，成功创建后更新徽标。
每个 PTY 的解释器仍在创建时固定，工具栏切换通过关闭旧 PTY、新建所选类型实现。
### 3.3 全局默认 Agent Shell（设置）

设置 → Runtime 下新增设置项，与"关闭主窗口时"等本机行为设置同级呈现：

```text
默认 Agent Shell   [Windows PowerShell 5.1 ▾]
                   新会话创建时使用的 Shell；修改不影响已有会话。
```

- 下拉选项来自 Host Shell 目录投影；未安装类型禁用并标注"未安装"。
- 当前选中项如果因卸载变为不可用：设置项显示为无效态（"Windows PowerShell 7（不可用）"），
  不自动改选；用户需手动改选后保存。保存仅影响之后新建的会话。
- macOS／Linux 平台该设置项显示当前平台 Shell（`/bin/sh`）且不可更改（本版 Unix 无多
  Shell 绑定能力），行内说明"当前平台使用系统默认 Shell"。

### 3.4 Session Agent Shell（右栏会话分区）

右栏“会话”分区内，基本属性下方用分割线隔开独立一行，选择控件在左，刷新按钮在右：

```text
[Windows PowerShell 5.1 ▾]               [刷新]
```

- 点击选择控件弹出四种固定类型的列表（同3.1的可用性规则）；可访问名称保留“切换会话Agent Shell”。
- 切换和刷新共用MCP/Skill的控制指令流程，不创建Run、不触发模型回复，只展示控制结果。
- 选择后立即提交切换指令并关闭弹层；消息流中出现一条待处理的控制指令条目
  （复用现有队列中指令的展示形态：排队中／执行中）。
- 排队期间该行显示"切换排队中 → 目标类型"；不锁定消息输入。
- 会话当前绑定值始终来自 Host 投影，客户端不本地预测成功。
- 2026-09-13：增加“刷新 Shell 环境”操作，显式重新确认当前显示的绑定类型，复用该类型的既有切换指令和输入队列。同类型成功结果显示“已刷新 Agent Shell”。运行中允许提交；已有 Shell 变更排队时暂不开放刷新，避免将旧显示类型误作后续目标。普通输入不触发环境探测。

### 3.5 切换结果消息

消息流中的切换结果复用现有控制指令结果消息形态：

```text
✅ 已切换 Agent Shell：Windows PowerShell 5.1 → PowerShell 7
   此消息之后的命令将以 PowerShell 7 语法执行。

⛔ 切换 Agent Shell 失败：PowerShell 7 不可用（未检测到 pwsh）
   当前会话仍使用 Windows PowerShell 5.1。
```

成功消息必须同时体现"从什么切到什么"与"从哪条消息起生效"，与功能设计 5.4 的顺序
语义一一对应。失败消息必须保留旧绑定事实。

## 四、交互流程

### 4.1 交互终端创建（Windows）

新建终端 → 沿用来源工作目录，以平台默认 Shell 打开 PTY 标签 → 按需在顶部工具栏切换并重建。
异常路径：Host 未就绪／创建失败按现有终端错误口径展示；类型失效见 6.2。

### 4.2 Agent Shell 切换（全平台入口，Windows 首次生效）

右栏 [切换] → 选择目标类型（禁用不可用项）→ 提交 → 队列条目（排队中 → 执行中）→
结果消息（成功／失败）→ 右栏绑定值更新（以 Host 投影为准）。
活动 Run 期间允许提交切换（排队语义本就如此）；不弹"当前有任务运行"的额外确认——
排队顺序保证了活动 Run 用旧 Shell 完成，无需用户干预。

### 4.3 新建会话

新建会话时绑定值取当时的全局默认（Host 侧行为），UI 不在新建流程中再问一次 Shell；
用户随后可经 4.2 切换。跨平台不可执行绑定（如数据迁移后）见 6.3。

## 五、视觉与组件规范

- Shell 选择列表、徽标、设置下拉全部复用现有组件（`SelectionPopover`／`Dialog`／
  标签样式），不新增组件类型；本版不引入平台专属视觉风格。
- 类型名称统一文案：`Windows PowerShell 5.1`／`CMD`／`PowerShell 7`／`Git Bash`；
  徽标短文案：`PS 5.1`／`CMD`／`PS 7`／`Bash`。同一类型在终端、设置、会话、消息流
  中名称一致。
- "未安装／不可用"用现有禁用态文案样式，不使用红色警示（不是错误，是环境事实）。

## 六、状态与异常

### 6.1 平台与依赖诊断

设置 → Runtime 诊断页在 Windows 上展示平台行（`Windows · x64/arm64`）及依赖状态清单
（`rg`、PowerShell 7、Git Bash 等：可用／未安装）。各能力内部不重复诊断面板，但涉及
依赖缺失的能力（文件搜索无 `rg`、MCP 命令启动失败）在自身错误信息中明确标注
"缺少依赖：xxx"，不显示泛化的"无结果"或"连接中"。

### 6.2 已创建资源依赖失效

- 已打开终端的 Shell 可执行文件被卸载：不影响已运行进程；重启该终端标签时按创建类型
  重新拉起，失败则给出"该终端类型已不可用（原因）"并引导新建其他类型终端。
- 会话绑定的 Shell 被卸载：绑定保留，右栏显示"当前绑定不可用"警示（黄色），Run 装配
  失败时消息流出现明确错误（功能设计 5.1）；重新安装并恢复可用后警示自动消失，不回退。

### 6.3 跨平台绑定不可执行

打开绑定为当前 OS 不可执行 Shell 的会话（数据迁移场景）：会话可打开浏览，右栏绑定行
显示"当前系统不可用"，发送首条消息前弹出一次性说明（该会话绑定的 Shell 在本系统不可
执行，需切换后继续），提供直达切换入口。不静默替换，不阻止浏览历史。

### 6.4 远程密码（Windows）

远程连接表单不渲染"记住密码"（现有 `platform === "macos"` 条件已满足），密码仅当次
使用；不显示"为什么不支持"的常驻说明，避免噪音。macOS 行为不变。

### 6.5 自启与 Windows 特性空置

Desktop 当前无自启入口（自启属于 v0.25.2 Client CLI 能力），Windows Desktop 无需展示
任何自启状态；若后续出现跨平台自启统一入口，Windows 必须显示"本版未提供"禁用态，
不得保存假成功。MSI 未签名／WebView2 联网引导属于安装期与 Release 说明文案，不进入
应用内 UI。

## 七、验收口径

对应功能设计验收表的 UI 侧条款：

| 验收 | UI 口径 |
| --- | --- |
| A20 | 新建终端列表与设置下拉的可用／禁用状态与 Host 目录一致；不出现任意路径输入 |
| A21 | 每个终端标签的类型徽标正确且运行期间不变 |
| A23 | 全局默认修改后仅新会话变化，已有会话右栏值不变 |
| A24 | 切换的排队条目、结果消息、右栏值三处一致，顺序语义与消息流可对照 |
| A25 | 失败消息保留旧绑定；重启后右栏值来自持久绑定 |
| A26 | Fork 后新会话可独立切换；Clear／恢复后绑定不变 |
| A31 | `rg`／可选 Shell／MCP 依赖缺失的展示符合 6.1，无静默失败文案 |
| A19 | Windows 远程连接无"记住密码"，连接流程本身与 macOS 一致 |
| A36 | Windows 安装与设置中无自启入口或为明确的未提供状态 |

## 2026-09-13 Windows 标题栏验收修订
- 用户要求Windows窗口与应用整体标题栏一致：隐藏原生菜单栏及原生标题栏，在应用标题栏右侧提供最小化、最大化/还原、关闭按钮。
- 复用既有Linux窗口控制、原生maximize事件和request_desktop_close流程；不新增关闭/退出Runtime语义。macOS保留现有原生红绿灯。
- 连接页与主工作区均有窗口控制，不能使尚未连接时窗口无法关闭。Windows配置decorations=false，原生应用菜单不挂载，托盘菜单及Runtime状态不受影响。
