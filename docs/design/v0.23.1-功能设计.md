## 二、现状与目标

现有 MCP 已提供配置管理、stdio/Streamable HTTP、按 Server 发现、固定调用网关、审批、工具记录
和图片结果物化。浏览器接入应首先验证这些能力能否直接组合使用，不因外部工具具有页面状态而
默认增加产品浏览器管理系统。

本版建议使用 **本机已安装的 Chrome + Playwright MCP，通过 stdio 接入**，交付两种用法：

| 用法 | 用户目标 | 页面与登录状态来源 |
| --- | --- | --- |
| 助手专用浏览器 | 让助手打开网页并完成任务 | 独立浏览器数据目录，可人工登录并保留状态 |
| 当前浏览器 | 让助手继续处理已经打开的页面 | 用户通过官方扩展选择的现有 Chrome 页面 |

Playwright MCP 官方说明覆盖持久数据目录、页面结构读取和基本操作；官方扩展说明覆盖连接现有
浏览器及标签选择。以上是选型依据，不代表本项目已完成真实集成验证。
参考 [Playwright MCP](https://github.com/microsoft/playwright-mcp) 与
[官方扩展](https://github.com/microsoft/playwright/tree/main/packages/extension)。

本版实际交付为：

1. 两份经过验证、可经现有 MCP 管理页导入的配置样例，区分专用浏览器和当前浏览器。
2. 一份本地环境准备、连接、使用、停止、重新连接及故障处理说明。
3. 正式 Runtime 与 Desktop 的两种模式验收证据，包括真实浏览器和至少一个真实模型任务。
4. 实测确有缺口时的最小修复；若现有机制已足够，文档、配置和验证也可构成版本交付。

## 三、功能范围与使用路径

### 3.1 安装与配置

- 复用现有“设置 → MCP”新增或导入功能；两种模式使用名称和业务说明明确不同的普通 Server。
  样例名称建议为“浏览器 · 专用”和“浏览器 · 当前”。这些名称不是 Runtime 内置特殊身份。
- 用户只需配置所需模式，也可以同时配置两种。每次任务建议通过 `/mcp` 明确选择对应 Server；
  这沿用既有本次输入/Run 的范围限制，不增加会话永久“当前浏览器”设置。
- Chrome、Node.js 和 MCP Server 使用外部安装环境。交付说明固定已验证的 Server 版本、
  支持的 Node.js 版本和扩展版本记录，避免默认随 `latest` 自动改变行为。
- 样例标出需要替换的绝对路径；桌面启动环境下应能找到可执行程序，不能仅证明终端命令可运行。
- 配置保存、连接测试、`/mcp refresh` 沿用 `v0.23.0` 的语义；保存配置不等于活动连接已切换，
  目录发现成功也不等于浏览器已连接或网页操作成功。
- 本版不提供浏览器安装器、扩展自动安装、依赖自动升级、新设置页或新 Slash 命令。

### 3.2 助手专用浏览器

1. 用户配置专用浏览器 Server，使用独立、持久的浏览器数据目录，默认以可见窗口工作。
2. 用户在对话中选择该 Server 并发出任务；由 MCP Server 按需启动或连接其拥有的浏览器。
3. 需要登录时，由用户在该浏览器窗口中完成；之后在同一会话继续任务。
4. Agent 读取当前页面，再执行查找、点击、输入或表单操作，并通过后续页面结果核对完成情况。
5. 后续使用同一数据目录时可复用尚未失效的网站登录状态；不承诺永久免登录或恢复未保存表单。

数据目录与日常 Chrome 分开，不复制日常 Cookie、不迁移浏览器数据库。会话清空、归档或删除
不被扩展为清理浏览器数据；删除 Server 配置也不自动删除其数据目录。

### 3.3 当前浏览器

1. 用户在希望使用的 Chrome 用户配置中安装官方 Playwright 扩展，并打开目标网站。
2. 配置当前浏览器 Server，用户在对话中选择该 Server 后发出任务。
3. 首次实际连接时，由扩展提供连接确认和页面选择；Desktop 不复制一套标签选择器。
4. Agent 首先核对返回的页面标题、地址和状态，随后在选定页面继续任务，保留页面原有登录和输入。
5. 需要改变可访问标签范围时由用户在扩展提供的界面中处理，再让 Agent 重新观察。

推荐流程保留扩展的人工连接确认。连接不到指定浏览器或选定页面时明确报告，不能静默改用专用
浏览器、另一个用户配置或重新打开同一 URL 冒充接管成功。扩展授权针对浏览器连接；`/mcp`
限定的是 Server，两者都不自动等同于本产品不同 Session 之间的页面隔离。

### 3.4 基本操作和展示

本版验收页面导航、读取可访问性结构、元素点击、中文输入、表单选择、按键、页面滚动/定位、
条件等待、标签列举/切换及截图。工具名和参数以固定版本 Server 实际披露的 Schema 为准。

- 元素操作优先基于新近页面快照；导航、页面变化或人工接管后重新观察，不复用失效元素引用。
- 截图用于需要视觉信息的步骤和结果展示，不要求每次操作都回传整页大图。
- 截图回流使用现有 MCP 图片链路，验收模型须支持已有 tool-result image 投影。
  当前 MCP 路径不能直接推导出自动辅助识图回退；纯文本模型使用结构化页面信息和不回传图片的配置。
- 对话中复用现有 Tool Detail 展示真实 Server、工具、参数和结果；网页本身在 Chrome 窗口查看。
- 任意网页、验证码、复杂画布、完整浏览器扩展生态及所有登录方式不作为通用成功承诺。
  坐标视觉工具、上传下载和其他高级能力不作为本版必验项，不为它们扩展应用资源协议。

### 3.5 人工操作、取消与重新连接

- 用户希望手动操作时，先通过现有停止入口停止 Agent；必要时在扩展中断开当前连接。
  等浏览器动作停止后再操作，完成后重新发送继续指令。复用现有 Run/Goal 控制，不新建接管状态机。
- 取消含义是停止后续执行并传播取消，不保证撤销已经发生的点击、提交，也不把 MCP 等待结束
  当作浏览器副作用已经完全停止；使用说明必须解释相应版本实测行为。
- MCP 超时、断线、刷新或 Runtime 重启后，先重新连接并读取实际页面，再决定是否继续。
  不自动重放上次点击或提交，不承诺恢复浏览器内存状态。
- 活动浏览器任务期间不主动刷新对应 Server。用户显式刷新可能导致连接或窗口被回收，需实测并记录；
  两种模式分别验证关闭连接的影响，尤其不能因退出 MCP 意外终止用户日常 Chrome。

### 3.6 首版并发边界

本版支持的使用约定是：**同一个浏览器目标在同一时间由一个会话执行连续任务**，使用者在继续
另一会话前先停止或结束前一任务；不对同一目标开启子 Agent 并行操作。

现有 MCP 连接按 Server 共享，工具串行属性和并发数为一都不足以保证跨多个调用的业务互斥。
该约定是明确的首版使用限制，**不是已经实现了自动占用锁或跨会话隔离**。其他非浏览器任务继续
使用既有并发能力；本版不承诺两个浏览器模式同时运行的隔离性。

验收必须复核共享连接行为，说明扩展的 client 隔离与本产品 Session 的区别。若要求系统自动阻止
跨会话争用，需要另行调整功能设计，不能在补丁版里悄悄增加通用租约、调度或浏览器资源实体。

## 四、模块边界与复用核查

| 既有归属 | 本版复用内容与边界 |
| --- | --- |
| `assistant-runtime` MCP | 配置、目录、Run 披露范围、授权和调用；不直接执行浏览器 CDP |
| `runtime-host` MCP | stdio 子进程和协议连接、环境过滤、图片物化；不保存第二份浏览器业务状态 |
| Desktop | 现有 MCP 管理、选择、审批、停止和工具详情；不增加网页或资源标签页 |
| 外部 MCP Server/浏览器 | 页面、登录状态、浏览器数据目录和工具动作 |
| Agent Core/Protocol | 工具循环以可靠 exchange receipt + 批内序号生成 ToolMessage ID；不新增协议类型 |
| Runtime Host 存储 | 启动恢复旧版 ready pending 时规范化 ToolMessage ID；不重放工具、不迁移数据库 |

核查依据为当前工作树，不把前序版本仍在进行的验收视为已通过：

- [MCP 功能设计](v0.23.0-功能设计.md)：设置、手选范围和手动刷新语义。
- [MCP 调用网关](../../crates/assistant-runtime/src/mcp/tool.rs)：实际 Server/Tool 身份和授权事实。
- [MCP Registry](../../crates/assistant-runtime/src/mcp/registry.rs)：共享连接、调用限流和刷新回收。
- [MCP 结果转换](../../crates/assistant-runtime/src/mcp/registry/result.rs)及
  [Run 工具装配](../../crates/assistant-runtime/src/runtime/model.rs)：图片能力与已有大小上限。
- [Host 连接实现](../../apps/runtime-host/src/mcp/connection.rs)：stdio 环境、单次发送与取消边界。
- [Agent 系统架构](../modules/agent-system.md)：Runtime 业务权威和工具适配边界。

“删除本次新增机制后，现有事实是否已经足够”的结论：现有 MCP 机制足以承载普通浏览器调用，
但真实验证暴露了与浏览器无关的通用恢复缺口。修复只改变 ToolMessage ID 分配和旧 pending 恢复，
不增加浏览器工具、状态、持久化表或产品进程。

## 五、权限与兼容性

- 继续复用既有 Plan/Build、Ask/Auto 和 Server/Tool 权限；选择 Server、安装扩展或网页宣称
  “允许”均不代替 Runtime 授权。页面内容是任务数据，不提升为系统指令。
- 权限按实际工具能力解释。允许点击不意味着产品能自动识别按钮背后的支付、删除或发送语义；
  不宣称本版新增了网页业务级审批或域名强隔离。验证使用无真实业务副作用的页面。
- 用户密码和验证码在浏览器中输入，不放入示例、提示词或工具参数。扩展凭据若确需配置，沿用
  既有 secret 路径；推荐样例不包含免确认令牌，故障记录和截图避免携带真实账号敏感信息。
- 仅复用现有配置及协议，不设计新的数据库迁移、Cookie 导入或 Session 格式变更。ToolMessage ID
  修复复用已经持久化的唯一 exchange receipt，因此不增加 Session 递增序号字段。
  外部浏览器数据不纳入本版 Session 导入导出，也不能称为操作系统强沙盒。
- `v0.23.0` 继续独立验收和归档；本版以其最终稳定行为为基线。若缺陷属于前序版本尚未完成的
  通用 MCP 能力，归回前序收尾处理，避免在两条版本记录里声称不同的完成状态。

## 六、明确非目标

右栏资源工作区、目录树、文件预览标签、内嵌网页、WKWebView 自动化、CEF、浏览器画面投送、
原生桌面 Computer Use、自研浏览器驱动、浏览器管理中心、自动安装/更新系统、浏览器池、
跨会话并行操作调度、远程浏览器云服务和无人值守登录均不在本版范围。

## 八、本版流程简化与验证推进

2026-09-04 用户明确确认“本版本可以简化流程，直接进入验证阶段”。本版沿用上述范围，直接
验证现有 MCP 与本机 Chrome，不单独补技术方案、界面设计或开发计划，也不为了版本号新增代码。
本项授权只适用于本版，不修改通用开发流程和前序版本的验收状态。

[验收记录](v0.23.1-验收记录.md)集中保存环境、配置、执行证据、失败与待验证项。使用独立的
临时 Runtime Home、测试页面和专用 Chrome 数据目录，保留日常浏览器和真实应用配置。
若发现现有实现缺口，先记录可复现证据及归属，再按最小范围处理；范围扩张仍须另行确认。
版本保持验证中，直至实际验收完成并获用户确认，不把进入验证等同于验收通过。
