## 二、问题修复与设计

| 事项 | 已确认事实与边界 | 本版需要收敛的结果 |
| --- | --- | --- |
| 分支继承历史丢失轮次结构 | Fork 复制规范消息前缀，未复制应用层 Run／Step 关系，目标历史缺少原轮次、Step、状态及时间。前端按连续消息合并的临时补丁已撤回，问题未修复 | 保留复制前后的可靠历史结构；界定失败重试、多 Step、半轮截断、重复分支、重启、源会话删除及用量不重复记账；评估既有分支恢复与迁移 |
| 会话文件、数据库职责与 ID 作用域 | JSONL 不能独立还原完整产品历史；`runs.run_id` 为全局主键，部分索引及查询仅按 RunId 定位。用户希望完整历史随会话文件保存，不同会话可保留相同历史 ID | 与分支问题统一设计权威事实、历史与活动执行分工、会话内身份及恢复方式；格式、数据库改法和迁移方案尚未确定，不预设新增历史表或双重权威 |
| 跨网络 STUN 配置与交付 | 跨设备 Peer 只从 `EZ_ASSISTANT_DESKTOP_STUN` 读取配置，默认空，测试包未提供默认配置；手机热点直连失败的完整 ICE 与网络原因未还原 | 收敛两端配置入口、服务来源和交付方式，补跨网络及网络切换验证；继续禁用 TURN，不承诺所有 NAT 均可直连 |
| 远程桌面超时与终端断连稳定性 | 已修复终端关闭标签卡住，但桌面偶发连接超时及终端通道断开根因尚未确认；本地标签释放不等于远端 PTY 清理确认 | 基于实际链路区分授权、控制连接、业务流、ICE／媒体和 PTY 生命周期，复现并定位后定向修复，避免用关闭修复冒充连接稳定性修复 |

历史与 ID 方案需核查 `runs`、`run_message_refs`、`skill_activations`、`model_request_records`、
`pending_tool_exchanges`、`body_appends`、`session_feedback`、`child_tasks.parent_run_id`，
以及外键、全局内存索引和序列化内容；`run_message_refs` 当前没有 SessionId 列。
不以复制历史恢复原任务，不重复统计历史调用。以上为源码设计影响范围，不是数据库操作授权。
