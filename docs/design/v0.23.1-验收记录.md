## 发现与处理

1. **导航快照只返回文件链接。** 0.0.80 的自动快照采用文件输出；显式 `browser_snapshot({})`
   返回 YAML。最初直连脚本错误地期待导航响应包含表单内容，断言失败；按实际 Schema 和响应
   改成显式观察后通过。切换标签后也需重新观察。这是验证脚本和用法调整，不是产品修复。
2. **指定截图文件名时没有 MCP image。** 传 `filename` 只保存并返回链接；省略它才带图片内容。
   修正调用用法后，正式 Runtime 图片物化、模型投影和预览已通过；无需增加图片 Adapter。
3. **扩展误报的根因是 macOS `EPERM`。** 最新会话确认扩展已安装；token 已配置、refresh 成功且
   活动子进程收到 token 后，`browser_tabs` 仍失败。0.0.80 会先扫描 Chrome Profile，扫描错误被
   折叠为空列表，因而误报“Extension not found”；token 在此后的连接页阶段才使用。加入
   `--executable-path` 绕过 Profile 扫描后，基本连接通过。
4. **工具发现不等于浏览器已连接。** 两份配置显示 connected 只证明 MCP 目录可用；实际
   `browser_tabs` 才验证扩展连接。修复后两层均已通过，暂不引入新的产品浏览器状态。
5. **当前浏览器配置修复。** 在 `browser_current.args` 增加显式 Chrome 路径，保存前候选测试发现
   24 个工具，refresh 后 Browser Server connected。只读列举返回 1 个标签。接入前备份、数据库
   精确增量和剩余边界见 [修复证据](../resources/v0.23.1-browser-validation/current-browser-fix-results.json)。
6. **compact 后旧 ToolMessage ID 被复用。** 主控会话 generation 28→29 完成 compact 后，新 Run
   的 Core 只扫描执行投影并重新分配 `toolmsg_1`；完整持久化 Conversation 已有同名消息。工具结果
   已进入 `ready` pending，但启动恢复追加时被 Conversation 唯一性校验拒绝；随后 Runtime 又无法
   在 pending 未清除时结算中断 Run，最终以 `runtime storage is unavailable while attempting to
   settle interrupted recovery run` 退出。SQLite `quick_check` 为 `ok`，不是数据库损坏、Chrome、
   MCP token 或 macOS EPERM 导致。
7. **最小恢复修复。** Core 改用已在副作用前可靠持久化的 `ExchangeReceipt + 批内序号` 生成
   ToolMessage ID，分配不再遍历当前上下文。Host 启动恢复会把 v0.23.0 已冻结的 ready 结果改为
   同一格式后提交，只改变消息外层 ID，不重放工具、不改变 Tool Call 配对或结果正文。没有新增
   Session 字段、全局计数器或数据库迁移。
