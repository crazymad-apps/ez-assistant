## 实施边界与技术取舍

- 复用 `ModelService.compact`，仅 `ResponsesProtocolAdapter.openai()` 改用 `/responses`、`store:false`、`stream:true` 与末尾 `compaction_trigger`；其他方言保持既有请求。
- 独立辅助调用不执行工具、不建立生成续接链、不增加重试或自动回退。复用 SSE 分帧器，严格校验唯一完成终态、原生压缩项、取消和响应大小。
- 将返回的压缩项与保留的 user/developer/system 输入组成既有 `responses.compacted_window`。不新增持久化格式，旧窗口可继续回放。
- 企业中心识别显式流式压缩，沿既有 compact 权限与绑定准入、调用记录及费用归类；HTTP 原始正文透传，WS 复用无状态临时链。旧 unary 路由保留给已发布客户端和其他方言，不新增双写或失败回退。
- 不改 UI、模型配置或用户会话数据；客户端与中心须配套更新，旧中心会明确拒绝新请求。用户随后明确授权本机中心更新，远程部署和正式发布不在授权范围。

## M0 验收

验证方言隔离、压缩后继续生成及再次压缩、错误/断流/取消/超限、中心准入与 HTTP/WS 透传。仅使用离线夹具和新建隔离测试环境，不调用真实付费模型。

实现与定向验证完成，等待用户确认。Adapter、中心 HTTP/WS 隔离联调及权限/计量回归通过；全工作区静态检查通过。全工作区测试在 Host 已记录的跨用户不存在会话 503/404 差异处失败，未扩大修复。用户随后授权 macOS 打包，包含当前工作区修复的 Apple Silicon 本地测试包已构建签名，源码快照一致；未公证或发布。

测试包实机反馈 400 后，确认实际连接的旧本机中心在准入阶段拒绝新请求。已用此前保存的完整真实压缩请求验证同一上游：首次返回服务过载失败终态，按其提示重试后压缩完成；真实成功响应通过客户端与中心的完整分帧解析。追加修正流内失败伪造 HTTP 400 的问题，服务过载按结构化错误分类且保留重试提示，不自动重试压缩；定向回归及静态检查通过。该错误分类补修尚未进入已交付安装包，不影响已有包使用新入口。
