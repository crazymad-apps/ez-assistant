## 二、实际能力结果

1. 压缩后的 Context Summary 持久化 usage adjustment；窗口判断先扣除压缩点前 usage，首个新
   Provider usage 到达后恢复权威基线，关闭了“压缩成功后立即再次误压缩”的现场故障。
2. 摘要旁路请求复用当前模型真实请求的 System、Conversation、Tools、reasoning 与 Provider
   Options 前缀，只追加隐藏压缩指令并禁用工具调用；不改写原上下文来换取缓存命中。
3. Runtime 从当前 Session 的可靠记忆工具结果计算相对冻结快照的净变化，随既有 Summary 和
   generation 原子持久化；连续压缩不会复活旧值、删除项或重复净变化。
4. 自动阈值、Provider overflow、手动压缩、父/子 Agent、重启、改写和分叉共用一致的合法性、
   提交和恢复边界；失败不产生半提交，也不重放已经执行的工具。
5. 正式 Host 故障同构样本只压缩一次并完成原 Run；protected tail 本身超窗时最多恢复两次后
   明确失败，原始历史和工具副作用仍完整。
6. M2 同步关闭 Desktop 可靠投影污染：请求实体、Conversation owner、事件水位和最新页连续边界
   均受校验，不增加协议字段或 Runtime 持久化状态。
7. 同期的小型 Composer 样式修正将主发送/停止按钮与普通工具按钮的 hover 规则分离；主操作保持
   蓝色，仅轻微加深。该项不改变 C02 业务语义，提交时应保持独立。
