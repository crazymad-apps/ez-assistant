# v0.27.0 C01 界面交互设计指导：企业管理后台

## 一、设计信息

- 日期：2026-09-18。
- 状态：2026-09-20 正式前端已沿用原型组件与样式完成，M3 及近期页面调整已获用户确认；不借正式化调整视觉设计。见[开发计划](开发计划.md)及 [UI 框架决策与原型](UI框架决策与原型.md)。
- 影响工程：`apps/enterprise-admin/`；接口由 `apps/enterprise-center/` 提供。
- 依据：[功能设计](功能设计.md)、[技术方案](技术方案.md)、[总体设计](../../总体设计.md)、[前端编程规范](../../../../specs/前端编程规范.md)。
- 范围：管理员登录、用户管理、本人账号、管理审计及其加载、错误、失效状态。
- 不涉及：C03 Runtime 用户入口、C04 模型管理与调用日志、Host 管理、数据库运维页面或注册/找回密码。

## 二、页面与入口

### 2.1 入口及导航

正式后台入口为 Center 的 `/admin/`。前端会话 Cookie 保存后台 Token，页面启动或刷新先恢复凭据并查询本人身份；确认前不展示登录页或管理数据。查询成功保留原路由，网络故障提供重试而不清除凭据；无凭据或确认失效才进入登录页。切回页面重新查询本人身份，失效时清理凭据和投影；加载期间不闪现用户列表和管理菜单。

| 页面 | 入口 | 常驻内容与动作 |
| --- | --- | --- |
| 管理员登录 | 未登录访问 `/admin/` | 账号、密码、登录按钮；错误或服务不可用反馈 |
| 用户管理 | 管理员登录后的默认页面、主导航“用户管理” | 搜索、角色/状态筛选、有界分页、创建用户、编辑、启停、重置密码 |
| 本人账号 | 顶栏当前账号入口 | 本人账号、显示名、角色/超级管理员标记、修改本人密码、退出登录 |
| 管理审计 | 主导航“管理审计” | 筛选、记录列表、分页、脱敏详情 |

不设置空白仪表盘、不展示未实现的模型管理或工作站菜单，不提供普通用户的后台个人中心。普通用户误用后台登录时显示“此账号无管理后台权限，请通过 Runtime 登录”，不签发后台 Cookie；不自动跳转到猜测的本机/远程 Runtime 地址。

2026-09-18 用户要求采用正式路由库：登录、用户管理、审计列表/详情由 React Router Hash 路由驱动，不再以页面状态进行条件切换。原型弹窗保持不变；2026-09-20 修正为刷新恢复有效登录，不恢复表单草稿，凭据失效重新登录后可回到所请求的本地路由。浏览器前进/后退切换页面，不能撤销已提交操作；编辑离开需确认，提交中禁止站内导航。

### 2.2 布局

- 桌面采用窄侧栏与主内容区：侧栏只放“用户管理”“管理审计”，顶栏展示当前页面标题与当前管理员账号入口。
- 当前账号入口沿用原型顶栏下拉菜单：账号信息、修改密码、退出登录。
- 2026-09-20 用户明确移除侧栏左下角“企业中心”及重复的“退出登录”，不留底部分隔线或占位；退出仅保留在顶栏账号菜单，品牌与面包屑不变。
- 主内容区按标题/主操作、筛选、列表、分页依次排列；不加统计卡片、重复副标题或说明横幅。
- 用户创建/编辑、账号信息及两种改密沿用原型 Modal；审计详情仍在主内容区展示，提供“返回列表”。不引入侧边抽屉。
- 返回列表保留本次访问的检索条件和页码并重新获取数据；离开后台或身份变化时清理这些页面投影。
- 响应式规则原样沿用现有原型：窄窗口收起品牌长标题，保留导航；表单单列，表格容器横向滚动。不另造移动端布局；实际可用性按下述矩阵验收，不以沿用样式代替实测。

首版面向桌面浏览器。布局验证至少覆盖 1440×900、1024×768、720px 宽度及 100%/125%/150% 缩放；这里只规定验收尺寸，不宣称已实测。

## 三、用户管理

### 3.1 列表与检索

列表只常驻账号、显示名称、角色、状态和操作。超级管理员在账号旁显示文字徽标“超级管理员”，不作为第三种角色；当前登录用户可标注“本人”。创建时间等低频字段进入编辑页的只读详情，不常驻内部数字 ID。

2026-09-20 用户指定：列表中 display_name 对应列的表头改为“用户名”，另一列仍为“登录账号”；仅调整表头文案，不修改字段、接口或编辑逻辑。

- 搜索框占位为“搜索账号或显示名称”，Enter 或“搜索”执行，避免每个输入字符触发请求。
- 角色筛选为全部/管理员/普通用户，状态筛选为全部/启用/停用；本轮采用有可访问名称的 Ant Design Select；编辑页两角色仍使用 Radio.Group。
- 变更检索或筛选回到第一页；分页默认每页 20 条，首版无需额外页大小配置控件。
- 行内只保留“编辑”“重置密码”和“停用/启用”，不添加批量操作与删除入口。
- 请求中显示列表加载状态，保留检索条件；加载失败不得渲染成“暂无用户”。筛选无结果显示“没有符合条件的用户”，提供“清除筛选”。
- 行动作绑定稳定用户 ID；排序或刷新后不能把打开中的密码重置目标替换为同一行号的新用户。

### 3.2 创建与编辑

“创建用户”打开独立表单弹窗，包含账号、显示名称、角色、初始密码及确认密码；默认普通用户、启用。账号格式和密码长度沿用技术方案，不在页面另设一套规则。确认密码仅用于前端防误输入，不发送为第二份后端密码字段。

编辑页显示不可编辑的账号，允许修改显示名称与角色；启停通过明确的单独操作完成，不混在普通字段保存里。密码不出现在编辑表单或详情返回中，由独立“重置密码”入口处理。

- 新建用户不提供超级管理员复选框；标记不属于普通编辑 DTO。
- 创建成功后返回列表并明确反馈已创建账号；恢复的当前筛选可能不包含新用户时提示“当前筛选可能不显示该用户”，不伪造一条不符合查询结果的列表项。
- 仅修改显示名称直接保存，不弹出额外审批确认；修改角色时在保存前显示目标账号、变更后角色及“该用户全部登录将失效”的确认信息。
- 停用确认明确“停用账号 X，其全部登录将失效”；启用只表明允许重新登录，不声称恢复旧登录态。
- 操作本人角色/状态时额外说明“本次登录也将失效”，按成功结果返回登录页。
- 最后管理员保护由服务端判断；页面不按当前分页计算“还剩几个管理员”。失败显示稳定原因，保留可修订表单，不乐观更新列表。

未提交表单离开当前视图时提示放弃修改；提交期间禁止重复提交和切换到另一个编辑目标，不把关闭视图误表述为取消服务器已接纳的写操作。密码字段在关闭、成功和身份失效时清空，不写入浏览器存储或表单日志。

### 3.3 超级管理员展示边界

用户列表和本人账号页可以展示服务端返回的标记；不得从账号名、首行位置或固定 ID 推断超级管理员。没有任何账号删除入口，服务端禁止删除规则仍需单独验证，不能以 UI 无按钮代替。

不新增“授予/取消超级管理员”交互。已确认禁止 API 停用/降权/修改标记，页面相应动作禁用，资料和密码可管理；数据库可直接赋予标记，所有保护按标记判断，不绑定初始化账号。

## 四、两种密码操作

两者分别命名、分别提供入口，不能因目标等于当前管理员而自动替换流程：

| 项目 | 修改本人密码 | 管理员重置密码 |
| --- | --- | --- |
| 入口 | 本人账号页“修改密码” | 用户管理中任意用户的“重置密码” |
| 标题 | 修改本人密码 | 重置用户密码 |
| 目标 | 当前认证用户，不提供目标选择 | 明确展示目标账号和显示名称，目标 ID 来自点击记录 |
| 输入 | 原密码、新密码、确认新密码 | 新密码、确认新密码，不显示或提交原密码 |
| 提交动作 | 修改密码 | 重置密码 |
| 提示 | 修改成功后本人全部登录失效 | 重置成功后目标用户全部登录失效；目标为自己时包括当前后台登录 |
| 服务端接口 | `/api/auth/password` | `/api/users/:id/reset-password` |

本人改密与管理重置分别使用原型的单层对话框，表单本身明确目标、后果和提交动作，不再叠加第二个确认弹窗。关闭后恢复触发焦点。

密码默认隐藏，提供可访问的显示/隐藏按钮，只影响本次输入；使用正确的 current-password/new-password 自动填充语义。不阻止粘贴或密码管理器，不显示已保存密码或密码摘要，不提供密码复制到剪贴板功能。

原密码错误明确定位原密码输入框；新密码不符合要求和两次输入不一致定位对应字段。重置本人密码也不增加原密码字段；修改本人密码即使是超级管理员也不能省略原密码。

成功修改自己密码后先确认成功结果，清空密码及管理页面投影，进入登录页并显示“密码已修改，请重新登录”。重置其他用户成功则关闭对话框，留在列表并显示成功反馈，不错误退出操作者。

## 五、本人账号、登录与退出

### 5.1 登录

登录页使用简洁表单，不引入 Desktop 的 WebGL 背景、工作台转场或原生能力。标题为“企业管理后台”，仅含账号、密码和登录动作，不增加注册、找回密码、记住密码开关或 API key 登录入口。

提交时保持按钮尺寸，显示“登录中”，防止重复提交；账号输入可保留，密码不持久化。错误按类型展示：

- 认证失败：“账号或密码错误，或账号不可用”，不区分账号不存在和已停用。
- 后台角色不足：提示使用 Runtime，不出现只读的普通用户后台。
- 限流：“操作过于频繁，请稍后重试”；只有服务端返回可靠等待信息时才显示倒计时。
- 中心不可用：“暂时无法连接企业中心”，提供显式重试，不显示认证失败或创建默认账号的入口。

### 5.2 本人账号与退出

本人账号只读展示账号、显示名称、角色和超级管理员标记，提供修改本人密码与退出登录，不放管理员重置按钮；如需管理重置自己，回到用户管理明确选择自己。

退出调用服务端当前 Token 撤销接口，提交中先遮蔽管理数据；成功后清空投影及密码表单，返回登录页，不撤销其他登录态。服务端未确认时显示“退出尚未确认”，保留重试退出入口，不宣称已退出或立即通过身份恢复重新展示后台数据。

其他位置的改密、停用或角色修改导致当前登录失效时，下一个受保护请求收到失效结果，统一清理界面并回到登录页。C01 不增加轮询、WebSocket 或推送机制来即时广播注销；切回后台页面时可重新查询本人身份，不能承诺其他标签页瞬时同步。

## 六、管理审计

审计页只有筛选、记录列表、分页和详情，不添加运营图表、导出或删除。筛选按时间范围、操作者、操作类型和结果组织；沿用原型 Ant Design Select，补齐正式契约要求的 RangePicker。条件变更回到第一页并查询，“查询”可手动刷新。

操作者筛选通过已有用户查询选择稳定用户 ID，不能按易变显示名称关联审计；选择项显示账号以便区分同名用户。无认证操作者显示“未认证”，已认证记录按稳定身份呈现，不猜测失败登录属于哪个现有用户。

列表常驻时间、操作者、操作、目标与结果；时间按浏览器本地时区展示，并标明当前时区。日期范围转为 UTC 后查询，不能把本地日期直接当 UTC 边界。详情页可展示精确时间、请求关联 ID、脱敏失败原因与普通字段前后变化。

2026-09-20 用户要求列表和详情显示操作者用户名、目标用户名（登录账号，不是显示名称）。后端按稳定用户 ID 关联现有 users 表，在审计响应中提供 actor_username/target_username；保留原 ID，不依赖前端用户分页缓存，不新增持久化字段或姓名快照。未认证显示“未认证”，无目标显示“—”；有 ID 但关联用户缺失时回退“用户 #ID”，不猜测名称。

“修改本人密码”和“管理员重置密码”使用不同动作名称。密码事件只展示发生过操作，不渲染任何原密码、新密码、密码摘要、token 或 key；未知详情字段不自动按 JSON 展开。C01 不出现 LLM 请求/响应快照入口。

## 七、视觉、组件与可访问性

沿用现有原型的主题、布局及样式。2026-09-18 用户授权正式使用其 Ant Design 6 基础组件及 ConfigProvider Token，显式替代此前不引入组件库的建议。不引入 Ant Design Pro/Umi，也不跨应用导入 Desktop 的构建配置；本轮不借通用 Token 规范修改已确认原型的视觉细节。

- 字号遵循 12/14/16px 三档 Token；单行控件高度使用 24/32/40px 三档，常规表单采用 32px，登录主动作可采用 40px。
- Token 在 Admin 私有样式入口集中维护，只纳入当前页面实际需要的语义，不复制 Desktop 全量终端/会话样式或新建公共主题包。
- 输入框、按钮和 radio 均有可访问名称；文本输入有非空 placeholder，placeholder 不代替无障碍标签。密码表单保留明确字段名称，避免误填原密码与新密码。
- 所有操作支持键盘，焦点可见；对话框管理焦点、Escape、焦点返回和 aria 关系，不由每个调用方重复实现。
- 错误放在相应字段或当前表单内，使用可感知的状态通知；不能只靠红色边框、Toast 或 hover 解释失败。
- 提交中/禁用/错误不能改变控件外框高度；长账号、长显示名及错误文案不能压缩到隐藏动作，详情允许换行。
- 弹窗最大高度受视口限制，只有明确的内容区滚动；页面与列表滚动所有权清楚，不通过整体裁切掩盖布局溢出。
- UI 只持有服务端投影与当前表单草稿。不同账号的数据不得通过返回按钮、迟到响应或内存列表泄漏；成功与否以服务端结果为准。

## 八、异步与异常反馈

| 情况 | 必须表现 |
| --- | --- |
| 初次读取 | 显示加载；不以空表冒充加载完成 |
| 查询失败 | 展示局部错误和重试；不清除检索条件，不写入“成功”状态 |
| 保存成功但列表刷新失败 | 明确“保存已完成，列表刷新失败”，只重试读取，不自动重发写操作 |
| 写请求超时/断连、提交结果不明 | 明确“操作结果未确认”，不宣称失败回滚，不自动重发；可读取普通字段或查审计辅助核对，不能凭密码不可见字段猜测是否已修改 |
| 账号重复/最后管理员保护 | 显示对应原因，保留非敏感草稿，服务端未接受时不改列表 |
| 身份失效 | 清空管理投影、关闭密码表单、回到登录；只显示一次失效提示 |
| 多请求并发返回 | 只接收与当前身份、查询条件和目标匹配的结果；后到旧响应不能覆盖保存成功后的事实 |
| 未知错误 | 使用安全提示及请求关联 ID，不展示异常栈、SQL、连接地址或任意上游文本 |

页面关闭和请求取消不意味着服务器回滚；网络结果不明时不提供“已取消修改”的反馈。密码操作的不确定结果应由用户核对登录/审计后再决定是否重新操作，不新增密码验证旁路接口。

## 九、交互验收口径

实施时至少回证以下用户路径，关联功能验收 C01-A02/A03/A06/A07/A09/A11/A13：

1. 初次加载、管理员登录、普通用户误入、错误密码、中心不可用各自反馈正确，无管理数据闪现。
2. 创建/搜索/筛选/分页/编辑/启停完整闭环；列表刷新失败与保存失败不混淆。
3. 管理员修改本人密码要求原密码；在用户管理中重置自己或任意其他用户不要求原密码，页面标题、字段和接口均区分。
4. 重置别人不退出操作者，重置自己或个人改密成功后当前后台登录失效；失败不误报成功。
5. 超级管理员标记来自服务端，不能通过表单伪造；不出现删除入口，保护规则另外通过 API 验证。
6. 改密、停用和角色变化引起失效后，旧页面、返回操作、迟到请求均不能恢复管理数据。
7. 审计检索及详情可用，两种密码操作可区分，秘密不进入列表、详情或页面日志；浏览器仅允许会话 Cookie 保存后台 Token，密码和 LLM key 不保存。
8. 退出成功与退出未确认准确区分，不把只清空前端视图当作服务端注销成功。
9. 键盘、焦点返回、错误定位、长文本、窄窗口和缩放通过真实浏览器检查，不以 DOM 单元测试替代布局验证。
10. 两个工程分别构建、合并制品后页面/API 同源可用；不依赖前端开发服务器和 Tauri。

原型边界见 [UI 框架决策与原型](UI框架决策与原型.md)。正式实现与循环验收结论见[开发计划](开发计划.md)，不另建验证记录，不以原型或单元测试冒充正式全链路验收。
