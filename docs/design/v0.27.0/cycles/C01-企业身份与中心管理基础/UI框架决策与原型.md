# C01 UI 框架决策与交互原型

- 日期：2026-09-18。
- 授权：用户要求先制作无后端业务的前端原型，确认页面效果，并进行 UI 框架决策。
- 状态：2026-09-18 用户授权正式前端沿用本原型的组件与样式，Ant Design 6 转为正式选择。下文原型边界保留为历史背景；正式实现与循环验收状态见[开发计划](开发计划.md)。

## 框架决策

推荐 React + TypeScript + Vite + Ant Design 6，业务布局用 Sass。React 等基线不变；本次对“暂不引入成套组件库”的旧交互建议作显式调整，仅作用于 enterprise-admin。

| 方案 | 本项目取舍 |
| --- | --- |
| Ant Design 基础组件 | 采用。现成的 Table/Form/Modal/Select 等适合当前 CRUD、密码操作和审计页，统一校验、交互与主题，减少自行维护控件的工作 |
| 沿用 Desktop 私有组件或自建整套控件 | 不采用。Desktop 主要服务会话工作台，直接跨应用依赖破坏边界；当前后台已有明确表格/表单需求，无需重新建设组件库 |
| Ant Design Pro 等全套后台脚手架 | 本轮不采用。四类页面不需要额外应用框架、复杂路由及模板层，保留轻量 Vite 工程 |

Ant Design 提供 TypeScript React 组件、国际化和企业 Web UI 能力；本次查询到 `antd 6.6.4` 与 `@ant-design/icons 6.3.4`，采用精确依赖和本工程锁文件。[官方介绍](https://ant.design/docs/react/introduce/)。颜色、控件高度与圆角优先通过 ConfigProvider 配置，不用选择器重写组件内部结构。[官方主题文档](https://ant.design/docs/react/customize-theme/)。

代价：增加组件库依赖与对应包体，并接受其表格/弹窗交互风格；最终结合原型效果、构建及浏览器验证决定是否转为正式方案。该试用不改变 Desktop，也不把库内部 CSS-in-JS 扩散到业务代码。

## 原型边界

- 工程：`apps/enterprise-admin/`；代码和模拟数据在独立 `prototype/`，正式 `src/` 暂不创建。
- 默认进入模拟管理员用户列表，常驻“交互原型 / 模拟数据”标识，可从底栏查看登录页。
- 展示登录、用户检索/筛选/分页、创建/编辑、启停、管理员重置密码、个人改密和审计详情。
- 数据在内存中变化、刷新恢复演示状态，无 API、数据库、Host 或模型请求，无 Cookie/localStorage。
- 模拟密码为公开演示输入，页面提示不要使用真实密码；不是产品默认密码。
- 超级管理员未决的停用/降权操作只提示未模拟，不借 UI 确认新权限规则。
- 演示操作生成的审计是内存样例，不能当作中心审计已实现。

## 验证记录

- `npm run build:prototype`：TypeScript 检查与 Vite 构建通过。存在单 JS chunk 超过 500 kB 的警告，当前约 1 MB（gzip 约 322 kB）；原型不隐藏此代价，正式入口需评估页面级拆包。
- `npm run lint` 通过；`npm run test:prototype` 5 项演示模型测试全部通过。Node 22.16 的原生 TS 类型剥离有实验特性提示，不用于生产运行。
- 真实浏览器已操作：创建/搜索/编辑用户、检查管理员重置本人密码弹窗不含原密码、本人账号表单包含原密码、管理员登录、普通用户误入拒绝、审计列表与操作详情、空数据/失败预览及重试、重置演示。
- 已查看用户列表、登录页、本人账号和密码弹窗截图；默认窗口与 720px 宽度检查通过，窄窗口采用顶部导航，文档宽度未超出视口，表格自身可横向滚动。浏览器未发现 error/warn 日志。
- 未执行：完整键盘/缩放/多浏览器矩阵、全部改密和启停组合，以及任何后端、数据库、真实认证/会话/审计验收。截图在本轮评审会话查看，未另存为正式验收附件。
- 原型有意简化：列表每页 8 条以展示分页；返回列表重新挂载筛选状态；审计暂不含日期范围；没有服务端异步竞争与真实会话恢复。正式交互要求仍以交互指导为准。
- 包版本 `0.0.0` 是私有原型占位，不是 Center 发布版本，不提升 Runtime 版本。

原型授权本身不等于正式实施授权；后续用户已明确授权开始正式前端，本轮据此进入 M3，不提升 Runtime 版本或宣布循环完成。
