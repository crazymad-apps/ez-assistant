# H5 播报帧缓冲与电流声修复方案

- 记录日期：2026-08-28
- 状态：第二版修复已实现并完成确定性回归，待用户重新试听
- 目标版本：v0.21.0（M6 门禁缺陷修复）
- 影响模块：H5 播放端、`speak` output cycle 上限、Host 连接播放队列；不修改
  Device WSS 协议、Rust Host 帧化和 Node codec

## 一、原始问题与已排除范围

- H5 播放长文本多段播报时偶发电流声或电子杂音；同一 TTS PCM 用 `ffplay` 播放无杂音。
- 真实 PCM 取证确认采样率为 16 kHz，无 clipping、明显 DC 偏置或异常高频能量。
- Host 640-byte/20 ms 帧化、尾帧 `sample_count`、WSS、Node 解码与 H5 bridge 字节均正确。

因此故障位于浏览器本地播放，不在音源、协议或 Node 解码。

## 二、失败的第一版修复与现场证据

第一版把“每帧到达即用 `currentTime + 40 ms` 排期”改成：

- 主线程维护 15 帧（约 300 ms）队列；
- 20 ms 定时器按 120 ms lookahead 批量创建 `AudioBufferSourceNode`；
- 上溢时报告 `playback_buffer_overflow`，H5 再发送 `playback_cancel`。

该方案经真实试听证明不可接受：

1. 用户只听到一两段。H5 当前诊断明确记录了
   `playback_start → playback_cancel → playback_end(cancelled)`；15 帧队列在主线程停顿时上溢，
   随后的 `playback_cancel` 按既有 Host 语义清空了当前和全部待播片段。
2. 电流声仍存在。即使开始时间连续，每个 20 ms 帧仍创建独立的
   `AudioBufferSourceNode`，浏览器会在大量节点启停和独立重采样边界上产生新的不连续风险。
3. 单元测试只验证了计划时间戳，没有验证真实浏览器渲染内核，因此不能证明听感问题已解决。

结论：扩大主线程小队列或继续调整 lookahead 数值都不是正确修复；第一版实现与结论撤销。

## 三、最终实现：单一连续 AudioWorklet 流

### 3.1 连续渲染

```text
PCM16 LE / 16 kHz frame
→ Float32
→ 跨帧有状态线性重采样到 AudioContext.sampleRate
→ MessagePort
→ 单一长期 AudioWorkletProcessor 队列
→ 单一 AudioWorkletNode
→ AudioContext destination
```

- 整轮生命周期只使用一个长期存在的 `AudioWorkletNode`，不再为 20 ms 帧创建 Source；
- 重采样器保留相邻传输帧之间的插值状态，不在帧边界重置；
- Worklet 在音频渲染线程按 render quantum 连续取样，主线程定时器不再承担音频时钟；
- 首次累计 120 ms 后开始，真实下溢后累计 80 ms 再恢复；
- Worklet 队列按 Context 原生采样率限制为 90 秒，容量异常只终止本地当前段并显示诊断，
  **不再自动发送 `playback_cancel` 清空 Host 后续队列**。

### 3.2 分段与完成

- 相邻 `speak` 在同一 Worklet 时间轴中插入 160 ms 原生采样率静音气口；
- 每个 `playback_end(completed)` 在重采样尾部之后放入 marker；只有 marker 被渲染线程消费后，
  H5 才认为该段真正播放完成；
- 新段已经开始或还有 marker 未排空时，不提前显示整条播报完成；
- 用户主动“停止播报”、新输入、连接关闭和正式 `playback_end(cancelled)` 仍按产品语义清空本地队列；
- 收到样本数与 `playback_start.sample_count` 不一致时，本地明确失败，不伪造完成。

### 3.3 `speak` 队列上限

- Host 单连接播放 FIFO 上限为 20；
- Runtime 单个 output cycle 最多成功接受 20 次 `speak`，第 21 次在 Host TTS 前失败；
- Tool Description 和隐藏补播提醒都明确 20 段上限，更多内容必须压缩取舍。

## 四、验证

- 连续重采样跨多个 20 ms 传输帧时不重置相位，最终输出样本数稳定；
- Worklet 首缓冲、下溢恢复、跨 chunk 连续输出、marker 排空和容量边界有独立测试；
- H5 控制器覆盖样本计数、160 ms 气口、完成等待、正式取消和本地异常不取消远端队列；
- 当前实际浏览器已成功注册并启用构建后的 AudioWorklet，控制台无加载错误；
- Node/H5 typecheck、25 项测试、lint、生产构建及 M6 隔离 E2E 通过；
- 最终听感仍必须由用户刷新原 H5 页面后，用真实多段 TTS 再次确认。

## 五、本次不做

- 不修改 Device WSS、Host PCM 帧化或 Node codec；
- 不把重采样上移到 Host，不修改 TTS 输出格式；
- 不因本地浏览器抖动自动撤销 Runtime 已接受的其他 `speak`；
- M7 仍负责录音侧 AudioWorklet、完整故障矩阵和产品化终端硬化，不再重复迁移播放端。
