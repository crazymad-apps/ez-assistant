- 反馈日期：2026-09-10。
- 状态：已在 `v0.26.0` M5 实现，2026-09-17 随版本验收归档。
- 目标版本：`v0.26.0`。

### 原始反馈

> 这个问题记一下, 不要每个模型provider后面都加上冻结解释, 你要么就把select入口直接冻结了, 加上tooltip

### 问题与期望

- 不在每个 provider 条目后重复追加冻结解释。
- 本次仅记录问题与用户期望，后续安排实现。

## UI-003 新会话默认使用上次选择的模型

- 反馈日期：2026-09-15。
- 状态：已在 `v0.26.0` M4 实现并于 2026-09-16 获确认。
- 目标版本：`v0.26.0`。

### 原始反馈

> 模型选择, 新会话也默认使用上次选择过的模型

### 问题与期望

- 当前新会话草稿不记住 Composer 中最近一次模型选择，只会回退 Runtime 全局默认模型。
- 在草稿或已有会话中成功选择具体模型后，之后创建的新草稿默认使用该模型。
- 默认值按 Desktop 当前连接目标隔离，本机与不同远端 Host 不互相传播。
- 已有 Session 和已经打开的草稿不被后续选择追溯改写。
- 用户选择“默认模型”时，清除设备端具体模型覆盖，之后的新草稿重新跟随 Runtime 全局默认模型。

## UI-004 macOS 滚动边界回弹收口

- 反馈日期：2026-09-16。
- 状态：已在 `v0.26.0` M5.1 实现并于 2026-09-16 获确认。
- 最终补充：M6 根据用户反馈扩展至 Windows Desktop；2026-09-17 随版本验收归档。以下保留最初仅 macOS 的需求原貌，普通 Web/Linux 仍不匹配规则。
- 目标版本：`v0.26.0`。

### 原始反馈

> macos下滚轮滚动会导致macos特有的缓冲滑动, 应该是 默认浏览器带来的特性

### 问题与期望

- macOS WebView 的滚动容器到达边界后仍会继续越界并产生橡皮筋回弹，界面出现整体缓冲滑动。
- 仅在 macOS 禁止滚动边界越界与链式回弹；普通滚轮、触控板惯性和容器内部滚动继续可用。
- Windows、Linux 和普通 Web 不因本项改变滚动语义。

## UI-006 正文与 reasoning 输出跟随及自由滚动

- 反馈日期：2026-09-16。
- 状态：已记录并完成代码初查，未实现。
- 目标版本：待定。

### 原始反馈

> 现在reasoning和text正文, 都不能随输出自动滚动到底部, 因为最新行输出后可能就导致程序判断当前已经不是在最底部了, 但是我希望能维持用户自由滚动的能力, 避免一直被锁定在底部

### 问题与初查

- 正文所属消息列表已有底部跟随状态，但每次 scroll 都按当前底部距离重新赋值；需要核查
  内容增长、程序滚动及布局变化触发的事件，避免误当作用户主动离开底部。
- reasoning 使用最高 180px 的独立滚动区域，目前没有对应的输出自动跟随逻辑。
- 正文所涉位置：`apps/desktop/src/features/conversation/ConversationView/index.tsx`；
  reasoning 所涉位置：同目录 `ToolSegments.tsx` 的 `ReasoningBox` 及 `index.module.scss`。

### 期望行为与后续验证

- 用户原本处于底部跟随状态时，新增正文或 reasoning 后继续滚动到对应区域底部；不能仅因
  新内容把底部推远，就取消跟随。
- 用户主动向上滚动查看已有内容时暂停跟随，后续输出不得抢回视口；仍允许正常滚轮、触控板、
  键盘及滚动条操作，不持续锁定到底部。
- 用户主动回到底部，或点击消息列表现有的“回到底部”按钮后恢复跟随。
- 消息列表和 reasoning 内部区域分别维护跟随意图，嵌套滚动不能误切换另一层的跟随状态。
- 验证连续换行、大块增量、布局变化及程序滚动时的事件顺序，并覆盖用户上滚后继续输出、
  回底恢复、reasoning 展开收起、切换会话和加载更早消息的滚动位置保持。

本条先保留问题和交互目标，具体修复与版本归属另行安排。

- 后续实现时核查现有上下文用量来源和展示机制，明确数值更新时点及压缩后的展示语义；
  数据暂不可用时不显示为零占用。
