# 企业用户删除

- 记录日期：2026-09-28。
- 状态：已纳入 `v0.29.0` 总体设计；Feature 细节待独立设计，未实现。
- 来源：下一版本规划讨论。
- 目标版本：`v0.29.0`；2026-09-28 已启动[总体设计](../versions/v0.29.0/总体设计.md)，当前草稿待确认。
- 影响范围：企业中心用户管理、企业管理后台、身份失效及关联数据边界。

## 用户原始要求

> 下个版本把删除用户的功能加上，现在只有停用，没有删除功能。

## 已确认目标

- 企业后台用户管理增加独立的“删除用户”能力，停用继续作为不同的操作保留。
- 删除不能只是将 `enabled` 改为 false 后换个名称；需明确账号删除后的列表、登录、查询
  和关联数据语义。
- 本次要求是下一版本功能规划，不是立即删除现有用户，也不授权清理现有数据库或 Host 文件。

## 已核查基础

- [`UsersController`](../../apps/enterprise-center/src/users/controller.ts) 当前提供查询、创建、
  编辑/启停和重置密码，没有删除接口。
- 现有用户只有 `enabled` 状态；身份变更复用中心事务、审计和 Token/key 撤销机制。
- 现有规则保护 `is_super_admin` 用户，并检查最后可用管理员。删除设计应明确对应保护，
  不能绕过已有账号管理约束。
- [`enterprise-center.md`](../modules/enterprise-center.md) 中“不提供 DELETE”描述既有版本
  边界；本次用户要求调整下一版本范围，后续实现时同步修订该约束，不据旧边界拒绝设计新能力。

## 建议交互与后续设计边界

- 管理员在用户列表或详情发起删除，确认界面明确目标账号、影响及是否可恢复；具体权限和
  是否允许删除本人、超级管理员及最后可用管理员，正式设计中确定。
- 删除成功后阻止账号继续登录，处理已有登录 Token 和 LLM key；核查 Host 已登录身份、
  缓存、活动请求及会话的后续行为，不仅移除后台列表中的一行。
- 明确物理删除或逻辑删除、账号名称是否可复用、再次创建是否作为新身份；不能使重建同名
  用户自动继承旧用户的数据或访问权。
- 核查调用记录、用量统计、审计、内容快照、反馈中心及其他用户引用的保留与展示；
  不默认级联删除历史业务记录，也不把关联数据处理留给数据库报错后临时决定。
- 企业中心账号删除与各 Host 本地用户数据清理是不同动作。是否提供清理能力另行确认，
  本项不自动向所有 Host 下发文件或会话删除。
- 删除结果与审计需一致，处理重复提交和并发账号变更，失败不可伪报成功。

本轮只读代码并记录需求，未连接或写入数据库，未新增删除接口。
