## 问题与定位

从超长会话创建分支时，弹窗长时间停留在“正在处理”。当前路径先读取完整源历史再截取，逐一复制涉及的子任务历史和工具图片，并重新序列化主历史。新历史直接写入无缓冲文件，产生大量细碎写调用；本次隔离历史片段对照确认，该写入方式有显著开销。片段实验不代表完整分支接口或界面的端到端耗时，不能直接外推整体提速比例。

复制期间持有 Runtime 操作写锁，并占用同一用户域的单 Store worker，其他依赖这些入口的请求可能排队。前端还等待应用列表刷新和新会话加载，全部阶段共用“正在处理”，无法区分复制与加载。

分支消息旁逐条显示“继承”，用户质疑其必要性。内部 `inherited` 标记用于区分复制历史与本分支真实执行，限制旧运行的重试、取消等操作；显示该标签并非维持内部语义的必要条件。

## v0.33.1 已确认范围（2026-11-10）

- 去掉逐条消息、处理过程及子任务中重复的“继承”标签或前缀。
- 保留内部 `inherited` 标记、历史身份及对旧运行重试、取消等操作的限制；不改变分支历史、执行状态或持久化语义。
- 本次仅确认界面文案优化纳入版本；分支复制性能及复制／加载阶段反馈不随之纳入。

## 待评估方向

- 新历史写入使用有界缓冲，保留显式 flush、文件同步、完整校验及事务发布顺序。
- 减少源历史重复读取和新分支提交后的重复装配，评估按分支位置有界读取。
- 根据优化后的残余耗时缩短共享阻塞范围，保持源代次校验、独立历史、失败清理及受监督生命周期。
- 区分复制与加载状态，不自动重发有副作用的分支命令。

分支性能候选实现顺序沿用 [F02 技术方案第 5.4 节](../versions/v0.32.1/features/F02-分支历史与会话存储修正/技术方案.md#54-长会话分支性能修正2026-10-22-草案暂缓实施)，本记录不修改已发布版本边界、不授权实施这些待评估事项。
