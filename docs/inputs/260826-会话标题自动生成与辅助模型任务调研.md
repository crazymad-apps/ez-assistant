# 会话标题自动生成与辅助模型任务调研

- 记录日期：260826
- 状态：已纳入 `v0.22.0` 功能设计
- 来源：与用户的设计讨论；对本地 OpenCode、Hermes Agent 和 Kimi Code 的只读实现调研
- 目标版本：`v0.22.0`

> 正式范围与决策以 [`v0.22.0 功能设计`](../design/v0.22.0-功能设计.md) 为准；本文保留调研事实，
> 不再作为待评估方案单独推进。

## 一、原始内容

探索 OpenCode 等开源 Agent 如何自动生成会话标题，重点判断它们是否：

1. 使用小模型或当前会话模型执行独立摘要；
2. 向主 Agent 提供会话标题工具，由模型主动决定调用；
3. 由宿主或 Runtime 调用独立的标题生成服务。

讨论中形成的原始方向是：

> 标题生成和未来的压缩、摘要等辅助推理可以共用一条“辅助模型任务”路径，
> 但不污染主 Agent 的工具权属和会话消息。

本输入只记录调研事实与候选方向，不表示已经确认引入某个版本，也不提前确定
公共接口或具体抽象形式。

## 二、调研结论

主流实现不是“给主 Agent 一个标题工具，让它自己决定何时调用”，而是由宿主或
Runtime 在明确的会话生命周期节点触发一次独立、无工具的标题生成请求。是否使用小模型，
属于这条旁路请求的模型路由策略，不改变它不属于主 Agent Tool Loop 的性质。

| 项目 | 生成方式 | 模型选择 | 是否由主 Agent 调工具 |
| --- | --- | --- | --- |
| OpenCode | 隐藏的 `title` Agent 读取首次用户上下文，异步生成 | 标题 Agent 显式模型 → Small Model → 当前会话模型 | 否，请求明确传入 `tools: {}` |
| Hermes Agent | 首轮回复完成后，后台执行一次 `title_generation` LLM 请求 | 可单独配置 provider/model，并支持自动路由和主模型兜底 | 否，标题请求未传入工具定义 |
| Kimi Code | Runtime 截取会话片段后调用托管平台 `chat_title` 服务 | 开源仓库未包含服务端模型路由，无法确认 | 否；接口虽名为 tool，但它是宿主主动调用的服务方法 |

### 2.1 OpenCode

本地调研快照：`7565e03536`。

- 标题由固定代码在首次 Agent Loop 中异步触发，不依赖主模型主动决定。
- `title` 是一个隐藏的模型配置档案；其权限全部拒绝，标题请求的工具集为空。
- 标题模型选择顺序为：标题 Agent 显式模型、Provider Small Model、当前会话模型。
- Small Model 可由配置或插件指定，否则再按 Provider 可用的轻量模型家族选择。

主要代码位置：

- `packages/opencode/src/session/prompt.ts:193-253`
- `packages/opencode/src/agent/agent.ts:234-249`
- `packages/opencode/src/provider/provider.ts:1873-1925`

### 2.2 Hermes Agent

本地调研快照：`707f31668`。

- 在首轮 User → Assistant 交换完成后，通过后台线程执行，不增加用户看到主回复的延迟。
- 标题使用首轮用户消息和 Assistant 最终回复的有界片段生成。
- `title_generation` 是独立的辅助 LLM 任务，可以单独配置 provider、model、timeout 和语言。
- 会话期间如果用户手动设置了标题，持久化阶段会让手动标题胜出，避免后台结果覆盖用户意图。

主要代码位置：

- `agent/title_generator.py:95-186`
- `agent/title_generator.py:291-402`
- `agent/auxiliary_client.py:7903-8040`
- `hermes_cli/config.py:1736-1746`

### 2.3 Kimi Code

本地调研快照：`c8029f9f3`。

- Session Title Service 负责从主 Agent Conversation 组装 `user_prompts`、`first_turn` 或
  `digest` 片段。
- 客户端携带 OAuth 令牌调用托管平台 `/tools` 的 `chat_title` 方法；该方法不对主
  Agent 披露。
- 开源代码只能证明“标题生成被封装为宿主主动调用的托管服务”，不能证明服务端使用
  小模型、主模型或非模型规则。
- 持久化使用 `replaceable | generated | custom` 区分标题来源，非强制生成不覆盖用户标题。

主要代码位置：

- `packages/agent-core-v2/src/session/sessionTitle/sessionTitleService.ts:57-158`
- `packages/oauth/src/managed-tools.ts:33-91`
- `packages/agent-core-v2/src/session/sessionTitle/flag.ts:6-14`

## 三、ez-assistant 现状

当前 ez-assistant 没有调用模型或标题工具：接受 Session 首个 Input 时，直接取用户消息
的第一条非空文本，按 `MAX_SESSION_TITLE_CHARS` 截断后与 Input 一起持久化。

已有 `SessionTitleOrigin::Generated | User` 区分自动标题与用户标题，可作为未来实现“后台
生成期间用户手动改名时，用户标题优先”的基础，但是否扩展标题来源状态仍需在正式设计中确认。

主要代码位置：

- `crates/assistant-runtime/src/runtime/input/submission.rs:58-69`
- `crates/assistant-runtime/src/runtime/input/submission.rs:233-241`

## 四、候选方向

如果后续引入模型生成的会话标题，可评估以下方向：

1. 标题生成由 Runtime 在固定生命周期触发，不向主 Agent 装配 `set_title` 类工具，
   也不依赖模型自愿调用。
2. 首轮 Run 可靠结束后，使用首轮 User 消息与 Assistant 最终回复的有界片段异步生成，
   不阻塞主回复。
3. 模型路由可评估“显式标题模型 → 轻量模型 → 当前会话模型”，但不应在未有明确调用方前
   提前确定通用抽象。
4. 持久化结果时仅在标题仍可被自动替换时写入；如果用户已手动改名，则丢弃迟到的自动结果。
5. 当辅助模型不可用或生成失败时，可保留现有“第一条非空文本截断”作为兜底。
6. 标题生成、Conversation 压缩、摘要等能力都属于非主 Agent Loop 的辅助推理。当出现两个及
   以上稳定调用方后，可评估共用辅助模型任务的模型路由、超时、取消、用量记录与失败隔离
   路径；不把它们塞进 Run 工具装配流水线，也不写入规范 Conversation 消息。

## 五、待正式设计确认

1. 何时触发标题生成：首个用户 Input 接受后，还是首轮 Run 可靠结束后；
2. 标题输入仅使用用户意图，还是纳入首轮 Assistant 最终回复；
3. 标题模型的配置形态、兜底顺序、费用和可观测性；
4. 用户修改标题、Session clear、fork 和恢复时，自动标题的保留与重新生成语义；
5. 是否已有至少两个稳定辅助推理调用方，足以支撑公共路径，而不是为假想需求提前抽象。
