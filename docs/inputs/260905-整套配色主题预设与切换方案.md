# 整套配色主题预设与切换方案

- 记录日期：2026-09-05
- 状态：待评估（讨论方案已确认，版本归属待定）
- 来源：用户关于主题色切换的会话讨论与确认
- 目标版本：待定
- 影响范围：Desktop 外观、Markdown 代码高亮、Monaco 查看器及终端配色

## 一、原始意图

用户希望提供类似 VS Code 的整套配色方案：

> 不是, 我希望是类似vscode的那种, monokai、solorized配色方案之类的

针对工作台配色与代码语法配色的关系，用户进一步明确：

> 我们这个合并一下就行, 预设几种

本文统一使用正式名称 Solarized。最终确认方向是一个「配色方案」选项，每个预设统一包含
界面与代码高亮等完整配色，选择一次，全局切换。本文记录讨论结果，尚未进入版本设计或实现。

## 二、已确认的使用方式

1. 设置中提供统一的「配色方案」选择入口，展示主题名称和配色预览。
2. 点击预设后立即生效并自动保存，重启后恢复上次选择。
3. 界面、代码高亮和终端使用同一个主题选择，不提供各自独立的配色选择器。
4. 明暗属性由主题本身决定，不再单独组合浅色／深色模式或强调色。

首批内置四种预设：

| 预设 | 明暗属性 | 说明 |
| --- | --- | --- |
| 默认浅色 | 浅色 | 保留当前默认外观 |
| Monokai | 深色 | 提供 Monokai 整套配色 |
| Solarized Light | 浅色 | 提供 Solarized 浅色配色 |
| Solarized Dark | 深色 | 提供 Solarized 深色配色 |

本次范围为内置预设；任意 VS Code 主题导入、主题市场、用户自定义色值和系统自动切换
均未纳入本次确认范围。

## 三、统一配色范围

| 区域 | 随主题切换的内容 |
| --- | --- |
| 应用框架 | 侧栏、会话区、资源栏、标题栏及分割线 |
| 交互控件 | 按钮、输入框、菜单、弹窗、悬浮态、焦点态及选中态 |
| 会话内容 | 正文、链接、引用、工具卡片及状态提示 |
| 代码内容 | Markdown 代码块与 Monaco 查看器的背景、文字及语法高亮 |
| 终端 | 背景、文字、光标及 ANSI 配色 |

主题需要提供协调的背景层级、文字层级、交互颜色和状态颜色。成功、警告、错误等状态
在不同主题下保持可辨识的语义。图片、PDF 页面和第三方网页保留内容本身的颜色，其外围
工具栏和容器跟随应用主题。

## 四、实现方向与现有基础

每个预设集中维护界面颜色、代码高亮和终端配色。所有区域消费同一个 `theme_id`；
不同渲染器内部按各自接口应用该主题，对用户呈现为一次完整切换。

- 界面继续使用现有 [`tokens.scss`](../../apps/desktop/src/styles/tokens.scss) 中的
  `--ez-*` 语义变量，由预设统一提供变量值；组件不自行判断主题名称。
- [`MonacoTextViewer`](../../apps/desktop/src/features/resource-workspace/MonacoTextViewer.tsx)
  与 [`MarkdownContent`](../../apps/desktop/src/components/MarkdownContent/index.tsx)
  使用不同渲染链路，需要分别接入同一套预设，保持代码配色一致。
- 本地只保存一个 `theme_id`，复用
  [`desktopPreferences`](../../apps/desktop/src/native-bridge/desktopPreferences.ts)
  对应的 `desktop-preferences.json`，作为设备级桌面展示偏好。
- 主题选择由 Desktop 管理，不进入 Runtime 会话、Run 或业务配置。

落地时需要核查并处理的事项：

- 组件内残留的固定颜色、侧栏局部文字颜色覆盖，以及文件图标的明暗映射。
- 经典主题的具体上游来源、许可信息，以及本项目会话和工具状态等特有颜色的补齐。
- 原生窗口背景与控件的外观协调；启动时应用已保存主题，避免显示错误主题后再跳变。
- 切换时保留会话、文件标签、代码查看器和终端状态及滚动位置。
- 保存失败的反馈，以及主题配置缺失或无效时的默认处理。

这些事项在纳入目标版本后细化，不在本文中提前固定主题文件格式、适配依赖或逐项色值。
