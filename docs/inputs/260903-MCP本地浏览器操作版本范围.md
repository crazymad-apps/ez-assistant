# v0.23.1 MCP 本地浏览器操作版本范围

- 记录日期：2026-09-03
- 状态：已归档（`v0.23.1` 已暂停且不发布）
- 来源：用户关于下一版本、浏览器操作和右栏资源工作区的连续讨论
- 目标版本：`v0.23.1`；不改变当前 `v0.23.0` 的开发与验收状态

## 一、用户原始意图与范围收敛

用户最初希望下一版本开始 Computer Use 或浏览器操作，并倾向同时支持助手专用浏览器和
正在使用的本地浏览器。讨论中还提出将 Desktop 右栏改为资源工作区，以标签页查看目录、
工作空间文件及网页，并允许 Agent 接管栏内网页。

在讨论 Tauri WKWebView、CEF 和浏览器控制方式后，用户明确收紧下一版本目标：

> 那这样,下个版本的目标还是收紧一下,就是用mcp,使用本地浏览器

本次确认的是 **通过 MCP 使用本地浏览器完成网页操作**。浏览器使用独立于 Desktop 右栏的
本地浏览器窗口，右栏资源工作区及内嵌网页不进入本次范围。

用户随后确认按 `v0.23.1` 小版本规划：在 `v0.23.0` MCP 基础上完成本地浏览器集成、
配置使用说明和必要验证，按实际缺口做最小适配或修复。版本号收敛不扩大功能范围，也不意味着
当前版本已验收或已授权开始下一版本实现。

用户先授权进入设计阶段，随后于 2026-09-04 确认简化流程、直接验证，前序版本继续收尾；具体方案见
[v0.23.1 功能设计](../versions/v0.23.1/功能设计.md)。下文保留原始范围和候选语义，最终结论与实测结果以归档功能设计和验收记录为准。

## 二、保留的使用方向

沿用用户此前对两种本地浏览器用法的倾向，作为后续功能设计输入：

1. 助手专用浏览器：启动使用独立数据目录的本地浏览器，用户可在其中登录并保留登录状态。
2. 当前浏览器：连接用户正在使用的本地浏览器，操作选定页面并使用该页面已有状态。

此次收敛没有明确取消其中一种；连接入口、目标选择和两种模式的具体交付边界在功能设计中确定。
最初讨论未限定品牌；进入验证后按功能设计采用本机 Chrome + Playwright MCP，固定实测版本。

## 三、复用原则与待核查项

- 优先复用 `v0.23.0` 的 MCP 配置、按 Server 发现、固定调用网关、权限审批、记录与结果回传；
  不因浏览器接入就预先新增管理中心、浏览器专属 Agent Loop 或第二套工具调用体系。
- 功能设计需确定页面读取、导航、点击、输入、截图等基本操作和实际任务验收场景；
  文件上传、下载等附加能力按任务需要确定，不自动扩展为资源管理功能。
- 检查共享 MCP 连接下的实际页面状态与跨会话操作行为。单次调用串行不能直接等同于连续网页
  操作互斥；根据实测确定必要约束，不提前建设通用浏览器调度系统。
- 核查取消、中断和继续时的实际浏览器行为；不能把取消 MCP 等待表述为已撤销网页副作用。
- 当前浏览器连接、扩展要求、登录状态、截图回传和本地依赖应通过实际候选 Server 验证，
  实测进展见 [验收记录](../versions/v0.23.1/验收记录.md)。

## 四、后续候选，暂不纳入

- Desktop 右栏资源工作区、目录树、工作空间文件预览和统一资源标签页。
- 客户端内嵌网页、WKWebView 自动化桥接、CEF 集成或浏览器画面投送。
- 整个桌面及其他原生应用的 Computer Use。
- 自建浏览器驱动或替换 Tauri 的默认 WebView 引擎。

这些想法继续保留，不视为不采纳；由后续版本单独确认。
