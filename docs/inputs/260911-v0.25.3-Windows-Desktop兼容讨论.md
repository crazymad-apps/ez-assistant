# v0.25.3 Windows Desktop 兼容范围讨论

- 记录日期：2026-09-11
- 状态：已吸收进 v0.25.3 功能设计，草案待确认
- 来源：用户会话讨论
- 目标版本：v0.25.3

## 一、原始目标

下一个版本插入 Windows 兼容工作，原有后续组网版本依次顺延。版本管理只记录“Windows
兼容”的总目标，具体范围和技术口径保留在本输入记录中，待启动 v0.25.3 功能设计时吸收。

Windows 首批交付 Desktop 产品，Desktop 内置 Runtime Host；暂不支持 Windows Client，也不新增
npm win32 Host 附件。Windows 应保持当前 Desktop 的主要功能一致，而不是只完成 MSI 打包和空壳启动。

## 二、已确认范围

### 2.1 产品与平台

- Windows 产品形态为 Desktop + 内置 Runtime Host。
- 不支持 Windows Client。
- 不单独分发 Windows Host，不新增 npm win32 Host 附件。
- x64 与 arm64 同时交付，但系统范围分别为：
  - x64：Windows 10 1809 及以上；
  - arm64：Windows 11 及以上。
- 用户具备 x64 Windows 测试环境，并可在本机安装 ARM Windows 11 虚拟机进行手工测试。
- Windows 保持当前 Desktop 的主要功能一致；具体模块以设计阶段对现有实现的核查为准。

### 2.2 安装、分发与验收

- 仅生成 MSI，不生成 NSIS 安装包。
- MSI 采用当前用户安装，尽量不要求管理员权限；如果 Tauri／WiX 或 WebView2 的真实安装边界无法满足，
  技术方案必须基于验证结果说明，不得静默改成系统级安装。
- WebView2 使用联网引导下载方式，不把完整 Runtime 离线嵌入安装包。
- 首版允许暂不做 Windows 代码签名，并接受相应的 SmartScreen 提示；正式发布信息应明确该限制。
- x64、arm64 两个 MSI 均应由可重复的自动化构建流程产出，并提供 SHA-256 校验值。
- 两个架构的 MSI 分别由用户在对应 Windows 环境中手工安装验收，不以“构建成功”替代运行验收。
- Windows 安装包通过 GitHub Release 分发，不通过 npm 分发。
- MSI 升级应保留既有用户数据；卸载 Desktop 时也保留用户数据，不默认删除 Runtime Home、会话、
  Workspace、模型、MCP、Skills 等持久内容。

### 2.3 生命周期与平台功能

- Windows 不做自启。
- macOS／Windows 已有窗口关闭行为应继续由现有设置项控制，不为 Windows 写死“隐藏到托盘”或
  “直接退出”，也不额外创建一套关闭语义。
- Windows 需要适配和回归托盘、窗口关闭、退出 Desktop、停止 Runtime 等已有能力，并保持现有
  业务边界。
- 如果跨平台自启接口要求 Windows 提供实现，可保留明确的空置／不支持状态，不能表现为配置成功。
- Windows 首版不接入 Windows Credential Manager；记住远程 Host 密码的能力在 Windows 上暂时
  空置，不使用普通配置文件或其他弱化方式冒充安全凭据存储。具体采用隐藏、禁用还是“不支持”提示，
  留到界面设计结合现有设置入口确定。

## 三、终端与 Agent Shell

### 3.1 两类选择相互独立

采用分别设置的方案：

- 交互终端类型由用户选择；
- Agent Shell 类型独立选择，不强制跟随交互终端；
- 首次可以使用 Windows PowerShell 5.1；
- 不根据机器上偶然安装的软件静默改变默认环境。

v0.25.3 支持的固定类型为：

| Shell | 可用条件 | 交互终端 | Agent Shell |
| --- | --- | ---: | ---: |
| Windows PowerShell 5.1 | Windows 内置 | 支持 | 支持 |
| CMD | Windows 内置 | 支持 | 支持 |
| PowerShell 7 | 检测到 `pwsh.exe` | 支持 | 支持 |
| Git Bash | 检测到 Git for Windows 的 `bash.exe` | 支持 | 支持 |

- 本版本取消自定义 Shell，不允许用户填写任意可执行文件、启动参数或命令模板。
- PowerShell 7、Git Bash 未安装或不可用时不能被选为实际执行环境。
- Git Bash 应使用可嵌入 PTY 的 `bash.exe`，不能把会另开 GUI 窗口的 `mintty.exe` 当作 Agent Shell。
- WSL 是未来候选，v0.25.3 不实现；以后接入时应作为正式 Shell 类型处理发行版、路径映射和文件域，
  不能借自定义 Shell 绕过这些边界。

### 3.2 全局默认与会话绑定

- 全局设置中可以选择默认 Agent Shell。
- 全局值只作为新会话的默认选项，不静默修改已有会话。
- 右栏会话上下文中可以切换当前会话的 Agent Shell。
- 实际执行以持久化的会话绑定状态为准，不以当前全局默认值为准。
- 每个 Run 使用创建时冻结的 Shell 环境；模型上下文需要知道当前操作系统、Agent Shell、命令方言、
  路径及转义约定，不能只依赖历史消息猜测。

### 3.3 通过现有输入队列切换

右栏切换 Agent Shell 时，复用类似 MCP Refresh 的机制，插入一条带结构化变更信息的 User Message，
进入现有 Session 输入队列，不建立绕过队列的即时配置通道。

顺序语义如下：

1. 当前正在运行的 Run 继续使用其冻结的旧 Shell。
2. 排在 Shell 切换消息之前的输入继续使用旧 Shell。
3. Shell 切换输入到达队首时，Runtime 更新持久化会话绑定。
4. 切换消息对应的 Run 及后续输入使用新 Shell。
5. 切换失败时不能写入成功绑定或表现为已经生效。

User Message 用于记录用户意图和上下文变化，会话绑定才是权威状态；上下文压缩、历史分页或 Runtime
重启不能导致 Shell 选择丢失或退回全局默认。

## 四、主要功能一致性

Windows 应覆盖当前 Desktop 的主要使用闭环，设计阶段至少核查：

- 会话、消息、队列、审批和恢复；
- 模型、权限和设置；
- Workspace、附件、文件、图片和 PDF；
- 用户浏览器；
- 交互终端与 Agent Shell；
- MCP stdio 与 Streamable HTTP；
- Skills、主控会话、子 Agent、Goal 和长任务；
- 本机 Runtime 启动、本机自动认证和打开 Web；
- 远程 Host 连接；
- 托盘、窗口关闭和 Runtime 生命周期；
- 数据库自动升级、备份及用户数据保留。

“主要功能一致”不表示所有第三方 Skill、外部命令或仅适用于 Unix 的用户脚本都自动跨平台可用；
产品自身必须明确报告平台依赖和不可用能力，不能静默失败。

## 五、明确不做

v0.25.3 不包含：

- Windows Client；
- 独立 Windows Host 安装包；
- npm win32 Host 附件；
- NSIS 安装包；
- Windows 自启；
- Windows Credential Manager；
- 自定义 Shell；
- WSL；
- 首版必须完成 Windows 代码签名；
- 为 Windows 重建一套窗口关闭或 Runtime 生命周期业务语义。

## 六、技术方案阶段待核查

以下是实施风险和核查项，不是本输入记录提前指定的技术实现：

1. Tauri／WiX 的当前用户 MSI、升级码、x64／arm64 目标与 WebView2 联网安装行为。
2. Desktop 内置 Runtime Host 的架构匹配、Sidecar 命名、启动、重连、退出和更新覆盖。
3. Windows ConPTY、终端尺寸调整、UTF-8、Ctrl+C、取消和子进程树清理；评估 Windows Job Object。
4. PowerShell 5.1、PowerShell 7、CMD、Git Bash 的发现、交互启动和非交互命令包装。
5. Agent Shell 会话绑定的现有承载位置、Run 冻结、Fork、Clear、恢复和队列切换原子性；优先复用
   现有 Session 输入及 MCP Refresh 机制，不预设新队列或第二份状态。
6. Windows 路径，包括盘符、反斜杠、中文和空格、大小写、长路径、目录联接、reparse point、UNC
   及 Git Bash 路径表达。
7. MCP stdio 对 `.exe`、`.cmd`、`.bat`、`node`、`npx`、Python 等启动形态的兼容。
8. Runtime Home、本机 bootstrap 凭据、权限文件、数据库、日志、上传和临时文件在 Windows 用户权限
   模型下的安全边界。
9. WebView2 用户浏览器、多标签、导航、弹窗、下载、缓存和重启恢复。
10. 托盘、关闭行为设置、退出 Desktop、停止 Runtime、系统注销／关机与任务恢复的现有实现核对。
11. Windows 凭据能力空置时的 UI、诊断和协议表现，确保不会假报保存成功或降级为明文存储。
12. 自动化构建、两个架构的 MSI、SHA-256、未签名发布说明和 GitHub Release 流程。
13. 中文 Windows 环境下的用户名、Workspace、附件、终端输入输出和安装运行验证。
