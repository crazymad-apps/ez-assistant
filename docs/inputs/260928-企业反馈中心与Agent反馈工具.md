# 企业反馈中心与 Agent 反馈工具

- 记录日期：2026-09-28。
- 状态：已纳入 `v0.29.0` 总体设计；Feature 细节待独立设计，未实现。
- 来源：下一版本规划讨论。
- 目标版本：`v0.29.0`；2026-09-28 已启动[总体设计](../versions/v0.29.0/总体设计.md)，当前草稿待确认。
- 影响范围：企业中心、企业管理后台、Desktop/Web 用户入口、Runtime 工具装配与 Host 中心通信。

## 用户原始要求

> 下个版本加一个反馈中心，并提供工具给 agent，让 llm 可以直接将使用过程中发现的问题总结反馈给企业中心，用户也可以手动发起反馈或者让 agent 发起反馈。

## 已确认目标

- 2026-10-02 用户补充：“反馈增加一个目标字段，比如是针对平台、或者某个插件、或者知识库的什么内容，方便后续进行统计。”手动与 Agent 共用结构化目标，细化见 [F04 功能设计](../versions/v0.29.0/features/F04-企业反馈中心与Agent工具/功能设计.md)。
- 企业中心集中接收和管理产品使用问题反馈。
- 用户可以通过界面手动填写并发起反馈。
- 用户可以在会话中委托 Agent 整理问题并提交反馈。
- Agent 可通过正式工具，将使用过程中发现的问题总结并直接提交到企业中心；不能只生成
  一段让用户自行复制的文本作为工具能力的替代。
- 三种来源共用同一反馈事实和中心处理流程，不建立相互独立的反馈系统。
- 当前是产品需求记录，不是要求本次开发会话立即向企业中心发送真实反馈。

## 候选功能范围

以下为设计建议，具体字段、界面与处理流程尚未确认。

1. **用户反馈入口**：填写标题、问题描述、期望结果及复现信息，提交后能确认是否成功，
   并查看本人反馈及处理状态。入口位置和截图/附件能力在设计时明确。
2. **Agent 反馈工具**：接收结构化的问题总结，复用当前企业身份提交，返回真实反馈编号和
   提交结果；失败时向 Agent 明确说明，不能虚报成功。工具名和参数留技术方案确定。
3. **企业管理后台反馈中心**：管理员查看反馈列表和详情，了解来源、提交用户、应用版本及
   环境信息，处理并记录结论。首版状态、筛选和回复能力需设计确认，不提前扩展为项目管理系统。

## 现有边界与复用方向

- 当前 `assistant-runtime` 的 `feedback` 与 `ask_user` 是 Agent 向用户提问、等待回复或
  轮后接收回答的会话机制；本需求是向企业中心提交产品问题，不复用其待回答状态或表作为反馈工单。
- 企业中心持有反馈记录及处理结果的权威状态；身份、权限、审计与管理后台入口优先复用既有能力。
- Agent 通过 Runtime 正式工具装配接入，Host 承担中心传输适配；不让 Agent Core 直接依赖
  企业中心 API 或数据库，不让模型接触登录凭据或自行拼接任意提交地址。
- 手动与 Agent 入口共用中心接收能力，记录实际提交身份和来源，便于用户查看和管理员处理。
- 默认提交与问题有关的总结及必要环境信息，不自动上传整段会话、完整工具日志、项目文件或
  凭据；附件与更多上下文的选取、预览及允许范围由设计明确。
- Agent 自主提交是用户要求的能力，不在需求记录中擅自收窄为“每次必须人工批准”；
  具体启用方式、工具权限与防重复规则在功能设计中统一确定。
- 同一提交的网络重试不能重复创建反馈；错误、离线和账号变化须返回明确结果。
  是否需要离线暂存另行评估，不默认新增持久队列或后台上报服务。

## 后续设计待明确

- 用户反馈入口位置、本人反馈列表、管理员处理状态和结果回传方式。
- 问题类型、字段及必要环境信息，截图、附件和会话关联的首版范围。
- Agent 主动发现问题后的提交时机、重复反馈控制和既有权限模式如何承载。
- 企业模式未登录/中心不可达时的行为，以及用户和管理员各自的可见范围。
- 反馈提交不应误停原任务；失败应可理解、可重试，不引发反复反馈循环。

本轮只记录需求；未新增 API、工具、数据库结构，未发送真实反馈。
