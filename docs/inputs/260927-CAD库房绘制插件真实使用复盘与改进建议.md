## 一、复盘背景

本次任务从库房草图重绘，逐步推进到智能电动密集架及设备售前预布置。用户反馈整体执行约一小时，等待时间偏长。

现有执行记录不足以精确还原各阶段耗时，因此不对各环节编造分钟数或占比。可以确认的是：耗时主要来自离线绘图流程的反复调试、全量重建和图面精修，而不是 AutoCAD 长时间计算。

**核心结论：方案设计、工具调试和交付精修混在同一流程中，没有先验证最小绘图流程，也没有尽早交付可供判断的首版。**

## 二、执行中实际遇到的问题

| 环节 | 实际问题 | 影响与责任 |
|---|---|---|
| 建筑理解 | 初版擅自在辅助区与整理区之间增加隔断 | 造成不必要的重绘和尺寸重算；属于助手对草图的过度推断 |
| 底图修正 | 后续明确两处矩形为窗户，机房玻璃隔断不另计总长，上下房间保持同宽 | 属于资料澄清，应及时固化到建筑输入，避免后续反复解释 |
| 运行环境 | 随包 Python 路径过长，图片库加载 DLL 失败 | 使用短路径映射解决；是额外开销，但不是主要耗时原因 |
| 图块导入校验 | 默认属性省略、名称大小写、数值表示方式等差异被初始比较方法判为不一致 | 多轮排查才能区分等价表达与真实变化；不应直接把差异都归为图块损坏 |
| 文字样式冲突 | 建筑图与设备源图库均有 Standard 样式，但字体定义不同 | 需要显式隔离样式，不能覆盖建筑原有资源，也不能忽略冲突 |
| 中文渲染 | 首次完整预览出现中文方框及标题显示异常 | 说明字体测试发生得太晚，导致完整预览返工 |
| 图面可读性 | 门区标签、原有注记与设备图块相互压叠 | 需要调整标签和引线，但不应每次都触发整套几何重建 |
| 核查证据 | 部分计数最初来自生成记录，而不是最终 DXF 独立统计 | 后续补做最终回读计数，并收紧碰撞检查的适用范围 |
| 执行组织 | 标签等局部修改多次触发完整生成、检查和多张预览输出 | 重复工作被放大，是执行效率下降的重要原因 |

说明：本轮未完成 AutoCAD 原生验证，实际工作主要在离线生成、回读、检查与渲染阶段。

## 三、主要流程原因

### 1. 没有先做最小样例测试

应先通过少量典型图块和中文文字，验证导入、保存、回读与预览能否正常工作，再运行完整方案。

本次顺序相反：完整布局已经生成，才陆续发现导入比较、字体和渲染问题，使每次排查都牵涉整张图。

### 2. 方案设计与交付精修没有分阶段

密集架方向比选、设备计配、门区小件、吊顶分图、图例、放大图、黑白底预览、说明文档和打包核查连续展开。

这些工作并非都没有必要，但应先让用户看到能够判断布局的首版，再开展完整交付精修，避免长时间没有可见成果。

### 3. 缺少按变更类型划分的重跑机制

移动标签、修改字体和调整架组，对应的校核范围不同。本次多次采用全量重建，未充分区分：

- 几何变化；
- 设备与数量变化；
- 纯文字、引线和显示变化。

### 4. 把讨论建议误解为实施授权

用户提出“最好形成固定脚本方便测试”，当时仍处于复盘讨论阶段。助手不应直接启动脚本实施计划。

## 四、哪些工作应保留，哪些重复应避免

### 必须保留的工作

- 比较可行的密集架方向、节列组合和固定列位置。
- 核查门扇、柱、开启空间、运动包络和通道。
- 识别标准产品与项目要求的冲突，例如 RFID 标准型号净通道不足。
- 保留建筑几何及设备源块、颜色、线型和必要资源关系。
- 从最终文件回读数量与关键几何，而非只相信生成过程中的计划数据。
- 检查中文显示与图面可读性。
- 明确原生 CAD、消防、结构承载、锚固及厂家深化的待核范围。

### 应避免的重复工作

- 擅自补充建筑结构，再因客户纠正而返工。
- 在完整项目上才开始验证基础字体与图块导入。
- 将等价的默认属性表达误报为几何损坏。
- 每改一个标签就重跑全套生成与校验。
- 首版布局尚未交给用户判断，就提前完成大量精细交付版本。
- 在讨论阶段未经明确授权启动文件修改或脚本实施。

## 五、讨论建议：固化“小样预检脚本”

### 1. 定位

建议将跨项目反复出现的技术问题，固化为独立、可重复运行的小样预检。

它应回答：

> 当前环境和绘图流程是否能正常工作？如果不能，问题位于哪个环节？

它不应回答：

> 当前项目的布局、消防、承载和施工条件是否合格？

### 2. 固定检查与项目检查分离

| 检查类别 | 建议内容 | 结果边界 |
|---|---|---|
| 通用技术预检 | Python 与依赖、路径可用性、中文字体、代表性图块导入、颜色及文字样式、默认属性规范化、保存回读、预览生成 | 判断离线绘图流程是否具备开展工作的条件 |
| 项目级校核 | 建筑净尺寸、门窗柱、门职责、架体规格、容量、通道、运动包络、设备配置与厂家限制 | 必须依据本项目资料单独执行，不能由通用小样替代 |
| CAD 原生核验 | 原生打开、字体显示、AUDIT、另存与回读渲染 | 需实际 CAD 环境与执行证据，不能由离线预检代替 |
| 专业复核 | 消防、结构承载、锚固、空调负荷及施工合规 | 由厂家及有资质专业人员复核 |

### 3. 建议的小样范围

- 一个代表性密集架块及操作构件。
- 少量覆盖典型实体类型和文字样式的设备块。
- 一组中文标题、设备名称和尺寸注记。
- 一次导入、另存、最终回读及预览。
- 一份能够定位问题的检查报告。

小样不应带入历史项目的房间尺寸、门职责、设备数量或验收结论，也不应逐渐膨胀成另一个完整项目。

### 4. 建议提前确定的比较规则

- 默认值省略与显式写出，应按明确的 DXF 语义判断是否等价。
- 对允许忽略大小写的资源名称，采用明确的比较规则。
- 等价数值表示可以规范化，但不得因此忽略真实尺寸差异。
- 同名文字样式冲突应显式隔离并记录映射，不能静默覆盖。
- 图块几何、颜色、线型、嵌套引用和资源定义应纳入检查。
- 容差和允许差异必须事先定义，不能为了“通过”而临时放宽。

### 5. 建议的结果表达

| 状态 | 含义 |
|---|---|
| 自动检查通过 | 本次测试范围内的自动检查满足预设条件，不等于项目或施工验收通过 |
| 自动检查失败 | 输出具体失败项、影响及定位信息，不静默继续完整生成 |
| 人工看图待确认 | 已生成预览，但需要检查中文、标签、颜色与可读性 |
| 原生 CAD 待验证 | 尚未取得原生打开、AUDIT、保存和回读证据 |

字体文件存在、程序没有报错、成功生成图片，都不能单独等同于“中文显示正确”。同样，离线回读通过不能等同于原生 AUDIT 通过。

### 6. 如后续获准实施，建议的验收方向

- 能独立运行，不依赖某个项目的完整生成脚本。
- 只读源图库，输出到独立目录，不覆盖建筑底图或插件资源。
- 在相同环境和输入下可重复测试，结果可追溯。
- 明确区分通过、失败、警告及人工／原生待核项。
- 失败时能指出原因，并以明确退出状态阻止后续自动流程误判成功。
- 包含代表性的正常测试和故障测试，例如字体缺失、块缺失、真实几何或颜色变化。
- 记录测试耗时，用实际数据判断是否提高效率，不预先承诺固定完成时间。

以上为讨论建议，尚未作为新的固定脚本实施。

## 六、建议的后续执行顺序

### 阶段一：锁定建筑输入

以用户本次确认的墙、门、窗、柱和隔断为准。未知项标注待核，不通过自行加墙、扩门或改尺寸解决。

### 阶段二：运行技术小样预检

在完整绘图前验证基础工具流程。环境或关键导入检查失败时先定位问题，不在整张图上反复试错。

### 阶段三：先交可判断布局的首版

首版重点表达密集架、主要箱体设备、通道、容量和关键冲突，让用户先确认方向与空间取舍。

首版仍需必要的几何检查，不能以“尽快交付”为由跳过门扇、运动包络等关键核查。

### 阶段四：按确认方向深化

再补门区小件、吊顶设备、详细图例、完整清单、放大图与交付说明。

### 阶段五：按变化范围重跑

| 变化类型 | 建议重跑范围 |
|---|---|
| 建筑或架体变化 | 相关几何、容量、运动包络、门扇及通道；必要时扩大到全局 |
| 设备类型、数量或位置变化 | 对应设备保真、数量、安装面、朝向、检修区和相邻通道 |
| 标签、字体或引线变化 | 图面可读性、文字保存回读与预览；不无条件重建全部布局 |
| 最终交付 | 统一执行一次最终文件回读、数量与关键几何核对、预览检查及待核项汇总 |

### 阶段六：满足售前阶段目标后及时交付

达到布局清楚、数量一致、关键风险已标明、文字可读后，先交付当前阶段成果。没有必要的额外预览和标签微调，不应持续推迟用户看到首版。

## 七、当前结论与实施边界

1. 固定小样预检值得做，价值在于提前暴露工具链问题并减少跨项目重复调试。
2. 小样预检必须与项目设计、CAD 原生核验和专业复核分开，不能扩大其“通过”结论。
3. 提效不仅依靠脚本，还依靠首版早交、分阶段深化和局部变更局部重跑。
4. 讨论建议不等于实施授权，后续是否编写、修改或集成脚本，需用户明确决定。
5. 本次仅形成复盘 Markdown，不改动既有图纸、脚本或插件。

**总结：小样先行、首版早交、按变更范围重跑；保留必要核查，不把自动化结果冒充项目验收。**
