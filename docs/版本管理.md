# ez-assistant 版本管理

本文只维护当前版本状态、阶段路线和已归档版本入口。具体范围、设计、实现过程与验证证据以
对应版本归档为准；流程规则统一见 [`开发流程规范`](specs/开发流程规范.md)。

## 当前阶段

- 当前目标版本：`v0.9.0`。
- 状态：`待启动`。
- 已完成基线：`v0.8.0` 已建立正式 `assistant-runtime`、轻量应用协议、独立 Runtime Host 和
  真实跨进程 Agent 执行闭环。
- 当前开发重点：从长期能力地图中选择第一个正式 Runtime 业务模块；具体目标、范围与成功标准
  尚未确认，不从历史讨论自动推断。
- 应用边界：Tauri 是展示层和桌面平台适配层；Session、Conversation、Run、Harness、策略、
  审批、工作区、记忆、调度、持久化和事件记录等产品业务由 Runtime 持有权威状态。
- 长期物理架构：桌面 UI 与 Runtime 分进程运行；Session 不创建操作系统子进程，而是在同一
  Runtime 进程内按逻辑控制器和 Tokio 异步任务管理。该方向由后续版本逐步实现。
- 最近完成：[`v0.8.0 版本总结`](versions/v0.8.0/版本总结.md)。
- 下一步：讨论并确认 v0.9.0 的单一业务能力闭环，再进入功能设计。

## 长期开发方向

后续按照“Runtime 业务能力 → 应用协议 → 独立 Harness 回证 → Tauri 展示”的顺序推进。以下仅是
长期能力地图，不预先绑定 `v0.9.0`、`v0.10.0` 或 `v0.11.0`：

1. **会话、对话与持久化**：规范 Message、Run、Journal、恢复和 Repository/Store 边界。
2. **Harness 工作模式与审批**：将 Plan / Build、Ask / Auto、工具策略、Guardrail 和审批协调正式
   纳入 Runtime；UI 只提交模式意图、展示请求并返回用户决定。
3. **Workspace 与文件能力**：由 Runtime 管理会话工作目录、临时工作区、附件、文件变更和
   Artifact；Tauri 只提供文件选择、拖放等平台交互。
4. **记忆与长期助手能力**：正式装配 Pinned Memory、RecallSource、计划任务、后台服务和通知意图。
5. **独立 Runtime 与桌面客户端**：完善本地 IPC、单实例、断线重连和事件补取；桌面 UI 与 Runtime
   分进程运行，Tauri command 保持薄，不持有业务权威状态。
6. **系统后台生命周期**：在实际 Harness 与桌面链路稳定后接入 macOS 菜单栏、Dock、LaunchAgent
   以及其他平台的用户级后台运行机制。
7. **集成回证**：每个业务模块都使用正式 Runtime 重新验证 Core 候选 API，再决定哪些接口进入
   稳定承诺。

长期方向不预先决定数据库、Repository、UI 信息架构或迁移方案；具体版本边界在前一版本验收后
结合实际依赖重新确认。

## 版本与输入规则

- 状态统一使用：`待启动`、`设计中`、`计划中`、`开发中`、`验证中`、`已完成`、`已暂停`。
- 尚未纳入版本的想法保存在 [`docs/inputs/`](inputs/)；只有与当前版本目标一致的输入才进入
  功能设计，其他输入继续保留。
- 每个版本形成一个可独立验收的能力闭环，并依次经过设计、计划、分里程碑确认、验收和归档。
- 版本状态以用户确认和实际阶段为准；归档完成不依赖 Git commit、tag 或 push。
- 逻辑组件边界遵循 [`Agent 系统技术架构`](modules/agent-system.md)；物理 crate、协议和存储形态
  在对应版本设计中确认。
