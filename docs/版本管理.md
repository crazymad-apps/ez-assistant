## Agent Core 版本路线图

Agent Core 优先于应用层开发。路线图只确定版本边界和完成门槛；每个版本启动时仍需先形成功能设计和开发计划，再进入实现。

| 版本 | 主题 | 核心范围 | 完成门槛 |
| --- | --- | --- | --- |
| `v0.1.0` | 基础类型与模型层 | 建立规范对话、模型事件、Provider Codec、单次模型 Turn 和基础 testkit；完成首个 OpenAI-compatible Adapter，并覆盖 DeepSeek reasoning/tool-call 往返 | 不依赖 Tauri、数据库和真实工具即可完成单次模型调用的确定性测试；Provider 特有消息可无损编码和解码 |
| `v0.2.0` | Agent Engine 与工具循环 | 建立 `ExecutionSpec`、`ExecutionInput`、`AgentExecution`、类型化 Tool、Registry、Dispatcher、Execution Recorder、多轮工具状态机以及 FileSystem/Shell 能力契约 | fake model/tool 可覆盖纯文本、单工具、多工具、多轮工具、失败和取消；工具副作用前完成规范 AssistantMessage 记录 |
| `v0.3.0` | 上下文系统 | 建立 Prompt Compiler、上下文组装、token 预算、工具输出裁剪、压缩和 Provider overflow 恢复 | 长会话可在确定预算内稳定生成请求；压缩不破坏 reasoning、Provider 状态和 Tool Call/Result 配对 |
| `v0.4.0` | 安全与执行控制 | 建立 `Allow/Deny/Ask` 策略、Approval SPI、可选资源预算、超时、取消和 `Off/Observe/Enforce` Guardrail | 权限和 Guardrail 决策可独立测试；所有限制均显式配置，不存在隐藏终止条件 |
| `v0.5.0` | 可插拔记忆系统 | 建立 Memory Service、Memory Plugin、Memory Orchestrator、作用域、召回、观察、整合和 No-op/参考实现 | 本地、远程和混合实现可通过同一 SPI 接入；插件超时或部分失败不破坏 Agent 主循环 |
| `v0.6.0` | 扩展性与可靠性 | 完善 Provider/Tool/Memory Adapter 边界、错误模型、背压、重试边界、事件一致性和并发安全；补齐录制回放与故障测试 | 关键失败路径、取消、流中断、Recorder 失败和 Provider 兼容均有确定性 Harness 覆盖 |
| `v0.7.0` | Core 候选版 | 收敛公共 SDK、Facade、crate 边界、配置输入、文档、示例、性能基线和兼容矩阵 | Agent Core 对外 API 达到候选稳定状态；完整能力可在无应用层环境下端到端运行，允许进入 Runtime 与桌面应用开发 |

### 路线图约束

- 每个版本形成一个可独立验收的能力闭环，不因零散需求随意改变版本主题。
- 新想法先进入 `docs/inputs/`，只有符合当前版本目标时才纳入；其余保留给后续版本评估。
- 逻辑组件边界遵循 [`Agent 系统技术架构`](modules/agent-system.md)；是否拆为独立 crate 在对应功能设计中确认。
- `v0.7.0` 是 Core 开发阶段的候选完成门槛，不等同于整个桌面产品 `1.0`。Core 公共 API 仍需经过 Runtime 和真实应用集成后再判断是否进入稳定版。
- 路线图调整直接修改本节；已经启动版本的范围变化还必须同步更新该功能设计和开发计划。
